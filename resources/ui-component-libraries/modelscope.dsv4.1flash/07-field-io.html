01

风格介绍

适合：开发者工具 / 数据平台 / 生成艺术与技术品牌

这套组件库的图形全部来自算法：环弧、径向刻度、网格底纹都是确定性生成的结果。底色是中性浅灰（近乎单色），强调色只有一个电光蓝 —— 与 33px 网格底纹共同构成「计算中」的视觉。数据读数使用等宽字体，交互克制到只有颜色变化。

特征 01生成式图形

主视觉是算法生成的环弧与径向刻度，固定种子、可复现、可微调参数。

特征 02单色系 + 单强调

中性灰阶打底，唯一的电光蓝 #2F5BFF 承担全部强调。

特征 03网格显影

33px 网格底纹贯穿全页，象征所有图形都由坐标定义。

特征 04代码感排版

读数、标签、图注统一等宽字体；字号小、字距正、无装饰。

提示词 DNA（用于扩展 AI 生成素材）

Field.io generative design style:
- Abstract geometric patterns, algorithmically generated
- Dynamic composition that feels computational
- Monochromatic base with one vibrant accent
- Mathematical precision in spacing
- Voronoi diagrams or Delaunay triangulation
- Clean code aesthetic

标志性做法（延续这套风格时保留）

  • 环弧图形是这套风格的签名，出现于 Hero 与分区装饰。
  • 分区标题带 2px 黑色顶线，形成「代码区块」的分隔感。
  • 按钮默认近黑，悬停时才点燃电光蓝。
  • 橙色 #FF5C35 一页最多出现一处（错误或关键警示）。

灵感来源

参考 Field.io（伦敦/柏林）的生成艺术与数据装置：British Council 数字装置、品牌生成视觉系统。抽象几何由算法生成，单色系底 + 一个高饱和强调色，数学精确的间距，干净的代码感。

03

扩展指南

新增组件或页面时, 按这四步走即可保持风格统一。

  1. 新增图形时写生成规则（正弦扰动 / 角度步进），而不是手绘路径。
  2. 颜色只从灰阶 + 电光蓝里取；橙色留给真正的错误态。
  3. 所有读数与标签用等宽字体；正文字号不小于 13px。
  4. 网格、刻度、坐标轴这类「计算痕迹」可以保留，它们是风格的一部分。

延续与扩展时应做

  • 图形由算法生成并固定种子
  • 标签读数统一等宽字体
  • 保留网格与刻度痕迹
  • 强调只用一个电光蓝

会破坏这套风格的做法

  • 手绘插画式图形
  • 引入第二个强调色
  • 柔和渐变与模糊光晕
  • 圆角超过 3px

想要第 21 套风格? 复制任意一套文件, 只替换 :root 变量块与该风格专属的组件覆写即可 —— 骨架、组件标记与交互脚本都可原样复用。

折叠面板

为什么「每天一次」要靠状态文件去重?
窗口语义不能依赖循环频率: 程序可能重启、循环周期可能调整。把执行记录写进 state_file, 重复执行同一动作才会是幂等的。
校验之后的代码为什么不做防御性检查?
配置在 validate_config 一次性全量校验并聚合报错, 之后的代码假定配置正确 —— 这样错误只有一个出口, 不会散落在各分支里。
