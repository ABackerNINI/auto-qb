连接 qBittorrent

auto-qb 本身不下载东西，它是通过 qBittorrent 的 Web UI 去读种子、改种子的。所以第一件事是告诉它 qB 在哪、用什么账号登录。填好之后点一下下面的「测试连接」，能连上就说明配置对了。

这四项就是 qB Web UI 的地址和账号密码。如果 qB 里没启用 Web UI，auto-qb 什么都做不了。

装 qBittorrent 的那台机器。auto-qb 和 qB 在同一台电脑上就填 127.0.0.1，在另一台机器上就填那台机器的内网 IP，比如 192.168.1.20。

qB Web UI 监听的端口，qB 默认是 8080。改过的话以 qB 里显示的为准。

这三个值决定 auto-qb 的「勤快程度」。默认值对绝大多数人够用，除非种子特别多、机器特别慢，否则不建议动。

秒

每隔多久看一次所有种子的状态，并处理到期的任务。默认 2 秒。不能填 0。

个

一轮里最多执行多少个自动化任务。填得太大，单轮时间会变长，界面反应也跟着变钝。

秒

清理、限速曲线这类周期性任务的间隔。从上一次结束开始算，所以不会越跑越密。

运行状态存在哪

运行状态、日志、跳检备份放在哪个目录。可以写相对路径（相对程序目录），也可以写绝对路径。

改了要重启。这个目录在启动时就确定，改完必须重启 auto-qb 才生效。

记录「上次做到哪了」。重启之后会接着上次的进度继续，不会从头再来一遍。

自动化

这一页决定「种子加进来之后 auto-qb 帮你在后台做什么」。每一项都是可选的：不想要就关掉，auto-qb 只会做你开了的那几件事。

标签

同一个站点在不同种子上可能留下 HHan 和 hhan 两个标签，开启后只保留一个。某个站点想例外，可以到「站点」那页单独关掉。

跳过哈希校验的种子会被打上这个标签，方便日后一眼认出它们其实没校验过。留空表示不启用跳检。

辅种分组

已启用

关掉之后每个种子各管各的。

核对组里的文件是不是还在磁盘上。发现少了就整组暂停，免得继续做种却上传不出东西。

发现缺文件时，给组里每个种子加上这个标签，方便在 qB 里筛出来处理。

规则

一条规则就是一句话：「当……的时候，做……」。条件要全部满足才会执行动作；有多个动作时按从上到下的顺序依次执行。规则按顺序逐条判断，不是命中一条就停。

当 做种时间 至少 7 天 时， 删除种子（同时删除文件）

删除连带文件，且无法撤销。确认你知道自己在删什么再启用这条规则。

当 分享率 小于 0.5 而且 做种时间 至少 2 天 时， 暂停种子

通知

出错或者做了有风险的操作时，弹一条系统通知提醒你。走的是系统自己的通知中心，不用装插件、也不用配微信邮件之类。

关掉之后，消息只出现在界面里，不会再弹系统通知。

达到哪个严重程度才提醒你。默认 WARNING，也就是日常信息不打扰，只有出问题才弹。

这段时间里不弹通知。可以跨午夜，比如 23:00-08:00。留空 = 全天都弹。

条

一小时内最多弹多少条，超出的直接丢掉。用来防止一次故障刷出几百条通知。

分钟

这段时间里内容相同的通知只弹第一条，避免同一件事反复轰炸。填 0 = 不做合并。

platform · 系统原生通知

目前只支持系统原生通知，Windows / macOS / Linux 都走系统自己的通知中心。
