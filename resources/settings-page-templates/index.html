设置页重构 · 四套模板

这次没有沿用旧版式 —— 四套模板的导航模型、字段排版、说明文字的落点都不一样，挑一套再动手改。 另外还有一套按「A 的视觉 + C 的布局 + D 的说明（改成就近浮窗）」拼出来的组合方案，列在最前面。 五套用的是同一份内容（连接 / 自动化 / 限速 / 站点 / 规则 / 通知 / 界面与日志）， 所以差异纯粹是版式与信息架构，横向比较才有意义。 顶部可以切主题：所有模板都走真实 WEB UI 的同一套颜色令牌，切主题时模板跟着变，不会出现「只在深色下好看」。

先说清楚现在的问题

诊断来自 src/auto_qb/web_ui 当前实现

「乱、硬、丑、描述不对」其实是四个不同的毛病，分别对应下面四块。新版把每一块都换了个解法，不是换个配色了事。

① 乱 · 三种折叠容器语义重叠

现在有 group / section / subcard 三种「可折叠块」，还有 pattern_list 的折叠列表，规则卡又有自己的折叠。用户看不出该点哪个。

② 硬 · 一律「标签 | 控件」两列

所有字段挤进同一套两列网格，说明文字只能塞在控件下面当小字。长说明写不下、短说明又显得干。

③ 丑 · 卡片与行的层级靠边框堆

普通分组是一张卡片，站点/规则/限速又各是一套完全不同的布局，同一页里四种视觉语言并存。

④ 描述 · 写的是实现，不是用途

「落盘轮转与格式」「图形界面的监听与鉴权」这类分组说明是技术视角；个别条目还写错了（见文末对照表）。

四套模板 + 一套组合

点「打开实页」在新标签里交互试用
A + C + D

仪表台 × 卡片总览 × 就近说明浮窗

按「A 的视觉 + C 的布局 + D 的说明」拼出来的那一套：切角与分段 LED 的仪表台观感、首页卡片总览与二级页、说明改成点「?」就近弹出的浮窗。

  • 视觉: 10px 切角 + hairline + 等宽读数 + 分段 LED（A）
  • 布局: 首页卡片网格 + 搜索 → 二级页 + 面包屑（C）
  • 说明: 行尾「?」点开就近浮窗，内容是 D 那五段（D 的内容，浮窗的形态）
  • 说明不再占常驻侧栏 → 二级页能铺满，也不会出现「右栏空着」
  • 控件: 全部方角、零圆角、无切角（切角在卡片/块这类大面上保留作 A 的签名）。发光走 box-shadow，由 --glow（聚焦态，三层：柔光环 + 亮芯 + 22px 余光，沿用 Ash Thorp 原值）与 --glow-soft（悬浮态）两个令牌统一提供，改一处全站生效。 应用范围：输入框/下拉框（聚焦）· 按钮（悬浮+聚焦）· 首页卡片（悬浮+聚焦）· 小标签 pill（悬浮+选中）· 「?」说明钮（悬浮+打开）· 开关（聚焦+开启态）。 按钮依旧不带橙色填充；开关取自 amd/04-fathom（方角 44×24 + 纯白滑块）。
  • 语义化语调：重要 / 危险的按钮与输入框用不同色的描边 + 发光， 由 --tone 驱动（描边与发光必然同色）。 三档：常规 --accent · 重要 --warn（影响面大但可逆：凭据、改了要重启、弱化安全边界） · 危险 --error（破坏性 / 不可逆：明文密码、对外暴露、删除）。 ⚠ 静息态描边也带语义色，不用聚焦就能看出轻重；聚焦时才变实色并发光。

qBittorrent 连接与主循环节奏让 auto-qb 连上你的 qBittorrent，并决定它多久检查一次「主循环」是实现词，用户不知道那是什么

关于 Ash Thorp

你点名最喜欢的一套

方案 A 里加了一个「皮肤 → Ash Thorp 原色」开关，切过去就是暖炭底 + 暖橙主光 + 10px 切角 + 分段 LED 那套观感的 1:1 落地版。 但要注意一件事：现在的 WEB UI 有 5 套主题，其中 2 套是亮色，如果直接把 Ash Thorp 的色值写死，亮色主题会立刻崩掉。

所以模板的做法是：版式用 Ash Thorp 的形式语言（切角、hairline、等宽读数、方向光），颜色仍然走主题令牌， 于是 5 套主题都能看。要不要把「暖炭 + 暖橙」真的做成第 6 套主题（css/themes/ash.css + theme.js 加一行）， 是个可以独立于版式选择的决定 —— 你先挑版式，主题的事之后单独定。
