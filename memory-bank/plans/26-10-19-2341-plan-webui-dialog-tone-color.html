WEBUI 弹窗语义配色分级(删除/跳检警示醒目化)

给通用弹窗引入 tone 三级语义分级与可选的警示条形态, 让「不可逆的删除」与「有代价的跳检」在视觉上一眼分开, 并解冻被一条全局规则抹平成灰的警示行图标 —— 不新增任何色值, 不动既有 DOM 结构与类名。

§01目标与设计原则

背景

删除确认框与跳检预检框不是两套模板, 而是同一个通用 .modal 单例(shared/tpl/popovers.html:114-198, 状态机在 shared/ui_feedback.js::_openModal)。两者全靠 JS 传参区分形态: 删除走 delete_flow.js::_confirmDelete(danger:true + icon:"#i-trash-x"), 跳检走 drawer.js::_skipCheckDialog(danger:true + icon:"#i-bolt" + okDisabled + busy + verdict)。

问题在于: 这个单例目前只有一个布尔维度(danger)可用于分流配色。语义等级完全不同的两个动作(一个不可逆、一个有代价但可恢复)落到同一支 CSS 分支上, 于是二者长得一模一样; 而真正承替代价说明的文本与行式明细, 又完全落在语义色体系之外。

做到什么程度算成

  1. 一眼分级 —— 不可逆删除 = error 红系; 有代价跳检 = warn 琥珀系。等级由标题区整体承载(图标 + 文字 + 底 + 左边框), 而非仅一枚 16px 图标。
  2. 警示会说话 —— 跳检固定警示区 4 行(drawer.js:327-330)、删除 HR 风险行(delete_flow.js:155-158)恢复语义色; 预检 verdict 的「禁止 / 需强制 / 前置条件全部满足」三态按各自等级染色, 不再共用同一个灰。
  3. 三套皮肤一致 —— atlas / console / prism(五主题)视觉等级等价; 两个亮色主题(frost / golden)下文字对比度可读。

验收判据: 三套 UI 下两个目标弹窗的标题区与警示行均带语义色; 其余 17 处 _openModal 调用点视觉零变化; commands run test.full 绿; commands run dev.e2e 的 W3 跳检确认链仍绿。

设计底线 / 不变量(违反即停)

  1. 不改 DOM 结构、不改既有类名 —— tests/test_webui_static_dom_panel.py:2977-2989 对确认钮整钮块、busy 行、verdict 区容器做整行硬锚定; e2e/menus.spec.mjs:257/267 依赖 .modal-title 文本与 .modal-actions .bt.danger-solid。
  2. 按钮一个字不动 —— .bt.danger-solid(确认钮与第三钮「强制跳检」)保持实心红。按钮表达「这个动作有后果」, 标题 tone 表达「这个框的整体语境等级」, 是两层语义, 不合并。
  3. 不新增色值 —— 一律取 --warn / --error / --green 及其 -soft / -line 三件套(conventions/webui.md:21-25 状态色族纪律)。
  4. _skipPrecheck 六态分支语句清单零增删 —— T24 守阵(test_skip_check_dialog_verdict_render)对每个分支做逐语句等值比对, 加一行就是红。任何 tone 派生必须落在这六个分支之外。
  5. 既有对话框零变化 —— 新增字段一律走「空串 / false = 不挂载」惯例(与 busy / verdict / cls 同口径)。
  6. 范围守恒 —— 只动两个目标弹窗 + 通用 tone 通道; 共用同一详情行范式的其它弹窗(限速 / 移动 / 重命名 / 分享率)一行不改。

§03方案总览

三层装饰模型

层载体作用域缺省
L1 框级 tonemodal.tone(error / warn)标题区图标 + 文字染色按 danger 派生(见下表), 既有调用点零变化
L2 可选警示条modal.strip(布尔)标题区加 -soft 底 + 3px 左边框 + 圆角false = 既有全部对话框外观零变化; 仅两目标框开启
L3 行级语义row.tone(ok / warn / error)行内 .ico + .d-label 染色, .d-value 保持中性空 = 沿用现有灰(--fg-dim)

为什么 L1 和 L2 要分成两个开关: 全仓库有 11 处 danger:true 对话框(config_editor.js 5 处、dialogs.js 2 处删除分类/标签、config_hub.js、drawer.js:871 删除 Tracker, 加上本方案两个目标框)。若让 tone 直接连带警示条, 等于把 9 个本轮范围外的弹窗一并改掉 —— 与底线 5、6 冲突。拆成两个开关后，染色对所有 danger 框一次性补齐且不新增 CSS 分支，而警示条只对显式开启的两个目标框生效 —— 两者解耦，互不牵连。

tone 派生表(_openModal 单点)

调用形态派生 tone与现状比
danger:true(未显式给 tone)error零变化(现状就是红)
danger:false(未显式给 tone)warn零变化(保现状琥珀)
显式 tone:"warn"warn新增能力 —— 跳检框用
显式 tone:"error"error新增能力 —— 删除框用

为什么非 danger 派生 warn 而不是 info: 现有非 danger 对话框的标题图标虽落到 #i-info(ui_feedback.js:121, 缺省 modal.danger ? '#i-warn' : '#i-info'), 但 CSS 默认色是 --warn 琥珀(components.css:550)。若派生为 info(蓝), 19 处调用点会集体变色 —— 违反底线 5。这个「info 图标配琥珀色」的历史不一致登记为 §07 R1 连带发现, 本轮不改。

CSS 参考实现(三套皮肤成对, 同一份文本)

/* ① 框级 tone: 只染色, 不动版式 —— 既有全部对话框外观零变化 */
.modal.tone-error .modal-title .ico,
.modal.tone-error .modal-title > span { color: var(--error); }
.modal.tone-warn  .modal-title .ico,
.modal.tone-warn  .modal-title > span { color: var(--warn); }

/* ② 警示条形态: 仅 strip:true 生效(本轮只有删除框 / 跳检框开启) */
.modal.strip .modal-title { padding: 8px 11px; border-radius: var(--radius-sm); }
.modal.strip.tone-error .modal-title { background: var(--error-soft); box-shadow: inset 3px 0 0 var(--error-line); }
.modal.strip.tone-warn  .modal-title { background: var(--warn-soft);  box-shadow: inset 3px 0 0 var(--warn-line); }

/* ③ 行级语义: 只染 ico + label; value 保持 --fg-soft 中性, 保长句可读性 */
.modal-detail-row.is-warn  > .ico, .modal-detail-row.is-warn  > .d-label { color: var(--warn); }
.modal-detail-row.is-error > .ico, .modal-detail-row.is-error > .d-label { color: var(--error); }
.modal-detail-row.is-ok    > .ico, .modal-detail-row.is-ok    > .d-label { color: var(--green); }
  • 用 box-shadow: inset 画左侧 3px 色条 —— 不占布局宽度, 不改变 .modal-title 的 flex 排列, 避开弹窗 overflow-y:auto 下负边距溢出的老问题。
  • 特异性: 现有 .modal.danger .modal-title .ico 是 0-3-0, 上述 .modal.tone-error .modal-title .ico 同为 0-3-0 且后加载 ⇒ 生效。保留旧规则不动, 供未走到派生通道的兜底。
  • prism 五主题无需新增令牌 —— --warn / --warn-soft / --warn-line / --error-* / --green* 在 ocean / galaxy / orbit / frost / golden 五份 themes 里均已声明(conventions/webui.md:64 双色令牌族纪律)。
