3.3 超额线: 做种 ≥ 3× 要求即免除在线对账21:25 用户定稿, 常量 SEED_EXEMPT_RATIO = 3

网站是绝对的权威

本地做种时间 ≥ 3 × required_seeding_time + extra_seeding_time(常量 3 倍)⇒ 放行, 且免除在线对账义务 — 取数侧不再为它翻页、下载、对账(§4.2 对象集排除)。但这条线不是判定上的免死金牌: 遇到网站「考察中」仍是「考察中」(管束) — 网站权威压过超额线。两者的分工: 超额线免除的是「主动核实成本」, 不推翻站点结论; 被动命中(它的行在已翻范围内被宽泛名称粗配认出为考察中 → 该行是 A 档必被无条件下载 → infohash 精配确认; 或恰已算出 infohash 直接精配)时, 站点档位照常生效 — 粗配误配由 A 档全下载的精配自愈。

这条线同时解决了覆盖早停的一个真问题: 特别老的种子可能藏在清单很深处, 若它们都在覆盖对象集里, 覆盖深度会被拉到全清单 — 而这些种子 3× 义务早已超额, 没必要管。排除后, 覆盖深度只由「未对账新种子 + 考察中种子 (含被动命中考察中的超额种子, 罕见)」决定。它也不依赖完成时间(只看本机 seeding_time 计数器, 恒可信) — 纯辅种做满 3× 同样出对象集, 完成时间不可信的残余场景进一步收窄。

  • 考察中不因「没看到」而静默丢失: 上波命中考察中的种子, 本波没在 A/B/C 中找到 ⇒ 一律当作无证据(22:38 定稿)→ 失踪观察期维持管束。观察期出口: 该种子完成时间位置被本波覆盖且未重见, 连续 MISSING_GRACE_WAVES=2 波 ⇒ 判「移出」放行; 任何波重见 ⇒ 按档位定论。streak 用种子自身位置的局部覆盖证明推进, 与整波校验解耦(防单条失踪死锁)。
  • 档位独立: 某档本波失败(网络/解析)只影响该档的新证据, 不污染其他档 — A 档成功 B 档失败时, A 档的命中/未列出判定全效, B 档对象维持原状态。

逐种子 verified_ttl 删除, 站点数据不再存任何「证据年龄」时间戳 — 状态 = 最后观测事实 + 上述存续规则。

§4

波次引擎

废除「档位 × 页数」双层循环与预算轮转, 重写为单一波次模型(hr/service.py 的 _do_fetch 整体重写)。 波的类型不是配置 — 它由索引与证据状态推导, 是波结束时的结果:

4.1 单一波型: 每波都以全量对账为目标26-09-28 20:27 用户定稿, 无波型之分

废除「增量波/全量波/续翻波」三波型与断点续翻 — 每波都从第 1 页开始、以覆盖全部对象为目标。 理由是清单是动的: 顶页新插入会把旧行往后顶, 波与波之间什么都可能变 — 任何「从断点继续」「凭上波已见过而跳过」都在赌上波的覆盖假设仍然成立, 赌输就是漏。 所以每波自证覆盖: 覆盖结论只来自本波抓到的页面, 不继承上波任何覆盖假设。

  • 触发: 取数线程每 poll_interval(常量 60s)醒来, 到期(refresh_interval)/Retry-After 期满 → 发波; 站点锁被占 → 让位(多实例语义不变)。
  • 翻页方式 — A/B/C 轮流: 三档清单各自独立分页, 每档从第 1 页起, 轮流推进(A1 → B1 → C1 → A2 → B2 → C2 → …)。某档覆盖完成(§4.2)即退出轮转, 剩余档继续。D 档(已免罪)不翻 — 命中 D 与「未列出」同为放行, D 档没有增量信息; 命中 D 的种子由覆盖判据按未列出放行, 结论一致。
  • 档位独立收波: 每档独立覆盖完成(停翻条件任一成立/翻到末页/异常截断)→ 该档数据有效(§3.4), 档内命中定论 + 覆盖范围内「未列出」签发(过 §5.3 语义防伪: 流转守恒 + 总量骤降 + 零行戳)+ 终态冻结出集(§4.4)。无「整波成败」概念 — 某档失败只影响该档, 其他档判定全效(22:48 定稿)。
  • 预算截断(max_pages_per_wave / 单轮等待上限 900s 常量) → 该档证据在截断点截止(截断点之前的数据仍然有效 — 命中照常, 未列出待下波续判), 下波从头再翻。无断点续翻(每波自证覆盖)。

4.2 覆盖早停: 三个停翻条件本波自证, 全部基于排序假设 · 21:17 定稿

对档位 X(A/B/C), 维护本波覆盖对象集 = 该站本地种子中的「未对账者」(新下载/锚点漂移回炉, 位置未知) ∪ 「考察中者」(行 1 管束中, 档位随时会变 — 转终态即出集合)。超额种子(≥3×, §3.3)不在对象集 — 免除在线对账义务, 不驱动覆盖深度、不为它翻页下载; 但已见行与它们做被动匹配(名称粗配或恰已算出的 infohash): 被动命中「考察中」→ 网站权威生效转管束(进考察中集合), 命中终态档 → 维持放行。 已终态/移出的放行种子也不是对象 — 终态不可逆(§3.2), 不再为它们翻一页、下一发。 判据的主体是本地种子 — 清单里不属于本地 qB 的行(别的客户端下载的/已删除的)不构成继续翻页的理由。 每抓完一页, 检查三个停翻条件, 任一成立即该档停翻(三者都要求该档排序单调校验通过, 都只用本波信息 — 与被否决的「整页全部是已见过的 tid」划清界限: 那个依赖上波索引状态, 而这三个条件每一个都能在本波内独立证明「更深处不可能有覆盖对象」):

  • 完成时间可信度分层(条件①的适用前提): 本机下载完成(downloaded ≥ size)或曾对账绑定过站点行(记住了站点侧 done_iso)的种子, 完成时间可信, 参与条件①; 纯辅种(本机无下载记录且从未对账)的 completion_on 与站点完成时刻无关联, 不可信 — 不参与①, 由②/③或翻到末页收尾(方向安全, 只费页数); 首次对账后即获得站点侧时间, 下波起恢复。可信度是演进量: 对账越多, 早停越准。
  • 对齐余量: 本地完成时刻与站点页面完成时间存在时差(时钟漂移/传输确认差), 比较时留常量余量; 余量内不能确定就继续翻 — 保守方向多花页数, 不会漏。
  • 节奏自证(用户口径的量化落点): 覆盖深度由「覆盖对象集最老的完成时间」单点决定 — 首波全部未超额种子未对账, 翻到最老对象位置或到期段(全量效果, 大站 20 页级); 此后种子陆续对账、转终态或做满 3× 出集, 对象集收缩到「未对账新种子 + 考察中种子」, 集中在完成时间较新的一侧(特别老的超额种子已被排除, 不会再拉深), 覆盖深度单调变浅, 稳态下一两页即停 — 「这波 20 页、下波 1 页」由此涌现, 不靠波型配置。
  • 空对象集的停翻语义: 对象集为空(全部终态/超额/已对账)时条件①视为已满足 — 无对象即无覆盖义务, 每档翻 1 页捕获可能的新增即停(轻量波)。顶页新插入若属本地种子, 它必然是新下载 → 未对账 → 对象集非空, 轻量波天然升级; 本地无感的新插入(他机下载)不构成翻页义务(§9 残余风险已列)。
  • 旧三早停的去向: 考核期到期早停②原样恢复(本表条件②); 本地覆盖早停③恢复为条件③(infohash 确认版, 严格版前提「无待回填」保留); 超龄早停①的概念被条件①吸收(超龄线 = 对象集最老完成时间, 无需 completed_age_limit 配置)。

4.3 波内流水(与现状的差异点)

STEP 1
取页 → 解析 → 校验

扩展通道取页、adapter 解析、表头/字段/排序校验 — 契约与现实现一致, 扩展零改动。表头缺失/行解析失败 → 失效点截断(之前有效); 排序失效 → 强制早停, 不能继续翻页(§3.4), 不判停站。

STEP 2
行处理(逐页增量落盘)

行 → 按 §4.5 规则取得身份(A 档无条件下载 / B·C·D 粗配触发下载 / 永久层已有档案直接用)→ infohash 精配与本波覆盖对象对账: 命中即按档位定论(考察中 → 管束 / B/C/D 终态 → 放行并出集合, §3 矩阵), 管束事实即刻生效; 旧的放行记录被命中考察中即撤销。

STEP 3
覆盖判据 / 预算

每档每页后查三个停翻条件(§4.2), 任一成立即退出该档轮转; 预算到顶 → 该档截断(截断点之前数据有效)。

STEP 4
波完成 → 全量重算

该档数据有效 → 覆盖范围内未列出者签发放行(过 §5.3 防伪)、命中者按档位落账、转终态者移出对象集(状态冻结)— 对象集每波收敛。

STEP 5
回填下载

.torrent 只为覆盖区间内缺 infohash 且不在永久层的行下载(§4.5, 每条受同一间隔约束), 删除「页面只在新轮/下载只在复用轮」的 split 特化分工与复用轮特判 — 数据有效期语义由证据健康(§3.4)接管。

4.4 对象集每波收敛, 终态冻结

v2 草案的「增量波捕获重现 → 撤销放行」依赖增量证据健康, 且放行续期要靠全量波 — 两套证据等级互相纠缠。 单波型下这个复杂度不存在: 覆盖对象集每波从「未对账 ∪ 考察中」现算, 命中即定论, 转终态即冻结出集; 放行记录一经签发不再需要续期(终态不可逆, §3.4)— 取数量随对象集收缩单调下降, 没有任何需要跨波维护的增量状态。

4.5 下载规则: 身份登记一次, 状态追踪靠 tid21:44 用户定稿修订

下载 .torrent 的唯一目的是给清单行登记身份: 页面行只有 tid + 截断名称, 没有 infohash — 首见时下载解析出 infohash 存入索引永久层, 此后该行的身份永久有效, 状态追踪不再需要下载: 每波翻页读到同一 tid 的新档位(A→B→C…)即更新索引、按判定表改判, 转变延迟 ≤ refresh_interval。生命周期示例: 10-01 完成的种子进 A 档(remain=30D)→ 首波下载对上本地 → 命中考察中管束; 做种到 remain=0 站点转 B → 下波同 tid 读到新档位 → 放行 + satisfied 出对象集; 判 C(终态)→ 放行; 行移出清单 → 未列出放行。

  • 同一 tid 永远只下载一次: 永久层(downloaded)算过即存档、永不重取 — 档位怎么变都不再产生下载; 跨波累计下载量趋近「A 档行 ∪ 覆盖区间内行 ∪ 粗配疑似本地的终态行」, 远小于清单总量。A 档下载量大时按日额跨波分摊, 未下完的下波续排(永久层去重)。
  • A 档(考察中)行无条件全部下载(用户 21:44 定稿): A 命中是唯一管束正证据, A 档行的身份完备性是硬规则 — 不依赖覆盖区间的推断(完成时间漂移/排序异常的残余风险全部消除), 不因「看起来不像本地种子」跳过。A 档行天然有限(考核期内的种子), 下载一次永久存档。
  • B/C/D 档(终态)行 — 覆盖区间 + 宽泛名称粗配(D1 已拍板, 21:53): 终态行仅当「名称粗配疑似本地」才下载。粗配走宽泛路线(用户定稿): 不是完整/前缀匹配, 本地名称与行名称存在足够长的连续重合段(阈值常量 K, 实施时按真实样张调, 建议 12~15 字符)即判疑似 — 宁可误配不漏配。漏配后果分析(全部方向安全, 无漏 HR): 已达标×B 漏配零后果(satisfied 本地已成立); 未达标×B 漏配丢达标标签; 未达标×C/D 漏配最坏误管束(保守), 直到被覆盖或补上 — 管束正证据只有 A 命中, 而 A 档行无条件全下载, 终态行漏配不可能漏 HR。粗配误配(把别人的行认成你的)= 多下载一次, 且 A 档行全下载规则下 infohash 精配必然校正 — 粗配永远只是疑似触发器, 定论一律 infohash 精配(未列出判定除外 — 它是「没看到」, 不需要 infohash)。
  • 覆盖区间外的行不下载(对 A 档的补充: 已见行中的 A 档行由上一条无条件覆盖; 未翻到的页不涉及)— 覆盖判据(§4.2)保证区间外没有覆盖对象。
  • 下载本身受同一套频控(min_interval 90S / 日额 / 单轮等待上限); 下载失败按 §3.4 截断处理(重试上限常量), 无独立退避。

  • 结构完好的波得到零行: 不签发未列出放行(改版空表即整站误放行, 不冒这个险), 全部种子落行 4 本地兜底(未达标管束) + WARNING(骤降校验在零行场景的特例)。
  • 人工对账: --hr-confirm-empty <站点>(CLI)与 WebUI 站点卡片按钮写入一次性确认戳(存站点数据, 非配置); 之后零行波可正常签发放行。
