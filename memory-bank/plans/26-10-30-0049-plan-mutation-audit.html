1.2 为什么先 rules

  • 对象优先级第 1 位 —— 可行性报告 §11 按「判据密度 × 出错代价」排: ① rules/ ② hr/ ③ config/ ④ core/。hr/config 已做完(hr 六轮全清、config 七轮全清), rules 是剩面里优先级最高的; 常驻锚 §07 里它挂「待做(优先级 1)」。
  • 实测分数全项目最低 —— 报告 §11: rules/ 与 infra/utils.py 覆盖率同为 98%, 变异杀死率却差 17 个点(55.5% vs 72.5%); 3,270 变异里存活 1,446 条, 从未做过三分类, 一个真洞 issue 都没有。判据多的地方, 测试最容易只写「跑通」不写「边界」。
  • 出错代价是真实种子上的错误动作 —— 规则引擎的输出直接作用于生产种子: 加标签/分类、暂停、跳检(黄金法则的保守默认对象, 错放 = 对未校验种子跳过哈希检查)、转移(MoveTo 路径)。recheck_fail 上限闸(RECHECK_FAIL_LIMIT)错一处, 边界种子反复 recheck 或漏处理。
  • 复合体, 边界最难写全 —— 条件判据(大小/状态/空闲/做种时间) + 表达式子语言(lexer/parser/eval/env 四层) + 动作副作用 + 注册表去重 + checking_meta 的在检竞态窗口。表达式求值层的运算符边界与求值顺序, 覆盖率给不出刻度。
  • 本轮的核心产出是一个刻度, 不是一次修复 —— 报告那次实测只是可行性调研的一次性观测(§1.2 报告自己的「数字可复现性边界」); 本轮跑正式审计轮, 首轮以实测为准, 真洞按主题入池。

§02现状与痛点

  • 覆盖率 98% 量不出强弱 —— 报告 §11 实测: rules/ 3,270 变异 / 杀 1,813 / 存活 1,446 / no tests 1 / 超时 10 → 杀死率 55.5%(7.48 mut/s · 墙时 7m31s · --max-children 4 · WSL 8 核 · 定向 6 文件池)。同一份代码覆盖率 98% —— 两条路都「跑到了」, 但近一半变异没人抓得住。
  • 那次实测是单次观测 —— 报告 §11 自己标注: rules 的 7m31s 与 55.5% 只测了一次, 变异执行本身确定, 但不能当正式基线; 正式审计轮以本轮实测为准。
  • 1,446 条存活从未分类 —— config 轮(七轮)与 hr 轮(首轮 + 七个模块轮)都已走完「三分类 → 真洞入池 → 补测 → 复跑」全流程; rules 是常驻锚 §07 里唯一「分数已知但零处置」的包。
  • 池宽/池窄的经验已有单点 —— 报告 §11: rules 同进度点 6 文件池 vs 全 tests 池杀死率只差 1 个点(52.4% vs 53.6%), 池宽的代价在内存不在结论; hr 首轮推论: 池覆盖整包时假存活≈0(抽验 24/24), mutants.verify 缩不了候选, 工作量在读 diff 判真洞 vs 等价 —— 本轮池(16 文件)属宽池, 直接按这个口径排人力。
  • 主仓代码自报告基线已演化 —— 报告实测时 rules/ 2,662 行 → 现在 2,731 行(§1.1); 变异数估算按现行行数外推, 首轮以实测为准。

§03方案总览

3.1 主线

一轮整包审计(S1–S8, 同 hr 形态): 首轮拿正式刻度 → mutants.report 导出带 diff 清单 → 三分类(宽池口径: 直接读 diff 判真洞 vs 等价) → 真洞按主题入池 → 按模块拆补测轮(后续计划或续轮, 不在本计划展开)。计划拍板后冻结, 执行时轮次进共享任务档案。

3.3 测算基数

口径依据变异数单轮时长
现行行数外推 2,731 行 × 1.2/行(报告 §08 实测 2,662 行 → 3,270 变异 = 1.23/行) ≈ 3,300 ≈ 40–80 min
  • 墙时不用报告的 7m31s 外推 —— 那是 6 文件池的单价锚(7.48 mut/s); 本轮池 16 文件 / 470 fn, 与 hr 池(15 文件 / 457 fn)同量级, hr 实测 ≈1.4 mut/s(≈0.7s/变异) → 3,300 变异 ≈ 40 min。按 skill 口径「每 1,000 变异 ≥12 min 并留 2x 余量」→ 排期按 40–80 min。mutants.run 的 timeout 已是 7200s(R15 抬过), 整包单轮在窗口内。
  • 本轮不做「剔除纯数据声明」的精化: config 首轮这么估后实测 +26%; 估算只用于排期, 首轮一律以实测为准并原样记进切片。
  • 变异数显著偏离的处置: 明显低于 ≈3,300 → 一批声明被排除属正常记一笔; 明显高于 ≈3,600 → 先核 glob(commands run mutants.status 看 only_mutate 是否多收文件)。

§04实施步骤

命令一律走 task id(命令本体与陷阱内建在 mutants 包里, 不手拼裸命令)。用法细节用 commands run show mutants.run 取。

S1 · 环境就绪 —— 建/刷新 WSL 镜像仓 + 依赖 + mutmut。幂等; commands run mutants.setup。门槛: 本机需 WSL。多 clone 并行时 --mirror '~/auto-qb-mut-rules' 各占一份 + --children 降到 3(硬约束 14)。
S2 · 首轮 —— 对 rules 包整包跑一轮, 池 = §3.2 的 16 个文件; 记下变异数 / 杀死率 / 耗时 / 工具版本 / 选择池 / no tests 计数。commands run mutants.run -- --target '**/rules/*.py' --pool tests/test_rule_base.py tests/test_rule_engine.py tests/test_rules_core.py tests/test_conditions.py tests/test_state_matrix.py tests/test_file_access.py tests/test_registry.py tests/test_actions.py tests/test_checking.py tests/test_ops.py tests/test_relocate_exec.py tests/test_expr_parse.py tests/test_expr_eval.py tests/test_mixins_tags.py tests/test_trigger_events.py tests/test_hr.py。入场条件(硬): 基线全绿 —— 先 commands run test.quick, 不绿先修别跑变异。存活清单落盘, 终端只回显头部, 读全文按需 grep 别整读。
S3 · 导出 + 三分类 —— commands run mutants.report -- --target '**/rules/*.py' 拿带 diff 的清单与按状态/按模块汇总; 逐条判「真洞 / 等价变异 / 假存活」。宽池推论(hr 首轮实测): 池覆盖整包 ⇒ 假存活≈0, 别指望 mutants.verify 缩小候选, 工作量直接落在读 diff。rules 域高频等价形态预警: 短路求值中无副作用的右支、离散状态枚举上的 <=/<、re-export 别名、异常文案; 高频真洞形态: 条件边界(早一行/晚一行)、RECHECK_FAIL_LIMIT 计数增减时机、INFLIGHT_TTL 比较方向、求值短路顺序、env 白名单漏项、MoveTo 路径拼接。
S4 · 手工确认 —— 候选多时先按「判据密度 × 出错代价」与变异形态(边界/continue-break/and-or/语句删除)收窄再 commands run mutants.verify -- --from-report <清单> [--only-status survived](全套件 apply → 跑 → 还原, ≈15s/条); 宽池下它只做确认不做筛选。判据: 红 = 假存活(池没选到); 不红且行为错 = 真缺口。候选只有形态没 id 时走硬约束 13 形态级手搓复验(不进存活计数)。
S5 · 补测 —— 只对确认的真洞加断言: 改 tests/ + 同步文件头 docstring「## 测试计划」, 补完 commands run test.full; 守阵必须红验(同构变异 → 目标用例红 → 还原复绿, 源码零残留)。真洞指向代码缺陷时不顺手改 —— 按范围守恒入池 memory-bank/issues/。
S6 · 复跑 —— 同目标同池再跑一轮看存活数下降; 带新守阵时先 cp 测试进镜像再 --no-refresh(硬约束 11, 否则 git checkout -f 把未提交守阵冲掉)。
S7 · 记录 —— 基线切片 memory-bank/testing/baselines/YY-MM-DD-HHMM-mutants-rules.md(必填字段见 skill 记录口径; 切片自带 **Refs: 行); 任务档案追加一行轮次(轮次号先 git fetch 看远端, 并行会话撞号时后到者重编号); 真洞各自入池, issue 填 doc-refs。
S8 · 更新常驻锚 —— 改 issue 26-10-08-0642-test-mutation-audit-standing §07 覆盖进度总表的 rules/ 行: 日期 / 变异数 / 杀死率 / 轮次 / 状态(待做 → 已做(余量在池) 或 已做(已清)) / 切片链接; §08 台账补行。
