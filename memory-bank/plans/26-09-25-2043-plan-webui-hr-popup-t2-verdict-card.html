模板 T2 · 结论卡

结论先行的一秒判断卡: 顶部档位色结论带直接回答「能不能删」, hero 区只放一个最关键的量, 其余明细降级为两列小字渐进披露 —— 服务只想扫一眼就做删除决定的场景。

  • 结论带置顶: 档位词 + 结论短语压成一条档位色横带, 先判断后证据; 不像 T1 档案卡那样按「结论/依据/站点侧值/本地值」逐区平铺完整规格。
  • hero 单一焦点: 只保留一个最关键量(还需做种大号 mono / 已达标 check 徽记 / 白话短语), 其余数值全部降权成小字; T3 进度仪表则是把时间账目逐段铺开、以过程感取胜。
  • 窄卡单列纵读: 卡身收窄 ~280px, 信息不删但强分层 —— 本地/站点两列 kv 小字、依据与「站点值滞后」角注垫底, 扫读路径一条直线到底。

实现说明

  1. 触发面与延迟: 触发面 = 做种时长单元格(.m-dur)整体或行内来源徽标(.hr-src); mouseenter 120ms 后显示, mouseleave 160ms 后隐藏, 移入弹窗保持显示(可选中复制); ESC / 页面滚动即关; 无 hr_safety 的行(R8)不触发。
  2. 定位: position: fixed 锚定触发矩形; 优先上方(间距 10px), 上方空间不足翻下方; 横向夹取视口(8px 边距); 弹窗带指向箭头, 方向随翻转换边, 水平对准触发中心并夹在卡内。
  3. 字段映射: 结论←hr_safety_text, 色←hr_safety, 徽标←hr_safety_src, 依据←hr_reason; 站点侧值←hr_site_need / hr_site_remain / hr_site_ratio / hr_site_dl(与详情抽屉 hrSiteLine 同源); 本地←seeding_time / hr_req_time / ratio / hr_req_ratio; 旧 :title="hrDurTitle(m)" 移除。
  4. 落点: shared/hr.js 单点渲染方法 + 6 处模板绑定(两 UI × 组内成员/种子页/明细三语境) + 两套 CSS 同值规则; z-index 140, 高于 ctx-menu 100 与 speed-pop 131。
  5. 本方向(T2 结论卡)实现要点: 结论带 = 档位柔底(--hr-pending-soft / --error-soft / --green-soft / 中性 --surface-2 同族; 未达标为独立红档 hp-s-failed, 与考察中橙分色 —— 2026-09-25 用户修正)+ 档位色 600 字重档位词, 右侧并排生命周期 chip(考核中/已结束)与来源徽标; hero 只取一个已有字段(站点 need → 大号数字 / safe 已达标 → check 线性徽记 / 策略与未核 → 白话短语, 禁止现场做减法); failed 桶名「考核未通过」(终态已成立, 不叫不能删 —— 2026-09-25 用户修正), 移出删除点名集合; 生命周期(2026-09-25 语义修正): 已达标/未达标/免罪均为考核期已过的终态, 标「已结束」, 不再显示还需/剩余倒计时(R3 hero 改白话「考核期已过，结果未达标」); 仅考察中标「考核中」并显示还需做种大数。映射 ← hr_safety_src: site_scope=考核中; site_satisfied / site_unsatisfied / site_released / local_exempt=已结束; policy / local / unverified 不标。本地/站点 kv 两列降权, 无站点值收成单列; 常显样张与交互弹窗同一 render 函数出 markup, mockup 与将来 Vue 组件同构。
