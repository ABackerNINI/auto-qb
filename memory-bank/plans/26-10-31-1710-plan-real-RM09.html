08给执行代理的风险点

  1. 回执依赖主循环命令线: 产品必须完整主程序非 dry-run(--dry-run 不启 WEB, §2.7; 命令消费在 module.py:131 命令线钩子)。回执用 _wait 轮询 /api/cmd/{cmd_id}(system.py:42), 别 sleep 死等也别假设同步返回——POST 的 200 只代表「入了队」。
  2. 删除是不可逆写: RM09-02 只对 real-fake 标签的自造种子发 delete; 目标 hash 必须来自用例自己 add 的回执, 绝不从实例种子清单里挑(pause-all 前置下真实种子全 stoppedUP, 名字像也不行); delete_files=false 的语义断言(数据还在)是防"真删用户数据"语义破的关键红验, 别删。
  3. reannounce 三态的时序坑: 「已受理: 推迟至」依赖首次 reannounce 建立的 min 间隔基线——三态子步骤顺序别乱(先活跃失败, 再窗内推迟); 确认跟踪到 deadline(REANNOUNCE_CONFIRM_TIMEOUT=30s)才写终态回执, 「未确认」是设计态不是 FAIL; 死端口 announce 用 http://<本机局域网IP>:1/announce(别用假域名走 DNS 出外网, §2.9)。
  4. qB 5.2 状态枚举: 暂停=stoppedUP(不是 pausedUP), 端点语义经 /torrents/stop-start(§2.5); 删除后 qB info 消失可能慢一拍, 轮询再断言; 多标签「, 」连接口径(RM05 坑)在本片标签类命令若涉及, 记得 strip。
  5. 移动的三个前置: 目标目录预建(GATE_SPACE fail-closed, §2.9); 落点只认 tests-real/.work/ 与 R:/qbt-fake/; 单成员组恒 FORM_DIRECT——断言 save_path 与文件真搬, 别断言别名/journal(那支只有重启补发路径到得了)。
  6. 组命令需要真归组: RM09-06 的假种子必须带 announce 且测试配置 trackers 有 domains 条目(§2.9), 等归组视图出现成员再发命令; 组 key 传参按端点的 URL 编码态口径(_group_key_param, torrent_cmds.py bulk 段注释)。
  7. PUT /api/config 写的是运行配置: 测试配置在临时 data_dir(非红线 config.yml); 改键选非 R 级(interval 类), R 级段(data_dir/state_file/fs)提交即回退+restart_required(RM02-04 口径)——想验 R 级回退去引用 RM02-04, 别在本片重测。
  8. keys 还原纪律: RM09-08 写前快照、写后还原、还原后字节比对——keys 是鉴权面, 残留脏键可能影响同会话后续用例的端点鉴权。
  9. 转移端点只测负向: 正向 transfer_run 会真把种子搬去 target 下载器——未授权配第二下载器前别碰; test 端点断言「零写副作用」。
  10. 并行陷阱重申: 直跑 pytest 会 -n 8 抢端口——沿用 rm01 conftest 文件锁先例或走 real.suite(§2.8)。Windows 收尾停产品走 lib/app.py(taskkill /F /T 口径, §2.7), 别手工发信号。
