§1背景与目标

用户诉求：HR 在线核实的结论要在 WEB UI 上有体现，让人一眼分清哪些种子可以安全删除、哪些不能；并且每个结论要明确展示它来自哪个优先级（v3.0 口径：在线考察中 > 在线已达标 > 在线未达标 > 本地）。

数据面已经齐了：后端 _hr_view_fields（src/auto_qb/webui/views.py:180）早已把站点核实四态（hr_state：受管束 / 安全放行 / 未核实 / 超龄豁免）、站点档位（hr_site_lane A/B/C/D）、依据（hr_reason）与站点侧值全部算好，并经 _member_view / _seed_view 透传到种子页、明细、搜索的每一条记录。缺口全在呈现层。本计划不新造判定——展示字段全部从既有 check_hr_condition / check_hr_satisfied / hr_judgement() 派生，与打标流程同源，徽章与标签芯片天然不会互相矛盾。

§2现状盘点（差距在哪）

位置现状差距
做种时长列（种子页 / 明细 / 组内成员，两套 UI 共 6 处）已挂本地 HR 配色（hrTimeClass 的 pending/reached）与「已做种 / 要求」后缀，在承担 HR 展示职责站点核实态（四态 + 档位）完全不可见；配色只有本地口径
HR 筛选器只有「达标 / 未达标」两档（本地口径）没有安全放行、未核实、超龄豁免档；没有来源维度
删除确认框完全不提 HR最危险的一步反而是盲的，需要风险点名
详情抽屉已有两行：三态·依据（hrStateLine，来源是「站点/本地兜底」二值）与站点侧值对照（hrSiteLine）要点开才看得到；来源口径粗于 v3.0 的四档优先级链
辅种组表 / 追剧表 H&R 列组级计数（未达标 N / 共 M）组级够用，本计划不动

§3核心设计：安全档位 × 来源档位（后端单点）

_hr_view_fields 新增三个展示字段，判定与来源在前后端各说一遍的坑直接堵死（前端只做 token → 徽标文字映射，不重算）：

  • hr_safety — 删除安全档位：danger（考察中·橙）/ failed（未达标终态·红，2026-09-25 用户修正）/ safe / unknown / none；
  • hr_safety_text — 含来源的完整人话短语（全 UI 唯一口径，如「在线·考察中，义务未了」「本地·兜底，已达标」）；
  • hr_safety_src — 来源档位 token（下表）。

安全档位（颜色语义）

档位判定（后端单点，不新造）颜色含义
不能删·考察中站点 A 档命中（考察中）；以及策略受管束（mode=all / unknown_policy=hr / 新鲜度闸门的未核实）复用既有 pending 橙考核进行中，删除可能吃 H&R
考核未通过站点 C 档命中（考核期已过仍未达标，终态）独立红档 hr-fail（--error 族）考核结果已成立的终态 —— 2026-09-25 用户修正：删除无新增惩罚，不叫「不能删」、不进删除点名；独立醒目红，不与考察中混橙、不能是绿
可删已达标（站点 B 档或本地够线）；或站点安全放行（verified_non_hr）；或超龄豁免（exempt）复用既有 reached 青义务已了或从未有
未核实state=unknown 且未被按受管束管束（宽松 policy 才出现）中性 dim站点还没查到它
不适用站点未配 HR / 从未触发无色（—）无约束

配色站点结论优先于本地：站点说已达标但本地做种时长没够线 ⇒ 也显示 reached（v3.0「档位即结论」）；反之站点考察中 ⇒ 恒 pending。未接入站点的行回落现有 hrTimeClass 本地配色，行为与今天逐字一致。

来源档位（对齐 v3.0 优先级链）

hr_safety_src产生条件安全档位单元格徽标
site_scope 在线·考察中站点清单命中，档位 A不能删在线
site_satisfied 在线·已达标站点清单命中，档位 B可删在线
site_unsatisfied 在线·未达标站点清单命中，档位 C不能删（failed 红）在线
site_released 在线·已核实完整核实且不在清单（安全放行）可删在线

抽屉现有二值字段 hr_satisfied_src（「站点/本地兜底」）退役，hrStateLine 改读 hr_safety_text + hr_safety_src——避免两套来源字段各说各话。

§4呈现设计：做种时长单元格的三层信息

单元格里状态与来源分层展示、都不藏：

  • 颜色 = 能不能删（橙 / 青 / 灰 / 无色）——扫颜色知生死；
  • 来源徽标 = 2 字小芯片「在线 / 本地 / 策略 / 未核」，跟在时长与「/ 要求」后缀旁——不悬停也能看出结论是站点给的还是本地兜的；
  • 悬停 title = hr_safety_text 全短语 + hr_reason 依据原文 + 站点侧对照值（与 hrSiteLine 同源）。

其余出口同步吃这套字段：详情抽屉三态行改读新档位来源；删除确认点名带来源；筛选器按安全档位 + 来源副档；选中统计给「不能删」计数。cellSeedingTime、「/ 要求」后缀、列显隐偏好全部不动。

§5分阶段实施（P1–P4）

P1做种时长单元格升级（核心诉求）
  • 后端：views.py::_hr_view_fields 加 hr_safety / hr_safety_text / hr_safety_src（种子页/明细/搜索已全走这条通道，零额外接线）。
  • 前端：shared/hr.js 加 hrDurClass(m) 单点方法（有站点态按四档配色、无站点态回落现 hrTimeClass 逻辑）与 hrSrcBadge(m) 徽标文字；6 处模板绑定（atlas/index.html:476/584/764 与 prism/index.html:502/610/790）换绑 + 补 :title 与徽标节点。
  • CSS：两套 UI 各加徽标样式（复用既有 pending/reached 语义令牌，不新造色族）。
  • 守阵：四档派生 + 来源映射正反测试；前端字段一致性守阵（模板新引用字段断言在后端键集）。
P2删除链点名（安全闸门）
  • shared/delete_flow.js::_deleteFlow 单点改一处：目标含「不能删」种子时，确认框点名「所选 N 个中有 M 个仍在 HR 管束（在线·考察中），删除可能导致站点 H&R 惩罚」+ 列出前几个名字 + 危险样式按钮。
  • 四个删除入口（组 / 种子 / 剧集 / 批量）同构收口于此，自动生效。
P3筛选器扩档
  • shared/hr.js::hrOptions 两档 → 四档（不能删 / 可删 / 未核实 / 不适用），谓词消费 hr_safety；组级 = 组内成员命中，走 facetRows 既有单点。
  • 加来源副筛选（在线核实 / 本地兜底 / 策略）——「只看本地兜底的行」正是最需要等在线核实结果的一批种子。
P4选中统计
  • 批量选中时状态栏提示「已选 N 个，其中 M 个不能删」；计数从删除流同一目标集合派生，不按视图阵列另算（跨视图裁剪陷阱）。

§6约束与守阵

  • 前端只着色不重算：判定与来源全部后端单点（pitfalls/web-ui/contract-api「取数单点放后端」）；HR 标签着色靠文本逐字相等的既有纪律照旧。
  • 两套 UI 成对改：6 处模板 + 两套 CSS 同值；改完加静态计数断言（pitfalls/web-ui/template-render）。
  • Vue 语义：hrDurClass 等带参方法放 methods（不在 computed）；新名在三处 grep 查重；模板内不用下划线前缀标识符。
  • 跨视图聚合：筛选选项走 facetRows 单点；选中统计从删除流目标集合派生——不依赖按视图裁剪的阵列（contract-api「已第三次」条）。
  • 前端字段一致性守阵：模板新引用的 hr_safety* 字段断言在后端键集里，hr_safety_src 的档位映射 token 打错即红。
  • 浏览器冒烟：前端表达式错误只有浏览器能发现——两套 UI 各跑一遍做种时长列三个语境（组内成员 / 种子页 / 明细）。

§7决策记录

#决策理由
D1不新增 HR 列，复用「做种时长」列承载安全档位与来源用户纠正（2026-09-25）：种子页与明细表的做种时长列已在担任 HR 展示职责（本地达标配色 + 要求后缀）；再加一列是重复信息且挤压行宽
D2结论必须带来源档位（hr_safety_src 八 token）用户指令（2026-09-25）：v3.0「档位即结论」之后，界面上每个结论都要能看出它来自优先级链哪一档；二值「站点/本地」粒度不够
D3颜色只编码「能不能删」，来源用文字徽标编码避免把颜色语义乘出 4×8 组合；色盲与多色混乱风险都压在文字上兜底
D4不新造色族，安全配色复用既有 pending/reached 令牌，未核实用中性 dim两套 UI 令牌同值纪律的维护成本最低；未核实态低频（仅宽松 policy），不值得一个新色族
D5种子页做种时长列默认隐藏的现状不动列显隐偏好本就存浏览器，用户已按需开启；改默认值反而打扰既有用户
D6未达标（C 档）独立红色档：hr_safety 新增 failed token（--error 族），与考察中的 pending 橙分色，也绝不是可删绿；桶名「考核未通过」，不在「不能删」集合 —— 终态已成立，删除无新增惩罚，删除确认不点名、批量统计不计（2026-09-25 二次修正）；界面不出现 A/B/C 档描述、「义务未了」措辞撤除用户修正（2026-09-25）：已达标 / 未达标 / 已免罪都是考核期已过的终态，只有考察中是进行中 —— 终态未达标要有自己的醒目颜色；「不能删」与 A/B/C 档描述都不符合界面实际需要
