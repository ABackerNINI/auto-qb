各写死点的引入时间与生效考证(git log -S): ① config.toml R:/ 前缀 —— 2026-09-23 引入, 2026-09-28(4ba6cb7f)重写保留; 本机 R: 不存在, 全程静默回落; ② pkg_scoped.py 的 R:\Temp\auto-qb\tests —— 2026-11-01(0024c5ce)引入, 当日起必走自带 [WARN] 沿用环境默认 分支; ③ mutants.py 的 R:/ 三处 —— 2026-10-08(637be05f)引入, 本机未跑过 mutants, 无生效记录; ④ tests-real/conftest.py:59 的 H: 注释 —— 引用同系列假设, 同无效。 仓库首个提交为 2026-08-24, 历史约 10 周——任何「多年/三年」的说法均无出处, 本文一律以提交时间戳为准。

02

设计

02.1探测顺序与判定(单一配置点)

bootstrap_tmpdir():          # tests/conftest.py 模块级调用, 早于 basetemp 实体化
  0. TMPDIR 已在 BOOTSTRAP_MARK 之下 → 复用(xdist worker/嵌套调用幂等口)
  1. 按 TMP_ROOT_CANDIDATES 顺序探测, 首个可写者胜:
     ("R:\\", "Temp") → ("H:\\", "Temp") → (系统 %TEMP%, "")
  实例根 = <选定根>/auto-qb-tests/<repo路径hash8>-<pid>-<rand6>, mkdir 原子
  设 TMPDIR 指向实例根; tempfile.tempdir 缓存清 None
  断言 gettempdir() 在新根下, 否则立即 raise(禁止静默降级)

判定「可用」= 目录可创建+可写测试文件(对齐 gettempdir 自己的判据), 不猜盘类型。

盘符优先级单一配置点: 候选表 TMP_ROOT_CANDIDATES 定义为 bootstrap 模块顶部常量 (唯一一份, tests/_tmp_bootstrap.py; conftest 只做模块级调用, 不复制顺序)。 新环境扩展/增删候选只改这一个常量。防散落措施: ① 常量带注释「全局唯一, 引用者 import 不得复制字面量」; ② 归档进 tests/test_tmp_bootstrap.py 的回归用例——断言仓库内不出现第二处 Temp/auto-qb-tests 或盘符列表字面量(grep 型守卫, 与 check_command_drift 同思路)。

02.2失败与回落

  • R:/H: 不存在 → 走下一级, 这是正常分支不是失败(B 环境常态走 %TEMP%, 已拍板接受)。
  • 选定根 mkdir 失败 / 最终断言不符 → 直接 raise, 输出选定根与每级判定结果。不允许带病跑。

02.2b强硬约束: 外部 TMPDIR 一律拒收(刻意堵死, 非可配置项)

测试进程启动时, bootstrap 先做来源判定, 再谈探测:

  • 合法(自举值): TMPDIR 指向 <候选根>/auto-qb-tests/<hash>-<pid>-<rand> 之下 ——即 BOOTSTRAP_MARK = "auto-qb-tests" 段必须出现在路径中(判定前统一 normcase(realpath()), 防 8.3 短名/大小写/\\?\ 前缀变体)。→ 复用, 幂等。
  • 非法(外部值): TMPDIR 存在但不含该标记(如 shell 环境注入的 H:\Temp、用户手设的任何值) → 响亮报错退出, 不静默采用、不帮忙兜底。报错形如: 
    [FATAL] 外部 TMPDIR 拒收: 'H:\Temp'(进程 pid)。
测试 TMPDIR 由 tests/_tmp_bootstrap.py 自举探测(R→H→%TEMP%), 不接受外部设置。
正确做法: 清掉环境变量后重跑(set TMPDIR= 或新 shell); 要换根, 改 TMP_ROOT_CANDIDATES 单一配置点。
    退出码 rc=4(与锁的 rc=3 区分)。这是刻意的堵死, 不提供 AQ_TMP_ROOT 之类的绕过口—— 旧配置失效却无人察觉正是"允许外部兜底"造成的。

子进程继承模型: 自举只写 os.environ["TMPDIR"](不清 TEMP/TMP——它们留在系统默认, 而 Python 端消费方全走 gettempdir(), TMPDIR 优先级最高)。继承方式分两路: ① env 继承(xdist worker、任何 subprocess 默认 env=None 的子进程)——拿到自举值, 子进程内 bootstrap 走合法幂等口, 不重新探测; ② 仅进程内(若只设 tempfile.tempdir)——不传播, 子进程丢失。 因此必须走 env 继承这一路。消费方对账: pytest basetemp/tmp_path/TemporaryDirectory 全走 gettempdir()(吃 TMPDIR); e2e/harness 子进程若直接读 os.environ["TMPDIR"] 也拿到同一值; 两边一致。

既有用法新约束下是否成立
xdist worker(execnet 克隆父 env)成立 ✓ 继承自举值, 幂等口复用同一实例根
嵌套 pytest(测试内再起 pytest)成立 ✓ 默认继承 env, 幂等口; 显式清 env 者按外部拒收报错(合理——嵌套跑本来就该同根)
e2e/harness 子进程成立 ✓ 继承父 env; harness 自身也走同一 bootstrap 时幂等
mutants.py 子进程成立 ✓ 本轮纳入改造: 其 env["TMPDIR"]=R:/... 删除, 改继承(届时父进程已自举)
agent/用户 shell 预设 TMPDIR 后跑测试拒收 rc=4 报错退出, 文案指引清变量; 这是设计目标本身

02.3实例唯一根与 mkdir 抢占

  • 目录名内嵌 pid + rand6, mkdir 已存在即重摇(NTFS mkdir 原子)。
  • xdist worker 克隆父进程环境 → 继承同一 TMPDIR → 同一次运行共根(正确语义); 跨运行根互异。
  • pytest-current 软链在 basetemp 父目录 → 实例化后互不覆盖 ✓。

02.4残留清扫(双条件)

pytest「只留最近 3 个」按父目录算, 实例化后失效, 必须自举清扫: bootstrap 时扫 <选定根>/*, 删除条件 = mtime 超阈值(默认 12h, 待拍板) AND 目录名内嵌 pid 已死, 双条件缺一不可; 只整删实例根不进子树; 新建目录 mtime=当前时刻, 天然免疫。

02.5互斥锁(测试进程自举)

面设计
位置<系统TEMP>/auto-qb-locks/<repo路径hash8> —— 固定系统 temp(不随实例根走, 否则锁被切碎), 不进仓库(不脏 git status)
获取conftest 内 mkdir 原子; 锁内容写 pid + 进程CreateTime + repo路径 + 可读启动时刻
僵尸判定pid 存活 AND CreateTime 一致(防 PID 复用); 被 taskkill /F(常态操作, 已实证)后由下一位获取者自愈回收
失败策略失败即退(rc=3, 打印持锁者 pid/启动时间/已运行时长), 不等待——agent 场景等待会被绕开, 等待比失败更危险
粒度宁重勿轻: argv 判定预计收集根——含 tests 目录且无 -k → 写重型取排他锁; 带 -k/具体文件/-n 0 --no-cov → 排查型放行。误判只许偏重不许偏轻; 逃生口 AQ_TEST_LOCK=off|force
释放pytest_sessionfinish + atexit 双挂
