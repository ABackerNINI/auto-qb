3.3 引擎设计要点 (调研提炼)

  • 规范化序列化: 修饰键固定序 Ctrl→Shift→Alt→Meta (VS Code 展示序; tinykeys 归一序同族), 存「修饰键集合 + 主键」而非自由字符串, 比较时集合无序比对。
  • event.key vs event.code (MDN): key 是布局相关字符 —— "Shift+2 在 US 键盘是 @, UK 键盘是 \""; code 是物理键 —— "KeyQ 在 Dvorak 上是 ', AZERTY 上是 A"。实践口径: 字符语义快捷键用 key, 要求物理位置稳定用 code。本案: 主匹配 e.code (位置语义, 录制/重绑稳定), 显示名由 code 映射人类键名; 布局差异的极端情况由「用户可重绑」兜底。
  • 作用域系统: VS Code 的 when 子句 / JupyterLab 的必填 selector 都是「上下文圈定」—— 本案用五值枚举 scope ∈ global/list/drawer/settings/modal + 优先级即可, 不需要表达式引擎。
  • ? 帮助浮层是标配: Gmail / GitHub / Trello / YouTube / Slack / JupyterLab 全都有。本案 ? 开快捷键面板, 与搜索框内的「?」幽灵按钮 (点击, 非按键) 无冲突。
  • 输入抑制双保险: 输入元素过滤 (INPUT/TEXTAREA/select/contenteditable) + isComposing 守卫; 中文输入法组合期间 keyCode 恒为 229 是浏览器实证行为 (hotkeys-js 源码有此守卫, MDN 未明文记载)。
  • Mac 归一: Mousetrap 的 mod / tinykeys 的 $mod / @github/hotkey 的 "Mod localizes to Meta on mac, Control on Windows or Linux" —— 默认键表如涉 Ctrl 组合, 定义层留 mod 语义槽位即可 (本案用户环境以 Windows 为主, MVP 可不做平台分支, 见 §08-⑥)。
  • 浏览器保留键边界: Firefox 明确忽略页面对核心组合的 preventDefault (Mozilla bug 1052569); Chromium 区分 reserved accelerators (Ctrl+W 类) 与页面可处理项 (Ctrl+F 类); 唯一合法强捕通道 navigator.keyboard.lock() 仅限安全上下文+全屏场景。经验边界: Ctrl+S/F/P 可拦, Ctrl+W/T/N/Q 及其 Shift 变体不可拦 —— 黑名单以此为准。
  • 录制器 UX: VS Code "Define Keybinding" (⌘K ⌘K) = 按下即录制的只读输入框 + 人类可读键名 + Enter 落键; 叠加实践共识: 纯修饰键单击拒收、冲突警告、Esc 取消。

3.4 坑清单 (调研 + 上游实证)

坑判据与对策
IME / CJK 组合输入组合期间 keydown 照发且 isComposing=true、keyCode 恒 229 —— 匹配器第一步就拦 repeat || isComposing, 双保险 (三段屏蔽之一)。
非 US 布局漂移key 值随布局与 Shift 实时变; 用 e.code 规避, 显示名靠 code→键名映射; VS Code 在 Linux 上也要重启才能刷新布局缓存 —— 布局问题没有银弹, 可重绑是兜底。
长按自动重复字符键 keydown 以 repeat=true 重复 —— 录制器与序列型绑定一律忽略 repeat。
纯修饰键修饰键自身发 keydown —— 匹配器等非修饰键落定才判定; 录制器把「只按了 Shift」判无效。
preventDefault 与 passivepassive 默认仅限 wheel/touch 系挂在 window/document/body 上 —— keydown 不在其列, preventDefault 正常可用; 多 handler 礼仪: 先查 event.defaultPrevented。
keyCode 已废弃MDN 明示 avoid —— 新实现一律 key/code, 这也是排除 keyCode 系库的根因之一。

上游 WebUI (develop client.js) 现有: Ctrl/Cmd+A 全选、Delete 删除所选 (Shift+Delete 永久删)、Esc 关弹窗、Ctrl/Cmd+F 聚焦过滤框, 均带输入框守卫; 无自定义机制、无 ? 浮层。自定义快捷键的 feature request (#11930 / #10084) 在上游多年 open —— 本项目做此功能属先行, 无上游兼容包袱; 但默认键位应与上游习惯兼容 (全选/删除/聚焦搜索语义对齐), 降低肌肉记忆迁移成本。

04

存储定案: 后端独立文件 vs localStorage

4.1 候选盘点 (先排除两个伪候选)

候选裁定理由
写进 config.yml排除生产红线文件 (真实 PT 域名/凭据引用, AI 不动); 且 UI 偏好不是程序配置 —— 会污染 validate_config / schema / 热重载语义, 用户还可能手工编辑它。
并进 state.json排除黄金法则 5: 主循环单线程是 state_file 唯一写者。快捷键保存在 web 线程发生 (PUT 请求), 走 state.json 就必须引跨线程写通道, 破坏单一写线程假设。
后端独立文件 auto-qb-data/webui-keys.json候选 Aweb 线程独占写, 与 state.json 互不干扰; web.token 已是「非 state 小文件」先例。
前端 localStorage autoqb.ui.keys候选 B与列偏好/主题同范式, 零后端改动。
混合: 后端真值 + localStorage 镜像候选 C (缓议)收益仅「跨标签活同步」; 见 4.5, MVP 不做, 保留后路。

4.3 定案

定案建议 · 待用户确认

后端独立文件 auto-qb-data/webui-keys.json, 前端经 GET/PUT /api/keys 读写。前案 0822 预选 localStorage 的论据是「服务端持久化 = 写 config.yml 红线」—— 这是假二分: 独立文件既不碰 config.yml 也不碰 state.json, 两个排除理由都不成立。而 localStorage 方案的三个真实代价 (每浏览器分叉 / 清站点数据即丢且已在本项目发生过 / 不进备份) 对「用户录制的配置」类信息是错档; 它唯一的实质优势 (零后端) 换算过来只有约 200 行含测试的代码。

localStorage 的正当性边界也说清楚: 列宽 / 主题 / 时间口径继续留在 localStorage 是对的 —— 那些是低成本可重派生的派生偏好。本定案不迁移它们, 只是为「信息价值更高」的快捷键选对档位; 两范式并存且各安其位, 不是破坏一致性而是补全分层。

4.4 文件与接口规格

  • 路径: <state_file 同目录>/webui-keys.json (即 auto-qb-data/webui-keys.json, 与 web.token 同一寻址规则)。
  • 结构: { "schema_version": 1, "template": "aqb-default", "overrides": { "<action_id>": "<归一化串 or 空=禁用>" } } —— 只存用户改过的条目, 未提及的 action 用当前模板基准; 模板机制见 §4.7 (v1 一次到位预埋, 本期只有 aqb-default 一套, overrides 语义与原 bindings 等价)。
  • 读时: schema_version 校验 (沿 26-09-26-0506 版本链口径) → 结构校验 (dict[str,str] + 值正则) → 未知 action_id 忽略 (注册表前向兼容) → 与默认表合并后下发; 文件损坏 → WARN + 尝试 .bak → 仍坏用默认表 (atomic_write keep_backup=True 范式兜底)。
  • 写时: 面板保存才写 (PUT 整份替换); 后端重校验结构, 非法 422; 黑名单/冲突仍由前端面板拦截 (后端只做结构层, 键位语义归前端单一事实源)。
  • 端点: GET /api/keys (返回生效表 (模板 ⊕ overrides) + template id + schema_version) / PUT /api/keys; 鉴权走全局 Bearer 依赖 (零额外工作); 金清单 +2 并同步 test_web_route_manifest_frozen。
  • 前端适配器: AQB_KEYS.load()/save() 单点封装 —— 启动拉取失败 → 默认表 + toast 提示; 保存失败 → 本地回滚 + 报错。引擎对其余代码只暴露这一对函数。

4.5 跨标签与多设备语义 (明示边界)

保存即落盘并即时生效于当前标签; 其它标签在下次刷新后生效 —— 与「设置页改 config, 其它标签刷新才见」的既有语义一致, 不新增同步机制。混合方案 (候选 C: 后端真值 + localStorage 镜像做 storage 事件同步) 的唯一增益就是把「刷新才见」提前到「即时」, 对低频编辑场景不值一套双写一致性代码 —— MVP 不做; 适配器单点保证了将来要加是一个文件内的事。多设备键位差异 (如 Mac 的 Cmd) 若将来成为真需求, 按 JupyterLab 的 winKeys/macKeys/linuxKeys 键槽扩字段, schema_version 升 2。

4.6 反悔路径

引擎对存储介质无感知 (只认 AQB_KEYS.load/save)。若用户拍板后改主意要 localStorage: 删两个端点与守阵、把适配器换成 localStorage 实现 (含 storage 事件), 引擎与面板零改动 —— 决策可逆, 沉没成本只有已删的 ~200 行。

4.7 绑定模板机制 (缓议·仅预埋, 2026-09-30 用户确认)

用户提出的方向: 预定义多套绑定模板 (如「auto-qb 默认 · 单键高效」/「保守 · 全带修饰」), 可整表切换, 且支持基于模板派生自定义 (在模板之上只记个人差异), 外加导入/导出。可行性结论: 可行, 复杂度中低 (~+150-250 行含守阵), 与既有架构零冲突 —— 模板就是注册表里的第二份 def 数据, 派生/合并/校验全部复用既有单点 (注册表 / 归一化 / danger 与黑名单规则 / PUT 校验)。

  • 数据形状 (唯一需要预埋的决策): §4.4 的 {schema_version, bindings} 改为 {schema_version, template: "aqb-default", overrides: {<action_id>: <归一化串 or 空>}} —— bindings 语义从「整份键表」变为「相对模板的差异」。生效表 = 模板基准 ⊕ overrides (override 恒胜出, 撞车 toast)。GET 返回生效表 + template id (引擎仍只消费生效表, 零改动); 面板显示「当前模板 + 已派生 N 条」。建议 v1 一次到位: 现在改只是字段名, 日后再改要 schema 升级迁移。
  • 模板定义进注册表: 每套模板 = 注册表内一组 def (静态数据字面量, 可被守阵逐条断言: 模板内无冲突 / 全模板过 danger 与黑名单规则)。新增模板 = 纯数据追加, 不碰引擎。
  • 切换语义: 换模板 = 改 template 字段 + PUT, overrides 保留 (派生自定义不丢); 生效表重算后若有 override 与新模板撞车, override 仍胜出并 toast 说明。面板提供「清空派生, 回到纯模板」一键。
  • 导入/导出: 纯前端实现, 零新增端点 —— 导出 = 生效文件 JSON (template + overrides) 走 blob 下载; 导入 = FileReader 读入后走与 PUT 完全相同的结构校验 + 注册表 action_id 校验 + danger/黑名单校验, 合法即本地生效并提示保存。跨设备迁移天然走服务端文件, 导入/导出主要用于备份与分享。
  • 约束: 危险判定口径与确认框标注 (§08 v3) 对所有模板与导入内容一律生效 —— danger 条目无论绑到什么键, 快捷键路径的确认框都不可省略, 面板 ⚠「单键触发 (有确认框)」标注照常显示; Delete 额外删除操作在注册表之外, 不随模板切换/导入导出变化 (各模板与上游 qB 习惯天然一致)。
  • 缓议理由: 本期 W1-W7 不含多模板; 但 schema 形状按本节预埋, W6 实现成本 +~10 行。真做多模板时加 W6.5 (模板选择器 + 清空派生 + 导入导出 UI), 引擎与端点不动。

5.1 注册表与引擎

5.2 自定义面板 (设置页)

  • 入口: ①设置页新增「快捷键」分区 (分区详情页尾块 —— 「运行日志」客户端只读块同款先例); ②任意页面 ? 打开帮助浮层 (只读速查, 附「前往设置自定义」链接)。顶栏不加按钮。
  • 面板形态: 带遮罩居中 modal, 按 group 分组列出; 每行 = 动作名 + 当前键位 chip + 录制钮 + 重置钮。
  • 录制交互 (§3.3 VS Code 模式): 点录制 → 只读输入框「按下组合键…」→ 首个非修饰键落定即收 → 展示人类可读键名; 纯修饰键拒收; Esc 取消 (引擎屏蔽层保证录制态不触发其它动作); 冲突 → 提示「已绑定为 X: 交换 / 覆盖(对方置空) / 取消」; 黑名单 → 当场拒绝并说明; danger 条目录到无修饰单键 → 允许, 行内标 ⚠「危险操作 (有确认框)」。
  • 重置: 单条重置回默认 / 全部重置; 空串 = 显式禁用该动作。
  • 保存语义: 面板改动先本地生效 (即时试用) → 「保存」PUT 落盘; 离开面板未保存 → 提示放弃或保存。面板底部注明: 键位存于服务端 webui-keys.json, 所有浏览器共享。
