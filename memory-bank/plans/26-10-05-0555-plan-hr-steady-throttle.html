02方案设计 —— 动态间隔闸 + 稳态旗标落盘

2.1 判据：对账对象集为空

两个动议场景统一落同一判据（报告 §13.2 已论证）：S1（本地零交集）⇒ anchors 空 ⇒ 对象集空；S2（本地全 B/C 终态/放行/超额）⇒ anchors 全部撞排除链 ⇒ 对象集空。_build_objects（service.py:1327–1365）纯内存现算，唯一副作用是漂移回炉（:1351 del data.verified[h]）。判据：

steady = anchors_known and not objects      # anchors_known 见 §2.5 —— 采集失败不算稳态
interval = site_conf.idle_refresh_interval if steady else site_conf.refresh_interval

2.2 现算点提级：闸门前算一次，传参进波

现算点从 _do_wave（:539–540）提级到 _refresh_locked 顶部（now = self._now() 之后、复用窗之前），一次现算把 (objects, observing, unmatched) 传参进 _do_wave，删除其内部调用 —— 杜绝双跑现算与双回炉。复用窗 / allow_fetch / force 各分支返回前判据已在手，稳态旗标各分支都能刷新。

行为变化说明（有意，且正是机制所需）：漂移回炉从「波时」提前到「poll 时」（≤60s）。本机重下的种子其放行记录作废更及时，同时它进入对象集 ⇒ 判据翻非空 ⇒ 间隔闸回退 —— 报告 §13.2「新下载自动破稳态」依赖的正是这一步。回炉语义本身不变（仍是「回清单/重下 ⇒ 重新受管束」）。开销：每 poll 每站一次 O(index+anchors) 内存遍历，零额外 IO（§13.2 已裁定可接受）。

2.3 间隔闸动态取值与破稳态即时回退

闸体 :483–489 的 due_wave = healthy + site_conf.refresh_interval 改用上面的 interval；waiting 理由在稳态期带标记（如「未到拉取时刻(拉取间隔·稳态降频, 还差 Xs)」），日志与 self-explanatory。破稳态回退不需要任何触发器：对象集翻非空 ⇒ interval 回常态 ⇒ healthy + refresh_interval 早已过去（healthy ≥ 24H 前）⇒ 闸门立即放行 ⇒ 下一 poll（≤60s）开波。发现延迟 5H → ≤60s + 波时长（报告 R1）。

2.4 稳态旗标落盘（展示链的桥）

HrWaveMeta（model.py:383）加 idle_mode: bool = False，to_json/from_json 按既有 _as_* 助手口径补一行。写盘纪律：仅翻转时写（if data.wave.idle_mode != steady: 赋值 + self._persist_step(session)）—— 稳态期每 60s poll 旗标不变 ⇒ 零写盘，守「自动 poll 零写盘」纪律；翻转至多每天几次。展示层从落盘旗标读（§2.6），重启后语义保留。不 bump schema 版本（§1.3 版本策略）。

2.5 锚点失败 ≠ 稳态（报告 §13.3 实现纪律的精确化）

现在 _collect_anchors 异常返回 {}（worker.py:323–325），与「本站零种子」不可区分 —— 若不修，主循环侧故障会被当成稳态而降频（报告 R5 唯一实质风险）。契约改为三态：

worker._collect_anchors 返回语义refresh_site 收到的 anchors间隔闸行为
映射（可能缺某站键）采集成功该站键缺失 → {}；有键 → 非空映射{} = 确认零锚点 ⇒ 可降频（S1 场景主路径）
None（anchors_fn 未接 / 异常）采集失败/未知None（不再被 :432 or {} 吞掉）不降频（按常态间隔；wave 行为沿用现状 {} 不变）

落点：worker.py:317–325 失败分支改返回 None；run_once:300 改 anchors_by_site.get(site, {}) if anchors_by_site is not None else None；service.refresh_site:432 去掉 anchors or {} 的吞并（None 直通 _refresh_locked，wave 路径内部再 or {}）；refresh_all:449–450 同款。现算仍用 anchors or {} 的结果，仅 anchors_known = anchors is not None 参与稳态判定。

2.6 展示同步（单点换算）

site_conf_interval（status.py:589–590）加 wave 参数：wave.idle_mode 为真 ⇒ 返回 idle_refresh_interval。:331 next_at、:351 视图 refresh_interval 字段、:605 blocking_reason 全部自动跟随 —— 稳态期「下次核对清单」显示 24H 倒计时，与闸门真实行为一致，不产生新的 S2 式误读。

2.7 明确不变项

  • 复用窗：service.py:1171–1174 min(reuse_window, refresh_interval) 不跟随降频间隔 —— 稳态期复用窗仍 2H，新鲜度与节奏解耦（报告 §13.4 不变项，语义正确）。
  • force（立即拉取）：跳过复用窗与间隔闸不动；账号安全线 min_interval / 日额 / Retry-After / 时间窗照常（:501–510 在间隔闸之后，天然不受影响）。
  • 防伪语义：命中即撤销放行（_record_hit :915–925）与守阵 tests/test_hr_service.py:744/748 一字不动；观察期 / 终态冻结 / 放行签发全链不动。
  • 单波开销：对象集空不跳波（波照开、页照翻），降频省的是波次不是单波页数（§13.2；改覆盖语义不在本计划）。
  • 30 天 INDEX_RETENTION 淘汰：与降频无相互作用（还挂清单的行至少每天重见一次，last_seen 持续刷新）。
