§01目标与设计原则

背景: 第一轮(dt_table 真接线, 26-11-10-0027)把 gridTemplate/aligns 委托 DT_TABLE.layout() 单点后, HR 三表是 D4 例外清单里除 04 卡片外的全部残留面: 列定义无 tpl/align/width 字段, 表头与单元格手摆, 零列交互零持久化(守阵钉死, 见 §02)。第二轮目标 = 三表迁 aq-table grid 链路并入全局枚举, 四项交互与主表同一套机制、同一个 v5 store。

目标一句: HR 三表成为主表同款 grid 面 —— 几何走 DT_TABLE.layout() 单点、交互走主表既有单点、状态落 autoqb_cols_v5 同款 store; dt_table 六口子全活(registerCell/cellOf 顺势接, E2); 现网 HR 面信息与样式逐列保真。

做到什么程度算成: §04 三波判据全绿 + 用户终验(HR 三表四项交互手测 + 主表回归四面 06/09/10/11)点头关单。

设计底线/不变量:

  • 单一生产者延续: HR 三表几何只经 DT_TABLE.layout()(经 ALL_TABLE_DEFS 同款 computed 链), 不出现第二处拼轨。
  • 交互机制近零新增: 四项交互全部复用主表单点(startResize/startColDrag/openHeadMenu/toggleColumn/persistPage), HR 侧只写插头不写引擎。唯一例外(E7 兑现所需): 拖序侧 locked 守卫 —— 引擎既有 locked 只守隐藏(menu.js:39/columns_persist.js:99), columns_drag.js 零 locked 检查(主表 locked 列今天全可拖序), 补 startColDrag/applyColOrder 守卫属新增引擎行为, 波及主表 locked 列拖序(§07 R7)。
  • 持久化向后兼容: HR 三表作新 page 键进 autoqb_cols_v5, 不升版本(app.js:739-741 口径「新增 page 是向后兼容扩展, 升版本会清空用户手调」), 不动存量用户数据。
  • 保守默认(黄金法则 2): hrKv k 列 locked —— 拆散 k/v 对的操作(隐藏 k/拖走 k)不可表达。
  • 判据前置: 验收清单在本篇写死交用户过目(10-14「判据自设+零用户验收」教训)。

§02现状与痛点

  • 三表定义与渲染: HR_TABLE_DEFS 独立注册表(src/auto_qb/webui/static/shared/hr_status.js:104-137), 注释自述「不进 TABLE_PAGES, 否则列选择器/列对齐会多出分组」(:24-27) —— 零交互时代的正确理由, 交互化后列选择器分组恰是隐藏列恢复入口(E6)。hrDetail 十列全 sortable(:105-118), 借壳 <aq-table mode="thead">(tpl/settings-detail.html:338-340) + tbody 手写 v-for 十 td(:343-356), 排序逐站点内存态(hrs.sortSel/sortDir hr_status.js:163-165, hrsSetSort :292-304); hrWave 八列全手写(:120-131; settings-detail.html:383-402, 行数 ≤4 注释明言不接排序); hrKv 两列 header:false(:133-136) 无列头原生表(settings-detail.html:370-380), 值格内嵌「确认空清单」按钮(:375-376)。
  • 零交互零持久化: 守阵钉死「HR 三表零 grid 几何」(tests/test_webui_static_r4_node_batteries.py:2011-2012)与「hr_status.js 无 localStorage」(tests/test_webui_static_dom_page_hr.py)。
  • 主表交互机制单点齐备(HR 只差插头): 拖宽 startResize(columns_persist.js:154-205, Shift 邻列互挤; 生效宽度双轨 recomputeEffective :13-24)+autoFitColumn; 拖序 startColDrag(columns_drag.js:45-101); 右键 openHeadMenu/headMenuHide(menu.js:20-45, locked 拒绝)→toggleColumn(columns_persist.js:97-113); 持久化唯一漏斗 persistPage(:66-80)落 autoqb_cols_v5(app.js:395, {pages:{<tableId>:{hidden,order,w}}}); 新增 page 向后兼容不升版本(app.js:739-741)。
  • aq-table 两形态: 组件 table.js:73-104; mode="thead" 分支自述「设置页 HR 详情表借壳专用, 不挂拖宽/重排/右键」(table.js:81-84) —— 四项交互只在 grid 模式存在; grid 表头自带全部交互入口(tpl/xtpl.html:232-242 mousedown 拖序/contextmenu 右键/resizer 拖宽)。
  • 视图归属: settings 页 hr_check 分区(settings-detail.html:223)的 .hr-full-modal 全屏覆盖层(v-show="hrsOpen" :279-280), 不走抽屉桥、无 anchor。
  • 守阵面(迁移即翻面): D4 例外清单守阵 test_r4_dt_table_exception_list_geometry_guard(test_webui_static_r4_node_batteries.py:2275, probe :1849-2044)含「HR 三表注册在盘」「HR 三表零 grid 几何」「settings-detail 零 grid 几何」「hrDetail 借壳形态在」四类断言, 迁移后全部改口径; assert 豁免层 ASSERT_SKIP_FACES(columns_grid.js:14-17)不含 HR(本就不是 grid 面); parity e2e 口径注释 e2e/dt-table-layout-parity.spec.mjs:29-32。
  • 数据链与可验性: HR 数据来自 /api/hr/status 与 /api/hr/sites/<site>/entries(hr_status.js:190/:229); e2e 跑 ui_harness 桩服 --hr-scene on|empty|off(scripts/ui_harness.py:39-41)。纯前端改造, 几何/交互桩可验, 不依赖真机 qB/HR fetch。

§03方案总览

主线(E6): 并入全局枚举 + 迁 grid 模式 —— HR 三表注册进 ALL_TABLE_DEFS(新 page 键 hrDetail/hrWave/hrKv), 列定义补 tpl/align 直接喂 DT_TABLE.layout() 单点; 每表一对 computed 按既有模式登记(columns_computed.js:139-189 同构); colAlignCss 对齐注入/列选择器分组/resetAll/fitAll/assertLayouts 枚举随并入自动覆盖。settings-detail.html 原生表迁 aq-table grid 容器 + grid 行。

交互(E1/E3): grid 模式表头自带四项交互入口(xtpl.html:232-242), HR 侧零新引擎; 状态经 colW/colHidden/colOrder(page 键 = 三表 tableId)走 persistPage 落 v5 新 page 子树, 不升版本。

排序(E8): hrDetail 排序并入引擎 setSort(col.key, tableId), 删 hrsSetSort/hrs.sortSel/sortDir 专用状态; 行为差: 排序选择从逐站点记忆变表级(拍板接受)。

单元格(E2): 手写 td 迁 grid 行后, 值格渲染器(徽章/mono/num/人话)注册进 DT_TABLE.CELLS(registerCell), 模板经 cellOf 消费 —— dt_table 六口子全活。

借壳退役: mode="thead" 唯一消费方(hrDetail)迁走后分支整体退役(table.js/xtpl.html), 守阵同步翻面 —— 本计划的直接后果, 随迁移同笔落地。

范围外(E5): 04 卡片(drawerTrackerV04)不动, 已入池 issue 26-11-17-0038 待排期; 例外清单收缩后它成为唯一几何旁路例外。

分期(E4): W1 迁壳+几何单点+守阵翻面 → W2 交互全量+持久化+单元格注册化 → W3 e2e+终验; 每波一笔提交(止损沿用第一轮 D8 条款)。
