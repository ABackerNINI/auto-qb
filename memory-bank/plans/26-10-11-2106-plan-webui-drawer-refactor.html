01 目标与边界

把第二套渲染技术整条换掉，而不是再打一层遮罩补丁

1.1 目标

  • 渲染单点：抽屉正文由 Vue 3 全局组件承载（与 <aq-table> / hub-field 同形态），彻底消除「Vue + 字符串 DOM」两套渲染技术并存。
  • 数据层剥离：把取数 / 竞态 / 等待集合 / 软切换序号从渲染代码里剥到与渲染无关的模块，让软切换协议有唯一宿主——这是治「换目标闪烁」结构性的手段。
  • 列表接壳：Tracker / 用户 / 文件三张列表注册进 <aq-table>，拖宽 / 排序 / 右键隐藏与主视图同源；这正是 P6 承诺的「接入面」落成真实代码。
  • 变体收敛：15 个过程式字符串变体不再逐一手搬；改为配置驱动的声明式密度档位（档数见拍板点）。

1.2 非目标（本计划明确不做）

  • 不改数据契约（前端 drawer.detail/trackers/files/peers 形状不动，后端零改动、零新端点）。
  • 不引入构建链（继续 Vue 3 CDN + shared/tpl/*.html 分片 + 全局 mixin 接线；无 SFC、无打包器）。
  • 不动流量图：qb_traffic_chart.js（uPlot）零改动，仅以薄包装承载其宿主 ref。
  • 不改抽屉几何契约（停靠占文档流、高度夹取 [240px, 70vh] 与持久化）与键盘口径（Alt+1..5、合并重排）。
  • 不为现有字符串 DOM 写任何适配层——现有抽屉整体废弃，不做兼容迁移。
与上一份抽屉计划的关系 26-10-06-0838（专题 webui-detail-panel-redesign，状态 Done）建成的是现有变体体系（注册表 + 宿主 + classic 兜底 + 15 变体）。本计划不是它的改版，而是其后继重建：目标架构、渲染技术、变体策略都不同，故另立专题而非在同文件堆版本。

04 目标架构

唯一核心 + 渲染适配：先剥数据层，再换渲染

与表组件计划 §03 同一取向。P0–P5 已证明「主视图 / 设置页 = Vue」这条主路径成立；重建把详情面板并入该路径，并把取数从渲染里剥出去。

  • 渲染模型：Vue 3 全局组件（app.component，与 <aq-table> / hub-field 同形态），模板放 shared/tpl/*.html 分片；无 SFC、无构建链。组件只贡献模板与最小实例态，行为经 $root 或独立模块（对齐 <aq-table> 的接线口径）。
  • 数据层抽离：把「取数 + 竞态 + 等待集合 + 软切换序号」从渲染代码剥到与渲染无关的 shared/drawer_store.js，成为软切换协议的唯一宿主。这是治「闪烁 7 次复发」的结构性手段，而不是再加一层遮罩补丁。
  • 列表复用表壳：Tracker / 用户 / 文件三张列表注册进 <aq-table>（与 HR_TABLE_DEFS 同法：独立注册表，不进 TABLE_PAGES），行模型渲染器各一份 ⇒ 拖宽 / 排序 / 右键隐藏与主视图同源。
  • 流量页签：qb_traffic_chart.js（uPlot）零改动，用一个薄 Vue 包装组件承载其宿主 ref。
  • 变体策略：15 个过程式变体不再逐一手搬；改为「每页签 N 档密度变体」的声明式配置（列 / 卡片 / 结构由描述符决定），档数见拍板点 D2。

05 分步实施 W0–W6

一步一停手点，每步独立验收、可回退

06 不变式与移植清单

重建最容易丢的六条

  • 软切换协议整体移植，不许重写：160ms 延迟点亮遮罩；按 tab 待到集合；每个入集数据源都必须显式登记（含跨模块的流量）；入口「同目标幂等短路 / 换目标交棒」；标题取 memberByHash 而非等详情。
  • 几何：停靠面板占文档流，高度变化传导给列表——任何「会改高度的内容更新」先问要不要动几何。
  • 持久化：drawerTpl / drawerMerge / 高度 / drawerTab 零迁移或显式映射；脏值 / 坏 JSON 一律回落默认（不报错）。
  • 形态数据域单一、UI 挂点各自独立：qbCurScope 派生；别从另一形态的拍板外推落点。
  • 键盘：Alt+1..5 重排先于流量门控；帮助文案随态改写；行级 roving 四件套。
  • 无构建链：分片清单序 + prism/index.html 210 行硬顶（腾行手法见 pitfalls/web-ui/frontend-split.md）。

08 风险与红线

九条会静默失效或误伤的点

R1 · 持久化键不得升版本 / 改名 drawerTpl / drawerMerge / 抽屉高度 / drawerTab 旧值必须可读——升级零观感差异，旧 id 一律显式映射而不是清空。
R2 · 软切换协议整体移植（7 次复发的教训） 最易丢的两条：跨模块登记（流量页签必须在 store 里显式登记）与 160ms 延迟点亮（快响应下点亮遮罩 = 制造新闪烁）。重建若"顺手简化"这两条，闪烁必复发。
R3 · e2e 是硬约束 drawer-groups-shows / drawer-merge / column-prefs / 快捷键四支 spec 逐条对齐；新面板若改文案 / 类名，同轮改 spec，不许放宽容忍。
R4 · 无构建链 Vue 3 CDN + shared/tpl 分片；禁 SFC / 打包器。组件形态照 <aq-table>（只贡献模板，行为经 $root 或独立模块）。
R5 · 三皮肤 CSS 成对 新类要么复用既有类，要么三份 CSS 同步 + 成对守卫；.dt-host 限宽 1400 与 .drawer-split 封顶 2400 等布局口径需保留（classic 历史恒满宽，误伤即回归）。
R6 · 流量图边界 qb_traffic_chart.js 保持 Vue 所有、零改动；宿主 ref 与 ResizeObserver 契约不变。
R7 · 双实现期歧义 新旧并存必须单一挂载点 + 特性开关；禁「两个都渲染、靠 CSS 藏一个」——那会重演 variant-singleton-shadow 的静默双跑。
R8 · 守阵不得放宽 重建期 test_drawer_tpl_* / _dtMounted / dtHtml 相关守卫同轮改版（删或改口径），不许「删断言了事」；计数变化必须补覆盖。
R9 · 不为将废弃的旧面板写适配层（反向沉没成本） 表组件计划 §03 的 DOM 适配 table-dom.js（条件项）只在 D1 选「保留字符串 DOM」时才做；若重建走 Vue，该条件项直接作废。

09 拍板点

四处需要用户先定方向

拍板结论（26-10-11）用户指令「按推荐实施」= D1/D2/D3/D4 一律取推荐项 A：Vue 3 组件重建 · 收敛为声明式密度变体 · 按页签分波替换 · 三列表注册进 <aq-table>。据此 W0/W1 已落地，W2 起照此推进。
D1渲染模型

A · Vue 3 组件重建 ｜ B · 保留字符串 DOM 只做清理（抽 store + 修问题）

推荐 A：与表组件计划的单适配取向一致，且是唯一能让「接入面」变成真实代码的路径；B 只能治表面问题，第 7 条（两套渲染技术）与第 8 条（维护量）原地不动。

D2变体去留

A · 收敛为声明式密度变体（每页签 2–3 档，配置驱动）｜ B · 15 变体逐一手搬 Vue ｜ C · 全删只留一版式

推荐 A：保住「换版式」能力的同时把 15 份过程式字符串换成配置；B 是把维护负担原样搬家，C 丢能力（用户既有偏好也要迁移）。

D3切换策略

A · 按页签分波，旧抽屉当 A/B 基线逐页签替换 ｜ B · 一次性大爆炸替换

推荐 A：每波可独立验收、可回退，且能把 §03 的逐面等价清单当验收面；B 一旦回归，定位成本极高。

D4列表接入

A · Tracker / 用户 / 文件三列表注册进 <aq-table> ｜ B · 面板自带私有表壳

推荐 A：这正是表组件计划 P6 说的「接入面」，且拖宽 / 排序 / 右键隐藏与主视图同源、零新维护点；B 会长出第三套表系统。
