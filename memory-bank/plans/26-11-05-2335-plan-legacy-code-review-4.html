§01目标与设计原则

为什么做：code-review skill 制度化于 26-11-04，此前的代码只经过不成体系的评审轮（R2 十批制 26-10-30、GTM 专项、测试增量轮），均未走现行方法（16 条 checklist、review.check 引文逐字校验、分级处置 schema）；且 R2 之后 127 个 commit 已把 core/webui 大半改写。全库当前状态从未被现行方法完整评过。

完成判据（存量语境铁律，取代 skill 的「收口前 blocker 清零」）：

  • 批次全覆盖无断号——manifest 守卫断言全部 src 生产文件被且仅被一个批次认领；
  • 每条采信发现都过 review.check 引文校验（refute 即弃，不复核）；
  • 全部发现处置完毕：P0 呈报拍板 / major·minor 聚合入池 / nit 记录；
  • 终报告（单文件 HTML dark）入库，批次地图实测回填。

不变量：本轮零代码改动（纯盘点）；不触碰 config.yml / auto-qb-data/；路线对 develop 的唯一写入 = 认领 / findings / 状态三类 ship.commit；路线 clone 不切分支不动 HEAD，不拦 develop 上任何其他工作。

执行模型

  • 并行：5 条路线文件互斥，可被 5 个不同 clone 的 agent 会话各自认领同时执行（认领协议 §04）；路线数即并行度，认领任意子集任意顺序。
  • 串行：路线内批次串行派遣只读 reviewer 子代理（宿主并发上限，pitfalls/kb/kb-subagent-concurrency.md）；分面拓扑照 skill ③（单批 ≤400 行全能 / 超过或触安全敏感面拆 正确性/安全/测试缺口）。
  • 全局单冻结 hash：全部路线评同一快照（D12）；路线 clone 不动 HEAD，用 git archive 导出快照评审，develop 零扰动。
  • 状态单点：认领 / 钉值 / 批次进度全在机器 JSON（D14）；本计划 HTML 静态不因执行改版。

review.lane 命令规格（S0 实现，D13/D15）

子命令行为失败即停（可见错误）
claim --route X --owner <id>route JSON 不存在才建：写入 owner / status=claimed / freeze hash（取 manifest 钉值：生成时点 ls-remote 核验的 develop tip，D17）已认领 / 树脏 / freeze 不可达（非 HEAD 祖先）
start --route X校验树净 → git archive <freeze> 导出快照到 repo 外目录（默认 <repo>/../auto-qb-review4-snap/，可 --snapshot 覆盖）+ 写入 hash 标记文件 → route JSON 记钉值与快照路径 → 打印三件套与本批文件清单未 claim / archive 失败 / 快照标记写不齐
verify --route X每批派遣前与交回后复核：树净 / 快照存在且标记吻合 / route JSON 状态一致；通过则打印当前批三件套任一不满足
done --route X校验 findings JSON 与小结已落盘 → 翻 status=done → 提示 ship.commitfindings 缺失 / 状态不是 in-progress

派遣三件套（存量适配，照抄派遣不临场发挥）

  1. 只读契约（照抄 skill ③ 原文）：禁止一切写操作——git 状态变更 / 写任何文件 / 跑 kb 等写类 task id 一律禁止，只允许读命令；AGENTS.md 开工同步对本任务豁免，主会话已完成同步。
  2. 评审目标钉死：读 快照目录（冻结 hash <freeze> 的 git archive 导出，非 git 仓库，纯只读树）；发现里的行号与引文一律以快照内容为准。
  3. 开工自检：快照根存在且 .snapshot-hash 标记 == 路线钉值，否则停手报告不评审；收尾复核：verify 通过才采信发现。

findings 与引文校验

  • schema 与 skill ④ 完全一致（七字段，不增字段；lane/batch/钉值由文件名与 route JSON 承载）：
[{"file":"src/auto_qb/core/state.py","line":42,"quote":"单行内连续片段",
  "severity":"blocker|major|minor|nit","claim":"问题一句话",
  "relevance":"相关|不相关","fix":"修法一句话"}]
  • 校验：commands run review.check --findings <json> --root <快照目录>——引文与快照逐字比对（±3 行），refute 直接弃不复核。校验发生在路线会话（其快照即权威），聚合会话只抽查不重跑。
  • 不报清单（照抄 skill ④）：理论风险说不出具体失败场景 / 风格偏好 / 库推荐 / 已在撞车底册的条目，一律不报。
