01

背景与问题

计划 26-09-27-1318 落地的绑定机制是: 档案 domains(存 web 域) 与各 trackers.<名>.domains(存 announce 域) 做小写精确交集, 恰好命中一个 tracker 配置才算绑定成功(site_presets.match_trackers, 校验/loader/前端三处同口径)。CarPT 实测踩雷: 用户站点只配了 tracker.carpt.net(announce 域), 档案存 carpt.net(web 域), 交集为空, 前端报「未绑定: 没有站点的域名包含 carpt.net」。

根因不是「精确匹配不够容错」, 而是设计层面把两个命名空间拉郎配:

  • web 域(用户浏览器访问的站点主机) 与 announce 域(种子内 tracker 服务器主机) 是两个独立事实, 可能是主域与子域(Announce 域恰为 Web 域子域, 如 BTSchool / CarPT), 也可能毫无从属关系(web 是 foo.net、announce 是 bar.cc);
  • 现行机制要求用户把 web 域塞进 trackers.*.domains —— 该列表本义是 announce 域名空间(供种子侧 match_tracker_confs 匹配 tracker URL), 塞入 web 域是语义污染, 且在「两域无关」的站点上用户根本无从猜起;
  • 档案侧 page_domain 字段虽预埋了「web 域硬编码覆盖」, 但绑定键仍走比对, 两套语义纠缠在同一份 domains 字段上。
用户裁决(2026-09-27, 三轮收敛的定稿口径): ① web 域与 tracker 域是两个东西, 不能比对, 只能映射 —— 一切跨命名空间匹配(含后缀容错方案)全部否决; ② 不做旧设置兼容, 免维护负担; ③ 已知映射直接硬编码进档案(BTSchool 对应哪个 announce 域是程序已知事实), 用户不自行绑定。
02

目标与非目标

目标

  • 绑定 = 映射: 程序内不存在任何「web 域 vs announce 域」的比对; 唯一允许的匹配发生在 announce 命名空间内部(档案硬编码的已知 announce 域 vs 用户 trackers.*.domains), 这是同一命名空间内的「已知值查表」;
  • 零绑定配置: 启用 CarPT 只需 hr_check.sites.carpt.mode 一个键 —— 档案已知它的 announce 域是 tracker.carpt.net, 自动绑定到用户配置里含该域的站点条目;
  • 显式兜底: 默认映射未命中(用户 domains 写法特殊 / 一站多 announce 域 / 歧义)时, hr_check.sites.<id>.tracker 填 trackers 键名直接指定;
  • web 域彻底档案化: hr_page_url 只由档案硬编码的 web 域派生, 与用户 domains 的写法完全无关;
  • 旧键一次性自动迁移: trackers.<名>.hr_check 不设常驻兼容层; 注册配置 schema 迁移 v1→v2(26-09-26-0506 版本链机制), 加载时把旧结构改写到 hr_check.sites, 存量配置零手工动作、config.yml 零修改;
  • 生产 config.yml 零修改照常工作(红线不触碰): CarPT 靠已知映射自动绑定, BTSchool 旧键靠迁移链自动搬家。

非目标

  • HR 运行链路(service / channel / parse / 锚点)零改动 —— 仍只读派生好的 TrackerConfig.hr_check;
  • 不新增站点 / 不写 adapter; 档案数据除字段重组外事实不变;
  • 全局 hr_check 其余项(总开关 / 频控 / 取数通道)口径不变;
  • 生产 config.yml 全程不动(红线) —— BTSchool 旧键由迁移链自动改写, 用户无手工动作(见 §8)。
03

设计: 三命名空间与映射制

3.1 三个命名空间, 各归各位

命名空间例(CarPT / BTSchool)事实来源用途与纪律
web 域 carpt.net / pt.btschool.club 档案硬编码 web_domain 仅派生 hr_page_url 与前端展示; 永不参与任何匹配
announce 域 tracker.carpt.net / pt.btschool.club 档案硬编码 tracker_domain(已知映射) + 用户 trackers.*.domains 唯一允许匹配的空间: 默认绑定 = 已知值在同命名空间查表
tracker 条目名 tracker_carpt_net / BTSchool 用户配置的键名 显式覆盖键 tracker 按字符串相等引用; 无任何匹配语义

3.2 档案模型修订(site_presets.py)

SiteHrPreset 字段重组 —— 原 domains: Tuple(语义含混: 既是绑定键又兜底 web 主机) 与 page_domain(web 覆盖) 两字段, 拆成职责单一的两个单值字段:

字段变更说明
web_domain新增 替代 domains + page_domainweb 命名空间, 档案硬编码; page_url() 改无参: https://{web_domain}{page_path}
tracker_domain新增announce 命名空间的已知映射(该站公开 tracker 主域); 默认绑定的查表键
domains删除跨命名空间比对的载体, 连同 preset_for_domains(旧键迁移反向查找)一起退役
match_trackers保留·改口径口径改为: 用户域名 t 命中档案 tracker_domain d 当且仅当 t == d or t.endswith("." + d) or d.endswith("." + t)(同命名空间的双向子域容错, 兼容用户配主域或 tracker 子域两种写法); 命中 0 个或 ≥2 个交校验层, 本函数只查不报
preset_id / adapter / page_path / download_path / page_param不变页面事实照旧

档案数据(首发两站, 事实均已在 adapter docstring / 生产配置里核实):

btschool:  web_domain = "pt.btschool.club"   tracker_domain = "pt.btschool.club"   (两域同值)
carpt:     web_domain = "carpt.net"          tracker_domain = "tracker.carpt.net"  (两域无关, 映射制的价值所在)

3.3 绑定解析: 默认映射优先, 显式键兜底

每个 mode != off 的 hr_check.sites.<id> 条目, 解析顺序(loader 与校验同口径, 判定单点仍在 site_presets):

  1. 显式映射: 条目 tracker 非空 → 按 trackers 键名直取; 键不存在 → 配置期报错;
  2. 默认映射: tracker 为空 → match_trackers 用档案 tracker_domain 查表; 恰好 1 个 → 自动绑定(用户零配置); 0 个 → 报错(文案附档案已知 announce 域, 指引补域名或显式指定); ≥2 个 → 报歧义错, 要求显式指定;
  3. 唯一性: 同一 tracker 条目被两个启用中的站点绑定(无论显式还是默认) → 报错;
  4. hr 段必填: 最终绑定的 tracker 条目必须有 hr 段(沿用 1318 计划的静默失效防线)。

派生填充不变: 绑定结果写 TrackerConfig.hr_check(adapter / hr_page_url / 路径 / 参数来自档案, mode / 微调来自配置), 下游零感知。派生视图的 tracker 字段回填解析出的条目名, 供报告与前端展示。

3.4 旧键处理: 走 schema 迁移链 v1→v2, 不设常驻兼容层

「不兼容旧设置」与「用户零手工迁移」并不冲突: 兼容是校验/loader 里常驻的旧键接受层(每次加载都要伺候旧结构, 维护负担的源头); 迁移是版本链上的一次性纯函数变换 —— 翻完旧结构即不存在, 程序里不再有任何伺候旧键的代码。项目已有现成机制(计划 26-09-26-0506: infra/versioning.py 版本链 + loaders._migrate_config_schema 分派), config kind 目前 v1、迁移表为空, 本章是它的首个生产落地:

  • 版本推进: CURRENT_VERSIONS["config"] 1 → 2; 注册 MIGRATIONS["config"][1]。存量配置缺失 schema_version = v1, 加载时沿链迁移(幂等, 重放同链即可), 磁盘物化发生在下一次 WebUI 保存(writer 统一盖章) —— 迁移即时生效, 落盘自动完成;
  • 落点与依赖纪律: 迁移函数是纯函数(dict→dict), 但需要 SITE_PRESETS 做档案定位, 不能进 infra(versioning 只依赖 .errors)。落 config 层(config/site_presets.py 或新建 config/migrations.py), 在 config 包加载时注册进 MIGRATIONS["config"](import 即注册, 早于任何 load_config); infra 的版本表只抬号;
  • 档案定位用同命名空间比对: 旧键自带 hr_page_url, 其 host 与档案 web_domain 同属 web 命名空间 —— preset_for_web_host(host) 精确匹配定位档案(小写归一), 不触碰 tracker 域名; 映射目标不迁移(交给档案默认映射自动绑定);
  • 改写规则: 对每个 trackers.<名>.hr_check: ① mode=off 或非字典 → 直接删除(新口径下 off = 键不存在); ② mode != off 且按 host 定位到档案 → 在 hr_check.sites.<档案 id> 建/并入条目(搬 mode 与微调项 scopes/interval/翻页上限/超龄线/配额, 页面事实四键 adapter/hr_page_url/download_path/page_param 丢弃 —— 值一律以档案为准), 然后删除旧键; 新旧并存时新位置获胜; ③ 定位不到档案(缺 hr_page_url / host 陌生) → 旧键原地保留, 交给校验层报错(见 §5)。

06

Web UI 改动

「HR 在线核实」分区的站点接入卡片(键集仍来自 schema 常量, 交互不变), 绑定状态展示改映射口径 —— config_hub.js 的 hrSiteBoundTrackers / hrSiteBindText / hrSiteBindClass 合并为单一 hrSiteBinding(preset):

  • 显式 tracker 已填且存在 → 「已映射: X」(正常色);
  • 显式已填但键不存在 → 警告色「映射目标 X 不存在 —— 保存后校验会报错」;
  • 未填 + 默认映射恰 1 命中 → 「已自动绑定: X(档案默认映射)」;
  • 未填 + 0 命中 → 警告色「未绑定: 档案已知 announce 域(tracker_domain)未命中任何站点配置 —— 请补域名或显式指定 tracker」;
  • 未填 + ≥2 命中 → 警告色「默认映射歧义: A、B 都命中 —— 请显式指定 tracker」。

卡片展示的站点网址改用 web_domain; tracker 微调字段经 hrSiteTuningFields 自动出现在卡上(那张表排除 mode 后全量渲染 schema 字段表), 无需另做控件。

用户侧迁移效果

站点落地后的启用方式
CarPTconfig.yml 只写 hr_check.sites.carpt: {mode: partial}(tracker 不填) —— 档案已知 announce 域 tracker.carpt.net 自动绑定到现有 tracker_carpt_net 条目, 该条目 domains 不用补任何域名, 本轮报错场景就此消失
BTSchool(存量旧键)零手工迁移: 现有 trackers.<BTSchool 条目>.hr_check(config.yml:484)在首次加载时由迁移链 v1→v2 自动改写为 hr_check.sites.btschool(host 定位档案, 微调项随迁, 旧键删除), 内存即时生效; 下一次 WebUI 保存时写回磁盘并盖 schema_version: 2 章。用户唯一可感知的变化: 保存后的 config.yml 里旧键消失、新位置出现等价配置
红线提示: config.yml 是生产文件, 本计划的实现不触碰它 —— 上表 CarPT 一行是用户启用动作, BTSchool 一行完全自动。生产文件在存量状态下加载即正确, 无需任何预先编辑。
09

不做的事

  • 不做常驻旧键兼容层(用户裁决, 与迁移不矛盾): 现行「兼容接受 + 每次加载等价迁移」的常驻代码全部删除 —— 旧结构只在 schema 迁移链 v1→v2 里被处理一次, 翻完即不存在, 程序内不再有任何伺候旧键的分支;
  • 不做跨命名空间比对: 后缀容错绑定方案(修订稿 v1)一并否决 —— 它仍是「web 域 vs announce 域」的比对, 只是放宽了容差;
  • 不做 tracker 下拉选择控件: tracker 先以微调字段(文本)形态出; 下拉(候选 = cfgTrackerNames)留作后续 UX 增强, 不在本章范围;
  • 不支持一站多 announce 域: 档案 tracker_domain 暂为单值; 真出现多 announce 域的站点时再扩成 Tuple + 显式键兜底, 现在不过度设计。
