02目标形态与交互规格

2.1布局 (报告 §03 方案A原图)

┌──────────────────────────────────────────────────────┐ │ 顶栏 / 筛选 / 搜索 │ ├──────────────────────────────────────────────────────┤ │ 种子列表 (flex: 1, 光标行高亮 + 滚动跟随) │ │ row 3 │ │ ▶ row 4 <-- .kb-cursor, 详情面板跟随此行 --> │ │ row 5 │ ├────────────────── 拖拽调高 · 可收起 ──────────────────┤ │ 详情面板 (默认约 42vh, 全宽, 无任何遮罩) │ │ [常规] [Tracker] [用户] [内容] [×] │ │ 名称 / 哈希 / 大小 / 状态 / 进度 / HR … │ │ tracker 表 / peers 表获得全宽 (本站宽表受益) │ └──────────────────────────────────────────────────────┘

布局参数: 面板默认高约 42vh; 拖拽调高夹取区间 [240px, 70vh]; 收起态只留面板头部 (~44px 行高); 全宽贴列表容器; 高度与开合态持久化 (键族见 §3.5)。动画从右缘 translateX 滑入改为下滑 + 淡入 (transition 组件 200ms 保留, 高度不可过渡 —— 只动 transform/opacity)。

2.2键盘行为矩阵

2.3跟随模型 (Web 端连动纪律)

  • 触发单点: 光标落地处 (_kbApplyCursor) 尾部挂一个入口, 面板开且当前页为种子页时 → 请求详情跟随; 鼠标路径未来接同一入口 (§1.3 相邻预留)。
  • 防抖 200ms: 连发上下键时不逐行拉详情; 停稳才发。
  • 在途请求代际 (seq): 换 hash 后旧响应一律丢弃, 防止慢响应把新种子的详情覆盖成旧的 —— 报告 §02 共识第 3 条「连动节流」的本站实现。
  • hash 未变短路: 光标落回同一行不重拉; 页签内 5s 轮询 (_startDrawerPoll) 照旧, 两者不互相打架。

03关键集成点 (代码事实, 已复核 @ 0a66c7c0)

报告 §01 的取证仍然成立; 本节是报告没展开、实施时最容易踩的五个集成点, 锚点已在本基线复核。

3.1DOM 落点: tpl-manifest 注入目标要改

抽屉模板经各皮肤 index.html 的 tpl-manifest 注入, 现挂 "into": "app" (atlas/index.html L138, console / prism 同构), 即 #app 尾部兄弟节点 —— 这正是它能全屏浮在所有页面之上的原因。停靠化必须换落点:

  • 推荐: shared/tpl/torrents.html 的 viewMode === 'torrents' 模板内、.group-table 之后新增停靠容器 .drawer-dock, 三皮肤 manifest 的 drawer 条目 "into" 改指该容器。种子视图父容器改 flex column (列表区 flex:1; min-height:0, 面板 auto)。
  • 依据: 抽屉入口全站唯二 —— torrents.html L27 双击、ctx-menus.html L85 右键「详情」, 都在种子视图; 面板随视图 v-if 隐藏, 天然解决「开着抽屉切到站点/设置页, 浮层残留 + scope 误判」 (现浮层形态下抽屉跨页常驻)。
  • 备选 (不推荐): 模板留 #app 尾部, 靠 flex order 塞进视觉位置 —— DOM 语义与可达性都差, 弃。

3.2scope 派发与浮层名单 (shortcuts.js, 三处联动)

  • _kbScope() L388-392: if (this.drawer.open) return "drawer" —— 停靠面板只存在于种子页, 该分支必须加页面条件 (page === "torrents" && drawer.open), 否则面板开着切页后会误判 scope 把列表键位全灭。
  • _kbOverlayBusy() L395-399: 名单摘除 drawer.open —— 停靠面板不是浮层, Delete 等注册表外绑定与列表键在面板开着时保持可用 (W2)。W1 阶段先不动这两处: 面板开着键位行为与现状一致 (drawer scope, 列表键死), W1 键盘零回归, W2 再放开。
  • drawer-tab-general/trackers/peers/content L266-279: scope "drawer" → "list", run 改双态 (§2.2); 目标解析取 kbCursor (kind=torrent) / 单选种子, 非种子页或无目标时 toast 提示后忽略。drawer scope 机制保留 (条目清空)。

3.3Esc 退栈链: 零改动, 走查确认

shared/dialogs.js escBusy() L485-487 已含 drawer.open, 快捷键引擎 _kbOnKeyDown 首行即把 Escape 整键让给退栈链 —— 「面板开 Esc = 关面板」已经成立。只需走查确认两层序: 关面板 → 再 Esc 落到「清除全部筛选」兜底 (计划 26-10-02-1632 已实施)。遮罩点击关闭随遮罩一起消失, 无迁移项。

05拍板点 D1-D4 (实施前逐项定)

D1面板初始态: 页面加载时面板默认开还是关?
  1. 默认收起, 高度记忆仍生效 (推荐) —— 首屏列表满高, 需要时一键/一键键位唤起; 与「面板是列表的附属」心智一致。
  2. 恢复上次开合态 —— 重开浏览器回到上次现场, 但「上次开着」对隔天回来的人未必是想要的。
  3. 默认展开 42vh —— 面板常驻, 最接近 Deluge 心智, 但牺牲首屏列表。
D2Enter 在面板已开时的语义 (报告原文写「Enter 开/关面板」)?
  1. 已开则仅跟随不关 (推荐) —— 关面板只走 Esc 与关闭钮; 理由: Enter 是列表高频键, toggle 语义下连发/误触会意外关面板, 且「跟随」已让 Enter 的开面板职责在开态失去意义。
  2. 开/关 toggle —— 忠于报告原文; 需把 row-open 排除出 repeat 放行, 防长按连发翻转。
D3窄屏降级: 列表容器过窄时面板怎么办?
  1. ≤900px 转全屏覆盖主区 (推荐, 保留关闭钮) —— 停靠意义随宽度消失, 全屏覆盖是移动端抽屉惯例, 面板 body 零改动。
  2. 维持停靠最小高 —— 简单, 但窄屏下列表只剩两三行, 违背本约束的初衷。
  3. 本次不做降级 —— 窄屏是低频场景, 记 issue 挂起。
D4报告 C 路线波次的取舍确认
  1. C 波 1 (抽屉内光标动作) 废弃、C 波 3 (遮罩降档) 取消 (推荐) —— 前者被方案A的 scope 存活语义取代 (§1.2), 后者被 W1 结构性取代, blur 摘除由本计划承接、PERF-01 收尾不延迟太多。
  2. C 波 3 仍先行单独落地 —— 仅当本计划排期明显延后、且用户中途想要缓解时才值得 (双倍维护三皮肤遮罩)。
