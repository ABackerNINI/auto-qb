跨组文件交叉检测与紧急处置

组边界不等于文件不交叉 —— 三类场景会让不同组的种子在磁盘上指向同一物理文件，新种子下载静默覆盖已下载/已完成数据，不可逆。本计划在分组模块内加一道跨组交叉防线：全量物理路径展开、MISSING 豁免、仅暂停涉事下载方、WebUI 组视图提示，与现有同组冲突检查同级。

01

问题与场景

本程序按「(规范化 save_path, 排序后的文件相对路径元组)」归组（group_key_of，src/auto_qb/core/modules/grouping_mod.py:41-49）—— 文件列表文本上不同即不同组，但组边界不等于磁盘上不交叉。issue 26-09-22-2221 列了三类真实场景：

#场景为什么现有防线够不到
① 同 save_path 下文件列表部分重叠（A=[ep01,ep02]、B=[ep02,ep03]） 列表不同即归入不同组；ep02 是同一物理文件，组内三条防线（大小一致性 / multi-dl·mixed / 缺文件扫描）都只做组内比较
② 文件名仅大小写不同（Windows 不区分大小写） path_normalize（src/auto_qb/infra/utils.py:477-488）只统一分隔符与压缩斜杠，不做大小写折叠 —— 文本上不同组，磁盘上同一文件
③ 不同 save_path 经 junction / symlink / 盘符别名指向同一物理目录 path_normalize 不解析任何别名，两个词法不同的 save_path 归成两组，落盘却是同一目录

后果：新种子下载写盘时静默覆盖另一组已下载/已完成的同名文件 —— 数据损坏静默且不可逆，被覆盖组随后做种数据错误、校验失败、误触发 MISSING 处置。现有唯一的下载冲突检查 _check_download_conflicts（grouping_mod.py:373）docstring 明确只覆盖同组，全代码检索无跨组交叉检测（issue 02 节取证）。

issue 内旧锚点已漂移。issue 报告里引用的 src/auto_qb/mixins/grouping.py / src/auto_qb/utils.py:411 等路径是 2026-09-22 的旧位置，kernel 模块化重构后已全部迁移。本计划全部锚点按 2026-10-04 勘察重标（core/modules/grouping_mod.py / infra/utils.py），认领时须逐点复验（见 S0）。

03

目标与不变量

目标

  1. 三场景全检出开关开启后，部分重叠 / 大小写不同 / 别名同目录三类交叉在「下载中」状态下当轮检出并警告。
  2. 处置克制且可恢复只暂停涉事下载成员；冲突消除后去重记录清除，用户手动恢复下载会再次触发（与同组检查同语义）。
  3. 零新增 qB 请求检测只消费 store.groups / store.group_sizes / store.by_hash 三份内存数据，不新增任何 /api/v2 调用。
  4. 默认静默开关默认 false，行为与今天逐字节一致；关闭时零额外开销。

不变量（改动不得破坏）

  • path_normalize 是分组键单一事实源 —— 大小写折叠 / 别名解析只准加在跨组检测自己的归一层，严禁改 path_normalize 本身（scripts/qb_capture.py 与 match_path_patterns、fs 校验共用它）。
  • 单一写线程 —— 跨组检测挂在 post 相位（主循环线程），去重集合只在主循环线程变更。
  • fail-fast 配置契约 —— 新键进 validate_config 全链路 + schema + 键面基线，守卫测试绿才算落地。
  • 软信号不落盘 —— 去重集合纯内存（对齐 download_conflict_warned 口径，store.py:91；「软信号不落盘」注释先例 :92-95），重启即失忆，方向是「更早恢复检测」，保守。
  • 检测不触盘 —— 只用词法归一与 realpath_lexical（目录级），不调用 exists/getsize，不引入 UNDETERMINED 三态分支。

04

机制设计

四步判定：展开 → 事件 → 豁免 → 处置

  1. 物理路径全量展开对每个组，把组内成员的文件列表（store.group_sizes[key][hash] 的规范相对路径）拼上 save_path，归一成物理路径键，建反向索引 物理路径 -> [(组key, hash)]。数据全部来自内存，零 qB 请求。
  2. 交叉事件判定同一物理路径被 ≥2 个不同组 key 引用即交叉事件（同组多成员共享路径是分组定义的固有属性，归同组检查管，不在本判定内）。
  3. MISSING 豁免（D3）事件任一侧参与者带 missing_tag 即豁免该事件 —— 带标签侧是「已知缺文件、等用户重下补救」的状态，对侧重新下载这些文件是合法补救。
  4. 警告 + 处置非豁免事件中存在「下载中」参与者（判定谓词与现有 :415 同款）才激活：逐对聚合警告一次；非 dry-run 时暂停涉事下载方（D2）并登记去重。

物理路径归一层（本检测私有的唯一新归一逻辑）

  • 目录部分解析别名：以组 key 首元（即 path_normalize 后的 save_path，归组键单一事实源）为输入，经 file_access.get_file_access().realpath_lexical(...) 解析 —— Local 实现 = normcase(realpath(_strip_win_prefix(path)))（file_access.py:210-211，junction/symlink 在此解析）；Mapped 实现 = 纯词法 normcase(normpath(_norm_logical(path)))（:339-340，D3 决策的「保守不误报」退化）。两个实现都不走映射表、不产生 UNDETERMINED / FileAccessError。每轮对每个不同 save_path 只解析一次（运行内 dict 缓存），syscall 次数 O(组数) 而非 O(文件数)。
  • 文件名部分只做词法折叠：物理键 = os.path.normcase(os.path.normpath(os.path.join(目录解析结果, 相对路径))) —— 大小写场景②由 normcase 折叠（Windows 生效，POSIX 恒等即不误报），不再对每个文件做 realpath。
  • 兜底：解析包 try/except (OSError, ValueError)，异常回退纯词法 normcase+normpath —— 畸形路径不得打断主循环，且词法回退方向是「少检出」，保守。
  • 不碰 path_normalize：上述全部逻辑收进检测自己的模块级纯函数（建议名 _cross_physical_key，落 grouping_mod.py），utils.path_normalize 一行不动。

数据复用与成本

数据来源角色
store.groupsstore.py:87（内存驻留）组 key → 成员 hash；组 key 首元即归一 save_path
store.group_sizesstore.py:88（首归组拉一次 files，惰性缓存）组 key → hash → {规范相对路径: 大小}；展开的文件清单来源
store.by_hash每轮快照状态判定（state_enum + amount_left，谓词同 :415）与 tags_set（D3 豁免）
store.dirty_groupsstore.py:82只读短路门（见下），消费单点仍是 _check_download_conflicts:392-396

扫描时机：独立于 dirty 增量走全量，但保留零变化短路。交叉常只有单侧脏（组 A 下载中、组 B 静止），按组增量会漏；故检测开启时每次扫描都全量展开（O(总文件数) 纯内存）。但 dirty_groups 恰好是状态/成员/归组/自有动作变化的完整登记 —— 增量轮次（rounds_applied > 0）且 dirty 为空时，交叉事件集合与上轮逐字节相同，直接返回。静止种子库（做种为主）零成本；有下载活动的轮次才付 O(文件数) 的字符串字典构建成本。

插入位置敏感：必须在同组检查之前、且不消费 dirty。_check_download_conflicts:392-396 是 dirty_groups 的唯一消费点（读取 :392、取出即复位 :396）。跨组检测挂在 _on_post（:96-101）中 _handle_save_path_changes 之后、_check_download_conflicts 之前，对 dirty 只读不复位，两套检查共用同一份变化登记，互不干扰。

去重与消除（对齐现有模式）

  • 去重集合：store.cross_group_conflict_warned: Set[Tuple[Any, Any]]，元素为排序后的组对 (key_a, key_b)（按 str(key) 排序取规范序）。store.py:91 旁新增，注释沿用「软信号不落盘」口径。
  • 去重粒度取组对而非「组对+物理路径」：警告按组对聚合（路径列表展示前 3 处 + 「等 N 处」），整列表重叠时避免一次成百上千行警告；组对激活期覆盖其全部共享路径，处置语义等价。用户骨架提示过「key 含派生物理路径也可续用」，按防刷屏理由收窄为组对（调整理由见 S3 改法要点与汇报）。
  • 消除：每次扫描重建 active 组对集（非豁免且含下载中参与者），list(warned) 遍历，不在 active 的 discard —— 对齐 :424-426。下载方被暂停后状态转移，下轮组对失活、去重清除；用户手动恢复下载会再次触发（与同组 multi-dl/mixed 完全同语义，test_grouping.py:445-486 先例）。
  • dry_run 语义：警告照发；if dry_run: continue 放在 warned.add 之前、暂停之前 —— dry-run 不暂停、不记去重（严格对齐 :437-440 顺序）。

  2. 消除：active 组对集（含 S2 的豁免/下载中判定）算完后，for pair in list(warned): if pair not in active: warned.discard(pair)。

    for ka, kb, paths, dl_hashes in active:      # paths 供消息, dl_hashes = 涉事下载方
    if (ka, kb) in warned:

风险与回退

七条已知坑与对策（每条都有测试或 grep 钉住）

#坑对策与钉子
1 误改 path_normalize —— 它是分组键单一事实源（grouping_mod.py:49、scripts/qb_capture.py import、match_path_patterns utils.py:491、fs 校验共用），加大小写折叠/realpath 会全局改变归组语义 归一逻辑全部收进检测私有的 _cross_physical_key 与目录解析缓存；实施后 git diff src/auto_qb/infra/utils.py 必须为空；既有 test_grouping 全量绿 = 分组语义未漂移的回归证明
2 按 dirty 增量做跨组检测会漏 —— 交叉常只有单侧脏 全量展开（D 决策）；仅保留「rounds_applied>0 且 dirty 空」零变化短路（事件集合逐字节相同，正确性无损）；只读不复位 dirty，消费单点仍是 :396（取出即复位） —— 挂载点选在 _check_download_conflicts 之前（S2 改法要点 6）；测试 13 钉单侧脏场景
3 reset_runtime 清不清去重集合没有显式决策 —— 热重载后行为不可预期 已显式决策：不清（组 key 与警告语义在重建后仍成立，消除循环兜底过期条目，对齐 download_conflict_warned 先例 :426-433）；决策写进 reset_runtime 注释；测试 12 钉死，防后人顺手加 clear
4 dry_run 顺序错误 —— 若 warned.add 在 dry-run 分支前执行，dry-run 会「记了去重但不处置」，下次真实执行被去重吞掉 顺序逐字对齐 :437-440：警告 → if dry_run: continue → warned.add → 暂停；测试 11 钉「警告在、stop 0 次、warned 空」
5 Windows 大小写用例在 Linux CI 上失效 —— normcase 在 POSIX 恒等，硬断言会假红或假绿 拆 POSIX 不误报断言（全平台）+ Windows 真检出断言（skipif os.name），见 §06；junction 用例同样平台标记
6 触盘 / 引入 UNDETERMINED 三态分支 —— Mapped 部署下 exists 类调用会撞映射 miss，词法检测被三态语义复杂化 检测零触盘：只用 realpath_lexical（两实现 file_access.py:210-211 / :339-340 都不走映射表、不产生 UNDETERMINED / FileAccessError）与纯字符串运算；目录级解析带 try/except 兜底词法；Mapped 部署别名交叉漏报是已知且被接受的保守退化（D1），写进 §08 边界
7 _sync_paused_state 同 tick 改写 store 状态 —— 真实 stop 会让测试快照失真、去重断言污染 测试一律 mock.patch.object(mgr.api, "torrents_stop")（:461-466 标准写法）；生产链路与现有同组暂停共用同一校准机制（下轮 refresh 对齐），无新增风险

性能风险

全量展开成本 = O(总文件数) 字符串运算 + O(组数) 次 realpath 系统调用（目录级 + 运行内缓存）。仅在「开关开启 且（首轮 或 dirty 非空）」的轮次支付；静止种子库零成本。若超大库（数十万文件级）实测单轮展开超预算，降级路径是给短路门加粗粒度指纹（组数/成员数/文件数三元组缓存）——本期不做，先实测（S5 基线数字）再议。

  1. 运行期一键回退：cross_group_conflict_check 默认 false，配置关掉（或删掉该键）= 整条检测链旁路，行为与今天一致；去重集合是纯内存字段不进 state_file，回退零状态残留。
  2. 代码级回退：S2/S3 全部改动收在 grouping_mod.py 新增方法 + _on_post 一行接线 + store.py 一个字段；S4 是 views 一个字段 + 前端一处 span。按步分批提交，单步 revert 即可，互不牵连。
  3. 配置面回退：删键需同步移除 models / sections（KNOWN_GROUPING_KEYS + 校验元组）/ schema Field 三处，重跑 commands run test.keys-update 并回写 keys.md —— 非破坏删键，无需抬版本。
