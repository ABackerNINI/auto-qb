§01目标与设计原则

两个目标,两条主线

目标主线判据
① 统一风格机器面强制(命令自动填 + 守卫拦新增),正文行文完全自由(余地)新建件头字段/命名/状态词 100% 合规且由命令产出;守卫对新增面判红可机检
② 减少修改步骤一次逻辑动作 = 一条命令 + 一次填空;时间戳、命名、meta、索引重建、Refs、状态行等派生面一律由命令派生,agent 零手写§04 步数对照表:高频工作流机械步数下降 ≥ 60%

设计底线(不新增规范单点)

  • 命令是既有单点的执行器:时间取 timekit(UTC+8 钉死)、状态词表取 _common.DOC_STATUSES(HTML 5 词)与档案 4 词表、cap 取 _common.CAP_POLICY、命名与认领链口径遵 conventions/doc-forms.md——命令与模板里不出现第二份词表/命名规则,全部 import。
  • 模板是规范的渲染器:模板产出的头部字段与 doc-forms 定义逐字一致;守卫钉住「模板头 ↔ 单点定义」同源(先例:test_skill_cap_table_matches_cap_policy 钉 cap 表)。
  • 余地边界:强制面 = 元数据头、文件命名、必备章节存在性;骨架段落可删可留空;正文句式、口吻、详略零约束。

§04SLOT 填空机制与七族模板

机制:模板 = 默认正确的骨架 + 填空标记

  • 模板内需要 agent 写内容的位置放 <!-- SLOT: 说明 -->(md 族用 HTML 注释同款,可 grep)。agent 的动作从「回忆规范→从头写」变成「替换标记、删多余段」——删比写快,且删不出来错。
  • kb.new 建完即打印 SLOT 清单(带说明),agent 不必打开模板源文件;守卫对新增面校验「无残留 SLOT」——没填完过不了检查。
  • 骨架段落标注「可删」:模板给的段是默认存在,不是强制存在;守卫只查头部字段与必备章节存在性,不查段落齐全(Q1 推荐 A:机器面强制 + 骨架可裁)。

§05步数对照与剩余人工步骤的量化裁定

5.1 口径与判据

步 = 一次命令调用或一次「打开文件做编辑」;SLOT 段落数不计步(一次编辑可填完全部段)。机械剩余 = 本可派生却仍需人工的确定性动作,目标恒 0。一个动作能进命令的判据(三条缺一即留人工):①输入已在命令参数或系统事实中(时间/路径/词表/查重) ②执行确定性、无判断 ③失败可整件回滚(渲染后一次落盘)。
