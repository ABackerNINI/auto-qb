02 / 方案核心

逻辑路径进 → syscall 边界映射 → 逻辑路径出; miss 一律"不可判定"

# 新模块 src/auto_qb/infra/file_access.py
UNDetermined = ...                       # "不可判定"哨兵(缺失≠不可判定)

class FileAccess:                        # 全部方法: 逻辑路径进 → 逻辑路径出
    def exists(path) -> bool | UNDetermined
    def isdir / isfile(path) -> bool | UNDetermined
    def getsize(path) -> int             # 不存在/不可判定 raise FileAccessError
    def disk_usage(path) -> (total, used, free)
    def scandir(path) -> [Entry(name, logical_path)]   # entry 译回逻辑空间
    def mkdir(path)                      # Mapped 实现: 挂载点可写即放行(真实 mkdir),
                                         # 只读挂载(EROFS/EACCES)语义化拒绝
    def realpath_lexical(path) -> str    # normcase+normpath, 不做符号链接解析
    def open_path(path, select=False)    # Mapped 实现: raise NotSupported
    def map_to_container(p) -> str|None  # None = miss(fail-safe 判定点)

class LocalFileAccess(FileAccess):  # 宿主直跑现状: 直通 syscall + 长路径前缀(收编散点)
class MappedFileAccess(FileAccess): # 容器: path_map 前缀表(casefold, / 折叠后匹配);
                                    # miss → UNDetermined/NotSupported, 绝不返回"不存在"
  • 单例与注入: 模块级 get_file_access() 按配置构建(空表 → Local; 非空 → Mapped), 热重载不切换(进 R 级"需重启", 与 data_dir 同档, 文档写明); 单一写线程假设不受影响(包装层无状态, mkdir 除外且本就只在 Web 请求线程)。
  • 三态的判定语义(安全红线, report §05): 映射 miss → exists 返回 UNDetermined 而非 False。check_filelist 把 UNDetermined 翻译为「路径不可判定: 'path'」; 缺文件扫描跳过该组 + WARNING(不暂停不打标); exists() 表达式把 UNDetermined 翻译为 ExprError(显式报错优于静默 False, 与 disk_* 现状同口径)。
  • 映射匹配规则: 入参先 path_normalize(折叠 \→/), 源前缀 casefold 比较, 命中后替换前缀得容器路径; \\?\ 前缀在匹配前剥掉(容器是 Linux, 前缀本不会出现, 防御性处理)。

既有坑的对治(report §04): routes/fs.py:134 拿 scandir 的 entry.path 与逻辑空间白名单比较 —— 包装层把 entry 译回逻辑空间后该处不改语义; 白名单比较改用 realpath_lexical(逻辑路径上做不了 realpath, 逃逸防护退化为词法比较, 与 fs.py:57-59 既有已知限制同口径, 注释写明)。组 key / qbapi 回传 / 跳检备份元数据零改动(它们消费的字符串从未经过包装层)。

05 / 取舍记录

四个已定的取舍(拍板时如推翻, 在此追加变更记录)

  1. 显式配置键, 不自动探测容器 —— 探测命中即改变核心行为, 违反保守默认; 映射表本身就必须配置(§03 note)。
  2. 三态 fail-safe 优先于功能完整性 —— 映射 miss 宁可"功能退化为报错/跳过", 不可返回"不存在"去重演误暂停事故(report §05 红线); 代价是配错的用户会看到 ExprError/WARNING, 这是想要的行为。
  3. mkdir 按挂载点可写探测放行(2026-09-27 拍板放宽) —— Mapped 实现真实执行 mkdir, 不在代码层一刀切; 只读挂载由 EROFS/EACCES 语义化拒绝兜底, 启动自检预告可写性。与"所有写操作都通过 qB"的设计张力由 :ro 默认挂载兜住(compose 示例仍写 :ro, :rw 是用户的显式选择)。
  4. 挂载点约定 /mnt/downloads —— 映射表消化任意前缀, 约定只为示例配置不爆炸; 不做自动推断。

风险与回退

  • 回退面: path_map 空 = Local 全量直通 = 现状; W1/W2 合并看也是"调用点换皮", 出问题 git revert 单波即可。
  • 最大残余风险: drvfs(Windows→WSL2)挂载上 getsize 逐文件的性能与 disk_usage 数值正确性 —— W5 第一项实测, 若数值不可信, disk_* 表达式在文档标注"Windows 宿主容器部署不保证"并维持救回其余触点。
  • 兼容性: 状态文件零新增(映射表不进 state); state schema 不动; 组 key 逻辑空间不变 ⇒ 与宿主直跑的实例互换挂同一 qB 无缝。
