flaky 测试结构化治理: 时钟注入与抖动消除

把 tests/ / e2e/ 的时序抖动类 flaky 从「逐案打地鼠」升级为结构化消除: 生产代码全量时钟注入、测试侧统一假钟、消灭固定睡等, 并用守阵 + 随机序巡检防回归; 平台差异做机制化收敛, 不建隔离区、不放开 retry。

§01目标与设计原则

背景

时序/抖动类 flaky 反复冒头: 修掉一个(跨零点、分钟戳、时钟粒度坍缩…)另一个又冒出来, 呈打地鼠形态。memory-bank/pitfalls/testing/ 中 flaky 直接相关坑档已 10+ 条, 全部是逐案修、无机制沉淀。另有平台差异类(Windows 定时器刻度、POSIX vs nt)偶发假红。业界实证(Microsoft ISSTA 2019): async-wait/时序是 flaky 第一大类根因, 且属确定性根因——可复现、可根治, 与网络类概率性根因不同, 值得先治。

目标(做到什么程度算成)

  1. 守阵上线且零存量违例: tests/ 裸 time.sleep 归零(白名单外)、e2e waitForTimeout 归零、src/ 裸取时归零(白名单外)、bind 位固定端口归零; 新增即红。
  2. 测试侧假钟统一单点: 4 套旧假钟类全部迁完并删除。
  3. 生产时钟注入全覆盖: 44 文件 161 处取时点全部收口。
  4. 本机全量(含 e2e fast)连续 5 次绿。
  5. flaky 台账 / 根因类目覆盖表 / testing 文档 / 坑档回写完成。

设计底线/不变量

  • 时间控制权在测试: 生产代码不裸取时; 测试不真睡等真时序。断言区间不精确值(业界共识: 完全冻结+精确断言脆弱)。
  • retry 不是修复: pytest 主套件 reruns 恒 0; 新引入的 flaky 必须 fail CI 当场修, 修不了走 skip(reason+issue 入池), 不养隔离区。
  • skip 必带理由+issue 链接, 纳入巡检审计, 防腐烂。
  • 本计划不新增生产配置键(不触发 validate_config 面); pytest-randomly 等是 dev 依赖+CI job, 不进生产配置。
  • 黄金法则不冲突: 守阵只做只读扫描断言; 单一写线程/幂等/状态持久化口径不受影响。

§03方案总览

主线: 三根支柱

  1. 时间控制权收归测试——生产 src/auto_qb/infra/clock.py 单点(Clock protocol + 系统时钟), 组件构造期注入(默认系统时钟), 叶子函数走单点; 测试侧 tests/clock.py 统一假钟(advance/freeze + autouse 复位)。
  2. 消灭固定睡等——Python 侧 sleep 改「事件同步或 wait_until(cond, timeout) 条件轮询」(收编 tests/helpers.py:1268/1425 两处雏形); e2e 侧 waitForTimeout 改 expect(locator).toHaveXxx() / expect.poll() / toPass()。
  3. 防回归机制——四类守阵(裸 sleep / waitForTimeout / 裸取时 / bind 位固定口)+ pytest-randomly 周巡检(随机序暴露顺序依赖与随机数依赖)+ flaky 台账。

辅助: 平台差异机制化收敛(tests/platform_tolerance.py 容差单点+规范, 不做生产平台抽象层); 根因类目覆盖表归因框架; e2e 提速走 shard 隔离桩(D14)。已拍板决策见 §06(D1–D14)。

S1 基建

  • src/auto_qb/infra/clock.py: Clock protocol(now() / monotonic())+ SystemClock 系统时钟单点。生产代码唯一合法取时入口。
  • tests/clock.py(或并入 helpers 单点): 统一假钟 advance()/freeze(), fixture 级自动复位(xdist 每 worker 独立, 不跨 worker 共享); 用法规范一段。
  • wait_until(cond, timeout, interval) 条件轮询 helper: 收编 tests/helpers.py:1268/1425 两处雏形为单一实现。
  • 守阵 4 条(复用既有扫描框架): ① tests/ 裸 time.sleep; ② e2e/ waitForTimeout; ③ src/ 裸 time.time/monotonic(白名单 clock.py); ④ bind 位固定端口(配置值位不拦)。存量违例先入白名单单点(带理由注释), 随 S3/S4 清零后收紧。
  • 全量 + 基线切片。

S2 生产时钟注入(按域 4 提交, 每步全量+基线)

  1. core: state.py、qbmanager.py 等——组件构造期收 clock 参数, 默认系统时钟单点。
  2. hr 域(runtime/service_wave/feeder 等)——与既有 runtime.sleeper 注入口径对齐。
  3. webui/traffic 域。
  4. 其余(cli/rules/infra/tools)叶子——纯函数直接走 from auto_qb.infra import clock 单点。

每步验收: 该域 0 处裸取时; 全量绿+基线; 高风险整合前 cp -a .git 备份(AGENTS 建议口径)。

S3 tests/ 清理(逐域推进)

  • 63 处 sleep: 线程协作点改 Event/Queue 同步或 wait_until; 时间语义(阈值/过期/节流)改注入假钟——feeder(10)、qbmanager_loop(7)、traffic_store_paths(5)、qbmanager_tasks(5) 优先。
  • 4 套旧假钟(hr_helpers.Clock、traffic_sample_support._Clock、两处内嵌 _FixedClock)迁 tests/clock.py 后删除。
  • 126 处 monkeypatch time 收敛到统一假钟。
  • 挂钟性能断言(耗时上界类)迁出功能测试: 改 CPU 时间/行为断言, 或独立基准轨。

S4 e2e 清理

  • 91 处 waitForTimeout: DOM 条件→expect(locator).toHaveXxx() 自动轮询; 非 DOM 条件(后端状态/localStorage/URL)→expect.poll()/toPass(); 动画遮蔽用 trace 复盘, 不加 timeout。
  • 21 处 setTimeout 审计: 属业务延迟语义的保留并注释, 属睡等的改造。
  • retry 探测口径: CI retries:1 保留为探测器, Playwright flaky 标记进台账当场修。
  • flaky 台账上线 memory-bank/testing/(用例名/根因类目/状态/处置/日期)。

S5 e2e 并行化(D14, 插在 S4 之后——先清睡等再定 shard 数)

  • 卡点校正: 串行是 playwright.config.mjs:30-32 的刻意设计(单共享桩, 用例互相影响观测)——直接 workers:N 会用新 flaky 换速度; Playwright 并行的正确形态是 shard 多进程。
  • --shard=x/N: 每个 shard 是独立进程, 各自拉起自己的 webServer——桩 --port 0 OS 分配 + wait 捕获注入已具备全部前提, reuseExistingServer:false 纵深不受影响; 改动面 ≈ npm script。
  • shard 数在 S4 跑完后按实测时长定(91 处固定睡等是串行时长大头, 清完先量化); shard 内先保持 workers:1, 跑稳后纯只读 spec 才考虑升 workers。
  • 边界: perf.spec.mjs 等 CPU 敏感用例钉单 shard(与 D10 性能断言迁出协同); 模式矩阵轮(env 组合决定桩形态)轮间保持串行, 提速落在每轮内部。
  • 验收: fast 门禁时长实测数字进基线切片(补上 e2e 时长无基线的空缺); 0 新增 flaky。

S6 收口

  • tests/platform_tolerance.py: Windows 15.6ms 刻度(≥2 tick 余量)等容差常量单点; 「跨平台断言规范」入 testing 文档; 平台相关 skipif 强制带理由+负责人。
  • pytest-randomly 周巡检 job: 随机序+固定 seed 输出(可复现), 允许 reruns 作统计采样; 主套件默认顺序不动; 巡检红→入池修。
  • 根因类目覆盖表(§03)入 testing 文档单点; tests-real 补一条「真时序轨职责边界」规范。
  • 最终验收: 本机全量(含 e2e fast)连续 5 次绿。
