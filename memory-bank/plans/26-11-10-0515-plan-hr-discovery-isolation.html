HR 发现通道多 clone 与多环境隔离(登记簿拆分+环境带+显式裁决)

§01目标与设计原则

背景

同机 ≥2 个 clone 启用 HR 通道时,所有 clone 共写同一份用户级登记簿,发现响应返回全机实例清单(含 token),扩展取首个命中并遍历全部实例通信 —— 跨 clone 混串(issue 26-11-03-0315)。同时测试世界的验收桩默认绑生产带 18788,日常浏览器的生产扩展会发现它 —— 测试/生产互相可见。历史上固定口还被生产实例长期占用,引发过测试 flake(0115,已被 0330 修复收档)与误杀事故(pitfalls/ops/port-kill-prod-instance.md)。

目标(做到什么程度算成)

  1. 任何 /api/hr/discover 响应只含本 clone 的实例与 token —— 与 clone 数、机器数、未来新增多少个无关;
  2. 生产扩展在默认配置下不可能发现/连上测试世界的任何东西,反向亦然;跨带只剩「人工显式填地址」这一条路;
  3. 扩展在未经显式选择时不服务任何 clone;恰好一份应答时自动服务(单实例用户零感知);
  4. 公开单实例用户与现有生产部署:零配置变化、零迁移动作。

三条硬性质(每个决定对它们负责)

  • P1 零记忆: 新 clone、新机器、未来加多少个 —— 任何时刻不存在「需要有人记得去做」的动作;
  • P2 显性失败: 出问题必须是「显眼地不工作、亮着等你裁决」,绝不「悄悄干错活」;
  • P3 单实例零配置不倒退: 公开用户「装好即用」保持原样。

设计底线/不变量

  • 发现协议结构不动: 端点路径、门序(origin→配对→GET)、心跳 30s/TTL 120s 语义全部保留;
  • 兼容口径「只加不改」(§06 D8): 新旧双端任意搭配不得坏,兼容矩阵见 §03;
  • 不引入 native messaging、不做跨机发现(26-10-14 两份报告的结论维持,路线 B 缓行);
  • 公开默认 18788 一字不动;新增配置键必须同步 schema/hr.py + validate_config + 键面守阵(黄金法则 4);
  • 测试世界与生产世界的分界是端口带,不是人的自觉 —— 凡工具链起的东西一律测试带(§06 D4/D5)。

痛点

  • 混串: 扩展把多个 clone 的实例混列并逐个轮询、健康账混记;生产实例实测正占 18788(pitfalls/ops/port-kill-prod-instance.md),dev clone 落 18789/18790,混串进行时;
  • 身份缺失: endpoint 每次重启随机(port=0)、id 被 merge 丢弃、name 是随机乱码 —— 扩展今天无法跨重启稳定识别同一实例;
  • 测试-生产互见: 桩在生产带可被生产扩展发现合并;生产实例占口曾致测试 flake(0115,已收档)与「先杀后问」误杀事故;
  • 容量: 候选仅 3 个,第 4 个 clone 无发现服务;一旦响应隔离落地,绑不到候选口的 clone 直接隐形 —— 容量从「列表少一项」变成「实体消失」,必须先扩(§06 D6)。

§03方案总览

三个装置,彼此独立、三层防御(从内到外兜底):装置一让混串在协议层不可表达,装置三让跨世界误连在默认配置下不可达,装置二让「服务谁」永远经过显式裁决。

装置一 · 协议隔离(后端)

登记簿按 clone 拆分: %LOCALAPPDATA%\auto-qb-hr\<sha1(data_dir)[:12]>.json,每 clone 只写、只读自己的文件;发现响应天然只含本 clone 实例(文件里物理上没有别家的条目)。写入/心跳/TTL 剪枝逻辑不动;旧共享文件 instances.json 遗留不读不删、不迁移(P3 备选见 §05)。顺带消掉多进程共写一份 JSON 的读改写竞态。

装置二 · 显式裁决(扩展)

探测全部 8 个候选口、收集所有应答(弃 find-first);每份应答 = 一个干净 clone。

生产clone ── 发现@18788-18795 ──应答──▶ 只含生产实例(带标签)
测试桩   ── 测试带 28788     ──应答──▶ 只含自己(仅测试扩展可达)

扩展: 应答恰 1 份 ──────────▶ 自动服务(持久化,单实例用户零感知)
      应答 ≥2 份且无选择 ────▶ 一个都不服务 + 选项页横幅「请选择」
      已选 clone 消失 ───────▶ 服务空转 + 显眼提示,绝不自动落到别家

选择按标签记(独立存储键,抗 parseInstances 三键重建与发现集整批替换);新 clone 上线 = 多一份候选答案躺在列表里,不是新污染源、不是新的「要记得去关」。

装置三 · 环境带(工具链)

测试带 = 28788-28795(生产带 18788-18795 的镜像,避开 Windows/Linux 临时端口段)。hr_ext_stub.py 默认口 18788→28788;dev.run 注入测试带(机制见待拍板 P1);pytest/CI 维持现状(已隔离)。验收规程: 独立浏览器 profile 加载同一份 unpacked 扩展(= 测试扩展,存储天然独立),发现地址填 http://127.0.0.1:28788。生产扩展与公开默认 18788 零改动(§06 D4/D5: 「默认值翻转」路线被 agent 起桩实态否决)。

参数定案

  • 候选口 3→8(双侧常量 + 协议守阵同步,§06 D6);
  • 标签键 hr_check.channel.name,默认回落 data_dir 目录名 —— dev clone 目录名天然互异,真实多实例用户目录名撞车时显式设键(§06 D7);
  • 已知限制: 第 9 个 clone 无发现服务(数据端点不受影响),文档一句带过。

兼容矩阵(只加不改)

搭配行为评估
新后端 + 新扩展目标态: 响应单 clone + 标签 + 显式裁决设计目标

§07风险与对策

风险触发条件处置
单应答自动服务的赌注落空多 clone 机器上生产实例停机,dev clone 成唯一应答 → 扩展自动服务 dev接受并显式声明: 唯一=正确在单实例场景恒真,多实例场景被裁决分支拦住;名称列让当前服务对象显眼可见,可随时改选
Windows 排除段吞掉候选带部分端口18788-18795 部分落进开机预留段(netsh excludedportrange,每次开机不同,pitfalls/testing/consecutive-port-run.md)绑定顺延逻辑已有(_try_bind 逐个试),扩展对无应答口天然容忍;极端全吞 = 发现不可用但数据端点照常(现有语义不变)
旧扩展 + 新后端自动服务任意单 clone多 clone 机器上扩展未升级过渡态,严格优于混串现状;随扩展升级自然收敛,不做兼容代码
dev.run 注入改变真机验证的发现口用户想显式验证生产带发现行为P1 落地时留显式豁免参数;豁免是「故意的」,不属遗漏类
桩的 28788 被占/落排除段开机预留段恰含 28788 或残留桩进程现有报错 + port_kill 提示路径;人工 --discovery-port 换口(验收规程写明)
测试世界误用生产带(回归)后续改动把 18788 或 28788 字面绑进 tests/守卫测试扩展双向禁绑(18788 与 28788),S5 落地
