01方案裁决与范围划界

1.1 两个问题在 v2 上的合并解

报告 §02 的关键观察：v1 里「有观测」只能表达成「有一行」，于是单种图为了省磁盘不观测空闲（问题一：空闲 = 缺口 = 断线文案），全局图为了语义完整为空闲付出 90%+ 冗余零行（问题二：文件膨胀）。z 行补上缺失的行型——「廉价表达连续零速观测」——两个问题互为代价的关系解除：

  • 问题一（语义倒挂）：空闲段出现 z 行 → 桶有 (0,0) 观测 → 图上连续 0 平线；tooltip 0 值与缺口文案分离；空闲段不再断累计增量链；30d 单种图由 z 派生 hour 行（avg=0）带 0 线（§04/§05）。与 qB 桌面 / VueTorrent / Flood / ruTorrent 全体生态先例对齐（报告 §04.3）。
  • 问题二（体量）：全局空闲 24h 从 2,880 行零行（≈115KB）压成 ≈144 条行程行（≈6KB）；行程行自带 start/end 时间边界——不依赖间隔推算，采样间隔配置变更后新旧数据各自如实（报告 §05 候选 B 的核心优势，验收判据 4）。

1.2 范围划界（非目标）

  • 零新配置键：sample_interval / raw_window / rollup_window 口径全部不变；新增封口节奏为模块常量（§03.1），非配置键——黄金法则 2/4 免事务，config/schema/键面 fixture 全链不动。
  • API 响应形状不动：points/totals/meta 三段结构、金清单 75 条、鉴权与 last-good 兜底全部沿用；仅组空态判据一行补 z 行（§04.4）。
  • 组图语义不动：组不落盘、借 global.dat 判停机（traffic_grid.py:204–221）的原设计正确；z 行让全局观测表更满，组图语义自动受益，聚合函数零改动。
  • 不动前端图表机制：uPlot 双系列、spanGaps:false、悬停取值机制全沿用；只改文案与零桶标签（§05）。
  • 存量数据不迁移：双读单写，v1 文件原样保留直到自然滑出保留窗或首次 z 追加/重写时升级头行（R3）；旧 v1 空闲段显示为缺口，属历史数据如实呈现。本 clone 生产 config.yml 未启用 qb_traffic（零存量，已核实），他 clone 若已启用按上述规则自然过渡。

02格式 v2 设计（traffic_store.py）

2.1 行型定义

# auto-qb qb-traffic v2                      ← 头行版本号 = 双读门闩(原 v1 常量升级, traffic_store.py:113)
key,<系列标识>                               ← 不变
raw,<epoch_s>,<dl_rate>,<up_rate>,<dl_total>,<up_total>   ← 不变; 语义收窄为「非零速率采样行」
raw,<epoch_s>,,,,                           ← 不变; null 行(断连/缺字段), v1 v2 同形
z,<start_s>,<end_s>,<dl_total>,<up_total>   ← 新增: 零值行程行(Z_FIELDS = 5)
                                            [start,end] 闭区间按采样节奏观测, 速率恒 (0,0);
                                            totals 快照行程内恒定(无传输则 all-time 计数不增长)
hour,<hour_epoch>,<dl_avg>,<dl_max>,<up_avg>,<up_max>,<dl_total>,<up_total>  ← 列不变; 聚合口径扩展(§04.3)
  • ZRow 数据类：{start: int, end: int, dl_total: int, up_total: int}（恒非负整数，时间列整数秒，口径对齐 RawRow/HourRow）；ParsedSeries 增加 zruns: tuple = () 字段（默认空元组——v1 文件恒空，构造点向后兼容）。
  • 逐列冻结纪律：v1 行型（raw/hour/null）的列定义一字不改；v2 = v1 解析器 + z 行型（增量解析，非平行实现，报告 §06.1）。
  • 行程内 totals 恒定是设计契约：快照取行程开启时首个零样本的 all-time 累计对，后续零样本不刷新（§03.4 论证：刷新会让 qB 中途重启的计数器回落把 0 平线打出 null 洞）。

2.2 解析分发与坏行校验

  • 头行版本分发（parse_dat_text，traffic_store.py:217–277 扩展）：头行恰为 v2 → 接受 z 行；头行仍为 v1 → z 行按坏行计数（v1 语义逐字节不变，既有 42 用例零改动通过 = 双读回归的验收线）；其它头行维持「整文件记坏」现行口径。
  • z 行校验（宽松，防手编损坏放大影响面，报告 §06.3）：列数 = 5；四数值列经既有 _parse_int_field（空/负/非数值 → ValueError → 坏行）；end ≥ start 必查；end − start ≤ 86400（模块常量 ZRUN_MAX_SPAN_S，宽松上界——合法行程 ≤ ~1h+间隔抖动，超界即损坏）。违者一律按坏行跳过计数，走既有 5% 且 ≥2 行的损坏阈值隔离（traffic_store.py:509–528）。
  • 坏行影响面：一行坏 z = 一段空闲异常，比坏 raw 行大——三重封顶：校验拦截 + 损坏阈值隔离 + 行程封口节奏把单行程时长压在 ~1h 内（§03.1）；下次封口重写自洁（坏行不算内容一致，现行机制）。

2.3 写路径：append_z_run 与头行升级（R3）

  • append_z_run(key, start, end, dl_total, up_total)：与 append_point 同款追加纪律（open("a") + flush，崩溃丢 ≤1 行；尾部半行先补 \n；文件不存在则建头行 + key 行——头行直接写 v2）。
  • 硬不变式：绝不向 v1 头行文件追加 z 行。追加前检查头行版本，v1 → 先做一次内容保持重写（行不变，头行升 v2，绕过 same_content 短路）再追加。否则 v1 解析器把 z 行判坏行，反复追加会累积坏行触发整文件隔离——用测试钉死（P1 验收）。
  • 重写保留 z 行：_rewrite_file（traffic_store.py:415–443）输出序 = 头行(v2) + key + hour 行 + z 行 + raw 行；_seal_file 裁剪对 z 行按 end ≥ now − raw_window 保留（z 行属 raw 段数据，其派生 hour 行在 hour 段按 rollup_window 独立留置）；same_content 判定把 z 行纳入比较。
  • index.json 零改动：z 行不影响条目结构（format 1 不动）；惰性建文件/冻结/解冻/淘汰纪律全部沿用——空闲期 z 追加与 raw 追加同样推进 updated_at（动过的种子停做后不会因「无 raw 行」被误判超龄淘汰）。

03采样器：开放行程（open run）纪律（traffic_sample_mod.py）

3.1 行程结构与封口触发

每系列内存至多一个开放行程 {start, last_seen, dl_total, up_total, samples}（self._open_runs: dict[系列键, OpenRun]，主循环线程独占，黄金法则 5 不变）。速率 (0,0) 的采样只推进内存行程（last_seen / samples +1，不落盘、不建采样点、不动 baselines/latest——§03.4）；封口即经 append_z_run 落盘并移除行程。五触发：

#触发封口区间落盘形态
①非零样本到达[start, last_seen]先 append z 行，再 append raw 行（同轮两行，文件序 = 时间序，报告 §06.2）
②null 点到达（断连 / 关键字段缺失）
R2		[start, last_seen]先 append z 行，再 append null 行——z 覆盖不得横跨断连期，否则把「未知」虚标成「观测到 0」
③行程时长 now − start ≥ ZRUN_FLUSH_S(600)，每零采样检查
R1		[start, 当前样本 ts]append z 行，行程移除（下个零样本开新行程）——0 平线落盘延迟 ≤10min
④行程样本数 samples ≥ ZRUN_CAP_SAMPLES(120)同 ③同 ③（写侧保险，Prometheus head chunk 先例；interval < 5s 时先于 ③）
⑤小时封口扫描（_maybe_hourly_seal，traffic_sample_mod.py:347–379）全部开放行程先 flush-all（逐系列 append z 行，end = last_seen）再调 store.seal_sweep——hour 归并能看见全部行程（报告 §06.2 触发②）；断连轮照常触发（现行语义）
  • 常量非配置键：ZRUN_FLUSH_S = 600 / ZRUN_CAP_SAMPLES = 120 / ZRUN_MAX_SPAN_S = 86400 为模块常量（对齐 TRAFFIC_DIR_NAME 先例）。600s 取值理由：与最大采样间隔同阶，@30s 默认下 0 平线延迟 10min、空闲 z 行 144 行/天（≈6KB/天，仍 ≈20x 压于 v1 零行）；想要报告原样（仅小时封口 + 120 样本）删常量 ③ 即可。
  • 崩溃/重启：内存行程随进程消失——丢一段「零性」（≤600s 的纯零信息），与丢一行零行等价，无信息损失（报告 §06.2）；已落盘 z 行 / raw 行 / null 行不受影响，重启后零样本按纪律重新开行程。
  • dry_run / enabled=false：现行短路全部沿用——dry_run 不落盘（行程在内存照常推进，flush 触发静默跳过 append）；未启用不建任务零开销。

3.3 单种行程开启条件（拍板点落实）

防文件数失控（报告 §06.2）：零样本仅在「该系列已有数据文件或已开行程」时开启/延长行程。「已有数据文件」的判定 = index 条目存在（建文件与建条目同步，traffic_store.py:554–565；启动 reconcile 保证条目↔文件一致）——新增 store.has_entry(infohash) -> bool 公开方法（dict 查零样本轮询，每轮 ≤ 种子数次 dict 命中，无 IO）。语义恰为用户直觉：动过的种子停下 = 0 线；从没动过的种子 = 无数据（空态）——用户抱怨的是前者被画成断线，不是后者没有图。惰性建文件三闸（惰性建 / 空闲零 raw 行 / 删种冻结淘汰）全部保住。

3.4 baselines/latest 为何不碰：行程快照固定在开启时刻

  • 零样本不动差分基线：基线只在 raw 采样点推进（现状）。空闲段 all-time 计数本就不增长，下一活跃样本对「最后活跃基线」的差分与对「零样本假想基线」的差分同值；而 qB 中途重启（计数器回落）时，固定基线让重置在下一活跃样本的桶上如期现形（null + 恢复），与 v1 语义一致。
  • 行程 totals 快照固定在开启时刻、后续零样本不刷新——同理：若刷新，qB 空闲期重启会把更低的 totals 写进后封的 z 行，读侧差分在空闲段中段打出 null 洞，0 平线断裂。固定快照下，回落统一在下一活跃样本处现形（一处 null），平线本身完好。
  • 非零转轮的 totals 归因：最后活跃样本（totals T）→ 空闲行程（快照 T，采样间隙的残余传输使实际 T+Δ 时不刷新）→ 下一活跃样本（T+Δ+…）：读侧差分把 Δ 计入行程后首个活跃桶，累计只延迟归属、绝不丢失（快照差分链的性质）。
  • latest 镜像：零样本不产出采样点（镜像冻结在最后活跃点）——镜像本就是排障用途，不参与语义。

04读侧：行程展开语义（traffic_grid.py + store 聚合口径）

4.1 raw 段覆盖展开（_obs_from_raw 扩展，traffic_grid.py:117–142）

  • 相交即覆盖：z 行使其覆盖区间 [start, end] 相交的每个桶（桶 [b, b+w)，条件 start < b+w 且 end ≥ b）获得速率 (0,0) 观测，totals = 行程快照——空闲段在图上是连续 0 平线，中间没有可漏的逐点行（报告 §03.4 的全局抖动缺口问题免费消失）。
  • 混桶 raw 优先：桶内同时有 raw 行与 z 覆盖时（小数间隔下转轮桶可同时含最后活跃行与行程起点，罕见边缘），取 raw 聚合结果、z 覆盖让位——确定性规则，一个桶的粒度，图上不可见；测试钉住即可。
  • totals 续链（series_totals_points，traffic_grid.py:175–193）：z 派生桶携带行程快照进入相邻差分——空闲段每桶 delta = 0，链不断；其后首个活跃桶恢复有基线，「窗口累计」不再漏计空闲后的活跃增量（报告 §06.3）。计数器重置（qB 空闲期重启）仍在下一活跃桶现形为 null（§03.4），两向独立判定沿用。

4.2 hour 段聚合扩展（store._aggregate_bucket，traffic_store.py:454–470）

  • z 派生 hour 行：桶被 z 行覆盖 → 该桶可产 hour 行——单种空闲小时由此产出 avg=0, max=0 的 hour 行，30d 单种图从「整幅空白」变为带 0 线（报告 §06.3；P5 已做孤点渲染，此前缺的是 hour 行本身）。「桶内全 null 不产 hour 行」现行规则不变（null 行仍不参与）。
  • 加权均值：混合桶（同小时既有活跃 raw 行又有 z 覆盖）avg = (Σ raw 速率 + 0 × w) / (n + w)，权重 w = 行程与本桶交集秒数 ÷ 采样间隔（报告 §06.3「样本数估算，仅用于均值权重」）——混合小时的均值从 v1 的「活跃期均值」变为更真实的「加权小时均量」，30d 视图语义微变，docstring 写明口径。seal_sweep / seal_hour 签名增加 interval_s 参数（调用方从 config.qb_traffic.sample_interval 现取）。
  • 桶末快照：hour 行 totals 取桶末观测的快照——z 行覆盖桶末时即行程快照（空闲期计数不增长，与最后活跃样本同值，无歧义）；纯活跃桶沿用「最新非 null 行」现行规则。
  • catch-up 补封兼容：_seal_file 的待封桶集合扩展为「有 raw 行的桶 ∪ 被 z 行覆盖的桶」（due_before 口径同款）；行程跨小时边界（≤1h+抖动）时按交集拆权重进相邻两桶。

4.3 组聚合与辅助函数

  • 组三函数零改动（group_null_mask / group_rate_points / group_totals_points，traffic_grid.py:204–270）：它们消费桶观测表——z 派生观测进入成员/全局观测表后，组图空闲 0 线与停机断线的区分自动受益（全局 z 覆盖填满空闲桶 → 不再误判停机）。
  • earliest_row_ts（traffic_grid.py:196–201）：把 z 行 start 计入最早观测（z 行是一次真实观测）。
  • ParsedSeries 消费面：read_series / read_series_checked / 损坏阈值管线零改动（zruns 随解析结果自然携带）。

4.4 API 层一处小改（traffic_qb.py）

组空态判据 all(not p.raw and not p.hours …)（traffic_qb.py:152）补 zruns：成员文件可能只剩 z 行（raw 行已滑出 24h 窗、hour 行未封的窗口内）——判「从未产过流量」须含 not p.zruns。其余端点逻辑（空态、last-good、window 校验、鉴权）零改动；单种全空闲窗口因 z 派生桶非 null，自然不再触发全 null 空态（报告 §07 症状三），「从未传输」保留空态文案（§05）。

08风险与缓解

风险等级缓解
一行坏 z = 一段空闲异常（影响面大于坏 raw 行）中三重封顶：宽松校验（end≥start + span ≤ 86400）→ 既有 5% 且 ≥2 行损坏阈值隔离 → 600s/120 封口节奏把单行程压在 ~1h；重写自洁（坏行不算内容一致，P1 钉）
0 平线落盘延迟（未封口行程在图尾呈缺口，文案在该窗口不精确）低修正 R1 把窗口从 ≤1h 压到 ≤10min；§05 已声明残留；不可接受再议 API 形状增强（拍板点保留）
双读复杂度（v1/v2 解析并存一个版本周期）低v2 = v1 解析 + z 行型（增量非平行）；头行分发单点在 parse_dat_text；本 clone 零存量；「未升级不追加 z」硬不变式 + 测试钉住
混合小时 avg 语义微变（活跃期均值 → 加权小时均量）低报告 §06.3 明文口径；更真实反映小时均量；docstring 与变更记录写明；纯活跃 / 纯空闲桶数值不变
压缩比估算偏差（报告 5–10x 为 raw 段口径）低§6.2 已修正为全文件 ≈3.5–5x（hour 段地板）；P5 以真实工况实测入基线切片，验收判据 3 的 ≥5x 目标改按 raw 段口径核
单种恒采遍历开销（每轮遍历 by_hash 判零样本）无遍历本就发生（活跃过滤只是 skip）；行程 = 每系列一条小 dict；has_entry 为 dict 查——可忽略（报告 §8.1 同判）
