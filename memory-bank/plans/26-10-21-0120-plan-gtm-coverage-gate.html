§01目标与设计原则

主仓覆盖率已经靠「阈值 + 基线切片 + watchlist」压到 99.41%(见前序计划 R5), 但工具侧 tools/global-traffic-monitor(下称 gtm)这半边完全没有门禁: 它有 10 个测试档、303 个用例, 却既不产出覆盖率, 也不在 CI 里跑。而 gtm 与主仓是跨进程契约的两端——主仓 webui/tool_client.py 调 gtm 的 POST /subscribe、/heartbeat、/unsubscribe、/config, 主仓侧这条链有 99% 门槛守着, 工具侧裸奔。契约漂移不会在提交时红, 只会在用户那边以「订阅莫名其妙失效」的形式出现。

所以本计划要拿到的是三样东西, 按此优先级:

  1. 门禁存在且真能拦(P0, 零覆盖增量即可交付)——任何人往 gtm 加未测代码, 提交即红;
  2. 可测面推到位(P1–P3)——把 230 个单位缺口里「本来就该测、只是没人测」的部分清掉, 推到 96 区间;
  3. 机制化(§05)——阈值阶梯、双平台切片、变异红验、豁免治理、与主仓的联动跑法, 让它不再回沉。

设计底线(不变量)

#不变量为什么
I1口径独立, 不合算: 工具侧阈值只写在 tools/global-traffic-monitor/pyproject.toml 的 [tool.pytest.ini_options] 里; 主仓 pytest.ini 的 --cov=src 与 --cov-fail-under=99 一个字不改两套分母混算会互相稀释: 工具侧 90% 会把主仓 99% 拉下去, 主仓 99% 会把工具侧门槛变成一句空话。另见坑档 testing/nested-pytest-config.md(子包必须自带 ini, 否则向上拾取根配置)
I2阈值恒低于当期实测, 且取双平台较低者再留 0.8–1.0 点余量gtm 的平台分支(winreg / systemd / launchd)天然只在一边可执行, 两侧覆盖率不可能相等; 用高的一侧定档, 另一侧每次都假红
I3不靠 pragma 冲数字: 平台分支一律走注入替身(installer 已内建 runner / registry / home / uid 注入点), 现存 1 行 pragma: no cover(units.py:54)只减不增豁免是治理对象, 不是提分工具。主仓第二轮已把「豁免只减不增」写成机制, 工具侧从第一天就照办
I4零真实副作用: 不写真实 %LOCALAPPDATA%/global-traffic-monitor、不写真实注册表、不起真子进程; tests/conftest.py 的 hermetic 守阵(真实指针目录前后快照比对)必须持续全绿门禁让测试被更频繁地跑, 副作用类问题的暴露面同步放大
I5一条命令可复现: 本地 commands run test.gtm 与 CI 跑同一份 addopts, 不靠人记参数靠人记参数的闸门等于没有闸门; 主仓 test.one 加 --no-cov 就是这条的镜像教训

2.3 为什么 T2.6 的「起步 85」要上调到 88

T2.6 定 85 时手上没有实测值(工具 venv 坏, 取不到数), 只能给一个保守下限。现在实测 90.4%, 若照 85 落地: 门槛与实测差 5.4 点 ≈ 130 个单位——等于允许任何人往工具侧塞 130 行未测代码而闸门不响, 门禁形同虚设。取 88(实测 − 2.4 ≈ 58 单位)的理由: ①第一次上闸要给双平台差异与口径迁移留缓冲, 不能贴着实测; ②58 单位仍远小于「一个中等功能」的量级, 拦得住真实回沉; ③P1 之后立刻抬到 91, 88 只是过渡档。

为什么不把工具侧并进主仓那套门槛

技术上可行(CI 里多跑一步), 但会带来三个立刻的坏处: ①分母污染——主仓 --cov=src 只覆盖 src/auto_qb, 并入 src/gtm 后 2405 个单位会稀释主仓 99.41%, 阈值必须整体下调, 等于把主仓刚赎绿的门槛又拉红; ②平台差异放大——主仓 CI 是 ubuntu + windows 双矩阵 × 双 python, 工具侧门槛要在 4 个组合里同时成立, 定档难度翻倍; ③依赖耦合——工具侧刻意只依赖 psutil/filelock/pyyaml 且自带锁, 并进主仓环境就破坏了这个「auto-qb 依赖变动不影响工具」的设计。所以走独立 job + 独立阶梯。

§04实施步骤

排序原则: 先把闸门装好(哪怕一行测试不写), 再清「整块空洞」, 最后收「容错出口」长尾。每阶段独立可提交、独立可验收; 预估单位按 §2.1 换算, 完成时以工具目录内 uv run pytest 实测为准。
