§01目标与设计原则

背景

用户报「WEBUI 种子移动中的状态显示为了『其它』」。实为一个三层判定链的最末端表象: qB 的原始 state 串 moving, 落到后端分类函数时被兜底成 other, 再由前端文案表翻成「其他」。同一颗种子在抽屉详情里却显示「移动中」, 两处自相矛盾。

目标(做到什么程度算成)

moving 在全部四个消费面上都成为一等公民:

消费面今天修完之后
显示主表 / 组行 / 追剧集行显示「其他」显示「移动中」, 与抽屉详情口径一致
筛选状态下拉里没有这一项, 筛不到下拉与分布条出现「移动中」并可点击筛选
聚合被算进「其他」桶独立成桶, 组态按 §03 的 rank 位参与争夺
命令被判为「活跃」, 强制汇报可点可发按非活跃拦截, 删除前汇报跳过

设计底线(不变量, 违反即视为改坏)

  1. 不动第三方库的谓词。只在项目自己的 state_kind() 里加分支, 不 patch qbittorrentapi.TorrentState —— 谓词集合是上游定义的,「MOVING 是孤儿成员」是上游事实而非缺陷, 修错层会导致依赖同步时回归。
  2. 前后端两张优先级表必须同步。views.py::_SHOW_STATE_RANK 与 app.js::STATE_RANK 由 tests/test_webui_static_skins.py::_scan_state_rank 机械比对, 改一边不改另一边必然染红。
  3. 命令闸门前后端两表必须同步。commands.py::REANNOUNCE_BLOCKED_STATES 与 decorate.js::REANNOUNCE_BLOCKED_STATES 由 tests/test_webui_static_dom_panel.py 断言集合相等, 差一项就红。
  4. 不新增颜色令牌、不新增 sprite symbol。现有色板 --blue/--paused/--green 足以表达 moving; 新增令牌会撞三皮肤令牌名相等的守阵, 新增 symbol 要同步改三份 index.html 的内联 sprite 并检查 67 symbol 逐字相等。这是把改动成本按在地板上的关键约束。
  5. 范围守恒。抽屉三份 STATE_TEXT(drawer_tpl/01/02/03)与 kindText 的四份重复文案属既有技术债, 不在本计划内重构, 按 create-issue 流程入池。

§02现状与痛点

根因链

qB WebUI 返回 state = "moving"
        ↓  TorrentState("moving") == TorrentState.MOVING
六个谓词集合全部不含 MOVING  ← upstream 事实
        ↓
WebviewMixin.state_kind()  (views.py:177)  一路判空 → return "other"
        ↓
decorate.js:145  kindText → "其他"
        ↓
主表状态列 / 组行 / 分布条: 「其他」   ← 用户看到的 bug

而抽屉详情走的是另一条路:drawer_tpl/01-general-hero-tall.js:31 等三处的 STATE_TEXT 直接按 qB 原始 state 取文案, 早已写着 moving: "移动中"。两条从不交叉。这就是同一颗种子自相矛盾的来源。

证据: qB v5.3.0 的 19 个 state 全映射(逐一核实)

结论: 当前目标的 qB 版本里, moving 是唯一一个「会出现、却归错类」的状态。

第三方库里多出来的三项: 历史遗产

qbittorrent-api 的 TorrentState 枚举有 22 个成员, 比上游多了三项。逐一定性:

多出项上游现状归类风险
allocatingqB v5.3.0 源码全文无此符号; libtorrent 里 allocating = 6 被 #if TORRENT_ABI_VERSION == 1 包住并标 TORRENT_DEPRECATED_ENUMother(同为孤儿成员)⚠ 老版 qB 才出现, 一旦出现即复刻同一个 bug
pausedDL / pausedUP旧名, 已被重命名成 stoppedDL / stoppedUP, 库中保留作兼容paused无害(命中 is_stopped)
顺带钉住两条源码事实(后面用到):
① moving 是强遮蔽态。torrentimpl.cpp:1289-1347 的 updateState() 里, Moving 的判定顺位仅次于 checking_resume_data, 高于 MissingFiles 与 Error —— 也就是说搬迁期间文件丢失或报错, qB 给出的 state 仍是 moving。这就是 moving 必须独立成档的第二个理由: 混进 other 会让搬迁期的任何异常都不可见。
② moving 期间传输是真的停的。libtorrent 搬数据时所有 peer 传输都会让位, 这也是 §03 把 moving 判为「非活跃」的上游依据, 与项目自身 relocate_units.py:464 的 GATE_MOVING(对 moving 成员再下发命令即阻塞)同源同判。

§03方案总览

主线

  1. 后端分类:state_kind() 在 is_stopped 之前插入 MOVING 分支, 返回新 kind "moving"。插入位置须在 is_stopped 之前 —— moving 不命中任何谓词, 放哪都行, 但放此处与「先判特殊态」的现有读法一致。
  2. 前端枚举/文案/分布: app.js 的 STATE_RANK、decorate.js 的 kindText/kindIcon、dialogs.js 的 distSegments order, 三张硬编码表各加一项(详见下表)。
  3. 三皮肤着色: 复用现有色令牌, 新增 .k-moving / .s-moving 两套选择子。
  4. 命令闸门: moving 按「非活跃」处理, 前后端两表同步加项。
  5. 测试补位: 既有 parametrize 的期望值从 ("moving","other") 翻成 ("moving","moving")。

§05待拍板清单

P1 · allocating 怎么处置

已拍板 2026-10-29 已采纳 A: 并入 moving 同档 —— state_kind 的一条分支同时收 MOVING 与 ALLOCATING。

它是第二个孤儿成员, 但当前目标版本(qB v5.3.0)根本不产出它。风险窗口取决于生产环境实际跑的 qB 版本。

  • A(推荐) 并入 moving 同档。ALLOCATING 与 MOVING 同为「qB 在动磁盘、不传输」的合成非活动态, 且当前版本出现概率≈0。成本近乎为零(与 S1 同一行分支), 即使误合并, 用户看到的也是「移动中」而非「其他」。
  • B 单独第 8 档。文案「分配中」, 语义最准, 但 CSS 与四张表的改动量翻倍。
  • C 本次不动, 入池跟踪。严格守住 Q1 批准的范围不放。前提是能确认生产环境连的 qB 不会产出 allocating; 确认不了则回落到方案 A。

P2 · moving 在 rank 表里的位次

已拍板 2026-10-29 已采纳 A: moving: 5, 原 other: 5 顺延 6(不扰动已验证顺序)。前后端两张表同步。

决定「一组里既有常规状态又有 moving 成员时, 组行显示哪个」。现有顺序是踩过两次坑调出来的(app.js:871-876 注释留着事故史)。

  • A(推荐) 排 paused 之后、other 之前。即 moving: 5, 原 other: 5 顺延为 6。理由: 不扰动任何已验证的相对顺序, moving 与 other 相邻、语义同属「非典型态」。
  • B 紧邻 error(moving: 1), 其余顺延。理由: moving 是「别插手」的临时锁定态, 应当高于常规活动态; 且本系统搬迁是整组行为(relocate_mod 按组下发), 组态如实显示「正在搬」更贴近真实。代价: 重排五个已验证的位次。

P3 · 「其他」要不要改成「未知」

已拍板 2026-10-29 已采纳 A: 本次不改。other 先收敛回 unknown 单一来源; 改文案会溢出到 drawer.html:34 与 drawer_head.js:18 的 tone="other" 两处, 另开一轮查清再动。

拆分 moving 之后, other 理论上只剩 unknown 一个来源, 「未知」更诚实。但有一个已知陷阱: 流量抽屉把 tone="other" 硬写在 tpl/drawer.html:34, drawer_head.js:18 的 tone default 值也是 "other" —— 改文案会溢出到那两处。

  • A(推荐) 本次不改。先把 moving 分出去, 让 other 收敛回单一来源; 若收尾时仍看到「其他」字样, 单开一轮查清 tone 消费面再改。
  • B 本次一并改为「未知」, 同时排查两处 tone 消费。

P4 · 是否给 moving 加 e2e 断言

已拍板 2026-10-29 已采纳 A: 加 —— e2e/state-moving.spec.mjs(prism + atlas 双皮肤绿)。

  • A(推荐) 加。在 e2e/ 补一条「state=moving 的种子主表显示移动中」的用例, 钉住本次行为的回归面。
  • B 不加。只靠 pytest 守 classify。
