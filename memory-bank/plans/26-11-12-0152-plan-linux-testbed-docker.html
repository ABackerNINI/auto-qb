§01目标与设计原则

背景

认领 issue 26-11-12-0053 两缺口: ①test.linux 引擎包装超时 900s 已不够 —— 仓库 478M 走 docker bind 挂载 cp -a 实测 ~1MB/s(光拷贝 ~10 分钟), 加 uv sync + 全量 pytest 合计 ~15 分钟; 超时杀包装进程后容器成孤儿(docker run 客户端死、容器不随 --rm 退), 输出全丢。②默认镜像 python3.12 与 .python-version=3.13 错位, uv 补下载托管 CPython(源在 github)容器内不通 → uv sync 直接失败。

但本计划不止修这两点: 用户拍板「彻底解决 linux 测试端」, 把 pytest / e2e / 变异测试三个 Linux 面统一到一个可移植、可重建、可清扫的体系(变异残留一并纳入, 用户 2026-11-12 显式授权)。

目标(G1–G5, 做到即成)

  • G1 环境一次性搭好: Dockerfile 入库, 镜像烘焙(apt 系统依赖 + 双 Python venv 模板 + node + playwright chromium + npm 依赖); 他机重建 = clone 仓库 → commands run test.linux-env 一步到位。
  • G2 复制仅拷代码: 排除清单式 tar 流推送(剔 __pycache__ / .venv / node_modules / dist / .tools / auto-qb-data 等; .git 必须随拷 —— test_commands_engine 的 find_root() 靠向上找 .git, 坑档 pitfalls/testing/attachments/patching-local-linux-repro.md 实证)。478M → 约 183M(含 .git 99M), 且走 exec 管道不走 bind 挂载。
  • G3 残留统一: 容器内一切测试态(代码副本 / venv / 变异镜像仓 / pytest 实例根)收敛 /root/auto-qb-tests/ 单根; 宿主 docker 面与 WSL 侧旧残留清空(§04 S5)。
  • G4 并行隔离: 每会话独立 workdir, TMPDIR 实例根 / 动态端口 / 写重型锁(按仓库路径 hash 分锁)天然隔离; 允许多会话同时跑全量。
  • G5 双缺口根治: 超时改分层(引擎 1800s + 容器内 timeout 内层先到, 干净退出); 「孤儿容器」随 docker run --rm 形态退役 —— 常驻容器 + exec, 无容器生命周期问题; exec 客户端被杀的残留进程由下轮 workdir 级 pid 清扫兜底。

设计底线 / 不变量

  • 环境即代码 > 手工态: 镜像可弃可重建; 容器内不留「必须手工抢救」的状态, 重建即净室。
  • 幂等: test.linux-env 重跑无害(hash 未变 = 秒级 no-op); 清扫一律「内嵌 pid 已死 + mtime 超龄」双条件(与 tests/_tmp_bootstrap.py 同款纪律), 绝不按名字猜删。
  • 白名单清扫: 宿主 docker 面只动 auto-qb 相关物, 不碰同机 PT 工具容器(downonly / IYUUPlus / tr-bitcake×2 / pt-accelerator, 2026-11-12 docker ps -a 实录)。
  • CI 不动: .github/workflows 零改动; 本体系只做「本机复现 Linux CI」, 交付与否仍只看 Gitee。
  • 生产口径: 失败行 / 清理指引 / 报错文案按生产标准写(失败行自带下一步), 不留糙面。

§02现状与痛点

现链路

commands run test.linux(.commands/test/scripts/linux_ci.py)= docker run --rm uv 官方镜像 python3.12-bookworm-slim, 容器内全量 cp -a → 删 .venv → uv sync → 全量 pytest; 引擎 timeout=900s(.commands/test/config.toml:53)。WSL 路线被坑档记为「可能被安全策略拦」(2026-09-22 实测 wsl.exe 命中 Program Blacklist), 且即便可达也只有变异测试在用。

痛点证据(2026-11-12 实测)

  • 拷贝面大而无当: 478M 工作树构成 —— __pycache__ 82M / .git 99M / node_modules 21M / dist 26M / memory-bank 39M / tests 91M / src 13M; 按排除清单(含 .tools 的 vnu.jar 31M)剔除后真正要拷的「代码+测试+被测试扫描的文档面」约 84M, 现在每次全搬。
  • bind 挂载 ~1MB/s(issue 26-11-12-0053 实测): 光拷贝 ~10 分钟, 900s 包装超时必炸成孤儿容器。
  • Python 版本错位: 3.12 镜像 + .python-version=3.13 → uv 补下载托管 CPython, github 容器内不通(容器通 PyPI 200), uv sync 直接失败。
  • node 缺失面: e2e(playwright, 根 node_modules 21M + package-lock.json 在库)只在 Windows/CI 跑; WSL Ubuntu-26.04 内 Linux node 不存在 —— 现有 npm 是 Windows 侧 /mnt/h/Programs/nodejs/npm 经 interop PATH 泄漏的假货(实测 node 不存在而 npm --version 出数); 另一会话在 docker ubuntu 裸镜像同样撞「无 node」。
  • 残留实测: WSL 侧 7 个 mutmut 镜像仓 ~/auto-qb-mut*(base/core/hr/hr-display/hr-svc/rules/w8fix)共 ~1.63G(各含独立 .venv)+ ~/.cache/uv 258M; docker 侧孤儿卷 auto-qb-uv-cache 48M(2026-10-11 建, 来历不明)+ 可回收镜像层 1.8G + 构建缓存 650M。
  • 变异体系绑死 WSL: mutation-testing skill 8 条硬约束含多条 WSL 专属坑(打挂要 wsl --shutdown 才救回 / /mnt IO 52s/116MB / zsh 壳 $PWD 失真 / .wslconfig 限 8 核); 镜像仓与 pytest 测试态分裂两地, 清扫纪律两套。

§03方案总览

形态主线(D1–D7 落点)

Docker 常驻容器 auto-qb-testbed(基底 ubuntu:24.04 对齐 CI ubuntu-latest; --restart unless-stopped), 会话一律 docker exec 进容器干活; 容器重建 = 净室, 镜像重建 = 环境刷新, 宿主侧零长期态。Docker Desktop 本身就跑在 WSL2 后端 VM 里(同 8 核 / 12G 预算, .wslconfig), 选容器不选裸 distro 的决定性理由是环境即代码可移植重建(用户拍板理由)。

镜像分层(贪心缓存序; tag 带 uv.lock hash8 锁版本)

  1. 系统层: ubuntu:24.04 + apt —— python3.12(含 venv 模块)、git、tar、rsync、curl + NodeSource LTS nodejs(与 CI lts/* 同源)+ playwright 系统依赖。3.13 不走 apt(noble 官方源无 python3.13, 评审轮 1 引 ubuntu.com 可用性页实测; 3.13 走构建期烘焙, 见烘焙层)。
  2. uv 层: pip install uv 走国内 PyPI 镜像(依赖面国内镜像站优先, D8); ghcr COPY --from 降为备选(github 系直连, 不通走人工代理)。
  3. 环境变量层: ENV UV_PYTHON_DOWNLOADS=never —— 运行期零下载(两个解释器都已进镜像, 发现即用); issue ② 由「构建期烘焙 + 运行期禁取」结构性根除。另烘 UV_DEFAULT_INDEX/UV_INDEX_URL=国内 PyPI 源(只管 export/pip 面;运行期 delta 走 pip 路线, 见 §10 R4)。
  4. 依赖烘焙层: 拷 pyproject / uv.lock / package.json / package-lock.json → RUN UV_PYTHON_DOWNLOADS=manual uv python install 3.13(RUN 级作用域覆盖 ENV 层的 never —— 否则显式 install 也被拦, 构建自锁, 评审轮 2 引 uv#7340; 托管 CPython 源 github releases —— D8 落点: 直连优先, 失败停手请用户手动开代理; 备选 deadsnakes PPA, launchpad 直连)→ uv export --format requirements-txt --no-hashes(S1 下半实跑修正: 0.13.7 已移除 --generate-hashes 旗标, 现行不带; 钉版由 --frozen 导出锁文件版本清单保住) + uv pip install -r --index-url 国内镜像 ×2(3.12 = 系统 apt / 3.13 = 托管; R4: uv sync --frozen 跳过 index 校验、按 uv.lock 的 files.pythonhosted.org 绝对 URL 下载, 镜像索引对它无效, 见 §10)→ /opt/venv-3.12 与 /opt/venv-3.13 模板; npm ci(registry.npmmirror.com)→ /opt/e2e-node; playwright chromium --with-deps 烘焙(二进制走 npmmirror 镜像)。
  5. 网络策略: 见下「网络策略」节(D8)。

网络策略(D8, 2026-11-12 用户拍板)

镜像与依赖一律国内镜像站优先; github 系资源直连; 连不上 → 停手请用户手动开代理, 代理开着重跑——脚本不内置代理、不自动重试、代理地址不进代码。落点与候选:

  • 基底镜像 ubuntu:24.04: Docker Hub 国内镜像源优先(候选: 清华 / DaoCloud / 1ms 等, 实现时实测钉值记入 task note, 可配置不写死); ghcr 直连仅在备选路线用到。
  • apt 层: 换清华/阿里 ubuntu noble 源(main + updates + universe)。
  • PyPI(uv 烘焙与运行期 delta): 清华/阿里 PyPI 镜像, 经 uv pip install --index-url 显式传入(UV_DEFAULT_INDEX/UV_INDEX_URL 烘进 ENV 只管 export/pip 面 —— uv sync --frozen 跳过 index 校验、按 uv.lock 的 files.pythonhosted.org 绝对 URL 下载, 对它无效, 机制事实与改法见 §10 R4)。
  • npm: registry.npmmirror.com; playwright 浏览器二进制: PLAYWRIGHT_DOWNLOAD_HOST 指 npmmirror 镜像。
  • github 系(ghcr / github release 等): 直连优先; 失败 → 失败行「停手 + 开代理指引」, 用户手动开代理后重跑(S1 停手点)。

代码同步(D4: 推模式)

排除清单 tar 流: 宿主 tar --exclude=… 打包工作树(含 .git 与未提交 WIP)→ docker exec -i 解到 /root/auto-qb-tests/<slug>/code。排除清单: __pycache__ / .venv / node_modules / dist / .tools(vnu.jar 31M, gitignored 本地件, 容器不烘 java 用不上) / .coverage* / .pytest_cache / .ruff_cache / auto-qb-data / tmp-analysis(dist 已 grep 实证零测试引用); memory-bank/ / resources/ / docs/ / tools/ / .commands/ / .agents/ 必须随拷(tests/conftest.py、helpers.py、kb 守阵引用面, 2026-11-12 grep 实证)。首建 workdir 后 cp -a 模板 venv → uv export --no-hashes + uv pip install 补项目 editable 与依赖 delta(S2 实测「cp 模板 vs 全建」取快者; 不用 uv sync —— R4 机制事实, 见 §10)。

workdir 布局与并行(D5)

/root/auto-qb-tests/<slug>/(slug 由会话 --name 传参或自动 pid+时刻生成); 每会话一个, 互不相见。隔离面: pytest TMPDIR 实例根(bootstrap 自举, 收 auto-qb-tests 标记路径)、端口动态取号(tests/_test_ports.py 既有纪律, 需补核 test_hr_server.py:920 写死 discovery_port 一处)、写重型锁按仓库路径 hash 分锁 —— 每会话 workdir 路径不同, 锁互不相撞。

§07风险与对策

编号风险 / 触发条件处置
R1ghcr COPY --from 直连失败(github 系)主线本就不走它: uv 改 pip install 走国内 PyPI 镜像(D8); 若坚持 ghcr 路线, 直连失败 → 停手请用户手动开代理后重跑, 不自动重试
R2NodeSource 源不可达(nodesource.com 非 github 系, 直连)降级 apt nodejs(24.04 = 18.x, playwright 1.63 兼容 ≥18); npm 与 playwright 二进制本就走 npmmirror 不受影响
R3tar 流吞吐不达标(Git Bash tar + docker exec -i 管道, 首跑实测 ~183M)降级容器内 rsync 增量(从 /src 只读挂载, delta 小; 1MB/s 慢面只伤首轮)或 git bundle 差量
