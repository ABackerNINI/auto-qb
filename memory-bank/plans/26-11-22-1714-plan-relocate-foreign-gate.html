§01目标与设计原则

为什么做

7 件同属 relocate-foreign-gate 收尾簇: 2 件 bug 是生产必现面(dir_alias + 同根兄弟布局的删链门假依赖自锁不可自愈; 差集窗口与 2S tick 拍频错位致 foreign 活到达漏接约 1/4), 4 件观测性/交互问题是 S4 排障断链的直接原因(daemon 续任零日志、在账扫描零痕迹、confirm 三步交互无预告、武装行内部命名泄漏), 1 件收编兑现归组副本 docstring「不引入第二套语义」的既有承诺。

做到什么程度算成

  • 3 批全部 ship(每批独立 code-review + 提交, 批间互不阻塞);
  • 判定/游标/文案面全部单测钉住, 既有全量无回归;
  • 真机 S4 复验清单(§04 批3)五项通过(用户跑);
  • 7 个 issue 翻转 Closed 并回填实际修法/验证方式/测试数字; 档案 26-11-22-backend-relocate-foreign-gate.md 追加 R3 修复轮节;
  • 收尾按会话协议: test.full + 新基线切片(数字实测誊写)。

设计底线/不变量

  1. 不动 chain_gate_hits 候选面本体与 qbapi D16 消费 —— 精判落点在 relocate_exec._chain_gate_deps 消费侧; D16 调用形态 root==equal_root, 等值面在其冗余, 且自带 R3 交集豁免(qbapi.py:316-320);
  2. 黄金法则不破: 消费即排空发生在主循环单线程内; 无新配置键; 保守默认(清单不可得宁拦勿漏);
  3. D13「无周期兜底」拍板维持 —— 不新增 arm 等待期周期扫描;
  4. 重放不带 confirm 位的安全语义(「绝不代用户点头」, relocate_exec.py:130-131)不改行为, 只改回执文案预告;
  5. 历史计划 HTML(0434 等)不改写 —— 口径以档案 R2/R3 为准(档案已记录 0434 R3 行成因注记不准的修正)。

F1 判别口径(本计划核心一句)

目录级 job 的等值面命中(_norm(sp) == _norm(equal_root))且 scope 在场 → 逐记录取文件清单, 按「任一文件落 scope 下」判别: ru.under_alias_root(os.path.join(sp, rel), (anchor,)) 任一命中 = 依赖保留; 全不命中 = 兄弟假依赖豁免; 清单不可得/空 = 保守计依赖(宁拦勿漏, D10)。

为什么用 per-file「任一文件落 scope 下」而非「内容根 == scope」: 混合布局(部分文件落 junction、部分落真实兄弟目录)也是真依赖, 内容根判别会误豁免; per-file 判别统一覆盖纯落进/混合/兄弟三态。等值面原意(chain_gate_hits docstring :2158-2163)是拦「经别名落进作用域的组外种子(save_path 恰等 job.src)」的真依赖 —— 本精判只豁免可证明不经别名的兄弟, 真落进与混合全部保留, 2076c889 的拦截意图不动。

范围限定: 精判只作用于等值面命中(sp 归一恰等 equal_root)—— scope 前缀面命中按几何即真依赖(数据落 junction 树)不精判; 祖先格命中在 chain_gate_hits 内已带内容根覆盖判别不重复; file job 维持既有 R2 交集精判; scope 缺失旧账(anchor 回落 src)不精判维持保守(与旧锚同口径)。

F2 游标口径

store 侧「自上次消费以来累积」: 拍首清空行删除(零变化轮不再抹账 —— 结构根因), 轮末改 pending | added 累积(基线轮整体不计、断连清空、重连基线语义保留); 字段改名 last_added_diff → pending_added_diff(名字不再撒谎); 新方法 take_added_diff() 返回并清空, relocate_foreign 消费即排空。已核实全仓唯一消费方, 排空不偷数据。
