关键设计细节

4.1认证门首帧(FX-01)

根因是"首帧状态未知却被当成已知"。修法把初始值从"未授权"改为"未知(验证中)", 三条明确路径才能离开该状态 —— 与 fail-closed 一致: 由"假定要密钥"变成"假定正在验证", 最坏情况只是多一次加载态, 而不是把密钥表单闪给用户。 

// app.js data(): 初始即"验证中"(遮罩显示加载卡而非表单)
authRequired: true,
bootstrapping: true,      // was: false —— 这一行就是"闪现输入界面"的根因

// mounted(): 只有这三条路径离开 bootstrapping
1) pub.web.skip_local_verify  → authRequired = false           // 本机免鉴权, 直进
2) savedToken 验证通过        → authRequired = false           // bootstrap() 成功分支
3) 无 savedToken / 验证被拒    → bootstrapping = false           // 才渲染密钥表单

配套: 加载卡加 min-height(与表单等高的占位), 避免"加载卡 → 表单"本身的高度跳动; 并把它写成 CDP 可断言项(见 §07.2), 让"第二次出现"的这类回归以后能被测试挡住。

4.2表格口径单点化(FX-02/03/04)

现状: 三条口径的表达式在模板里各出现三次(明细表 / 种子页 / 追剧集明细), 且逻辑直接写在 {{ }} 里。本轮把三条口径收成 methods, 模板改为调用 —— 这既是本轮三条诉求的实现方式, 也顺带消掉"改一处漏两处"的结构性隐患。 

/* methods 新增三个派生函数(返回值语义 = 单元格显示文本, 空串即不显示) */
cellSeedingTime(m) {                       // FX-02
  const t = m.seeding_time || 0;
  if (t <= 0 && !(m.hr_triggered && m.hr_req_time)) return "";   // 0 分钟且无 HR 要求 -> 不显示
  return this.fmtDuration(t);
}
cellPeers(m, dir) {                        // FX-03: dir = "seeds" | "leechs"
  if (m.kind === "paused") return "";      // 暂停种子不显示用户/做种
  return dir === "seeds"
    ? this.fmtPeersQb(m.num_seeds, m.num_complete)
    : this.fmtPeersQb(m.num_leechs, m.num_incomplete);
}
cellRatio(m) {                             // FX-04
  if (!m.progress) return "";              // 进度为 0 的种子不显示分享率
  return (m.ratio || 0).toFixed(2);
}

HR 前缀保留: 做种时长列在 HR 已触发时仍显示 / 要求时长, 所以隐藏判断必须带上 hr_triggered && hr_req_time 条件 —— 只看 seeding_time <= 0 会把"HR 要求但还没开始做种" 的种子一起隐藏掉(那正是最需要看见的一类)。 对齐占位: 隐藏用空串而非 v-if 移除节点 —— 单元格仍在 grid 里, 列宽与表头不会错位。

4.6选择模型: 互斥 + 派生(FX-11/12)

现状是"两个并列数组, 各视图各看一个"。目标模型是一个权威 + 一份派生: 权威仍是两个数组(组 key / 成员 hash), 但入口处互斥; 所有视图的选中态一律读派生集合。 

// 1) 互斥(FX-11): 入口处清另一侧, 并给一次轻提示说明口径已切换
toggleGroupSel(g)  { this.selMembers = []; ... }     // 选辅种 -> 清种子选择
toggleMemberSel(m) { this.selGroups  = []; ... }     // 选种子 -> 清辅种选择
// shift 系列(shiftGroupSel/shiftMemberSel/shiftTorrentSel) 与 clearSelection 同步改

// 2) 派生(FX-12): 组选择 -> 成员 hash 闭包, 供所有视图读
selHashSet() {                                        // computed
  const s = new Set(this.selMembers);
  for (const k of this.selGroups) {
    const g = this._findGroup(k);
    if (g) for (const m of g.members) s.add(m.hash);   // 虚拟行只有 1 个成员
  }
  return s;
}
// 3) 三视图统一读派生集合
种子页 .torrent-row   :selected = selHashSet.has(m.hash)
追剧集明细 .member-row :selected = selHashSet.has(m.hash)
追剧剧行/集行          :selected = 该集全部成员 ⊆ selHashSet; :partial = 命中但非全选
辅种页 .group-row      :selected = selGroups.includes(g.key); :partial = 派生集合命中其部分成员
  • 批量条计数不随视图漂移: selGroups 非空就报 N 个辅种(即使当前在种子页), selMembers 非空报 N 个种子 —— 用户切视图时看到的"已选"口径保持不变, 这是"打通"的直观体现;
  • 批量目标: _bulkTargets() 按 selMode 只出 keys 或只出 hashes(不再混发); 后端 _cmd_bulk_torrents 已同时支持两者, 无需改后端;
  • 追剧页选中入口: 剧行/集行保留"点击 = 展开"的原行为(不破坏现状), Ctrl/⌘+点击 = 选中该剧/该集全部成员, Shift+点击 = 范围选择(与表格一致的修饰键语义);
  • 半选态需要新视觉(左色条 + 半透明底, 对应"部分成员被选"的 indeterminate 语义), 用现有 --accent-soft 降透明即可, 不引新色;
  • Esc 取消选择顺手接入既有 Esc 退栈(浮层 → 对话框 → 清选择), 与 想法.md 里的同源诉求合并落地。

风险与红线(不动清单)

  • 生产文件红线: config.yml 与 auto-qb-data/ 一律不碰(AGENTS.md 明文); 调试一律用 minimal.yml / test_yamls/ + 临时 data_dir, 完事清理。
  • 单一写线程: 新增的 /api/open-path 只读快照 + 调用系统打开, 不进命令队列、不写 state; 其余改动全在前端。删除链统一后仍走 bulk_torrents 既有命令通道。
  • 前端 DOM/CSS 契约(views.css 头注 + pitfalls 已列): .sticky-head 与 --head-h、 --statusbar-h、.group-head/.detail-head、gridStyle 列模板、.ctx-menu、 tpl-ce-field、sprite #i-* 单点、toast/确认框单例 —— 一律保留, 新功能以"新增类"接入。
  • CSS 结构守阵: 本轮大量改 CSS/模板, 而"漏 ; } / 选择器被吞"与"<transition> 吞弹窗" 都是已入 pitfalls 的真实故障形态 ⇒ 每次改完先跑 test_frontend_static_bundle_health, 不做批量收尾式修改。
  • 不做的事: 不引构建链 / 不引新依赖 / 不引第三方图标库(手写 inline SVG + sprite 单点); 不做行入场动画与数字滚动(pitfalls 明文: 2s 整表重渲染会反复播放); 动效仍尊重 prefers-reduced-motion。
  • 旧口径冲突先在决策点定案: FX-05 的列对齐与 FX-02/03/04 的"空值显示"都动到 TBL-01/TBL-02 时代的显示规则, 改动只改本轮明确点到的那几列/那几种状态, 不顺手统一全表空值策略。
  • HR 口径: FX-02 隐藏做种时长时必须保留"HR 已触发"分支(见 4.2 注), 不得让 HR 种子因"0 分钟"而隐身; hr_triggered/hr_req_time 一律消费后端算好的字段, 前端不重算阈值。
  • 选择模型改动面最大: FX-12 会改三视图的选中渲染与批量目标构成 ⇒ 必须逐子项跑 CDP 断言, 不允许"一次改完再看"(回归不可二分定位)。
