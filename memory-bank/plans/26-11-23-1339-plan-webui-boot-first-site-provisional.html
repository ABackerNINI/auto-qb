§01目标与设计原则

背景: 计划 26-11-18-0259(Done)在启动首轮 apply_sync 后、full_round 之前提前发布一「基础代」, 让首份数据秒出。基础代发布时所有记录 tracker_conf 尚未绑定(full_round 与 added 循环都在其后), 于是派生出两个症状:

  1. site = r.tracker_name 在 tracker_conf is None 时返回字面量 "Unknown" —— 整批种子站点列显示 Unknown。
  2. _site_alert 见 conf is None 且行内已有真实 tracker URL(来自 qB maindata, 入库时按脱敏单点落 mask 值但 host 保留)→ 返回 no_site_conf, 前端把站点 chip 画成橙底虚线并提示「站点未在配置中」 —— 这是对已配置站点的假告警。

North Star: 基础代站点列显示可辨识的推断站点名而非 Unknown、且不触发假告警; 补全代恢复真值与真告警。前提是不抵消 0269 的提前发布收益(首份数据 ≤2s 判据不回退)。

设计底线 / 不变量:

  • 基础代只算展示用的站点名 + 临时态标记, 不绑 rec.tracker_conf —— 绑 conf 会带上规则/HR/限速副作用, 且等于把真匹配挪前, 抵消提前发布目的(D2)。
  • 廉价解析必须纯内存: match_tracker_confs(config.trackers, [rec.tracker]), 不调 torrents/trackers。真 trackers.match() 每种子一次 qB API(冷缓存约 210 次), 正是被 0269 抢在前面的那段管线。
  • 四视图同轮发布铁律不破: 站点 chip 的每个成员行都来自 _member_view 单点(flat / singles / groups 成员 / shows 剧行的成员经 memberByHash 解析), 同代同标记; shows 剧行本体的 node["sites"] 是未被前端消费的聚合字段, 不在本修复面。单一写线程、不引入新锁、不挂配置开关(承 0269 D11)。
  • 补全代语义不变: 真 conf 绑定后站点名、HR 派生字段、no_site_conf 真告警照旧; 任务线错误原因仍自占一代(0269 S2 实测)。

§03方案总览

主线(D1/D2/D3 拍板): 选项2 为主 —— 基础代用 rec.tracker 经 match_tracker_confs 纯内存解析出站点名填 site; 选项1 为辅 —— 同一行加 site_provisional=True 临时态, 基础代 site_alert 一律留空(「尚未评估」而非「未配置」), 前端据此把站点 chip 压暗。第二拍真 conf 绑定后 site_provisional=False、站点名取真值、告警按真值重算, chip 恢复常态色。

站点名口径: 廉价解析得到的 conf 按 tracker_name 同款口径取名(tags[0] 非空否则 name), 保证一拍与二拍显示同名、不闪变。匹配不到时基础代保留 "Unknown" 但带临时态(不告警), 二拍由真 conf 决定。

临时态传递: 新增行级布尔字段 site_provisional(缺省 False)。发布链加一个显式参数从提前发布点透传到视图构建 —— 推荐在 _publish_locked 入口据参数置本代标记、各行构建期(_member_view / _seed_view)读该标记写字段(全部构建都在 _publish_locked 临界区内, 含 delta upsert 的 _publish_locked 重入, 见 runtime_views.py:310/608/637)。参数经 run_sync_line → web 模块 flush_views → _publish_locked 下传; 用参数而非环境态, 避免 Web 线程 ensure_state 触发的发布串味, 守住单写线程与「不新增共享可变标记」。shows 剧行本体无此字段, 其站点 chip 由成员对象经 memberByHash 提供, 见 §07 R5。

分期: S1 后端廉价解析与临时态 → S2 前端压暗与指纹 → S3 守阵红绿双验 → S4 真机/e2e 验收与回写。
