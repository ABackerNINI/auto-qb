WEBUI 动效皮肤 flux 分步实施计划

给 WEBUI 做一个零依赖的动效组件库（shared/fx/ 单点）+ 一套多风格候选的动效皮肤 flux（fork 自 console、只做 dark）：先桌面调研提炼动效模式，再用 showcase 页让用户逐组件挑选动效变体，最后挂进 flux 皮肤——现有 atlas/prism/console 三皮肤一行不碰。

§01目标与设计原则

目标

  • 动效组件库：覆盖 WEBUI 大部分交互元素(按钮/弹窗/列表/标签/输入框/浮层等)，同一组件提供多种动效变体供选择，交互动效(hover/点击/入场/切换)齐全。
  • 可直接挂载：组件库以 data-fx 属性约定 + 单挂载器交付，往元素上加一个属性即生效——统一入口、单一维护点、漏挂载可检测。
  • 华丽但跟手：华丽度交给用户在 showcase 上挑选精修；跟手性以设计指南(软约束)约束候选池，不作硬守阵。
  • 新皮肤 flux：以 console 为基础 fork，只做 dark 系列；多风格 preset 候选(neon/glass/crisp)，挑选后落定 1 套为主、其余留在库里可切回。

设计底线(不变量)

  • 零依赖：纯 CSS + 原生 JS，不引入任何运行时动效库(借鉴其设计，不引其代码)。
  • 存量隔离：atlas / prism / console 三皮肤的文件一行不改；存量动效(约 145 处 transition、42 个 @keyframes)不收编。
  • 只换视觉不改名：类名与 DOM 结构被 JS 耦合(列宽拖拽、ctx-menu 挂钩)，flux 遵守 conventions/webui.md 既有纪律。
  • 令牌名集相等：flux 令牌名必须与三皮肤齐(缺名 = var() 声明计算值阶段整条静默作废)，并扩展守阵收编 flux。
  • 既有惯例不破：prefers-reduced-motion 降级块照写；新元素 tooltip 走原生 title 不自造浮层；新增交互入口走 triggers.js + webui-scope C1-C5 契约。

动效设计指南(软约束，非守阵)

候选拗不淘汰、只标注。每条动效变体在 showcase 页标注"合成器友好 / 交互反馈时效"，用户筛选精修时参考；确有表现力需要、实测不卡的允许破例。

  • 优先动 transform / opacity / filter(filter 限小型元素)；动布局属性(width/height/top/left)的候选标注 layout 警示但不禁止。
  • hover/按下反馈目标 ≤100ms，入场动效 ≤400ms；高密度列表(torrent 行)不做全行 stagger。
  • 每个 @keyframes 配 prefers-reduced-motion: reduce 降级块(这是硬惯例，不属软约束)。

§02现状与痛点

WEBUI 形态

  • FastAPI 静态挂载(src/auto_qb/webui/server/factory.py:20)，无 Jinja、无服务端渲染；static_ui.py::mount_static_ui 把 webui/static/ 整目录挂在 /，根路径按 cookie autoqb_ui 307 重定向到上次使用的 UI。无前端构建链：Vue 3 全局构建(vendor 预编译产物) + window.AQB_XXX mixin 域 + 24 个 shared/tpl/*.html 模板分片由 boot.js fetch→注入→放行链装载。
  • 三皮肤同构：atlas / prism / console 各自 style.css → components → views → dialogs，尾部接共用层 shared/console_hub.css(1559 行)；链接序由守阵钉死。「新增 UI = static/<名字>/ 一个目录，无需后端改动」是既有惯例。
  • 皮肤无中央注册表：目录即 URL，cookie 记忆；但模板分片内用 <template v-if="ui === '…'"> 做皮肤分支——新皮肤 flux 作第四个 ui 值时，ui !== 'prism' 类分支自动涵盖，精确匹配分支(ui === 'atlas' / ui === 'console')需逐个盘点。

守阵现状(tests/test_webui_static_skins.py)

守阵位置对本计划的意义
令牌名集 parity:2025硬编码枚举 ("atlas","console")+prism —— flux 默认不被收编，收编与否是决策(D14: 收编)
模板分片接线 + CSS 体量帽:1754挂行顺序、link 序受钉；atlas components.css 已顶 700 行帽(pitfall css-file-line-cap)，fx 库要预留分文件
按钮体系成对:2066.bt 六变体三皮肤成对定义，flux fork 后自动继承，改动须同步
transition parity:2866既有动效一致性守阵，flux 变更后是否扩展收编在 S5 评估
静态 bundle 健康:1712shared/ 新增文件须过体检

另有 DOM 接线测试(test_webui_static_dom_page.py 34 个、…panel.py 61 个)与 Playwright e2e 42 spec 兜底。

痛点

  • 动效是有存量无体系：145 处 transition / 42 个 keyframes 分散在三皮肤 CSS 里，同名效果多处实现，改一处要过三处守阵——这是「新皮肤另起炉灶、存量不收编」(D8)的动机。
  • 华丽度无候选可比较：现有动效都是单配方，用户要「同一组件多种动效供选择」，需要 showcase 矩阵而不是逐个改皮肤试。

§03方案总览

落点架构

static/
├── shared/fx/                 ← fx 库单点(D7)：动效唯一维护点
│   ├── fx.js                     挂载器：扫 data-fx 属性统一初始化 + 漏挂载检测
│   ├── fx.css                    动效基线：令牌 + [data-fx] 基础规则 + 降级块
│   └── fx-presets.css            风格 preset：neon / glass / crisp 三套令牌配方 + 变体
├── fx/showcase.html           ← 挑选界面(D13)：P0 组件 × 3 preset × 变体矩阵
└── flux/                      ← 新皮肤(D14)：fork console，只做 dark，唯一消费者

两层变体模型

层挂载口语义示例
组件层data-fx="btn" data-fx-variant="glow"单组件的行为变体(换一个属性值=换一个动效)按钮: glow / sheen / lift / flat…
风格层<html data-fx-preset="neon">整套风格一键切换(令牌配方整体替换)neon / glass / crisp

同一 HTML 结构上，组件层挑「这个按钮用哪种动效」，风格层挑「整站什么气质」——showcase 页两层都可实时切换对比，挑选结果落定后写死进 flux。

组件覆盖清单

批次组件
P0(showcase 首批、S6 挂载)按钮(.bt 一族: primary/ghost/danger/danger-solid/icon/sm)、弹窗(modal，含 tone 分级)、抽屉(12 变体共壳)、列表行(torrent 表格行，选中/锚点/光标三态)、输入框(focus 态)、toast/通知、页签切换(groups/torrents/shows/settings)
P1(S7)标签/badge、进度条、开关、右键菜单、状态栏、dock、登录遮罩、busy 骨架、数字滚动(速度/体积实时数据)
不做自定义 tooltip 浮层(纪律: 原生 title，.aq-tip 单例不动)

兼容与降级(D5)

  • Chrome/Edge：全特性(@property、:has()、color-mix()、View Transitions、scroll-driven animations)。
  • Firefox/Safari：自动降级——纯 CSS 特性缺失时该条声明整条作废(无害)；View Transitions 一行 if (document.startViewTransition) 探测；scroll-driven 动效自然缺席。降级目标 = 无动效终态，不为旧浏览器保动效。
