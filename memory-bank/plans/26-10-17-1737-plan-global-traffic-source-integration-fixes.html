全局流量来源联动缺陷修复 (Phase 1)

逐条修掉「全局流量来源」联动上线后暴露的 9 个缺陷。设计主轴：把"数据来源"提成一个有一等总开关（traffic_source.enabled）的显式功能——关闭即停取数 / 停订阅 / 停自动拉起；并让设置页如实反映"来源 ↔ 工具 ↔ 限速曲线"的依赖关系。快照解耦与设置页合并卡属重构，另立 Phase 2。

§01目标与设计原则

为什么做：26-10-17-0339 把"数据来源二选一 + 整机流量监视器(工具)联动"接进设置页后，上线即暴露 9 个问题（拉起黑框、无关闭入口、来源错显、状态色/对齐、无效链接、切源后图表陈旧…）。本轮把它们逐条修掉，并补一个"来源总开关"，把"关闭工具"从一件没处安放的动作变成一等语义。

做到什么算成：§04 的 S1–S8 每条都有可验判据；enabled 关→开可逆且不误伤曲线配置；工具参数单位按项目既有 time/size 惯例呈现。

设计底线 / 不变量

  • 取数唯一入口不变：谁要 dat 路径一律走 paths.dat_path(config)；总开关闸门加在该单点，不散落各处。
  • 写点唯一：流量快照仍由 ctx.web.set_traffic_view 单点整体替换（"解耦成独立模块"是 Phase 2 的议题，本计划不动）。
  • 单一写线程：关闭 / 刷新一律入队主循环执行（黄金法则 5）。
  • 保守默认：关闭是显式动作，默认 true；不写盘改别的功能的配置（不擅自置 global_speed_limit_curve.enabled=false）。
  • fail-fast：新配置键必须进 validate_config 并同步 config/schema.py（守卫测试会查）。

§03方案总览

主线：① 加顶层 traffic_source.enabled 一等开关（含闸门 / 文案 / 快照 off 态）；② 工具侧补 POST /shutdown；③ 去黑框；④ 设置页四修；⑤ 工具参数改走 hub-field 的 time/size 并统一复合串；⑥ 「关闭工具」按钮 + 确认框 + 依赖元数据；⑦ 切源即刷新。分期见 §04 末表。

§04实施步骤

S1 — 加顶层 traffic_source.enabled（契约先行）

  • models.py::TrafficSourceConfig 增 enabled: bool = True（与 provider 并列，段级总开关）。
  • schema/groups.py 的 traffic_source 组 fields 首项加 Field("enabled","启用","bool",default=True,help="…")，无 show_if（恒可见）；同时带依赖元数据 affects=("global_speed_limit_curve","rules","history_chart")（供 S4 确认框）。
  • validate_config 收该键；config/schema.py 镜像同步；loaders.py 读取（缺省 true）。

验收：守卫测试（配置键全量一致性）通过；enabled 缺省为 true；enabled:false 经 loaders 正确落对象。
依赖：无。可独立提交。

S2 — 取数闸门 + 快照 off 态 + expr 文案

  • paths.dat_path(config)：enabled is False → 返回 ""；unavailable_reason(config) 增分支「流量来源已关闭（traffic_source.enabled=false）」—— 与取数分支同源（防止按文案改完不生效）。
  • tool_client._desired() 首行加 if enabled is not True: return False,"流量来源已关闭" → 订阅线程不再注册/心跳。
  • agent.ensure_running() 开头同闸门 → 不自动拉起。
  • speed_curve_mod._publish_traffic 增 off 状态分支（判定优先于 gslc is None/enabled=False 的 disabled）：来源关闭时发 off 快照（history 空、不查档、不动 qB）。
  • rules/expr/env.py::_traffic：unavailable_reason 文案透传，引用流量变量的规则判定失败并明确告警（不静默当 0）。
  • 前端：state==='off' 时「流量来源已关闭」关闭态（区别于 disabled=曲线未启用）；enabled=false 时 provider 选择器与子参数区灰显禁用（不隐藏）。

验收：enabled=false 时——dat_path 返回空、unavailable_reason 指向开关、订阅线程 _desired 返回 False（守阵测试复现不泄漏线程）、ensure_running 不拉起、曲线任务发 off 且不动 qB、expr 报错文案含"已关闭"；enabled 关→开往返后行为完全恢复。

S3 — 工具侧 POST /shutdown + auto-qb 代理

  • gtm/server.py：ControlServer 增"请求停止"回调（接收 stop_event.set）；新增 token 保护的 POST /shutdown——先回 200，再触发停止。
  • gtm/__main__.py：把 stop_event 交给 ControlServer；退出仍走既有 finally（最终落盘 + 释放锁 + 停控制面 + 删发现指针）。
  • auto-qb：routes/traffic_monitor.py 增 POST /api/traffic/monitor/shutdown（代理工具 /shutdown，带 token）。

验收：工具侧单测——/shutdown 无 token → 401；带 token → 200 且进程在有限时间内优雅退出并删指针；auto-qb 代理端点码透传。

S4 — 「关闭工具」按钮 + 确认框 + 依赖元数据

  • 按钮可见条件：provider==global_traffic_monitor && enabled==true && 工具可达。
  • 点击 → 确认框，文案列出受影响功能（由 S1 的 affects 元数据驱动）：「将停止工具进程，并关闭整个流量来源功能（限速曲线、expr 流量条件将暂停取数；历史流量图关闭）；开机自启注册不受影响。」
  • 动作次序：先写 enabled=false 并保存（复用既有配置保存路径，热重载）→ 再调 POST /shutdown（避免停的瞬间被订阅线程抢拉）。
  • 不切 provider（D3）。

验收：点关闭→确认后，设置项 enabled 变 false 且已落盘；工具进程退出、状态变"未运行"；重启 auto-qb 后不再拉起；「启用」开关可一键恢复。

S5 — 去黑框

  • auto-qb agent.launch_tool：Windows 下把 creationflags=DETACHED_PROCESS 换成 CREATE_NO_WINDOW（进程自带不可见控制台，且不共享 auto-qb 控制台 → 关 auto-qb 不带走工具）；stdin/stdout/stderr 仍重定向 DEVNULL；Popen 注入点/白名单（tests/sidefx.py）不破坏。
  • 工具侧 launch.cmd：优先 .venv\Scripts\pythonw.exe（无 console 子系统），保留回退。

验收：真机点「立即拉起」无可见窗口；关掉 auto-qb 后工具仍在跑；test.full 中 Popen 守阵不红。

S6 — 设置页四修

  • #3：provider != global_traffic_monitor 时，整块隐藏工具状态 / 工具参数 / （已删的）「打开工具设置」/ 立即拉起。
  • #4：tmStateClass() 的 ready 由 "on" → "ok"；复核其余态映射（launching/launch_failed→warn，not_running/not_installed→灰）。
  • #5：只读状态行加专用类（如 .hb-row.hb-ro）：标签去掉 padding-top:7px、内容与标签同缘对齐；不动全局 .hb-row；e2e 几何守阵加"行标签与行值同缘"断言。
  • #6：删除「打开工具设置」按钮（tmOpenToolSettings 一并清理）。

验收：来源=TM 文件时工具区块不出现；「已就绪」为绿色；状态行几何断言通过；全站无 tmOpenToolSettings 残留引用。

S7 — 工具参数改 hub-field（下拉 + ?）+ 统一复合串格式

  • auto-qb 侧：工具参数（sample_interval/flush_interval_s/lease_ttl_s/heartbeat_interval_s/notify_timeout_s＝time；flush_delta_bytes/notify_threshold_bytes＝size）改用既有 hub-field 渲染（UNIT_KINDS + UNIT_OPTIONS + help → 数值框＋单位下拉＋? 浮窗）；默认单位＝TIME_UNITS=("S","M","H","D") / SIZE_UNITS=("B","KiB","MiB","GiB","TiB")。
  • 格式统一：盘上/契约只留复合串（"30S"/"10MiB"），不留"数值 + 独立单位"两种形态。工具侧新增解析单点 gtm/units.py（parse_duration/parse_size/format_*，文法镜像 auto-qb TIME_UNITS/SIZE_UNITS），gtm/config.py 的校验/回显/落盘改走它。
  • 迁移：读侧接受旧数值（sample_interval:5.0→"5S"、1048576→"1MiB"）并按语义平移；写侧只写复合串；解析不出的旧值进聚合错误。
  • 校验权威在工具侧；auto-qb 前端只做 UI 拆/合（"10MiB"→10+MiB），不复制文法规则。

验收：工具 config 单测覆盖 parse/format 全单位 + 非法串聚合报错 + 旧数值迁移；设置页工具参数呈现为下拉 + ?；保存后盘上是复合串。

S8 — 切源即刷新（#7/#8）+ #8 真机复现

  • 先复现：真机走一遍"切工具→保存→观察→切回 TM 文件→保存→等满一个 interval"，取证 #8 是否自愈（若不自愈，另记 issue 或在 S8 内追加修复）。
  • 后端：reload_config 成功后，若 traffic_source（provider/enabled/dat_path）发生变化 → 立即入队现成的 refresh_traffic（复用单点，零新逻辑）；refresh_traffic_view 需覆盖 off 态（现曲线停用时直接跳过）。
  • 前端：保存成功后主动重拉 /api/traffic/history 重画（已打开的图表即时更新）。

验收：切源保存后立即（不等 interval）历史图即为新来源数据；enabled 关闭后立即转为关闭态；refresh_traffic 只读不写 qB（不误触发限速）。
