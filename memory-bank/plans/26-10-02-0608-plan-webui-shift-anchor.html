WEBUI Shift 连选起点
与键鼠联动机制统一

现象：Shift 连选的「起点」与键鼠光标各说各话 —— 鼠标点过第 5 行、按 Shift+↓，选中的却是从列表第一行到第 6 行的整段；点第 5 行再 Shift+点击第 20 行，同样从表头开始选。本计划在报告 26-09-30-1806（方案 B 已落地：点击落光标 + 视口就近回落）的基础上，把选择起点（anchor）也纳入键鼠统一模型。只出计划，不改代码。

01 · 结论 TL;DR

根因：Plan B 统一了「光标」（focus），却没统一「起点」（anchor）。点击现在会落 kbCursor，但 Shift 区间选择的起点仍是另一套状态机 selAnchor*——它只由 Ctrl/⌘+点击与「展开」写入（toggleGroupSel / toggleMemberSel / _toggleUnit / toggleExpand），普通点击不写、键盘移动光标也不写。于是 Shift 扩展读到的起点要么是陈旧的，要么为空——为空时四处实现一律兜底到 list[0]（列表首行）。

业界成熟实现（Windows 资源管理器 / macOS Finder / VS Code）对这件事只有一条口径：普通点击同时设置焦点与「选择锚点」（Win32 的 selection mark），方向键只移焦点，Shift+方向键/Shift+点击从锚点扩到目标；锚点在一次扩展手势中保持不变。见报告 §4.4。本项目缺的正是「点击落锚点」这一条，以及键盘首次扩展时「以光标为起点」的兜底。

推荐 · 方案 B

① 把四处重复的 list[0] 起点兜底抽成单点解析 _selAnchor(kind, list)，兜底链改为「显式锚点 → 当前光标 → [辅种页: 展开的组] → 列表首行」；② 五个点击入口的普通点击路径补落起点（Shift 路径不落，保持「同一起点多次扩展」）；③ _kbExtend 在移动光标之前以当前光标为起点（首次 Shift 扩展的原点）；④ 追剧页起点缺失时形成区间而非退化为单单元切换。纯前端 JS，改动集中在 selection.js + shortcuts.js 两文件，不碰滚动实现、不碰后端、不加配置键。详见 §06。

02 · 问题现场（代码取证）

Shift 区间选择的四个消费者全部只读 selAnchor*，从不读 kbCursor——这就是「起点与光标脱节」的本质：用户心智里的「我现在在第 5 行」是光标，而区间实际从「锚点」（可能为空/陈旧）开始算。

03 · 复现矩阵（改前）

三视图 × 两通道，改前实际行为（list 指当前视图的线性行集合）：

场景操作改前实际行为
M1种子页：普通点击第 5 行 → Shift+点击第 20 行锚点为空 → 从 list[0] 选到第 20 行（应 5–20）。
M2种子页：普通点击第 5 行 → Shift+↓先移到 6 行，锚点为空 → 选 list[0]–第 6 行（应 5–6）。
M3种子页：无点击，纯键盘 ↓ 到第 20 行 → Shift+↓锚点为空 → 选 0–21 行（应 20–21）。
M4种子页：Ctrl+点击第 5 行（锚点=5）→ 点第 12 行（普通，光标=12）→ Shift+点击第 20 行锚点仍是 5 → 选 5–20。此路正确（Ctrl+点击已落锚点），但普通点击第 12 行不改变起点——与「最近点击处为起点」的直觉不符。
M5辅种页：普通点击组 A 展开 → Shift+点击组 B锚点=A（展开时写）→ 选 A–B，正确；但若组 A 已展开、普通点击将其收起，锚点不更新 → 从旧锚点或 list[0] 起算。
M6辅种页：普通点击某组明细成员行 → Shift+↓成员行不在键盘线性链（_kbRows 只含组行）→ 光标回落视口组行，且成员锚点为空 → 走组口径 list[0]。既有「成员行 vNext」限制。
M7追剧页：普通点击剧 A → Shift+点击剧 C_extendUnit 锚点为空 → 只切换剧 C 一个单元，不成区间；同时把锚点置为 C，第二次 Shift 才成区间（应一次成 A–C）。
M8追剧页：展开剧 A 的集 → Shift+↓同上，首拍退化为单集切换。

M4/M5 是「起点陈旧」的子集；M1–M3、M7–M8 是「起点缺失落 list[0] / 退化」的子集。两类都源于 G1–G5。

04 · 目标口径：统一起点模型

把起点（anchor）也纳入 Plan B 的键鼠统一模型，收敛为三条法则（与报告 §4.4 / §5 的业界共识同源）：

  1. 起点 = 最近一次「显式落位」的位置。显式落位 = 鼠标普通点击或 Ctrl/⌘+点击某行，或键盘 Shift 扩展手势的原点（按下 Shift 前光标所在行）。
    落起点 ≠ 选中：写的是区间起点语义，不改 selGroups/selMembers 的选中集合——与 2026-09-17「普通点击不选中」及 Plan B「落光标 ≠ 选中」完全一致。
  2. 扩展期间起点不变。Shift+点击 / Shift+方向键只移动焦点并「锚点→目标」整段并入；起点在整段手势内保持不动，便于多次 Shift 从同一起点扩展（沿用既有注释口径 selection.js:47）。Shift 本身不重置起点。
  3. 无有效起点时以光标为起点。当前上下文没有可用锚点时，以 kbCursor 解析出的行为起点（键盘），而非 list[0]。兜底链：
    显式锚点(有效) → 当前光标(有效) → [辅种页: 当前展开的组 expandedKey，既有产品规则] → 列表首行(最后手段)。

与既有口径的关系

① 不动「普通点击不选中」——只多写一个 selAnchor*，选中集合不变；② 不动「落光标 ≠ 选中」——起点是第三个独立语义，与 focus 一样不触碰 selection；③ 保留「展开的组作为 Shift 默认起点」这条用户既定规则（menu.js:98），仅把它排在「光标」之后作为次选兜底。

05 · 方案比选

方案 A 只改兜底（list[0] → 光标）

把 G1 四处兜底由 list[0] 改为「kbCursor 命中当前列表则用它，否则 list[0]」。能修 M1/M2/M3/M7 的「从表头起选」；不能修键盘「先移动后取起点」导致的塌陷（G2），也修不了「普通点击不落起点」的陈旧锚点（G3，M4/M5）。改动最小，可作为方案 B 的子集先行。

方案 B（推荐） A + 起点单点化 + 点击落起点 + 键盘起点建立

在 A 之上补三件事，使起点真正与键鼠联动（详见 §06）：

  • 起点解析单点：新增 _selAnchor(kind, list) 与 _selSetAnchor(kind, id)，四处消费者（shiftGroupSel/shiftMemberSel/shiftTorrentSel/_extendUnit）统一调用，消除重复兜底的口径漂移风险（当前四处各自 list[0] 就是漂移源）。
  • 点击落起点：五个点击入口的普通点击路径补写对应锚点；Ctrl/⌘ 路径已写（经 toggle*Sel）；Shift 路径不写（法则 2）。
  • 键盘起点建立：_kbExtend 在 _kbMove 之前，若当前上下文无有效起点，以当前光标为起点——修 M3 的塌陷。

收益：M1–M8 全部消除或按直觉收敛；改动集中在两个 JS 文件、不碰滚动/模板/后端；与既有 _kbTargets 目标解析（有选中走集合、无选中走光标）无缝。

方案 C 起点与光标合并为单一字段

激进做法：删掉 selAnchor*，区间起点直接取 kbCursor。不可行——会破坏法则 2（起点在扩展期间必须不动，否则 Shift+↓ 连按只能选到相邻两行）。起点与光标是功能上不同的两件事（同报告 §4.1 引 APG「DOM focus 与 selected state 是不同的事」）。

推荐理由（B）

① 三视图两通道的起点行为统一到一条口径；② 把「四处各写一遍的 list[0]」收成单点，符合本项目「单一事实源」纪律，后续改鼠标路径不会悄悄丢衔接；③ 复用 Plan B 已就位的 kbCursor 与视觉双轨，无需新视觉；④ 改动面小、可静态守阵钉住。

W3键盘起点建立（Shift 手势原点）

_kbExtend(delta) 开头、_kbMove 之前，若当前上下文无有效起点则以当前 kbCursor 落起点（手势原点）：

_kbExtend(delta) {
  this._selSeedAnchorFromCursor();   // 无有效起点 -> 以当前光标为起点(手势原点)
  this._kbMove(delta);               // 移动光标(含视口就近回落)
  ... shift*Sel / _extendUnit ...    // 锚点 -> 新光标整段并入
}

要点：先落起点后移动，否则光标已变、区间塌成单行（G2）。若光标为 null，维持现状（解析器最后兜底 list[0]）——低优先级边界。

08 · 风险与坑

  • 禁用 scrollIntoView（坑档 pitfalls/web-ui/hover-keynav-fight.md）：落起点本身不滚动；若实现中顺带滚动跟随，必须继续走 _kbScrollRowIntoView 的 getBoundingClientRect 差值路线。
  • JS/CSS 块注释 */ 提前终止（坑档 pitfalls/web-ui/js-comment-terminator.md）：写「落起点」注释时避免在块注释里出现 */；node --check 对此仍会全绿，只有运行期才炸。
  • 前端拆分口径（坑档 pitfalls/web-ui/frontend-split.md）：新增方法属 methods，挂 window.AQB_SELECTION 即可；data 字段不许进 app.mixin（selAnchor* 已在 state.js 根选项，不动）。
  • 修饰键分支顺序：kbCursor 写入已由守阵钉在 event.ctrlKey 之前；新增的 _selSetAnchor 必须同序，否则 Shift+点击会先扩展后落起点，自相矛盾。
  • 轮询刷新下的身份失效：起点按身份存；若该身份在刷新后消失，_selAnchor 应回落光标/首行（不崩），沿用 Plan B 的「按身份重定位」精神。
  • 成员行限制：辅种页明细成员行不在 _kbRows 线性链（既有 vNext）——本计划不扩围，仅保证起点口径统一；避免顺手改造成大重构。
  • 守阵易脆：断言按字符串位置（_selSetAnchor 在 _kbMove 之前）实现时，注意匹配范围限定在方法体内，避免跨方法误判。

09 · 待拍板口径决策点

决策点选项与建议
① 普通点击是否落起点 建议落（Explorer/Finder 口径：点击同时设焦点与 selection mark）。这是本方案的核心；若选择不落，M1/M2/M4/M5 无法根治，只能靠键盘兜底部分缓解。
② 无 Shift 的 ↑↓ 移动光标时，起点是否跟随 建议不跟随（起点只在点击/Shift 手势原点落定），保持「同一起点多次 Shift 扩展」。跟随会让 Shift+↓ 连按只能选相邻两行。
③ 辅种页组行普通点击（展开/收起）是否一律落起点 建议一律落（写在 toggleExpand 之前），使「点击=落起点」与展开态无关；现状是「仅展开时落、收起不动」。
④ 追剧页 Shift 区间粒度 建议沿用现有「剧/集单元」粒度（_showUnits），不引入新的半选语义；仅把「缺失起点」从单单元切换改为区间。

10 · 范围外
