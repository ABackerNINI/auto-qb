00目的 · 范围 · 口径

本件为该 issue 的形态选择件:把三种候选修法并排写成可拍板的对照 —— 各自改哪一行、覆盖哪几条封口路径、 两路(在线 / 离线)能否逐位重建、留下什么残余、要动几个文件。拍板前不动码。

为什么另开一件(而不是就地改计划 26-10-15-0829)

该 issue 是那份计划的派生件,但计划自己的 §03 P1 裁决记录已把当时可见的四形态逐个裁决完毕 (1A 否决 / 1B 与 1B' 不实施 / 定期封口用户否决),计划 §07 #1 已收口为「四形态全不实施」。 本轮认领复验时找到一条此前未被枚举的路径(§03),形态面因此重开 —— 于是新件而非改版: 计划那一节是「当时为什么不做」的快照,本件是「现在怎么做」的新方案面。

范围(三形态共有的性质)

  • 只改 agg 入账用的 totals —— 即 _agg_feed / _agg_credit_day_file 写进小时桶的累计快照。游程内部各小时按「开启快照 → 末端真值」按覆盖秒线性插值 (与 raw 面 P2 摊配同一口径:把隐形增长摊回游程)。
  • 不动 rate lane(游程区间速率仍恒 0)、不动 raw 面差分链与 v4_totals_points 的摊配输入、 不加写盘次数、不新增跨 flush 的待结算态、不扩大崩溃丢失窗口。
  • z/n/r 行格式:形态 A / B 完全不碰;形态 D 明确扩列(见 §04)。

非目标

  • rate lane(游程内隐形字节是否该进 hour avg)—— 同批入池的另一件 26-10-16-0020-question-agg-rate-lane-invisible-bytes 是口径判断题,需另一次拍板,与本件可各自独立推进。
  • raw 面(1m–24h) —— 同症状已由计划 26-10-15-0829 的 P2 读侧摊配修好,本件不回头动它。
  • 历史行不回补 —— 已写进 agg.dat 的冻结行是既成事实,修法与既有「历史坏行不回补」口径一致。

02机理

三条链叠加造成归属错位;三形态都只动第 2 环。

链 1
合成槽 + 冻结快照

_record_slots(:315)把一条 z 记录的 run_len 个槽 回填分布在 [开启, 末端] 之间 —— 这些槽是合成的观测点,不是采样时刻。而它们的 totals 是游程开启时刻的那一对快照(盘上语义由 OpenRun 冻结,raw 面差分链依赖它)。

链 2
逐槽常量入账

_agg_feed 的 V4ZeroRun 分支(:1055)把这一对常量按槽区间原样记进 agg.pending —— 于是「游程内部每个槽的真值」被写成一个常数。

链 3
小时行取桶内末样本

v4_hour_agg(:811)的 totals = samples[-1] —— 游程内部的小时, 其「小时末应有的累计值」被写成「游程起点值」;增长只能从游程结束后的覆盖开始体现, 于是差额在下一个封口点一次性出现(真机表现即报告 §05 的「07:00 小时行 totals 线一次 +15 MB 台阶」)。

读侧为什么够不到(issue §05 已排除项,本轮复核维持)

v4_agg_obs(:753)对 agg 行是直映、不建差分链,而天文件里游程内部的槽本身 就是同值合成槽 —— 磁盘上没有任何字段记录「增长发生在哪一刻」。所以这不是读侧判据的问题, 是写侧入账时就丢掉了时间锚点。

03与既有裁决的关系(新证据改变了什么)

计划 26-10-15-0829 §03「P1 收益评估与形态裁决」已逐条记过当时四个形态的裁决与理由 (此处引而不抄,见 计划 §03 P1 裁决记录): 1A 改 z 行 totals 语义 = 把 raw 面台阶搬到游程首桶、run[2] 为空致 P2 判据失效 ⇒ 比现状更糟,否决; 1B 补尾部记录 / 1B' 带派生速率 = _agg_feed 逐记录即时入账,事后记录追溯不到游程内部 ⇒ 不实施; z 游程定期封口 = 用户否决(行数代价 + 撕开「空闲期主文件零写入」不变式); 挂起结算 = 未评估,成本最高。

本轮新证据:存在第四条路径 —— 末端值不需要新增态就能拿到

1B' 的裁决里写「要真正落在游程内部,必须『处理 z 行时已知末端值』,而这只剩三条路:依赖已否决的 1A、 给 _agg_feed 加挂起结算态、或不可行(只用现有字段推不出)」。本轮读码 + 复验发现三条路之外的第四条:

  • z 记录不是逐样本入账的 —— 它是游程封口那一刻才成为一条记录、才走到 _agg_feed (_seal_run :778 → _append_record :804 → _agg_feed :931)。
  • 而在最主流的封口路径上,触发封口的实测样本与它的 totals 就在调用方手里:非零样本到达时同轮先 _seal_run 再出 r 记录(触发 (1))。也就是说
    「处理 z 行时已知末端值」= 调用方手里那个值,传一手即可 —— 不改盘面(不触 1A)、不引入跨 flush 态(不触挂起结算)、不扩大崩溃窗口(游程内部信用本来就只在封口时结算一次)。
但新路径带来一个新约束面:两路可复原性

这条路径把「末端值从哪来」压在了在线路径的内存上,而 issue §04 的 ❗ 要求在线写入的行与 离线 catch-up 从天文件重建的行同口径 —— 否则重启后补算的段与在线段会在同一个系列里口径分叉, totals 线上出现一个来源不明的接缝。于是形态分野的真正判据是:

末端锚点(时刻 + 快照)在不在盘上、离线能不能读回来? —— §04 的三形态正是这条判据下的三个答案。

另注:形态的覆盖能力只取决于「封口路径有几条能拿到锚点」。游程的封口触发源共五条 —— ① 非零实测样本到达;② 00:00 硬切(游程不跨天);③ stop() 优雅退出;④ 采样间隔热重载关块; ⑤ 天级保险闸(ZRUN_CAP_SAMPLES / ZRUN_FLUSH_S)。

A同天锚点插值

做法

游程内部第 k 个槽(时刻 t_k ∈ [t0, t1])的 totals 由两端实测锚点线性插值: v(t) = S0 + round((S1 - S0) × (t - t0) / (t1 - t0)),t0/S0 = 游程开启槽与开启快照, t1/S1 = 右锚点(同文件内游程之后的首个 totals 观测)的时刻与快照。逐槽取整、余额归右锚点所在桶, 保证 Σ 小时增量 = S1 - S0 严格守恒(与 P2 摊配的取整口径一致)。

落点

  • 在线:_seal_run(:778)→ _append_record(:804)→ _agg_feed(:931 / V4ZeroRun 分支 :1055)多带一个「右锚点」入参; 非零样本封口时由触发封口的实测样本提供,其余封口路径缺省(None)= 不插值。
  • 离线:_agg_credit_day_file(:1403)在展开块内槽序列时,对每个 z 记录向后定位 同块内首个 totals 观测,作为右锚点走同一个插值函数。
  • 两路共用同一纯函数(时刻/快照进、逐槽值出)—— 镜像靠同源而非靠巧合。

覆盖 / 残余

  • 覆盖:①非零实测样本封口(真机事故的形态)。
  • 残余:②00:00 硬切封口的游程右锚点在下一日文件里 ⇒ 保持冻结 —— 而低载实例上「整夜不开一口、 只在午夜封一次」恰恰是常态,于是夜间段的小时行与当日 day 行仍偏低。
  • ③④⑤三条路径(A 与 B 同):stop() 封口后进程消失、改间隔封口会关块、保险闸封口没有后继实测样本 —— 右锚点要么不在盘上、要么在块/文件边界之外,两路一律回退冻结(这是刻意的保守支,见 §07 风险节)。

可复原性

逐位可复原:右锚点两侧取的是同一个盘上记录,时刻与快照都不含在线独有信息(在线用的就是那条 r 记录的 ts 与 totals)。

B全路径插值(含跨午夜)

做法

同 A,但右锚点允许落在下一日文件:00:00 硬切时,触发切日的零样本同时是「新游程的开启快照」, 它与下一日文件里新 z 记录携带的快照是同一个值;时刻取块首口径(int(ts)= B.start), 两路因此仍可取到同一对 (t1, S1)。

落点

  • 在线:00:00 硬切那条封口路径(_advance_run :750 内换型/跨天分支)把当前零样本的 (int(ts), totals) 作为右锚点一并交下去;stop() / 改间隔 / 保险闸三条仍不传(见残余)。
  • 离线:_recover_series 的「边读边遍历」改为「先解析读集内日文件、再按序遍历」, 为每个日文件提供「下一日文件的首个 totals 观测」作为右锚点。读集不变(仍 = agg 水位所在日 → 今日, 常态 1 个、跨日界至多 2 个),所以 recovery_reads / recovery_stats 的计数口径不变 —— 变的只是解析时机(先全部解析再遍历)。

覆盖 / 残余

  • 覆盖:① + ②两条主路径 —— 覆盖低载实例的实际形态。
  • 残余一(③④⑤):stop() 封口后进程消失,右锚点在盘上不存在;改间隔封口会关块; 保险闸封口没有后继实测样本。这三条两路一律回退冻结。
  • 残余二(③④⑤的次生形态,仅当放宽判别时才会遇到):若把这三条也做成「在线用手里的末零样本值」, 则该值不在盘上,离线只能取到「下一个 totals 观测」(可能是很久之后的记录)⇒ 锚点时刻/快照出现 亚刻度偏差(差 ≤ 一个采样间隔的流量)。本形态不采用该放宽,故残余一保持为「冻结」而非「近似」。
  • 残余三:跨午夜锚点要求在线侧用块首口径 int(ts) 与离线对齐 —— 若新游程恰好不是块首记录 (极端组合),两路锚点时刻会差一个亚刻度;插值到小时粒度上远低于取整门槛,但仍属「非逐位」, 需在实施轮写进口径注释与守阵(见 §05 判据 4)。

可复原性

主路径逐位可复原;残余三处为「同口径但亚刻度可能不同」,由判据 4 的守阵钉住(不是靠约定)。

Dz 行扩列(末端快照落盘)

做法

给 z 行加一对「末端快照」列,封口时把当时已知的末端值写进去(拿不到就写成与冻结列相同的值 = 显式退化)。 raw 面差分链仍消费原来的 delta 列/冻结列,故 raw 面逐字不变;agg 面(在线与离线)都改读新列。

落点

  • traffic_store.py:z 行格式化与解析(format_v4_z_row / parse_v4_*)、 以及文件尾「v4 行型定约」那一段注释(格式单点)。
  • traffic_sample_mod.py:_seal_run 写末端值;离线 _agg_credit_day_file 直接读列。
  • 格式位次需定约:现有 z 行是 z,<run_len>,<dl_delta>,<up_delta>[,<dt_ms>] —— 可选尾列 dt_ms 的存在使「追加两列」的位次必须显式拍板(插在 delta 与 dt_ms 之间按列数分支, 或把末端对作为最末可选尾列),且旧文件无新列时必须解析为 None → 退化冻结(向后兼容)。

覆盖 / 残余

  • 覆盖:①—⑤全部五条封口路径,且不再依赖「后继记录是否在盘上」——离线不需要前视、不需要遍历改造。
  • 残余:③④⑤三条路径的末端值来自「运行中最后一条零样本的读数」而非日后实测点,属于游程内部信用本来就采用的口径 (它与「开启快照」同源同级),不是新引入的近似;但它是盘上新增的证据,须在口径段写明它表达的是 「封口时刻已知的末端观测」而不是「游程末槽时刻的真值」。

可复原性

逐位可复原且两路同源(离线读的就是在线写入的那两列),三形态里唯一不需要「两路各推一次」的一支。

05判据与守阵计划

验收判据(三形态共用)

  1. 逐小时单调且右端对齐:游程内部各小时行 totals 单调不减,游程结束所落小时行的 totals 等于右锚点快照 (A/B)或盘上末端列(D)。
  2. 增长守恒:游程内各小时增量之和 = S1 - S0(逐小时取整偏差 ≤ 1 字节;余额归右锚点桶)。
  3. 消除单桶台阶:同一游程下,「游程结束所落小时行」的 totals 增量不再等于游程全量增长 —— 与 raw 面 P2 摊配后的区间速率量级一致(报告 §05 的「+15 MB 台阶」不再出现)。
  4. 两路同口径:在线产出的 hour/day 行,与离线 catch-up 从同一天文件重算的行,逐列相同 (A 逐位; B 主路径逐位、残余三处按声明口径; D 逐位)。
  5. 不回归面:游程内部小时行仍存在、cov_s 不变、rate lane 逐字不变(游程区间仍恒 0)、 天文件字节与 raw 面读侧取值逐字不变(A/B);D 另加「旧文件无新列 → 退化冻结」的兼容用例。

三态读法:「覆盖」= 两路都能拿到锚点并按插值入账;「冻结」= 保持今天的现状(游程内部行程快照), 不是新缺陷、也不需要额外处理 —— 只是这一段的归属错位未被修。**残余的可见后果集中在形态 A**:低载实例上占比最大的 夜间段小时行与当日 day 行(日对账用的就是它)仍偏低。

07风险 · 取舍 · 回滚

  • 「模型化数值」的张力(三形态共有):插值出来的小时末 totals 不是任何一次实测读数。 权衡:agg 面磁盘上没有更细的锚点可用,而 raw 面在同一问题上已经采用同一口径(P2 摊配按覆盖秒摊回游程), 区别只在落点(读侧 / 写侧)。不做插值就等于默认把增长全部归给游程结束那一小时 —— 那是另一种、更差的模型。
  • 均匀假设:游程期间的增长实际由握手字节的随机到达构成,插值假定它沿时间均匀。 量级正确、逐小时位置是近似;落在「按覆盖秒摊配」这条既有口径内,不引入新的近似族。
  • B 的离线改造面:把恢复读集从「边读边遍历」改成「先解析再遍历」,读的文件集合不变但内存驻留变多、 相关守阵(读集有界 / recovery_stats)需要复验;这是 B 相对 A 的主要代价。
  • D 的格式代价:z 行扩列要动「v4 行型定约」这条格式单点,且可选尾列 dt_ms 的位次必须显式定约; 好处是彻底摆脱「前视 / 两路各推一次」,并且把「增长发生在哪一段」变成盘上可判的事实。
  • 回滚:三形态都只改 agg 入账逻辑,回退即恢复冻结口径;已写入 agg.dat 的行不回补(与既有口径一致), 因此回滚无数据迁移成本。形态 D 若已落盘新列,旧解析器会把该列当坏行处理 ⇒ 回滚前需保留一段兼容解析(实施轮必须一并设计)。

08待拍板项

  1. 形态选择:A / B / D(§04 对照表 + §06 残余矩阵)。建议取向:要「低载实例的日对账也正确」就排除 A; 不愿碰行格式就取 B;愿意为「盘上可判 + 离线零前视」付格式代价则取 D。
  2. 若取 B:③④⑤三条路径是否也放宽为「用封口时手里的末零样本值」 —— 放宽会带来与离线侧的亚刻度锚点偏差 (§04 B 残余二)。本件默认不放宽(两路一致优先于覆盖率)。
  3. 是否连带处理 rate lane(另一件 26-10-16-0020-question-agg-rate-lane-invisible-bytes): 本件建议不连带 —— 那是口径判断题(速率图要不要含非 payload 成分),需要单独拍板,且与本件无实现依赖。
  4. 是否设最小跨度门槛(例如游程跨度 < 2 × 采样间隔 时不插值,避免把正常抖动当陈旧增长): 倾向设,取值与是否配置化随形态一起定(配置化须同步校验层与 schema 单点)。
  5. 实施批次与立档:A 预计触 1 个源文件、B 预计 1 个源文件(离线遍历在采样模块内)、D 预计 2 个源文件 —— 均低于「≥3 源文件」阈值;专题档案已在(tasks/26-10-15-*),按惯例追加而不新建。
