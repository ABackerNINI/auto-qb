§01目标与设计原则

用户反馈「分类 / 标签 / 站点鼠标 hover 辉光没有统一, 部分辉光仅显示一侧或两侧」。经只读核查, 这三处就是表格单元格里的三种可点击筛选 chip .cat-chip / .tag-chip / .site-chip(模板 shared/tpl/xtpl.html:262-290、xtpl-cells.html:22-30)。辉光只在 flux 皮肤存在, 因此「统一」= flux 内部三种 chip 之间的统一, 不是跨皮肤统一。

算成: flux + 有 fx preset + 非选中态下, 三种 chip hover 时都呈现同一条四层 --fx-glow-stack 辉光, 四边闭合、角部不缺光; 站点 chip 的 3px 微切角视觉逐字保留; 三旧皮肤与顶栏筛选面板零变化。

§02现状与痛点

根因: 切角裁掉外发光, 且只有站点 chip 中招

flux 的 flux/css/fx-mount.css:282-286 给三种 chip 统一挂了 box-shadow: var(--fx-glow-stack), 但 flux/css/components.css:330-333 的 .site-chip 在控件层用了 clip-path: polygon(3px 0, ...)。项目自己的硬知识已写明二者互斥:

shared/console_hub.css:18-20
  1. **切角与发光是死敌**: clip-path 会把 box-shadow 与 filter 的外发光整圈裁掉,
     只剩 drop-shadow 一条路, 而它没有 spread 参数 ⇒ 控件层一律方角, 切角只留大面

于是同一条辉光规则里, site-chip 被自身裁剪(观感即「只显示一侧或两侧」), 而 tag-chip / cat-chip 无 clip-path → 四边完整。components.css:373-374 的注释也自认「本皮肤 site-chip 有 clip-path 切角, ::after 一并被它裁」——选中态底线的两端正是这样被切掉的。

覆盖率: 「辉光单点」名不副实

元素 / 状态flux 现状证据
三种 chip hover(非选中)四层 stack 辉光; 站点 chip 被 clip-path 裁fx-mount.css:276-286 + components.css:332
三种 chip 静息 / 基础 hover仅有 filter: brightness(1.12), 无辉光components.css:376-379
.f-on 选中态被 :hover:not(.f-on) 排除, 只剩底边 2px 线fx-mount.css:282-284、components.css:380-383

即: 配方公式是单点, 但「哪些元素 / 哪些皮肤 / 哪些状态有辉光」从不是单点, 这才是「没有统一」的制度性根因, 不是某一行 CSS 写错。另有一套负 spread 柔光族(全库 0 0 16px -8px 14 处落点)与 stack 并存, 属另一套设计语言, 本次不收敛。

§03方案总览

主线(F1): 形状与辉光分层。把 3px 切角从 .site-chip 本体挪到底层绘制层(空闲的 ::before), 本体不再持有裁剪, 于是 fx-mount.css:285 的 box-shadow 四边完整; 切角视觉逐字保留, 三种 chip 继续消费同一条 stack, 不引入 drop-shadow(无 spread、无法复刻四层硬芯, 会重演 26-11-04 治好的「雾蒙蒙」), 不改共用模板。

§04实施步骤

W1-1 · 形状分层(仅 .site-chip)

在 flux/css/fx-mount.css 新增带 html[data-fx-preset] 前缀的规则; tag-chip / cat-chip 形状不动:

html[data-fx-preset] .site-chip {
  position: relative;            /* 基线 components.css:330 无定位包含块, 只有 .f-on 有 */
  background: transparent;       /* 本体不露方角, 底色交给 ::before */
  clip-path: none;               /* 覆盖 components.css:332, 让本体 box-shadow 不被裁 */
}
html[data-fx-preset] .site-chip::before {
  content: ""; position: absolute; inset: 0; pointer-events: none;
  clip-path: polygon(3px 0, 100% 0, 100% calc(100% - 3px),
                     calc(100% - 3px) 100%, 0 100%, 0 3px);  /* 逐字搬运 components.css:332 */
  background: var(--surface-2);
}

W1-2 · 语义柔底传递(零新增令牌, I2)

不能用 currentColor 或 background: inherit: 柔底是 15% alpha(flux/style.css:43-50 --green-soft: rgba(63,214,153,.15)), 字色是实色; 而本体已改 transparent, inherit 拿到的也是 transparent。全库无 background: inherit 先例; 现成模式是 components.css:549-555 的 .ce-note.warn::before 每状态各写一份 background。

故按状态各写一条 ::before 背景, 共 8 组, 顺序须与现有源顺序一致(views.css:92 明确「站点问题 > 搜索命中 > 种子状态」; :82-84 只讲搜索命中让出底色):

状态柔底来源
基线 / seeding--surface-2 / --green-softcomponents.css:330, 334
downloading + checking--st-soft, --blue-soft:335
paused + other / error--paused-soft(transparent) / --error-soft:336-338
sa-no-conf / sa-tracker--warn-soft / --error-softviews.css:94-96
search-hittransparentviews.css:85-86
G8 行状态(.group-row.s-* 等)只染 tag / cat chip, 不涉及 site-chipcomponents.css:354-369

所有新选择器以 html[data-fx-preset] 开头, 避开 _selectors 的 startswith(".site-chip.sa-") 收集, 保证 test_webui_static_skins_widget.py:465-470 的四皮肤键集相等仍绿。

W1-3 · 语义边线与 hover 同属性覆盖

  • box-shadow 是单一属性: 常态 inset 阴影(components.css:337 paused/other、views.css:86 search-hit、components.css:347/349 HR 左边线)在 hover 时会被 fx-mount.css:285 的 stack 整体替换, 这是现状而非新引入, 实施时须逐态确认可接受。
  • 本体改 transparent 后, 画在本体上的 inset 描边与 sa-no-conf 的 border-bottom: 1px dashed 会呈方角矩形边线, 与 ::before 的切角轮廓不完全贴合。W1 先做最小改动 + 真机目检: 若 3px 切角处方角痕迹可见, 再把这几条边线一并迁到 ::before(同一切角绘制层, 被 clip-path 裁成切角形状)。不改 views.css 规则体, 以免撞静态守阵。
  • .f-on 保持 :hover:not(.f-on) 排除(F2); 其 overflow: hidden 裁的是内容/后代, 不裁元素自身外阴影, 不影响本方案。

W1-4 · :focus-visible 预留(D4 的如实落地)

按 D4, 在 fx-mount.css 把同款辉光规则的选择器扩成 :hover:not(.f-on), :focus-visible:not(.f-on), 使「hover 与键盘聚焦共用同一套辉光」在样式层成立、单点不变。但必须如实标注: 当前三种 chip 无 tabindex, 该分支不会命中(§02 末条)。本波不改共用模板, 因此 W1-4 是样式层的预留, 不是键盘可达性的实现。若要让 chip 真正可键盘聚焦, 需改 shared/tpl/ = 动四皮肤 = 破 I1, 属另一件事, 见 O5。

为何不直接省略: D4 是用户拍板结论, 计划不能悄悄丢掉; 但也不能假装已实现键盘可达性。写成「样式预留 + 事实注记」是唯一不扩大范围、不静默假设的落地方式。
