§01目标与设计原则

为什么做: 缺失站点导出/导入 tracker 合并功能(M1~M5, 计划 26-11-03-2337 R1)已全量入库 develop(7 提交, rebase 后即 b01609ca 之前 7 笔), 但只有单测覆盖 —— 真机面(CLI 连真 qB 扫描 tracker 再落盘 YAML)未验。本轮补 CLI 导出面 4 条真机用例。

做到什么程度算成: RM10-11~14 全 PASS(或如实记 FAIL/BLOCKED), 基线切片落档, 官方实跑时刻 HEAD 记为新基线 commit(旧 5b795217 clone5 lineage 解析不到, 按「写不出 commit 从首轮重来」口径重立)。

设计底线 / 不变量:

  • 只读面: 产品侧只调 qB 查询接口; 实例里只动本轮自造的 real-fake 假种子(全程 paused), 真实种子零触碰(环境2 主实例实测 0 枚)。
  • 零外连: announce 全部用 http://127.0.0.x:1/announce IP 字面量 + 死端口 —— hostname 提取(urlparse().hostname)不含端口, 故用互异 IP 字面量造互异域名, 天然零 DNS、零外连; 种子全程 paused 不 announce。
  • token 零落盘: 导出配置指向副实例 56590(bypass_local_auth=True, 空凭据直连, 规程 §2.5.2), 不写任何 token 进配置文件; 两 token 只经环境变量注入。
  • 产物一律落 tests-real/.work/rm10/, 收尾删净; pytest.ini testpaths 不动。

§02现状与痛点

  • 功能面: exporter.py 新增 collect_torrent_tracker_hostnames(逐种集合)/group_missing_domains(共现 union-find)/build_merged_entry(代表=组内最短 tie 字典序); cli.py 加 --split-trackers(配合校验: 缺 --export-yaml 即 parser.error); 单测 tests/test_exporter.py +243 行全绿(基线切片 26-11-04-0035: 4944 passed / 10 skipped / 覆盖率 99%)。
  • 真机缺口: RM10 既有 8 条(26-10-31 轮)只覆盖逐域名旧行为(RM10-01/02), 无合并面、无 --split-trackers、无追加模式合并。
  • 环境前提: 环境2 主实例 56589 真实种子 0 枚(2026-11-01 实测, 本轮开工复核仍 0), 副实例 56590 空库草稿本且 localhost 免鉴权 —— 造法比照 RM05 用副实例, 规避「token 写进导出配置落盘文件」。
