kb.nav 增加「右键置顶 (pin)」: 置顶专区 + 双向显示 + 行内 pin 图标

给本地导航页 kb.nav 加一条人工置顶能力: 右键任一文档即可 pin, 被 pin 的件进「置顶专区」, 同时**仍留在原列表**里 (双向显示), 原列表每件带一个 pin 图标。本文件记录方案与取舍; 决策与实施记录见 §09。

01需求与解读

#用户原话我的解读 (待确认)
1kb.nav 增加右键 pin 功能在文档行上右键弹小菜单, 一项「置顶 / 取消置顶」; 复用现有右键交互语言 (本地页, 自绘浮层)。
2需要有 pin 专区台账视图新增一块**置顶专区**面板, 列出全部被 pin 的件, 空则整块隐藏。
3文档 pin 后同时显示在专区和非专区专区是**增量区**: 被 pin 的件照旧留在原表格里 (受原筛选/排序支配), 专区只是一份"总在眼前"的副本 —— 不做"从列表挪走"。
4为非 pin 区的文档增加 pin 图标非专区 (即原列表) 的每一行都带一个 pin 图标: 未 pin = 空心淡色, 已 pin = 实心高亮。点它即可 pin/取消, 右键是等价入口。
范围边界 (本方案按「最小可用」画线)
  • v1 只做台账视图 (#v-ledger) —— 它是文档列表的所在地, 也是用户日常盯的那张表。卡片墙 / 控制台**不改** (见 §07 D2)。
  • pin 是"看的人"的偏好, 不是文档属性 —— 不写进任何件的 meta, 不碰四工位文件, 不碰 gen_doc_map / nav_data 的数据契约 (数据层零改动)。
  • 零后端改动 —— 不加写接口, 不破坏「服务模式零落盘」纪律 (见 §03)。

2.2 三个交互的形态

交互形态细节
右键菜单 光标处弹一块小浮层, 3 项无子菜单 取消置顶 / 置顶到专区 打开原文 复制仓库路径
首项文案随当前件状态翻转; 菜单项数按 webui.md「一级只放高频」口径收敛, 不设二级。关闭: 点空白 / Esc / 滚动 / 切视图。

置顶专区 toolbar 与表格之间的一条横向面板, 空则隐藏 标题 置顶 · PINNED (n) + 每条一行紧凑条目 (pin 图标 + 形态徽章 + 标题链接 + 取消按钮)。条目多时面板内滚动 (限高)。不受下方筛选/搜索影响 (见 §05)。
空心图钉 = 未置顶 实心图钉 = 已置顶 图标一律内联 SVG (无外链图标库, 守 test_shell_no_external_resources) 不用 emoji 图钉 (code-style 口径: 代码/资源禁图形符号)

03状态与持久化

pin 集合是纯前端状态, 只有一个落点问题: 存哪。两个候选:

方案做法优点代价
推荐 A
浏览器 localStorage		 键 mb-nav-pins = 被 pin 的 link 数组 (顺序即置顶序), 与既有 mb-nav-view 同款写法 零后端改动; http 与静态件两种模式都能用; 不碰仓库文件, 不产生 git 噪声; 实现量最小 只在本浏览器/本机生效, 不跨机器共享; 清缓存会丢; file:// 下个别浏览器禁写 → 降级为本次会话内存态
备选 B
仓库文件 + 写接口		 memory-bank/.nav-pins.json + POST /api/pins, 服务端读写 跨浏览器/跨机器一致, 可入库共享 破坏「服务模式零落盘」纪律; 需新增写路由 + 防穿越/防 CSRF 考量; 静态件模式无法写; 可能被 git 跟踪造成噪声
为什么推荐 A

kb.nav 是"人的导航页", pin 表达的是**个人视线偏好**而非库的事实 (库的事实权威在四工位 meta 单点, 见 conventions/doc-forms.md)。 用 A 可以不触碰任何数据契约与生成器, 风险面最小; 若日后确需跨机共享, 再按 B 升级 (A→B 只换 loadPins/savePins 两个函数的实现, 渲染侧不动)。

键名与 VIEW_KEY 一样集中在一处常量; 读写一律 try/catch 兜底 (既有 saveView 同款), 写失败静默降级不弹错。

两个易踩点 (写进实现注释, 免得后人再踩)
  • 行点击会抢事件: 行上的 click 委托 (L914) 会因按钮冒泡而误开详情抽屉 —— pin 按钮必须早退。

05与既有机制的相互作用

既有机制本方案的处理
形态/状态/类型筛选, 全局搜索专区不受影响 (pin 的意义就是"总在眼前"), 原表格照旧受筛选 —— 因此被 pin 的件在筛掉时不进表格、但仍留专区; 筛中时两处都在 (= 需求 3 的"同时显示")。
排序下拉原表格排序不变; 专区按**置顶顺序** (最近 pin 的在前), 给用户可控的次序。
30s 轮询 /api/datapin 状态与数据无关, 轮询重渲染后原样保留 (S.pins 不被 derive 重置); 已失效 link (件被删/改名) 不渲染, 可选自动清理。
静态导出 --gen-static无需改导出逻辑; 静态件里 localStorage 若被浏览器禁写, 降级为会话内存态 (pin 仍可用, 刷新即丢)。
dark 主题 / 零外链新样式全用既有暗色令牌; 图钉为内联 SVG —— 既有守阵 test_shell_is_dark / test_shell_no_external_resources 继续过。
台账列序守阵图钉**内嵌 title-cell**, 不新增 <td> —— test_ledger_status_column_between_form_and_title 无需改动 (这是选内嵌而非独立列的主要理由)。

07待拍板决策 (审核请逐条给意见)

#决策点选项我的推荐
D1pin 存哪 A 浏览器 localStorage (零后端) / B 仓库文件 + 写接口 (跨机共享) A
D2做哪几个视图 仅台账 / 台账 + 卡片墙 / 三视图全做 仅台账
D3专区是否受筛选/搜索影响 不受 (总在眼前) / 跟随筛选 不受
D4pin 图标放哪 标题单元格内嵌 (零列序改动) / 新增独立 pin 列 (需同步列序守阵) 内嵌
D5右键菜单项 置顶/取消置顶 · 打开原文 · 复制仓库路径 / 只留前两项 三项
D2 / D4 是唯一有连锁代价的两项

D2 若选"三视图全做", pin 集合本身是 link 键、天然可复用, 但三处都要加图标与右键绑定, 工作量约翻倍; D4 若选"独立列", 需同步改 test_ledger_status_column_between_form_and_title 的期望列序 (该守阵是用户定调, 改动要显式记一笔)。

08实施与验收

分三步 (拍板后执行)

  1. S1 结构与样式: 加 #pinZone / #ctxMenu DOM 与 CSS 段; 加常量与 S.pins; 加 loadPins/savePins/isPinned/togglePin/pinZoneItems。
  2. S2 接线与渲染: renderLedger() 画专区 + 行内按钮; wire() 挂右键 / 专区委托 / 关闭逻辑; boot() 装载 pins。
  3. S3 守阵与收尾: 新增 4 条守阵 + docstring 清单; commands run test.full 全绿; 起 commands run kb.nav 人工过一遍 (pin / 取消 / 筛掉后专区仍在 / 轮询 30s 后仍在); 基线切片 + activeContext 回写 + kb.index。

验收判据 (人工可复现)

  • 右键任一行 → 出菜单 → 点「置顶到专区」: 该件立刻出现在专区, 且原表格里它的图钉变实心 (两处同时可见)。
  • 被 pin 的件被状态筛选筛掉时: 表格里消失, 专区里仍在。
  • 等 30s 轮询刷新: pin 与专区不变 (不被数据重播种)。
  • 点行内空心图钉 → pin; 再点 → 取消, 专区同步增删; 点图钉不弹详情抽屉。
  • 专区点条目 → 新标签打开原文; 专区 ✕ → 取消置顶; 空专区整块隐藏。
  • commands run test.full 全绿, 既有 11 条 kb-nav 守阵一条不红。
