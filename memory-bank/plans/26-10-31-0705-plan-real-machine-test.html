§01目标与设计原则

为什么: 规程把真机实测切成 11 片, 但每片都卡在同一件事 —— 没有一个「不碰真实种子也能测」的种子来源。RM00 就是解开这个卡点的基建片: 它不通, 后面 10 片只能靠人工暂停 + 人工目视, 成熟度永远停在 L0。

做到什么算成(验收三条, 与规程 §03 同源): ① L1 正向 —— 构造种子加进 36595 后 upspeed==0 && dlspeed==0 持续 ≥60s 且伪 tracker 收到 ≥1 次 announce; ② L1 反向 —— 关掉伪 tracker 后种子进 error/stalledUP 且无任何外网连接; ③ L2 —— 36596 从 36595 拉完同一构造种子, 期间 upspeed>0 持续 ≥10s, 完成后做种时间增长。

不变量(违反即中止, 不是警告): ① 只碰 127.0.0.1:36595/36596; ② 两个实例里的真实种子全程 paused, 运行期看门狗每 2s 复核; ③ 不动生产 qB(D://Programs//qBittorrent-2 与 D://Programs//Files 下那两个运行中的实例); ④ 构造种子的 announce 只指 127.0.0.1; ⑤ 不改 src/。

§02现状与痛点

2026-10-31 07:00 前后实测(命令走 real.* 之前的手工探测):

事实值
两实例版本qBittorrent v5.2.3(单个 44 MB 静态 exe, 目录里带 profile/ 即自动 portable)
365958 个真实种子, 全部 stoppedUP(非活跃), listen_port=26803, 有 tag MISSING
36596空库(0 种子), listen_port=60537 → 执行中改为 60539(60537 被生产实例占着, 见 D4)
种子字段名upspeed / dlspeed(不是 up_speed; 按后者读会 KeyError)

四个当场踩到的坑(全部已解, 写进 §07 与切片):

  1. 工具 shell 起的 GUI 进程会被连带杀掉 —— Start-Process / cmd start 起的 qB 在命令结束后消失, 无崩溃事件(实测 pid 43224/43636 均如此); 经 explorer.exe <exe> 拉起才活过调用边界。
  2. --portable 不是 5.2.3 的参数(用户指出), 传了会走到异常路径(实测出现一次 0xc0000005 崩溃); 无参数启动即可。
  3. 本机有 HTTP_PROXY, urllib 直连 127.0.0.1 会拿到 502 Bad Gateway(代理转的); 必须 ProxyHandler({})。
  4. 36596 的 API key 鉴权对本机恒 403(换密钥、重启、换源 IP 都无效), 而 36595 同样配置正常 ⇒ 已把 36596 改成 WebUI\Address=127.0.0.1 + LocalHostAuth=false(比原来 0.0.0.0 暴露到局域网更安全), 配置留了两份备份。

§03方案总览

主线: 假种子 + 伪 tracker ⇒ 种子处于「做种中但零流量」; 双实例互传 ⇒ 唯一的「真流量」通道, 且两端都只打本地 tracker。

落点内容
tests-real/lib/qb.py极简 qB 客户端: 绕代理、Bearer 可选、403 自动降级免鉴权
tests-real/lib/bencode.py + torrent.pybencode 编解码 + 造单文件 .torrent(announce 可指任意 URL)
tests-real/lib/tracker.py伪 tracker: /announce 返回 bencode, peer 列表可配(默认零 peer), 记录每次 announce
tests-real/lib/guard.py三层守卫: 端口/镜像路径白名单 · 种子归零 · 2s 看门狗
tests-real/runner.pyCLI: guard/up/down/pause-all/list/run/suite; 默认 dry-run, --yes 才真跑
tests-real/rm00_infra/RM00-01..06 六条用例(pytest 兼容, 不进 testpaths); 编号见切片 §01
.commands/real/config.tomltask id 收口, 文档只写 id

分期: 本轮 = S1–S6(基建 + 三条验收)。不做: 任何业务功能实测(那是 RM01–RM10), 任何 src/ 改动。

§07风险与对策

风险触发条件处置
L2 不通(实例间连不上)progress 长期 0 / 无 peer 连接按规程退路: L2 置 Dropped 并写明原因, 不硬撑第三次排期
真实种子被误启看门狗发现 upspeed/dlspeed > 0立即 pause + 记违规; ≥3 次中止本轮, 结论记 ABORTED
端口被生产实例占用guard 发现端口归属不在白名单拒跑(fail-closed), 不提供 --force。**BT 监听端口同理**: 起停后核 connection_status, 见 D4
qB 版本升级改变 API字段名/端点 404 或 KeyError先修 tests-real/lib/qb.py 再跑, 不绕过断言
实例"没报错但什么都没发生"种子状态正常却零 announce / 零流量先跑 tools/diag_l2.py 看 connection_status 与 announce 计数, 再怀疑加密/防火墙 —— 实测两次根因都在这两项(D4/D5)
