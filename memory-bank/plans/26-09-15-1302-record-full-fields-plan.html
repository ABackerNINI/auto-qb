TorrentRecord 全字段缓存

把 qB 种子对象的全部数据字段一次性纳入 TorrentRecord 快照,数据层成为唯一事实源;后续 WebUI 功能(详情面板、会话流量、限制管理、资源概览、磁链复制...)只做展示接入,不再逐个回头改 compat / record / store 三层。

日期 2026-09-15 分支 backend/develop 范围 src/auto_qb/torrents/ 状态 已实施 · 2026-09-15
00

背景与现状

种子数据链路:主循环每 tick 走 sync/maindata 增量同步,TorrentStore._apply 把变化字段灌进 TorrentRecord.apply_delta,分组、规则、Web 视图全部只读这份数据层。这条链路的字段面目前是收窄的:

qB /api/v2/sync/maindata → TorrentStore.apply_sync / _apply
→ TorrentRecord.apply_delta(21 个快照 slot + _raw 兜底)
→ GroupingMixin 分组索引 · 规则引擎 · WebviewMixin._build_group_view(仅 13 个 _VIEW_FIELDS)
层级内容位置
快照 slots21 个字段(hash/name/state/downloaded/ratio/added_on...),apply_delta 逐字段比较,变化集驱动视图置脏compat.py · record.py
_raw 兜底6 个跳检重加字段(seq_dl / ratio_limit / share_limit_action...),仅属性访问兜底,不计变化集record.py __getattr__
惰性缓存tags_set / state_enum / trackers_info / files,跨 tick 存活record.py
Web 透出13 个 _VIEW_FIELDS 派生值 + HR 展示字段,量化步长防每 tick 重建view.py · web_view.py

缺口:qB 实际返回的字段有 50 个上下(会话流量、ETA、peer/tracker 概要、限制策略、磁链、infohash、队列优先级...),其余在 apply_delta 处直接丢弃。未来每个 WebUI 功能都要回头改 compat → record → store 三层,还要各自证明不影响视图置脏语义 -- 这是不必要的重复成本,一次补齐更划算。

01

目标与非目标

目标:快照字段从 21 个扩展到 qB 种子对象的全量数据字段(预排 52 个,批次 0 定稿);新字段全部可选、带默认值;视图重建成本与现状完全一致;规则引擎 / HR 判定 / 分组行为零变化。

非目标(本轮不做):不改 web.py 与前端;不把任何新字段加入 _VIEW_FIELDS;peers / properties 端点(per-torrent 高频动态数据)不入快照,未来详情功能按 _files / _trackers_info 的惰性缓存模式另行处理;不动 tracker_conf 匹配与 HR 判定逻辑。

02

设计决策 D1-D5

D1

承载方式:slots 全量声明,_raw 降级为前向兼容兜底

所有已知字段声明为 dataclass slots:类型化、C 级属性访问(热路径)、IDE 可见、守卫测试可查。qB 新版本引入的未知字段照旧落 _raw(apply_delta 现有分支),升级 qB / qbittorrent-api 时数据不丢,字段表可增量补声明。

否决:全部塞 _raw 动态承载 -- __getattr__ 兜底是 Python 级派发,热路径慢约一个数量级,且失去类型与文档价值;slots 声明成本是一次性的。

D2

RE_ADD_FIELDS 六字段升格进快照

seq_dl / f_l_piece_prio / ratio_limit / seeding_time_limit / inactive_seeding_time_limit / share_limit_action 本就是 torrent info 字段,当年为省内存放 _raw;WebUI 未来要展示限制策略,一并升格为 slots。skip_checking.py 的属性访问不受影响,RE_ADD_FIELDS 常量保留(CheckAction 引用与启动校验语义不变)。

附带的行为面变化(可接受):升格后这六个字段的变化会计入 changed 集(原先完全静默)--规则引擎不消费它们,最坏情况是一次多余的增量扫描,且语义上更正确。

D3

版本兼容:新字段全部可选,REQUIRED 校验面不变

启动期 fail-fast 校验只针对"缺失即假数据决策"的危险字段,维持现有 27 个(21 快照 + 6 重加)不变。新字段缺失时保持 slot 默认值,不报错 -- trackers_count 等是 qB 5.x 才有,4.x 用户升级 auto-qb 不能炸。apply_delta 的 v is None → skip 语义天然兼容"端点未返回该字段"。

D4

视图纪律:缓存 ≠ 展示,新字段默认不进 _VIEW_FIELDS

本轮分组视图重建成本零变化:静止种子库每 tick 近零成本的现状保持。未来某功能真正展示某字段时,才把该字段加入 _VIEW_FIELDS(高频字段如 eta / num_leechs / availability 需配 _VIEW_QUANTUM 或走 WebSocket 推送,届时是该功能自己的设计题)。加一条测试把这条纪律锁死。

D5

哨兵值原样透传,数据层不做语义解读

completion_on / last_activity 的 -1(从未发生)、eta 的 8640000(无限)等哨兵在数据层原样存取,展示层自行翻译。数据层只保证两件事:存的原样、取的即时。
