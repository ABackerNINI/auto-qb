§01目标与设计原则

1.1 目标与完成判据

把 qB 后端从「只保证 5.2.3」抬到「5.2.3 与 5.3.x 双版本同库同服」,且 5.2 生产全程零行为回归。完成判据(全部满足才算成):

  1. 🔴 修复合入:WebUI「分享限制」命令在 5.3 下可用(请求体含 shareLimitsMode,有守阵测试),5.2 下行为不变;
  2. 跳检重加字段缺口补齐或明确记为已知限制(拍板 D1);
  3. 库钉版 qbittorrent-api==2026.10.1,test.full 全绿并新建基线切片;
  4. 真机升 qB 5.3.x 后,§04.4 六项走查全部通过,基线重测切片落盘;
  5. 双版本支持口径与部署注记回写 memory-bank/ 与根 README(docs issue 销账)。

1.2 设计底线/不变量(违反即破坏既有架构)

  • 不读 app_version:版本差异一律靠字段探测与响应形态双认——这是对 5.3 天然兼容的架构根因(报告 §1.3),本计划不引入版本号分支;
  • 单一 Facade 出口:所有 qB 调用收敛在 core/qbapi.py,新参数只加在 facade 层,调用点显式传值;
  • 快照前向兼容:5.3 新字段经 _raw 落袋(record.py),不进强校验字段;重加白名单 RE_ADD_FIELDS 只增不删;
  • 库钉版下限 2026.8.1 永不降:跳检(is_skip_checking)的 5.3 兼容完全依赖该库对 skip_checking/seedMode 的双发行为(库 torrents.py:423-428),降版 = 跳检静默失效;
  • 禁开 RAISE_ERROR_FOR_UNSUPPORTED_QBITTORRENT_VERSIONS:保持库对未知新版本(如 5.4.0alpha1)的前向兼容姿态,该旗标不进 qbclient.new_client(qbclient.py:52-67,保持只传 host/username/password/api_key/REQUESTS_ARGS)。

§03方案总览

3.1 主线

双版本支持策略沿用报告 §08.1 已验证的库机制:同一个库同时服务 5.2.x 与 5.3——库逐端点按实时探测的 WebAPI 版本门控(version_introduced/version_removed),对过新的 qB 判定只会更宽松;本项目侧不新增任何版本判断代码,只做三件事:facade 补参、重加白名单补字段、守阵测试,然后把库与 qB 按时序抬上去。

4.1 P1 · facade 补参 + 守阵测试(🔴,先合)

  1. facade:core/qbapi.py torrents_set_share_limits(:197)增加形参 share_limits_mode: str = "Default" 并透传给 self._client.torrents_set_share_limits(:214;库签名 Literal["Default","MatchAny","MatchAll"] | None);

4.2 P2 · 跳检重加字段补齐(🟡,与 P1 同批)

实施改道(R1,2026-10-31):issue 建议把 share_limits_mode 补进 RE_ADD_FIELDS,但实施时发现 RE_ADD_FIELDS 同时喂 REQUIRED_TORRENT_FIELDS(qbmanager.py:836 启动期对 qB torrent info fail-fast 校验)——放进去 5.2(无该字段)会启动即报 QbCompatError。实际落点改为 _EXTENSION_FIELDS(同样并入 _SNAPSHOT_FIELDS 与快照 slots,重加透传不受影响);另发现 snake_case kwarg 在 2026.8.1 会发错键名,透传须用 camelCase shareLimitsMode(库 _format_payload 对未知 kwargs 并入 POST data)。
  1. torrents/compat.py share_limits_mode 进 _EXTENSION_FIELDS(实施改道,见上);record.py 快照 slot share_limits_mode: Optional[str] = None(slots 同步守卫 test_torrents.py:934 护航);
  2. core/modules/ops_mod.py _skip_add_call(:1041-1057)的 torrents_add(...) 补 camelCase kwarg shareLimitsMode=tor.share_limits_mode 透传(现有 share_limit_action=tor.share_limit_action 旁边);
  3. 双版本安全:5.2 快照无该键 → 缺省 None → 库不发键,行为不变;5.3 下原样回传,模式不再被重置;
  4. 验收:单测覆盖「5.2 形态快照(无该键)重加透传 None、5.3 形态快照(有该键)请求体带原值」两分支;test.full 全绿。
