外部旧路径种子通知账启动自愈

本篇只回答: 外部旧路径种子通知账(relocate.foreign.notified)在 job 终态/清空历史后永久滞留,如何在不推翻 D4「终态 mismatch 重落 + 恰重发一次」拍板的前提下,用启动接管期的孤儿账自愈清掉陈旧条目。

§01目标与设计原则

目标:在 relocate 模块接管(enabled=true 的启动或热启用)时陈旧 A/mismatch 账归零;活跃 job 的 A 账与全部 B 账不动;D4 重落重告警语义不动;dry-run 零副作用;不 materialize 账键。边界:enabled=false 时 _load_jobs 不被调用(启动/热启用两处均包在 if enabled 内),关闭态的存量账要等模块被启用才自愈 —— 与"闸关闭期间视图冻结"同一边界(Open issue 26-11-21-1326-feat-relocate-foreign-view-stale-gate-off)。

  • 不变量:单一写线程(清理挂 _load_jobs 尾部,主循环线程);写前走只读视图判存在;删除用 pop(h, None) 幂等。
  • 不做:不引入周期定时器;不改在账跳过与 D4 文件清单比对;不动 config.yml 与 auto-qb-data/ 里的人工数据;不写一次性清账脚本。
  • 范围外:确认框反复出现的 UX 问题(另 issue 26-11-24-2150-bug-relocate-probe-reask-ui-loop);兄弟目录洪泛防御(B1 已落地);在账每拍重评(B 方案未采纳)。

§02现状与痛点

  • 取证 2026-11-24 21:30,目标 clone auto-qb-data/state.json:relocate.jobs 为 0,但 relocate.foreign.notified 有 61 条(60 mismatch + 1 A),first_seen 全在 11-21 14:11:41–51;root h:/pt/longseeding/hdhome,location I:/PT/LongSeeding/HDHome,phase 仍 armed,job_id jr-a2ce556d0165 / jr-d4834171bd83。
  • 日志:11-21 14:11:41 activation 扫入池 61 条;14:34 两个 job 收尾完成(当时终态清理逻辑尚未落地);14:41「清空历史: 已清除 4 条,剩余 0 条」;之后 reconnect 扫 0 候选 —— 账在 job 消失后永久滞留。
  • 三条清理出口全错过:_foreign_cleanup_notified 只在种子从 qB 快照消失时删;_foreign_cleanup_job_terminal 只在"非终态→终态"边沿跑,边沿已过;_foreign_full_scan 对在账 hash continue,不再重判。
  • 当前代码 B1 内容根预筛已接线(relocate_foreign.py:454 调用、:521 定义),兄弟目录洪泛不再复现。残留路径仅剩:终态后才到达的 mismatch、空 job 表的存量启动、闸关闭期间视图冻结(Open issue 26-11-21-1326-feat-relocate-foreign-view-stale-gate-off)。

§03方案总览

主线:启动接管期一次性自愈,不做周期扫、不做落账拦截。落点 = relocate_mod._load_jobs 尾部(reconciled 回写之后、prune_success_history 与接管写穿同窗)。单期实施,D1–D8 见 §06。

决策结论默认 / 备选
范围A 窄版自愈:启动清孤儿 + 保留 D4 重落推荐 / C 仅数据清理、B 在账重评均未采纳
时机启动扫一次;落账拦截撤销推荐 / 周期扫未采纳
判据kind ∈ {A, mismatch} 且(job 不在 _jobs 或已终态);B 一律保留推荐
存量靠下次启动自愈清当前 61 条,不写脚本、不改 state.json推荐
开关清理函数本身只受 dry-run 限制、不受 foreign_torrent 限制;但调用点 _load_jobs 仅在 relocate.enabled=true 时执行(启动/热启用),故关闭 enabled 时存量账不自愈推荐(评审 minor 修订)
验收单测 + test.full + 测试 qB 走真机 real.up 路径用户指定

§07风险与对策

风险 / 触发处置
误清活跃 job 的 A 账(判据取盘上陈旧 job 表)判据只认 _load_jobs 已灌回的内存 self._jobs;启动对账先跑,清理后跑。
foreign_torrent=false 时清账但发布视图冻结属已入池 Open issue 26-11-21-1326-feat-relocate-foreign-view-stale-gate-off 的既有边界;本计划只清账不修冻结,清完调一次发布换代。
enabled=false 时存量账不自愈_load_jobs 仅在 enabled 时调用(启动 relocate_lifecycle.py:43 / 热启用 :113,取证 2026-11-24 22:10);关闭态属同一冻结边界,需先启用模块才触发清理。
dry-run 误写账调用点包 if not self._dry_run(),与 _migrate_legacy_accounts 同判;单测守阵。
终态 mismatch 重告警继续刷通知26-11-21-1326-refactor-relocate-foreign-notified-cleanup 的 D4 用户拍板接受(重落 + 恰重发一次);本计划不改,若日后要改须新拍板。
