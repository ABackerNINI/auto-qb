kb.nav 拉取按钮结果可区分

本篇只回答: 怎么让 kb.nav 顶栏「拉取」按钮在「无更新」「真更新」「本地领先」三种成功结果下给出可区分的反馈。

doc-added 26-11-26-2221 · doc-updated 26-11-26-2241 · doc-status Done · 载体 单文件 HTML(dark)
来源 用户指令「kb.nav 的拉取按钮无法区分无更新与更新成功，grilling 后修改」 · 三轮 grilling 拍板 D1–D14 · 前序专题 tasks/26-11-11-memory-bank-nav-pull-retry.md（容错层，本轮只动反馈层）。

§01目标与设计原则

后端 classify_pull() 早已分出四态，message 也有「已是最新 xxx」/「已快进到 xxx」/「本地领先…」之别，但 /api/pull 响应只有 {ok, message}，前端 doPull() 成功分支三态一律显示「已更新」1600ms、message 从不呈现 —— 用户点完按钮不知道究竟拉到了新提交还是本来就是最新。目标：三态在按钮上文案可区分、按钮不换行不抖动、失败路径不变。

不变量：①仅快进语义不动（分叉/重叠/离线一律失败、绝不 rebase），②失败仍走 showError overlay，③CSRF 头 X-Nav-Action 与 POST 方法不变，④静态导出 / file:// 仍隐藏按钮，⑤不新增依赖。命中立档阈值 4（需产出计划）。

§02现状与痛点

后端 nav_server.py:353-366 四态分类；:412-422 三态只把差异写进 message；:484 只回 {ok, message}。前端 nav_page.html:2301-2305 成功三态统一「已更新」+ .ok 绿 1600ms；:137-148 按钮 inline-flex + 13px 图标 + flex:none，无 white-space 约束。守阵 tests/test_kb_nav_shell.py:594-608 只钉「成功 refresh / 失败 showError」，零三态文案断言。

真机锚点：基线 26-11-11-0659 记录过「已是最新 90764579」——后端能算出来，只是前端没显示。

§03方案总览

主线：后端把分类结果作为结构化字段随响应返回，前端按字段切换按钮标签文案；失败态统一 error，仍由 overlay 承载原因。落点两文件 + 一组守阵，单批实施（D1/D6/D7/D8/D11/D12/D13/D14）。
