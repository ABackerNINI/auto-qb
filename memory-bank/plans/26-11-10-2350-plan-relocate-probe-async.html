relocate 同机强探测异步化: run_probe 移出主循环(daemon 单飞 + FIFO 等位 + 意图重放自动续跑)

本篇只回答: relocate 的 E1 同机强探测(run_probe)如何移出主循环线程——daemon 单飞线程执行 + FIFO 等位队列 + 意图重放自动续跑,消除 FS 不可达时最长 ~35s 的主循环阻塞,且探测闸门语义(D5/D6/D7)逐条不变。

§01目标与设计原则

为什么做

issue 26-11-10-0638:探测的证读/证写/清理三段轮询全走 time.sleep(预算 10+10+5s,轮询间隔 0.25s,另加 qB HTTP 超时 connect 3s/read 10s,qbclient.py:22),且经 _ensure_probe 在主循环线程同步执行——FS 不可达时单次探测阻塞整库监控约 25s+(上界 ~35s)。与成文纪律三处直接抵触:relocate_lifecycle.py:267「单步零阻塞」、relocate_common.py:18「单步 < 50ms」、taskqueue.py:319「无 run 内 sleep」。

做到什么程度算成

  • 探测全程(FS 正常与故障)不再占用主循环线程可感知时长——主循环单步仍 < 50ms;
  • 迁移在探测结论到达后自动续跑,web 与规则两条路径均然,不要求用户/规则重试;
  • 探测闸门语义逐条不变:闸门 D5 位置契约(passed 前零建账零 setLocation)、闸门 D6 无旁路、闸门 D7 缓存决策表;
  • 既有探测相关测试(test_relocate_probe.py 36 用例 + 执行闸 test_relocate_exec_probe_gate.py 10 用例)语义保留。

设计底线/不变量

  1. run_probe 本体零改动:自带预算与 finally 清理的自包含黑盒,原样进线程;
  2. 黄金法则#5:state 写(probe_put/pending 增删)只在主循环线程;探测线程零 state 写、零建账、零 setLocation;
  3. 同步直通路径不动:单成员组(闸门 D2)/dry-run/assume_shared(闸门 D7)/same_fs_proved(闸门 D4)/缓存命中(闸门 D3)各分支行为逐条不变;
  4. 全局单飞:任一时刻至多一个探测在飞(FS 故障不放大);
  5. 零新增配置键:validate_config 不动。

§02现状与痛点

现状(取证 2026-11-10 08:32,认领复验,行号为当日值)

  • relocate_execute(relocate_exec.py:1041)先 _buckets 分桶(:1067),for records in groups: 循环内每组经幂等 skip/部署闸/evaluate_group 后调 _ensure_probe(:1126→定义 :1134)——探测按组触发,一组一个指纹(src save_path → dst);单成员组完全不探测(:1153,闸门 D2)。
  • _ensure_probe 决策表按序短路(:1140-1151 docstring):单成员组跳过 → dry-run 跳过 → assume_shared 跳过 → same_fs_proved 放行 → 指纹缓存命中放行/blocked → 未命中则 run_probe 纯同步执行(:1209,常态 ~1.3s),其后按 probe.status/probe.env 写缓存或返回 blocked。
  • run_probe(relocate_probe.py:321)自包含:造种→落源→add→证读(可见轮询 _await_probe_torrent + recheck 轮询,预算各 10s)→证写(_write_proof_poll,10s)→清理(_cleanup,5s);轮询体全 time.sleep(0.25);四常量 relocate_probe.py:48-51;finally 保证所有出口清理(:409-411)。
  • 两条上游均在主循环线程:规则动作(rules/actions/transfer.py:33,interval 经 TaskQueue.run_due、事件经同步相位分派)与 web 命令(commands_torrents.py:475/:707,经主循环 consume_commands)。
  • 探测结论三去向:执行闸(建账与否)、预检只读缓存(relocate_plan.py:588,零副作用)、probe_put 持久化(relocate_mod.py:126-135,容器 state.data["relocate"]["probes"])。

痛点证据

复验结论(2026-11-10 08:32,已记入 issue):指控链全部成立——同步调用无线程/异步、三段 sleep 预算 25s、上游两路径均主循环线程、与三处成文纪律抵触;R4 行号漂移:run_probe 174→321、_ensure_probe 707→1134。项目先例(移出主循环两形态):notify 系 daemon 线程(infra/notify.py:229);relocate 回收系独立进程(_spawn_daemon relocate_exec.py:1684,detached 子进程,非线程)。无 ThreadPoolExecutor、无主循环 asyncio 化。

§03方案总览

主线(拍板 D1-D10,见 §06):探测执行位置从主循环线程挪到 daemon 线程(拍板 D1),run_probe 本体零改动;结论经线程安全结果队列回主循环,由 on_task_line 消费(拍板 D9);迁移经「意图重放」自动续跑(拍板 D2/D6);pending 与等位队列持久化 state(拍板 D7);单飞 + FIFO 等位(拍板 D3/D10);web 两段回执(拍板 D8)。

落点

  • 探测 runner(relocate_probe.py 内小型封装):daemon 线程跑完整 run_probe;全异常捕获→合成 failed verdict(带 reason),杜绝「线程死→verdict 永不到→pending 挂死」;结果投递 queue.Queue;runner 可注入——测试内联同步执行,既有用例语义保留。
  • _ensure_probe 改造:指纹缓存未命中时不再同步跑 run_probe,改为:单飞空闲→入队并立即 kick 启动探测线程;在飞/等位→同指纹把 hashes 合并进已有 pending 条目(去重),异指纹追加等位队尾;返回「探测中」gate 回执(与 evaluate_group blocked item 同形,note 标注「同机探测已入队」,web 侧凭它发受理段回执)。
  • pending 容器:state 键族 relocate.probe_pending,按指纹 FIFO 列表,条目 {fingerprint, hashes, src, dst, origin, ts}——只存意图不存快照(拍板 D6),重放走 relocate_execute 幂等面全新鲜;持久化 ⇒ 探测窗口(~35s)内进程退出,重启后自动续跑(拍板 D7,黄金法则#3)。
  • verdict 消费(拍板 D9):RelocateModule.on_task_line 在 lifecycle 步进之前消费结果队列,每 tick 至多一条:①probe_put(按闸门 D7 原语义写/不写缓存)②重放队首条目(re-invoke relocate_execute:命中 passed 缓存→闸门放行→_start_job;命中 failed 缓存→blocked)③清条目④单飞槽空闲→kick 下一条探测(主循环只启动线程,不等待)。防自环:重放结果若仍是探测 gate blocked(env=True 失败未缓存的闸门 D7 2 情形)→丢弃条目终止自动链,下次真实触发(规则 tick/用户)再试——否则自己发起的重放会无限再探。
  • web 两段回执(拍板 D8):命令即时回执「已受理:同机探测进行中」;verdict 消费 tick 向同一回执补发终态。补发通道按 runtime_commands.py 回执存储面现状定(回执本就是主循环单写者,:293),S4 内钉死形态;规则路径回执形态不变。
  • 残留兜底(拍板 D4):优雅退出不 join 探测线程;中途残留(add 完成/证读中途/证写中途/清理中途各断点)交既有 sweep_probe_residue 启动清扫,S5 逐一核验覆盖、有洞在 sweep 补。

整组移动影响面(拍板 D10 的依据,已核码)

场景行为
同组整组搬(最常见)零退化:全组一个指纹→一次探测,pending 收全组 hash,verdict 后整组同批重放续跑,常态多 ~1.3s 延迟
一次点击跨多路径批量(桶出 G 个组)组1 探测,组2..G 入等位队尾,FIFO 逐个自动续跑,常态总代价 G×~1.3s;不再要求用户重点
两组同时各搬(规则并发/连点)后来者入等位队,verdict 消费后自动接续;规则路径自愈语义不变

线程内探测异常 → verdict 丢失 → pending 挂死线程被杀/解释器异常/不可预期崩溃runner 全异常捕获合成 failed verdict(S1);兜底:pending 条目带 ts,启动清扫对超龄条目(> 探测上界 × 裕度,如 120s)清条目并记审计
