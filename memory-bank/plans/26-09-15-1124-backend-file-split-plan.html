摘要与判定

用户诉求是"体积较大、职责不清"的文件。按此过滤, 44 个文件里同时满足两条的只有一个: qbmanager.py(1118 行) —— 它把核心循环、Web 视图组装、Web 命令消费、汇报确认跟踪、 qB 客户端构造五簇职责堆在一个类里, 是历代 WEB UI 轮次(第五~七轮)持续往里加方法的结果, 基线 2026-09-05 时约 800 行, 现已涨到 1118 行。其余三个大文件(schema 855 / torrents 725 / validation 687)属于大而职责单一: 拆它们不是为了救架构, 是为了导航与并行修改的冲突面。

02

拆分原则(硬约束)

  • 纯移动, 零行为变化。不改任何函数签名、日志文案、返回值语义; 拆分是搬家不是重写。 回归守卫 = 现有 871 个测试 + --dry-run 冒烟, 不新增测试(没有新行为可测)。
  • mixin 契约照旧。新 mixin 文件头部 docstring 必须声明所依赖的宿主属性 (config/store/api/task_queue/client/state/...), 与现有 6 个 mixin 同模式。
  • __init__ 是唯一组合根。全部实例状态(web_commands/_web_results/_reannounce_pending/ _group_view/_singles_view/_search_index/_traffic_view/_suppress_events...)留在 core __init__; 新 mixin 是纯方法簇, 不携带状态初始化。
  • 单一写线程不动。mixin 化不引入线程、不改队列写入者; 命令仍由主循环线程经 _drain_web_commands 消费, Web 线程仍只读快照+投递。
  • 模块转包必带 re-export。torrents / config.schema / config.validation 转包后, __init__.py 重导出全部既有公共名与被 tests 引用的私有名 (_VIEW_FIELDS/_VIEW_QUANTUM/_strip_none), 保证调用方与测试零改动。
  • 依赖方向不新增环。新 mixin 依赖 ⊆ {config, torrents, utils, qbapi, taskqueue}; qbclient.py 仅依赖 qbittorrentapi + stdlib; 遵守 rules/base.py "不 import qbmanager"的防环模式。
  • 每批独立提交。中文一句话提交信息; 任何一批之后停下, 仓库都是完整可发布状态。

3.1边界裁量说明

  • status_snapshot 留守: 它同时服务 Web(/api/status)与托盘 UI 轮询, 不是 Web 专属, 放 core 更诚实。
  • _cmd_build_search_index 归命令簇: 虽然业务上是搜索, 但它是 handlers 分发表的一员, 与分发逻辑放一起可读性最好; _build_search_index 本体仍在视图簇。
  • apply_new_config 留守: 配置生命周期(L0/L2 重建 + R 级重启)是引擎职责; 若拆后 core 仍 >650 行, 备选项是再抽 mixins/config_reload.py(~75L), 本批先不动。
  • 组合签名变更为 8 mixin: QbManager(RuleEngineMixin, TagsMixin, CheckingMixin, GroupingMixin, TrackerMixin, SpeedCurveMixin, WebviewMixin, WebCommandsMixin); 新方法名与现有全部不冲突, 追加在尾部即可。
  • 测试 import 面改动(仅 2 文件): test_qbmanager.py 与 test_local_qb_service.py 的 LocalQbClient / _new_client 改从 auto_qb.qbclient 导入; _throttle 留守不动。其余测试零改动。
