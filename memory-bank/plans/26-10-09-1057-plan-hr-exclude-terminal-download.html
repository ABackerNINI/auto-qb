03方案设计

3.1 一句话

把名称粗配的候选面从「全量本地种子名」收窄为「受管(未排除)本地种子名」。理由: 排除种子在本实例已无对账义务、判定侧对其恒返 None, 因此.torrent取回的身份没有任何消费方 —— 让它的名称继续驱动身份下载纯属浪费。

3.2 数据流 (改前 / 改后)

# 改前: 名称面 = 全量锚点名
_WaveContext.local_names   = (a.name for a in anchors.values() if a.name)          # 含被排除者
_row_looks_local(row)      = any(fuzzy_name_match(n, row.name) for n in local_names)
  ⇒ 终态行粗配命中"被排除种子" ⇒ pending_downloads ⇒ 取一次 .torrent(无消费方)

# 改后: 名称面 = 受管锚点名(排除位派生)
_WaveContext.local_names_managed = (a.name for a in anchors.values()
                                    if a.name and not a.excluded)                   # 派生自同一排除位
_row_looks_local(row)      = any(fuzzy_name_match(n, row.name) for n in local_names_managed)
  ⇒ 只命中被排除种子 ⇒ 不下; 命中任一受管种子 ⇒ 照旧下
# !local_hashes 保持全量: 排除种子仍被"认识"(行带其 infohash 仍判本地命中), 见 §03.3

3.3 为什么在「名称候选面」动刀, 而不动命中面

面载体作用本项
命中面(身份)local_hashes行带 infohash 时判「本地命中」/ 站点换 tid 接管 / _run_downloads 回填比对 —— 「排除 ≠ 不认识」的实质载体保持全量, 一行不改
名称候选面(启发式)local_names唯一用途 = 终态行的身份下载触发器(决定"要不要去确认身份")收窄为受管集

名称面从不参与定论(定论一律 infohash 精配), 它只是「这个陌生终态行值不值得花一次请求去查身份」的启发式。排除种子不值得 ⇒ 从候选面移除不损失任何判定能力。实现即「把被排除种子从粗配候选集里剔除」 —— 候选集只放受管名, 不引入任何额外的「排除集判定」分支。

实现形态约束(唯一正确写法, 非拍板点) —— 收窄候选集, 而非「命中排除名即 return False」: 粗配是宽松判据(FUZZY_NAME_K=12: 标题信号串存在 ≥12 字符连续重合即判疑似, 噪声词已剔除), 同一部剧的不同集 / 季会互相命中 —— 实证(2026-10-09, HEAD 1f5334e5): 
行名 Example.Ultra.S01E01.1080p.x265-GROUP
  命中 排除种子 Example.Ultra.S01E01... ?  True
  命中 受管种子 Example.Ultra.S01E02... ?  True   # 同一行同时命中(标题前缀 ≥12 字符重合)
跨季 S02E01 vs S01E01(排除): True     完全不同剧: False
故「一行同时粗配命中排除种子与受管种子」确实可能发生(同剧不同集/季 + 一颗被排除一颗受管), 不是纯理论边界。唯一正确写法 = 候选集只放受管名(not a.excluded): 命中任一受管名即下载(保守方向 —— 绝不漏掉受管种子的身份); 若写成「命中排除名即 return False」, 会误杀这类行、漏下受管种子的身份(漏管束 > 多一次请求)。这不是二选一, 是形态约束, 故不设 D2。

3.4 与 A 档硬规则的边界 (不可混改)

触发器为 elif lane == LANE_SCOPE or self._row_looks_local(row, wave) —— A 档(考察中)行经前一个析取项无条件下载(短路, 连 _row_looks_local 都不求值), 这是「A 命中是唯一管束正证据、行身份完备性不依赖名称推断」的硬规则, 与本项无关。本项只影响第二个析取项, 即非 A 档的 B/C/D 终态行。issue 已明示「别把 A 档硬规则一起改掉」。
