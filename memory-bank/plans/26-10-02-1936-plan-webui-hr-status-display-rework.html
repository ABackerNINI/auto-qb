#问题现状目标
1 站点状态区不可折叠 「站点状态」块(settings-detail.html:244-365)打开 HR 分区即常驻展开, 站点多、表长时把配置项挤出视野; 打开分区即拉一次 /api/hr/status + 每站点明细(config_hub.js:379)。 整块可折叠, 默认折叠; 折叠态头部保留一行摘要(站点数 / 数据截至); 展开交互与「运行日志」块同款(hb-blk-hd + 展开/收起钮)。
2 表格拥挤多栏换行, 展开后要全屏 表① 十列塞在设置分区卡片内, 名称/状态等列大量换行, 行高参差难扫读。 提供「全屏」入口把表格扩展到除导航栏(顶栏)与状态栏外的整个视口; 推荐做成覆盖式弹窗(同一表格组件换容器, 关闭即回原位), 备选内嵌全屏 —— 见决策点①。
3 老旧(未做种)种子混排 表① 行集 = 站点 HR 清单全量(含失踪行, 上轮拍板), 其中大量是本地从未下载/已删除的老旧条目, 与本地正在做种的条目混在一起。 后端为每行导出「本地做种」标记(与本地库 join); 默认只显示本地做种中的行, 工具条提供按钮一键显示老旧行 —— 判定口径见决策点③。
4 表头不能排序 表① 行序固定为后端「档位·下载量」口径(status.py:396), 前端无任何排序控件。 表头可点击排序, 交互对齐种子页(shared/sort.js setSort 三态: 首点降序 → 再点升序 → 第三次恢复默认; 箭头指示激活列); 本期不做拖动列/隐藏列。
5 「B毕业」表达不清 表① 上次核实列来源徽章显示「B 毕业」(status.py:66 SOURCE_TEXTS); 「毕业」是 PT 圈黑话, 与档位「B 已达标」并存时口径混乱。 统一替换为「已达标」系文案(与档位人话 LANE_TEXTS.B = "已达标" 对齐); 全部出现位置与替换口径见 §3.5, 是否连带注释/日志一并处理见决策点②。
6 信息层级混乱 一行里「档位: B已达标」「上次核实(放行判定): 未核实」「状态: 在列 · 最近被见到 10-02 18:33」三段文本长相相近、堆在一起, 需逐字分辨才能读出含义。 重组为三段结构化列: 档位徽章列 / 核实结论列(结论徽章 + 来源·时间小字)/ 在列列(在列·失踪徽章 + 最近被见到小字)—— 版式细节见 §3.6 与决策点④。

§3

方案设计(逐条)

3.1 问题 1 · 站点状态区可折叠, 默认折叠照抄运行日志范式

  • 交互: 「站点状态」.hb-blk-hd 头部加「展开 / 收起」按钮(文案随态), 内容区 v-show; 默认 hrsOpen = false。
  • 折叠态摘要: 头部副题位显示一行状态 —— 未加载: 「默认折叠, 展开后读取」; 已加载: 「N 站点 · 数据截至 <ts>」(数据在 hrs.loaded/hrs.sites 里现成可取, 不新拉)。
  • 取数时机(决策点⑤): 推荐「首次展开才拉」—— 打开 HR 分区不再自动 loadHrStatus()(config_hub.js:379 现状), 改由展开触发; 折叠态点「全部立即拉取 / 刷新」= 顺手展开再拉(hubLogsLoad 同款)。
  • 不持久化: 展开态不进 localStorage —— 与运行日志一致(state.js:241-249 先例), 每次进分区默认折叠; 表② <details> 排障视图的「不持久化」纪律不变。

3.2 问题 2 · 全屏查看: 覆盖式弹窗(推荐) vs 内嵌全屏决策点①

  • 推荐: 覆盖式弹窗 —— 站点卡片工具条加「全屏」钮, 打开一个除顶栏与状态栏外占满视口的覆盖层(position: fixed; top: 顶栏底缘; bottom: var(--statusbar-h)), 表格组件原节点移入覆盖层(过滤器/排序/数据原样带过去, 零新请求), 关闭(✕ / ESC / 点遮罩)后移回原位。优点: 复用 modal 基建思路、上下文不丢、三套 UI 只需各自一份全屏变体样式。
  • 备选: 内嵌全屏 —— 站点卡片原地扩展铺满内容区。缺点: 要把 .hb-blk 暂时跳出设置分区的栅格/滚动容器, 三套 UI 布局各异, 侵入大、关闭后还要恢复滚动位置, 得不偿失。
  • 弹窗内布局: 头部 = 站点名 + 数据截至时间 + 关闭钮; 主体 = 工具条(档位 chips / 老旧切换)+ 表格; 表格占满宽, 名称列不再限宽换行。
  • ESC 纪律: 2026-10-02 已有计划把 ESC 定为「清除全部筛选」兜底键(26-10-02-1632)—— 全屏弹窗的 ESC 关闭须挂弹窗层自身的作用域且在筛选清除之前拦截, 实现时与该计划的行为核对, 不抢不漏。

3.3 问题 3 · 默认只显示做种中的, 按钮查看老旧后端 join 出标记, 前端本地过滤

  • 后端(推荐, 决策点③): api_hr_site_entries 响应层用 manager.store.by_hash 按 infohash_v1 → v2 顺序探测本地库, 给每行加 local_present: bool(本地库中存在); state 语义分类复用 views.py:143-162 单点。是否细分「做种中 / 暂停」进决策点③(a/b 选项)。
  • 前端: 工具条在档位 chips 右侧加一个切换按钮 —— 默认「显示老旧种子 (N)」, 点击后变「只看做种中 (M)」; 过滤与档位 chips 叠加(AND), 纯前端本地过滤, 不回后端、不重拉。
  • 计数: 按钮文案里的 N/M 由当前行集现算(和档位 chips 计数同一层); 过滤后空态文案区分「该站点本地没有 HR 种子」与「该档位暂无」。
  • 口径提醒: 「本地不存在」≠「无 HR 义务」—— 站点清单里本地从未下载的条目也在此列, 这正是用户要的「老旧」噪音桶; 默认隐藏它们不改变任何判定/打标行为(纯展示层过滤)。

3.4 问题 4 · 表头点击排序, 对齐种子页三态 + 箭头, 本期不做拖动/隐藏列

  • 三态语义(同 sort.js): 首次点击该列 = 降序 → 再点 = 升序 → 第三次 = 恢复默认序(后端「档位·下载量」口径)。列间切换 = 直接以新列降序开始。
  • 箭头样式: 仅激活列显示箭头(升序 ▲ / 降序 ▼, accent 色), 非激活列 hover 出浅色箭头位 —— 与种子页「激活列才有 arrow」一致(tpl/torrents.html:9-13)。
  • 排序键: 按原始值排不按人话 —— bytes/ratio/秒数/epoch 数值比较, 名称/tid/done_iso 字符串比较, 档位列按 A<B<C<D 固定秩; 空值(null/—)恒排最后(两个方向都不参与反转)。排序在当前过滤后的行集上进行, 纯前端, 不回后端。
  • 可排序列: 档位 / 核实结论(按 verified_ts)/ 名称 / tid / 上传量 / 下载量 / 分享率 / 还需做种 / 完成时间 / 在列(按 last_seen) —— 全列可排; 表② 波次表不接排序(行数 ≤4)。
  • 明确不做(用户口径): 拖动列、隐藏列、列宽拖拽、列设置持久化 —— 种子页那套 colDrag/双轨机制不引入。

§5

分阶段实施计划(拍板后执行)

四个阶段强顺序: ②③ 都改同一批前端文件, 串行避免互撞; ① 为 ③ 的数据前提(若决策点③选前端 join 则 ① 相应收缩)。 每阶段由一个独立子代理串行执行, 可独立验证、独立提交。

阶段 1 · 后端:「本地做种」标记导出 + 「毕业」文案统一预估 4 src + 2-3 test, ~120-220 行

  • src/auto_qb/webui/server/routes/hr.py(api_hr_site_entries 响应层)
    用 manager.store.by_hash 以 infohash_v1 → v2 顺序探测本地库, 每行追加只读标记 local_present(布尔; 是否细分做种/暂停态按决策点③拍板); join 口径注释钉在路由层, entry_details 本体保持纯站点口径。
  • src/auto_qb/hr/status.py(:66 SOURCE_TEXTS; 如决策点③需要可在 EntryDetail 加字段)
    SOURCE_TEXTS[SOURCE_SATISFIED] "B 毕业" → "已达标"。
  • src/auto_qb/hr/resolve.py(:234, :350)
    "B 档毕业后移出" → "已达标移出"; "在线·已达标(毕业)" → "在线·已达标"。
  • src/auto_qb/hr/events.py(:109)
    日志行 "全部毕业/被清除?" → "全部已达标移出/被清除?"。

    SOURCE_TEXTS 新文案断言; local_present 三态用例(本地存在/不存在/仅 v2 命中); 用户可见字符串「毕业」零残留守阵。

明确不做的事(范围守卫)

  • 不做拖动列 / 隐藏列 / 列宽拖拽 / 列设置持久化(用户明示「暂不做」) —— 种子页 colDrag/双轨机制不引入;

  • 不改任何 HR 判定 / 签发 / 取数调度逻辑 —— local_present 只是展示层只读标记, 过滤纯前端视图操作;
  • 不进轮询: 全屏/过滤/排序零新请求, 折叠展开不新增定时器;
  • 不新增第二套悬浮层: 表① 单元格仍不挂原生 title(hr-tooltip-overlap.md), 新徽章不加悬浮提示;
  • 不动表② 排障视图的结构(本轮只继承其成对样式纪律);
  • 不碰红线文件(config.yml / auto-qb-data/); 计划外发现的问题一律入池 memory-bank/issues/, 不顺手修。

待拍板决策点(每条含推荐项)

#决策点选项推荐理由
① 全屏展开方式 (a) 覆盖式弹窗: fixed 层让出顶栏与状态栏, 表格节点移入, 关闭移回
(b) 内嵌全屏: 站点卡片原地铺满内容区
(c) 新浏览器标签/窗口		 a (a) 复用 modal 基建思路、上下文不丢、过滤/排序状态随节点保留、三套 UI 只需一份全屏变体样式; (b) 要把 hb-blk 暂时跳出设置分区滚动容器, 三套 UI 布局各异侵入大; (c) 脱离应用上下文且多窗口状态不共享。
② 「B毕业」替换口径 (a) 用户可见 4 处全改(§3.5 A 类)+ 测试同步, 注释 6 处不改
(b) 注释一并改(全库「毕业」清零)
(c) 仅改表① 徽章一处(status.py:66)		 a (a) 用户可见面全清、与 LANE_TEXTS.B「已达标」对齐, 注释保留内部域术语便于 grep 溯源、diff 最小; (c) 会留下 hr-pop/CLI 里另两种「毕业」写法, 口径依旧分裂。
③ 「做种中/老旧」判定口径与过滤位置 (a) 后端 join, local_present = 本地库存在(含暂停/异常), 本地不存在 = 老旧
(b) 后端 join, 严格 state 分类 == seeding 才算做种中
(c) 前端本地 join(零后端改动)		 a (a) 暂停/异常的 HR 种子仍是义务对象, 折进「老旧」会造成「已无义务」错觉; 主噪音恰是本地从未有过的清单行。后端 join 让键(v1/v2/大小写)与 state 分类口径收单点(views.py:143-162), 前端零新逻辑; (c) 违反 contract-api「前端消费后端算好字段」纪律。
④ 信息重组版式 (a) 三列结构化: 档位徽章 / 核实结论(徽章+来源·时间副行)/ 在列(徽章+最近被见到副行)
(b) 档位+核实合并一列双行
(c) 维持三列仅微调措辞不改结构		 a (a) 三段信息视觉结构各异(色徽章/圆角徽章+副行/描边徽章+副行), 不再靠逐字分辨; 列名「核实结论」「在列」直接承载口径; (b) 合并后 B 档+已核实重复出现「已达标」两词; (c) 不解决「三段文本堆叠难分辨」的主诉。
⑤ 折叠后取数时机 (a) 首次展开才拉(运行日志 hubLogsToggle 同款)
(b) 打开 HR 分区仍立即后台预拉(折叠只藏 UI)		 a (a) 默认折叠的本意就是「不常看的东西不为它常备请求」—— 打开分区不再背一次全量状态 + 每站点明细; 折叠态点拉取/刷新 = 顺手展开再拉, 已有先例无新交互。

除上表五点外, 本计划还有两处默认值(非阻塞, 可随拍板一并调整): ① 展开态不持久化(与运行日志一致, 每次进分区默认折叠); ② 表② 波次表不接排序(行数 ≤4 无意义)。
