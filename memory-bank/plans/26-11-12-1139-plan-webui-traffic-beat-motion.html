§01目标与设计原则

背景

实时流量图 (shared/qb_traffic_chart.js, uPlot 1.6.x Canvas) 每次续拉走 :1017 的 prev.setData([data.xs, data.up, data.dl]) 原地快路，两帧之间瞬时换数据、无中间态。用户要「有动感、节奏把握好」: 动画集中在拿到数据后的几百毫秒内，不超过 1 秒; 可以接受动画更新慢于数据最多 1s。参考对象为音游的判定帧反馈。

R1 关键补漏: 「瞬时更改」实际有两层，且主因不是数值——① 整图左移一格: points 是定长桶数组，每拍最左桶出窗、右端进新桶，xs 随之重建，而 scales.x 只有 time:true、无固定 range，uPlot auto-range 跟随数据，于是所有旧值在屏幕上瞬时左移一格; ② 末点数值跳变。初版只处理了 ②，且 §04 demo 是「40 点原地改末点、不 shift」，与生产滚动行为不符。本版把 ① 抽成 L0 左移底座，五个模板全部跑在它之上。

R2 视觉升级: 用户反馈初版模板「不够大胆前卫」，且 T3 整曲线残影不适用 —— L0 已经把旧帧摆回旧位置再推开，再叠一层整曲线残影是双重影、遮挡谱面、生产侧还要缓存一份 2880 点旧窗口。本版退役该模板，槽位由「棱镜碎裂」接替，并引入所有模板共用的 视觉引擎 V（色彩 / 形状 / 粒子三层 + 严格图层顺序），让动效大胆但绝不盖住读数。

R3 双轨补漏: 用户 26-11-12-1235 指出「流量图具有上传 / 下载双曲线，目前的模板只有 1 条有特效」。核查 qb_traffic_chart.js:1052-1065 确认生产是 series[1] 上传 (--today-up) + series[2] 下载 (--today-down) 两条独立折线，共用 y scale、各自 spanGaps:false; :1017 的 setData([xs, up, dl]) 同时换两列; tooltip（drawer.html:124-125）、统计栏图例（:155-156）、限速虚线（:968-982）全是双通道。初版实验台第二条曲线只是 disp.map(v => v×0.34+0.06) 的暗灰静态陪衬，既没有独立数值中间态，也没有独立 Δ / 等级 / 反馈，等于把一半数据通道排除在方案之外。本版补 L1 双轨底座，五模板全部按双轨运行。

R5 扫描束重构 + 并入综合模板: 用户 26-11-12-2147 指出「故障扫描也加入综合模板，但是竖向扫描线需要更改，当前的竖向扫描线不够精致」。核查旧实现只有一层 10px 对称渐变 fillRect + 3 条固定长度实心速度线: ① 对称所以没有方向感，读不出「扫」; ② 只有一层，没有硬核与边缘层次，1x DPR 下被抗锯齿糊成半透明胶带; ③ 位置在两轨中点、与曲线无关; ④ 亮束本体若横穿全幅就会压住谱面。本版把 T4 扫描束重做为双相位「亮束入场 + 回声全幅扫掠」: 亮束由「亚像素 1px 硬核 + 2.5/5/10/16/24/34px 六层 Lv 晕 + 双侧 ±1.6px 色散 + 5 段非对称彗尾 + 7 条固定模式梳齿（R6 起改 3/5/7，随 lead 等级）」构成，纵向亮度按两轨末点 y 的包络起落; 亮束止于判定线，扫掠感交给 α≤0.20、按曲线包络着色的回声承担，全程零 fillRect 铺底。同时把 T4 并入 T6 综合模板（强度 ×0.78），模板数量不变。（R7 已把回声从整幅扫掠改为「越线 100–200px 内淡出硬停」，见下条）

R7 回声行程收紧: 用户 26-11-12-2325 指出「竖向扫描线不要扫过全屏，在过右边的线后逐渐透明，大概在过右边的线后 100–200px 的位置完全消失」。R5 的回声是 g.R → g.L 的整幅扫掠（0.18–0.7beat 走完全幅宽），虽只有 α≤0.20 + 曲线包络，仍是一道横穿数据的竖线——与 I6「装饰不得抢谱面」和 R4「背景不得整块变化」的气质相反，也会让读数区每拍被一条移动直线切过。R7 把回声改成受控行程 + 距离衰减: 越过判定线（绘图区右缘）后，alpha 按已走距离 pow(1 − d/span, 0.85) 递减，d = span 处直接停止绘制（几何保证，不是把 alpha 调小到看不见）; span 取 100–200px（auto = 绘图宽 ×0.22，clamp 到该区间，宽屏约 150–200px、窄屏取下限 100px），并把行程窗口收到 0.18–0.45beat 做匀速位移，让淡出沿路径均匀分布而不是「先冲后停」。整幅扫掠降级为 full 对照档（导出标注 comparison-only，不交付）。束体的六层结构、曲线包络、梳齿、切片全部不动——本次只改回声能走多远。

R8 调参产品化 + 交付收敛: 用户 26-11-13-0020 要求「将数值调整设计为一个单独的页面挂在右键菜单上，只做 T6，其余模板当参考但不实现」。此前所有控件都长在计划文档的 §04 实验台里，产品里没有任何调参入口 —— 用户要么接受写死的默认值，要么改代码。R8 把控件搬进产品: 流量图右键出一张独立面板（非模态浮层，边调边看），滑杆即时生效，「预览一拍」解决采样 600s 时等不到下一拍看效果的问题; 参数存 autoqb.ui.qbFx，不进配置 schema。同时交付范围收敛到 T6: T1–T5 只作为 T6 的构成要素与设计证据保留在 §04，不单独接线。一处硬边界: 采样周期在面板里只读 —— 改它要动后端与数据文件（config.qb_traffic 的 sample_interval_multiplier 与落盘聚合桶宽），面板只管观感，不碰采集。

R4 背景与霓虹重构: 用户 26-11-12-1309 指出三点 —— ① 背景不要闪烁: R2 的「色调呼吸」会在判定帧给整个绘图区叠一层主色相半透明色，整块背景亮度随拍变化，正是 drawer-switch-flicker.md 所警惕的「快的中间态本身也是一种闪」; ② 右边缘背景应与其它地方一致: R1 为演示新桶入场给 g.R → W 铺了 rgba(109,179,201,0.05) 底色，形成一条常驻色差带; ③ 曲线描边被 D1 钉成语义色后，T1 靠「给曲线 / 背景染霓虹色」的表现不再成立。本版删除两处整块铺色、把霓虹收成只作用于非曲线、非背景元素的横切 N 层，并新增 T6 综合模板把 T2 / T3 / T5 / T1 组合起来。

目标（做到什么程度算成）

  • G1 可见的中间态: 数据落袋后有可感知的过渡，覆盖整图左移一格与末点数值跳变两层，不再是硬切; 显示值与真值的偏差、以及视口偏置，均在 1s 内归零。
  • G2 节奏正确: 冲击锚在判定帧 (t=0)，主区 <1s，次区极轻且默认开、可调关; 采样周期变化时自动适配，不写死 1.5s / 3s。
  • G3 零闪烁回归: 不重建 uPlot、不触发空态/遮罩、不回跳、不遮挡曲线与 tooltip; 不改变悬停坐标语义; 相邻两拍边界曲线位置连续。
  • G4 六个可选模板 R4 / R5: 同一节奏底座 + L0 左移 + L1 双轨 + 视觉引擎 V + N 霓虹层之上给出 6 种帧间过渡实现（含集大成的 T6 综合模板，R5 起见 五层：T2 光带 + T3 粒子 + T4 扫描束 + T5 分级 + T1 霓虹），可交互、可调参、可导出配置。R8 收敛: 六种实现全部保留为参考，生产只交付 T6，其余五种作为 T6 的构成要素与设计证据（见 §03 交付口径与 §05.8）。
  • G5 大胆但守读图 R2: 霓虹色相 / 几何形状 / 粒子爆发全部落在曲线之下或曲线描边本身; 遵循信息层级「谱面 > 反馈效果 > 氛围装饰 > 背景可视化」，曲线永远最后以高亮描边重绘在最上层。（R4: 霓虹色相不得整块铺到背景，只允许落在局部几何 / 粒子 / 描边元素上）
  • G6 双轨守恒 R3: 上传 / 下载各自独立 Δ 与等级、各自数值插值、各自静默判定; 曲线描边恒用各自语义色（与图例 / tooltip / 限速虚线色义一致），Lv 分级色只作用于反馈层; 粒子 / 碎片 / 辉光预算按两轨合计计，不得因双轨翻倍; 默认 D3-b 双轨各发半套，两条曲线都有可见反馈。
  • G7 背景静态 + 霓虹不越界 R4: 画布底色、网格、判定线静态虚线与右边缘底色在任意帧 / 任意模板 / 任意配色档下恒定，不得对绘图区或右边缘做整块半透明铺色; 霓虹色相只允许出现在判定线局部亮段、环外圈、粒子外圈、锚点辉光、角落徽标等非曲线元素上，且由 T5 分级联动决定色相。

设计不变量（违反即破坏设计）

编号不变量可验证判据
I11s 绝对硬上限: beat = clamp(period × 0.4, 320ms, 1000ms)，真值在 t ≤ beat ≤ 1s 完全落地; 左移偏置同样在 t ≤ beat 归零任意合法 multiplier 下，动画结束时刻 − 数据到达时刻 ≤ 1000ms
I2周期自适应: period 取 _qbPollMs() 实算值（meta.interval_s × 1000 夹到 1.5s–600s），每拍重算改 sample_interval_multiplier 后不改任何代码，节奏自动跟随
I3不闪: 不 destroy/new uPlot、不重跑 loading 空态、不触发 ResizeObserver 连锁、新拍以当前显示值为起点打断旧动画（禁止回跳）逐帧采样无 E→L→E 交替（沿用 e2e/drawer-switch-no-flash.spec.mjs 量具）
I4读数不撒谎: 禁止 overshoot; y 值只插值尾部 1–2 个点; data / 悬停锚 / tooltip 取值一律瞬时定档为真窗口; 纵轴 scale 瞬时定档（每帧 setData(..., false) 不重算 range）; x 视口只允许 ±1 格偏置（见 I8）插值序列单调收敛、不越界; 动画期间 tooltip 读数与已落袋真值逐字一致
I5判定帧锚定: 冲击在 t=0 同帧触发，视觉不得晚于约 80ms; --ease-spring 只许用于装饰层缩放逐帧探针首帧即见冲击
I6 R2 改写 / R4 收紧大胆不越层级 + 背景静态: 分级 + 无变化静默; 装饰层允许覆盖曲线所在像素，但曲线必须在装饰之后以高亮描边重绘在最上层; 层级固定「静态背景 → 网格 / 判定线 → 几何 / 粒子 / 扫描 / N 霓虹元素层 → 曲线描边 → 数据锚点」; R4: 删除「背景色调呼吸」与「右边缘入场地带」两处整块铺色，任何帧不得给绘图区 / 右边缘叠半透明色块; 反馈层不得抢到谱面之上，背景可视化不得抢到第二层任一时刻曲线像素对比度不低于静态基线; 固定两点（绘图区中央 / 右边缘）背景 RGB 逐帧恒定且二者相等; 静音看动效能猜到节奏即判「背景太吵」; Δ≈0 连拍 10 次叠加层零绘制（静态网格不计）

痛点证据

  • R1 补漏（方案级，最高优先）: 初版把「瞬时跳变」等同于末点数值跳变，漏掉整图左移一格这个主因; 因此 5 个模板都只演示原地变形，无法回答「值更新后图层整体左移怎么做中间态」。用户 26-11-12-1153 指出后核查生产几何确认，本版补 L0 并重写实验台使其真实 shift + push 一格。
  • R3 双轨漏项（方案级）: 初版五个模板的特效锚点、Δ 分级、数值插值、粒子池全部绑定单条主曲线，第二条只是 disp.map(v => v×0.34+0.06) 的暗灰静态陪衬。落地会立刻暴露四类问题: ① 两轨 Δ 常不同（下载飙升 / 上传平稳），单通道等级把两者错误归并; ② 单列 null 缺口或零流量时静默判定无从下手; ③ 两轨同时爆点会发两套粒子，预算翻倍、画面打架; ④ 若把 Lv 分级色刷到两条曲线上，上传 / 下载的语义色与图例色义断裂。本版补 L1 双轨底座与主导轨仲裁。
  • R2 T3 退役: 「整条曲线残影淡出」在 L0 引入后不再适用 —— 语义重复（L0 起始帧本就把整条曲线摆回旧位置，已产生旧帧可见感）、双重影（残影与新曲线分离时整屏两份谱面）、违反 I6 层级（残影盖在谱面上）、生产代价高（要额外缓存上一拍整列 ≤2880 点并在 draw 钩子再描一遍）。T3 槽位改为只作用于末点 / 判定线的「棱镜碎裂」。

外部调研（音游，取可用结论）

  • 反馈锚在判定帧: 视觉特效延迟 80ms 就会被感知为「画面慢半拍 / 打击感飘」; 应把视觉时间线对准判定帧而非动画固定播完时间。
  • 谱面滚动连续性: 音游的 Note 是连续向判定线移动的，判定线固定; 换成流量图即「曲线整体平滑左移一格、新桶从右边界滑到判定线」，而不是整图瞬移。这正是 L0 的动效语义来源。
  • 分级而非堆料: 普通 Note 用「小圆点闪光 + 不放大不抖动」的 Lv.1，连击/里程碑才升级; 反馈的信噪比比华丽度值钱。
  • 判定色是一手规范: Phigros 谱面行为标准写明判定线 AP 金 #FEFFA9 / FC 蓝 #A2EEFF / Clear 白 #FFFFFF，Perfect ±80ms / Good ±160ms，且只有 Perfect / Good 才播放打击特效 —— 对应本计划的 Lv 分级 + Δ≈0 静默。
  • Phigros 的克制路线: 大幅降低粒子，只留线框指示与轻微判读闪光，玩家反馈「判定读起来反而更清晰」—— 与 I6「不遮挡」同向。

R2 补充调研: 色彩 / 形状 / 粒子

  • 粒子三阶段 + 同帧: 等待期粒子低活跃散在边缘; 爆发瞬间向四周飞散、速度为平时 3–5 倍、可叠一次≤5px 微震; 拖尾阶段减速透明化，为下一拍蓄力。《Muse Dash》把「角色攻击 + 背景粒子 + 判定闪光」三层同帧触发，粒子最亮帧恰是判定线闪光同一帧 —— 信息高度重叠才会「打起来爽」。→ 直接落为 I9 的「最亮帧同帧」与三阶段速度曲线。（来源: 独游魔盒《音频可视化设计: 视听同步的视觉语言》）
  • 色调呼吸 → R4 修正为「局部霓虹」: Phigros 每次重拍让整个背景色调向主色相偏移一档、20 帧后回落，适合纯色背景 + 焦点全在音符的音游; 但流量图已有网格 / 缺口斜纹 / 限速虚线三层背景，且仓库记闪烁同族已到第九处，整块背景变色会被直接读成「闪」。→ R4 起本项目禁用整块背景色调呼吸，保留「Lv 色相在 ≤0.33×beat 内回落」的时间包络，但只作用于判定线局部亮段 / 环外圈 / 粒子外圈 / 锚点辉光（N 层），背景恒静态。（来源同上，结论已按本项目约束收窄）
  • 形状语言: Phigros 判定线可平移 / 倾斜 / 缩放 / 分裂（最多 4 条、8 种轨迹），电子核章节用故障艺术、破碎像素、闪烁警告框; Arcaea 用双色霓虹判定线与 Arc 蛇形弧线 / X 型交叉轨道; Beat Saber 用方块碎片炸开。→ 落为 V 的多边形环（三 / 六 / 八边）、旋转菱形末点、故障切片与速度线。
  • 信息层级硬约束: 「谱面 > 反馈效果 > 氛围装饰 > 背景可视化」; 若背景可视化抢到第二层以上，玩家会失控。自检法: 静音看画面还能大致猜到节奏 → 背景太吵。波形/频谱这类自带强视觉重量的元素不要铺成常驻底纹。→ 落为 I6 的图层顺序与次区只留极轻流动光点。
  • 前置条件: 《Phigros》的「看谱如看秀」建立在纯色背景 + 所有焦点集中在音符与判定线之上; 流量图已有网格 / 缺口斜纹 / 限速虚线三层背景，因此 V 的装饰只能集中在判定线附近一格，不能铺满全图。（R4 进一步收紧为：连「铺满全图的半透明色块」也禁用，背景完全静态）（来源: Phigros 资讯站 / 视觉与听觉双重冲击: 音游画面进化史）

节奏模型

判定帧 = 每次 _qbLoad 成功落袋的时刻。动效时间线按真实毫秒渲染，随 period 每拍重算:

period     = clamp(meta.interval_s × 1000, 1500, 600000)   // 每拍重算, 不写死
beat       = clamp(period × 0.4, 320, 1000)                  // 主区, 硬顶 1s
impact     = 0 .. 0.12 × beat                                 // 判定帧冲击 + 粒子爆发最亮帧
shift      = 0 .. shiftRatio × beat (默认 0.60)               // R1: L0 左移一格收敛
converge   = 0.12 × beat .. 0.60 × beat                       // 数值收敛
afterglow  = 0.60 × beat .. beat                              // 余辉衰减
neon       = 0 .. 0.33 × beat                                 // R4: 仅局部非曲线元素着 Lv 色; 背景零绘制

横向装饰线条: 联动定强度, 伪随机定长相 R6 新增 · 六模板共用

故障类表现里有两种横向线条 —— 撕裂切片（glitchSlices，短横条）与扫描束梳齿（细刻线）。R5 及以前两者都是常量几何: 切片 4 条 y 恒按 (i+1)/5 等分、x 恒在 g.R-66、长度恒 66px、α 恒 0.2、颜色只两色交替，只有 ±3px 抖动; 梳齿 7 条 y 恒等距 0.08+c×0.128、长度 6+(c×7)%13 全由常量 c 算出。结果是每拍长得完全一样 —— 既读不出强弱，也像贴在右边缘的贴纸。R6 把「强度」和「长相」拆成两件事:

维度由谁决定具体
强度

5.4 即时生效与「预览一拍」

采样周期合法区间 1.5s–600s: 若参数只在「下一拍真值到达」时生效，multiplier 调到 600s 的用户要等 10 分钟才知道自己拉的是什么。所以: 滑杆即改即用 + 手动预览一拍。

  • 即时: input 事件写内存并重算派生量（partCap / 行程 / 切片数 / 三档阈值），当前拍内装饰层下一帧就用新值; 唯一例外是 ease（当前拍不换式，避免中途换曲线造成位置跳变）。数值插值不回跳、不重排、不重建 uPlot。
  • 预览一拍: 采样 600s 时不必干等。语义六条 ——
    1. 不动窗口: 不 shift、不 push、dx ≡ 0，只跑尾部插值 + 装饰; xs / data 零变化;
    2. 假 Δ 贴近真实量级: target = shown ± clamp(0.18 + 0.35 × 粒子密度, 0.10, 0.50)，方向按轨交替 —— 不固定拉满 Lv.3，否则预览永远最高档，真到低 Δ 时参数对不上;
    3. 连点重启: 作废当前预览、从当前显示值重新起一拍，不排队不叠加（previewToken++ 递增即令旧帧失效）;
    4. 真值抢占: 预览期间真实拍到达 → 预览立即作废，真实拍走正常链路（真值永远优先）;
    5. 不写 store: 预览不产生任何持久化副作用，也不改 shown 以外的真值字段;
    6. 同预算: 与真实拍共用 I9 的 ≤28 指令/帧，不为预览放宽额度。
  • 不自动循环: 面板打开期间不自动假拍 —— 会与真实拍撞车，也会让「刚才那次是真是假」不可辨。要看连续效果就连续点，或去 §04 实验台开「连续播放」。
// 预览拍: 与 nextBeat 同构, 但去掉窗口搬运与 dx
function _qbPreviewBeat() {
  var token = ++S.previewToken;
  KEYS.forEach(function (k) {
    var c = S.ch[k];
    c.prev = c.shown;                                  // 以显示值接续, 禁止回跳
    var mag = clamp(0.18 + 0.35 * cfg().particles, 0.10, 0.50);
    c.target = clamp(c.prev + (k === 'dl' ? mag : -mag), 0.06, 0.94);
    c.delta = Math.abs(c.target - c.prev) / Math.max(c.prev, 0.08);
    c.level = levelOf(c.delta);
    c.committed = c.target;                            // 仅本帧用, 不落 data
  });
  S.lead = S.ch.dl.delta >= S.ch.up.delta ? 'dl' : 'up';
  S.beatStart = performance.now();
  S.preview = token;                                   // draw() 见 preview 则 dx = 0
  S.previewUntil = S.beatStart + cfg().beatMs;
}

5.5 持久化契约

键 autoqb.ui.qbFx（与 autoqb.ui.qbYAxisGlobal / qbWinGlobal 同族，前缀是 autoqb. 不是 qb.），单键一份 JSON，四皮肤共用、不分 scope（global / torrent / group 同一份）:

{
  "v": 1,
  "enabled": true,
  "impact": 0.7, "ease": "out",
  "palette": "neon", "particles": 0.7, "neon": true, "tail": true,
  "shift": "smooth", "shiftRatio": 0.6,
  "dual": "both", "tear": "linked", "echoSpan": "auto",
  "layers": { "band": true, "particles": true, "scan": true, "grade": true }
}
  • 为什么不分 scope: 动效是个人观感偏好，不是「这个数据视图该怎么看」; 分三份会让用户遇到「为什么换个图动效不一样」，也让实施多出三套读写与迁移。
  • 不进 config.qb_traffic: 不写后端、不动 KNOWN_QB_TRAFFIC_KEYS / fail-fast 校验 / 迁移，不随配置导出。
  • 读: JSON.parse 失败 / 非对象 / v !== 1 → 整体回落默认且不清键（保留原始串供诊断）; 逐字段校验（数值 clamp、枚举白名单、布尔严格 === true/false），未知键丢弃。
  • 写: 只在用户操作时写（不节流到每帧），try/catch 静默失败（隐私模式 / 配额满不得让调参崩）。
  • 落点（属主模块三件套）: 键常量 + 初值 + 持久化函数放 qb_traffic_chart.js，与现成的 qbWinStoreKey / qbInitialWindow / persistQbWindow（:88-104 / :657-661）同款 —— 仓库没有通用偏好助手可复用。注意该文件有 node 探针约束（源文件自注 :95、:130: 顶层不得碰 DOM / BOM，电池只给 global.window = {}、无 localStorage），所以 localStorage / matchMedia 一律在函数内惰性取，不在模块顶层求值。
  • enabled 只存用户意图: reduced-motion 只改有效值 effectiveOn = enabled && !reduce，自动置位永不回写 store —— 否则用户手动开过的动效在系统设置恢复后仍回不来; 面板「重置为默认」在 reduce 下只能把 enabled 写回 true（有效值仍为关），不得绕过红线。
  • 重置: 面板「重置为默认」= 写回上表默认值并立即生效，不删除键（用户可能只想回到默认，不想让旧值在下次启动时"复活"）。
  • 复制配置片段: 复用既有复制通道 commands_send.js:324-345 _copyText（非安全上下文 navigator.clipboard 不可用 → execCommand 降级 → toast 反馈）; qB WebUI 常走局域网 http，自建 clipboard 调用会静默失败。输出可直接粘进源码默认常量的 JS 片段（var QB_FX_DEFAULTS = { … };），比口头描述可靠; 与 §04 的导出块同一形状，但只含 15 个字段 + 只读值注释。

脏值场景: 旧版本键里若有已删字段（如 scene / amp / tpl），读时静默丢弃、写时自然清除;v 升级时按「缺省即默认」合并，不做逐版本迁移脚本 —— 这是观感偏好，丢一次可接受。
