WEBUI右键菜单文案统一:动词+灰色种子计数

把 WEBUI 右键菜单里启动/停止/删除三族动作的五种 scope 叫法(批量启动 / 启动该种子 / 启动整组 / 启动整剧 / 启动整集, 停止与删除完全同构)统一为单一形态「动词 + 灰色种子计数」——如「启动 42 个种子」; toast 回执同形, 删除确认框保留构成分解, 三处计数同源不漂移。

§01目标与设计原则

1.1 为什么做

同一批动作在四套菜单分支里有 5 种 scope 叫法 × 3 族 = 15 处菜单文案, 加上 toast 回执的 4 种形态, 共 19 种用户可见措辞描述同一件事情。三个直接代价:

  • 用户侧: 同一意图换个右键位置就换个说法, 「批量」与「整组」的差别还要用户自己推断;
  • 测试侧: e2e 靠精确文案区分菜单分支(如 trigger-scope.spec.mjs 断言「启动该种子」存在且「批量启动」不存在), 文案即分支判据 —— 改一处文案红一片 spec;
  • 口径侧: 计数三处各算 —— 菜单没有、toast 有括号计数、删除确认框有构成式计数, 同一动作三个数字源。

1.2 做到什么程度算成(验收)

  1. 四套菜单中三族动作的可见文案一律「动词 + 灰色 N 个种子」, scope 词(该种子/整组/整剧/整集/批量)一律去除;
  2. toast 一律「已执行: 动词(N 个种子)」同形;
  3. 删除确认框的构成分解保留, 且与菜单计数同源(同一 selTargets 解析);
  4. e2e 六个 spec 的 scope 断言改挂 :data-kind / :data-count 后全绿;
  5. commands run test.full + e2e 全量全绿, 实测数字誊进基线切片;
  6. conventions/webui.md 的术语漂移行修正, 并补一条菜单动作文案口径约定。

1.3 设计底线(不变量)

  • 菜单项集与排序不变 —— 四支 parity 守阵 test_frontend_ctx_menu_group_actions_parity(multi 与单组两支同集, webui.md:13)不破;
  • 动作分派不变 —— ctxAct / actTorrent / actEpisode / act 的 action 名、后端端点、flags 门控原样;
  • 计数随权威选择(selGroups/selMembers)而非当前视图/过滤 —— delete_flow.js 既有口径, 不退化;
  • 单一计数源 —— selTargets() 一处解析, 菜单 / toast / 对话框三处渲染派生;
  • 高危契约不变 —— 删除仍走确认框(H&R 提示 + 构成分解), danger 样式与「…」省略号保留;
  • 范围守恒 —— 计划外缺陷(如左缘测试缺口)入池, 本计划一行不顺手修。

§03方案总览

3.1 主线(一句话)

动词 + 灰色种子总数, 四支菜单全收; toast 同形; 删除确认框构成式保留; 三处计数从同一 selTargets() 派生。

3.2 落点表

表面现状改后
四支菜单三族项(15 处)5 种 scope 叫法「启动 / 停止」+ 行内 <span class="ctx-note">N 个种子</span>; 「删除…」+ 同后缀(省略号/danger 保留)
.ctx-menu 容器无 data 属性:data-kind="multi|single|group|episode" + :data-count="N"(D9)
toast 回执4 形态已执行: 动词(N 个种子) / 动词失败: …(D2/D11)
删除确认框bulkCountText 构成式保留, 改从 selTargets() 派生(D6)
快捷键面板 / 状态开关族无变体不动(D7)

3.3 计数语义(D3/D5)

N = 实际受作用的种子总数: 单种子 = 1; 单组 = 组成员数; 整剧/整集 = 成员 hash 数; 批量 = selGroups 成员合计 + selMembers。四支的数据前端在菜单打开时均已持有(g.members / menu.episode.hashes / selection.js 权威态), 不必等后端。计数在模板渲染时求值 —— 菜单对象被替换(右键另一行)即新作用域, 天然等于「打开时快照」; 与 delete_flow「计数随权威选择而非当前视图漂移」同口径。

N 恒 ≥ 1: 批量菜单仅在选中集合非空时出现(CTX-03); 组空即删组(grouping_mod.py:385); 剧/集必有成员。不存在「0 个种子」渲染态。

3.4 分期

单波次, S1–S9 顺序执行(§04), 无并行分期; 每步独立可验。
