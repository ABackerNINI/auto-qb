§01目标与设计原则

目标

消除「种子自身当日校验失败(recheck_fail_count(state, hash) > 0)后仍可跳检」的静默洗白路径。做到什么程度算成:三条跳检路径 —— 规则侧 without_reference 段 mode=skip-checking、WEB 单发、WEB 批量 —— 在自身当日计数 > 0 时均不再静默通过:WEB 侧预检确认框摊开 WARNING 且执行需显式 force(记审计),规则侧直接 skip(记 INFO);test.full 基线不回退。

设计底线(不变量)

  1. hash-keyed 自身只读:G9 只读自身 hash 的计数,禁止按组键放大。跨站辅种同一内容 = 不同 infohash = state 里两条独立记录,B 站失败不殃及 A 站(A 站若被拦,拦它的是既有 G8 的「文件映射一致」判定 —— 那是故意的、方向正确的共享物理数据防护,与本闸各司其职)。测试须有「B 失败、A 自身计数 0 → G9 不出判」断言钉死。
  2. case-2 对齐(用户拍板 D2'):WEB 侧 GATE_FORCE(WARNING + force 逃生 + 审计),对齐 26-10-05-0314 三分流哲学「只拦确定的情形;不确定的给逃生通道」。计数含噪声(START_TIMEOUT 宽限耗尽未开检 = 数据未知非坏,ops_mod.py:303 与 FAILED 真数据证据 ops_mod.py:258 同样 bump),>0 不是确定性信号,不配 blocked。
  3. 治疗路径保护(D4):full-checking 模式不被拦 —— 它是自身失败种子的唯一翻案路径(噪声型失败只能靠重跑 recheck 洗清),且已有 3 次/日冷却(ops_mod.py:176)限频。规则侧闸门必须 mode-scoped 到 skip-checking。
  4. 计数语义零改动(D6):沿用 recheck_fails 现接受面(与 G8/决策链 1.6 同宽,「继承既有假阳性面,不发明更锐利谓词」),state 零迁移、bump 写点不动。收窄(FAILED/START_TIMEOUT 分记)另入池:26-11-05-0853-feat。
  5. 前端零改动:case-2 渲染(force 逃生确认)G5/G7 已落地,预检 skip_check_precheck 自动摊开 G9,无新增前端工作。

§03方案总览

主线:谓词单点 + 双落点(拍板 D1)

镜像 skip_checked_today 的既有同源模式(checking_meta 谓词单点,ops 侧与规则侧各自消费,防两套谓词漂移):

# checking_meta.py 新增(谓词单点, 与 recheck_fail_count 同文件同族):
def self_recheck_failed_today(state, hash: str) -> bool:
    """该种子自身当日发生过校验失败(含 START_TIMEOUT 噪声, 接受面与 G8/链 1.6 同宽)。
    hash-keyed 只读自身 —— 禁止按组键放大(跨站同内容不同 infohash, 互不殃及)。
    消费方: ops_verdict G9(WEB, case-2 force)/ checking.py 链 4(规则侧, mode-scoped skip)。"""
    return recheck_fail_count(state, hash) > 0

落点 1:WEB 侧 G9(case-2,拍板 D2'/D5)

ops_verdict._skip_gates_detail,G8 之后、partial 之前插入(detail 现顺序 dedup→G3→G4→G5→G6→G7→G8→partial→filelist;G9 紧跟 G8,同属「校验失败已证伪/存疑」判定族)。注意 G9 判自身,与 G8 的循环(others)平行,不进 for h in members 循环:

# G9 自身当日校验失败(case 2): self_recheck_failed_today 单点谓词, hash-keyed 只读自身。
# 计数含 START_TIMEOUT 噪声(数据未知非坏)故不配 blocked —— 对齐三分流「只拦确定的情形」;
# 与 G8(他人失败+同映射 = 确定性证伪)的分级差异是故意的, 两处注释互指。
if self_recheck_failed_today(self._ctx.state, hash):
    verdicts.append(GateVerdict(
        "G9", GATE_FORCE,
        f"该种子今日校验失败 {recheck_fail_count(self._ctx.state, hash)} 次: 数据完整性未证实"
        f"(含未开检/异常的噪声可能), 跳检将把未验证数据标为有效并上传; 确知失败为噪声时方可强制; "
        f"安全出路 = 先 full-checking(通过即自动解除)/次日计数重置"))

force 豁越走 _skip_gates 既有路径(ops_verdict.py:110 附近:WARNING +「force 审计」INFO),零新增机制;预检 skip_check_precheck 自动把 G9 归入 force 类(cls=force,确认框要求显式强制),前端零改动。

落点 2:规则侧链 4 内 mode-scoped 前置闸(拍板 D4)

checking.py 决策链 4 内、前置文件检查之前;仅 segment mode == "skip-checking" 时判定,full-checking 模式零影响(治疗路径保护)。不加新链号(避免误导读者以为全模式生效):

# 决策链 4(skip-checking 段): 自身当日校验失败 -> 不再跳检(规则侧自动化无 force 概念,
# 保守硬 skip; WEB 侧同谓词为 case-2 可强制 —— 两边强度差异是拍板 D2' 的故意的)
if segment.get("mode") == "skip-checking" and manager.ctx.ops.self_recheck_failed_today(ctx.hash):
    return ActionResult.skip("该种子今日校验失败, 数据完整性未证实, 不再跳检; "
                             "请改用 full-checking 修复(通过即解除, 次日计数重置)")

规则侧 ops.self_recheck_failed_today 经 ctx.ops 暴露(与 ctx.ops.skip_checked_today 同通道);若 ops mixin 暴露面不含新谓词,直接从 checking_meta import(规则侧已有 from ..checking_meta import 先例)。

不强加的面

  • 决策链 1.6 / G8 的 others-only 语义不动(拍板 D4:1.6 是推断,新闸是自身直接证据,不同层不合并)。
  • 计数 bump 写点 / state schema / 冷却逻辑不动(D6)。
  • full-checking 模式与 WEB recheck 路径不动(治疗与排障路径,冷却已限频)。
