让固定闸门真的跑起来

现在预检只把闸门命令打印出来，跑不跑、红没红，全靠执行提交的人记得。 本方案让闸门由脚本执行、红了即 STOP：命令里需要“本次改过的文件”“某个 skill 的路径”这类 运行期才知道的信息，用占位符声明，由预检展开成真实命令；展开不了的才停下来。 只有需要人读输出做判断的才打印给人 —— 那已经不是闸门，是提醒。

改动面 3 个脚本 + 1 份配置 + 1 份 skill 文档 依据 .commit-flow.toml · preflight.py · _ship_config.py · SKILL.md 状态 待确认

01问题：打印出来的闸门靠不住

当前预检第 9 步只做一件事：把命中的闸门拼成一行 WARN，再在表尾列出命令。它不执行任何一条。

# preflight.py 现状（212–236 行）
gates = gates_for(changed, cfg["gates"])
if gates:
    rows.append((WARN, "提交前闸门", "; ".join(note for note, _ in gates)))
...
if gates:
    print("\n该跑的闸门命令:")
    for _, cmds in gates:
        for cmd in cmds:
            print(f"  - {cmd}")

这个设计漏掉的三件事，恰好都是“AI 会犯错”的地方：

  • 漏跑 —— 列表混在一张十来行的检查表里，WARN 又不挡退出码，跳过毫无阻力。
  • 漏判 —— 跑了但没看退出码，或者在输出里扫一眼“没报错”就当过。
  • 假性“不能自动” —— <改过的 py 文件>、<create-issue skill> 这类占位符 被当成“脚本没法补全”，于是整条闸门退回打印。但预检已经掌握这些信息：改动清单来自 git status --porcelain，skill 目录可以按名字搜到。缺的只是展开机制，不是能力 —— 把它归进“人来做”，等于白扔脚本已经知道的东西。

结论：闸门的价值在于“红了不让提交”，而不是“提醒你该跑了”。只要执行权在记忆里，闸门就等于没装。

02六条设计原则

  • 能自动的一律自动。命令固定、退出码可判的，脚本直接跑，红了进 STOP、退出码 1 —— 不给“记得跑”留机会。
  • 不能自动的才打印。含占位符、需要人挑文件或需要人读输出的，仍只列命令，语义保持 WARN。
  • 自动与否是配置事实，不是代码猜测。由 auto 字段显式声明；脚本不去猜“这条能不能跑”， 猜错就是静默执行了一条本该由人确认的命令。
  • 先展开，再执行；展开不了就停。占位符名拼错、skill 目录搜不到 → 报 STOP， 不降级成打印 —— 降级意味着“看起来跑过了”。
  • 占位符只描述“运行期才知道的信息”，不描述逻辑。它不能做条件判断、不能挑 subset， 越界的表达就该写成自己的脚本，塞进占位符只会让配置变成一门没人懂的语言。
  • 配置写错就停，不带着错继续。闸门可能很贵（测试、格式化、索引自洽）， 一个拼错的键让它静默失效，比它报错坏得多 —— 报错会被立刻发现，静默失效会让人以为“该跑的跑过了”。 所以未知键、非法值是 STOP，不是 WARN。

执行语义

  • 执行顺序：先展开占位符，再执行，整体在预检第 9 步、打印检查表之前跑完 —— 结果要能进那张表。
  • 执行方式：subprocess.run(cmd, shell=True, cwd=仓库根, timeout=gate.timeout)。 Windows 下 uv run / python 都依赖 shell 解析，不能走 argv 列表。
  • 结果落表：每条自动命令一行 [PASS] / [STOP]（命令 + 退出码 + 耗时）；全绿则汇总成一行 PASS。
  • 输出：成功只留一行摘要；失败打印末 20 行，够定位即可 —— 全量输出会把检查表冲掉。
  • 退出码：任一自动闸门失败 → STOP → 退出码 1，与现有“有 STOP 就返回 1”一致。

在流水线里跑几次（时间线）

翻了 commit.py / push.py 的源码，预检在一条流水线里共有 3 个触发点 —— commit.py 内部自己也调了一次：

S1/S2 手动 preflight（--phase push 默认）              → 自动闸门跑 ①
   ── 回写知识库 / 文档（改 memory-bank/ 与 docs/）──
S3 commit.py 内部 preflight_main(["--phase","commit"])  → 自动闸门跑 ②
S6 push.py 内部自动（--phase push --no-auto）              → 不跑闸门，只核状态
（手动那次取消 —— 见下）

定下的分工：① 与 ② 都真跑，pytest 每周期跑两次；S6 那次取消手动、收进 push.py 并固定 --no-auto。

  • ① 必须真跑，而且必须在改文档之前。项目测试里带着文档 / 知识库结构守卫 —— 实测 tests/test_memory_bank.py 直接读 memory-bank/， test_web.py / test_torrents.py 也涉及文档。 放到回写文档之后才跑，会因为文档改到一半、索引尚未重建而报红， 而且分不清红的是代码还是文档。先在改文档之前跑一次，就把“代码本身是绿的”锁定了， 之后文档引起的红一眼可辨 —— 也顺带避免文档漂移被误判成代码问题。
  • ② 必须真跑：回写之后工作区状态变了，提交进去的是“代码 + 文档”一起， 提交那一刻必须再验一次。它由 commit.py 内部触发（硬编码、不带 --no-auto）， 红了就中止提交（commit.py 已按 rc != 0 退出）。
  • 取消 S6 的手动预检，改由 push.py 内部自动跑（--phase push --no-auto）。 手动那次有一半是重复的 —— push.py 自己已经 fetch 并判落后 （落后即退出码 1）。但它不查的几项不能丢：工作区脏不脏、分支 / 上游对不对、 红线文件有没有又被改出来、镜像远端在不在。尤其本方案下自动闸门会改工作区 （yapf 重写文件、sync 建 junction），推送前那次“脏”检查正好能抓出 “闸门产生的改动没被一起提交”。所以做法是收进去，不是取消 —— 和 commit.py 内嵌预检的做法对齐，也不再靠人记得手动跑一遍。

两次是刻意接受的，不是没优化掉：两次回答的是两个不同的问题 （“代码本身过不过” / “连文档一起提交过不过”），合并成一次反而会掩盖其中一半。 单次成本用 --no-cov 压住。这条分工要写进 skill，不能靠人记得。

占位符：把“运行期才知道的信息”交给脚本

占位符展开为展开失败
<root>仓库根绝对路径—
<skill-dir:NAME>skill 目录：依次找 <root>/.agents/skills/NAME、 <root>/.codebuddy/skills/NAME、用户级 skills 目录； 第一个存在的即命中（本仓库 .codebuddy/skills 是指向 .agents/skills 的 junction，二者同一份）STOP
<changed:GLOB>本次改动里匹配 GLOB 的文件，拼成一条命令（路径逐个加引号）跳过 + 记一行
<each:GLOB>按匹配文件把这条 run 复制成多条命令，每条替换一个文件； 条数上限 = 顶层 each_limit（默认 99，可配、可在 --show-config 里看到）， 超过即 STOP跳过 + 记一行

改动清单的取法（changed = staged + unstaged + 未跟踪，预检已有）：

{ git diff --name-only --diff-filter=ACM -- '*.py';
  git diff --cached --name-only --diff-filter=ACM -- '*.py';
  git ls-files --others --exclude-standard -- '*.py'; } | sort -u

--diff-filter=ACM 是必须的：D（已删除）状态的文件磁盘上不存在， 喂给 yapf -i 会直接失败。<each:> 存在的理由之一是 Windows 命令行 8191 字符上限 —— 改动多时不能拼成一条巨长命令，只能逐个调用。

校验（fail-fast，进 draft_issues()）

  • 顺序是先展开后校验：先跑占位符展开，展开后命令里仍残留 <…> → 报“占位符未识别 / 无法展开”（STOP 级）。不是“见到尖括号就 STOP” —— 那样合法的占位符写法会被自己拦下来。
  • <skill-dir:NAME> 在所有候选位置都搜不到 → STOP，不猜、不降级成打印。
  • auto = true 但命令展开失败 → STOP（同上，不降级）。
  • timeout ≤ 0 或非整数 → STOP，不静默取默认。
  • 未知键 → STOP。顶层键必须在 KEY_DEFAULTS 白名单内； gate 键必须在 {match, run, note, auto, timeout} 内。 报错要点名：键名 + 所在 gate 的 note（顶层则标“顶层”）+ 允许键清单。不是 WARN —— 见第 02 节原则 6：闸门很贵，静默失效比报错坏得多。
  • 未知字段仍按现状忽略 —— 但 auto 拼错成 auto_run 会静默退化成“只打印”， 这条只能靠 --show-config 人工看；见第 08 节待定项。

新增命令行开关

--no-auto：只列不跑。用途是“只想看预检表”或推送前那次复跑不想再等一遍全量测试。

04本仓库现有闸门怎么分

加上占位符之后，结论翻过来了：7 条命令全部可自动。 原先被认为“只能靠人”的三条，缺的都不是能力，而是展开机制。

闸门（match）命令自动展开来源
src/ tests/yapf -i <changed:*.py>是改动清单
src/ tests/uv run pytest tests -q --no-cov是—
memory-bank/issues/python <skill-dir:create-issue>/scripts/gen_issues_index.py --check是skill 搜索
memory-bank/tasks/python scripts/gen_tasks_index.py --check是—
.agents/skills/python <each:.agents/skills/**/scripts/*.py> --help是改动清单 + 逐条
""（新增 · 每次命中）python scripts/sync_agent_skills.py是—
AGENTS.mdpython scripts/check_context_caps.py是—

三条原先“需人”的怎么落的：

  • yapf —— <changed:*.py> 从改动清单取（含未跟踪的新文件）， 排除 D 状态；逐个文件调用以绕开命令行长度上限。
  • issues 索引 —— <skill-dir:create-issue> 实测命中 .agents/skills/create-issue（.codebuddy/skills/create-issue 是同一份的 junction）。
  • 脚本冒烟 —— <each:…> 把一条 run 按匹配到的脚本复制成多条 python X --help。GLOB 走 pathlib.rglob 语义（** 跨目录）。

于是“人工闸门”这个分类在本仓库被清空 —— 打印路径只剩 --no-auto 和配置里显式标 auto = false 时出现。这不是过度自动化：闸门存在的意义就是不让步， 需要人判断的东西本来就不该伪装成闸门。

05改动清单

文件改什么
_ship_config.py ⓪ 新增 GATE_KEYS = {match, run, note, auto, timeout} 白名单与 config_problems(cfg) -> list[(level, msg)]：未知键（顶层 / gate 级）走 STOP， 初稿体检类走 WARN；替代现有 draft_issues()（只被 preflight.py 一处调用，改签名无外部影响）； ① KEY_DEFAULTS 加 auto = false、timeout = 600、顶层 each_limit = 99（保守默认：不标就不执行）； ② 校验改为先展开后判残留（展开后仍有 <…>、 skill 目录搜不到、timeout 非法、<each:> 超 each_limit → STOP）； ③ render_template() 初稿每个 gate 都带上 auto 与注释： 探测出的测试命令标 true，格式化命令写成 yapf -i <changed:*.py> 并同样标 true， 注释写明“auto = true 会被真的执行，且会改工作区”。
preflight.py ① 新增 expand_placeholders(cmd, ctx)：展开 <root> / <skill-dir:NAME> / <changed:GLOB> / <each:GLOB>， 返回 1~N 条真实命令，展开不了抛错； ② 新增 find_skill_dir(name)：按 03 节的顺序搜 skill 目录，搜不到返回空（由调用方转 STOP）； ③ 新增 run_auto_gates(gates, root)：先展开、再 shell 执行 + 超时 + 收集 (命令, rc, 耗时, 末 20 行)； ④ 第 9 步改为“展开 → 跑自动闸门 → 结果进表 → 剩下的仍打印”； ⑤ 加 --no-auto； ⑥ 模块 docstring 与用法注释改口径（不再是“只读”）。
push.py ① 内嵌预检：推送动作之前先跑 preflight_main(["--phase", "push", "--no-auto"])，非 0 即中止推送 —— 取消 S6 的手动那一步，同时保住它原本在查的那几项（脏 / 上游 / 红线 / 镜像）； ② 新增 --skip-preflight 逃生开关，与 commit.py 的同名开关对齐。
副作用：fetch 会变成两次（预检一次 + push.py 自己一次）—— 幂等、无新对象时开销可忽略，不为此重构。
SKILL.md ① S2 那一行改写成“闸门由预检执行：占位符自动展开，红了即 STOP；--no-auto 时只列不跑”； ② 脚本表里 preflight 的“只读预检”改成“预检 + 自动闸门（会写工作区）”； ③ 配置章节补 auto / timeout 字段说明，并整张占位符表搬进去； ④ 反模式补一条“手写 <改过的 py 文件> 这类自造占位符，指望脚本猜” —— 只认 03 节那四个，其余报 STOP； ⑤ 写死两条纪律：格式化类闸门必须在逐路径暂存之前（见第 08 节第 7 条）； 测试必须在回写知识库 / 文档之前跑一次，回写之后提交前再跑一次（见 03 节时间线）。
.commit-flow.toml 按第 06 节拆分并补 auto；同步闸门标 true。

06配置改造示例

现在（两条命令挤在一个 gate 里，格式化靠人挑文件）

[[gates]]
match = ["src/", "tests/"]
run   = ["yapf -i <改过的 py 文件>", "uv run pytest tests -q"]
note  = "Python 改动: 先格式化再跑全量测试"

改成（拆开 + 占位符 + auto）

# 格式化: 脚本从改动清单取文件, 逐个调用(绕开命令行长度上限)
[[gates]]
match = ["src/", "tests/"]
run   = ["yapf -i <changed:*.py>"]
auto  = true
timeout = 120
note  = "格式化: 只碰本次改过的 py 文件"

[[gates]]
match = ["src/", "tests/"]
run   = ["uv run pytest tests -q --no-cov"]
auto  = true
timeout = 900
note  = "全量测试(跳覆盖率报表): 脚本自动跑, 红了即 STOP"

[[gates]]
match = ["memory-bank/issues/"]
run   = ["python <skill-dir:create-issue>/scripts/gen_issues_index.py --check"]
auto  = true
timeout = 60
note  = "issue 索引: skill 路径由预检定位, 找不到即 STOP"

[[gates]]
match = ["memory-bank/tasks/"]
run   = ["python scripts/gen_tasks_index.py --check"]
auto  = true
timeout = 60
note  = "任务档案索引: 索引是生成物, 必须自洽"

# 冒烟: <each:> 按匹配到的脚本把这条复制成多条 python X --help
[[gates]]
match = [".agents/skills/"]
run   = ["python <each:.agents/skills/**/scripts/*.py> --help"]
auto  = true
timeout = 300
note  = "skill 脚本冒烟: 改了哪个跑哪个"

# 同步: 空串 = 每次提交都命中(拉取来的 skill 改动不产生 diff)
[[gates]]
match = [""]
run   = ["python scripts/sync_agent_skills.py"]
auto  = true
timeout = 60
note  = "skill 链接同步(幂等): 拉取来的改动靠每次提交兜一次"

[[gates]]
match = ["AGENTS.md"]
run   = ["python scripts/check_context_caps.py"]
auto  = true
timeout = 60
note  = "引导文件: 超 8000 字符 IDE 注入时尾部被静默截断"

代价：gate 数 5 → 7，每条多两个字段。收益是“哪些命令真的会被执行、拿什么文件执行” 在配置里一眼可见 —— 这两样现在都只存在于执行者的记忆里。

07预检输出改造

现在

  [WARN] 提交前闸门      Python 改动: 先格式化再跑全量测试

该跑的闸门命令:
  - yapf -i <改过的 py 文件>
  - uv run pytest tests -q

无 STOP；1 项 WARN 需人工确认 —— 可以继续。

改后

  [PASS] 自动闸门        5 条全过 (yapf 1.1s / pytest 42.3s / gen_issues_index 0.5s
                                  / gen_tasks_index 0.4s / sync 0.2s)

无 STOP —— 可以继续。

失败时打印展开后的真实命令 —— 否则看到的还是占位符，没法定位：

  [STOP] 自动闸门        python .agents/skills/create-issue/scripts/gen_issues_index.py --check → rc=1 (0.5s)
      展开自: python <skill-dir:create-issue>/scripts/gen_issues_index.py --check
      _index.md 缺登记: 26-09-22-0800-xxx
      ...（末 20 行）

1 项 STOP —— 处理完再提交。

展开失败（占位符拼错 / skill 找不到）时，不降级成打印：

  [STOP] 自动闸门        无法展开: <skill-dir:create-issues> (已试 .agents/skills/ · .codebuddy/skills/ · 用户级)

1 项 STOP —— 处理完再提交。

配置写错（未知键）时点名到具体那一条 gate，让人一眼改对：

  [STOP] 配置体检        gate「全量测试(跳覆盖率报表)」出现未知键: auto_run
                          允许键: match / run / note / auto / timeout

1 项 STOP —— 处理完再提交。

耗时是真实数字，取自命令实际墙钟时间 —— 不预置、不估算。

08风险与未决

  1. 全量 pytest 的耗时。基线 1143 passed（2026-09-22 Windows 实测）。 自动跑意味着每次预检都要等它 —— 已定：用 --no-cov（跳过覆盖率报表； 覆盖率数字仍由 memory-bank/testing.md 基线那一跑负责，不是闸门的事）。
  2. 闸门会被跑多次。三个触发点里定下跑两次（改文档前 + 提交前）；第三处（S6）收进 push.py 并固定 --no-auto，所以不会变成三次。已定：接受两次， 单次成本用 --no-cov 压住。代价要写进 skill：改文档之前必须先跑一次测试， 否则文档守卫（tests/test_memory_bank.py 等）会让结果与代码状态混在一起。
  3. shell=True 的可信级别。命令来自仓库内自己的配置文件，可信度等同 Makefile； 不用白名单（会锁死跨项目复用）。但 cfg 读的是仓库根文件，被人改过就等于被执行 —— 与“改 Makefile 就能执行任意命令”同级，写进 skill 说明。
  4. preflight 的“只读”口径要改。docstring、SKILL.md、AGENTS.md 里都写着“只读预检”， 自动闸门会写工作区（sync 建 junction）。三处口径需同步改，否则文档漂移。
  5. 没有机械守卫。tests/ 里现在没有任何用例覆盖 preflight / _ship_config（全库 1143 个用例也不含它们）。 自带一份（已定：放 skill 目录，详见本节末尾「决议」第 3 条）—— 放进项目 tests/ 会把跨项目资产和本仓库耦合。
  6. 字段拼错会静默退化（改前的最大风险）。auto 写成 auto_run 时， gate 级不做键过滤，gate.get("auto", False) 取到默认 false， 闸门退回“只打印”且输出无任何痕迹。 已定：未知键一律 STOP，顶层与 gate 级同标准 —— 见下方「未知键」决议。 代价是新增键必须先加白名单才能用（否则配置一写就挡住提交）—— 这是 fail-fast 应付的价钱，接受。
  7. 格式化与暂存的相互作用。yapf -i 会改工作区：若文件此前已 add 过， 格式化后 index 与工作区不一致。现在顺序（S2 闸门 → S3 暂存）天然安全，且 commit.py 是逐路径 git add 会重新收录 —— 但这条要写进 skill，不能靠顺序巧合， 否则哪天有人把暂存挪到闸门前面就会静默提交旧内容。
  8. <each:> 展开的规模没有上限。一次改 30 个 skill 脚本就是 30 条命令。 可接受，但要在输出里显示实际条数，别让“预检怎么变慢了”变成一个谜。 已定：上限 99（顶层 each_limit，可配、可 --show-config 显示）， 超过即 STOP 并提示拆分提交范围。
  9. 展开用的是预检那一刻的改动清单。自动闸门自己产生的新改动（yapf 重写文件、 sync 建 junction）不回流进清单 —— 这是刻意的，否则会自我触发成循环。

决议（2026-09-22 定稿）

  1. 测试命令用 --no-cov。项目 pytest.ini 的 addopts 自带 --cov=src，闸门那一跑不需要覆盖率报表；覆盖率基线数字归 memory-bank/testing.md 维护，与闸门无关。
  2. 执行时间点：改文档之前那次（S1/S2）+ commit.py 内部那次（S3）都真跑； S6 的手动预检取消，收进 push.py 内部自动跑（--phase push --no-auto）。 即 pytest 每周期跑两次，接受 —— 两次回答的是“代码过不过”与“连文档一起过不过”两个不同问题，合并会掩盖一半； 且第一次必须在改文档之前（文档守卫会让后跑的结果不可信）。不引入 phase 字段。
  3. self-test 放 skill 目录：.agents/skills/my-commit-flow/scripts/test_preflight.py， 与被测脚本同目录。不进项目 tests/ 的理由：这份 skill 是跨项目资产， 绑进本仓库 tests/ 会把两边耦合起来。实测 pytest.ini 里 testpaths = tests，项目那 1143 个用例不会收集到它 —— 也不该收集， 它依赖的是 skill 自己的脚本而不是 src/。 跑法：python <skill-dir>/scripts/test_preflight.py（stdlib unittest，零依赖）。 覆盖点：四种占位符展开与展开失败、gate 分类、未知键校验、超时 / 失败 → 退出码 1、 each_limit 超限、--no-auto 确实不执行。
  4. “未知键”分两层 ——
    ① 顶层：load_config 里 cfg.update({k: v for k, v in data.items() if k in KEY_DEFAULTS}) —— 不在 KEY_DEFAULTS 里的键被静默丢弃， 把 staged_panic 拼成 staged_panicc 不会有任何提示。
    ② gate 级（真正的危险）：gates 是原样透传的 dict 列表，不做键过滤， 于是 auto_run = true / autoo = true 不会报错 —— gate.get("auto", False) 取到默认 false，闸门静默退回“只打印”： 你以为自动化了，其实一条都没跑，且输出里没有任何痕迹。
    处理：未知键一律 STOP（退出码 1），不是 WARN。 gate 允许键固定为 match / run / note / auto / timeout；顶层键必须在 KEY_DEFAULTS 白名单内。 报错信息要点名键名 + 所在 gate 的 note（顶层则标“顶层”）+ 允许键清单，让人一眼改对。
    为什么不是 WARN：闸门可能很贵（全量测试 / 格式化 / 索引自洽），拼错一个键让它静默失效， 结果是“以为该跑的跑过了” —— 这比报错坏得多。WARN 会被淹没在十来行的检查表里， STOP 才会被处理。付的价钱：以后新增配置键必须先加进白名单，否则一写就挡住提交。
  5. <each:> 上限 99：顶层键 each_limit，可在 --show-config 看到、可覆盖；超限 → STOP 并提示拆分提交范围。
