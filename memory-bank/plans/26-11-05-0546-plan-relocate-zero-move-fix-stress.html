§01目标与设计原则

1.1 背景

生产事故(取证报告 26-11-05-0417): ACT_FINALIZE 归位把共享物理文件挂 .!qB,下次整组迁移按声明名 stat 全 miss,qB 报「成功移动」但零搬移,10min 后停滞看门狗才判失败。issue §06 给了 5 条修法,其中修复 5(renameFolder 两步复位)已经在实验 G5 单点验证过一次。本计划=实施前的压测轮:不改生产代码,先静态核机制,再在测试 qB 上把用户点名的六个方向逐一打出证据,给后续实现轮一份"哪里能照抄、哪里必须收紧"的清单。

1.2 压测问题清单(用户点名)

  1. 主要方向(renameFolder 两步复位)能否正常工作?
  2. 是否符合设计约束:不删种 / 不 skip_check 重加 / 不读盘校验?
  3. 同组多种子(共享同一物理内容根)修复时有没有竞态?
  4. 改目录名(两步复位的内容根改名)会不会影响同目录下其它种子(组外共享者)?
  5. 种子在上传(活跃做种流量)时,修复与搬迁各会发生什么?
  6. (附加,静态分析发现)两步之间是异步入队,step1→step2 的时序窗口有没有竞态?

1.3 设计底线 / 不变量

  • 数据安全第一:本轮只在测试实例(36595/36596)+ real-fake 假种子 + R:/tests-real/.work 上操作;生产 26586/16585 与 I:\PT\ 零触碰。
  • 三项设计约束全程作为断言:不删种 / 不 skip_check 重加 / 不读盘(哈希)校验 —— 每个修复实验都要核 qB 日志与种子账面,确认没有 recheck / re-add / delete 发生。
  • 先复现再修复:每个修复实验先构造出冻结态(错位),修复后再断言「磁盘原名 + 账面 1.00 不动 + 嵌套搬迁恢复真搬」。

§03方案总览

3.1 更优方案比对(静态分析结论)

  • 治本(阻止错位诞生)不可行:错位发生在 finalize 归位 + 自动 recheck(need_full_check ⇒ force_recheck),无 API 可抑制;resume 是收尾目的本身,绕不开。事后纯改名复位是三项约束面内的唯一通路(recheck=完整哈希违背「不读盘」;skip_check 重加违背约束;renameFile 有 G4 的 409 前科)。
  • ⑤ 的降级选项:检测到错位只告警不自动修。折中推荐:目录形态内容根 + 组内专属(content_root_exclusive 现成事实)→ 自动修;单文件/多根/有组外共享者 → 检测 + 告警交人。以 E1.4/E1.7 实测结论定边界。
  • ①②③ 是互补纵深:②(短窗核验,信号 = dst 侧证据或 moving)是真正兜底网,不管什么原因的零搬移都能抓;①③ 是前置 UX。不替换,只收紧:① 升三态;② 明确信号 = dst_size>0 / dst_ready / moving,save_path 翻转单独不认;③ 成分级比较 + 全成员覆盖。
  • ⑤ 的收紧清单(实测确认后写进实现轮):按物理内容根去重(一次两步修全组,成员级各修既有害又多余);两步之间磁盘证据驱动(tmp 根出现且文件摘净才发 step2);检测逻辑识别「声明根不在 + 临时根在」=上次修复中断 → 补完 step2 而非重新 finalize;组外共享者降级告警。

8.2 重大发现:G5 配方的前提对生产冻结形态不成立(🔴)

冻结态有两个变体, 由 rejected 恢复路径决定(报告已注「F1 vs G 竞态」, 本次实证两形态对修法的影响):

变体完成位两步复位来源路径
形态 Gtrue成立(G5 + 本次 T6 复现): step1 立即摘后缀完整校验通过的恢复
形态 F(生产)false不成立: makeActualPath(torrentimpl.cpp:628)对未完成文件恒挂 .!qB, renameFolder/renameFile 任何目标都摘不掉后缀; 摘后缀唯一通路 = 完整哈希 recheck(实测 prog=0 态 recheck 全清自愈; 冻结态 recheck 置完成位)或 skip_check 重加checkingResumeData 路径(E0.2 复现 = 生产同形)

即 issue §06 建议修法 5「三项约束全守」的承诺对生产形态不成立:要么放宽约束③允许对检出成员定向 recheck(数据已知完好, 读盘是确认不是修复; 成本 = 全量读一遍), 要么对形态 F 只检测+告警+人工摘后缀。另有配套收紧:修复成员的映射必须与磁盘一致(recheck 先行对齐)且按内容根去重一次覆盖全组(E1.3 竞态); 崩溃窗检测须识别「声明根不在+临时根在」=修复中断(E1.6); 单文件/多根形态只能告警(E1.7)。

8.3 修法收紧结论(喂实现轮)

  1. ① 三态(在 / .!qB / 缺失)必要且充分 → §05 D2 默认成立。
  2. ② 信号改道:成功/进行证据 = moving 态(真搬必有, 零搬移永无; paused 种子也有); dst_size 不可作进度证据(预分配假 ready); 完成 = not moving 且 dst_ready(同卷瞬搬 8ms 即完成, 不误杀); 失败 = not moving 且 dst 空 30s(E3.2 实证)。
  3. ③ 成分级嵌套判据(大小写不敏感, 全成员覆盖) → E2.3 逻辑已验证。
  4. ⑤ 按形态分流 → §05 D4 待拍板。
  5. ④ 失败反馈面照旧实现轮做。
