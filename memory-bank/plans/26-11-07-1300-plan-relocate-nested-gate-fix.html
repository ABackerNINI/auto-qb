§01目标与设计原则

事故: 启用整组迁移后, 移动一个 3 文件种子到组成员声明源内的兄弟目录(PTing\xxx → PTing\待删\xxx)被 GATE_NESTED 硬拦。用户三点质疑经代码核实全部成立(见 §02): 闸门锚点用声明源而非别名真实落点(内容根)、闸门形态盲、文件级形态无自递归可能。

做到什么算成:

  1. 用户场景(文件级组迁入源内待删兄弟目录)预检放行, 且真机全链路(setLocation → 建链 → fastresume 改写 → 核验 → 删链)走通: 账面 1.00 / 磁盘原名 / 零 recheck / 零拒载。
  2. 真形态不放松: 目录别名(DIR_ALIAS)且新旧内容根互嵌 → 预检硬拦(数据不进执行期卡死形态); 平铺反向(junction 指向自身祖先)同样被拦。
  3. 在途 job 期间往旧根兄弟目录停车不再误拦(job.scope 收窄)。
  4. 「新家嵌在旧声明源树下」以 confirm 披露 D19 连带后果; UI 在提交前可见「移动 = 整组迁移」语义。
  5. 既有不误伤面(兄弟目录/前缀同串/尾斜杠/大小写/父目录方向)在新锚点下回归全绿。

设计底线 / 不变量 (继承 0546 §1.3): 数据安全三约束全程断言 —— 不删种 / 不 skip_check 重加 / 不读盘(哈希)校验; 生产实例 26586/16585 与 I:\PT\ 零触碰, 只在测试实例 + real-fake 假种子 + R:/tests-real/.work 上操作; 闸门保持纯函数不触盘; 预检拦截先于任何数据移动(fail-fast); 真机实验先行(D7): 任何结构判据先上真机构造场景实证, 与推演不符即回炉改设计, 不带假设进实现。

§03方案总览

主线: 判据从「目标 ⊆ 成员声明源(全形态一刀切)」改为按形态分治 —— 结构危险面收敛为「互嵌 × 目录别名」一种; 其余形态放行, 后果用 confirm/note 披露; UI 补两个披露点。判据全部经 P1 真机实验实证后才实现。
