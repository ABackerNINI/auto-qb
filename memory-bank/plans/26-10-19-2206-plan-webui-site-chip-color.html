站点问题改色表达与 chip 图标收口

把「站点有问题」从图标通道搬到颜色通道：缺配置染橙底、tracker 报错染红底，chip 里只剩「命令结果」一种图标并固定放在站点名之后 —— 图标位置不再随状态跳，两类错误也不再撞脸。

§01目标与设计原则

做到什么算成

  1. 位置统一：chip 内图标只出现在站点名之后，且只可能是「命令结果」一种 —— 一列扫下去图标位置恒在同一处。
  2. 站点问题一眼可见：缺站点配置 = 橙底（+ 虚线底边），tracker 报错 = 红底；不必 hover、不必开抽屉。
  3. 两类错误不再撞脸：站点问题走颜色，命令结果走图标；即使同时发生，也是"变色块 + 一个图标"两个通道，不是两个红叉比位置。
  4. 提示触发面放大：hover 整块 chip 就出文案（含站点问题与命令结果两行），不再要求精准悬停 11px 图标。
  5. 明细行同语义：辅种明细 / 追剧未识别行的站点文本同样按站点问题染色并带同一份 tooltip。

不变量（实施时不得让步）

  • 后端一行不动：site_alert / site_alert_msg 契约与 refresh_tracker_health 取数逻辑不变；本件是纯前端表现层返工。
  • 不新增颜色令牌：三皮肤（棱镜含 5 套主题）已有的 --warn-soft/--warn/--error-soft/--error 足够；主题文件零改动。
  • 不新增列、不改列宽：图标仍塞在既有 gap:4px 里，尺寸 11px 不变。
  • 命令结果状态仍存 state.js::alertIcons（hash 键 map）—— 不挂行对象，服务端每代都是新 dict。
  • 三皮肤同步：任何新规则三份齐备，由静态守阵机械比对键集。

四条观感问题的根因

  • P1 位置不统一：不是漂移，是"位置即语义"的设计副作用 —— 健康固定在文字前、结果固定在文字后；于是只有健康问题时看着像"前图标"，只有结果时看着像"后图标"，同一列里位置随状态跳。
  • P2 状态色不跟随：chip 底色只由种子状态决定，站点问题只改图标颜色 —— 一个"绿底红叉"的 chip，主体仍在说"做种中"。
  • P3 提示触发面过窄：title 挂在 11px 的 <svg> 上，用户必须精准悬停图标；chip 本体只有"点击=筛选"。
  • P4 两类错误撞脸：站点报错与命令失败共用 i-x-circle + 红色，唯一差别是左右位置 —— 而位置本身正是 P1 要消掉的东西。

§03方案总览

3.1 通道分工：站点问题 = 颜色，命令结果 = 图标

语义载体视觉寿命数据源
缺站点配置chip 底色 + 虚线下边框橙底橙字 + 1px dashed 底边常驻，配置补上即灭site_alert == "no_site_conf"

示意：① 健康（种子状态色）② 缺配置（橙底+虚线，无图标）③ 报错（红底，无图标）④ 成功（图标在文字后）⑤ 报错 + 命令失败（红底 + 文字后一个叉，两个通道互不冒充）。

3.2 颜色与优先级

/* 底色优先级: 站点问题 > 搜索命中 > 种子状态(现状不动) —— 源顺序即优先级 */
.site-chip.sa-no-conf { background: var(--warn-soft);  color: var(--warn);
                        border-bottom: 1px dashed var(--warn); }
.site-chip.sa-tracker { background: var(--error-soft); color: var(--error); }
/* 搜索命中让出底色, 改用描边(各皮肤沿用自己既有的 accent 描边色) */
.site-chip.search-hit { background: transparent; box-shadow: inset 0 0 0 1px var(--accent-line); }
/* 变色后文字与图标同源: 图标不再写死语义色, 由 currentColor 继承 chip 前景 */
.site-chip .sx { color: currentColor; }
叠加态结果说明
站点问题 + 种子状态色站点问题赢种子状态由「状态」列表达，chip 底色让给更稀有的站点事实
站点问题 + 搜索命中站点问题赢底色，命中改描边两个信号都不丢：块 = 站点坏了，圈 = 这行为什么在列表里
tracker 报错 + 种子 error 态视觉与纯种子错误相同错误态整行已红，chip 再红无信息增量（D2 拍板）
缺配置 + tracker 报错缺配置优先（橙）与后端判定优先级一致（配置缺失时报错文本不可信）

3.3 tooltip 与无障碍

  • 提示挂在 .site-chip 整块（title 由 ui_feedback.js 迁成 data-aq-tip），图标不再单独挂 title。
  • 两类文案并存时合并为两行，顺序「站点问题 → 命令结果」；单条时不加换行。
  • 两类站点问题都补 aria-label（读屏可读）；缺配置另加虚线下边框作为非颜色通道（色盲/灰度下可与实底红区分）。

3.4 明细成员行

.m-site 保持纯文本（明细表是密集阅读面，chip 会加高度），有站点问题时染文字色并挂同一份 tooltip；类名与 chip 同族（.m-site.sa-no-conf / .sa-tracker），颜色规则复用同一组令牌。

3.5 分期

一次做完（纯前端、无后端改动、无数据迁移）。
