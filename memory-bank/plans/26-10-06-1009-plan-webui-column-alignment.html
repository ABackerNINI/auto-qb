决定方案的三条几何事实(改前已逐条核对代码)

① .group-head / .group-row / .detail-head / .member-row 本来就是 display:grid; gap:10px —— 列与列之间已存在一条 10px 的列间距。彻底方案把把手挪进这条既有间距, 不新增任何宽度开销。

② 表头格子 .h-cell{padding-right:10px} 只有表头有; 值格子 .g-stat / .m-stat 的 padding-right 是 0。右对齐时两边各贴「自己内容盒的右缘」⇒ 差 10px(行有 1px 边框则 11px)。

③ 把手 .h-cell .resizer 之所以塞进 padding-right, 是因为 .h-cell 自身 overflow:hidden(给列名省略号用)—— 把手伸出格子右缘会被裁掉、点不到(星图 components.css:250-251 有注释记着这个动机)。解耦的关键: 把省略号下移到内层标签, .h-cell 自己就能 overflow:visible, 把手便能自由落到列间距里。

PHASE 5常驻回归守卫(防复发)1 用例

本轮缺陷的成因是「几何」, 而 tests/test_web.py 的近 300 条守阵全是读文件文本的静态断言 —— 原理上看不见盒子模型。故在 e2e/smoke.spec.mjs(真浏览器 + 桩服务, 三皮肤已循环)加一条几何断言, 让「表头↔值错位」与「0 值又居中」今后由 CI 拦住。

// 在 for (const skin of SKINS) 内追加: 逐列比对「表头↔值」内容盒右缘, 并对右对齐列钉住值格 text-align
test('右对齐列: 表头与值右缘对齐(±1px), 且值格不居中', async ({ page }) => {
  await page.goto(`${BASE_URL}/${skin}/`);
  await page.waitForSelector('.group-row');
  const bad = await page.evaluate(() => {
    const cRight = (el) => el.getBoundingClientRect().right - parseFloat(getComputedStyle(el).paddingRight);
    const out = [];
    for (const head of document.querySelectorAll('.group-head[data-table]')) {
      const page_ = head.dataset.table;
      const cells = [...head.children].filter((c) => c.classList.contains('h-cell'));
      const row = document.querySelector(page_ === 'detail'
        ? '.member-row[data-table="detail"]' : `.group-row[data-table="${page_}"]`);
      if (!row) continue;
      const rcells = [...row.children];
      cells.forEach((hc, i) => {
        if (getComputedStyle(hc).textAlign !== 'right') return;   // 只看右对齐列
        const rc = rcells[i]; if (!rc) return;
        const d = cRight(rc) - cRight(hc);
        if (Math.abs(d) > 1) out.push({ page: page_, delta: Math.round(d * 100) / 100 });
        if (getComputedStyle(rc).textAlign === 'center') out.push({ page: page_, zeroCentered: true });
      });
    }
    return out;
  });
  expect(bad).toEqual([]);
});
