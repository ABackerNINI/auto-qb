§01目标与设计原则

功能背景(memory-bank/plans/26-11-03-2337-plan-missing-site-tracker-merge.html, 已入库 develop, 功能面基线 commit b01609ca): GET /api/sites/missing(src/auto_qb/webui/server/routes/sites.py)在逐域名 sites 之外追加 groups: [{name, domains, entry}] —— 同一颗种子共现的缺失域名 union-find 分组(跨种子传递闭包), name=代表站点名(组内最短域名派生, 与 sites 同一 taken 序列顺延), domains=组内全域名 sorted, entry=合并默认条目; groups 可为空数组; 全单元素组时 domains/entry 与 sites 一一对应、组名顺延。

本轮目标: RM10 附加轮已把 CLI 导出面(M1/M2)真机钉住(tests-real/rm10_notify/test_rm10_export_merge.py 4 条全绿); 本轮补齐 WebUI 读侧(M3/M4)的真机面 —— 只读: 全部断言落在 GET 端点载荷上, 产品进程经 dev.webui 安全模式(规程 §2.4)起停, 零写侧操作(不 POST /api/config、不动种子状态)。

设计底线/不变量: ① 真实种子全程非活跃(环境2 两实例当前 0 枚); ② 零 DNS 零外连 —— announce 全部互异 127.x IP 字面量 + 死端口 :1(RM10 实测事实: extract_tracker_hostnames 取 urlparse().hostname 不含端口, 同 IP 异端口塌缩成一域, 故用互异 IP); ③ 种子全程 paused 不 announce; ④ token 只经环境变量, 产品配置指副实例(56590 bypass_local_auth 空凭据直连), 配置文件零 api_key 落盘; ⑤ 只碰白名单 56589/56590。

id档位验证面与期望值
RM08-10 L2 groups 分组契约: 造场 A=[127.0.0.7,127.0.0.12] B=[127.0.0.12,127.0.0.13] C=[127.0.0.14], 配置 trackers 配一个不命中域(rm08grp.invalid)保缺失面。断言: torrents==3, domains==4; sites 原形(逐域名 name/domain/entry, 名单恰 127_0_0_12/13/14/7); groups 恰 2 组 —— 合并组 ["127.0.0.12","127.0.0.13","127.0.0.7"](传递闭包) name=127_0_0_7_1(代表=组内最短, 与 sites 同 taken 序列顺延撞名加后缀) + 单元素组 ["127.0.0.14"] name=127_0_0_14_1; 每组 entry.domains==组内全域名 sorted、hr/限速示例段与 sites 条目同源; sites 与 groups 的名字集零交集。

RM08-12 L2 三分支自适应引导的数据面前提: 同一造场(种S1=[127.0.0.31] 种S2=[127.0.0.32])先后两个形态 —— 全单组: 断言每组 len(domains)==1、groups 数==sites 数、逐组与逐 site 一一对应(domains==[site.domain], entry 与 site entry 逐键相等, name==site 名 + _1 顺延)、载荷上「存在 ≥2 域名组」闸门判定为假; 经 /torrents/addTrackers 给 S1 追加 127.0.0.32 变成共现场后新起一份产品进程复扫: 断言出现 ≥2 域名组(闸门判定为真) —— 同一载荷自带 groups, 前端免第二次请求即可判定(数据前提本体)。执行期实测修正: 两形态必须各起一份产品进程 —— 产品 store 对种子 tracker 列表惰性缓存且只在产品自身 tracker 写操作时失效(record.py:269-276 / qbapi.py:261-268), 绕产品直改 qB 对在跑进程不可见(首跑单进程版假红, 记切片 §03)。
