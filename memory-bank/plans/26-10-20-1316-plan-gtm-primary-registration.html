global-traffic-monitor 正主注册与让位代拉设计

给整机流量监视器建立「正主注册」制度：三处 ID 一致才握笔写数据，非正主安装启动即让位（代拉正主）并退出；claim 是唯一人工易主通道。机器上永远只有一个安装、一份数据，恢复/移动/自启/归并全部显式交还用户。

§01目标与设计原则

背景

同机并存两个 auto-qb 实例 A/B（多 clone 并行部署），各带一份 global-traffic-monitor（下称 gtm）安装；数据目录默认跟随安装（D12：<安装>/data）。工具死亡后，先启动的一方按对称逻辑拉起自己那份安装并占领指针与数据落点 → 两份数据不互通（复算见 §02）。

目标（验收总则）

  1. 写入者唯一：整机只有一个安装写数据——注册正主；版本血统纯，不同版本安装不互写 state.json/dat。
  2. 非正主即让位：启动时识别出自己不是正主 → 代拉正主后退出；代拉失败/被拒时给用户可见原因（状态注记 + 设置页）。
  3. 恢复交还用户：移动、易主、自启、存量数据归并全部是显式人工动作（文档引导 + claim 按钮），工具只陈述事实、永不猜测。
  4. auto-qb 零记录读写：判定与书写全沉工具侧，auto-qb 只做编排与展示。

设计底线（不变量）

  • 单一判定者：工具是自身状态（记录 / id 文件 / 注记）的唯一判定者与书写者；auto-qb 不读不写。
  • 读/写非对称：读 dat 是跨包稳定契约（任意安装的 auto-qb 都可出曲线）；只有正主安装可写。
  • 零自动猜测：primary.json 只 claim 时写一次，此后零自动刷新（唯一例外：补写为空的 data_dir 信息位）。
  • 显式优先：env GLOBAL_TRAFFIC_MONITOR_DATA_DIR / --data-dir 高于一切默认。
  • 最小机制：不加会话/租约/选举/自动刷新/HTTP 新端点；不做 caretaker 代写数据。
  • fail-safe 降级：记录/注记损坏一律按缺失或矛盾降级（WARNING），永不死锁、不静默。

§02现状与痛点

现状机制（代码单点）

  • 订阅线程每轮 ensure_running（core/traffic_source/agent.py:249，由 webui/tool_client.py:250 调用）：probe（读指针 + GET /status 200 才算在跑）→ 失败则 resolve_launch_target（agent.py:178-196：tool_exe 优先，tool_dir 为空回落本 clone 仓库内 tools/global-traffic-monitor）→ detached 拉起（agent.py:199-229，Windows CREATE_NO_WINDOW / POSIX 新会话——auto-qb 退出带不走工具）→ 探活成功即订阅（“别的实例已拉起也不重复拉”，agent.py:252）。
  • 数据目录 = <安装>/data（工具 gtm/storage.py:87-98，D12/D16：env GLOBAL_TRAFFIC_MONITOR_DATA_DIR / --data-dir 可覆盖）。
  • 指针 endpoint.json 与单实例锁 instance.lock 锚用户级目录（storage.py:119-142），与 data_dir 解耦；就绪只认探活、锁在绑端口前 acquire（坑档 traffic-source-discovery-pointer）。

痛点时间线（原场景复算）

  1. 平时：A 的工具先起，指针与数据在 A/data；B 订阅。
  2. 机器重启 / 崩溃 / POST /shutdown 致工具死亡（优雅退出删指针；崩溃留残留指针）。
  3. B 先启动：probe 失败 → 拉起B 侧安装 → 单实例锁已随原进程死亡释放 → 端口默认随机（0）不冲突 → bind 成功覆盖写指针 → 数据写 B/data。
  4. A 后启动：probe 到 B 的工具 → 直接订阅 → 曲线/规则读 B/data。

后果：A/data 历史成孤儿，两份数据不互通；反复横跳时 dat 历史行与 state.json 当日基线反复断裂。附带三坑：删除安装 = 删其数据；拷贝安装目录 = 拷贝分叉；不同版本安装互写 state.json/dat 是跨版本风险（快照字段语义随版本演进）。工具缺席时 auto-qb 侧不静默当 0（config/models.py:370，流量变量显式报错）——连续性代价可见，不停摆误判。

§03方案总览

主轴：正主注册（machine-level identity）+ 让位代拉 + claim 人工通道。数据目录解析保持现状（env/--data-dir 显式 > 安装默认）——不加 pin 文件、数据不挪进用户目录（用户目录只新增几十字节的记录与注记）。

三处 ID（文件名 tool-id；uuid；schema 版本化，未知按降级）

位置文件角色写者
安装目录<install>/tool-id安装身份（先于数据可读，定引导顺序：我是谁）工具首启生成
用户目录（指针目录）primary.json机器注册的正主：{schema, id, install_path, data_dir(信息位), version(信息位)}工具认领（O_EXCL）/ claim 命令
数据目录<data_dir>/tool-id数据归属（版本血统防线：这份数据归谁写）正主认领时写入

启动判定矩阵（工具进程最早期，acquire 单实例锁之前；让位方不持锁）

分支判据动作写数据?
① 认领无 primary.jsonO_EXCL 原子建记录（自己三项）→ 正主路径是
② 正主record.id == 我的 install-id 且 record.install_path == 我的 realpath正主路径是
③ 拒绝id 同但 path 异（拷贝件 / 安装被移动）拒绝启动 + 人读提示（人工改记录或删记录重认）+ 写注记否
④ 让位record.id ≠ 我的 id记录自洽校验 → 自洽：代拉（执行 record.install_path 下 D19 启动器）后立即退出不等待；矛盾（目标安装 tool-id ≠ 记录 id，或目标即自身）：写注记退出否

正主路径续查：解析数据目录（env/--data-dir > 安装默认）→ 读 <data_dir>/tool-id：缺失 → 写入认领；== 自己 → 过；≠ 自己 → fail-fast（“该数据属于其它安装（id …），拒绝跨版本接管”）→ 补写记录里为空的 data_dir 信息位（仅此字段，不算自动刷新，不削弱 ③）→ 照旧：单实例锁 → bind → 写指针 → 采样通知。

claim——唯一人工易主通道（护栏 = 二次确认框）

  • 入口：安装目录内第二启动器 claim.cmd / claim.sh，D19 同族契约——零参数、意图写在脚本内容里（映射到自己的 python -m gtm claim；编译态退化为调同目录 exe 的 claim 子命令）。缺该文件 = 旧安装，按钮提示升级。否决方案：给 launch.cmd 传参、env 传令牌（不可见 API）。
  • 语义：非阻塞试拿单实例锁 → 拿不到拒绝（“工具正在运行，请先停止”）；数据目录 id ≠ 自己 → 拒绝（“该数据属于其它安装”）；通过 → 原子重写 primary.json（id/install_path/data_dir 三项全用自己的事实）→ 释放锁 → 退出 0。
  • auto-qb 侧：有界前台执行（timeout 30s，退出码 + 输出展示在状态区）；按钮在设置区恒显示（可见性不劳 auto-qb 判断——claim 的自检就是判断）；恢复流程 = 现有「停止工具」→ 新「以本安装重登记」→ 现有「立即拉起」。

状态注记（工具侧书写，auto-qb 只读展示）

指针目录 deferred.json（谁让位 / 代拉目标 / 结论 / 时间戳）：让位（④）与被拒（③）时由工具书写；正主成功启动或 claim 成功时由权威方清除。auto-qb 状态区据此展示“主工具注册于 X，当前未在运行（本实例工具已让位）”类文案——判定在工具侧，展示在 auto-qb 侧，永不反向。

明确不做：pin 文件；数据挪进用户目录；给启动器传参 / env 传令牌；新 HTTP 控制面端点；记录自动刷新；面包屑以外的提醒子系统；确认框前后对照（auto-qb 无记录可读，拿不到 before-state）。

§04实施步骤

期内容验收判据
P1 工具侧身份与矩阵identity 模块（install-id 生成/加载、primary.json 读写与 O_EXCL 认领、三处校验、deferred.json 写/清）+ cmd_run 启动序列插桩（身份 → 数据归属 → 单实例锁 → bind → 写指针 → 采样）矩阵 ①②③④ 单测；③ 拒绝 + 注记；④ 代拉后立即退出（不等待）；④ 记录自洽矛盾拒绝；data-id 三态（缺失/同/异）；空 data_dir 信息位补写；未知 schema 降级；常量镜像守阵扩展现有 test_pointer_constants_mirror_tool_side
P2 claimgtm claim 子命令 + claim.cmd/claim.sh（源码态/编译态两形态）+ 拒绝路径（锁争 / 数据归属异）claim 成功 / 两拒绝路径单测；原子重写（并发安全）；与 P1 共用 data-id 校验，无第二套判据
P3 auto-qb 侧agent.py：claim 启动器常量镜像 + resolve_claim_target + run_claim（有界前台）；设置页：按钮 + 二次确认框 + 状态区读注记展示原场景 e2e 复算（工具死 → B 起 → 代拉 A → A 指针出现 → B 订阅 → 同一 dat）；拒绝文案可见；ensure_running 与订阅编排零改动（让位全在工具内）
P4 文档与引导工具 README + 仓库文档：数据落点规则 / primary.json 是什么怎么改 / claim 流程（停止 → 重登记 → 拉起）/ 禁止拷贝安装目录 / 新机先启 A / 存量分裂人工归并步骤文档审查：新人可按文档独立完成 claim 全流程与归并

实现顺序约束（硬）

  • 单实例锁仍在绑端口前 acquire（坑档 traffic-source-discovery-pointer）；claim 持锁期间不采样。
  • 矩阵判定在取锁之前完成；让位方全程不持锁、不写数据。
  • 所有落盘复用 storage.atomic_write_text（tmp + fsync + replace），读者任意时刻只见完整文件。
  • 镜像常量（指针目录名、记录/id/注记/claim 启动器文件名、schema 版本）auto-qb 与工具各持一份同值——改一侧必须同步另一侧，有守阵钉住。

测试要点

  • install-id：缺 → 生成落盘；已有 → 加载不重生成。
  • 认领：无记录 → O_EXCL 建（幂等）；双安装并发首启 → 输家读记录转 ④。
  • 矩阵 ②：id+path 同 → 正主；③：拷贝件 / 移动件 → 拒绝 + 注记；④：自洽 → 代拉 + 退出；矛盾（目标 id 不符 / 目标即自身）→ 注记 + 退出。
  • data-id：缺失 → 写入认领；同 → 过；异 → fail-fast 拒绝跨版本接管。
  • claim：成功 / 锁争拒绝 / 数据归属异拒绝；claim 成功清注记。
  • 注记：④/③ 书写；正主启动成功清除；损坏按缺失降级。
  • 端到端：原场景复算 + 版本只读不写（B 侧 auto-qb 订阅、出曲线正常；B 侧工具零写入）。

§07风险与对策

风险触发条件处置
path 误判（该跑的被拒）symlink / junction / subst 使 realpath ≠ 记录 pathrealpath 归一；拒绝提示教用户核对 realpath；确认本人后可改记录或删记录重认
存量已分裂数据被立错升级后先启动的一方恰是短数据那份文档人工归并（选定保留目录 → 合并/选定 dat → 保证 data-id 一致）；claim 通道矫正，工具不自动选举
新机误先启 B首次部署顺序反了，B 先认领文档「先启 A」；要改回须 claim（先停 B 工具），人工显式
claim 时正主仍在跑用户不停工具直接点重登记claim 持锁争拒绝 + 提示「先停止」；设置页已有停止工具入口
记录 / 注记损坏手改坏 / 写入中断按缺失或矛盾降级（WARNING）+ 走默认路径；永不死锁、不静默
旧安装缺 claim 入口升级前的老安装按钮检测入口缺失 → 提示升级；优雅降级，不阻断既有功能
data-id 拒绝阻断合法接管用户确实想让新版本安装接旧数据文档给显式步骤：停工具 → 确认版本兼容 → 删 <data>/tool-id → claim；删 id 是显式人工动作，工具不提供绕过开关
双 auto-qb 同时拉起各自工具工具死后双方探活窗口重叠单实例锁去重（输家 fail-fast）；认领 O_EXCL 去重（输家读记录转 ④ 让位）
auto-qb 侧误读工具记录实现期为图省事直接读 primary.json 推导状态D7/D8 拍板在先；状态只读 deferred.json（工具侧书写）。守阵：代码评审 + 常量镜像单点测试
