现状

current
现网图标 · extensions/hr-fetch-proxy/icons/
  1. 「H」与功能无表意关联 —— 用户看不出这枚扩展是「取数代理 / 通道」，只当又一个字母图标。
  2. 16px 下偏小偏弱 —— 字形高 8px、上下留 4px 边距，一列工具栏图标里识别成本高。
  3. 故障时信号重复 —— 红框 + 浏览器角标「!」双报警，字形本身没帮上忙。
  4. 底形偏方 —— 圆角 3px，与 Chrome 现代扩展图标的 squircle 语言有距离。
A

中继

relay

双向箭头即「代理通道」—— 页面数据与后端两端往来。字形本身在说：这枚扩展在搬数据。

工具栏实尺寸 16px · 左无框 / 右绿框
角标 ! 由浏览器徽标叠加（chrome.action.setBadgeText），不在 PNG 内；四版同此。
  • 纯几何、无字母依赖 —— 跨语言可读；16px 下 2px 箭杆与箭头依然清晰，是四版里小尺寸最稳的。
  • 与功能命名直给 —— 选项页与 README 里的「通道 / 代理」字样，能与图标对上号。
  • 横向构图 —— 与 B 的 H 一样偏横向，视觉体重轻，适合常驻工具栏。
B

H 精修

lettermark

保留既有「H」识别资产：字形加粗加高、垂直居中，底形圆角 3 → 4。认知零迁移，只换手艺。

工具栏实尺寸 16px · 左无框 / 右绿框
  • 迁移成本最低 —— H 的识别不变，字形从 8px 高加粗到 10px 高并垂直居中，工具栏里更挺。
  • 仍然没有功能表意 —— 适合「不想动认知、只想更精致」的取舍。
  • squircle 化 —— 圆角 3 → 4，接近 Chrome 自带扩展图标的底形语言。
C

放大镜

magnifier

取数 / 核查 —— 镜圈加镜内两条清单线：把页面上的数据看一眼，拿回来。

工具栏实尺寸 16px · 左无框 / 右绿框
  • 语义最贴「取数」动作本身 —— 核查 H&R 页面 → 回传后端，图标即流程。
  • 小尺寸优先不糊 —— 16px 时清单线弱化为点缀，主体是干净放大镜；32px 以上才显出「数据」含义。
  • 斜向手柄 —— 45° 指向角落，与镜圈不抢视觉；四版中唯一的斜向构图。
D

盾牌对勾

shield check

H&R 守护 —— PT 语境里盾即账号安全，对勾表示「查过了、没问题」。

工具栏实尺寸 16px · 左无框 / 右绿框
  • 主题关联最强 —— 扩展存在的理由就是守 H&R，盾牌是对这个词的直译。
  • 竖向构图 —— 与 A / B 的横向气质区分明显，一列图标里不会混。
  • 主要风险 —— 「盾 + 对勾」与安全类扩展（杀毒 / 广告拦截）语义轻微撞车。

怎么选

how to choose
  • 想「一眼知道这扩展干什么」 → A / C / D（表意优先）
  • 想沿用既有 H 识别、零认知迁移 → B
  • 通道 / 代理概念最直给 → A；取数动作最直给 → C；H&R 主题最强 → D
