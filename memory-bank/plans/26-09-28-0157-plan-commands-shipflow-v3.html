所有被标注「多余 / 这是什么」的行都有明确代码出处；没有一行是意外，全是设计出来的噪音。

实贴症状机制根源
「Exit code 3 ← 会引导 agent 查 code3 是什么意思」引擎把「task 脚本非 0」映射为退出码 3（run.py:31 FAILED = 3），且失败输出不自解释 → E2 统一为 0/1，失败行自带语义
「开工自检(--check-started, 全程只读) ← 多余」preflight.py:543 的检查表表头
「远端在 e8978704，本地没有它的对象(从未 fetch?) ← fetch 不是脚本该干的事吗」sync 被设计成只读不自愈（preflight.py:27「连 fetch 都不做」:130）——它只报告缺什么，把动作推回给调用方
「[WARN] 工作区 树脏(与主线齐平, 不影响开工) ← 多余」preflight.py:540，齐平时也打工作区行
「退出码 0=可开工, 1=需先处理 ← 退出码多余」preflight.py:546 的口径脚注
「[自证] ship.commit 将要执行: + 完整 python 绝对路径 ← 这是什么??」run.py:57-62：任务标了 risky = true（ship/config.toml:13）就回显展开后的首条命令——E1 去掉该标记即可，零引擎改动
「[WARN] 上游 / 镜像远端 居然输出了两次!!」commit.py:152 跑一遍预检(--phase commit)，续跑 push.py:127 再跑一遍(--phase push)——每遍都打整张检查表，WARN 自然成对出现
「[WARN] 闸门 跳过(无匹配文件)…不是闸门失效 ← 这是什么???」preflight.py:391-393：<each:> 无匹配时特意打一行「按设计跳过」——v2 怕人误会，结果人人误会
「[WARN] 镜像远端 没找到…可不管 ← 多余」×2 +「=== 尝试一次镜像直连 === ← 多余」preflight.py:681 + push.py:227-244：镜像状态在两个阶段各报一次
「RESULT: OK 0e52b4f 已提交(9 个文件)并推送; 远端与本地一致; 镜像结果见上 ← 多余」commit.py:226 的 v2 协议行——信息重复且啰嗦

根因一句话：v2 计划（26-09-26-2345）四层设计里，L1「输出契约 RESULT 协议」把「出示证据」当成了默认路径——每次成功都打检查表、打清单、打协议行。方向反了。L2 零参数化、L3 编排合一是对的，v3 继承；L1 推翻为「沉默即成功」；L4 错误导航保留，但收成失败行的「原因 + 下一步」各一句。

03

行为规格 — 每个任务做什么、沉默时做什么

沉默 ≠ 没查。现有内部检查一个不删，只是不再逐项汇报；行为变化集中在 sync（从只读报告变为自动完成）与预检的归并。

3.1 sync 重构：从「报告缺什么」到「直接做完」行为变化最大

现状 sync = preflight.py --check-started，只读、不 fetch、不合并，把「先 fetch」「先快进」写进 WARN 让调用方自己动手——这正是被点名的「fetch 不是脚本该干的事情吗」。v3 的 sync 自己做完：

fetch gitee develop→ls-remote 取远端真值(绝不读 refs/remotes)→对比本地 HEAD
齐平→已同步 <hash>　·　纯落后→git merge --ff-only FETCH_HEAD→同步成功
分叉(树净)→自动 rebase 保持线性(D1 已拍板)　·　冲突即 abort→失败行　·　离线→失败行
  • 树脏交 git 裁决，不再自算重叠配方：改动文件与远端新提交无重叠时 merge --ff-only 本来就会成功；有重叠时 git 自己拒绝（"local changes would be overwritten"）。脚本把 git 的拒绝翻译成一行失败输出 + 步骤指针（pipeline.md「同步路径」），删掉自算 overlap 的 60 行配方逻辑（preflight.py:143-180 sync_recipe）。
  • 分叉（本地有独有提交）→ 自动 rebase（D1 已拍板，2026-09-28 用户定调：rebase 禁令已移除，必要时用 rebase 保持提交历史线性）：树净时 git rebase <远端tip>——只改写按定义未推送的本地独有提交，历史保持线性，取代 v2 时代因禁令而生的「reset --hard + format-patch」替代舞蹈；中途冲突 → git rebase --abort 全量自动回滚 + 失败行（跑前后仓库指纹一致）；树脏 → rebase 无法进行，直接失败行（先提交或 stash——stash 已解禁，但脚本不代做，沿用「树脏停下报告」纪律）。rebase 自动留 ORIG_HEAD + reflog 底。
  • 合流失败一律自动回滚现场（rebase --abort / merge --abort / ff 失败 git 本身自回滚），保证 sync 失败后仓库状态与跑之前一致——写状态的命令必须比只读的更干净地失败。

3.2 ship.commit 重写：编排不变，输出归零

内部 sync(齐平才继续)→闸门(auto=true 真跑, 静默)→算暂存计划(红线拦)→逐路径 add
→commit -F 消息文件→ref 三处核对(静默)→消费即删消息文件(静默)→内联推送→提交成功 <hash>
  • 预检只跑一遍：现状 commit 阶段(--phase commit)与 push 阶段(--phase push)各跑一遍完整检查表，是 WARN 翻倍的根源。v3 没有检查表，push 复用同一套内部函数只做「落后核对」，不再重复任何输出。
  • 闸门静默通过：11 条闸门机制、配置、展开器（<changed:>/<each:>/<skill-dir:>/<root>）原样保留；全过时一行不打。闸门红 = 失败输出里给闸门名 + 末 20 行输出（现状行为保留，只是从检查表行变成失败块）。<each:> 无匹配 → 静默跳过，不再解释「不是闸门失效」。
  • 删除的检查项：上游核对（preflight.py:578-583——ahead/behind 判定早已走 ls-remote 真值，上游名纯属摆设）、平台关键词提示（preflight.py:676-677——改动面是否要跨平台复现是 agent 的判断，不是固定 WARN）、配置来源行（preflight.py:555）。
  • 顺带修复已入池 issue 26-09-28-0128：逐路径 git add 撞「已暂存的删除」——工作区里已不存在的路径改走 git rm --cached -- <path>（按文件存在性分流），重写 commit.py 时一并落掉，该 issue 在实施时认领关闭。
  • 保留的拒绝语义（失败行化）：拒批量 add（-A / . / *）、红线文件拒提交（config.yml / auto-qb-data/）、消息文件缺失（提示写到 .git/COMMIT_MSG_AI.txt）、无可提交改动。

3.3 ship.push / verify-ref

  • ship.push（补推/重验）：ls-remote 核对齐平（落后时树必净——刚提交完——直接走同一套 sync 快进）→ 推主线（瞬时连接失败自动重试一次，保留）→ 核远端 ref == 本地 → 推送成功 <hash>。
  • 镜像：仍自动尝试一次（保持 GitHub 新鲜度），但全程静默——成功不打、失败不打、没有镜像远端也不打（D2）。AGENTS.md「镜像失败只如实报告一次」口径随之修改。
  • verify-ref：排障工具，保留任务入口；PASS 收成一行，FAIL 保留现有详细处置步骤（format-patch 留底 → update-ref 防 GC → reset --soft）。

3.4 preflight 公开任务移除（D3）

my-commit-flow.preflight 的全部价值（闸门执行、红线、落后核对）被 commit 内部化；独立入口只剩排障时让人困惑的第三条提交路径。处理：preflight.py 改名收编为共享模块 _pipeline.py（闸门引擎 + 占位符展开 + changed_files + 红线 + --init/--show-config），config.toml 删掉该任务。AGENTS.md 的 my-commit-flow.preflight 引用同步清理。

风险与回退

风险对策
sync 从只读变为写状态（fetch + 快进/rebase）合流失败一律自动回滚现场（abort / git 自回滚）；验证矩阵含「跑前后指纹不变」断言；ff / merge / rebase 都是拦截层修复（2026-09-25）后已解禁的操作
分叉自动 rebase 改写本地提交 hash只改写按定义未推送的独有提交（已推送的必在远端链上，不会被触及）；ORIG_HEAD + reflog 自动留底；冲突即 --abort 全量回滚；验证矩阵含「跑前后指纹一致」与「提交内容不变」断言
引擎退出码改动波及其它包已核实无脚本消费 rc=3；仅 harness 显示的数字变化；独立成 M3 可单独回退
闸门静默后「跑没跑过」不可见失败输出含闸门名与末 20 行（该路径可见性不降）；成功与否由「提交成功」背书——提交成功必然闸门全过，这正是编排合一的语义
回退整个重构落在一笔提交内（M1-M3 可拆但同分支），git revert 即回 v2；包目录自包含，无外部状态
