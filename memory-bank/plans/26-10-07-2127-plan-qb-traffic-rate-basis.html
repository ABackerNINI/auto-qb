00 · Scope

背景与范围

用户命题「流量图太陡」经四阶段调研, 报告 26-10-07-2031 裁决采用方案 B: 图的速率通道从「qB 瞬时速度直采」改为「计数器差分区间平均」(t0→t1 传了 10MiB, 平均速度 = 10MiB ÷ (t1−t0))。纯读侧: .dat 行型、state_file、采样器写路径、配置键全部零改动, 旧数据即刻按新口径出图; 瞬时速度照常落盘(agg 层 dl_max 峰值聚合源 + 原始信号留存), 仅不再上图。

用户命题追加两项, 本计划的处理口径:

  1. 万桶级治理(纳入实施): 部分视图达到万桶级、性能差, 按成熟方案分析后裁决为 raw 段窗桶数上限(03 节)。实测根因: 生产 config.yml:507 已是 sample_interval: 1.5S(= main_tick), 24h 视图 = 57600 桶/系列(报告按 30s 默认推的 2880 桶不适用现况)。
  2. 采样间隔演进(仅写入计划, 不实施): 默认 30s 改 1× main_tick、设置仅能按 main_tick 倍数设置 —— 两项一并作为设计决定 D6 记录在案, 留作独立后续切片; 其对方案选择与实施的影响分析见 02/03 节(结论: 不改变方案 B 的选型, 但使桶数上限从「高频采样部署的治理项」升格为「默认配置也必需」)。

实施范围 = 04 节 S1-S4 四步(每步独立可验证、工作量均衡、串行执行)。非目标: 展示层平滑(报告 D 案, B 落地后观感再议)· 采样间隔演进实施(D6)· agg 段 Δ/cov_s 严格统一(报告 §06 可选项)· 前端任何改动。

02 · Decisions

设计决定 D1-D7

  • D1 口径 = 方案 B, 不做 A/B 可选项(报告 §06: 双口径=双倍测试面, 业界无先例)。瞬时速度照常落盘, r 行 rate 列原样, agg 层 dl_max 不动。
  • D2 注入层级 = 桶点级(v4_series_points 之后、v4_grid_obs 之前): 宽桶(采样抖动/暂停恢复 w>interval)按真实覆盖秒分摊, 字节守恒; obs 级差分会把宽桶增量整段落进首个覆盖桶出假尖峰(报告 §06.4)。
  • D3 窗首种子 = 读侧 t0 外扩一个响应桶宽(grid.t0 - grid.interval)取前驱桶点作差分链种子, 种子点不外发(v4_grid_obs 对窗外覆盖天然跳过; floor 对齐时窗首桶并入跨界覆盖与现状口径一致, 字节守恒)。种子跨真空(程序停机)时 v4_series_points 既有真空判定自动断链, 离线期 qB 自行传输的字节不会误归恢复后首桶。1m 窗必带, 否则半图空。
  • D4 v4_grid_obs 豁免: rate=None 但 totals 有效的点允许参与归桶 —— 只更新覆盖末端与快照链(rate 权重记 0), 使后续桶差分基线不断; 桶完全无速率覆盖时出 0 线 + 快照照记(程序刚启动的窗首桶, 1/N 缺口视觉无感)。
  • D5 万桶级治理 = 读侧桶数上限 MAX_RAW_BUCKETS = 2880: raw 段桶宽 = max(ceil(sample_interval), ceil(span/2880))。裁决论证见 03 节。
  • D6 采样间隔演进 —— 仅写入计划, 独立后续切片(用户拍板): ①默认 30s 改 1× main_tick, 推荐形态 = 哨兵 0(默认 0.0 语义「跟随 main_tick(1×)」, 显式值口径不变; 解析 helper 单点, _apply_interval 与 traffic_qb.py:92 两消费点接入; 校验放行 0; 注意哨兵 0 现会被运行期 max(1.0, ·) 吞成 1s, 实施时必须显式处理); ②设置仅能按 main_tick 倍数设置 —— 配置语义从「秒值」改「倍数」(如 2x), 校验与运行期取整逻辑随之简化, 届时按黄金法则4 四处登记(models 字段 / validation 白名单 / schema Field / 守卫测试)。两项实施时合并为一个切片, 先 ①后②或一步到位均可。
  • D7 前端零改动: qb_traffic_chart.js 不动。轮询拍 = meta.interval_s = 桶宽, 桶加宽后 24h 视图更新拍从 1.5s 变 30s —— 更新粒度与数据粒度一致, 接受; 1m-30m 小窗仍 2s 拍。

D6 对方案选择与实施的影响(用户问点, 正面回答)

  • 不改变方案 B 的选型: 计数器差分区间平均对采样节拍不敏感 —— 采样越密差分链越细, 口径与边界语义完全同构(报告 §05 矩阵对任意采样率成立); 区间平均反而是「采样间隔可以放心调小」的前提(点值始终是真平均, 不会引入更多抖动)。
  • 但放大了桶数上限的必要性: 桶数 = span ÷ interval。默认 30s 时 24h 窗 = 2880 桶(上限式零影响); 默认变 1× main_tick(2s)后 24h 窗 = 43200 桶 —— 万桶级从「高频采样部署的现况」(用户 1.5S 已是 57600)变成默认配置也必踩。故 D5 的桶数上限不是可选优化, 是采样间隔演进的前置依赖: D6 实施前必须先有 D5。
  • 倍数设置与上限数学自洽: 「间隔恒为 main_tick 整数倍」实施后, 桶宽 = max(N×main_tick, span/2880) 的取整口径不变; 采样间隔演进切片的验收里应补「默认配置下各窗桶数 ≤2880」断言。

05 · Risk

  • 回滚 = revert 读侧提交: .dat 行型 / state_file / 采样器写路径零改动, 无数据迁移, revert 即回旧口径。
