§01目标与设计原则

1.1 背景

dir_alias 收尾设计(guardian 在 qB 关闭期间删 junction → qB 重启 → 成员 fastresume 找不到文件(missingFiles,设计预期输入)→ reconcile 的 ACT_FINALIZE setLocation 归位)在生产触发 26-11-05-0420 零搬移灾难:归位把共享物理文件改名挂 .!qB,下次搬迁按声明名 stat 全 miss,qB 报「成功移动」而数据未动。压测(0546)证明形态 F(完成位 false)下 API 层无修复通路,整案不采纳,relocate 整组迁移待完全重构。本计划 = 重构:用 fastresume 改写让成员在 qB 重启时原生加载新位置,missingFiles/ACT_FINALIZE/seed_mode 账面恢复链整体消失。

1.2 目标与「算成」标准

  • 整组迁移收尾后:所有成员经一次 qB 重启加载到新路径,账面 progress=1.00 不动,零拒绝载入、零重校验、零 re-add。
  • 失败态永远收敛到「链接还在、成员可读、journal 待重放」,不存在需要 API 修复通路才能解开的冻结态(0420 灾难的结构性根源)。
  • 真机验收 = 本计划 §03.4 的 N 系列断言在实现后的代码路径上复跑全绿 + 0546 继承项回归。

1.3 设计底线 / 不变量

  • 数据安全第一:fastresume 是 qB 的私有账本,任何写入必须「校验通过才落盘 + 落盘前有备份」;坏文件 = 种子被静默丢弃(N6 实测,仅 INFO 级日志)。
  • 三项设计约束继承(0546 §1.3):不删种 / 不 skip_check 重加 / 不读盘(哈希)校验。本方案天然满足:改写只动路径键,加载核对由 libtorrent 的尺寸级 file_stat 完成(本版 verify_resume_data 只比大小不比 mtime,storage_utils.cpp:560-580)。
  • 黄金法则:journal 等跨轮次状态进 state_file(法则 3);预检 fail-fast 聚合报错(法则 4);单主循环线程执行改写与删链(法则 5);重复执行无副作用 —— 改写幂等(已是目标值则跳过)、删链幂等(门不满足就不删)。
  • qB 是 fastresume 的唯一写方:auto-qb 只在「qB 进程确认下线」的窗口写入,运行期零写入 —— 这是 N1(0.5s 覆盖)换来的铁律。

§03方案总览

3.1 主线时序

预检(全部 fail-fast, 任一不过即拒迁并给文案)
  后端=Legacy(app/preferences 直读) · BT_backup 可达可写 · 成员无 AutoTMM
  · 嵌套目标闸门(成分级, 继承 0546) · 源侧三态检查(在/.!qB/缺失, 继承 0546)
     │
     ▼
搬迁 mover(setLocation) ── 信号核验: moving 态出现或 dst ready, 30s 无信号快败(继承 0546 §8.3)
     │
     ▼
建 junction(旧路径→新位置), 全员恢复做种(经 junction)
     │
     ▼
当场: journal 记账 → state_file(黄金法则3): {hash, old_root, new_root, 时间}
     │                    (auto-qb 自身重启/崩溃后仍可重放)
     ▼
qB 下线窗口(主循环 2s tick 探测 WebUI 失联):
  逐成员改写 fastresume —— 双键前缀替换(保串风味) → bdecode 往返自校验
  → 备份 .bak → 原子落盘(tmp+replace) → journal 消费
  窗口内任一步失败: 留 journal 下窗口重试; qB 抢先重启 = 本轮放弃(无害, N4 实证自愈)
     │
     ▼
qB 重启 → 核验: API 全员 save_path == 新路径(逐成员, 等值比较)
     ├─ 通过 → 删链门: 扫「save_path == 旧根 或 位于旧根之下」(等值 OR 前缀, N5 教训)
     │         命中=0(含组外共享者) → 删 junction → 终态
     │         命中>0 → 维持 junction, 等依赖消失后下轮再判
     └─ 未通过(改写被错过/失败) → journal 悬挂, junction 维持, 等下一窗口重放
