§01目标与设计原则

1.1 背景

dir_alias 收尾设计(guardian 在 qB 关闭期间删别名 → qB 重启 → 成员 fastresume 找不到文件(missingFiles,设计预期输入)→ reconcile 的 ACT_FINALIZE setLocation 归位)在生产触发 26-11-05-0420 零搬移灾难:归位把共享物理文件改名挂 .!qB,下次搬迁按声明名 stat 全 miss,qB 报「成功移动」而数据未动。压测(0546)证明形态 F(完成位 false)下 API 层无修复通路,整案不采纳,relocate 整组迁移待完全重构。本计划 = 重构:用 fastresume 改写让成员在 qB 重启时原生加载新位置,missingFiles/ACT_FINALIZE/seed_mode 账面恢复链整体消失。

R1 并入:原 0247 计划(单回收 daemon + supersede 再迁移)基于重构前的收尾机制设定 —— 它要优化的 guardian 层恰是本计划要退役的对象,其「daemon 必须守在 qB 退出瞬间删链」的存在理由随旧链证伪而蒸发;但它的两个真实痛点仍在:per-job guardian 进程模型难观察难管理(随退役蒸发),以及未收尾前无法再次迁移(GATE_UNFINISHED 一刀切,pending 窗口可能持续数小时到数天)。经 grilling 重考量:daemon 复活但职权换位(等 qB 下线批量改写 fastresume —— 这个事件监听者必须在 auto-qb 缺席时也能存活,否则收敛倒退),再迁移按新机制重写设计整块并入。

1.2 目标与「算成」标准

  • 整组迁移收尾后:所有成员经一次 qB 重启加载到新路径,账面 progress=1.00 不动,零拒绝载入、零重校验、零 re-add。
  • 收敛公理(D10):收尾收敛不得依赖用户退出顺序,也不得依赖 auto-qb 恰在窗口现场 —— 「auto-qb 关闭时的 qB 退出」「关机风暴/开机双自启竞速」「qB 长期不退出(按钮兜底)」三类情形都有界收敛,journal 不允许永久悬挂(悬挂态单项良性,但 junction 存续/拦截面/确认门/跳检屏蔽全部随悬挂时长单调增风险)。
  • 失败态永远收敛到「别名还在、成员可读、journal 待重放」,不存在需要 API 修复通路才能解开的冻结态(0420 灾难的结构性根源)。
  • armed/rewritten 相位可对同组再次发起整组迁移:旧侧别名全部移交新 job,零悬空、收尾者唯一(0247 目标继承,D15);分阶段换盘、目标路径选错要改不再被闸死。
  • 真机验收 = §03.5 的 N 系列断言在实现后的代码路径上复跑全绿 + 0546 继承项回归。

1.3 设计底线 / 不变量

  • 数据安全第一:fastresume 是 qB 的私有账本,任何写入必须「校验通过才落盘 + 落盘前有备份」;坏文件 = 种子被静默丢弃(N6 实测,仅 INFO 级日志)。
  • 三项设计约束继承(0546 §1.3):不删种 / 不 skip_check 重加 / 不读盘(哈希)校验。本方案天然满足:改写只动路径键,加载核对由 libtorrent 的尺寸级 file_stat 完成(本版 verify_resume_data 只比大小不比 mtime,storage_utils.cpp:560-580)。
  • 黄金法则:跨轮次状态进 state_file(法则 3)—— R1 修订注记(D13):改写账沿既有 per-job journal 文件协议落盘(daemon 唯一写方),state.json 内的 job 镜像由主循环合并,「state.json 单写线程」(法则 5)不动;预检 fail-fast 聚合报错(法则 4);重复执行无副作用 —— 改写幂等(已是目标值则跳过)、删链幂等(门不满足就不删)、重放幂等。
  • qB 是 fastresume 的唯一写方:auto-qb 侧(无论主循环还是 daemon)只在「qB 进程确认下线」的窗口写入,运行期零写入 —— 这是 N1(0.5s 覆盖)换来的铁律;窗口进入判据 = guardian 现成三证(进程不在 + 端口拒连 + 稳定 30s),严于 WebUI 探测。
  • 破坏性步骤必须被监督(D11):别名删除等文件系统破坏性操作只在主循环在线执行;daemon 职权仅限 fastresume 改写(有 .bak 可回滚),绝不删链 —— 0420 灾难正是无监督收尾链闯的祸。
