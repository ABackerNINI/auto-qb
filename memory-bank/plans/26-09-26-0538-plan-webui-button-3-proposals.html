现状诊断为什么"大部分按钮与 UI 不符"

基于 2026-09-26 对两套 UI 的实机截图(stub 预览)逐面板核对, 问题集中在四类:

  • 存在感失衡: 弹窗底部动作(取消 / 确认 / 删除 / 添加)只有 7px 上下内边距的细边框小按钮 —— 在 520~860px 的大弹窗里"漂浮", 主操作压不住场面; 取消钮在深底上几乎隐形(用户点名: 各种弹窗确认按钮、添加种子的取消/添加)。
  • 家族碎片化: 同屏并存 ce-btn / bulk-btn / filter-btn / sb-btn / row-btn / prio-btn / tabs button / hb-btn… 八套写法 —— 高度 21~34px 不等, 圆角 999px 与 7px/0px 混用, 无任何一处共享"按钮"定义。
  • 状态纪律缺失: hover 全族只有背景微变; 按下反馈只有部分家族有 scale; 键盘聚焦棱镜侧没有可见 ring; disabled 有 .3/.45/.5 三种; "加载中"只有个别按钮手写 spinner —— 语义状态不成体系。
  • 两套 UI 不成对: 同名类(.ce-btn.primary)在星图是渐变白字、在棱镜是实心深底字, 手感不一致; 五主题下对比度各自为政。

三组方案共享同一套语义与类名(主 / 次 / 幽灵 / 危险描边 / 危险实心 / 图标), 区别只在形状语言与强调强度。挑定后两套 UI 一次成对落地。

对比速览怎么选

维度A · 精修现行B · 胶囊统一C · 强声明
整体一致性中(弹窗矩形 vs 工具栏胶囊仍两种形状)最高(全 UI 同为胶囊, 与顶栏/筛选/浮条零冲突)高(形状统一为圆角矩形, 靠强对比成体系)
弹窗主操作醒目度较高(渐变+微光)较高(渐变胶囊)最高(实心品牌+深色字, 明度对撞)
与现行观感的距离最小(渐进改良)中(形状变胶囊)较大(按钮气质整体换新)
风险低 —— 但"碎片感"只解决一半低 —— 需接受大按钮全部变胶囊低 —— 深色字配方在五主题已逐个校准对比度
落地工作量三方案相同: 统一 .bt 类族 → 两套 UI 各写一份令牌接线, 模板类名成对替换(ce-btn 等逐族迁移)同左同左
  • 三方案语义与类名完全一致(bt-p / bt-s / bt-g / bt-d / bt-dp / bt-i + sm 档), 也可以两套 UI 各挑不同方案(例如星图 B + 棱镜 A), 互不影响。
  • 落地时将成对替换: 弹窗动作(ce-btn) / 批量浮条(bulk-btn) / 筛选(filter-btn) / 状态栏(sb-btn) / 抽屉行内(row-btn·prio-btn) / 登录页 / 页签 —— 全部收敛到同一族。
  • 设置页 Console Hub 的 hb-* 是刻意的 Ash Thorp 发光语言, 保留其形, 只对齐尺寸节奏与状态纪律(高度档 / 聚焦 ring / 禁用 / 按下), 不混入胶囊或双色配方。
  • 状态图例: 悬停=鼠标停留 · 按下=按压瞬间 · 聚焦=键盘 Tab 可见 ring(无障碍) · 禁用=不可点 · 加载=命令回执等待期(带 spinner, 防重复投递)。
