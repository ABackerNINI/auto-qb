§01目标与设计原则

把候选清单 issue 26-11-20-0408 的 P1/P2/P3 从「盘点」推进到「可开工」: P1 实施错误日志推送化, P2 只补 transfer D5b 两段回执（relocate 半边已交付不重做）, P3 出只读评估结论、不写实施代码。一份计划三阶段, 共用一套 SSE 纪律, 不另建子 issue。

设计底线（不变量）

  • 单一写线程: 主循环线程纪律不破; P1 的发布点是日志线程, 靠 notify 非阻塞保证安全（不引入线程交接队列）。
  • 只推信号与小真值: 绝不推全量状态（3000 种子一轮全量约 63ms, 见 events.py:40-41）。
  • 复用既有基建: 一次性票据 / 心跳 / 满额 503 退轮询 / 单调 seq + 低频对账, 不加配置键。
  • 通道分工: 高频 per-scope 流走专用通道（P0 E1 已落地, 本计划不碰）; 全局低频通知走 /api/events 枢纽。
  • 范围守恒: P0 收口、relocate 两段回执、抽屉实施均不在本计划内; 计划外缺陷一律入池 issue。
  • 幂等: 重复执行无副作用; 状态变更只走 state_file 与既有回执面。

P2 长任务: relocate 已交付, transfer D5b 是唯一缺口

  • relocate 探针 D8 两段回执已实施闭合: 计划 26-11-10-2350 状态 Superseded, R3 记提交 7d99ce32（T4 web 两段回执）, RM11 真机复验 PASS 后专题闭合。

  • 回执基建已就位: cmd 事件带 cmd_id 广播（runtime_commands.py:315-318）, 前端按 id 过滤兑现（commands.js:323-324）, waitCmd 事件与轮询赛跑（:210-215）; transfer 终态经 receipt_port -> set_result 已接线（runtime_transfer.py:564）。

P3 抽屉: 收益被服务短缓存封顶

  • startPoll("drawer") 节拍为主节拍 1.5/2/3s（drawer_store.js:172-198）; 渲染是「写字段不重建 + Vue 同值不触发」（:30-48/260-262）。

  • P0 前置条件: 专用通道代码已交付（traffic_stream.py:60-61, runtime_stream.py:125-134）, 但计划 26-11-18-0037 状态仍 Open, 档案 26-11-18-webui-traffic-stepwise 仍 In Progress, Docker e2e 与真机冒烟两项补验未清偿。本计划不碰 P0 收口。

§07风险与对策

风险触发条件处置

受理段被当终态提前结算onCmdEvent 按 cmd_id 无条件兑现 waiter 且 warn 终结（commands.js:234-235/323-324）; onTruthEvent 认 truth 即结算（:348-372）—— 服务端受理信号无论走 cmd 还是 truth 都会被当终态S2-a 硬约束: 后端不推受理信号, 受理段由前端 POST 返回即本地渲染; 终态才走 set_result -> notify("cmd"); 不改 waitCmd、不建新事件类型。这是 S2 最高优先级风险。

P3 评估结论悬空量化数据不足以下结论结论: 条件触发(暂不实施)。实测(2026-11-27 S3, 一次性探针, 未落文件): ①RoCache 命中率 —— 用项目真实 RoCache(context.py:15-48)注入假钟、按 currentPollMs() 三档推进 N=10000 拍, 以 fn 调用次数反推: trackers(ttl=2.0s)@1.5s=50.00%(5000/10000) / @2s=0% / @3s=0%; peers(ttl=1.0s)三档均 0%; tp 双源合并@1.5s=25.00%(5000/20000)。②抽屉轮询空转率 —— node 经 vm 加载真实 _dtMergeRows(drawer_store.js:35-48), 喂 python 实测命中序列(N=2000): 命中拍返回同一行对象引用 → 字段零变化/行引用稳定/顶层新数组(Vue 同值不触发), 可确定空转 trackers@1.5s=50.00%(1000/2000) / tp 双源@1.5s=25.00% / @2s·@3s=0%(0% 仅表示 RoCache 不吸收、可确定空转为 0, 不代表实际无空转; 真实 qB 数据变化率需真机, D11 P3 免真机故本批不测)。理由: 结构性空转只在 1.5s 档出现且峰值 50%(单源)/25%(双源), 2s/3s 档缓存不吸收; 渲染层已「写字段不重建 + Vue 同值不触发」把空转的用户可见成本压到≈0, 剩余仅 qB 调用且已被 RoCache 部分吸收; 反面证据: 推送化本身需 per-scope 订阅 + seq + 对账 + 断档重拉 + 前后端同提交, 改造成本不低, 且命中率越高说明 RoCache 已吸收越多 qB 调用、可省调用越少(本批实测 1.5s 双源 25% 已吸收四分之一), 收益上限受限; P0 per-scope 通道(26-11-18-0037)仍 Open、真机冒烟未清偿, 复用前提不成立。触发阈值(三条同时满足才另起独立排期, 不在本计划内实施): (a) 真机实测抽屉页签空转率 ≥60%(本批仅结构性下界, 真实 qB 数据变化率需真机、D11 P3 免真机); (b) 同口径 RoCache 命中率 ≤10%(本批实测 1.5s 双源 25% / 2s·3s 0%), 即缓存已吸收不了白拉、每拍真实穿透 qB; (c) P0 计划 26-11-18-0037 收口且真机冒烟通过。
