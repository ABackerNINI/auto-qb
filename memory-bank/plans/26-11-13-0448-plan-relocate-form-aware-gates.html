§01目标与设计原则

为什么做

生产整组移动(文件级别名形态)进入待收尾窗口后,旧根目录出现两单误拦(用户定性, D2/D3):

#操作现行行为事实
误拦① 在旧根 R:\Download\PTing 下添加新种子(文件夹包,异名) 「落点确认」弹窗,断言「账面会记在旧路径 —— 成为删链门的永久依赖(旧路径别名将永不删除)」 文件级别名下旧根是真实目录,别名只是成员内容根里的逐文件链接;异名新种子的数据落原盘真实目录,不经别名、不依赖别名。原设计 1604 §3.6 场景 1 明文「无影响 / 独立成组」
误拦② 删除 PTing 下组外别的种子(带文件) D16 拒绝:「带文件删除会经别名删到已迁往新位置的数据」 组外异名种子的文件是真实文件,删除不经任何链接;D16 的 N5 依据(junction 穿透 / 文件级 symlink 跟随)对它们不成立

根因:0808 D16 的前提「pending 期往旧根添加非本组种子 = 删链门永久依赖」是不分别名形态的过度泛化 —— 它只对目录别名(一切落点被 junction 重定向,真依赖)与文件级同名(落点撞链接树,真依赖 / 真覆盖,1604 §3.6 场景 2/3)成立。三处判据忠实复现了这个过度泛化(§02)。附带缺陷:0808 重定义对账表时丢失了原设计 1604 §3.5 对账表的「种子已不存在 → failed(torrent_gone) 保留现场」行 —— 收尾窗内成员消失(包括 D16 文案自己推荐的出口「仅删除种子」)后 job 永不收敛,1300 D4/R5 披露的「D16 摩擦收尾后消失」前提(收尾会及时发生)随之击穿。

做到什么程度算成

  1. 添加面:文件级收尾窗内,异名落点静默放行(§3.6 场景 1);同名落点(落点即链接)仍 confirm 且文案改准(场景 2/3);目录级 confirm 保留(D10/D16 原样)且判据扩成前缀(补「深层添加绕过弹窗」覆盖洞)。
  2. 删链门:文件级 job 的组外种子按「文件清单 × 链接路径交集」精判 —— 不相交(异名)不算依赖,收尾照常收敛;目录级判据原样(scope 前缀 + src 等值面)。
  3. 删种拦截:文件级 job 的 D16 拦截面收窄为同一交集判据 —— 组外异名种子带文件删除当场放行;成员 / 同名撞链接根仍拦。
  4. 成员收缩:收尾窗内成员经多拍确认消失 → 收缩 job.hashes + WARNING 留痕;全部成员删光 = 空集核验通过,自然走删链门收尾。
  5. 自愈:生产现状(armed + 组外种子已落旧根,无论弹窗当时确认与否)在修复后的代码路径上零人工干预收敛到 done —— 生产不跑任何恢复操作(用户拍板 D7);qB 下一次重启(自然或经「立即收尾」按钮)即完成收尾。

设计底线 / 不变量

  • 本计划是对 0808 D16 的「前提形态化修正」,不是推翻:confirm 预防面(D10 防静默改盘)与 N5 拦截本体保留;修正的只是判据对文件级形态的适用范围。
  • 数据安全三约束(0546 §1.3)全程断言:不删种 / 不 skip_check 重加 / 不读盘(哈希)校验。
  • 豁免判据宁拦勿漏:交集判据的输入(文件清单)不可得 → 照旧拦(现状行为),绝不猜「不相交」。
  • 判据纯函数不触盘;预检拦截先于任何数据移动(fail-fast)。
  • 生产 26586/16585 与 I:\PT\、config.yml、auto-qb-data/ 零触碰;真机验证只在测试实例 + real-fake 假种子(D7)。
  • 真机实验先行(1300 D7 同款纪律):任何结构判据先上真机构造场景实证,与推演不符即回炉,不带假设进实现。

§03方案总览

主线:三处判据共用一个精确谓词 —— 文件级 job 下,「种子的文件清单与 job.alias_paths 是否相交」;相交 = 真(依赖/穿链接风险),不相交 = 误拦面豁免。目录级判据原样保留。外加成员收缩行与文案修正。
