待收尾迁移种子的 WebUI 可见性与路径链展示计划

在不改写 qB 保存路径语义的前提下，为「已搬走但尚未收尾」的种子增加一层只读展示：行内状态标记 + 按需路径链浮窗；路径筛选保持 qB 口径，另设独立的迁移状态筛选。先交付可确认事实的最小面，再分阶段增加文件系统探测与 qB 标签。

§01目标与设计原则

目标：让用户在 WebUI 里能回答四个问题——①这颗/这组种子是否正在迁移、是否已搬走待收尾、是否失败；②qB 报告的保存路径与实际数据位置是否不同；③路径跳转链是什么（A → B → C，含非 auto-qb 创建的链接）；④如果是 auto-qb 设置的跳转，属于哪个 job、何时设置、属于哪种触发来源、当前收尾到哪一步。

做到什么程度算成：P0 后端只读投影上线，列表/详情能稳定显示迁移状态且不改变任何既有筛选与操作语义；P1 行内标记与详情可用、键盘/触屏可达；P2 浮窗能按需展示完整路径链并对不可判定态显式标注「未确认」；P3（可选）qB 标签镜像。每一阶段可独立回滚。

设计底线（不变量）：

  • qB 的 save_path 是生效值：save_path 参与路径筛选、删除汇报、转移改写、移动预填与 qB setLocation 语义，展示层绝不复写它，只加派生标注。
  • 三层拆分：显示值 / 筛选值 / 生效值各自独立；新增能力只加新层，不改旧层口径。
  • 事实源优先 state：迁移状态与归属以 state.json 的 relocate.jobs 为准；文件系统探测只提供「当前可验证/不可验证」，不反向覆盖 job 记录。
  • 不知道就显示未确认：映射 miss、权限失败、远端不可达、环、跨范围目标，都标「未确认」并给原因，不猜成「不存在/已迁移」。
  • 列表零文件探测：列表构建只做内存 join；任何 lstat/readlink 只在用户打开浮窗或显式刷新时发生。
  • 单一写线程：job 快照由主循环发布为不可变元组，Web 线程只读；不在 Web 线程遍历主循环可变 dict。
  • 黄金法则 4：若新增配置键（仅 P3 标签），必须进 config.validate_config 并同步 src/auto_qb/config/schema/。

2.2 压测结论：哪些假设站不住

  1. 「把路径改成移动后路径」站不住。 保存路径不是一个展示字段，它是筛选键、删除汇报分组键、转移改写基准、移动预填值和 qB 生效值。直接改写会同时破坏路径筛选、删除提示、转移预览与后续 setLocation 语义。结论：显示层加标注，筛选层保持原口径，生效层不动。
  2. 「每行实时探测跳转链」站不住。 列表首屏按行 lstat/readlink 会叠加网络盘/权限失败/长路径成本；且用户鼠标扫过就会触发大量重复探测。结论：列表只读 state 内存；链路按需探测 + 短 TTL 缓存 + 显式刷新。
  3. 「qB 标签可以当事实源」站不住。 标签可被用户手工删除、被 tracker 规则 remove_tags 清掉，也可能与用户自定义标签冲突。结论：state 是唯一事实源；标签只能是可选镜像，且读取端不得依赖它。
  4. 「一次 realpath 就能拿到完整链」站不住。 需要逐跳识别 junction / 符号链接 / 挂载点 / 硬链接；Windows junction 目标可能是 \??\ 前缀，POSIX 符号链接可能是相对路径；还要处理环、跨卷、跨允许根、权限失败与探测期间变化。结论：逐跳探测、有上限、有环检测、有「未确认」态。
  5. 「谁设的可以从文件系统判断」站不住。 文件系统只给出链接目标，不给创建者。结论：归属只能来自 job 记录（alias_paths 精确匹配 + origin）；不匹配就标「非 auto-qb 设置」。
  6. 「待收尾 / 已完成靠 phase 一位就能讲清」一半成立。 phase 十态可精确映射到用户状态，但终态 job 在 state 里永久保留，不能用「存在 job」当「仍在迁移」。结论：后端做状态归并，终态 done 不进行内徽标，失败态要可见。
  7. 「hover 浮窗就够了」站不住。 触屏没有 hover，键盘用户也无法悬停；本项目已有 aq-tip 锚点漂移与浮层 Esc 退栈的坑。结论：徽标必须是可点击、可聚焦的按钮；hover 只是鼠标的快捷入口。
  8. 「组行路径与筛选天然一致」已被 armed 打穿。 首成员口径既有实现本身在混合路径组上就是不稳定的。结论：组级迁移状态由后端聚合，前端不再从首成员推导。

§03方案总览

3.1 三层路径语义（D1）

层值消费者本计划是否改
显示值qB save_path 原文 + 迁移徽标/工具提示组行、成员行、详情抽屉只加标注，文本不变
筛选值qB save_path（组=首成员，成员=原文）路径筛选、HR 搜索、转移目标预览不变；新增独立的「迁移状态」筛选
生效值qB save_pathsetLocation、删除、限速、转移、添加落点绝对不变

路径列显示「qB 路径」并在其后加一个 → 目标 徽标，是解决「看起来没移动」的最小改动；筛选仍按 qB 路径，用户若想筛「迁移相关」用新维度，而不是让路径筛选偷偷跟随物理位置。

3.2 状态归并（D2）

用户状态来源 phase行内展示说明
迁移中moving / watching「迁移中」qB 正在搬字节；mover 的 save_path 可能已变
待收尾moved / armed / removing / removed / finalizing「已搬走 · 待收尾」数据在 dst，qB 仍可能指向 src；别名仍在或正在拆
已完成done不进行内徽标终态；详情里保留最近一次迁移记录
迁移失败failed「迁移失败」警告需保留现场；原因进详情/浮窗
已撤销cancelled不进行内徽标回滚完成；详情可见历史

3.3 分期落点

阶段范围交付物明确不做
P0 只读投影后端成员/组 relocate 标注、job 快照发布、origin 字段、聚合状态、指纹更新不做 UI、不做文件探测
P1 行内可见前端路径列徽标 + 详情「迁移」段 + 独立迁移状态筛选 + 键盘/触屏可达不做完整链探测、不做标签
P2 路径链后端 + 前端按需链探测端点、浮窗链展示、归属、未确认态、缓存/刷新不做每行预探测
P3 qB 标签（可选）配置 + 后端opt-in 单标签镜像；生命周期内加/摘；失败不致命不作为事实源、不做启动期复活

3.4 数据契约（草案）

成员视图新增可空对象 relocate（无 job 时省略/为 null，旧前端不受影响）：

{
  "state": "moving | pending_finalize | done | failed | cancelled",
  "phase": "armed",                  // 原始相位，排障用
  "job_id": "...",
  "mover": true,                     // 该成员是否 mover
  "src": "R:/Seeds/A",
  "dst": "S:/Seeds/A",
  "alias_kind": "dir | file |",
  "alias_count": 12,
  "armed_at": 1760000000.0,
  "updated_at": 1760000000.0,
  "origin": "web | rule | cli | unknown",
  "reason": ""
}

组视图新增聚合对象（同键名，结构不同；前端按组行读取）：

{
  "state": "moving | pending_finalize | failed | mixed | done",
  "pending": 3, "total": 4,
  "job_ids": ["...", "..."],
  "dst": ["S:/Seeds/A"],             // 去重后的目标路径
  "updated_at": 1760000000.0
}

不把 job 的 plan、完整 alias_paths 塞进每轮轮询载荷；路径链与更细的现场走 P2 的按需端点。避免重蹈「显式动作才需要的字段不塞进轮询载荷」的坑。

§04实施步骤

步骤内容验收判据
P0-1
job 快照发布		 主循环在 job 变更后发布不可变快照（hash → 最佳 job 的映射 + 聚合元数据），Web 线程只读；不直接遍历 ctx.relocate._jobs。 Web 视图构建期间对 job dict 零遍历；同一 hash 同时存在终态旧 job 与新 job 时取活跃者；快照变更能触发视图刷新（至少 30s 轮询内可见）。
P0-2
成员标注		 _member_view 增加 relocate；状态归并单点在后端；不改 save_path 行。 relocate 关闭 / 无 job / 旧 state.json 三种情况字段为 null 且视图不炸；旧 job 无 origin 显示 unknown。
P0-3
组级聚合		 _build_group_row 增加组级 relocate；优先级 failed > moving > pending_finalize > done，同优先级多 job 记 mixed；计数 pending/total。 成员顺序任意打乱，组级状态与 dst 集合不变；mover 与未 mover 混合时不再显示「路径一致」。
P0-4
origin 归因		 relocate_execute 增加可选 origin；三处调用方分别传 web / rule / cli；旧 job 默认 unknown。 WebUI 手动移动、规则 move_to、命令行三路各有真值；未知来源不冒充 auto-qb。
P0-5
前端指纹		 decorate.js 的记忆化指纹加入成员 relocate 签名与组 relocate 签名；同步槽位长度断言。 job 相位变化后组行徽标不陈旧；仅 store 数据不变而 relocate 变化时也能刷新（必要时主循环 touch Web 快照）。
P1-1
行内徽标		 路径列文本后加小徽标（迁移中 / 待收尾 / 迁移失败）；徽标独立点击，@click.stop 不触发路径筛选；徽标是 button，可 Tab 聚焦、Enter/Space 打开。 点路径文本仍按 qB 路径筛选；点徽标只开详情；触屏可点开；四皮肤下不增高行、不撑破路径列。
P1-2
详情段		 抽屉详情新增「迁移」段：状态、src → dst、job_id、origin、设置时间、别名形态/数量、原因、最近记录。 done/cancelled 只在详情可见，不污染列表；failed 的原因可复制；字段为空显示「—」。
P1-3
迁移筛选		 新增独立 facet：迁移中 / 待收尾 / 失败 / 有过迁移；沿用 facetRows / _facetOptions 取数单点，不新增按组自算的第二套实现。 种子页与辅种页计数口径各随行走；不改变路径筛选结果；选中后与其它筛选可组合。
P1-4
浮窗骨架		 复用 HR 弹窗形态：120ms 显示 / 160ms 宽限、body 级 teleport、fixed 定位、上方优先翻下方、横向夹取、Esc/滚动/缩放关闭；底色用不透明 --bg-pop，不走 blur；Esc 退栈顺序按视觉层级。 四皮肤无透底；下部锚点不压元素；键盘 focus 可打开；滚动时随锚点关闭而不漂移。
P2-1
链探测端点		 GET /api/relocate/chain?hash=...&refresh=1；只收 hash，起点由服务端快照派生（优先 root_path/content_path，回退 save_path）；沿用 _require_relocate 403 门控；逐跳 lstat/readlink，上限 8 跳，环检测，目标规范化（相对链接、\??\ 前缀、长路径）。 不接受客户端任意路径；点在允许根内才继续展开，范围外标 outside_scope；环标 cycle；权限失败标 unknown；非 Windows / Mapped / 远端返回 unknown 而非猜。
P2-2
归属与证据		 每一跳与该 hash 的 job alias_paths 精确归一比对：命中给 job_id / origin / armed_at / phase；未命中标「非 auto-qb 设置」；记录存在但文件已消失标 stale_record。 手工 junction、其他工具符号链接不误归因；同一路径被多 job 用过时优先活跃 job。
P2-3
缓存与刷新		 服务端 LRU（键 = hash + 起点 + job generation），TTL 20s，容量 128；refresh=1 绕过；前端同一时刻只发一个链请求，结果区显示探测时间。 连续扫多行不产生 N 倍探测；job 状态变化后旧缓存不冒充新事实；探测失败可重试。
P2-4
浮窗链展示		 节点行：路径、类型（目录/文件/junction/符号链接/挂载点/硬链接）、状态（已确认/未确认/不存在/环/范围外）、归属章；自动换行、可复制；长链可滚。 A → B → C 完整可见；不可判定不给假结论；硬链接只显示「N 个名字」不伪造目标。
P3-1
qB 标签（可选）		 新配置 relocate.pending_tag，默认空 = 关闭；armed 时加、终态时摘；幂等、dry-run 感知、失败仅告警；不读回作为事实源。 关闭时零 qB 写；开启后 qB UI 可见；用户删除后 WebUI 状态不受影响；被 remove_tags 清掉不导致状态错乱。

§05待拍板清单

按重要性排序；每条都给了推荐（默认）与备选，不阻塞计划推进。

编号问题推荐（默认）备选
D1 MVP 边界：先做「状态标注 + 详情」，还是把完整路径链一起上？ 先 P0+P1 最小面：状态可用、筛选不破坏；P2 再做完整链。理由：状态事实源已存在，链路探测是新读能力，风险与测试面大，分开可独立回滚。 一次做到 P2：用户马上能看到 A → B → C，但首版范围与验收面显著变大。
D2 保存路径筛选怎么处理？ 保持路径筛选 = qB 路径；新增独立「迁移状态」筛选。理由：路径筛选是既有契约，多消费者依赖；新维度语义清晰。 给路径筛选加「按实际位置筛选」开关（默认关）：更贴近物理位置，但同一条目会同时属于两个路径集合，容易产生「筛 src 却筛出 dst」的误解。
D3 qB 标签本期做不做？ 本期不做，留 P3 opt-in。理由：标签可被用户/规则删除，不能当事实源；写入 qB 增加失败面与清理责任，而 WebUI 已能回答同一问题。 本期做 opt-in 单标签：qB 界面直接可见，但需接受标签污染、被清掉后语义漂移、回滚清理复杂。

§09兼容与回滚

  • 旧数据：relocate.jobs 旧记录无 origin → 显示「未知来源」；phase 缺省沿用 moving；不需要迁移脚本。
  • 旧前端/旧客户端：新增字段是加法，旧消费方忽略；save_path、组键、路径筛选选项不变。
  • 功能关闭：relocate.enabled=false 时不发标注、链端点 403、徽标不渲染；无 qB 写。
  • 回滚：P0/P1 纯读展示，回滚 = 隐藏徽标/详情段；P2 回滚 = 摘除端点与浮窗，无 state 变更；P3 回滚 = 配置置空，标签仅随 job 生命周期自然摘除（不自动复活）。
  • 数据安全：链探测只做 lstat/readlink，不读文件内容、不写盘、不投命令；沿用 _require_relocate 与 fs.py 的允许根白名单口径。
