01结论：可行，且分三段落地

可行。现有前端是「无构建链的 Vue 3 全局版 + 按域拆分的 window.AQB_* mixin 包」， 动作入口已经是语义方法（bulkAct / act / actTorrent / _deleteFlow …），偏好持久化也有现成范式（localStorage + 跨标签 storage 同步）。 快捷键是挂在既有动作上的一层输入映射，不需要动后端、不需要动 config.yml。

唯一需要新增的概念是「光标行」：现在点击行不产生选中（onMemberClick 普通点击 直接 return），选中只由 Ctrl / Shift 修饰键产生 —— 也就是说界面里根本没有"当前行"， 而上下键导航必须有一个。这是本次真正的设计增量，其余都是接线。

建议的落地顺序

第一段（必做）：键盘引擎 + 光标模型 + 高频动作键位（约 30 条），先让"能用"落地。
第二段：自定义面板（录制 / 冲突检测 / 重置 / 跨标签同步）。
第三段（可选）：抽屉内、设置页内、文件优先级等局部作用域键位。

03四个技术难点与判据

难点一 · 光标行可能没渲染（虚拟化）

_rowWindow() 每轮算一次前缀和 pre[]（行高逐行实测，_rowHs）， 用它切出 [start, end) 渲染窗口，算完即弃。要让"↓ 按到第 300 行"能真的看到， 需要先知道第 300 行的 y，再滚动到那儿。

方案

① 在 _rowWindow() 末尾把 pre 存进 this._rowPre[kind]（与 _rowHs 同级，不落盘）；② 新增 _kbScrollToRow(kind, idx)：取 pre[idx] + _winTop[kind]，window.scrollTo 到"刚好露出"的位置 （目标已在视口内则不动，避免每次按键都跳）；③ 窗口未启用（rowWin=false / 行数 < 200 / 尚未量齐）时退化为 querySelector('[data-hash="…"]') + scrollIntoView({block:'nearest'})。

判据：3000 行库下连按 ↓ 到底部，光标不丢失、不出现空白窗口、末行可达。 这条只能真机量（静态守阵测不到），进 §8 走查清单。

难点二 · 输入态与中文输入法

单个字母键做快捷键，最大的坑是"用户正在打字"。三段屏蔽，缺一不可：

  • e.isComposing 为真（或 e.keyCode === 229）→ 直接放行，一个键都不吃；
  • 事件目标是 input / textarea / select / contenteditable → 只放行白名单（Esc 关窗 / Ctrl+Enter 提交 / 设置页 Ctrl+S），其余一律交回浏览器；
  • 有模态层（确认框 / 添加 / 统计 / 限速 / 抽屉 / 管理 / 元信息）打开时 → 只放行该层白名单， 列表动作全部失效（否则会在看不见列表的地方删种子）。

判据：在搜索框里输入拼音（如 "zhongzi"）时，不能触发任何快捷键、不能吞字； 输入法候选框弹出期间按 / 应落在输入框里。

难点三 · 键位冲突（浏览器 / 系统 / 输入法）

浏览器保留键是拦不住的那部分（Ctrl+T/W/N、F5/F11/F12、 Ctrl+Shift+N/I/J/C、Ctrl+P/F/R、Ctrl+Alt+Del、mac 的 Cmd 系与 Ctrl+↑ Mission Control）。自定义面板必须能当场认出并提示， 而不是等用户发现"按了没反应"。

判定口径

匹配基准用 e.code（物理键位）+ 修饰位，不用 e.key： e.key 随键盘布局与输入法变化（mac 上 Option+P 打出的是 π）， e.code 不变。显示层再走 code → 标签 映射（KeyP→P / Slash→/ / Digit1→1 / BracketLeft→[）。 功能键（Arrow* / Escape / Enter / Space / Home / End / PageUp / PageDown / F1–F12） 仍用 e.code，两者本就一致。

难点四 · 行位置随刷新漂移

列表每轮轮询（lastRid）重排，排序方向、筛选、搜索都会让"第 i 行"换人。 光标记身份不记下标：每轮渲染后按 id 在新列表里重新定位；找不到就落到"原下标裁剪后的最近一行"； 列表空则光标为空（此时动作键提示"先选一行或选种子"）。

04架构设计

文件与接线

  • 新增 src/auto_qb/webui/static/shared/shortcuts.js —— 挂 window.AQB_SHORTCUTS（mixin：状态 + 方法）+ window.AQB_KEYS（注册表常量）。 两处 index.html 都要挂，且排在 app.js 之前。
  • 新增 shared/shortcuts.css（光标行描边、快捷键面板、录制态）—— 走现有 CSS 令牌族；新挂件类必须能被 _scan_page_class_wiring 找到规则。
  • 面板模板放两份 index.html（与列选择器同款：模板在 HTML，逻辑在 shared）。
  • commands.js 内抽 _actCore(action, {keys, hashes})， act() / actTorrent() 各自退化为薄包装。仅此一处重构， 其余文件不改行为。

注册表（单一事实源）

SHORTCUTS 条目形状

{ id, group, label, def, scope, danger?, fixed?, run(vm) }

def 是默认键位（"KeyP" / "Ctrl+Shift+KeyL" / "" = 默认不绑定）；scope ∈ global / list / drawer / settings / modal； danger 的条目（删除类）在面板里标红且不允许绑到无修饰的单键； fixed 只有 Esc（退栈链硬编码，不给改）。 键位表、面板列表、冲突检测、守阵断言全部读这一张表 —— 表外无键位。

匹配与存储

  • 归一化：mods = (ctrl?"" )+(alt)+(shift)+(meta)，顺序固定 Ctrl+Alt+Shift+Meta+<code>；meta 与 ctrl 在 mac/Win 上分别归一，避免"两边都要按"。
  • 存储：localStorage["autoqb.ui.keys"] = { "<id>": "<归一化串>" }。 缺键 = 用默认；空串 = 显式禁用；storage 事件整份采纳（与列偏好同机制，跨标签一致）。
  • 冲突：同一串被两条占用 → 后写的顶掉先写的，并 toast 提示"已从 X 移交给 Y"； 命中保留键黑名单 → 面板内拒绝并给出"浏览器占用，换一个"。
  • 重置：单条"恢复默认" + 全局"全部恢复默认"（清 localStorage 键）。

光标与选中（两套状态，不合并）

状态取值语义
选中（既有）selGroups[] / selMembers[] 互斥的两类口径，批量动作的目标集合。不动。
光标（新增）kbCursor = {kind, id} kind ∈ group / member / torrent / show / ep；id = 组 key 或种子 hash。 视觉 = 1px 虚线描边（与选中底色的语义不同，别复用）。
目标解析_kbTargets() 有选中 → 用选中集合（走 bulk 链路，与批量浮条同口径）； 无选中 → 用光标行（组行展开为成员 hashes / 种子行单 hash）。

为什么要"有选中就用选中"：右键菜单已经这么判（menu.js:_ctxMulti）， 键盘沿用同一口径才不会出现"我明明选了 3 行，按 p 却只暂停光标那一行"。

06自定义面板设计

入口（三处，互为冗余）

  • 快捷键 ? —— 主入口，任何非输入态可达；
  • 设置页「常规」分区页尾的一个块 —— 与"运行日志 / HR 在线核实"同款（那两块已并入分区页尾， 是现成的"客户端只读块"先例）；
  • 顶栏不新增按钮（右侧已有 设置 + 棱镜 + 状态徽章，再加会挤）—— 若后面觉得不够显眼，再按 R11 的图标语义类补一个，属另一轮。

面板形态

  • 与统计/限速同层：无遮罩 modal 会挡住列表，键盘场景下更该用带遮罩的居中弹窗（录制态要吃所有按键， 遮罩能明确"现在在录"）；关闭走 Esc / 点遮罩 / 关闭按钮。
  • 列表按注册表 group 分组：全局导航 / 光标与选择 / 一级动作 / 次要动作 / 队列与开关 / 局部（抽屉·设置）/ 未绑定。每行 = 动作名 + 当前键位（chip）+ 「改键」「清除」「默认」。
  • 顶部一行：搜索框（按动作名或键位过滤）+ 「全部恢复默认」。
  • 底部一行说明：偏好按 浏览器 + 站点地址 存（localStorage 的 origin 隔离）， 换机器/换端口不跟着走 —— 这条必须写出来，否则又是一次"改了没生效"的报障。

改键（录制）交互

  1. 点「改键」→ 该行进入录制态（chip 变成"按下新的组合键…"，Esc 取消，点别处也取消）；
  2. 捕获第一个 keydown：stopPropagation + preventDefault， isComposing 时不收；单修饰键（只按 Ctrl）不收，等真键；
  3. 三种结果：① 命中黑名单 → 行内红字"浏览器占用，换一个"，留在录制态； ② 命中已有条目 → 提示"会从 X 移交给 Y"，确认后 X 置空； ③ 空闲 → 写入并即时生效；
  4. 写 localStorage + toast；同标签即时生效，其它标签靠 storage 事件整份采纳。

危险动作（D8 删除）额外一档：绑到无修饰单键时二次确认一次 —— 默认 D 本身就是这个形态， 所以面板里对 danger 条目显示的是"⚠ 单键触发（有确认框）"，不禁止（禁止会让默认表自相矛盾）。

09风险与不做的事

风险

① 光标被当成选中 —— 两套状态视觉若做得像，用户会以为"光标行 = 已选"，按 P 就只暂停一行。 缓解：光标用 1px 虚线描边（不铺底），选中保持现有底色铺底 + 左侧条；首次出现光标时 toast 一句。

② 浏览器抢键 —— /（Firefox）、Ctrl+S、Ctrl+Home/End 可能被浏览器先拿走。缓解：真机实测后，抢不过的那几条从默认表里摘掉（改成空默认位，由用户自定）。

③ 大库上的性能 —— 光标移动会触发一次滚动 + 一次窗口重算。缓解：滚动进视口只在"目标不在视口内"时执行， 不在每次按键都滚；前缀和复用现成的，不另算。

④ 文档漂移 —— 键位表写进文档就会过期。缓解：文档只写口径，键位以注册表为唯一事实源， W7 的守阵 ① 兜住。

本轮不做

序列键（如 G 然后 S）—— 需要超时状态机，收益不抵复杂度； Vim 风格 J/K —— 与"上下键"重复； 服务端持久化（写进 config.yml）—— 那是用户生产配置（红线文件），且 UI 偏好属于"这台浏览器"， 与列偏好 / 主题 / 时间口径同一档，一律 localStorage； 手机/平板触屏手势 —— 无键盘可谈。
