WEBUI 选中摘要: 种子个数 + 合计/实际占用大小

选中种子时在筛选行显示「已选 N 个种子 · 合计 X · 实际占用 Y」：个数走既有选中闭包，合计 = Σ 选中种子 size，实际占用 = 按辅种组（同一份文件的多站点副本）去重、每组取最完整副本 —— Y 仅在小于 X 时出现。设计主轴：所有口径挂既有单点（selHashSet / memberByHash / 组行 size 语义），零新配置、零新交互入口、零新 CSS。

§01目标与设计原则

为什么做：多选种子时（最典型：种子页搜出一部片子的多个站点副本，Ctrl 逐个圈选），用户看不到「选了多大」。旧批量控制条只显示「已选 N 个种子」且已于 2026-10-05 退役（动作入口与右键批量菜单重复，见 ab98b356），qB 原生 UI 则有选中合计。本轮把纯展示的选中摘要补回来：个数 + 合计大小 + 去重后的实际占用。

做到什么算成：§04 的 S1–S5 每条验收判据通过；三视图（辅种/种子/追剧）口径一致；无选中时零占位；实际占用仅在 Y < X 时出现；删除确认框同口径出现该行。

设计底线 / 不变量

  • 选择权威不变：N / X / Y 全部派生自 selGroups ∪ selMembers（经 selHashSet 单点展开），不新存任何选择状态、不加新的写入口。
  • 派生值后端算：内容单元标识 occ_key 由后端 _member_view产出（与组行 key 同键空间），前端只消费、不自己推断组归属。
  • 保守默认 / 纯展示：不加任何新交互入口（清除选择仍走 Esc；批量动作仍走右键菜单）——不重蹈控制条「重复入口」退役覆辙。
  • 死类零残留：不复活 .bulk-* 任何符号（守阵 test_frontend_bulk_bar_retired 已钉死）。
  • 零新 CSS：指示器整行复用 .strip-note（三套皮肤逐字同款）——「不加新视觉语言」是从构造上不可能与主题不符（D12）。
  • 跨层口径单点：Y 的算法只有一个函数（selection.js::selSizeSummaryOf），筛选行与删除确认框共用，防两处各自演化。

§03方案总览

主线：① 后端 _member_view 加 occ_key（归组种子带其组 key，未归组不带）→ 三视图所有行自带内容单元标识，种子页缺口补齐；② 前端 selection.js 落唯一算法单点 selSizeSummaryOf(members) + selectedSize computed；③ topbar.html 筛选行指示器（.strip-note 样式，退役控制条原槽位）；④ 删除确认框加条件行「实际占用」（同一函数同一口径）；⑤ 守阵 + e2e + 文档回写。

三条口径推论（拍板 D8/D10 的直接后果）：① Y ≤ X 恒成立（单元 max ≤ 单元成员和）；②「X ≠ Y」⇔「选中了同一内容单元的 ≥2 个副本」——正是用户要的「辅种 Y 只算一份」；③ 只选 1 个副本时 X = Y，不显示 Y。跨组文件交叉（cross_group_conflict）不再去重（D9）：该风险后端另有标记，选中摘要不重复担这份语义。

§04实施步骤

S1 — 后端 occ_key（契约先行）

  • views.py::_member_view(r)：归组种子（self.store.group_key(r.hash) 非 None）带 occ_key = encode_group_key(key)；未归组为 null（字段恒在、null = 不适用，与 availability 同族契约；前端 m.occ_key || ("self:" + m.hash) 兜成自单元）。形状纪律：函数仍以 return {字典字面量} 收尾（occ_key 进字面量、组 key 查表前置）—— 守阵 test_seed_view_no_member_view_restatement 的 AST 提取假设第一个 return 就是字典字面量，改成 d = {...}; return d 会把它跑炸（R1）。
  • 落点即覆盖三视图：组行 members、singles、种子页 torrents（_seed_view 经 {**_member_view(r), ...} 继承）；追剧页成员经 memberByHash（groups ∪ singles）解析，同源。
  • occ_key 与组行 key 同键空间（都走 encode_group_key）——这是守阵的不变量：每个成员的 occ_key 必等于其所属组行的 key。
  • 线程安全：group_key 是 member_to_key 字典单次 .get()（非迭代），与 Web 线程重建路径并发无「dictionary changed size」风险（该风险只在迭代，见 _build_group_view 的快照纪律）。

验收：守阵测试——① 合成库里每个归组种子 _member_view 带 occ_key 且 == 组行 key；② 未归组种子（singles）occ_key 为 null；③ _seed_view（种子页）同样带（经继承，不重述）。
依赖：无。可独立提交。

S2 — 前端摘要算法单点（selection.js）

  • selSizeSummaryOf(members)：入参 = 成员行数组（须带 size / occ_key）；遍历累计 total（X），同时按 m.occ_key || ("self:" + m.hash) 分单元记最大 size；输出 {total, occupy}。约 12 行，零依赖。
  • selectedSize computed：selectedCount 为 0 时早退返回 {0,0}（不建索引）；否则把 selHashSet 经 memberByHash 解析成成员行，交 selSizeSummaryOf。
  • 解析不到的 hash（轮询竞态的极端窗口）在 X/Y 中同步少计——与既有 bulkDelete 摘要计数同口径（_deleteMembers 同样跳过解析不到的行），不新创第三种行为。

验收：函数为纯函数（同输入同输出）；selectedCount=0 时不触达 memberByHash；选择变化后摘要与 selectedCount 同轮更新。

S3 — 筛选行选中指示器（topbar.html）

  • 位置：状态图例之后、筛选说明之前（退役控制条原槽位）；v-if="selectedCount"，无选中零占位。
  • 文案：已选 <b>N</b> 个种子 · 合计 <b>X</b>，Y < X 时追加 · 实际占用 <b>Y</b>；Y 的数值挂 :title 解释「辅种组内多站点副本只计一份（取最完整副本）」。
  • 样式：class="strip-note sel-summary"——.strip-note 是三套皮肤逐字同款的既有规则（> b 自动提亮），.sel-summary 只是 e2e 选择器钩子（无 CSS）。
  • 不改 .status-strip 的 v-if 条件（page==='groups' 下三视图恒渲染，无回归面）。

验收：三视图选中即显、Esc/清除后即隐；单位走 fmtSize（1024 进制两位小数）；只选未归组单种子时不出现「实际占用」；双皮肤（atlas/prism）视觉一致。

S4 — 删除确认框「实际占用」条件行（delete_flow.js）

  • _deleteDetails：在既有「总大小」行（= X，全成员求和，不动）之后，Y < X 时 push 一行 {icon:"#i-hdd", label:"实际占用", value: fmtSize(occupy), hint: "…"}；X/Y 由 selSizeSummaryOf(members) 同一函数产出（_deleteMembers 已是成员行数组，天然匹配入参）。
  • popovers.html 详情行 :title 绑定加 d.hint || 前缀（既有行无 hint 字段 → 行为逐字不变；verdict 行同模板同族，一并受益但本轮不消费）。

验收：删同组 2 个副本 → 框内出现「实际占用」行且值 < 「总大小」；删未归组种子 → 不出现；行结构与既有五行一致（图标/label/value/title）。

S5 — 守阵 + e2e + 文档回写 + 全量基线

  • 前端静态守阵（test_webui_static_dom_page.py 族）：① topbar.html 指示器存在且消费 selectedSize/selectedCount；② selection.js 定义 selSizeSummaryOf 与 selectedSize；③ delete_flow.js 的 Y 行走 selSizeSummaryOf（不另写求和）；④ 不复活 .bulk-*（既有守阵已覆盖，本轮回归）。
  • e2e（multiselect-shows.spec.mjs 追加 2 条 test）：种子页 Ctrl 点选同组 2 个种子（合成库 i 与 2k/2k+1 同 save_path，size 轮转 2/8/25/60 GiB ⇒ X≠Y 恒成立）→ 断言 .sel-summary 文本含「已选 2 个种子」与「实际占用」，且数值 = fmtSize(s₀+s₁) / fmtSize(max)；第二条走删除确认框同口径（data-aq-tip 双读提示）。期望值从 DOM data-hash 现推（不写死行序魔法数，300/3000 规模均成立——最高两下标恒为同组对）。落点纪律复用该 spec 既有 clickRow（对冲 sticky-head 拦截 flaky）。
  • 文档回写：conventions/webui.md 补 occ_key 载荷契约 + 选中摘要口径（X/Y/单元 max/跨组不去重）；测试文件头「## 测试计划」清单同步。
  • commands run test.full 实测 → kb.new baseline 誊写数字；kb.wrap 收尾；达立档阈值则 kb.new task。

§07风险与对策

风险触发条件处置
occ_key 载荷增长大库（数千归组种子）每轮全量/增量响应体变大只在归组行带一个既有键空间的字符串；组视图 members 本就内嵌回传（P-02），增量占比小。实测（2026-10-18，300 种子全归组合成库）：单行均长 55B，/api/state 增量 16.5KB = +1.7%，无异常，不入池
sizeMismatch 组 Y 与组行 size 列边角不一致组成员大小不一致且用户选中其中一部分两条口径分工写进文档：组行 = 展示代表值（后端现定），摘要 = 占用去重取 max（D9）。不追求一致——一致要么牺牲 Y≤X 要么改组行语义，都超出本轮范围
渲染到点击之间种子被删选中 hash momentarily 解析不到X/Y 同步少计（同 bulkDelete 摘要口径）；下一轮轮询交集过滤（polling.js L239-249）后自然收敛
大库下 computed 抖动每轮轮询都换 groups/torrents 行引用selectedCount=0 早退；memberByHash 本就每轮重建（存量成本），本功能只多一次「选中集大小」的 Map 构建；renderMs 埋点（polling.js L250-252）持续监控
三皮肤视觉漂移有人后续给指示器加样式零新 CSS 是本轮的防漂移设计；真要加样式必须三套同步（既有成对纪律 + test_webui_static_skins 族守阵）
e2e flaky（既有签名）宽行 + 2s 整表重渲染相撞时 scrollIntoViewIfNeeded 居中滚动顶掉落点复用 multiselect-shows.spec.mjs 既有 clickRow 落点纪律（滚回 0 + elementFromPoint 验落点 + 失败即报不等 30s），不新写点击路径
