站点引用规则拒绝重复 — rules_ref 判重

站点的规则引用列表（trackers.<站点>.rules）目前只校验格式与存在性，同一引用写两遍会静默通过。本计划先回答「重复引用有没有实际用途」——结论是没有：运行时按规则名去重，重复条目完全惰性，只可能是误操作。据此在配置校验层拒绝重复，并在 WebUI 下拉侧防呆，文案与文档同步。

§1

背景与动机

站点通过 rules 字段声明要执行的规则，填 @规则集（整组）或 @规则集.规则名（单条），既可从下拉选择也可直接粘贴。校验层只回答两件事：是不是 @ 开头、引用的目标存不存在——同一引用出现两次时无人过问。

重复条目进入运行时后被按名称去重，行为上毫无差异，只会在设置页留下两行一模一样的引用，让用户无从判断「写两遍是不是有特殊含义」。这不符合黄金法则 4（fail-fast：配置错误在 validate_config 聚合报错）——错误配置应当被拒绝，而不是带着惰性条目存活。

§3

重复引用的实际用途分析

结论

重复引用没有任何实际用途。运行时按规则名去重使重复条目完全惰性；引用语法无参数、无次数、无权重语义，重复不承载任何信息——它只可能是误操作，应当拒绝。

论据 1 · 执行幂等：写两遍不会跑两遍

_resolve_refs 以规则名为 seen 键去重（rules_mod.py:377-392），种子绑定的规则列表里每条规则至多出现一次。interval 规则按去重后列表逐条建种子级任务（rules_mod.py:425 附近），on_* 事件规则按同一列表过滤分派（rules_mod.py:327-329）——引用次数不进入任何执行路径。

论据 2 · 无次数/权重语义可被重复表达

引用是无参字符串；interval / execute_once / cooldown / stop_following_rules_if 等全部执行语义定义在规则 spec 侧（validation/rules.py:11-21 的 RULE_KNOWN_KEYS）。「引用两次 = 跑两遍 / 优先级更高」这类直觉在实现里不存在，也不存在任何按引用次数加权的机制。

论据 3 · 无顺序增益

@规则集 展开按规则声明序（enabled_rules 顺序）追加，重复条目不改变去重后列表的相对顺序；事件规则的执行顺序由互不相同的规则的先后决定，与重复无关。

重复从哪来（误操作来源）

  • 下拉重复选同一条：refPick 追加前不查重、ceRefOptions 不隐藏已引用项，连点两次即得两行相同引用；
  • 粘贴或把某行改成与另一行相同（自由文本行始终可编辑）。

边缘辨析：@A 与 @A.b 同填（本次不处理）

这是另一类冗余——集合包含重叠：绑定集合与只填 @A 完全相同。但二者是不同字符串，且「整组 + 点名一条」存在可读性意图；判包含重叠需要集合关系推导，复杂度与误报风险都不成比例。归入非目标（§7），本次不拒绝、不告警。

§4

方案（四波次）

W1 · 后端校验判重（核心）

在 _check_rule_refs（validation/rules.py:54）现有逐条循环之后加第二轮判重：

seen: dict = {}  # 归一形 -> 首现序号(判重); 仅 @ 开头的合法形参与
for i, ref in enumerate(refs):
    r = str(ref).strip()
    if not r.startswith("@") or not r[1:].strip():
        continue  # 畸形引用已在第一轮报格式错, 不叠加查重错
    if r in seen:
        errors.append(f"{where}[{i}]: 规则引用重复(与第 {seen[r]} 条相同): {r}")
    else:
        seen[r] = i
  • 归一键 = str(ref).strip()：与函数现有归一口径一致；"@A" 与 "@A "（尾随空白）判重；不折叠大小写（规则名大小写敏感）；序号 0 基，与 path_map 先例（sections.py:406）一致。
  • 报错示例：config.trackers.T1.rules[2]: 规则引用重复(与第 0 条相同): @example_rules。存在性错误照旧各报各的（聚合报错不互斥）。
  • 备选被否：按 r[1:].strip()（去 @ 后内剥离）归一——能把 "@ A" 判进重复，但那只在规则集名真的带前导空格时才有意义（病态），代价是报错里显示的不是用户原文。
  • loaders 不去重、writer 不改写用户数据——只拒收，不静默修正（见拍板点 B）。

W2 · 前端防呆（WEBUI 设置页）

  • ceRefOptions 的下拉选项按当前站点已引用值过滤（行级加 refOptions() 计算属性，模板 xtpl.html:102-105 改用之）——已引用的规则根本不出现在下拉里，误选入口消失；
  • refPick 追加前查重 no-op，作双保险（防过滤渲染前的连选竞态）；
  • 自由文本行保持可编辑（粘贴体验不动），由此产生的重复由 W1 在保存时报错兜底，toast 通道（cfgSave catch）零改动即展示；
  • 不做行内实时红框校验——要动 Vue 行级校验面，收益不成比例（见非目标）。

W3 · 文案与文档同步（4 处）

统一补一句「重复引用会被配置校验拒绝（同一引用写一次即可）」：

§6

风险与拍板点

  • 存量兼容：若现有 config.yml 已含重复引用，升级后启动/保存即报错——这是 fail-fast 的意图而非回归，修复动作明确（删多余行）。拍板点 A：直接报错（推荐）vs 先 WARN 一版观察。拍板结果（用户已确认）：直接报错，无 WARN 观察期。
  • 不做静默去重迁移：writer / 迁移链不改写用户数据（黄金法则 2 保守默认）。拍板点 B：确认只拒收、不修正。拍板结果（用户已确认）：只拒收、不修正。
  • 影响面：rules 在绑定三元组（domains/rules/groups）相等比较里（rules_mod.py:115-133），用户删掉重复行会触发一轮 L2 结构重建——一次性，无害。
  • 回滚：撤销 _check_rule_refs 判重分支与前端过滤即可，无状态、无格式变更。
§7

非目标

  • @A 与 @A.b 的包含重叠不拒绝、不告警（§3 边缘辨析）；
  • 不做设置页行内实时校验（保存时后端聚合报错已可见）；
  • 不做静默去重（迁移链 / writer 均不改写用户数据）；
  • 不动 loaders 的保序加载语义与 rules_ref 控件的粘贴交互。
