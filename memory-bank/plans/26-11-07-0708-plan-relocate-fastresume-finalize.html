WebUI 设置页接线收口: bt_backup 上页、描述换新与退役键移除

本篇只回答: 怎么收整组迁移 fastresume 收尾功能的 WebUI 设置页缺口 —— bt_backup 动态映射上页(嵌「整组迁移」组)、relocate 组 help 换新口径、退役键 finalize_timeout 移除, 并补 e2e settings spec 防复发。前一件计划 26-11-05-0808 的 WebUI 范围只有反馈面与「立即收尾」按钮(已接线), 设置页是它计划外的缝 —— 本篇是那道缝的收口, 不改 26-11-05-0808 本体。

§01目标与设计原则

为什么做: 用户在设置页无法配置 bt_backup(键被 hidden=True 藏掉, 只能手编 YAML), 且设置页迁移相关描述仍是旧链口径——收尾机制与再迁闸门两处与已实现行为相反。用户定性 blocker: 设置页是配置的主要入口, 入口缺失等于功能没交付完。

做到什么程度算成:

  • 设置页能完整配置 bt_backup(host:port → 路径 的增/删/改 + 保存回读), 组件落在「整组迁移」组语境里;
  • 设置页受影响文案与新实现口径一致, 不再有「重启后自动 setLocation 收尾 / 未收尾拒绝再迁」的旧话;
  • 退役键 finalize_timeout 从 schema 与设置页消失, 旧配置残留不炸加载;
  • e2e settings spec 落地 —— 设置页不再零浏览器级断言。

设计底线/不变量:

  • 法则 4 镜像面: 移除配置键同样要同步 validate_config + schema + 键面守阵, 不能只删一处;
  • help 文案 schema 单点(groups.py)透传到设置页(config_editor_tree.js:66)—— 只改单点, 不在前端复写文案;
  • hidden 机制坑(pitfalls/web-ui/config-field-unexpressable-in-ui.md)不被破坏: bt_backup 上页走专用组件, 不是把动态映射塞进通用编辑树(那正是它当初 hidden 的成因);
  • config.yml 红线不动 —— 接线完成后由用户自行在 UI 配置。

§02现状与痛点

键全链在, UI 是被主动藏掉的: config.bt_backup({"host:port": 路径}, 缺省空表 = 功能不启用)schema/models/loaders/validate 全链在(schema/groups.py:56-65 · models.py:616-618 · loaders.py:517,717 · validation/core.py:363 + sections.py:736-752)。但 groups.py:60 打了 hidden=True(注释: 动态映射「与 trackers 站点段同性质, 通用编辑树表达不了」)→ config_editor_tree.js:32-34 跳过 → webui/static/ 下 bt_backup 零命中、无 trackers 式专用卡, 只能手编 YAML(keys.md:29 明说)。生产 config.yml 也未配 —— 功能当前整体未启用。

旧描述两处, 一处与实现相反:

  • groups.py:435-437 relocate 组 help: 「qB 下次重启后自动 setLocation 收尾; 有未收尾迁移的组会被拒绝再迁」—— 收尾机制已换成 fastresume 双键改写 + 回收 daemon; 且 armed/rewritten 的组已放行再迁(keys.md:153)。两处口径均与实现相反;
  • groups.py:502-510 finalize_timeout: 已退役无消费者(models.py:537 注释 · keys.md:148), 仍按旧链文案渲染在设置页。

结构性空档: e2e 30+ spec 无任何 config/settings 专项 —— 设置页回归只靠 schema 静态守阵, 没有浏览器级断言。这是本次「代码全绿但入口没人看过」能发生的根因之一。

留痕(拍板 D6 不修不入池): 计划/任务档案引用的提交链(c84049d4..4f70190f)与仓库实际链(113d02c7..1c66a7b9)全体不一致, 疑似先记档后 rebase 改史所致。追溯时不能按档案哈希对账。

主线四件 + 防复发一件, 对应拍板 D1–D7(§06):
