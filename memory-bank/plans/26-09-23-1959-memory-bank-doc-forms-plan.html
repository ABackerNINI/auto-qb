病症 ① 同一专题被讲述 4~5 遍各遍独立演化

  • column-prefs（列设置被重置）：根级报告 1 + 计划 2 + issue 1 + 档案 1 = 5 份；
  • optimistic-ui（乐观 UI）：根级报告 2 + 计划 2 + issue 1 = 5 份。

四份文档各写一遍根因与取舍，没有任何机制保证它们一致：链接靠人手写，跨件关联靠 slug 眼力比对， 没有统一主键把「同一件事的材料」串起来。

病症 ② 两套状态、两套索引，而计划 / 报告零登记后果已显形

  • 状态词双轨：issues 用 Open / In Progress / Fixed / WontFix / Duplicate， 档案用 In Progress / Pending / Completed / Abandoned —— 同义不同词。
  • docs/plans/ 与 docs/ 根没有任何 meta（44 份计划只有 viewport 一行）， 机读不了类型、状态、专题；也没有 _index.md、没有守卫、没有闸门。
  • 后果 1：存量违规无人拦 —— docs/plans/26-09-15-1150-dependency-lock-report.md 违反「计划一律单文件 HTML」；
  • 后果 2：版本靠堆文件表达 —— webui-optimization-plan v1/v2/v3 三份并存， fix-plan-round9/round10 与档案 round9/10/11 并存， 没有「哪份被谁取代」的记录；
  • 后果 3：状态靠人记得改 —— 34 份档案里 18 份仍挂非终态（17 In Progress + 1 Pending）， 其中若干正文已写明「剩实机走查 / 未提交」。

病症 ③ 发现路径只有 ls + grep跨形态入口不存在

  • 根级 7 份报告中 3 份的全仓入链 ≤ 2 条；26-09-21-0408-seed-group-status-mapping.html 是 0 引用孤儿。
  • 想查「column-prefs 的全部材料」需要在四个目录各 grep 一遍 —— 没有跨形态的专题视图。
病因一句话：四个工位缺一套共同协议 —— 统一主键（专题）、统一类型、统一状态词、统一索引视图、统一生命周期规则。 目录分离本身不是病，登记方式各自演化才是。

03统一协议

P1 · 类型与命名4 个 token

唯一的分类维度是 4 个类型 token：issue | plan | report | task。 analysis / feasibility / audit / handover 一律归 report，不再自制词。

  • 新件：YY-MM-DD-HHMM-<type>-<topic>.html （memory-bank/plans|reports/），时间戳用命令取当前值；
  • 存量 51 份不改名：docs/plans 有 125 条唯一路径被全仓引用，改名的引用面远超收益 —— 类型由所在目录 + meta 判定，文件名 token 只是纯文本引用的可读性增强；
  • issues 现有 <stamp>-<type>-<slug>.html 与 tasks 现有 YY-MM-DD-<领域>-<专题>.md 已符合，不动。

P2 · 统一元数据 doc-*HTML 与 MD 同名字段

<meta name="doc-type"    content="issue | plan | report | task">   ← 唯一分类维度
<meta name="doc-topic"   content="memory-bank-doc-forms">        ← 跨形态串联主键（今天缺的就是它）
<meta name="doc-status"  content="Open | In Progress | Done | Dropped | Superseded">
<meta name="doc-added"   content="26-09-23-1959">
<meta name="doc-updated" content="26-09-24-1012">
<meta name="doc-refs"    content="同专题其它件的相对路径（逗号分隔）">   ← 认领链 / 取代链

任务档案用现有字段承载同一语义（Status / Added / Updated / Summary），新增一行 **Topics:** 作主键； issues 保留现有 issue-* meta，新增 doc-topic / doc-refs。

刻意不做无收益的字段改名：字段名不是漂移源，状态词才是。把 39 + 34 份存量的 issue-status / Status 全量改名为 doc-status 只增加迁移成本与守卫改动，不增加一致性 —— 生成器里一张字段映射表（单点）即可。

P3 · 统一状态词（5 词）四形态共用

Open  →  In Progress  →  Done   |   Dropped   |   Superseded
形态旧词新词语义
issueOpenOpen未修，待排期
issueIn ProgressIn Progress已被某计划认领
issueFixedDone已修并验证（写明验证方式与数字）
issueWontFixDropped决定不修（写明理由）
issueDuplicateSuperseded与既有件重复 / 被他件取代（写明指向）
taskPendingOpen已立档未开工
taskCompletedDone完成
taskAbandonedDropped放弃
plan—（今天无状态）Open / In Progress / Done / Superseded待拍板 / 实施中 / 全部落地 / 被新版取代
report—Done快照完成即终态，不再流转

存量一次性脚本改写状态行与 meta（39 issues + 34 档案），守卫正则同步改成单一词表。

P4 · 统一索引与专题视图一个生成器，两个视图

  • 各形态索引：memory-bank/plans/_index.md 与 memory-bank/reports/_index.md（生成物，按状态分区，行 = 类型 · 简述 · 链接，与 issues 同款）； issues / tasks 的索引已存在，不动。
  • 跨形态专题视图：memory-bank/_doc-map.md —— 按 doc-topic 聚合，一行一专题，列出该专题名下的 issue / 计划 / 报告 / 档案及各自状态。 这是「统一」的落点：用户与 AI 只从这一个入口即可看全一件事的全部材料。
  • 陈旧标记：生成器对 In Progress 且 doc-updated 超 30 天的件打 ⚠ 陈旧 （只标不改状态）。

P5 · 生命周期与单一权威正式消除职责重复

  • 每条事实只在一个工位有权威：修不修 → issue；怎么修 → plan（冻结）；实际怎么修 + 验证数字 → 档案 + progress/；现场快照 → report（冻结）。
  • 改名不建新文件：计划改版 = 同一文件内 ## 变更记录 段 + 抬 doc-updated + 状态流转；禁止再出 -v2 / -v3 / -roundN 新文件（存量保留，新规只对新件生效）。
  • 认领链双向可查：issue 被认领时在其 doc-refs 指向档案，档案 **Topics:** + doc-refs 指回 issue；生成器校验双向一致，缺链即闸门红 （今天这条链只存在于正文散文里）。存量豁免，只校验 doc-added ≥ 26-09-24 的新件。

决策树：要记一件事 → 放哪儿单点写入 conventions/doc-forms.md

scope 蔓延：顺手统一 TODO.md / 想法.md / AGENTS 结构 diff 里出现计划未列的文件 范围守恒（见 02 节「不做的事」）；只修正指向计划文件的路径串

07决策点

五个决策点，均给出默认取值 —— 拍板时未否决即按默认执行。

D1 · 默认：统一 5 词表

状态词是否一次性统一

统一为 Open / In Progress / Done / Dropped / Superseded，存量脚本改写（39 issues + 34 档案）。 备选是在索引层做映射、文件保留旧词 —— 省迁移，但会长期养一张翻译表，必然漂移。

D2 · 默认：存量不改名，新件带 type token

存量 51 份文件名是否对齐

不改名（125 条唯一路径的引用面）；新件命名 YY-MM-DD-HHMM-<type>-<topic>.html。

D3 · 默认：两个视图都做

索引形态

各目录 _index.md（沿用 issues/tasks 模式）+ 跨形态 _doc-map.md 专题视图。 只做前者等于没解决「看全一件事」。

D4 · 默认：机械修正路径串

25 份留档 HTML 的内链

只改 docs/plans/ 路径串，不改任何成文内容（与 2026-09-18 任务档案改名的处置同款： 只改路径，历史叙述保留）。

D5 · 默认：转 HTML 后并入 reports/

存量 md 违规件怎么处置

docs/plans/26-09-15-1150-dependency-lock-report.md（依赖锁定调研，report 类型） 转为单文件 dark HTML，落 reports/，顺手清掉库内唯一的「计划目录出现 .md」违规。
