1背景与目标

种子状态有两条回写通道：① qB 全量/增量同步（sync/maindata rid 增量，权威）；② auto-qb 自有停/起/暂停/恢复经 QbApi._sync_paused_state 直接把合成状态写进快照。后者是「照快照推一个值写进快照」——推错的每一分都会成为快照与 qB 真值之间的差。

报告 26-10-12-2148 取证了 6 类不一致风险面（R1 值域压平 / R2 完成位陈旧推断 / R3 隐式吸收无登记 / R4 异步应用竞态 / R5 全量形态零覆盖 / R6 静默部分应用），并在 26-10-12-2229 把「自有动作的状态变化被静默吸收」由「免误触发保护」改判为「信号压制」——暂停的磁盘风险与谁按下暂停键无关，自家停种同样必须被缺文件扫描与状态事件感知。

本计划要达到的

  • 值不再撒谎：快照中 state 只来自 qB 真值，R1/R2/R6 结构性消除。
  • 信号不再被吞：自有停/起按源无关语义触发分组转移检测与 on_torrent_state_enum_changed。
  • 同 tick 新鲜度保留：动作后同 tick 读到的 state 是新值（幂等门 / 冲突集合重算 / 视图脏）。

本计划明确不做的

  • 不引入任何 deferral（不改任务重排、不延迟消费方）——这条正是 B2 相对 A3 的全部取舍所在。
  • 不动 tags/category 的显式 self_caused_fields 机制，也不把它们的写后同步纳入本次真值通道（见 §3.1 的窄口径）。
  • 不改 torrents_recheck 等其它写操作的形态。

2方案定位

B 系的自由度在发射层而非值层：值层（真值回写）三支相同，发射层分三支，而只有 B2 解除信号压制。

形态发射层做法源无关发射结论
B1不处理——靠「真值 == 下轮上报」的巧合吸收抑制保留与 2229 已改判的立场冲突，淘汰
B2 = B′动作前基线登记 pending_self_state，下轮以基线作 prev 强制发射解除本计划采用
B3 = B + Cstate 的 self_caused_fields 同款期望值登记，匹配即吸收、失配告警抑制保留只买到可观测化，非本次目标
与 A3 的关系

B2 与 A3（删合成值 + 局部 deferral）是同一目标的两条路，差别在把哪一层设成构造性保证：A3 保住「快照严格 = 最近一次 sync 的应用结果」，B2 保住「同 tick 全决策新鲜」。本次拍板选 B2，代价是每个暂停轴动作 +1 次 torrents_info 调用、净增一条登记通道。反过来说：只要未来不把「快照严格 = sync 结果」定为架构不变量，B2 就不需要那条跨切面的 deferral 纪律。

3设计：值层与发射层

3.1 值层 —— _sync_paused_state 改写为 _sync_state_truth

四个 Facade 入口（qbapi.py:128-148）在调完 raw client 之后，改为调用新方法 _sync_state_truth(hashes)，语义是「把 qB 此刻的真值 state 带进快照」：

def _sync_state_truth(self, torrent_hashes) -> None:
    hashes = self._to_list(torrent_hashes)
    if not hashes:
        return                      # None / 空 = 全量形态: 跳过 + debug 日志(R5)
    # 1) 动作前基线捕获 + 登记(发射层用): 此刻快照仍是动作前的值
    for h in hashes:
        rec = self.store.by_hash.get(h)
        if rec is not None:
            self.store.register_self_state(h, rec.state_enum)   # setdefault: 保留最早基线
    # 2) 直查真值(fail-closed)
    try:
        info = self._client.torrents_info(torrent_hashes=hashes)
    except Exception as e:
        logger.warning(f"写后直查真值失败(下轮 sync 校准): {e}")
        return                      # 不写; 登记保留 -> 下轮 sync 的自然 delta 会发射
    # 3) 只回写 state 单字段(窄口径, 见下)
    for t in info:
        h = t.get("hash") if isinstance(t, dict) else getattr(t, "hash", None)
        rec = self.store.by_hash.get(h) if h else None
        if rec is None:
            continue                # qB 静默跳过不存在的 hash(R6): 不写, 无副作用
        if rec.apply_delta({"state": t.get("state")}):          # state 变更自动失效 _state_enum
            self.store.mark_truth_dirty(h)                      # 与 _apply 同口径: view_changed + dirty_groups
窄口径：只回写 state，不回写全字段 必做

torrents_info 返回的是整个种子对象（含 tags、category、name…）。若照报告原文「逐条 apply_delta(t)」全字段回写，会顺带把 tags/category 的变化也应用进快照——而这两个字段在 store 侧另有一套显式 self_caused_fields 登记机制（store.py:346-387）。两条路径同字段双轨，会出现「同一变化经 info 回写不触发、经 sync 触发」的竞态，且可能与登记机制互相消费。

本计划采用窄口径：只把 state 一个字段写回。完成位（is_complete）由 state 后缀派生，写对 state 即修好 R2，无需回写 progress/amount_left。「是否放宽到全字段」列为非目标（§10），要放宽须单独立件并先解决与 self_caused_fields 的双轨口径。

store.mark_truth_dirty(h) 是新增的 store 方法，目的是把「变化字段 → 视图脏 / 组脏」的口径收成单点（对齐 store.py:237-244 的既有判据）：命中 _VIEW_FIELD_SET 置 view_changed，命中 _CONFLICT_FIELDS（store.py:191）登记 dirty_groups。这样真值通道与 sync 通道共用同一判据，避免两处各自演化。

3.2 发射层 —— pending_self_state 显式通道

问题在于：真值回写让快照当场就是新值，轮末 update_state_snapshot（store.py:301-307）又把新值固化为下轮基线；于是下一轮 qB 上报同值时 apply_delta 检不出 delta，store.state_changed 为空，两个消费点（grouping_mod.py:201、rules_mod.py:332）根本不会看到这个 hash——「新鲜度」与「发射」共用同一机制，这正是报告 §4.2 点名的机制张力。B2 的解法是把发射从「靠 prev/cur 差异」改为显式登记驱动。

容器与生命周期

  • store.pending_self_state: Dict[str, TorrentState]（hash → 动作前 state_enum）。纯内存、不落盘（与 state_snapshot 同级）。
  • store.register_self_state(h, before_enum)：setdefault 语义——同一 hash 在本轮被多次自写时保留最早基线，否则中间那次转移会丢。
  • 清理三处单点：① 发射并消费后移除；② 种子被删除时移除（镜像 store.py:269 对 self_caused_fields 的清理）；③ reset_runtime（store.py:459-478）随 state_snapshot 一并清空。

发射相位接线

在 _refresh_torrents 相位表起点（transitions 广播之前，qbmanager.py:815 附近）取一份本轮只读快照，随相位 payload 下发给两个消费点：

self_state = self.store.pending_self_state.copy()      # 只读视图, 不清容器
self.events.emit("transitions", {"dry_run": dry_run, "self_state": self_state})
# events_removed 相位 payload 同挂 self_state -> rules_mod._on_events_removed 转发给 _dispatch_events

两个消费点把「本轮待观测集合」由 store.state_changed 扩为 state_changed ∪ self_state，并把 prev 的取值改为「登记命中则用基线，否则用 state_snapshot」：

  • grouping_mod._handle_state_transitions（grouping_mod.py:180-212）：循环集合扩为并集；prev = self_state.get(h) or state_snapshot.get(h)；既有判据 (cur.is_complete and cur.is_stopped and prev.is_uploading) or (cur.is_errored and not prev.is_errored)（:205-207）原样保留。
  • rules_mod._dispatch_events（rules_mod.py:330-338）：把 :333 的 if h not in prev or prev[h] == cur: continue 改为按登记命中取 prev，其余不变。
  • 消费：命中并实际发射（cur != prev）后记入本轮的已消费集合；轮末（post 相位之后、update_state_snapshot 之前，qbmanager.py:879-883）把这些 hash 从 pending_self_state 移除。未发射成功的登记保留到下一轮（at-least-once，允许失败轮重复发射一次）。
两条必须写进代码注释的纪律 必做

① 不许污染 store.state_changed。那个集合的语义是「本轮 qB 上报的 state 变化」，把自写 hash 塞进去会破坏它作为权威通道产物的含义（也让 delta_fields/事件口径漂移）。发射必须走独立的登记集合。

② 登记只改 prev，不改基线。不要用「把 state_snapshot[h] 改成动作前值」来制造 delta——那会污染真值基线，等真值下轮落地时又被判成「外部变化」，造成双重触发。基线永远记真值，发射只借登记里的动作前值当 prev。

一条可直接采用的落地捷径

若不想给两个消费点都改签名，可在相位表起点把登记 hash 的 prev 写进一份独立的只读视图（上面 self_state 的做法即此），消费点只多读一个 payload 键。不建议直接改 store.state_snapshot：它在失败轮不重建（update_state_snapshot 在 :883，失败轮走不到），覆写会残留到下一轮。

4时序与相位约束

主循环一拍的结构是 command line →（P0-5 条件强制）sync 线 → task 线；apply_sync 只在 _sync_line 开头跑一次（qbmanager.py:700-709），transitions 相位排在任何自有动作之前（qbmanager.py:810-815 的注释明写了这个刻意安排）。这两条事实决定了登记被消费的时机：

自写来源位置登记何时被发射
WEB 暂停/开始/批量（最高频）command line，sync 线之前同一 tick：命令线先登记，随后 sync 线的 transitions/events 相位即可消费（P0-5 已把真值补进快照，qbmanager.py:525-528）
分组停种（grouping_mod.py:248/388/461/591）、事件规则动作sync 线中段（torrents_added/post/events 相位）下一 tick：登记发生在发射相位之后，只能等下一轮的 transitions/events
interval 规则动作、ops auto_start（ops_mod.py:274/471）task 线（run_due 批次内）下一次 sync 线：task 线不跑 _refresh_torrents，登记等到下一轮 sync 线的发射相位

结论：验收口径必须按来源分开写。WEB 路径的「同 tick」与分组/任务线路径的「下一轮」不是一件事，混在一起写会得到一条永远测不准的守阵。

6失败路径与边界

情形预期行为
qB 对不存在的 hash 静默跳过（R6）torrents_info 返回里没有该 hash ⇒ 不写、不报错、无副作用。快照保持旧值，下轮 sync 校准。
写后直查抛异常fail-closed：只 warning，不写真值；快照保持旧值，登记保留 ⇒ 下轮 sync 的自然 delta 会带来发射，不会因 fail-closed 而漏发射。
R4 异步窗口：resume 后 qB 尚未翻状态info 读到的仍是旧值 ⇒ 快照不变、登记保留；下一轮 qB 真翻时 apply_delta 产生真实 delta，两个消费点用登记基线发射一次。登记在cur == 基线时被丢弃，不会无限残留。
全量形态 torrent_hashes=None（R5）_to_list(None) == [] ⇒ 跳过 + debug 日志。与现状一致（零覆盖不扩大），但不静默。
失败轮（_refresh_torrents 中途抛异常）轮末消费不执行 ⇒ 登记保留到下一轮，允许重复发射一次（at-least-once）。这是刻意选择：宁可偶发重发，不可静默丢发。
同一 hash 一轮内被多次自写setdefault 保留最早基线，发射一次报告净转移。
热重载（reset_runtime）pending_self_state 随 state_snapshot 清空，不跨重载残留。

E2发射：分组停种 → 下一轮触发；且不重复触发（登记消费后）不消费登记即重复触发即红
E3无人可发：cur == 基线（动作未改变状态）⇒ 不发射 + 登记被丢弃不丢弃即残留即红
E4R4 异步：替身首轮返回旧值、次轮返回新值 ⇒ 登记跨轮存活、次轮发射一次且不重复把 prev 改用 state_snapshot（不覆盖）即发射丢失即红
S1静态：全库无合成 state 落点（qbapi.py/store.py 无 state= 写点）残留一处即红
S2静态：pending_self_state 不落盘（state.json 无该键）写入落盘即红
C1一致性：qB 自身 WebUI 暂停与 auto-qb WebUI 暂停行为一致（都触发扫描）两条路径结果不一致即红

7.4 已知行为变化（必须写进守阵，不许含糊过去）

同 tick 幂等由「构造性」降为「真值节拍」

报告 §5 对 B 行的「同 tick 新鲜度全保留（幂等/视图脏/组脏）」在 resume 这条路径上过于乐观。今天的合成回写在 client 调用返回后立即写入 stalledUP/stalledDL，所以同 tick 的守卫（basic.py:113/126）必然读到「已开始」而 skip。B2 写入的是真值，而 qbmanager.py:536-538 的注释已明说「resume 后 qB 要过一会儿才翻状态」——异步窗口内 torrents_info 读到的仍是旧值，同 tick 第二次 resume/start 可能重发请求。

这不是缺陷回退到「不可用」，而是把「构造性幂等」换成「真值节拍幂等」：qB 的 start/resume 本身幂等，重发无害，代价只是重复 HTTP 与日志噪声。本计划要求把这条写成显式守阵（记录当前行为），而不是假装幂等无损。若用户不接受该退化，见 §10 的可选加固 S4。

9验收要点

  1. 全库无合成 state 值（S1 静态守阵：qbapi.py/store.py 无 state= 落点）。
  2. 自有停/起在下一轮（WEB 路径同 tick）被转移检测与状态事件看到，且不重复触发。
  3. qB WebUI 暂停与 auto-qb WebUI 暂停行为一致（都触发缺文件扫描）。
  4. WEB 暂停后 ≤1 tick 前端翻态（P0-5 路径同 tick 落地真值）。
  5. fail-closed 生效：写后直查失败不写真值、不破坏发射语义。
  6. 同 tick 幂等按 §7.4 显式记录（真值节拍），若采纳 S4 则回到构造性。
  7. 全量测试基线数字入 testing/baselines/ 新切片（口径见 testing/baseline.md，正文只引用 kb.baseline，不手抄）。

10风险、非目标与回退

风险

  • 热路径 +1 次 API：每个暂停轴动作多一次 torrents_info（单 hash 与批量均为 1 次）。这类动作是低频事件（规则触发 / 用户点击），但大库上批量暂停整组时 hash 列表可能很长——须在 S1 实测一次调用耗时与负载，写进 task 档案。
  • 登记通道与 self_caused_fields 双轨：两者容器同层、语义相反（一个吸收一个发射）。实现时不得共用容器或互相消费；B3 若后续要走，须先合并设计。
  • 发射相位接线动到 _refresh_torrents 相位表：这是主循环核心，改动需谨慎——只加 payload 键与轮末消费，不改相位顺序。
  • 5s/轮询类 UI 表象：本改动不触前端；但「自家停种现在会触发扫描」可能带来新的日志行与一次额外磁盘 stat，属预期收益，须在坑档写明避免被误当回归。

非目标

  • 不把 info 回写放宽到全字段（§3.1）。
  • 不引入 deferral、不做任务重排、不建跨切面不变量。
  • 不改变 tags/category 的写后同步与其登记机制。
  • 不把「快照严格 = sync 应用结果」立为架构不变量（那是 A 系的形态）。

回退

S1 与 S2 各自独立可 revert：只回 S2 ⇒ 行为回落 B1；S1+S2 同回 ⇒ 恢复今天的合成回写。不需要数据迁移（state 快照与两套登记均为内存态，state.json 无相关键），回退不涉及状态兼容。
