§01目标与设计原则

背景

配置散在四处，没有任何「整份备份 / 一键迁移」通道：

  • 主配置 config.yml（仓库根）：WebUI 可整树读写（掩码哨兵 + write_tree），但没有整份原文下载/上传端点——备份恢复只能手动拿 auto-qb-data/config.yml.bak；
  • WEBUI 服务端设置 = 快捷键 auto-qb-data/webui-keys.json（GET/PUT /api/keys）——无导出通道；
  • WEBUI 浏览器偏好 = localStorage 15+ 键（主题/列布局/抽屉/时间格式/流量图窗口…）——用户既定裁决「只存浏览器，不上服务端」（app.js:376 注释），零迁移通道；
  • gtm 工具配置（tools/global-traffic-monitor）主权在工具自己的数据目录——主程序侧零备份面。

跨机迁移 / 换 clone / 劫后恢复，今天只能逐项手填。做到什么程度算成：一次导出 = 一个文件；一次导入 = 勾选 section → 确认 → 应用 → 报告；掩码敏感值永不落 bundle 明文；运行时状态永不迁移。

设计不变量

  1. 掩码不出机（D2）：导出端点是纯掩码面——不新增「秘密读取原语」。web.skip_local_verify=true 时 loopback 免鉴权（auth.py:167-171），明文端点 = 本机任意进程可静默读走 qB 凭据。
  2. 浏览器偏好不服务端化：收集/写回全在前端；bundle 文件经手但不落服务端存储（与「只存浏览器」裁决精神一致，D3）。
  3. 不碰工具数据区：主程序对 gtm 只经 HTTP 契约通信（tool_client.py:16、traffic_monitor.py:14-17 明文架构约束）——gtm 段在线读 / 在线写，离线跳过（D9）。
  4. config.yml 导入保注释：全程 ruamel round-trip（掩码化导出与导入落盘都不丢注释/格式）；每次导入前 .bak。
  5. 运行时状态不进 bundle（D5）：导出 = 「配置」而非「整机快照」——state.json 的 exec_history 去重、skip_check_backup 账本与本地 .torrent 强绑定、流量历史是缓存，导入他机必破坏不变量。
  6. fail-fast 聚合报错（黄金法则 4）：config/keys 校验失败整体拒绝、不半应用；gtm 是唯一「可跳过」面（工具在线才可写，D9）。

敏感字段面（决定 D2）

  • 掩码判定单点：SENSITIVE_KEY_PARTS = ("password","passkey","token","secret","cookie","authkey","api_key")（writer.py:64-65）+ transfer targets 条目 password/api_key（loaders.py:163-164、writer.py:70-75）。
  • gtm 配置树无敏感字段（webhook 订阅者在 gtm 的 state.json、控制面密钥在 monitor.token——都不属「配置」面），导出无需掩码。
  • web.token/hr.token 留空 = 自动生成落 <data_dir>，跨机不用带。

导出/导入既有先例（决定技术形态）

  • 下载先例：.torrent 导出 = 内存字节 Response + Content-Disposition（torrent_detail.py:235-246）+ 前端 Blob <a download>（commands_send.js:375）——无 FileResponse 先例。
  • 导入先例：hubImportSites（config_hub_tracker.js:229-293）= 只读扫描 → confirmDialog → 写配置树待审；全仓无 UploadFile/multipart 先例 → bundle 导入走 POST JSON（前端 FileReader 读文本，天然不需要 multipart）。
  • 前端收集偏好不经服务端的实现位：导出时客户端把 ui_prefs 段并进已下载的服务端 bundle 再落盘；导入时客户端先摘走该段本地写回，只把服务端三段 POST 上去。

痛点

备份 = 手动复制 .bak（还得赶在下次保存覆盖前）；跨机迁移 = 全部配置逐项手填；快捷键自定义与浏览器偏好完全无法带走。golden 面测试基线 6086+ 的项目里，配置是唯一没有版本化出入口的用户资产。

§03方案总览

bundle 形态（D1）

{
  "format": "auto-qb-config-bundle",
  "bundle_version": 1,
  "created_at": "2026-11-14T12:34:56+08:00",
  "app_version": "<导出时 auto_qb 版本>",
  "config_yaml": "<掩码化 YAML 原文, 注释保留>",
  "webui_keys": { "schema_version": 1, "template": "...", "overrides": { ... } },
  "gtm": { "config": { ...13 键合并树含 v2 键... }, "tool_version": "...", "captured_at": "..." },
  "ui_prefs": { "autoqb.ui.theme": "...", "autoqb_cols_v5": { ... }, "...": "..." }
}
  • gtm 离线导出时该段为 null；缺段 = 不含该面；导入对未知 section（顶层）忽略 + warnings（向前兼容）；section 信封内未知键忽略不报错——gtm.config 例外：未知键由工具侧校验整份拒绝（gtm/config.py:250,260-261）→ 400 → warnings → 该段不应用（见 R3）。
  • 文件名 auto-qb-backup-<YYYYMMDD-HHMMSS>.json。

  • 新 router server/routes/backup.py：GET /api/backup/export + POST /api/backup/import（direct 端点、非 cmd 透传）；登记 ROUTE_BUILDERS（routes/__init__.py:8-23）+ 金清单 _GOLDEN_ROUTES（test_web_route_manifest.py:20-114）。
  • 前端新文件 static/shared/ui_prefs.js：PREF_KEYS / PREF_EXCLUDED 双清单单点 + collect()/apply()（window.AQB_* mixin 惯例，manifest scripts 排 app.js 前）。
  • 按钮：设置页 actbar .hb-actbar .ab-r「放弃改动」左（settings-detail.html:515-522，常显不随脏态隐藏）——shared 模板四皮肤自动 parity，无 ui-diff 分支。
  • 登记闸（D8/D11）：新守阵 tests/test_webui_static_ui_prefs.py —— 扫 static/ 全部 JS 里 localStorage/sessionStorage 键族字面量（前缀 autoqb./autoqb_/gtm. 两族形态都收，防下划线键逃出登记闸；扫描面限存储键字面量及其 const 单键定义——document.cookie 赋值（autoqb_ui，下文已拍板不入本期）与事件名（autoqb:* 冒号族）不在闸内），每个键必须 ∈ PREF_KEYS ∪ PREF_EXCLUDED 否则红；双清单与 ui_prefs.js 源码交叉验证（两侧一致性守阵先例：keys 串正则两侧守阵）；负例自钉。
  • 脏态交互（D12）：导出恒读磁盘，cfgDirty 时提示「导出的是已保存配置，未保存改动不含在内」不阻断；导入时 cfgDirty 先弹「未保存改动将丢失」，确认后先 cfgDiscard() 再走三闸。

导入交互流（三闸，D6）

  1. 选文件 → JSON shape 检查（format 字段不符直接报错）；
  2. confirmDialog：分 section 勾选（bundle 含该段才可勾，缺段灰显）+ 摘要行（bundle 版本 / 创建时间 / 来源 app 版本 / config schema 版本 / gtm 工具版本）+ 固定提示行「bundle 含机器相关路径（gtm tool_dir/tool_exe、qB 保存路径、transfer targets 路径等），导入后请核对」（D10）+ cfgDirty 警告；
  3. POST /api/backup/import（只带勾选段；ui_prefs 留在本地不经服务端）→ 应用；
  4. 结果 dialog：applied / skipped / warnings 报告 → 确认后 location.reload()（keys / 配置热重载 / 偏好一次到位）。

§07风险与对策

#风险触发条件处置
R1掩码不可 resolve（bundle 有条目、本机无对应键）跨机导入且本机无同键条目（如 bundle 含第 3 个 transfer target）聚合 422 逐路径列出，用户编辑 bundle 或先建条目；绝不把 "********" 字面量写盘（fail-fast 黄金法则）
R2bundle 来自更新版本config schema_version / bundle_version 高于本机拒绝并提示先升级本机；旧版本靠启动迁移链 materialize_schema_migration 兜底（qbmanager.py:509）
R3gtm 工具侧拒绝键集导出/导入两端 gtm 版本不同（未知键被工具拒，gtm/config.py:260-261）工具 400 原样透传进报告 warnings；不阻断 config/keys 应用；http_host/http_port 改动需重启工具的既有口径进提示
R4机器路径迁移后静默失效tool_dir/tool_exe/dat_path/qB 保存路径指向旧机confirm 摘要固定提示行（D10）；traffic source 降级为 not_installed 五态，不崩（agent.py:613-619）
R5偏好键格式漂移将来 cols_v5→v6 等键格式变更双清单登记闸强制显式登记；apply 只覆盖 bundle 内出现的键，缺键保持本机值
R6导入覆盖未保存编辑cfgDirty 时点导入脏态确认前置（D12）+ 导入后 reload
R7ruamel round-trip 破坏注释/格式掩码化导出或导入落盘S1 测试钉「掩码前后 diff 仅敏感值行」byte 级一致；非敏感行原样
R8导入与 PUT /api/config 竞写并发请求复用 _WRITE_LOCK 同一单点（writer.py:51-56）；单写线程黄金法则不破
