01方案C 合规化裁决（与报告推荐 A 的偏离记录）

报告 §07 推荐方案 A 的第 3 条理由是「C 买错了先例……违背『状态持久化统一进 state_file』的黄金法则 3」。用户拍板 C，本节把这条张力收掉，并逐条给报告点名的 C 三项负担以机制。此节是拍板 C 的合规化论证，实施与评审以此为口径。

1.1 定性：流量历史是观测数据，不是程序状态

黄金法则 3 所指的「跨轮次状态」是参与程序逻辑与恢复的状态：任务队列结构、去重窗口（record_execution）、跳检备份、字段基线。qB 流量历史是纯展示的观测数据：

  • append-only：只追加、不参与任何决策，规则引擎不读它（报告 §2.4 非目标已锁死）；
  • 丢失无一致性后果：停机/崩溃丢一段曲线，只是图上多一处断线（§05 的 null 语义恰好如实表达），不像 state 丢窗口会破坏幂等或去重语义；
  • 体量本质是日志型：随窗口线性增长、按龄淘汰——与 logs/ 同类，与 state.json「小而关键、整体原子替换」的访问模式相反。

故归类为观测/日志数据，落 data_dir 子目录，不入 state_file。state.json 保持程序状态单点（黄金法则 3 不破），同时免掉方案 A 的隐藏代价：100 组 ≈3–4MB 观测数据进 state.json 后，每次 maybe_flush（默认 120s）都是全文件原子重写。

1.2 报告点名的 C 三项负担 → 本计划的机制

报告点名的负担（§06/§07）本计划的机制
文件数随种子数线性增长三轮拍板后文件总数 = 1 (global) + 有过流量的种子数（组不落盘，组数项消失）；爆炸源头（种子数）由三闸收敛：惰性建文件（首次活跃采样才建，从未传输的种子零文件）+ 空闲零行（活跃过滤不变，§03.2）+ 删种冻结淘汰（§02.5）；单文件 ≤205KB 封顶（§02.3）
追加写崩溃产生半行需容错读侧坏行/半行跳过（对齐 TM 解析先例 curves.py:48-73 的坏行纪律）；重写走 temp + os.replace 原子替换；损坏超阈值移 .corrupt 重建，不静默吞（§02.4）

1.3 C 相对 A 的实质收益（写进档案备查）

  • state.json 零改动：无 v4 迁移、无版本链风险；差分基线不落盘、重启重置（§03.4），首窗 null 与停机空洞语义天然一致。
  • 24h 高分辨率段跨重启存活（两类落盘系列）：C 的 raw 段落盘即持久（报告方案对比表中 C「重启存活：全存活」的兑现），A 的 24h 内存环重启即丢；读侧统一从 dat 文件取数，内存结构退化为差分基线（三轮拍板后连组身份映射也没有，§03.3）——二轮拍板后单种同样采样即落盘，「重启清零」的 UI 告示整体取消。
  • 写放大更小、崩溃丢失更小：平时每采样间隔追加一行 ≈50B；A 每次 flush 全量重写 3–4MB。崩溃丢窗口：C ≤ 1 个采样行，A ≤ state_save_interval（120s）。

1.4 对报告 §9.1 的设计修正（三轮拍板后收敛为读侧口径）

  • 子目录名 qb-traffic：kebab-case 对齐既有兄弟目录（skip-check-backup/hr）；qb- 前缀与 TM 口径的流量数据在目录层划界（报告 §2.2）。硬编码常量（对齐既有子目录先例，全部非配置键），建目录走 os.makedirs(..., exist_ok=True)。子目录名不做配置键——用户拍板只要求「合适的子目录」，少一个旋钮；真有需求后续加键是纯加法。
  • 创建时机：enabled 且首次采样时惰性创建（enabled=false 的安装不产生任何文件/目录，P3 验收项）。

2.2 落盘范围：全局 + 单种两类落盘（三轮拍板收窄；单种入盘沿用二轮拍板）

全局与单种两类系列落 dat 文件，分组系列不落盘（三轮拍板）：组流量 = 组内成员单种流量的可加和，成员通常 ≤50，读侧聚合成本可接受，不值得为它维护一套文件与身份机制；全局含全部种子，读侧推算（遍历全库求和）难度大且 server_state 本就直供，依旧落盘。二轮拍板的「单种历史入盘」沿用——它恰好是组推算的数据基座：组曲线 = Σ 成员单种曲线，成员文件缺失（从未传输）按 0 计（§04）。单种落盘的关键优势：infohash 本身就是永久稳定身份——移动目录、增删文件、删后重加都不变，直接以 <infohash>.dat 命名，无需任何身份层。

  • 生命周期：首次活跃采样时惰性建文件（从未产生流量的种子零文件零开销）→ 删种 → 文件冻结（停止追加）→ 同 hash 重加 → 解冻续写（历史保留，计数器回落由 §03.4 判重置兜底）→ 冻结超 rollup_window 淘汰（§02.5）。
  • 体量：空闲种子零采样行（活跃过滤 §03.2 不变），文件只含活跃时段；单文件上限同 §02.3（205KB，对应连续活跃满窗的上界）。文件数 = 有过流量的种子数 ≪ 库内种子总数；典型辅种库并发活跃几十~几百 → 增量 10–100MB 上界量级，实际远小。
  • 写读路径：全局与单种共用同一套 writer/reader/封口/裁剪/容错（§02.3–02.5）；组聚合复用单种 reader（§04），无第三套代码路径。

2.3 文件格式 v1

# auto-qb qb-traffic v1                          ← 头行：格式标识 + 版本

                                                    组无文件（三轮拍板，§04）——指纹只是查询定位符，不入存储层

字段口径说明

raw.dl_total / up_total累计快照，bytesPrometheus 口径：存快照、消费侧差分；速率与累计双轨互证（报告 §4.4）

行格式刻意与 TM 的 history_traffic.dat（YYYY/M/D ul/dl，curves.py:48-73）同构不同义：同为行式文本、坏行跳过的容错纪律对齐，但 TM 是外部只读文件、我们是自有写路径——「半行容错是我们自己的义务」（报告 §06 的告诫，§02.4 兑现）。单文件稳定上限：raw 24h@30s = 2,880 行 ≈150KB + hour 30d = 720 行 ≈55KB ≈ 205KB/文件；200 活跃种子 + global ≈ 41MB 总量上界（全部满窗连续活跃的保守假设；空闲种子零行，实际远小），分摊在 201 个独立小文件里；组曲线读侧聚合现算，不占文件。

2.4 写路径与读路径

写（仅主循环线程，黄金法则 5）

  • 平时：每次采样 open("a") 追加一行 raw + flush——崩溃丢 ≤1 行；不做常驻句柄（每小时 rewrite 需要换文件）。
  • 小时封口（每小时首个采样触发一次）：读全文件 → 追加 hour 行 → 按窗裁剪（raw 段留 raw_window、hour 段留 rollup_window）→ 写 *.tmp → os.replace 原子替换（对齐 utils.atomic_write 的 tmp+replace 纪律）。单文件 ≈205KB，每系列每小时一次，成本可忽略。
  • rewrite 崩溃窗口：os.replace 前崩溃 → 旧文件完好，丢本小时已追加的 raw 行（≤1h 数据，null 语义如实呈现）；os.replace 后崩溃 → 新文件完好。无中间态。

读（Web 线程 API，只读）

  • 半行/坏行容错：不匹配格式或字段非法的行跳过并计数（纪律对齐 curves.py:60-71）；仅尾部半行是正常崩溃残留。
  • 损坏阈值：坏行占比 > 5% 判文件损坏 → 原文移 <name>.corrupt 后按空文件重建（不静默吞数据，也不让一个坏文件常驻报错）。
  • Windows 替换竞态：reader 打开期间 os.replace 目标会失败——rewrite 侧遇 PermissionError 退避重试 ×3（每次 50ms）；读侧文件 ≤205KB 一次性快读即关，窗口极小。

2.5 index.json 与清理/淘汰

index.json：
  { "format": 1,
    "torrents": {
      "8f14e45f…":   { "frozen_at": null,          # 非 null = 种子已删，冻结不再追加（重加即解冻）
                       "created_at": 1727…, "updated_at": 1727… } } }
  • 启动对账（reconcile）：扫描 qb-traffic/ 目录与 index 求差——孤儿 dat（index 无条目）从头行 key, 重建条目；失配以头行为准自愈；index 条目无文件则删条目。对账只读目录与头行，永不动 raw/hour 数据。
  • 冻结与淘汰：种子删除 → 文件冻结（停止追加）；同 hash 重加 → 解冻续写。采样任务每小时顺带（复用封口时机，无独立任务）检查 frozen 文件，now - updated_at > rollup_window 即删除文件 + index 条目。组无文件，无冻结/淘汰概念——组曲线随成员集现算（§04）。
  • index.json 写入：utils.atomic_write（tmp + replace），仅条目变化时写（封口 / 冻结 / 解冻 / 淘汰时点），非每采样。

    组身份映射 fp_to_surrogate / last_hash_surrogate 随三轮拍板拆除——组不采样不落盘，§04）

3.4 差分与基线重置规则（沿报告 §9.2，落盘部分按 C 改）

  • 速率字段直采不差分；累计差分在消费侧（API 栅格离散时）进行：delta = max(0, cur - last)；cur < last（qB 重启会话归零 / alltime 回退 / 删种重加）⇒ 判计数器重置：该桶记 null，基线更新为 cur。
  • 基线不落盘：程序重启 → 基线为空 → 重启后首个采样只立基线不出增量（首窗 null）。这是方案 C 免掉 state v4 的关键取舍，代价 = 每次重启损失 1 个采样窗的累计增量（速率曲线不受影响——瞬时值对重启免疫），与「停机 = 断线」的拍板语义一致。
  • 种子身份天然稳定（三轮拍板后无身份层）：单种系列挂 infohash——移动目录/增删文件不触碰它，无需任何吸收机制；种子删除 → 文件冻结，同 hash 重加 → 解冻续写，all-time 归零由回落判重置兜底。组无身份问题——组曲线按查询时刻成员聚合（§04），指纹变化只换查询键，不换数据。

3.5 断连与空值防御

  • qB 断连退避期间（qbmanager.py:549-559）采样任务照常出队：server_state 为 stale → 该轮出 null 点（写 raw,t,,,, 空值行，读侧还原为 null）——不沿用旧值画假曲线，也不断档（恢复后曲线连续、断连段为洞）。
  • 增量轮字段缺失防御（报告 §11.2-④）：采样读 server_state 关键字段缺失/空值 → 该轮按 null 处理并 DEBUG 记录，不写 0。

04分组读侧推算设计（三轮拍板 · 组不落盘，成员单种 dat 聚合）

三轮拍板：组流量可以由组内种子流量推算（成员通常 ≤50，聚合成本可接受），不值得为它落盘；全局含全部种子、推算难度大，依旧落盘。这使二轮拍板的「组 key 稳定化」失去对象——组系列不落盘，就没有可断的键：指纹（(path_normalize(save_path), 排序文件名元组)，grouping_mod.py:41-49）只是查询时刻的定位符，移动目录/增删文件换键后，新键照样聚合同一批成员的单种历史，曲线天然连续。二轮引入的代理身份键 + 成员表决吸收（fp_to_surrogate/last_hash_surrogate/index members 快照/启动表决）整体作废；数据基座 = 二轮拍板的单种入盘：组曲线 = Σ 成员单种曲线。

4.1 聚合算法（API 层现算，§08 分组端点）

  1. 成员集：查询时刻 store.groups[当前指纹键]（key → [hash…]，store.py:87-89）——与分组视图/弹层同源同刻，不新造组概念（范围守恒）。
  2. 速率：各成员单种序列按 §05.1 栅格离散到桶 → 桶内 Σ 成员均值；桶内无行成员按 0 计。
  3. 累计增量：逐成员先差分（max(0,·) + 回落判重置，§03.4 同款）再求和——先逐成员差分再相加，避免单成员计数器重置把全组差分打成大负数；成员某桶增量缺失（无行/重置/窗首基线缺失）按 0 计，组口径宁可少计一桶不出洞。
  4. 桶 null 判定（借全局系列当真值源）：桶在全局系列为 null（程序停机/qB 断连——global 恒采 + 断连写空值行，§03.5）→ null；桶早于组内全部成员文件的最早行（组尚无任何观测）→ null；其余桶即使全员空闲也出 0——组图空闲段是 0 线、停机段是断线，二者靠 global.dat 区分，这是单种图做不到的（单种空闲与停机同为无行）。

4.2 语义边界（刻意声明）

  • 组历史 = 查询时刻成员集的全程聚合：新成员的历史一并计入（回溯可见），成员移除后其历史从组曲线消失。不维护成员随时间的快照——那正是被拆除的身份层；该口径与分组弹层瞬时值完全同源（弹层本来就是当前成员 sum），列表与图永不打架。
  • 指纹变化（移动/增删文件）：store.groups 的键变、成员不变 → 图跟着新键走、数据同一批，曲线连续——二轮拍板点名的两个「毁灭性」场景（含 save_path 断史 / 增删文件换键）在此口径下无伤，两约束自动满足。
  • 合并/拆分：成员集怎么变，曲线就怎么聚合——读侧聚合与列表视图共用同一成员集，初版担忧的「图合并、列表拆分」分歧不复存在。

4.3 请求成本

  • 每请求 ≤50 成员文件 × ≤205KB（24h 窗只消费 raw 段、30d 窗只消费 hour 段）；空闲成员零行、从未传输成员无文件，典型远小于上界。
  • 弹层打开期间按采样间隔低频续拉（§07），非后台常驻；不做聚合缓存——真机压力实证后再议（P4 钉 50 成员聚合正确性与耗时单测）。

拍板落实状态：三轮拍板两条（组不落盘读侧推算 / 全局保留落盘）由本节落实；二轮拍板的两条组 key 约束（不得含 save_path / 不得因增删文件换键）在读侧口径下自动满足——数据挂 infohash 与 global，键只当查询定位符，无键可断；代理键 + 表决吸收机制及相关单测面全部移出计划。

05时间栅格与 null 断线语义（拍板④落定）

5.1 栅格离散（读侧统一口径）

  • raw 行时间戳 = 采样时刻 epoch_s（不对齐栅格——qB 重连退避、主循环抖动都会让采样时刻漂移，存储层不假装均匀）。
  • API 层把 [t0, t1] 按 栅格 = 采样间隔离散：bucket = floor(t / interval) * interval；桶内多行取速率均值；空桶 = null。24h 窗 ≈2,880 桶（raw 段），30d 窗 ≈720 桶（hour 行，hour_epoch 即桶键）。
  • 累计增量（totals 段，报告响应形状的细化）：相邻桶累计快照差分，max(0,·)；cur < last 判重置 → 该桶增量 null（§03.4）。
