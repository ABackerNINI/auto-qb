kb.nav 多选与批量右键菜单

给 kb.nav 导航页台账加文件管理器式多选（Ctrl/Shift 点击）与批量右键菜单——行属于选中集合时菜单升级为批量（如「复制仓库路径 · 3」一次复制 3 行）；交互逻辑参照 auto-qb webui selection.js/menu.js 既有口径，单文件 nav_page.html 内闭环，服务端零改动。

§01目标与设计原则

背景与目标：kb.nav 台账目前只能单条交互——批量复制路径/隐藏/置顶要逐条右键。本计划给台账主表与置顶专区加多选，右键菜单按「行 ∈ 选区 → 整集合生效」升级为批量。算成的标准：①主表+置顶区可 Ctrl/Shift 多选且双区同亮；②右键批量四项全部可用，复制 N 件 = N 行文本；③Esc /「已选 N」chip / Ctrl+A 齐备；④tests/test_kb_nav.py 守阵扩条全绿。

设计底线 / 不变量：

  • 纯前端会话态：nav_data.py/nav_server.py 零改动；选区不落 localStorage（同 S.sel 口径）。
  • 选区以 link 为键：与可见性、双区显示解耦（置顶件双向显示，两处同亮）。
  • 普通左键单击语义不破坏：单击 = 单选高亮 + 开抽屉，不动多选集（auto-qb「普通点击不选中/不清选」口径，用户明确拒绝「单击清多选」——容易误触）。
  • 右键不改选区：不新增、不清空（auto-qb menu.js 口径）。
  • 幂等（黄金法则 1）：批量置顶/隐藏对已处于目标态的成员零副作用。
  • 零列结构改动：不加列、不加 td，ledgerCells 复用——列序守阵不触发。
  • file:// 静态导出同样可用：剪贴板沿用现有双链路降级（navigator.clipboard → execCommand）。

§02现状与痛点

载体 .agents/skills/memory-bank/scripts/nav_page.html（1599 行单文件）。相关现状：

  • 单选：主表 #aRows 行为 <tr data-link>，单选态 S.sel（tr.sel 高亮 + 详情抽屉，nav_page.html:1025-1026、1347-1356）。
  • 右键菜单：openCtx(x, y, link) 硬编码单 link，固定 4 项（置顶/隐藏/打开原文/复制仓库路径，nav_page.html:1119-1133）；主表、pinZone、hidZone 三处 contextmenu 委托共用（1357-1362 / 1370-1375 / 1386-1391）；菜单点击分发在 1393-1402；copyPath 双链路降级（1138-1152）。
  • Esc 退栈链已存在：overlay → ctxMenu → drawer → sel（1404-1431，计划 26-10-13-0324）。
  • 渲染/状态：POLL_MS=30000 轮询 re-render（1592）；pin/hide/筛选落 localStorage（765-839），S.sel 会话态。
  • 置顶双向显示：被 pin 的件照旧留在主表，主表/pinZone 两处同 data-link（renderPinZone 注释，nav_page.html:1049）。
痛点：整理知识库时「把这一批过时的 issues 都隐藏」「把相关 5 件路径发给别人」都要逐条右键，N 件 = N 次操作。

§03方案总览

3.1 状态模型

  • S.multi：link 数组（会话态，入栈序）；派生 Set 判成员。切视图即清空（§06 D5）。
  • S.multiAnchor：Shift 扩段锚点 link（普通/Ctrl 点击落锚点，Shift 不动锚点——auto-qb 法则 2，可从同一起点多次扩段）。
  • 渲染：renderLedger/renderPinZone 出行时按 link ∈ 选区挂 class="msel"——轮询 re-render 天然存活（状态在 S、DOM 重建时重挂）。

3.2 交互模型（照 auto-qb 口径）

手势语义出处
普通左键单击现行为：清单选高亮 → 该行 S.sel + 开抽屉；不动 S.multiselection.js onTorrentClick（D3）
Ctrl+click切换该行多选态（同时落锚点），不开抽屉同上（D1）
Shift+click锚点→该行在当前可见序的区间并入选区（new Set 合并去重，锚点不动）；不开抽屉selection.js shiftTorrentSel（D1）
右键（行 ∈ 选区）菜单升级为批量：作用于整个选中集合（有序 link 数组快照，打开菜单那一刻冻结）menu.js CTX-03（D4）
右键（行 ∉ 选区）保持现状单条菜单，四项文案不变同上（D4）
Esc退栈链末档新增：其它层全关后再按 = 清空多选（D9）
Ctrl+A焦点不在输入框且台账视图：全选主表当前可见行，preventDefault（D11）

3.3 批量菜单语义

  • 文案带计数（D12）：批量态每项加灰色 N 后缀，如 隐藏条目 · 3、复制仓库路径 · 3；单条态保持现状文案。菜单项动作走与单条同一条分发链，只是目标从 1 个 link 变 N 个。
  • 置顶/隐藏动态单项幂等（D6）：全已置顶 → 显示「取消置顶」，否则显示「置顶到专区」（动作 = 把未达态成员置到该态，已达态不动）；隐藏同理（选区在主表，恒为「隐藏条目」方向）。
  • 打开原文（D7）：逐个 window.open；N > 5 先 window.confirm("将打开 N 个标签页，继续？")，取消则不动。被浏览器拦弹窗静默失败（同 copyPath 静默降级口径）。
  • 复制仓库路径（D8）：每行一个 memory-bank/<link>，顺序 = 主表当前可见序（aFiltered() 序）；被筛选掉但仍在选区的行追加在后（按 DATA.items 全量序）。

3.4 辅助件

  • 「已选 N」chip（D10）：顶栏计数徽章，点击清空多选；N=0 隐藏。
  • 双区同亮（D13）：置顶件在主表与 pinZone 两处行都挂 msel；批量目标 = 选区 link 去重集。hidZone 不参与多选，右键保持单条（D2）。

§07风险与对策

风险触发条件处置
window.confirm 打断用户手势链，其后的 window.open 可能被弹窗拦截批量打开 >5 且浏览器策略严接受：拦截即静默失败（D7 口径），不重试不降级；实测若高频再议 overlay 确认层
浏览器扩展吞键（Vimium C 吞 Esc 有前科——提交 5885d7a6 取证）用户装 Vimium 类扩展已知坑无代码侧解；Esc 退栈链已有 IME 守卫与可见性判据，行为与现状一致，不新增风险面
msel 与 sel 高亮同框视觉混淆（CSS 特异性互盖，同 pitfalls/web-ui/layout-css.md 三层底色坑型）一行同时被单选和多选两态底色用不同通道（accent 弱底 vs 现状强调），实施步骤 1 验收判据单列；踩坑按动作记 pitfalls/web-ui
菜单打开期间选区漂移（轮询 re-render / 用户再点击）菜单存活 30s 轮询窗口重叠openCtx 冻结 link 数组快照（auto-qb D5「打开时快照」口径）；菜单存活期点行先关菜单，不存在动作时目标集与文案 N 不一致
列序守阵误触实施中顺手改 ledgerCells 列结构不变量明确：不加列不加 td；review 时对照 tests/test_kb_nav.py 列序断言
