口径警告(照抄 baseline.md 常驻警告)
  • 门槛飘红是既有欠账, 不是回归: 97.66% vs --cov-fail-under=98 的 FAIL 已连续多轮在基线切片留痕, 全量用例 0 failed; 本计划第一目标就是把它赎绿。

§5

机制建设 — 让覆盖率不再回落

历史规律: 覆盖率这类「没人拦就缓慢回落」的指标, 靠自觉守不住。上一轮已建立 M1–M4, 本计划延续并新增 M5–M7:

机制说明落地时点
M1 阈值阶梯--cov-fail-under: 维持 98(P0 后, 首次转绿)→ P1 后 98.5 → P2 后 99。阈值恒低于当期实测 0.3–1 个点, 兼顾并行口径波动与特性新增稀释。抬阈值是阶段验收动作的一部分, 与基线切片同一轮落地, 不单独提前。test.quick 的 --no-cov 豁免不变 —— 提交闸门保持快速, 覆盖率检查由 test.full 与基线切片承担。每阶段验收
M2 基线切片按 testing/baseline.md 口径: 一条基线一个切片, TOTAL + 条数 + 耗时区间; Windows 与 Linux 两侧都重测再落数字。每阶段验收
M3 红验纪律每阶段新用例抽 ≥10% 做变异红验: 临时注入缺陷确认测试能红。夹具必须让目标分支真正抵达。每阶段验收
M4 增量不欠账本计划执行期间及之后, 新功能 / 新模块一律带测试落地; 缺口只减不增, 否则 M1 阈值直接拦住。常态
M5 watchlist(新)行覆盖 <95% 的单文件清单(现 10 个, 见 §2.3 尾注)。每轮基线切片复查一行; P0/P1 各阶段验收时逐项核销; P2 目标清零。新增文件行覆盖 <90% 即在当轮切片点名。P0 起每轮
M6 豁免治理(新)pragma 豁免行数进基线切片记录面, 只减不增; 本轮新增豁免必须逐块写明理由(照上一轮 tray 豁免先例), 防止豁免变成习惯。常态
M7 工具侧门禁评估(新)gtm 工具侧(hermetic 用例, 无覆盖率门槛)在 P2-T2.6 出评估结论: 是否加 --cov-fail-under、起步值多少、CI 是否纳入; 实施另立任务, 不计入本计划单位。P2
与既有计划的关系

本计划是 上一轮覆盖率提升(91% → 96%) 的第二轮, 全部机制沿用其 M1–M4 框架, 不重复提案; 与各专题计划(gtm / 全局流量来源 / webui 系列)并行不冲突 —— 补测试不改产品代码, 若某专题顺带覆盖了本计划目标行, 在对应阶段任务表标注「由 X 顺带清偿」即可, 不重复补。

§6

范围外 · 变更记录

6.1 明确范围外(本计划不做)

  • gtm 工具侧覆盖率门槛实施 —— 仅 P2-T2.6 出评估结论, 实施另立任务。
  • per-file 硬门禁 / CI diff-coverage / 变异测试扩面 —— watchlist 清零、99% 稳住之后再评估, 现在上重机制只会拖慢每次提交。
  • tray widget 主体治本 —— 上一轮 P2 决策延续: 需 headless 依赖注入等架构改动, 单独立项; 本计划只维持既有豁免口径, 不新增 pragma。
  • 产品行为扩测 —— 本计划只补既有逻辑的测试覆盖, 不评审、不扩展产品行为本身。
