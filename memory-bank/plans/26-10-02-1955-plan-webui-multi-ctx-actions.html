+ 跳检菜单配置开关

03

设计要点

  • 批量动作全部走既有 bulk 合单通道(POST /api/torrents/bulk 扩 _BULK_ACTIONS), 不为每个动作开新逐项路由 — 与 recheck 特判先例同构, 路由金清单零新增(W4 导出归档除外)。
  • 批量跳检经 ops 层逐 hash 串行: 新 _bulk_skip_check_via_ops(commands.py, 样板 _bulk_recheck_via_ops 601-645), 逐 hash ctx.ops.skip_check(h, source="web") — R2 复核 / 同日去重 / 备份 / 打标守卫全部原样保留, 只加聚合回执(ok N / 跳过 M 按原因 / 失败 K)。串行是单写线程假设的硬要求(concurrency 坑), 禁止并发扇出。
  • 配置键 web.skip_check_menu(bool, 默认 false)只门控 web 面: 菜单显隐 + web 侧端点; 绝不进 OpsModule.skip_check 内部 — rule 源跳检(high-risk-ops 防护体系的一部分)不受任何影响。
  • fail-closed 双层: 菜单项 v-if="flags.skip_check_menu" 不渲染 + web 端点(enqueue 与 bulk 分派处)配置关时 403, detail 文案注明键名。gate 读实时配置(与现有路由取 cfg 同路), 不按值持有旧 Config(hot-reload-held-config 坑)。
  • 前端 flags 通道走新端点 GET /api/webui/flags(鉴权后): 不扩 /api/config/public — 它是登录前 loopback 专用, 扩它等于改其安全语义; 新端点登录后取一次入 state.flags(初值 {skip_check_menu: false}), 设置页保存配置后同步刷新。
  • 批量导出走后端 zip 归档(D1 推荐): 新 POST /api/torrents/export-archive body {hashes: [...]}(POST + JSON body, 免 URL 长度问题; 下载走裸 fetch + Blob 特例口径)。服务端逐 hash 校验存在性(缺失即 400 带 missing 明细)→ 逐个 client.torrents_export → io.BytesIO + zipfile 组装; 条目名 = 清洗后的种子名(非法字符 → _), 重名追加 hash 前 8 位防撞。单选导出现状不动。
  • 三皮肤共用 shared/: 模板与 JS 一处改三处生效(frontend-split 聚合口径); 菜单新项排序对齐单选分支语义(开始/暂停 → 强制汇报 → 重新校验 → 跳检 → 限速/移动 → 标签分类 → 导出 → 删除)。
  • 批量限速语义(D3 推荐): 对话框两项(上传 / 下载)留空 = 不改该项, 只提交有值项; KiB/s ×1024 与单选同口径; 0 = qB 语义的"无限制", 允许; 负数路由层拒收。批量移动: promptDialog 空 prefill(多选无意义当前值)→ 确认框展示目标路径与 N。
耗时与回执: 批量跳检耗时随 N 线性增长(单枚阻塞 ~6s 级), 聚合回执可能超过 waitCmd 默认窗口 — 沿单选口径放宽至 60s 并依赖 SSE cmd 事件赛跑兜底(waitCmd 实现 commands.js:100-123), 回执未到前 toast 停留"进行中"。
04

决策点 (待拍板 · 不拍板按推荐走)

D1多选导出的形态推荐 B

B · 后端 zip 归档(推荐): 一次下载得单个 zip; 任意选中规模可控; 文件名清洗与防撞在服务端单点; 无浏览器"多文件下载"授权摩擦。
A · 前端循环逐个触发下载: 零后端改动(复用 GET /api/torrents/{hash}/export), 但浏览器首次会弹"允许下载多个文件"、大选中(数百+)不可控、中途失败无汇总。

D2服务端是否同步封禁 skip-check推荐 是

是 · fail-closed(推荐): 菜单隐藏 + web 端点(单发路由与 bulk 分派)配置关时 403。理由: 菜单隐藏只是 UX, 直调 API 仍可跳检; 现有单发端点无任何调用方残留(skipCheckTorrent 是唯一入口, 键表无 skip 直达键位), 加 gate 不破坏存量。
否 · 仅菜单隐藏: 改动更小, 但"配置开启才显示"退化为纯展示层开关, 与高危动作默认关闭的仓库原则(保守默认)不符。

D3批量限速对话框口径推荐 留空不改

留空 = 不改该项(推荐): 上传 / 下载两输入各自独立, 只提交有值项; 与单选 _editPost "可各自缺省"口径一致, 多选场景下几乎必有"只想改上传"的需求。
两项必填: 实现最简, 但多选时把不想动的方向的限速也覆盖掉, 语义粗暴。
