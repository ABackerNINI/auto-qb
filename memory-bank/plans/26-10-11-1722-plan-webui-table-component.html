01 目标与边界

把五份表壳收敛成一份，让“加一张表”变成“注册一行”

1.1 目标

  • 公共表壳：表头（列名 + 排序箭头 + 拖宽把手 + 拖拽重排指示线 + 右键菜单）、行容器、行窗口化占位，收敛为一份可复用实现。
  • 四项交互齐备且同源：拖拽换位、拖拽调宽、点击排序、右键隐藏——全部由既有单点承载，组件只是消费方。
  • 差异派生：每张表的差异只落在 4 个轴上（列定义 / 行模型与单元格 / 行为开关 / 宿主与滚动同步），不复制表壳。
  • 可接入面：主视图（辅种 / 追剧 / 种子页 / 成员明细）与设置页（HR 各类表）接入同一套描述符；详情面板的用户 / 文件列表作为重构后的目标接入面（本轮不迁移）。

1.2 非目标（本轮明确不做）

  • 不改观感、不改列集合、不改数据契约（前端 SEED_ITEM / GROUP_ITEM / SHOW_ITEM 形状不动，后端零改动）。
  • 不引入构建链（继续 Vue 3 CDN + 全局 mixin + shared/tpl/*.html 分片聚合）。
  • 不重写列状态模型——双轨模型（意图 / 生效）是定案，本轮只把它的页枚举泛化。
  • 不为现有详情面板做兼容适配：详情面板问题多、后续将完全重构且不考虑兼容（用户 26-10-11 定），本轮不迁移它的表、不为它的字符串 DOM 架构写兼容层，只为重构后的面板预留接入面（见 P6 / D4）。
本计划的落点 用户诉求是“抽公共模板组件”。盘点后落点收窄为两件事：① 抽表壳（模板单点）；② 把 4 页硬编码泛化为表注册表。行为单点已经存在，重写它只会把稳定面搅动一遍。

03 目标架构

一个核心引擎，两个渲染适配

渲染技术目前是分裂的——主视图与设置页是 Vue，现有详情面板是字符串 DOM（宿主归插件自管，Vue 零感知）。但详情面板后续将完全重构、不考虑兼容，为它现有的字符串 DOM 架构写适配层属于沉没成本。因此收敛目标收窄为：把与渲染无关的部分（描述符 + 行为引擎）抽成唯一核心，配一个 Vue 适配作为主路径；DOM 适配降级为条件项——仅当重构后的面板仍走字符串 DOM 才需要，见拍板点 D4。

3.1 描述符注册表（差异的唯一声明处）

把今天散在 app.js（列常量）、columns.js（四页枚举）、sort.js（视图分派）里的“表身份”收进一张注册表，每张表一行：

  • id：表标识（即今天的 page 键：group/detail/torrent/show，后续新增 peers/files/hr…）。
  • columns：列定义数组（今天四组常量原样搬入）。
  • rowModel：行数据模型名，决定单元格渲染器与行类名。
  • features：行为开关（sort/resize/reorder/hide/window）——差异表只需关掉不需要的项。
  • defaultSort、hostRef、pickerGroupLabel：默认排序键、滚动容器 / 表头 ref 名、列选择器分组标题。

3.2 核心引擎（把“四页硬编码”换成“按 id 迭代”）

columns.js 里所有写死四页的地方改为遍历注册表：TABLE_PAGES 常量退役、recomputeEffective/colAlignCss/gridStyle/_headEl/_winGapOf 一律吃 tableId。这一步零行为变化，是后续所有步骤的地基。

3.3 两个渲染适配

  • Vue 适配 <aq-table>：全局组件（app.component，属既有接线四形态之一）。只包表壳（表头 + 行容器 + 占位），行仍由调用方 v-for 内联渲染——这是为 3000 行窗口化路径保留的硬约束（见 06 风险 4）。单元格经“行模型渲染器”产出，避免 127 条分支再复制。
  • DOM 适配 table-dom.js（条件项，默认不做）：只有当重构后的详情面板仍采用字符串 DOM 渲染时才需要。它复用 dtHtml 转义单点 + H.wireEvents 事件委托，输出同一套类名。不为现有抽屉做迁移——现有抽屉将整体废弃。

3.4 必须保持的不变式

  • 双轨列状态铁律：只存意图，派生宽度不落盘（pitfalls/web-ui/columns-persist.md）。
  • 行窗口化占位契约：占位高 = 折叠行高之和，逐行实测不近似。
  • 三皮肤同名类成对；新增类要三份 CSS 同步。
  • 无构建链；分片文件按 tpl-manifest 清单序装载。
  • 不为将废弃的详情面板做兼容：现有抽屉（字符串 DOM + 15 变体）不迁移、不写适配层；表组件只需保证“重构后的面板能干净接入”。

06 风险与红线

九条会静默失效或误伤的点

风险 1 · 列偏好被重置（复发陷阱） 双轨模型铁律：新增表 = 新增 pages 子键，绝不升 COLS_STORE_KEY 版本。升版本会清空用户手调的宽 / 隐 / 序——这正是历史上“列宽时不时被重置”的机制性来源。见 pitfalls/web-ui/columns-persist.md。
风险 2 · 守阵会红（不能删，只能改口径） _scan_column_cells_paired（tests/test_webui_static_skins.py:569）要求每个列 key 在模板里有 col.key === 'k' 字面分支。渲染器收敛后该字面不再存在——必须同轮把守卫改为扫渲染器注册表，而不是放宽或删除。同理 test_frontend_frozen_column_boundary_wiring 钉住三个横滚单点。
风险 3 · prism shell 210 行硬顶 新增 shared/*.js 片段要三份 index.html 的 scripts 各加一行，而 prism/index.html 贴着 210 行上限跑——加一行必须先腾一行（删空行即可，勿压行）。见 pitfalls/web-ui/frontend-split.md。
风险 4 · 窗口化热点不得退化 3000 行场景靠“只渲染视口附近几十行”压住主线程。若把每行包成一个组件实例，会在 2s 轮询刷新时引入新的 patch 开销。组件只包表壳，行仍内联 v-for 渲染；行窗口化的 padTop/padBottom 契约原样透传。
风险 5 · 拖拽手势的类名白名单 startResize/startColDrag 靠 closest(".group-head")||closest(".detail-head") 认容器（columns.js:440 / :546）。新表若换容器类名而白名单没扩，表现为“拖了没反应”，无报错。
风险 6 · 全局 mixin 与根选项的边界 组件方法域走 app.mixin；data/computed/watch/生命周期只能进 state.js/lifecycle.js 经根选项展开——塞进全局 mixin 会波及一切组件实例（含 hub-field），静默双跑。见 pitfalls/web-ui/frontend-split.md。
风险 7 · 三皮肤 CSS 成对 表壳类名（.group-head/.h-cell/.resizer/.col-drop-line）在三份 CSS 里各有规则。新增类必须三份同步；有 shell 行数与成对守卫盯着。
风险 8 · e2e 逐位一致 列设置、隐藏列宽保留、横滚边界落影等场景在 dev.e2e 与冒烟里有断言。每步收口都要跑，不能只看 pytest。
风险 9 · 视觉零回归 本轮不改观感。表壳抽取若改了 DOM 层级（如多包一层 div），会破坏 :nth-child 列对齐规则（colAlignCss 依赖 [data-table] 的直接子元素）与 grid 布局。DOM 等价比对是本轮的硬验收。
风险 10 · 为将废弃的面板投入适配（沉没成本） 详情面板待完全重构，任何“让现有抽屉的表接入公共组件”的工作都会被整体丢弃。本轮把抽屉排除在迁移范围外，只在 P6 留契约；反过来，也不要为迁就现有抽屉的字符串 DOM 而扭曲表组件的接口设计。

07 拍板点

五处需要用户先定方向

D1组件形态

A · 纯引擎 + Vue 全局组件 <aq-table>（单适配）｜ B · 模板内 v-for 描述符循环 ｜ C · 纯引擎 + Vue 组件 + DOM 构建器（双适配）

推荐 A（随详情面板移出范围而升级）：主视图与设置页都是 Vue，单适配即可覆盖本轮全部接入面；DOM 构建器（C）只在重构后的面板仍走字符串 DOM 时才补，属条件项。

D2单元格渲染方式

A · h() 手写 VNode 函数注册表 ｜ B · 保留声明式模板，但按行模型收敛为单份

推荐 B（先做 B，A 留作 P6 之后的可选优化）：声明式对 127 条分支的迁移更安全，且不触碰窗口化热路径。
