现状摸底结论

逐文件核实了前端三份主文件（index.html / app.js / style.css / config_editor.js / config_rules.js）与后端 web.py、qbmanager.py、schema.py、curves.py、speed_curve.py 的相关代码，影响方案的事实如下：

  • F1
    站点配色已是"底色=状态、文字=站点哈希" `.sc-0..7` 文字色（app.js `siteHue()` djb2 哈希）+ `.site-chip.<kind>` 状态底色。回退只需删哈希类并给状态类补 `color`，明细行圆点前缀不受影响。 index.html 站点 chip :class · app.js siteHue() · style.css .sc-*
  • F2
    命令队列是 fire-and-forget，无结果回执 `/api/groups/{key}/reannounce` 等仅入队即返回 `queued:true`，主循环 `_drain_web_commands` 执行后结果只进日志 —— "强制汇报显示是否成功"需要先补一条回执链路。 web.py `_enqueue` · qbmanager.py `_drain_web_commands` / `_cmd_reannounce_*`
  • F3
    历史流量数据现成，只差透出 Traffic Monitor 的 dat 文件天然是"每天一行 上传KB/下载KB"，`curves.parse_history_dat` 已解析为按日升序的 (日期, 上传, 下载) 列表。天/月/年视图 = 原始行 / 按月求和 / 按年求和，主循环限速任务每轮已解析该文件，顺带发布即可，无需新任务。 curves.py `parse_history_dat` · mixins/speed_curve.py `_publish_traffic`
  • F4
    成员视图没有 name 字段 `_build_group_view` 的 members_view 含 hash/site/save_path/size 等 16 字段但不含种子名 —— 删除确认框要显示"种子名"需在成员视图补 `name`（`name` 已在 `_VIEW_FIELDS` 置脏集合内，无额外置脏工作）。 qbmanager.py `_build_group_view` · torrents.py `_VIEW_FIELDS`
  • F5
    折叠语义与登录闪现的根因明确 日志/WEB UI/通知三个分组是"单 object 字段分组"，走 `cfgFlatten` 的 group 类型默认折叠；规则卡折叠态存于 `collapsedRules`，缺省=展开。登录遮罩初始 `authRequired:true`，本地密钥 bootstrap 验证期间呈现的就是密钥表单 —— 闪现来自"验证中"与"输入"共用同一张卡。 config/schema.py GROUPS · config_editor.js cfgFlatten/cfgRuleCollapsed · app.js bootstrap()

04

关键设计细节

4.1数值列对齐与零值居中（R04）

分组表五个数值格共用 `.g-stat`：加 `text-align:right`，表头按既有 `hc-<列key>` 机制补五条右对齐规则；`.g-stat.zero { text-align:center }` 让"—"居中（em dash 居中在右对齐列里形成干净的留白锚点，也是常见表格做法）。明细表数字格目前无统一类名，模板补挂 `m-stat`（只加 class，不动 grid 结构与列数）。size 单元格内的 `risk-mark ⚠` 跟随数字右对齐。不动：H&R/站数列的居中（上一轮明确要求）、`.group-head/.detail-head` 拖拽锚点。

4.2站点配色回退（R01）

目标态：`.site-chip.seeding { background: var(--green-soft); color: var(--green); }`——字体与背景同时承载状态，同一站点的不同状态一眼可分，站点身份由 chip 文字本身表达。删除项：`siteHue()` 方法与注释、`.sc-0..7` 八条规则、模板里的 `sc-` 类拼接；`.stalled/.stalled-dl/.stalled-up` 三条 chip 规则是死代码（`m.kind` 只有 6 种语义值，不可能出现），一并清理并回写 pitfalls。明细行 `m-site/m-state` 的圆点前缀与本需求无关，保留。

4.3多选交互设计（R03）

操作分组表明细表
普通点击展开/收起明细（现状不变）切换该成员选中
Ctrl / ⌘ + 点击切换该组选中切换该成员选中
Shift + 点击从锚点组到当前组整段选中当前展开明细内从锚点成员到当前成员整段选中
右键有选中集合时弹批量菜单；无选中时保持现状（组菜单/单种子菜单）

选中集合 = `selGroups`(组 key) + `selMembers`(成员 hash)，增量刷新（groups 整表替换）后按 key/hash 交集保留，避免轮询清空选择。批量操作浮条挂表格上方（sticky 不随横向滚动），含：已选计数、"开始 / 暂停 / 强制汇报 / 删除…"四个动作、清除选择。组与成员混合选中时：组动作作用于组、成员动作作用于成员，删除合并为一份清单进确认框。搜索虚拟行只支持成员级操作（无真实组 key，右键已退化为单种子菜单——沿用该约束）。

4.4命令回执时序（R05）

"成功"判定深度：qB `torrents_reannounce` 调用无异常即记成功（announce 请求已交给 qB 发出）。不在第一版做"tracker 已响应"级确认——需要轮询 `torrents/trackers` 比对 `next_announce` 重置，且部分私站 tracker 状态字段不可靠，收益低复杂度高；若未来需要可在 `_cmd_reannounce_*` 内扩展，回执结构不变。超时上限 15s：主循环 tick 2s + 命令执行毫秒级，15s 已覆盖数个积压 tick；UI 等待期间按钮/菜单显示"汇报中…"。

4.5删除确认框（R06/R07/R08）

modal 结构扩展两块通用能力（保持单例与 Promise 契约、取消/遮罩/Esc 结算不变）：

  • checks 多选项：替代现有单 `checkbox` 字段（删除文件选项 + 强制汇报选项并存，各自独立勾选）；"删除前强制汇报"默认勾选。
  • details 信息区：图标 + 键值行。整组 = 组名 / 成员数 / 站点列表 / 保存路径 / 总大小；单种子 = 种子名 / 站点 / 当前状态 / 保存路径 / 大小。标题图标 danger 态改 `i-trash-x`。

执行编排（勾选汇报时）：逐目标 `reannounce → 轮询回执`，全部成功才逐目标 delete；任一汇报失败 → toast 明确"X 个种子汇报失败，已保留未删除"，不继续删除。批量场景同链路，浮条/modal 上显示进度（第 n/N 个）。不勾选 → 走现有直删流程。

4.6历史流量图（R02）

实现与限速曲线预览图同一路数（纯内联 SVG、`v-bind` 动态 viewBox、显式 aspect-ratio），无新依赖。数据窗口：天=最近 30 天、月=最近 12 个月、年=dat 覆盖的全部年份；月/年视图聚合 = 按 `date.year/month` 分组求和。入口仅在"今日流量"卡渲染时出现（未启用限速曲线则既无 dat 也无卡，语义一致）。stale（数据源暂时不可读）时入口置灰并提示沿用上次数据。

05

待确认决策点

以下 4 项按推荐项默认执行，回复确认或改选即可：

D1多选交互：修饰键方案（不加列）

推荐 Ctrl/⌘ 选中 + Shift 范围，普通点击行为不变。 备选：行首 checkbox 列——更易发现但要动列模型（列宽存储升 v4→v5、全列宽重置），且占用一列宽度；修饰键方案零列成本，代价是"可多选"需靠浮条提示发现。选 checkbox 列的话多选触发也可以做成"浮条上的'进入多选模式'"折中。

D2"汇报成功"的判定深度

推荐 qB API 调用成功即成功（语义="已向 qB 下发重报指令"），超时 15s。 备选：轮询 `torrents/trackers` 确认 tracker 状态变 working / next_announce 被重置——更接近"汇报真的被 tracker 接受"，但部分私站字段不可靠、实现与测试复杂度显著上升。建议第一版取前者，回执结构预留升级空间。

D3历史流量入口图标

06

风险与红线（不动清单）

config.yml / auto-qb-data/ 生产文件与运行时目录，本轮完全不触碰。

列模型与拖拽锚点：不加列（D1 推荐项下），`COLS_STORE_KEY` 维持 v4；`.group-head/.detail-head` 锚点结构、grid 列数一致性约束不动。

鉴权安全语义：`authRequired` 仍是遮罩唯一门控且仅验证成功放行，主界面 DOM 不提前创建；bootstrapping 只是遮罩内渲染态，不构成放行路径。

单一写线程：命令执行、结果 map 写入只在主循环线程；Web 线程维持"读快照 + 投递"。

语义色纪律：对比色留给 HR 未达标与错误信号；新增组件不与状态徽标/HR chip 争视觉权重（同一语义不双重表达）。

前端表达式风险：computed/methods 分界（模板里 computed 不加括号、带参辅助一律 method）——两次实锤翻车点，阶段 B/D/F 模板改动逐条自查 + 冒烟。

跳检/删除流程：不触碰规则引擎的跳检四阶段与删除守卫；本计划只改 WEB 触发的删除编排（qB `torrents_delete` 调用点不变）。
