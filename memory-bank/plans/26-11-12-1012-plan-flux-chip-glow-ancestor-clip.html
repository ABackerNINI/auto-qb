§01目标与设计原则

旧计划 26-11-10-0921 已完成 .site-chip 形状分层(W1 / S4), 现为 doc-status: Done, §10 R1 记实施完成(W1 / S4 落地、W1-3 边线迁移由用户真机目检触发并经裁决接受、test.full 全绿), 其中目检记录只覆盖 .site-chip。但其验收口径只覆盖「三种 chip 共用同一条辉光配方 + site-chip 四边闭合」, 标题所承诺的视觉效果没有完全兑现: 分类/标签 chip 的辉光仍被祖先裁剪, 且 hover 态下的状态标记表现不一致。本轮是补齐旧计划绘制层差额, 不是重做旧计划。

算成: ① flux + glass / neon + 非选中态下, 三种 chip hover 均呈现四边闭合的同一条 --fx-glow-stack 辉光; ② .tag-chip.hr-pending/.hr-done 的 H&R 状态竖线在 hover 前后持续可见, 与 site-chip 的 S4 迁层同构; ③ crisp 全关、.f-on 无辉光、三旧皮肤零变化维持现状; ④ 新增像素级红绿双验能自动抓回「祖先裁剪」与「边线覆盖」两类回归。

§02现状与痛点

规则层早已统一, 差额全在绘制层

flux/css/fx-mount.css:296-303 是一条共用规则: .site-chip / .tag-chip / .cat-chip 的 :hover:not(.f-on) 与 :focus-visible:not(.f-on) 同消费 var(--fx-glow-stack); :276-281(transition) 与 :304-310(active 缩放) 同样三者共用。这套共用早在 26-11-04 四轮修落地, 旧计划 W1 只针对 .site-chip 新增形状分层(:447-485), :444-445 还明确写「tag-chip/cat-chip 无 clip-path, 形状不动(D3/D9)」——只改 site-chip 是旧计划的显式范围, 不算实施漏做。

面site-chiptag-chip / cat-chip
本体裁剪W1 覆盖为 clip-path: none, 切角迁 ::before本体无 clip-path(但自带 overflow:hidden 做文本省略)
直接父容器.g-sites 无 overflow(components.css:328).g-tags/.m-tags、.g-cat/.m-cat 有 overflow:hidden(components.css:340-341)
hover 时状态边线paused / other / search-hit inset 与 sa-no-conf dashed 已迁 ::before(fx-mount.css:463-485), 持续可见H&R 左边竖线仍画在本体 box-shadow(components.css:346-349), hover 被 stack 整体替换 → 消失

模板 shared/tpl/xtpl-cells.html:66/76/86 证实三种 chip 的直接父分别是 .g-tags / .g-cat / .g-sites。父级 overflow:hidden 会裁掉画在盒外的 box-shadow; 这四个格无 padding、chip 紧贴上下边缘, 辉光必然越界 —— 正是用户原话「部分辉光仅显示一侧或两侧」。

实测证据(只读核实轮, 最小 Chromium 实验)

  • 祖先裁剪: 子元素白色外发光采样像素 RGB, 父 overflow:hidden 时上方 [0,0,0] / 左侧 [0,0,0], 父 overflow:visible 时上方 [136,136,136] / 左侧 [135,135,135]; 容器内两者同为 [203,203,203] ⇒ 裁剪只发生在容器边界外。
  • 放行量: --fx-glow 在 neon / glass 均为 12px(fx-presets.css:89/173), crisp 为 0(:232); stack 最大层 0 0 12px 3px(shared/fx/fx.css:153) ⇒ 需约 16px 外扩余量。
  • 候选修法行为: hidden / clip(无 margin) 上/左亮度 0/0; visible 与 clip + overflow-clip-margin:12px|24px 均为 136/168; :has(span:hover) 动态切 visible 单独复核亦生效(has:true, overflow:visible, 136/168) —— 多 case 实验里一度不生效是内联 style 优先级压过类规则, 真实项目无此问题。
  • 坑档缺口: clip-path-clips-outer-glow.md 只写「控件本体 clip-path 裁外发光」, pitfalls/ 全库无「祖先 overflow:hidden 裁后代外发光」条目; shared/row_lang.css:202-229 的行内注释实证过同机理(首格裁剪负偏移左条), 但未入档。

Q6 与 H&R 的关系(释义澄清)

此处 HR = H&R(Hit & Run, PT 站做种考核), 对应项目 src/auto_qb/hr/ 模块、WebUI 的 H&R 列与 --hr-pending / --hr-done 语义色, 不是人力资源缩写。.tag-chip.hr-pending/.hr-done 是标签 chip 上的两档 H&R 状态类, components.css:346-349 分别用 box-shadow: inset 2px 0 0 var(--hr-pending) / var(--hr-done) 在左侧画 2px 橙/青状态竖线。

与本次修复的关系是同一条 hover 辉光规则的副作用: box-shadow 是单一属性, hover 规则整体写入 stack ⇒ 用本体 box-shadow 画的竖线被替换。旧计划 S4 已把 site-chip 的同类常态 inset / dashed 边线迁到 ::before, 于是 hover 态下 site-chip 边线持续可见、tag-chip 的 H&R 竖线消失, 构成三种 chip 之间的次生不一致。

诚实边界: Q6 不是「辉光四边闭合」的必要条件 —— 主修法是 Q5 的祖先裁剪放行; Q6 补的是 hover 态语义标记的一致性, 属 Q1-A 范围决策下的顺带项。若口径只钉辉光, Q6 可剔除记为遗留; 本轮用户「其余按推荐」已把它纳入(D6)。

分类 chip 与 HR 的关系(2026-11-12 追问核实, 只记事实不改范围)

渲染层没有特殊对待: 模板 xtpl-cells.html:80-82 / 165-167 与 xtpl.html:288 的 cat-chip :class 只绑 f-on, 不调 tagClass(全库无 catClass); CSS 无 .cat-chip.hr-*; 行状态色规则(components.css:354-369)里 cat-chip 不带 :not(.hr-pending):not(.hr-done) 排除, 被无条件染成绿/蓝/红。基线本体也只有灰底 + 字色 + 省略(:350-352)。

但数据层关联真实存在: config/models.py:45-49, 59-63 的四个输出键 hr.add_tag / add_category / add_tag_for_satisfied / add_category_for_satisfied 允许把 HR 触发/达标标记写成分类(maintenance_mod.py:326-340 走 set_category); 分类也是 HR 排除表命中面(exclude_categories, models.py:50-52, 65-66; hr_excluded_by 含 category / tag+category, views.py:310-311)。⇒ 同一 HR 语义若配到分类路径, 在表格里就是普通灰 chip 且被行状态色覆盖, 拿不到标签路径的橙/青语义色与左竖线 —— 这是既存的展示层不对称。

本轮不扩大范围; 该功能已另案入池: 2026-11-12 用户拍板「另案登记」——分类 chip 具备与 tag-chip 对等的 HR 效果(hr-pending / hr-done 语义色 + 状态边线 + 行状态色 :not() 让路)列为另案目标, 已入池 memory-bank/issues/26-11-12-1037-feat-webui-cat-chip-hr-semantics.html(feat/standard, Open, 未认领、未排期)。实现需新增后端 HR 分类字段 + 改四皮肤共用模板与四皮肤 CSS, 必然破 I1「仅改 flux」, 故不纳入本计划 S1–S6; 改造面与候选方向见该 issue §04 / §06。按范围守恒, 本计划只记事实与正文交叉引用, 不给修复方案、不建认领链(issue 的 doc-refs 留空)。Q5 的 .g-cat/.m-cat 裁剪放行仍覆盖分类 chip 的辉光(Q1-A「三种 chip 绘制层统一」); Q6/S2 的竖线迁层只作用于 .tag-chip.hr-*, cat-chip 无 HR 边线故不涉及。

旧计划口径差距与验收缺口

  • 旧计划 §02 那句「tag-chip/cat-chip 无 clip-path → 四边完整」是根因分析盲区: 只查了 chip 本体, 没查祖先链; I5「HR 左侧 2px 竖线原样保留」在 hover 态下并不成立; R1 的目检记录只覆盖 site-chip。
  • 验收放行原因: e2e/flux-site-chip-shape-glow.spec.mjs:132-200 主判据只验 site-chip 的 computed clipPath, 旁证只比三种 chip 的 computed boxShadow 是否逐字相同; 静态守阵只读文本。坑档自己写明「DOM 与 getComputedStyle 值完全正常 —— 纯绘制层裁剪, 静态检查与样式值全对也发现不了」。
  • 范围外三件不纳入: ① focus-visible 键盘化(三种 chip 均无 tabindex, 三者一致, 改需动四皮肤共用模板破 I1); ② 旧计划 §02 三条规范漂移(D14 另案); ③ 四皮肤统一(改共用 CSS 破 I1)。另: 三旧皮肤无辉光、crisp 全关辉光均为旧计划 D5 / D8 设计, 与本轮「不统一」无关。

§04实施步骤

S1 · 祖先裁剪放行(主修法, D5)

/* 祖先裁剪放行: 保留内容裁剪语义(不建立滚动容器), 只把裁剪边界外扩给辉光让路 */
html[data-fx-preset] .g-tags,
html[data-fx-preset] .m-tags,
html[data-fx-preset] .g-cat,
html[data-fx-preset] .m-cat {
  overflow: clip;
  overflow-clip-margin: 16px;
}
  • 为什么是 clip 而非 visible: overflow:clip 不建立滚动容器、保留裁剪语义, 避免动到「标签全量展开换行 + 逐行实测行高承接」与吸左首格几何(I3); overflow-clip-margin 只把裁剪边界外扩, 实测 12px / 24px 与 visible 放光效果一致。
  • 16px 的来历: 12px blur + 3px spread + 1px 硬芯余量, 覆盖 stack 最大层 0 0 12px 3px; 不新增任何 CSS 令牌(I2)。
  • 不做 :has() 动态放行: 静息零变化虽诱人, 但每帧样式重算且 focus-visible 分支不命中时辉光仍被裁(D5 备选 C 已否)。
  • 验收: computed 断言四个父容器 overflow === 'clip' 且 overflowClipMargin === '16px'; 红验把 margin 归零或退回 hidden 即红; 四皮肤键集扫描不收集带前缀选择器。

S2 · H&R 状态竖线迁层(仿 S4, D6)

html[data-fx-preset] .tag-chip { position: relative; }  /* 基线 components.css:342 无定位包含块; .f-on(:380) 已有同值, 不冲突 */

html[data-fx-preset] .tag-chip.hr-pending::before,
html[data-fx-preset] .tag-chip.hr-done::before {
  content: ""; position: absolute; inset: 0; pointer-events: none;
}
html[data-fx-preset] .tag-chip.hr-pending::before { box-shadow: inset 2px 0 0 var(--hr-pending); }
html[data-fx-preset] .tag-chip.hr-done::before    { box-shadow: inset 2px 0 0 var(--hr-done); }

/* 本体常态竖线撤下, 由 ::before 承接; hover 时本体仍单独消费 --fx-glow-stack, 两者互不同属性覆盖 */
html[data-fx-preset] .tag-chip.hr-pending,
html[data-fx-preset] .tag-chip.hr-done { box-shadow: none; }
  • 与 S4 的差异: tag-chip 本体自带 overflow:hidden; text-overflow:ellipsis(components.css:344) 且基线无 position; 但 ::before 的 inset:0 画在盒内, 不受本体裁剪; 补 position:relative 后定位包含块成立。.tag-chip.f-on::after 底线占 ::after, 与 ::before 不冲突。
  • 不改 components.css:346-349 原文: 用前缀规则覆盖, 三旧皮肤的 HR 边线(含 prism 的 1px 描边形态)零变化(I1)。
  • 验收: hover 前后 getComputedStyle(el,'::before').boxShadow 含 inset 2px 0 0 且像素采样左侧竖线亮度不归零; 本体 hover 时 boxShadow 仍等于三种 chip 共用的 stack 值; 删掉迁层规则即红。

S3 · 像素采样 e2e(Q3-A / Q7-A)

新增独立 e2e/flux-tag-cat-chip-glow.spec.mjs, 显式取 flux(走 SKINS_ALL, 不改 SKINS 默认值)。沿用只读核实轮已跑通的采样路径: page.screenshot() → 在 page.evaluate 内把截图解码成 Image → canvas.getImageData 采 chip 上/下/左/右外侧 1–4px 处亮度。

  • 判据用相对亮度差, 不用绝对 RGB 常量(避免 deviceScaleFactor / 抗锯齿 / 字体差异导致脆断言); 四边均需显著高于未放行基线。
  • 红绿双验: 把 overflow-clip-margin 归零或 overflow 放回 hidden ⇒ 红; 删 S2 迁层规则 ⇒ H&R 竖线像素红; 恢复 ⇒ 绿。按 smoke.md:104-105 留痕。
  • 不引入 toHaveScreenshot(Q3 备选 C 已否), 现有 e2e/flux-site-chip-shape-glow.spec.mjs 不动 —— 一篇一件事, 旧专题守阵不被稀释。
