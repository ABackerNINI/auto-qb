04

关键设计细节

4.1吸顶贴合(R01)

现状数学: 批量条吸顶上缘 = --head-h, 表头吸顶上缘 = --head-h + --bulk-h, 而 --bulk-h = 条高 + 10(margin) → 恒定 10px 缝。修正:

// app.js _syncBulkHeight: 不再把 margin 计入偏移
const h = el ? Math.round(el.getBoundingClientRect().height) : 0;  // 去掉 + 10
/* style.css 配套: 批量条吸顶时与表头齐平, 底部圆角去掉并以 1px 分隔线衔接,
   两根条读起来是一组连续的吸顶块 */
.bulk-bar { margin-bottom: 10px; }            /* 未吸顶时保留与表格的间距 */
.bulk-bar { border-bottom-left-radius: 0; border-bottom-right-radius: 0; }
.group-head { border-top: 0; }                /* 贴合处不叠双线 */

未吸顶时批量条在文档流里与表头相隔 10px(现状不变); 吸顶后两条零缝堆叠 —— "自然靠近"即此。 断言: 滚动后 groupHeadTop - bulkBarBottom === 0。

4.2筛选条占位(R02)

"清除筛选"占位的原始诉求(出现/消失不推动整行按钮)必须保留, 所以不能退回 v-if。 方案: chip 常驻渲染, 未激活时 opacity: .32 + cursor: default(已有 :disabled), 删除 visibility: hidden。宽度不变 → 整行位置依旧稳定; 右缘从"隐形 chip 右缘"变成"可见 chip 右缘", 空位消失。

4.3删除确认框(R03/R04/R05)

  • 取数修复: _findGroup 改为 decoratedGroups.find(...) || groups.find(...) —— decorated 是原始组的字段超集(key 相同), 对 delGroup/bulkDelete 无副作用, 仅补齐 save_path。
  • 三入口口径统一: 单种子 / 整组 / 批量删除确认框统一为「目标信息 details + 待删成员明细(站点 · 名称 · 保存路径) + 汇报/删文件两选项」。批量删除把选中组展开到成员级(组多时明细区滚动, 头部显示"N 个组 · M 个独立种子 · 共 X")。
  • 尺寸: wide 560 → 720px(路径 R:\... 长度通常 30-60 字符, 720px 下整行放得住); 明细区 max-height 180 → 260px; 值区已可选中复制(保留)。
  • 成员行布局: 一行 = 站点(定宽) + 名称(flex) + 路径(muted, anywhere 折行); 路径与名称同组时路径仅显示一次的优化不做 —— 保持逐行自证, 避免隐式推断。

4.4H&R 筛选(R07)

与现有四个筛选器完全同构(filterDefs 第五项), 模板无需新分支:

// 口径(与组级 H&R 列/hrGroupTitle 完全一致, 后端算好的计数字段, 前端只比较):
未达标 = g.hr_pending > 0                      // 有成员触发 HR 且未满足
达标   = g.hr_triggered > 0 && g.hr_pending === 0  // 触发过且全部满足
无 HR  = 两者皆否 —— 不匹配任何选项(筛掉)
// 选项: [{value:"达标", count: 达标组数}, {value:"未达标", count: 未达标组数}]
// 状态: hrFilter: [] —— 与 tagFilter 等同形, clearFilters/_logout 复位同步补一行
// 虚拟行(搜索未归组): r.hr_triggered / r.hr_satisfied 同口径换算(filteredGroups 已有先例)

图标用现有 sprite #i-hr, 语义色 .ico-f-hr → var(--hr-pending); strip-note 文案追加 HR 分支; HR 列排序已存在, 筛选与排序互不干扰。

4.5单种子视图(R08)

数据: 已归组种子 = filteredGroups 成员平铺(全部筛选/搜索口径天然继承); 未归组种子后端补齐 —— ensure_group_state 增加 singles 数组, 形状与成员视图完全一致(name/site/save_path/HR 字段都在), 由 _build_group_view 同一快照重建, 走同一版本门控(rid)。 可行性已核实: store.view_changed 对任意种子的 _VIEW_FIELDS 变化与组成员变化都置真, singles 不会读到陈旧状态。

# qbmanager.py(新增, 供 ensure_group_state 调用)
def _build_singles_view(self) -> List[dict]:
    grouped = {h for members in self.store.groups.values() for h in members}
    return [ self._member_view(r) for r in self.store.by_hash.values()
             if r.hash not in grouped ]        # 成员视图字段构建函数从 _build_group_view 提取复用

前端:

  • 列模型新增 TORRENT_COLUMNS: name(锁定) + site/state/速度×2/总上传/大小/分类/标签/进度/做种时长/分享率/save_path(可选)/hash —— 与 DETAIL_COLUMNS 大部分同 key, 列宽记忆按 key 走新 page 名 "torrent"。
  • 视图开关: 状态条左端或列选择器旁的分段控件(图标 i-cards / i-list, sprite 已有), 持久化 autoqb.ui.view。
  • 交互复用: 行点击=选中(member 语义), Ctrl/Shift 范围选择(shiftMemberSel 需视图感知: 单种子视图下在平铺列表取范围), 右键=单种子菜单, 批量条对 hash 直接生效 —— 全部现有机制, 无新命令。
  • 排序: 独立 sortedTorrents(默认 added_on 降序, 三态循环同现规则)。
  • 空态/加载: 复用 .empty; singles 与 groups 同请求到达, 无新轮询。

4.6信息栏双模式(R09)

  • 状态: railMode: "side" | "top", localStorage autoqb.ui.rail; 切换按钮在顶栏(列选择器旁, 新图标 i-panel), title 动态。
  • top 模式: 紧凑条渲染在第一个 .sticky-head 内(状态条之后) —— 与顶栏/状态条构成一体的玻璃吸顶块, --head-h 由 _syncHeadHeight 实测自动长高, 表头/批量条/左栏偏移零额外代码联动。同时 .layout 切单列、原 .rail 不渲染。
  • 两排布局(防拥挤): 第一排 = 下载速度 + 上传速度(重点信息, 15px 加粗 + tabular-nums + 语义色图标); 第二排 = 辅种分组 · 种子总数 · 刷新间隔 · 今日流量(上/下, 保留历史入口按钮) · 限速对照(保留 mismatch warn 色与手动锁图标), 11.5px muted 胶囊, 条件渲染与左栏卡片一致(未启用限速曲线则不出现)。
  • 响应式: 900px 以下 top 模式第二排允许换行(与状态条同策略)。

4.7视觉刷新(R10)

  • 配色(令牌级): 底色系从高饱和藏蓝转向更中性的冷灰蓝(降低大面积底色的色彩倾向, 前景层级不动); 分隔线统一降为 hairline 档; 阴影降档(shadow-2/3 减淡); 语义色(HR 橙/达标青/状态六色)保留 —— 它们是功能色。全部走 :root 单点, 不散写。
  • 图标: sprite 单点追加: i-panel(信息栏模式切换)、单种子视图复用 i-list/i-cards、H&R 筛选复用 i-hr; 顺带把线宽/端点统一复核一遍(16×16 + stroke 1.7 约定不变)。
  • 动效(手感级): ①视图/信息栏模式切换 200ms 淡入位移(复用 page-in); ②筛选弹层/列选择器已统一节奏, 补齐弹层关闭淡出; ③批量条出入场已有; ④首屏骨架不做 —— 轮询 2s 场景下收益低。红线: 不做行入场动画与数字滚动(pitfalls 明文: 2s 整表重渲染会反复播放); 全局 prefers-reduced-motion 降级已有。

风险与红线(不动清单)

  • 生产文件: config.yml、auto-qb-data/ 不碰(AGENTS.md 红线)。
  • newui 不碰: 本轮仅旧 UI; 重设计决策里的"旧 UI 视觉冻结"被用户本轮显式要求(旧 UI 也要视觉刷新)取代 —— 冻结仅限 newui 相关文件, 工作区已有的 newui/ 副本与 index.html 入口链接保持原样不提交不删除。
  • JS↔DOM 契约(style.css 头注 + pitfalls): .group-head/.detail-head(列宽拖拽锚点)、gridStyle 列数同源、.search-hit、.ctx-menu、.sticky-head + --head-h、tpl-ce-field、sprite #i-* 单点、toast/确认框单例 —— 全部保留, 新功能以新增类/新增 page 方式接入, 不改既有挂钩。
  • 列宽存储: 单种子视图新增 page 名 "torrent" 属向后兼容扩展(loadColState 对缺失 page 返回空), 不需要升 COLS_STORE_KEY 版本; 若后续重排 group/detail 列集则必须升版本(v4 → v5)。
  • 后端: 只在 qbmanager/web.py 加 singles 透出, 不碰命令队列/单一写线程假设; ensure_group_state 的 rid 门控语义不变(singles 与 groups 同版本返回, 前端 updated !== false 分支一并替换)。
  • 动效红线: 不做行入场/数字滚动(pitfalls 第六轮条目); 全部动效尊重 prefers-reduced-motion。
  • HR 口径: 达标/未达标只消费后端算好的 hr_triggered/hr_pending, 前端不重算模板/阈值(pitfalls: HR 判定前后端各写一遍 = 自定义标签立即失效)。
