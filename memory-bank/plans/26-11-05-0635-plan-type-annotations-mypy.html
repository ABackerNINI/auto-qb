§01目标与设计原则

为什么做: issue 26-09-21-1408(2026-09-21 入池)指出全库类型注解覆盖低、pyproject 无 mypy/pyright 配置, 类型回归无静态防线; 二评报告(26-10-30-0237)§8.6 又把 RUF013 隐式 Optional 债(批C/批D/批T/批GH 点名)并入本池备注, 要求处置时合并处理。

做到什么程度算成(标准清偿口径, D1):

  1. mypy 接入跑通: [tool.mypy] 配置 + dev.typecheck task id + 豁免面之外全绿;
  2. RUF013/隐式 Optional 债全库清零(含二评点名处);
  3. 优先模块(config/core/rules 插件层/torrents)注解补全;
  4. 抵抗面(tray/expr 闭包/webui 裸 dict)进 per-module allowlist, 且有守阵保证 allowlist 只减不增;
  5. issue 置 Done, rules/webui 剩余覆盖缺口作为递减目标留池内备注。

设计底线/不变量:

  • 行为零差异: 全部改动限签名级(注解)与显式类型表述, 不改运行逻辑; 任何一处注解改动若需改函数体, 停下来单独评审。
  • 红线不动: config.yml、auto-qb-data/ 不碰; minimal.yml 等示例配置不动。
  • 闸门不放松: 覆盖率闸(Windows 99.0)与 test.full 既有判据不动; typecheck 不进提交闸门(D3)。
  • allowlist 只减不增: 豁免清单冻结进守阵, 新增豁免必须显式改守阵 —— 摩擦是有意的。

痛点本质: 注解债已从「好看不好看」变成「防线缺位」—— 312+ 处签名宣称 T 实收 None, 类型检查视角下全部误报; 二评 4 个批次各自独立撞见同一类问题, 静态工具缺位让这类债只能靠人工评审发现。

§03方案总览

主线: mypy 全库默认宽松起跑 → RUF013 债机械清偿 → 优先模块补全后逐个收紧(disallow_untyped_defs) → 抵抗面 per-module 豁免进 allowlist 并冻结守阵。与 issue 原建议「渐进接入, 先 torrents/config 后 mixins/web, allowlist 递减」同向, 落点按 2026-11-05 实测缺口修正为 config/core/rules 优先(webui 剩余面大, 留递减)。

§04实施步骤

S1 · mypy 接入

  • [dependency-groups] dev 加 mypy(PyPI 实查定版, 照 yapf 条目注释惯例写明版本依据), 跑 commands run env.sync。
  • [tool.mypy]: python_version = "3.12"(与 requires-python 单点对齐); 全局起步宽松(不开 strict, 依赖缺 stub 的三方库按 ignore_missing_imports 处理); 分级用 [[tool.mypy.overrides]] per-module。
  • .mypy_cache 确认进 .gitignore(若已被通配覆盖则留一行注释指认)。
  • .commands/dev/config.toml 照 dev.fmt 形态收录 dev.typecheck(run = ["uv run mypy <args>"], timeout 兜底 —— mypy 缓存目录与 yapf 同族沙箱风险, 参照 pitfalls/testing/sandbox-tool-cache.md)。收录前先跑 task-command-surface 消费点检查(pitfalls/kb/task-command-surface.md: run 条数/生成器集合可能被测试或文档写死断言)。
  • 验收: commands run dev.typecheck 跑通并产出首份全库错误分级清单(该清单只进本档案执行记录, 不散抄)。

S2 · RUF013 债全清

  • AST 脚本定位全库 arg: T = None(含多行签名), 产出清单按子包分批; 每处改 arg: T | None = None(PEP 604, 3.12 运行期原生支持, 无需 future import)。
  • 逐处目检防语义误标: 默认 None 但实现从不接受 None 的(如二评 C-02 判定过的曲线注入点属「None 回落默认」, 是合法 Optional; 反例是「None 必然炸」的)—— 属后者的不是注解债而是潜在 bug, 单独入池不静默改。
  • 二评点名处逐条核销: core/curves.py:76、config/validation ×2、notify ×2、webui 批量面随 S2 全库扫描一并覆盖。
  • FastAPI 边界注意: routes 层 body: dict = None → body: dict | None = None 语义等价; 不动无默认值的注解(参照 pitfalls/backend/deps-upgrade-2026-10.md: FastAPI 0.x 按注解决定 422 行为); dataclass 默认值同步改写。
  • 分族跑定向测试(改哪个子包跑哪族), 全部完成后 commands run test.full。
  • 验收: AST 复扫隐式 Optional 归零; mypy 对应错误类清零; 全量绿(数字见 kb.baseline)。

S3 · 优先模块注解补全

  • config(模式重复度最高, 先做): loaders/validation 边界函数补 spec: dict 入参、parse: Callable[..., T] | None = None 类参数、-> XxxConfig 返回。
  • core: qbapi.py 27 处 Facade 方法补返回注解(**kwargs: Any 转发面保持); qbmanager/module/state/taskqueue 机械补齐。
  • rules 插件 LSP 对齐: conditions.py 13 个插件类 __init__(self, spec: ...) 与 match(...) -> bool 对齐基类签名; actions 同理对齐 -> ActionResult。registry 的 PluginEntry.decl: Any/executor: Any 既有意逃逸口保持不动。expr/ 闭包工厂(env.py)高阶链噪音大, 不在此步强标, 留 allowlist。
  • torrents: 已 94% full, 查漏即可。实施修正(2026-11-06): config 补全落点按 9 文件 78 处执行(writer/migrations 一并查漏, 不止 loaders/validation); torrents 查漏 4 处; core 批次 qbapi Facade 返回注解实补 37 处(上行原写 27 处为粗点数)。
  • 验收: AST 复测四个目标面 full 率(前后对照写进执行记录); 该四面子集上开 disallow_untyped_defs 可跑绿。

S4 · allowlist 分级 + 守阵

  • 抵抗面 per-module 豁免(overrides ignore_errors = true 起步): tray.*(GUI 三方回调)、rules.expr.env(闭包工厂)、webui routes 中裸 dict payload 重灾区按首跑错误量决定豁免粒度(优先用 error code 级豁免而非整模块, 收窄递减空间)。
  • 已全注解面(config/torrents/core 选定面)加 disallow_untyped_defs override —— 这就是「递减」的推进方式: 模块从豁免侧迁到收紧侧。
  • 新增 tests/test_mypy_allowlist_guard.py: 静态扫描 pyproject 的 overrides 清单 vs 测试内冻结清单, 出现新增豁免模块即红; 照 test_test_plan_docstring_guard.py 形态(合成源红验内建); 文件头带「## 测试计划」docstring 清单(机械守卫强制)。
  • 验收: commands run dev.typecheck 豁免面外全绿; 守阵用例通过 + 掐掉守阵后红验成立; commands run test.full 全量绿。
