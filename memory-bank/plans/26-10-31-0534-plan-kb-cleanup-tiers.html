§01目标与设计原则

目标

降低 agent 读库的 token 消耗与噪音、消除自相矛盾的过时约束，同时不丢历史 —— 「删掉」和「不用每次都读」是两件事，本计划只做后者，前者留到观察期之后单独授权。

设计主轴

按价值维度分级，而不是按时间一刀切。理由：本库 37 天产出 710 条基线切片（≈19 条/天）、124 条活动切片（≈3.9 条/天），日历时间与「有没有被验证过」几乎不相关 —— 一条 9 月的坑档可能仍是唯一判据单点，一条上周的档案可能已经完全失效。

设计底线 / 不变量

  1. 本计划不删除任何文件（R0–R3 只打标与外迁；删除最早在 R3 之后单独一轮，且需再次显式授权）—— 见 §05 P1。
  2. 判别法不随叙事搬走：L1 / L2 处置后，主档摘要里的判据单点必须仍在主档可读位置。搬走的只是叙事、事故时间线、踩错的路。
  3. 生成物不手改：所有 _index.md 由 kb.index 生成，任何改名 / 删除 / 改摘要后一律重跑生成器，冲突的解法是重跑不是人工合并。
  4. 外迁原文逐字节原样搬，不手抄 —— 手抄会引入不可见的行尾 / 缩进漂移（pitfalls/git/editing-traps.md 记的就是这类事故）。
  5. 保守默认：kb.tier 所有高风险动作默认 dry-run，purge 强制 --apply，闸门不通过直接退出。

2.5 机制缺口（根因）

现有防线只有两条：cap 外迁（治文件体积，不治条目数）与 CLOSED_KEEP（治索引，不治目录体积）。缺的第三条是「按价值 / 时间分级」。

  • 外迁的触发条件只有「主文件撞 cap」 —— 完结与外迁是两条独立的轴，一条已完结但没撞 cap 的条目会被无限期保留在原地。
  • attachments/ 在 EXCLUDED_DIRS、不计 cap —— 所以外迁只治 cap、不治目录体积。issues/attachments/_archive.md 107KB 就是明证：索引降下来了，目录一点没小。
  • plans/ 与 tasks/ 连 CLOSED_KEEP 都没有（issues/ 有），这条防线可以直接复制。

§03方案总览

3.1 四级生命周期

级含义判据处置位置
L0 活跃判别法仍常被引、近期仍复发近两轮内有复发，或守阵字段为空但判别法是唯一单点原样保留主档
L1 降噪规则有用，只是啰嗦结论已收口，但复发流水 / 踩错的路 / 事故时间线占了大半篇幅删叙事，不挪位置，判别法不动主档
L2 外迁整段只剩排障价值已彻底解决，叙事对日常判断零贡献整段搬 attachments/，主档留指针附件
L3 待删观察期满，可批量清L2 + 守阵齐全 + 反向引用清零 + 跨越 2 轮零复发本计划不执行删除（见 §05 P1）附件

为什么 L1 不直接合并进 L2：那批约 77 个文件正是日常最可能撞上的，搬走就多一次跳转；而 attachments/ 不计 cap，搬过去的东西永远不会被 cap 守卫再提醒一次。

3.2 分级标记落点

写在主题文件头部区第 4 行：> 等级: L2。已查证：生成器只解析三行头的三个具名字段（# 标题 / > 摘要: / > 触发:），头部区是「首个 ## 之前的行」，额外行不干扰索引生成。不建总表（D8 选 A：访问频率不高，总表的收益不抵它与文件的漂移成本）。

3.3 五轮分期

轮范围动作性质产出
R0 工具新建 kb.tier四动作 + 守阵测试 + 基线切片代码批量能力就位
R1 试点pitfalls/git/ + ops/（24 文件）定级 → L1 删叙事 / L2 外迁 / L3 打标 → 验证 → 重跑索引文档判据校准
R2 铺开其余 5 类（226 文件）套用 R1 判据，按批推进文档全库定级完成
R3 体积tasks/ plans/ testing/baselines/ activeContext/补 CLOSED_KEEP 出口 + 老基线外迁 + 切片蒸馏代码 + 文档索引回落 cap 内
R4 根治复发榜 11 个高频坑只分堆 + 立项，不动手文档三堆分类表

R0 必须最先做：R1 打标、R2 批量外迁的工具就是 kb.tier。若按原顺序（R4 才做命令），R1/R2 得手工打 250 个文件的标、手工搬外迁段 —— 既慢又必然漂移。

R1 · 试点轮：git/ + ops/（24 文件）

  1. 逐个定级，写入 > 等级: 行。
  2. L1：删叙事（复发流水、踩错的路、事故时间线），判别法与摘要里的判据单点一字不动。
  3. L2：整段原样搬 attachments/，主档留一行指针；顺带修正 §2.3 表里的过时约束（这几条正好都在 git / ops 两类里）。
  4. L3：只打标，不删。
  5. 验证：doc.caps + kb.check + doc.links + test.full（试点轮跑全量）+ 重跑 kb.index。

R2 · 铺开轮：其余 5 类（226 文件）

套用 R1 校准后的判据。分批粒度见 §05 P2。每批只跑 test.quick + doc.caps + doc.links（外迁会引发链接深度变化，必须当场验），轮末再跑一次 test.full。

R3 · 体积轮：索引与目录

  • tasks/ 与 plans/ 补 CLOSED_KEEP=60（与 issues/ 同值、同一套常量语义），全量清单另落 attachments/_archive.md。粗算 tasks/ 保留 82 条（60 完结 + 22 在办）后索引约 8.7k 字符，安全落回 25,200 cap 内。
  • reports/ 不动：cap 才 39%，且 69 份是审计 / 决策依据 —— 藏起来比占索引更糟。
  • testing/baselines/：老切片外迁（口径已明说「最新一条 = 事实源，老的是不可变快照」，信息损失最小，收益/风险比最高）。
  • activeContext/：配蒸馏节奏而非一次性清理 —— 完结专题沉淀进 progress/ 后删切片。
  • 验收：test.full（含新增 CLOSED_KEEP 守阵）+ doc.caps（验证索引回落）+ kb.check。

§07风险与对策

风险触发条件处置
误删仍活跃的判别法250 个主题文件里 64 个压根没写 守阵 字段 —— 没有守阵就等于「根因有没有进代码/测试」这个判据缺失，凭「很久没复发」判死必然误杀无守阵字段的条目不进 L3；要进必须先补齐守阵或明确判定「无需守阵」
反向引用断链conventions/webui.md:82,107,124、webui-scope.md:71-74、AGENTS.md:11 都在点名具体坑档；modules.md:21、checking.md 亦然删除 / 改名前 grep -rn 全仓（含 conventions/、AGENTS.md、skill 的 references/）
外迁后链接位移附件深度 +1，所有相对链接要前缀一层 ../搬完立刻跑 doc.links 收口
复制现有附件的写坏形态唯一 web-ui 附件是逐字符一行（4,935 行 / 18,579 字节 / bytes-per-line=3），与 editing-traps.md 自己记的写盘事故同源按原换行风格原样写回，写完验 bytes/行 数比 与 b.count(b"\r\n")；该 artifact 不计 cap 所以守卫抓不到，只有人读能发现
