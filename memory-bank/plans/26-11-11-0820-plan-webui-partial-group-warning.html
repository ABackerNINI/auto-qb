§01目标与设计原则

背景

辅种组 = 同 save_path + 同文件表归组,组内成员共享同一份物理文件(磁盘只占一份,static/shared/app.js:53)。对组内部分成员做带文件删除或移动保存路径,会静默破坏其余成员(文件被删/被搬走,其余成员仍指向原路径),且不可逆 —— 这是生产数据面,不是体验面。

目标(做成判据)

  • 三个落点预警上线: 删除确认框部分组行 / 设定位置(迁移关)确认框 / 设定位置(迁移开)扩张披露条;
  • 「部分组」谓词单点实现并有守阵;
  • 非部分组与整组入口行为零变化(组键入选/单成员组/虚拟行/不带文件删除,流程与文案均不动);
  • 后端纵深缺口入池占位(issue 26-11-11-0823),不在本轮实施。

设计底线 / 不变量

  1. 不骚扰原则: 无害路径不提示 —— 不带文件删除正是辅种退役的正常路径;整组入选、成员全选(选择袋自动晋升组键)、单成员组、虚拟行(未归组命中)一律不触发。
  2. 谓词单点: 部分组判定一处实现,删除链/移动链共用,与 _findGroup/memberByHash 同源解析面(selection.js:551 先例)。
  3. 复用既有弹窗体系: details/checks/tone 结构与 HR 风险行范式(delete_flow.js:109),不新造弹窗组件。
  4. 零 API 契约变更: 纯前端;/api/torrents/bulk 请求/回执形状不动。
  5. 伤害面值得多一次点击,知情面不打断流程(D3/D4 的分界线)。

§02现状与痛点

行号均为取证当时(2026-11-11 08:20),漂移后按符号与 grep 词重定位。

选择模型(事实)

  • 选择袋双通道: groupKeys(整组,组键级联全组成员)+ memberHashes(散员),后端展开去重单一权威(commands_torrents.py:632-634 组键模式 DLG-02);
  • 组内成员全选 → 自动晋升组键入选;撤到不全 → 组移出,残留「半选」态(selection.js:321、selection.js:451-453)—— 部分选中是稳定可判的常态。

删除链现状

四入口(右键组/右键种子/整集整剧/批量)统一走 _deleteFlow(delete_flow.js:144)→ _deleteDetails(:116,目标/成员/站点/保存路径/总大小[+实际占用] 五行结构)→ _confirmDelete(:278,「同时删除磁盘文件」默认不勾)。确认框有 HR 风险点名行(tone error,:153-159 消费 _hrRiskOf)但没有任何「只选了组内一部分」的提示 —— 带文件删除部分组时,共享文件被物理删除,组内其余成员必然缺文件。

态行为现状问题

主线

落点触发条件形态拍板
① 删除确认框删除目标含部分组_deleteDetails 末尾追加一行(tone error、wide,HR 风险行同款);文案绑定「同时删除磁盘文件」勾选语义D5

§04实施步骤

步内容验收判据
S1谓词单点: selection.js 新增 _partialGroupsOf(keys, hashes) → [{key, name, sel, total}]。判定: 真实组(!virtual 且 total>1)有成员 ∈ hashes ∧ 组键 ∉ keys ∧ sel<total;hash→组反向查 decoratedGroups(与 _findGroup(selection.js:551)同源,不用 filteredGroups 独走)守阵覆盖五形态: 组键整组 / 成员全选(晋升) / 部分选中 / 跨组混合(部分+整组并存) / 单成员组+虚拟行(均不触发)

§06拍板记录

#结论(2026-11-11,用户「按推荐」)被否备选
D1预警面=三项: ①带文件删除×部分组 ②设定位置×迁移关×部分组 ③设定位置×迁移开×部分组(扩张披露);「整组移动开关」=relocate.enabled 两态rename_fs/转移/跳检/重校验/恢复强制开始/不带文件删除/元数据类均不入(理由见 §02 排除面)
D2谓词: 真实组(成员数>1)有成员入选 ∧ 组键不在 groupKeys ∧ 未全选;单种入口落在多成员组 = 1/N 照触发;组键入选/全选晋升/单成员组/虚拟行不触发;跨组只列被部分选中的组—
D3迁移关+部分组移动: 提交时弹确认框(error 档),确认才发;非部分组维持现状直发A 警示条直发(伤害不可逆,不够);C 阻断(「挪一个种子单放」存在合法意图,过硬)
D4迁移开+部分组移动: 设定位置对话框内嵌披露条(warn 档,开框即见),不加确认步骤B 确认框(与既有迁移 confirm 回路叠加成双确认);C 只靠回执文案(事后才见)
D5删除链: 部分组时确认框恒显一行(tone error、wide),文案绑定「同时删除磁盘文件」勾选语义;details 静态结构零改动B 改造 _openModal 支持 details 随勾选联动(动通用弹窗结构,影响面全局)
D6本轮仅前端;后端对「部分组×带文件删除」「部分组×迁移关移动」的 fail-closed 拒收入池待排期(issue 26-11-11-0823)B 同轮做后端拒收(API 契约变更+测试面扩大,超出本轮范围)
