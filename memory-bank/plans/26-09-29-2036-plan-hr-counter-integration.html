结论速览

三步走：M1 核心对平机制（上线即现状 —— 所有 adapter 默认无计数，全路径逐字节等价今天）；M2 首批站点启用（CarPT 分页区间形 + BTSchool，前置样张与口径校准）；M3 退役与打磨（计数站点免人工零行戳、告警升级、可选优化）。M1 不依赖任何拍板即可开工，行为变更点只有一个：批量「未列出」签发闸门多一个 AND 条件。

问题本计划的答案依据
改多大？ 纯增量，~6 文件 model 加 3 个 additive 字段、adapter 基类加 1 个默认空钩子、service ~40 行、events 1 条文案、status/report 展示、测试；无配置键、无 schema 版本抬升、无迁移脚本

什么必须先拍板？ 只拍 P1–P3 M1 开工不需要等样张；M2 需要 D2 样张（用户侧动作）+ 校准策略（推荐方案 A）（§7）
§1

背景与目标

1.1 报告结论承接

可行性报告 26-09-29-1803 已论证：站点 HR 页计数是清单的校验和，不是清单的替代品 —— 它补上现有防线（守恒 / 零行戳 / 行序 / 末页标记）全部缺失的「绝对量」轴，唯一能在当波报警 B / C 档翻页标记失效导致的批量误放行（报告 §3.1：C 档深处未达标种子被当作「未列出」签发放行，站点侧仍在计它未达标）。两站真机实测均有计数，收益即期。本计划把报告 §7 集成草案落成可执行的修改项。

1.2 目标

  • 堵误放行洞：站点报了计数的档，「翻到末页」还必须「行数对平」才承认全深度覆盖；对不平当波冻结批量签发，下一波自愈。
  • 零行人机环节退役（限计数自证空集的站点）：count=0 ∧ rows=0 视同人工确认戳，无需 --hr-confirm-empty。
  • 截断可量化：预算截断波的 rows vs claim 差值写进 wave.notes 与走查报告，排障直接看缺口。
  • 改版检测双通道：计数与表格结构在页面上是解耦的两个区域，表格塌了计数还在（或反之）可当波报 parse 类告警，不再等连续 3 波失效升级。

1.3 非目标（本轮明确不做）

  • 不加任何配置键 —— 计数可用性是 adapter 层的站点事实而非用户决策（黄金法则 4 的配置校验面自动免疫）。
  • 不缩短失踪观察期（报告 §5.1 已裁：省的只是保守方向的管束时长，换来的风险敞口不值）。
  • 不动 HR 上限的处罚面（用户裁决）；徽章总数轴互证列为备选项缓做（§7 P3）。
  • 不做末页追翻省略（报告 §5.1 定性为优化非简化，收益偶有，风险面新增 —— 缓做，§7 P3）。
  • 不改 config.yml / 不动红线文件；不引入绕开单一写线程的并发代码（计数随 HrLaneState 走站点文件，多实例无感）。
§2

设计定稿

报告 §7 是草案；本章是对照代码实况（基线 b6ce666）收口后的定稿，与草案的差异点逐一说明理由。

2.1 提取契约：adapter 逐页上交「本页能证到的档位声明数」

采用报告草案的签名 parse_counters(html) -> dict[lane, int|None]，落点在 adapters/base.py 的 HrAdapter（:34），基类默认返回空 dict（= 现状）：dict 而非逐档单值，是因为 tab 形站点的计数条在任何一档的任何一页都同时带着全部档位的数（考察中 (12) · 已达标 (3) · 未达标 (2)）—— 第 1 页一次解析即全档有据。契约三条：

  • 只在本页能证到该档总数时才返回该键：tab / 摘要形任意页可证；分页区间形（CarPT 实证）只有「无下一页」的末页能证（区间终点 = 档内累计行数，1 起含端），早停波拿不到总数；空表页无标记 ⇒ 无键。
  • 键缺 = 无证据 = None 降级，绝不猜测、绝不拿「目前为止的行数」冒充总数。
  • 未实证口径不覆写：子类只在样张实证「计数 == 全深度翻页实抓行数」后才覆写本方法（§6 R1 铁律）。

实施期补充（M1 落地后核对代码时识别，M2 定形时必核）：本签名不带档位参数 —— tab / 摘要形无碍（计数条同页带全档），但分页区间形站点须由页面自身辨认所属档位（如 CarPT 页内的活动 tab 标记 / 档位标题），样张核对时先确认页面确实携带这一信息；若页面不带，M2 需回到计划改签名（如 parse_counters(lane, html)），不可让 adapter 记「上一页 scope」之类的隐式状态去猜。

service 侧合并规则：每档取首个非 None（wave.counter_claims.setdefault(lane, v)）。tab 形即第 1 页的值（波内最早快照）；分页区间形中途页无键、末页才非 None，自然胜出。波内声明的临时账挂在 _WaveContext（service.py:292 区）新增字段 counter_claims: Dict[str, int]，随波生灭；持久化走 HrLaneState 的 additive 字段（§2.3）。

提取调用点：波次引擎每页 parsed = adapter.parse_page(lane, html)（service.py:614）成功解析之后、停翻判定之前 —— 与解析同源同一份 HTML，零额外请求，频控面零变化。

2.2 收紧落点：改 releases_enabled 一处，不改 full_depth 字段本身

报告草案写的是「full_depth and (count_claim is None or rows == count_claim)」。对照代码，full_depth 有两个赋值点（service.py:646 ②到期段停翻 / :656 末页）和四类消费点（releases_enabled :954、缺席证明 _absence_proven_all :1325、观察期位置覆盖 _position_covered :1305、状态展示）。把 AND 折进赋值点会连带收紧观察期出口与终态冻结 —— 超出报告划定的「只影响缺席证明 → 批量签发」范围。定稿：字段语义不动，闸门单点收紧：

# service.py::_finish_wave，在 releases_enabled 计算(:953)之前，~12 行
for st in lane_states.values():
    claim = wave.counter_claims.get(st.lane)
    st.count_claim = claim
    st.count_match = None if claim is None else (st.rows == claim)

depth_broken = any(st.ok and st.full_depth and st.count_match is False
                   for st in lane_states.values())

releases_enabled = ( 既有三条件 ) and not depth_broken

为什么这等价于报告的语义表达式且范围更精确：批量签发的缺席证明唯一入口是 _sign_releases（:1117）→ _absence_proven_all（:1310），而它只在 releases_enabled 为真时被调（:959-960）—— 闸门在源头关死，下游 _absence_proven_all 的 if st.full_depth: continue（:1325）一行不用改就自动继承收紧。full_depth 字段保持「结构性翻页到底 / ②到期段」的原始语义，「计数对平的全深度」由 count_match 联合表达，二者在唯一消费闸门处合流。连带效应逐项核对：

路径受影响？说明
批量「未列出」签发（:959-960 → :1117）是（唯一行为变更）depth_broken 波整波不签发，下一波自愈 —— 与守恒违约同款处置方向
观察期出口（:943 _advance_observation）否执行序在闸门之前，且既有注释已明示「观察期出口与批量签发解耦」（:957）—— 语义自洽
终态冻结（:962 _freeze_terminal）否走位置覆盖证明（:1293），不依赖本闸门；报告口径「终态冻结不动」逐字成立
命中 / 管束（:633 行处理、判定侧 resolve.py）否行处理在闸门上游；判定侧只读档位结论，不读覆盖证明
新鲜度 / 健康 / 复用窗（:966、:986）否healthy 看 rows > 0 or full_depth，与计数无关；有效波照常设复用窗

字段类型 / 默认语义

to_json / from_json（model.py:330 / :343）同步三键；不抬 schema 版本（先例：v3 观测字段 additive 不抬版；旧程序读新文件时 from_json 忽略未知键，双向兼容）。

⚠ 陷阱 T1

旧档案反序列化的 None 语义

from_json 里 count_claim 不能走 _as_int(raw.get(...)) 缺省路径 —— 旧站点文件没有该键，raw.get 返回 None，_as_int 会把它变成 0，于是所有存量档案瞬间变成「声明 0 行」⇒ 全站永久 mismatch ⇒ 批量签发永久冻结（正是要防的那个事故，换了个入口）。必须显式判空：claim = raw.get("count_claim"); count_claim=None if claim is None else _as_int(claim)。守阵：旧版站点文件（无三键）加载后 count_claim is None 且 releases_enabled 判定与旧逻辑逐位一致（§5 T3）。

2.4 mismatch 的判定边界与告警

mismatch ≠ 行数不等。只有「本波承认了全深度」的档才可能 mismatch —— 预算截断 / ①③停翻的波 rows < claim 是预期内的量化差值（还没翻完），写进 wave.notes（如 档位 C 截断: 实抓 20/声明 50, 差 30 行）与走查报告，不告警不冻结。判定矩阵（报告 §3 记忆点的落地版）：

full_depth ∧ claim≠rows → mismatch: 冻签发 + counter_mismatch 告警 · claim=0 ∧ rows=0（全档）→ site-attested empty · claim>0 ∧ rows=0 → page_changed 硬告警 · claim=None → 现状不变 · 截断波 rows<claim → notes 量化差值（信息性）
  • 当波告警：mismatch 走 _warn_parse（service.py:1231，已含节流）+ 新事件 events.counter_mismatch(site, lane, seen, claimed)（events.py，[HR 页面改版] 前缀族，:63 order_broken 同款）；文案必须带 §6 R1 的引导：「若连续多波对不平，可能是计数口径校准错误 —— 请跑 --hr-once 走查核对或摘除该站计数覆写」。
  • 升级：count_mismatch_streak ≥ LANE_FAIL_ALERT_STREAK（=3，service.py:154）时以 ERROR 级再报一次（模式照抄 _maybe_alert_lane_fail :1241，只提示人不改行为）—— 这是对「服务端缓存陈旧偶发不平」与「口径校准错误永久不平」的区分信号（§6 R1/R2）。
  • 计数>0 ∧ 行数=0：整表被吃光 / 第 1 页即被截的显式信号，按报告草案走 events.page_changed（:58）硬告警，同样冻结（0 ≠ claim 自动使 depth_broken 成立）。

2.5 零行自证：确认戳的计数等价物

现口径：confirmed_empty = zero_rows and data.empty_confirmed_at > 0（service.py:952）。追加 OR 分支：

confirmed_empty = zero_rows and (data.empty_confirmed_at > 0
                                  or all(st.count_claim == 0 for st in lane_states.values()))

语义：三档声明全部非 None 且全为 0 才算站点自证空 —— 任一档 None（分页区间形空表无标记、或计数站点个别档未证到）都自动落回人工戳路径，None 参与全称量词即为假，保守方向自动成立。计数自证空的波：zero_listing 软提示不再触发（:992-995 的 not confirmed_empty 条件天然覆盖），签发照常 —— 报告 §5.1「人机环节整个退役」在 M1 机制层一次到位（M2 启用站点后才实际生效；M3 收尾改 CLI / WebUI 提示语）。分页区间形站点（CarPT 若仅此形态）维持人工戳不变 —— 空表页无标记，无法自证空集，这是设计而非缺陷。

2.6 展示面

  • CLI --hr-status（status.py:198-210）：档位行在 {pages}页{rows}行(全) 基础上补计数 —— rows/claim 形态（如 17行/声明17），count_match is False 时显式标 对不平。
  • 走查报告（report.py 档位段）：同口径补一列；截断波的差值行直接可见（§1.2 第三条目标）。
  • WebUI：M3 打磨项（站点状态块档位行补计数徽章），不在 M1。

  • 验收：全量测试绿 + 走查实测数字记入档案进度日志。

§6

风险推演

风险后果处置（设计内消化）
R1 口径校准错误（首要，报告 §8.1） 永久 mismatch = 批量签发永久冻结（骤降保护同款误触面换入口） 铁律「宁可不用，不可错用」进 parse_counters 覆写约定：样张未实证「计数 == 全深度实抓行数」一律返回空 dict；告警文案自带「可能是口径校准错误」引导摘除；连续 3 波 ERROR 升级；M1/M2 分离保证机制错误与校准错误可分别定位
R2 服务端缓存陈旧（§8.2） 偶发 mismatch 该波不签发、下一波自愈（方向保守，代价一轮波）；偶发与持久的区分靠 streak 升级信号
R3 站点改版把计数移走 / 改名 解析不到计数 返回空 dict ⇒ 自动降级现状（fail-open 到今天的行为）；与表头结构区分器（ParsedScope.header_found，base.py:19）是解耦双通道，谁先报警都行
R4 分页区间形空表无标记 该形态站点无法自证空集 设计内：人工戳机制原样保留（§2.5）；只有 tab / 摘要形兑现零行戳退役
R5 波内清单漂移 TOCTOU（§3.3） 页间计数 / 行数不一致 首非 None 取第 1 页声明；行数对不平时冻签发下波自愈；只冻签发不撤命中，与既有防伪失败方向一致
R6 迁移陷阱 T1 旧档案 count_claim 被读成 0 ⇒ 全站假 mismatch 永久冻结 from_json 显式判空（§2.3）+ T3 旧档案加载守阵 + 红验
R7 ②停翻 × tab 形计数（M1 实施期识别） ②到期段停翻的档 full_depth=True 但深处到期行未翻 —— tab 形计数若把它们计入总数，rows < claim 每波成立 ⇒ 批量签发持续冻结且不 self-heal（假冻结，R1 同款症状但非校准错误） M2 校准必验项：样张核对「②停翻波的 rows vs claim」——计数口径若含到期段深处行，则该口径对 ②停翻波不可用（按铁律该站不启用计数，或 M2 另立计划给 ②来源的 full_depth 加可区分标记后再豁免该门，取舍届时拍板）
§7

拍板点

立项与排期。按本计划 M1 → M2 → M3 推进（推荐）。M1 零拍板依赖、上线即现状，可即刻开工；M2 等样张；M3 等 M2 实证。若只批 M1，机制与展示先落库，两站启用延后，无任何半成品风险。
校准策略（报告 D3）。方案 A：样张实证后硬编码启用（推荐，与现有 adapter「站点事实」口径一致 —— carpt 当年即此路径）；方案 B：前 N 波影子模式只记录不执行。取 A 则 §6 R1 铁律随 docstring 落地；取 B 需另加观测面与切换判据，成本高一截。
备选项取舍。末页追翻省略 / HR 上限总数轴互证 / 登录态佐证，默认全部缓做（报告定性：优化非简化 / 依赖 D4 口径实证）。同意缓做则 M3 只做提示语与 WebUI 两件小事。
样张采集（报告 D2，用户侧动作，不阻塞 M1）。两站各采当期三档样张（含翻页中途页与空表页），定形载体（tab / 摘要 / 分页区间）与口径（B 档是否含自动通过、免罪后减不减、区间终点语义）。
