§01目标与设计原则

为什么做:主计划 26-10-17-0339 的 S19(真机验收,四场景)至今没有逐项验收记录 —— R3 已核实「现网指针 + /status 探活 + 订阅在跑,但无逐项验收记录」,主计划因此停在 In Progress。而 S19 定义之后,该模块又经历了三波实质变更(§02),按 S19 原文验收会漏掉大半新面。本计划把验收基线对齐到今天的代码现实,并按用户拍板改用桩测口径。

做到什么算成:§04 的 A1–A7 每一步都有可勾选的实测判据;全过之后主计划 S19 具备收口条件(四场景 + 新增面全部有逐项实测记录,写进任务档案)。

设计底线 / 不变量

  • 绝不触碰真实 qB:验收配置的 qbittorrent.host/port 一律指向本机桩服务(tests/helpers.py:459 的 FakeQbServer,标准库 http.server、真机语义);不登录、不读写任何真实 qB 实例。
  • 红线文件零接触:不改 config.yml、不写 auto-qb-data/;验收配置的 data_dir/state_file 显式指到 tmp-analysis/(已 gitignore)下的独立目录。
  • 仅 Windows 侧:只验 launch.cmd / HKCU Run 注册表 / DETACHED_PROCESS 等 Windows 路径;POSIX 分支(launch.sh/systemd/plist)不在本轮验收范围(单测与 CI 另一侧已覆盖)。
  • 现场可还原:验收会停/起真实工具进程、读写用户级发现指针 —— 开工前备份 endpoint.json 与工具 config,验收后按 A7 还原。
  • 逐步骤显式授权:沿用主计划请求边界,每个 A 步骤开工前逐项确认(「继续」不算授权)。

§04实施步骤(每步开工前逐项授权)

A0 · 准备

  • 建 tmp-analysis/acceptance-gts/:桩 qB runner(独立脚本,import tests.helpers.FakeQbServer 常驻前台跑并打印端口)、acc-a.yml/acc-b.yml 两份验收配置(各自独立 data_dir/state_file → 单实例锁天然不冲突)。
  • 备份现场:发现指针 endpoint.json(用户级平台目录 global-traffic-monitor/)与工具 config 各拷一份进工作区;记录当前 HKCU\...\Run 自启值与工具进程状态。
  • 冒烟:起桩 qB → commands run dev.run -- tmp-analysis/acceptance-gts/acc-a.yml --dry-run,确认配置校验全过、qB 连上的是桩。
  • 判据:dry-run 日志显示 qB base_url 为桩端口;工作区内三件套(runner/两 yml/备份)齐;真实 config.yml 与 auto-qb-data/ 的 mtime 未变。

A1 · 场景①:工具未跑 → 自动拉起 → 订阅成功 (主计划 S19①)

  • 前置:停掉现网工具进程(经设置页「关闭工具」或直接结束进程),确认指针仍在或已删 —— 两种起点各验一次(指针在 = 探活失败转拉起;指针缺 = 纯引导拉起)。
  • 起桩 qB → 起实例 A(真实运行,非 dry-run)→ 设置页观察五态流转:未运行 → 拉起中 → 已就绪。
  • 判据:①顶栏/历史图/限速曲线出数(数据来自指针 data_dir,状态区「数据目录」= 指针值,配置面无 data_dir 键);②实例 A 日志里拉起动作只有「零参执行 launch.cmd」一步,无 uv/入口名/子命令拼装(§08「拉起不依赖 uv」);③指针 host/port 为随机端口,`gtm endpoint` 子命令打印与指针一致;④首次引导超时预算 120s 内探活成功。

A2 · 场景②:自启(HKCU Run)后重启机器 → 探测到在跑、零拉起 (主计划 S19②,对象已换轨)

  • B 级(等价模拟,先行):读 HKCU\Software\Microsoft\Windows\CurrentVersion\Run 的自启值 → 手工执行该值里的命令行(等价登录拉起)→ 工具起 → 再起实例 A → 判据:探测到在跑、日志无 Popen(§08「工具在跑:零拉起」)、五态直达「已就绪」。
  • A 级(真重启,权威):用户配合真重启机器一次 → 登录后确认工具已自启 → 起实例 A → 同上判据。
  • 顺带核:注册值命令行指向启动器(launch.cmd / Phase 2 的 claim.cmd 矩阵按身份);注册失败路径可见(非静默,dd4bccb8 的修复面)。

A3 · 场景③:双 auto-qb 实例共享同一工具 (主计划 S19③)

  • 实例 A 在跑且已订阅 → 用 acc-b.yml(独立 data_dir/state_file)起实例 B。
  • 判据:①B 探测到工具在跑,跳过拉起(Popen 零调用);②A/B 各自订阅互不干扰 —— 两实例的顶栏/历史图数字同源推进、互不覆盖对方快照;③工具侧不因第二个订阅者出错(日志无异常);④对应 §08「多实例共享」。

A4 · 场景④:切回 TM 文件来源 (主计划 S19④)

  • 设置页把 provider 切到 traffic_monitor,dat_path 指向一份 TM 格式 dat(取工具 data 目录 dat 的副本,见 D3)→ 保存。
  • 判据:①保存后历史图立即换为新来源数据、不等一个 interval(Phase 1 S8 切源即刷新);②paths.dat_path() 改走配置 dat_path(日志可证);③工具参数保留但不参与取数,工具进程不被自动关闭(关闭是显式动作);④provider=TM 时设置页工具区块整块隐藏(Phase 1 S6);⑤切回 gtm 再验一次往返,行为对称。
