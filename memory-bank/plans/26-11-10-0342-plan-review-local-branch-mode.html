§01目标与设计原则

背景: 通用委派 prompt 的世界是「任务全程在本地分支 + 每步 ship.commit --no-push + 完成后合流本地 develop」, 与多 clone 并行推进共存。实测扰动: 远端 develop 每推一笔, 该 clone 的批评审即被打断——即使本 clone 全程只在本地工作。

目标: 本地分支任务全程(批评审 → 修复 → 合流前)不受远端推进扰动; 组合树窗口推迟到合流时点用一次廉价终审收口。

设计不变量:

  • 隔离要求(用户拍板, 通用 prompt 原话): 实施过程不被其它 clone 的提交影响。
  • 机械面零改动: sync.py / commit.py / check_review_trace.py / review_pack.py 一行不动。
  • 判定自证式: 分支态判定不依赖 agent 声明, 探针现查(ls-remote 属读命令, 与现行 ④ 同款成本)。
  • develop 干流口径不变: 直接在 develop 上干活的齐平协议(26-11-07-0201 D1/D4/D5)原样; 本地态是新增分支态, 不是替代。

§02现状与痛点

现状: 齐平协议在 code-review skill 三处无条件核对远端:

位置现行行为锚点
③ pack 前置主会话生成评审包前强制 my-commit-flow.sync, 逃生口只认「确实解决不了(离线)」SKILL.md:46
④ 三钉自检reviewer 跑 git ls-remote 取远端 tip, git rev-list --count HEAD..<tip> 落后>0 → 停手不评审, 出路「sync 后重派」SKILL.md:64-65
④ 收尾复核评审交回后再查远端, 推进了 → 「修复/收尾前必须重新 sync」SKILL.md:67

痛点(本地分支工作流下三处全坏):

  1. reviewer 必停: 本地分支基于旧 develop 且必有本地提交 → 远端每推一笔, 落后计数恒>0 → 每批评审必停手, 与分支自身改动无关。
  2. 出路是死路: sync 跟当前分支(_ship_config.py:203, .my-commit-flow.toml branch=""), 对无远端对应的分支 ls-remote origin <分支> 取不到 ref(sync.py:85-90) → 失败「拿不到远端 origin/<分支> (离线?) —— 联网后重跑」(sync.py:431)。这不是离线, 重跑恒败; ③ 的逃生口不适用, agent 卡死或临场发挥。
  3. 组合树窗口错配: 齐平 = 评审上下文必须含远端全部最新代码(SKILL.md:37), 该口径为「直接在 develop 上干活」设计(先例档案 tasks/26-11-07-memory-bank-review-rebase-gap.md:23 D4/D5); 本地分支模式下它把远端推进强行拉进每个评审时点。

无辜面(已查证): ship.commit --no-push 不同步不推送(commit.py:584); review_pack.py 纯本地零网络(grep 实证)。扰动源纯在协议文本, 不在 git、不在机械面。

§03方案总览

主线: 协议单点(code-review SKILL.md)增「本地分支态」, 判定用机械探针; 合流时点用 test.full + 挂「远端交叉面」的接缝终审收口组合树窗口; 通用委派 prompt 补基线钉死。拍板 D1–D6 见 §06, 残留 P1 见 §05。

落点 1 —— ③④ 本地分支态 (D1/D2)

探针(主会话与 reviewer 同一判定式, 各自现跑): git ls-remote origin <当前分支> —

探针结果分支态远端核对
取得到 ref远端分支态现行三态原样: 落后=0 放行(含本地领先) / 落后>0 停手 / tip 取不到「无法核实」
取不到 ref本地分支态(判定表新增第四态)放行远端核对: 自检只钉 diff 范围 + HEAD 锚两钉; 收尾复核跳过远端核对, HEAD 锚复核照旧
  • ③: 本地态下 pack 前置 sync 跳过, 评审记录记「本地分支态」行(替代现行「齐平/未齐平」二态记录)。
  • ④: 本地态下三件套第三钉填「本地分支态(探针 ref 不存在)」—— 派遣模板原文写进 skill, 照抄不临场发挥。
  • 明文口径: 本地态评审对象 = 分支自身 diff 锚点链; 远端推进不进评审上下文; trailer · 齐平 字段缺省(本就不强制, 弱校验不涉); · 基 / 检 P/T / 锚点 walk 纯本地照旧。

落点 2 —— 合流收口 (D4)

  • 时点: 最终 rebase 到 develop 之后、等待提交指令之前。注意 rebase 后本地 develop 领先远端, 终审在现行三态下自然放行(落后=0 含本地领先), 无需新协议。
  • 内容: test.full(运行时行为兜底) + 一次接缝终审(≤200 行, 现行「批间接缝」定义不变)+ 远端交叉面: 指路件附 git log <任务开工基线>..origin/develop --oneline, 终审 checklist 挂「与远端新进提交的交叉面」一条 —— 只管测试兜不住的接缝/文档/口径面。

落点 3 —— 通用委派 prompt 修订 (D5)

两行, 全文见 §04 S2: ① 可写子代理派工钉死基线 hash + 本地分支 sync 报错属预期(P1 可砍); ② 合流后插入 test.full + 接缝终审再等待提交指令。

§07风险与对策

编号风险触发条件与处置
R1探针撞名: 两个 clone 建了同名本地分支且对方推过 → 探针取到同名 ref, 误判为远端分支走现行三态(停手)触发: ls-remote 命中同名 ref。处置: 停手行自带人工介入点, 不会静默评错; 工作流每任务独名分支, 概率可忽略
R2本地态窗口内远端推进的语义交叉漏检(测试兜不住的接缝)处置: D4 终审交叉面 + test.full; 仍漏属测试缺口, 照 scope-guard 入池
R3与 26-11-07-0201 齐平协议口径漂移(两处文本各自演化)处置: S1 验收明示「develop 干流口径原文零改动」, 本地态只做增分支; 评审 checklist 18(口径单点)把关
R4reviewer 对第四态理解不一, 派遣临场发挥处置: 本地态三件套模板原文写死在 skill ④, 照抄不临场发挥(现行纪律)
R5改版生效期间新旧协议混用处置: 生效即时无迁移态; 历史 trailer 不追溯、锚点 walk 照旧识别(先例 26-11-07-0441 生效日语义)
