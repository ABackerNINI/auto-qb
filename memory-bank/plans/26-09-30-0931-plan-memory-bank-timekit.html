01

背景与根因

文档日期时准时不准、体例漂移、文件名出现未来时间 —— 探索结论：不是没人守规矩，是规矩从未具备执行条件。

约定早已存在，但那条命令根本不存在
conventions/doc-forms.md:31「时间戳用命令取当前值」、webui.md:59「日期时间用命令取当前值，不靠记忆」—— 但 .commands/ 全部包里 grep 取时命令 0 命中，全仓库也不存在任何 UTC+8 单点。日期实际上全是 agent 按会话上下文手敲的：系统提示里的日期、记忆、推算，哪个都能写进去，未来时间与错值由此而来。
守卫只查形状，不查值
tests/test_memory_bank.py（441 行 / 24 测试）校验文件名形状、章节结构、索引一致性，但不校验任何日期值；gen_active_recent.py:87 对格式坏的「最后活动」strptime 失败后静默回退文件名时间 —— 坏数据永远不红。
唯一的脚本化取时点未钉时区
create-issue scripts/_common.py:56 的 stamp() 用裸 datetime.now() —— 机器本地时区，未钉 +08。它是唯一往 KB 文件名写时间戳的脚本，换个时区的机器跑就会产出错值文件名。

结论

02

目标与非目标

2.1目标

  1. 时间单点：KB 一切日期只有一个来源 —— 脚本 timekit.py，UTC+8 钉死，与机器时区无关。
  2. 流程可执行：把「时间戳用命令取」从一句空话落成真实存在的 commands run kb.time，SKILL.md 挂硬性步骤。
  3. 守卫可机检：未来日期、坏体例、非法文件名日期全部判红，接进 kb.check 与提交闸门。
  4. 守卫脚本随 skill 走：memory-bank 相关守卫全部收进 .agents/skills/memory-bank/scripts/，整目录拷走即可移植。

2.2非目标

  • 不兜「过去日期的错值」（如把 09 写成 06）—— 无真值可比，守卫做不到；靠「只从 kb.time 取」的流程规避。
  • 不查正文的未来日期 —— 正文可合法引用未来日程（排期、里程碑）；值检查只做文件名与元数据。
  • 不动项目级脚本：check_context_caps / check_command_drift / sync_agent_skills 含项目专属值，留根。
03

方案设计

3.1时间单点 timekit.py（skill 第 9 个脚本）

位置 .agents/skills/memory-bank/scripts/timekit.py，纯 stdlib，复用 _common 的根/目录探测。时区实现：

datetime.now(timezone(timedelta(hours=8))).replace(tzinfo=None)

即 naive UTC+8 墙钟：与全库现有 naive 解析（gen_active_recent 等）一致，不引入 aware/naive 混算；与机器时区无关，TZ 无关性用测试钉住。子命令：

子命令输出用途
date2026-09-30Added / Updated / 正文日期
time2026-09-30 09:31最后活动 / 正文时刻
stamp26-09-30-0931文件名前缀 YY-MM-DD-HHMM（沿用现行定宽约定）
（无参数）三行全打commands run kb.time 默认形态，一次取全
check / --check违规清单时间守卫（见 3.3），有违规退出码 1
$ commands run kb.time
date:  2026-09-30
time:  2026-09-30 09:31
stamp: 26-09-30-0931

3.2流程接入（让约定第一次可执行）

  • 新 task kb.time（.commands/kb/config.toml）：timekit.py <args>；kb.check run 列表追加 timekit.py --check。
  • SKILL.md 新增「时间口径与取时」节（现 6,347 / 15,000 字符，余量充足）：KB 内任何日期（文件名前缀 / Added / Updated / 最后活动 / doc-added / 正文）一律取自 commands run kb.time 输出，禁用模型上下文里的日期与手工推算；会话开始 / 收尾 / 任务档案规范相应挂钩；附格式表。
  • conventions 两处指针落地：doc-forms.md:31 与 webui.md:59 的「用命令取」写到真命令 commands run kb.time。
  • AGENTS.md 不动：7978 / 8000 字符，余量仅 22；路由经 skill 收尾链路自然触达。

3.3守卫规则（三层）

层范围规则
文件名 tasks 的 YY-MM-DD；切片与 HTML 制品的 YY-MM-DD-HHMM 合法日期 + 不晚于当前时刻，未来 = 违规；时分位合法性一并校验
元数据 **Added:** / **Updated:** / > 最后活动: / HTML meta doc-added / doc-updated 合法 + 未来 = 违规；「最后活动」必须严格 YYYY-MM-DD HH:MM
正文 全部 .md / .html 的日期 token 非规范变体（斜杠 / 不补零 / 中文日期 / 紧凑 8 位 / ISO-T）= 违规；规范 token 不查未来（正文可合法引用未来日程）

豁免机制：md 跳过围栏代码块与行内代码；行内 <!-- time:allow --> 标记豁免所在行（HTML 注释渲染不可见，适合 plans 制品里的机器数据样例）。输出 file:line + 违规类型 + 修复提示。

3.4守卫脚本收进 skill（移植性）

  • 迁移 scripts/check_doc_links.py → skill scripts（第 10 个脚本）：已核实耦合极低 —— 根探测改用 _common.find_root() 即可；同步改两处引用：提交闸门 run 改 <skill-dir:memory-bank> 占位符、tests/test_memory_bank.py 的 importlib 加载路径。原路径删除。
  • 接线天然兼容：kb.* 与闸门命令全走 <skill-dir:memory-bank> 占位符（SKILL_DIR_CANDIDATES 动态解析），脚本随 skill 目录整体搬迁时 config 零改动。
  • references/PORTING.md（新）：移植清单 —— 拷 skill 目录 → 建 memory-bank/ 骨架 → 可选挂 pytest 薄壳 / .commands/kb 包 / 闸门。

3.5收口静默回退 + create-issue 钉 +08

  • gen_active_recent.py:87：「最后活动」存在但格式坏时 --check 报红（不再静默回退）；整行缺失仍按设计回退文件名时间。收口在存量清洗之后做，保证闸门全程不红。
  • create-issue _common.py 的 stamp() / long_date() 改用同一 UTC+8 naive 墙钟（本地内联常量，不跨 skill import）—— 它是唯一往 KB 文件名写时间戳的脚本，不钉则非 +08 机器上 issue 名仍会错。

06

验收标准

  • commands run test.full 全绿，含新增守卫用例（未来文件名日期 / 坏「最后活动」/ 斜杠日期三种种子经 --mb-dir 指向 tmp 夹具全部逮住）。
  • 时区无关性：TZ=America/New_York 子进程跑 timekit.py 输出仍是 UTC+8（测试钉住）。
  • timekit --check 对存量 KB 零违规（清洗完成后）。
  • kb.check 与提交闸门都含时间检查；kb.time 三行输出可用。
  • doc.caps 绿（SKILL.md ≤ 15,000 字符）。
  • 收尾时新坑入 pitfalls/kb/：「约定命令不存在 → agent 凭记忆写日期；日期值无机检」（触发 / 判别 / 处置三必填）。
07

边界与风险

  • 过去日期错值兜不住：守卫只能校验「体例 + 未来」，无法发现把 09 写成 06 这类过去错值 —— 如实承认，靠流程（只从 kb.time 取）规避，git 历史可回查。
  • 正文未来日程不查值：只查体例；需要豁免的机器数据用 <!-- time:allow --> 行内标记。
  • 红线：不碰 config.yml / auto-qb-data/ / AGENTS.md（余量仅 22 字符）。
  • 范围守恒：实施中撞见的计划外缺陷一律入池 issues/，不顺手改。
  • 提交：实施完成 ≠ 提交 —— commit / push 仍需用户显式说「提交」。
