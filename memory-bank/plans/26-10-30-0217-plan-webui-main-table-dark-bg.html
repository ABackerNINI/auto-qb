WebUI 主表暗主题背景重设计: 可交互模板选型

重设计主列表(主表)暗主题下的行/列背景语言——提供 4 套可交互模板(§03)供选型，主轴是「把行底从与页底纠缠的中间调里解放出来：要么干净地落在页底上(平板)，要么明确地浮起来(卡片)」。

doc-added 26-10-30-0217 · doc-updated 26-10-31-0414 · doc-status Done · 载体 单文件 HTML(dark)
来源 会话用户指令：「主表列背景色(暗主题)看着灰蒙蒙、界面很脏，需要重新设计；先设计几个简单的可交互 UI 模板供选择，模板写入计划文件」

§01目标与设计原则

为什么做：用户反馈默认暗主题(ocean)下主表「灰蒙蒙、界面很脏」。根因不是某个颜色选错，而是背景层次语言模糊——行底、页底、悬停、芯片底全挤在同一段中间明度里，谁也不比谁干净。

做到什么程度算成：用户在 §03 的交互模板里选定一套；实施后主表暗主题肉眼不再有「蒙灰」感，且既有判据不回归（吸左首格计算底 == 行板计算底，见 pitfalls/web-ui/frozen-column.md）。

设计底线 / 不变量：

  • 吸左首列(名称列)必须不透明且与行板同底——半透明挡不住横滚的兄弟列（views.css:171 注释既有口径）；半透明状态色一律「同色 linear-gradient 叠不透明基色」合成。
  • 只动暗主题的背景令牌与行语言；亮主题(frost/golden)不动。
  • 状态语义色(绿/蓝/黄/红/accent)与文字层级不重设计——本轮只收敛背景面。
  • 表头/吸顶、抽屉表格面(shared/dt_table.css) 与主表共用令牌族，改令牌须全链核对，不允许主表干净了、抽屉仍蒙灰。

§02现状与痛点

主表当前是「行卡」语言：每行一张卡——不透明行底 + 1px 描边 + 圆角，行间 5px 间隙露页底。ocean 主题实测：

  • 行卡三件套：src/auto_qb/webui/static/prism/css/views.css:275（.group-row { background: var(--bg-row); border: 1px solid var(--border-soft); border-radius: var(--radius) }）+ views.css:149 行距 gap: 5px。
  • 吸左首格同底：views.css:172（background: var(--bg-row)）。
  • ocean 令牌（themes/ocean.css:7-13）：页底 --bg: #0d1724 vs 行底 --bg-row: #112034——逐通道差仅 (4, 9, 16)/255，且色相向蓝偏移；悬停 --bg-hover: #1c3050、芯片底 --surface-2: rgba(255,255,255,.06)（ocean.css:80）、描边 --border-soft: rgba(255,255,255,.07)。

「灰蒙蒙」的构成：行底与页底明度几乎相同但色相略偏 → 每行读作页底上「没擦干净的一块」；再叠每行一圈白 7% 描边 + 圆角 + 5px 缝隙，形成低对比卡片墙；行内状态芯片/表头 hover 又是一层白 6% 中间调。整页没有任何一个面是「干净的页底」，全部被半层灰覆盖。

悬停动效候选（文字方案 · 拍板 D4）

背景换色后 hover 仍不够明显的补救走动效。候选全部是纯 CSS、零 JS、不碰布局的「简单动效」，可单选也可组合（组合默认以 M1 为底）：

编号动效观感实现面备注
M1 · 提亮渐入（推荐底座）hover 底色 160ms 渐入（现有 transition 保留），终值再提一档：白 8% → 白 12~14%行「浮亮」，最克制最小：改一个令牌值不动位移不动物体；名称列合成色随之重算一档
M2 · 名称列左条滑入名称列左缘 2px accent 竖条，hover 时 120ms 渐入（透明→半亮），移出淡出指向性最强——视线锚点在行首，一眼定位悬停行小：名称列 ::before 伪元素 + opacity 过渡与选中态左条同语言（选中=常驻实色，hover=半亮），层次自然
M3 · 行微抬hover 时整行 translateY(-1px)（120ms）「卡片被拿起」的物理感最小：一行 transform现行主表已有此动效（views.css:277 .group-row:hover），本方案=保留现状；A/B/D 无卡语言下「抬」的语义弱化，更适合 C
M4 · 高亮扫入hover 瞬间一层高亮从左向右扫过行面（~200ms，一次性）动感最强，扫过方向=阅读方向中：伪元素 translateX 动画；与吸左首格合成规则叠加需单独验证高频扫表时可能显闹；与 B 的斑马叠加最需验证
M5 · 名称文字点亮hover 时名称文字色提亮一档（--fg → 纯白）；caret 变 accent 现行已有文字级微反馈，最安静最小：一条 color 规则单独用不够明显，只作组合佐料

推荐组合：M1 + M2——亮度解决「面」的可见性，左条解决「位置」的可见性，都是低动效里最稳的一档；若 D1 选 C 可再加 M3。M4 动感强但与吸左列/斑马的叠加验证成本高，不默认推荐。

实施定稿：A 与 B 双实施、可切换（grilling 后拍板，2026-10-30）

经 grilling 确认（结论全录 §06）：**不二选一，A/B 都实施、用户可切换**；范围三皮肤暗主题全量；默认 A；未来可能推进到抽屉内/设置中各表格面 ⇒ **按移植设计**。架构如下：

  • 引擎 shared/rowlang.js（新，仿 prism/js/theme.js 模式）：head 同步执行（首帧前定 html[data-rowlang]，无 FOUC）；持久化 localStorage["autoqb.ui.rowlang"]（隐私模式回退会话内生效）；值域 flat(A) / wave(B)，缺省 flat；切换派发 autoqb:rowlangchange 事件；document 级事件委托绑定 .rowlang-item（菜单未渲染时空操作）。三皮肤 index.html 各挂一行 script。
  • 菜单：shared/tpl/topbar.html 的 #theme-menu 内加「主表行语言」分组（两个 .rowlang-item：平板发丝线 / 波纹扩散）——顶栏模板三皮肤共用，一处改动全量生效（已核实 atlas/console 均加载该模板；主题引擎虽是 prism 专属，行语言引擎是 shared，不依赖主题引擎）。prism 亮主题（frost/golden）下该分组用 CSS 隐藏。
  • 规则单点 shared/row_lang.css（新，三皮肤共用，加载序在皮肤 views.css 之后）：全部规则键在 html[data-rowlang=…] + .rl-scope 上——作用域类 .rl-scope 首版只挂在主表容器 .torrents-dock（groups.html 模板加一个 class）。抽屉各面/设置面不挂类 = 零变化，满足「不更改列表其它元素」。
  • 移植契约（核心要求）：未来任何表格面采用行语言 = 容器挂 .rl-scope 一个 class，结构规则/JS/菜单零改动；tint 全部走「令牌带白 alpha 回退」（如 var(--rl-hover-tint, rgba(255,255,255,.12))、--rl-wave-tint(.09)、--rl-zebra-tint(.03)、--rl-bar）——暗主题现在零令牌工作，未来亮主题或个别面微调时只需覆写令牌值，不改结构规则。
  • 亮主题排除：行语言选择器前缀 :not([data-theme="frost"]):not([data-theme="golden"]) 单点写在 row_lang.css（atlas/console 无 data-theme 不受影响）；未来亮主题采用时删前缀+补令牌即可。
  • 两套语言定稿：A(flat) = 行透明落页底 + 1px 发丝线分行 + hover 白12% 渐入 + 名称列左条；B(wave) = 斑马纹(白3%) + 「波即高亮」扩散波(白9% 实色 scaleX 驻留, JS 写 --mx) + 名称列左条。两套共用：名称列左条语言（hover 白条 120ms/选中 accent 实色条）、选中 accent 10%+左条、搜索命中/错误/校验/展开状态按既有合成口径重锚到新行底。名称列 padding-left 2→8px 让位（拍板 Q4a）。

§04实施步骤（按 §03 实施定稿细化）

  1. 引擎与菜单：新建 shared/rowlang.js（head 同步、localStorage、data-rowlang、委托绑定，见 §03）；shared/tpl/topbar.html 加「主表行语言」分组；三皮肤 index.html head 各挂一行 script。验收：切换即时生效、刷新后保持、隐私模式不报错、首帧无闪变。
  2. 规则单点：新建 shared/row_lang.css（三皮肤 views.css 之后加载）；flat/wave 两组结构规则键在 html[data-rowlang=…]:not(亮主题) + .rl-scope；tint 走「令牌带回退」；groups.html 给 .torrents-dock 挂 rl-scope。验收：grep 无皮肤路径内的新行语言规则（单点不破）。
  3. 行语言规则体：行底/分隔/描边圆角、flat hover 白12% 渐入、wave 斑马+「波即高亮」扫层（--mx origin + mousemove 委托监听也放 rowlang.js）、名称列左条（hover 白条/选中 accent 实色条）+ padding-left 2→8px、行缝 flat 归零/wave 归零、.is-hscrolled 发丝线保留。验收：§03 两个 mock 的观感在真页复现。
  4. 状态底重锚：expanded/selected/partial/search-hit/err/bad/is-chk/is-pending 各状态行与吸左首格的合成基色从 --bg-row 换成新承光底（flat=页底；wave=页底+zebra 奇偶两套）。验收：每一状态首格计算底 == 行板计算底（逐通道差 < 可辨阈 20，判据见 pitfalls/web-ui/frozen-column.md）。
  5. 不改面清单核对（范围守卫，对应 §06 Q5）：抽屉 04-11 各面、表头/吸顶、列宽列序、排序筛选、状态芯片、行高密度、字号字色、亮主题 frost/golden——逐一截图/样式对比确认零变化；shared/dt_table.css 级联序不受影响。验收：抽屉四面无新异色带，亮主题页面 diff 为空。
  6. 回归与基线：commands run test.full + 新基线切片；涉及皮肤 CSS 断言的守卫测试（如 test_frontend_hr_detail_table_wiring）核对/更新。验收：全量通过、基线数字入 kb.baseline。

§07风险与对策

  • 吸左首格异色回归：触发条件——改了行底但首格合成基色没跟着换。对策：沿用 §04-4 的逐通道判据 + pitfalls/web-ui/frozen-column.md 检查单。
  • B 模板奇偶错位：触发条件——筛选/展开/窗口化导致 :nth-child 与视觉行序不一致。对策：奇偶 class 由渲染层按数据行序写入而非依赖 DOM 序；实施前先做一版小样验证。
  • 亮主题误伤：触发条件——把暗主题配方写进了共用层。对策：所有新值只进各主题令牌文件；共用层只允许结构性规则（描边/圆角/分隔的开关需要亮暗同态时，亮主题的 frost/golden 单独声明回退）。
  • 抽屉面观感不同步：触发条件——主表换语言后 shared/dt_table.css 族底仍是旧语义。对策：§04-5 全链核对 + 截图目验四个抽屉面。
  • 级联序失守（新）：触发条件——shared/row_lang.css 的规则输给皮肤 views.css 的行规则（特异性或加载序），行语言静默失效或半生效。对策：加载序钉死在皮肤 views.css 之后；行语言规则键 html[data-rowlang] 提高特异性；实施后用计算样式断言（首格底==行板底）自证。
  • 作用域类漏挂/多挂（新）：触发条件——.rl-scope 漏挂（行语言不生效）或误挂到抽屉面（违反「不更改其它元素」）。对策：首版只在 groups.html 的 .torrents-dock 挂；核对清单里加「grep rl-scope 全仓应只有主表容器一处」。
  • 亮主题排除遗漏（新）：触发条件——:not(frost/golden) 前缀写漏一条规则，亮主题出现白 tint 高亮。对策：前缀收敛为 row_lang.css 内的单一选择器组（@layer 或 SCPP 变量不可用则用重复前缀+守卫注释）；§04-5 亮主题 diff 为空验收。
  • 首帧闪变（新）：触发条件——rowlang.js 非同步加载或晚于首帧执行，默认 flat 与用户所选 wave 之间闪一次。对策：仿 theme.js 在 head 同步执行；三皮肤 index.html 挂载点核对。
