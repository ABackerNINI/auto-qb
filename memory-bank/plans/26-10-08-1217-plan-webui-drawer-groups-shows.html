1 · 需求

用户命题：WEBUI 辅种页 / 追剧页需要支持种子详情面板。

拍板要点（本轮澄清）：

  • 入口粒度：成员行级（辅种页展开明细里的成员行、追剧页集明细里的成员行）—— 面板一次显示一个种子的详情，语义与种子页一致。
  • 触发方式：成员行右键「详细信息」+ 成员行双击 + 键盘/鼠标光标 + 快捷键（Alt+1~5 双态入口）。
  • 挂载与切换：复用底部停靠面板（.drawer-dock），三视图共用槽位；切换视图时面板状态保持（与现有跨页保持语义一致）。

2 · 现状（代码事实，26-10-08 实读）

2.1 面板与视图的强绑定

停靠面板的可见性单点在 drawer.js 的 drawerVisible computed：

drawerVisible() {
  if (!this.drawer.open) return false;
  if (this.page !== "groups") return false;
  if (this.drawer.kind === "traffic") return true;
  return this.viewMode === "torrents";   // ← 种子详情限种子视图
}

打开单点 openTorrentDrawer(hash) 首行同样有守卫：

async openTorrentDrawer(hash) {
  // 防御分支(W1): 面板落点只存在于种子页(torrents 视图), 非种子页没有 .drawer-dock
  if (this.page !== "groups" || this.viewMode !== "torrents") return;
  ...
这两个守卫是唯一的实际障碍。辅种页/追剧页调用 openTorrentDrawer 会静默返回——不报错、不提示、什么也不发生。

2.2 入口其实已经接好了一半

关键发现：辅种页的成员行与追剧页的集明细行，右键已经复用种子页的单种子菜单：

  • groups.html:140 成员行 @contextmenu.prevent="openMemberMenu($event, m)"
  • shows.html:127 集明细行 @contextmenu.prevent="openMemberMenu($event, m)"
  • menu.js:168 openMemberMenu() 设 menu.hash = member.hash，而 ctx-menus.html:74 的 v-else-if="menu.hash" 分支已含「详细信息」项（ctx-menus.html:85 → openTorrentDrawer(menu.hash)）。

结论：右键菜单项无需新增，它已经渲染、已绑定正确 hash；点下去只是因为 2.1 的守卫而静默失效。

2.3 缺的部分

面现状本计划
面板可见性仅 viewMode === "torrents"放宽到 groups 视图下的三 viewMode
打开守卫仅 torrents 视图同 2.2 放宽

3 · 设计

3.1 面板挂载：三视图共用槽位

.drawer-dock 已是 app 级分片（dock.html，boot.js 按选择器注入），落点在种子视图的 <main class="content"> 上（groups.html:3 的 torrents-dock 类）。

方案：把 torrents-dock 这个几何钩子的挂载条件从 viewMode === 'torrents' 放宽为「主内容页恒挂」。因为三视图（torrents/groups/shows）都在同一个 <main class="content"> 内用 v-if 切换，槽位天然只有一个、天然共用。

<main class="content" :class="{ 'torrents-dock': true }">
<!-- 或直接去掉条件类, 由 CSS 决定是否留出底部空间 -->
高度治理注意：.torrents-dock 是 W3 拖拽调高与 _kbViewBottom 收口依赖的几何钩子。放宽后需确认：①未开面板时该 class 不留白（否则辅种页/追剧页底部会凭空多出一块）；②收起/展开动画的 dock 高度补偿逻辑对三视图一致生效。判据：.torrents-dock 在 drawer.collapsed 且 !drawer.open 时高度为 0。

3.2 可见性单点放宽

drawerVisible() {
  if (!this.drawer.open) return false;
  if (this.page !== "groups") return false;
  if (this.drawer.kind === "traffic") return true;
  return true;   // ← 种子详情: groups 视图下三 viewMode 一律可见
}

即种子详情不再限视图，只限「主内容页」。理由：面板是表行附属，而三个视图都是表行；成员行在三视图里是同一批 hash（selHashSet 早已跨视图同源）。

3.4 成员行双击

两处成员行模板补 @dblclick：

  • groups.html 成员行：@dblclick="openTorrentDrawer(m.hash)"
  • shows.html 集明细成员行：同上
双击 vs 单击冲突：成员行单击 onMemberClick 目前是不选中（只落光标）。加双击不会冲突，但需确认双击的两次单击不会触发两次 onMemberClick 副作用 —— 现有实现只写 kbCursor/anchor，幂等，无副作用。与种子页 torrents.html:27 同款写法，风险已在该页消除。

3.5 键盘光标链纳入成员行

shortcuts.js:471 _kbRows() 现为：

// 光标线性链: 辅种页=组行; 种子页=平铺行; 追剧页=剧/集单元(决策②: 成员行 vNext)。
if (this.viewMode === "torrents") return this.filteredTorrents.map(...);
if (this.viewMode === "shows") { ... 剧行 + 展开的集行 ... }
return this.filteredGroups.map((g) => ({ kind: "group", id: g.key }));

改动：在 groups 分支的组行之后、shows 分支的集行之后，分别插入展开的成员行（kind: "torrent"）：

// groups 视图: 组行 + (展开组)成员行
const out = [];
for (const g of this.filteredGroups) {
  out.push({ kind: "group", id: g.key });
  if (this.expandedKey === g.key) {
    for (const m of this.sortedMembers(g.members)) out.push({ kind: "torrent", id: m.hash });
  }
}
return out;

shows 分支同理：集行之后插入该集展开的成员行。选中/展开逻辑（_kbExpandRow/_kbCollapseRow）对 kind === "torrent" 已无展开语义，需确认 _kbOpenRow 落在 openTorrentDrawer 分支（现已在：shortcuts.js:690 注释「种子行: 详情面板」）。

3.6 Alt+1~5 双态入口

_kbDrawerTab 的两处放宽：

  1. 守卫：if (this.page !== "groups") { toast; return; }（去掉 viewMode !== "torrents"）。
  2. 目标解析：const hash = c && c.kind === "torrent" ? c.id : this._kbSingleHash(); —— 光标是成员行时直接取 hash。3.5 落地后这在三视图内一致成立。

3.7 键盘跟随 _kbFollowDrawer

单点里已有 page + kind 守卫（「相邻视图零开销返回」）。需复核其 kind 判据是否只认 torrent——若是，3.5 落地后成员行光标自然命中，无需改；若含 viewMode 判据则需要放宽。

4 · 影响面与风险

项说明
坏影响：无跨页错位面板仍限主内容页（设置页不出现）；三视图同在 groups 页内，切设置页行为不变。
守阵需同步test_webui_static_dom_panel.py::test_frontend_qb_traffic_drawer_page_guard 第 1 段硬断言 return this.viewMode === "torrents"; —— 放宽后必须改这条断言（改为「三视图一律可见 + 仍限主内容页」）。
键盘链长度变化辅种页大库展开整组可能产生数百成员行；_kbViewportRow 前缀和换算依赖 _rowPre，需确认成员行也在窗口化前缀和的覆盖内（否则光标定位退化）。
收起态 peek_drawerPeekTarget 现含「种子页守卫」，需一并放宽到三视图（否则收起态鼠标换目标在辅种页失效）。
