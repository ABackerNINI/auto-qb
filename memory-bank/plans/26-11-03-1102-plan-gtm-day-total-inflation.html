§01目标与不变量

1.1 目标

  • 主目标：断网/网卡被过滤再恢复时，当日累计只增加「该卡恢复窗口的真实增量」，不再把整份生命周期累计入账。
  • 次目标：单轮单卡单方向速率超过阈值时留下常驻可见告警——auto-qb 主界面底部状态栏恒显横幅/徽标（不依赖打开设置页），点击可看完整文案并可「已知晓」；GTM /status 与设置页「工具状态」行提供详情，日志只作取证；只告警，不改记账结果。
  • 第三目标：新增配置键由程序迁移落盘，用户不需要手工加键/删键；迁移不写主 config.yml，退回旧版本不会因未知键 fail-fast。
  • 非目标：不改 dat 契约、不改 auto-qb 读取/聚合/限速、不引入第三方依赖、不修正已落盘的历史虚高行（见 §12 不做清单）。

§02现状与根因（摘要）

完整取证在 issue。这里是修法直接依赖的三条事实：

  1. 基线是「合计」而不是「逐卡」：sampler.py:339-340 把过滤后所有卡的计数求和，:369-381 用这个合计与上轮合计做差，并在任何「合计变小」时把合计基线无条件覆盖为收缩后的值。
  2. 网卡 down 会被过滤：AdapterFilter 默认 exclude_down=True（sampler.py:109，无配置开关）。链路断开期间合计基线被降到子集（常见为 0）。
  3. 媒体断链不清零网卡计数：恢复后合计读数 = 该卡整个生命周期累计，于是 delta = 整份累计。现网实测：注入 ≈273.4 GiB 上传 / ≈528.5 GiB 下载；当日累计 336.41/538.52 GiB；与用户断网前读数（62.96/9.997 GiB）的恒定偏移完全吻合。
为什么必须拆成逐卡：「合计变小」这一个信号同时覆盖三种完全不同的事件——真·计数器回绕、网卡被过滤、过滤集配置变化。只看合计永远无法区分；只有把基线落到每张卡上，才能在事件发生的那一边分类。

§03方案总览与关键决策

编号决策结论
D1主修法A：逐网卡基线。内存与 state 都保存每卡 (last_up, last_down)；delta 按交集逐卡计算后求和。
D2旧载荷降级state version:1 不丢弃：保留 day/当日累计，逐卡记忆置空 → 首轮每卡只立基线、delta=0（不虚高，代价 ≤1 个采样间隔少报）。
D3消失卡记忆筛选集中消失的卡保留记忆，不做「消失即删」。仅按 7 天未见 TTL 清理，避免 state 无界增长；8 天后回来的卡按新卡处理（delta 0）。
D4观测阈值（C-prime）速率口径：rate = delta / eff_dt，单卡、单方向判定；配置键 sample_rate_warn_bps（内存 B/s，盘上复合串如 "1GiB/s"），默认 1 GiB/s。超阈值只 WARNING，不记 0、不丢弃、不改 day 累计。
D5告警可见面（v3 重定）主告知 = auto-qb 顶栏常驻横幅/徽标：流量快照追加可选字段 gtm_anomaly（数据来自 GTM /status.last_spike，只增不改），statusbar.html 在每次打开 WebUI 时恒显；点击看完整文案，× 可本机消警。次级：设置页「最近异常」行、GTM /status。日志只作取证。
D6配置升级新键写入 <data_dir>/config.v2.yml overlay；启动时程序检测缺失键并原子写入；主 config.yml 零改写；旧版本只读主配置，因此可安全回滚。禁止人工加键/删键。
D7契约冻结（v3 扩一处）history_traffic.dat、auto-qb 读取/聚合/限速零改动；GTM /status 与 auto-qb 流量快照均只追加可选字段（last_spike / gtm_anomaly），旧消费方/旧前端忽略即兼容；新增顶栏 1 组模板 + 1 段 CSS + 2 个前端 helper。

4.4 采样算法（伪代码，可直接照写）

selected = self.filter.select(counters, stats)
if not selected:
    warnings.append("无适配器通过过滤: 合计按 0 计 (...)")   # 文案不变

now_mono = time.monotonic(); now_wall = time.time()
dt = self._dt_since_last(now_mono, now_wall, interval_hint)   # 见 §06.3

delta_up = delta_down = 0
next_base: dict[str, tuple[int,int]] = {}
per_nic_delta: list[tuple[str, int, int, tuple[int,int], tuple[int,int]]] = []
any_reset = False
baseline = not self._nic_base            # 逐卡记忆为空 => 本轮全为新卡

for name, io in selected.items():
    cur = (io.bytes_sent, io.bytes_recv)
    prev = self._nic_base.get(name)
    if prev is None:                     # 新卡(或 v1 升级后的首轮): 只立基线
        next_base[name] = cur
        continue
    du = cur[0] - prev[0]; dd = cur[1] - prev[1]
    if du < 0:                           # 该卡真回绕: 只清零这一张卡
        any_reset = True
        warnings.append(f"上行计数器重置 | nic={name} cur={cur[0]} last={prev[0]} delta 记 0")
        du = 0
    if dd < 0:
        any_reset = True
        warnings.append(f"下行计数器重置 | nic={name} cur={cur[1]} last={prev[1]} delta 记 0")
        dd = 0
    delta_up += du; delta_down += dd
    per_nic_delta.append((name, du, dd, cur, prev))
    next_base[name] = cur

# 关键: 合并而不是替换 —— 消失卡的记忆保留(等它回来按真实增量算)
self._nic_base.update(next_base)
self._nic_seen = {**self._nic_seen, **{n: now for n in next_base}}
self._prune_nic_base(now)                # 仅清 7 天未见的条目
self._last_up  = sum(v[0] for v in self._nic_base.values())
self._last_down = sum(v[1] for v in self._nic_base.values())
self._last_sample_mono = now_mono
self._last_sample_wall = now_wall

# C-prime: 只算速率/只告警, 不修改 delta/day (见 §06)
self._evaluate_rate(per_nic_delta, dt, interval_hint)
self._day_up += delta_up; self._day_down += delta_down

4.6 回滚兼容（旧版本读 v2 载荷）

v1 解析器对 version != 1 走降级：当日累计从 dat 恢复、基线取当前值 → 首轮 delta 0，不会重新引入冲高。代价是丢失 v2 里的逐卡细节与 state 内更精确的日累计（最多一个 flush 间隔）。因此 state 升级可回滚，无需数据迁移。配置侧的回滚见 §07.6。

§06C-prime：速率阈值、dt 处理与告警

6.1 口径（按用户否决点改版）

  • 定义：rate = delta / eff_dt，单位 B/s。判定对象是单张网卡、单个方向（上行与下行各算各的），不是合计。
  • 触发：某卡某方向 rate > threshold 时 logger.warning，并在 state 写入 last_spike。严格大于才告警；等于阈值不告警。
  • 动作边界（C-prime 核心）：不记 0、不丢弃、不白名单、不改 day 累计、不改 dat 行。同一轮该卡该方向的 delta 照常入账；回绕是唯一的记 0 分支，且在专属告警里说明。
  • 阈值语义不随采样间隔漂移：速率 = 字节/时间，间隔调大时 dt 同比变大，正常流量速率不变；这正是本次改口径的目的。

6.2 单位、键名与默认值推导

盘上单位：复合串 "1GiB/s"（与 auto-qb 既有 speed 文法一致）；内存单位：int B/s，字段名 sample_rate_warn_bps。不存绝对字节值。

6.3 dt 从哪来、怎么钳制（逐场景给期望值）

来源：time.monotonic() 优先（单调、不受系统对时影响）；`now_mono` 与 `now_wall` 在读取计数器同一时刻采样。`dt = now_mono - last_mono`。进程重启后单调钟断代，改用 state 里持久化的 last_sample_wall 做兜底：`dt = now_wall - last_sample_wall`。

钳制：eff_dt = min(dt, WARN_DT_CLAMP_FACTOR * interval_hint)，常量 WARN_DT_CLAMP_FACTOR = 3；interval_hint 由主循环每轮传入当前 config.sample_interval（默认 5s），不在 sampler 内部缓存。这样长 gap 不会把注入量摊薄到阈值以下。

6.6.5 失败降级（GTM 不可达不得影响主界面）

  • 指针缺失 / 密钥缺失 / 连接失败 / 非 200 / JSON 非法：fetch_last_spike 返回 (False, None)；快照不发布该段（有旧值保留旧值，无旧值就不渲染），只记一条 DEBUG（同因节流），不抛异常。
  • 旧 GTM 无 last_spike：返回 (True, None) → 发布 gtm_anomaly=None → 横幅不渲染，其余照常。
  • 快照告警段异常：_refresh_anomaly 的边界 try/except 隔离；流量 periods/history 的发布顺序不受影响（先取告警、失败即返回，随后照常读 dat）。
  • 前端字段异常：gtmAlert() 对非对象/缺 ts/ts 不可解析一律返回 null，模板 v-if 不渲染；不抛 JS 错误、不影响速度/通知/流量 pill。
  • 不可达期间的用户观感：主界面保持原样（有旧告警显示旧告警，无则不显示），不会出现空白、报错或加载态卡死。
为什么这条通道可依赖：①它挂在主界面底部状态栏，用户每次打开 WebUI 都看见，不依赖设置页访问频率；②数据来自 GTM 的持久 last_spike，不依赖被 pythonw 丢弃的 stderr；③传递复用既有快照轮询与接口，不新增路由、不把密钥交给浏览器；④GTM 不可达时整段静默降级，主界面不受牵连；⑤有 24h 窗口与本机 ack，不会长期占位。局限：它不是系统级弹窗，用户完全不开 WebUI 时仍只能事后查日志——这符合「不引入平台依赖」的范围约束。

§07配置升级与回滚（overlay）

7.1 为什么不能直接写进 config.yml

GTM 的 validate_payload 对未知键是 fail-fast（config.py:233-235）。若迁移把 sample_rate_warn_bps 写进主 config.yml，用户退回旧版本时旧代码会因「未知配置键」直接拒绝启动。删除键又必须人工操作，违反本轮第 3 条否决。因此 v2 采用 主配置零改写 + 新键独立 overlay：旧版本只读 config.yml，天然看不到新键。

7.2 文件与载荷

# <data_dir>/config.v2.yml
# 由 gtm v2 自动创建/维护；旧版本不会读取本文件

只允许出现 _V2_FIELDS（当前仅 sample_rate_warn_bps）。overlay 里出现未知键 → 与主配置同等级的 fail-fast，报「config.v2.yml 未知键: <key>」。

7.4 备份与写回原子性

  • 主配置：v2 功能从不写入 config.yml，因此不需要为它做备份。既有 migrate_legacy_config 若因旧版裸数值改写主文件，改写前复制一份 config.yml.bak（单世代，覆盖式）。
  • overlay：每次改写前，若旧文件存在，复制一份 config.v2.yml.bak（单世代，覆盖式）；解析失败时提示用户可从该备份恢复。
  • 原子写：写同目录临时文件 <name>.tmp.<pid> → flush + os.fsync → os.replace（Windows 上同卷替换原子）。不做跨目录写，避免跨卷替换不原子。
  • 写序：保存设置时先写 overlay、后写主配置。若主配置写失败，overlay 已经包含新键，加载时仍以 overlay 为准；若 overlay 写失败，主配置保持旧值，不产生半套配置。
  • 失败降级：overlay 创建失败（目录只读/磁盘满）→ logger.warning 后用内存默认值继续启动，不阻断采样；状态写入本来也会暴露同一目录问题。

7.5 保存路径拆分

save_config(path, cfg, overlay_path=None):
    main_payload    = {k: v for k in payload if k not in _V2_FIELDS}
    overlay_payload = {k: v for k in payload if k in _V2_FIELDS}
    if overlay_path is None:            # 既有测试/旧 API: 保持单文件行为
        atomic_write(path, payload); return
    atomic_write(overlay_path, overlay_payload)   # 先 overlay
    atomic_write(path, main_payload)              # 主文件永不含新键
