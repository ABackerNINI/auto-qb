00结论与拍板回执

用户拍板（2026-10-04）：A 台账 / B 控制台 / C 卡片墙三套主视图「各有优点，都保留可切换」—— 不裁掉任何一套，做成同一页面里的三个可切换视图。

可行性结论（本轮已论证）：四工位状态全部在结构化 meta 单点（doc-status / issue-status / 档案 **Status:**），关联已有 doc-topic 主键与 doc-refs 双向认领链，扫描器 gen_doc_map.collect() 现成可用。26-10-01-2125 报告裁定「AI 路由索引落盘、人的查询视图现算」——导航页属后者，不违裁定；页面数据零落盘，不新增多 clone 合并热点。

当日实测底盘：全库 383 件（计划 102 / 报告 31 / 问题 124 / 档案 126）、226 个专题（活跃 70）、数据快照 JSON 269KB；全量扫描 <1s；三原型（265–274KB 单文件）Playwright 渲染自检零 JS 报错。

02数据层 · nav_data.py

新脚本 .agents/skills/memory-bank/scripts/nav_data.py：import gen_doc_map.collect() 取全量条目，再做一层薄 enrich（原型的数据装配逻辑已验证，直接固化）：

  • issue 侧补 issue-type / issue-tier / issue-summary；全形态补 doc-updated（缺省回落 stamp）；
  • 派生 topics[]（专题键 + live 标记，live 口径同 gen_doc_map.is_live）与各形态 × 状态计数；
  • 输出 {stamp, items[], topics[]} 单个 JSON；stamp 取数据自带的最新 doc-updated/issue-stamp，不生成依赖当前时钟的内容（沿用 gen_doc_map 的纪律）。

函数签名 collect_nav(mb: Path) -> dict，服务层与静态导出共用这一个装配点。

03服务层 · nav_server.py

新脚本 .agents/skills/memory-bank/scripts/nav_server.py，纯 stdlib（http.server），零新依赖：

路由行为
GET /返回页面壳（读 nav_page.html 进内存，UTF-8）
GET /api/data每请求现算 collect_nav()，JSON 直返（前端 30s 轮询此端点实现准实时）
GET /memory-bank/<path>静态映射四工位原文，供「打开原文」链接；resolve 后必须仍落在 memory-bank/ 内，越界即 403（防 ../ 穿越，测试钉死）
  • 绑定 127.0.0.1（不暴露局域网）；--port 默认 8765；--gen-static [dir] 把「壳 + 注入数据」落盘成单文件到指定目录（默认 tmp-analysis/nav/，gitignored），作为不开服务的 fallback——链接前缀用相对路径 ../../memory-bank/。
  • CLI 入口沿用 _utf8_stdout() Windows 编码兜底；端口被占时报错行内提示 --port。

04页面壳 · nav_page.html

三套原型（tmp-analysis/nav-design/template-{A,B,C}*.src.html）合并为一个壳。合并原则：视图各自独立成容器，共享同一份数据与全局状态，切换零重建（display 翻转）：

  • 顶栏（三视图共有）：品牌位 + 全局搜索框 + 视图切换分段控件（台账 / 控制台 / 卡片墙）+ 数据戳（stamp + 件数）。视图选择记忆在 localStorage（try/catch 包裹，file:// 下降级为默认视图）。
  • 视图 A 台账：左栏过滤轨（形态 / 状态 / issue 类型 / 关联开关）+ 排序表格 + 行点击详情抽屉（元数据 / 声明引用 / 反向引用 / 同专题件三段）。
  • 视图 B 控制台：四工位统计带（分段状态条）+ 专题频道列表（活跃点亮）+ 条目 readout 行内展开认领链。
  • 视图 C 卡片墙：专题卡片（活跃优先）+ 形态/状态药丸过滤 + 「还有 n 件」展开。
  • 数据接入：壳加载后 fetch('/api/data')，成功渲染 + 每 30s 静默重拉（仅更新 DATA 并重渲染当前视图，保持过滤状态）；fetch 失败显示错误态（含「改用 --gen-static 静态件」提示）。静态导出模式由壳内 __DATA__ 注入（构建脚本替换），无 fetch。
  • 链接前缀自适应：file: 协议 → ../../memory-bank/；http: → /memory-bank/。
  • 三视图共用一套状态色（Open 青 / In Progress 琥珀 / 完结系灰绿），沿用深色规格（color-scheme: dark，底 #0e~#14，字 ≥ #d8）；动效仅 hover 反馈，尊重 prefers-reduced-motion。

08风险与缓解

风险缓解
269KB JSON 每次轮询全量重传loopback 下 <10ms 量级，30s 一拉无感；不做增量 diff（383 件规模不值）
多 clone 同时起服务撞端口占用即清晰报错提示 --port；服务是短命工具进程，无常驻冲突面
壳被当成第二真相源（前端渲染状态与 meta 漂移）页面纯只读 + 数据每请求现算；任何状态修正都落回各件 meta
三视图整合后行为与原型漂移S2 以原型为移植源不改交互设计；Playwright 截图对照 shots/ 基准
静态导出件被误提交默认落 tmp-analysis/（已 gitignored）；服务模式零落盘
