01拍板结论(grilling 收敛)

三轮拍板形成的全部决策,后续实施不得再自行变更;确需变更按「计划改版 = 同文件内变更记录 + 抬 doc-updated」处理。

议题结论
监控口径整机网卡流量(全适配器合计,排除回环与 down 网卡),与 TrafficMonitor 同口径 —— 工具是 TM 的替代,仅记录整机流量历史,不参与限速联动
进程形态tools/global-traffic-monitor/ 独立 Python 包(多模块,非单脚本),自带 venv,不 import auto-qb
自启跨平台:Windows 计划任务(登录时触发)/ Linux systemd --user / macOS launchd;由 auto-qb WebUI 开关幂等注册/卸载
采集库psutil(net_io_counters(pernic=True)),三平台统一;除 psutil + filelock 外零第三方依赖(HTTP 用 stdlib)
落盘格式TrafficMonitor 兼容 history_traffic.dat(每行「YYYY/MM/DD 上传KB/下载KB」),auto-qb 读侧 curves.py 零改动;日累计起步,格式预留扩展位
控制面工具自带本地 HTTP 服务(127.0.0.1 + token 文件):GET /status · PUT /config · 订阅/心跳/注销;last-writer-wins
通知累计上下行合计变化 ≥ 阈值(默认 100 MiB)→ 向所有存活订阅者推送(带单调事件号);启动/崩溃恢复后首帧落盘补发一次;订阅方慢轮询兜底
配置主权工具自有 config.yml(工具数据目录),auto-qb WebUI 设置页经控制面代理读写;auto-qb 自身集成参数在其 config.yml 新段
多实例工具 = 唯一写者 + 服务端;多个 auto-qb 实例各自注册订阅(端点 + token + 心跳租约)、各自冷却去重、各自刷新自己的 WebUI
auto-qb 收到通知后冷却检查 → 主循环线程重读历史文件 → 重发流量快照 → 前端历史流量图刷新(经既有 SSE/轮询通道)
过渡dat_path 双支持:可指向工具输出,也可指回 TM;并行对照 24h 一致后再摘 TM

02目标与非目标

目标

  • 独立进程记录整机流量日历史,TM 兼容格式落盘
  • 开机自启(三平台),崩溃自恢复(停机窗口 ≤ 采样间隔)
  • Δ ≥ 阈值主动通知,auto-qb 收到即刷新历史流量图(目标滞后 ≤ 通知链路本身,约秒级)
  • 工具配置与自启开关进 auto-qb WebUI 设置页
  • 多 auto-qb 实例并发接入,互不干扰

非目标(范围外)

  • 小时级粒度采样(日累计起步,后续演进位)
  • provider 抽象、限速联动、qB 口径取数
  • 进程级流量(ETW)、SNMP/路由器口径
  • 改动 TM 读侧 curves.py 与既有 qB 流量采样器 traffic_sample_mod
  • 工具的独立 WebUI(状态经 auto-qb 设置页可见即可)

03总体架构

图 1 · 单写者共享服务 + N 订阅者:文件始终在写(兜底),通知只加速

核心不变量:工具是历史文件的唯一写者,写入用「临时文件 + os.replace」原子替换,任意时刻读者(任意数量)看到完整一致的文件;通知推送与文件落盘解耦 —— 推送失败不影响落盘,订阅者丢失通知也可靠慢轮询兜底,两条通道互为冗余。

04实施步骤

共 11 步(S0–S10)。每步给出改动面、要点与出口判据;建议顺序见 §06。所有「默认值」可经 WebUI 设置页调整(§05)。

S0包骨架与依赖隔离

新建 tools/global-traffic-monitor/:pyproject.toml(包名 global-traffic-monitor,入口命令 gtm)、src/gtm/(sampler / storage / server / notifier / installer / config 六个模块)、README.md、tests/。独立 venv(uv 管理),依赖仅 psutil + filelock;HTTP 服务与客户端全部 stdlib(http.server / urllib.request),保证三平台 pip install即装、auto-qb 依赖变动不影响工具。

出口空包可安装可起(gtm --version),独立 venv 与 auto-qb 环境互不污染(装/卸 psutil 验证隔离)。

S1采样器 sampler

每 sample_interval(默认 5s)读 psutil.net_io_counters(pernic=True),按适配器过滤(默认排除 loopback 与 down 状态,可配 include/exclude 正则)后全适配器合计 up/down。维护上次读数快照:本次 < 上次 → 判定计数器重置(网卡重连/重启),delta 记 0 并 WARNING,不产生负流量。按本地日界维护当日累计,跨天 00:00 硬切写新行。崩溃恢复:启动读 state.json 恢复上次快照与当日累计;state 缺失/损坏时当日累计从 dat 末行恢复(若有),计数器基线取当前值(停机窗口丢流量,WARNING 说明)。

出口单测覆盖:正常 delta、重置归零、跨天切换、state 缺失降级;手工跑 10 分钟与任务管理器网速页量级吻合。

S2落盘 storage

单写线程(与采样同一线程)内写 TM 兼容文件:首行总行数 N,每行 YYYY/MM/DD 上传KB/下载KB(整数 KB,与项目 curves.py 解析一致)。写 = 临时文件 → os.replace 原子替换。落盘节流:日累计变化 ≥ 1 MiB 或距上次落盘 ≥ 30s(对齐 TM 落盘节拍),内存活尾随时可服务。state.json(上次快照/当日累计/事件号/租约表)同法原子写。filelock 保证工具单实例,二次启动 fail-fast 报错。

出口并发读守阵(读进程只见到完整文件,无半行/截断);kill -9 后重启日累计接续不丢不重(丢失窗口 ≤ 采样间隔);产出的 dat 文件直接被 curves.py 解析通过(复用现有解析测试)。

S3控制面 server

stdlib ThreadingHTTPServer,强制绑定 127.0.0.1(端口默认 8099,可配;占用即 fail-fast)。鉴权走 Bearer 头,密钥首次启动原子生成 monitor.token(compare_digest 比对,照 auto-qb auth.py 模式)。端点:

  • GET /status — 采样状态、当日累计、末事件号、订阅者数、文件路径
  • PUT /config — 全量校验 → 原子写 config.yml → 热重载(last-writer-wins;文档注明多实例盲写风险,设置页「读后写」缓解)
  • POST /subscribe {endpoint, token} / POST /heartbeat {id} / POST /unsubscribe {id} — 注册表落 state.json

租约:last_heartbeat + lease_ttl(默认 180s)过期剔除;订阅方每 60s 心跳。

出口鉴权拒绝(无 token/错 token)单测;租约剔除单测;端口冲突 fail-fast 实测;config 热重载不丢采样。

S4通知 notifier

采样循环内累计「距上次事件的上下行合计变化」,≥ 阈值(默认 100 MiB)时:①先确保文件已落盘(读者届时必读到新值)→ ②事件号 +1,构造事件体 {event_id, day, up_bytes, down_bytes, total_bytes, ts} → ③向所有存活订阅者 POST(超时 3s,失败记 WARNING 不阻断)。启动/崩溃恢复后首帧落盘补发一次(事件号接续)。订阅方以事件号去重 + 冷却(§05)收敛。

出口阈值触发/启动补发/重复投递去重单测;两订阅者(含一个假死端点)场景推送不阻塞采样循环(>10s 压测)。

S5自启 installer

gtm install-autostart / gtm uninstall-autostart,幂等:Windows 用 schtasks(/SC ONLOGON,当前用户,TR 指向 venv python);Linux 生成 ~/.config/systemd/user/gtm.service 并 systemctl --user enable --now;macOS 写 ~/Library/LaunchAgents/ plist 并 launchctl bootstrap。注册前检查存在则跳过,卸载反向;均先探测平台再执行,不支持的平台给出明确提示。该命令由 auto-qb WebUI 开关调用(S6),也可命令行直接跑。

出口三平台注册/卸载/重复注册(幂等)测试(平台命令层 mock);真机重启后工具自起、GET /status 正常。

S6auto-qb 配置面

新增 global_traffic_monitor: 配置段(models.py dataclass + loaders + validation 的 KNOWN_CONFIG_KEYS / 段校验 + schema 表单元数据,四处同步,黄金法则 4),键位:

# config.yml
global_traffic_monitor:
  enabled: false            # 联动总开关(保守默认)
  tool_url: "http://127.0.0.1:8099"
  tool_token_path: ""     # 工具 token 文件路径;空 = 默认 data/monitor.token
  subscribe: true           # 启动时注册订阅 + 心跳
  notify_cooldown_s: 600   # 通知冷却(秒),事件号去重另算
  autostart: false         # WebUI 开关:调工具 installer

WebUI 设置页新增「全局流量监视器」区:经新代理端点读写工具 config(设置项 = §05 工具侧参数表)、显示 /status、自启开关(幂等调 gtm install-autostart)。前端复用既有设置页表单框架,不新开页面。

出口新配置键过 validate_config 守卫(缺校验/缺 schema 即红);设置页读写工具参数真机可见;未知键仍被拒。

S7auto-qb 接收面

新增路由 POST /api/traffic/monitor/notify(复用 make_require_token 鉴权):校验 → 事件号/冷却去重 → _enqueue 主循环命令(黄金法则 5,不绕开单写线程)→ 重读 dat_path 指向的历史文件(现有解析路径)→ 重发流量快照(_publish_traffic 等价逻辑)→ 既有 SSE/轮询通道自然推前端,历史流量图与顶栏刷新。启动时若 enabled 且 subscribe:向工具注册订阅 + 起心跳;停止时注销。

出口端点鉴权/冷却/重复事件单测;真机:工具发事件 → WebUI 历史图与顶栏 ≤ 数秒内刷新(对照 E2)。
