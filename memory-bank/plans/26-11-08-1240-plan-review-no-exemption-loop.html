PLAN · memory-bank · doc-topic: review-no-exemption-loop

评审流程改造: 废除裁量豁免 + 修复增量强制复评 + 基哈希机械闸门

本篇只回答:怎么把分批评审的两条政策缝——「小提交与修复增量不经评审」——闭合掉:Review-Skip 裁量豁免整体退役、可评行数 >0 必评、每次增改当场复评直到「裁决后零 actionable」,并以基哈希机械闸门把「当场复评」从纪律变成不可绕过。锚点合并拓扑 bug(26-11-08-0903)已修,不在本篇范围。

§01目标与设计原则

用户观察到部分豁免审核的提交与并发工作交错(2026-11-08 会话)。实证澄清:所谓「同时合并 review」事故 = 26-11-08-0903——平铺 log 锚点被侧分支 tip(带的是正常 Review: trailer)遮蔽 + 树差把主线已评整支算进本批(实算 9910 行 vs 真实 272),commit a9e1cbcf 已修;废除豁免对它是无效药。真正未闭合的是两条政策缝:

  • 缝① 小提交:累计 <50 行且未触安全面 → 整批跳过(SKILL.md ① 触发表)。
  • 缝② 修复增量:评审发现 → 修复 ≤100 行 → 不强制复评(SKILL.md ⑤「修复后不强制二轮」),trailer 的 检 P/T 覆盖不到这最后一公里。

目标(做到什么算成):任何可评内容增量在提交前都有对应评审轮次;每轮出口 = 裁决后零 actionable;「改了没复评」由闸门机械拦截,不靠自觉。

设计不变量(本轮不动):判断与机械分离;评审对象定义(代码 + 事实性文档,生成物/记账类机械排除);能力分档(≤400 全能档 / 敏感面分面 / >400 拆批);pack 前置 sync + 三钉自检;两个已声明残余窗口(④ 评完到提交间远端推进、⑤ remerge 失败冲突解决面)维持声明。

§02现状与痛点

机械面现状:批次锚点 = first-parent 主线最近一条带 Review:/Review-Skip: 的提交(check_review_trace.py:277,两者都推进锚点——豁免提交不会滚进别人的批次);闸门强制 trailer 并校验 检 P/T 下界 P ≥ 修+入池;行数实算含未跟踪文件、记账类/生成物不计入。能力分档:≤400 行全能档 1 派遣 / 触安全面分面 2-3 派遣 / >400 拆批。

痛点证据:

  • 豁免是裁量口:Review-Skip: 仅要求理由 ≥4 字,「确属免评」全靠 agent 自觉;2026-10 以来 27 笔。多 clone 并发时,任何一笔未评小改都与远端工作交错入库。
  • 修复增量缝:⑤ 现行「修复后不强制二轮;>100 行才追加一轮」,≤100 行的修复 diff 无人看过就随批入库。
  • 字面「空 []」不可用:实测发现数 ≈ 派发次数 × 5.6、与批次大小无关(reports/26-11-06-0723-report-review-capacity-experiment.html),原始空数组存在两个失效模式——不终止(nit 底噪循环)与 Goodhart(出口是空数组时,最省力的路是软化 reviewer 提示词,评审质量静默塌方且不可审计)。出口必须落在裁决层。

§03方案总览

三条主线 + 一条边界,全部已拍板(结论编号见 §06):

3.1 豁免退役(D2 / D8 / D9)

  • Review-Skip: trailer 退役:新提交写它 → 闸门判红;历史 trailer 在锚点 walk 照旧识别,不追溯。
  • 闸门下限退役:可评行数 >0 即必须有 Review: trailer;实算恒 0(纯生成物/记账类)才静默。
  • 对象定义保留:代码 + 事实性文档才可评;生成物(gen_all.py --list 清单)与记账类(任务档案/会话切片/基线切片)机械排除不计行;混合提交只数可评面。

3.2 修复循环(D3 / D4 / D5 / D10)

  • 扳机:上一轮评审快照之后,工作树可评内容出现任何新 diff → 必走一轮;dev.fmt 算改动(要格式化就在评审前做,不设「只是格式化」口子);记账/生成物补写不触发。
  • 出口:裁决后零 actionable——refute 弃、计划外入池算闭合、blocker/major/minor 当场修完;nit 不阻塞但留痕(档案 review 行)。轮次不限,直到某轮零 actionable。
  • 载体(形态修正):修复发生在工作树,轮间无提交对象,对象级增量不可行(git stash create 不含未跟踪文件,弃)。每轮 pack 照旧生成整批过滤 diff(锚点→当前树),评审指令限定「只报新增改动的问题 + 校验上一轮发现未被回退」,上一轮发现清单随包附带——已干净的代码不被重新开庭(意图保住),载体可落地。
  • 接缝终审:收口接缝终审(≤200 行跨批)保留原样;发现处置与批次轮拉齐(相关 blocker/major/minor 修完才收尾,计划外入池);接缝修复引出的新改动照扳机走循环。

3.3 基哈希机械闸门(D6 / D7)

  • trailer 新增 · 轮 <R>(缺省 1,修复循环轮数)与 · 基 <hash>(= 末轮 pack 输出的整批过滤 diff 哈希);修 / 入池 / 检 P/T 改全轮累计口径,下界 P ≥ 修+入池 照旧成立;派发 K 保持首轮拓扑派遣口径、不累计——修复轮派遣若计入 K,会掩盖 >400 行批「首轮只派 1 次」的违规、稀释容量下界(发现数 ∝ 派发次数),修复轮深度已由 轮 R 与累计 检 P/T 反映(P0 评审 F4 修正)。
  • 提交时闸门按同一套过滤实现重算暂存 diff 哈希,与 · 基 比对:不一致判红 → 补一轮复评取新基;失败行给「重跑 pack 取新基」出路。
  • review.pack 每次运行输出当前基哈希;过滤实现与实算共用,末轮后补写记账/生成物不影响哈希(不误红)。
Review: <范围> · <N> 行 · blocker <N> · 修 <N> · 入池 <N> · 检 P/T[ · 轮 R] · 基 <hash>[ · 派发 K][ · 分面][ · 齐平 <远端tip前8位>]

3.4 派遣与分档边界(D11 / D12)

不加轻量档:统一子代理派遣,每轮照走 pack 前置 sync + 三钉;无子代理环境走 ⑧ 降级自查(同 schema、过 review.check、同样留痕),任何环境下都无需豁免逃生门。全能档 400 行阈值与拆批/分面拓扑原样保留——退役的只有 50 行下限,与 400 行上限互不相干。
