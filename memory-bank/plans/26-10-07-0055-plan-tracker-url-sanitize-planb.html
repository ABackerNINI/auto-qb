01任务与转计划裁定

现状核验（本计划的第一手结论）

报告档 meta 标「已实施(2026-10-04 复核)」指的是前置工程——日志端脱敏（issue 26-09-21-1408：infra/utils.py:294 sanitize_tracker_url，只留主地址形态，用于 webui/commands.py:631/:640 的编辑/移除日志行）已落码。方案 B 的四个波次本体按 20bd2157 取证均未落码：Facade torrents_trackers 纯透传、详情 API 仍把原文发给浏览器、编辑功能全链路在、仓里没有 mask 函数。本计划即从零开工。

批次结构修正（转计划时发现的编排问题）

报告 §07-4 建议「先批 W1 + W2 止血」——这条不可执行。W2 让 /api/torrents/{hash}/trackers 只回 mask 值后，前端移除按钮提交的也是 mask 值（drawer.js:556 trackerRemove 提交的就是行上显示的 url），而旧后端 _cmd_remove_tracker（commands.py:634）把它原样直传 qB 的 torrents_remove_trackers(original_url=…)——qB 按原文精确匹配，必然找不到。移除功能会在 W2 与 W3 之间被打断。同理，编辑弹窗在 W2 后预填的是 mask 值，等于已废。所以：详情 API 收口、删除改道、编辑下线三件事必须收敛成原子批次（本计划 S2/S3），不能按报告的波次跨批拆开。

转计划裁定（三个实现口径，开工前可否决）

  1. mask 函数 = 新增 mask_tracker_url()，不动既有的 sanitize_tracker_url()。报告在两个选项里留了口子（§05-W1）：选新增的理由是日志路径（只留主地址）的行为与 test_utils.py:1115 既有测试一行不动，符合保守默认；日志不需要 path 与参数名，两个形态不冲突。
  2. 批次重排为 S1→S4（见 §04）：S1 源头归一化（零行为）→ S2 编辑下线（纯删除，先杀掉「弹窗预填原文」这个最敏感点）→ S3 收口切换（详情 API + 删除改道，原子批）→ S4 守阵 + 红验 + 回写。报告 W1 的「补一个脱敏字段、保留原文不下线」是双轨期的残留表述，单轨定案（报告 §01-⑧）后 S1 直接归一到位，同样零行为。
  3. path 末段处置规则：报告示例 https://site/announce?passkey=9f2c… 保留 path 可见，而 §04 又提到「path 末段是可能藏凭据的位置」。合成规则：path 末段若为高熵形态（≥16 位连续 [A-Za-z0-9_-]）则整段替换成 hash，否则原样保留——announce/announce.php 等端点名保留诊断价值，/announce/<32位hex> 这类 path 凭据被覆盖。规则是纯字符串判定，确定性不受影响。

03方案 B 执行口径

mask_tracker_url(url) -> str 规格（infra/utils.py，R1–R9）

#规则
R1虚拟条目原样透传：url 以 "**" / "[DHT]" / "[PeX]" / "[LSD]" 开头 → 原样返回，不进任何改写（裸 [DHT] 形态也覆盖；报告 §02 实测 sanitize 会把裸形态小写破坏前缀识别——mask 必须在函数内挡掉，不依赖调用方过滤）。
R2非字符串 / 空 / 解析不出 host → 返回 SANITIZE_FALLBACK（"<invalid-url>"），绝不抛异常。后果可控：两侧同函数 ⇒ 比对一致；多条不可解析 → 命中多条 → error 不猜。
R3scheme 保留并小写；缺 scheme 时从 path 首段兜底取 host（镜像 sanitize 的处理）。
R4netloc 去 userinfo（取 @ 之后），host 小写，端口保留。
R5path 保留；末段匹配 ^[A-Za-z0-9][A-Za-z0-9_-]{15,}$（≥16 位高熵）→ 整段替换为 hash16；fragment 丢弃。
R6query 按 & 拆段，有 = 的段改写为 名=hash16(原值)（值取原文子串，不做百分号解码），裸名参数原样；段序不变。铁律：不按参数名挑——所有值一律 hash，passkey/authkey/token/uid/secret/任意私站命名同权。
R7hash16(v) = sha256(v.encode("utf-8")).hexdigest()[:16]。确定性、不加盐（加盐则两次拉取值不同，唯一性与基线差分一起失效）。
R8唯一性：同 host 不同 path、同 path 不同凭据值 ⇒ mask 互异（hash 保值差异）；完全相同 url ⇒ mask 相同。⇒ mask 可当内容标识直接用于删除定位（W3 方案的前提）。
R9配套 mask_tracker_entry(entry: dict) -> dict：条目缺 url 或命中 R1 → 原样返回；否则 {**entry, "url": mask_tracker_url(entry["url"])}，status/msg/num_peers 等其余字段不动。

形态示例：

https://pt.example.com/announce?passkey=abc123def456&uid=7
  → https://pt.example.com/announce?passkey=<h16>&uid=<h16>      (path/参数名可见, 值全 hash)

udp://tracker.opentrackr.org:1337/announce
  → 原样 (无凭据可藏; path 末段 "announce" 不命中 R5)

https://pt.example.com/announce/1a2b3c4d5e6f7a8b9c0d1e2f
  → https://pt.example.com/announce/<h16>                        (path 末段 24 位高熵 → hash)

** [DHT] **   →   ** [DHT] **                                     (R1 透传)

守阵断言红验方式
