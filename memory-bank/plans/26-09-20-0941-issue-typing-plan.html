01为什么改

现有 skill 只有一种形态：7 段固定结构的 HTML 报告（现象 / 证据 / 影响面 / 根因 / 建议修法 A+B / 涉及文件 / 状态日志）。四个毛病，都能在存量里对上号：

毛病存量的实证
表单过重26-09-19-2359-memory-bank-push-rule-drift 本质是"conventions.md 写禁 push，与 AGENTS.md 新规矛盾"，一句话的事，却走了全套 7 段报告
分析易过期报告里钉的是 app.js:2315 / app.js:3319 这类当时的行号与"初步根因"；到真正开工时 web_runtime 重构已落地，行号与结论双双失效
没有类型文件名只带 <领域>-<专题>，索引按状态分区；想只看"文档类"或"性能类"只能逐条读
绑死本仓库meta 叫 aqb-issue-*、issues 目录写死 memory-bank/issues/、仓库根靠 parents[4] 反推 —— 换项目就跑不起来
目标不是"把报告写得更短"，而是让入池成本与问题重量成正比：轻问题 2 分钟入池回主线，重问题才值得停下来取证。

02通用化：去项目绑定

这套 skill 要能在之后的项目里直接装、直接跑，所以项目相关的六个绑定点全部参数化。通用部分（类型枚举、档位规则、五态状态机、防过期原则）不动 —— 它们本来就不含项目假设。

绑定点现在改成
meta 名aqb-issue-slug / -stamp / -status / -title / -summaryissue-slug / -stamp / -status / -title / -summary，另加 issue-type / issue-tier。去掉 aqb- 前缀，任何项目都能读
issues 目录硬编码 <root>/memory-bank/issues--dir 参数；不传时按序探测 memory-bank/issues → issues → docs/issues，都不存在则报错要求显式指定
仓库根Path(__file__).parents[4]
（假定 skill 装在 .agents/skills/<name>/scripts/）		从脚本目录向上探测 .git（目录，或 worktree 的 .git 文件）作为根；探测不到再退回 parents[4]；--root 始终可覆盖
模板品牌kicker「auto-qb · 计划外问题」
footer「auto-qb · ...」		通用文案，不出现项目名；需要时用 --project <名> 注入，不传就不显示
索引 HEADER写死 ../../.agents/skills/create-issue/... 相对链接由脚本按 issues 目录与根的相对关系算出 skill 链接；算不出就只写脚本名、不写链接

03类型枚举

参考 GitHub 的 label / issue-type 分类，按本仓库的实际分布收敛成 8 类。类型 token 直接进文件名，是唯一的强制分类维度（优先级、模块这些不加 —— 加了就又变成大单）。枚举单点定义在 new_issue.py 的 TYPES 常量里，以后增删只改这一处。

token含义什么时候用它默认档位
bug缺陷行为不符预期、报错、回归、平台兼容L2 标准
perf性能慢、卡顿、无谓重建、内存 / CPUL2 标准
docs文档文档漂移 / 缺失 / 写错 / 与代码不一致L1 便签
test测试用例缺失、失败、守卫缺口L1（缺口）/ L2（失败）
refactor技术债重构、耦合、命名 / 格式不一致、历史 TODOL1 便签
feat功能新增能力或增强（未排期）L2 标准
chore杂项依赖升级、CI、配置、脚本维护L1 便签
question待拍板缺决策就动不了手（方向二选一、等用户定调）L1 便签

不单列的类型，归到哪儿

  • security —— 不入池。与 scope-guard 的例外 2 一致：当场告知用户并修；确需留痕时用 bug + 严重度"高"。
  • regression / compatibility —— 归 bug，正文首行标注即可，不占一个类型。
  • epic / RFC / 大改造 —— 不进 issues/，走 memory-bank/tasks/ 档案或 memory-bank/plans/ 计划。这一条要写进 skill 的反模式。

04三档表单

类型决定档位，档位决定模板。L1 便签是这次新增的形态 —— 大约 30 行 HTML，三段，两分钟填完。

L1 便签L2 标准
适用docs / refactor / chore / question / test 缺口bug / perf / feat / test 失败
必填段现象一句话 · 位置 · 状态日志现象与场景 · 证据（贴原文）· 影响面（3 行表）· 定位锚点 · 状态日志
可选段建议一句根因（默认"待查"）· 建议修法（不再强制 A/B 两案）
时间预算≤ 2 分钟≤ 10 分钟，超时就只写事实 + 待查，回主线

对比现在的 7 段报告：省掉的是"影响面四行表 / 根因 / 方案 A+B / 涉及文件清单" —— 对一句"这里写错了"来说，那些全是噪声。

L2 删了什么、留了什么

  • 涉及文件清单（独立段） → 并入"定位锚点"，与符号名、grep 词写在一起。
  • 根因（初步）必填 → 降为可选，模板里默认就是"待查"。
  • 建议修法 方案 A / 方案 B 必填 → 一段可选，有想法就写一句，没有就"待定"。
  • 保留：现象与场景、证据（贴原文不转述）、影响面（收敛成 3 行）、状态变更日志。

05文件名与索引

命名

<issues dir>/<YY-MM-DD-HHMM>-<type>-<slug>.html

memory-bank/issues/26-09-19-2359-docs-memory-bank-push-rule-drift.html
memory-bank/issues/26-09-20-0941-bug-webui-show-row-no-pending.html
                        └ type 是文件名第二段，扫描目录就能按类型聚合
  • slug 放宽：正则从"必须两段"改成 ^[a-z0-9]+(-[a-z0-9]+)*$（允许单段），<领域>-<专题> 降级为"建议"而非强制 —— 分类职责已交给 type。
  • 脚本新增 --type（必填，choices 校验）；--tier 可不传，由 type 推导，传了就覆盖。
  • meta：新增 issue-type（索引据此聚合）与 issue-tier（只做统计）；原有 5 个 meta 去掉 aqb- 前缀（见第 02 节）。

索引行格式

## Open
- [docs] [conventions.md 禁 push 与 AGENTS.md 矛盾](26-09-19-2359-docs-...html) — 一句话
- [perf] [节拍门控未减少总重建次数](26-09-19-2122-perf-...html) — 一句话
  • 仍按状态分区（状态是排期视角）；行内 [type] 取代原来的 `Open` · 冗余前缀。
  • 索引顶部加一张"按类型计数"表（Open 状态下的分布），扫一眼就知道欠债结构。
  • 文件名缺 type 或 type 不在枚举里 → 脚本报错退出（--check 同样校验），护栏建在生成器里而不是靠自觉。

06防过期原则

这几条要写进 SKILL.md，是这次改动真正的骨架 —— 光把表单砍短，agent 还是会为了填满字段去读代码。

  1. 只记事实，不记结论。根因与修法默认"待查"；有结论才写，不确定就写"已排除：X、Y"。
  2. 行号要标"当时"。定位锚点 = 符号名 + grep 关键词 + 当时的行号（注明取证时间）。代码漂移后靠符号和 grep 重新定位，行号只是加速项。
  3. 不为填单做分析。入池是"顺手记一笔"，不是"先调查清楚"。时间预算写死在 skill 里：L1 ≤ 2 分钟、L2 ≤ 10 分钟。
  4. 证据贴原文并标时间。日志 / 报错 / 命令输出原样贴，附取证时间，让读者自己判断新鲜度。
  5. 开工时先复验。认领一条 issue 后第一件事是重跑锚点、确认现象仍在；报告里补一行"复验：<时间> 仍复现 / 已消失"。
