接口核实结论：qB 有现成接口，不需要绕路

qBittorrent WebAPI 从 2.0 起就提供备用速度模式端点，备用限速值走 app/preferences。项目所依赖的 qbittorrent-api 2026.8.1 已全部封装。

端点 / 字段语义项目侧现状
GET /api/v2/transfer/speedLimitsMode 返回 0（主速度）或 1（备用速度） 需新增透传 后端暂未调用
POST /api/v2/transfer/toggleSpeedLimitsMode 在主/备之间切换（qB 4.5+ 亦可用 setSpeedLimitsMode 带 mode 精确指定） 需新增命令 入命令队列走单一写线程
app/preferences: alt_dl_limit / alt_up_limit 备用下行/上行限速，单位 bytes/s，0 = 不限（主速度另有 transfer 端点，与本项目 qbapi.py 现有单点一致） 需新增读写 app_set_preferences() 客户端已有
server_state.use_alt_speed_limits 当前是否备用速度生效，随 qB maindata 每轮下发 已在前端 规则引擎 sys.alt_speed_on 已消费，前端可从 statsServer 直接读，无需新查询端点

后端落点：切换命令在 webui/commands.py 注册并复用命令回执（waitCmd）模式；备用限速读写挂在 core/qbapi.py 现有全局限速方法旁。前端按钮的点亮态直接吃已有轮询，不引入新请求周期。

01

三套模板的公共决定

以下六条在三套模板里完全一致，挑选时只需比较「位置 × 图标 × 弹窗布局」的差异。

  • 只放图标 —— 按用户要求全部为纯图标按钮，语义靠 title 悬浮补全（与现有 .sb-spd 同一口径）。
  • 位置带 —— 都在状态栏右侧速度区（.sb-speed）附近，不进左侧流量/统计区。
  • 弹窗主/备同窗 —— 对齐 qBittorrent 客户端「速度设置一页含主+备」的习惯；落点为扩展现有 .speed-pop 就近浮层（380px），不新开居中 modal。
  • 写入通道分工 —— 主速度沿用现有 speed override 通道；备用速度新增 setPreferences(alt_dl_limit/alt_up_limit) 命令。两组一次「应用」分别提交。
  • 图标体系 —— 走各主题 index.html 内联 sprite：乌龟（备速）为本设计新绘 symbol，仪表 i-gauge 复活复用；atlas / prism / console 三份 sprite 同步加。
  • 与限速曲线的关系 —— 曲线任务只写主速度（transfer 端点），不动 alt_*；备用速度独立。计划阶段需注明二者互不接管。

模板 A · 乌龟开关

TPL-A

单图标双态 · 贴 qB 桌面心智 · 最小改动

一只乌龟图标放在速度组最左：熄灭 = 主速度生效，点亮（绿）= 备用速度生效。单击切换。这正是 qBittorrent 桌面端/官方 WebUI 的心智模型（乌龟 = 备用限速），PT 老手零学习成本。

模板 B · 角标合成图标

TPL-B

仪表+乌龟角标 · 独立位 · 与"完整统计"同级

按钮不挤进速度组，而是独立放在速度组之前（与左侧「完整统计」按钮同视觉级），一眼区分「切换」与「改速度」两种动作。图标 = 仪表盘主体 + 右下角乌龟角标：仪表态表示主速全开，角标亮起表示备速接管。

优点 — 动作语义最清晰（切模式 ≠ 改限速，两个位置两件事）；独立位不受速度组 hover 样式干扰；合图标在 16px 下仍有层次感。

模板 C · 分段直切

TPL-C

仪表|乌龟两段并排 · 状态零学习成本

不做「一只图标变两态」，而是两段并排、当前段高亮：仪表段 = 主速度，乌龟段 = 备用速度。点另一段即切换。哪套在生效不看颜色联想、直接看高亮在哪段，认知负担最低。

优点 — 状态表达最直白（高亮在哪段，哪套生效），不需要 title 也能看懂；两态各有专属图标，色盲友好（位置信息 + 颜色双通道）。
代价 — 占两个图标位（分段容器约 54px），状态栏最宽；「点一下就切」没有确认，误触成本比 A/B 略高（但切换本身可逆、低危）。

05

横向对比与推荐

弹窗三套都是主/备同窗，差异只在布局（纵向两节 / 左右两列 / 双组+生效高亮），实现成本几乎相同；真正的取舍在状态栏按钮。

维度A 乌龟开关B 角标合成C 分段直切
状态栏占宽最小（约 24px）小（约 26px，但独立占位）最大（约 54px）
状态可读性靠灭/亮 + title靠角标 + 软底最好（高亮位置直读）
贴 qB 心智最高（乌龟 = 备速是 qB 惯例）独创隐喻，需学习较高（乌龟仍在）
误触风险低（按钮小、语义单一）低略高（大热区、即点即切）
实现改动量最小：+1 按钮 + 浮层加一节中：+1 独立按钮 + 合图标 + 浮层两列中：+1 分段控件 + 浮层双组高亮
推荐 A（乌龟开关） —— 满足「只图标按钮」前提下改动最小、与 qB 桌面/官方 WebUI 的乌龟隐喻完全对齐，占宽最省。若更看重不靠悬浮提示就看懂当前模式，选 C（分段直切）；B 的独立位适合未来还要挂「模式相关动作」（如定时切换入口）时再考虑。
