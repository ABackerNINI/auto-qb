整组移动外部旧路径种子零破坏处置 (IYUU 辅种冲突)

本篇只回答: 整组移动收尾窗前后, IYUU 等外部工具经 qB WEBUI 按旧路径添加的辅种种子如何被识别与处置——收尾窗内零破坏纳入收尾、收尾后只通知; 全程不删种、不重加、不跳检、不静默全量校验。

§01目标与设计原则

背景

IYUU 按其缓存的本地种子 save_path 经 qB WEBUI 直接添加跨站辅种种子。整组移动 (relocate) 会改变组内种子的路径, 移动后旧路径先后经历「别名桥接 → 别名删除」两个阶段, IYUU 用旧路径加的新种子在两个阶段各有一种坏法 (§02)。

目标 (三条全达成 = 完成)

  1. 收尾窗内到达的旧路径同内容种子自动纳入在途收尾, 收尾不再被它们卡死;
  2. 收尾后到达的旧路径种子 100% 被发现并通知 (含数据现位置提示);
  3. 对种子与组数据零破坏。

设计底线 (不变量)

  • 零破坏性动作: 不删种、不重加、不跳检、绝不静默跑全量校验 (D8/D9);
  • 文件清单不一致的种子绝不自动处置, 只告警 (D4);
  • 处置不依赖 tracker 配置命中, 与 IYUU 具体添加形态无关 (D6);
  • 全量扫描只在时机触发, 无周期兜底 (D12/D13);
  • 一切处置动作进事件日志 (D14)。

§02现状与痛点

relocate 收尾机制三段 (现状)

  1. 搬迁: qB setLocation 搬 mover 数据 → 新位置有数据, 其余成员 save_path 仍是旧路径;
  2. 桥接: moved 相位末在旧路径建别名 (junction/symlink/hardlink), 穿透校验通过转 armed 后, 旧路径成员经别名继续做种;
  3. 收尾: qB 下线窗 daemon 改写 BT_backup fastresume (save_path → 新路径) → 重启 qB → 核验全员到位 → 删链门扫「还有谁依赖旧路径」→ 删别名 → done。

痛点

  • 场景 A (收尾窗内到达): 新种子 save_path = 旧路径, 数据经别名可达、能正常做种, 但它不是 job 成员 ⇒ ① 删链门把它当第三方依赖, 收尾卡在 armed 不结束; ② fastresume 改写不覆盖它, 永远到不了新路径; ③ 「删链门扫描 → 删链」窄窗内到达则删链后立即文件丢失。用户实际撞到的是本场景。
  • 场景 B (收尾完成后到达): IYUU 服务端缓存移动前路径, 下次辅种仍按旧路径加; 别名已删 ⇒ 立即缺文件。qB 对 skip_checking 添加也做基础文件检查 (D11), 故呈 missingFiles 而非假种, 但种子不可用。
  • 链式再迁移 (A→B→C): IYUU 缓存最老的第 A 代路径, 需把终态 job 账的 src→dst 边拼成传递闭包; 终态账滚动保留 20 条, 老映射会消失。
  • 侦测面限制: 新增种子事件管线在 tracker 域名未命中配置时直接跳过 (qbmanager.py:1057-1071), 事件收不到; relocate 目前无新增种子订阅。

§03方案总览

落点: relocate 模块内新面 (relocate_foreign.py + 配置键挂 relocate 段), 复用 job 账 / 别名 / 收尾机器, 不建独立模块 (D7)。

侦测 (D12): 每拍消费同步层原始 added 差集 (store 现算, 未经 tracker 过滤门) —— 成本 O(本拍新增), 与库里种子总数无关; 全量扫描只在四个时机触发 (启动首轮 / job arm / 开关翻转 / qB 重连首轮), 无周期兜底 (D13)。

处置分流 (均以「路径命中 + 文件清单一致」为前提, D4):

  • 场景 A (活跃 job 作用域命中) → 零破坏纳入收尾 (S3): 追加 state job.hashes + spec.members 双面; pre-armed 到达纳入即暂停、arm 随成员恢复 (D10); 待收尾标签增量补打。
  • 场景 B (终态账旧根命中, 含链式闭包) → 只通知 (S5): 告警含数据现位置; 处置留给用户 (D8)。

纳入后的自动覆盖面 (实时派生自 job.hashes): fastresume 改写清单 (spec 双写后)、核验覆盖、删链门成员豁免、缺文件扫描让路、跳检让路、既有删种拦截面 (计划 26-11-05-0808 的 D16)。需手补的只有: spec 双写、pending_tag 增量、pre-armed 暂停/恢复、核验悬挂放宽 (S4)。

明确不做: 删种重加、跳检、自动全量校验、场景 B 种子自动迁移 (D8/D9)。

§07风险与对策

风险触发条件处置
R1 核验悬挂放大纳入成员改写迟迟不回流, 触发单次重放闸后永久悬挂S4 守卫: 按 journal rewrite 状态区分 WAIT 与 VERIFY_FAILED
R2 删链窄窗漏侦测「删链门扫描 → 删链」之间到达, 差集已消费但处理未及自愈: 落场景 B 通知; 不扩大自动动作
R3 差集漏消费单拍差集异常跳过且无周期兜底 (D13)接受边界: 下次时机触发自愈; 场景 A 漏纳的可见后果 = 删链门卡住收尾 (良性态); 频率异常时再议兜底
R4 IYUU 突发批量加种一拍差集数十条单拍有界 FIFO 分拍处理, 主循环不被拖长
R5 清单不一致种子写穿目录别名目录别名形态下同目录异内容种子落旧路径既有已确认行为 (迁移确认框明示), 只告警不改
R6 内容不同但大小相同的跨站种罕见重打包场景属 IYUU/跳检自身域, 不新增校验; 文档记边界
R7 终态账滚动丢映射20 条滚出最老 done 账通知文案降级「映射已过期」; 不新增持久账 (D2)
R8 spec 第二写者armed 后读-改-写 spec仅主循环线程写 + 原子读改写; journal 零写 (改写清单 = spec.members − 已收口 现算)
R9 纳入成员被用户删收尾窗内用户删除纳入种子absence_shrink 既有机制正确收缩 (静默缺席不计数), 无新机制
