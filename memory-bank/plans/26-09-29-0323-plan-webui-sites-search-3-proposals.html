站点搜索 × 列表交互 · 三方案 覆盖 · 键盘 · 命中数 · 按钮区分

对象: 设置页 → 站点 分区(trackers) 的搜索与站点列表 · 现状: 跳转器交互(9667186, 命中下拉 + 点外即收) · 关联: 计划 26-09-27-1852 / 档案 tasks/26-09-28-webui-sites-page-search · 样机: 令牌取控制台皮肤真值, 实现走皮肤令牌(三皮肤共用)

怎么用 三套方案的样机都能真的操作: 点进搜索框敲字过滤, ↑↓ 移动、Enter 选中、Esc 清空(中文输入法组词中不误触)。 顶部标签或 123 切换方案。

现状四个痛点

搜索本体(全字段匹配、语法)已入库且好使; 要解决的是它的「呈现与操作」层。

P1
命中下拉盖住站点设置, 视觉突兀

浮层与页面同底色同边框, 盖上来缺少「这是一层」的层次表达; 收层虽已修(点外即收), 覆盖瞬间的观感仍是硬伤。

P2
不支持 ↑↓ / Enter

现在只有 Esc; 键盘用户必须鼠标点命中行, 高频挑站场景断手。

P3
命中数挤在搜索框里

「命中 4 / 8 个站点」常驻输入框右侧, 框内拥挤、宽度被挤占, 一打字就更逼仄。

P4
「新增站点 / 导入缺失站点」与站点 pill 同形同排

三个按钮共用 .hb-pill 一套皮, 动作和「对象」混在一行, 分不清哪个是站点哪个是操作。

对比 拍板 试输入: 云 · 教育 · -教育 · "电子书"

方案A · 就地过滤(Live Filter)

一句话: 干脆不要浮层。输入即过滤站点 pill 本身, 不匹配的变暗退后、匹配的原位待命 —— 没有「盖上来」这回事, 层次问题从根上消失; 命中数移出输入框落在列表上方一行, 新增/导入升格为独立动作条。

可交互样机 A点搜索框试试: 「云」看名称命中 · 「教育」看跨字段 · 「-教育」看仅排除词 · ↓Enter 键盘直达
站点 · 共 8 个

设计要点
  • 过滤不挪位: 不匹配的 pill 降为 18% 透明度 + 去饱和, 位置不动 —— 零回流跳动, 且保留「库里有谁」的上下文; 160ms 过渡。
  • 命中数一行: 「命中 4 / 8 个站点」落在搜索框与 pill 行之间(mono 小字淡入), 右侧顺手给 ↑↓Enter 键位提示; 输入框里从此只有输入。
  • 动作条独立: 新增(虚线描边)与导入(幽灵钮)在搜索框上方右对齐, 左端「站点 · 共 N 个」计数抬头 —— 动作与对象彻底分行分形。
  • 键盘: ↓↑ 在命中 pill 间移动(accent 描边指示), Enter 选中(选中即清词, 与现行跳转器拍板一致), Esc 清空。
  • 零命中: 计数行转 warn 色「没有命中」, 提示换更短的词; 上方「新增站点」动作条保持可用。
实现落点
settings.html(pill 行绑过滤 class + 计数行; 删 hb-tr-drop 分支) · config_hub.js(保留 hubTrackerHits; 增键盘焦点索引, 删点外收层对浮层的依赖) · console_hub.css(.off/.kb 态 + 计数行) · 守阵 test_frontend_tracker_search_wiring 同步(下拉断言改过滤断言)。
成本 / 风险
低 —— 结构变化最小(做减法删浮层)。风险: 站点很多时「变暗保留」视觉噪声略高; 搜索语法提示从浮层移到计数行后, 首次使用者少了下拉里的引导语, 靠 placeholder 承接。

方案B · 锚定面板(Refined Dropdown)

一句话: 保留跳转器形态, 把「下拉」升格为名副其实的一层面板。实底抬升面 + 面板头(命中数 + 键位) + 面板尾(Esc 提示) + 键盘活动项高亮与入场动画 —— 覆盖还在, 但它是有清晰层级语义的覆盖, 不再像页面自己长歪了一块。

可交互样机 B点搜索框敲字 → 面板浮现 · ↑↓ 移动 · Enter 打开 · Esc 收起 · 鼠标悬停即高亮
站点搜索 ↑↓ 选择Enter 打开
点命中直达详情, 搜索词不保留Esc 清空并收起
设计要点
  • 面板三段式: 头(「站点搜索」标签 + 命中数搬到这里 + 键位提示)/ 列表 / 尾(Esc 提示) —— 命中数从输入框里请出去, 输入框只剩输入与清空。
  • 分层面孔: bg-elev 实底 + border-strong + shadow-3 + 入场 160ms 上浮淡入, 与 search-help-pop 同一浮层视觉口径 —— 盖住详情时「这是一层」一眼可读。
  • 键盘活动项: ↑↓ 移动高亮(accent-soft 底 + 左缘 accent 竖条), 与「当前选中站」角标(当前)分属两个语义; Enter = 点命中(选中即清词收层), IME 组词中不劫持回车。
  • 动作区分离: 站点 pill 行尾加动作区 —— 「＋ 新增站点」虚线描边、「⤓ 导入缺失站点」幽灵钮, 与实底站点 pill 一眼分层; 搜索态整行隐藏(维持现行行为)。
  • 悬停即高亮: 鼠标 hover 同步键盘活动位, 键鼠混用不打架。
实现落点
settings.html(下拉容器改三段式结构 + pill 行尾动作区) · config_hub.js(命中索引 state + hubOnKey 扩 ↑↓/Enter, 现有 Esc/点外收层路径全保留) · console_hub.css(.px-* 面板头尾/活动条/入场动画, 视觉口径对齐 search-help-pop) · 守阵: 收起路径四条断言不变, 增键盘路径断言。
成本 / 风险
低-中 —— 现形态精修, 交互心智零迁移。风险: 覆盖详情的本质仍在(靠面板层次表达缓解); Enter 与中文输入法组词需 isComposing 守卫(三案通则); 面板限高内滚动与点外收层的边界要回归。

方案C · 聚焦搜索层(Focus Layer)

一句话: 搜索时让位 —— 整个分区退成背景, 搜索框升为主角。聚焦或敲字时, 站点列表与详情一起退隐变暗, 搜索行升为带实底面板的浮层、下方展开结果与快捷动作; 收起时整体交还。覆盖不再是事故, 而是主动的舞台调度。

可交互样机 C点搜索框(或敲字)进入搜索态 · ↑↓Enter 同 B · Esc / 点暗处退出 · 注意结果尾部的「新增站点「词」」
站点搜索 ↑↓ 选择Enter 打开
设计要点
  • 舞台调度: 进入搜索态, 列表与详情 280ms 退到 30% 透明度 + 暗幕垫底, 搜索行升为实底面板 —— 「谁在前台」由明暗直接回答, P1 的突兀感转为仪式感。
  • 面板结构同 B: 头(命中数在此)/ 列表 / 尾; 键盘行为与 B 完全一致, 学一次两处通用。
  • 尾部快捷动作(方案C 独有): 搜索态面板尾常驻「＋ 新增站点「词」」虚线钮 —— 搜不到就当场建, 不用退出搜索再找新增; 这是「导入缺失站点」流程的天然入口位。
  • 退出三路: Esc / 点暗幕 / 选中命中, 都交还舞台(反向过渡同一组令牌); 焦点始终留在输入框, 不跳。
  • 空态即引导: 聚焦未输入时面板给语法速览(空格=且 · -词排除 · "短语"), 教学成本压进交互里。
实现落点
同方案B 全部落点, 另加: config_hub.js(hub.searchFocus 状态 + 进入/退出方法, Esc 分支排进 hubOnKey 既有次序, 与 lifecycle escBusy 链核对) · console_hub.css(.pc-* 舞台/暗幕/退隐/升层) · settings.html(暗幕与面板结构) · 守阵增「进入/退出聚焦层」两条路径断言。
成本 / 风险
中 —— 状态机多一态, 但键盘/匹配层与 B 复用。风险: 聚焦层 z 序要与 aq-tip / hb-pop / 命令回执对表(浮层单点清单核对); 窄屏 + 输入法候选窗遮挡需真机实测; 暗幕不用 backdrop-filter(毛玻璃性能坑, pitfalls/web-ui/css-perf-parity)。

四条痛点全部解决是入场线, 差别在「结果呈现在哪」与状态复杂度。
