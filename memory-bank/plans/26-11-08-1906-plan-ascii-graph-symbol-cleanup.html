§01目标与设计原则

把 memory-bank/conventions/code-style.md 里「示例清单 + 等字兜底」的模糊禁令, 变成机检可读的判据; 存量按目录分批清偿; 同时立一道闸门防回潮。做到「规范 / 闸门 / 存量」三者同源、复扫归零算成。

  • 先定口径再动代码: 0044 的口径不落定, 1621 两件范围就定不下来, 闸门也没有判据。D1 是本计划的根决策。
  • 闸门带病上岗: 存量 309 单元 / 2178 处(基线 4cff729d)一次清不完(用户 2026-11-06 拍板「先入池等排期」), 闸门必须先能只拦新增、允许递减。
  • 判据单一事实源: 规范表 A 与闸门常量双向校验, 只改一侧当场红。
  • 不碰放行面: .md 与交付 *.html 放行; 功能性数据、逐字镜像、第三方设计骨架、WebUI 可见文案逐条豁免并写理由。
  • 范围守恒: 本轮只落判据 + 计划 + 闸门; 存量清偿与 issue 认领 / 翻状态仍等显式开工。commit / push 已由用户显式说「提交」解锁并于 R1 执行, 不改变存量源码零改动这一事实。
