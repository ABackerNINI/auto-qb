SEC 01

目标与范围

在不引入构建链、不触碰后端 API 的前提下，为新旧两套 UI 建立可长期并存的工程结构，并给新 UI 一套令牌化的多主题体系。

编号目标内容
G1全新视觉体系按 frontend-design 方法重定设计方向：数据密集、机房值守气质，一个记忆点（左栏舵台的速度大数字），明确拒绝 SaaS 卡片墙与深底单酸绿等 AI 模板特征。
G2并存可切换旧 UI 原样保留（唯一改动：顶栏加一个"新版 UI"链接），新 UI 走 /newui/，两套随时互切，旧 UI 全程可用。
G3多主题首发 5 套主题（2 暗 2 亮 1 品牌定制），全部落在 CSS 自定义属性层，切换不改组件样式，偏好持久化到 localStorage。
G4独立文件易维护新 UI 全部产物收敛在 src/auto_qb/web_ui/static/newui/ 子目录；逻辑层三件套（app.js / config_editor.js / config_rules.js）保持单一来源共享，不复制分叉。

明确不做

  • 不加后端配置键（主题偏好纯前端存储；将来若要服务端默认主题，须按黄金法则进 validate_config + schema.py）
  • 不引入构建链（沿用 vendored vue.global.prod.js，pip 装完即用的项目形态不变）
  • 不改任何 /api/* 端点与鉴权；不改 config.yml、auto-qb-data/（红线）
  • 不改动旧 style.css 与旧模板的既有类名/DOM 契约

现状盘点

2.1 前端文件规模

文件规模职责

2.2 架构事实（决定方案走向）

  1. 静态服务零成本扩展：web.py:277 app.mount("/", StaticFiles(directory=static_dir, html=True)) —— 新建 newui/index.html 后，/newui/ 天然可访问，后端零改动。
  2. 缓存已兜底：非 /api 响应统一 Cache-Control: no-cache（web.py:289），新目录文件自动继承，升级即生效。
  3. 模板即设计：Vue 无 template 选项，以 #app 容器 innerHTML 为模板 —— 新 UI = 新的 index.html 模板层 + 新 CSS；JS 逻辑层可原样复用。
  4. 令牌体系有先例：旧 style.css 头部注释明文规定"类名与 DOM 结构受 JS 耦合，重做视觉不得改名或增删列"，且已实现单 :root 令牌分层 —— 新 UI 的主题架构是这条路线的自然延伸。
  5. 脚本顺序固定：vue → config_editor.js → config_rules.js → app.js（mixin 先于根实例），新入口必须保持。
  6. 响应式现状：断点 1180px（隐藏指标胶囊）/ 900px（顶栏折行 + 单列）。

SEC 05

主题系统设计

5.1 令牌契约（tokens.css 定义的语义层）

组令牌（要点）
背景分层--bg / --bg-card / --bg-row / --bg-hover / --bg-sunken / --bg-elev / --glass
前景--fg / --fg-muted / --fg-dim / --fg-soft
品牌--accent ×（hi / soft / line / ring）
语义四色green / blue / warn / error ×（本色 / soft 底 / line 描边）—— 状态、上传下载、成败回执共用来源
数据扩展六色violet / pink / teal / indigo / cyan / lime × soft —— 筛选 chip、图例、分类图标
HR 标记--hr-pending / --hr-done ×（soft / line）+ --hr-hit
派生数据色--limit-hit / --limit-actual / --today-up / --today-down
描边与表面--border / --border-strong / --border-soft / --surface-1 / --surface-2 / --hairline
几何 / 动效radius 三档、shadow 三档、ease 三支、dur 三档（主题一般不动，特殊气质可覆盖 radius/阴影性格）
字体（新增）--font-display / --font-ui / --font-mono —— 主题的排版个性入口（系统字体栈，不引外部字体）
明暗声明（新增）每主题带 color-scheme: dark|light，原生控件（滚动条/表单）跟随

5.2 切换机制

  • 挂载点：<html data-theme="ocean">；组件样式永远只引用语义令牌。
  • theme.js 在 <head> 同步执行：读 localStorage['autoqb.ui.theme']，未选择时跟随 prefers-color-scheme —— 首帧即正确主题，无 FOUC。
  • 切换器：新 UI 顶栏弹出面板（色点 + 名称 + 明暗徽标），点选即换 + 持久化；URL ?theme= 可临时覆盖（便于冒烟测试）。
  • 5 个主题 CSS 全量随页面加载（合计约 8 KB，不值得做按需加载）。

5.3 首发主题集（色值为提案，以 M3 实测对比度为准）

5.4 主题质量约束

  • 对比度：正文 ≥ 4.5:1，大字（≥18px）≥ 3:1；每主题全部令牌对跑 WCAG 校验脚本（M3 落地）。
  • 状态不依赖单色：语义色一律配合图标/文字（沿用 sprite 单线图标语言），色弱可辨。
  • 数据六色（violet/pink/teal/indigo/cyan/lime）在每主题下互相可辨 —— 暗底提亮、亮底压暗，禁止直接复用暗色值。
  • 排版个性：--font-display 允许主题差异（如麦秋用衬线 display，深海用 Bahnschrift 类工业无衬线），正文一律高可读系统栈。

SEC 08

风险与红线

红线（任一违反即回滚）

  • config.yml 与 auto-qb-data/ 一个字节都不动。
  • 旧 style.css、旧 index.html 除"顶栏 +1 切换链接"外零改动。
  • 共享 JS 三件套只做加法：新增 computed/事件/守卫可以，改名/删除/改既有行为不行。
  • 不加配置键；不引构建链；不改 /api/*。
  • 新增测试必须同步该测试文件头部"## 测试计划"清单（项目明文规定）。
