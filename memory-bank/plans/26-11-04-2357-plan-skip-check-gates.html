§01目标与设计原则

背景: issue 26-10-11-2045 —— 跳检成功 ⇔ 种子已完成是同一事实的两面, 而闸门顺序 G3(已完成, blocked)排在 dedup(今日已跳检, blocked)之前, 执行路径取首个未过闸门 ⇒ 同日重跳恒被 G3 拦下, dedup 的文案与 skip 类别结构性不可达。

目标(做成即算成): 同一 hash 当日跳检成功后, 同日任意来源(web/规则直调 ops)再跳, 回执恢复 dedup 语义 —— 文案「今日已跳检过该种子(跨规则去重)」、类别 skip; 且不再需要测试侧手动还原 progress 才能走到 dedup。

设计底线/不变量:

  • 拦停行为零变化: 修复只改「回执的文案与类别」(fail→skip), 不改拒不拒 —— dedup 与 G3 同为 GATE_BLOCKED, force 均不可豁越, 两种顺序下都不发生重复跳检。
  • 谓词单点 + 两路径同源(T18)不破: 只调整 _skip_gates_detail 内 verdicts 追加顺序, 执行路径 _skip_gates(ops_verdict.py:80)与预检 skip_check_precheck(:49)自动同源, 不碰派生逻辑。
  • 只读铁律(T20)不破: dedup 判定本就是纯只读(dict 查询), 前移不引入任何写入/prune; skip_check_day 清理仍留在执行路径尾部。
  • filelist 短路语义不变: 短路条件是「存在 blocked 未过」—— dedup 与 G3 都是 blocked, 两种顺序下该布尔同值。

§02现状与痛点

闸门判定单点已从 ops_mod.py move-only 切到 ops_verdict.py(issue 复验行已更新锚点, 取证 2026-11-04):

锚点内容
ops_verdict.py:134顺序注释: G3 → G4 → G5 → G6 → G7 → G8 → partial → dedup → filelist
ops_verdict.py:188-200G3 谓词(progress>=1 且无在途证据 → blocked「种子已完成…跳检无任何意义」)
ops_verdict.py:288-291dedup 谓词(skip_check_day.get(hash)==今天 → blocked「今日已跳检过该种子(跨规则去重)」)
ops_verdict.py:80-87执行路径取首个未过闸门: dedup → ActionResult.skip, 其余 → fail

痛点:

  1. 回执类别被改写: web 批量跳检按 is_failed/is_skipped 分桶(commands_torrents.py:800-808), 「N 个跳过: 今日已跳检过…」变成「N 个失败: 种子已完成…」—— 失败计数虚高、跳过统计丢失 dedup 语义。
  2. 拒因文案被改写: 用户看到「已完成」而非「今日已跳检过」, 去重的自解释价值丢失。
  3. 可测性受损: 两条既有用例被迫手动还原 progress 绕开 G3(tests/test_ops_skip.py:94 · tests/test_checking_skip.py:196), 「保真替身下真实发生的同日重跳」没有用例覆盖 —— 即回归面裸奔。
  4. 新发现(入池时未记录): 规则侧第二重遮蔽 —— rules/actions/checking.py:100-103 决策链 0「种子非暂停中未完成状态, 无需校验」(skip)在委托 ctx.ops.skip_submit 之前; 跳检成功 ⇒ 已完成 ⇒ 规则源同日重跳恒被链 0 拦下, 同样走不到 ops dedup 闸门。与 ops 侧同构, 但类别本来就是 skip(无分桶口径损伤, 仅文案不同)。范围处置见 D1。

§03方案总览

主线(= issue 建议修法 1, 三选一里语义最正、代价最小): 在 _skip_gates_detail 内把 dedup 判定块(:288-291)整体移动到 G3/G4 判定之前(verdicts 追加顺序调整), 谓词与文案零变化; 同步更新 :134 顺序注释与 dedup 条目注释。改动约 10 行移动 + 注释。

为什么放最前而不是「G3 之前、G5 之后」: dedup 是全组最便宜的谓词(一次 dict 查询), 且「今日已跳检过」对「为什么不能再跳」是最直接的答案 —— 任何后续闸门(G5 在途校验/G8 组内证伪)提示的是「这次跳检本身的危险」, 而对一次重复请求, 「已经跳过了」恒为真且优先。代价: 当日已跳检 + 恰逢在途校验时, force=False 回执从 G5 的「正在全量校验」变为 dedup 的「今日已跳检过」—— 拦停等价(force 均到不了执行), 接受(风险 R3/D2 备选留了退路)。

分期: 单期完成(代码 + 测试 + 全量基线), 无分期表必要。
