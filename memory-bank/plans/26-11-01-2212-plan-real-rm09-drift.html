新面可 HTTP 断言范围(代码实况核实结论)

choose 规范形(保存通道)—— 可 HTTP 断言, 成立: 编辑器前端只改 static 477df090 面内文件, 服务端语义全部落在既有端点 PUT /api/config(routes/config.py:134)与校验器 src/auto_qb/config/validation/rules.py(choose 感知: W3-B 起校验器 fail-fast 同径分流 _validate_choose_block, 嵌套 choose 直接拒绝; 旧扁平形经 normalize_action_entry 单点漏斗翻译后同套校验)。链路: PUT → write_tree(结构校验与启动同路径, ConfigError → 400 + 磁盘不触碰) → R 级字段回退 → round-trip 写盘 → 投递 reload_config 热重载; 回执 changes 收顶层段路径 + restart_required。另有 POST /api/config/preview 只读同口径。⇒ 正向(applied/落盘 YAML 规范形/回读一致/热重载真作用)与负向(400 逐字文案 + 磁盘字节零触碰)均可脚本断言。

徽标面 —— 服务端无新端点, 纯 DOM 判定, 大部分不可 HTTP 断言: W1-B commit 36699dd5 只改 static 三件(config_hub.js/config_rules.js/settings.html), 无任何路由/配置改动; 未启用徽标与升级提示由前端 cfgRuleRetiredHint 单点直接从规则 spec 检测退役键名(stop_following_rules_if / ignore_next_action_error, 键面保留识别)渲染, 数据来源就是既有 GET /api/config 树(RM09-07 已覆盖的通道)。⇒ HTTP 侧唯一有意义的断言 = 退役键经 PUT 保存通道键面保留不拒绝、落盘保留(校验器 rules.py:43/158/404 对两退役键同径校验取值/params 而非拒收)—— 这条并入 RM09-11④; 徽标 DOM 渲染/卡脚提示交互已被静态守阵 tests/test_webui_static_dom_page.py(W1-B +107 行)与 e2e 轨钉住, 划引用 + L0 目视挂账, 不硬造用例(D2)。
