乐观UI扩面: 重命名乐观补丁+主备速度切预翻转

把乐观 UI 从 pause/resume 白名单扩面到两项真机实测确认的真缺口 —— 种子重命名（回执 5.6ms 但名字可见 ~1.7s）与主备速度切（确认延迟 0~1.5s 随 sync 相位）；添加种子经实测确认已被补刷新链覆盖（~34ms），不改码。设计主轴：零后端改动，全部落在前端显示层，复用既有乐观四件套（贴上/回执撤下/真值对账/兜底回滚）。

§01目标与设计原则

issue 26-10-01-2137 的扩面诉求（「所有基本不会失败的响应式反馈改成乐观 UI」+「添加种子当拍可见」）经代码分析与两轮 grilling 收窄，再经真机实测定案。做到什么程度算成：

  • S1 重命名：点击确认对话框后，行上新名字当帧可见（回执级 ~10ms）；命令失败 / 3s 无回执 / 8s 无真值确认，一律回滚原名，绝不留假状态。
  • S2 主备速度切：点击乌龟按钮立即预翻转高亮（0ms 级）；轮询确认后自然过渡不弹回；四路失败（回执 error / 发送失败 / 3s 无回执 / 8s 未确认）回滚。
  • S3 添加种子：不改码，凭实测数字结案（§02）。
设计底线 / 不变量（沿用乐观 UI 既有红线，违反即破坏设计）：① 失败 / 未知绝不留永久假状态——回滚显式回到补丁前的最后已知真值；② 值覆盖保持到「服务端真值同意」，不靠等真值的时间，防弹回；③ 值覆盖只盖「值来自我们」的字段（name 是我们下发的值；use_alt_speed_limits 的显示翻转是前端本地态，不是 store 回写）——写后同步字段边界（plan 26-10-21-2323 §4.3）零触碰，后端一行不改。

§02现状与痛点

2.1 机制现状

乐观 UI 主体在 static/shared/commands.js（P0-3，计划 26-09-20-2139 + D2 改造后）：白名单制，_optimisticPatch 只认 pause/resume；四件套 = 点击贴补丁（压暗）→ 回执撤下（~85ms）→ SSE truth 事件 / 轮询快照对账（_optimisticSettled 通用分支已支持任意补丁键逐键比对）→ 3s/8s 兜底回滚。机制本身是通用的，扩面成本在「结果是否可预测」与「行上哪些字段要盖」，不在机制。

2.2 真机实测（2026-10-30，qBittorrent-testing 5.2.3 @127.0.0.1:36595，auto-qb 独立配置 8 种子库）

链路回执数据可见回执时拉 stateSSE裁决
添加种子(n=5)~30ms~34ms(均值)命中 5/5ver ~14ms已被补刷新链覆盖,不改码
重命名(n=5)~5.6ms~1717ms(扑空 5/5)命中 0/5ver ~1694ms真缺口:补刷新时 qB 未反映新名,只能等下个 1.5s 周期
主备速度切(n=6+2 相位对照)~11ms均匀 [0, 1.5s] 随 sync 相位命中 0/8无 cmd/ver/truth 事件真缺口:前端只能靠轮询发现翻转,预翻转是唯一修法

注意:绝对值随库规模放大(代码注释:3000 种子全量序列化 ~63-189ms);各段相对结构是可靠结论。speed_alt_toggle 不在 RESYNC_COMMANDS(commands.py:121)⇒ 无补刷新;server_state 来自 store sync 快照(server/routes/state.py:83),不进视图版本 ⇒ 永远不会有 ver 事件。

2.3 代码锚点

  • 重命名:drawer.js::_editPost(hash,"rename")(drawer.js:553)只 toast,行名等下轮 sync;后端 commands.py:862 _cmd_rename_torrent 明确「快照 name 不手工改」。
  • 速度切:dialogs.js::toggleAltSpeed 注释「新状态由主轮询回读,不本地预翻转」(计划 26-09-28-0037 当时搁置);显示单点 sbAltOn(dialogs.js:730)读 statsServer.use_alt_speed_limits,乌龟按钮与限速浮层双组高亮都引它。
  • ⚠ 注释漂移(本轮分析被它带偏一轮):runtime.py:539 附近注释仍写「回执推迟到补刷新之后再写」,与 D2 后 defer_receipt「回执立即写」(runtime.py:1063)的实现不符——S4 随本计划修正。

§04实施步骤

S1 重命名乐观补丁(仅前端)

  1. commands.js:新增通用注册口 applyOptimisticPatch(hashes, action, patch) —— 与 applyOptimistic 同骨架,但补丁由调用方显式给出(不查 _optimisticPatch 白名单);注册进 pendingOps(grey=true, hold=false)。既有 resolveOptimistic / _expirePending / reapplyPending / _snapshotTruth / _optimisticSettled(通用分支逐键比对 {name})对它零改动生效。
  2. drawer.js::editRename:对话框确认后、POST 之前调 applyOptimisticPatch([hash], "rename", {name});沿用 _editPost 回执链——ok 转 hold(值覆盖到快照同意),error / 发送异常走 resolveOptimistic(..., false) 回滚原名。抽屉 detail 刷新照旧(_editPost 已有 _fetchDrawerDetail)。
  3. onTruthEvent 守卫:现实现给每个 pendingOp 注入 kind(commands.js:342)——rename 的真值是 kind 而非 name,必须加 action 守卫:只对 pause/resume 的 op 注入 kind,其余 action 的 op 保持原 patch(否则补丁被掺入无关键,对账判据被污染)。
  4. 覆盖面(决策 D3):_forEachRow 三数组(torrents / singles / 组成员)+ 抽屉 detail/头部;追剧行 / 集行的聚合名不碰(等 sync 自然更新,hold 兜底防弹回);memberByHash 不补丁(右键菜单 / 导出文件名短暂滞后 ≤1.7s,与今天持平)。
  5. 验收:确认对话框后行名当帧更新;命令失败回原名;3s 无回执回原名;快照 name 对齐后自动清除不弹回;真机复测「点击→行上新名可见」降到回执级(<50ms)。

S2 主备速度切预翻转(仅前端)

  1. state.js:data 加 altOverride: null(形如 { value, ts, hold },与 pendingOps 同语义的但单布尔)。
  2. dialogs.js:sbAltOn 改为「override 优先,server 兜底」的显示单点——乌龟按钮高亮 / title 与限速浮层双组高亮都引它,自动跟随;toggleAltSpeed:点击 → 预翻转(记录 server 当前值为回滚目标)→ POST;altToggling 防重入照旧。
  3. 四路回滚(决策 D8):回执 error / 发送失败 / 3s 无回执 → 回滚到 server 值;ok 转 hold,等 refresh 带回的 statsServer.use_alt_speed_limits 与 override 一致 → 清除 override(实测确认延迟 = 距下个 sync 节拍相位,≤1.5s);8s 未确认 → 清除(回落 server 值,借 TRUTH_HOLD_MS 同款兜底语义)。对账点放在 statsServer 赋值处(polling.js:365)。
  4. 验收:点击当帧翻转(0ms 级);e2e:点乌龟 → 高亮立即变 → 轮询确认后不弹回;故意断 SSE 验证 3s 回滚;双组高亮与按钮 title 同步。

S3 添加种子(不改码)

issue 复验行已补(2026-10-30):「下个 tick 才显示」已消失,实测 t0→数据可见均值 34ms。本计划不为此写任何代码;若未来大库下该数字劣化再回来另立方案(候选:前端「回执武装、ver 完成」的一次性定向刷新,而非直查真值——plan 26-10-21-2323 方向是减少直查)。

S4 注释修正(1 处)

runtime.py consume_commands 的 RESYNC_COMMANDS 分支注释改为 D2 现行语义:回执立即写(defer_receipt)、真值延后推、扑空窗口实测 <10ms;随 S1 同一提交,防实现与注释再度漂移。

S5 测试与验收口径(决策 D9)

  • 静态守阵:仿现有 webui 守阵模式——钉「applyOptimisticPatch 调用点必须先于 POST」「onTruthEvent 的 kind 注入必须带 action 守卫」两条,防回归。
  • 单测:rename 四态(贴上/回执 hold/失败回滚/快照对齐清除)+ altOverride 四态,仿 pause/resume 乐观既有用例;新测试同步文件头「## 测试计划」清单。
  • e2e 两条(Playwright,贴 26-10-06 计划既有矩阵):改名立即可见不弹回;乌龟按钮立即翻转不弹回。
  • 收尾:commands run test.full + kb.new baseline 记实测数字;真机复测两链延迟写进档案。
