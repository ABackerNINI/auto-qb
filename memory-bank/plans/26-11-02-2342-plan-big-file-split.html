§01目标与非目标

目标：在不改变任何运行时行为、接口、文案与视觉的前提下，把仓库中体量最大的源文件降下来，并按风险从低到高形成可独立验收的轮次。

  • G1 体量目标：对判定为「拆」的 56 个候选执行拆分，拆分后每个新文件 ≤1000 行；原文件要么消失，要么只保留入口/门面。
  • G2 零行为目标：第一轮只搬测试代码，生产代码（src/）零改动；后续轮次只做「等价搬迁 + 重导出」，不改逻辑、不改公开符号、不改默认值。
  • G3 可回滚目标：每个文件一条可独立回退的步骤，落一份「函数 → 目标文件」清单；失败只回退该文件/该批次，不回退整轮。
  • G4 可追溯目标：全部数字来自 26-11-02 扫描与本次 AST 结构统计，不在计划里新造数字；执行时新增数字必须来自实测输出。

非目标：

  • N1 不拆「没必要拆」的 2 个（演示样张、常量/接线内核）；22 个暂缓文件本轮不动，只在附录记录触发条件。
  • N2 不做架构重设计、不合并模块、不改配置键、不改测试断言语义、不做「顺手重构」；计划外的缺陷按范围守恒入池，不在拆分动作里修。
  • N3 不处理被排除的 51 个大文件（技能资产/旧快照/设计样张），也不处理 ≤1000 行文件。
  • N4 本轮不改源码、不拆文件、不 commit、不 push；只新增本计划文档并重建知识库索引。

§03处置原则与轮次划分

处置三类，判定顺序固定：

  • 拆：存在两个以上可命名、可独立验证的职责面，且拆分后能保持接口/测试语义不变。
  • 暂缓：职责可切但当前收益低于回归成本（共享依赖广、真机环境、临界 1000 行、单组件），记录触发条件后再动。
  • 没必要拆：行数增长来自演示数据、模板字符串或常量单点，拆分只会把单一事实源打散，收益为负。

§05第一轮执行步骤、验证闸门与回滚

执行步骤（每个文件一遍）

  1. S0 前置：确认工作树只含本计划文档；commands run kb.baseline 看最新基线；commands run test.full 留一份拆分前实测输出。
  2. S1 依赖盘点：AST 列出模块级函数/类与其调用点；grep 该模块被其它测试/守阵引用的位置；产出「函数 → 目标文件 + 共享辅助归属」映射，登记到任务档案。
  3. S2 文档面切分：把原文件头部「## 测试计划」清单按函数归属分配；新文件各写自己的清单，条目文案不改；并确认不触发 tests/test_memory_bank.py 的结构守卫。
  4. S3 搬迁：逐段剪切到目标文件；只补最小 import；共享辅助先落到 support 模块，再让各文件 import；不重排、不格式化、不改名。
  5. S4 单文件验证：commands run test.one -- tests/<新文件1> tests/<新文件2> ... 全绿；失败即回滚该文件。
  6. S5 收集面守恒：commands run test.one -- tests --collect-only -q，拆分前后收集用例总数必须相等；函数名集合做差必须为空（仅允许路径前缀变化）。
  7. S6 批次全量：每完成 2–3 个文件跑一次 commands run test.quick；每完成 5 个跑一次 commands run test.full（含覆盖率门槛），与 S0 基线对比 passed/skipped 数量。
  8. S7 轮末收口：commands run test.full 全绿 → commands run kb.index / commands run kb.check → 按实测输出新建基线切片（commands run kb.new baseline --total "<实测>"，数字只誊写不编造）。

回滚方式

  • 回滚粒度 = 单个原文件（含其新文件与 support 模块），不是整轮。
  • 按映射清单逐个删除新文件（用显式文件列表，禁止 git clean），再 git restore -- <原文件>；support 模块若被其它已完成文件引用，先回退引用方再删。
  • 回滚后重跑 G1/G2；若已跑到批次全量，再补一次 test.quick。
  • 若失败根因是共享辅助归属判断错误，先调整归属再重搬，不在失败状态上叠改。
