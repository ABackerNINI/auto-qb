核心判断

  • 没有结构性障碍，全是工程量。波次一/二已把种子中心视图、16 个写命令端点、管理端点补齐；本轮 30 条诉求中 28 条是前端呈现与交互打磨，只有 4 条半动后端（peers 修复、统计空值、bulk 删除语义、限速体系）。
  • 一条已定位的硬 bug 打头阵：/api/torrents/{hash}/peers 调用了 torrents_peers()，而 qbittorrent-api 2026.8.1 只有 sync_torrent_peers()（本机实测 hasattr=False），一行修复 + 补测。
  • 先修缺陷、再动表格层、再动骨架。导航 IA 重排（NAV-01）和两个大面重构（详情/设置页）必须排在表格布局（TBL-08 底部状态栏）之后，否则返工两次。
  • 双 UI 纪律是本轮最大成本项。30 条里 20 条要求「同步实现两个 UI」：星图（atlas）与棱镜（prism）模板层各一份，共享逻辑层（shared/app.js）单一来源——凡是列语义、色彩规则、键盘逻辑尽量下沉 shared，模板只做呈现。
  • 派发友好。32 项已按「单 agent 一个波次可独立吃下」的粒度切分，波次间只有 3 处硬依赖（TBL-08 → NAV-01，NAV-01b → RFB-02，SPD-04 ← SPD-01 语义），其余可并行。

02 · category notes

分类详述与实施要点

归类逻辑

用户的原始分组（辅种管理/设置页面/其它）是「发现问题的位置」，不是「改动发生的位置」——同一条诉求的修改往往横跨共享逻辑与两套模板。因此按改动性质重新归类为 8 类，使每个类别的验收方式与实施顺序一致：

类别性质主要验收方式风险等级
FIX 缺陷行为错误或明显不一致，先复现再修复现路径回归 + 单测/冒烟低（改动小）
TBL 表格表格渲染与布局体系改动，牵一发动全身双 UI 列清单走查 + 吸顶冒烟高（sticky/列宽契约）
DLG 弹窗对话框信息架构与文案语义逐弹窗冒烟脚本低
CTX 右键菜单视觉与全局行为走查 + 事件冒烟低
SPD 限速唯一动限速决策逻辑的类别，必须单测先行curves 单测 + 真机 dry-run高（影响生产限速）
NAV 导航页面拓扑与导航结构全页面切换冒烟 + 列宽记忆回归高（watch(page) 契约）
RFB 重构整页信息架构重排真机走查清单中（范围大但隔离）
PRS 棱镜功能补齐（移植已有实现）与星图对拍冒烟低

关键实施要点

表格层（TBL-01/02/03/05/08 的公共底座）

  • 先定列模型，再动渲染。TBL-05（列拖排+隐藏）要求把散落在模板里的列定义收拢为 shared 层的统一列模型（现有 TORRENT_COLUMNS/SHOW_COLUMNS 与 page 列宽记忆机制是起点），TBL-01/02/03 的渲染规则挂在列模型上。顺序：列模型 → 空值/文案语义 → 色彩规则 → 布局 → 拖排交互。
  • 状态底色只做「文字底色」。诉求明确是行文字底色（chip/单元格文字带状态底），且「已有颜色的栏不用修改」——实施前先盘点现有底色栏（站点配色、HR、速度类），输出清单避免双重着色。
  • 底部状态栏是交接件。TBL-08 产出的状态栏容器要预留 slot（速度摘要 / 统计入口 / 全局状态），NAV-01a 直接填入，避免二次返工。railMode 的 top 模式与 --head-h 联动逻辑按第八轮经验做实测联动冒烟。
  • 空值语义分层。表格单元格空白化（TBL-01/02），但详情/弹窗里「qB 未提供」类信息保留占位说明——两处诉求不同，不要一刀切。

限速体系（SPD-01/03 的正确性优先）

  • SPD-01 是本轮唯一改变生产行为的逻辑修改（全局限速决策），必须：先写失败单测（超出末档流量 → 当前行为=解除限速，期望=末档 clamp），再改 curves.py，真机 dry-run 观察一档周期。
  • SPD-03 新配置键走完整管线：models 字段 → validate_config 聚合校验 → schema/ Field 声明（设置页自动渲染）→ 守卫测试 → mixin 短路 → /api/speed/mode 状态透出。缺任何一环守卫测试会红。
  • SPD-04 的弹窗只是搬运现有控件，端点零改动——不要顺手重构限速端点。

导航 IA（NAV-01 的拆解）

  • 当前拓扑：辅种管理（内含 分组/种子/追剧 三态视图切换 + 左 rail）/ 设置 / 统计（弹窗）/ 日志（顶层页），共 4 个一级页。
  • 目标拓扑：分组 / 种子 / 追剧 三个一级页（原三态视图升级）+ 右侧设置（内含日志）+ 底部状态栏（常显统计摘要 + 打开完整统计）。辅种管理聚合壳层取消。
  • 风险集中在 page 切换机制：表格区卸载重建、列宽记忆重实体化、命令回执目标页——全部要走一遍双 UI 切换冒烟。建议 NAV-01a/01b 分两次提交。
