1背景与目标

种子状态有两条回写通道：① qB 全量/增量同步（sync/maindata rid 增量，权威）；② auto-qb 自有停/起/暂停/恢复经 QbApi._sync_paused_state（qbapi.py:96-126）把合成状态（只会写 pausedUP/pausedDL/stalledUP/stalledDL 四值）直接写进快照。后者制造了 6 类不一致风险面（报告 §3 的 R1–R6），并在 26-10-12-2229 被改判为「信号压制」—— 自家停种本应被缺文件扫描与状态事件感知，却被隐式吸收吞掉。

报告 26-10-12-2148 的 26-10-13-0441 修订进一步取证：qB 服务端的 torrent 状态本身按 BitTorrent/Session/RefreshInterval 节流刷新（默认 1500 ms），写后直查 torrents_info 读到的是写前值 —— 这封顶了所有「真值回写」类方案（B 系），同时强化 A 系：既然真实「新鲜」在 qB 侧本来就不存在，删掉合成回写不损失真实新鲜度，只损失自造的假新鲜。原 B2 计划（plans/26-10-13-0413）已置 Superseded。

本计划要达到的

  • 快照语义收敛为单源：state 只来自 qB 同步的应用结果，R1/R2/R3/R6 结构性消除，R5 的不对称顺手消解（全库统一等同步）。
  • 源无关发射：自家停/起与外部变更在转移检测与状态事件上一视同仁（不再有「经 qB WebUI 暂停会扫描、经 auto-qb WebUI 暂停不扫描」的不对称）。
  • 不放弃安全面：G4/G6 这类「陈旧-放行 ⇒ 脏数据洗白」的闸门用局部 deferral 收回。

本计划明确不做的

  • 不做全系统 deferral，不引入「任何状态依赖消费方不得对自写 hash 出决策」这条跨切面不变量。
  • 不动 tags/category 的显式 self_caused_fields 机制（另一条车道，继续原样运行）。
  • 不引入任何形式的合成 state 值（连「只带意图的假值」也不引入 —— 见 §4.4 的边界）。

2方案定位与选定形态

形态内容R1–R6源无关发射G4/G6 安全窗新增不变量
A1 纯透传移除删回写与合成值，零补偿全消天然获得窗口开出无
A2 = A1 + 幂等标记加 pending_writes 意图标记（只带意图不带假值）全消天然获得窗口开出一个意图标记（轻）
A3 = A1 + 局部 deferral只对校验类决策延迟到下一 tick全消天然获得收回「校验类不得对自写 hash 出决策」
A4 = A1 + 全系统 deferral所有状态依赖消费方均延迟全消天然获得收回跨切面不变量（重）

选定 A3，幂等层面可叠加 A2 的 pending_writes（可选件，见 §4.4）。理由：A 系内部的分水岭只有 G4/G6 一道 —— 其余差异都是 ≤1 tick 滞后，且与外部变更今天已有的工作模式完全对称（且这里的「外部变更」本就受同一 qB 节流约束，见 §5）。

A 系相对 B 系的结构性优势

A 系对 qB 服务端节流免疫：它的正确性不依赖「能拿到比 qB 更新鲜的值」，只依赖「快照 = 同步结果」。B 系（真值回写）恰好在这一点上被 26-10-13-0441 的取证证否。因此本计划的验收口径里不出现任何「同 tick 必达新鲜」的断言（§5）。

3前置确认（第一步，必做）

P1 · G4/G6 可达性确认 决定形态

命题：同一 run_due 批次内，是否真能出现「任务 X 起下载方 D（auto_start 或规则 start）→ 任务 Y 对同组成员 C 跑跳检」？若能，A1（无 deferral）下 G6（ops_mod.py:655 → store.group_has_downloading store.py:402-418）会读到陈旧快照而放行 ⇒ C 被删重加、D 正在写同一物理文件 ⇒ 脏数据洗白；同族还有 G4（ops_mod.py:640）与决策链 0/1（checking.py:88/94）。

判据：用真实规则集 + 任务注册面推导同批次任务序列（不能只凭「理论上可能」）。结论只有两个出口：① 不可达 → 形态取 A1，§4.3 整个 deferral 层可省；② 可达 → 取 A3，deferral 为必需品。这一步不做完不该动实现。

P2 · state_changed 同名消歧 必做

qbmanager.py:517 的局部变量 state_changed（语义 = 本批命令是否改了 qB 状态，P0-5 判据）与 store.state_changed（语义 = 本轮 qB 上报的 state 变化集）同名不同义，且同处一个主循环体。实施前先改名（例：局部变量 → cmd_changed_state），否则后续所有涉及「变化集」的改动都容易串线。

P3 · 测试替身能力补齐 必做

tests/helpers.py:332-343 的 FakeClient.torrents_start/stop/pause/resume 只 append calls、不翻转 self.torrents 里种子的 state。A 系守阵要断言「停/起后快照不变、下一轮同步后才翻位」，就需要替身能随后续同步把这颗种子报成新状态 —— 四个方法须真实改 state（含 pausedUP/pausedDL 完成位语义）。

4设计

4.1 值层 —— 删除合成回写

  • 删 qbapi.py:96-126 的 _sync_paused_state，四入口（:128-148）只调 raw client（与 torrents_recheck 等透传写操作同形态）；连带重写 torrents_pause 的 docstring（:136-141，引的 issue A-04 与「不写回则同 tick 读到旧值」口径全部作废）。
  • 删 store.update_torrent_fields 的 state= 形参（store.py:487）与相关分支（:503 / :506 / :512-516 的 state 那一半 / :535-536 / :543-544）。注意：tags_changed 仍要驱动 dirty_groups，删的时候别把 tags 那条一并带走。
  • 重写 store.update_state_snapshot 的 docstring（store.py:303-305）：「自有动作经 QbApi 同步过的状态同样计入，故下轮不会被误判为外部状态变化」整句前提消失 —— A 系下快照只记同步结果，自家动作的变化靠下一轮真实 delta 被看见（正是目标）。
  • 重写 qbmanager.py:810-815 的相位注释：原文「必须在本轮任何自有动作之前观测……否则会把自家停种误判为外部『上传转暂停』」的理据在 A 系下自然消失（不再有当场改写快照的自有动作）。

4.2 自写集 own_writes（deferral 的判据来源）

  • store.own_writes: Dict[str, float]（hash → 登记时刻，供 TTL 兜底）。纯内存、不落盘（与 state_snapshot 同级）。
  • 登记：四个 Facade 入口在 raw client 调用成功后登记（值 = 当前时刻）。
  • 逐出：_apply 应用到该 hash 的新 state 时逐出（切点就在 store.py:239-240 收集 state_changed 处）。
  • 失败轮保留：_apply 未跑或抛异常时不逐出（对齐 reset_sync 的 rid 语义），下一成功轮再逐出。
  • 三处清理单点：① 种子删除时镜像清理（与 store.py:263-269 的 self_caused_fields.pop 并列）；② reset_runtime（store.py:459-478）清空；③ TTL 兜底 —— 登记超过 T（建议 10s，≈ qB 节流上限的数倍）仍未逐出 ⇒ 丢弃 + warning。
为什么 TTL 兜底是必需件，不是锦上添花 必做

deferral 会把命中 own_writes 的任务重排到下一 tick。若某次命令在 qB 侧实际未生效（种子已被删、qB 拒收、状态本就没变），该 hash 的 own_writes 永不逐出 ⇒ 相关任务无限重排（活锁 / 饿死）。TTL 兜底是这条链路的下限保证；同时它给「deferral 有界」提供了不依赖 qB 的独立依据 —— 有界性不能只押在「qB 缓存一定会前进」上。

4.3 局部 deferral —— 只延迟「校验类」决策

统一判据：目标 hash（或其所处组的任一成员）∈ own_writes ⇒ 本轮不出决策，重排下一 tick。落点三处，覆盖全部会因陈旧状态误放行的校验面：

#落点说明

  • 不做全系统 deferral：那会把「校验类」这条可枚举的纪律升级为跨切面不变量（漏一个现存消费方 = 静默陈旧决策，未来新消费方天然裸奔）。除非用户把「同 tick 全决策新鲜」列为硬需求，否则不升级。

4.4 幂等（可选件 A2）

  • 现状：basic.py:113/126 的前置幂等门读快照 is_stopped；删回写后同 tick 二次 stop/start 会重发 HTTP（qB 侧幂等 ⇒ 无功能错误，代价只是重复请求与日志噪声）。
  • 可选加固：加 pending_writes: Dict[str, str]（hash → 停/起意图），守卫查询改为 is_stopped or h in pending_writes。只带意图、不带任何假 state 值，因此不犯 R1–R6 任何一条。
  • 边界：pending_writes 与 own_writes 语义不同（一个供幂等门查询、一个供 deferral 判据），但同层同生命周期 —— 实施时必须一次决定是合并为单容器（带两个字段）还是分列两容器，禁止各写各的造成双轨。

5时序与相位约束

主循环一拍的结构是 command line →（P0-5 条件强制）sync 线 → task 线；apply_sync 只在 _sync_line 开头跑一次（qbmanager.py:700-709），transitions 相位排在任何自有动作之前（qbmanager.py:810-815）。

发射时机（经 26-10-13-0441 取证修正）

不要写「WEB 路径同 tick 必达」 口径纪律

A 系下发射由 qB 上报的真实 delta 驱动。而 qB 服务端状态按 RefreshInterval（默认 1500 ms）节流 ⇒ 发射时机 = qB 缓存前进后的最近一轮同步，量级 ≤1.5 s，不保证同 tick。WEB 路径虽然命令线在 sync 线之前、且 P0-5 会强制补刷新（qbmanager.py:525-528/540），但那次补刷新读到的仍是 qB 的节流缓存 ⇒ 只有恰逢缓存已前进才同 tick。

这条不是缺陷，而是 A 系的特性：自家动作与外部变更的到达时机完全对称（同受 qB 粒度约束），A 系不引入任何「比 qB 更快」的幻想。守阵必须按此写，否则会得到一条偶发假红的测试。

自写来源位置发射落在哪一轮
WEB 暂停/开始/批量command lineqB 缓存前进后的那一轮同步（≤1.5 s 量级；恰逢缓存已前进则同 tick）
分组停种（grouping_mod.py:248/388/461/591）、事件规则动作sync 线中段（torrents_added/post/events 相位）≥ 下一轮（相位已过；且受 qB 缓存约束）
interval 规则动作、ops auto_start（ops_mod.py:274/471）task 线下一次 sync 线之后（task 线不跑 _refresh_torrents）

deferral 的有界性

两条独立依据，缺一不可：① own_writes 在同步应用到新 state 时逐出（依赖 qB 缓存前进）；② TTL 兜底（不依赖任何外部条件）。实施时若只留 ①，就等于把「任务不饿死」押在 qB 一定会前进上 —— 那是隐藏假设。

7失败路径与边界

情形预期行为
命令在 qB 侧未生效（状态本就没变 / 种子已删）own_writes 不逐出 ⇒ 由 TTL 兜底丢弃 + warning；期间相关任务重排（≤T），不饿死。
失败轮（_apply 未跑 / 抛异常）own_writes 保留 ⇒ 下一成功轮再逐出；deferral 继续生效（保守方向）。
全量形态 torrent_hashes=None（原 R5）A 系下自动消解：不再有任何回写，「单种/批量/全量」三形态的快照新鲜度来源统一为同步 —— 不再有形态相关的不对称。
热重载（reset_runtime）清空 own_writes（及可选 pending_writes），不跨重载残留。
种子被删除删除清理补 pop（镜像既有 self_caused_fields 处置）。
同 hash 连续两次自写登记刷新（值取最新时刻即可 —— deferral 只需「是否自写」这一布尔语义）。
qB 服务端节流（RefreshInterval 默认 1500 ms）A 系不依赖它绕过；只影响发射与逐出的时机（≤1.5 s 量级），不影响正确性。

8.3 新增守阵（必做）

编号守阵红验方式
V1值层：停/起动作后快照不变；下一次同步应用后 == 替身真值（含 checkingUP 等非四值枚举）残留一处合成写回即红

11风险、非目标与回退

风险

  • 纪律性安全：A3 用「校验类不得对自写 hash 出决策」这条不变量换 G4/G6 安全 —— 漏掉任一现存消费方 = 静默陈旧决策。缓解：消费点可枚举（D-1/D-2/D-3 三处 + 各自守阵），且 D-1 是队列级统一闸门（覆盖面兜住 task 线全体）。
  • 重排的活锁边界：必须有原因码 + TTL 下限；S2 的 D2 红验是这条的机检。
  • 任务 hash 归属：D-1 的判据需要队列项能给出目标 hash；若现结构没有，S0 需先补该字段（属实施期判定项，未知就先探明，不要假定）。
  • UI 显示延迟：≤1 tick 量级（受 qB 粒度约束）；P0-5 与 truth_pending 仍兜底用户点击场景。

非目标

  • 不做全系统 deferral；不引入跨切面不变量。
  • 不引入真值回写（B 系结论：qB 服务端节流使其值层退化为 no-op）。
  • 不改 tags/category 的写后同步与登记机制。
  • 不改 qB 侧 RefreshInterval（用户 26-10-13 定调保持默认）。

回退

S1 与 S2 各自独立可 revert：只回 S2 ⇒ 行为回落 A1（快照单源、但 G4/G6 窗口在）；S1+S2 同回 ⇒ 恢复今天的合成回写。无需数据迁移（state_snapshot/own_writes/pending_writes 均为内存态，state.json 无相关键）。
