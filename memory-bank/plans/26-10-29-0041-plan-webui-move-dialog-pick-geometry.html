WEBUI 设定位置对话框 · 点选只回填 + 几何平滑过渡

让「设定位置」只剩一条写路径(按钮 / 手输回车), 并把对话框几何从「开层瞬跳 272px」改成「基线抬高 + 200ms 平滑过渡」, 打开时不再自动弹下拉。

来源 会话 grilling 两轮(Q1–Q7) + 用户 2026-10-29 修订指令(窗口更大气 / 不写多余文案 / 不自动展开 / 不能跳变要用动画)

§01目标与设计原则

两条报障, 两个落点

  1. 点选候选就移动 → 点选 = 只回填 + 收面板; 真正移动只由底部「设定位置」按钮或手输后回车发起。
  2. 窗口太小 + 点下拉高度跳变 → 收层态基线从实测 243px 抬到 360px(更大气); 开层不再 0 ↔ 272px 一步到位, 改走 200ms 高度过渡 + 面板淡入下移。

不变量(动了就是回归)

  • 三入口名/签名与下游投递不变: editMove → _editPost、editMoveMulti / editMoveGroup → _bulkEditPost(守阵 + 触发登记表钉这些)。
  • combobox 四绑不变, 仍走单点: 收层合帧 _popBlurArm / 限高 _fitAddPop / 悬停接管 comboHoverIdx / 键盘导航 comboKeydown。
  • 三皮肤成对(atlas / console / prism), 漏一档 = 该皮肤无样式。
  • 不新增说明文案(用户 Q6: 明显的交互逻辑不必写) —— 预留区保持留白, 不放提示语。

设计原则

  • 单一写路径: 点选只做「选中」, 写动作必须显式(按钮 / 回车)。与「添加种子」三下拉的 pickAddPath 口径一致 —— 那边点选本来也只回填。
  • 布局变化必须可过渡: 任何由 class 切换引起的高度变化都要有 transition, 不允许瞬跳。
  • 数字单点: 高度 / 预留量 / 时长只写在三皮肤 CSS, JS 只留一个与 CSS 时长对齐的 settle 常量(两处互相点名)。

§02现状与痛点

症状代码位置机理
点选即移动drawer.js:699-705 moveApplyPath回填 + 收面板后直调 submitMoveDialog() —— 无二次确认。

§03方案总览

A 线 · 提交语义收口(行为)

编号落点内容
A1drawer.js moveApplyPath改为纯回填: movePathInput = p / movePathMenu = false / movePathHi = -1, 删掉 submitMoveDialog() 调用。焦点留在输入框(mousedown.prevent 已保)。
A2add_torrent.js comboKeydown + drawer.js onMovePathKeydown回退分支加可选钩子: const fn = ctx.onEnter || ctx.onPick; fn(v)。仅 move 传 onEnter: (p) => { this.movePathInput = p; this.submitMoveDialog(); } ⇒ 手输回车仍提交; 有高亮项时 Enter 只回填(经 A1), 再按一次才提交。其余四个下拉不传该钩子, 行为零变化。
A3move-dialog.html 按钮:disabled="moveBusy || !movePathInput.trim()" —— 按钮成为唯一提交路径后, 空态直接置灰; submitMoveDialog 的空值校验保留为兜底。
A4drawer.js openMoveDialog / openMovePathMenu聚焦前置 moveSuppressOpen = true; openMovePathMenu() 首行消费该标志并 return(只聚焦不展开)。之后点输入框 / 按方向键照常展开。

B 线 · 几何平滑化(观感)

编号落点内容
B1三皮肤 dialogs.css.modal.move-dialog { min-height: min(360px, calc(100vh - 120px)) } + .modal.move-dialog .modal-actions { margin-top: auto; padding-top: 16px } —— 动作条钉底, 多出的高度留在 body 与动作条之间(呼吸感), 收层态不再是小个子。body 不能加 flex:1: 全局 * { box-sizing: border-box } 下 padding 会长在固定高度里, 内容反被挤成滚动条。
B2同上.modal.move-dialog .add-dialog-body { transition: padding-bottom 200ms var(--ease) }; .pop-open 仍切 272px ⇒ 高度 360 → 515 平滑长高(约 155px), 收层平滑回落。删掉瞬跳, 保留 pop-open 类(守阵/template 接线不变)。
B3同上面板入场不另加规则(实施时纠正初稿): .pop-menu 自带 animation: drop-in .12s(opacity 0 + translateY(-4px) 起, 见 components.css), 再加 .pop-enter-* 是死规则且与动画争同一组属性 —— 用户看到的「跳变」在容器高度, 由 B2 承担。
B4drawer.js openMovePathMenu开层置 _movePopSettleT = 240ms(> CSS 200ms), 到点重跑 _fitAddPop("movePathList") —— 过渡中量到的净空偏小会误限高, settle 后复位重测; 收层/关窗清定时器。
B5同上@media (prefers-reduced-motion: reduce) { transition: none }(项目既有先例: dialogs.css:447)。
为什么不做「高度恒定 + 常驻 272px 预留」: Q7 定为打开不自动展开后, 恒定高会在第一眼露出 ~270px 空箱(且 Q6 不许写文案填它)。改为「基线抬升 + 平滑过渡」, 三个诉求(大气 / 不跳 / 有动画)同时满足, 且没有空箱。

§05待拍板清单

实施时两项均按推荐默认落地, 无遗留待拍板项。

  • 基线高度 360px(min-height: min(360px, calc(100vh - 120px))) —— 实测收层态 360、开层 515(prism)/513(atlas)。单点可调, 不动其它规则。

§07风险与对策

风险触发条件处置
过渡期 _fitAddPop 误限高候选 /api/paths 在 200ms 内返回, watcher 量到半截净空 → 列表被限到 120px 且不再自恢复B4 settle 240ms 后复位重测; 判据: settle 后 listH == 210(e2e 断言)
短视口基线过高视口高 < 480, min() 夹取后 360 不可达body 自身滚动 + _fitAddPop 限高兜底(与添加种子同口径); 768 高视口必须实测可用
共享单点加钩子波及其余四处某处误传 onEnter / 默认值写错钩子默认回落 onPick, 只有 move 传; 守阵钉回退分支表达式 + 四处冒烟
面板入场过渡误伤其它浮层把 .pop-enter-* 写成全局选择器限定 .modal.move-dialog; 守阵查「限定作用域」
抑制展开标志泄漏只在首次置 true, 第二次打开不聚焦/不展开openMoveDialog 每次重置; 判据: 连开三次都能点开下拉
置灰被当成故障批量设定位置无预填 → 按钮一进来就是灰的D4 已拍板为预期; 若审阅觉得像坏了, 退回「点击后再 toast 校验」
