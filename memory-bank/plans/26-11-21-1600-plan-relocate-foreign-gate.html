§01目标与设计原则

为什么做: 真机整组迁移暴露两类问题 —— ① foreign 判定门按 save_path 恰等入门, 同一下载目录下所有无关种子涌入候选, D4 落 mismatch 后直通 WEBUI「旧路径外部种子」标注与 WARNING 通知, 60:1 噪音淹没真信号, 且条目滞留到种子删除为止; ② 收尾窗 qB 下线到收尾完成的约 11 分钟全程零可见反馈(对账 WAIT 静默 + daemon 无日志面 + rewritten 合并静默 + 完成 INFO 不过面板/推送门槛), 用户误判「收尾未触发」。

做到什么程度算成: 兄弟目录种子不再进候选账面与呈现; mismatch 语义回归「同内容根异内容」真形态且文案准确; job 终态时 A/mismatch 条目随终态清理; 收尾窗每个推进点(qB 下线等待 / 改写完成待核验 / 收尾完成)在日志与 WEBUI 种子行同步可见; daemon 窗口行为可从日志实证(含 L1/L2 进窗路径); 真机全链验收通过。

设计底线/不变量: 判定门收窄只丢「通知/纳入候选」, 绝不触碰收尾链与成员面(丢错 = 下个时机扫重试, 保守向); 黄金法则 2(合法关闭配置不得被 materialize 出账键); 主循环单写线程不破(终态清理与预筛都在既有单线程面内); 幂等(预筛/清理可重复执行零副作用); 丢弃无账(D2 拍板延续: 「从来不是候选」不建持久负缓存); 零新配置键(daemon 日志路径硬编码); 场景 A 纳入接缝(_foreign_on_scenario_a)零改动 —— 预筛是它前面的过滤网; 判据纯函数化收编进 relocate_units 便于守阵。

§02现状与痛点

判定面: _foreign_classify(relocate_foreign.py:232-258, 取证 26-11-21 15:00)候选门 = save_path 归一恰等 job.src/继承条目 src(场景 A)或终态账闭包边键(场景 B)——qB 的 save_path 是下载保存根目录, 内容根在其下一层, 同根全部种子命中。D4 文件清单比对拦住误纳但 mismatch 落账(_foreign_record_mismatch:503)即进呈现(foreign_member/views_relocate.py:124 只列 B/mismatch)。组键事实: 组键 = 归一 save_path + 排序文件元组(group_key_of 单点, relocate_plan.py:294-295 组装), 组员恒共享同一内容根, job.scope 即该内容根(混合/平铺退化时 = save_path); 候选文件表有记录级惰性缓存(_file_map), 内容根可零附加 API 现算。

账面: notified 唯一清理点 = 种子消失(_foreign_cleanup_notified:816); 全量兜底扫对在账 hash 跳过(_foreign_full_scan:205), job 翻终态无任何重评/清理 —— mismatch 条目挂已终态 job 永久呈现。

反馈面: 收尾窗 qB 下线对账判 WAIT 无日志(relocate_exec.py:1329 处理分支静默); daemon stdout/stderr 全 DEVNULL(_spawn_daemon→_popen_detached, relocate_exec.py:2776-2790)且模块从未配置 logging handler —— 进窗/逐成员改写成败全部丢弃; journal rewritten 相位合并无日志行(relocate_exec.py:1266); 「收尾完成」INFO 进不了 errlog 环(WARNING+ 口径, runtime.py:263)也进不了推送(min_level=ERROR, notify.py:221)。

痛点证据(真机 2026-11-21 14:11 会话): activation 全量扫入池 61 条, 仅 1 条真外部种子(场景 A 纳入 2bf4b6b6), 其余 60 条全部为兄弟目录无关种子(用户逐条核对); reconnect 扫入池 0 条证明滞留; qB 下线(14:23)到收尾完成(14:34)之间除连接 ERROR 外零输出。

§03方案总览

三批落地, 批次互不牵连评审; 判据纯函数化收编 relocate_units 单点:

批内容拍板
B1 判定门内容根预筛候选经纯路径门(现行为)入门后、D4 比对前, 复用同一次文件表拉取(记录级惰性缓存, 零附加 API)经 content_root_of 现算候选内容根: ≠ 命中 job 的 scope → 静默丢弃(DEBUG, 不入 notified 不呈现); = 才进 D4。场景 A/B 两路同修(B 经闭包边产出 job 的 scope 比对)。退化形态(平铺/混合 scope=save_path)预筛恒过回落 D4。不可判定(文件表空/取数失败)按现 None 口径出队待时机重扫D2/D6
B2 账面终态清理 + 文案job 翻终态单点清理 notified 内该 job 的 kind=A 与 kind=mismatch 条目(幂等, 写在终态落账处); kind=B 保留(通知主体, 留到种子消失); 被清的真同根种子交时机扫自然重判为场景 B(收尾后正确语义)。mismatch 文案改口径: 「同内容根目录下内容不一致, 疑似外部工具重加了不同版本」, 呈现档位词表不扩面; 1326(A 类滞留)随本批收口D3/D4/D5
B3 可观测性 + WEBUI 行同步① daemon 日志落盘 <data_dir>/logs/recycle_daemon.log(INFO, append 无轮转, 路径硬编码, 与 auto-qb.log 分文件); ② 收尾窗 qB 下线等待提示(状态翻转去重 INFO, 带 pending 数); ③ rewritten 相位合并加日志; ④ WEBUI 种子行迁移状态细化同步: 收尾窗内区分「qB 下线等改写窗 / 已改写待回连核验 / 收尾完成(新保存路径)」, 全部派生自既有账面(phase + journal 合并态 + qB 连接态 + pending 数)经 jobs_snapshot 发布面, 零新增 state 键; 推送管道不动(无里程碑旁路)D1/D7/D8

§07风险与对策

风险触发条件对策
预筛误丢真外部种子候选文件表与磁盘布局差(qB 剥根/NoSubfolder 形态)使 content_root_of 现算结果 ≠ scope, 但 D4 本可判同预筛只丢通知候选不触碰成员面; 误丢无账, 下个时机扫重试 + 文件表不可判定走 None 口径保守; 守阵钉 content_root_of 全 layout 形态(E7a/E7b 实证口径复用)
退化形态洪泛残留平铺/混合组(scope=save_path)下兄弟种子仍全量进 D4 mismatchD2 拍板接受; 平铺共享目录种子会被组键并组为成员, 残留面罕见; 文档与文案把该边界写清
终态清理与纳入竞态同拍内 foreign 纳入(on_task_line 前段)与 job 翻终态(相位机推进)交错黄金法则 5 单写线程内顺序化: 纳入先落账, 终态清理在其后同拍或下拍执行, 双面幂等(重放零副作用)
daemon 日志写失败/双写交错盘满/句柄被占; 同实例两 daemon(被 pid 抢占机制排除)logging 失败静默降级(best-effort, 与主循环同纪律); 每实例一进程一文件, append 单写; 心跳/退位机制保证至多一个 watcher
WEBUI 行状态滞后一拍误导派生账面(qB 连接态/journal 合并)与真实现场有快照延迟只消费既有发布快照字段不新造状态机, 展示语义按「最后已知」; 文案避免绝对化措辞
