03方案设计 (方案 B)

3.1 一句话

把「是否被 HR 排除」这个布尔量随锚点带过线程/模块边界 (它在 hr_anchor() 里还活着, 出了 record 就丢了), 然后在对象集现算处用它作第四档排除。命中集构建不动 ⇒ 被排除种子仍被认识, 只是不再被对账。

3.2 数据流 (改后)

TorrentRecord.hr_anchor()  ──(S1 新增) excluded=self.hr_excluded()──▶  HrAnchor
   └─ HrRuntime._anchors()  {站点: {infohash: HrAnchor}}        # 不变
        └─ worker.run_once → service.refresh_site(site, anchors) # 不变
             ├─ _WaveContext(anchors)                            # 不变: local_hashes/local_names 取全量
             │     ⇒ 被排除种子仍是「本地命中」(不误触发 .torrent 下载)
             └─ _build_objects(anchors)  ──(S2) if anchor.excluded: continue──▶  不进 objects
                   ⇒ steady = anchors_known and not objects 可为真
                   ⇒ interval = idle_refresh_interval (24H)

3.3 为什么是 B (而不是 A)

维度A: 在 _anchors 里剔掉B: 锚点带排除位, 仅出对象集
对象集 / 稳态结果等价等价
对行匹配 / 身份登记的影响会变: 被排除种子从 local_hashes/local_names 消失 ⇒ 其站点行不再按本地命中处理 (命中登记 / 名称粗配触发的下载路径随之改变)不变: 与现状逐字相同
爆炸半径大: 影响 3 个消费面 (对象集 + 命中 + 身份下载)小: 只影响对象集一个面; 判据落点单一
结论—选 B: 改动可被一条守阵钉死, 回归面最小

3.4 被排除种子的「另一半语义」必须保留

报告 §08 的守阵方向②在此落地: 排除 ≠ 不认识。被排除种子仍进 wave.local_hashes / local_names —— 站点清单里与它对应的行仍被识别为本地命中, 不因排除而多下一次 .torrent。这是 B 与 A 的实质分野, 也是守阵 S3-2 要钉死的点。

05拍板点

#事项建议 (待拍板)
D1 种子「中途被排除」(原本已有 verified 放行记录 / data.index 行) 时, 是否清理其既有记录? 不清理。排除是判定侧的叠加态, 撤销排除后应能立即恢复原判定; 清理会让「临时排除」变不可逆, 且无收益 (判定侧对其返 None, 残留记录不产生行为)。本计划默认不清理, 不改一行相关代码。
D2 是否顺带省掉「被排除种子终态行的身份下载」(现状: 终态行按名称粗配命中会下载一次 .torrent)? 本批不做, 已入池(2026-10-08 用户拍板) → issue 26-10-08-1304(perf · Open)。它属于方案 A 的副作用面, 且改动会触及命中/身份路径, 与 B「爆炸半径最小」的取舍相悖。

07风险与不变项

7.1 已接受的风险

#风险评估
R1用户误排除一颗确有 HR 义务的种子 ⇒ 它不再被在线核实, 且该站稳态更易触发 (拉取变稀)接受。这正是「排除 = 不纳入 HR 体系」的既定语义: 判定侧 hr_managed 早已对它恒返 False、展示侧早已标注「已排除」。本计划只是让取数侧对齐既有语义, 不引入新的语义分歧。发现延迟上界由宽限期语义决定 (报告 §13.6: 与 24H 量级匹配)。
R2被排除种子不再驱动「未列出」放行签发无判定影响 (其判定已被短路); 不构成漏管。
R3稳态更易触发 ⇒ 若存在遗漏的「未排除新义务种子」由既有机制兜住: 新种子进 anchors ⇒ 对象集翻非空 ⇒ 下一 poll (≤60s) 立即回常态开波 (报告 §13.2), 本计划不改该机制。

7.2 不变项 (须逐条保持)

  • _WaveContext.local_hashes / local_names 仍从全量 anchors 构建 (命中识别 / 名称粗配 / 换 tid 接管语义不变)。
  • 锚点三态契约 (None=采集失败不降频 / {}=确认零锚点) 不变。
  • 稳态判据 steady = anchors_known and not objects 与间隔闸取值式不变 (仅对象集成员变化)。
  • 复用窗 min(reuse_window, refresh_interval) 不跟随 idle；force 跳两道调度闸；min_interval/日额/Retry-After/时间窗照常 —— 全部不变。
  • 判定侧 / 展示侧 (record 三入口 + hr_excluded_by) 一行不改。
