§01目标与设计原则

背景。用户 2026-11-15 报障: WEBUI 状态栏上传/下载速度数值变化时, 周边 UI 元素位置跳动。速度每轮轮询(1.5-3s)都会变, 单位串与整数位随之变, 整组宽度跟着变, 视觉上是持续的横向抖动。

目标(算成标准)。① 速度组内每个元素(两枚 .sb-spd、两枚 .val、两枚 .lim、.sb-sep)在任意速度样本切换的全过程逐帧矩形零位移, 容差 1px(不只比终态, 含 flux 360ms 补间中间帧); 口径限宽视口(>900px) —— 窄屏按 R1 只保证 .sb-speed 右缘不动(.lim 只设 4ch 下限, 长限速值仍会撑开、组内元素随之左移), .val/.lim 的位置在窄屏不作为不变量; ② 四皮肤(prism/atlas/console/flux)一致; ③ 34px 锁高与右缘位置不变, 窄屏不新增溢出裁切。

不变量。不动 fmtSpeed/fmtSize 等格式化函数(全局共用, 外溢到抽屉速度格与图表轴标); 不动任何 JS(D3, 含 flux numRoll); 不动左栏 .sb-today/.sb-stats; 不新增令牌(尺寸纪律只管弹窗宽度档, min-width 字面量与既有 .fx-val/.m-progress .val 同范式); 四皮肤同值。

§02现状与痛点

容易被误判的一点。四皮肤的速度值早就是 mono + 等宽数字: atlas/css/dialogs.css:471、prism/css/views.css:79(.sb-spd .val), :479/:87(.lim), console/style.css:158-159、flux/style.css:166-167(顶层 .sb-item .val, .sb-spd .val, .sb-spd .lim)。所以「数字字形不等宽」不是根因, 不必再往字体方向查。

真根因: 整段字符串长度变。format.js:35-38 fmtSpeed: 零值一律 "0 B/s"; 非零走 _fmtLadder(:22-34)—— 固定 2 位小数、1024 进制、单位串随量级变化。于是同一组元素在不同时刻是 "0 B/s"(5 字符) / "1023 B/s"(8) / "1.00 KiB/s"(10) / "1023.99 KiB/s"(13) / "9.99 MiB/s"(10) / "999.99 MiB/s"(12)。限速侧 .lim 更极端: dialogs.js:564-567 三形态 —— "不限"(≈3-4ch) / "—"(1-2ch) / fmtSpeed(v)(最长 13ch), 落差 3-6 倍。

为什么会推动整组。.sb-speed 是状态栏最后一项(statusbar.html:102-133), 右缘由容器右内边距钉死; .sb-spd 是 flex: 0 0 auto(prism/css/views.css:73-76、atlas/css/dialogs.css:465-468、console/css/dialogs.css:412-415、flux/css/dialogs.css:424-427), 宽度完全跟随文本。右缘固定 + 宽度变 = 左缘平移, 组内下载图标、数字、斜杠、限速、键帽一起左右挪。

放大器。flux 皮肤 fx-mount.js:450-490 的 numRoll 在 360ms 内逐帧改写 .sb-spd .val 文本(ROLL_SEL :461), 把一次跳变摊成连续 20+ 帧的小幅抖动。这是既有设计(webui-fx.md:19 允许状态栏级低频面), 不是独立根因。

已排除项。① 左栏 .sb-today/.sb-stats 变化被 .sb-spacer{flex:1} 吸收(statusbar.html:66 在速度组左侧), 不推动右组; ② 未读徽标 .sb-err-badge 出现时按钮 .sb-err 向右被速度组左缘钉住、只能向左挤 spacer(console_hub_controls.css:365-368 flex:0 0 auto), 速度组不动 —— D14 据此从「定宽」改判为「零改动 + 守卫」。

§03方案总览

主线。给 .val 与 .lim 各设一个不随内容变的定宽槽, 使 .sb-spd 宽度恒定; 纯 CSS, 一行 JS 不动。

元素规则落点依据
.sb-speed .sb-spd .valmin-width: 13ch; text-align: right;shared/console_hub_panels.css 尾段(与 :629 .sb-speed 同段)D7 D9 D10
.sb-speed .sb-spd .limmin-width: 13ch; text-align: left;D8 D9 D10
窄屏 @media (max-width: 900px).sb-speed .sb-spd .lim { min-width: 4ch; }D8
.sb-err不改, 维持 flex: 0 0 autoshared/console_hub_controls.css(现状)D14

13ch 是算出来的, 不是拍的。fmtSpeed 有界档最长形 = "1023.99 KiB/s" = 7+1+5 = 13 字符, "1024.00" 同为 7 字符, GiB 档到 "9999.99 GiB/s" 仍是 13 字符(≈10 TiB/s, 现实两个数量级余量)。12ch 会让 1023.99 这一档撑开, 方案即失效。12px mono 下 1ch ≈ 0.6em = 7.2px(字体回落到 Consolas 的 0.55em 时 ≈ 6.6px), 13ch ≈ 86-94px; 仓库同源佐证: qb_traffic_chart.js:3182-3184 给 10px 等宽字体留 84px 装 11 字符(单字符 ≈ 6px = 0.6em) —— 那里的 10px 是字号, 不是每字符 10px。

对齐方向有讲究。.val 右对齐: 数字右端紧贴 /, 位数增长向左扩展, 视觉上「右端不动」; .lim 左对齐: 不限/—/数值都从 / 右侧起笔, 避免短文案孤零零飘在 13ch 槽右端造成断裂感。

落点为何在共享层。四皮肤这条规则一字不差, 按 webui.md:16「逐字节相同的规则族进 shared 尾段单点」; 皮肤内只保留真差异(atlas/prism 在各自 dialogs.css/views.css 定义 mono 字体, console/flux 靠顶层 style.css), 那些不动。写四份 = 四个漂移点。

§07风险与对策

#风险触发条件处置
R1窄屏右组挤爆.lim 13ch 使右组总宽增加约 18ch(≈130px), 小视口左栏 + 右组超出容器S1 在 @media (max-width: 900px) 把 .lim 退到 4ch(覆盖 不限), 牺牲限速值低频跳动换不裁切 —— 窄屏契约只保 .sb-speed 右缘不动, 组内元素允许左移; 900px 取四皮肤共有的最窄断点(另有共有 1320px 一档), 不另造
R2极端 GiB 值撑开速度 ≥ 10000 GiB/s(约 10 TiB/s), 超出 13ch接受撑开。定 width 会裁掉真实速度数字, 比极端值偶尔跳更糟; 现实网络不可能达到
R3三位数未读撑宽errUnread ≥ 100(徽标 3 字符)生产极少; .sb-err 向左挤 spacer, 速度组不动; 仅当 spacer 已归零时才可能裁右侧, 见 R4
R4窄屏裁切窄视口下 spacer 已被压到 0, 再遇到 badge 出现或超长限速值.statusbar{overflow:hidden} 裁右侧, 不是位移; 记录为已知边界, 由 R1 的窄屏退让一并缓解
R5皮肤 CSS 反向覆盖以后某皮肤写更高特异性规则声明 min-width(如 .sb-speed .sb-spd.spd-down .val = (0,4,0))。等/更低特异性的写法(只写 .sb-spd .val, 或原样照抄 .sb-speed .sb-spd .val)实际不生效 —— 四皮肤 CSS 都在共享层之前加载, 同或低特异性恒被后加载的共享规则压掉; 但仍要拦, 防将来共享层改选择器或加载序后翻脸S2 判据按「四皮肤内任何命中 .sb-spd .val/.lim 的规则都不得声明 min-width」(子串匹配, 不锚行首), 不比选择器字面; 变异自证两态各验一次: 等特异性声明虽不生效但守阵应红, 更高特异性声明则真覆盖且必须红
R61ch 随字号漂移各皮肤 .val 字号不同(12/12.5px)ch 是按当前字号算的相对单位, 定宽自动跟随字号; 不写死 px
R7既有键帽断言撞红statusbar-kbd-entry.spec.mjs 量 .sb-speed 左右缘定宽后该组位置恒定, 断言只会更稳; 若真红按失败行裁决, 不静默改断言
