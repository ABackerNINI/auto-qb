§01目标与设计原则

背景

用户指出根目录与顶层目录组织混乱。盘点结论:决定移动范围的不是「目录看着像什么」,而是谁按字面路径引用它们——

  • 生产代码运行时解析 <repo>/tools/global-traffic-monitor(src/auto_qb/core/traffic_source/agent.py tool_dir 兜底),tools/ 已被伴生工具占住语义;
  • e2e 被 8 类字面引用钉住(playwright 配置 / package.json / CI 白名单与运行行 / .commands dev 四 task / Python 守阵与 flaky allowlist);
  • tests-real 被 .commands/real 十余行 task、安全守阵扫描根、.gitignore 与真机规程钉住,且用例文件名 test_rmNN_*.py,并入 tests/ 会被主套件误收集;
  • pytest.ini 的 addopts 与 tests/_tmp_bootstrap.py 是并行 / TMPDIR / 覆盖率闸的单点,tests-real/runner.py 已用 --no-cov -n 0 反制 ini;
  • .dockerignore 有窟窿:node_modules/、config/(生产凭据)、e2e/、tests-real/、tools/、package*.json 等全部进 build context。

目标(做到什么算成)

  • 测试树三分:tests/unit(原 tests 全部内容)+ tests/e2e + tests/real,主套件零误收集;
  • 根目录瘦身:minimal.yml、hatch_build.py、assets/、scripts/ 的 sim_*、env.sh 全部离根或清除;
  • docker 归置:config/ 并入 docker/config/,.dockerignore 窟窿补齐;
  • pytest 配置并入 pyproject,pytest.ini 删除;
  • 全部移动 git mv 完成、旧路径引用清零(memory-bank 冻结历史件豁免)、结构守阵与 test.full 全绿、实测数字落新基线切片。

设计底线/不变量

  • 零逻辑改动:只动位置与引用,不改任何行为(含报错文案/默认值);
  • 红线:根 config.yml 与 auto-qb-data/ 内容一字不动;.commands/、.agents/、memory-bank/、src/ 位置不迁移,行内引用/注释更新豁免;
  • 单 commit 交付:移动+引用更新+文档回写一笔提交,不留中间态;
  • grep 快照闭环:动手前全库 grep 旧路径冻结引用清单,收尾按清单清零核对。
