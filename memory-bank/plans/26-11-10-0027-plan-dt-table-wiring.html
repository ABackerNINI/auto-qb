§01目标与设计原则

背景: dt_table.js 自 26-10-13-0811 W1 落地起生产零调用(issue 26-11-08-0147)。根因链: W1 停手点只做 node 电池自测(计划内)→ W2 起「接内核」被 --tbl-pad-x/--tbl-gap CSS 变量方案实质替代(修几何靠变量收敛而非调用内核)→ 守阵与 parity e2e 的验收口径恰好都覆盖不到「调用链是否存在」→ 测试全绿关单把未接线固化; 次日(26-10-14)复查否定后代码冻结, 双口径(DT_TABLE 死口子 vs columns_grid._gridTemplate/colAlignCss 平行计算)存续至今。

目标一句: DT_TABLE.layout() 成为全仓表格几何字符串(轨道串/对齐)的单一生产者, assertLayout() 进入生产渲染自查; 现网渲染输出逐面等价、零行为差。

做到什么程度算成: §04 三波判据全绿 + 用户终验四面(06/09/10/11)通过; HR 三表不进本轮(第二轮立项, 方向已拍板 D7)。

设计底线/不变量:

  • 几何等价不变量: 委托前后 gridTemplate 与 aligns 逐面相等 —— 由等价性探针先证后改, 探针红 = 停手, 不是修到红变绿。
  • 保守默认(黄金法则 2): assertLayout 不一致只 console.error 不打断渲染。
  • 判据前置: 验收清单在本篇写死交用户过目(10-14「判据自设+零用户验收」翻车的对症)。
  • 例外明文化(D4): 不接口子在例外清单点名, 守阵钉住「清单之外零旁路」。

§02现状与痛点

  • 零调用: window.DT_TABLE 六口子(src/auto_qb/webui/static/shared/dt_table.js:117-127), 全仓 grep 生产仅定义处命中; 四皮肤 index.html 均同时加载 columns_grid.js 与 dt_table.js(flux :188/:197, prism :181/:192, console :180/:191, atlas :176/:187)。
  • 实际几何链: app.js 列定义 {key,label,tpl,sortable,locked,align}(app.js:209-303, DRAWER_TABLE_DEFS 注册 :496-612) → columns_grid._visibleCols/_gridTemplate(columns_grid.js:47-50, colWidths[page][key] || c.tpl 拼轨) + colAlignCss(columns_computed.js:65-79, 注入 <style id="col-align-css">) → 每表一对 computed(:139-189) → 表壳 :style="$root.gridStyle(tableId)"(tpl/xtpl.html:224/373) + 桥 Teleport(xtpl.html:330-383, 锚保活 H.anchFill drawer_templates.js:299-308)。
  • 输入端今天仍对得上: layout(cols, widths) 消费 key/tpl|width/align(dt_table.js:41-68; label 仅进 checkLabels 的 L3 路径)与列定义同名词可直接喂; colWidths[page] 与 widths 参同构(键→CSS 长度)。
  • 守阵缺口: node 电池只喂合成列(tests/test_webui_static_dom_panel_drawer.py:1822-1864 手写 {key:"a"...}), 从不喂真实列定义 —— 生产零调用时无后果, 接线后必补。
  • 同步可行性: c39ab3b7..HEAD 五路径(columns_grid.js/columns_computed.js/dt_table.js/dt_table.css/drawer_tpl/)实测 39 笔(HEAD f905b7b7 时点), 无一触碰几何契约(-S 实证: 仅大文件拆分 20a74274 move-only 触及 _gridTemplate/colAlignCss; 性能波 e6b02991 只加窗口化 content-visibility/_rowWindow); 经典三张 26-10-14 已整体退役(391b3337), 全部表面走同一链 —— 接线面比 0811 设计时更小; flux 皮肤 fork console 零专属列, 接源头自动覆盖。
  • 语义例外: HR 三表(hr_status.js:104-140)均无 tpl/align 字段, layout() 对它们只能出全默认轨道 —— hrDetail 借 <aq-table mode="thead">(settings-detail.html:338), hrWave/hrKv 走原生 table/v-for(settings-detail.html:372/:381-389); 三表不接, 第二轮改造(D7)。

§03方案总览

主线(拍板 D1/D2): 函数级单点委托 —— columns_grid._gridTemplate 与 colAlignCss 内部改为委托 DT_TABLE.layout()(轨道串与 aligns 从同一个返回值取), 删除旁路拼接。调用方(主视图 computed + 抽屉桥)与 DOM 零改动, 全部表格面(含主列表、含 flux)立即单点。被否决的备选: B 链路级直调(绕开 columns_grid 几何函数, 回归面 8 面×4 皮肤, 增量收益不值)、C 只接抽屉面(把双口径洗成白名单的名义接线)。

渲染自查(D3): assertLayout 常驻生产渲染 —— 三处 O(1) 计数(grid 轨道数/列头格数/首行子格数), 不一致 console.error(含 tableId 与三方计数)不打断; 未挂载豁免保留。挂载点(桥 Teleport 完成后 / 主视图渲染后)W1 首日实证选定, 不设拍板。

本轮接线范围(D6): 只接 layout + assertLayout 两个口子。checkLabels 已有测试侧消费(kernel 守阵 L3 全仓扫描), 留原地不算死口子; registerCell/cellOf(单元格注册表)挂账 HR 第二轮 —— 那一轮要动单元格渲染, 顺势接最省, 去留届时裁决。

例外清单(D4): HR 三表(hrDetail/hrWave/hrKv) + 04 卡片形态面 = 已裁决例外, 不接; 守阵断言「清单之外的表面零旁路几何」。

分期: W1 等价性探针+委托 → W2 渲染自查+例外守阵 → W3 e2e 语义+终验收单; 每波一笔提交(止损 D8)。
