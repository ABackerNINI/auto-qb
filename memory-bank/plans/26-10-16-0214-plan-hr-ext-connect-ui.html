3.2 行级状态判据(新)

数据源 = instanceHealth 台账(后台每轮轮询后整份落盘, 键 = 端点)。S2 给台账条目补结构化 state 字段后, 选项页按下表渲染; 四色语义与工具栏徽标族同源(绿=通 / 橙=可自愈的故障 / 红=要人动手的故障 / 灰=暂无数据):

色短语判据悬停 title
● 绿正常h.ok === truenote + 最近联系时间
● 红token / 来源被拒state ∈ {401, 403} —— 要人改 token 或 extension_idnote + 改法指路
● 橙连败 N 轮 / 连不上!ok 且 state ∈ {down, http, bad-endpoint}note(含排查清单) + 连败轮数
● 灰还没轮过无台账条目(刚添加 / 停用中 / SW 刚醒来)「等待下一轮轮询, 或点行内『测』立即探一次」

3.3 数据流(单一写入口)

  • 选项页不直写 instanceHealth —— 后台是唯一写者(轮询路径与探测路径都经 noteInstanceHealth), 选项页只读 + storage.onChanged 自动重渲染(既有 scheduleConnRender 通道复用)。
  • 新消息: probe-all(无参, 逐实例探测)与 probe-one {endpoint}。后台处理函数复用轮询的「拉任务清单」一步(GET /api/hr/tasks, 只读, 不执行任务), 探测结果照常进台账 → 选项页经 onChanged 自动刷出新状态。
  • 总览状态卡沿用 connStateOf(options.js:296)四态, 不新增第五态; 行级四态是每实例粒度, 与总览(实例集合粒度)分层不混用。

3.4 文案与操作列纪律

  • 徽标图例改写: 「浏览器工具栏的扩展图标状态色外框(常驻, 非本页元素): 未配置(无外框) · 连接正常(绿框) · 重连中(橙框) · 发现失败(红框, 图标角标补 !); 悬停图标有中文结论, 点图标即回本页。」四态各配色样(框式)。
  • 来源徽标一律「手动 / 自动」(R2); 手动条目 token 列 = 前 32 位指纹 + 悬停完整值, 未填标红「未填」; 自动条目 token 列 = 「-」(R1)。
  • 操作列: 手动条目只有「删」; 自动条目留空, 悬停可见「由发现租约自动管理, 删除后下轮发现会重新补入」(R3)。「载入」与行内「测」不回潮 —— 改 token 走删除重加, 探测走「重测全部」。
  • 排序: 手动组在前、自动组在后 —— 沿用上游 26-10-15-2357 Q9/S1 的「手动恒在前」语义(discovery.js::mergeInstances 已保证, 渲染不重排, 只按清单顺序); 模板示例行序与实施同此口径。
  • 每次进页必读的信息只有: 状态卡 + 实例表; 机制解释(端口顺延 / port:0 随机 / 配对码安全口径 / 排障表指路)全部进「说明与排障」折叠区。
  • 按钮口径: 「自测端点连通」更名「重测全部」。#status/#hint 保留为动作反馈区, 紧贴动作按钮行。

3.5 工具栏图标外框(R4, 路径 A)

  • 现状事实: manifest.json 的 action 无 default_icon(工具栏显示 Chrome 默认字母图标), 徽标的字号/占地/位置由浏览器固定渲染、无任何 API 可调 —— 这是「挡住大半图标」的根源。徽标没有「加外框」的形态, 唯一路径是 chrome.action.setIcon 重画图标本体。
  • 资源: 新增 extensions/hr-fetch-proxy/icons/ 8 个 PNG(基础无框 + 绿/橙/红框 × 16/32px), 由入库脚本(如 scripts/gen_ext_icons.py)一次生成 —— 零运行时绘制、像素级可控(色框外加暗色描边保证与图形分离)、SW 被回收无重建负担、Edge 同样支持。运行时 OffscreenCanvas 绘制(路径 B)已评估并放弃(缓存/重建成本高, 16px 观感不可控)。
  • 态映射(判据仍是 badgeStateOf, 跨层守阵继续有效): 未配置→基础无框图; 连接正常→绿框; 重连中→橙框; 发现失败→红框 + setBadgeText('!')(唯一非空徽标文本, 其余态一律清空)。触发点(pollAll 收尾 / 发现收尾 / onInstalled / onStartup)不变; setTitle 悬停中文结论不变; setIcon 失败沿现有 try/catch 静默降级(title / 选项页总览兜底)。
  • 对比度: 基础图形取中性深色底(不随浏览器主题变), 框色 = 徽标四态既定色(#2e7d46 / #b8802f / #b0453d), 具体字形实施期定(C8)。

  • 红/橙判据漂移: 行级四态与徽标四态是两个粒度, 守阵只钉 rowHealthOf 自身真值表 + §3.2 判据文本, 不做跨层比对(总览判据已有 26-10-15-2357 S6 的跨层守阵, 不重复覆盖)。
  • 模板与实施漂移: 模板是示意, 实施以本计划 §03 判据与 §04 步骤为准; 布局细节(间距/字号)实施期可按真实页面微调。

09候选模板与选型

三份候选稿均为单文件 HTML、dark 主题、假数据、轻交互(四态切换演示 / 悬停详情 / 折叠展开 / 重测全部演示), 双击即开。选型回复「模板 A/B/C」即可; 也可指定「A 的布局 + C 的状态条」这类组合。

模板布局差异化看点适合
A 纵向流单列自上而下: 状态卡 → 发现操作 → 实例表 → 动作行 → 折叠说明与现有页面节奏一致, 改动最克制; 状态卡是新增焦点想最小改动、快速验收
B 双栏台账左栏连接操作与说明, 右栏实例健康台账常驻操作与观测分离; 台账(状态/最近联系/连败)一眼全览常开页面盯着连接状况
C 顶部状态条(激进)连接状态压缩为页面常驻顶部状态条(sticky, 四态 + 实例数 + 上次发现), ①区只剩发现与实例表滚动到②③④也始终可见连接状况; 「不静默」的极致形态接受整页结构变化、要全局可见性
