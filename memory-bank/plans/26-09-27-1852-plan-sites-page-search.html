站点页搜索: 名称 / 域名 / 标签全字段匹配与多命中展示

给 WebUI 设置「站点」二级页加一个搜索框, 匹配站点名、域名、标签、分组乃至全部配置字段; 匹配语义参照种子搜索方案, 多命中时逐站展示「命中字段 chip」。本文档内嵌可交互示例模板; 五个设计问题已于 26-09-27 拍板(见 08 节), 已于 26-09-28 实施(见 10 节变更记录)。

01

背景与目标

设置页「站点」分区(hub.view === 'trackers')目前把全部站点平铺成一排 pill(站点名 + 配置键数), 没有任何筛选手段 —— 站点一多, 找某个站只能肉眼扫。设置首页虽然有一个搜索框(hub.query), 但它命中的是 schema 字段元数据(label + key + help, config_hub.js:250-266), 搜不到站点名、域名、标签这些站点数据。

目标: 在站点二级页 pill 行上方加一个搜索框, 输入即筛 —— 命中站点保留, 未命中隐藏; 每个命中站点展示「哪些字段、什么值命中了」, 让用户一眼看出为什么这个站出现在结果里。

范围: 只动 trackers 分支; 三套皮肤(atlas / prism / console)共用同一份模板与 JS, 一处改动三皮肤同时生效。零后端、零 schema、零配置结构改动。

02

参照: 种子搜索方案

种子搜索是本仓库已定案的搜索范式, 语义直接沿用; 差异只有「跑在前端还是后端」一处:

维度种子搜索(参照)站点搜索(本计划)
归一化[\W_]+ → 空格 + lower (views.py:35-37), 大小写 / 分隔符不敏感, CJK 可搜同语义; 前端实现须用 [^\p{L}\p{N}](见 04 节的坑)
查询语法空格分词隐式 AND; -词 排除; "短语" 连续子串 (views.py:40-72)照搬同一套语法, 用户零学习成本
匹配单位「行」: 每个字段值归一为一行, 正词逐词跨行 AND, 负词任一行命中即整颗排除同构: 每个站点建一组行, 规则一致
匹配位置服务端单点 views.py::search_torrents — 因为文件名候选行需要扫盘建索引前端: 配置树已整棵在内存(GET /api/config), 与标签/分类 facets 筛选同模式; 服务端化无收益反增 API 面
防抖400ms(服务端有成本)即时计算 — 站点数通常 < 100, 归一化行预建一次, 匹配可忽略
命中高亮仅行级 search-hit 标记, 不做逐词片段高亮同口径: 命中字段值整值强调, 不做片段 mark(见 05 节)
状态持久化不持久化, 刷新即清一致: 不持久化

取舍说明 — 种子搜索 2026-09-26 收敛到服务端, 理由是「文件名候选行要扫盘建索引 + 前端禁止复活匹配代码」(filters.js:82-86)。站点搜索不碰文件系统, 数据源就是已加载的配置树, 属于 facets 同族的纯内存筛选, 不违反该决策; 匹配函数仍收敛为前端单点(一处 norm / 一处 parse / 一处 match), 不在模板里散写。

03

搜索范围: 字段清单

站点 = config.trackers.<站点名> 的 dict, 合法键集合 KNOWN_TRACKER_KEYS(validation/sections.py:88-99)。每个键归入一个字段组, 字段组名就是命中 chip 上显示的中文标签:

字段组(chip 标签)来源键取值方式层级
名称dict 键站点名本身, 每站一行内容 · 必搜
标签tags列表逐项一行(第一个标签即界面显示名)内容 · 必搜
域名domains列表逐项一行(镜像域名全部可搜)内容 · 必搜
分组groups列表逐项一行内容 · 必搜
删标remove_tags模式串逐项一行(含 regex: 前缀原样可搜)扩展
规则rules引用串逐项一行(@规则集.规则名)扩展
上传限速 / 下载限速upload/download_speed_limit树内已是可读字符串("2MiB/s"), 直接搜扩展
HRhr.*子 dict 递归到叶子("3D" / "80%" / 输出字段标签), 全挂「HR」组扩展
不搜remove_similar_tags布尔, 无可读文本—
不搜hr_check旧键(值以 HR 档案为准), 且不属于本页范围—
不搜掩码叶子值 === 掩码哨兵 ******** 的行跳过 — 今天站点下无敏感键, 防的是未来新增键(如 rss passkey)把掩码串当内容—

序列化兜底口径(与树的真实形态解耦): 字符串原样 / 列表逐项 / 数字 String() / 布尔跳过 / dict 递归到叶子。用户诉求「所有配置字段」由「扩展 + HR」两层满足; 布尔与旧键除外(无文本可搜)。

04

匹配算法

norm — 归一化

与 views.py::_search_norm 同语义: 折叠分隔符为单空格 + 小写 + 去首尾空格。命中判定全部在归一化文本上做子串包含。

⚠ 前端实现的坑 — Python 的 \W 是 Unicode 语义(CJK 算词字符); JS 的 \W 是 ASCII 语义, s.replace(/[\W_]+/g,' ') 会把整个中文词折成空格, 中文搜索直接废掉。前端必须写 s.replace(/[^\p{L}\p{N}]+/gu, ' ').toLowerCase()(u 标志必带)。这条拟在实施时按动作写入 pitfalls/web-ui/。

parse — 查询语法(照搬种子搜索)

  • 空格分词 = 隐式 AND: 每个正词都要命中(行可以不同)
  • -词 = 排除词: 任一行含排除词, 整站出局; 只写排除词时不出结果, 改出提示「只有排除词 — 请补一个要包含的词」
  • "短语" = 连续子串; -"短语" = 排除短语
  • 宽容容错: 孤立 - 忽略, 未闭合引号收到行尾(与种子搜索解析器同款行为)

执行顺序与预计算

  • 负词优先(任一行命中即整站排除), 再做正词逐词跨行 AND —— 与 views.py:783-808 主循环同构
  • 预计算: 配置加载后每站建一次归一化行(行携带字段组 + 原始值), 之后每次输入只跑匹配, 无防抖
  • 配置保存 / 重载后重建索引行(挂在现有 cfgLoad 流程上)
05

多命中显示方案

核心问题: 一个搜索词同时命中某站的名称、域名、标签多个字段时, 怎么呈现。定案(可调, 见 08 节待拍板):

  • 结果行制: 搜索激活时 pill 行整体替换为「命中站点列表」, 未命中站点隐藏(不是置灰 —— 置灰在长列表里还是找不到目标)
  • 命中字段 chip: 每个命中字段一枚 chip = 字段组名 + 命中值; 命中值整值强调(accent 色), 不做片段级 mark —— 归一化匹配下片段反算要维护原文偏移映射, 种子搜索也停在行级强调, 收益不值
  • chip 上限 3, 超出收进 +n; chip 顺序: 名称 → 标签 → 域名 → 分组 → 删标 / 规则 / 限速 / HR
  • 站点排序 = 配置原序: 不做相关性排序, 设置页要的是可预测; 名称命中的站点把名字染 accent 色即是视觉锚点
  • 点击命中行 = 保留搜索, 右侧出详情: 搜索态下命中列表居左、所选站点字段详情居右(左右分栏); 点其它命中行直接切换右侧, 不打断搜索; Esc 或 × 返回全量列表
  • 左右联动: 右栏正在显示的站点, 左侧对应命中行高亮(选中态)
  • 仅一个命中 → 直接选中: 搜索结果只有一站时自动选中, 右栏立即出该站详情, 无需再点

项定案

与首页搜索关系互不影响: 首页 hub.query 搜配置项元数据, 本搜索搜站点数据, 键名分开(trackerQuery)

  • Q3 · 排序: 保持配置原序

验收清单

  • 搜名称 / 标签 / 域名(含镜像) / 分组 / 规则引用 / 限速值 / HR 数值均能命中, 且 chip 显示对应字段组与命中值
  • 大小写混输(hh vs HH)命中一致; 域名带点输入 hhanclub.net 命中(分隔符折叠后照样包含)
  • -词 排除生效; 仅排除词出提示; 多词 AND 跨字段生效
  • 计数 / 清空 / 空态文案正确; 点击命中行右侧出该站详情且搜索词保持; 左栏对应行高亮联动; 仅一个命中时自动选中; Esc / × 恢复全量列表
  • atlas / prism / console 三皮肤下布局与配色一致(共用版式层 + 皮肤令牌)
  • 中文词命中正常(\p{L}\p{N} 归一化, 不是 ASCII \W)
  • pill 与命中行只显示站点名, 无配置键数徽标(26-09-27 调整)

待拍板(示例模板里都能直接体验)
