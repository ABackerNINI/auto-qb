WEBUI 右键菜单自定义重排(重排/显隐/跨层)实施计划

行右键菜单四支(单组/单种子/整集整剧/多选批量)从静态模板直写改为注册表单点 + 布局数据驱动：每支可重排、可显隐、可把项移入/移出「更多操作」次级、分隔线可拖可删; 布局存 config.yml 的 web.ctx_menu(与跳检开关同一配置通道), 在设置页新卡「WebUI」里定制, 保存后当前标签热应用、其它标签刷新生效。默认布局与今天逐位一致 —— 不写配置时行为零漂移。

§01目标与设计原则

做到什么算成

  1. 四支全能力定制: 单组 / 单种子 / 整集整剧 / 多选批量四支, 每支可勾选显隐、↑↓/拖拽重排、把项在一级与「更多操作」次级间移动、添加/删除分隔线; 危险项(删除…)与普通项同等对待(D12 完全自由)。
  2. 服务端持久化: 布局存 config.yml web.ctx_menu, 过 validate_config 全套; 配置备份/迁机自带; 按实例隔离(换端口 = 各存一份, 与跳检开关同通道同语义)。
  3. 保存后立即生效: 设置页全局保存成功后, 当前标签菜单按新布局热应用; 其它标签/浏览器刷新后生效(D8)。
  4. 零漂移默认: 不写 ctx_menu 键时, 四支菜单与今天(静态模板)逐位一致 —— 41 个一级项 + 12 条默认分隔线 + 单种子次级 11 项 2 线, 一项不差。
  5. 次级为空不显示入口: 「更多操作」在其子项为空(全隐藏/全被移走)时不渲染入口(D7) —— 遵循「单选项菜单 = 半残 UI」退役原则。

不变量(实施时不得让步)

  • 动作链路一行不动: 所有入口方法与下游复用(commands.js 的 ctxAct/_actCore/bulk 链、drawer.js 多选对话框、组级六入口)保持原样 —— 本件只改「渲染哪些项、什么顺序」, 不改「项点了干什么」。
  • 门控与布局正交: flags.skip_check_menu / qbTrafficOn / reannounceMenuGate() 三重门控原样保留; 布局只管顺序与显隐意图。门控关闭的项在布局里保留槽位(用户开启开关即归位), 与 colOrder/colHidden 双轨同款语义。
  • 三皮肤零视觉回归: .ctx-menu/.ctx-item/.ctx-sep 类名与三套皮肤 CSS(atlas/console/prism 各自 components.css)不动; 共享模板单点重构, 三 UI(atlas/prism/console)由 loader 注入同吃。
  • fail-closed: /api/webui/flags 拉取失败或 ctx_menu 缺省 ⇒ 回落默认布局(与 skip_check_menu 失败回落 false 同口径)。
  • config.yml 契约从严: ctx_menu 进 KNOWN_WEB_KEYS + 形状校验; 未知 id / 残缺结构不 500 —— 后端夹紧, 前端补尾。

结构性痛点

  1. 静态模板直写, 项集奇偶靠人肉: 加/改一项要手改四支之一; pitfalls/web-ui/ctx-menu-branch-parity.md 记着 2026-10-09 用户报「辅种页单组右键菜单缺选项」—— 给批量支补项漏了单组支, 两条路径静默分叉(不报错不白屏, 纯「菜单里没这个选项」)。
  2. 单项不可显隐: 按 conventions/webui.md 分层原则, qB 通用低频项(队列×4/分享率/复制族/超级做种…)已进「更多操作」, 但对 PT 日常用户仍是噪声; 单种子支一级 14 项起, 整屏菜单找不到常用项。
  3. 唯一不可定制的交互面: 列偏好有列选择器(col-picker, 勾选+拖拽+持久化), 键位有快捷键分区(GET/PUT /api/keys), 菜单布局既不可定制也不可持久化 —— 每换一个浏览器/端口就要重新适应。

§03方案总览

主线 = 注册表单点 → 布局数据 → 模板消费 三段式, 数据走既有配置通道, 不造第二套机制:

config.yml web.ctx_menu ──► /api/webui/flags ──► state.flags.ctx_menu ──► ctxItems(branch) computed ──► ctx-menus.html v-for
                              ▲                                                          (默认布局 = 注册表定义序, 零配置即今天)
设置页新卡「WebUI」定制块 ──► cfg.tree.web.ctx_menu(草稿) ──► cfgSave PUT /api/config ──┘ (保存后 loadWebFlags 双拉, 当前标签热应用)

3.1 数据模型(config.yml web.ctx_menu)

web:
  ctx_menu:            # 缺省整个键 / 缺某支 = 该支用默认布局; 迁移零漂移
    group:             # 支名 = triggers.js variant: multi / episode / member / group(D11 四支各自独立)
      order:           # 一级渲染序: 项 id 或分隔线 token("sep:xxx"); 未入序项按定义序补尾(与 colOrder 同款)
        - resume
        - pause
        - reannounce
        - "sep:d1"
        - recheck
        - skip_check
        - limits
        - location
        - meta
        - export
        - "sep:d2"
        - delete
      hidden: [export]        # 隐藏项仍在 order 占位, 勾选恢复即归位(与 colHidden 同款)
      sub:                    # 「更多操作」次级; 缺省 = 默认(当前仅 member 支有内容, 其余三支默认为空)
        order: [queue-top, queue-up, super-seeding, copy-name]
        hidden: []
    member: { order: [...], hidden: [...], sub: { order: [...], hidden: [...] } }
    multi:  { order: [...], hidden: [...], sub: { order: [...], hidden: [...] } }
    episode: { order: [...], hidden: [...], sub: { order: [...], hidden: [...] } }

语义规则(逐条对齐列双轨, 前端单点实现、后端只验形状):

  • 补尾: 注册表新增项(未来功能)/用户序里没有的 id ⇒ 按定义序追加在末尾, 不丢项。
  • 跨层移动 = 把 id 从 order 移入 sub.order(或反向); 两层各自独立排序。
  • 分隔线一等公民(D10): 默认线 token 由定义序位置定(sep:d1…), 可删可拖; 用户添加 = sep:uN(N = 当前最大 + 1, 不复用已删 id); 删掉所有线不报错。
  • 次级为空不显示入口(D7): sub.order 过滤掉隐藏项后无可见项 ⇒ 不渲染「更多操作」父项; 「更多操作」文案恒定不可重命名。
  • 门控串联: 最终可见 = 布局可见 ∧ 门控通过(flags.skip_check_menu / qbTrafficOn / reannounceMenuGate()); 门控关闭时槽位在布局里保留 —— 定制块对门控关的项显示但打「当前开关未启用」徽标, 避免用户误判。
  • 后端宽松: 校验只查形状(order/hidden 为字符串数组、sub 同构、token 格式); 未知 id 不报错(前端补尾/忽略), 与列偏好「换版本不丢布局」同款韧性。

3.3 渲染重构(ctx-menus.html: 静态直写 → v-for 消费)

  • 每支内部: <div v-for="it in ctxItems('group')" :class="['ctx-item', it.cls]" @click="ctxRun(it)">; it.kind === 'sep' ⇒ <div class="ctx-sep">; 次级: ctxSubItems('member') 非空才渲染「更多操作」父项。
  • 交互全部保留: CTX-05 收起延迟(SUB_CLOSE_DELAY_MS + 父项 mouseleave 语义)、openSub/toggleSub/keepSub/scheduleSubClose、_subFitViewport 实测钳位与 subFlip、is-gated 置灰 + title 提示、danger 样式、ctx-caret、_markCtxSource 触发源强调。
  • menu.js 适配面极小: openMenu/openMemberMenu 等开菜单逻辑不动; 新增 ctxItems(branch) / ctxSubItems(branch) computed(读 flags.ctx_menu + 注册表 + 当前分支判据)与 ctxRun(it) 分派(按 it.act 调原方法, 一个 switch/映射表, 不碰原方法体)。
  • 加载序约束同 menu.js: ctx_menu.js 必须排在 app.js 之前(app.js 末尾 app.mixin(window.AQB_CTX_MENU))。
