01

背景与结论

设置页「?」浮窗是配置项说明的唯一出口, 文案写在两处: 后端 schema(config/schema/*.py 的 help / risk / default)与前端富文案(config_hub.js 的 HUB_HELP, 命中时整段覆盖 schema)。本次把六个分区全部「?」项逐条与代码实现对照, 结论如下。

27 处问题分四档:P1(5 行)描述与实现相反或张冠李戴, 会直接误导操作 —— 最典型的是「移动种子」写的是不搬磁盘文件, 实际 qB 会真搬;P2(2 行)是过时/架空文案与一处永不显示的富文案死键;P3(17 行)缺关键边界或主语易误读;P4(3 行)压根没写说明, 浮窗显示「这一项还没有说明。」。

全部修复只改 help / risk 字符串与一处页面静态句, 不涉及任何行为变更, 守卫测试的键集合基线不受影响。其中 parse_missing_rate_max 的「去留」是行为决策(恢复消费或废弃删键), 不在本计划内动手, 只修文案并建议入池。

02

核对方法与数据链路

「?」浮窗内容组装在 config_hub.js :: hubHelpOf: 富文案 HUB_HELP[去 config. 前缀的路径] 优先, 未命中回退 schema 的 help / risk / default。因此同一个键可能有两层文案, 富文案会整段盖掉 schema —— 核对时两层都查。

核查按分区拆了五路只读代理(常规 / 自动化 / HR 在线核实 / 限速+站点 / 规则+插件), 每条结论都要求给出 file:line 证据; 四处高影响结论(移动种子、HR 条件、parse_missing_rate_max、任务队列起算点)由主会话复核源码二次确认。判定档位:❌ 与实现相反 / ⏱ 过时架空 / ⚠ 不完整 / ❓ 易误导 / 缺 help。

覆盖面:常规、自动化、HR 在线核实、限速、站点、规则六个分区中出现「?」的全部配置项、站点微调字段、曲线编辑器内嵌字段、全部条件 / 动作插件说明, 以及六个分区的首页卡片 lede; 另核对了浮窗「默认值」栏的对象 / 数组渲染。合计 164 项次核查, 27 行进优化表, 其余文案与实现一致(清单见 08)。
