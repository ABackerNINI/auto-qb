§8

执行规则(认领协议)

  1. 本计划零代码分析——每条的分析动作在认领开工时做;表内摸排注只是入口提示,以现场为准。
  2. 认领走认领链:issue 的 doc-refs ↔ 任务档案的 **Refs:** 双向登记,生成器校验,缺链闸门红。
  3. 四类动作逐项显式确认:新建文件 / 入池 issue / 认领 issue / commit+push;「继续」「接着做」不构成授权。
  4. 波次是建议顺序不是硬闸:跨域条目可并行(如 W6 docs 与 W2 内核),同域串行;波内彼此独立可乱序。
  5. 完成一条:issue 报告的封面徽标与 <meta name="issue-status"> 两处一起改 Done,重跑 commands run kb.index;收尾走 DoD 5 步(含 test.full 基线切片记实测数字)。
  6. In Progress 条目(26-09-21-0219)认领前先对齐前史:查实际进展,补 doc-refs 认领链,状态如实改回 Open 或继续推进。
  7. 全部 31 条清完后本计划转 Done;若中途出现新入池 issue,并入最近适配的波次,不为新条目重开计划。
