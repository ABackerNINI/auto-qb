qB 流量图限速线按当时值分段

限速虚线从「拉取那一刻的当前值画满整窗」改为「按限速历史逐时段分段」——每段画在各自时间区间内, 反映当时真实生效的 qB 全局限速; 缺记录的区间不画线、不猜测。后端在主循环采样点顺带记录限速变化事件, 按天落独立小文件(qb-traffic-v4/limits/), 目录与流量数据一致, 不新增配置键。

§1背景与问题定性

流量图(qB 口径, 三挂点: 全局 / 分组 / 单种)的画布注解层会画限速虚线。用户报: 线显示的是当前限速值, 有误导性——窗口默认 24h, 期间限速可能变过多轮, 但线只反映「现在」, 历史曲线段对着一条不属于那个时刻的限速看。

现状事实落点(已核到代码)
限速线 = 拉取响应那一刻的值, 横线画满整个窗口shared/qb_traffic_chart.js _qbDrawLimits(draw 钩子, x 取整个绘图区)
取值单点 = server_state.dl_rate_limit / up_rate_limit(当前生效值)shared/dialogs.js speedLimitBytes(R10-04 单点)
限速会变: 限速曲线模块按档位自动改写 / WebUI 手动覆盖 / 备用限速切换core/modules/speed_curve_mod.py 每轮查档后 set_global_speed_limits
主循环采样点每轮已拿到完整 server_statecore/modules/traffic_sample_mod.py _sample_global
注解层范围: 主线共享图面三挂点生效; 变体 13 省略注解层, 14/15 有2026-10-08 拍板(issue 26-10-07-0149) + W7 变体恢复裁定
26-10-08 既有拍板(限速取 qB 全局限速、上下载各一条、自动模式峰值超限才画)是本计划的前置契约——本计划只改「线的取值方式」(单值 → 分段历史), 不推翻其余判据。

§2已裁定事项(grilling 拍板记录)

#决策裁定
D1记录什么qB 全局限速的实际生效值(上/下行分开); 不记曲线目标值——手动保护跳过时目标并未写进 qB, 记目标会制造新的失真
D2记录挂点主循环流量采样点顺带对比, 有变化才追加事件; 单线程(黄金法则 5)、零新增请求, 天然覆盖一切变化源(含 qB 原生界面手改)
D3存储与保留分天保存(独立天文件), 目录与流量数据一致; 不加配置键; 保留时间与流量图最大保存时间对齐(用户修订项, 26-10-12 两轮裁定: 先定独立文件, 后定分天; 见 §3-D3′)
D4前端画法限速虚线按历史分段: 每段画在各自时间区间, 最后一段延伸到当前时刻; 上/下各一条、色随方向; 可见性判据逐段化(延续 26-10-08 拍板); 文案标明「按当时值」
D5缺数据区间记录起点之前不画线、不回填——「没有线」就是「当时值未知」的诚实表达
D6生效范围主线三挂点照旧全生效; 变体 13/14/15 维持现状(13 无注解层、14/15 有), 不为变体额外定制
D7悬停读数十字线 tooltip 增补「当时限速」读数(取悬停时刻生效的事件值)

§3方案设计

D3′ 数据记录与存储(后端)

  • 存储形态(用户拍板 D3, 两轮裁定终值 = 分天): <data_dir>/qb-traffic-v4/limits/<YYYY-MM-DD>.dat —— 目录与流量数据一致, 天文件名与 v4 天文件同款日期格式(单点 V4_DATE_FORMAT); limits/ 不是系列目录(v4_rel_dir_to_key 只认 global/ 与 torrents/<hash>), 系列扫描与整目录淘汰天然跳过它, 不会被误删误列。每文件体量天然有界, 与 v4 天文件形态同构。
  • 行格式(追加写, 纯文本 CSV): <epoch_s>,<up_bytes_s>,<down_bytes_s>; 值 = 采样时刻 server_state 读到的生效值, 0 = 该方向不限速。备用限速生效期间读到的即生效值, 以 qB 实际下发为准, 事件序列如实反映切回切出。
  • 事件语义: 每轮采样对比内存缓存的上一记录值 (up, down), 有变化才追加 + flush; 变化粒度 ≤ 采样间隔(默认 30s)。事件率 = 限速物理变化率的镜像, 记录器自己不制造事件, 文件增速有天然上界(≤ 采样率 × 行宽)。
  • 跨天轮转: 00:00 硬切新天文件(v4 关块同款触发, 不新造时钟); 新天首行 = 基线 carry(上一生效值无条件写入, 值没变也写)——单看一个天文件自洽可读, 读侧拼接无需回溯前一天文件。重启去重口径: 启动首轮若与当日文件末条相同则跳过(不产生假事件; 已有基线 carry 的天文件同理)。
  • 失败降级: 追加 OSError → WARNING(节流)+ 本轮不记, 不上抛——记录器是观测面, 丢失 = 事件缺口, 读侧「延续语义」自然兜住; 不因它挂主循环。撕裂尾(崩溃致残行)读侧跳过, 与 traffic_store 坏行豁免同理念。
  • 读侧: 按窗口日期集合只读涉及天文件(24h 窗至多 2 个, 与流量 raw 段同形状) + 合成首事件(窗口起点 ≤t0 的最近生效值; ≤t0 的事件可能落在前一天文件末行, 读时窥前文件末行 carry); 记录起点前不给值(D5)。解析走 mtime+size 键控缓存(照 V4DayCache 形状): 文件没变零解析——不淘汰策略下历史持续变大, all 窗口也不因总历史变大而多花解析。
  • 保留对齐口径(D3): 流量图最大可看范围 = day/month 聚合行(全保留、无淘汰, 6mo/1y/all 窗口即看它); 限速天文件同样不淘汰, 两者生命周期一致——对齐语义逐字落地, 且不新增配置键。
  • 落点: 记录器与读侧收进 core/traffic_limits.py(traffic_* 家族单文件小类, ~百行级); 接线在 traffic_sample_mod.py _sample_global 内调用(仅主循环线程, 黄金法则 5)。

D3″ API(读侧)

  • webui/server/traffic_qb.py 的 _respond 统一附加 limits 字段——全局限速三作用域同源(26-10-08 拍板), global / torrent / group 三个 payload 同一份, 分组/单种不另读文件。
  • 形状: limits: [[ts, up, down], ...]——窗口内的变化事件按时间升序; 首元素是合成事件 = 窗口起点时刻的生效值(≤ t0 的最近事件), 前端据此直接构段; 记录起点晚于窗口起点则首元素从记录起点开始, 起点前不给值(对应 D5)。
  • 按窗口日期集合读涉及天文件; 单天体量小(变化才记 + 基线 carry, 一天几十条), mtime+size 解析缓存兜住 all 窗口多年积累; Web 线程只读, 与写侧(主循环)无锁竞争, 最坏读到半行由撕裂尾豁免兜住。

D4/D7 前端(分段线 + 悬停读数)

  • _qbDrawLimits 改分段绘制: 从图数据 data.limits 构段 [seg_t0, seg_t1) × (up, down), 每段 x = 各自时间区间(经 valToPos(·, "x")), 最后一段延伸到当前时刻; 上一段与新段之间天然呈阶梯。缺口(无流量采样)处线仍画——限速是时间真值, 独立于流量存在与否(缺口斜纹已表达无采样)。
  • 可见性判据逐段化: 每段每方向 0 < v < ymax 才画该段该方向的线(延续 26-10-08 拍板「自动模式峰值未超限速不画」的逐段版本); 0(不限速)/缺值不画。
  • 数据通路: _qbChartBuild 建图与静默续拉快路(setData 原地换数据)都要把 data.limits 随图暂存(uPlot u.data 只有三列, 需挂在图记录上), 快路换数据时同步换——否则限速变更要等整图重建才可见。
  • 悬停读数(D7): _qbHoverOf 按悬停桶时刻二分事件序列取生效值, tooltip 增补「当时限速」一行; 模板改动在悬浮读数区(实现时定位具体挂点)。
  • 文案: 流量页签说明区增补一句「限速虚线 = 当时生效的 qB 全局限速; 记录起点前不显示」; 纵轴 limit 模式的上限口径不变(仍取当前全局限速 ×1.2, 见 §5 取舍)。

§5风险与取舍

点判断
曲线目标值不记录手动保护期间曲线「想写但被跳过」, 生效值未变 → 无事件, 图上如实无变化。若以后想看「曲线意图」, 另立项(曲线状态已有 state.speed_limit_curve 日键, 保留 7 天, 形状不合图用)
纵轴 limit 模式仍取当前值它只是视口缩放选择, 不是历史表达; 按窗口内最大限速排轴属新语义, 本轮不做(记录在案, 需要时另议)
采样间隔 = 事件时间分辨率限速变化时刻精确到采样轮(默认 30s); 对 24h 以上窗口远小于一个像素宽, 足够
缺数据区界定限速是阶梯函数: 记录起点后每个时刻恒有生效值(0 = 不限速也是值)——内部无缺口, 唯一缺区 = t < 首事件(记录起点), 不画线即「当时值未知」的诚实表达(D5)。停机/写失败窗口内发生的变化, 事件时刻延迟到恢复后首个采样, 误差 ≤ 停机时长; 值本身不丢(恢复首轮基线补上), 时刻误差图上不标注(成本大于收益, 已知边界)
病态翻转护栏外部脚本级高频改限速(每个采样间隔翻转)是唯一理论风险, 文件增速上界 ≈ 采样率 × 行宽(~100KB/天/文件); 防(不删数据——删了违背对齐语义), 走常量阈值 WARNING + 节流(照 _BAD_LINE_WARN_* 先例, 观测面异常可见); 图面如实画阶梯, 本身就是诊断信息
文件无头行纯 CSV 追加, 无 v4 头行门闩需求(单文件单写者、无换代语义); 若未来改格式, 按行解析失败即豁免, 自然兼容
多实例data_dir 每实例独立, 文件随实例隔离, 无共享冲突

§6非目标

  • 不做单种/分组级限速历史(qB 单种限速是另一字段族, 且 26-10-08 已拍板限速线三作用域同源取全局)。
  • 不为变体 13 补注解层、不为 14/15 做定制(W7 恢复现状即终态)。
  • 不加配置键、不做独立保留期淘汰(用户拍板 D3)。
  • 不改限速曲线模块本体、不改状态栏/限速浮层的当前值口径。
  • 不回填历史(功能启用前的限速无从得知, 不猜)。
