§01目标与设计原则

背景

前序计划 26-11-12-0344 已实施完成(S1–S6 五笔提交 3df2c3b9 / 8a4b255f / cc342b57 / b661be35 / e544bfd2, doc-status: Done, 四皮肤真机截图目检过)。实机反馈五点: ① 打开右键菜单第一眼聚焦在键帽而非文字; ② 按钮形式的键帽丑; ③ 状态栏键位提示丑; ④ 添加种子 / 列选择的提示丑; ⑤ 覆盖不一致 —— 静态界面只有极少数元素有提示, 主页面切换 / 设置 / 搜索框 / 皮肤切换等都没有。用户要求全面改造, 倾向「按住 ctrl 显影」或「一个切换开关」。

本轮不是改样式, 是推翻前序件的形态决策重做: D1(常驻) / D3(不做 hold-reveal) / D6(设置 Ctrl+, 不做) / D7(状态栏按钮键帽物理不可行) / D2(顶栏·状态栏 title 否决) 一并解禁或反转, 详见 §07。

目标

  • G1 零抢焦点: 默认隐藏, 菜单打开瞬间只有文字; 显影态下文字仍是第一视觉层级 —— 靠布局与弱化实现, 不靠「一次只显一个」。
  • G2 去按钮化: .aq-kbd 从「有底 / 有框 / 2px 厚底边」退化为灰色括号包裹的弱化纯文本。
  • G3 覆盖一致: 所有「注册表已绑键 + UI 有稳定挂点」的元素一律补提示, 不留旧样式孤岛。
  • G4 键位零二次维护: 取数链单点不变, 改绑即时跟随 / 空串即隐藏 / 空位绑键后自动出现。
  • G5 范围收窄: 纯显示层。注册表零改动、零新增键位、帮助浮层与设置键位面板内容·布局零改动。

设计不变量

  • I1 取数单点不动: kbShortcutDisplay(item, draft)(shortcuts.js:167-171) → kbSerialWithDraft(:136-139) → kbDisplayName(:149-157); 菜单侧 ctxKeycapOf(ctx_menu.js:332-337)。任何模板禁写死键位串。
  • I2 显影是纯 CSS class: <body> 上一个 class, 只用 opacity / visibility / color, 不碰任何几何属性 —— 大列表对强制同步重排敏感(lifecycle.js:359-361 明记 3000 行下是「不跟手」直接来源)。
  • I3 零布局跳动: 菜单走「固定预留键位列」(平时空白、显影填文本); 顶栏 / 状态栏 / 页签走 ::after 或绝对定位 badge。文字位置永不因显影位移 —— 显影只解决「抢焦点」, 撑宽药丸 / 挤出 34px 状态栏 / 菜单折行要靠挂载手法解决, 不会自动消失。
  • I4 生命周期闭环: 必须自带 keyup 移除 + 每次任意 keydown 自愈校正 + window blur + visibilitychange(hidden) 强制清 class, 并在 unmounted 撤除(lifecycle.js:287-316 纪律)。全仓当前零 keyup、零修饰键状态跟踪、零 blur 兜底, 这是全新机制。
  • I5 不吞事件: 不 preventDefault、不 stopPropagation, 照抄 shortcuts_engine.js:48 对纯修饰键的放行做法; 否则引擎 :46 的 defaultPrevented 礼仪会让组合键整条动作被跳过。
  • I6 令牌与皮肤纪律: 只用既有令牌(--fg-dim / --fg-muted / --font-mono), 零新增令牌; .aq-kbd 令牌集与守阵 AQ_KBD_TOKENS(test_webui_kbd_keycap.py:61)同步。共享模板 + 共享 CSS 改一处四皮肤自动同构; 皮肤专属 components.css 需四处同步。

定案理由与必做约束

反引号: 58 条 def 无 Backquote(KB_CODE_NAMES shortcuts.js:146 只是显示名, 黑名单 :85-104 亦无); 非输入态零浏览器默认; 与 Ctrl/Shift+click 多选零冲突; 纯 Backquote keydown 引擎无 item(:54-64 无-item 分支只处理 Delete)不争抢; 不在 8 个 KB_MODIFIER_CODES 里, 不受修饰键状态问题波及; 引擎输入态已屏蔽(:65), 显影无需 preventDefault 就不破坏输入。

  1. 仅当 e.code === "Backquote" 且 !e.repeat 且非 IME 组合期(shortcuts_engine.js:47 同式)时 add; 绝不 preventDefault / stopPropagation(I5)。
  2. 输入态跳过显影: 复用 :53 同式 closest("input, textarea, select, [contenteditable]")。不吞字符 —— 输入框内按反引号仍正常输入, 键帽不闪, 属可接受边界(不是显影场景)。
  3. keyup 移除 + 每次任意 keydown 自愈校正(keyup 丢失时下一次按键立即纠正)。
  4. window blur + visibilitychange(hidden) 强制清 class(可并入 lifecycle.js:225 的 _onVisChange)。
  5. 避开录制态: 冒泡阶段注册、判 kbRecId(state.js:311); 捕获阶段 _kbOnRecordKey(shortcuts_panel.js:181-183) 对所有 keydown 全吞。
  6. CSS 只用 opacity / visibility / color; unmounted 撤除全部句柄(lifecycle.js:287-316)。

F1 为何只做备选: 输入框内零破坏(不产字符)优于反引号, 但必须吞浏览器帮助页、kiosk / 远程桌面 / 浏览器进程接管 F1 的环境收不到或 preventDefault 无效, 且 F1 的「帮助」直觉与 Shift+/ 帮助浮层(shortcuts.js:398)语义略偏。Alt 否决依据: 浏览器单按聚焦菜单栏 / 设置(用户指出)、Alt+1..5 已绑抽屉页签(:370-382)、OS 常吞 Alt keyup、Alt+Tab 切窗。

「显影」解禁了什么(关键论证)

前序件 D6 / D7 / D2 三条否决全部建立在「键帽常驻占位」之上: 设置 Ctrl + , 全串 ~40px 拉长 .tabs 药丸; 状态栏反斜杠三变体单字符不可区分、全串挤出右角速度组、34px 锁高物理不可行。改成默认隐藏后:

  • 默认零占位 → 药丸宽度 / 状态栏右角不再被挤;
  • 括号包完整串(Ctrl + \ / Shift + \ / \) → 三者可区分, 「, 单标误导」消失;
  • ::after / 绝对定位不进布局流 → 34px 与药丸宽度约束消失。

解禁的是「落点」, 不是「常驻」: 这些落点只在显影态 / 开关常驻态出现, 默认态一律隐藏。若把 badge 写进布局流, 三条否决会立刻复活 —— 挂载手法(I3)是解禁成立的前提, 不是可选项。
