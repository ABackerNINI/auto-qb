§01目标与设计原则

1.1 为什么做

执行模型已从「规则顺序链」演进为「每规则每种子独立任务 + 事件即时分派」,但三处旧链式遗留在生产路径悬空:① stop_following_rules_if 六档全为死配置(process 返回的 (handled, stop) 被 _run_rule 整体丢弃,G1/G12);② ignore_next_action_error 伪动作项把控制流藏进数据字段、作用域跨条目(G5)——注意它是活键:引擎确实在消费它,只是语义错位,生产 config.yml 未用但外部用户可能在用;③ 条件异常 = 规则硬停 + 「停止后续规则」矛盾日志(G2)。同时缺错误策略、编排分支、可观测性与单点注册(G4/G6/G9 等)。

配置面前提(D1 拍板新增):本项目已全面转为 webui 配置,用户不手改 config.yml。因此两键退场的升级提示必须在 webui 可见(未启用徽标/规则卡提示面),不能只靠日志;webui 编辑器是本方案所有配置面改动的第一呈现面。

1.2 做到什么程度算成

  1. 两键退场(升级路线,D1):载入层识别两键 → 含键规则转未启用(enabled=false)+ 每次载入 warning,话术给出 ignore_next_action_error 的等价新写法(on_error: {policy: continue});原规则内容在配置中原样保留供用户改写;不做运行时兼容(不做 ignore→on_error 自动映射);引擎侧不再消费两键;process 返回值契约收口为被引擎显式消费的 verdict,base.py:280 误导话术修正(G1/G5/G12)。
  2. 错误策略一等化:每动作可声明 on_error(policy 三档,retry = 任务级 requeue),条件异常降为「本条本轮不命中」且可解释(G2/G5)。
  3. 表达力最小完备:组合树 all/any/not 替代隐式 AND 与「逗号分组」约定(G4),choose 块覆盖动作分支(G6,D3 转正);不做报告 §6.4 边界外的任何东西(Rete / 级联 / 依赖图 / 通用循环 / 图灵完备表达式)。
  4. 可观测:per-run trace 按(规则×种子 hash)维度环形保留,回答「这条规则为什么没跑/跑了什么」。
  5. 单点注册:新增动作/条件从「改 4 处」(G9)降为改 1 处,schema/校验/兼容表从 registry 派生;未用条目全部保留(G13)。

移出本期(D6):mode(同种子重触发策略)与具名共享状态——设计说明与升格触发条件保留在 §03.4,出现真实跨规则协作诉求或引擎引入并发时立项。

1.3 设计底线(不变量,优先级高于以上目标)

  • config.yml 生产红线零改:现有规则在新引擎下零改加载,旧行为语义逐条保持(条件 AND、动作顺序、cooldown 去重、checking 子段契约)。兼容靠载入层规范化完成,不写一次性迁移脚本改用户配置。
  • state_file exec_history 兼容:去重键口径(规则名:hash)与 prune 语义不随重构改变;既有历史数据载入不丢、去重行为不回退(重置一次去重窗口 = 生产事故面)。
  • 黄金法则不破:幂等靠 state_file 去重语义保持;单一写线程(单规则线程)假设不引入绕开者;fail-fast(新配置键全进 validate_config + config/schema.py);保守默认(所有新原语默认值 = 现状行为,见 §03)。
  • 分期独立可交付:任意一期停工,系统都处于语义自洽、测试全绿的状态。

§03方案总览

3.1 主线:退 → 立 → 收

  • 退(W1):两键按 D1 走配置升级路线——键面保留识别(schema/validation 侧用于升级检测),载入检测到即把含键规则转未启用 + warning(每次载入提示,webui 可见),原内容原样保留供改写,引擎侧不再消费;同时收口 (handled, stop) 悬空契约、修正误导日志话术。「要么实现要么删除,不留宣称语义的日志」(报告 §05 反模式结论)——引擎不再有死路径,键面退场由升级提示承接。
  • 立(W2–W4):per-step on_error(W2)→ 组合树 + choose(W3,D3 转正)→ trace + evaluation 枚举位(W4);每步默认值 = 现状行为(保守默认),旧配置零改等价;webui 编辑控件随期同步(D8)。
  • 收(W5):单一 registry 收编 schema 派生 / 兼容表 / watch_fields / 键面守卫(G9/G10/G11/G13,未用条目全部保留)。

3.2 兼容层设计(硬约束的落点)

核心是一个载入规范化单点(下称 normalize_legacy_rule(),规划中的新函数,建设期钉在 W2——W1 无归一需求,R7):config 解析后、schema 校验之前把旧扁平语法规范成引擎唯一可见的新形态(位置钉死:normalize 在校验前,归一后的形态才进校验器)。要点:

旧形态(生产/测试现场)规范化结果
条件 - path: [...](单键 dict 列表)叶子节点,整列表包一层隐式 all:(语义 = 现行 base.py:187 的 all(...))
「逗号分组」约定(G4)不做全局一刀切 any:按条件枚举逐一核对映射表——tags/state 等行内分隔符 = AND、条件组间 = OR(以 conditions.py 现行为准);本期只承诺生产已出现形态,每个条件类型单独写映射测试
conditions: ''(hhan 规则)normalize 天然不见:空串经 _strip_none(validation/core.py:106-128)在载入前已整键剔除,与现行「无条件 = 直接过」等价——兼容表特此注记,勿在 normalize 里为空串再建分支
动作 - add_tags: [...](单键 dict){type: add_tags, params: [...]},缺省 on_error: {policy: stop}(= 现行失败即止)
stop_following_rules_if / ignore_next_action_error不归一、不映射(D1:不做运行时兼容):载入层识别即把该规则转未启用 + warning,原键在配置中原样保留;normalize 只处理仍在服务的 legacy 语法
防漂移约束:引擎与校验器只认规范化后形态,禁止出现「读 legacy 键」的第二语义分支——避免 G4 的 hr 双语义分歧(conditions.py:160-163 有意分歧)在更大尺度重演。normalize_legacy_rule() 是 legacy 词汇的唯一容身处,配专项守卫测试 + 生产 5 条规则的规范化快照比对。两条附注(R1):① 错误定位回映射——校验器报错时看到的已是归一形,报错话术必须把归一形坐标翻回用户写的扁平坐标(如「第 2 个动作」而非归一后的结构路径);② 不得改变规则命名——命名复合形 组.规则 是 exec_history 去重键的前半,normalize 只动 conditions/actions 结构,键名原样透传。
  • exec_history 兼容:去重键 = 规则名:hash(core/state.py:281),hash 输入口径保持现状(spec 序列化原样),重构不改其输入;W4 trace 是新增键面,不迁移既有 exec_history;载入回归测试断言旧 state 文件读入后去重判定不变。
  • checking 子段契约:with/without_reference、pending/resume 断点续跑、未知键 fail-fast(26-10-06-0028 拍板)全部原样保留,规范化不动 checking 内部结构。

3.4 移出本期原语的设计说明(D6,升格时现成约束)

以下两组原语不进本期实施,设计在此存档;升格触发条件:出现真实跨规则协作诉求,或引擎引入并发时立项。

  • 引擎级 mode(同规则同种子重触发策略):设计为规则级可选键,single(默认,= 事件路径现状:任务在跑则忽略重触发)/ restart / queued 三档;restart 需任务取消原语,牵动面最大。
  • 具名共享状态:规则可读写 state_file 具名键,规则间零通信原语的补位;明确不做级联。升格时的现成约束(原 W4 收口三件套):① 键命名空间——具名键统一挂在规则名前缀下,防跨规则误写;② 可见性顺序——读写均在单一写线程内串行,写入随 state_save_interval 落盘,读方只见上一落盘态;③ prune 上限——具名键面复用 exec_history 同款保留期 + 上限逐出机制,防止无上限增长(键面进 validate 白名单)。

§04实施步骤

实施总范围已拍板为 W1–W5 全序列(D7)。分期按错误代价排序:先退两键(拖着是误导与事故面)→ 再上错误策略(修最重的行为缺陷)→ 再上编排块(纯增量)→ 最后 registry 化(动面最大,放最后且前四期全绿后开工)。每期独立可交付、可回退。
