整组迁移 qb_temp 闸门按归属收窄

把整组迁移 qb_temp 闸门从「内容根里任何 .!qB 都硬拦」收窄为「只拦本组自己的 .!qB」——外组/无主条目按归属降级为告知性 notes；依据 libtorrent 1.2/2.0 源码核实的逐文件搬运语义，判定层零改动、收窄全部发生在事实收集层。

来源 用户报障(WEBUI 单种子移动被无关 .!qB 误拦) + 同会话两轮取证与全面安全分析; 用户指令「写计划文档, 然后按建议实施」

§01目标与设计原则

背景：relocate.enabled=true 时 WEBUI 单种子移动走整组迁移闸门（计划 26-10-18-1604 P5 三入口接线，现行决策）。事实收集层把内容根目录里别的种子的 .!qB 文件也计入硬拦面——共享剧集目录里另一集正在下载（如 413INSTC-305.mp4.!qB）就会拦下本组迁移，属误报，且该场景（同目录多种子）是辅种库常态，几乎不可用。

目标：硬拦面收窄到「本组文件处于 .!qB 未落定态」；外组/无主 .!qB 降为告知性 notes。完成判据：内容根存在外组 .!qB 时单种子移动可正常发起（守阵三案绿 + test.full 全绿）；本组文件 .!qB 态仍被拦。

设计底线/不变量：① 闸门 id qb_temp 不改名（前端与测试按 id 断言）；② 「本组数据未落定必拦」的磁盘态竞态兜底不弱化（GATE_INCOMPLETE 之外的独立防线）；③ dir_alias 的内容根专属（exclusive）前提不动；④ 三入口（单个/批量/规则 move_to）共用同一判定，单点收口；⑤ 保守默认：归属判定的两个误判方向都必须偏保守（不得把该拦的放行）。

§02现状与痛点

现状链路：relocate_mod.py 事实收集处 qb_temp_entries = [ext 中以 .!qB 结尾] + [本组 names 中以 .!qB 结尾]——ext（内容根里不属于本组的条目）在 _classify_entries 之前就被整类抽走，没走归属判定；relocate_units.evaluate_group 见 qb_temp_entries 非空即 blocked（GATE_QB_TEMP）。

痛点 1（误报，根因）：libtorrent 1.2 与 2.0 的 aux::move_storage()（src/aux_/storage_utils.cpp，RC_1_2/RC_2_0 两分支源码均已核）只遍历 f.file_range()（种子自己的文件表）逐文件 move_file（rename 失败回退 copy），搬后只删「变空的」源子目录（remove 非空即停，且从不删 save_path 本身）——外来文件（无论 .!qB 还是已完成）既不会被搬走也不会被删。共享目录里任何一集在下载/暂停未完成，该目录所有单种子移动全被拦。

痛点 2（自相矛盾）：外来普通文件（external/misc）现状只 note 不拦（「只链路本组文件， 不动杂项」），外来 .!qB 却硬拦——同一归属两类处置。后者是 lt 1.1 时代「整目录连坐」行为的防御残留（libtorrent #435，该行为在现行 1.2/2.0 已不存在；issue 2020 年 stale 关闭，算法已被逐文件实现取代）。

旁证：本项目真机报告 26-10-18-0826（qB 5.2.3 / lt 2.0.13 实测）「组内第一个种子真正搬文件并保留进度，其余成员撞目标同名 need_full_check」与逐文件语义一致。

§03方案总览

主线（收集层三分，判定层零改动）：relocate_mod._group_facts 把 ext 的 .!qB 条目剥后缀后按归属三分——

归属判据去向效果
own-matched剥后缀 ∈ 本组 _top_children（或本组 names 本身带后缀）qb_temp_entries维持 GATE_QB_TEMP 硬拦（数据未落定）
foreign-matched剥后缀被同 save_path 其它种子文件表命中（复用 _classify_entries 的 belongs 机制，单次扫描）external_entries随现有组外 note，不拦
unowned两者都不中（孤儿残留/非种子写入者）misc_entries随现有杂项 note，不拦（D1）

落点：src/auto_qb/core/modules/relocate_mod.py（收集+分类）、relocate_units.py（仅 GroupFacts docstring 与闸门文案同步，gate id 不变）、tests/test_web_relocate.py、tests/test_relocate_units.py。三入口共用 evaluate_group，一处收窄全入口生效。

决策表：D1（unowned 处置）见 §06——采纳分析轮推荐 A（降 note）。

R1 增补（26-11-02-0220）：同族第二例 —— 空间/同卷闸门的「目标叶子未建」误报

用户复测报同类误拦：GATE_SPACE「目标卷剩余空间不可判定」。根因同族——收集层把「合法的暂不可见」交给硬拦：目标叶子目录尚未创建是迁移正常输入（libtorrent move_storage 落地即 create_directories，上轮源码已核），而 shutil.disk_usage 要求路径已存在（本机实证 missing → WinError 3）→ target_free=None → 硬拦；且同卷判定（os.stat 取 st_dev）在叶子未建时同样不可得 → 按跨卷保守处理让形态降级/拒绝（实施中发现，与空间同一机制一并收口）。用户配置无 fs.path_map（已核实），报错文案首位的「容器映射未覆盖」属容器实现语义，对 Local 场景误导。

方案A（收集层祖先回退，两处同一机制）：_volume_free_resolved（disk_usage 失败逐级上溯第一个可用层取卷剩余）与 _same_volume_resolved（same_volume None 逐级上溯第一个可读层比 st_dev）；上溯到根仍不可用/盘未就绪/UNC 不可达 → 维持 None → 硬拦照旧（保守默认不破）。junction/卷挂载点之下新建目录物理落在「最近存在祖先」所在卷，两处语义均正确。方案B：same_fs 单成员 note 文案对齐实现（原文「目标冲突/空间未预检」与实现不符，实为「其余闸门照跑」）。

§07风险与对策

风险触发条件处置
lt 版本差异（源码读的是分支头，非 2.0.13 原包）实际运行环境的 lt 行为与分支头不一致（整目录连坐仅存在于 ≤lt 1.1 时代）真机复验用例兜底：内容根放外组 .!qB 执行迁移，断言其原地不动；支持面钉 qB ≥4.3（lt 1.2+）
归属误判（同目录同名不同内容）外组文件名与本组文件名相同/互为剥后缀形态两个误判方向均偏保守：误判外组→无主=继续拦；误判外组→本组=多拦一次。无放行风险
TOCTOU 预检后状态漂移预检通过到 qB 实际搬运之间外组开新下载逐文件语义下无影响；本组成员已 pause + GATE_MOVING/GATE_INCOMPLETE 兜底
守阵漏改导致收集层回归未来重构 _group_facts 时恢复旧的整类抽取三案守阵钉住收集层语义（foreign/unowned 不进 qb_temp、own-matched 必进），闸门表断言保留
祖先回退语义边界（junction/挂载点/映射实现）目标祖先链上有 junction/卷挂载点，或容器映射实现下叶层不可读新建目录物理落在「最近存在祖先」所在卷——两处上溯语义均正确；映射实现逐层上溯同样适用；全链不可达维持硬拦（守阵钉住）
