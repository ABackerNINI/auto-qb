种子转移到其它下载器: 后端移动管线 + per-target 配置 + 四支右键菜单

把主 qB 的种子任务原样转移到用户在 WebUI 配置的其它下载器(qB 先行, Transmission 留接口暂不做)——保留分类/标签/保存路径/限速等字段且字段集按目标各配一套; 语义是「移动任务、不动数据」: 转移在后端执行, 前端经四支右键菜单「转移到」触发, 确认弹窗参照删除流四段式。

§01目标与设计原则

背景与目标

PT 场景下需要在多个下载器之间搬家(换 qB 实例、分流做种)。现状只能手动逐个导出 .torrent 重加: 字段(分类/标签/路径/限速)全丢, 且常规重加必然触发重校验甚至重下载。本计划交付: 右键选中(单/多/整组/整剧) → 选目标下载器 → 确认 → 后端自动完成「导出 → 字段映射 → 目标添加 → 验证 → 删源」的移动管线; 目标下载器在「WebUI」设置卡里增删改配, 保留哪些字段按目标各配一套。

设计底线(不变量, 违反即错)

  1. 数据文件永不移动、永不删除——删源只删任务(deleteFiles=false);「转移」不含任何数据搬运。
  2. 任何不成功路径不碰源——添加失败/验证超时/目标已存在/目标报 error → 源任务原样保留。
  3. 未完成种子绝不以跳检形式添加——跳检添加未完成数据 = 假 100%, 必坏; 跳检开启时对未完成种子自动逐条降级为校验添加(D8)。
  4. 同机硬约束——主 qB 与目标下载器必须同机, 转移后数据对目标可达; 转移后绝不重新下载。
  5. 凭据只从服务端出网——前端不持有、不出网目标下载器凭据。
  6. 新配置键全部进 validate_config + config/schema.py(黄金法则 4), fail-fast 聚合报错。

§02现状与痛点

架构事实(26-10-31 探索核实): 本项目是独立 daemon + 自托管 WebUI(FastAPI, webui/server/factory.py:20), 前端从不直连 qB, 全部走 /api/*(shared/auth.js api()); 这决定了转移必须在后端执行——浏览器直连目标 qB 会被 CORS 卡死, 且凭据不该进前端。

可复用的现成管线:

  • 后端 QbApi facade 已有全部所需原语: torrents_export(core/qbapi.py:320)、torrents_add(:180)、分类/标签全套(:59-87)、单种子上下行限速(:126/:135)、share limits(:197)。
  • 右键菜单: shared/ctx_menu.js:23 四支 CTX_BRANCHES = [multi, episode, member, group], :103 有 kind:"submenu" 先例, episode 支本身就是多 hash 集合(menu.js:157-160); 布局可经 config.web.ctx_menu 定制。
  • 批量管线: 选中解析 selection.js:125-235 → commands.js:749-752 POST /api/torrents/bulk → waitCmd 回执 + toast 三态 + 行内图标 setRowIcon。
  • 确认弹窗范本: shared/delete_flow.js:199(删除流), modal 引擎 ui_feedback.js:181。
  • 设置卡: 「WebUI」卡 config_hub.js:254-263, 二级页 tpl/settings-detail.html:60; 配置树读写走 GET/PUT /api/config(server/routes/config.py:116/:134), schema 单点 config/schema/。

痛点: 目前没有任何转移能力; 手动搬家丢字段、丢做种状态, 且无法做到「不动数据」。

§03方案总览

三层结构

层落点内容
配置层config.web.transfer + WebUI 设置卡targets[](名称/类型/base_url/用户名/密码/启用/per-target 字段集/转移后状态/跳检开关/路径映射表); schema + validate 同步
执行层新模块 src/auto_qb/transfer/orchestrator(状态门/导出/映射/添加/验证/删源/失败分类) + adapter 注册表(adapters/base.py 协议 + qb 实现 + tr stub)
交互层前端 shared四支右键菜单「转移到」submenu + 确认弹窗四段式(参照删除流) + waitCmd 逐项结算

单种子执行流水(orchestrator)

状态门(下载管线态拦截, §03 状态门)
  → 源 export(QbApi.torrents_export, 取 .torrent bytes)
  → 字段采集(按 per-target 字段集, 从源种子 properties/maindata 取当前值)
  → 路径映射(有序前缀替换, 默认空 = 原样)
  → 跳检决策(progress==100% 且目标跳检开 → skip_checking=true; 否则 false)
  → adapter.add_torrent(bytes, fields, skip_check)
  → 验证: 轮询目标 maindata, hash 出现 且 state ∉ {error, missingFiles}(10s 超时)
  → 成功: 删源(仅任务, deleteFiles=false; 确认框勾选「仅本次保留源种子」则跳过)
    失败: 源保留, 分类记录(export失败/已存在→跳过/认证失败/超时/error)

状态门

  • 拦截(不可转移, 预检写明原因): metaDL、downloading、stalledDL、queuedDL、checkingDL、allocating、forcedDL(下载管线态)、missingFiles(数据已丢)。
  • 放行: UP 家族(uploading/stalledUP/pausedUP/stoppedUP/queuedUP/forcedUP/checkingUP)、pausedDL/stoppedDL(未完成但暂停, 走非跳检通路, 目标 recheck 保留进度续传余量)、error(按完成度走通用规则)。
  • 跳检判定不看状态名看完成度: progress == 100% 且目标跳检开 → 跳检; 其余一律校验添加。同批混态逐种子判定, 结果注明「未完成, 已自动改为校验添加」。

per-target 字段集

字段/开关类型新建模板默认备注
保存路径字段(锁死)必开(置灰)同机硬约束下关掉 = 数据不可达, 违反不变量 1
分类 / 标签 / 分享率限制 / 做种时长限制 / 上行限速 / 下行限速字段开目标不支持的字段由 adapter 降级并在结果注明
超级做种字段关高危项默认关
转移后状态单选保持原状态备选「统一暂停」= 多一道人工闸
跳过校验开关开未完成种子自动降级, 见状态门
路径映射规则表空(原样)有序 from→to 前缀替换, 首条命中生效, 只作用于保存路径终值

§06拍板记录

#决策点结论(26-10-31 拍板)
D1转移语义移动任务: 目标添加成功后删源(仅任务, 不删文件); 确认框「仅本次保留源种子」勾选默认不勾
D2数据策略默认跳检添加、per-target 可切换; 定死主 qB 与目标同机, 数据必须对目标可达, 不得重新下载、不得移动数据
D3字段集粒度per-target 各配一套; 保存路径锁死必开; 新建模板除超级做种外全开
D4配置存放挂「WebUI」设置卡, 配置树 web.transfer; 密码明文落 config.yml(与现有 qB 凭据同款), UI 遮显
D5菜单结构一级项「转移到」+ submenu(目标列表); 四支全挂(multi/episode/member/group), group 支沿用现有 scope 解析(选中集优先, 否则整组成员)
D6执行与失败串行逐种子; 失败分类不中断批次; 批量无上限; 不自动重试
D7确认弹窗参照删除流四段式(预检→明细→执行→结算), 含改写路径预览与「仅本次保留源种子」
D8未完成种子不禁止; 目标跳检开时自动逐条降级为校验添加; 下载管线态(metaDL/downloading/stalledDL/queuedDL/checkingDL/allocating)仍拦截; 风险分析通过(§07)
D9转移后状态per-target 单选: 保持原状态(默认)/ 统一暂停
D10扩展接口DownloaderAdapter 协议(capabilities/test_connection/add_torrent(data, fields, skip_check)); 注册表按 type 实例化; TR 为 stub(test 即「暂未实现」), 不做假接口

§07风险与对策

风险触发条件处置
映射配错 → 目标 recheck 得 0%路径映射规则写错前缀/目标盘符确认弹窗展示被改写的保存路径预览(肉眼可查); 底线兜底: 数据文件全程不删, 最坏损失 = 任务元数据, 重加 .torrent 再 recheck 可恢复全部已有进度
「hash 出现」以 error 态出现目标报路径无效等成功判定收紧: hash 出现 且 state ∉ {error, missingFiles}; error 即判失败、源保留
验证超时早于大种子 recheck 完成超大种子校验超 10s按 D1 口径 hash 出现即算接受; 文件不删故无数据损失, 见风险 1 的兜底
跳检 + 数据实际缺失理论上同机不会发生error 态判定兜底; 同机硬约束(D2)从根上消除
批量无上限拖长执行一次转移数百种子串行 + 逐条超时, 不并行不重试; 确认弹窗明示数量, 用户自担耗时; 行内图标可随时观察
凭据泄漏config.yml 外流 / 日志外泄明文仅限本机 config.yml(与现有 qB 凭据同款); UI 密码框遮显; 日志一律不落目标凭据
