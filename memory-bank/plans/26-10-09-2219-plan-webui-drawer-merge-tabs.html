01

背景与现状

种子详情面板(停靠抽屉)现有五页签:general 常规、trackers Tracker、peers 用户、content 内容、traffic 流量。计划 26-10-06-0838 建立了「经典 + 模板变体」体系:每页签有独立的变体选择器(.dt-select),变体文件 drawer_tpl/NN-<tab>-<slug>.js 自注册,经三份主题 manifest(atlas / console / prism 的 index.html)装载,当前 15 个变体。

报告 26-10-07-0542 §2 为治「4K 下键值栅格/英雄行等分拉伸到视口宽」,给四个页签的变体宿主加了单点限宽(drawer_templates.js 00-core 注入):

.dt-host[data-dt-host="general|trackers|peers|content"] { max-width: 1400px; margin: auto; }

这条限宽在窄屏零变化、在中屏恰到好处,但在高分辨率屏幕上,居中内容两侧出现大片空白。

与本轮直接相关的第二层现状是渲染层的双轨重复:四个页签的经典视图活在 tpl/drawer.html 的 Vue 模板里(v-if/v-show 链),15 个变体又在各自的 JS 里以命令式 DOM 重写同类内容——加载/错误/空态外壳、小节标题、键值栅格、表格骨架,每个变体各造一遍。任何「把某页内容放到别处显示」的需求(合并视图正是这种)在现状下要么复制模板、要么复制变体,重复是结构性的。

02

问题陈述(R2 修订)

用户动议(R1 概括):面板限宽后,高分辨率屏幕上两边都是空的;考虑把「常规&内容」「Tracker&用户」合并,仅当宽度足够时提供合并选项,可切换。

R2 补充反馈,对 R1 方案(合并 = 页签下的特殊变体)的三点修正:

  1. 无法自由选择——R1 把合并做成 general 页签下的一个变体,合并后另一列(内容)以固定只读版式出现:另一页签自己的模板选择(经典或任一变体)被钉死,交互也被 v1 只读收敛砍掉。用户要的是随时右键开关、两列各自保持完整的页能力。
  2. 功能需要完整保留——合并列不是预览,就是那一页本身:优先级、重命名、封禁等交互在合并态照常可用。
  3. 各页做成插件,减少代码重复——把每一页的内容渲染收敛为统一契约的可复用单元,单页签视图与合并列消费同一个实现,顺带治 §1 末段的结构性双轨重复。

把动议拆成四个可独立验证的诉求:

  1. 利用宽度——高分屏留白不该浪费,但不许回到「内容拉伸满视口」的老病;出路是并排放两份完整的页内容。
  2. 门控——合并只在宽度足够时有意义;窄屏下强行双栏会把每列挤到不可读,开关必须按宽度可用性约束。
  3. 自由可逆——右键即开即关,不分页签顺序、不锁定模板;状态跨会话记忆。
  4. 插件化——每页一个实现,单栏与合并共用;新增显示形态(未来的三栏、浮窗)不再复制内容层。
03

构想:四条设计决策

D1页插件化:每一页一个统一契约的实现

把「页」从模板与变体的双轨里抽出来,收敛为页插件(page plugin):常规、Tracker、用户、内容四页各自成为一个自包含插件,连同其全部变体,统一注册到页注册表,契约一致:

{ tab, id, render(ctx), notify(type), destroy(), available?(ctx) }

配套一个部件工具箱(widget kit):加载/错误/空态外壳、小节标题、键值栅格、表格骨架、行级键盘 roving tabindex 助手——插件按需取用。经典四链从 drawer.html 的 Vue 模板移植为 id: "classic" 的正式插件(持久化键值不变,经典仍是 drawerTplSel 的合法值,只是从「v-show 包裹层」变成「注册表条目」);15 个既有变体契约不变、原样入表。本轮不强制变体迁移到工具箱(范围守恒),迁移是后续渐进事项。

这一步的收益与合并无关也成立:单页签视图的加载/空态/错误外壳从「四份 Vue 链各一套」变成「工具箱一份」;此后任何新显示形态都是「换个宿主挂插件」,不再有内容层复制。

D2合并 = 布局模式,不是某个页签的变体

合并是抽屉级的布局标志(drawer.merge ∈ {"off", "gc", "tp"},独立持久化),不是挂在某个页签下的变体。生效且门满足时,抽屉正文渲染双列宿主,两列各自挂对应页签当前选中的页插件——常规列尊重常规页签的模板选择(经典或任一变体),内容列同理。模板选择 × 合并开关两个自由度彻底解耦,R1 的「无法自由选择」由此消解:用户可以「常规经典 + 内容树形变体」合并,也可以两边都经典,切换器照常各管各列。

合并对左列右列配对理由
"gc"
常规 + 内容		 常规页(所选插件) 内容页(所选插件) 「这是什么种子」与「它装了什么」是同一次阅读的两个半页;均以静态数据为主,无秒级跳动。
"tp"
Tracker + 用户		 Tracker 页(所选插件) 用户页(所选插件) 「谁在供种」与「谁在下」是连接观察的一体两面;同为 5s 轮询表格,节奏同频,数据供给可共享一套扩展。

流量页签不参与合并:图表满宽是它的本性;合并标志在流量页签/流量形态下暂不渲染(标志保留,回来自动恢复)。

D3右键开关:自由切换,门内可用

开关入口 = 抽屉正文/页签栏右键菜单(新增 ctx-menus.html 的抽屉菜单种类,走既有 openMenu 家族 + _menuFitRefit 视口拟合):

  • 两项带勾选态:「常规+内容 并排」「Tracker+用户 并排」,点了即在 "gc"/"tp"/"off" 间切换(选一对即关另一对,同一时刻至多一对生效——双列已占满可读宽度,三栏不在本轮)。
  • 宽度门不满足时两项置灰不隐藏(title 注明「窗口宽度不足」)——置灰传达「功能存在但被宽度挡住」,比藏起来更可发现;门满足即恢复可点。
  • 右键之外保留一条快捷路径:页签栏双击等效切换当前页所属对的合并(可选加项,实施时定)。

门判据取 window.innerWidth >= 1920(常量单点,初值 1920,可调):1920 屏合并后每列约 930px,真正比单栏 1400px 更好用;1366/1600 笔记本屏合并只会把每列挤到 700px 以下。与 R1 相同,门是运行时的暂态遮蔽,不是选择撤销:合并开着把窗口缩窄,生效表现回落单栏(当前页签),标志保留;拉宽自动恢复双栏。

D4功能完整保留:合并列就是页本身

合并列挂的是页插件的正式实例,不是只读镜像:内容列的行选中、优先级菜单、重命名,用户列的封禁等动作照常可用。配套的唯一硬要求是交互状态按实例隔离(§5.6):同一页插件可能同时存在挂载于单栏与合并列的两份实例(互斥可见),行选中、弹层锚点这类状态不能共享全局单例。R1 的「v1 只读收敛」取消。

一句话构想

每页一个插件(经典链移植入表 + 部件工具箱),合并 = 抽屉级布局标志 + 右键勾选开关 + 宽度门;两列各挂各自所选插件,功能全量保留,门只遮蔽不撤销。

04

路线对比与选型

路线做法结论
A' 页插件 + 布局模式 + 右键开关(R2 选定) 四页插件化(经典移植入表 + 工具箱),合并为抽屉级布局标志,右键勾选开关,两列各挂所选插件。 自由选择(模板 × 合并解耦)、功能全量、重复收敛;代价是 classic 移植的大批次(§6 S1)。
A 合并 = 页签下特殊变体(R1) 合并作为 general/trackers 页签下的新变体 id,复用变体注册体系。 用户反馈否决:选择器只能表达「当前页签的一个形态」,另一列的模板选择被钉死、交互被砍(无法自由选择);合并列内容要复制实现(代码重复),弃。
B 头部独立「并排」开关 + 现状双轨 不动渲染层,新增标志直接把两个页签的既有 DOM 拼进双栏。 双栏拼「Vue 经典链 DOM」做不动(v-if 链与页签互斥绑定),拼变体 DOM 则必须复制内容层;不插件化就没有自由组合的原料,弃。
C 取消 1400px 限宽 内容满宽,高分屏不再留白。 治标反弹:4K 下键值栅格拉伸正是报告 26-10-07-0542 §2 限宽要治的病;表格行在 3840px 下不可读,弃。
D 上下堆叠合并 常规在上内容在下,一页滚完。 不解决宽度浪费(留白依旧),只是把页签换成了滚动距离,弃。
E 纯 CSS 容器查询双栏 @container 按宿主宽度自动分栏。 只解决布局,解决不了开关可用性、影子期回落、第二列数据供给与实例挂载;弃。
05

技术方案(路线 A' 细化)

5.1页插件契约与部件工具箱

  • 契约:{ tab, id, render(ctx), notify(type), destroy(), available?(ctx) }。render 负责整页状态(加载/错误/空/有数据),数据落袋走既有 _dtNotify 通道,卸载走 destroy(定时器/监听/弹层清理)。
  • 注册表:TPL_REG 扩为页注册表,允许 id: "classic"(原哨兵转正式条目);drawerTplSel 持久化键值与白名单校验口径不变——存储向后兼容,升级零迁移。
  • 部件工具箱:核心层新增共享构建器——stateShell(加载/错误/空三态外壳)、sectionHead、kvGrid、dataTable(含冻结首列钩子)、行级键盘 roving tabindex 助手(dt10/11/12 已用的那套上提单点)。经典插件全部经工具箱构建;变体不强制迁移,新变体鼓励用。
  • 文件布局:页插件放 drawer_pages/(classic 四件 + 后续插件),既有 drawer_tpl/ 15 变体原样;三主题 manifest 各增对应行。

5.2经典链移植:行为逐位不变的硬约束

S1 是全方案风险中心(§8),移植必须满足三条不变式:

  1. DOM 结构与类名钩子原样——FX-22 换页签过渡、截断族、冻结首列、row-btn/prio-btn 等 CSS 都钉在经典链的类名与层级上(drawer.html 注释明言「四个页签 body 与 FX-22/截断族原样保留」);插件产出的 DOM 与现模板逐类名一致,移植是「搬运」不是「重写」。
  2. 交互链原样——行选中、filePrio 优先级菜单、重命名入口、键盘 roving 域,事件委托目标与状态读写路径不变(状态隔离改造见 §5.6,单独成批可回退)。
  3. Vue 职责收缩而非清零——drawer.html 保留头部(页签栏/切换器/统计栏)与宿主骨架;四页签经典 body 从模板移除,加载/错误/空态一并进插件。Vue 与插件的争用红线(显隐只走宿主自身)沿用既有纪律。

验收锚点:S1 合入后,门不满足、合并关闭的状态下全站行为与移植前逐位一致(含 DOM),e2e 全绿——这一批独立可回退。

5.3合并布局层:标志、宿主、宽度门

  • 状态:drawer.merge ∈ {"off","gc","tp"},独立 localStorage 键(白名单校验,脏值回落 "off",与 readSel 同纪律);不在 drawerTplSel 里,两个自由度互不污染。
  • 宿主:生效且门内时,drawer-body 渲染双列容器(grid-template-columns: minmax(560px,1fr) minmax(620px,1.15fr); gap: 24px,上限 2400px 居中——.drawer-split { max-width: 2400px; margin: auto; } 单点),两列各自一个列宿主;容器是 drawer-body 直接子节点,FX-29 遮罩(.switching > *)照常命中。滚动沿用单一共享滚动,两列顶对齐独立生长。
  • 挂载:列宿主挂对应页签当前 drawerTplSel[tab] 指向的页插件;单栏态挂载逻辑(_dtMountActive)复用,只是目标宿主不同。页签栏照常工作:合并态下当前页签属于生效对时双列渲染;点对外页签(如流量)则本轮单栏渲染该页签,标志保留,回来自动恢复双列。列序按对固定(gc: 常规左/内容右;tp: Tracker 左/用户右),不随当前页签换序——位置记忆比「当前优先」稳定。
  • 宽度门:判据 innerWidth >= DT_MERGE_MIN_WIDTH(1920),常量与判据函数单点在核心层,菜单置灰(§5.4)与挂载守卫共用。resize 防抖 150ms:双列激活但门转不满足 → 拆双列回单栏(标志不动);影子期门转满足 → 重建双列。

5.4右键开关:抽屉菜单种类

  • ctx-menus.html 新增抽屉菜单分支(menu.drawer),触发点 = 抽屉正文与页签栏的 @contextmenu.prevent;种子详情形态才渲染(流量形态无此项)。
  • 两项:「常规+内容 并排」「Tracker+用户 并排」,勾选态反映 drawer.merge;点击互斥切换(选一对即关另一对,再点已选项即关)。
  • 门不满足 → 两项置灰 + title="窗口宽度不足";置灰项不触发 = 无入口即无状态变化。视口拟合走既有 _menuFitRefit,Esc 关闭走既有退栈链。

5.5数据供给与轮询:归 drawer.js,插件零触碰

插件纪律沿用「禁触碰轮询生命周期」,合并的第二列数据供给全做在 drawer.js,按「合并标志 + 门」门控:

  • gc 对:openTorrentDrawer / _loadDrawerTab 在合并生效时补一发 _fetchDrawerFiles;非当前页签的 trackers/peers 列表数据在双列激活时按需首发(进入 tp 对时两列表各一发)。
  • tp 对:_startDrawerPoll tick 在合并生效时对 trackers 页签同时拉 _fetchDrawerPeers(true)(5s 同频,与用户页签单用时负载相同);peers 页签同理反向。
  • FX-29:_drawerWaitSources 按生效对扩展(gc: ["detail","files"];tp: ["detail","trackers","peers"])——遮罩等全对数据源齐再掀,不掀半新半旧。
  • 请求代际纪律原样:补拉走既有 (silent, seq) 签名,换目标/换代际在途响应照旧丢弃。

5.6交互状态按实例隔离(功能完整保留的关键)

现状里一批交互状态是 app 级单例:filePrio(优先级弹层)、drawerSelPath(内容行选中)、批量选中集合。单栏态「同一时刻只挂一页」时单例无害;合并态下两个页插件实例同时活着,单例会串列(左列选中右列弹菜单)。改造原则:

  • 插件实例持有自己的视图态:行选中、roving 锚点、列内排序记忆进实例;destroy 随实例销毁。
  • 跨实例单点状态保持单点:filePrio 弹层是文档级单例,但「谁打开了它」的锚点/indices 归打开它的实例;同一时刻只允许一个实例持有,切换选中即转移——与现状「切页签失效」语义一致,只是宿主从页签换成实例。
  • app 级数据(drawer.files 等)仍是共享单点,实例只读渲染——数据单点、视图态隔离,两层不混。

这一批独立成批(S4),在单栏态先行合入验证(行为不变),再被合并态消费。

5.7回落链

异常处置
某插件实例渲染抛错实例级回落:该列回挂 classic 插件实例并 drawerTplSel[tab] 复位落盘(既有语义,宿主从全局单实例变为按列实例);另一列不受牵连。
门转不满足(双列激活中)拆双列回单栏,标志保留;拉宽自动重建(暂态遮蔽)。
存储里 merge 脏值 / 插件 id 已删白名单回落("off" / classic),与 readSel 同纪律。
关面板逐实例 destroy(定时器/监听/弹层清理)+ 清宿主;filePrio 单例若被某实例持有则强制归还关闭。

  • 两列各自尊重该页签的模板选择:左列经典 + 右列变体、双经典、双变体均成立;切换器改某列模板只影响该列。

  • 合并态点对外页签(流量):该页签单栏渲染,标志保留;回到对内页签双列恢复。
  • 合并态换种子:遮罩等全对数据源齐才掀,无半新半旧;代际纪律在途丢弃照旧;5s 轮询双源同频、document.hidden/非主内容页照旧跳过。

  • 三主题 manifest 一致,既有守阵(变体注册、FX 族、按钮体系、静态体量)全绿。
