缺失站点导出/导入 tracker 合并

缺失站点导出(CLI)与导入(WEBUI)默认把「同种子共现」的多个 tracker 域名合并为一个站点条目(domains 数组),可选拆回逐域名;两端共用同一分组构件,口径不漂移。设计主轴:分组只在缺失域名内做 union-find,合并条目的站点名/默认标签由组内最短域名生成。

来源 用户指令「导出缺失站点时默认合并同一颗种子的多个 tracker 到同一个站点,可选择分开;WEBUI 导入缺失站点同步支持」→ 会话 grilling 两轮拍板(D1~D6,见 §06)后定稿

§01目标与设计原则

为什么做:一个 PT 站点常有多个 tracker 域名(主站域名 + announce 子域等)。现状是一域名一条站点条目,同站被拆成多条,标签/限速/HR 要重复配 N 遍。目标:导出与导入默认产出每站一条(domains 数组本就是 schema 原生形态),想拆的能一键拆回。

做到什么程度算成:

  • CLI --export-yaml(两种模式)默认产出合并条目,--split-trackers 拆回逐域名(与改造前输出逐字节一致);
  • WEBUI「导入缺失站点」在存在会真实合并的组时弹三钮引导(合并默认+推荐),否则维持现状路径;两种选择都只填编辑器待审,保存仍走既有 PUT /api/config;
  • 两端分组结果一致(同一构件),全量测试绿 + 新基线切片。

设计底线 / 不变量:

  • 不新增 config 键 —— 开关是 CLI flag 与前端交互,不进 config.validate_config/schema;
  • 只读面不变 —— 依旧只调 qB 查询接口,不碰任务队列与 state_file(qB 调用次数与现状相同,逐种查 tracker 那次遍历不变);
  • 已配置域名永不进产物 —— 分组只在缺失域名集合内做,已配置域名不参与粘合(保守:两个从不直接同现的缺失域名,不因都碰过某已配置域名而合并);
  • 产物一律待审 —— CLI 是模板用户填键,WEBUI 是填编辑器不落盘,合并错焊肉眼可查、可改。

§02现状与痛点

  • collect_all_tracker_hostnames(src/auto_qb/core/exporter.py:27)把「域名↔种子」关联在收集时就丢掉了,只返回去重集合——分组所需的共现信息无处可取,这是要动的根。
  • CLI export_yaml_template(exporter.py:100)逐域名 build_tracker_entry(domain) → 一域名一条,站点名/标签由该域名生成(gen_tracker_name :69 / gen_default_tag :58)。
  • WEBUI /api/sites/missing(src/auto_qb/webui/server/routes/sites.py:29)与 CLI 同一套构件、同样逐域名;前端 hubImportSites(config_hub_tracker.js:202)扫描后直接 confirmDialog 列清单确认,无合并概念。
  • 现成可复用件:对话框层已有三钮 confirmThreeDialog(ui_feedback.js:179,返回 true|"extra"|false,extra 钮恒按 danger-solid 渲染)——形态对得上本需求,只差第三钮的样式位。
  • 测试现状:tests/test_exporter.py、tests/test_web_backend_misc_sites.py(6 条 missing 端点用例 + 前端接线测试 :122);e2e 无 spec 覆盖此流程。

§03方案总览

3.1 后端分组构件(exporter.py,两端共用)

  • collect_torrent_tracker_hostnames(api) -> list[set[str]]:逐种收集,每颗种子一组,单种查 tracker 失败 = 空集(沿用现状静默跳过);旧的 collect_all_tracker_hostnames 改为对它做并集,调用方签名不变。
  • group_missing_domains(torrent_sets, missing) -> list[list[str]]:仅对 missing 做共现 union-find(任一种子内两缺失域名同现即并,跨种子传递闭包);输入先 sorted 保证确定性;全单元素组时退化为现状。
  • build_merged_entry(domains, taken):代表域名 = 组内最短(tie 取字典序),站点名与默认标签由代表域名经既有 gen_tracker_name/gen_default_tag 生成;domains 列表 = 整组 sorted;其余字段与 build_tracker_entry 同源。

3.2 CLI(--split-trackers)

  • export_yaml_template 增参 split_trackers: bool = False;False 走分组合并,True 恒拆(逐域名,行为=现状);only_missing 与追加模式共用同一落点(exporter.py:129-137 往 trackers_config 塞条目),一处分支两模式同时生效。
  • cli.py 加 --split-trackers(store_true),并加入与 --only-missing 同款的配合校验(不带 --export-yaml 时报错);export_yaml 透传。

3.3 WEBUI:响应加 groups + 三钮自适应引导

  • /api/sites/missing 响应追加 groups: [{name, domains: [...]}](name=代表站点名,与 CLI 同规则);sites 字段保持逐域名条目原形——现有断言与逻辑零破坏,加字段向后兼容。
  • 前端 hubImportSites 三分支:
    1. 无缺失 → 现状 toast(不变);
    2. groups 全单域名 → 现状 confirmDialog 直接列清单(不变);
    3. 存在 ≥2 域名组 → 三钮弹窗:「取消」/「拆分导入」/「合并导入」——合并=ok 钮(Enter 默认、推荐样式),拆分=extra 钮;body 带解释文案(同站多域名合并后共享标签/限速/HR,拆分会产生重复站点)+ 合并明细列前 ~10 组、超出折叠「…另有 N 组」。拆分导入走现状逐域名路径;合并导入每组一条(entry = 代表 site.entry + domains=组内全域名,键=代表名)。
  • _openModal/confirmThreeDialog 扩展 extra 钮样式位(opts.extraStyle:缺省 "danger-solid" 兜底,既有调用点渲染零变化;本需求传 ghost——「拆分导入」不是破坏性动作,不该渲染成红钮)。
  • 同名不覆盖语义保留(现有 config_hub_tracker.js:224 skip 逻辑,合并模式按组代表名查重)。
