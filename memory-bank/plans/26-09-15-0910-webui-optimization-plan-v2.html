摘要

本轮需求分三类。修 bug: 历史流量图悬停闪烁(命中区只覆盖单柱, 桶间空隙反复触发 leave/enter)与设置页"日志 / WEB UI / 通知"折叠头点了收不起来(三态记录永远写不出 false)。补交互: 已选批量条吸顶、Shift 多选以展开组为锚点、 强制汇报的"等待中 → 成功 / 超时失败"持续强反馈、删除确认框扩容并展示成员明细。视觉分家与精修: 展开态改"结构语言"、 选中态独占"强调色语言", 外加图标字形替换、配色令牌微调与轻动效。

04

关键设计细节

4.1历史流量折线图与悬停修复(R01/R02)

闪烁根因: 现模板里命中区 <rect class="hist-hit" :width="histBarW()"> 只覆盖每组的第一根柱, 且 enter/leave 挂在逐桶的 <g> 上 —— 指针扫过桶间约 4px 空隙时 histHoverIdx 归 -1, tooltip 随之显隐交替, 表现为闪烁。

改法: 悬停事件上移到图表容器一层 —— 在 .hist-chart 上挂 mousemove, 用 getBoundingClientRect() 把指针 x 折算进 viewBox 坐标再换算桶索引, mouseleave 一次清除; 图形元素一律 pointer-events:none。追踪连续无空隙, tooltip(已有 pointer-events:none)不再闪烁。

折线图规格: 双系列(上传 = --today-up 青, 下载 = --today-down 靛, 延续今日流量卡配色), 直线段 + 小数据点; 弹层 680→860px, viewBox 920×380; 悬停画竖向 crosshair + 两系列高亮点 + tooltip(靠右自动翻转); 打开弹层时线条做一次 stroke-dashoffset draw-in(全局 prefers-reduced-motion 已自动关停)。 天/月/年聚合(historyBuckets)、Y 轴刻度、汇总行全部复用。

4.2批量条吸顶与表头联动(R03)

.bulk-bar { position: sticky; top: var(--head-h); z-index: 6; }。批量条出现时表头吸顶偏移必须同步下移, 否则两吸顶条重叠: app.js 在 updated() 里量测 .bulk-bar 高度 + 下边距, 值变化才写 :root --bulk-h(无选中时 0 —— 沿用 --head-h 的"值未变跳过"模式, 不每帧写变量); 表头吸顶改 top: calc(var(--head-h) + var(--bulk-h, 0px))。层叠次序遵循既有教训: topbar(31) / status-strip(30) / bulk-bar(6) / group-head(5)。

4.3强制汇报的反馈状态机(R05)

第六轮已把回执做实: 命令投递返回 cmd_id, reannounce 的回执由主循环 tracker 确认跟踪器 (_check_reannounce_pending, 30s 窗口)在确认成功 / 确认失败 / 超时后写入, /api/cmd/{id} 以 pending → ok | error 透出。缺的只是前端呈现形态 —— 本轮把瞬时 toast 换成常驻、可更新的状态条:

实现上给 toast 系统加最小扩展: toast() 支持 sticky(不自动消失)并返回 id, 新增 updateToast(id, { text, kind }); _logout() 清空 toasts 的既有逻辑天然覆盖新句柄。 四条链路统一接入: 组汇报(act)、单种汇报(actTorrent)、批量汇报(bulkAct, 终态含"成功 N / 失败 M"汇总)、删除前汇报(_reannounceBeforeDelete, 失败保留种子不删除的既有语义不变)。 命令投递失败(网络/鉴权)仍走红色 error, 与"超时"区分。

4.4展开态与选中态分家(R07)

现状两者都靠"accent 左条 + accent 边框 + 高亮底"表达, 是相似度的来源。分家方案:

状态视觉语言具体规则
选中 selected强调色语言(独占)accent-soft 底 + accent 左条 + accent-line 边框(维持现状), 是页面上唯一的"accent 行"
展开 expanded结构语言底色改下沉(--bg-sunken 系), 边框中性(--border), 移除 inset 左条, 底部圆角取直并与下方 .detail 面板相连 —— 行"打开成面板"而非"被染色"; caret 旋转保留
两者叠加—左条与柔底(选中) + 下沉与直角(展开)同时生效, 互不覆盖仍可读

4.5设置页短段折叠移除(R10)

三段(日志 log / WEB UI web / 通知 notify)各由一个 open=True 的 object 段声明"平铺", 但渲染层仍生成 ce-group 折叠头; 且 cfgGroupToggle 的两态切换(记录存在 → 删除 / 不存在 → 写 true)对缺省即为 open 的段 写不出显式 false, 点击永远收不起来 —— 即"有折叠但不能点击折叠"。

改法: ①cfgFlatten 对 kind === 'object' && f.open 的段不再生成 group 项, 子字段以同级 depth 直接并入渲染序列(无段头 / 无 caret / 无缩进, 输入框左缘与其它组对齐 —— 遵循"普通段子字段不缩进"的既定约束); ②cfgGroupToggle 改为写入"当前有效态的取反"(openGroups[key] = !cfgGroupOpen(path, field)), 三态语义修补后对任何段都正确(防御性修复, 移除折叠头后主路径不再触达)。

4.6删除确认框(R06)

_confirmDelete 增加 wide 形态(.modal.wide { width: 560px }); 信息区值元素从单行省略号改为可换行(white-space: normal; word-break: break-all)并允许选中复制 —— 长种子名与保存路径完整可读; 整组删除在信息区下增加成员明细滚动区(每行 = 站点 + 种子名, max-height 约 180px), 单种删除保持现有五行信息。两个勾选项(删除前强制汇报 / 同时删除磁盘文件)与"汇报失败不删除"的前端编排语义不变。

4.7Shift 多选锚点(R08)

shiftGroupSel 的锚点解析改为: selAnchorGroup(Ctrl+点击设置的) → expandedKey(当前展开组在可见列表内时) → 列表首行。同时 toggleExpand 在普通点击展开时把 selAnchorGroup 同步为该组 —— 于是"展开一组 → Shift 点另一组"即从展开组起选, Shift 仍不更新锚点, 可从同一起点多次扩展。明细表 Shift 已限定在展开组内, 行为不变。

06

风险与红线(不动清单)

  • 生产文件: config.yml 与 auto-qb-data/ 不触碰。
  • 类名 / DOM 耦合: .group-head / .detail-head(列宽拖拽锚点)、.search-hit / .ctx-menu / .detail-* / .pop-menu / .col-menu 等逻辑挂钩不得改名或增删列; 列定义与 autoqb_cols_v4 不动(本轮不加列)。
  • computed / methods 分界: 模板里 computed 不加括号、带参辅助一律 methods —— 两次实锤翻车点, 阶段 B/C/D 模板改动逐条自查。
  • 交互原语单例: toast / modal 是单例, 新增 sticky toast 句柄要随 _logout() 一并清空; confirm/prompt 的 Promise 契约不变。
  • sticky 层叠上下文: topbar 与 status-strip 各有 backdrop-filter, z 序已排定(31/30), 批量条(6)与表头(5)不得越位。
  • 动效边界: 不做行入场与数字滚动(分组视图 2s 级重渲染会反复播放); 新动效只用 transform/opacity, reduced-motion 全局降级已覆盖。
  • 图标: 新增图标只进 index.html 的 sprite(16×16 + stroke 约定), 不引外部图标库。
  • 后端: web.py / qbmanager.py 零改动; 删除"汇报失败不删除"的前端编排语义不变; 跳检/删除守卫等高风险业务代码不触碰。
