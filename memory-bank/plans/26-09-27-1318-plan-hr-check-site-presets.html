01

背景与问题

HR 在线核实(计划 26-09-22-2204 落地, CarPT adapter 已于 56c04e0 接入)的站点级配置现挂在 trackers.<站点>.hr_check(9 个字段, src/auto_qb/config/schema/hr.py:169)。四个问题:

  • 填写项过多: 启用一个站点要填 URL、路径、翻页参数等, 而其中绝大多数对已支持形态是唯一确定值, 不是用户该做的选择;
  • 易配错: adapter(页面形态)、hr_page_url(必须是登录后可达的 myhr 页)、download_path(须含 {id} 占位)、page_param(站点各不相同) —— 校验层只能拦部分(如缺 {id}), 拦不住「值合法但语义错」(URL 指到别的站、page_param 写成 p);
  • 未支持站点无防护: 任何站点都能自由启用 mode != off, 写错配置要到运行期才发现(adapter 未登记只是该站跳过, 原因埋在 HR 状态里);
  • 配置位置割裂(REV2 新增裁决): 启用/微调一个站点要在「站点」分区里逐站翻找, 而 HR 在线核实的总开关、频控、取数通道在「HR 在线核实」分区 —— 同一件事的两半分居两处, 站点越多越难对账。

事实依据: adapter 工厂(src/auto_qb/hr/adapters/__init__.py)里, 一个 adapter 名对应一组完全由代码确定的页面事实(scope_param / scope_values / 表头名 / 列名), 配置里唯一真正「每站不同」的只有主机名与页面路径 —— 而主机名就是用户已在 domains 里维护的站点域名。

REV2 修订说明: v1 方案是站点段就地瘦身(四键移出配置、其余留在 trackers.*.hr_check)。用户裁决改为站点段整体上收: 「站点」分区不保留任何 HR 在线核实配置, 启用与微调全部进「HR 在线核实」分区点选完成。本文按 REV2 重写 §3 起, v1 的档案表与 URL 推算设计保留并沿用。
02

目标与非目标

目标

  • 新增内置站点档案表: 站点 → (adapter, 页面路径, 种子下载路径, 翻页参数名, 域名), 代码写死, 随版本发布; 首发 btschool·nexusphp 与 carpt 两档;
  • 站点级配置整体上收: 新段 config.hr_check.sites.<档案 id>(mode + 微调项), trackers.<站点> 下 hr_check 键废除——「站点」分区的配置模式与 UI 一并移除;
  • 「HR 在线核实」分区成为唯一入口: 总开关 / 频控 / 取数通道(现状) + 站点接入卡片(新增)——每张卡 = 一个已支持站点, 点选启用 + 微调, 卡上显示绑定到的站点配置与绑定状态;
  • 绑定自动化: hr_check.sites.<id> 与 trackers 的关联按域名交集自动完成, 用户不填任何引用; 绑不上 / 绑到多个 → validate_config fail-fast;
  • 生产 config.yml 零修改照常工作(红线文件不许动; 旧键兼容接受、语义等价迁移)。

非目标

  • 全局 config.hr_check 其余 17 项(总开关 / 频控 / 通道)口径不变, 仍在原分区原地; 变的只是站点子段的位置;
  • 不新增站点 / 不写新 adapter;
  • 不改 HR 运行链路的数据流 —— SiteHrCheckConfig 模型与 TrackerConfig.hr_check 派生字段保留, service / channel / parse / 锚点路径零感知(见 §3.5)。
03

方案设计

3.1 内置站点档案表(沿 v1)

落在 config 层(src/auto_qb/config/site_presets.py, 纯数据), 不放 hr 包 —— hr/adapters 依赖 config.models, 反向 import 成环(config 是下层; 与 sections.py:59 不复用 EXTENSION_ID_RE 同一先例)。hr 层只读它。

SITE_PRESETS 首发两站(页面事实来自 adapter docstring 的样张核对)

adapternexusphpcarpt

page_path/myhr.php/myhr.php

每条档案 = SiteHrPreset dataclass; scope 参数 / 表头名 / 列名等页面事实仍由 adapter 类自带(档案只存 adapter 名, 不重复存), 衔接仍走现有 build_adapter。

3.2 配置面: 站点子段上收为新段 config.hr_check.sites

hr_check:
  enabled: true                 # 总开关(不变)
  channel: { … }                # 取数通道(不变)
  min_torrent_interval: …       # 全局频控默认值(不变)
  sites:                        # ★ 新增: 站点接入, 键 = 内置档案 id
    btschool:
      mode: partial             # off / partial / all —— 点选启用
      hr_page_scopes: [A, B, C] # ┐
      refresh_interval: 12H     # │ 微调项(全有默认, 可不写)
      max_pages_per_refresh: 5  # │
      completed_age_limit: 0    # │
      max_torrents_per_hour:    # ┘ 留空回退全局配额
站点级字段裁决(REV2: 整体搬家, 不是就地瘦身)
字段裁决说明
trackers.<站点>.hr_check(整个键)废除YAML 兼容接受并等价迁移(见 3.4); schema / UI / 文档全部移除
hr_check.sites.<id>.mode上收 · 主开关语义不变(off/partial/all); 键名必须是档案 id(未登记 → 报错 + 已支持清单)
sites.<id>.hr_page_scopes / refresh_interval / max_pages_per_refresh / completed_age_limit / max_torrents_per_hour上收 · 微调默认值与校验原样搬运(scopes 必含 A/B/C、age_limit 0 或 1D~3650D 等)
adapter / hr_page_url / download_path / page_param移出配置档案填充, 任何配置位置都不再接受(v1 旧键例外见 3.4)

mode != off 需要该站有 hr 规则段(要求做种时长等)的既有约束保留, 但校验点随绑定移动: 见 3.3。

3.3 站点 ↔ 配置绑定: 域名交集自动完成

  • 档案 domains 与 trackers.<站点>.domains 有交集 → sites.<id> 绑定到该 tracker; 用户零引用配置(不用填 tracker 名, 不用填域名);
  • 启用(mode != off)但没有任何 tracker 域名命中 → 报错: hr_check.sites.btschool: 已启用但没有站点的 domains 包含 pt.btschool.club —— 请在对应站点的域名里补上该域名;
  • 命中多个 tracker(域名重叠配置) → 报错: 绑定必须唯一, 提示重叠的两个站点名;
  • 绑定的 tracker 无 hr 段 → 报错(原「mode != off 必须配 hr 段」约束的搬家版, 文案同步指向新位置);
  • hr_page_url 推算 = https://{命中的域名}{page_path}: 生产实证可行 —— 现网 BTSchool 的 domains[0] 就是 pt.btschool.club, 与其旧 hr_page_url 主机一致。若某站 web 域与 tracker 域不同, 档案里加 page_domain 覆盖(档案级, 不是用户级, 见 §08)。

3.4 兼容策略(生产 config.yml 零修改)

  • 旧键 trackers.<站点>.hr_check 兼容接受并等价迁移: loader 读到 mode != off → 按域名交集找档案, 命中则视为等价于 hr_check.sites.<id>: {mode: …}(微调项若旧配置里写了也一并搬) —— 现网 BTSchool(mode: partial + hr_page_url)不改一字, 加载结果与现在完全相同;
  • 旧键里的 adapter / hr_page_url / download_path / page_param 四键: 读取后丢弃, 值一律以档案为准 —— 配置里写对写错行为一致, 这正是本次要消灭的易错面;
  • 新旧并存(同站既写了旧键又写了 sites.<id>) → 新位置获胜, 旧键忽略; 校验层无警告通道(errors-only), 迁移语义写进文档与 schema help, 不做运行期告警;
  • 旧键 mode != off 但域名绑不上档案 → 与新位置同口径报错(未支持站点)。

3.5 数据流(改动后; 下游零感知的关键 = 派生字段)

config.yml
  hr_check.sites.<id>: { mode, 微调项… }        ← 新唯一配置源
  trackers.<站点>.hr_check: { … }(旧键, 兼容等价迁移)
    │ loaders(load_config 后处理)
    │   ├─ sites.<id> 校验档案 id + mode/微调项解析
    │   ├─ 域名交集绑定: sites.<id> × trackers → 唯一命中
    │   │    命中 tracker 的 TrackerConfig.hr_check = SiteHrCheckConfig(派生填充)
    │   │    (adapter / hr_page_url / download_path / page_param 来自档案, mode/微调来自配置)
    │   └─ 兼容: 旧键 mode != off → 等价并入 sites.<id> 后走同一绑定
    ▼
config 对象内: 配置真相在 hr_check.sites, trackers.*.hr_check 只是绑定结果视图
    ▼
HrRuntime.site_confs() {tracker_name: tc.hr_check} / _hr_anchors / check_hr_condition /
build_adapter / hr.service / hr.channel —— 零改动(site_confs 的推导点本就在 runtime,
消费的也全是派生字段; 唯一变化是推导的输入从「用户配置」换成「绑定结果」)
为什么不直接让下游读 hr_check.sites: 每种子锚点(qbmanager._hr_anchors)与判定链路都经 rec.tracker_conf 定位站点 —— 保留派生字段意味着「配置搬家」对十几处消费点完全透明, 改动面收敛在 loader / validation / schema / UI 四处, 也天然继承现有 mode != off 需 hr 段的防线位置。

fail-fast 时机: 校验器(validate_config)看不到 loader 产物, 绑定类报错(绑不上 / 绑多个 / 缺 hr 段)在校验层独立做一遍(直接读 yaml spec + domains, 不依赖 loader), loader 不报错只填值 —— 与现有「合法性唯一入口是 validate_config」口径一致。

Web UI 改动

「HR 在线核实」分区(唯一入口, 新增站点接入块)

  • 分区尾部(站点状态块之前)新增「站点接入」块: 数据源 = schema.constants.hr_check_site_presets, 每个档案一张卡片;

  • TRACKER_FIELDS 删 hr_check 后, 站点编辑器表单自动不再渲染该块(schema 数据驱动, config_editor.js cfgTrackerItems() 无硬编码字段清单, 已核对);

  • config_hub.js HUB_SECTIONS.hr_check desc/lede 更新: 「启用方式: 本分区站点接入卡片点选; 页面地址/解析器等由内置站点档案自动处理」; 站点分区 lede 里「HR 设置」措辞同步改为「HR 规则」。

08

风险与开放问题

  • web 域 ≠ tracker 域的站点: URL 取命中的 tracker 域名推算, 若某站 myhr 页不在该域会推错。对策已内建: 档案结构预留 page_domain 可选覆盖(档案级硬编码, 仍不对用户暴露); 首发两站均无此问题(BTSchool 生产实证, CarPT 样张同域)。
  • 绑定随 domains 隐式变化: 用户改某站点 domains 可能悄悄改变 HR 绑定(原配置模式下 hr_check 显式挂在站点下, 无此问题)。缓解: 绑定结果在 HR 分区卡片上可见 + 站点状态页本来就有每站取数现状; 校验期把「绑定变更」静默发生的场景压缩到「改域名」这一件事上。
  • 旧键静默等价迁移: 旧配置里的微调项会原样搬进派生值, 但四个档案键被丢弃 —— 有意为之(消灭易错面), 校验层无警告通道本轮不告警, 文档标注; 若日后要显性化走独立 issue。
