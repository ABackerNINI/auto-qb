§01目标与设计原则

背景与目标

用户提案(2026-11-19): WEBUI 列风格切换 —— (1) 进度条可选常规条或控制台式方块条;(2) 进度条颜色可选跟随进度而非种子状态;(3) 下载/上传速度颜色可根据限速设置变化;(4) 剩余时间/分享率/活动时间/最近活动/可用性等数值列参考同类着色;(5) 文件大小/速度单位颜色可选统一或预设几组不同颜色, 覆盖大小/总大小/已下载/上传/下载等全部 B/MiB[/s] 类单位。

做到什么程度算成: 五个维度各自可从主种子表表头右键菜单切换, 选择立即生效(免刷新、跨标签同步)、随设置备份走; 四皮肤全部呈现一致语义; 默认状态下视觉与现状零差异; 不动 config.yml、不动主循环与状态文件。

设计底线 / 不变量

  • 保守默认: 五维默认值全部 = 现状(依次为「跟随皮肤 / 跟随状态 / 跟随现状 / 关 / 统一」), 用户不选 = 零视觉变化、零行为变化。
  • 零新增令牌: 全部颜色映射走现成令牌; 13 个候选令牌(--indigo/--cyan/--lime/--teal/--pink/--violet/--accent-hi/--fg-muted/--fg/--warn/--error/--green/--blue)已逐皮肤×逐主题核对齐(atlas/console/flux 单 :root; prism 五主题各自提供, tokens.css 仅结构令牌)。
  • 展示偏好不进 config.yml: 沿既有拍板(D3), 走 localStorage + ui_prefs 登记闸; 配置侧(schema/validate/KNOWN_WEB_KEYS/键面基线)零改动。
  • 判定单点: 一切分档/拆分判定是 shared/format.js 里的纯函数家族, 不散抄; 着色映射是 CSS(皮肤令牌), JS 只产档位类名, 不产颜色值。
  • 四皮肤同轮补齐: 新类名四皮肤全部有对应规则(挂件类名→CSS 配对闸); 四皮肤逐字节相同的规则族进 shared/console_hub.css 尾段单点(共用规则族纪律), 真差异留皮肤内。
  • 纯前端展示面: 不触碰主循环/任务队列/state_file/黄金法则 1–6 的任何假设; 不触碰 config.yml 与 auto-qb-data/ 红线。

§02现状与痛点

进度条

  • 纯 CSS div(span.bar + i 填充), 无 canvas; 骨架同一份四行模型复用(shared/tpl/xtpl-cells.html :58-61 组行 / :178-181 种子行 / :277-280 集行 / :339-341 对端变体)。
  • 条色 = var(--st, var(--accent)), --st 由行状态类注入(k-seeding→绿 / k-downloading→蓝 / k-checking→warn / k-moving→violet / k-error→error; prism css/components.css:180-186, atlas views.css:192-198, console components.css:142-148 / flux components.css:143-149); 常规条填充兜底 var(--st, var(--accent)) 仅 atlas/prism, console/flux 的 LED 填充兜底为 var(--st, var(--green))(console components.css:425); 百分比文字另按状态着色。用户无法选「跟随进度」。
  • console/flux 皮肤已是 LED 分段条(repeating-linear-gradient, console components.css:424-425), atlas/prism 只有常规条 —— 方块条无法跨皮肤选择。
  • 已知坑档: 数值盒 min-width: 4em 定宽解耦条长(pitfalls/web-ui/progress-bar.md, 守阵 _scan_progress_val_parity) —— 本计划着色不得破坏该几何。

数值色阶与单位

  • 已有 numTone 两档(shared/format.js:165-168): 值/分母 <0.75 → tone-low(fg-muted), 否则 tone-high(accent-hi); 已挂 dlspeed/upspeed(分母 = 全局 qB 限速单点 shared/dialogs.js:555 speedLimitBytes, null=未知/0=不限)、uploaded/downloaded(分母 size)、availability(分母 1)、up_limit/dl_limit。
  • ETA 列无阈值变色(仅 zero 留白); 时间列无着色。ratio/做种时间列已有 HR 伴值着色: hr.js:85-96 hrRatioClass/hrDurClass 挂在主表种子行模型(xtpl-cells.html:209 ratio 格 / :198 做种时间格; 成员行 xtpl.html:286/296 同挂), atlas/css/views.css:56-57 对 .m-pair.pending/.reached 有真实文字着色 —— 本计划的 D10 语义类不覆盖该 HR 口径(共存规则见 D10/S4)。
  • 大小/速度格式化为单一文本节点(「123.45 MiB」不拆数值/单位, xtpl-cells.html:160 等), 单位无法独立着色。格式化单点 shared/format.js(AQB_UNIT_LADDER :13-16, fmtSpeed :35, fmtSize :39, fmtEta :67 哨兵 8640000, fmtRelTime :84)。

皮肤与令牌

  • 四皮肤 atlas/prism/console/flux(目录即 URL); prism 另有五主题(ocean/galaxy/frost/golden/orbit, html[data-theme])。
  • 令牌名集 parity 硬闸: tests/test_webui_static_skins_skin.py:393(prism 侧取 tokens.css+base.css+themes/* 并集)。

偏好链先例(本引擎照抄的范式)

  • 时间列口径: 常量+load 单点 shared/app.js:421-434(autoqb_timefmt_v1) → state 注入 shared/state.js:96 → 菜单写链 shared/menu.js:74-88(Vue 响应式赋值 + localStorage + toast) → 跨标签 storage 监听 shared/lifecycle.js:321-327(adoptTimeFmt 整份采用)。
  • ui_prefs 登记闸: 任何 autoqb.* 键必须登记 shared/ui_prefs.js:29-80 PREF_KEYS/PREF_EXCLUDED 之一, 否则 tests/test_webui_static_ui_prefs.py 红。
  • rowlang 引擎先例: html[data-*] + 纯 CSS + 首帧同步 + 事件派发, 不进 Vue 状态 —— 本引擎取其「顶层属性派生 CSS」思路, 但开关值同时进 Vue 响应式(渲染器分支需要, timeFmt 同款)。

表头右键菜单(入口落点)

  • 绑定在表壳 <aq-table> 模板逐列 @contextmenu.prevent.stop(shared/tpl/xtpl.html:219), 处理函数 openHeadMenu(shared/menu.js:20-34); 菜单 DOM 是手写 Vue 模板块(shared/tpl/ctx-menus.html:88-121), 现有 4 个功能组(最多 6 个菜单项): 隐藏列 / 排序直达(按列降序/升序两项) / 时间口径(相对/绝对两项, 带 ctx-tick 勾) / 列选择器入口。无按表 allowlist —— 门控都在项级, 新增维度项须加 headMenu.page === 'torrent' 判定。
  • 二级 flyout 机制只有行菜单有(ctx-menus.html:54-69 + menu.js:294-402 openSub 族); 钳位锚死行菜单容器(menu.js:342-343 $refs.ctxMenu) —— 复用需把 host ref 参数化。
  • 容器共用 .ctx-menu(z100, 高于 .aq-tip z90); HR 全屏模态开着时挂 above-full-modal→z135。
  • 既有守阵: test_webui_static_skins_table.py:1089-1103(钉 headMenuSort 方法体)、test_webui_static_dom_panel_dialogs.py:961(菜单状态↔容器 ref 对 + watcher)、test_webui_static_dom_panel_misc.py:435(模板注释锚)、_scan_ctx_sub_width(子面板 min-width 260 互证); e2e 六个右键隐藏列用例按 .ctx-item 文本定位。

§03方案总览

主线

新建「列风格引擎」(timeFmt/rowlang 杂交范式): localStorage 单键 autoqb.colstyle.v1 存五维选择 → 启动注入 Vue 响应式 state + 同步写 <html> 五枚 data-cs-* 属性 → 渲染器按响应式状态产档位类名(纯函数单点), CSS 按 data-cs-* 属性派生选择器做颜色/形状映射(令牌) → 菜单写入即改 state+属性, 全链免刷新。

色板方块是本文档内的谱表示意(取各皮肤令牌的代表性观感), 不是规范色值 —— 规范只认「档位→令牌名」映射(§04 S3/S4 落表); 同一令牌名在四皮肤/五主题取值各自不同, parity 由令牌闸保证。

固定端点: 进度 0% 恒 --fg-muted(条为空, 文字灰); 速度分母 0(不限)/null(未知) 恒不着色; 速度 0 本就空白显示(fmtSpeedOrDash), 无色调。分档边界左开右闭((0,20%] 为第一档, 20% 归第一档)。选任一谱 = 启用 20% 分档(分档结构固定, 谱只决定颜色); 温度谱是「热度计」语义(进度 100% 也染红), 用户显式选择自担。

§04实施步骤

S1 引擎与存储

  • shared/app.js: 常量 COLSTYLE_STORE_KEY = "autoqb.colstyle.v1" + COLSTYLE_DEFAULTS(五维默认值)+ loadColStyle()(范式抄 timeFmt :421-434; 容错: 解析失败/字段缺失逐字段回落默认)。
  • shared/state.js: data.colStyle 注入(范式抄 timeFmt :96); 首帧同步: load 先于首渲染(theme/timeFmt 同款, 无 FOUC)。
  • 引擎同步单点(新函数, 建议放 shared/ui_prefs.js 或独立 shared/colstyle.js): state↔<html> 五枚 data-cs-barstyle/-barramp/-speedramp/-numeric/-units 属性双向同步, watch colStyle 派发; 变更免刷新即时生效。
  • shared/lifecycle.js: storage 监听跨标签同步(范式抄 adoptTimeFmt :321-327, 整份采用幂等)。
  • shared/ui_prefs.js: autoqb.colstyle.v1 登记 PREF_KEYS(进备份 bundle)。
  • 验收: 切换写键→即时生效→跨标签同步; PREF 登记闸绿; 首帧无闪烁(theme 先例同判据)。

S2 表头菜单面

  • shared/tpl/ctx-menus.html: 表头菜单块尾部(「显示/隐藏列…」后)加分隔线 + 5 维度项(v-if="headMenu.page === 'torrent'")+ 各维度 .ctx-sub flyout(骨架平移行菜单 :54-69)+ ctx-tick 勾选态 + 色样 DOM。注意六格色带/样例字全部用令牌 class, 不内联色值。
  • shared/menu.js: openSub 族钳位锚参数化(:342-343 $refs.ctxMenu → host ref 参数, 行菜单调用点传旧值零行为变化); 新增 headMenuStyle<Dim>(value) 写链(范式抄 headMenuTimeFmt :74-88: 写 colStyle + localStorage + 保持菜单开)。
  • shared/state.js: flyout 次级状态只两层, 复用 subMenu/subFlip/subTop, 不加第三层(D12)+ 收起链接线(:220-225/:701); headMenu watcher :721 已含钳位。
  • 四皮肤 css/components.css: 色样类规则; 逐字节相同族进 shared/console_hub.css 尾段。四皮肤色样配对的机械保障归 S6 新增「模板类→CSS」守阵(既有挂件闸 _scan_page_class_wiring 只扫 <main> 标签上的挂件类 —— 实际命中 shared/tpl/settings.html 等页壳, 四皮肤 index.html 无 <main> —— 覆盖不到 ctx-menus.html/xtpl-cells.html 片段模板新类)。
  • 验收: 菜单开合/钳位/勾选/写入; 非 torrent 页(抽屉变体/HR 表)不出现新项; 既有 6 个右键 e2e 不红; 静态守阵(headMenuSort 钉/refs↔watcher 对/模板锚/_scan_ctx_sub_width)绿。

S3 进度条两维

  • 样式维(纯 CSS): html[data-cs-barstyle="led"] 下 .m-progress .bar > i 换 LED 分段底(repeating-linear-gradient 移植, 段数/几何照 console 现行); "plain" 强制常规; 缺省/「跟随皮肤」不出规则(皮肤默认呈现)。共用族进 shared 单点, 皮肤差异段留皮肤内。
  • 颜色维: 渲染器(行模型单点)按 progPct 产档位类 csb-0..csb-5(0=空端点, 1..5=五档, 100%→csb-t); 类名只表档位, 颜色由 html[data-cs-barramp="<谱>"] .m-progress .bar > i.csb-2 { ... } 派生映射(谱×档 = 4×7 条规则, 共用族单点)。「跟随状态」不出档位映射规则(现状 --st 链不动)。条与百分比文字同色; 组行同口径(同一模板骨架)。
  • 分档判定纯函数(format.js 新增, 如 progBand(p))单点, node 电池钉边界(20% 左开右闭/端点)。
  • 验收: e2e 真浏览器计算色断言(state-moving.spec 先例逐通道比对); _scan_progress_val_parity 不回归(数值盒定宽几何不动); LED 形态在 atlas/prism 可选且 console/flux 默认不变。

S4 速度色阶与数值列色阶

  • 速度: 渲染器分档判定(speedBand(bytes, limit), 分母读 speedLimitBytes 单点 dialogs.js:555; limit 0/null → 无类; bytes=0 → 无类本就空白; >1.0 → over 档)产 csp-1..csp-5/csp-over; 「跟随现状」保留 numTone 类链不动, 「关」由 data-cs-speedramp 关闭映射。谱映射 CSS 同 S3 模式。
