01 目标与边界

1.1 用户裁定与目标函数

本计划的目标函数继承审计报告 §2 的 G1–G3，并由用户 26-10-12 的最新裁定补全第④条前置：

① 所有表格统一：每一个数据列表表面都具备主表四件套（拖宽 / 排序 / 右键隐藏 / 列偏好持久化）；

② 交互逻辑类似：同一套手势语言与实现单点——行为同源，不要求观感相同；

③ 减少维护点：交互逻辑实现份数下降且可数；新增一个表格表面 = 注册一行描述符 + 一个行模型渲染器；

④ 「不考虑兼容」= 旧表格全部重写（用户 26-10-12 澄清，取代审计中悬而未决的 fork）：变体的表格体重写为引擎消费面，不再保留手搓实现，也不需要为旧表格行为做兼容过渡。

与 W7 裁定的边界划分：W7 的「模板原样找回」约束在本轮只对表格体解除——变体的版式外壳（卡片布局 / 分组结构 / 树形缩进 / 批量操作条 / 吸顶行为等非表格部分）维持 W7 恢复形态，一行不改；被重写并接引擎的只有 8 个列表变体中的表格体。这样「模板能力保留」（变体仍存在、仍可选）与「表格统一」（能力同源）两个已定裁定同时成立，互不侵犯。

03 目标架构

3.1 总图：引擎唯一，表格体重写，外壳不动

变体的渲染分层重划——外壳层（字符串 DOM，W7 资产，不动）与表格体层（Vue 组件，本轮重写，消费引擎）：

层形态归属本轮动作
变体外壳（头部/卡片/分组/树架/批量条）字符串 DOM（dtHtml + 插件挂载机械）drawer_tpl/*.js不动（仅删其中的表格体拼装代码与列宽 CSS 注入）
变体表格体（列表区）Vue 组件（表壳 + 行模型渲染器）tpl/xtpl-cells.html 体系重写：每变体注册一行描述符 + 复用/新增行渲染器
交互引擎（拖宽/排序/隐藏/偏好/对齐）Vue 根实例单点columns.js + sort.js不动（仅 U1 三件泛化扩展）
桥（外壳内的表格体挂载点）Teleport 锚（D1=M1 推荐）drawer.html + 挂载机械新建（U1 spike 验证）

3.1.1 桥的三种候选（拍板点 D1）

M1 · Teleport 锚（推荐）：变体字符串 DOM 在表格区输出一个空锚（如 <div data-dt-table-anchor="peer">，由 dtHtml 拼进外壳）；drawer.html 在变体分支内用 <Teleport :to> 把表格体组件（aq-table 表壳 + 行渲染器）渲染进锚内。Teleport 目标的存在性由一个响应式标志控制（挂载机械 _dtRender 完成后置位），时序风险见 R2。优点：单一 Vue 应用、引擎零感知外壳、外壳零感知引擎；表格体的列宽/偏好/手势全部走既有单点。缺点：新增一条「字符串 DOM 与 Vue 树共存」的时序路径，需 U1 实测。

M2 · 正文组件化：列表类变体把整个正文区（表格体 + 紧邻的表格级工具条）改为 Vue 组件分支，外壳只留头部。比 M1 多让渡一块版式，少一层桥。备选。

M3 · 变体全 Vue 化：8 个列表变体整体重写为 Vue 组件（drawer_tabs 体系）。重写面最大，且实质上废弃变体外壳资产——与 W7「模板能力保留」裁定冲突，不推荐，仅列作对照。

3.2 描述符注册表（差异的唯一声明处）

沿用 1722 §3.1 / 2106 W2 已定型的模型——每变体一行，进 DRAWER_TABLE_DEFS（与经典三表同注册表、同形状，ALL_TABLE_DEFS 聚合面自动扩大）：

  • id：变体表标识（如 drawerPeerV07）——偏好按 table-id 隔离，与经典表互不串扰（R1）。
  • columns：列定义数组——以 DRAWER_*_COLUMNS 为底做列子集/变体专属列裁剪（数据声明，不算维护点）。
  • rowModel：行模型名——优先复用经典渲染器（peer/tracker/file 已有）；变体专属格（如 07 的仪表盘格、08 的分组头格）新增变体行模型渲染器，每行模型一份（1722 P3「127 条分支」教训：不做同名列跨表合并，只做单份收敛）。
  • features：行为开关（sort/resize/hide/window）——变体数据量为面板级（数十~数百行），window: false；树表 10/11 的排序开关见 D4。
  • defaultSort / hostAnchor：默认排序键 + Teleport 锚选择器。

3.3 必须保持的不变式

  • 双轨列状态铁律：新增表 = 新增 pages 子键，绝不升 COLS_STORE_KEY 版本（pitfalls/web-ui/columns-persist.md）。
  • 单一 Vue 应用：Teleport 是根应用内的传送，不是 createApp 子应用（pitfalls/web-ui/frontend-split.md）。
  • 三皮肤同名类成对：表格体吃引擎对齐 CSS（colAlignCss 按 table-id 注入），变体注入 CSS 中的列宽规则同波删除，三份皮肤同步。
  • 无构建链：新增组件片段走 x-template 分片 + 三份 index.html 清单行（prism 210 行硬顶，见 R5）。
  • 行为同源 ≠ 观感同源：表格体保持各变体的版式个性（列子集、密度、格子样式经渲染器与变体 CSS 表达），手势与状态必须同源（G2 口径，审计已钉）。

06 风险与红线

R1 列偏好被重置（复发陷阱，1722 风险 1 同款）

新增变体表 id = 新增 pages 子键，绝不升 COLS_STORE_KEY 版本——升版本会清空用户手调的宽/隐/序。守阵沿用既有持久化红线。

R2 桥的挂载时序（W7 已付过一次学费）

字符串 DOM 晚于 Vue 渲染：Teleport 目标锚必须等 _dtRender 完成才存在。W7 的 dtMenuPick 同步挂载扑空教训直接适用——标志位翻转 / $nextTick 时机必须覆盖四条路径（初次打开 / 页签切换 / 软切换 / 合并双列），U1 spike 是硬闸门。种子重挂路径（state.js watcher 的 $nextTick 支路）也要过。

R3 守阵计数锚会红（不能删，只能改口径）

W7 恢复的 panel 守阵钉了大量变体断言面（reannounce ④ 三变体、菜单/注册表面、tooltip I 组变体条目），表格体重写会改变计数与锚形态——同轮改版 + 红绿双验，不放宽不删除（1722 风险 2 定式、1722 P5「计数照改 + 补覆盖」先例）。

R4 W7 恢复的 4 条变体 spec 同轮对账

drawer-peers-columns / drawer-peers-sticky-flush / drawer-trackers-reannounce / drawer-content-dt11-sticky 等断言的是旧手搓表格的列宽/交互——重写后逐条改口径为引擎手势，不许静默删除；新增变体表面手势用例（审计 P3 的欠账）。

R5 三皮肤 CSS 成对 + prism 行数硬顶

删列宽规则与新增表壳类规则必须三份皮肤同步（成对守阵盯着）；新增 x-template 分片要三份 index.html 各加一行，prism 贴 210 行上限，加一行先腾一行（pitfalls/web-ui/frontend-split.md）。

R6 观感回归

重写不改版式个性（D5 口径）。表格体 DOM 结构变化可能破坏变体专属 CSS 选择器（如 08 的分组行选择器）——逐变体视觉对账，变体注入 CSS 中仅删列宽/表格布局规则，版式规则保留。

R7 排序语义逐列核对

07/08/09 的手搓比较器各有口径（空值位次 / 进度 / 速度 / 键盘转发），并引擎时逐列核对；语义确实特殊的表可走「借壳不并排序」先例（HR D3=B），但必须记档并在 Q3 对账中单列，不得静默并存两套。

R8 性能：表格体进 Vue patch 路径

变体数据为面板级（数十~数百行），features.window: false；但仍须在 5k 种子桩冒烟确认打开/切换无卡顿（features.window 开关保留为将来大数据表的后路）。

R9 范围守恒

只动表格体。执行中撞见变体外壳、非表变体、主视图、经典链的任何「顺手想改」，一律入池不修（scope-guard 纪律）——2106 的教训就是从范围蠕动开始的。
