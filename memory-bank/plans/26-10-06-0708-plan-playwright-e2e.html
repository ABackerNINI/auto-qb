01结论与拍板点

issue 26-10-06-0458 指出: 真浏览器断言两条轨道并存 —— 旧脚本 scripts/ui_smoke.cjs 背着 105 项断言却拿不到任何框架能力, 新轨 e2e/(2026-10-06 引入)只有 4 项最小集。本计划把旧脚本按断言块分 6 批迁入 e2e/, 配一次基建批(S0)和一次退役批(S7)。核心纪律来自 issue 原文:

  • 一次搬一个断言块, 不整仓重写 —— 每批迁完先与旧脚本对跑、数字对齐, 再删旧块;
  • 同一断言只允许一处定义 —— 迁移期两套并存是脚手架, 不是终态, 双写不过夜(每批收口即删);
  • 存量 flaky 所在块优先搬 —— trace viewer 正是为「追剧集行 Ctrl+click 超时」这类时序故障准备的。

本计划不认领 issue、不动代码; 拍板后由实施会话按步执行, 每批一个独立提交(提交需逐次显式授权)。

默认拍板含义: 四项均按推荐方案执行; 任一项想改, 改的只是对应设计决策(§3)与受影响批次, 批次骨架不变。

03目标终态与设计决策

3.1终态定义(S7 验收口径)

  • scripts/ui_smoke.cjs 删除; 全部 ≈105 处断言由 e2e/ 下按块拆分的 spec 文件承载, 每条断言一处定义;
  • 模式矩阵保留: 双皮肤 × ok|error|hang × skip-check on|off × hr-scene on|empty|off, 通过环境变量驱动、门控 helper 跳过、commands 任务命令化, 不靠人记 env 组合;
  • 「每次改前端」门禁 = @fast 子集(分钟级), 全量矩阵轮在收尾/排障时跑;
  • 知识库与文件头注释中「人工深挖走 ui_smoke.cjs」的表述全部改写(清单见 S7)。

3.2D1 · 模式矩阵: env 参数化(拍板点 P2)

e2e/harness.mjs 的常量段改为「默认值 + env 覆盖」, 桩命令仍单点拼装:

// e2e/harness.mjs (拟改动示意 —— 参数名与 ui_harness.py CLI 一一对应, 已核对)
export const CMD_RESULT = process.env.E2E_CMD_RESULT || 'ok';   // ok | error | hang
export const SKIP_CHECK = process.env.E2E_SKIP_CHECK || 'on';   // on | off
export const HR_SCENE   = process.env.E2E_HR_SCENE   || 'on';   // on | empty | off
export const TORRENTS   = Number(process.env.E2E_TORRENTS || 300);

export const HARNESS_CMD = [
  'uv run python scripts/ui_harness.py', `--torrents ${TORRENTS}`, `--port ${PORT}`,
  CMD_RESULT !== 'ok' ? `--cmd-result ${CMD_RESULT}` : '',
  SKIP_CHECK !== 'on' ? '--skip-check-menu off' : '',
  HR_SCENE   !== 'on' ? `--hr-scene ${HR_SCENE}` : '',
].filter(Boolean).join(' ');

配套两件事: ①e2e/lib/mode.mjs 提供 requireMode(...) 门控 —— 模式不符的 describe 整组 test.skip, 并在 skip 消息里写明当前 env 值(排障一眼看出「为什么没跑」); ②PORT 保持 8137 不动 —— 模式轮是串行人跑, 不是并行实例, 换端口反而破坏「撞残留服务宁可失败」的既有纪律。

3.3D2 · 断言单点与对账协议(拍板点 P3 的执行纪律)

迁移期两套并存仅存在于「一批的内部」。每批严格执行五步(§5 展开): 新 spec 绿 → 旧脚本同参数轮绿 → 对账映射 → 删旧块 → 双复跑。任何一步红即停批, 旧脚本在对应批次收口前始终保有完整断言, 回滚面恒为「一个 commit」。

3.5D4 · 断言翻译守则(全批统一, 防止逐批各自发挥)

  • 交互走真实手势: 旧脚本 page.evaluate 直调 vm 方法(${INST}.hubGo(...) 等)凡有真实 UI 路径的一律换成 locator 手势(getByRole 优先); 仅两类允许保留 evaluate —— 注入/复原桩态(如 hrsHist.badOnly = false)与 vm 内部时序探针, 保留处须注释说明理由。
  • 等待语义升级但不失真: 装饰性 waitForTimeout(600/800) 换成 expect 自动等待 / expect.poll; 但两类 sleep 是断言语义本身, 原样保留 —— 时序窗口(乐观 pending 须存活 2500~6000ms)与「跨一个轮询周期再看错误」。整表每 2s 重渲染抢点击的坑(smoke.md)仍在: 动作类断言沿用落点纪律(行左缘 position:{x:8,y:8})与「断言优先取值」。
  • 阈值数字逐字保留: P1-2/P1-3 预算、2500~6000ms 窗口、轮询分档期望值 —— 这些是回归基准, 不是实现细节。
  • 多页面用例: 每条 test 默认独立 context(localStorage 天然隔离, 比旧脚本单 context 干净); 块 H 的多标签/多视口在 test 内 context.newPage() + setViewportSize, 顺序依赖的组用 test.describe.serial 显式声明。
  • 颜色/样式断言: 沿用「读 :root 自定义属性而非 computed 背景」的 Dark Reader 纪律(smoke.md), 由 lib 统一提供取色 helper。

3.6D5 · 最小门禁 @fast(拍板点 P4)

S1 起在 spec 内用 test(...) 名称加 @fast 标记(或 Playwright tag 语法), package.json 增 "test:e2e:fast": "playwright test --grep @fast", commands task dev.e2e 的 note 改指 fast 子集为日常门禁。现 smoke.spec.mjs 的 4 项在 S1 收口时并入 views.spec 并删壳文件 —— 渲染健康断言从此单点。

5.1每批五步对账(数字对齐的可执行定义)

  1. 新 spec 绿: 本批 spec 双皮肤跑绿(涉及模式的批加对应模式轮);
  2. 旧脚本同参数轮绿: 常驻后台起桩(run_in_background + 新端口, smoke.md「桩没起来/旧进程」三条判据防误判), node scripts/ui_smoke.cjs --base … --torrents 300 --ui both 同参数绿;
  3. 对账映射: 旧块 add() 调用点数 vs 新 test 数写进 spec 头注释映射表 —— 允许 1:N(合并/拆分), 但每个旧断言名必须能找到去向下落;
  4. 删旧块: 同一 commit 内删除旧块(单点纪律的物理保证);
  5. 双复跑: 旧脚本复跑确认总数下降且零残余失败, 新 spec 复跑绿。
