01现状盘点：混杂在哪

包内共 82 个 .py（含 __init__/__main__）+ 前端资产 35 个文件 ≈ 1.29 MB。 config / rules / torrents 三个域包结构清晰，问题集中在两处：表现层 Python 代码散布，与根目录平铺。

混杂点一：WEB 表现层散布在 5 处

#现状位置体量（实测）内容性质
1ui.py（根目录）≈530 行 / 22.7 KB托盘常驻 UI（CustomTkinter + pystray + 单实例 IPC）桌面表现层
2web_runtime.py（根目录）≈605 行 / 33.2 KBWEB 表现层门面 WebUIRuntime（视图快照/命令队列/节拍判据）WEB 表现层

02目标与非目标

目标

  • 一眼分清前后端：WEB 全家（路由 + 运行时 + 视图构建 + 命令处理 + 静态前端）住进 webui/；桌面托盘住进 tray/；与 core/ 同级并列。
  • 根目录语义分层：17 个平铺 .py → 1 个（cli）；入口 / 配置 / 核心域 / 基础设施 / 表现层五类各归其位。
  • 为后续加层留位：新增表现层（如 TUI、插件宿主）= 顶层新建一个同级包，不再往核心域里塞（落位规则见 §04）。
  • mixin 包语义归正：mixins/ 只剩真正的核心域切片（6 个），表现层切片迁出。
  • 零行为变更：57 个 API 端点、静态 URL（/atlas/ /prism/）、日志命名空间、线程模型全部不变。

非目标

  • 不动 config/ rules/ torrents/ 三个域包的内部结构 —— 它们已经是好的；是否收进 core/ 属后置另案（§09）。
  • 不动 tests/ 44 文件平铺 —— 另立主题，避免一次改动混两类语义。
  • 不动 mixins/ 剩余 6 个核心 mixin 的拆分方式（God Object 治理另案）。
  • 不下线 atlas 旧 UI、不借机改任何实现细节。
