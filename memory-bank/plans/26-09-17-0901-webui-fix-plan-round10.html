2.2结构性缺陷两条

① 列偏好"升版本即清空 + 绑定 origin" (R10-09)

两个独立机制叠加成"时不时重置"的体感:

  • origin 隔离: localStorage 按 scheme://host:port 分区。用 127.0.0.1:8080 看过、 又用 localhost:8080 打开一次, 就是两套偏好; 换端口/换机器更彻底。
  • 版本升级 = 清空: 每次为新列升 COLS_STORE_KEY, 用户此前手调的列宽、隐藏列、列序全部归零 —— 这是"前几轮升级后感觉被重置"的机制性来源(第九轮只加列、未升版本, 所以当时没触发)。

结论: ① 偏好改存服务端(见 §04.7), 浏览器存储降级为"首屏快速渲染缓存"; ② 载入时做跨版本迁移(旧键 → 新键, 按列 key 求交集合并), 升版本不再清空用户偏好。

04

关键设计细节

4.1状态栏取数与单位(R10-04 前半)

单一取数点输出 bytes/s(与 fmtSpeed 同源): server_state.dl_rate_limit / up_rate_limit;0 = 不限速(显示"不限"), 缺失 = "—"(区分"未知"与"不限")。 状态栏文案、速度染色分母、悬浮说明三处引用它。浮层内的编辑仍走 /api/speed/mode(KiB/s), 两套单位只在各自的显示层换算 —— 不在同一函数里混用(这是本轮唯一容易写错的地方)。

4.2状态栏配色与信息密度(R10-02/03/05)

新增状态栏专用底色令牌(五主题各一值, 与页底形成可见层级, 但不与顶栏冲突); 去文字标签后保留图标 + 数值, 语义靠 title 悬浮补全, 且"不限速"保持弱化态; 历史按钮并入今日流量块, 去掉该块右边框, 只留图标间距 —— 结构上成为子元素后, "隔断"自然消失。

4.3对齐口径进列模型(R10-08)

给列定义加 align(left / right / center), 表头与单元格共用同一来源: 模板输出 c-align-{align}, CSS 只保留三条通用规则(不再维护 .hc-* 硬编码名单)。 按用户清单逐一确认: 文本/时间/哈希类 = 左(含添加于 / 做种时长 / 最近活动三列, 本轮由右改左), 数值/大小/速度/比率 = 右, 计数类保持既有居中口径不变。

4.4状态色与选中色(R10-06/07)

状态色覆盖面扩到文本型格子, 但只染文字(不铺底), 零值/"—"不染(既有规则延续); 芯片类(站点/标签/分类)是否一并跟随行状态色见 D6 —— 它们自身已表达成员级语义, 强行覆盖会丢信息。 选中态改为独立令牌族(底色 + 描边 + 左色条), 五主题统一给非绿值, 与"做种中"的绿族彻底分开。

4.5UI 偏好服务端化(R10-09)

数据结构沿用现有形态({widths, hidden, manual, order}, 按 page 分组), 落到服务端单点存储; 前端载入顺序 = 服务端值 → 浏览器缓存兜底(首屏不闪); 变更时节流上报(拖列宽不必每次 mousemove 都发请求)。 同时补 跨版本迁移: 读旧键按列 key 求交集合并, 升版本不再清空用户偏好。 落盘通道走主循环(单一写线程), 崩溃丢失窗口需在决策点 D3 明确是否可接受。

4.6打开目标文件夹(R10-10)

语义改为: 路径是目录 → 直接打开; 路径是文件 → 打开其所在目录并定位选中该文件 (Windows 走"选中"参数, macOS 走"reveal", Linux 退化为打开父目录)。 仍坚持"路径由服务端从自身快照派生"的红线 —— 不接受客户端传路径。

4.7路径选择能力与安全边界(R10-11)

新增端点只提供目录浏览: 给定起点列出子目录、支持上溯、支持新建文件夹, 返回绝对路径。 安全边界(必须写进实现): ① 路径规范化后必须落在允许的根集合内(已配置保存路径 / 用户显式授权根), 越界一律 403; ② 只列目录不读文件内容; ③ 仅鉴权通过(或本机免鉴权)可用; ④ 拒绝 .. 穿越与符号链接逃逸。 这条是本轮唯一新增的服务端文件系统读能力, 也是唯一需要专项安全用例的改动。

4.8弹窗尺寸与长文本三件套(R10-12/13)

尺寸令牌族: 窄(确认/输入框) · 标准(表单/统计) · 宽(删除确认/添加种子) · 超宽(历史流量), 两套 UI 共用同一组值, 抽屉宽度一并纳入。长文本统一口径: 单行省略 + title 全文 + 复制按钮; URL/hash/路径这类不可断行的值走"宽行 + 复制", 不再无限换行顶高窗口。

4.9鉴权模式显式化(R10-01)

把"是否有身份"从"是否有密钥串"里拆出来: 免鉴权 = 直接进主界面 + 不发 Authorization 头; 密钥模式 = 原流程不变。三条守卫(api / 轮询续排 / 标签页可见性)统一按模式判断, 避免"改两处漏一处"导致轮询静默停摆。

4.10删除详情行统一派生(R10-16)

四个入口只交目标集合(keys / hashes / 文案上下文), 详情行由统一函数派生: 目标名 → 计数 → 站点集合 → 保存路径集合 → 总大小; 单目标退化为逐项明细, 多目标给"集合 + 计数"。 这样四个入口看到的窗口结构完全一致, 差异只剩标题与文案 —— 正是用户要的"同一个删除窗口"。

  • 单一写线程: UI 偏好落盘走命令队列(主循环消费), Web 线程不直接写状态文件; 新增端点保持"只读快照 + 投递命令"的既有形态。
  • 前端契约(views.css 头注 + pitfalls 已列): .sticky-head/--head-h、--statusbar-h、 .group-head/.detail-head、gridStyle 列模板、.ctx-menu、sprite #i-* 单点、 toast/确认框单例 —— 一律保留, 新功能以"新增类/新增令牌"接入。
  • 列状态存储版本: 本轮会动列模型(新增 align)与尺寸令牌 —— align 属渲染属性(不影响存储结构), 不需要升 COLS_STORE_KEY; 若最终仍要升, 必须同时实现旧键迁移(否则重演"升版本即清空")。
  • CSS 结构守阵: "漏 ; } 导致其后规则被整段丢弃"与"<transition> 吞弹窗"是已入 pitfalls 的真实故障形态 ⇒ 每次改完先跑 test_frontend_static_bundle_health, 不做批量收尾式修改。
  • 鉴权改动是状态机改动: R10-01 会碰 api() 与两处轮询守卫, 必须一次改完并实测三条路径 (本机免鉴权 / 有效密钥 / 错误密钥), 半途状态最容易出"能进但轮询静默停摆"这种难查的问题。
  • 不做的事: 不引构建链 / 不引新依赖 / 不引图标库; 不加行入场动画与数字滚动(pitfalls 明文: 2s 整表重渲染会反复播放); 动效仍尊重 prefers-reduced-motion。
  • 两套 UI 同构纪律: 星图与棱镜的模板改动必须成对; 本轮状态栏 4 项、弹窗 2 项、菜单 1 项、抽屉 1 项都要过两遍。
