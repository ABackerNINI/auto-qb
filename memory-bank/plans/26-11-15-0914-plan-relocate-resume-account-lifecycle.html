§01目标与设计原则

背景。relocate 恢复确认机制(952d3daa, P2a)落地后的批次评审产出五份计划外 issue, 全部挂在两根轴上: 账的生命周期轴(账 = job 对象生命周期, 而 job_id 跨生命周期复用、已删成员无闭账出口)与消费面轴(浮窗入口、计数器读面)。五件同根, 联合立项一次修完。

目标(算成标准)。① 0344: 同 (mover,src,dst) 终态重发时旧账余量结转进新账, 覆盖不再丢账, 结转成员按新生命周期重获补发预算; ② 0345-deleted: 已删成员有闭账出口(连续 N 拍确认真删除), 账面与 webui 不再永久挂账; ③ 0345-popover: done/cancelled 终态且有余量的行浮窗可弹, 与抽屉入口一致; ④ 0345-feat: 两个失败计数器有读面(停机摘要一行); ⑤ refactor 便签: 维持现状, 跨层私有借用不扩面; ⑥ 全量测试绿入新基线切片。

设计底线/不变量。

  • 闭账保守原则只放宽给「确认真删除」: _member_stopped docstring 的「宁挂账勿漏恢复」(防快照空窗误关账)原意保留——判据从二态(停/没停)扩三态(停/没停/连续 N 拍确认删除), 空窗不误闭。
  • pending ⊆ resume_hashes 不变式保持(relocate_lifecycle.py:193 注释先例); 闭账双面同删, 不破坏并集语义。
  • 展示边界不动: RELOCATE_TONE 行内口径与「不出已完成结论」边界一条不动(D11); 账机制与展示边界的合流缺口只修浮窗入口, 不动行内结论。
  • 黄金法则面: 结转与闭账全部发生在主循环 task_line 单线程内(法则 5, 无新并发); 幂等(法则 1——streak pop + 账移除收敛, 重复拍无副作用); 零新配置键(法则 4 面, D9 走常量); 保守默认(法则 2——闭账是保守闸的收窄噪音方向, 不新增任何高风险动作)。
  • 边界: 不新增搬迁发起入口; 不动 register_job 遗留 API 本身(生产零调用, 只在 S0 复验时修正 issue 锚点, D14); 不建 attempts 分母(D13)。

§02现状与痛点

机制底盘(取证于 e2825b4b)。恢复确认账是 job 级三字段(frozen dataclass, relocate_units.py:320/327/328): resume_hashes(发起时被暂停成员名单)/resume_pending(仍未确认回运行态的余量)为 Tuple, resume_retries 是 job 级 int, 非按成员。穷尽上界 _RESUME_RETRY_MAX = 3(relocate_lifecycle.py:26)。对账 _reconcile_resume_pending(lifecycle:276-318)每 main_tick(默认 2s)一拍(on_task_line 尾部 :457), 扫全部 job 含终态(:293-296); 唯一闭账出口 = pending 全员回非 stopped(:297-303 清账 INFO); 穷尽后不再补发、只收敛账面并每开账回合一笔告警(:306-316, _resume_exhausted_warned 去重)。四个终态出口(failed :327-328 / cancelled exec:1798-1801 / done-direct exec:603-604 / done-alias exec:1211-1215)都不清账——账随 job 挂账, 经 _note_resume_state 持久化进 state.json(units:325), 跨重启存活。

痛点五件(带行号证据)。

  • 0344 结转缺失: job_id 由 mover|src|dst 派生(units:1119-1128, docstring 自述幂等), 终态重发同组落同一 id。真覆盖点是 _start_job 的裸赋值 exec:1583(issue §02 原锚 register_job 生产零调用, 属遗留 API, 已改判 D14); 覆盖前旧对象只被读两处(:1456 终态检查 / :1430 读 prev.tag_on), _carry_prev_tag_state(exec:1422-1435)只继承 tag_on 一位——resume 账不读不继承, 覆盖即静默丢弃。
  • 0345-deleted 永不闭合: _member_stopped(lifecycle:228-238)对不在 store 的成员恒判「停着」(docstring 自述保守防快照空窗误关账)→ 已删成员的 pending 永不满足闭合条件, 穷尽后永久挂账; resume_hashes 同面不清理; webui 待恢复成员/哈希两行如实显示已删哈希(drawer_rows.js:148-151)。
  • 0345-popover 入口缺失: 浮窗触发 = relocateView(row) 非 null(relocate_pop.js:44), 而 relocateView 对 done/cancelled 恒 null(decorate.js:51 RELOCATE_TONE 无此二态, 注释自述「行内回落单排正常色」); 内容组装 assembleRelPop(pop.js:119-158)if (!view) return null 双保险无旁路——账在弹不出。抽屉无此边界(只看 relocateResumeText 非空), 终态照常可见。
  • 0345-feat 零读面: _tag_failures/_resume_failures(relocate_mod.py:74/:80 初始化, lifecycle:174/:254/:312/:380 累加)——写点之外全仓无读取/持久化/快照/webui 消费面, 重启清空; 逐次失败已有 WARNING(:174/:254/:312), 缺的是终身总量对账入口。
  • refactor 便签: views_relocate.py:14 跨层借 lifecycle:26 私有常数(注释钉契约 + 测试兜底), 单一消费方, 现状可接受。

邻接观察(不在本批): _member_stopped 判 state_enum.is_stopped, qB moving 态非 stopped——成员处于 moving 会被 reconcile 视为「已恢复」闭合账。语义说得通(非暂停), 只记不动。
