## 思考过程与决策

- **修法定位**(代码事实): 原因 = `.kb-row-label { flex: 1 1 200px }` 吃满剩余空间把键帽+按钮组推到行右端; 同族松排(ctx-custom-row/tr-tgt-row)存在但容器窄、症状轻, 用户拍板不动不入池(范围守恒)。
- **D1 机制**: 键帽列要「跟最宽行」⇒ 逐行独立容器做不到跨行取最宽 ⇒ 单一 grid + `.kb-grp`/`.kb-row` `display: contents` 展平; 每分组一张 display:table 的方案因组间不对齐被否。
- **D2 副作用拍板**: 录制提示/冲突条各占整行; 虚线分隔与录制高亮移到三单元格(列 gap 归 0 用 padding 拉开防断缝)。
- **D3 防抖**: 键帽列 `minmax(220px, auto)` —— 底线之内列宽不随数据变化, 超出才跟最宽键帽, 键帽 nowrap。
- **D4 限宽**: `.hr-full-modal.kb-full { max-width: 1120px }` kb 专属 modifier, 骨架不动(HR 站点状态覆盖层同吃骨架, 零波及); 皮肤层无 `.kb-row` 覆盖已核实。
- **D5 数字定案**: 名称 420 / 键帽底线 220 / 限宽 1120(验证模板可调滑杆目检后用户拍板); 列表整体居中, 视口放不下横向滚动兜底(目标屏 1920×1080)。
- **无计划文档**: 方案在会话里 grilling 收敛, 未走 plans/ (小任务, 阈值外)。

## 实现计划

1. 模板: section 加 `kb-full` 类; v-for 分组包 `.kb-table` 包裹 div(说明段/加载失败段留网格外)。
2. CSS: `.kb-table` grid 三列 + 居中 + 滚动兜底; 展平与单元格化; `.hr-full-modal.kb-full` 限宽; `.kb-danger` nowrap。
3. 守阵: 类名断言同步 + 新增 CSS 锚。
4. 验证: test.full + 只读评审 + 实机截图目检。
