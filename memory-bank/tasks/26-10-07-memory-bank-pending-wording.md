## 思考过程与决策

- **根因定性(不是流程疏忽)**: `commit` 的 hash 由 tree + parent + author/committer + 时间戳共同决定 ——
  想把它写进文件就改变了 tree, hash 随之变化, 循环无解 ⇒ **一个提交永远无法包含自己的 hash**。
  而收尾 DoD 要求回写件**随主提交一并暂存**(AGENTS.md 提交节) ⇒ 回写必然写在这个 hash 逻辑上
  尚不存在的时点。所以 `待提交` 是约束下的必然产物, 不是谁忘了改。
- **现有兜底已实证失败**: 2026-09-27 审计(`reports/26-09-27-1547`)记着「切片停在『`等待提交`』而提交
  实际已完成 —— 切片与计划 meta 双陈旧」。且与既有坑档 `pitfalls/kb/commit-hash-refs.md` 的原则
  (「写入时优选**会存活的引用**」)自相矛盾: 回写里写一个**尚不存在**的 hash, 是同一问题的更早版本。
- **解法空间与排除**: ①时不变措辞(改口径, 零成本) ②哨兵 + 自动回填**第二笔提交**(可行但每次多一笔;
  ❌不能靠 amend 回填 —— amend 改 hash, 回填值立刻又过期, 且已推送禁 amend) ③带外账本(实测"半存在":
  `.workbuddy-ai/memory/` 已在记 `提交成功 <hash>`, 但它 **gitignored + 每 clone 一份 + 助手手写无机检**,
  不能当可托付的账本 of record; 真正的持久账本是 git 自己 —— 提交消息 + `git log --grep <专题键>`,
  rebase 改 hash 但**消息文本保留**) ④❌「先算 hash 再写」不可行(依赖自身内容与时间戳)。
  拍板 ① 为主。
- **守卫判据的三次收敛(关键设计决策)**:
  - **不能一刀切禁 `未提交`**: 基线切片里 76 处 `未提交改动` / `未提交的工作树` 是**树态描述**
    (说明"这条基线测在哪棵树上"), 是解释数字差异的必需元数据(例: `26-10-06-0547` 用它解释 passed
    对不齐) —— 删它是毁证据。判据改为「`未提交` 作**状态标记**」+ 树态名词短语豁免。
  - **带日期的流水条目豁免**: 日期条目**自带时点**, 不会过期; 改写它是篡改日志(如「2026-10-05 批 3
    落地(改动留工作区`待提交`)」当时确为真)。故扫描只判**无日期前缀的行** —— 用户拍板选此档
    (现状 88 处判红 / 38 处豁免; 备选"全量清"会抹掉历史事实, 未采纳)。
  - **`testing/baselines/` 不入扫描面**: 它是**出厂即冻结的测量快照**, 其 `未提交` 描述测量时树态、
    不随提交更新, 本缺陷形态在那里不成立(该目录有 91 处 `未提交`, 全为树态元数据)。
- **⚠ 守卫首版有真 bug(自查抓到)**: 粗体判据写成 `\*\*[^*\n]*未\s*(?:提交|commit|入库)[^*\n]*\*\*`
  —— `[^*]` 会从**上一个粗体的收尾**横跨到**下一个粗体的开头**(中间恰好无 `*`), 把普通行文里的
  「未入库」误判成状态标记(实测 `26-09-21-webui-filter-data-and-color-flicker.md:19` 误报)。
  改为「先按 `\*\*([^*\n]+)\*\*` 取**配对好的粗体段**, 再判段内容」。**回归证据**: 误报行修复后零命中。
- **⚠ 清洗脚本踩到已记的坑**: `Path.write_text(...)` 吃 `newline=None` 默认值, Windows 上按
  `os.linesep` 把 LF 翻成 CRLF ⇒ 64 个文件整份变 `w/crlf`(`.gitattributes` 归一化下 `git diff` 只显示
  改动行, 肉眼不可见; 是 `git` 的 "CRLF will be replaced by LF" 警告暴露的)。已就地重写为 LF
  (0 残留), 并按 DoD 记 `pitfalls/git/editing-traps.md` 复发 +1。
- **判据沉淀(可复用)**: ①**一个提交不能包含自己的 hash** —— 任何"提交后回填"的设计都绕不开这条,
  要么换时不变措辞, 要么用第二笔提交, 要么接受"文档滞后一笔"; ②**守卫必须让"清的就是守的"** ——
  清洗脚本 `import` 守卫的 `scan_text`, 不做第二份判据(否则两处各自演化, 实测首版两边差 2 处);
  ③**正则匹配 markdown 粗体要按"配对段"取**, 别用 `[^*]*` 横跨。
