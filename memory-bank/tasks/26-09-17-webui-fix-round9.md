## 思考过程与决策

- **25 项按成因而非界面位置归并成 8 类**(A 启动鉴权 / B 表格口径 / C 状态栏 / D 选择模型 / E 菜单分层与后端 / F 删除语义 / G 抽屉 / H 表格交互), 其中 9 条来自同一批根因 —— 不先归并必然"改一处漏两处"。
- **分阶段按依赖而非按类别排**: 公共底座(单元格口径单点化、浮层锚定契约)先落地 → 结构性重构(选择模型、删除链)放中段 → 纯呈现重构(抽屉)放最后, 避免"大重构 + 大改版"同时进行导致回归不可二分定位。
- **D1 = 方案C**: 共享逻辑层(`shared/app.js`)的改动天然双 UI 生效; 纯版式类改动(CSS/模板)以棱镜为主。
  实施时按此执行: FX-01~04/07/08/10~16 双 UI 同步, FX-05/06/09/17~25 只做棱镜。
  例外: FX-07/08 的状态栏虽属"共享", 仍两套模板都改(否则星图的"历史流量"入口与限速浮层缺失会成为新的断链 —— 星图此前**根本没有限速浮层**(只有按钮), 本次一并补齐)。
- **删除链统一以右键行为为准(D5 = A)**: 右键的"汇报前置 + 目标明细 + 失败保留"是诉求指向的语义; 批量的"单命令聚合回执 + 收尾清选择"是更优实现, 保留不降级。
