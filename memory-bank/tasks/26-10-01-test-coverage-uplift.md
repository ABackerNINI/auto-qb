## 思考过程与决策

- **先测后写**: 不凭印象排阶段, 先 `commands run test.full` 拿当前数字, 再 `coverage json` 导出逐文件聚合, 得到缺口总量 (1,030 行 + 595 分支出口 = 1,625 单位) 与分包/分文件分布。
- **单位经济学定目标**: 分母 17,718 (13,300 语句 + 4,418 分支出口), 每单位 ≈ +0.0056%; 93/95/96% 分别需 +385/+740/+917 单位 —— 据此把「提升到多少」翻译成可验收的单位数。
- **按形态分类而不是按包分类**: 四形态 (A 整块功能空洞 / B 错误分支长尾 / C GUI 主体 / D 入口壳) 决定手法与难度; A 类最优先 —— `versioning._migrate_hr_site_1_2` 整函数、`events.py` SSE 生成器等是「从没被测过」, 不是「测不到」。
- **tray (36%) 单列 P2**: 全仓最大单文件欠账 (277 单位), 但主体是 CustomTkinter/pystray widget, 治本要架构抽取 —— 本计划只做逻辑缝 + 逐块豁免, 治本另立项 (决策已写进计划 §3-P2)。
- **机制优先于意愿**: `--cov-fail-under` 阈值随阶段抬高 (92→94→95), 永远低于当期实测 1 个点 (给并行分支 partial ±1 留余量); `test.quick` 走 `--no-cov` 有意豁免, 提交闸门速度不变。
