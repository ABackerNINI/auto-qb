## 原始请求

1. 「`memory-bank/plans/26-11-12-0344-plan-webui-kbd-hints.html` 已完成，但是当前的快捷键提示太显眼了，打开右键菜单第一时间会聚焦在快捷键上而不是文字上，需要修改」。
2. 「按钮形式的提示太丑」「状态栏上的键位提示太丑」「添加种子 / 列选择的提示也太丑」。
3. 「总之需要全面改造。我倾向于按住 ctrl 显示或者一个切换开关。grilling 然后出一个方案」。
4. Q5 追加：「可以参考成熟的做法，比如 vscode 将右键菜单调大，快捷键提示右对齐，与菜单文字间距拉长，通过这样的方式解决抢焦点的问题。或者使用灰色括号+快捷键提示使其不显眼。不要 b」。
5. Q9 追加：「撞 ctrl 键有什么影响吗？alt 键是浏览器聚焦设置的键位可能撞。反引号与 F1 候选」。
6. 范围追加：「界面上只有添加种子 / 列有快捷键提示，其它的比如主页面切换 / 设置 / 搜索框 / 皮肤切换等都没有，不一致……做成按键显影之后之前的问题就不存在了，能加上的都加上」。

## 思考过程与决策

- grilling 三轮 Q1–Q10 全部拍板 D1–D11，结论表权威在计划 §07，本档案只记取舍要点。
- **总形态**：用户否了单开关(推荐 B)，选混合 C（默认隐藏 + 按住显影 + 开关常驻），接受两套机制 + 状态机 + 触发键冲突核查的成本；C 状态机定「全局单开关、两态互斥、纯 CSS class、零 JS 重绘」。
- **显示态**：Q3 否「一次只显一个」、Q5 否 hover 提亮，改走 VS Code 式菜单加宽 / 右对齐 / 间距拉长 + 灰色括号弱化纯文本；显影只解决抢焦点，撑宽药丸与 34px 状态栏靠「固定预留键位列」与 `::after` 绝对定位两种挂载手法解决（零布局跳动）。
- **触发键**：Ctrl 对多选功能零影响（读 `event.ctrlKey`），但按住逐行点选期间键帽全程常亮属结构性不可消除，且全局零 keyup / 零 blur 兜底、误 `preventDefault` 会反噬组合键与输入框 → 否决；Alt 单按聚焦菜单栏 + `Alt+1..5` 已占 → 否决；反引号零占用、非输入态零浏览器默认、无需 `preventDefault` 即不破坏输入 → 定案；F1 备选。原 D3 对 Ctrl 的否决理由仍成立，本轮靠换键而非改机制绕开。
- **推翻与保留**：推翻前序件 D1 / D2 / D3 / D6 / D7，收窄 D10 / I4（开关控件说明例外）；保留 D4（纯键盘动作不造挂点）、D9（四皮肤一步到位）、D11（取数同源）。
- **边界**：皮肤切换注册表无条目、纯键盘动作无稳定挂点、设置页 hub 表外 `<kbd>` 不走注册表 → 一律跳过；本轮纯显示层、注册表零改动。
- **三条事实纠偏**：注册表真实行号 `shortcuts.js:222-413`（前序件写 `178-369`，S1 插入取数单点后 +44 行）；常驻 `.aq-kbd` 是 3 个不是 2 个（漏算状态栏「键位」入口）；`check_wording` 扫 memory-bank 文档、不扫前端模板。
- 外部检索未取得菜单 accelerator 版式的权威参数，故不预写宽度 / 间距数字，留实施期四皮肤真机截图目检定案。
