## 思考过程与决策

- **根因是自由裁量, 不是符号本身**: 旧稿只有示例清单 + 「等」字兜底, legacy-review4 按宽口径把 `→` `⇒` `≠` 一并判违规。处置 = 把判据写成**码位区间**三张表, 表 A (禁用) 与闸门常量 `BAN_CLASSES` 双向机检同源, 只改一侧当场红。
- **表 B 豁免有代价已认**: docstring 靠箭头分层 (数据流 vs 推导), 机械换成 `->` 会合并两类语义, 故箭头 / 章节符 / 数学符豁免; 0229 批按宽口径清掉的 `.js` 注释箭头不回滚 (既成事实), 宽口径评审结论作废。
- **闸门形态**: 冻结清单粒度 `(文件, 字符类) → 处数` + 「递减不红」, 先带病上岗只拦新增。存量归零后 `FROZEN = {}`, 机制不拆 —— 将来确有一整批既有符号仍走同一登记入口; 此时闸门实际形态 = 纯只拦新增 (未登记 key 冻结值视为 0, 实测 > 0 即红)。
- **豁免必须逐条带理由**: 功能性数据 (gitmoji 映射 / 被断言数据) 与 WebUI 可见文案 (`✕` 关闭图标) 登记进 `EXEMPT_CELLS`; 整目录 / 整文件豁免不防新增, 往这些面加符号须重审理由。
- **决策编号**: 计划 D1-D6 (判据 / 冻结机制 / 只入 pytest 闸门 / 文案豁免 / 开工时序 / 落地顺序), 计划路径见 Refs。
