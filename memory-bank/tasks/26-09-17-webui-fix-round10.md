## 思考过程与决策

- **16 项按成因归 7 类**(A 启动鉴权 / B 底部状态栏 / C 表格呈现口径 / D 用户偏好持久化 / E 服务端能力 / F 弹窗与长文本 / G 抽屉与删除), 其中 4 条同属状态栏、3 条同属表格口径 —— 不归并就会修成"改一处漏两处"。
- **三条硬 bug 是本轮的真正重点**(都有确定根因, 不是"看运气"):
  1. **状态栏限速读了不存在的字段名** —— 前端读 `server_state.dl_limit/up_limit`, 而 qB 真键是 `dl_rate_limit/up_rate_limit`(前者是**单种子**字段)。后果不止"限速恒显示 —": 同一字段还作**速度染色分母**, 所以色阶**从未生效过** ⇒ 修一处必须同时修两处, 故先做"取数单点"。
  2. **星图同时存在两个限速窗口** —— `.speed-pop`(第九轮新增)与 SPD-04 旧模态共用 `speedOpen`, 点一次必开两窗; 棱镜侧第九轮已删净, 星图遗漏 ⇒ 删旧模态 + 静态断言"全站 `.speed-dialog` 模态引用计数 = 0"。
  3. **本机免鉴权仍被弹回密钥页** —— 前端把"有身份"与"有密钥串"绑死(`token = savedToken || ""`), 而 `api()`/轮询守卫都要求 token 非空 ⇒ 进主界面首个请求就自判无凭证并登出。修法 = 鉴权模式显式化(`authMode` + `authOk` 单点判据) + **不带空 Bearer 头**。
- **结构性缺陷两条**(R10-08 对齐 / R10-09 偏好):
  - 对齐口径散在"表头 CSS 名单 + 单元格 CSS + 模板"三处, 只改一处必然产生"表头左、值右"。故把 `align` 提升为**列模型属性**, 由 `colAlignCss` 按**当前可见列**生成 `:nth-child` 规则注入 `<head>`(表头与值同源)。**为何不逐格挂类**: 值单元格 67 个 × 4 视图 × 2 套 UI, 逐格挂必漏。
  - 偏好重置的机制性来源 = **"升版本即清空"**(v2→v3→v4 每次升版等于把用户手调的宽/隐/序归零) + localStorage 的 **origin 隔离**。用户要求只存浏览器 ⇒ 前端侧能做的两件事: ①**不再用升版本应对列集变更**(宽/隐/序一律按列 key 存, 新增列只是"没有记录"); ②保留**旧键迁移**(`LEGACY_COLS_KEYS`), 升级/换键都不再清空。origin 隔离作为已记录限制写入 pitfalls(用户明确不接受服务端化)。
- **服务端新增能力的安全边界是本轮唯一高风险项**: `/api/fs/dirs`(读) + `/api/fs/mkdir`(写)必须白名单(允许根 = 已知保存路径, 与 `/api/paths` 同源)+ 只列目录 + realpath 后判边界(`..` 穿越与符号链接逃逸一并挡掉)+ 单层名字校验, 并配专项用例(越界 403 / 穿越 403 / 逃逸不入列表 / 同名文件 409)。
- **顺序按依赖排**: 先"单点底座"(取数/对齐/状态色/选中色/尺寸令牌) → 再状态栏(4 项在同块 DOM) → 服务端能力 → 弹窗与长文本 → 鉴权/删除链/文案(两处状态机)。
