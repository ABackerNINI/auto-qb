## 原始请求

调研成熟的解决方案，解决以下问题，写一份详细的报告（调研可交给子智能体）：
- qb 流量速度 0 被记录为「断线无数据」
- 压缩流量纪录文件大小，提高保存间隔。速度为 0 是常态可据此压缩；时间也是高重复信息，可考虑保存开始时间+间隔、之后推算，注意配置可能更改。

执行口径：先确定如何保存流量历史，对比方案优劣；暂时不考虑二进制形式保存（可调研对比供以后选择）；然后在此基础上解决问题一。

## 思考过程与决策

- **现状取证**（代码事实，报告 §02）：v1 行式 dat 逐点落盘（`raw,<ts>,<4列>`，null 行全空），全局恒采（0 也写行）、单种活跃过滤（`dlspeed>0 or upspeed>0` 才采，空闲零行，方案C刻意拍板）；读侧空桶=null=断线语义；组图借 global.dat 区分真空闲/停机（单种图做不到）；前端 spanGaps:false + 悬停「断线 · 无数据」(drawer.html:115)。
- **问题一根因**（报告 §03）：主因 = 单种活跃过滤的语义倒挂（最大量常态观测落入异常编码）；次因 = tooltip 文案二义 / 间隔配置变更旧段变稀伪断线 / 全局活跃段偶发抖动缺口。全局与组图的 0 线语义本就正确，问题收敛在单种。
- **调研横向结论**（报告 §04）：工业界 0 与无数据严格二分（Prometheus stale marker / RRD heartbeat / Netdata gap 点 / Grafana null 三选项 / 状态页三态）；qB 生态（qB 桌面 / VueTorrent / Flood / Deluge）全部定频推 0 样本，唯一同构先例 ruTorrent trafic 固定桶把空闲渲染成 0，无任何先例把空闲画成缺口。
- **存储决策**（报告 §05-06）：推荐 **v2 零值行程行**（`z,<start>,<end>,<dl_total>,<up_total>`，开放行程内存延伸、三触发封口[非零样本/小时封口/120 样本上限]，读侧覆盖展开）。压缩主力是零值行而非时间戳列（后者仅占 ~23%），z 行自带时间边界 → 免疫间隔配置变更；用户提案「开始时间+间隔推算」的工业版（段头隐含时间戳）成立但文本下仅 +20% 且与坏行容错相抵 → v3 备选。JSONL 反向 2.6x 排除；整文件 gzip/zstd 失去可 grep 性不采用；二进制留档（SQLite 最低成本 / Gorilla 最高密度 / Parquet 只适合归档导出 / RRD-Whisper 对空闲零收益）。
- **关键拍板点**（留给实施计划）：①单种行程开启条件建议「已有数据文件或已开行程才记 0」（防从未传输种子击穿文件数三闸，语义=动过才画 0 线）；②前端第一版只改文案不动 API 形状；③全局活跃段 spanGaps 阈值默认不做。
