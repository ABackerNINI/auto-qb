# 子智能体中途夭折遗留混合工作区

> 摘要: 子智能体(配额耗尽等)半途夭折不会回滚它已落盘的改动 —— 计划内改动与计划外动作在同一批文件里混杂交织, 直接续派会在脏底子上叠新错。
> 触发: 子智能体夭折, 配额耗尽, 混合工作区, 计划外改动, git status 白名单, 续派

### 夭折现场: 计划内/计划外改动同文件交织

- **触发**: 派发的子智能体中途夭折(2026-10-01 实测: 配额耗尽), 工作区遗留下它的部分产出 —— 实例: 一次运行在完成计划内改动之外, 还夹带了**计划外的模板抽离**(把大模板拆片的动作没被要求却做了一半), 与计划内改动落在同一文件, diff 里两类改动混杂交织。
- **判别**: 夭折后先 `git status --short` + `git diff` 逐文件核对**是否越出计划白名单**(计划授权的文件清单之外的任何改动都算越界); 同一文件内"计划内段落 + 越界段落"并存时, `git checkout -- <file>` 整文件丢弃会连计划内产出一起扔, 必须按段落分辨。
- **处置**: ①先全量备份: `git diff --output=/tmp/<标号>-mixed.patch`(字节原样, 不经控制台编码 —— 见本目录 sync-pull.md 的 PowerShell 补丁转码条); ②**精确回退越界部分**: 越界段落从 `git show HEAD:<file>` 原样取回归位, 计划内段落保留; ③**续派时把「开工先核对 git status 白名单」写成显式指令**(不复述假设), 让接手的子智能体第一脚先确认脚下是净底子; ④回退后跑一遍守阵(test.quick 级)确认计划内部分未受伤, 再续派。
