# 断言有效性

> 摘要: 恒真 / 恒红 / 安慰剂 / 量错对象 —— 断言失去意义的所有已知形态(含"样本与配置脱节"), 以及红验与 A/B 归因的纪律。
> 触发: 写断言, 红验, 反向对照, 阈值, 恒真, 摆设断言, 顺序断言, 冒烟失败归因, flaky, 反查表长度, infohash v1 v2, 手写样本, 配置没被读到

### 写"修复前必失败"的用例必须做**红验**(把修复临时还原, 确认用例失败)

- **触发**: 写"修复前必失败"的用例。
- **判别**: 并发 / 时序类尤其容易写成**安慰剂**(有锁绿、无锁也绿 —— 因为无锁时最后发布者胜出, 四份数组仍自洽)。
- **处置**: 改成**确定性**断言(让重建卡在 builder 里不放行, "能否返回"只取决于有没有锁)。
  红验优先用**运行时 monkeypatch 还原旧实现**(不碰工作区), `lru_cache` 记得先 `cache_clear()`。

### 两种"摆设断言": 恒真 与 某模式下恒红

- **触发**: 新增断言。
- **判别**: ①**恒真断言**(`epRows >= 0`)—— 整页空白照样 PASS; 判据一律写 `> 0` 或等值比较;
  ②**某种模式下恒红**(error 模式下回执瞬间返回 ⇒ 乐观窗口在采样前就关了)—— 该模式**实际没人跑**。
  **"恒红"和"恒真"一样让断言失去意义。**
- **处置**: 新增断言时**两条都查**。

### 反查表 / 映射的"条数"常常不等于"对象数"

- **触发**: 断言 `len(反查表) == N`(例: `hr` 的 `index_by_infohash()`, 2026-09-24 M2 首跑红)。
- **判别**: 一张种子可能同时有 **v1 与 v2 两个 infohash**, 反查表**两个键都收** ⇒ 一条种子 = 2 个键,
  断言 `len(...) == 1` 必红; 而两个键都空时又会被过滤掉 ⇒ 长度既不等于对象数也不成整数倍。
- **处置**: 断言**语义集合**而不是长度: `{e.tid for e in view.by_infohash.values()} == {TID_A}` ——
  既盖住"两个键都收"又盖住"空键不描"。

### A/B 结束后读到的基线是"改动后"的值 ⇒ 断言退化成自比
- **触发**: 写 A/B 对比断言。
- **判别**: A/B 函数收尾会把开关还原。
- **处置**: 在**同一段** `page.evaluate` 里**来回切开关各读一次**并等两帧。

### 冒烟断言别用"固定睡 N 毫秒再采样"

- **触发**: 写冒烟时序断言。
- **判别**: 两种假象**方向相反**: 动作规模大时补丁还没贴完 ⇒ **假失败**;
  补丁贴在 POST 之前、失败要等回执才回滚 ⇒ **假阳性**。
- **处置**: 改成 `waitForFunction` **等条件成立**(成功等目标 class 出现, 失败等 `pendingOps` 归零再断言"不留假状态")。

### 手写的输入样本与**配置**脱节 ⇒ 解析 / 过滤类断言退化成摆设 (2026-09-25)

- **触发**: 测"按某个配置项解析/过滤文本"的功能(日志按等级过滤、按格式抽字段…), 样本是**手写字符串**。
- **判别**: `test_api_log_endpoint` 手写了三行 `2026-09-16 01:00:00 [INFO] 启动完成` 当语料, 而测试替身
  `web_env` 的 `logging.format` 其实是 **`%(message)s`**(没有等级字段)—— 也就是说**配置从来没被读到**,
  真正被测的只是"字面量 `[WARNING` 在不在行里"。于是: ①该用例在旧实现下绿、在新实现下**反而红**;
  ②真机上 format 一换(无方括号)整个功能恒空, 而测试**照样绿**。
- **处置**: 输入样本**必须由被测配置生成**, 不能手写 —— 本项目统一 `_log_lines(fmt, recs)` 走
  `logging.Formatter(fmt)` 渲染; 且**显式设** `mgr.config.logging.format`(替身默认值往往是简化版,
  不设就等于没测配置这条链)。**判据**: 问一句"把配置项改成另一个合法值, 这条断言还会绿吗?" ——
  会绿 ⇒ 它没测配置。红验时优先"临时还原旧实现"(见本文件首条), 本例一次红验就暴露出 7 条用例全在测它。
- **同族**: 解析类失效的表现常是**静默空结果**(见 backend/format-driven-parse.md), 所以断言里除了
  "命中几条", 还要钉住**"筛不了"必须有提示语**, 否则"筛不了"与"确实没有"在断言里长得一样。

### 桩是**瞬时**的 ⇒ 顺序型 / 延迟型缺陷本地永远测不出来

- **触发**: 写"某段代码必须在某次 IO 之前/之后发生"的断言。
- **判别**: 桩瞬时 ⇒ 顺序永远成立。
- **处置**: 断言必须**人为造慢**才有意义(`page.route` 注入 800ms, 再断言点击 → `.is-pending` < 400ms)。
  两坑: Playwright 新版路由谓词收到的是 **URL 对象**(先 `String(u)`);
  点击时刻取**菜单项的 click 事件**(捕获阶段)—— `h.click()` 含鼠标开销, 实测**虚高 ~250ms**。

### 只读调用点就断言"机制不生效" ⇒ 先看 computed 依赖链

- **触发**: 怀疑"机制没工作"。
- **判别**: 组行状态色取自 `decoratedGroups.status.primary`(是 `_aggStatus` 的 computed),
  上游成员的 `kind` 一变它就会变 —— **"机制没工作"与"没绑 class"在源码里长得一样**。
- **处置**: 先问 ①值是不是 computed 派生 ②模板有没有绑这个 class ③**真跑一次看 DOM**(hang 桩 + 150ms 即可)。

### 「A 必须先于 B」这种**顺序**断言, 必须在 **B 发生的那一刻**取证

- **触发**: 写顺序型断言(2026-09-22 issue 26-09-21-1347)。
- **判别**: 跳检要求".torrent 备份先于 `torrents_delete` 落盘", 若只断言最终结果
  (跳检成功 + 事后备份已清理), 那么"删除前备份"与"重加失败后补一份"**两种实现对这条断言都绿** ——
  而后者正是要修的崩溃窗口。
- **处置**: 在被调方(这里是客户端的 `torrents_delete`)外面**加一层包装, 在调用瞬间快照备份文件是否存在**。
  **泛化: 凡是"X 必须在 Y 之前/之后"的约束, 断言点必须落在 Y 上, 不能落在流程末尾。**

### "实测 + 缓存"读不到时**不要**缓存兜底值

- **触发**: 写"读一次就缓存"的实测值。
- **判别**: 曾把种子页间距**永久缓存成兜底 0px**(占位按 0 算 ⇒ 总高少算 ~14855px)。
- **处置**: 量不到就返回 `null` 并**不缓存**, 由调用方本轮退回全量渲染。
  **泛化: 任何"读一次就缓存"的实测值, 都要先分清"值真的是这个"与"现在读不到"。**

### 冒烟失败先做 A/B 归因, 不要默认"是我改坏的"

- **触发**: 冒烟出现失败项(2026-09-21)。
- **判别**: 把改动临时改回旧值再跑一遍同样的冒烟, **失败项集合相同即为既有失败**。
  实测: 修辅种页状态色后冒烟 58 项失败 2 项(两 UI 各一条 `P0-3 乐观态及时落回真值`),
  换回旧表重跑**同样那 2 项** ⇒ 与本改动无关。
- **处置**: 如实报"既有"即可, **别顺手去修不相关的断言**(那是范围守恒的反面)。

### ❗断言量错对象 ⇒ 永久红, 且极易被误读成代码回归

- **触发**: 某条断言**恒红**, 但代码逻辑看起来没错(2026-09-21 二次复核, 撤掉本轮修复重跑仍是同 2 项)。
- **判别**: 那是**断言量错了对象** —— 它的下界 80ms 出自 D2 之前的语义(那时"撤下"要等真值落地 ⇒ ≥120ms),
  而 D2(`0c18fcd`)之后**压暗由回执结束**(实测 17~20ms, 设计使然),
  "等真值"那一段改由**值覆盖(`pendingOps`)**承担 ⇒ 该断言应改量 `pendingOps` 的释放时刻,
  而不是量 DOM 上的 `.is-pending`。
  ✅ **2026-09-22 已修**(用户直接指派, 不再属"计划外"): 拆成两条**各量各的对象** ——
  值覆盖量 `pendingOps` 归零(80~1000ms, 桩里实测 350~400ms)、压暗量 DOM(实测 ~20ms)。
  **判别法(通用)**: 一条断言里若出现"某机制 X 结束"的下界, 先确认它量的那个**可观测对象**是否还由 X 决定 ——
  机制重构后"语义"与"观测对象"会**分家**, 此时断言不报错、只是**永久红**, 极易被误读成代码回归
  (本条被误读了两轮)。
- **处置**: 重构机制后, 回头检查所有"量该机制结束时刻"的断言。

### ❗配套陷阱: 阈值不能按"正常值 × 余量"拍, 必须按"**退化路径实测值**"反推

- **触发**: 新增时间类断言的阈值。
- **判别**: 压暗那条第一版拍了 400ms(rationale: 正常 ~20ms、D2 前退化 ~3s, 400 看着很保守)⇒
  **退化路径擦线过关**(压暗不结束时 DOM 会挂到值覆盖释放才消失 ≈350ms, 实测 **349/374ms 全绿**)⇒
  压到 **250 才必红**。
- **处置**: 新增时间类断言时**必须把"坏了会是多少"也测出来**, 只测"好了是多少"等于没定阈值。
  ⚠ 退化值随库规模浮动(refresh 越慢越大), 换 `--torrents` 档位要**复标**。

### `test_run_loop_throttles_without_stop_event` 偶发翻红

- **触发**: 全量跑出 1 条红。
- **判别**: 同一份代码全量跑两次: 一次 `1097 passed + 1 failed`, 一次 `1098 passed` ——
  它是**墙钟时序**断言(主循环节流间隔), 在覆盖率开启 + 全量负载下偶发超时;
  单跑 `tests/test_qbmanager.py` **43 passed 恒绿**。
- **处置**: 全量跑出 1 条红时**先换全新临时根重跑一次再判回归**, 别急着改代码 ——
  **真回归会稳定复现**。
