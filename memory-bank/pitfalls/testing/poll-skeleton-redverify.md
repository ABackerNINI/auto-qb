# 红验突变的还原校验: grep 会被注释形态骗过 + 电池失控要带超时

> 摘要: 手写红验脚本(逐条改源码 → 跑目标守阵 → 还原)时, 「还原」这一步的两个静默失败形态 ——
> 等级: L0
> 进程被杀导致突变残留, 而用 grep 校验还原又被「注释形态的突变体」骗过; 以及突变让 node 电池
> 陷入微任务死循环时, 无超时的 `subprocess.run` 会把整个会话挂住。
> 触发: 红验, 突变还原, grep 校验, 注释形态突变, node 电池挂起, subprocess 超时, 微任务死循环

### 突变体 `/* n += 1; */` 仍含 `n += 1` —— grep 校验「已还原」是假的

- **触发**: 自己写红验脚手架(非 mutmut): 读源码 → `str.replace(锚点, 变异体, 1)` → 跑守阵 → 还原。
  两类诱因同时出现时踩中: ①脚本被中断(超时被杀 / `taskkill` / 断言先失败)导致 `finally`
  里的还原没跑; ②事后用 `grep -c "n += 1;"` 之类**子串包含**确认「已还原」。
- **判别**: 还原校验全绿, 但目标守阵**忽然跑不过或挂住**(症状与刚才那条突变体完全一致)。
  本次实况: 突变体是 `/* n += 1; */`, 而 `grep -n "n += 1"` 在两种形态下都命中 ⇒ 误判为已还原,
  挂着突变体跑了 12 分钟才靠 `git diff` 里那行 `+          /* n += 1; */` 看出真相。
- **处置**: 三条 ——
  1. 还原**无条件**: `try/finally` 不够(进程被 SIGKILL 时 finally 不跑), 中断后必须**重跑一次
     `git diff --numstat`** 看改动行数是否回到本轮基线;
  2. 校验还原用 **`git diff` 的增删行**看, 不用子串包含 —— 变异体与原文同含某子串是常态
     (注释掉 / 加前缀 / 改比较符都如此);
  3. 突变体**不要写成注释形态**(用换值 / 删行 / 短路), 否则既难校验又容易留下半截。
- **守阵**: 无(脚手架是一次性的); 靠上面三条纪律自守。

### 突变让电池陷入微任务死循环 —— `subprocess.run` 不带超时 = 会话挂死

- **触发**: 守阵的 node 电池用 `subprocess.run([node, "-e", 探针, ...])` 真跑前端代码, 而突变
  恰好拆掉了循环的**递增/收摊条件**(如 `n += 1`): 探针里 `ms: () => 0` 的那几型不排定时器,
  `await` 全部落在微任务队列 ⇒ 事件循环永远轮不到宏任务, node 既不退出也不产出 ⇒
  `subprocess.run` 无 `timeout` 就一直等, xdist worker 一起挂住。
- **判别**: 单条守阵平时 0.2s, 突变后跑 2 分钟 / 12 分钟都没输出; `timeout 120 uv run pytest`
  退出码 124; 日志里只有 `bringing up nodes...` 没有用例结果。
- **处置**: 电池一律带 `timeout=`(本仓取 60s)并在 `TimeoutExpired` 里抛**人话断言**
  (「骨架循环疑似失控 —— 拍数递增 / 收摊条件被拆?」), 让红验的结论是「红」而不是「挂」;
  排查时先 `taskkill //F //IM node.exe` 清残留进程, 再按上面第一条核对源码是否被突变残留。
- **守阵**: `tests/test_webui_static_dom_panel.py::test_frontend_poll_skeleton_single_point`
  (电池调用带 `timeout=60`)。
- **复发**: 0 (复踩时在此行追加「+N (日期): 为什么没命中」, 无复发可删本行)
