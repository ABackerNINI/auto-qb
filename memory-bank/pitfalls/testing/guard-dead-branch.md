# 扫描型守阵自身分支静默死掉(捕获组取错类) —— 全绿不等于守阵活着

> 摘要: 扫描型守阵的「没扫到」与「扫了没有违规」输出完全一样 —— 正则后来为 `\1` 回引用补了捕获组, 消费处组号没跟着挪, 整个分支从此恒扫引号字符, 检出能力归零而 pytest 照样全绿(issue 26-10-11-2030 实证: 保留前缀守阵的指令表达式分支死了很久, docstring 宣称的两类形态覆盖实际只覆盖一类, 连白名单回退式红验都被骗过)。防死单点 = 扫描逻辑抽函数 + 守阵内**恒久活性探针**(已知违规样本必须命中); 红验必须「注入已知违规」, 不能只「收紧白名单」。
> 等级: L0
> 触发: 守阵, 死分支, 捕获组, group(1), group(2), 正则改形, 回引用, 假绿, 红绿双验, 活性探针, 扫描型守阵, 静态守卫, 检出能力, docstring 宣称, 白名单回退

### 指令分支恒扫引号, 全绿无征兆 (2026-10-12)

- **触发**: 给既有正则补 `(["'])` 捕获引号(为了 `\1` 回引用)—— 后面所有捕获组序号**整体 +1**, 消费处 `m.group(1)` 从「表达式」变成「引号字符」。编译期零告警、运行期零异常, 该分支每次都「成功」扫一个引号, 永远 0 命中。实例: `test_frontend_template_no_reserved_prefix_identifiers` 的指令表达式分支(issue 26-10-11-2030), 26-10-03-1412 的复发形态(指令处理器写 `_x()`)按设计该由它拦, 实际整支死掉。
- **判别**: ①对守阵正则单独喂一条已知违规合成样例, 打印捕获组语义 —— 表达式在引号捕获之后时组 1 必是引号本身, 消费处取组 1 即死支; ②把该分支的 spans 数出来(不只看最终 problems), spans 非空而命中恒 0 = 分支在扫垃圾; ③docstring 宣称的覆盖形态逐条对表, 每种宣称形态都要有「合成样例必须命中」的断言兜着, 否则就是没被真正覆盖。
- **处置**: ①修法 = 消费处组号跟捕获组位移同步(表达式挪 `group(2)`); 修完先跑存量预览(守阵变严可能首次爆出存量违规, 先确认 0 存量再收口), 再做**真注入红验**(往任一真实 tpl 写 `@click="_probeRed()"` 必须报红, 还原后复绿); ②防复发单点写法 = 扫描逻辑抽成模块级函数, 守阵尾部加**恒久活性探针**: 每条宣称形态各喂一条已知违规断言必须命中、白名单内建另喂一条断言必须放行 —— 探针与真实模板走同一函数, 分支再死 = 守阵红, 不依赖一次性红验; ③红验纪律补一条: 红验要**注入已知违规**, 不能只收紧白名单 —— 后者隐含假设被验分支活着, 恰恰是被验对象(issue 里 P5 轮的白名单回退红验就是这么漏掉的)。

### 电池条目级空转: 断言被副作用吃掉 / 返回值丢弃恒真 (2026-11-04, issue 26-11-04-0504)

- **触发**: 扫"分支死"扫不到的另一形态 —— node 语义电池的一条 check 里, 被测调用写在**逗号表达式**中, 真正比对的是调用之后的树状态。若调用没生效, 状态就没变, 期望值看似"没变"的形态也跟着静默成立(此处是"输入本应是扁平列表"这一步没被钉住, 而期望写成 `{all:[...]}`, 二者只在调用真执行时才互斥)。同电池另一条更露骨: `(f(), f(), true)` —— 两次返回值被丢弃, 第三元素字面量 `true`, **无论实现如何都绿**。
- **判别**: ①逐条问"这条若把被测函数改成空函数, 会不会红"; 空函数仍绿的条目 = 恒真; ②调用写在逗号表达式里的条目, 把调用**抽成独立语句**并在调用前后各断言一次(前置: 输入确为旧形态; 后置: 输出为新形态), 前置断言常常就暴露"夹具早就是新形态"; ③整组电池的 `ok/total` 是否能在 Python 侧被证明"结果被真实比对"——`assert not failed` 只证明全绿, 不证明没早退。
- **处置**: ①条 1 改三步分开(钉输入 → 调归一 → 钉输出); ②幂等条改快照深比较(归一可能无返回值, 别拿返回值当比较对象; 比较**被测对象本身的整棵快照**前后)—— 另附"非幂等样本必须被抓出"的专桩, 自证该比较模式可红; ③Python 侧端到端活性注入: 探针支持 `liveness` 参数追加一例必红期望, 二次运行断言该红**精确出现在 failed** 且 `total` 恰 +1, 早退/结果被吞时注入红不出现即守阵红(本例落地: `tests/test_webui_static_dom_page_layout.py::test_frontend_rule_tree_and_choose_editor` 第 5 步); ④收口做变异红验: 改坏被测实现(杀归一/改非幂等)必须精确报对应条目, 还原复绿。
