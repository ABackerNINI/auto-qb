# 用例循环 ts+i 跨本地零点把按天计数清零 —— 距零点时段必红 flaky

> 摘要: 用例喂 `observe(ts+i)` 循环(i 到阈值+30)拿 `ts = int(time.time())` 时, 距本地零点 &lt;循环跨度秒的跑必红 —— 生产代码按天重置计数是**正确**语义, 用例未固定「同一天」致阈值永不达, 告断言红。修法锚循环起点当日 00:01 走仓库现单点 `v4_day_epoch`(本地口径, 与 `v4_epoch_date_str` 一致), **别**用 `//86400*86400`(UTC 秒对齐, 非 UTC+0 日界错位即新 flaky)。2026-10-13 流量图限速历史两条用例实证; 2026-10-19/20 两轮扩形(按日文件 / 秒分精度 / 锚 base 不锚 now); **2026-10-22 四轮实证两种同族新形态: 导入时求值的 `date.today()` 模块常量(通知面 6 条)与「用例 now 镜像服务端窗口」的几何分档断言(qb 端点面 1 条, 00:00:00-00:00:30 窗口)**; **2026-11-03 五轮: `_Clock()` 默认 epoch(`1_700_000_000`)在 CI 的 UTC 下是 22:13, 用例的封口水位 `h2+3610` 跨本地午夜触发日封口(本机 UTC+8 是 06:13, 恒绿)**;**2026-11-03 六轮: 滚动窗栅格桶数在 `t1 % interval == 0` 边界秒翻转 —— 两次请求比较响应全等未钉钟, CI 慢一点就多/少一个空桶(win32 Python 3.13 `test_web_longtail_traffic`)**;**同轮三条尾桶定位用例(3d/组 30d/6mo)按 B「只替换端点模块时钟」收口, 双面钟红/绿实证**。

### 按天计数护栏 + 用例循环跨零点 = 时刻相关必红

- **触发**: 写 / 改用例喂时间戳循环(`for i in range(N): observe(..., ts + i)`, N 千秒级)对生产代码有**按天重置计数**护栏(单天事件超阈值即告), 或排查「全量 / 单文件跑在距本地零点约 N 分钟内必红, 其余时段绿; CI 多数时候绿」。
- **判别**: 生产代码形如 `if self._day_events_date != date_str: self._day_events = 0`(`date_str = v4_epoch_date_str(ts)`) —— 按天语义**正确**, 不受影响。缺陷在**用例**: `ts = int(time.time())` 现时刻, 循环跨度 N 秒; 距零点 &lt; N 时循环跨天, day1 计数封顶 `距零点`、day2 计数 `N - 距零点`, 两者 &lt; 阈值 ⇒ 告**永不触发**, 断红。死窗 offset∈[阈值−N+1, 阈值−1] 实测(阈值 2000、N 2030 ⇒ offset∈[31,2000]; offset≤30 edge day2 仍达阈值即绿)。失败签名与"caplog 没采到"完全一样 —— 别归到 [log-capture.md](log-capture.md) 那条采集层坑, 这条是生产代码压根没打(按天语义正确, 用例喂跨天)。
- **处置**: 锚循环起点**当日 00:01** —— `ts = v4_day_epoch(int(time.time())) + 60`, 跨度 &lt;86400 恒同日, 计数不再跨天清零。**用仓库现单点 `v4_day_epoch`**(本地时区, 与 `v4_epoch_date_str` 的 `datetime.fromtimestamp` 口径一致), **别**用 `int(time.time()) // 86400 * 86400 + 60` —— 后者按 UTC 秒对齐, 非 UTC+0 时与 `v4_epoch_date_str` 日界不一致(UTC+8 上距零点 &lt;8h 仍跨天), 即把另一时刻现红新 flaky。备选(不推荐): 把循环跨度 &lt; 距零点剩余秒 —— 脆弱, 换个时刻又红。
  **守阵(时刻无关证)**: 把 `time.time()` 钉在死窗 —— `day0 = v4_day_epoch(int(real())); time.time = lambda: day0 + 86400 - 1359` 再跑两用用例即绿; 修复前同时刻直读探针 `day_events` 远低于阈值即红验锚点。
  **泛化**: 凡是"按天/按周期重置内存计数"的护栏, 用例喂跨周期时间戳即把阈值永不达 —— 先问一句**循环跨度 vs 距周期边界**, 锚起点周期内固定。同族 [monotonic-warn-sentinel.md](monotonic-warn-sentinel.md)(哨兵 0 点 = 开机时刻) —— 两坑都是"用例假设某时钟的 0 点/边界, 生产语义正确但用例未固定"。

### 2026-10-20 三次实证: 「必须留真钟」的那类窗口用例怎么修 —— 锚 base 不锚 now(issue 26-10-20-0024)

- **触发**: 用例时间轴起点必须留在真钟(端点 `window=24h` 由**服务端**按 now 收边, 锚了就与服务端算的窗分家), 但用例另有派生量 `base = ((now - 600) // 30) * 30` —— 每天 **00:00-00:10** 这 10 分钟里 `now - 600` 落到**前一日**, 派生量跟着翻天。
- **判别**: 现象是「00:00-00:10 内跑必红, 00:10 过后自愈」; 红的不是业务断言, 而是**依赖前驱块间隔的那个**(本次是跨日长洞 → 应为 null, 翻天后长洞消失判成 0)。与上一条的 23:59-00:00 窗口**互补**: 两条合起来, 00:00 前后约 11 分钟门禁都会红。原始时刻已过时就用**假墙钟构造复现**(`monkeypatch.setattr(time, "time", lambda: v4_day_epoch(_real) + 300)`)。
- **处置**: **保留 `now` 在真钟**(involved / 端点收边 / 造数全照旧), 只把派生量锚到**当日 00:00** —— `base = v4_day_epoch(now)`。它必在 24h 窗内(窗尾是 now, 当日总在窗里)且恒落 involved 末日, 跨日长洞前提恒成立, 改动面 = 破面。⚠️ 这里**不是**上面那条的正午锚点: 对「必须留真钟」的用例, 锚 now 是禁招, 只能锚派生量。
- **守阵**: 参数化两档 —— 真钟 + 假钟当日 00:05(`@pytest.mark.parametrize("frozen_offset", [None, 300])`), 把那 10 分钟**永久钉在门禁上**, 不用等真钟撞进去。红验形状与别处相反: 改回旧写法后**假钟档红、真钟档(当时在窗口外)仍绿** —— 说明钉的是窗口本身而不是当时的钟点。
  **附带认知**: 服务端 `_grid`(traffic_qb.py:133)与用例同读 `time.time()`, **钉一次双边生效**, 不存在「钉了用例却钉不住服务端」的分家风险(钉 `time.time` 前先取一次真值算当日 00:00, 别在 lambda 里再取)。
- **为什么没命中(复发 1)**: 0013 那轮只扫了 `test_traffic_limits.py` / `test_expr_eval.py` 两个文件, **没扫 `test_web_traffic_qb.py`** —— 同款 `t0 = now-600` 就埋在那儿。坑档第 22 行自己写着「别把上次只修了 2 例当成整类已修」, 结果口径里没列"按目录扫"的清单, 又漏了。下次修这类: **先 `grep -rn "int(time.time())" tests/` 列全文件清单再动手**, 并用假钟把清单整体跑一遍(本次: traffic 全家族 14 文件 281 例在假钟 00:05 下全绿, 邻域证伪)。

### 2026-11-03 五次实证: 冻结 epoch 的**默认值**在其他时区落到日界前(不是 ts+i 循环)

- **触发**: 用例用固定时钟 `_Clock()`(默认 `1_700_000_000.0`)派生 `h1 = now // 3600 * 3600` / `h2 = h1 + 3600`,
  再以 `h2 + 3610` 作封口水位; 本机 UTC+8 下本地钟点 06:13(同日), CI 的 ubuntu / win32 两个 runner 均为 UTC,
  本地钟点 22:13 ⇒ 水位跨本地午夜, `_agg_flush_series` 的**日封口**提前触发。
- **判别**: 失败签名 `agg.day_hours == 0`(期望 2)、`month_days` 恰一行 `cov_s=3600`、`day_epoch=None` ——
  生产按小时/按天语义**正确**, 是"同日多 hour"用例前提在另一个时区不成立。**别**去改日封口条件。
- **处置**: 时钟钉在**本地正午** `_Clock(now=_w5_ts(2026, 6, 15, 12, 0, 0))`(与 0013 轮正午锚点同口径),
  前后各 12h 余量、跨时区恒同日; 不要用 `int(time.time())` 现时刻。
- **守阵**: `tests/test_traffic_sample_store.py::test_w5_ingest_acc_same_day_multi_hour`; 红验 = `TZ=UTC` 下旧写法必红
  (实测 `day_hours=0`), 改后绿; 本机 UTC+8 下两版都绿, 只在本机跑等于没验。
- **为什么没命中**: 第一眼把"固定时钟"当成"时刻无关", 没算默认 epoch 在**目标时区的本地钟点**
  (`1_700_000_000` 在 UTC = 22:13, 离日界仅 1h47m); 本机 UTC+8 恰好离日界 17h+, 掩盖了这条。
  下次看到用例内固定 epoch, 先问一句**该 epoch 在 CI 时区的本地钟点离日界多远**。

### 2026-11-03 六次实证: 滚动窗栅格桶数在边界秒翻转(跨请求比较响应全等必红; 复发 3)

- **触发**: 用例两次 GET 同一 raw 段窗端点(`window=5m`)之间执行落盘, 断言响应逐点全等
  (`assert body == live_body`)。栅格是滚动窗 `[now-300, now)`, 桶数 = `ceil((now - floor(now-300))/30)`:
  `now % 30 == 0`(恰在边界秒)时开放桶 `[now, now+30)` 覆盖为 0 被省略 = **10 桶**,
  下一秒 `r > 0` 又补回 = **11 桶** —— 第二次响应在尾部多一个空桶, `meta` 不变(`stale=False`)。
  失败签名: `points`/`totals` 长度差一, pytest 列表 diff 显示中部插入一个 `None`(对齐渲染位置,
  实际差异在尾部); 本机(Windows)请求间隔亚秒恒绿, CI 慢一点才有概率触发。
- **判别**: 是**用例假设**而非产品缺陷 —— `build_grid(window, now)` 的滚动窗语义与
  "欠覆盖桶不出现" 都正确; 与快照/flush 去重、stale 降级无关(两次响应数据点完全一致, 只差尾部空桶)。
- **处置**: 入口钉钟 `now = int(time.time()); monkeypatch.setattr(time, "time", lambda: float(now))` ——
  服务端 `_grid`(traffic_qb.py)与用例同读 `time.time()`, **钉一次双边生效**, 三次请求同一栅格;
  不要改成"只比有效桶/放宽长度语义"(会放掉快照与 flush 竞态不重不漏的判别力)。
  守阵: 受控时钟取 `r=0/5/29` 三档(边界秒、边界后、边界前)三次请求逐点全等均绿;
  红验: 允许时钟在两次请求间推进 5s(从 `r=0` 到 `r=5`)即复现尾部多一个 `None`。
- **为什么没命中(复发 3)**: 0024 与 2026-10-22 两轮只把"周期边界"理解成自然日/窗口起点
  (`now-600` 跨日、`base` 派生量), 没把它推广到**桶宽取整**本身: 任何
  `ceil((t1 - floor(t0)) / interval)` 形状的栅格, `t1 % interval == 0` 与 `> 0` 是两种桶数形态。
  下次写"多次请求响应必须全等"的用例, 先问一句**两次请求之间时钟是否冻结**;
  凡是滚动窗端点(`/api/traffic/qb/*` 的 raw 段), 一律钉钟再比全等。
- **补(同轮, 复发 4): 尾桶定位类同族** —— `points[-1]`/`[-2]`/`totals[-1]` 取自
  `build_grid(now).last`, 端点另行现读墙钟: 整点/零点跨过即尾桶前移一格/一天。
  处置改为 **B(只替换端点模块时钟对象)**: `tests/webui_helpers._freeze_traffic_endpoint_clock`
  把 `traffic_qb.time` 换成固定钟(测试进程其它 `time.time` 不冻), 三条用例各接一行。
  红/绿实证(双面钟: 用例帧读边界前 B-1, traffic_qb 帧读边界后 B+1):
  `3d/group_30d` 旧写法 `assert None == {'t': <昨日开放小时>}`(行 189/295),
  `6mo` 旧写法 `assert None == {'t': <昨日日界>}`(行 228); 接 B 后三条全绿。
  判别口诀: 断言量若来自**用例侧边界推导**(尾桶/长度/全等), 端点时钟必须与用例同源;
  若只用**绝对桶键**查找(带 ≥1 桶余量), 跨边界无害, 不必钉。
