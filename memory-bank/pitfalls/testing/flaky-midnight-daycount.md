# 用例循环 ts+i 跨本地零点把按天计数清零 —— 距零点时段必红 flaky

> 摘要: 用例喂 `observe(ts+i)` 循环(i 到阈值+30)拿 `ts = int(time.time())` 时, 距本地零点 &lt;循环跨度秒的跑必红 —— 生产代码按天重置计数是**正确**语义, 用例未固定「同一天」致阈值永不达, 告断言红。修法锚循环起点当日 00:01 走仓库现单点 `v4_day_epoch`(本地口径, 与 `v4_epoch_date_str` 一致), **别**用 `//86400*86400`(UTC 秒对齐, 非 UTC+0 日界错位即新 flaky)。2026-10-13 流量图限速历史两条用例实证; 2026-10-19/20 两轮扩形(按日文件 / 秒分精度 / 锚 base 不锚 now); **2026-10-22 四轮实证两种同族新形态: 导入时求值的 `date.today()` 模块常量(通知面 6 条)与「用例 now 镜像服务端窗口」的几何分档断言(qb 端点面 1 条, 00:00:00-00:00:30 窗口)**。

### 按天计数护栏 + 用例循环跨零点 = 时刻相关必红

- **触发**: 写 / 改用例喂时间戳循环(`for i in range(N): observe(..., ts + i)`, N 千秒级)对生产代码有**按天重置计数**护栏(单天事件超阈值即告), 或排查「全量 / 单文件跑在距本地零点约 N 分钟内必红, 其余时段绿; CI 多数时候绿」。
- **判别**: 生产代码形如 `if self._day_events_date != date_str: self._day_events = 0`(`date_str = v4_epoch_date_str(ts)`) —— 按天语义**正确**, 不受影响。缺陷在**用例**: `ts = int(time.time())` 现时刻, 循环跨度 N 秒; 距零点 &lt; N 时循环跨天, day1 计数封顶 `距零点`、day2 计数 `N - 距零点`, 两者 &lt; 阈值 ⇒ 告**永不触发**, 断红。死窗 offset∈[阈值−N+1, 阈值−1] 实测(阈值 2000、N 2030 ⇒ offset∈[31,2000]; offset≤30 edge day2 仍达阈值即绿)。失败签名与"caplog 没采到"完全一样 —— 别归到 [log-capture.md](log-capture.md) 那条采集层坑, 这条是生产代码压根没打(按天语义正确, 用例喂跨天)。
- **处置**: 锚循环起点**当日 00:01** —— `ts = v4_day_epoch(int(time.time())) + 60`, 跨度 &lt;86400 恒同日, 计数不再跨天清零。**用仓库现单点 `v4_day_epoch`**(本地时区, 与 `v4_epoch_date_str` 的 `datetime.fromtimestamp` 口径一致), **别**用 `int(time.time()) // 86400 * 86400 + 60` —— 后者按 UTC 秒对齐, 非 UTC+0 时与 `v4_epoch_date_str` 日界不一致(UTC+8 上距零点 &lt;8h 仍跨天), 即把另一时刻现红新 flaky。备选(不推荐): 把循环跨度 &lt; 距零点剩余秒 —— 脆弱, 换个时刻又红。
  **守阵(时刻无关证)**: 把 `time.time()` 钉在死窗 —— `day0 = v4_day_epoch(int(real())); time.time = lambda: day0 + 86400 - 1359` 再跑两用用例即绿; 修复前同时刻直读探针 `day_events` 远低于阈值即红验锚点。
  **泛化**: 凡是"按天/按周期重置内存计数"的护栏, 用例喂跨周期时间戳即把阈值永不达 —— 先问一句**循环跨度 vs 距周期边界**, 锚起点周期内固定。同族 [monotonic-warn-sentinel.md](monotonic-warn-sentinel.md)(哨兵 0 点 = 开机时刻) —— 两坑都是"用例假设某时钟的 0 点/边界, 生产语义正确但用例未固定"。

### 2026-10-19 二次实证: 同病不止「按天计数」, 还有「按日文件」与「秒/分精度」(issue 26-10-19-0013)

- **触发**: 用例拿 `ts = int(time.time())` 当时间轴起点, 后续 `ts+30/60/120`(或护栏循环 `ts+i`)推进; 或断言/判定里出现 `_read_day(date)`、`v4_epoch_date_str(now)`、`utils.time_in_range(now.time(), …)` 这类"按自然日/按分钟"的实现口径。同一病灶三种形态:
  1. **按天计数**(上一条, 2026-10-13);
  2. **按日文件**: 跨零点后事件落进**次日**文件, 断言仍在 `_read_day(date)` 读**起点那天** ⇒ 行数少一、末行对不上。窗口型更隐蔽: `t0 = now-600` 跨到前一日, 合成首事件的取值文件与断言前提分家。
  3. **秒/分精度**: 旧 `date_time` 条件走 `utils.time_in_range`(秒精度, 23:59:01-59 出界) vs 表达式 `sys.time_of_day = hour*60+minute`(分钟精度, 1439 在内) —— 「全时段」配置把分叉窗口摆在每天最后一分钟, 等价性用例在那一分钟必红。
- **判别**: 现象是「23:59-00:00 之间跑必红, 其余时段全绿」, 且失败断言全是计数/末行/等价性, 与业务无关。先问一句 **用例时间轴跨度 vs 距日界/分钟边界的余量**。注意别把"上次只修了 2 例"当成整类已修 —— 同文件里其余裸取时的用例仍在埋雷(**部分修复把整类问题盖住了**, 这是上次没命中的真实原因: 口径只写"内存按天计数", 看到按日文件断言时不认成同一坑)。
- **处置**: 文件级用例一律 **正午锚点** `ts = v4_day_epoch(time.time()) + 12*3600`(同一 `v4_day_epoch` 单点, 前后各 12h 余量, 比 00:01 更抗后续加长跨度)。**例外**: 靠真钟收边的窗口查询用例(端点 `window=24h` 由服务端按 now 算窗)必须留在真钟上 —— 锚了反而错。精度类用**冻结时钟**(本地 `datetime` 子类 + monkeypatch 目标模块的 `datetime` 名, 让旧条件与表达式读同一瞬间), 并把历史分叉时刻(23:59:30)保留成**守阵位**持续跑。修 flaky 要按"文件/目录"扫一遍同款取时, 不是只修红了的那几条。
- **时刻无关证(最快)**: 把 `time.time` 钉在死窗(如 23:59:50)跑「改前 / 改后」两份文件对照 —— 改前必红、改后必绿, 比等到半夜跑一次可靠得多。同理改实现精度时, 临时去掉修正行跑守阵应红(红验), 再还原。
- **附: 实现侧分叉已收口(2026-10-19 用户拍板"直接改")** —— `utils.time_in_range` 改成**分钟粒度**(先 `replace(second=0, microsecond=0)` 再比), 端点整分钟含在内; `00:00-23:59` 从此真的覆盖全天, 与表达式 `sys.time_of_day` 同口径。三个消费方(规则 `date_time` 条件 / 通知 `quiet_hours` / HR 限速 `allow_window`)一起变 —— 这是单点修正的必然代价, 改前先列全调用面。

### 2026-10-20 三次实证: 「必须留真钟」的那类窗口用例怎么修 —— 锚 base 不锚 now(issue 26-10-20-0024)

- **触发**: 用例时间轴起点必须留在真钟(端点 `window=24h` 由**服务端**按 now 收边, 锚了就与服务端算的窗分家), 但用例另有派生量 `base = ((now - 600) // 30) * 30` —— 每天 **00:00-00:10** 这 10 分钟里 `now - 600` 落到**前一日**, 派生量跟着翻天。
- **判别**: 现象是「00:00-00:10 内跑必红, 00:10 过后自愈」; 红的不是业务断言, 而是**依赖前驱块间隔的那个**(本次是跨日长洞 → 应为 null, 翻天后长洞消失判成 0)。与上一条的 23:59-00:00 窗口**互补**: 两条合起来, 00:00 前后约 11 分钟门禁都会红。原始时刻已过时就用**假墙钟构造复现**(`monkeypatch.setattr(time, "time", lambda: v4_day_epoch(_real) + 300)`)。
- **处置**: **保留 `now` 在真钟**(involved / 端点收边 / 造数全照旧), 只把派生量锚到**当日 00:00** —— `base = v4_day_epoch(now)`。它必在 24h 窗内(窗尾是 now, 当日总在窗里)且恒落 involved 末日, 跨日长洞前提恒成立, 改动面 = 破面。⚠️ 这里**不是**上面那条的正午锚点: 对「必须留真钟」的用例, 锚 now 是禁招, 只能锚派生量。
- **守阵**: 参数化两档 —— 真钟 + 假钟当日 00:05(`@pytest.mark.parametrize("frozen_offset", [None, 300])`), 把那 10 分钟**永久钉在门禁上**, 不用等真钟撞进去。红验形状与别处相反: 改回旧写法后**假钟档红、真钟档(当时在窗口外)仍绿** —— 说明钉的是窗口本身而不是当时的钟点。
  **附带认知**: 服务端 `_grid`(traffic_qb.py:133)与用例同读 `time.time()`, **钉一次双边生效**, 不存在「钉了用例却钉不住服务端」的分家风险(钉 `time.time` 前先取一次真值算当日 00:00, 别在 lambda 里再取)。
- **为什么没命中(复发 1)**: 0013 那轮只扫了 `test_traffic_limits.py` / `test_expr_eval.py` 两个文件, **没扫 `test_web_traffic_qb.py`** —— 同款 `t0 = now-600` 就埋在那儿。坑档第 22 行自己写着「别把上次只修了 2 例当成整类已修」, 结果口径里没列"按目录扫"的清单, 又漏了。下次修这类: **先 `grep -rn "int(time.time())" tests/` 列全文件清单再动手**, 并用假钟把清单整体跑一遍(本次: traffic 全家族 14 文件 281 例在假钟 00:05 下全绿, 邻域证伪)。

### 2026-10-22 四次实证: 「导入时求值」与「镜像断言几何分档」两种同族新形态(通知面 6 条 + qb 端点面 1 条)

- **触发**: ①用例把时间算成**模块级常量**(`EVENT = {"day": date.today().isoformat(), ...}` 在 import 时求值一次, 运行期复用), 而消费方(服务端)在**请求时**才读 `date.today()` 判当日 —— 全量套件 23:59 收集 / 00:00 后执行, 常量对服务端就是「非当日」; ②断言的期望值由**用例自己的 now 镜像**服务端窗口(日期集合 / 栅格桶形态), 且期望形态依赖一个会随时刻翻转的前提(如「当日首记录已入窗」)。现象依旧是「23:59→00:00 跨日窗口必红, 单独复跑 / 跨日后重跑全绿」。
- **判别**: ①导入时求值: 把 `date.today` 换成分阶段假类(收集期返回前一天, `pytest_collection_finish` 后返回当天)再跑目标文件 —— 改前 6 条正向量(queues / duplicate / no_throttle / command_execution / gate / logs)全红, 改后全绿。注意执行体路径(`publish_event`)也有一份 `date.today()` 判据, 直投命令的用例同样红。②几何分档: 把全局 `time.time` 冻在当日 00:00:15(**双边一致, 不错边**)跑目标文件 —— 改前 `StopIteration`(期望的 null 字典不存在); 根因是当日首记录槽 = base+30, 在 00:00:00-00:00:30 之间大于窗尾 `t1 = now` 被丢弃, base 桶无观测 = **空桶 null**(`rate_points` 逐桶出条目, 无观测即 null), 而旧断言只认跨日长洞的 null 字典。生产行为正确, 是断言只认一种形态。
- **处置**: ①导入时求值 → 改**调用时求值工厂**(`def _event(**ov): return {..., "day": date.today().isoformat(), **ov}`), 每次投递现算; 日期/时刻常量不许留在模块级。②几何分档 → 期望值按几何分档: `now <= base+30`(首记录未入窗)期望空桶 null, 否则期望跨日长洞 null 字典; 同时真钟档**钉在本用例入口时刻**(`_anchor = time.time(); monkeypatch.setattr(time, "time", lambda: _anchor)` —— 用例与服务端同读 `time.time`, 钉一次双边生效; 窗口位置仍是现网形状, 只消除两端横跨零点的 ms 级竞态), 并把 00:00:15 加成常驻假钟档(`@pytest.mark.parametrize("frozen_offset", [None, 300, 15])`)。
  **守阵(红验形状)**: 把条件断言改回旧写法(只认 null 字典)→ 00:00:15 假钟档红、真钟档与 00:05 档仍绿 —— 钉的是窗口本身而非当时钟点, 与 0024 同款反向验证。
- **为什么没命中(复发 2)**: 0024 那轮的假钟扫描(00:05)对**导入时求值**类病灶天然免疫 —— 双边同时被钉, 导入值与请求值恒等, 扫多少遍都照绿; 且扫描范围按文件清单列(traffic 家族 14 文件), 通知面的模块级常量不在列。下次修这类 flaky: 除假钟整体跑一遍外, 必须另做 `grep -rn "date.today()" tests/` 专扫**模块级 / 夹具级**求值(行首无缩进的赋值), 并对「断言期望由用例 now 镜像服务端窗口」的用例问一句**期望形态的前提在邻近时点是否翻转**(翻转就要按几何分档, 不是只认一种形态)。
