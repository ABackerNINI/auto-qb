# 变体文件批量编辑: heredoc 中文标点与切片偏移必致 JS 语法坏

> 摘要: 对 drawer_tpl/*.js 这类「字符串数组拼 CSS/JS」的变体文件做批量编辑(heredoc 重写、切片替换、python 正则改写)时, 两个高频翻车点: ①heredoc 内容里的**中文标点**(「」（）等)或行尾引号被 shell/编码吃掉, 产生残行(如孤立的 `07");`); ②切片偏移算错一行, 替换把相邻声明腰斩。两者都**不报错于编辑时**, 只在运行/加载时炸。纪律: 变体文件任何批量编辑后必跑 `node --check <file>`(加载前语法闸), 守阵(静态扫描)再做第二层。
> 触发: 批量编辑变体, heredoc 改 js, 切片替换, 残行, 语法错误, node --check, drawer_tpl, 字符串数组, 中文标点, 引号错位, 编辑后没检查语法

## 真实案例(2026-10-13, 计划 26-10-13-0811 W5)

- 用 heredoc 批量改 07/09 变体(anchTouch 退役), 切片偏移一行: 文件里残留一行孤立的 `07");` —— 编辑时零报错, 直到 `node --check` 才炸 `Unexpected token`。
- 同坑再犯: 08 变体残留 `8");` 形态残行 —— 同一修复(正则 `\n0[79]"\);\n` 清理)。
- 另一处: python 脚本给 doc-refs 追加反向声明时闭合引号位置写错一位, refs 解析失败 —— 引号闭合位置必须整行复制后再改, 不许手拼。

## 纪律

1. **编辑后必跑 `node --check src/auto_qb/webui/static/shared/drawer_tpl/<file>.js`** —— 变体文件是纯 JS(字符串拼 CSS), 语法闸一次全覆盖;
2. heredoc 内容里避免中文标点贴着引号边界; 切片替换以「整行 + 前后各一行上下文」为锚, 不数偏移;
3. 批量编辑后 `git diff --stat` 对行数变化做 sanity check(删 N 行加 M 行对不上就是切多了);
4. 静态守阵(skins/dom_panel)是第二层网, 但它扫**形态**不扫语法 —— 语法层只有 node --check 这一道, 别指望守阵兜底。
