# 变异分数与存活清单是「测试选择池」的函数

> 摘要: 窄池跑出来的存活清单, 相当一部分是「相关测试不在池里」的**假存活** —— 同一目标同一套变异, 只把池从 1 个测试文件换到 5 个, 存活数 97 → 70(−27%); 一个被判成 SURVIVED 的变异, 拿**全套件**手工改一次其实是被杀死的。判一个存活变异是不是真洞, **唯一标准**是拿全套件手工造同构变异看红不红。不先立这条规矩就投产, 第一份存活清单会被当成缺口单, 人力全浪费在伪洞上。
> 等级: L0
> 触发: 变异测试, mutmut, pytest-gremlins, 存活变异, 杀死率, 选择池, 假存活, 等价变异, 真洞, 机器提名手工确认, 变异审计

### 存活数是池的函数, 别当缺口单 (2026-10-08, 可行性调研实测)

- **触发**: 用 mutmut / pytest-gremlins 跑完一轮, 拿到一份「存活变异」清单, 准备按清单去补测试。
- **判别**: ①同一目标 `infra/utils.py`、同一套变异, 只把选择池从 1 个测试文件换到 5 个 → **存活 97 → 70**(−27%);
  ②把一个被判存活的变异(`utils.py:485` 的 `return re.compile(...)` 改成 `return None`)拿**全套件**跑 → `8 failed, 2761 passed, 4 skipped`, 其中 3 条新红 ⇒ 全套件**能**杀死它, 而 5 文件池把它报成 `SURVIVED`(且那次选中了 501 个用例);
  ③反向也要防: 池里「有测试覆盖但没杀掉」(`survived`)与「没有任何测试覆盖」(`no tests`)是**两类**, 两个工具的分母不同, 分数只能各自纵向比。
- **处置**: ①**三分类**——真洞(全套件下同构变异仍不被杀且行为确实错) / 等价变异(变异后行为在所有输入上等价, 如 `@dataclass(frozen=True)` → `False`) / 假存活(相关测试不在池里); ②**唯一判据 = 拿全套件手工改一次**——机器只负责提名, 确认必须手工; ③**选择池必须写进基线切片**(不记池的数字跨轮不可比); ④包级反而是例外:`rules/` 用「6 个定向文件」与「全 `tests`」跑到同一进度点, 杀死率只差 1 个点(52.4% vs 53.6%) —— 覆盖引导已把相关用例挑出来了, 宽池的代价落在**内存**(会打挂 WSL)而非结论上; ⑤目标不是「分数涨」, 是「包内不再有不知道为什么活着的变异」, 别设 `break` 阈值追 100%。
- **守阵**: 无自动守阵(判据是人的判断)。落地靠流程: 基线切片**强制**记「选择池」字段 + 每轮**必须**走三分类步骤 —— 见 skill `mutation-testing`「一轮的标准步骤」与「三分类」两节。

**复发**: 2 —— ①2026-10-08 可行性调研两轮实测(Windows gremlins 宽窄池对照 + WSL mutmut 全套件手工验证)同坑两证; 该轮结论: 这是变异测试**唯一**必须靠人兜的一环。②2026-10-16(global-traffic-monitor S9 **手工**红验, 非 mutmut 链路; 池 = 单个测试文件): 「鉴权绕过」突变(`webui/server/auth.py` 的密钥比较分支改成 `compare_digest(token, token)`)在 notify 单文件池里报 **SURVIVED**(rc=0) —— 该文件只断言「没带 Bearer 也 401」, 突变打的比较分支它压根没走到; 按本条判据拿**全量池**复验, 被 `tests/test_web_auth.py::test_api_requires_token` / `test_skip_local_verify_cross_site_guard_credentials_bypass` / `test_webui_backend_errlog.py::test_errlog_requires_token` 三条杀死 ⇒ 判定为假存活。**同轮增量**: 「该变异在原池不死」本身就是覆盖信号 —— 端点级守阵只测「没带凭证」时, 密钥比较分支整条无人看管; 已给该守阵补「错 Bearer 也 401」(补后同一突变在原池即可判红)。**适用面扩写**: 本条判据不限于 mutmut 分数, **手工红验**(临时 harness 逐条突变)同样成立 —— 记红验结论必须写清「池是哪个文件」, SURVIVED 一律先拿全量池复验再定性。
