# 分段 docstring 批量改写: 段边界口径必须与守阵/取证脚本同源, 先出底数再动手

> 摘要: 对「## 测试计划」这类分节 docstring 做机械批量改写时, 段边界若用 `##` 前缀匹配, 段内 `###` 小节标题会被误判成同级边界提前截断 —— 截断点之后的既有条目整段「消失」, 缺列数翻倍, 新条目插进错误小节(2026-10-22 实证: 16 文件误插 814 条, 真值 341)。边界必须只认同级 `## `(## + 空格); 动手前先跑只读取证脚本出底数, 改写脚本的逐文件数字必须与底数对上 —— 对不上即口径分歧警报, 立刻停手。
> 触发: 批量改写 docstring, 测试计划回填, 段边界, ###, 小节被截断, 缺列翻倍, 插错小节, 机械改写脚本, 底数核对, git diff 账目, 误插, 两份解析实现
**Refs:** memory-bank/tasks/26-10-22-test-plan-docstring-guard.md

## 触发

- 写脚本批量改写/回填分节 docstring(「## 测试计划」/「## 参数」等同级分节结构), 需要定位「节」的起止行。
- 守阵或取证脚本与改写脚本是**两份实现**, 各自解析段边界。

## 判别

- **病根**: 边界判据写成 `line.startswith('##')` —— `### 小节` 也命中, 段在第一个 `###` 处被截断, 而该节真正的同级边界远在其后。截断段里 listed 只算到截断点, 截断点之后的既有条目全部被当成「缺列」, 数量整段翻倍。
- **当场警报(本案救命的一道)**: 动手前先用只读 ast 脚本复验出底数(逐文件缺列数), 改写脚本的逐文件数字必须与底数一致 —— 本案复验 295 vs 首跑 814, 数字对不上即刻识破。没有底数对照时误插是**静默的**: 守阵按同一错误口径自验也绿。
- **事后账目**: `git diff --stat` 总插入行数 = 预期条目数 + 段结构行数(标题/空行), 逐文件核对; 多出来的即误插。

## 处置

- 边界只认同级: `startswith('## ')`(## + 空格), `###` 是段内小节不算边界; 段**起点**判定可放宽(含「测试计划」即认), 段**终点**必须同级口径。
- 已经插花的文件: 开工树净时 `git restore` 本轮改动后修正口径重跑; 不要在花掉的基础上做减法回退(残留判断比重跑贵)。
- 防复发三件套: ①只读取证脚本先出底数; ②改写脚本逐文件数字与底数强校验(不一致中止不写盘); ③段解析逻辑从守阵模块 import 单一来源(`guard._plan_section`), 只 import 正则不管住边界 —— 两份手抄的解析逻辑迟早分叉。
- 守阵: `tests/test_test_plan_docstring_guard.py`(`_plan_section` 钉同级边界口径, 合成源红验内建)。
