# 读源码文本的静态守卫会把变异判据洗成「全杀」，真洞清单清零

> 摘要: S4「全套件手工确认」的判据是「同构变异 **是否让某条用例变红**」。若池里含**读源码文本**的静态守卫(措辞守卫 / 数字守卫, 断言 `read_text()` 里的包内字符串/数字与冻结常数一致), 它们在挂载环境里**基线就红或本就近红**, 于是**任何** src 变异都会让它们继续红/转红 —— 机器把全部候选报成 `KILLED`(假存活), 真洞清单被洗成零, 整轮判据报废。判别: 报「全杀」时先看基线绿不绿(有既有红守卫就可能伪杀), 再 `grep` 池里有没有 `read_text`/`Path(...).read_text` 型断言。处置: **变异判据排除读源码文本的静态守卫**(显式 `--deselect`), 且 S4 前必须先跑一次基线确认 `passed`。
> 触发: 变异测试, mutmut, S4, 全套件确认, 假存活, 全杀, 幸存清零, 真洞清单为零, 读源码文本, 静态守卫, 措辞守卫, 数字守卫, read_text, 基线就红, 既有红守卫, 镜像 memory-bank 落后, deselect, 判据污染, 结构性伪影

### 74 条候选「全杀」是伪影: 两条读源码文本的措辞/数字守卫在基线就红 (2026-10-08)

- **触发**: 认领 writer.py 长尾 issue(74 条 S4 真洞候选), 在**镜像**工作树对所有 74 条逐条 `mutmut apply` → 跑**全套件** → 拿红/绿判 KILLED/SURVIVED。
- **判别**: ①**现象(错判)** —— 74 条**全部 KILLED**(假存活), 与首轮 S4 的「74 条全套件杀不掉(真洞)」结论**完全相反**; 若不核基线, 会误以为「首轮 74 条全是漏判的假存活」, 把 issue 误判成「无洞可补」直接关掉。②**根因(两层)** —— 一是镜像工作树含**另一工作流未提交的改动**(`tests/test_config.py` +309 行), 池里多出别的 issue 的守阵(属**池漂移**, 见 [mutation-pool-artifact.md](mutation-pool-artifact.md), 只是加重不是主因); 二是**主因**: 镜像 `memory-bank/` 落后 develop 一条, 使两条**读源码文本**的守卫(`tests/test_memory_bank.py::test_wording_guard_is_green_on_current_kb` / `test_number_guard_is_green_on_current_kb`, 断言包内手抄的措辞/数字与冻结常数一致)在**基线就红** —— 它们对 **src 文本**敏感(镜像里变异体写进同一份 tracking 树), 于是**任何** src 变异都让这两条维持/转红 ⇒ 机器把所有 74 条都判成「被杀死」。③**判别口诀** —— 拿到 S4 结果先问两句: **「基线绿不绿?」**(有既有红守卫 ⇒ 一切 src 变异都被它「杀」)与 **「池里有没有读源码文本的断言?」**(`grep -rn "read_text" tests/` 命中措辞/数字类守卫 ⇒ 必是结构性伪影); 两问任一为「是」, 先修判据再谈结论。④**二次验证** —— 复位镜像 `tests/` 后重跑仍全 KILLED(说明仅清池漂移不够); 实测这两条守卫在**原样 HEAD** 上也 **2 failed**(「手抄测试数字 395 处 > 冻结常数 394」), 属**既有债务**且与本轮无关; **显式 `--deselect` 这两条既有红守卫**后基线绿(`2802 passed`) → 74 条得 **71 SURVIVED(真洞) / 3 KILLED(假存活)** —— 这才是有效判据, 也**反证了 issue 的前提成立**。
- **处置**: ①**判据排除读源码文本的静态守卫** —— `--deselect` 掉(它们在变异语境下**恒红**, 不是被测行为的信号); ②**S4 前强制核基线绿** —— 先跑一次 `-x --deselect <已知既有红>` 下的全套件, 确认 `passed` 再逐条 apply; ③镜像即便 `git status` 干净, `memory-bank/` 也可能落后而带着既有红守卫, 判据须**显式**排除而不是「假设干净」; ④**别把既有红算到本轮头上** —— 原样 HEAD 复现同样 2 failed ⇒ 判为另一工作流债务(范围守恒入池), 本轮不修。
- **与既有条目的边界**: [mutation-pool-artifact.md](mutation-pool-artifact.md) 讲「**池没选到**相关测试 ⇒ 假存活(漏杀)」; 本条讲的是**反面** —— 池里混进**恒红**守卫 ⇒ **伪杀**(把真洞洗成零)。[static-guard-mutation.md](static-guard-mutation.md) 讲「静态守卫**拦不住**真突变(漏杀)」; 本条讲「静态守卫**乱杀**一切(伪杀)」。三者是变异判据在「池选择」「守卫灵敏度」「守卫基线态」三个正交面上的盲区。

**复发**: 1 —— 2026-10-08 writer-tail 实施轮一次实证(镜像池污染 + 两条既有红守卫, 74 条被伪杀成零); 靠「先核基线绿」当场抓出并改用干净判据重跑, 得有效判据 71 真洞 / 3 假存活。**为什么没提前命中**: 首轮 config S4 的池(6 个定向文件)恰好**不含**读源码文本的守卫, 没暴露这个面; 加上「镜像看着干净」的心智模型让人跳过「先跑基线」这一步 —— 故自立本条。
