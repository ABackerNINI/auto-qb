# 单文件跑 xdist 并行 -n 8 挂死

> 摘要: 只跑**一个**测试文件却用默认的 `-n 8`, 会长时间**零输出**看起来像挂死 (实测 7 分钟无一行, 只有 1 个 worker 存活); 单文件 / 少量用例一律 `-n 0` 串行, 同一批用例 24s 跑完。`test.one` 已内置 `-n 0`。
> 触发: 单文件 -n 8, 挂死, 零输出, xdist worker 卡住, test.one, 单文件慢, 并行度
**Refs:** memory-bank/tasks/26-11-09-docs-ascii-symbol-cleanup.md

## 本篇只回答

单跑一个文件时并行度该怎么选: 为什么 `-n 8` 在这里是**纯亏**, 以及怎么一眼区分「并行起停慢」与「用例真挂死」。

### 单文件 / 少量用例用 `-n 8` 跑 —— 长时间零输出, 像挂死

- **触发**: 只想验证一个测试文件 (或 `-k` 筛出几条), 直接裸跑 `uv run pytest tests/<file> -q` 或显式加 `-n 8` (2026-11-09 实测: 单跑守阵文件 7 分钟零输出)。
- **判别**: ①**零输出 + 进程还在 + 只有个别 worker 存活** —— 不是用例挂死 (真挂死会卡在某条用例且 CPU 静默), 而是 xdist 为 1 个文件的少量用例起停 worker 的开销吞掉了全部收益; ②对比例: 同一文件 `-n 0` **24s** 出结果; ③反例 —— 全量收集 (`test.quick` / `test.full`) 用 `-n 8` 是甜点 (实测 ~40s / ~134s), 并行本身没问题, **只有收集面小的时候不划算**。
- **处置**: 单文件 / 少量 `-k` 用例一律 `-n 0`; `commands run test.one -- tests/<file>` 已内置 `-n 0` 与 `--no-cov`, 直接用它就同时避开本坑与覆盖率假红坑。真需要并行收益时把范围放大到目录级再谈并行度, 不要给单文件加 `-n`。
- **守阵**: 无 —— 依赖机器与 xdist 版本的时序, 不稳定复现; `test.one` 的 `-n 0` 是单向收敛的默认值, 正确口径已固化在命令里。
- **同族**: 单文件收尾的**覆盖率门槛假红**是另一个独立坑 (一个挂死、一个假红), 两者处置都指向 `-n 0` / `--no-cov`, 见 [single-file-coverage-gate.md](single-file-coverage-gate.md); 全量并行甜点与 `-n auto` 的坑见 [parallel-run.md](parallel-run.md)。
