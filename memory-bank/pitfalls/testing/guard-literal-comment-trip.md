# 反回潮守阵按字面量判红: 注释/文档字符串里写退役标识符也会红

> 摘要: 「X 已移除/退役, 不得回潮」类守阵按 `assert "标识符" not in 源码` 扫描**整份源文本**(含注释与 docstring) —— 在同一份源码里写退役说明注释时把标识符原文写进去, 守阵立刻判红, 且报错信息极具迷惑性(明明只是注释)。写退役说明要么换措辞避开标识符, 要么守阵侧排除注释。
> 等级: L0
> 触发: 移除功能, 反回潮守阵, 退役注释, assert not in, 判红, 注释, 文档字符串, 源码扫描

### 退役说明注释踩中自己的反回潮锚(2026-10-16 实证)

- **触发**: 移除 WEBUI 流量图纵轴上限读数(qbYAxisCapText / .qb-tools-hint)时, 在 `qb_traffic_chart.js` 的原 computed 位置留注释「工具条读数 qbYAxisCapText …已随 UI 移除」, 同时守阵新钉 `assert "qbYAxisCapText" not in js` —— `test.one` 即红, 断言打印的「命中处」正是那行注释。
- **判别**: 报错行号指向**注释/文档字符串**而非可执行代码; 守阵本体是源文本字面量扫描(不做注释剥离)。
- **处置**: 二选一 —— ①注释换措辞避开标识符(本轮取此: 「纵轴工具条的『上限 …』常驻读数已随 UI 移除」, 不写 computed 名); ②守阵改扫「去注释后的源码」(成本高, 仅当标识符必须在注释里出现时用)。立新反回潮锚时顺手 grep 一下**同轮要写的注释文案**, 别让说明文档自己踩雷。
