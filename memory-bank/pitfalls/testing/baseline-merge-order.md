# 基线切片的合流序漂移: 最新切片数字与当前树实测不符

> 摘要: 基线切片的合流序漂移: 最新切片数字与当前树实测不符
> 触发: 基线, kb.baseline, 数字对不上, 最新切片, 合流, sync, 快进, 多clone, 扶正

## 本篇只回答

多 clone 并行下, sync 合流后 `commands run kb.baseline` 列出的「最新」切片数字与当前树实测**对不上**时, 怎么归因、怎么扶正; 不覆盖基线记录体例本身(那是 [testing/baseline.md](../../testing/baseline.md) 的口径)。

### 两侧各记一条基线再 sync 合流后, 最新时间戳切片反映的是另一侧旧树

- **触发**: 多 clone 并行, 两个 clone 在重叠时间窗各做一个批次并各记基线切片, 之后 `my-commit-flow.sync` 快进合流。合流后按口径读「最新一条 = 单点事实源」, 但该排序键是**时间戳** —— 较晚时间戳的切片可能记录的是合并前某一侧的树。实例(2026-11-07): 本 clone 03:45 记 5471(树 4fa6ecef), 远端 03:39 记 5479(树含 kb.nav 用例), 快进合流后最新切片(03:45)比实测**少 8**。
- **判别**: 收尾跑 `test.full`, passed 数与最新切片不符时先别归因本批 —— `commands run kb.baseline -n 5` 看次新切片: 若某条较旧切片与本轮实测**逐位同**(passed + TOTAL 行), 差值即全部来自合流进来的那一侧批次(本例 03:39 切片 = 5479 + 同一 TOTAL 行), 不是本批引入。
- **处置**: ①归因清楚后**新建一条切片**扶正「最新 = 事实源」(`kb.new baseline --total <实测>`), 差值行写明来源批次与对应切片; ②旧切片**不改**(切片写完不改, 不可变快照); ③别把合流差值误记成本批增量; ④无机检兜底(kb.baseline 只排序不验树), 全靠收尾 DoD 的 test.full 实测对照这一步。
- **复发**: 0 (复踩时在此行追加「+N (日期): 为什么没命中」, 无复发可删本行)
