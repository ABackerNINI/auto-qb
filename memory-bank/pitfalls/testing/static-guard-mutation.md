# 前端静态守阵的「字符串包含/链式正则」断言对行为突变不敏感

> 摘要: 读 JS/模板源码的静态守阵, 若断言只查「字符串在不在」或把多个弱正则串起来, 行为被突变(短路禁用/删语句)后它照样绿 —— 守阵看着活着, 拦不住真突变。升级方向: **整行活性锚定**(匹配带上下文的整行/整块, 摘一个 token 即失配) + **逐分支语句清单**(状态机每个分支的独有语句逐一断言在位); 红验突变必须与被测行为**同构**, 只打「整块删除」等于没验过。
> 触发: 静态守阵, 静态守卫, 字符串包含, in 断言, 链式正则, 突变盲区, 红验不红, 守阵空转, 短路禁用, 删语句

**Refs:** memory-bank/tasks/26-10-05-webui-danger-guards.md

### 「字符串包含」拦得住整块删除, 拦不住短路禁用/语句删改 (2026-10-05)

- **触发**: 给前端行为写静态守阵(读 JS/模板源码断言结构在位), 首版图省事用 `'this._recheckConfirm(' in src` 这类包含断言(S3 T13)或多条弱正则串起来分段匹配(S4 T24)。
- **判别**: 红验换着突变形态打: ①**短路禁用**(分支条件改 `if False and ...` / `action === "recheck" && false`)—— 调用语句还在, 包含断言**照绿**, 行为已死; ②**删改分支内关键语句** —— 守阵只锚了入口调用没锚分支体时也**照绿**。红验过「注释整块」这类粗突变不代表守阵活: 粗突变连字符串一起删自然红, 细突变留字符串改行为就漏。
- **处置**: ①**整行活性锚定** —— 正则抓带代码上下文的整行/整块再断言关键 token 在其中(T23 对 modalOk 抓 `<button ref="modalOk"[\s\S]*?</button>` 整块再断 `:disabled` 绑定在里面), 摘一个 token 即失配; ②**逐分支语句清单** —— 状态机每个分支断言其独有语句在位(T24 对 blocked/force-only/降级分支逐一列清单), 不靠一条正则包打; ③**链式正则是盲区重灾区** —— 后段在前段失配时可能匹配到别处, 每段都要「扫不到即 assert 失败」的反恒真兜底(同 assertions.md「取值锚点」条); ④**红验突变与被测行为同构** —— 想拦短路就打短路、想拦删语句就删语句; ⑤读源码前先剥注释再锚代码结构(T23 的 `re.sub(r"//[^\n]*", "", …)`), 防「注释改写误红 / 行为挪进注释不红」两个方向。

**复发**: 2 —— 2026-10-05 S3 T13(字符串包含拦不住短路禁用, 升级整行活性)与 S4 T24(链式正则对语句删改盲, 升级逐分支清单), 两棒同坑同修法, 靠红验抓出。**为什么没提前命中**: 写守阵时的心智模型是「锚住符号在位」, 缺「符号在位 ≠ 行为在位」的判别; assertions.md 既有条目讲的是断言恒真/量错对象与红验纪律, 没有静态守阵这一具体形态的条目, 路由到了也对照不上 —— 故自立本条。
