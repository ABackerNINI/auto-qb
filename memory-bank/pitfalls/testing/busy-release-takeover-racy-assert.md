# 「全占 → 释放 → 等接管」形态用例的两处计时脆弱位

> 摘要: 后台重试/接管类用例(占满候选 → start False → 释放一位 → wait_until 等后台接管)有两个假红面: ①**裸调度断言** —— start 返回后立刻断言「此刻还没 started」, 但后台线程最早 retry_min_s(注入值 0.05s)就能合法翻真, 主线程被停摆 ≥50ms(-n 8 冷启动常态)即假红, 且零信息增量(返回值已承载该语义), 应删; ②**等待时限按单跑实测定** —— 释放出的动态端口会被 OS 再分配给别的 worker 的 bind(0), 抢住期 = 那个用例服务器的存活期, 可能 >5s, 时限要按并行竞争时长定界(加宽只罚真失败路径)。issue 26-11-15-0546(该用例族第三次入池)。
> 触发: 后台重试, 接管, start False, 全占候选, wait_until 超时, 裸调度断言, not started, 释放端口被抢, 动态端口再分配, squatter, 计时敏感 flaky, retry_min_s, hr discovery

### 断言「后台线程此刻还没做到」= 对线程调度的裸奔

- **触发**: 给「同步路径失败 + 后台异步兜底」写用例, 在同步返回后、后台首拍之前插一条「此刻必须还没发生」的断言(如 `assert not srv.started`)。
- **判别**: 失败无 traceback 存档也讲不出机理时先逐行排查断言面 —— 问一句「这条断言在后台线程合法推进后还成立吗」: 后台线程首拍最早在 retry_min_s(测试注入的 0.05s)后, 主线程只要在 start() 返回到断言行之间被停摆 ≥50ms(全量 -n 8 冷启动/CI 抢占), 断言就假红。单跑大概率绿、全量偶发红是常态签名。
- **处置**: 先问信息增量 —— 同步返回值(`start() is False`)已承载「未同步绑成」语义时, 「此刻还没翻真」零增量, 直接删(issue 26-11-15-0546 实修); 真有增量要保的, 改成**有界等待反向断言**(参照 [cross-thread-teardown-assert.md](cross-thread-teardown-assert.md): 等它发生而不是赌它没发生)。
- **判别口诀**: 「not yet」断言只能钉在**没有后台线程**或**后台首拍被确定性推迟到断言之后**(事件同步, 非 wall-clock 间隔)的形态上; wall-clock 注入的 retry_min_s 推不开主线程停摆, 不算确定性推迟。

### 等待时限按「并行竞争时长」定界, 不按单跑实测定

- **触发**: 「释放资源 → wait_until 等后台接管」给 timeout 时, 照单跑实测耗时(0.3–0.7s)的几十倍随手给 5s。
- **判别**: 释放位是动态端口(此前被本用例 hold)时, close 之后端口回到 OS 动态池, `-n 8` 下会被再分配给别的 worker 的 `bind(0)`/`free_port()` —— 抢住期 = 那个用例服务器的存活期(可 >5s); 接管线程 0.1s 一拍, 抢住者一退即接管, 但 timeout 若小于抢住期就假红。
- **处置**: 加宽 timeout(26-11-15-0546 实修 5.0 → 15.0) —— 条件轮询命中即返回, 加宽只罚真失败路径, 成功路径零代价; 同时把「真失败」的判别信息留给断言消息。与本族相邻坑的分工: 探测/hold 阶段的碰撞面归 [free-port-toctou-parallel.md](free-port-toctou-parallel.md)(hold_run 单点已收编); 挂钟余量/上界形态归 [timing-tolerance.md](timing-tolerance.md); 本条管「hold 之后的释放-接管窗口」。
- **复发**: 0
