# 脚本化批量改名的两个坑(丢接收者 / 跨批漏迁)

> 摘要: 分批迁移类机械改名(W2 测试面 700+ 处)最易翻车的两处 —— ①正则替换串忘回填接收者, 整批替换全毁; ②名字按域分批 × 文件按域分批两个维度对不齐时, 该名字的替换规则不进脚本, 静默漏迁且**测试照样全绿**(旧名转发还在)。防御 = 捕获组回填 + 替换后畸形形态机检 + 全部批次提交后整仓验收 grep。
> 触发: 批量改名, 机械替换, re.subn, sed, 分批迁移, 迁移脚本, 旧名残留, 验收 grep, 漏迁, 接收者, 改名脚本, W3 删除波

### 替换串丢接收者: `re.subn(rf"\b{RECV}\.{pat}", rep, ln)` 的 rep 必须含捕获组 (W2 批次1 踩到)

- **触发**: 用「接收者限定」正则做旧名 → 新名替换时, 替换串只写新名口(如 `.web.token`)而没把接收者拼回去 —— `mgr._web_token` 全被替换成裸 `.web.token`。
- **判别**: 2026-10-01 实测 5 文件 376 处全毁且此时测试一行没跑, 纯靠 git diff 人工复核发现(plan 风险表「脚本化 sed + 人工复核 diff, 禁止盲替换」兑现); 若先跑全量会得到一片 SyntaxError/NameError, 被当成"新名口写错"浪费一轮归因。程序化判别: 替换后扫裸前导点畸形形态 `(?<![\w"'])\.(?:web\.|host\.|hr\.|ctx\.)`, 命中即整批中止。
- **处置**: 接收者进捕获组并在替换串回填 —— `re.subn(rf"\b({RECV})\.{pat}", lambda m: m.group(1) + rep, ln)`; 迁移脚本固定带「畸形形态检查, 命中即 exit(1) 不写盘」尾闸, 让这类毁坏被机检拦住而不依赖人眼(脚本样版见 26-10-01 档案 W2 进度日志)。

### 跨批漏迁: 名字的批与文件的批对不齐时, 静默漏迁且全绿 (W2 收官验收 踩到)

- **触发**: 按模块域分批迁移时(名字有名字的批, 文件有文件的批), 一个文件归进 A 批、但它的某个旧名的替换规则登记在 B 批规则表里 —— 该名字在这批被静默跳过。
- **判别**: 2026-10-01 实测三处(`test_trigger_events` 归批次4 但其 `_handle_maintenance` ×6 规则在批次2 表; `test_web` 的 `_assign_new_torrent` ×2; `test_hr` 的 `save_state` ×1), 全部测试绿 —— manager 转发层还在(W3 才删), 漏迁不报任何错; 只有对全部迁移名 × 全部目标目录的整仓验收 grep 才现形。
- **处置**: 分诊清单(plan 附件 JSON)的 `test_consumers` 既是施工图也是**验收面** —— 所有批次提交之后跑一遍整仓验收 grep(接收者级), 残留清零才算收官; 残留若属守阵/同对象断言类豁免, 必须能指到计划/档案的明确豁免条款(W2 只剩 test_qbmanager 别名守阵 9 行, 计划 §04 明确留 W3 同删)。
