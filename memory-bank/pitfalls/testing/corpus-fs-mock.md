# 语料回放 / 磁盘 mock 表

> 摘要: 脱敏要连"藏在 .gz 里的第二层 key"一起做; 窗口合并必须按序推进; 回放 config 的 tracker 段不能只信权威映射。
> 触发: 语料回放, disk.json, fs mock, 窗口合并, tracker 段, 脱敏 key, 反查表, group_exact

### 脱敏要连"藏在 .gz 里的第二层 key"一起做

- **触发**: 脱敏旁产物(以文件名 / 路径为 key 的表)。
- **判别**: `disk.json` 的**外层 hash 换了**、**内层相对路径还是真实文件名** ⇒
  真机资源名原样漏进语料, 而"凭据串扫描"与"hash 一致性自检"**都发现不了**
  (一个扫明文、一个只看 hash)。
  **判别法: 凡是"以文件名/路径为 key"的旁产物, 都要单独问一句"它的 key 过映射了吗"。**
- **处置**: 并加一条**结构性自检**: **旁产物里的每个 rel 都必须能在主产物里找到同名条目**(语料 W3 已加)。

### 窗口合并必须**按序推进**, 不能做集合净额

- **触发**: 合并增量窗口。
- **判别**: 先增后删与先删后加**结果完全不同**。
  `torrents` 要"逐 hash 后写覆盖 + 删除即刻生效"; `torrents_removed` **只在"删了且末态确实不在"时报**
  (先删后加不得报, 否则客户端会误删); `tags` / `categories` 同理按**最后一次事件**为准。
  写成 `adds - removes` 那种集合运算, 会把"窗口内加了又删"的标签**既不算 add 也不算 removed**
  ⇒ **该删的没删掉**。
- **处置**: 按序推进。

### `getattr(args, "x", 默认值)` 的默认值**只在属性缺失时生效**

- **触发**: 想给 argparse 参数兜底。
- **判别**: argparse 给了 `default=""` 时属性**存在且为空串**, `getattr` 直接返回 `""`,
  那个"默认值"**永远不会用上**。
- **处置**: 用 `args.x or 默认值` 显式兜底。

### ❗回放 config 的 tracker 段"只信权威映射"会让头号判据 `CORPUS.group_exact` **假绿**

- **触发**: 生成回放用的 config(2026-09-21 实测)。
- **判别**: 根因是 `qbmanager.py:685-690` —— **未匹配 tracker 配置的种子会 `continue` 跳过, 连带不参与归组**。
  而"权威映射"是按用户 config 的 `domains:` 字面量算伪域名, 但 auto-qb 的站点匹配是**后缀**匹配、
  两者**不总相等** ⇒ 该映射漏掉了语料里**最大的站点**(35 个种子)⇒
  真值 63 组**只分出 29 组**(`group_exact` 0 → 34)。
- **处置**: 判据变成 **"权威优先 + 统计兜底 + 只输出语料里真出现过的域名"**, 两者都不单独可信。

### ❗"集合里存的是脱敏后的值" ⇒ 拿原始字面量去 `in` 判断**永远为假**

- **触发**: 想判断"真机上有没有 `MISSING` 这个标签"。
- **判别**: 不能拿 `"MISSING" in 标签集合` —— 集合里的都是**伪名**。
- **处置**: 必须用**反查表**(伪名 → 原文)还原后再比。
  同类坑在"要拿原始值做判断的任何一处"都会出现(**标签 / 域名 / hash / 路径**)。
