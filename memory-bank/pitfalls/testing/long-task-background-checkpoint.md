### 前台长命令超 ~10min 无输出被宿主切断, 配额超限也能中途夭折

- **触发**: 前台(非后台)运行或委派预计 >10 分钟且运行期不产进度输出的长任务 —— 实例: 流量恢复基准 5000 系列语料生成(单 cell 20min+)与 run-matrix 全矩阵重跑(~50min 顺序); 子代理会话里前台长命令同样适用。
- **判别**: 命令在无报错的情况下被掐断(宿主按无输出超时回收), 或会话因模型配额超限中断 —— 现场特征是「任务没跑完但前段产出还在」。计划 26-11-21-1546 全程 3 次(宿主无输出切断 + 模型配额超限两类; S0 两次 >20min 切断见报告 26-11-21-1650 §03 本阶段观察), 因 harness 按 cell 落 JSON 而零数据损失。
- **处置**: 三件套, 写长任务前就定型: ①**一律后台跑**(ZCode `run_in_background` / 子代理派发说明里写明后台+轮询), 前台只留给秒级命令; ②**分批落盘** —— 长任务按 cell/批为单位实时把中间结果落盘(JSON 追加式, 同键覆盖/换键追加), 不攒到最后一次性写出; ③**幂等可续跑** —— 已完成批次重跑自动跳过或安全覆盖(语料生成幂等可重入), 夭折后续跑不重做前段。仓内现成范式: `scripts/bench_traffic_recovery.py`(硬约束 3「可重入: 每 cell 结果实时落 JSON, 中途失败不丢已完成进度」)与 `tests/real/.work/s5traffic/run-s5-matrix.sh`(~50min 顺序编排, 按门禁分阶段)。
