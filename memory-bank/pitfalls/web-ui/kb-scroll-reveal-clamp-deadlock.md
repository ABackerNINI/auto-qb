# 键盘跨窗滚动: scrollTo 被窗口化重渲钳位吞掉, 补正循环「只等 DOM」干等到死

> 摘要: `_kbScrollRowIntoView` 窗口化分支初发 `scrollTo(0, 折叠行y)` 后, 若窗口化重渲中途文档高度塌缩, scrollY 被浏览器**钳到底部残位**(不是原目标); 切片按残位继续渲染原位置(尾部), 目标行**永不**进 DOM。2026-11-10 修的跨帧补正 `revealWhenRendered` 只做「等目标行出现」这一件事, 行不出现就干等 deadline 然后按 P1-2 永久放弃 —— 页面停在错误位置, 键盘导航视觉失效。等待面加窗无效(行根本不会出现), A/B 两档窗宽红率同量级是判据。
> 触发: 键盘滚动不生效, Home End 不回顶, scrollY 钳位, 残位, 窗口化重渲, 文档高度塌缩, revealWhenRendered, 补正循环只等条件不重发动作, kb-cursor 类消失, 光标行未渲染, pollBand 卡死, P1-2 退避, deadline 干等
**Refs:** memory-bank/issues/26-11-18-0308-test-e2e-kbd-scroll-band-shard-flake.html

### 「补正 = 等目标出现」是半套修法, 动作本身要每帧重发 (2026-11-19, 已修)

- **触发**: 键盘 Home/End 跳折叠行(窗口化切片外) → `scrollTo(0, pre[idx] + winTop - vTop - 8)` 发出 → 同帧/邻帧窗口化重渲把文档总高短暂塌缩(scrollY 超出瞬时 maxScroll)→ 浏览器钳 scrollY 到底附近残位(每个失败现场各钳一个值, shard 负载下三现场实测 sy=18232 两例 / 20054 一例, 均在 End 落定位附近)→ 重渲完成后切片按**残位**渲染尾部, 目标行(首行)不在窗内。shard 并发负载放大重渲时长, 残位概率上升(e2e 同形态 240 例 39 红); 低负载下初发滚动恰好在塌缩窗之外, 几乎不复现(W3 采样 81 例 0 复现的原因)。
- **判别**: e2e 失败签名 = pollBand 超时「光标未到极值行, **光标行=未渲染**」(不是「已到极值行但被遮 N px」—— 那是几何校正问题, 另一族)。vm 现场三件套钉死: ①kbCursor 指向正确(filteredTorrents[0]); ②`_rowPre` 前缀和长度完好(P1-2 陈旧退避未触发); ③`kbInDom=false` + scrollY 停残位 + 切片 r0 在尾部。三件齐全 = 卡死态而非慢收敛; A/B deadline 窗宽(1s vs 5s)红率同量级(24/120 vs 15/120)是「窗宽无关」的机检证据。
- **处置**: 补正循环**每帧幂等重发动作**——窗口化分支的滚动封成 `rescroll` 闭包(目标位由闭包捕获, 同式重算), 行未进 DOM 时每帧重发(同值 scrollTo 不产生滚动 = 幂等), 行进 DOM 那帧 reveal() 校正收尾; deadline 放宽到 5s 只是慢收敛余量(每帧已有真实推进)。两条配套守卫缺一不可: ①实例级**代际令牌** `_kbRevealGen`(方法入口自增, 循环每帧核对)——否则重入(快速连按/回执重入)时并存循环每帧各自重发, 先按键的目标行进 DOM 后把页面从末键目标拽回, 「单发一次」旧语义的末键胜被改成首键胜; ②**用户滚轮/触摸退避**(每循环独立监听闭包对 + disarm 存引用, 并存循环互不摘对方)——循环活着期间用户手动滚动即 P1-2 提前放弃, 不逐帧劫持视口。一般纪律: **重试循环里「等条件满足」和「重发动作」是两件事, 2026-11-10 的修法只补了前者; 动作幂等(同值不产生效果)时每帧重发是安全的, 不幂等的动作才需要等条件**。
