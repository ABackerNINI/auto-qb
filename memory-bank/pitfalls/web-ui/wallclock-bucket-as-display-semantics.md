# 挂钟桶面把「显示语义」错当「存储结构」: 三台时钟分裂靠持有面糊裂缝, 换显示语义被迫重写整层读侧

> 摘要: 流量图 raw 段窗曾把样本数据栅格化进挂钟桶再展示(归桶/桶值缓存/尾桶持有/封口/回填五件套), 桶面一旦成型就被当成「数据的结构」—— 后续每次显示语义小改(桶宽表/补尾格/rewin 判据/轮询节奏)都要动这套读侧机器, 而三台时钟(桶栅格锚挂钟 / 样本按采样节拍 / 前端轮询节拍)的裂缝只能靠持有面(held 克隆)糊住。26-11-18-0037 换代才看清: 存储 v4 天文件本来就是逐样本槽, 桶化只是读侧表现层 —— 表现层语义与数据结构分层, 换显示语义(挂钟桶 → 样本分组点列)本不必动存储, 只该动装配纯函数。教训的普适形态: 数据结构只存测量事实, 一切「为了显示而做的变换」留在装配层。

### 把「为了显示而做的变换」留在装配层, 别让它长进数据链路

- **触发**: 给时间序列数据做展示时, 直觉方案是「先按墙钟栅格分桶/对齐, 下游好画」—— 桶化一旦实现(归桶函数/桶缓存/桶键派生), 后续需求(改桶宽/改窗口/改节拍)就默认「数据就是桶」, 在桶面上继续叠逻辑。实证(plan 26-11-18-0037): 流量图 raw 读侧从 26-10 到 26-11-17 连续三代在桶面上打补丁(桶宽=采样整倍恒 ≤500 桶 / 点位归属归桶 / holding 尾桶 / held 有界漏采回填 / 封口桶不可变), 直到用户报尾端失真才回溯出根因是桶面把显示语义错当存储结构。
- **判别**: 三个信号 = ①同一份数据在存储层与读侧各有一套时间语义(存储是样本 ts, 读侧是桶键), 读侧要维护「桶 → 样本」的归属/对齐机器; ②显示需求的小改动(轴粒度/窗口/节拍)频繁触碰读侧对齐机器而不是装配函数; ③出现为糊时间裂缝而生的「造值」面(持有克隆/回填)—— 时钟源不止一个(墙钟/采样节拍/轮询)时, 栅格化必然产生「桶内没有样本」的时刻, 于是有人提议复制相邻值填上。三信号齐 = 表现层已经长进地基, 该换代而不是继续补。
- **处置**: ①先问「存储本来的粒度是什么」—— 本案存储本来就是逐样本槽, 桶化只是读侧表现, 换代只重写装配纯函数(样本分组点列), 存储零迁移; ②表现层语义(桶化/分组/内插)与数据结构(样本槽)分层: 装配 = 纯函数(入参只有数据与时窗, 无时钟, 幂等), 缓存做在装配结果上(增量游标 + 前缀和), 显示语义再换也不动缓存的地基; ③换显示语义时接受「读侧机器整体退役」而不是逐桶打补丁 —— 沉没成本(26-11-15-1104 刚收口的桶面)不是保留理由(D2 拍板明确接受推翻)。
- **守阵**: 装配电池 tests/test_traffic_group_assembly.py(24 用例: 逐位分组/字节守恒对账/显式空值/超预算标注)+ V4SeriesGroupCache 与冷算逐位等价断言(tests/test_traffic_group_cache.py)+ 旧桶面符号全文件零残留 grep 复查(R6 先例)。
