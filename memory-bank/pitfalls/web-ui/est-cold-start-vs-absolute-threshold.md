# 千级首访改估算开窗后, 占位总高/滚到底的绝对阈值判据必须按行数分档

> 摘要: 千级首访改估算开窗后, 占位总高/滚到底的绝对阈值判据必须按行数分档
> 触发: 估算行高, 渐进量齐, 占位总高, 滚到底, e2e 绝对阈值, ROW_WIN_EST_MIN, 首访长任务, 总高不塌陷
**Refs:** memory-bank/issues/26-11-02-0902-perf-webui-first-visit-rowh-measure.html, memory-bank/tasks/26-11-02-webui-large-filelist-perf.md

### 把「首访占位总高与全量渲染逐像素相等」写成绝对阈值, 引擎一旦改成千级估算开窗就红

- **触发**: 窗口化引擎的冷启动策略从「全量渲染 → 量齐」改成「千级及以上首帧用估算行高开窗、随滚动渐进实测」(issue 26-11-02-0902 修法①)时, `e2e/perf.spec.mjs` 的「占位总高 Δ<50px」「滚动到底 |Δ|<200px」两条绝对阈值仍按精确冷启动语义写 —— 3000 行档实测 Δ -26701px / 滚到底 +27727px, 4 条用例(2 用例 ×2 皮肤)全红, 而默认 300 档全绿(低于 `ROW_WIN_EST_MIN`, 走原精确路径)。
- **判别**: 默认档 `commands run dev.e2e -- e2e/perf.spec.mjs` 全绿, 但 `E2E_TORRENTS=3000` 时报「窗口化 X vs 全量 Ypx(Δ …)」与「滚动到底不塌陷 …」; 且差值是**单向**的(首访低估、滚到底后增长), 不是塌陷/行间距失真 —— 对照全量渲染总高与 `getComputedStyle(container).rowGap` 实测值即可分离「估算收敛期」与「布局 bug」。
- **处置**: 判据按行数分档(`ROW_WIN_EST_MIN` 真值单点在 `app.js`, spec 内镜像常量仅作分档): **2026-11-02 二轮起阈值为 200(与 `ROW_WIN_MIN` 合并, 精确冷启动档消失)**, 低于 200 保持原绝对阈值(win==full 平凡恒等); 200 及以上「占位总高」只做粗界守阵(比值 0.5~1.5, 防 ×2 / 接近 0 的估算失真), 「滚到底」按**比例**禁塌陷(|Δ| < before×25% —— 收敛方向不定, 见复发行)。**不要指望「滚几段就能收敛到 2%」**: 全局均值只采样到走过的窗口, 方向偏差仍 13%~14%(实测 216538 vs 190979、首访 164278 vs 190979), 真要收敛须把全表滚一遍(3000 行 × 视口 24 行 ≈ 125 步), 代价不划算。也不要因为有红就删断言或放大到无判别力。
- **守阵**: `e2e/perf.spec.mjs` 两条断言的 `TORRENTS >= ROW_WIN_EST_MIN` 分档分支 + 「首访路径指纹」用例(gBR<150, 防误退回精确冷启动; 默认 300 档即实跑) + node 探针电池边界两断言(n=199 off / n=200 估算开窗)。
- **复发**: 1 (+1 2026-11-02 二轮): 分档分支自己也没逃过同类病 —— 「滚到底」估算档分支按「总高只会增长(补量不塌陷)」写单向判据, 但该分支在旧阈值 1000 下默认 300 档不可达, 从未被真实跑过; 阈值降到 200 后默认 300 档首次踩进即红(实测 22887→21591px, Δ-1296: 收敛方向取决于首屏采样行高与全局均值的相对高低, 可涨可缩)。教训: **分档分支落地时, 分档点两侧的真实可达档位(含默认档!)都要实跑一遍** —— 「分支在默认档不可达所以不用验」正是它滋生的缝隙; 没命中原因 = 写判据时只验了千级档(3000)没验 300。
