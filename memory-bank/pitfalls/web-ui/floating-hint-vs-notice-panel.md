# 陈述型提示别做页面浮层 (遮挡自动化测试截图)

> 摘要: 前端的"告知类"提示(陈述事实 / 排查路径, 不是故障)若实现成**运行时注入 body 的 fixed 浮层**(横幅 / 气泡 / 角标条), 会有两个固定代价: ①压在页面内容上, 用户"先关掉才能看"; ②**每次自动化测试都弹** —— 测试用全新浏览器上下文, 提示自身的"已提示"去重标记(localStorage/sessionStorage)在那一刻是空的 ⇒ 每张截图都被盖一截, 且截图差异比对(若有)会因它抖动。判据: **提示是不是错误?** 不是错误 ⇒ 进状态栏入口的**通知面板**(收起态 + 未读徽标), 不做浮层。
> 触发: 想给用户"提示一句", 加提示横幅, 弹一次就够的提示, 测试截图被遮挡, 每次跑测试都弹, 截图里有浮层, 空存储提示, 列偏好提示, toast 之外的提示, 陈述型通知, 告知类提示, _recordNotice

**Refs:** memory-bank/tasks/26-10-09-webui-notice-panel-exit.md

## 触发

要给用户一个"告知"(不是故障): 「本地址还没有列偏好记录」这类事实 + 排查路径、环境态说明、一次性上手提示。直觉做法是往 `body` 插一条 fixed 横幅 —— 这条直觉在**有自动化测试**的项目里必然付代价。

## 判别

- **是不是错误?** 面板(通知/日志)语义要按"最坏条目"命名 —— 一旦装进陈述型告知, 名字里的"错误"就会把告知读成故障。本文档记录的这一例因此连带把面板从「错误历史」改名「通知」。
- **它在测试里会弹几次?** 提示若靠 localStorage/sessionStorage 里的"已提示"标记去重, 那么在**全新浏览器上下文**(Playwright 每个 test 一个新 context、无痕窗口、清站点数据的环境)里标记恒为空 ⇒ **每次跑都弹**。2026-10-09 用户实报: 「每次测试时都会触发, 会遮挡测试截图」。这是"标记去重"的固有形态, 不是 bug。
- **它是"过路信息"还是"内容"?** 浮层会盖住页面主体(详情面板 / 表格 / 图), 用户要么被迫先关掉、要么带着遮挡读。收进面板则零成本。

## 处置

- **陈述型提示一律走通知面板的收集单点**(本仓 = `shared/ui_feedback.js::_recordNotice(text)`): 只入会话内环形缓冲 + 计未读, **不弹任何浮层**。面板默认收起、只在状态栏入口留一个未读徽标 —— 不占版面、不进截图。
- **不要把陈述型条目塞进 toast 通道**: toast 的"入历史"是按 kind 白名单(`ERR_HISTORY_KINDS`, 只收 error/timeout)做的, 为了让一条 info 入面板去放宽白名单, 会把**全站 info toast** 一并灌进面板。新单点比放宽白名单划算得多。
- **条目 id 要错开命名空间**: 面板条目来自三方(toast 数字 id / `b`+后端 seq / `n`+前端 seq), 收集单点按 id upsert; 撞号会把两条无关条目并成一条, 且**静默**。
- **kind 要低级别**: 陈述型固定 `info`(中性灰点), 红/黄点留给真故障 —— 否则"看有红点"这条用户判据失效。
- **守阵**: 钉"提示体里不得出现 `document.createElement` / `appendChild` / `position:fixed` / `z-index:9999`" —— 静态扫描拦得住形态回退, 拦不住"又新写了一个浮层", 故同族守阵还要钉**出口调用**(提示必须出现 `_recordNotice(`)。
