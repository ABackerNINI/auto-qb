# 表面底色族单点(表头异色带 / 吸顶落影泄漏)

> 摘要: 同一个视觉区域(面板 / 表区)的各层表面(列头底、行板底、悬停、落影)若被多处各写一遍——表头 `--bg-card`、行板 skin 卡底 `--bg-row`、行板透明露面板、页面级吸顶列头的 `--shadow-1` 落影——就会在主题切换时露出肉眼可见的色带 / 横条, 工具与截图都不易定位, 只有像素采样能实锤。修法是把该区域的表面色收口成**一个令牌族单点**(shared/dt_table.css: 表头 `--tbl-head-bg`、行板 `--tbl-face-bg` 默认 `var(--bg)`, 落影 `box-shadow:none`), 变体只声明密度/几何令牌; 页面级组件的观感语义(吸顶列头=「第二根导航」)被嵌入面复用时, 页面观感(box-shadow/sticky top)必须显式剥离。
> 等级: L0
> 触发: 表头异色, 异色背景, 色带, 横条, 表头下方颜色不一样, 背景不一致, 主题下表头发白, 抽屉表格底色, --bg-card, --bg-row, box-shadow 落影, 吸顶列头阴影, 三皮肤观感分叉

## 症状与取证(2026-10-13, 计划 26-10-13-0811 W6)

- 用户报「表头 IP/地址下方有异色背景」并给出两滴取色: rgb(253,254,255) vs rgb(242,246,251)。frost 主题下分别对应 `--bg-card` 与 `--bg`。
- 像素级采样(frost / prism / 07 面)实锤三层各算:
  - 表头 `.group-head` → `--bg-card` = rgb(253,254,255)(变体手写 `background:var(--bg-card)`);
  - 行板 `.group-row` → skin 卡底 `--bg-row` = rgb(247,250,253)(变体没重置背景, 主列表的行语言漏进抽屉);
  - 抽屉面板/页面 → `--bg-card` / `--bg` = rgb(253,254,255) / rgb(242,246,251)。
- 三块表面在主题下各取各值 → 表头下缘与行区之间必然出现一条缝色带; 换主题(frost 亮/dark)色差方向还会反转, 修死值永远修不完。

## 第二形态: 页面级观感语义泄漏(症状 2「速度列下方异常横条」)

- 三皮肤 `.group-head` 都声明 `box-shadow: var(--shadow-1)` —— 那是**主列表页面级吸顶**的「第二根导航」观感(prism views.css 有设计注释)。
- 抽屉表格面复用同一个 `.group-head` 类, 这条落影原样带进来: 表头直接贴着行区, 1px 模糊落影读作「表头下面多了一条横条」, 用户按列名指认(速度列)但其实全宽都有。
- 教训: **类复用 = 观感语义复用**。页面级组件(吸顶/落影/悬浮抬升)被嵌入面板时, 嵌入面必须显式声明剥离(box-shadow:none / 重定 sticky top), 不能指望"面板里应该没有"。

## 修法: 令牌族单点(W6 定案)

- 新建 `shared/dt_table.css`(三皮肤 index.html 在 dialogs.css 之后挂载):
  - 表头底 `var(--tbl-head-bg, var(--bg))` —— 与主列表吸顶列头同一「页面面板」语义;
  - 行板底 `var(--tbl-face-bg, var(--bg))` —— 同族, 表内(表头/行板)零色缝;
  - 行悬停 `--bg-hover` 收编; 表头 `box-shadow: none`(页面级落影不进抽屉);
  - 密度令牌 `--tbl-head-minh / --tbl-row-minh` 由变体声明值, 未声明 min-height:0 不生效。
- 变体只留个性(吸顶 top 补偿 / 字号 / 状态行底色), 不再手写任何表面底色。
- **守阵**: `e2e/dt-table-face-bg.spec.mjs`(四面×双皮肤: 表头背景==页面底 + 行板==表头 + 表头零落影)+ `test_drawer_tpl_table_face_bg_single_point`(--bg-card 禁回潮 / 令牌在位 / 挂载恰一次)。

## 方法论: 这类问题为什么总修不死

- **眼见为实要落到像素**: 截图目测 + computed style 各说各话, 最终仲裁是 `page.screenshot` → 画布 `getImageData` 逐点采样(getComputedStyle 只能告诉你声明值, 不能告诉你哪两层叠在一起)。
- **主题令牌是唯一出口**: 任何"写死一个接近色"的修法都在赌主题不换; 正确动作永远是「这个区域的表面族归谁管」——归到一个文件、一组令牌, 各层只引用。
- 红绿双验必须**红在目标断言**(本例: 首跑 8/8 红, 全中「表头背景 == 页面底」)——红验设计见 pitfalls/testing/red-verify-must-hit-behavior.md。
