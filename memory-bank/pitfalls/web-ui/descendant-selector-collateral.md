# 容器级后代选择器误命中后加的子元素

> 摘要: 容器级后代选择器误命中后加的子元素
> 等级: L0
> 触发: 给已有容器新增子元素后图标错位/样式怪

### 给既有容器新增子元素后, 容器级后代选择器把新子元素一起钉进老定位/样式

- **触发**: 容器里已有一条为首个子元素写的后代选择器 (如 `.gsearch svg` 本意只钉放大镜),
  之后往同一容器加第二个含 svg 的子元素 (如清词按钮) —— 新子元素被老规则误命中, 套上
  `position:absolute; left/top` 等本不属于自己的声明, 自己规则里没显式覆盖的属性全部漏进来。
- **判别**: 新子元素渲染错位/不居中但自身 CSS 看着没错 —— 开 devtools 看该元素的
  Applied Styles, 会有**不属于它的容器级选择器**出现在列表里; 或用
  `getBoundingClientRect` 量子元素中心 vs 父按钮中心 (dx/dy 非 0 即被钉走)。
  结构守阵 (查节点在不在) 拦不住这类, 波及面在样式不在 DOM。
- **处置**: 把容器级规则收窄成**直接子代** (`>`), 只钉它本意那一个 (`.gsearch > svg`);
  新子元素的 svg 保持流内由父 flex 居中 (auto-qb `.bt.icon` + `.ico` 同机制, 不给图标
  单独 absolute)。改完真机量 dx/dy 双 0 收口。
- **守阵**: `tests/test_kb_nav.py::test_gsearch_clear_button` 断言壳 CSS 里
  `.gsearch svg` 不存在且 `.gsearch > svg` 在位。
- **复发**: 0 (复踩时在此行追加「+N (日期): 为什么没命中」, 无复发可删本行)
