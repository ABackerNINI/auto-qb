# 行高实测表只量在场行: 滚出窗口的行存值陈旧, 窗口滑动 pad 超量替换内容跳数px

> 摘要: 行高逐行实测表 `_rowHs` 只在行渲染在场时更新 —— 行高变过且已滚出窗口的行存值永不修正; 窗口滑动越过它时 padTop 按陈旧存值超量替换, 渲染行整体跳 ±数px。e2e 像素级判据(T7 前置带 / S-A 公式落点)骑在漂移阈值边缘, 随机器环境两侧摆, 呈「整跑红/过滤绿」或「单跑也红」的假 flake 形态。
> 触发: 陈旧行高, 行高存值, 窗口滑动跳变, pad 超量替换, 内容跳数px, _rowHs, _measureRowH, 滚出窗口, 视觉跳变, 像素判据, 预热滚动, preheat

## 本篇只回答

行窗口化引擎(`columns_grid.js`)在「行高动态变化 + 行滚出窗口」下的 pad 漂移机制: 怎么判别、怎么在测试里消化(预热滚动)。产品侧的存值修正方案不入本篇(见 issue 26-11-15-0332)。

### 滚出窗口的行存值陈旧, 窗口滑动时 pad 超量替换让内容整体跳数px(像素判据呈假 flake)

- **触发**: ①页面首渲量齐全表(千级以下一轮全量渲染量齐)后, 某些行的实际高度变化(字体交换/内容重排, 机器环境相关)发生在行已被窗口化收走(滚出窗口)之后 —— `_measureRowH` 每拍只量 `querySelectorAll` 到的**在场行**, 存值永不修正; ②此后任何一次滑过该行的窗口下滑都会触发: padTop 按 `pre[start]`(存值累加)超量替换, 实际只该替换真实行高。e2e 里凡「深滚到中段 → 像素级对齐/让位 → 断言 ±2~4px 窗」形态的用例都在暴露面上(drawer-dock-stability T7/S-A 实证)。
- **判别**: 插桩逐帧采样对齐段 —— scrollY 精确落位、参照锚(列头底/状态栏顶)不变, 但行顶在**一次渲染 tick**(~33ms)内跳 ±数px(LayoutUnit 1/64 精度); 同帧 padTop 阶跃、`rowHVer` +1; `data-fx` stamp 为空(排除 fx 入场脚手架)。取证实录(2026-11-15, T7 对齐段): scrollY 10011=9934+77 恰等, padTop 9063.844→9133.453(+69.609), 行顶 159.375→163.203(+3.828 = 存值 69.609 - 实际 65.781)。
- **处置**: 测试侧在像素级对齐/让位滚动前**预热行窗口化**: `preheatRowWindow(page, dist)`(e2e/drawer-dock-stability.spec.mjs)—— 向下滚 dist 再滚回原位, 各等一次 `waitListSettled`; 途经区间的陈旧存值被回程逐帧实测替换刷成新鲜值, 之后窗口滑动的 pad 替换是等高精确替换, 对齐落点/让位终值恢复 ±0.5px 可依赖。dist 须 >= 该用例的最大后续滚动量(T7 对齐 ~792 / S-A 让位 ~566, 取 900)。判据本身不放松(前置带/公式窗原样)。
- **守阵**: 无专项机检 —— 这类漂移幅度环境相关, 静态守阵钉不住; 行为面由 drawer-dock-stability T7/S-A 的前置断言自然暴露(修前单跑红)。产品侧修正待 issue 26-11-15-0332 落地时补。
