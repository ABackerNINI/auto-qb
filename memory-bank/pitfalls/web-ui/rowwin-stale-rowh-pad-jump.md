# 行窗口化 pad 替换不是等高精确替换: 陈旧行高 + 占位基准漂移, 窗口滑动内容跳数px

> 摘要: 行窗口化引擎按 `_rowHs` 逐行存值累加前缀和, padTop = `pre[start]/z - gap`。两根因让「pad 替换」不等于「等高替换」: ①`_rowHs` 只在行渲染在场时刷新, 行高变过且已滚出窗口的行存值永不修正; ②占位基准(已实测行全局均值)每量到一行就微动 δ, 而 pad 区上百行未渲染行全按它估高, 被连坐搬 δ×N。两者都表现为 scrollY 不变、渲染行整体跳 ±数px, e2e 像素级判据(T7 前置带 / S-A 公式落点)当场撞红。
> 触发: 陈旧行高, 行高存值, 窗口滑动跳变, pad 超量替换, 内容跳数px, _rowHs, _measureRowH, 滚出窗口, 视觉跳变, 像素判据, 占位基准, 估算漂移, _rowH, preheat, 预热滚动

## 本篇只回答

行窗口化引擎(`columns_grid.js`)在「行高动态变化 + 行滚出窗口」与「未渲染行按均值估高」两种情形下的 pad 漂移机制: 怎么判别、产品侧怎么修、守阵钉在哪。产品侧修复已随 issue 26-11-15-0332 落地(两根因同批处置)。

### 同症两根因: 陈旧行高与占位基准漂移, 窗口滑动时 pad 不是等高替换

- **触发**: 两根因都会让 scrollY 精确落位时渲染行整体跳 ±数px, 但成因不同, 别只修一根就收工。
  - **根因一 · 陈旧存值**: 页面首渲量齐后, 某些行的实际高度变化(字体交换/内容重排, 机器环境相关)发生在行已被窗口化收走(滚出窗口)之后 —— `_measureRowH` 每拍只量 `querySelectorAll` 到的**在场行**, 存值永不修正; 此后任何一次滑过该行的窗口下滑都会触发: padTop 按 `pre[start]`(存值累加)超量替换, 实际只该替换真实行高。e2e 里凡「深滚到中段 → 像素级对齐/让位 → 断言 ±2~4px 窗」形态的用例都在暴露面上(drawer-dock-stability T7/S-A 实证)。
  - **根因二 · 占位基准漂移**: 未渲染行按 `_rowH[kind]`(已实测行全局均值)估高。从前每量到一行新行就重算均值 → δ; pad 区里可能有上百行从未渲染、全按这个均值估高 → padTop 被整体搬 δ×未量行数。取证(2026-11-16, flux 深滚): 106 行未量、均值 65.770→65.806(δ=0.036) → 渲染行整体 +3.8px。**只修根因一时 flux T7/S-A 仍红 5px**, 正是这一根。
- **判别**: 插桩逐帧采样对齐段 —— scrollY 精确落位、参照锚(列头底/状态栏顶)不变, 但行顶在**一次渲染 tick**(~33ms)内跳 ±数px(LayoutUnit 1/64 精度); 同帧 padTop 阶跃、`rowHVer` +1; `data-fx` stamp 为空(排除 fx 入场脚手架)。取证实录(2026-11-15, T7 对齐段): scrollY 10011=9934+77 恰等, padTop 9063.844→9133.453(+69.609), 行顶 159.375→163.203(+3.828 = 存值 69.609 - 实际 65.781)。**分根因**: padTop 阶跃且 `_rowHs` 有键被改 = 根因一; padTop 阶跃但 `_rowHs` 键值全没变、只有 `_rowH[kind]` 自己动了, 且跳变量 ≈ δ × (start 之前未渲染行数) = 根因二(别误判成根因一没修干净)。
- **处置**: 两根因同批产品侧修正。
  - **根因一** = `_reprobeRenderedRowH(kind, sig)`: 在 `_rowWindow` 重建 `pre[]` **之前**、所有早退之后调用 —— 此刻 Vue 还没 patch(`beforeUpdate` → render → patch 的顺序), 旧窗口的行仍在 DOM, 给它们量最后一发真值顶掉陈旧存值, 同一拍的前缀和就按真值累加。约束: **只刷已有键**(新增键 / 全局均值 / `_rowHVer` / `_rowHSig` / `_winMeasured` 一律留给 `updated()` 的 `_measureRowH`, 在 render 途中改响应式态会自激重渲); **零全表作废**(不删 `_rowHs`、不翻 `_winMeasured=false`、不扩签名 —— 踩 rowh-sig-and-transition-geometry 的坑就是 3000 行全量重渲 5.9~8.4s 长任务, 切页/关抽屉卡死复发); **同拍 sig 去重**(一拍里 `memberPadTop` / `memberPadBottom` / `winMembers` 各调一次 `_rowWindow`, 几何不变只量一遍, `_rowProbeSig` 是非响应式纯缓存, 在根 `created()` 初始化); **抽屉 `content-visibility:auto` 守卫**(被跳过行的 gBR 返回 `contain-intrinsic-size` = 27 内容盒 + 边框 = 28, 采信会把真值改坏, 必须先过 `checkVisibility({ contentVisibilityAuto: true })`); 探测位选择器与 `_measureRowH` 共用 `ROW_H_MAIN_PROBES` 单点(两处各写一份 = 改一处漏一处, 那个 kind 又留一批永不修正的存值); 三 kind 必须各自带 `[data-table="torrent"/"group"/"detail"]` 收窄 —— 剧集页的 `.group-row.show-row` / `.ep-row` 也带 `data-key`, 裸 `.group-row:not(.torrent-row)[data-key]` 会把**别座表的行**记成 group 行高, 并把 `_rowHAvgOf("group")` 污染成混合均值(冻结后的占位基准正是从这个均值来的, 脏了就一直脏); 另外 `h <= 0` 一律不采信(视图被 v-show 收走那一瞬 gBR 报 0, 写进去等于把该行真值抹成 0), 去重签名只在真量到行之后才落盘(空探先记账 = 同几何后续永不重探)。
  - **根因二** = 均值只在「首访量齐那一拍」校准, 之后**冻结**: 门只有两支 —— `!_winMeasured[kind]`(首校)与 `!(this._rowH[kind] > 0)`(存值非正 = 还没校准)。后者是「冻结不许冻结在无效值上」的兜底: 视图被 `v-show` 收走时行仍在 DOM、gBR 全报 0, 均值会校准成 0, 若就此冻住则切回来 est 恒回落成 `ROW_WIN_EST_H` 常量(42/44), 未量行 pad 恒短。新量行只把自己那一项从估算换成真值, 不再连坐搬整段 pad。**已知边界(刻意不做)**: 冻结后基准不随「行集变了 / 数据刷新了」重算 —— 想重算就得把 `_rowHs` 里上一批行的键剔掉(否则均值仍是被旧 population 稀释的混合值, 那是假的「重校」), 而按 kind 剔键对 member 是灾难(成员列表是逐组子集, 换组剔一次 = 每次展开都重新实测); 权衡后选稳定, 估偏只影响「从未渲染过的行」的占位与滚动条长度, 而基准一动滚动中的内容就整段跳(本 issue 要修的正病)。列集合/窗宽变化仍会翻 `_winMeasured=false`, 下一拍照常重新校准, 不残留旧几何。**运行时改 root zoom 不走本门, 走比例重标**(issue 26-11-16-0716 已修): 基准是 gBR 视觉 px 量值而重校签名只看布局宽度代与可见列数, zoom 门恒关 —— 修法不是删键翻量齐态(zoom 是全表一致缩放, 那等于白付 3000 行全量重渲), 而是 `_measureRowH` 开头比对 `_rootZoomOf()`(body gBR 宽/offsetWidth 比值实测单点, 与 `_winSigExtra` 缩放令牌同源)与上次校准基线 `_rowHZoom`, 变了全表乘 `zNew/zOld` 原地平移 `_rowHs`+`_rowH`(不删键、不翻 `_winMeasured`、不动冻结门), `_rowHVer` bump 一次。三个反直觉点: ①`_rootZoomOf` 量不到必须返回 **null** 不许回落 1 —— 回落 1 会把「body 暂时读不到」误判成「缩放回 1」, 1↔z 抖动反复重标整表; ②出窗最后一探要有**过渡拍让路**守卫 —— zoom 刚变、重标块还没跑的拍, 「旧缩放存值 vs 新缩放 gBR」的系统性差值(=行高×(1-z), 远超 0.5px 容差)会被当行高真变写进 `_rowHs`, 随后重标再乘一遍 = 双重缩放, 被改坏的行不再进窗就永不修正; ③e2e 判据里 `document.scrollHeight` 随 zoom 报**视觉 px**(与 gBR/scrollY 同空间) —— zoom 1→0.9 后正确总高 = 0.9×缩放前, 不是「前后相等」; 修复前 pad 视觉高不随缩放变(重标没发生), 判据写成「前后差小」永远绿。抽屉内容桥**不冻结**(挂 `content-visibility:auto`, 首拍是 intrinsic 28, 需逐拍收敛到真值 27; 重标块的乘法同样覆盖它的存值与基准)。
  - **测试侧绕过退役**: `e2e/drawer-dock-stability.spec.mjs` 的 `preheatRowWindow()` 删除 —— T7/S-A/S-C 改为**不预热**直接判, 任一根因回潮即撞红(预热只是把途经区间量一遍, 掩盖而非修复产品面)。位移判据两侧都必须用**分数精度**(采样器 `rowBf` / `rowTf`, 基线直接取 gBR 原值): 采样帧的 `rowB`/`rowT` 是 `Math.round` 过的整数, 拿它跟分数基线比会带最多 0.5px 量化偏置 —— 实测同一份代码基线 482.0625、落定 481.0625(真实位移恰 1.0px, 是「选中行开抽屉自身箱变」, 修复前 HEAD 上同样存在), 取整后读成 -1.0625 直接假红; 分数比较下 1px 恰读 1、2px 真回潮读 2。
- **守阵**: 静态 `tests/unit/test_webui_static_dom_page_layout.py::test_frontend_outgoing_rowh_reprobe_guard` —— 调用点位置(所有早退之后、pre[] 之前)、只刷已有键(`old === undefined` 必须 `continue`)、零全表作废(禁 `delete` / `_rowHVer++` / `_winMeasured` / `_rowHSig` / `viewMode` / `_winResize++`)、同拍 sig 去重、抽屉守卫、探测位单点(`ROW_H_MAIN_PROBES` 的 group 选择器不许退回裸 `.group-row:not(.torrent-row)`)、冻结门恰两支 + 已删的 `_rowHFrozen`/`_rowHListSig` 不许回潮、抽屉基准不冻、`created()` 初始化 `_rowProbeSig`。行为 `tests/unit/test_webui_static_r4_node_batteries.py::test_r4_outgoing_rowh_reprobe_kills_pad_jump`(22 项断言) —— node 真跑 `_rowWindow`: 红验(关掉重探)复现按 69.609 超量替换, 绿验断言真值 65.781 落地 / `padTop` 与 `_rowPre` 按真值重建 / 前后差恰 +3.828px; 另钉零全表作废、三入口同拍去重、几何变了才重探、`rowWin` 关闭零重探、抽屉未渲染行跳过(28 不许盖 27)、冻结门**两支各一条**(首校校准 / 已量齐但存值非正仍重校)、抽屉不冻、**抽屉探测位用真 `_rowHProbeRows` 跑三座锚**(content 采 27, peers 的 99 / segs 的 88 都不许落进 `drawerContent:*` 键)、**空探不记账**(行在场但 gBR 全报 0 的那一拍不落签名, 下一拍照常重探且不写 0)。静态守阵的全部断言跑在**剥注释后**的源码上 —— 否则把调用包进 `/* */` 或把门写成 `if (false) {` 再把旧条件留注释里就能骗过它(2026-11-16 实测)。e2e 像素面 T7/S-A/S-C 去预热后仍绿(撤修复即红)。**缩放重标面守阵**(issue 26-11-16-0716): 静态 `tests/unit/test_webui_static_dom_page_layout.py::test_frontend_rowh_zoom_rescale_guard`(剥注释断言)—— `_rootZoomOf` 恰一次定义且量不到返回 null、`_winSigExtra`/`_measureRowH` 共用该单点、重标块只平移不删键不翻量齐态、出窗重探过渡拍让路在位、`_rowHZoom` 在 created() 初始化; 行为 `tests/unit/test_webui_static_r4_node_batteries.py::test_r4_rowh_zoom_rescale_follows_root_zoom`(13 项) —— 首拍只落基线 / 全表等比例重标 / est 同比例跟随 / 键数·量齐态·签名零改动 / 重标后与逐行 gBR 逐位一致 / 同 z 幂等 / body 读到 null 不误判成 z=1 / 过渡拍让路不烧签名 / 重标后照常重探 / `_winSigExtra` 令牌两态口径 / 携带x重标共存(跨拍配对优先读 `_rowHs` 重标现值, 快照只兜底) / 携带回落(旧键被签名作废剔键面时才落快照值); e2e `row-window-zoom.spec.mjs` 加「运行时 zoom 1→0.9: scrollHeight ≈ 0.9×before + 末行可达」(关重标 3/3 红, 实测 2026-11-16)。
