# 尾桶持有克隆是「看起来有数据」的伪造面: 缺数据要显式可见不造值, 停滞与无数据必须可区分

> 摘要: 挂钟桶面的尾桶持有(traffic_grid.py:919-930, held = 上一观测桶速率克隆)让「还没有样本的时刻」显示成一段与上一桶完全相同的值 —— 曲线尾端恒平直, 直到真实样本落地改写才变斜线; 用户报的「最后一段偶尔平直, 下一拍移动到倒数第二段后变为斜线」正是持有改写的瞬间。教训: 拿「上一桶的值」垫显示 = 伪造数据(用户看到的是一段不存在的测量); 缺数据要显式可见(schema=2 显式空值点 / 断连徽标), 不造值; 停滞(有数据但停止更新)与无数据(测量不存在)必须可区分(徽标两态「滞后 Ns」/「已断连」)。
> 触发: 持有, held, 克隆, 尾桶, 平直, 斜线, 伪造数据, 显式空值点, 空值点, 徽标, 停滞, 断连, 缺数据, 垫值

### 「先垫个值让线不断」是显示层说谎

- **触发**: 曲线尾端出现空位/断线时, 修补直觉 = 「复制上一桶的速率把线垫住」(好看、不断线、判定线有值)—— 这个补丁会把「没有测量」渲染成「测到了且与上一点相同」。实证: 尾桶持有让稳态流量图尾端恒平直一段, 下一拍真实样本落地又改写回斜线 —— 显示面每次都在小范围内说谎, 用户以「数据失真」报障而不是以「缺数据」报障, 正因为伪造面成功了。
- **判别**: ①问「这段值对应哪个真实观测?」答不上来(值来自克隆)即伪造; ②用户报障措辞是「数值不对/形状怪」而不是「这里没数据」—— 说明缺口被填平了, 用户失去了分辨能力; ③实现里有 is_hold / held / carry-forward / backfill 这类把前值写进后位的概念 —— 检查它是否只在「确实测过」的语义下出现(26-11-15-1104 曾把 held 回填正当化给「有界漏采」, 根子还是造值)。
- **处置**: ①缺数据显式可见: 契约上让缺口带结构(schema=2 显式空值点 {t, dl:null, up:null}), 显示层让缺口可见(uPlot spanGaps:false 断线), 停滞/断连用徽标说明(「滞后 Ns」诚实等待 /「已断连」两条取数路径都断); ②停滞与无数据分流: 有数据但停止更新(主循环停顿) ≠ 测量不存在(断连)—— 前者画末样本冻结 + 滞后秒数, 后者画缺口, 两者共用一条曲线但语义面分开; ③真值优先于好看: 宁可断线/缺口不可造值 —— 显示语义的完整性是功能, 不是装饰。
- **守阵**: 显式空值点契约电池(test_traffic_group_assembly.py 缺口用例)+ 前端徽标两态 e2e(traffic-stream.spec / A5 冻结态改写「冻结期终点 = 末样本不动」)+ node 电池缺口判读用例(上下载皆 null 判缺口)。
