# 多形态宿主: 同一功能的控件散在多个头部/正文, 改一处漏一处

> 摘要: 抽屉/面板承载多种形态后, 同一功能(如流量图的「时间档位 + 纵轴设置」)的**数据域是共用的**(`qbCurScope` 单点派生), 但**UI 挂点各自独立** —— 全局/分组流量图走**流量形态头部**(`v-if="drawer.kind === 'traffic'"`), 种子流量图走**种子形态头部**(`v-else`, `kind === "seed"` + `tab === "traffic"`)。把控件从正文「上提到头部」这类版式改只接了其中一个头部, 另一个形态的同一功能就**整组消失**(2026-10-09 用户报「种子流量图的时间档位与纵轴控件弄消失了」)。既有守阵钉的正是「控件落在**流量形态头部**内」—— 断言为真而缺陷不在断言面内, 属**断言口径太窄**而非「没断言」。
> 触发: 多形态, 形态宿主, 两个头部, 控件消失, 按钮消失, 版式改回归, 上提到头部, 流量形态头部, 种子形态头部, drawer.kind, kind === "seed", kind === "traffic", tab === "traffic", qbCurScope, torrent 分支, 共用数据域不等于共用挂点, 断言口径太窄

**Refs:** memory-bank/tasks/26-10-09-webui-qb-traffic-seed-header-controls.md

### 「上提到头部 / 挪进某容器」只接了一个形态宿主

- **触发**: 改动形如「把 X 从正文挪到头部/工具栏」(改的是**位置**而非逻辑), 而该功能的 UI 在多个形态下由**不同的头部/正文模板**承载时。
  2026-10-08 实测: 流量图档位/纵轴自正文上提到头部, 只写进了 `drawer.html` 的 `v-if="drawer.kind === 'traffic'"` 头部; 种子流量图(`kind === "seed"` + `tab === "traffic"`)走 `v-else` 的种子头部 ⇒ 该页签控件整组消失。当时的提交信息写「三挂点(全局/分组/单种)共用同一段头部/正文」——**前提就不成立**: 单种与另两挂点**不共用头部**。
- **判别**: 改版式前先问「这个功能的 UI 在**所有形态**下分别由哪段模板渲染」。判据: ①找该功能的**门**是什么(`v-if` 条件) —— 若门是 `drawer.kind === "X"`, 而功能数据域的派生点(如 `qbCurScope`)另有分支, 两者不一致即嫌疑; ②数一数模板里同类控件块的出现次数(`grep -c 'class="qb-tabs"'`), 与形态数对不上就是漏接; ③`v-if` / `v-else` 两个头部的**子元素清单**逐个比对, 差异项逐个解释。
- **处置**: 每个形态宿主**各接一份**(本仓库无模板 partial 机制, 只能复写); 复写必须**逐字同源**, 并**加守阵钉住两块内层一致**(空白归一后比对) —— 否则一处改了另一处静默漂移。落点选**用户已拍板的那个形态的观感**。
  ⚠ **但「已拍板」只对当时那个形态成立**(2026-10-09 第 2 轮实证): 上一轮由「用户要求控件进头部栏」推断「种子侧照办即可」, 用户随后判定种子侧「太挤、小窗口下会变形」, 改口要它落**图下统计栏**。拥挤形态的落点是个**独立决策**, 别从另一形态的拍板直接外推 —— 拿不准就问一句, 比复刻完再返工便宜。
- **附带陷阱(该做法已被用户否决, 仅存为反例)**: 目标头部已承载导航等元素、控件再并进单行放不下时, 用容器包成一组 + `flex: 1 1 100%` + 置于容器**末位**, 可让控件组**恒**换到第二行(不依赖随视口宽漂移的自然换行; 置于中间会把后续元素顶到第三行)。**但这是把拥挤问题从"同一行挤"换成"头部整体变两行"** —— 2026-10-09 用户不接受(种子头部 44px → 65px)。拥挤形态的正解是**换落点**(本例: 图下统计栏), 不是把头部撑高。
- **守阵**: `tests/test_webui_static_dom_panel.py` —— `test_frontend_qb_traffic_chart_wiring`(流量形态头部控件组齐全 + 种子头部**不得**再有控件组 + 统计栏 `.qb-statctl` 落点与次序 + `qbCurScope === 'torrent'` 门 + 内层逐字同源) 与 `test_frontend_qb_traffic_yaxis_and_annotation`(`qbSetYAxisMode(` 计数 = 6 = 两处 × 三态 + 三皮肤 CSS 成对清单)。

### 控件组落进「由数据门的容器」⇒ 首载/错误态整组消失

- **触发**: 把控件搬进一个**渲染条件依赖数据**的容器(如流量图统计栏 `.hist-summary` 门在 `qbCurSummary` 上, 而 `_qbSummaryOf` 在数据为 `null` 时返回 `null`)。数据为 `null` 恰是**首载中**与**请求失败**两态 ⇒ 控件随之消失, 用户**连换档位重试都点不到**(「取不到数」与「点不到控件」互相锁死)。
- **判别**: 搬完控件后问一句「容器的 `v-if` 在**空/错/加载**三态下分别是真还是假」; 只要有一态为假, 控件就在那一态不可达。静态守阵查不出来(模板里控件确实"在容器内"), 必须按**状态**推。
- **处置**: 把容器本体的门**放宽到「有汇总 或 控件在场」**(`v-if="qbCurSummary || qbCurScope === 'torrent'"`), 汇总子项各自 `v-if="qbCurSummary"` —— 其它形态的渲染结果逐字不变。语义对齐 2026-10-08 之前「正文工具条恒可见」。
- **守阵**: 同上文件 —— 钉住统计栏本体门字符串(只写 `qbCurSummary` 即红)。
