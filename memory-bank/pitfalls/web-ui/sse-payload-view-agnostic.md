# 推送通道载荷粒度 = 事件源自然粒度: 别让生产者按订阅者视图折叠, 也别让消费者复制折叠逻辑

> 摘要: per-scope 广播通道(每 tick 每 scope 一帧, 流量 SSE /api/traffic/qb/stream 先例)不能按订阅者窗口折叠载荷 —— 事件源不知道订阅者的窗宽/k 分组, 按视图折叠 = 生产者追踪订阅者 UI 状态(fan-out 随订阅者视图组合爆炸 + 双向耦合)。自洽解 = 事件推自然粒度(per-tick 样本差分点), 消费者直显为尾点, 组粒度归位交给低频 GET 对账(30s)+ seq 断档重拉 —— 折叠逻辑只在读侧 GET 一处, 事件流与 GET 两源永远有单一权威对齐点。反面教材: 初版两处 docstring 把「前端现算」写进传输面 —— traffic_sample_events.py「组闭合/尾组更新语义属前端按其 stride 现算」/ traffic_stream.py「组闭合/尾组更新语义由前端按 GET meta.stride 现算」—— 那会在前端复制一套分组机器与读侧漂移; 计划 §03(2) 原文本是组粒度措辞「k>1 每 tick 尾组更新点 + 组闭合时新组点」(per-tick 实现对它的有意偏离见计划 §10 R1), 接缝终审发现两处 docstring 失实后修正(webui-traffic-beat.md 换代收口节同口径)。

### 广播帧别掺订阅者视图; 折叠逻辑只留一处, 两源对齐靠对账

- **触发**: 设计 SSE/推送通道时的两个对称陷阱: ①「既然订阅者按窗宽显示, 服务端干脆推折叠后的显示点」—— 事件源得知道每个订阅者的窗宽/分组 k, 订阅者换窗就重订阅/重算, 多订阅者不同窗 = 每 tick 每视图一帧, fan-out 与 UI 状态耦合; ②「事件推原始点, 前端自己按 meta.stride 折组」—— 消费端复制一套折叠逻辑, 与读侧 GET 的折叠各自演化必漂移(本案两处初版 docstring 就是 ② 的措辞, 逐字见摘要; 计划 §03(2) 原文是组粒度措辞, per-tick 实现对它的偏离记录在计划 §10 R1 —— 终审纠正的只是 docstring 失实)。
- **判别**: ①问「事件载荷的形状依赖了订阅者的什么状态?」答出窗宽/分组/排序任一项 = 生产者掺视图; ②grep 消费端是否出现与服务端同构的聚合/分组函数(本案 meta.stride 若被前端消费就会触发)—— 同一折叠逻辑出现两处即漂移隐患; ③推演「订阅者换窗/换分组时要发生什么」—— 需要重订阅/服务端配合 = 掺了视图; 不需要(只是本地显示粒度变化)= 干净。
- **处置**: ①载荷 = 事件源自然粒度(per-tick 样本差分点, 每 tick 每 scope 恰 1 帧, 几十字节), 广播面零订阅者状态; ②消费端对事件样本点只做「直显为尾点」这类零折叠合并, 组粒度归位 = 低频 GET 对账(30s)+ seq 断档重拉(D9)—— 折叠权威在读侧 GET 单点; ③事件与 GET 之间允许有界瞬态偏差(摊回份额/漂移), 由对账机制校准, 不为逐帧严格一致把折叠逻辑塞进事件源或消费端。
- **守阵**: SSE 端点电池(载荷形状/序号连续性/多订阅隔离)+ 前端 node 电池合并面(事件尾点预算 500+64, 双通道同故障截断)+ docstring 口径面(docstring 与实现失实由评审/终审揪出, 修正案见 webui-traffic-beat.md「读侧契约换代收口」节)。
