# 性能与刷新节奏

> 摘要: 主循环节拍、缓存边界、埋点与相对时间 —— 改热路径 / 改节拍 / 加埋点前必读。
> 触发: 性能, 热路径, jsonable_encoder, 节拍, 刷新, 轮询, 缓存, 埋点, 相对时间, 时间列, yapf

### 热路径返回裸 dict 会被 FastAPI 白跑一遍 `jsonable_encoder`

- **触发**: 改高频端点(递归遍历整个响应体做"可 JSON 化"转换, **全程占 GIL**)。
- **判别**: 端点里 `return` 裸 dict 就会触发。
- **处置**: 改成 `return JSONResponse(content=payload)` 走 `routing.py` 的短路
  (`isinstance(raw_response, Response)`)即可跳过。
  ❗**载荷里有非 JSON 原生类型(dataclass / datetime / set / Decimal / Enum)必须保留编码器**
  (如 `/api/config/schema` 的 dataclass), 否则**直接 500** —— 那趟遍历对它**不是白跑**。
  守阵用**计数替身**包住 `jsonable_encoder` 断言调用次数为 0(**刻意不用计时断言, CI 不可靠**),
  清单里明确排除 `/api/config/schema` 并写明原因。

### "载荷大"不等于"要裁字段": 优化前先量四步

- **触发**: 响应体大, 想裁字段。
- **判别**: 四步每步都能独立否决一个方向 —— ①字节**构成**(最大字段占多少, 裁掉能省几成)
  ②客户端**拆分**(parse / 赋值 / patch 各多少)③网络**对照**(同尺寸静态文件走同一栈要多久)
  ④服务端**端点内耗时**(5 行计时中间件)。④与①②③对不上就是**框架在收税**。
- **处置**: **排除法比猜测便宜。**

### 补刷新必须调完整的 `_refresh_torrents()`, **绝不能只调 `store.apply_sync()`**

- **触发**: 写命令后的补刷新。
- **判别**: `apply_sync()` 只更新 `by_hash` + `server_state`, 分组索引 / 任务 / 事件 / 搜索索引**一概不碰** ⇒
  新种子不归组、`on_torrent_deleted` 不触发、删除不处理、`store.groups` 残留幽灵、状态快照不推进。
- **处置**: 调 `_refresh_torrents()`; 且补刷新放在 `_drain_web_commands()` **整批结束后一次**
  (不是每条命令后各一次)。

### 命令线与 tick 线必须解耦

- **触发**: 想"让主循环提前醒来"处理命令。
- **判别**: 命令唤醒**只触发 `_drain_web_commands()`**, `_tick()` 严格按 `next_tick_at` 推进;
  自投递命令(`build_search_index`)**不唤醒**。
  先问一句 —— **提前跑的是消费, 还是整轮 tick?** 整轮会连坐三处:
  `max_tasks_per_tick` 的**速率语义**(默认 20 × 2s = 10 任务/秒)、两个每 tick API 预算(sync / tracker)、
  以及"唤醒→drain 拉 500 条文件 API→重建视图→又投递→立刻再唤醒"的**自激循环**。
- **处置**: 保持解耦; 验收加**不变量用例**: 2s 内连投 100 条命令, `_tick` 次数与无命令时**相同**。

### 分层节拍的等待必须是 `min(两条线的到期时间)`

- **触发**: 改分层节拍。
- **判别**: 不能退化成"单一 cadence + 内部门控"(任务间隔会被循环粒度量化: 1.5s 粒 + 2s 间隔 ⇒ 实测 **3s**)。
  **多事件等待顺序不能反**: 阻塞在 `wake_event` 上、分段只是为了让 `stop_event.is_set()` 被检查;
  反序时命令延迟退化到 ≤0.5s, **恰好抵消收益**。
- **处置**: 取 min + 保持等待顺序。

### 别给 `rebuild_views` 单独配节拍

- **触发**: 想给视图重建加定时器。
- **判别**: `ensure_group_state()` 已是"**请求驱动 + 脏门控**" ⇒ 视图重建频率天然 = 前端轮询频率,
  另配定时器只会在"前端没来取"时**白建**。
- **处置**: 服务端快于客户端时用 **rid 消费情况反向门控**(`_web_pending_ver`), 两个边界 ——
  **脏标记必须保留**(只是不生产, 不是丢弃变化)与 **`force=True` 必须绕过**(本轮有命令改了状态时真值必须立刻可见)。

### 只读端点短缓存的四个边界

- **触发**: 给只读端点加缓存。
- **判别**: ①写入点在 `_require_torrent()` **之后**(否则不存在的 hash 以**攻击者可控的键**进缓存 = **投毒**)
  ②**断连判定必须在缓存之前**(否则缓存把 503 掩盖成 200)
  ③失效键用**写序号** `_web_write_seq` 而不是主动失效(把"忘记调失效"换成"键空间增长", 有上限兜底)
  ④残留: 锁外调 `fn()` 会**惊群**、超 128 项整表 clear。
- **处置**: 四条一起满足。

### 埋点写完必须有人消费

- **触发**: 加埋点 / 立验收口径。
- **判别**: 没有承接方(断言 / 报表字段 / 走查表)的口径等于没写;
  前端埋点要覆盖**整条链路**(补丁 / POST / 排队 / 执行 / 端到端), 只量一段会在真机慢时**无从下手**。
- **处置**: 给每条口径**指派交付物**(见 [../kb/discipline.md](../kb/discipline.md))。

### 改主循环会**静默废掉**既有的节流守卫

- **触发**: 改主循环 / 分层节拍。
- **判别**: 靠"每轮一次 sync"假设的用例会在分层后**挂死而不是失败**。
- **处置**: 改写这类用例时判据要用**真实经过时间**, 不能用 mocked sleep。

### 改 `_tick` / `_sync_line` / `_task_line` 签名时必须同步**所有**测试替身

- **触发**: 改这三个方法的签名。
- **判别**: 替身签名不匹配 ⇒ 每轮调用抛 TypeError 被 `run()` 兜底吞掉 ⇒ 退出条件永不触发 ⇒
  **全量测试挂死 10 分钟而不报错**。
- **处置**: 用 `grep -rn "_tick = \|_sync_line = \|_task_line = " tests/` 找齐
  (**替身不一定叫 tick**, 也可能是局部 `def boom(...)`); 新参数一律给**默认值**。

### 格式化会顺手重排文件里本来就超宽的旧行(`dev.fmt`)

- **触发**: 格式化改过的文件。
- **判别**: 会让 diff 里多出与本次改动无关的重排。
- **处置**: 改配置 schema 这类文件时只格式化**自己加的那段**, 或改完先 `git diff --stat` 看行数是否异常。

### 相对时间("N分钟前")必须挂在**响应式时基**上, 否则会永久停在渲染那一刻

- **触发**: 做相对时间列(2026-09-20 实测)。
- **判别**: 后端 `last_activity` **按分钟量化**且只在活动发生时才变, 加上 `rid` 未变时 `/api/state`
  不回传数组(契约: 键不存在保留原引用)⇒ 行对象不被替换、也没有响应式依赖变化 ⇒ Vue 不重渲染 ⇒
  单元格里现取 `Date.now()` 算出的相对值被**冻结在渲染那一刻**(暂停的种子"刚刚"挂一整天)。
- **处置**: 读响应式 `nowSec`(`data` + `mounted` 起 30s 的 `setInterval`, `unmounted` 清掉)而不是现取时间;
  **30s 一跳是刻意的** —— 展示粒度只到分钟, 更密只会白付整表 patch, 与 P1-2 窗口化的成果相抵。
  复验: 浏览器里把 `nowSec` 拨快 1 小时, 相对文案应**整体加一档**。
  ⚠ 纯**时长**(做种时长 / ETA)**不在此列** —— 它们的值本身是秒数差, 不随时钟走。

### 同一列里别混两种格式

- **触发**: 把某列改成某种口径(2026-09-20 用户反馈)。
- **判别**: "最近活动"改相对时间时留了"超 30 天回落绝对日期"的兜底, 结果同列里
  "有的 3天前、有的 08-11 21:06"被读成**没改干净**。
- **处置**: 做"把某列改成 X 口径"这类改动, **要么全列统一, 要么别改** ——
  按阈值切换回落的"兜底"在读者眼里就是 bug;
  长跨度的可核对性改用 `title`(悬停看绝对时间点)补回, 与列内格式**解耦**。
