# canvas 图面注解层的配色误用发丝线令牌 —— 缺口斜纹「几乎不可分辨」

> 摘要: canvas 图面(流量图注解层)里的**面积底纹**若复用装饰性 1px 发丝线令牌(`--hairline`, alpha 仅 0.05~0.08), 再叠一层 `globalAlpha` 折半, 有效不透明度只剩约 3%, 深色底与亮色底上**都**等于没画(用户报「颜色几乎不可分辨」); 亮主题还有「白纹铺白底」的镜面变体。另: 症状为「没落到正确区域」时, 必须先把**几何**与**配色**分开验证 —— 几何经代数证明恒等、原诊断"位移"被实测证伪, 真因是配色不可见导致无法判读落点。
> 触发: canvas 注解层配色, 缺口斜纹, 斜纹看不见, 断线区域标注, 颜色几乎不可分辨, --hairline, 发丝线令牌, globalAlpha 折半, 有效不透明度, 白纹铺白底, 亮主题斜纹不可见, --qb-gap-hatch, 面积底纹 vs 发丝线, 令牌语义误用, 斜纹没落到正确区域, 几何恒等验证

### 症状「没落到正确区域」不一定是几何错 —— 先分几何 / 配色两问

- **触发**: 用户报「图上标注/底纹画在错误位置」且**同时**说「颜色几乎看不出来」。
- **判别**: 两症状同时出现时, 先怀疑"看不到 ⇒ 无法判读落点", 而不是急着改坐标。
  本例(2026-10-08, WEBUI 流量图缺口斜纹):
  ① 我按源码 `for (let x = xa - H; x < xb; ...)` 推断斜纹整体左移 H 像素, 并用一次复现
  (`paintedMin: 96.7` vs `expectXa: 329.7`)「证实」—— **误读了自己测量的含义**: 该复现量的是
  **线段左端**的并集, 而两式产生的线段集合**逐条相同**。
  ② 代数恒等: `B: x_k = xa - H + k*step` 画 `(x_k, x_k+H)` vs `A: s_k = xa + k*step` 画
  `(s_k-H, s_k)`; 因 `s_k = x_k + H`, 两者逐条完全一致, k 上限同为 `ceil((xb-xa+H)/step)`。
  ③ 数值枚举 6 组 (xa,xb,H,step) 组合全部「逐条相同=true」(55/55、49/49、48/48、122/122、
  185/185、13/13); 真浏览器 A/B 双面板渲染, 两式斜纹位置**完全相同**且都在缺口区。
  ⇒ 几何无缺陷; 用户感知的"未落到正确区域"由**配色不可见**造成(同源缺陷)。
- **处置**: ①报「位置错 + 看不清」时, 先做**几何与配色的分离判定** —— 几何用代数化简 + 逐条
  线段比对(必要时数值枚举), 配色用**实跑取真值**看 alpha; 两者各自独立下结论, 不互相脑补。
  ②**证伪了的诊断不得留成守阵锚** —— 本坑一度设过 `assert "let x = xa - H" not in gb` 类"位移"
  负锚, 该"缺陷"根本不存在, 设了就是**假锚**(后人改不动/乱改); 最终整块几何电池被替换为配色电池。
  ③几何若只是**等价改写**(如本次 `x=xa; x<xb+H` 画 `(x-H,T+H)->(x,T)`) —— 落码可以, 但注释与
  守阵都要标注「与原式恒等, 不设位移类锚」, 防后人误改。

### canvas 面积底纹不得复用发丝线令牌, 且不得叠 globalAlpha 折半

- **触发**: 给 canvas 图面加**面积型标注**(缺口斜纹 / 区间底纹 / 高亮带)并取色; 或改动画布注解层
  的令牌消费。
- **判别**: 底纹"画了但基本看不见"/"要凑近才有一点点"。根因是**令牌语义误用**:
  `--hairline` 是**装饰性 1px 发丝线**令牌, 实测各主题 alpha 仅
  `rgba(255,255,255,.055)`(ocean/galaxy/atlas/console)、`.05`(orbit)、
  `rgba(27,42,58,.07)`(frost)、`rgba(60,51,39,.08)`(golden);
  再叠 `ctx.globalAlpha = 0.5` ⇒ 有效不透明度约 **2.75%**。1px 发丝线靠"叠在边框上"才看得见,
  当面积底纹用强度差一个数量级。
  镜面变体: **亮主题用白色**(`rgba(255,255,255,.22)`)—— 白纹铺白底/米底上同样等于无。
- **处置**: ①**单列一枚专用高对比中性令牌** `--qb-gap-hatch`(深色主题 `rgba(255,255,255,.22)`,
  亮主题用**深墨色** `rgba(27,42,58,.22)` / 暖墨 `rgba(60,51,39,.22)`), 建图令牌单点
  `_qbChartTokens()` 产出 `gap: pick("--qb-gap-hatch", "--border-strong", "--fg-muted")` ——
  回退链**仍比 hairline 可见**, 绝不落回 `grid` 的极低 alpha; 用色处 `ctx.strokeStyle = tk.gap || tk.grid;`。
  ②**去掉多余的 `globalAlpha` 折半**(令牌本身已是最终强度), `ctx.globalAlpha = 1`。
  ③令牌必须**三皮肤(atlas/console/prism)+ prism 五主题(ocean/galaxy/orbit/frost/golden)成对定义**
  —— 缺一个就是那套皮肤下斜纹不可见。
  ④纪律: 面积底纹 / 高对比标注**一律单列专用令牌**, 不复用发丝线 / 网格线令牌。
- **守阵**: `tests/test_webui_static_dom_panel.py::test_frontend_qb_traffic_yaxis_and_annotation`
  §5b 静态锚(令牌三皮肤 + 五主题成对、亮主题禁白)+ node **配色电池**(记账式假 ctx 调真实
  `_qbDrawGaps`, 断言写入的 `strokeStyle` 走专用令牌、`globalAlpha` 不折半, 并做
  **令牌 alpha 量级下界 >= 0.15** 的数值判定 —— 静态锚可能被同步改掉, 数值下界不会)。
  红验四路均按预期变红(还原 `tk.grid` / 还原 `globalAlpha=0.5` / 摘 frost 令牌 / frost 误用白色 /
  摘 atlas 令牌), 还原复绿。
