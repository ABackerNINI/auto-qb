# canvas 图面注解层的配色与几何 —— 缺口斜纹「看不清」与「没落到正确区域」

> 摘要: canvas 图面(流量图注解层)里的**面积底纹**若复用装饰性 1px 发丝线令牌(`--hairline`, alpha 仅 0.05~0.08), 再叠一层 `globalAlpha` 折半, 有效不透明度只剩约 3%, 深色底与亮色底上**都**等于没画(用户报「颜色几乎不可分辨」); 亮主题还有「白纹铺白底」的镜面变体。**第二条(几何)**: 用 45 度线段铺"竖矩形"底纹时, 若只按线段底端 x 扫一个区间、再只把外层 clip 收到**整个绘图区**, 涂出的并集是"宽 = 图高的**斜向平行四边形**"(左右边界皆斜边) —— 用户报「未落到正确的区域, 且其倾斜超出了范围」。**必须逐 run 追加一次 clip 到目标矩形**。
> 触发: canvas 注解层配色, 缺口斜纹, 斜纹看不见, 断线区域标注, 颜色几乎不可分辨, --hairline, 发丝线令牌, globalAlpha 折半, 有效不透明度, 白纹铺白底, 亮主题斜纹不可见, --qb-gap-hatch, 面积底纹 vs 发丝线, 令牌语义误用, 斜纹没落到正确区域, 斜纹倾斜超出范围, 斜纹平行四边形, 45 度斜带 vs 竖矩形, 逐 run clip, 只裁绘图区不够, canvas clip 不改写记账端点

### 症状「没落到正确区域」—— 可能是真几何错, 别被"先分两问"带偏成"一定是配色"

- **触发**: 用户报「图上标注/底纹画在错误位置」, 且**可能同时**说「颜色几乎看不出来」。
- **2026-10-08 的两轮实测 (WEBUI 流量图缺口斜纹), 记成正面教训**:
  - 第一轮: 用户报「未落到正确区域 + 颜色几乎不可分辨」。当时判断**两症状同源** = 配色不可见导致
    无法判读落点, 于是只改配色(专用令牌), 并在坑档里写死「几何经代数证明恒等, 无缺陷; 原"位移"
    诊断被实测证伪」。**这个结论是错的** —— 代数"恒等"只证明了**两种写法互相等价**(旧式
    `x=xa-H; x<xb` 画 `(x,T+H)->(x+H,T)` ≡ 新式 `x=xa; x<xb+H` 画 `(x-H,T+H)->(x,T)`),
    却没有回答"这样画出来**应该是矩形还是斜带**"。两式同错, 恒等 ≠ 正确。
  - 第二轮: 用户复报「(第一次修复未成功) 标注未落到正确的区域, 且其倾斜超出了范围」, 附截图。
    栅格化模拟 + 真浏览器渲染证实: 画出的是一个"宽 = 图高 H 的斜向**平行四边形**", 缺口右段下半
    留白、左段上半越界到缺口左侧 —— 这才是用户看到的形状。
- **处置**: ①症状为「位置/形状不对」时, **不要因为"同时说颜色看不清"就跳过几何验证**; 更要紧的是,
  几何验证要验**"画出来的形状是否等于目标形状"**, 而不是验"两段代码是否等价"(等价可能一起错)。
  真值判据 = 栅格化/真浏览器渲染出形状, 或把假 ctx 记账的 `moveTo/lineTo` 端点做几何判定。
  ②**证伪了的诊断不得留成守阵锚**(本坑一度设过"位移"负锚, 后发现位移不是根因但"形状"是); 反过来,
  **已证的结论若在后续被推翻, 必须回改坑档**, 否则下一轮会被自己写下的错误结论带偏(本轮就吃了
  这条亏 —— 第一轮写在坑档里的"几何无缺陷"直接误导了第二轮的排查起点)。

### 45 度线铺"竖矩形"底纹: 只裁绘图区不够, 必须逐 run 裁到目标矩形

- **触发**: 给 canvas 图面加**区间型面积底纹**(用一组 45 度斜线表示的"缺口带 / 高亮区间 / 柱纹"),
  且区间由两个 x 边界 `[xa, xb]` 界定。
- **判别**: 底纹呈**斜向平行四边形**(左右两侧边界都是斜边), 表现为「某一半边留白、另一半边越出
  区间」—— 用户会说「没落到正确区域」「倾斜超出范围」。根因: 每条 45 度线段水平跨度恒为 `H`
  (图高), 扫线只让**底端 x** 覆盖 `[xa, xb]` 时, 线段的**左上端**在 `[xa-H, xb-H]` —— 并集是
  一条宽 `H` 的斜带; 外层 clip 只收到**整个绘图区**, 收不掉斜带那两条斜边。
- **处置**: ①在绘图区 clip **之内**, 对每个 run **再追加一次** `ctx.rect(xa, T, xb-xa, H)` +
  `ctx.clip()`(canvas 的 `clip()` 与已有裁剪区**求交**), 把斜带裁成"以 `[xa, xb]` 为左右竖直边"
  的竖矩形; 用 `ctx.save()/restore()` 包住每 run 的裁剪, 不要污染下一个 run。
  ②扫线范围仍要**覆盖整条带**(`x` 从 `xa` 到 `xb+H`)—— 裁剪切掉的是越界部分, 不是缩小扫描范围。
  ③判据必须是 `xa < xb`(退化 run 跳过, 不画零/负宽矩形)。
  ④**注意**: `clip()` 是画布操作, **不会**改写"记账式假 ctx"里记到的 `moveTo/lineTo` 端点 ——
  所以写守阵时不能断言"原始端点落在 [xa,xb] 内"(它们本就该越界, 靠 clip 收), 要断言"per-run 缺口
  矩形 clip 存在且 == 目标矩形" + "扫线覆盖了目标矩形两个边界"。

### canvas 面积底纹不得复用发丝线令牌, 且不得叠 globalAlpha 折半

- **触发**: 给 canvas 图面加**面积型标注**(缺口斜纹 / 区间底纹 / 高亮带)并取色; 或改动画布注解层
  的令牌消费。
- **判别**: 底纹"画了但基本看不见"/"要凑近才有一点点"。根因是**令牌语义误用**:
  `--hairline` 是**装饰性 1px 发丝线**令牌, 实测各主题 alpha 仅
  `rgba(255,255,255,.055)`(ocean/galaxy/atlas/console)、`.05`(orbit)、
  `rgba(27,42,58,.07)`(frost)、`rgba(60,51,39,.08)`(golden);
  再叠 `ctx.globalAlpha = 0.5` ⇒ 有效不透明度约 **2.75%**。1px 发丝线靠"叠在边框上"才看得见,
  当面积底纹用强度差一个数量级。
  镜面变体: **亮主题用白色**(`rgba(255,255,255,.22)`)—— 白纹铺白底/米底上同样等于无。
- **处置**: ①**单列一枚专用高对比中性令牌** `--qb-gap-hatch`(深色主题 `rgba(255,255,255,.22)`,
  亮主题用**深墨色** `rgba(27,42,58,.22)` / 暖墨 `rgba(60,51,39,.22)`), 建图令牌单点
  `_qbChartTokens()` 产出 `gap: pick("--qb-gap-hatch", "--border-strong", "--fg-muted")` ——
  回退链**仍比 hairline 可见**, 绝不落回 `grid` 的极低 alpha; 用色处 `ctx.strokeStyle = tk.gap || tk.grid;`。
  ②**去掉多余的 `globalAlpha` 折半**(令牌本身已是最终强度), `ctx.globalAlpha = 1`。
  ③令牌必须**三皮肤(atlas/console/prism)+ prism 五主题(ocean/galaxy/orbit/frost/golden)成对定义**
  —— 缺一个就是那套皮肤下斜纹不可见。
  ④纪律: 面积底纹 / 高对比标注**一律单列专用令牌**, 不复用发丝线 / 网格线令牌。

  (记账式假 ctx 调真实 `_qbDrawGaps`, 断言写入的 `strokeStyle` 走专用令牌、`globalAlpha` 不折半、
