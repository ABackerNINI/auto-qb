# UI 位置持久化 (顶层页 / 设置分区)

> 摘要: "刷新后回到别的页"这类报障的固定判据 —— 位置属于**用户意图**该落盘, 但只改初值不够(按需加载的页面必须在启动路径补一次加载), 且恢复的值必须对 schema 校验, 采用时要复用既有跳转方法。
> 触发: 刷新回种子页, 设置页刷新, 刷新掉回首页, 页面位置, 停在哪一页, page 持久化, hub.view, F5 丢位置, 记住上次在哪, 展开态被收起, 切视图, expandedKey, 分组展开, 追剧展开

### ❗位置落盘只改初值**不够**: 按需加载的页面必须在**启动路径**补一次加载

- **触发**: 把某个"刷新后应该停在这"的页面位置写进 localStorage(2026-09-25 实测)。
- **判别**: 顶层 `page` 改成读存储后, 设置页刷新**确实**停在设置页, 但页面内容是「配置加载失败 + 重试」
  —— 因为配置树是**按需加载**的(`cfgLoad` 只在 `openSettings` 与页内"重试"里调), 首屏 `cfg.schema` 永远 null。
  这个坑的隐蔽点在于**症状看着像"持久化没生效"**, 而 `page` 的值其实完全正确 ⇒ 只断言 `page` 的守阵会漏掉它。
- **处置**: 启动路径补一次加载, 落点选**两条登录路径的唯一汇合点**(`startPolling()` 尾部) —— 那里鉴权已放行,
  请求必定带得上凭证。守阵必须**同时**断言"page 对"与"数据已加载"(`cfg.schema` 非空 / 分区标题已渲染)。
- **守阵**: `ui_smoke.cjs`「设置页刷新保持位置」把 `page`+`hub`+`schema`+`crumb` 四项一起断言(已红绿双验);
  `tests/test_web.py::test_frontend_page_location_persisted` 静态钉住 `startPolling` 里那一次 `cfgLoad`。

### 恢复的值必须**对 schema 校验**, 不能无条件采用

- **触发**: 恢复一个"由 schema 定义"的键(分区 key / 分组 key 这类)。
- **判别**: schema 是**模块级常量**, 版本升级后分区会改名 / 删除; 而读 localStorage 发生在**模块加载期**,
  那时 schema 还读不到 ⇒ 只能**先取值、后校验**。无条件采用会停在空白分区, 页面上没有任何提示、也没有返回入口。
- **处置**: 校验放在 schema 到手的那一刻(`cfgLoad` 成功之后), 失败落回默认值; 采用时**复用既有跳转方法**
  (`hubGo`)而不是自己重设字段 —— 懒加载(`__logs` 拉日志 / `hr_check` 拉站点状态)与默认选中项
  (trackers / rules 的 key)都在那条路径里, 重写一遍必漏一半。

### ❗展开态同属用户意图: 切视图**不得置空**, 要按视图分桶带回

- **触发**: 在 `setViewMode` 这类"切视图/切页"的收口里复位任何 `expandedXxx`(2026-09-25 用户报
  「辅种页切到种子页再切回, 展开的组收起来了」)。
- **判别**: 展开态是"我正盯着这一组"这种**临时意图**, 与 `page` / `viewMode` 同类 —— 切走再切回
  就该还是那一组(不是"重新点开一次")。旧实现里三行 `expandedKey / expandedShows / expandedShowEp = null`
  写在同一个"顺手复位"习惯里, 写着像卫生操作, 实则是把用户意图丢掉。
  ⚠ 复位**不能删了了事**: 展开态确实不该串台到别的视图(种子视图没有展开概念), 所以正确形状是
  **按视图分桶暂存**(`expandMemo`), 切走收进桶并清空实时字段, 切回还回该视图最后一次的展开。
- **处置**: 还回前**必须验"那一行还在"**(组可能已被删/被筛掉), 并同步 `groupWin` 的退避判据 ——
  只判 `expandedKey` 非空的话, 一个过期的键会让行窗口**永久**退避成全量渲染
  (大库上 = 悄悄关掉 P1-2, 界面看着完全正常, 只是滚动变卡, 没人会往这里想)。
  守阵: `tests/test_web.py::test_frontend_expand_state_survives_view_switch`。

### 片段 mixin 里的"唯一漏斗"命名要先查重

- **触发**: 新增 `persistXxx` 这类"唯一写入口"方法。
- **判别**: 前端逻辑层是**十几个 mixin 注入同一个实例**, Vue 的合并是**后者覆盖前者且不报错**。
  `persistPage` 已被 `columns.js` 占用(列状态漏斗) —— 新写的同名方法会**静默**盖掉它, 表现为"列设置又坏了"。
- **处置**: 新方法名先全仓 grep 一遍(机检 = `test_frontend_static_bundle_health` 第 10 项跨片段重名)。
  本次用 `persistUiPage` 与列状态的 `persistPage` 区分。
