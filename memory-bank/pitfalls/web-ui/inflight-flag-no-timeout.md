# 单向「请求在途」标志 + 无超时请求 = 自愈路径被自身封死

> 摘要: 前端「loading 置真 → await 请求 → finally 复位」是最常见的形状, 但裸 `fetch` 没有超时 ⇒ 请求悬挂时 `await` 永不返回、`finally` 永不执行, 而轮询 tick 又拿**同一个标志**当跳过判据 ⇒ 复位路径被自己挡住(图表停在旧帧、无提示、不自愈, 只能手动刷新); 同族的第二个入口是「`await` 之后才排下一拍」的定时器链(悬挂即**永久停表**, 连标志都没有)。处置 = 请求级超时(把悬挂变成一次可报的失败) + 在用标志加计时兜底, 两层一起上。
> 等级: L0
> 触发: 前端轮询, 轮询停了, 图表停在旧帧, 数据不再更新, 加载卡死, loading 不复位, 不自愈, 手动刷新才恢复, fetch 无超时, AbortController, 请求悬挂, TCP 半开, 信号丢失

**Refs:** memory-bank/tasks/26-10-16-webui-chart-fetch-timeout.md,memory-bank/tasks/26-10-16-webui-raw-fetch-timeout.md

- **触发**: 任一次「单次请求悬挂」(服务端不响应 / TCP 半开 / 中间设备静默丢包) —— 不需要后端崩溃。凡取数链上存在**裸 `fetch`**, 悬挂就是实现上可达的状态。
- **判别**: 三问, 前两问同真即已成链 —— ①取数链上有没有裸 `fetch`(无 `AbortController` / 无 `signal`)? ②消费侧的 loading 标志是否**只在 `finally` 复位**, 且**被轮询 tick 当作跳过判据**(`if (loading) return`)? ③另一形态: 下一拍是在 `await` **之后**才排的(`scheduleNext()`)—— 悬挂即永久停表(连标志都没有, 症状同样是「再也不更新」)。
- **处置**: 两层一起上 —— ①**请求级超时**: `AbortController` + `setTimeout(..., 15s)`(取值的依据: 本机直连正常亚秒级、后端路由另有自身超时与降级返回), 外部 `signal` 用**链接**而不是覆盖(否则将来加取消会被静默顶掉), `AbortError` **翻译**成可读文案并打 `timeout` 标记(原始文案 "The operation was aborted" 对用户没有信息量, 也分不出超时与取消); 让 `finally` / 错误态路径照常执行 —— 这一步同时治好「流量图 loading 卡死」与「状态栏定时器停表」两种形状。②**在用标志的计时兜底**: 置位超过 N 秒即视为悬挂 → 强制续拉 + 一条 `warn`(阈值取请求级超时**之上**, 本例 2 倍, 只兜「连 abort 都没能让 finally 跑起来」)。计时起点写在**置位处**、`finally` **不擦** —— 换目标场景下旧请求的 `finally` 晚于新请求的置位到达(stale 分支故意不复位 loading), 擦一次就把新请求的起点抹成 0, 兜底从此永不触发。③**旁路裸 fetch 一并收口(2026-10-16, issue 26-10-16-1303)**: 给 `_request` 加超时**不覆盖**那些有意/历史地绕开它的取数口 —— 启动分片装载(`boot.js`, 鉴权就绪之前)、本机免鉴权判定、导出下载(二进制流)、快捷键密钥读写 x2; 它们各有一个停在中间的用户可见态(白屏 / 停在"验证中"/ 回执停在"进行中" / 面板 loading 不归位)。修法 = 低层单点 `shared/fetch_low.js::aqbFetch(path, opts)`(带超时, 返回**原始 Response**: 不解析 JSON、不判 401, 调用方各持自家收口) + 在守阵里钉「裸 `fetch` 零回潮」(允许清单: 单点自身 / `auth.js` / `boot.js`); `boot.js` 在清单脚本之前执行、用不了单点, 自带内联超时(10s, 阻塞首屏 ⇒ 早失败; 悬挂落到它既有的 `fail()` 可读占位)。**反向教训**: 修一条链上的主入口时, 顺手清点「还有谁自己开了一条同类路」—— 否则同一族症状会从旁路再回来。
- **复发**: `1` —— 同一条链 2026-10-12 已因「stale 谓词双重取反 → 不落袋 ⇒ loading 不复位 ⇒ tick 被挡」卡锁修过一次(`7aef8bc2`); 本次是**另一个入口**(悬挂而非逻辑错)。两次落点相同说明: 单点修复没覆盖「这条链上没有兜底释放路径」这一层, 故本轮把两层兜底都补上。
- **守阵**: `tests/test_webui_static_dom_panel.py` 的 `test_frontend_qb_traffic_load_stall_fallback`(tick 挡拍/放行逐拍)与 `test_frontend_api_request_timeout`(请求级超时六型); 两处都以 **node 行为电池**为主、静态锚只作兜底 —— 行为电池的失败形态包含「无输出」(悬挂路径把探针的 `await` 挂住, rc 仍为 0), 判据里必须显式拦空输出, 否则会以 IndexError 的面目报错。旁路收口另有一件 `test_frontend_raw_fetch_timeout_single_point`(低层单点 + 裸 `fetch` 零回潮 + `boot.js` 内联超时)。
