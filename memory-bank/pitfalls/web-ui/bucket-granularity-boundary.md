# 桶粒度判据的「不可分带」: 用聚合桶时间戳判定事件在链末哪一侧, 放宽/收紧都必须显式声明一桶宽

> 摘要: 判据的可分精度不可能高于它读取的数据粒度 —— 数据只有「桶」(时间栅格槽)时, 「事件(如进程重启)在链末之前还是之后」这类判定天然存在一条**一桶宽的不可分带**, 按桶覆盖端一刀切会把整条带判给「链已接续」而静默漏判; 修法 = 端点重定义为「链末桶前一桶起点」并写明端点含否, 再用**真实帧重建**的电池用例把两端钉住。2026-10-16 实证: P4 接缝提示判据 `_qbSeamHint` 左端「重启 ≥ 链末桶覆盖端 `t+interval`」把「重启后首采已入账、随后立即进入开放零游程」形态恒判为「链已接续」(首采恒落在重启后 ≤ 一个 main_tick, 总归进链末桶, 但尾区仍在) ⇒ 右侧整片无采样斜纹零提示(issue 26-10-16-0954)。
> 等级: L0
> 触发: 桶粒度, 判据边界, 不可分带, 链末桶, 接缝判据, 时间比较, 覆盖端, server_started_at, 首采入账, 重启缝, 聚合槽

### 拿桶时间戳比较外部事件时刻时, 先算「这条边界的实际带宽」

- **触发**: 前端判据用后端**聚合桶**(栅格槽)的时间戳去比较一个**外部事件时刻**(进程出生 `server_started_at`、重启时刻、采样点时刻…), 做「事件在链上 / 链外」「链已接续 / 链已断」这类二分。2026-10-16 实证: `_qbSeamHint` 左端要求「重启 ≥ 链末桶覆盖端 `t+interval`」才算缝; 但**首采恒落在重启后 ≤ 一个 main_tick**, 于是「重启后首采即链末桶」形态里 `started ∈ (t-interval, t+interval)`, 恒被左端挡在门外(实测帧: 重启 04:45:01 / 首采桶 04:45:02 / 04:45:04 起整片斜纹到右沿却零提示)。
- **判别**: 症状是**「判据不触发」而不是「报错」** —— 静态锚、类型、契约全对, 只是某段真实工况被静默归到另一个分支。量化法: 代入该工况的**可分辨上界**, 看边界带是否覆盖真实值域 —— 若「事件时刻」与「桶时刻」的差恒小于一个桶宽(采样节拍 + 落桶对齐所致), 则按桶覆盖端一刀切的边界**必漏**。本例两区间永不相交: 实际 `t_last - started ∈ (-interval, +main_tick]`, 判据却要求 `started ≥ t_last + interval`。
- **处置**: ①端点重定义为「**链末桶前一桶起点 `t - interval`**」(两端含), 注释里写明不可分带的成因与宽度(为什么恰好一桶宽、反方向界线在哪 —— 「链确已接续」= 链末桶起点晚于事件 + 1 个桶宽以上); ②把事故帧**蒸馏成纯函数入参**做电池用例(窗宽/桶宽/桶序/唯一观测桶/事件时刻), 正例覆盖事故帧本身 + 两端点边界(恰在左端→提示 / 早一桶宽→null), 反例覆盖放宽方向(把无约束的 `-Infinity` 类改动挡回); ③静态守阵钉**整行活性锚**(比较行整行匹配), 退回旧口径即红。
- **守阵**: `tests/test_webui_static_dom_panel.py::test_frontend_qb_traffic_yaxis_and_annotation` —— node 电池 `_qbSeamHint` 17 条(含实测帧重建三条与左端两点边界) + 第 6 节左端整行活性锚; 红绿双验 = 退回旧左端 4 红 / 去掉左端 3 红(见基线切片 `26-10-16-1204-qb-traffic-restart-spike-gap-p4-rev.md`)。
- **相邻纪律**: 放宽边界 = 放宽误报面, 必须同步论证**反方向仍能排除**; 改这类判据先回答「这条边界的不可分带宽是多少」, 答案来自采样节拍/落桶对齐的物理量, 不来自直觉。
