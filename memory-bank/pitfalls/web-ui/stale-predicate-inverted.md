# stale 谓词的取反被写成双重取反: 语义静默翻面, 图恒停在加载态

> 摘要: 同一对象上成对出现的 `active`(本图此刻该不该显示/拉)与 `stale`(在途响应是否**已过期**→丢弃)是**互为反义**的两个谓词; 机械改名/整行重写时把 `stale` 的 `!(...)` 敲成 `!!(...)`, 语义整个翻面 —— 恰在「本图正在被看」时判「已过期」。静态字符串守阵对此天然失明(`!` 与 `!!` 的差别只在运行时语义), 症状是**卡在加载态**: 无报错、无红、控制台干净, 只有用户看得见。
> 等级: L0
> 触发: 改 stale 谓词, 机械改名, 双重取反, 图加载不出来, 一直显示正在加载, loading 不复位, 谓词极性, _qbLoad, _QB_SCOPES, active 与 stale

### `stale` 是否定式; 写成 `!!` 就翻面

- **触发**: 改/重构一对同源判据(`active` 与 `stale`)里的任一个 —— 尤其**机械改名**(2026-10-12 实测:
  W2–W6 抽屉重构把 `t.drawer.kind === "seed"` 改成 `t.drawerIsSeed`, 整行重写时把 `!(...)` 敲成 `!!(...)`,
  `global` 那处保留 `!(` 未中招 ⇒ 症状只在种子/分组图)。
- **判别**: 三个特征叠在一起才能认出它 ——
  ① **症状是「加载不出来」而不是「报错」**: `_qbLoad` 里 `stale=true` 会让数据**不落袋** +
  `finally` 的 `if (!stale) loading = false` **不复位** + `if (stale) return` **早退不建图** ⇒
  `qbCurPending`(`loading && 无数据 && 无错误`)恒真 ⇒ 面板永远停在「正在加载流量数据…」;
  轮询 tick 又被卡住的 `loading` 挡住 ⇒ **永不自愈**。
  ② **静态锚全绿**: 源码里 `stale:` 键名、字段名、字面量一个没少 —— 字符串级断言看不见单/双 bang。
  ③ **同源另一半是对的**: `active` 与 `stale` 一起读就能看出矛盾(活跃时 `stale` 却为真)。
- **处置**: `stale` 一律写成**否定式** `!(...)`(与 `_drawerStale(hash, seq)` 的 `hash !== hash || …` 同族语义);
  改名/重构时**连同极性一起复核**, 不要只换标识符。若一处是 `!(...)`、兄弟处是 `!!(...)`, 先假定后者是错的。
  **守阵**: `tests/test_webui_static_dom_panel.py::test_frontend_qb_traffic_scope_stale_polarity` —— 两层:
  ① 静态极性(无 node 兜底): `torrent`/`group` 的 `stale` 表达式必须是 `!(t`, 出现 `!!(` 即红;
  ② **运行时行为**(主判据, node 电池): 用 `new Function(源码 + "return _QB_SCOPES;")` 取出作用域表
  (模块级 `const` 不会被 sloppy 直接 eval 漏到外层, 只有 function/var 会), 对三挂点喂
  「活跃 / 已切走 / 已关闭 / 换目标 / 功能关闭」五类上下文断言 `stale` 真假 + `active => stale === false` 同向性,
  并**真跑 `_qbLoad`**(假 vm + 假 api)断言响应确实落进 `qbTorrentData`/`qbGroupData` 且 `loading` 归位。
  红验: 注入 `!!(` ⇒ 静态层与 node 层**各自独立**变红(14 条失败, 含两条「落袋」断言) → 还原即绿。
- **为什么必须钉运行时而不是再加一条字符串锚**: 本次两处 `!!(` 与合法的布尔强制转换
  (`drawerIsSeed` 定义处的 `!!(this.drawer && …)`、`active` 谓词)在**文本上完全同形** ——
  按形态扫 `!!(` 会误伤合法的那些。判据只能是「这个谓词在真值上下文里给出什么」。
