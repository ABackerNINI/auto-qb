### 三轮补丁修不完的整列 x 向压缩: 视口从多源拼接的显示列现推, 任何一层失守即复发

- **触发**: 时间轴图表用 uPlot auto range(视口 = 显示列 [首,尾])而显示列是多源拼接物(本例: GET 组点列 + SSE 事件尾点 + 显示层补点)。任何让「列跨度 != 名义窗」的路径都产生压缩: 头部修剪失效(只增尾不剪头 -> 跨度单调变宽)、补点滞留(摆回拍被对账 GET 打断 -> 零变化判定不纠偏)、换窗竞态(旧窗口的在途响应覆盖新窗数据 -> stale 判据不含窗口名)、instant/reduce 档补点永不摘。用户症状恒为「左边的曲线不出窗口而是整列在 x 方向压缩」。
- **判别**: 三信号齐 = 该换代而不是继续补 —— (1)同一症状反复出现且每轮修的层不同(数据面/视口面/取数面各修一轮仍有残留); (2)修复引入的记账面越滚越大(补点携带门/打断继承公式重建/双锚分离记账, 每层都有自己的边界场景与盲区); (3)不变量只存在于「各层都正确」的组合态而非结构上强制(任何一条路径漏网即复发)。旁证: 电池场景数随补丁线性涨, 每轮都要补「上一轮没覆盖的打断形态」。
- **处置**: 把视口变成**显式恒等式**并在结构上使坏状态不可表达 —— (1)视口 = [anchor − span, anchor], anchor 取「语义上的窗口锚点」(本例 = 末样本时刻, 单调递增; 换窗竞态天然无害), 永不从数据现推(auto 全窗退役, 每次数据落袋后显式重申); (2)单列恒等(显示层补点/记账退役, 左缘裁剪数据由数据层余量列承担: 列 = [tail − (span+margin), tail], 整列替换后由历史保留合并回填); (3)取数有效性判据覆盖**全部维度**(作用域/上下文/窗口名, 发射时快照落袋前比对)。配套: 电池断言恒等式本身(收敛态视口跨度 == 名义窗)+ 余量列变异盲区封堵场景(auto 与锚视口同形的列会拦不住, 必须造带余量的列)。
- **守阵**: 节拍电池 J1-J10(锚判定)/L1-L9(在途锚/保留合并/余量修剪)/S14-S20b(打断续滑/单调锚/instant 落地/余量列封堵); 静态钉「退役件剥注释全文件零残留」(_qbRollJudge/_qbPadTailColumns/_qbInheritedViewport/_qbBeatVpRem/_qbPad)。
- **复发**: 0
