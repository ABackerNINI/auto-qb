# grid 跨列项的 max-content 摊进 auto/minmax 轨道, 列宽被无关内容撑大

> 摘要: CSS Grid 里跨全部列的项(说明段/横幅类)参与轨道尺寸计算 —— 它的 max-content 贡献会摊进 spanned 的 auto/minmax(auto,...) 轨道, 把「按内容取宽」的列撑远超设计底线; 守阵(类存在性/行数/DOM 断言)全绿也测不出, 只有实机截图/目检可见。
> 触发: 把「说明段落/提示条/横幅」等与数据行同容器、又给了 `grid-column: 1 / -1` 的元素留在网格内; 或容器既是 padding 壳又是 grid(为省行数/文件行数上限时容易这么干)。

## 26-11-11 快捷键覆盖层键帽列被 kb-note 撑到 ~375px(实机截图发现)

- **触发**: 键位编辑全屏覆盖层重排为单一 grid 三列(`420px minmax(220px,auto) auto`)时, 为在单分片 560 行上限内零行数增长, 把 `kb-table` 类直接挂在内层 padding div —— 说明段 `.kb-note` 与条件段 `.hb-hp` 成了跨全列网格项。`.kb-note` 文本 max-content ~950px, 缺口(950 - 其余轨道自然和 ~630)被摊进两条 intrinsic 轨道, 键帽列从 220px 底线被撑到 ~375px, 按钮组被推远。
- **判别**: 列宽明显大于 `minmax` 底线且与该列自身内容宽度无关; 打开 devtools 看轨道宽度 ≠ 设计值; 守阵全绿(类存在/DOM/行数断言都不覆盖轨道几何); 页面渲染正常无报错 —— 只有截图或目检能暴露。
- **处置**: 跨列说明性内容**移出网格** —— 给列表数据包独立 wrapper div 作 grid 容器, 说明段留在网格外的普通块级流里; 若文件行数上限卡着(本例 settings-detail 560 行), 行数代价用同块内折行合并抵消(合并开标签/长文本行), 净增 0 行。事后在 CSS 注释里写明「说明段留在网格外」的 why, 防后人省 wrapper 复发。
- **守阵**: 无(轨道几何是纯观感面, 静态守阵够不着; 对策 = 观感面改动必配实机截图目检, 见该任务切片 R0)。
- **复发**: 0
