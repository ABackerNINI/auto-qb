# 未保存改动守卫: 刷新键可拦, 但 beforeunload 必须随脏态挂摘

> 摘要: 做「有未保存改动时刷新要提醒」这类守卫时, 三处最容易踩: ① 别被 `shortcuts.js` 的 `KB_BLACKLIST`(把 `F5` 列为"浏览器不可拦组合")误导 —— 那条黑名单管的是"业务动作不许绑到这些键", 而**拦截浏览器默认刷新**是另一回事, 桌面端 F5 / Ctrl+R 的 `preventDefault()` 确实能取消默认刷新(移动端不可靠); ② 自绘框(可定制文案 / 可给「保存并刷新」)只能拦键盘刷新, 其余真实导航(地址栏回车 / 关标签 / 后退)JS 取消不了, 只能靠原生 `beforeunload` 兜底 —— 两套框并存是这类方案的固有代价, 不是实现缺陷; ③ 原生兜底**只在脏态期挂载**, 且**主动刷新前必须先摘掉**, 否则自绘框答完紧接着的 `location.reload()` 又弹一次原生框(双框连击)。
> 触发: 未保存改动, 刷新守卫, beforeunload, F5 拦截, Ctrl+R, 弹确认框, 防丢改动, 脏标记, bfcache

### 一: KB_BLACKLIST 的 F5 与"拦截刷新"是两件事

- **触发**: 在前端加"刷新前提醒" / 任何想拦 `F5` / `Ctrl+R` 默认行为的逻辑, 顺手读了 `shortcuts.js` 的键位黑名单。
- **判别**: 看到 `KB_BLACKLIST` 里 `bad.add("F5")` 且注释写"preventDefault 无效的组合", 于是断定"F5 拦不了" → 直接放弃键盘拦截, 只剩原生框(文案不可定制, 也就没有「保存并刷新」这一支)。判据: 黑名单的语义是**"业务动作不许绑到这些键"**(面板拒绑 + 守阵断言默认键不碰), 与"JS 能不能取消浏览器默认刷新"无关。
- **处置**: 键盘拦截写成**独立的 keydown 守卫**(如 `config_editor.js::_cfgOnReloadKey`), 不进注册表、不受黑名单约束; 用 `e.code` 物理键位判 `F5` 与 `Ctrl/Cmd+R`, `preventDefault()` 取消默认刷新; 并在代码注释里点明与黑名单的分工, 免得后来人按黑名单把守卫删掉。移动端 / 后台标签被回收时根本不触发 —— 属浏览器策略, 接受即可。

### 二: 自绘框拦不住真实导航, 原生兜底必须有

- **触发**: 给"离开页面"加自绘 modal 确认框(可写中文、可给多选项)。
- **判别**: 键盘刷新的路径被拦住了, 但**地址栏回车 / 关标签 / 后退**照样直接走人 —— 自绘 modal 无法取消导航, 唯一能取消导航的钩子是原生 `beforeunload`。只做自绘 = 漏掉一半路径。
- **处置**: 两条链并存 —— 键盘走自绘(可定制), 其余走原生兜底(`preventDefault()` + `returnValue = ""`, 文案由浏览器给); 已有弹窗打开时不叠自绘框(交给原生兜底), 免得 `_openModal` 把上一个悬空 Promise 静默结算为取消。

### 三: 兜底随脏态挂摘, 且主动刷新前先摘

- **触发**: 挂 `beforeunload` 监听 / 在自绘框里执行 `location.reload()`。
- **判别**: ① 无条件常驻挂载 → Firefox 直接放弃该页的 bfcache, 且每次刷新都弹框(用户被训练成闭眼点"离开"); ② 自绘框点了「刷新」后直接 `location.reload()` → 原生框紧接着又弹一次(双框连击, 用户答了两遍)。
- **处置**: 判据收在**脏态**一条上(本项目 = `cfgDirty`, 与页面上的"有改动还没保存"同源), 由 watcher 驱动挂载 / 摘除成对(幂等, 防句柄堆叠); 保存成功 / 放弃改动 / 登出各自清零即自动摘除; 任何主动刷新前先 `cfgGuardRelease()`。挂载范围别按"当前页"收窄 —— 配置树内存常驻, 改完没保存切走仍是脏的, 按页收窄会留下静默丢失的洞。
- **守阵**: `tests/test_webui_static_dom_page.py::test_frontend_unsaved_changes_guard_wiring`(六类不变量: 三选一框基础设施 / 挂摘成对 / 只拦 F5·Ctrl+R 族且脏态为假放行、已有弹窗不叠框 / 三分支含保存成败判定 / 刷新前摘兜底 / lifecycle 注册撤除 + state watcher 接线), 另含反向断言「config_editor.js 不得碰 Web Storage」(整树入存会把 `qbittorrent.password` 摆上 XSS 面)。
- **来源**: 2026-10-02 issue 26-09-25-1702 实施(报告 26-10-02-0508 路线 U1-b)。
