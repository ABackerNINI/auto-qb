# 抽屉换目标闪烁(软切换 FX-29)

> 摘要: 上下键跟随换种子时抽屉闪烁的四处成因 —— 换目标清空数据 -> body 落加载空态 -> 未记忆高度的面板抽成一条再撑回(列表与面板连锁跳动); 头部标题等详情, 中间一帧显示 40 字符 hash; general 的详情空态压在所有页签之前; 以及「快的中间态」本身也是一种闪。处置 = 软切换(保留旧数据撑几何 + switching 遮罩防串显 + 按 tab 登记待到集合, 全到手才落定)。**同族第五处(2026-10-05, 流量图)**: loading 空态接管的判据写窄成「无点」—— 空态文案与错误文案也是既有状态, 续拉同样不许接管。**同族第六处(2026-10-07, 流量图入口重入)**: 打开类入口缺同目标幂等短路, 重按 Ctrl+\ 把收图+重建+首拉各闪一遍 —— 已开着的东西再"打开"一次应当是零副作用。**同族第七处(2026-10-07, 详情面板显式换种子)**: 已开面板下换目标同样走入口整体重建路径 —— 交棒软切换, 不重建。
> 触发: 抽屉闪烁, 上下键切换种子, 面板塌一下, 标题变 hash, 正在加载详情, 串显, 防串显, 清空数据, drawer.switching, _switchDrawerTarget, switching 遮罩, 高度塌陷, 42vh, 空态闪烁, 暂无 qB 口径流量数据, 从未有传输记录, 每个轮询周期闪一次, loading 空态接管, qbCurPending, 错误文案闪, 重按快捷键, 重复打开, 入口重入, Ctrl+\, openTorrentDrawer, 换种子闪空态

### 「拉新数据前先清空旧数据」把等待渲染成一帧空态(连按 = 持续闪烁)

- **触发**: 跟随键盘换目标(`_switchDrawerTarget`)为防串显把 `detail / trackers / files / peers` 一把清空,
  每次光标停下都走一遍「整幅内容消失 -> 落到加载空态 -> 数据回来重建」。连按上下键时它不是"卡", 是**稳定复现的闪**。
- **判别**: 串显与闪烁被当成同一个问题的两面 —— 清空确实治好了串显, 代价是把"还没到"渲染成了"什么都没有"。
  凡缓存/_detail-over-write 类替换, **先清空再拉** 一律等价于承认「中间态可以是一片空白」。
- **处置**: 保留旧数据, 用**遮罩**而不是清空来完成同一件事 —— `drawer.switching` 期间内容降到 `opacity: .12`
  并 `pointer-events: none`(不可读且点不到), 新数据落袋才掀罩。串显守得住(读不到旧值), 几何也不动。

### 高度自适应的停靠面板: 内容清空 = 面板塌成一条, 列表跟着跳

- **触发**: 面板未被拖拽过(无 `drawerHeightPx` 记忆)时只有 CSS `max-height: 42vh`, **高度随内容**。
  空态把 body 从整幅表格压成一行 => 面板瞬间变矮; 数据回来又撑开。用户眼里是列表与面板一起上下抽动。
- **判别**: 停靠面板不是浮层 —— 它占文档流, 高度变化会传导给列表(滚动位置/可视行数)与 sticky 定位。
  "内容变了"和"面板尺寸变了"是两件事, 后者才是抖动源。给面板加过 `height` 记忆的用户**不复现**(所以报障会说偶发)。
- **处置**: 同上(不清空 => 切换期间高度不变)。更进一步: 任何**会改变面板高度的内容更新**都要问一句
  "这次更新要不要动几何", 能撑住的就撑住。

### 遮罩/加载态本身也会闪: 快响应要点亮它就是制造新闪烁

- **触发**: 遮罩若同 loading 一样立即点亮, 局域网详情常在 100ms 内到达 => 用户看到"内容淡下去又淡回来",
  等于把一次瞬切渲染成两次状态变化。
- **判别**: loading 态的价值随等待时长增长; 等待趋近 0 时它是净噪音。
- **处置**: 延迟点亮(`_drawerBusyArm`, 160ms)。短等待 => 用户看到的是"内容直接换成新的", 中间一帧都没有;
  慢下来才滑出加载胶囊。同一口径适用于任何"可能被秒回"的加载指示。

### 早到的单个请求不许提前掀罩(否则半个面板是上个种子的值)

- **触发**: 非常规页签一次切换发两个请求(详情 + 该 tab 列表), 任一完成就撤遮罩 => 另一处仍是旧值。
- **判别**: "有数据回来了" != "本次切换完成"。多个数据源的完成判定必须按**集合**而不是按**任一**。
- **处置**: 按 tab 登记待到集合(`_drawerWaitSources`: general=[detail], 其余=[detail, 该 tab 列表]),
  全部到手才 `_drawerSwitchEnd()`; 过期(stale)响应不登记; 切页签/开关面板视作打断并作废等待(否则遮罩挂死)。

### 头部标题不该等详情: 主表里已经有名字

- **触发**: 标题写成 `drawer.detail ? detail.name : drawer.hash`, 清空后又等一发请求 =>
  中间一帧把标题显示成 40 字符 hash 再跳回种子名(最刺眼的一跳)。
- **判别**: 详情是**唯一来源**不等于**唯一取处** —— 主表 `memberByHash` 每 1.5~3s 已同步, 名字当场可得。
- **处置**: `drawerTitle()` 优先取 `memberByHash.get(hash).name`, 详情只作兜底。
  凡"目标刚切换、真值还没到"的头部/摘要类显示, 先在已有的本地快照里找, 别默认退回原始 id。

- **触发**: 2026-10-04 的修法把 loading 空态门在「**无点**」上(`qbCurLoading && !qbCurPoints.length`),
  只覆盖了「已有图」一态 —— 空数据集(程序刚装/刚开、该种子从未传输)本来就没有点, 每轮 `_qbLoad`
  一亮 loading 就把空态文案顶掉一帧再换回。错误态同病: `_qbLoad` 发请求前就 `error = ""`, 错误文案
  同样每个轮询周期被顶掉一帧(错误态只是没被报, 不是没坏)。
- **判别**: 判据的**取值域**没穷举 —— 「无数据」被实现成「无点」, 而点在真实系统里有三种来源:
  ①首载未回(该亮 loading) ②响应为空态(该显示空态文案) ③请求失败(该显示错误文案)。②③ 都是
  **既有状态**, 续拉不许接管。凡「有没有 X 才显示 loading」的门, 先问 X 的所有取值里哪些算「有」。
- **处置**: 判据改为「本作用域**有无落袋结果**」—— `qbCurPending = qbCurLoading && !qbCurData && !qbCurError`

  `_qbLoad` **不再在发请求前清 error**, 改由**成功落袋**清除 —— 在途期不动既有状态(同「拉新数据前
  先清空旧数据」那条)。换目标期间的旧文案由 FX-29 遮罩(160ms 延迟点亮)兜住, 不靠清空。
- **为什么没命中**: 上一条复发记录的修法被写成「loading 空态只在**无数据**时接管」, 实现时
  「无数据」= `!qbCurPoints.length`(无点), 而本坑的判据是「有无落袋结果」—— 措辞里的模糊处
  就是下次复发的入口; 前一轮真机走查只走了「有图」路径, 空数据集(新装/新种子)不在验收项里。
- **守阵**: `test_web.py::test_frontend_qb_traffic_chart_wiring` 四锚 —— 模板门 `v-if="qbCurPending"` /
  `qbCurPending` 三合一判据(少一项 = 少一种既有状态被顶掉) / `_qbLoad` 里 `error` 清除只允许出现在
  `await this.api(` 与 `this[def.data] = data;` **之后** / setData 原地快路(原有)。
