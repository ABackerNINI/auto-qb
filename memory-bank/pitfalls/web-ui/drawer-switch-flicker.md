### 「拉新数据前先清空旧数据」把等待渲染成一帧空态(连按 = 持续闪烁)

- **触发**: 跟随键盘换目标(`_switchDrawerTarget`)为防串显把 `detail / trackers / files / peers` 一把清空,
  每次光标停下都走一遍「整幅内容消失 -> 落到加载空态 -> 数据回来重建」。连按上下键时它不是"卡", 是**稳定复现的闪**。
- **判别**: 串显与闪烁被当成同一个问题的两面 —— 清空确实治好了串显, 代价是把"还没到"渲染成了"什么都没有"。
  凡缓存/_detail-over-write 类替换, **先清空再拉** 一律等价于承认「中间态可以是一片空白」。
- **处置**: 保留旧数据, 用**遮罩**而不是清空来完成同一件事 —— `drawer.switching` 期间内容降到 `opacity: .12`
  并 `pointer-events: none`(不可读且点不到), 新数据落袋才掀罩。串显守得住(读不到旧值), 几何也不动。

### 高度自适应的停靠面板: 内容清空 = 面板塌成一条, 列表跟着跳

- **触发**: 面板未被拖拽过(无 `drawerHeightPx` 记忆)时只有 CSS `max-height: 42vh`, **高度随内容**。
  空态把 body 从整幅表格压成一行 => 面板瞬间变矮; 数据回来又撑开。用户眼里是列表与面板一起上下抽动。
- **判别**: 停靠面板不是浮层 —— 它占文档流, 高度变化会传导给列表(滚动位置/可视行数)与 sticky 定位。
  "内容变了"和"面板尺寸变了"是两件事, 后者才是抖动源。给面板加过 `height` 记忆的用户**不复现**(所以报障会说偶发)。
- **处置**: 同上(不清空 => 切换期间高度不变)。更进一步: 任何**会改变面板高度的内容更新**都要问一句
  "这次更新要不要动几何", 能撑住的就撑住。

### 遮罩/加载态本身也会闪: 快响应要点亮它就是制造新闪烁

- **触发**: 遮罩若同 loading 一样立即点亮, 局域网详情常在 100ms 内到达 => 用户看到"内容淡下去又淡回来",
  等于把一次瞬切渲染成两次状态变化。
- **判别**: loading 态的价值随等待时长增长; 等待趋近 0 时它是净噪音。
- **处置**: 延迟点亮(`_drawerBusyArm`, 160ms)。短等待 => 用户看到的是"内容直接换成新的", 中间一帧都没有;
  慢下来才滑出加载胶囊。同一口径适用于任何"可能被秒回"的加载指示。

### 早到的单个请求不许提前掀罩(否则半个面板是上个种子的值)

- **触发**: 非常规页签一次切换发两个请求(详情 + 该 tab 列表), 任一完成就撤遮罩 => 另一处仍是旧值。
- **判别**: "有数据回来了" != "本次切换完成"。多个数据源的完成判定必须按**集合**而不是按**任一**。
- **处置**: 按 tab 登记待到集合(`_drawerWaitSources`: general=[detail], 其余=[detail, 该 tab 列表]),
  全部到手才 `_drawerSwitchEnd()`; 过期(stale)响应不登记; 切页签/开关面板视作打断并作废等待(否则遮罩挂死)。

### 头部标题不该等详情: 主表里已经有名字

- **触发**: 标题写成 `drawer.detail ? detail.name : drawer.hash`, 清空后又等一发请求 =>
  中间一帧把标题显示成 40 字符 hash 再跳回种子名(最刺眼的一跳)。
- **判别**: 详情是**唯一来源**不等于**唯一取处** —— 主表 `memberByHash` 每 1.5~3s 已同步, 名字当场可得。
- **处置**: `drawerTitle()` 优先取 `memberByHash.get(hash).name`, 详情只作兜底。
  凡"目标刚切换、真值还没到"的头部/摘要类显示, 先在已有的本地快照里找, 别默认退回原始 id。
