# 界面页签集合改了, 键盘切换映射不跟着改 = 按了不是预期那一页 (静默)

> 摘要: 详情面板的页签快捷键(Alt+1~5)与**可见页签集合**是两套独立事实源 —— 页签栏收敛为合并页签后, 注册表五档仍按旧的四页签映射(`Alt+3` 名义「用户页」实际落到收起页签), 症状是**按了键切到别的页签**(不报错、不白屏, 只是"怎么跳到这页去了")。修法 = 键盘入口按 `dtMergeTabsOn`(与页签栏 `v-if` 同一判据)**按位次重排**到可见页签, 且重排必须**先于**功能门控; 帮助/设置面板文案同源改写。2026-10-10 用户报「标签合并后没有同步修改快捷键」。
> 触发: 改页签/子视图集合, 页签栏收敛或增删页签, 快捷键切错页签, Alt+数字不对, 合并页签, 快捷键没同步, 按了跳到别的页

**Refs:** memory-bank/activeContext/26-10-09-2226-webui-drawer-merge-tabs.md

### 页签集合 × 键盘映射 是两条事实源, 改一条必须同步另一条 (2026-10-10 实测)

- **触发**: 任何改变「页签栏里有哪些页签」的改动(合并/收敛/增删/门控隐藏)。此时**注册表里的默认键位与 label 不会自动变**, 因为键位是按键位单一事实源写死的静态表。
- **判别**: 症状是**按了键切到错误的页签**(不是"没反应")。合并态页签栏 = `[常规&内容][Tracker&用户](+流量)`, 而五档注册表仍是 `Alt+1..5 -> general/trackers/peers/content/traffic` —— 位次错位即本坑指纹。鼠标点击正常(走 `dtMergeTabPick`/`drawerTab`), 只有键盘路径中招。
- **处置**(在**键盘入口**单点收口, 不动鼠标路径):
  1. 重排表按**位次**: 合并态 `Alt+1..3` → 三张可见页签, 4/5 无对应 → 停用(null, 静默); 未合并(开关关/宽度门外)回落五档原样。
  2. **重排必须先于功能门控**: 第 3 档重排成 `traffic` 后仍要过 `qbTrafficOn` 门, 否则未启用也会切到无按钮的隐形页签(见坑 `drawer-open-vs-kind`)。
  3. 判据**复用页签栏的同一 computed**(`_kbMergeTabsOn` 读 `dtMergeTabsOn`), 不自造第二套; 门依赖视口宽时, 重排也随之随态。
  4. 帮助浮层 / 设置页的条目文案经**同一随态单点**(`kbLabel`)改写, 静态 label 仍归注册表(单一事实源), 只在本组 + 合并态时覆盖。
- **守阵**: `tests/test_web_shortcuts.py::test_drawer_tab_shortcuts_merge_remap`(静态: 位次表 / 重排先于流量门 / 判据单点 / 两处模板走 `kbLabel`) + `e2e/drawer-merge.spec.mjs`(真浏览器: 合并态 Alt+1/2 切两页签对, Alt+4 停用零变化, 双皮肤)。
