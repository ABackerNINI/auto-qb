# 抓页面时用松正则取小片段, 会匹配到别处的同类文本

> 摘要: 从 HTML 里抽一段小数字 / 小文本时, 不锤定结构的正则会匹配到页面上别处的同类文本 —— 结果**看着合法但值是错的**, 且不报错。
> 触发: 爬页面, 抓页面, 解析 HTML, 正则提取, 页脚区间, 分页判据, HR 统计页, 站点改版, 数字提取

## 症状与判据

- **触发**: 写页面解析时图省事, 用 `(\d+)\s*-\s*(\d+)` 之类的**松正则**去"抓那个数字"。
- **判别(2026-09-24 实踩)**: BTSchool `myhr.php` 页脚的「1 - 2」(条目区间)与数据行的
  **完成时间 `2026-09-21`** 几乎同形 —— 松正则先命中的是完成时间, 于是"最后页区间"恒为
  `(2026, 9)`。值**不是** None、也不报错, 单看返回值完全看不出错; 是测试断言
  `page_bounds(html) == (1, 2)` 当场把它抓出来的。
- **处置**: 抽小片段必须**锤定结构**(附近的专有标记 / 标签), 不能只靠"它长这样"。本例改成
  先 `&nbsp;` 归一化、再锤 `(\d+)\s*-\s*(\d+)\s*</b>` —— 日期后面从不跟 `</b>`, 一句话就把
  歧义消掉了。更稳的做法是走同一套栈式表格抽取(按列取), 而不是正则扫描全文。
- **同时值得记的一条**: 「认不出就返回 `None`」比「猜一个」安全得多 —— 本模块里
  `parse_duration` 遇到 4 段形如 `1:2:3:4` 直接返回 `None`, 就是为了不让下游拿错值去算闸门。
