# 按用户可配的格式串解析文本产物, 不能用字面量锚点

> 摘要: 解析"按 format 渲染出来的文本"(日志行首当其冲)时, 把字段的**书写形状**写死成字面量 —— 默认配置下侥幸能跑, 用户换一种 format 就**静默失效**; 过滤类失效的表现是"恒空", 与"确实没有"完全同形。
> 触发: 日志过滤, 按等级, 日志行解析, levelname, 日志格式, format, 正则提取, 文本解析, 恒空, 结果为空

## 症状与判据

- **触发**: 写"按等级筛日志行"这类解析 —— 从一行**已格式化**的文本里定位某个字段。
- **判别(2026-09-25 真机)**: `/api/log` 原实现是 `[ln for ln in lines if f"[{lv}" in ln]`, 锚死默认格式
  `%(asctime)s [%(levelname)s] %(name)s: %(message)s` 的**方括号**; 而 `log.format` 是**用户可配的**,
  生产 `config.yml` 写的是 `%(asctime)s - %(levelname)s - %(message)s`(无方括号)⇒ 选任何等级都恒空,
  界面只剩"日志文件暂无内容"。
  ❗**最坑的一点**: 它不报错、不抛异常、也不返回 None —— 与"这个等级确实没有日志"在所有观测点上同形,
  所以从"过滤结果为空"**无法区分**两种情形(旧测试也因此在旧实现下照样绿, 见 testing/assertions.md 同族条目)。
- **处置**: 解析必须**从配置的 format 反推字段位置** —— 本项目单点是
  `infra/logging.py::_level_line_re()`: 把 `%(levelname)s` 那一段编成命名组, 其余字段当
  "到下一个字面量为止"的通配符(`message` 用 `.*` 吞到行尾, 数字型字段用 `\d+`)。两条实现要点:
  ①**别把字面量里的空格放宽成 `\s*`** —— 字面量正是字段之间的**分隔证据**, 放宽会让前一个纯字母字段
  把等级名吃掉(实测 `%(name)s %(levelname)s` 的 `auto_qb.core INFO 启动` 会把等级解析成 `core`,
  锚定版才解析出 `INFO`); ②**要吸收字段宽度补的空格** —— `%(levelname)-8s` 会在等级名后补空格,
  漏了这条则"带宽度声明的格式一行都对不上、整份日志退化成筛不了"(实测踩到)。
- **兜底纪律: 筛不了就直说**。回**全部行 + `note` 提示语**, 绝不给静默空结果:
  格式里没有等级字段 → 提示语①; 格式有等级字段但**一行都对不上**(改了 format、文件里还是旧格式的历史行)
  → 提示语②。右对齐的 `%(levelname)8s`(等级名前补空格)同样定位不到, 也走这条提示, 不静默。
- **同族: 多行记录**。`exc_info=True` 打出的整段 traceback 折行后每行都不带字段标记 ⇒ 解析必须按
  **记录**取舍(解析得出的行开启新记录, 解析不出的行**跟随上一条**的取舍), 否则筛 ERROR 只剩
  `... 执行异常: ...` 标题行、把用户真正要看的栈丢掉。
- **守阵**: `tests/test_web.py::test_api_log_level_filter_follows_config_format`(生产格式) ·
  `::test_api_log_note_when_level_unfilterable`(两种"筛不了") ·
  `tests/test_logging.py::test_filter_log_lines_*`(格式形状矩阵 / 多行记录 / 提示语 / 字段宽度与 `%%` 变体)。
