# 环境态混进站点故障: 「等扩展超时」被当「页面改版」

> 摘要: 分类模型缺一层时, **通道 / 环境类**故障会掉进基类, 被下游当「站点故障」处理 —— 于是环境噪音进持久证据链(站点文件 `wave.notes`)、推进档位失败(连关几晚升成「疑似改版」ERROR), 并出现在前端错误历史。判据: **异常即分类** —— 「能不能靠重试解决」决定归属层; 出口按「层 × 档位」收放, 而不是在生产点打「给前端看 / 不看」的标记。
> 触发: 告警文案与真实根因不符, 环境态被当站点结论, 错误历史里出现「浏览器 / 网络 / 本机」字样, 通道静默, 取数超时, 新增告警出口, 想给日志打静默标记

**判别**:

- 该异常在抛出点用的是**具体类型**还是**基类**? 抛基类(如 `HrFetchError`)就会落进「站点 / 页面」出口 —— 归位靠**新增子类型**, 不是在下游加 if 判据。
- 归属层是谁? 沿用既有那条 **能不能靠重试解决**: 等通道恢复(等回传超时 / 端点未监听 / 未启用通道) = **通道层**; 需人到场(登录失效) = **账号层**; 需人核对页面(改版 / 字段 / 排序 / 守恒) = **站点层**。
- 该不该让前端(错误历史 / 系统通知)看见? **由可观测证据定, 不由产生点猜**: 通道层里「没人在用 WebUI」⇒ 静默, 「有人在场却收不到联系」或「被拒敲门(401/403 ⇒ 扩展在跑、是配置错)」⇒ 可见。
- 先看 **except 顺序**: 父类分支写在子类之前时, 新增的子类**可能无需改上层** —— 本案 S2「新增 except 分支」就因为 `except HrChannelUnavailable` 已在 `except HrFetchError` 之前而整步免做。

**处置**:

- **补分类**(根因): 给漏建模的那一支自己的异常类型, 让它落进**既有**出口 —— 不要在下游逐一打补丁。
- **层单点**: 文案模块出「事件 → 层」表, 生产点只选事件。这样「通道层事件被贴上站点层标签」在代码上**不可表达**。
- **出口收放**: 出口侧读标记(如 `infra/logging.is_record_suppressed`), 生产点只**声明归属**(如 `hr_domain` / `hr_silent`)。**不要**在生产点写「前端别收我」这类带出口名字的标记 —— 那是耦合, 而且只遮住前端, 下面的污染一点没动。
- **级别**: 静默子类降到 INFO/WARNING 之外, 还要注意「WARNING 以上会被推成系统通知」这条 —— 想「只打后端 log」就得同时挡住 errlog 与 notify 两条出口。

**守阵**: `tests/test_hr_service.py`(通道归位 / 不升级疑似改版 / 页面失败边界回归 / 层表)· `tests/test_hr_worker.py`(三档可见性)· `tests/test_webui_backend_errlog.py`(静默不入环)· `tests/test_notify.py`(静默不通知)· `tests/test_hr_server.py`(被拒接触面 + 401 节流)

**复发**: 2026-10-09 用户实报「关浏览器过夜, 错误历史出现 4 条 `[HR 页面改版] 页面取数失败(等待浏览器扩展取数超时 180s)` + 2 条 `[HR 通道静默]`」—— 根因即「等回传超时」抛的是裸 `HrFetchError`。修复见 [plans/26-10-09-0821](../../plans/26-10-09-0821-plan-hr-fault-domain.html)。
