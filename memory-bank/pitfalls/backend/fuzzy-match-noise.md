# 相似度判据里混进「通用技术词」⇒ 成片假重合(判据看着严, 实际在批量误配)

> 摘要: 用「够长的连续重合段」判两个发布名是否同一内容时, 若不先把分辨率 / 来源 / 编码 / 音轨这些
> **每个发布都一样**的词剔出判据, 重合段就会整段由它们构成 —— 提高阈值 K 也拦不住(年份 + 季标 +
> `Complete` + 分辨率能凑出 20 字符)。症状不是报错, 是**配额被悄悄烧掉**。
> 触发: 粗配, 相似度, 重合段, 名称匹配, fuzzy, 阈值 K, 假重合, 假阳性, 质量标签, 判据收紧, 白烧配额, 下载触发器

### 判据的空间里有多少成分是「所有人都有的」? (2026-09-29)

- **触发**: 写 / 调「两名字足够像 ⇒ 认定为同一对象」的宽松匹配(本仓: HR 粗配 `fuzzy_name_match`,
  原判据 = 归一化后存在 ≥K=12 字符连续重合段), 或给这类判据挑阈值。
- **判别**: 先算**重合段是什么构成的**, 而不是先看命中数。实测(用户真实数据 50 条活跃行 × 108 本地名):
  159 对命中里 **128 对**重合段是 `1080pwebdlh26` / `0pwebdlh265aac` / `1080pnfwebdl` /
  `2026s01complete1080p` 这类纯技术词, 真命中只有两族标题段。现象层表现为「功能正常、日志安静,
  但 114 次 .torrent 下载只有 2 次真命中」(每下 1 次都吃站点配额: 90s/请求、240/日)。
  ❗**提高 K 治不了这一类**: `2026s01complete1080p` 长 20, 双方都是 2026 年的剧 ⇒ 再高的 K 也能凑出来。
- **处置**: ①按**整词**剔噪声, 不做子串替换: 归一化前后都按分隔符切词, 命中
  「分辨率 / 来源 / 编码 / 音轨 / 发布类型 / 字幕」整词表即丢弃 —— 子串替换会把标题里的字符一起啃掉;
  ②短词也要收(`WEB-DL` 会拆出 `dl` 这种 2 字符整词, 漏掉它会让「信号串完全相等」这条通路失效);
  ③判据改在「信号串」上做, 并**保留信号串完全相等这条不受 K 约束的通路** —— 短标题(尤其中文)
  几乎只能靠它召回; ④落地前用真实数据算三组数字(剔前 / 剔后 / **新增**), 本仓实测剔 128、新增 0;
  顺手验的「再剔发布组后缀」零收益(4 → 4)就**不做** —— 没验证的规则别一起塞进判据;
  ⑤守阵固化真实样本对(误配必须不再命中 + 真命中必须保住), 红验方式 = 只回退实现、保留测试。
- **残余(有意留)**: 标题段短于 K 且两侧组标不同 ⇒ 不触发粗配, 该对象落回「无站点证据」兜底档 ——
  宁可少触发, 不再拿配额换假重合。
- **守阵**: `tests/test_hr_service.py::test_fuzzy_name_match_rejects_noise_only_overlap`(4 条真实
  假重合 + 2 族真命中)、`::test_fuzzy_name_match_unit`(噪声整词不构成判据 / 整名皆噪声不上判据);
  红验 —— 仅回退 `src/auto_qb/hr/service.py` 即这两条红。
