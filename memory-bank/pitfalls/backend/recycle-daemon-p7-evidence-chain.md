## 本篇只回答

recycle daemon 实例级下线证据链(2026-11-11 上线, 计划 26-11-10-0318)的竞争面为什么这样定义、判据语义是什么、settle 30s 的赌注依据、已知残余与外部警示全集。方案推演与拍板过程看计划/档案, 本篇不复述; 通道函数族与状态机的代码形态看 `tools/recycle_daemon.py`(观测面)/`relocate_journal.py`(obs 文件 helper)。

### 竞争面定义: 同 profile 实例才是 N1 竞争者(全机口径的病根)

- **触发**: 评估「谁的运行期重写会与 daemon 的收尾改写竞争」时, 直觉按「同机所有 qB 进程」算(名册只有映像名, 全机口径的历史成因)。
- **判别**: N1 铁律( qB 运行期零写入 )的竞争 = **同 profile** 实例对同一 BT_backup 目录 fastresume 的运行期重写; 不同 profile 实例不加载这些文件, 不构成竞争。全机口径把非竞争者(其它实例)也当竞争者挡窗, P7 形态(目标死+日常活)下窗口永不开——issue 26-11-07-0528 记录的正是这个病根。
- **处置**: 竞争面按 profile 收窄, 证据链按「目标 profile 的实例终将监听我们的 host:port, 别的不会」这个硬差异分辨实例归属(owner 归属记录/新面孔监听集), 全机口径原样保留为 L2 退化路径。

### L1 证据链三条件与「立即进窗」语义

- **触发**: 问「窗口什么时候开、为什么可以没有 30s 稳定期」。
- **判别**: L1 进窗 ⇔ ① owner 记录有效且 owner 已死(pid 消失 / pid 在但 create_time 不匹配 / pid 在但映像非 qB——后两条是 PID 复用防御) AND ② 端口拒连 AND ③ 新面孔状态机无未决成员; 三条件同时成立**立即进窗**(无 down_since 计时)。立即进窗的安全性根基: 「新身完全未起」的死亡间隙落盘安全(写时无 qB 运行, 新身读到改写件走 N4 别名加载自洽), 「已创建未绑端口」的尾部由未决态挡住; 逐成员落盘前复验与进窗判据**同级**(全套现读现判)——复验粒度低于进窗粒度 = 立即进窗不安全。
- **处置**: 改判据/复验逻辑时保持三条件与复验同级不拆; owner/absorbed 状态持久化在 obs 文件(`<data_dir>/relocate/obs-<instance_key>.json`), daemon 重启后恢复死证, 不因 daemon 停机丢判定。

### settle 30s 是有界赌注(依据: WebUI 绑定秒级)

- **触发**: 问「为什么 30s 不绑我们的端口就敢吸收一个新 qB 进程」。
- **判别**: qB WebUI 监听绑定发生在启动早期(秒级); 真机 P7 实测复活 bind 距窗顶复验仅秒级量级(S2 复活 bind +6.35s), 绑定探测单次 ~250ms。30s = 10 倍量级余量, 有界赌注成立的前提是「WebUI 绑定是启动早期动作」这条外部事实不变。
- **处置**: 常量独立(`NEW_FACE_SETTLE`, 30s)可调; 若 qB 未来把 WebUI 绑定延后或默认关闭, 本赌注失效——升级判据前先复核这条事实。误吸收代价面见下条残余。

### 已知残余(外部不可区分族): 四条

- **触发**: 认为「实装后 P7 就完全无风险」或排查「为什么收尾改写发生在不该发生的实例上」。
- **判别**: 以下残余的共同点是**外部观测原理上分不出**, 无零赌注堵法:
  1. **时钟回拨跨 owner 创建边界**: 零赌注吸收阈值 W1b 评审后已从混域比 `ct<ts_last` 升级为同域比 `ct<owner.ct`, 但回拨跨越 owner 创建时刻的角落仍原理性存在(概率面大幅缩小, 无法归零)。
  2. **用户改目标实例 WebUI 端口不同步 config**: 新身永不绑我们端口 ⇒ settle 后被吸收进窗。⚠ **警示: 改目标 profile 的 WebUI 端口必须同步 config.yml 与 bt_backup 表**, 否则该实例待收尾 journal 在窗时会被照常改写(写时它已死, N1 字面不破, 但改写结果与新端口配置脱节)。
  3. **同 profile 异常双开**(用户关单实例锁): 与 2 同族, 「外部不可区分」。
  4. **qb_back 可观测性缺口**: daemon run() 对 qb_back(窗开被复验拒/放弃落盘)**不退出不上浮**——CLI 退出码/journal/日志/窗标记四处无痕, 「窗开被复验拒」与「窗未开」外部不可区分(W3a S2 十次开环实证: 复验不过的证据靠驱动侧捕获 l1_calls/revive_mark 才完成取证)。排障靠驱动侧打点; run() 加留痕属后续裁决, 不在本轮范围。
- **处置**: 均为方案边界, 记档不复杂化判据; 撞上 2/3 时按「改端口须同步 config」警示先核对配置漂移再查代码。

### 通道解析纪律: None = 不可用 = 退 L2, 绝不产假证据

- **触发**: 改动/新增观测通道(netstat/PowerShell/proc 解析)的容错逻辑时。
- **判别**: 解析失败/超时(10s)的正确语义是「本拍观测不可用」, 不是「观测到空」——两者混写会把通道故障变成假证据(owner 死证凭空成立), 直接威胁 N1。
- **处置**: 解析器不硬赌输出格式, 解析不出一律返回不可用并退 L2(全机口径)+告警 60s 节流留痕; 真机 S3a 注入实测: 退 L2 后全机名册见日常实例, 110s 零开窗(保守方向正确); 为「让 L2 能开窗」而放宽解析 = 产假证据, 禁止(S3b 的等价注入是实验手段, 不是产品语义)。
- **守阵**: 判据纯函数与状态机单测(六场景桩测试, 含通道失败退 L2); 通道解析容错用例钉住「失败返回不可用而非空名册」。
