# 高风险业务操作

> 摘要: 代码里已有防护的高风险动作 —— 改动时**不得削弱**这些防护; 删种重加、强制汇报、限速覆盖都属于这一类。
> 触发: 改跳检, skip-checking, reannounce, 改限速, 删除种子, qB 版本兼容, 死防御清理, 状态观测

### 跳检 (skip-checking): 删种重加会丢统计, 内容错误会传垃圾数据 (PT 严令禁止)

- **触发**: 改 `checking` 动作 / 跳检流程 / 重加逻辑。
- **判别**: 七道防护**缺一即违规**: 部分下载(0<progress<1)拒绝跳检; 同规则同日去重 + **跨规则**同日去重(`skip_check_day`);
  强制 filelist 前置检查; 重加前轮询确认种子已从客户端消失(qB 删除异步 ≤5s, 未消失则放弃);
  重加属性**直传**(0/负值有语义, 不得 `or None` 吞掉)+ contentLayout 由 content_path/save_path/文件列表推断;
  无参考 warning; 重加失败 `.torrent` 落盘且元数据立即落盘。
- **处置**: 一条都不许削; 另注意**跳检过程中种子会从 store 消失** ⇒ 同 tick 后续动作必须容错。

### reannounce: 本质仍是高风险操作

- **触发**: 改 reannounce / 强制汇报逻辑。
- **判别**: 现有约束是同种子最小间隔 10M(`reannounce_ts`)+ 暂停种子跳过 + 加载期未配去重 WARNING。
- **处置**: 不得放宽上述约束; 规则侧应配 `execute_once`。

### qB 版本兼容: 快照字段缺失会**静默零值**, 比崩溃更危险

- **触发**: 加 / 改快照字段, 改 `REQUIRED_TORRENT_FIELDS`。
- **判别**: `_refresh_torrents` 首次拉全量时校验 `REQUIRED_TORRENT_FIELDS`(快照 18 + 跳检重加 6),
  缺失抛 `QbCompatError` → CLI 干净退出。字段缺失时规则会**基于假数据决策**。
- **处置**: **加深快照字段必须同步 `tests/helpers.py` 的 `FakeTorrent._SNAPSHOT_FIELDS`**,
  否则 sync 版本校验报缺字段、启动即退。**fail-fast 是有意的, 别改宽容。**

### `or 默认值` 会掩盖数值字段: 方向可能朝危险侧

- **触发**: 写 `progress or 0.0` 这类"兜底"。
- **判别**: 它把上游 bug 静默转成合法语义 —— `progress=None` → 视为全新辅种 → **放行跳检**。
  合法 `or` 仅限**空串 / 空容器归一化**与**除零防护**(判别标准见 `conventions/` 的代码风格篇)。
- **处置**: 已清理闸门 / HR 判定 4 处; 新增代码一律不用它兜数值。

### 死防御清理: 判别标准是"上游流程下可能不可能发生"

- **触发**: 看到"永远为真/为假"的守卫, 想删或想留。
- **判别**: 守卫条件在正确上游流程下**不可能发生** → 删; 是**真实可选语义**(惰性缓存、运行时状态、
  功能开关) → 留。
- **处置**: 已据此删掉 client setter 守卫、`store is None` 15 处等; 拿不准就按"是不是真实可选语义"判。

### 自有动作会污染状态观测: 观测必须放在归组 / 自有停种**之前**

- **触发**: 加 / 改状态转移观测(如"上传转暂停"检测)。
- **判别**: 观测点放在自有动作之后 ⇒ **自家停种被误判为外部状态变化**, 触发多余的缺文件扫描。
- **处置**: 观测固定在**轮次开始的干净观测点**; 顺序约束详见 `systemPatterns/`。

### 删除种子: auto-qb 不存在任何自动删除路径

- **触发**: 想加"自动删种"功能 / 改 `QbApi.torrents_delete`。
- **判别**: `torrents_delete` **仅跳检流程使用**, `delete_files=False` 固定;
  规则系统**无 delete 动作**, 唯一删除入口是 **WEB UI 命令**。
- **处置**: 保持这个边界 —— 加任何自动删除路径都要先推翻这条设计决定。

### 限速不覆盖手动值: 奇数 KiB 视为用户手动设置

- **触发**: 改限速逻辑 / 写"该保护生效"的断言。
- **判别**: 判定必须统一走 `utils.is_manual_speed_limit`(**三个调用点逻辑必须一致**)。
  ⚠ 断言前先确认测试数据**真的落在保护范围内** —— 造出偶数 KiB 会被程序正常覆盖,
  于是测的是"保护没生效时的行为"。
- **处置**: 三处调用点保持一致; 测试数据用奇数 KiB。
