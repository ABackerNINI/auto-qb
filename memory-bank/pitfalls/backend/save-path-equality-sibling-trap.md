# save_path 等值判据把同保存根兄弟目录种子当组内

> 摘要: save_path 等值判据把同保存根兄弟目录种子当组内
> 触发: save_path 等值/前缀判据,内容根,兄弟目录,组内身份,foreign 候选门,删链门,假阳性

## 本篇只回答

relocate/组账类判据里「以 save_path 等值或前缀当组内/作用域信号」这一类假阳性的触发与处置 —— 组内身份判据必须锚内容根, 不锚 save_path。

### 「save_path 恰等 job.src/旧根」的候选门会卷进全部兄弟目录种子

- **触发**: 任何把「save_path 归一恰等 job.src(旧根/下载保存根)」或「save_path 在其前缀下」当**组内/作用域身份**信号的判定面 —— qB 的 save_path 是**下载保存根目录**(内容根在其下一层), PT 库按分类目录做保存根是常态布局, 同一根下几十颗内容根各异的无关种子全部满足等值。已两踩: ① 删链门旧锚(2026-11-07 T1b/E7 实测假依赖, 组外兄弟种子顶进依赖集致收尾自锁, 修复 = 计划 26-11-07-1300 D9 重锚 job.scope); ② foreign 侦测面候选门(2026-11-21 真机, 计划 26-11-20-0434 落地后首次整组迁移, issue 26-11-21-1500: activation 扫描 61 候选 60 条为兄弟目录无关种子, mismatch 洪泛呈现与通知)。
- **判别**: 候选/依赖/拦截计数与真实形态严重失衡(如 61 候选仅 1 真命中); 被标记种子的**内容根**与迁移组内容根不同但 save_path 相同; R5 类文案(「同目录异内容」)与用户核对结果(「不同根目录的无关种子」)对不上 —— 出现这类错位先怀疑判定门锚错了路径维度, 而不是怀疑 qB 数据。
- **处置**: 组内身份判据锚**内容根**维度 —— 候选内容根经 `content_root_of`(layout_of 三形态: 唯一顶层段 = save_path/<段>; 平铺/混合退化 = save_path 本身)现算, 与 `job.scope`(建账既有产物)比对; 组员恒共享同一内容根(组键 = 归一 save_path + 排序文件元组, group_key_of 单点, 比内容根更严); 退化形态(平铺/混合, scope=save_path)预筛恒过、交文件清单比对兜底(保守回落, 不引入新行为); 复用同一次文件表拉取(记录级惰性缓存)零附加 API。新判定面立项时先对齐删链门先例(ru.chain_gate_hits 的 scope 锚 + 仅等值并列面), 别再从 save_path 入门。
- **守阵**: 计划 26-11-21-1600 B1 批为 foreign 门落内容根预筛纯函数 + 全 layout 形态单测(平铺/混合/大小写折叠/空文件表); 既有删链门形态守阵(test_relocate_units chain_gate 系列)同面。
- **复发**: 0 (建档前已两踩: 链门 T1b/E7 与 foreign 门 issue 1500, 见触发条 —— 建档即为此; 后续复踩在此行追加「+N (日期): 为什么没命中」)
