# 副本收编只搬主语义漏搬防御容忍 —— 单点契约比副本窄, 退化形态当场抓红

> 摘要: 收编重复实现(删副本改 import 单点)时, 副本与调用链共演化出的防御性容忍(str(x or "") 折 None/空之类)不在单点契约里 —— 只搬主语义, 既有调用点的退化形态输入(save_path=None)当场打红。容忍补在**调用点边界**折假值后再进单点, 不放宽单点契约。
> 触发: 副本收编, 重复实现合并, 删副本改 import, 单点, 防御分支, 假值容忍, None, 退化形态, content_root_of, 契约变窄, 调用点边界, 收编清单

## 本篇只回答

把同一语义的重复实现(副本)收编进单点(删副本改 import)时, 为什么会漏掉防御性容忍分支、怎么在收编时发现与处置 —— 收编清单里必须有「输入契约差」一栏。

### 主语义对齐 ≠ 输入契约对齐: 副本与调用链共演化的容忍是单点没有的

- **触发**: 收编动作(删副本 + 换名 import + 调用点改名)落地, 而副本所在模块与调用链已共演化: 调用点把「可能为 None/空的输入」直接递进去, 副本内部折假值消化 —— 这类容忍写在副本或调用链上, 单点(为另一条主链路而生)从没见过 None。实证(2026-11-22, issue 26-11-22-0604, 计划 26-11-22-1714 批1/F7): grouping_mod._content_root_of 副本收编进 relocate_units.content_root_of, 3 个调用点当场暴露 save_path=None 打红(test_web_relocate 退化用例抓红), 3 调用点补 str(x or "") 折假值后收口。
- **判别**: 收编 diff 只有「删副本 + 换名 import + 调用点改名」而无输入整形, 即为疑点; 单点的形参契约按主链路假设(必为 str/非空)声明, 而收编调用点的实参来源是「可能缺省的记录字段」—— 收编前 grep 调用点实参来源逐个核对; 退化形态用例(None/空)跑一遍即红。
- **处置**: 容忍补在**调用点边界**(str(x or "") 之类折假值后再进单点), 不放宽单点契约 —— 单点契约服务全部主链路, 为一个收编调用点放宽 None 容忍会把「非法输入可表达」扩散给所有主链路; 退化形态用例随收编一并搬运/守阵。
- **守阵**: 既有退化形态用例(test_web_relocate 平铺/None 面)+ 单点自身 layout 形态单测; 收编批的收尾闸门含退化面用例回归。
