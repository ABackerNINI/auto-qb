# 改名 / 移动 / 生成链接

> 摘要: 改文件名或移动文档后必须全仓查引用(坏链不会让任何测试失败); 生成型脚本写路径有两个必踩的坑。
> 触发: 改名, 移动文档, 重命名, 生成索引, 写链接, relative_to, relpath

### 改文件名 / 移动文档后必须查全仓引用 (三步缺一不可)

- **触发**: 重命名 / 移动任何被文档引用的文件。
- **判别**: **坏链不会让任何测试失败** —— 只能靠人工扫。引用面可能很大(实测 `testing.md` 132 处 /
  `pitfalls.md` 113 处), 且含 `.html` / `.md` / `.py` / `.yml`, **HTML 的 `href=` 与正文里的裸路径也算**。
- **处置**: ①改之前全仓 grep 旧文件名统计引用数 ②用 **Python 显式 UTF-8** 批量替换
  ③替换后再 grep 确认为 0。
  ⚠ 已知守卫缺口(建议未做): 加一个**相对链接存在性扫描**测试 —— 这是本仓库反复吃亏的一类。

### 生成型脚本往 markdown / html 里写路径: `relative_to` 不会生成 `..` 回跳

- **触发**: 写索引 / 报告生成器, 需要从 A 目录链接到 B 目录。
- **判别**: `Path.relative_to()` 在目标**不是前缀**时直接抛 `ValueError`; 捕获后返回空串 ⇒ **链接静默消失**。
  另外 Windows 的 `str(Path)` 带 `\`, 进 markdown 链接就是错的。
- **处置**: 用 `os.path.relpath()` 生成回跳路径, 进链接前必须 `.as_posix()`;
  落盘后**在真仓库里 `head` 一眼**, 别只看退出码 0。
