# cap 债务制: 降级守卫时别把「哨兵自己坏了」也算成阻塞

> 摘要: 尺寸 cap 从「提交前置条件」降级为**债务**(2026-09-30) 时, 有三处会静默把债务重新变成阻塞 —— warns 里混入非债务提示、检查器不可用被判 STOP、以及删除尺寸断言后守卫退化成恒绿。
> 触发: cap 债务, doc.caps, --strict, warns 混装, DEBT_MARK, 检查器找不到, 降级守卫, 恒绿守卫, 可发现性断言, 债务清零, 清理会话

## 债务制改造里三处「降级不彻底」

### 债务清单必须**带标记**: `warns` 里混着非债务的提示

- **触发**: 把 `check_kb_structure.check_caps` 的尺寸超限从 `problems` 挪进 `warns` 之后, 让 `scripts/check_context_caps.py` 去消费这个 warns 当「cap 债务 N 项」。
- **判别**: `check_caps` 的 warns **本来就有别的成员** —— 下限 `CAP_MIN_WARN` 的「文件过小, 考虑并入邻文件」提示。那是**建议不是欠债**; 直接把 warns 当债务累计, 实测一次就报出 **26 项债务**(全是"过小"), 而真实超限是 **0** ⇒ `doc.caps -- --strict` 永远红、清理会话按它收口必然徒劳(把小文件往外迁是错的动作)。
- **处置**: 债务行加**前缀标记** `_common` 侧的 `check_kb_structure.DEBT_MARK = "cap 债务: "`, 消费者只挑带标记的行累计; 非债务提示照旧只在 `check_kb_structure` CLI 里打印, 不进债务数。
- **判据**: 债务数必须**能清零** —— 一件债务对应一个动作(外迁/精简), 而"文件过小"没有这样的动作; 发现债务数在某次提交后变成常数不再回零, 第一嫌疑就是混进了非债务行。

### 「检查器自己不可用」必须跟着降级, 不能判 STOP

- **触发**: 降级改造里给 `doc.caps` 加 KB 角色 cap 组时, 写 `_kb_checker()` 找不到 skill 就返回 `problems`(抬成 STOP)。
- **判别**: 这是**降级不彻底** —— 债务制要取消的正是「一个与本次改动无关的环境状况在最贵时刻(会话尾部)拦住提交」。实测: 把 `REPO_ROOT` 指向一个没有 `.agents/skills/` 的 tmp 目录, 默认模式直接 rc=1, 而那时**没有任何文件真的超限**。
- **处置**: 分成三档返回 —— ①真·超限(硬规定角色) → `STOP`; ②找不到 skill / `memory-bank/` 目录 → `WARN`(只报告); ③债务 → `[债务]` 行。判据: **只有"文件确实越过了那条线"才配拦提交**, "没检查到"不配。
- **复发**: 0

### 尺寸断言删除后, 守卫不能随之恒绿 —— 要换成「可发现性」断言

- **触发**: 按债务制删掉「断言现行文档都不超 cap」的用例(它们会拦住合法的提交), 却没补新断言。
- **判别**: 债务制下**允许**文件超限, 那时旧断言不响、`doc.caps` 也不响 ⇒ 债务制形同虚设, 而且**没有任何用例会红** —— 降级改错了也不会被发现。只删不补 = 把守卫整个撤掉。
- **处置**: 换成**造违例**的断言: `tmp_path` 里造一个超限文件 → 断言它**进了 warns 而不是 problems**; 再造一个超限的 `AGENTS.md` → 断言它**仍在 problems** 且不出现在债务清单里。守的是「严重度仍然正确」, 而不是「今天恰好不超」。
- **判据(一句话)**: 降级一条守卫时, 问自己「降级之后它靠什么变红」 —— 答不上来就是把它删了, 不是降级了。
- **配套**: 硬规定角色集 `HARD_CAP_ROLES` 也要钉住(否则有人把 `agents` 挪进债务组, 那条 problem 断言立刻恒绿 —— AGENTS.md 超限就只剩一行提示, 尾部截断重新变回"写了但没人看见")。
