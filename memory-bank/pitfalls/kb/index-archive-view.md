# 索引条目数撑爆 cap: 让老条目**出索引**, 不是搬文件

> 摘要: 生成式索引撞 `index-auto` cap 且「无摘要口径」本身已 > cap(即摘要砍到 0 也超)时, 后备出口不是「搬走老条目」而是**视图归档** —— 生成器只渲染已关闭状态最近 N 条, 文件原地不动, 全量清单另落 `attachments/`; 因为搬文件的前提是「被搬物零引用」, 而实测零引用条目远不够清偿, 且会牵动 md 链接与双向认领链。
> 触发: 索引条目数撑爆 cap, 无摘要口径超 cap, 后备出口, 搬文件 vs 视图归档, CLOSED_KEEP, 归档索引, attachments, 冻结件认领链, issues/_index 触顶, EXTRA_GENERATED

## 为什么不是「搬走老条目」

- **触发**: 生成式索引撞 cap, 按 [cap-counting.md](cap-counting.md) 的判据算出**无摘要口径就已 > cap**
  (2026-10-11 实测 `issues/_index.md`: 243 条 / 31,196 字符, 无摘要口径 27,336 = cap **108%**)。
- **判别**: 老口径的后备出口是「按状态归档**无外部引用**的老条目」(搬文件到 `attachments/`), 但两个前提
  常常**同时不成立**:
  - ①**零引用的不够清偿** —— 同日实测 243 条里只有 **28 条**零外部引用(其中 Done 24), 全搬掉
    指数仍 ~27,600 > 25,200;
  - ②**有引用的搬不动** —— 被搬件若被 27 个 md 的链接 + 21 个件的 `doc-refs` / `**Refs:**` 认领链
    指着(其中 18 个是 plans/reports **冻结件**), 而双向认领链要求「目标存在 **且** 反向声明」,
    漏改一处 `kb.check` 立刻红(该检查的口径见 cap-counting「删片三查」条)。
- **判据(一句话)**: 搬文件的前提是「被搬物零引用」; **引用面广时该动的是视图, 不是存储位置**。

## 处置: 视图归档三步

1. **生成器加保留数**: `gen_issues_index.CLOSED_KEEP = 60` —— 已关闭状态(Done/Dropped/Superseded)
   只渲染最近 60 条, 末尾留一行指针说明「更早的 N 条已出本索引, 报告仍在 `issues/` 目录」。
2. **全量清单另落附件**: 同批生成 `issues/attachments/_archive.md`(全量、摘要不截断)。
   ⚠ **名字别叫 `_index.md`** —— 那会被 `index-auto` 角色套上 25,200 的 cap, 全量清单必然超限;
   `attachments/` 在 `EXCLUDED_DIRS`, 不计 cap。
3. **文件一个都不搬** ⇒ 零坏链、零认领链改动; 索引大小自此由常量钉住, 不再随入池线性涨。
   实测 31,196 → 16,960(余量 8,484)。

## 两个配套坑

- **新增非 `_index.md` 的生成物会让守阵红**: `test_gen_all_declares_exactly_all_indexes` 按
  「产出 == 库内全部 `_index.md`」比对 ⇒ 归档索引一出现就红。正解是在 `tests/test_memory_bank.py`
  的 `EXTRA_GENERATED` 里**显式登记**, **别**把断言放宽成恒真(那样白名单多报手写件就没人拦了)。
- **生成器必须同批产出主索引与归档索引**: 主流程是 `gen_all.collect()`(它被 `kb.index` 与
  `gen_issues_index --check` 共用); 只加进 `gen_issues_index.main()` 会让它俩对不上 ⇒ `--check` 恒红。
- **回写件里指回坑档的新链接也会写错层级**: `activeContext/` 与 `tasks/` 到 `pitfalls/kb/` 都只需
  `../`(两者都在 `memory-bank/` 的一级子目录), 我却写成 `../../` —— **同一轮连错两次**(切片一次、
  档案一次, 后者还是从前者复制来的) ⇒ `doc.links` 每次都当场报坏链(与
  [cap-counting.md](cap-counting.md)「外迁正文链接上移」同族, 方向相反)。
  判据: ①新建链接后**立刻** `commands run doc.links`, 别靠眼估层级;
  ②**跨文件复制链接 = 复制了错误的前提** —— 源与目标的目录深度不同, 复用必须重算。

## 同源膨胀: 同质指针行重复 N 遍

- `progress/implemented-webui.md` 末尾 41 条逐条写「已外迁 → `[implemented-webui-history.md](implemented-webui-history.md)`」
  占 **5,642** 字符, 而**目标同为一份文件** ⇒ 压成一行, **零信息损失**(原文都在 history 里)。
- 判据: 一批指针行指向**同一个**目标时, 它提供的是导航而非信息 —— 留一条就够, 按目标聚合。
- 附带坑: **引述链接字面量时别用省略号占位** —— 曾把它略写成 `[history](...)`, 被 `doc.links` 当成目标 `...` 报坏链;
  照抄原字面量并裹行内代码即可(检查器只豁免反引号内的字面量)。
