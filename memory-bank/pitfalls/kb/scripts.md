# 脚本自身的坑 (改名漏改 / STOP 分级 / 列宽解析 / 输出预算)

> 摘要: 脚本类改动里最容易漏的五件事 —— 冷门分支上的未定义名、STOP 级别一刀切、对固定列宽输出整段 strip、给调用方的输出做过有损摘要(只取末 N 行 / 略过提示都错, 终点是全文透传 + 声明式静默)、**正则匹配 markdown 粗体时用 `[^*]*` 横跨相邻粗体段而误报**。
> 触发: 改脚本, 改检查脚本, 预检, 解析 git 输出, 解析命令输出, 改名, 输出摘要, 截断, 略过 N 行, 信息预算, 全文透传, silent_success, token 税, 挑行, 守卫脚本, 正则, 粗体, markdown 解析, 误报

### ❗脚本里"改名漏改"留下的未定义名, 只在冷门分支上炸

- **触发**: 重命名脚本里的变量 / 常量。
- **判别**: 那行只在**冷门分支**上走(如"没找到镜像远端"才走), 主线路径会先把流程带过去 ⇒
  `NameError` 一直潜伏到真机碰上那个分支才暴露。**跑一遍抓不到**(正常路径不经过)。
  实测案例: `push.py` 把 `MIRROR_URL_NOW` 写成从未定义的 `MIRROR_URL`。
- **处置**: 只能**静态查** —— `my-commit-flow` 的 `scripts/test_preflight.py` 有 `undefined_names()`
  (ast 扫 5 个脚本的 Load/Store 名, 闭包可见性也算对), 附带两个自证用例(能抓到 `MIRROR_URL`、不被闭包变量误报)。
  改 skill 脚本后跑一次 `python <skill-dir>/scripts/test_preflight.py`。
  ⚠ 该静态检查目前**只覆盖 `my-commit-flow` 自己的 5 个脚本**, memory-bank skill 的脚本尚未纳入 —— 记在 W8 候选。

### 预检 / 检查表型脚本的 STOP 级别要按阶段区分

- **触发**: 给检查脚本加一条新的 STOP 判据。
- **判别**: 一刀切 STOP 会挡住安全动作 —— 例如"落后主线"在 commit 阶段只该 WARN, 到 push 阶段才 STOP;
  判错了会逼执行者用 `--skip-preflight` 绕过 ⇒ **护栏形同虚设**。
- **处置**: 每条检查都问一句"这条在当前阶段真的一票否决吗"; 阶段相关项按阶段分流。

### 解析固定列宽输出时不要对整段 `strip()`

- **触发**: 解析 `git status --porcelain` 这类固定列宽输出。
- **判别**: 对整段 stdout 做 `.strip()` 会吃掉**首行**的行首空格(`' M x'` → `'M  x'`)⇒ 未暂存被判成已暂存,
  且 `line[3:]` 连带把路径首字符切掉 ⇒ **红线检查静默放行**。
- **处置**: 只用 `rstrip("\n")`; 解析处再兜底 `line[:2].ljust(2)`。

### ❗守卫脚本里"配对语法"必须按**配对段**取, 别用 `[^*]*` 横跨

- **触发**: 写/改基于 markdown 结构的守卫(粗体段、行内代码、括号段、引用块)。
- **判别**: 判「粗体段里含某词」写成 `\*\*[^*\n]*未\s*(?:提交|commit|入库)[^*\n]*\*\*` —— `[^*]` 会从
  **上一个粗体的收尾 `**`** 一路吃到**下一个粗体的开头 `**`**(中间恰好没有 `*`), 于是把普通行文里的
  词误判成"粗体段内容"。实测 2026-10-07: 新守卫 `check_wording.py` 对
  `tasks/26-09-21-webui-filter-data-and-color-flicker.md:19` 误报 —— 该行有 `**决策 1(…)**:` 与
  `**先加载过辅种页…**:` 两个粗体段, 中间的普通文字里有「未入库」, 被判成"粗体未提交标记"。
  这类误报**只在"同一行有两个以上粗体段"时出现**, 单段样本测不出来。
- **处置**: 先用 `\*\*([^*\n]+)\*\*` **取出配对好的粗体段**, 再对**段内容**跑判据(而不是对整行跑一个
  带 `\*\*` 边界的长正则)。同时: 一次性清洗脚本要 `import` 守卫的 `scan_text` 复用同一判据 ——
  实测首版两边各写一份, 命中数差 2 处(守卫多抓粗体形态), 清完仍留违规。**判据单点是"清的就是守的"的前提**。
- **守阵**: `tests/test_memory_bank.py::test_wording_guard_flags_status_but_exempts_dated_and_tree_state`
  的夹具里第 4/5 行故意各含一个粗体段, 钉住"不跨段误报"。

### ❗"回给调用方的摘要"不能只取末 N 行 —— 结论在最后, 异常行在中段; 但"摘要 + 略过提示"同样错, 终点是全文透传

- **触发**: 给"跑命令并回摘要"的包装器挑行(本项目 = `commands` 引擎的 `run`, 原实现 `_tail` 只回末 3 行)。
- **判别**: 检查表型输出的结构是「逐行结果 … 结论行(如"无 STOP；2 项 WARN 需人工确认")」⇒ 只取末 3 行
  拿到的是**结论**, 而 WARN 的**内容**全被截掉。看不到内容时**唯一**的出路是把整条命令重跑一遍 ——
  实测代价: 预检被跑了两遍(21s × 2), 而预检里还挂着全量测试闸门。省下 3 行换来一整次闸门, 省反了。
- **处置**(2026-09-30 第二次反转后的终态): **全文透传, 引擎不做有损摘要, 不打「略过 N 行」提示**。
  本条目曾经开出的"摘要 = 末几行结论 + 异常行 + 略过 N 行提示"配方于 2026-09-30 被用户定调推翻 ——
  那个提示会把 agent 调用方逼成 `show` → 裸跑两步返工, 会话后期每步都是带全量历史的整轮请求,
  省 3 行换两轮 token 永远亏。省 token 的正确姿势是**声明式静默**: 任务在包配置标
  `silent_success = true` → 成功只留结论行(`N passed`/`TOTAL`), 失败照旧全文; 内部命令"能静默尽量静默"
  靠这条旗标, 不靠引擎截断。核心判据一句话: **调用方看不到内容时的每条出路(重跑 / show→裸跑)都是整轮
  请求, 有损摘要在 agent 会话里永远是负收益**。
  ⚠ 判据别用 `re.I`: 小写 `warnings`/`error` 是正常输出的一部分(pytest 收尾行), 抽出来就是新噪音。
  守阵: `.agents/skills/commands/scripts/test_engine.py` 的 `test_run_success_passthrough_full` /
  `test_run_failure_passthrough_full`(全文透传, 无「略过」提示)+ `test_conclusions_*`(声明式静默)。
  (2026-09-30 复发 +1: 按本条目旧处置实现的 `_digest` 摘要被推翻重写 —— 旧配方只对了"别丢中段异常行",
  没料到"提示本身"在 agent 场景会变成两步返工。为什么没命中: 当时只有"省 token"目标没有"返工轮次"成本模型。)
