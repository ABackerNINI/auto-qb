# 知识库与协作纪律

> 摘要: 纪律为什么"反复强调却从不执行"、埋点与验收口径为什么必须有人消费、**闸门能判红却没有能修的命令**、测试写在没人跑的地方等于没写。
> 触发: 规则不执行, 立档, 收尾, 埋点, 验收标准, 口径, 测试没跑, testpaths, 生成物, 重建提示, 报错文案指错命令, 照做仍然红

### 纪律"反复强调但从不执行"时按顺序查四条 (缺任一都会衰减)

- **触发**: 某条规则写了很多遍, 但每轮还是不照做。
- **判别**: 逐条对下四项, 哪项不成立就是它:
  ①**载体** —— skill / instruction 文件真的在吗;
  ②**规则暴露点是否落在决策点** —— 写在只对 `memory-bank/**` 生效的 instruction 里, 而"该不该立档"的决策发生在
  编辑 `src/` 的时刻 ⇒ 规则不在上下文里;
  ③**阈值是否可判定** —— "大任务要立档"无阈值 ⇒ 默认不立档;
  ④**有没有机械后果** —— 现由 `tests/test_memory_bank.py` 双向校验索引 ↔ 文件 / 命名 / 状态分区 / 必备章节。
- **处置**: 按查出的那一项补 —— 补载体 / 把规则挪到决策点 / 写死阈值 / 加守卫。**"再强调一遍"是最没用的处置。**

### 埋点 / 验收口径必须有人消费

- **触发**: 立计划 / 加埋点 / 写验收标准时。
- **判别**: 这条口径**没有承接方**(断言 / 报表字段 / 走查表) ⇒ 等于没写。
- **处置**: 每条验收口径**指派交付物**; 前端埋点要覆盖**整条链路**(补丁 / POST / 排队 / 执行 / 端到端),
  只量一段会在真机慢时无从下手。
- **实例(2026-09-24)**: `.commands/my-commit-flow/scripts/test_preflight.py`(47 条)一直**没有任何闸门在跑**
  —— `pytest.ini` 的 `testpaths = tests` 只收 `tests/`, 而提交闸门里也只有 `--help` 冒烟。
  后果不是"测试白写"这么轻: 包脚本里一条与 rebase 禁令相撞的旧文案("让工作区变干净再 rebase")就这样
  **躺到有人走查**才被发现。**判据**: 新写的守卫要能回答"哪条闸门 / 哪个 testpaths 会跑它";
  答不上来就是埋点没人消费 —— 已补 task `test.pkg` + 闸门 `match = [".commands/", ".agents/skills/commands/"]`。

### 闸门能判红, 却**没有一条能修的命令** —— 生成物的"重建提示"必须与闸门覆盖面同集

- **触发**: 写生成器 / 改 `commands` 包的任务定义 / 往提交闸门加 `--check`。
- **判别**: 两类动作各做一半就是本条形态 ——
  ①**闸门**判红某生成物(`my-commit-flow` 的 `memory-bank/` 闸门挂了 4 条 `--check`),
  ②生成物自己的报错文案(`_common.gen_cmd()`)给出"怎么重建";
  如果 ② 指向的任务**覆盖不到这个生成物**, 用户照文案跑一遍**仍然是红的**。
  2026-09-24 实测: `gen_cmd()` 忽略传入的脚本名、一律返回 `commands run kb.index`, 而 `kb.index`
  当时只跑 `gen_tasks_index` + `gen_kb_index` ⇒ `_doc-map.md` / `plans|reports/_index.md`
  的报错文案指过去**跑完照红**(闸门能红、修法不存在)。
  ⚠ 判据不是"提示里写了命令"(那种错最容易骗过走查), 而是**"照它做一遍, 红会不会消失"**。
- **处置**: 两条一起做, 缺一条都会复发 ——
  ①**让总入口的覆盖面 ⊇ 闸门判红的生成物集合**: `kb.index` / `kb.check` 必须与
  `my-commit-flow` 的 `memory-bank/` 闸门**同集**(改了闸门就要同步这两个任务的 `run`);
  ②**提示按脚本查表**(`_common.GEN_CMD_BY_SCRIPT`), 别退化成"所有脚本同一句" ——
  只校验不写文件的脚本(`gen_active_recent.py`)的"重跑"是 `kb.active --check`, 不是重建命令。
  守阵 `tests/test_memory_bank.py::test_gen_cmd_hints_name_real_tasks`: 调用点全覆盖 +
  task id 真实存在 + **提示说跑 `kb.index` 的脚本必须真的在它的 run 列表里**(两处红验过:
  退回旧的两条 `kb.index` ⇒ 红; 删掉一条 `GEN_CMD_BY_SCRIPT` 登记 ⇒ 红)。
