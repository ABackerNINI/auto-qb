# 知识库与协作纪律

> 摘要: 纪律为什么"反复强调却从不执行"、埋点与验收口径为什么必须有人消费、测试写在没人跑的地方等于没写。
> 触发: 规则不执行, 立档, 收尾, 埋点, 验收标准, 口径, 测试没跑, testpaths

### 纪律"反复强调但从不执行"时按顺序查四条 (缺任一都会衰减)

- **触发**: 某条规则写了很多遍, 但每轮还是不照做。
- **判别**: 逐条对下四项, 哪项不成立就是它:
  ①**载体** —— skill / instruction 文件真的在吗;
  ②**规则暴露点是否落在决策点** —— 写在只对 `memory-bank/**` 生效的 instruction 里, 而"该不该立档"的决策发生在
  编辑 `src/` 的时刻 ⇒ 规则不在上下文里;
  ③**阈值是否可判定** —— "大任务要立档"无阈值 ⇒ 默认不立档;
  ④**有没有机械后果** —— 现由 `tests/test_memory_bank.py` 双向校验索引 ↔ 文件 / 命名 / 状态分区 / 必备章节。
- **处置**: 按查出的那一项补 —— 补载体 / 把规则挪到决策点 / 写死阈值 / 加守卫。**"再强调一遍"是最没用的处置。**

### 埋点 / 验收口径必须有人消费

- **触发**: 立计划 / 加埋点 / 写验收标准时。
- **判别**: 这条口径**没有承接方**(断言 / 报表字段 / 走查表) ⇒ 等于没写。
- **处置**: 每条验收口径**指派交付物**; 前端埋点要覆盖**整条链路**(补丁 / POST / 排队 / 执行 / 端到端),
  只量一段会在真机慢时无从下手。
- **实例(2026-09-24)**: `.commands/my-commit-flow/scripts/test_preflight.py`(47 条)一直**没有任何闸门在跑**
  —— `pytest.ini` 的 `testpaths = tests` 只收 `tests/`, 而提交闸门里也只有 `--help` 冒烟。
  后果不是"测试白写"这么轻: 包脚本里一条与 rebase 禁令相撞的旧文案("让工作区变干净再 rebase")就这样
  **躺到有人走查**才被发现。**判据**: 新写的守卫要能回答"哪条闸门 / 哪个 testpaths 会跑它";
  答不上来就是埋点没人消费 —— 已补 task `test.pkg` + 闸门 `match = [".commands/", ".agents/skills/commands/"]`。
