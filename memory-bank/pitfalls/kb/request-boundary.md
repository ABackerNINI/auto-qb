# 请求边界 (问答 vs 执行任务)

> 摘要: 开工先判这一轮是"问答 / 只读"还是"执行任务" —— 把问答当执行任务去做, 是本仓库的**红线**。
> 触发: 用户提问, 想延伸排查, 想顺手入池 issue, 想顺手立档, 想 commit

### 把「问答」当「执行任务」是红线 (用户指定)

- **触发**: 用户说"能不能 X / 是什么 / 怎么看 / 有没有"这类**提问**; 或说完"继续 / continue / 接着做 / 你看着办"。
- **判别**: 这一轮**只是问** ⇒ 只在回复里作答; 想延伸排查(跑测试 / 冒烟 / 探针 / 实验)**先问**。
  ❗**"继续 / 接着做 / 你看着办"不构成授权** —— 只表示"把你手上这一步做完"。
- **处置**: 四类动作必须**逐项**显式确认, 少一项都不做: ①新建文件(计划文档 / 任务档案 / 报告)
  ②入池 issue ③认领 issue ④commit / push。反面案例见 [tasks-archive.md](tasks-archive.md) 与任务档案里的"把『问答』当『执行任务』"。
