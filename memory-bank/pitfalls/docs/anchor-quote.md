# 指针里的「引文」被顺手压了空格, 锚点就失效

> 摘要: 文档指针写成 `memory-bank/conventions/webui.md`「HTML 文档一律 dark 主题」时, 引号里的串是**目标小节标题的原文**(锚点), 靠 `grep` 字面匹配一步跳到那一节; 做空格精简 / 措辞润色时把它一起压掉, 检索立刻 0 命中, 指针退化成"指向整个文件", 逼人整读 —— 与顶部「禁止整读」纪律正面冲突。
> 触发: 精简文档, 压空格, 改指针措辞, 引号里的内容, 小节标题, grep 不到, 锚点, 引文, verbatim

## 判据: 引号里是「引文」还是「说法」

- **引文**(照抄, 一字不改, 含空格与 emoji): 指向别处小节标题的锚点 —— `见`memory-bank/conventions/webui.md`「HTML 文档一律 dark 主题」`、
  `见`memory-bank/conventions/collaboration.md`「🔴 跨仓库操作」节`。
- **说法**(可自由润色): 输出串 / 口令 / 状态位 —— 「已同步 <hash>」、「授权」、「提交」、「无法核实」。
- 判法: 能拿它 `grep -rn "<串>" memory-bank/` 命中某个 `## ` 标题的, 就是引文; 命中不了任何标题的, 是说法。

## 事故实证 (2026-10-06, AGENTS.md 空格精简)

- 那一轮把 AGENTS.md 的空格从 950 压到 163, 连引号里的引文一起压了 ⇒ 两处锚点当场断掉:
  ①`AGENTS.md:26`「HTML文档一律dark主题」 vs `webui.md:61 ## HTML 文档一律 dark 主题` → **0 命中**;
  ②`AGENTS.md:76`「🔴跨仓库操作」 vs `collaboration.md:38 ## 🔴 跨仓库操作: 绝对禁止` → **0 命中**。
  同批的「协作约定」因为目标标题本来就没有空格, 侥幸活下来 —— **这类 bug 不报错、不看不出, 只在真的去检索时才暴露**。
- 反例(写对的): `memory-bank/plans/26-10-01-1728-plan-doc-drift-repair.html:392` 引的是带空格的原文。

## 处置

- 精简脚本 / 手工润色都要把「」里的内容列为**例外**(与 `-` `<>` `.` `"` 并列): 引文照抄原文。
- 改完**必须回验**: `grep -rn "<引文>" <目标文件>` 至少 1 命中; 反向指针(别的文件引本文件的小节)同样要验 ——
  `collaboration.md:40` 引的是 `AGENTS.md`「🔴 跨仓库操作」节, 所以 AGENTS.md 自己的标题也必须带空格, 两边才对得上。
- 顺带一条: **emoji 串在 MSYS grep 里可能匹配失败**(本轮 `grep "🔴 跨仓库操作"` 返回 0 但串确实存在) ——
  验证带 emoji 的锚点改用 ripgrep / IDE 检索, 别拿 bash grep 的空结果当"不存在"。
