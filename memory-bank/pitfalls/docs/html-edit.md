# 改单文件 HTML 文档时吞掉闭合标签

> 摘要: 用字符串替换改计划 / 报告 HTML 时容易吃掉 `</p>` 之类闭合标签, 浏览器与 IDE 预览都**静默容错**, 肉眼看不出。
> 触发: 改计划 HTML, 改 issue 报告, 编辑 HTML, 闭合标签, 标签不平衡, 渲染不对但没报错

## 标签平衡只能机检, 不能靠看

### 字符串替换跨越段落边界时会吞掉尾部闭合标签

- **触发**: 用「替换片段」而不是「整文件重写」的方式编辑 `docs/plans/*.html` / `memory-bank/issues/*.html`。
- **判别**: 被替换片段首尾各带一半标签时最危险(如 `old` 以 `</p>` 结尾、`new` 忘了写)——
  新片段少一个闭合标签, 而 HTML 解析器**容错**: 它会自动补齐并继续渲染, 浏览器与 IDE 预览**都不报错**,
  于是"看起来正常"一直带到提交。注意**只检查未闭合列表还不够**: 更常见的表现是
  `section` 在 `p` 还开着的时候被关闭 —— 报错信息形如「乱序闭合: section 栈顶=p」。
- **处置**: 改完这类文档后跑一次标签平衡机检再交付, 用 `HTMLParser` 压栈 / 弹栈, 同时打印
  **未闭合栈**与**乱序闭合**两类错误(空栈报"多余闭合"也一并打)。实战里这条一跑就定位到行,
  比人工回看几十处替换快一个量级。
