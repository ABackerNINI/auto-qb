# 改单文件 HTML 文档时吞掉闭合标签

> 摘要: 用字符串替换改计划 / 报告 HTML 时容易吃掉 `</p>` 之类闭合标签, 也容易**残留整块旧内容** —— 浏览器与 IDE 预览都**静默容错**, 肉眼看不出。
> 触发: 改计划 HTML, 改 issue 报告, 编辑 HTML, 闭合标签, 标签不平衡, 旧块残留, 渲染不对但没报错

## 标签平衡只能机检, 不能靠看

### 字符串替换跨越段落边界时会吞掉尾部闭合标签

- **触发**: 用「替换片段」而不是「整文件重写」的方式编辑 `memory-bank/plans/*.html` / `memory-bank/issues/*.html`。
- **判别**: 被替换片段首尾各带一半标签时最危险(如 `old` 以 `</p>` 结尾、`new` 忘了写)——
  新片段少一个闭合标签, 而 HTML 解析器**容错**: 它会自动补齐并继续渲染, 浏览器与 IDE 预览**都不报错**,
  于是"看起来正常"一直带到提交。注意**只检查未闭合列表还不够**: 更常见的表现是
  `section` 在 `p` 还开着的时候被关闭 —— 报错信息形如「乱序闭合: section 栈顶=p」。
- **处置**: 改完这类文档后跑一次标签平衡机检再交付, 用 `HTMLParser` 压栈 / 弹栈, 同时打印
  **未闭合栈**与**乱序闭合**两类错误(空栈报"多余闭合"也一并打)。实战里这条一跑就定位到行,
  比人工回看几十处替换快一个量级。

> **复发: 1** — 2026-09-24(计划 v1.9 标记 M1 落地)又踩一次, 方向反过来: `old` **带了**收尾的
> `</tbody></table><p …>`, `new` 却只写到 `</tbody>` ⇒ `</table>` 与尾注 `<p>` 被吞。
> **为什么没命中**: 读过这条坑, 但只记成"别少写闭标签" —— 真正要记的是
> **「`old` 末尾带了几个收尾标签, `new` 就得原样补回几个」**;
> 而且当时是靠改完**回读那一段**发现的, 不是机检(机检是修完才跑) —— 正确姿势是**改完立刻先跑计数机检**再继续。

### 替换片段只盖到起始标记时, 旧块会整块残留(2026-09-24 实踩)

- **触发**: 想把一整块换掉(`<figure>…</figure>` / `<table>…</table>` / `<ul>…</ul>`),
  但 `old` 片段只写到**起始标记**(如以 `      <figure>` 结尾), 新内容里却又自带一个完整的同种块。
- **判别**: 新块 + **旧块尾部整块残留**(本例: 旧 `<svg>` + `<figcaption>` + 又一段 `<p class="muted">`),
  页面上同一张图渲染两遍、同一段结论说两遍。只查"配对性"看不出问题 —— 每块自身是平衡的,
  错的是**数量**: 正则统计成对标记出现次数, `<svg>` = 2 而非 1 就是它。
  判据(改完立刻跑, 几秒): ① `section`/`svg`/`figure`/`table`/`pre`/`ol` 各自开闭数量必须相等,
  且等于你心里数的那份(本库计划文档现阶段为 section 14 / svg 1 / figure 1 / table 11 / pre 4);
  ② 浏览器实渲染被改的那一节并截图, 重复块一眼可见。
- **处置**: 替换整块时 `old` 必须从该块**开标签一直盖到闭标签**(宁可长), 不要拿"下一节的起始标记"当尾巴;
  改完立刻跑上面的计数机检 + 截图一次再交付。
