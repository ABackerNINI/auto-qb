§02改了什么

分层(自下而上，每层单一职责)

层落点职责
配置契约models.py / loaders.py / validation/sections.py / schema/groups.pyweb.ctx_menu 键进契约：宽松校验(只验形状，未知 id 交给前端)，schema 打 hidden(结构是数据不是 UI 元数据)
注册表 + 合并语义shared/ctx_menu.jsCTX_ITEM_DEFS/CTX_SUB_ITEM_DEFS 定义序 = 默认布局；ctxMergeLayout 补尾/隐藏槽位/跨层认领/分隔线一等公民
渲染tpl/ctx-menus.html四支 v-for 消费 ctxItems('<支>')/ctxSubItems('<支>')，点击走 ctxRun(it)；判据链与子面板交互零改动
定制面板shared/ctx_menu_custom.js + tpl/settings-detail.html + console_hub.css四支 tab、两级固定区、显隐/↑↓/拖拽/跨层/分隔线/恢复默认；编辑直接写配置树
下发routes/config.py + state.js + lifecycle.js/api/webui/flags 带 ctx_menu；保存后 loadWebFlags 双拉热应用

三个关键决定(实施期定，计划里没写死)

  1. 面板不另存草稿：每次编辑整对象替换写回 cfg.tree.config.web.ctx_menu，脏标记/保存/放弃全走全局 actbar。代价是面板里改一笔就算「有改动还没保存」(与改其它配置项一致)，换来的是没有「面板草稿 vs 配置树」两份真值，也就没有"放弃改动到底放弃了什么"这类歧义。
  2. 面板读的合并布局 = 运行时用的那个函数(REG.ctxMergeLayout)：面板显示的顺序就是菜单将渲染的顺序。两套合并逻辑必然漂移，所以只留一套。
  3. 分隔线分两类：默认线(sep:dN/sep:sN)只能隐藏不能删(它是模板结构锚点，删了「恢复默认」对不上)；用户线(sep:uN)可删。隐藏的线仍在 order 里占位，勾回来即归位。

§03兼容与零漂移

  • 存量配置零动作：没有 web.ctx_menu 键 = 默认布局，四支逐位等于改版前(守阵硬编码钉住)。升级不需要迁移脚本，也不需要抬 schema_version。
  • 换版本不丢布局：用户布局里的未知 id 被忽略(不报错、不删配置)；注册表新增项会被补尾追加 —— 升级后新项自动出现，用户排好的顺序保持。
  • 跨层移动不会"回拽"：补尾时跳过「对层用户序已认领」的 id。否则把某项移进「更多操作」后，原层补尾会把它又 append 回来(实施期实测到的第一个语义坑)。
  • 次级菜单为空则不渲染入口(D7)：只剩分隔线也算空 —— 空面板带两条线比单选项更残。隐藏的项在面板里照样可见可恢复。
  • 跳检开关：键仍是 web.skip_check_menu，fail-closed 语义与端点 403 兜底一字不变；只是渲染位置从「常规」分区搬到新卡。schema 用 hidden 保留键(摘掉会被键面守卫判成"删键")。

§05已知边界

  • 不纳入(D3)：表头右键菜单 4 项、文件优先级(互斥单选)、底部抽屉菜单 —— 它们是不同语义的入口，不是"同一批动作的第四条路径"，混进同一张布局表只会让定制面板更难解释。
  • 布局是全局的，不区分浏览器/用户：配置在服务端 config.yml，与跳检开关同通道。多浏览器共享一份，符合"这是这台机器上 auto-qb 的界面偏好"的定位。
  • e2e 只跑 prism / atlas(SKINS)：console 皮肤共用同一份 shared 模板与 console_hub.css，静态守阵覆盖三套清单，真浏览器断言按既有约定只跑两套。
  • 不做导入/导出：布局是十来行 JSON，写进 config.yml 可手改可备份；再加一层导入导出只是给"配置搬家"提供第二条路径。

§06排查：用户说「菜单里没有某项」

  1. 先看 config.yml 的 web.ctx_menu：该项是不是在 hidden 里，或在 sub.order 里(被移进「更多操作」)。默认布局 ≠ 用户看到的布局。
  2. 再看开关：web.skip_check_menu 关 = 跳检项按设计不出现；qb_traffic_enabled 关 = 流量图入口不出现。
  3. 再看支判据：用户说的是哪一支(多选批量 / 单组 / 单种子 / 整集整剧)，对照 trigger-scope.spec.mjs 的 T-1~T-5 矩阵。
  4. 以上都不是，才是注册表真的少项 —— 加一行即可，模板不用动。
一句话口径：菜单项是数据(ctx_menu.js 注册表)，顺序与显隐是用户数据(config.web.ctx_menu)，模板只负责把两者按同一份合并语义渲染出来 —— 想改菜单，先问改的是"有哪些项"还是"怎么排"。
