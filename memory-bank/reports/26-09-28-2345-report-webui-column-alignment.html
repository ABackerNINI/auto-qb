WEBUI 表格列对齐审计

逐表逐字段盘点 WEBUI 全部 7 张表格列的左右对齐现状, 给出推荐口径与原因。结论先说: 主视图 4 张表的对齐机制健康(单点在列模型、表头与值同源注入), 真实混乱只有两处 —— 时间/时长族 4 个字段口径分裂、详情抽屉 3 张表数值列全部左对齐未跟主表口径; 另有 1 处(分享率)是已拍板的文档化例外, 不该动。

§1对齐机制现状

先讲机制, 因为"哪里能改、改一处够不够"取决于它。

主视图 4 张表(分组/明细/种子/追剧): 对齐是单点驱动 —— 每列的 align 值只定义在 app.js 的四份列模型数组里(GROUP_COLUMNS / DETAIL_COLUMNS / TORRENT_COLUMNS / SHOW_COLUMNS), 由 columns.js:650 colAlignCss 按可见列序生成 :where([data-table=…]) > :nth-child(n) 规则同时注入表头与值单元格(text-align + justify-content, left 也显式生成以免被 .g-stat/.m-stat 的 right 盖掉)。三套主题(atlas/console/prism)共用同一份模型, 不会出现"表头左、值右"的错位。0 值居中(.g-stat.zero)是有意保留的既有口径。

详情抽屉 3 张表(Tracker / 用户 / 内容): 没有列模型, 对齐散落在 CSS 与模板 —— .drawer-table th 一律左、td 无对齐规则(即默认左)、只有操作列 td.cell-act 显式右。这正是数值列全部左对齐的机制性来源。

§3混乱点定性

P1 · 主表真混乱 · 改 4 处 align 值

时间/时长族口径分裂

同为时间点, 完成于 右而 添加于 / 最近活动 / 见到完整副本 全左; 同为时长, 活跃时间 右而 做种时长 三表全左。合计 4 个字段 × 明细/种子 2 张表(均默认隐藏, 改动低风险)。用户翻列时"同一族一会儿左一会儿右"正是本次体感混乱的主源。

P2 · 抽屉表系统性缺口 · 9 个字段

抽屉 3 张表数值列全左

Tracker 的做种/用户、用户的进度/下行/上行/已下载/已上传/关联度、内容的大小 —— 全部落到 CSS 默认左。机制原因: 抽屉表没有列模型, CSS 只给 th 定了左。改法是在模板 th 上挂对齐类 + 每主题一条 CSS 规则(或 th/td 成对类), 三主题各改一份。

P3 · 已拍板例外 · 不动

分享率列左对齐

纯数值视角它与"可用性=右"同族不同口径, 但 2026-09-26 用户已拍板(明细表值含"实际 / HR 要求"双段, 左对齐起读更稳), 且分组/明细/种子三表已一致。保留并在列模型注释里继续挂着, 不建议翻案。

机制健康 · 无需动作

主表单点 + 居中口径

4 张主表表头/值同源注入, 历史上的"表头左、值右"错位已被 colAlignCss 治理; 0 值居中(.g-stat.zero)是有意保留。H&R / 站数 / 版本居中、进度条左、状态徽标左均为既定口径, 保持。

§4推荐口径规则(5 条)

判对齐先判字段性质, 不判"它现在长什么样" —— 以后加列照这 5 条走。

R1文本(名称/路径/标签/URL/Hash/状态徽标) → 左。从行首起读; Hash 虽是等宽串但不比较量级, 左比右好。
R2数值(字节量/速率/计数/比率/纯 % 文本) → 右。右对齐让小数点与单位纵向成线, 才能扫量级; 计数同理。
R3短徽标计数(H&R/站数/版本) → 居中。既有口径(2026-09-17), 窄列徽标居中视觉均衡; 状态徽标含文字走 R1 不居中。
R4时间点 → 左; 时长(做种时长/活跃时间)随时间族 → 左。项目拍板(2026-09-17)时间列=左, 时长带文字后缀文本性质强, 跟族不跟数值; 现有的 FX-28 相对/绝对开关按此基线工作。
R5进度条部件 → 左; 纯 % 文本 → 右。条形是从左往右填充的部件, 左对齐阅读自然; 无部件的百分比是纯数值走 R2。

§5建议改动清单(最小 diff)

  1. P1 · app.js 两处列模型: DETAIL_COLUMNS 与 TORRENT_COLUMNS 里 completion_on(完成于)、time_active(活跃时间)的 align: "right" → "left", 共 4 处单值修改; 表头/值经 colAlignCss 自动同源生效, 三主题无需另改。两列均默认隐藏, 不影响默认视图。
  2. P2 · 抽屉表数值列右对齐: tpl/drawer.html 三张表的数值列 th/td 挂对齐类(建议 .num), 三主题 CSS(atlas/console/prism 的 dialogs.css / views.css)各补一条 .drawer-table .num { text-align: right } 级规则; 涉及 Tracker 的做种/用户、用户的进度/下行/上行/已下载/已上传/关联度、内容的大小/进度。
  3. 明确不动: 分享率(P3 例外)、4 主表进度列、H&R/站数/版本居中、0 值居中、操作列右。
