2.3 引擎断点链(argv[0] 污染, 已立坑档)

# 实锤(2026-11-12): ZCode Linux 宿主把进程 argv[0] 设为相对 AppImage 路径
$ python3 -c "import sys; print(sys.executable)"
/home/nini/Desktop/MyProjects/ZCode/auto-qb-zcode-clone1/ZCode-3.17.2-linux-x64.AppImage   # 不存在
$ python3 -S -c "import os; print(os.readlink('/proc/self/exe'))"
/usr/bin/python3.12            # 内核真相没坏 —— 只是被污染的 argv[0] 骗了 CPython getpath
$ cat /proc/self/cmdline | tr '\0' ' '
./ZCode-3.17.2-linux-x64.AppImage /proc/self/cmdline   # 每条命令的噪声行同源

后果链: 引擎 _config.py:406 argv=[sys.executable, script] → script 形任务全炸 AppImage not found; 无 uv 时 wrapper 落 exec python → py2 读 UTF-8 源码炸 Non-ASCII character SyntaxError。装 uv 后 wrapper 走 uv run -q python 分支, argv[0] 正确, 整链自愈(实测 kb.active 等字面 python 任务一并恢复)。判别与应急配方见坑档。

§03方法与局限

3.1 方法

  • 探测面: 直跑事实命令(os-release/timedatectl/docker info/df/free/id/curl 八源带计时), 不依赖文档口径。
  • 断点面: 失败现场 → 逐层下钻(wrapper 脚本 → 引擎 _config.py:406 → sys.executable 实测 → /proc/self/exe 对照 → argv[0] 机制定性), 每层留原文。
  • 测试面: master 与 develop 分开实测; develop 用一次性 detached worktree(不动本 clone 分支, 测完即删); 每个「红→绿」结论都做单变量对照(装 node / 换 TZ)。
  • 建件面: 本报告 / issue / 坑档全部 kb.new 命令化创建, --refs 双向补链, 索引由命令重建。

3.2 局限(未覆盖面)

  • e2e 未跑: node 已就位, 但 playwright 需要 npm ci(node_modules)+ 浏览器二进制下载(PLAYWRIGHT_DOWNLOAD_HOST 指 npmmirror)—— 该面属计划 26-11-12-0152 S3 的验证范围, 本轮不抢。
  • 变异测试未跑: mutmut 原生 Linux 能力未验证; 计划 S4 迁移容器, 本机原生面留待需要时另行验证。
  • TZ 未改系统(拍板): 本机裸跑全量仍有 1 条红(test_hr_ratelimit), 修复前要么 TZ=Asia/Shanghai 前缀, 要么等 issue 26-11-12-2347 清偿。
  • docker 容器路线未实测: Docker Hub 直连断, 若启用计划 testbed 需先配 registry mirror(计划 D8 候选清单适用)。
  • 数字均为单次采样: 本报告是快照(develop@5dfb3662, 2026-11-12), 不进基线口径; 后续数字以 kb.baseline 切片为准。
