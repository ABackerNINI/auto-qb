HR 稳态期跳过 B/C 档取数可行性分析

动议: 「稳态时 B/C 页是否不用访问, 只访问 A 页」。取证结论: 技术上可做, 但收益极小 (每站每天省 2 个请求) 却换来一处真实的判定回归 + 两处结构性副作用, 且与 v3「每波自证覆盖」前提冲突 —— 不建议按「稳态 ⇒ 只看 A」直接实施。取证报告 26-10-03-1505 §13.2 其实已预先裁定过该方向:「若要再省页数需改覆盖语义, 不建议捆绑」。

02背景: 「稳态」在代码里是什么

先消除一处口径歧义 —— 「稳态」不蕴含「本地没有 HR 义务对象」, 它只蕴含「对账对象集为空」。两者在多数时候重合, 但差额正是本报告的关键 (§05)。

# hr/service.py:503-504 (波前现算, 每次 poll 一次)
steady   = anchors_known and not objects        # anchors_known: 锚点采集成功(失败不算稳态)
interval = site_conf.idle_refresh_interval if steady else site_conf.refresh_interval

三个必须记住的既有事实:

  • 稳态只改间隔, 不改行为: 默认 idle_refresh_interval = 24H, 常态 refresh_interval (生产 5H)。波照开、页照翻 —— 取证报告 26-10-03-1505 §13.2 原文:「降频省的是波次, 不是单波页数」。不跳波是本报告动议要动的那条口径。
  • 档位集合是单点常量: model.py:35 FETCH_LANES = (A, B, C); D 已免罪不翻 (TERMINAL_LANES = (B, C, D), model.py:37)。A=考察中 / B=已达标 / C=未达标 / D=已免罪。
  • 「空对象集 → 每档 1 页」的轻量波已被否决 (v3 审计 26-09-29-0404 §13.1, 用户定稿): 现行 accepted behavior 是空对象集仍按三停翻条件 / 末页 / 单波页数上限扫。生产日志里「一簇 3 请求」只是停翻条件② (连续 5 行 remain==0) 恰好命中 (报告 26-10-08-1235 §05), 不是设计上的「每档必 1 页」。
动议的隐含前提不成立: 「稳态 ⇒ 本地没有义务 ⇒ 只有新增考察中需要看 ⇒ 只看 A」。第 1 步就漏了 —— 对象集为空 ≠ 本地无种子在 A (见 §05)。所以「只看 A」不是「保守的省页」, 而是在一个不成立的稳态语义上加了一个盲区。

04稳态下逐项推演

稳态的定义 objects = 未对账 ∪ 考察中 = ∅ 直接给出两个空集: unmatched = ∅ ∧ observing = ∅。据此逐条推演「跳过 B/C」的后果:

消费点稳态下跳过 B/C 的后果定性
批量「未列出」签发 unmatched 为空 ⇒ _sign_releases 本来就没目标可签。跳过 B/C 使其闸门 releases_enabled 恒 False, 但稳态下无实际工作量损失。 无害 (但见 §06)
A 档观察期出口 / 终态退役 不会产生误判 (方向保守), 但条目永不退役: _freeze_terminal 拿不到该档 st.ok; _position_covered 恒 False。后果 = data.index 与判定视图 lane_terminal 持续膨胀 (活跃条目不受 _prune_index 30 天淘汰), 且终态放行记录不再落盘。 慢性副作用
流转守恒 0.7 刚进稳态那一波, prev_a_tids 里迁到 B/C 的行在本波 wave.seen 中看不到 ⇒ 留存率假跌 ⇒ 误报「流转守恒不达标」。 误报 (只冻签发闸门)
命中 B/C → 终态放行 多数场景无影响 (见下 §05 的论证: 非超额种子的 A→B/C 迁移发生在「非稳态期」, 那时本就会全档抓)。唯一例外是超额种子。 见 §05

为什么「多数场景无影响」是成立的

若一颗本地种子没有放行记录、也不在超额线上, 而它的索引条目还停在 A 档 —— 它就在对象集里 ⇒ 不可能是稳态 ⇒ 那一波会全档抓, B/C 的转档被捕获。所以「跳过 B/C」只在对象集为空时才生效, 而此时普通种子要么已终态、要么已放行, 不存在待发现的转档。

这条论证把问题收敛到一个精确的例外类 —— 对象集为空、但本地仍有种子在站点 A 档。下一节证明这个类非空且真实。

05判定回归: 超额种子 A→B/C 迁移失明

对象集的排除链里有一档是超额线:

# hr/service.py:1428-1429 (_build_objects)
if required_seeding_time > 0 and anchor.seeding_time >= SEED_EXEMPT_RATIO * required_seeding_time:
    continue   # 超额线(3×): 免除在线对账义务; 被动命中考察中仍转管束(网站绝对权威)
# SEED_EXEMPT_RATIO = 3.0 (service.py:108); CarPT 实测 3 × 36H = 108H ≈ 4.5 天

超额种子的语义是「本地做种已远超要求, 不必再为它翻页对账」。但它没有被判定侧放弃 —— 注释写明「被动命中考察中仍转管束 (网站绝对权威)」。于是出现这样的状态:

  1. 一颗本地种子做种 ≥3× 要求, 被排除出对象集; 它在站点上仍在 A 档 (考察中)。
  2. ⇒ 对象集可以为空 ⇒ steady = True ⇒ 间隔降到 24H。此时本地明明有一颗种子在 A, 但系统判稳态。
  3. 该种子转档 (A→B 已达标 / A→C 未达标) 后, 只能靠抓 B/C 页看到 —— 它在 A 页消失了。
  4. 若只看 A: 它在 A 页消失, 于是不在 wave.seen; 观察期出口又因 _position_covered 恒 False 被冻住 ⇒ 索引条目永远停在旧 A 档。
  5. 判定侧 build_site_view (resolve.py:413-423) 把「活跃 A 档条目」放进 lane_a; resolve_identity 行 1 (216-219) 优先命中 lane_a ⇒ 该种子被恒判「受管束」, 而站点其实早已给出终态结论。
性质: 这是结论错, 不是方向错 —— 它不会漏 HR (方向保守, 偏向多管), 但会让一颗早已达标/未达标的种子在界面与规则里长期显示「考察中·受管束」。而且不能自愈: 稳态下对象集恒空 ⇒ 永远不抓 B/C ⇒ 永远看不到转档。唯一出路是等下一次「对象集非空」的波 (新下载 / 新义务) 顺带全档抓一次 —— 对一个长期稳态的账号, 这可能是几天到几周。

反证 —— 现行实现是正确的: 现行每波全档抓, B 页命中 ⇒ _process_rows 记命中 ⇒ _record_hit 撤销/落放行 ⇒ 条目经 _merge_seen 更新为 B 档。所以本动议是从正确行为退化为错判, 不是「补齐一处缺口」。

根因不在 B/C 页, 而在稳态定义: 「对象集为空」被当作「本地无义务」。超额线是一个取数侧的豁免 (省对账), 却被当成了判定侧的豁免。若要动这个方向, 先修的是这条语义 (§08 口径①②), 而不是把 B/C 页砍掉。

06结构性副作用与口径冲突

6.1 「全档」是写死的假设, 不是可配的旋钮

_position_covered 与 _absence_proven_all 都硬遍历 FETCH_LANES 并要求每档 st.ok:

# hr/service.py:1586-1589 (_position_covered)
for lane in FETCH_LANES:
    st = lane_states.get(lane)
    if st is None or not st.ok:
        return False          # ← 少抓一档 = 覆盖证明整体失效

# hr/service.py:1200-1203 (releases_enabled)
releases_enabled = (
    all(st.ok for st in lane_states.values()) and ...   # ← 同上
)

这不是疏漏, 是 v3 的设计前提: 缺席式结论要求「该位置确实被扫过」, 而位置空间是跨档的 (一颗种子可能在任何档)。跳过 B/C 会把这条证明整体关掉 —— 稳态下恰好没工作量, 但一旦未来需要批量签发 (例如放宽超额线、或稳态定义收紧后对象集重新非空), 就会变成「有需求但闸门恒关」。

6.2 与 v3 基石「每波自证覆盖」直接冲突

v3 波次引擎的原文口径 (service.py 模块 docstring):「每波都从第 1 页开始、以覆盖全部对象为目标 —— 清单是动的, 任何『从断点继续』『凭上波已见过而跳过』都在赌上波的覆盖假设仍然成立」。「稳态期不查终态档」正是它要防的那类假设 —— 它赌「B/C 档不会有新的本地种子出现」, 而 §05 证明这个赌注会输。

6.3 上游已裁定过这个方向

取证报告 26-10-03-1505 §13.2 原文:「稳态期单波开销不变: 对象集空不跳波, 每波仍 A/B/C 各至少 1 页 (3 请求) —— 降频省的是波次, 不是单波页数; 若要再省页数需改覆盖语义 (v3 设计前提「每波自证覆盖」), 不建议捆绑。」本报告的结论与该裁定一致, 并补上了「为什么不能只砍 B/C」的代码级论证。

07收益量化

口径现状跳过 B/C 后变化
稳态单波请求 (每站) A/B/C 各 ≥1 页 ≈ 3 A 档 ≈ 1 −2 / 波
稳态请求量 (两站合计, 1 波/天) ≈ 6 / 天 ≈ 2 / 天 −4 / 天
占站点日额 (240/站) < 1.5% < 0.5% 零头

量化依据: 稳态 1 波/天 (idle_refresh_interval = 24H) × 两站; 请求量口径沿用取证报告 26-10-03-1505 §13.5 (稳态两站 ≈ 6 请求/天) 与报告 26-10-08-1235 §05 (一簇 3 请求 = 一波)。

结论: 收益是「每天 4 个请求」量级 —— 站点日额余量本就极大 (240), 而代价是 §05 的错判 + §06 的三处结构副作用。投入产出严重不成比例。若目标是「再降请求量」, 应优先看别处 (见 §08)。

注: 稳态下 A 档本身的翻页深度未在本次核实范围内 —— 若 §13.1 的「空对象集仍扫描」导致 A 档翻多页, 则瓶颈在 A 档的停翻条件, 而不在 B/C。这条列为 §09 待确认项。

08更安全的替代路径

若目标确实是「稳态期再少发几个请求」, 有三条不破坏判定完备性的路, 按推荐度排序:

#做法为什么安全代价
A 用页头 H&R 计数做「有据跳档」: 摘要形站点 (BTSchool / CarPT) 第 1 页即带全档计数 (计划 26-09-29-2036 已落地)。C 计数 = 0 ⇒ 有证据地跳过 C。 不是「猜稳态」, 而是站点自报的空集 —— 与既有「计数对平 / 零行自证」同源, 语义可证伪。 B 档在这两站无声明 (BTSchool/CarPT 计数只含 A/C), 跳不了 B; 需另立计划。
B 把「稳态期 B/C 各限 1 页」显式化: 给空对象集的 B/C 档设 max_pages=1, 而非依赖停翻条件②偶然命中。 只改翻页深度上限, 不动「抓不抓」 —— 覆盖证明仍成立 (第 1 页照抓), §05 的转档仍可见。 收益有限 (现状已近似); 需要新常量或配置, 与「程序能定的绝不配置」权衡。
C 收口既有 issue 26-10-05-0922: SiteHrCheckConfig.fetchable 全仓零消费方, 「listing=none 不取数」未被取数侧强制。 修的是真实缺口 (配置声明与行为脱钩), 方向明确。 与「省页数」不是同一目标, 但同属取数侧开销治理。

若仍要推进「稳态只看 A」

必须作为独立计划, 且先定两条口径 (否则等于在错语义上打补丁):

  1. 稳态定义是否收紧为「无本地种子在 A 档」(即把超额种子也纳入对象集 / 纳入稳态判定), 使「稳态」真正等价于「本地无义务」。注意: 这会让超额种子重新参与对账, 反而增加请求 —— 与动议目标相反。
  2. _position_covered / _absence_proven_all 的「全档」假设是否改为「参与档」—— 并论证缺席证明在缺档时仍然成立 (这是全报告最难的一步)。
  3. 补守阵: 「超额种子 A→B 迁移」必须被钉死 (当前无此用例, 因为现行实现天然正确)。

09未决问题 / 待确认

  • 超额种子在 A 档的真实占比: §05 的回归类是否在真机上常见? 需以站点文件 <data_dir>/hr/<site>.json 的 index 佐证 —— 看有多少活跃 A 档条目对应的锚点 seeding_time ≥ 3×required。若几乎为零, 该回归的频度低 (但性质仍是错判)。
  • 空对象集下 A 档实际翻几页: §13.1 裁定「仍按三停条件/末页扫描」, 生产却只见 3 请求/波。需真机日志确认 A 档的翻页深度 —— 若 A 档也常翻多页, 那真正值得优化的落点是 A 档停翻条件 (与 B/C 无关)。
  • 是否入池: 本报告只做可行性论证 (证据快照); 「要不要做 / 什么时候做」应在 issue 工位裁决 —— 未拍板前不入池。
  • 同族缺口: 「超额线」是取数侧豁免被当判定侧豁免的一例。是否存在别的「取数侧豁免 ↔ 判定侧权威」语义错位 (如 HR 排除在两侧的口径)? 值得在设计阶段一并列举 (参考报告 26-10-08-1235 同类问题的处置)。
