整组迁移零搬移假成功事故取证(relocate 零搬移)

生产整组迁移报「已发起」后 10 分钟判失败:qB 报「成功移动」但数据零搬移。取证结论——收尾归位把 3 个种子的共享文件名物理挂上了 .!qB 后缀,而 mover 的账面工作名仍是声明名;下次搬迁按声明名逐文件 stat 全 miss,qB 静默忽略并报成功。auto-qb 的 .!qB 闸门只扫内容根顶层,深层文件漏拦。全链路已在测试 qB 复现,修复方向已验证(renameFolder 两步纯改名复位)。

§01结论

直接原因链(每步均有实证,见 §02)

  1. 账面名与磁盘名错位(诞生于 11-04 收尾,非历史遗留):组迁移 #1 成功后,收尾(ACT_FINALIZE)把 non-movers 经旧路径归位到新位置;missingFiles 成员的归位搬迁/重建以「未完成姿态」计算目标路径(makeActualPath 完成位 false ⇒ 带 .!qB),把共享物理文件整体改名挂上 .!qB(实验 G2/G5 同款机制)。mover 的账面工作名仍是声明名(其 resume 被接受,未经重建)——错位就此诞生,seed_mode 做种不读盘,隐形。
  2. qB 搬迁对缺失源文件静默忽略:libtorrent aux::move_storage 逐文件"stat 不到就跳过",全部忽略后返回成功 → qB 日志「成功移动了 Torrent」,save_path 更新为 待删\测试,数据一字节未动。
  3. auto-qb 预检放行:GATE_INCOMPLETE 看 qB 账面 progress=1.00 通过;GATE_QB_TEMP 的 .!qB 检测只扫内容根顶层,而 .!qB 全在 BDMV/STREAM/ 深层 → 漏拦。
  4. auto-qb 相位机兜底但慢且哑:mover 永不进 moving、dst 恒 0 → 10 分钟(move_stall_timeout 默认 10M)后 move_stalled 判失败 → 恢复成员;失败原因只落在 job 账,无显式告警。

auto-qb 缺口清单(已入池:issue 26-11-05-0420-bug-relocate-zero-move)

  1. GATE_QB_TEMP 浅层扫描(放行根因):relocate_plan.py:197-219 只 scandir 内容根一层;应按声明文件做存在性核对,且按「声明名 或 声明名+.!qB」双查。
  2. qB「成功移动」不可信:qbapi.py:144-156 setLocation 纯转发,不消费异步搬失败;应下发后短窗内核对 mover 进 moving / dst 落盘,否则快败。

  4. 失败反馈面:move_stalled 只落 job 账,WebUI 应显式告警。
  5. ACT_FINALIZE 归位后磁盘名对齐(冻结根因):归位搬迁/重建会把共享文件挂 .!qB(G2/G5 实证)——收尾最后一步按声明名做 file_stat 级核对,发现 .!qB 化即 torrents/renameFolder 两步纯改名复位(实验 G5 验证);不删种/不 skip_check 重加/不读盘校验,三项设计约束全守。

§03方法与局限

方法

  • 生产只读取证:qB WebAPI(16585/26586 日志、torrents/info/files、log/main)、fastresume bencode 解析(BT_backup)、文件系统枚举与时间戳;生产种子与目录零写入。
  • 源码静态分析:qB v5.2.3 与 libtorrent 2.x 源码树(D:\Projects\Else),调用链逐跳核对。
  • 测试 qB 黑盒复现:副实例(36596,空库草稿本)+ 自造假种子(real-fake 标签)+ R: 内存盘;A/B/C/D/E/F/G 七组实验闭环后全部清场(种子删净、数据目录删除)。
  • 设计意图对齐:收尾设计(等 qB 关闭删 junction → 重启 → 成员文件缺失 → ACT_FINALIZE 归位 → seed_mode 保进度免重校验)与三项约束(不删种/不 skip_check 重加/不读盘校验)经用户确认,作为修正分析与企业务基线。

局限与未覆盖

  • 11-04 收尾的微时序无日志:guardian 删 junction、ACT_FINALIZE 归位、改名挂后缀均不写日志;「归位搬迁即挂后缀」由机制(G2/G5)+ 时序(缓冲静默)+ 修复验证(G5)三方锁定,但别名删除与归位的先后等细节未逐行还原。
  • rejected 恢复的账面形态有竞态:测试中同一流程偶现 stoppedUP(账面保留)与 missingFiles(账面丢失)两种恢复态(F1 vs G);两者都能进入冻结错位,但竞态条件未穷尽。
  • 9-19 之前 H: 侧数据的下载/管理历史不可考(日志滚出、H: 证据已随搬迁清理)——不影响结论:数据完整且原名已由用户证言与对账确认。
  • 生产 config.yml 指向 16585,而生产 auto-qb 实际连接 26586(排查初期曾误判);生产 auto-qb 的运行目录与 state 落账未能读取,job.plan.files/last_error 未能核对。
