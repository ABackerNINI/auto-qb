§ 01 / 结论

结论:收敛高度可行, 且比计划预设的更有利

两套模板语义同一性 98.1% —— 全模板约 4,300 行里差异仅 80 行; 且计划的判据「皮肤类名占比 > 90% 才评估收敛」实测为 皮肤类名差异 = 0 行(0%)。两套 UI 连类名与逻辑接线(v-if / @click / v-model)都几乎完全一致, 真实分叉不是「皮肤差异表」能概括的量级, 而是 3 个可枚举的功能代差点 + 2 个棱镜专属件 + 注释措辞。

建议: 可以进入「单一语义模板」收敛的实施评估。若实施, 差异面不是一套映射表, 而是先把 3 个代差点做产品决策(星图是否跟进棱镜的切换胶囊), 再把 2 个棱镜专属块做成 UI 条件渲染 —— 后者机械, 前者需要拍板。

口径提醒: 98.1% 是语义行口径(注释措辞差异计入了分叉, 若把注释行剔除, 语义同一性还要更高 —— 见 §3 的明细归类)。

§ 03 / 明细

差异清单(全部, 共 4 类)

① 棱镜已上切换胶囊、星图仍是原生勾选框(FX-20/21/24, 唯一的逻辑分叉源)

  • addOpen: 棱镜 5 个勾选项(添加后开始/跳过校验/顺序下载/首末块优先/自动种子管理)是 .opt-pill 切换胶囊(FX-20), 星图是 <input type="checkbox"> + label; 「跳过校验」警告行棱镜为常驻占位 :class="{ on: addSkipCheck }"(FX-21), 星图为 v-if 摘除节点。状态字段与绑定量完全同名同义(addStart / addSkipCheck / …), 差异只在呈现组件。
  • modal.visible: 确认框的单选项与复选项, 棱镜为 .opt-pill(FX-24, 含 danger: c.key === 'delete_files' 着色), 星图为勾选框; 绑定状态(modal.checked / modal.checks)同源。

② 棱镜专属块(星图无此功能)

  • col-ghost(列头拖动虚影, FX-25): 状态栏旁 3 行元素 + 配套 JS。
  • 主题切换器(topbar): 棱镜顶栏的五主题切换 + 界面互切链接(theme.js 委托绑定, 不进 Vue 状态); 星图只有界面互切链接(/prism/)。

③ 注释措辞(无运行时影响, 占结构差弧行的大头)

主区 template 的 33 行结构差异中, 绝大多数是注释行改写(如 groups/shows/ctx-menus/statusbar 分片 0.92–0.99 的差异全部是注释措辞)——两套模板各自演化了注释, 语义行未动。收敛实施时注释以单一来源为准即可。

④ 结构性小分叉

除去上述三类后剩余极少: 棱镜添加对话框比星图多出胶囊包装层(①的伴随结构), 以及主区内个别换行/属性排布差异(diff 归一空白后消失)。

§ 04 / 评估

「单一语义模板 + 皮肤差异表」的形态、条件与风险

形态

  1. 一套语义分片(现 tpl/*.html 14 片)上移为两套共用的唯一来源; 皮肤差异不再改模板结构, 由 CSS 主题层 + 少量 UI 条件承载。
  2. ①的代差点需要先拍板: 星图跟进切换胶囊(推荐 —— 与 26-09-26 按钮体系重构同向, .opt-pill 样式棱镜已有, 星图补一份 CSS 即可), 或保留双态由差异表分发(多一张要永久维护的映射)。
  3. ②的两个棱镜专属块改为 v-if="ui === 'prism'" 一类的条件渲染或组件插槽; col-ghost 若星图也要(FX-25 是体验改进), 直接功能补齐比条件渲染更干净。

条件(实施前必须成立)

  • boot.js 注入路径不变(单一模板 = 一份 tpl/, 两套 shell 各自清单指向同一组分片或共享目录)。
  • 守阵口径重写: 现有「双 UI 成对改」类守阵(bt 计数/批量菜单成对/meta 对话框成对等约 6 处)在单一模板下退化为单份断言, 数量不减但对象变了 —— 计划红线「守阵数量不减(迁移 ≠ 删除)」需按新对象重新清点。
  • 两套 CSS 的选择器面必须先完成类名归一核对(差异 0 说明类名已同构, 风险集中在 prism 主题引擎的 data-theme 变量面)。

风险与工作量口径

  • 风险中高: 模板单点化后, 一次改坏 = 两套 UI 同时坏(现状是只坏一套); 必须沿用 W1 的聚合等价 + 无头冒烟双兜底, 并把冒烟扩成双 UI 五主题矩阵。
  • 工作量: 1–2 轮(代差拍板 + 星图补 CSS + 模板上移 + shell 清单改指向 + 守阵重写 + 冒烟矩阵), 计划预估 0.5–2 轮的上线。
  • 收益: 「成对改」人肉纪律在结构上消失(坑库 template-render.md 的立纪律根源被拆除); 模板面积减半(约 4,300 行 → 约 2,200 行)。
不实施也已有的收益: W1 之后成对改已经从「两份 2,600 行文件间跳转」降为「两套同名分片间跳转」, 且名单同名同序由守阵钉死 —— 收敛是锦上添花, 不做不影响可维护性底线。
§ 05 / 方法

方法与局限

  • 对齐: python HTMLParser 取两套聚合模板(= shell 内联 + 分片按清单序, 字节等价于拆分前)的顶层元素, 按 v-if 条件 / teleport / drawer / 类名标记配对; 配对后 SequenceMatcher 逐行 diff。
  • 三分类: 剥掉 class 与指令后骨架相等 → 皮肤; 指令集合或绑定表达式不等 → 逻辑; 其余 → 结构。注释行归入结构(§3 已单独归类)。
  • 局限: ①对齐签名对未命名 transition 有假不对称(已人工核对为同一元素); ②行级 diff 不验证 JS 侧行为等价 —— 但 W1 已证明两套消费同一份 shared JS, 模板差异即全部差异面; ③本报告为静态分析, 实施收敛前仍需真机双 UI 五主题冒烟。
