免重启整组迁移方案研究

免重启整组迁移可行：qBittorrent 的 WebAPI 面没有任何"保留进度改路径"的入口，但 auto-qb 现有跳检四阶段就是可靠的免重启重加原语 —— 推荐「OS 别名接续(A)为默认、新路径重加(B)为元数据干净选项、机会式收尾(C)为中期路线」，qBittorrent 补丁(D)仅作长期候选。证据为 qBittorrent / libtorrent / auto-qb 源码逐行核对 + 本机 junction 实测。

来源 用户指令「功能需要整合进 auto-qb、避免重启，深入研究免重启的脚本化方案」(2026-10-18 会话)；前序报告 memory-bank/reports/26-10-18-0826-report-missing-files-setlocation-recovery.html 已验证「文件丢失 + 设定位置」恢复链(依赖重启)，本报告回答其免重启等价问题

§01结论

总判：免重启可行，且 auto-qb 已有约 90% 的机制。qBittorrent 公开接口(WebAPI/GUI)里不存在"保留进度直接改 save_path"的动作；但 auto-qb 的跳检四阶段(导出 → 删除保留文件 → 重加 → 恢复快照)本身就是与重启完全无关的重加原语，把它的"重加路径"换成新位置、把"数据移动"插在删除与重加之间，就是免重启的真实迁移。唯一无法用现成接口消除的是 dont_replace + 目标已存在 ⇒ need_full_check ⇒ force_recheck 这条全量校验路径(storage_utils.cpp:123-127 → torrent.cpp:9381)，绕过它有两条路：让 qBittorrent 看不见这次路径变化(别名接续)，或让重加走 seedMode 信任模式(跳过校验)。

四条可落地路线

路线做法save_path 元数据上传统计数据校验主风险定位
A 别名接续暂停组 → OS 层移动数据 → 原 save_path 建 junction/symlink → 恢复半迁移(仍指向 alias)全保留无低(可回滚)即期默认
B 新路径重加复用跳检四阶段，re-add 到新 save_path(seedMode=跳过校验)真实迁移分享率清零存在性 + 大小(重加自带)中(信任数据)即期可选
C 机会式收尾A 先落地；下次 qB 自然重启后组员进 MissingFiles，自动 setLocation 到真实路径 → reload 恢复 → 删 alias最终干净全保留存在性 + 大小低-中中期
D qBittorrent 补丁setLocation 增加保留进度参数，跳过 move_storage 直接 reload真实迁移全保留可带校验维护负担长期候选

决策依据

  1. 用户的痛点是"零校验成本"，不是"元数据洁癖"：A/C 保统计、保连接、保标签队列，失败可回滚，作为默认；B 用统计清零换元数据干净，按需选用。
  2. 对齐 auto-qb 黄金法则「保守默认」：A 完全不改 qBittorrent 侧任何种子状态，天然最保守；B 复用既有闸门体系(部分下载/活跃下载/同日去重)但须新增"搬迁完整性"闸门，默认关闭。
  3. D 最优雅但不合身：auto-qb 是独立 Python 工具，为它维护一份 qBittorrent 补丁的部署与漂移成本，违反「范围守恒」；仅当团队决定长期跟 qBittorrent 版本时再考虑。
  4. A/C 组合天然幂等：junction 存在性可探测、setLocation 走 qBittorrent 自身 reload 校验、失败即退回 alias 态，全程可重入。

若要落地的设计约束(仅设计，不写代码)

  • 复用既有件：QbApi.torrents_delete/add/start/stop/set_location、grouping_mod 的组与文件映射(group_key_of = save_path + 文件相对路径)、ops_mod 的闸门/备份/快照恢复/轮询确认、state_file 幂等落盘。
  • 新闸门(保守默认)：组内成员 save_path 一致；成员全部已完成(部分下载禁止，与跳检 G3/G4/G6 同口径)；组内无活跃下载；搬迁完整性校验(默认 size 全量比对，hash 抽样可选)；junction 目标卷与源卷冲突检查；网络路径(UNC/SMB)拒绝 junction 降级。
  • 别名的目录粒度：A 的别名单位 = 该组共享的数据目录。若 save_path 下混放多个组，须由组文件列表计算最小公共目录，避免误搬别组数据(grouping_mod 已有 file_map 可算)。
  • 验收标准：迁移后组员 progress 不变、状态回 seeding、无 rechecking 日志、无全量校验告警；B 路线须在确认框明示"本地统计清零"。

§02证据快照

A. 别名接续(junction/symlink 透明重定向)

  • junction 免管理员创建(本机实测)：PowerShell New-Item -ItemType Junction 创建成功、Test-Path 穿透解析正常(本会话 Windows 实测，非引用)。
  • libtorrent 不会把 alias 解析回真实路径：aux::complete() 是纯词法操作(拼 cwd，path.cpp:930-935)，只有 TORRENT_USE_UNC_PATHS 才走 canonicalize；qBittorrent 存/用的 save_path 保持 alias 路径不变。
  • 空闲空间查询穿透别名：Utils::Fs::freeSpace() = QStorageInfo(path).bytesAvailable()(fs.cpp:315)，OS 层解析 reparse 点，报的是目标卷——不误触"磁盘满"告警。
  • 暂停/恢复不触发 reload：TorrentImpl::stop()/start() 仅 m_hasMissingFiles 分支才 reload(torrentimpl.cpp:2043-2050)；本方案根本不进入该状态，进度/标签/统计/队列零改动。
  • 边界：junction 目标必须是本地卷绝对路径，不能指向 UNC/网络路径(Windows reparse 点限制)；网络存储须用 symlink(需管理员)或走 C/D。Linux ln -s 同理可行(libtorrent 同样不解析)。

B. 新路径重加(auto-qb 跳检机制的直接变体)

  • 现成四阶段骨架：OpsModule.skip_check(ops_mod.py:377-483)：R2 实时复核 → 前置闸门 → 导出 .torrent → 布局推断 → 备份(先于删除，崩溃安全) → delete(保留文件)+轮询确认消失 → re-add+轮询确认出现 → 恢复快照 → 打标 → 可选 start。
  • 重加入参：_skip_readd 调 torrents_add(..., save_path=tor.save_path, ..., is_skip_checking=True, is_stopped=True)(ops_mod.py)——迁移变体只需把 save_path 换成新路径，并把数据移动插在 delete 与 re-add 之间。
  • is_skip_checking 的真身：qbittorrentapi 把它同时发为 skip_checking/seedMode(qBittorrent 5.3.0 改名，qbittorrentapi/torrents.py:423-425)→ lt::torrent_flags::seed_mode(sessionimpl.cpp:3087)→ set_have_all(true)(torrent.cpp:2073-2077)——重加即报 100%，不做哈希。
  • 重加自带存在性+大小校验：seed_mode 下 verify_resume_data 走 seed 分支，要求全部文件存在且 size ≥ torrent 记录(storage_utils.cpp:551-581)；数据未搬全 ⇒ fastresume_rejected + 全量校验 ⇒ 变 0% 开始下载。迁移完整性闸门必须在重加前保证数据就位。
  • 统计清零是既有实证结论：_skip_readd 注释(引 report 26-10-11-2017 §4.1)实测"重加走 skip-checking ⇒ qB 把全部块视为有效(progress=1 / 本地统计清零 / 状态进 stoppedUP)"——分享率从 0 重记，须明示用户。
  • 内容的信任模型：与既有辅种跳检同等(不校验 hash)，但信任依据更强——搬迁前本种子自身就是 100%/做种态，风险收敛到"移动过程损坏"，由 size 全量比对闸门兜底。

C. 机会式收尾(A 的干净终局)

  • qB 重启后组员自动进 MissingFiles 并可用 setLocation 零 hash 恢复：前序报告已验证的链路(fastresume_rejected_alert → m_hasMissingFiles → setLocation → reload 带旧进度位图 → verify 通过 → 进度恢复，torrentimpl.cpp:2135-2142)。
  • auto-qb 已有触发器：grouping_mod 的缺文件联动(_handle_state_transitions/_scan_triggered_groups)与 qB 重连退避(qbclient.py 头注)——C 不需要新造轮子，只加一条 alias 待迁移状态与确认后删 junction。
  • 安全序：setLocation 成功(reload 校验通过、进度恢复)之后才删 junction；alias 在，任何一步失败都可回退到"数据在原路径透明可见"。

D. qBittorrent 补丁的最小形态

  • 参照物就是现成代码：torrentimpl.cpp:2135-2142 的 m_hasMissingFiles 分支 = "改 save_path + 刷新 ti + reload"。补丁 = 把该分支从 MissingFiles 条件解绑，经 controller 暴露一个参数(如 setLocation 的 keep_progress)，即可对任意状态的种子做"保留进度迁路径"。
  • 不选核心理由：auto-qb 是独立 Python 工具，为它维护 qBittorrent 分支的部署/漂移成本大于收益(范围守恒)。

§03方法与局限

  • 方法：逐行核对 D:\Projects\Else\qBittorrent(sessionimpl/torrentimpl/torrentscontroller/fs)与 D:\Projects\Else\libtorrent(torrent/storage_utils/path)源码；junction 行为在本机 Windows 实测；auto-qb 侧读 ops_mod/qbclient/grouping_mod/qbapi 与 qbittorrentapi 库源码。
  • 局限：未在真实 qBittorrent 实例端到端实测组迁移(本机无真实 qB 与辅种数据)，B 的"统计清零"等结论引用 auto-qb 既有实证(report 26-10-11-2017)而非本轮复测；未覆盖网络存储(SMB/NFS)场景、macOS/Linux 符号链接细节、robocopy/rsync 参数选型；未实测组内混入未完成成员的完整拒绝路径。
  • 前置依赖：C 路线结论依赖前序报告 memory-bank/reports/26-10-18-0826-report-missing-files-setlocation-recovery.html 对「文件丢失 + 设定位置」恢复链的机制验证(该链需一次重启才能进入)。
