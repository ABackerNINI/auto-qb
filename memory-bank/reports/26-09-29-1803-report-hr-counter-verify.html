§0

结论速览

HR 计数对现有模型是高价值、低成本的增量校验，但不是结构性简化。它是清单的校验和，不是清单的替代品 —— 它验证「我们看到的行数与站点声明一致」，却始终不提供行级身份与每种子结论。最值得做的一件事不是省代码，而是堵上 B / C 档翻页标记失效时批量误放行这个当前无独立防线覆盖的洞。

问题结论依据（详见对应章节）
能否成为数据完整性的强烈佐证？ 能，且是最强的一档 每档一枚当波自报的绝对行数真值，校验粒度恰好落在现有防伪的盲区（§3、§4）
能否简化模型？ 有限但实在 可退役「零行人工确认戳」这一人机环节；末页翻页可省。档位 / 身份 / 守恒 / 观察期全部保留 —— 那是本质复杂度（§5）
能否增强安全性 / 稳定性？ 能，双向 误放行方向：补第三道绝对量防线，守住 B / C 档截断；误冻结方向：改版检测从「连续 3 波」提前到「当波」（§4、§6）
前提风险？ 主风险已移到口径 两站 myhr 页实测均有计数（26-09-29 用户实测，§2.2）—— 可用性不再是障碍， 即期收益成立； 剩余风险是各站计数的载体与口径校准（§8.1）， 错用 = 永久假冻结

「HR 上限」（达到上限会受处罚）按用户裁决忽略其处罚面；但上限显示里的当前值（如 x / 50 的 x）若语义等于现行 HR 总量，是一枚潜在的总数轴计数，可与分档计数两两互证（§8.3）。

§1

现有模型的证据与防线

v3 波次模型（计划 26-09-28-1932，现行为 src/auto_qb/hr/ 约 6500 行）的判定根基是：站点清单是唯一权威，档位即结论 —— A 考察中 / B 已达标 / C 未达标 / D 已免罪（model.py:28-37）；本地数值不得越级推翻站点结论（model.py:113-126）。每波从第 1 页起对 A / B / C 三档翻页，之后走行处理、防伪、放行签发（service.py 波次引擎）。

与本题直接相关的是「未列出 → 放行」这条链：本地有、站点清单里没有的种子，要解除管束，必须先证明「它确实不在清单里」。当前模型围绕这个证明布置了如下防线：

机制守什么粒度 / 阈值位置
覆盖证明（full_depth / 位置覆盖）「未列出」放行的前提档位级；全深度或完成时间位置覆盖HrLaneState (model.py:290) · _sign_releases (service.py:1117)
A 档流转守恒相对量防伪（A 段定向吞行）上波 A 行本波留存率 ≥ 0.7，否则冻结批量签发_retention_check (service.py:1104)

§3

完整性佐证：每档一枚校验和

把计数放回 §1 的防线表会发现：现有防线全部是相对量或结构性的（留存率、表头、行序、末页标记），没有一条是「绝对行数」的独立真值。计数恰好补上这一轴，而且直接命中三个现有机制看不见的洞：

3.1 最强论点：B / C 档翻页标记失效 → 批量误放行

「未列出」放行要求各档缺席证明成立（_sign_releases, service.py:1118-1120），而 B / C 档的全深度判定唯一依据是「下一页」标记消失（NexusPHP 灰色不可点的下一页是无 <a> 的 <font><b>，nexusphp.py:10）。设想改版把翻页标记改名或移位：第 1 页即被判定「到底」，full_depth = True，深处未见的行全部被当作「不在清单」—— 落在 C 档（未达标）深处的本地种子会被批量签发放行、解除管束，而站点侧仍在计它未达标，直接滑向 HR 处罚。

现有防线为何拦不住：守恒只盯上波 A 档行的去向（A → A/B/C），不管 C 档自身的完整性；排序检查只看已见行的单调性，截断点之后的行序无从检验；失效告警要连续 3 波才升级。计数是这个场景下唯一能在当波报警的独立信号：站点报 C 档 50 行、实抓 20 行，mismatch 即刻把 full_depth 打回 False，批量签发冻结，下一波重试。

3.2 解析早断的静默截断

行解析以「HR 编号列非数字即认为数据区结束」（nexusphp.py:138-140）。一行脏数据（站点插入的广告行、异常行）会让本页行数静默少计，而 has_next 仍在 —— 当前模型感知不到行数缺口。计数对平检查（本波该档有效行数 == count_claim，账本字段 HrLaneState.rows 已存在，model.py:307）把这类静默截断变成显式 mismatch。

3.3 波内清单漂移（TOCTOU）

一波持续数秒到数分钟，期间站点侧增删行会造成页间不一致（第 1 页见过的行在第 3 页重现 / 消失）。计数对不平 ⇒ 该波不签发放行，下一波自愈 —— 处置方向保守（只冻签发、不撤命中），与既有防伪的失败方向一致。

一致性判定矩阵（本报告的记忆点）：match → coverage PROVEN · mismatch → coverage FREEZE (当波, 不撤命中) · counter>0 ∧ rows=0 → HARD parse alert · counter=0 ∧ rows=0 → site-attested empty · None → 现状不变
§4

防伪与安全：补上绝对量轴

4.1 三轴合围

现行防伪两道（守恒 + 零行戳）加上计数后成三轴，每轴盯不同失效形态：

轴性质抓住什么抓不住什么
流转守恒（现有）相对量 · 身份流A 段定向吞行（改版 / 解析回归）C 档截断；首波无 A 历史时不适用
零行戳（现有）空集证明整表被吃光部分清账；需要人工参与
计数对平（新增）绝对量 · 当波站点自报任意档任意原因的行数缺口（§3 三洞全覆盖）行被「等量替换」（数对、身份不对）—— 由守恒补

注意互补性：计数抓数量异常，守恒抓身份异常。要同时骗过两道，一次故障必须恰好吞掉若干行、又恰好让剩下的行覆盖全部上波 A 档 tid —— 概率上大幅收紧。而通道本身跑在用户自己登录的浏览器里（扩展转发，非对抗性中间人），威胁模型本就以「改版 + 解析回归」为主，这正是计数最有效的场景。

4.2 为什么它不重蹈骤降保护的覆辙

被移除的骤降保护同样是绝对量检查（总行数 < 基线 30% 冻结），被裁的直接原因是基线高水位永不回落：站点合法清账后，本地记忆里的高水位把批量签发永久冻死 —— 一个误触面无法自愈的机制（service.py:944-946）。计数把「绝对量」的真值来源从本地记忆换成站点当波自报：站点清了账，计数随之归零，不存在陈化；站点没清账而本地少抓了行，mismatch 冻结恰是正确反应。同一个安全价值，缺陷形态被消除。

4.3 安全收益的方向性

本模型的核心安全性质是不误放行（把仍被计数的种子当「未列出」放出去 = 滑向处罚）。计数 mismatch 的处置只冻「批量未列出签发」，不影响命中、管束、终态冻结 —— 失败方向与既有防线一致，全部朝保守侧倒。反向收益同样存在：计数对平时，合法签发的放行获得了站点级的数量背书，置信度高于纯结构性证明。

§5

简化潜力：能省什么，不能省什么

5.1 能省的

可退役 / 可省量级说明
零行人工确认戳（计数可用的站点）人机环节整个退役count=0 是站点自证空清单，证据强度高于人工对账戳；「结构完好零行 → 等人工」的 zero_listing 软提示（events.py:90）升级为「计数>0 ∧ 行数=0 → 当波硬告警」。适用面限定 tab / 摘要形计数（第 1 页即得数）—— CarPT 实证的分页区间形空表页不渲染标记， 无法自证空集， 该形态站点维持人工戳
末页追翻省少量页数rows == claim 即语义全深度，不必追到「下一页」标记消失；在对账收尾期（波已变浅）与停翻条件①③叠加时偶有收益。属优化非简化
观察期 2 波 → 1 波不建议计数对平时单波缺席已有数量级佐证，逻辑上可缩短；但省的只是至多一个 refresh_interval 的管束（保守方向），换来的却是「计数偶发错」直接漏判的风险敞口。建议保留 2 波，计数仅作记录

5.2 不能省的（本质复杂度）

以下机制全部保留 —— 它们解决的都是行级问题，而计数不携带行级信息：

  • 档位判定：计数无「哪个种子在哪档」；
  • 身份登记（.torrent → infohash，model.py:197-227）：计数无 tid，更无 infohash；
  • 流转守恒：等量替换骗得过计数，骗不过守恒（§4.1）；
  • 观察期 / 位置覆盖 / 新鲜度闸门：都是「这个种子此刻在不在」的时序与位置推理。

一句话收束：计数是清单的校验和，不是清单的替代品。校验和让完整性可机检，但内容仍要逐行读 —— 所以架构不动、复杂度基本不减，换来的是既有机制的每个结论都多了一层数量背书。这决定了它在 §7 里的集成形态是「收紧既有判定的一个 AND 条件」，而非新子系统。

§6

稳定性增益

  • 改版检测提前两个数量级：现行「同档连续 3 波失效 → ERROR」（service.py:129）以波周期计，3 波可能是数小时到一天。计数与表格结构在页面上是解耦的两个区域（tab 栏 / 摘要行 vs 数据表）—— 表格塌了计数还在、或计数还在但解析行数对不上，都能当波报 parse 类告警。检测通道从单变双。
  • 登录态负信号：页面上解析得到计数文本，本身即是「这是真 HR 页而非登录页 / 挑战页」的佐证，可作 looks_like_login（adapters/base.py:57）的补充证据，降低误判登录失效造成的取数停摆。
  • 截断账本可量化：预算截断的波（ACTION_PARTIAL）目前只有定性记录；rows vs claim 给出「还差多少行」的量化差值，写进 wave.notes 与走查报告，排障时直接看缺口。
  • 多实例无感：计数是每波页面事实，随 HrLaneState 走站点文件，不需要跨实例协调，不与「单一写线程」黄金法则发生任何交互。

§8

风险与校准

8.1 口径与形态漂移是首要风险

两站均有计数后， 可用性不再是风险， 首要风险转为校准：各站计数的载体（tab 后缀 / 摘要行 / 分页区间标记）与口径不统一 —— B 档计数是否含自动通过？免罪（D）后减不减？分页区间终点是否严格等于档内总行数？校准错误的后果是永久 mismatch = 批量签发永久冻结 —— 恰好是骤降保护被裁掉的那种误触面，只是换了个入口。所以铁律是：宁可不用，不可错用 —— adapter 只在样张实证「计数 == 全深度翻页实抓行数」后才返回非 None；拿不准一律 None（降级现状）。连续多波 mismatch 的告警文案里应明确提示「可能是计数口径校准错误」，引导摘除而非硬扛。分页区间形的推导规则按 CarPT 样张钉死：区间终点即档内累计行数（17 行数据显示 1 - 17, 1 起含端）—— adapter 只认这个语义, 新站点接入前须以自己的样张复核。

8.2 服务端缓存陈旧

若站点计数有服务端缓存滞后，偶发 mismatch 的处置是「该波不签发，下一波自愈」—— 方向保守、代价一轮波，可接受；连续 N 波（建议复用 3 波口径）不平时才升级告警。

8.3 HR 上限的总数轴用法

按用户裁决，上限的处罚面不管。但徽章形如 H&R: 12/50 的 12 若实证等于 A+B+C 现行总量，则它是一枚与分档计数相互独立又相互约束的总数（Σ分档 == 总数 == 实抓行数，三者两两互证），比任何单一计数都难被骗过。是否纳入属裁决点 D4。

§9

裁决点

是否立项。本报告建议：立。收益即期 —— 两站实测均有计数， 不必等新站点； 低风险（纯增量、缺数降级）、高价值（堵 B / C 档误放行洞 + 零行人机环节退役）。
样张采集与载体定形。两站各采当期样张（考察中 / 已达标 / 未达标三档， 含翻页与空表形态）， 定形各站计数的准确载体（tab / 摘要行 / 分页区间）与口径 —— CarPT 存档实证的「1 - 17 终点即档内总数」是分页区间形的推导基线， BTSchool 的载体待新样张确认。
校准策略。方案 A：样张实证后硬编码启用（本报告倾向，与现有 adapter 站点事实的口径一致）；方案 B：前 N 波只记录不执行（影子模式）后再启用。取 A 则 §8.1 铁律必须写进 adapter 覆写约定。
HR 上限总数轴是否纳入。若 D2 的站点恰好显示 x/y 徽章且口径可实证，建议一并纳入（三者互证，§8.3）。
