结论

6概念域

16涉及 shipped 文件
  • qB 有既定译词、我们没有对齐的 —— 最典型就是你点名的 Seeds:qB WebUI 译「种子」、GUI 译「做种数」, 而我们四处列头写成「做种」。同类还有:浪费(qB「已丢弃」)、见到完整副本(qB「最后完整可见」)、剩余量(qB「剩余」)、获取元数据(qB「下载元数据」)、文件缺失(qB「丢失文件」)、强制汇报(qB「强制重新汇报」)、重新校验(qB「强制重新校验」)、移动(qB「更改保存位置」)、首末块优先(qB「先下载首尾文件块」) 等。
  • qB 内部也分两种口径, 必须先选一种作准 —— 同一个概念, qB 的 WebUI 与 桌面 GUI 译文偶尔不同(Seeds、Completed、All-time share ratio、Session waste、Connected peers、剩余空间、Trackerless …)。我们是一个 WEBUI, 理应以 qB WebUI 为准; 但你举例用的是 GUI 的「做种数」。这是本报告第一个要拍板的口径(§10 D-Base)。
  • 状态词的系统性偏差:我们爱加「中」 —— qB 状态是「下载 / 做种 / 校验 / 暂停 / 排队 / 等待 / 错误」, 我们大量写成「下载中 / 做种中 / 校验中 / 已暂停 / 等待下载」。且我们自身不统一:同一「错误」态, 抽屉里叫「出错」、列表里叫「错误」;「做种」与「做种中」并存。
  • 动作词的偏差 —— qB WebUI 用「启动 / 停止」, 我们用「开始 / 暂停」; qB「强制重新汇报」, 我们「强制汇报」。这类改动影响菜单与 toast, 需一并核守阵。

一句话:方向词(上行/下行 → 上传/下载)是"字面替换"问题;术语对齐才是这轮的大头 —— 列头(做种/浪费/剩余量/见到完整副本…)、状态词(去「中」)、动作词(启动/停止、强制重新汇报…)、对端状态词(取流/供流)四族, 每一族都要先定"以 qB WebUI 还是 GUI 为准", 再逐条替换。

08

保持不动 / 我方自有概念

  • 已对齐 qB 的(保持) —— 名称/大小/总大小/进度/状态/用户/下载速度/上传速度/剩余时间/可用性/添加于/完成于/已下载/已上传/保存路径/分类/标签/Tracker/优先级/移动中/超级做种/重命名/删除/复制/打开目标文件夹/分享率(取面板口径) 等。这些是本次的目标基线, 不是改动对象。
  • 我方自有概念(qB 无, 不算不符) —— 站点 / H&R / 站数 / 版本 / 剧名·集 / 最近活动 / 最近动静 / 详细信息 / 导出 .torrent / 跳检 / 标签·分类编辑 / 通知面板 / HR 在线核实 / 限速曲线的档位命名 等。它们没有 qB 对应词, 只要求"不新造与 qB 冲突的词"。
  • 不要把状态「做种」改成「上传」 —— qB 的"上传态"叫做种(Seeding); 方向词的「上传」与状态的「做种」是两件事, 不可互换。
  • CSS 令牌 / 图表机制不动 —— 方向色 --today-up/--today-down 的取值、「上行=紫/下行=蓝绿」的注释可顺手对齐, 但配色逻辑与图表结构不变。
