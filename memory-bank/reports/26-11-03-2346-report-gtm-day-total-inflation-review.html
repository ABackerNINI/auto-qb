1.2 发现与处置

#发现处置
1fetch_last_spike 复用探活超时 10s,但它在主循环线程的快照 refresh() 里同步执行;GTM 控制面挂起(非拒连)时最长拖主循环 10s/轮 —— 对一个「允许失败、失败即静默」的横幅数据源不成比例已修:新增专用常量 SPIKE_TIMEOUT_S = 3.0(agent.py),取数默认超时改用它;补超时契约测试钉住「3.0 且严格小于探活超时」
2sample_once 直调误传 interval_hint <= 0 时 min(dt, 3×hint) 给 0,_evaluate_rate 除法抛 ZeroDivisionError(生产路径安全:_check_duration 拒绝 ≤0,仅直调 API 防御面)已修:_dt_since_last 对 interval_hint 先行校验(≤0/NaN 跳过判定 + DEBUG);补直调守阵测试。NaN 单独说:min(dt, NaN) 因 NaN 比较恒 False 会静默放行真实 dt,所以校验必须放在 hint 入口而不是 eff_dt 出口 —— 首版守卫写反了位置,被新测试当场抓红后改正
3save_config 拆分路径每次 PUT /config 都重写 overlay(含 .bak),即使值未变 —— 与启动路径 ensure_v2_overlay「相等不写盘」(I3)的幂等口径不对称已修:新增 _overlay_already_matches,overlay 已存在且解析值与内存值逐项相等时跳过改写(mtime 不变、不陪跑 .bak);补幂等测试(两次保存 mtime 不变、值变仍照常改写)
4「_restore_v1 不校验合计基线非负」撤回:评审误判。_opt_int 本就是「可选非负整数」契约,负值走 ValueError("负值: ...") → 损坏降级,既有行为已正确。新增测试保留为该契约的回归钉(断言「负值」文案),修复代码撤销
诚实记录:评审轮报告的第 4 条是错的 —— 报告里写的「顺手记一笔」级别问题经实核不成立。_opt_int 的 docstring("可选非负整数…否则抛")当时没有展开看。教训与「先索引后 grep」同构:断言"缺校验"前先看被调用的校验单点。
