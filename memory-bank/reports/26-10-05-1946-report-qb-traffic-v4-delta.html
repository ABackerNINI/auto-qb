qb-traffic · 存储格式可行性分析

块头基线 + Delta 行编码与按落盘切块

qB 口径流量 v3 天文件的 totals 列压缩、块生命周期重定义与跨块覆盖结算 —— 面向 v4 换代的完整可行性判定。

报告 · report topic qb-traffic-v4-delta status Done added 26-10-05-1946 基线 80f48bc7 (develop)
  1. Delta 编码可行,唯一安全的锚点是块头基线。 各行相对块基线独立可复原,现行「坏行整行跳过、不传播」纪律原样保持。
  2. 按落盘切块(块 = 批)推荐 —— 它把周期性重锚变成免费机制,是 delta 收益从「温和」变「值得」的钥匙,且写侧净简化。 header_written 退役、LiveTail 倒推分支结构性死亡、「块首 n 游程」特例被 n-only 前缀块取代。
  3. 「相对上一行」delta 不建议 —— 比块基线只再多省约 4-6% 整文件,却引入链式 totals 状态与坏行偏差语义。 勘误后的准确表述:偏差 Δ 在差分消费中抵消、速率列不受影响,是「不值」,不是「不可行」。
  4. 覆盖损失可消除 —— 连续性可从文件自身推断,「块间 = 真空」只是保守缺省而非必然代价。 自然推算把块边界覆盖损失从 0.33% 压到约 0.08%(仅剩 B.start 截断残差)。
  5. 整体是一次 v3 → v4 格式换代,宜早不宜拖 —— v3 数据现存 ≤ 1 天,是孤儿成本最小的时点。 R2 语义:旧目录原样留存不读不迁移;拖久则被搁置的 v3 历史线性增长。
01 · Verdict

结论

对「qB 流量把数据量(totals)存进块头、后续行用 delta 形式」的三轮推演收敛为一条实施路径:按落盘切块(每 flush 关块重开)+ 块头携带 totals 基线 + r/z 行存相对基线的 delta + 跨块覆盖按量级判别结算,打包成一次 v4 换代。判定:可行,净收益为正;但它是行宽封顶的结构性改进(约 -10~14% 文本量,并使行宽与 all-time 计数增长彻底脱钩),不是数量级级的空间手段 —— z/n 游程早已把空闲段压掉了。

三项分析过程中的判断修正已如实保留在正文:03 节修正「相对上一行 = 硬伤」的过重表述;05 节修正「块间覆盖损失不可避免」的误区 —— 两处修正都让结论更准确,且都不改变最终推荐。

02 · Background

背景与现状

v3 天文件每个 r 行携带 4 列数据:双速率 + 双 all-time totals 快照(Prometheus 口径)。totals 是行宽的大头且无界增长:all-time 计数每涨一个数量级,每行宽 2 字节,重鼠多年后单列 15-18 位。2s 档天文件 ≈ 2MB/天(store docstring 实测口径,约 48.6B/行),totals 两列约占一半。

v3 现行行型(格式契约单点:core/traffic_store.py 头注释)
B,<start_epoch>,<interval_s>                    # 块头:仅时间口径,无数据量
r,<dl_rate>,<up_rate>,<dl_total>,<up_total>[,<dt_ms>]  # totals = 绝对快照
z,<run_len>,<dl_total>,<up_total>[,<dt_ms>]      # 空闲游程,totals 恒快照
n,<run_len>[,<dt_ms>]                            # null 游程,无 totals

关键事实:读侧的消费形态本来就是 delta。UI 传输量段(traffic_grid 的 v3_totals_points / series_totals_points / group_totals_points)全部由相邻桶快照差分得出;速率列是直采列。因此存储改 delta 不改变任何下游语义,只是把差分从读侧挪到写侧,换来的是 totals 列宽度从「无界」变「有界」。

03 · Design Space

设计空间:三个 Delta 锚点

delta 必须相对某个锚点。三个候选的宽度、坏行语义与判定如下(行宽示例取 1 Gbps 满速持续负载:速率 100 MiB/s,all-time 50 TiB,2s 采样、600s flush):

锚点形态totals 列语义宽度(满速例)坏行影响判定
全局绝对 现行all-time 快照14+13 位,随年头增长仅损该行现状
块头基线 推荐相对块基线≤ 块窗 × 速率,11+10 位仅损该行(各行独立复原)推荐
上一行 否相对前记录≈ 速率 × dt,9+8 位偏差 Δ 传播至块尾不值

勘误:「相对上一行 = 硬伤」说过头了

初轮分析把相对上一行判为不可行,理由是坏行传播。修正后的事实:现行 dt 链在坏行「游标不推进」后,后续行的时刻同样整体前移一个间隔 —— 项目已经接受了这类「每坏一行、后续偏移一份」的语义;且 totals 的恒定偏差在差分消费(传输量段)里自动抵消,速率列完全不受影响。真实伤害仅是:坏行之后本块绝对 totals 快照整体低 Δ(Δ = 坏行那一份传输量),落到 hour/day 行的绝对 totals 与差分链的边界桶。所以它不是不可行,是不值:相对块基线已从 13-14 位压到 10-11 位,相对上一行再压到 9-8 位,差约 4B/行(整文件再省 4-6%),却要引入块内链式状态、解析器带链、以及一类新的偏差语义。

dt 链用逐行增量而 totals 不用,还有一层结构性理由:时刻没有更粗的自包含表示,只能逐行增量;totals 有 —— 块基线就是。坏行不传播这条现行纪律由此原样保留。

04 · Block Lifecycle

按落盘切块(块 = 批)

块基线方案的唯一短板是:现行块可长达一天(仅 00:00 / 改间隔 / 重置关块),块内传输量会让 delta 宽度退化回绝对量级。初轮曾以「周期性重锚需要加行型,不值」否掉重锚 —— 按落盘切块推翻了这个前提:每 flush 关块重开,用现成的块边界做重锚,零新行型,基线最多老一个 flush 周期(600s),delta 宽度从此 ≤ flush 窗 × 速率。

三个连锁影响

① 覆盖结算(唯一语义代价,见 05 节) —— 块首清零信用使每个 flush 边界丢一个采样间隔的聚合覆盖,量级判别可基本消除。② 游程随 flush 封口 —— 开放 z/n 游程不能再跨 flush;因 ZRUN_FLUSH_S = 600s ≈ flush 间隔,游程本就该封,实际只多约 144 行/天(+0.3%),顺带把「崩溃丢开放游程」窗口进一步压小。③ 写侧净简化 —— 块 = 批后 header_written 旗标死亡;LiveTail 的 head_pending=False 倒推分支结构性不可达(S6 刚建的代码可删);初轮最丑的「块首 n 游程 → 绝对模式块」特例被更干净的手段取代:n-only 前缀自成一个无基线块(n 行本就无 totals 列),同批内恢复传输时写侧拆块即可。

配比约束

收益依赖 flush_interval ≫ sample_interval(块内 ≥ 约 20 行):2s 档 B 行开销约 0.2%,30s 档升至约 5%,若 flush 被配到与采样同量级,B 行会吃掉 delta 收益。v4 校验应加一条配比约束或文档口径。

05 · Coverage Settlement

覆盖结算:从「一律真空」到「量级判别」

聚合对 hour 桶是前向记账:每条记录到达时,把上一记录的速率结算到 [上一槽, 本槽);结算触发器 = 下一条记录到达,信用挂在 open_credit。块首按现行定约「先清零、不结算」(traffic_sample_mod.py:826-831),于是跨块界的那一个间隔成了孤儿区间;离线 catch-up(_agg_credit_day_file, :1064-1075)同口径。按落盘切块把边界从每天 1-2 次变成 144 次/天:600s flush × 6 次/时 × 2s = 12s/时,cov_s 约 -0.33%(1.5s 档 -0.25%)。avg 分子分母同减、无偏;max / totals / 速率图(槽在两侧、桶非空)均不受影响。

误区修正:连续性可以从文件自身推断

「块间 gap = 真空」的真实身份是无测量时的保守缺省,不是必然代价。初轮论证错在:把「离线不知道边界成因(崩溃?跨天?改间隔?)」错当成「无法区分连续与断裂」。成因不可知,但连续性不需要成因 —— gap = 新块 B.start − 上一块末槽 这个数本身就在盘上(在线写侧游标与离线 v3_block_slots 重算的恒等正是 S6 钉死的镜像保证)。连续时 gap ≈ 一个标称间隔,断裂(崩溃窗口)时是分钟/小时级,量级差两三个数量级,一个阈值即可判。

结算方案机制覆盖损失代价判定
一律真空 现行块首无条件清零信用0.33%(块=批)/ 2s 每天(现状)—保守缺省
自然推算 推荐gap ≤ interval + DRIFT_TOL → 按上一记录速率结算;否则真空≈ 0.08%(仅 B.start 截断残差,上界 0.17%)零格式成本;在线/离线各改一处、同一函数同源推荐
延迟 e 行 可选下一块首记录到达时实测 gap,随下一块首次 flush 以 e,<gap_ms> 写在新 B 行前0+1 行型 + 写侧暂存上一块尾;长暂停也如实跨块记除非要完整对称口径

崩溃保护内核在两个方案里都不动:gap 超阈值 → 真空,「不虚记覆盖」的保守取向保留,判据从「一律真空」升级为「量级判别」。延迟 e 行与下一块首批同生共死 —— 崩溃则两者都没有,末块无 e 行 = 真空,恰好正确。自然推算顺带修复现行 v3 在 00:00 边界每天丢 2s 的既有损失;e 行的增量价值仅剩消除 ≤1s/边界的截断残差,以及把跨块长暂停与块内「dt 取实测大值如实入行」做成完全对称 —— 若不要这两样,选自然推算。

06 · Proposed Format

推荐方案:v4 格式规格

v4 行型(读写两侧同源定约,风格与现行 dt 链一致)
B,<start_epoch>,<interval_s>                       # 3 列 = 无基线块(仅 n 游程合法)
B,<start_epoch>,<interval_s>,<dl_base>,<up_base>  # 5 列 = 基线 = 块内首个带 totals 观测的快照
r,<dl_rate>,<up_rate>,<dl_delta>,<up_delta>[,<dt_ms>]  # delta 相对块基线;负值 = 坏行(解析免费校验)
z,<run_len>,<dl_delta>,<up_delta>[,<dt_ms>]         # 块内已传量;块首 z 的 delta = 0
n,<run_len>[,<dt_ms>]                              # 不变

定约清单

基线立点:块首记录带 totals(r 或 z)→ 基线 = 该快照,其 delta = 0;块首为 n 游程 → 写侧把 n-only 前缀拆成无基线块(3 列 B),恢复传输的记录开新块立基线 —— 解析守卫:无基线块内出现 r/z 即坏行。计数器重置(cur < last)强制关块重开 —— 写侧状态机唯一新增的关块触发点(现有:00:00 硬切、改间隔、落盘失败复位),新块基线 = 重置后 totals,首记录 delta = 0;否则块内出现负 delta。解析层新增免费校验:基线块内负 delta 必是损坏 —— 这是绝对值形态做不到的(绝对值里回落合法,delta 里非法)。块生命周期:每 flush 关块重开(块 = 批),interval_s 沿用小数秒口径(1.5 档)。

关键降本手法:delta 只存在于线格式

内存结构(V3Sample / V3ZeroRun / LiveTail / 聚合累计器)全部维持绝对 totals:parse_v3_day_text 以块基线做 cumsum 复原绝对值,format_v3_* 序列化时做减法,且 delta-vs-基线逐行独立、与 flush 批次无关,不需要跨批链状态。由此 v3_block_slots、读侧归桶、catch-up 恢复、agg.dat、WebUI 全部零改动,影响面收敛在 store 纯函数区 + 采样器状态机 + 测试。
