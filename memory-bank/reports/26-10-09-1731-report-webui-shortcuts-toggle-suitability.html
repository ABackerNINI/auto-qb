快捷键「改为切换语义」适配性分析
哪些适合「按一下开 / 再按一下关」

问题：现有快捷键里，哪些适合从「只负责打开」改成「开 / 关双态切换」（如 qB 流量图 —— 按一次打开，再按一次关闭）。本文档先给出判定准则，再对注册表内全部 59 条 快捷键逐条判定，最后给出适合 / 不适合总表与实现约束。只分析、不改代码。

01 · 结论 TL;DR

「切换语义」的适用范围很窄：只有「控制某个界面/浮层的显示与隐藏」且「关闭无副作用」的动作才适合。按此准则，注册表 59 条里：

判定条数典型代表
✔ 适合6 qB 流量图 Ctrl+\、统计面板 \、历史流量 Shift+\、详情面板 I、快捷键帮助 Shift+/、列选择器 K
◐ 有条件4 详情面板页签 Alt+1~5、行打开 Enter、限速浮层 L/Shift+L、打开设置 Ctrl+,
✖ 不适合49 导航类（1/2/3）、命令类（暂停/开始/删除/队列/复制）、移动与选择类、行级展开收起、流量图窗口循环 [/]

推荐

优先做 qB 流量图（用户点名）与详情面板 —— 二者本体是停靠抽屉，不在「浮层屏蔽名单」里，再按一次按键能正常抵达引擎，改造成本最低（只需在打开入口补一个「已开同目标 ⇒ 关」分支）。统计 / 历史 / 帮助 / 列选择器属于浮层，再按一次会被引擎的「浮层打开即屏蔽列表键位」闸门吞掉，需要额外放行（见 §07）。

02 · 判定准则

把一条快捷键改成「开 / 关切换」需要同时满足以下五条；任一条不成立即不适合或只适合有条件做：

#准则说明 / 反例
C1界面显隐 动作控制的是「某个界面 / 浮层 / 面板的显示与隐藏」，存在明确的「关」状态。
反例：切页（1/2/3）没有「关掉这一页」的语义。
C2关闭无副作用 再按一次只是把界面收起来，不丢数据、不发后端命令、不改 qB 状态。
反例：添加种子对话框、标签/分类对话框、限速浮层含输入框 —— 关闭会丢草稿。
C3键位语义单一 该键位只表达「打开这个界面」，没有并列的第二语义。
反例：Enter 在组行是「展开」、在种子行是「打开面板」，语义随行类型漂移。
C4重复按下期望明确 用户第二次按同一键，直觉期望是「关掉它」。
反例：队列上移 Ctrl+↑ 连按是「继续上移」，不是「撤销」。
C5有开关基础 代码里已有布尔开态或幂等短路，改造只需在打开入口加「已开 ⇒ 关」分支。
反例：危险动作（删除/重新校验）本质是一次性命令，无「开态」可切。

判定分三档：✔ 适合（五条全中）· ◐ 有条件适合（多数命中但有语义/副作用顾虑，需产品拍板）· ✖ 不适合（违反 C1/C2/C3/C4 之一）。

3.2 ◐ 有条件适合（4 条）

键位动作现状 / 顾虑建议
Alt+1~5详情面板页签 已是双态：面板关 ⇒ 开面板并定位页签；面板开 ⇒ 切页签（同页签再按无反应）。 可补「同页签再按 ⇒ 关面板」，升级为完整切换。需与「切页签」语义并存（不同页签仍切换）。

04 · 适合：逐条详解

4.1 qB 口径流量图 · Ctrl+\（用户点名，首选）

入口 openQbHistory() → openDrawerTraffic("global", "")。该函数在「已开着同一形态同一目标」时会幂等短路（注释自述「同目标重入短路……重复按键不闪」）—— 这正是「再按无反应」的根因。改为切换只需把这条短路分支从 return 改成 closeDrawer()。抽屉不在浮层屏蔽名单，第二按能正常抵达，改造面最小。

4.2 详情面板 · I

_kbOpenDrawer() → openTorrentDrawer(hash)，已开同 hash 时短路返回。语义上 I 就是「详细信息面板」的专属键，做成「按一下开、再按一下关」最符合直觉。注意与 Alt+1~5（页签）的协同：I 管「面板整体开关」，Alt+N 管「定位到某页签」。

4.3 统计面板 \ / 历史流量 Shift+\ / 快捷键帮助 Shift+/

三者都是纯展示浮层，各有现成的布尔开态（statsOpen / historyOpen / kbHelpOpen）与关闭方法（closeStats / closeHistory / closeKbHelp）。改成切换只需在 run 里加「已开 ⇒ 调 closeX」。唯一障碍是浮层打开后引擎会屏蔽列表键位（见 §07），需要放行本键。

4.4 列选择器 · K（切换逻辑已存在）

toggleColMenu(ev) 的方法体第一行就是 this.colMenuOpen = !this.colMenuOpen —— 切换函数现成。但 colMenuOpen 在 _kbOverlayBusy() 名单里，浮层一开，第二次按 K 就被闸门拦下（源码注释也写明「键盘再按被浮层屏蔽，关闭走 Esc」）。因此这条的改造 = 把本键从屏蔽闸门放行，几乎零新增逻辑。

05 · 有条件适合

5.1 详情面板页签 Alt+1~5 —— 升级为完整切换

现状 _kbDrawerTab(tab) 已是双态（关 ⇒ 开并定位；开 ⇒ 切页签）。补「同页签再按 ⇒ closeDrawer()」即可。需明确优先级：不同页签 = 切换页签；相同页签 = 关闭面板。这是「双态」的自然延伸，风险低。

5.2 行打开 Enter —— 建议保持现状

Enter 在组/剧/集行已是展开↔收起（切换），在种子行是打开抽屉。不建议让种子行的 Enter 去关面板：Enter 的主语义是「打开/进入」，与 Esc「关闭」分工清晰；若让它兼任关闭，会与「展开/收起」的既有直觉打架（违反 C3）。

5.3 限速浮层 L / Shift+L —— 不建议

浮层内是输入框，再按关闭会丢输入（违反 C2）；且下载/上传两方向共用一个键族，键位语义不单一（违反 C3）。若一定要做，只能限定在「未改动任何值」时才允许切换关。

5.4 打开设置 Ctrl+, —— 不建议

设置是独立页面而非浮层，没有「关」的概念（违反 C1）。若用户需要「从设置返回」，应新增一个明确的返回键，而不是让同一键在「进设置 / 出设置」之间来回切（那会与 1/2/3 的切页模型冲突）。

06 · 不适合：分类理由

49 条不适合的快捷键可归为「三类硬边界」，只要落进任一类就不该做切换：

边界一 · 非界面显隐（违反 C1）

导航（切页）、光标移动、选择、队列命令、qB 状态开关、流量图窗口循环 —— 这些动作没有「关」的状态。特别注意两个易混淆项：

  • qB 状态开关（TMM Shift+T、强制开始 Shift+F、超级做种）本身已经是「切换」，但它切换的是种子状态而非界面显隐 —— 语义已正确，无需改动。
  • 流量图窗口 [/] 是多档循环（13 档窗口前后翻），不是「开/关」；把它改成切换会丢失「连续翻档」的能力。

边界二 · 关闭有副作用（违反 C2）

所有表单类对话框：添加种子、标签/分类、移动位置、重命名、分享率限制、限速浮层。它们的「关闭」等于「放弃输入」，做成再按即关会让误触代价变高。

边界三 · 一次性命令 / 危险动作（违反 C1、C5）

暂停、开始、强制汇报、重新校验、删除、导出、复制、打开文件夹 —— 这些是「发一条命令」，没有「开态」可切；危险档（删除/校验/汇报）更应在确认框里兜底，而非引入一个可连按的开关。

易错提醒

不要因为「某个动作看起来像开关」就改切换。判据是 C1「是不是界面显隐」，不是「是不是可逆」。Space 切换选中、TMM 切换都是可逆的，但都不是界面显隐。

07 · 关键实现约束

若拍板实施，有三个必须知道的机制约束（均来自现有引擎，不是新设计）：

7.1 浮层屏蔽闸门会吞掉「第二次按键」

_kbOnKeyDown 里：浮层打开时（_kbOverlayBusy() 为真），除 settings/drawer 外的键位一律失效。而统计/历史/帮助/列选择器都在屏蔽名单里 ⇒ 浮层一开，本键就被拦。因此「适合」列表里：

  • 抽屉类（qB 流量图、详情面板）：抽屉已从名单摘除，第二按可直达，零障碍。
  • 浮层类（统计/历史/帮助/列选择器）：需要放行 —— 可选做法是给这些条目一个「自切换白名单」，在闸门分支里允许「自己控制的浮层开着时」仍消费本键。这是唯一的实现新增点。

7.2 幂等短路要改成「已开 ⇒ 关」

流量图与详情面板的打开入口已有「同目标重入短路」（返回、不重建）。做切换时，这条分支要从 return 改成 closeDrawer()。注意保留原有的「换目标」语义：不同目标 = 换目标，相同目标 = 关闭。

7.3 优先复用既有机制，别新造状态

  • 条件绑定 when：流量图窗口键已用 when: (vm) => vm.qbTrafficActive 实现「只在特定界面消费键位」。切换键若需要「仅在开态时响应」，可直接复用同一机制，无需新字段。
  • Esc 仍是唯一固定关闭出口：所有浮层/抽屉已由 lifecycle.js 退栈链负责关闭。切换只是给用户多一个「用同一个键关」的便利，不替代、不冲突 Esc。
  • 不改键表结构：切换是 run 内部的分支，不新增注册表字段，守阵与自定义面板无需改动。
