01结论(先行)

根因 · 一句话

采样任务的真实节奏不是配置的 sample_interval, 而是被主循环节拍(main_tick=2s)向上量化的值: 3s 配置实际 4s 一轮(next_run = now + 3 只能在 2s tick 边界到期)。读侧栅格却按 ceil(sample_interval) 切桶(3s/1.5s 档 → 3s/2s 桶宽)—— 4s 的行距落进更窄的桶, 桶系统性走空, 前端 spanGaps:false(null 桶断线不连线, §5.2 拍板语义)如实把空桶画成断口, 折线碎段; 1.5s 档桶宽(2s)恰为行距(4s)的一半, 每个数据点两侧桶全空 → 全部判孤点, 只剩点标。

伴随缺陷 · 两条

热重载错位: 采样任务 interval 注册时定死(_register_task 只在启动/队列重建跑), 运行期改 sample_interval 只立刻影响读侧(L0 换对象), 写侧节奏不动 —— 用户改 1.5s 后「写 4s / 读 2s 桶」错位拉满, 全孤点状态稳定复现。前端轮询下界残留: 刷新间隔夹取下界 15s 是放宽前的旧配置校验下限(26-10-04 边界已放宽到 1.5s, 前端没跟), 3s 采样下图固定 15s 才刷新 —— 即「更新频率固定不对齐」。

量化吻合

三个症状全部被同一机制定量解释: 4s 行距 × 3s 桶 → 6~12s 折线段 + 3s 缺口(「约 10 秒两条折线不连接」); × 2s 桶 → 全孤点(「只剩端点」); 轮询夹取 15s(「固定 ~10 秒更新」)。落盘行距实测 {4s: 39, 5s: 1}/40 行, 截图点距像素实测恒 48px ≈ 4.1s, 与演算一致。v2 零值行程(z 行)纪律无罪(§06 排除)。

3.2 节奏量化的代码链路

Task(interval=conf.sample_interval=3)          # traffic_sample_mod.py:228 注册
  → 每轮收尾 next_run = now + task.interval     # taskqueue.py:226 (_requeue)
  → 到期判据: 堆顶 next_run <= now 才弹出       # taskqueue.py:206 (_pop_due)
  → now 只在主循环 tick 推进: sleep(main_tick)  # qbmanager run(); main_tick 缺省 2.0s (config/models.py:331)
⇒ 有效节奏 = ceil(max(interval, main_tick) / main_tick) × main_tick
   interval=3, tick=2 → ceil(3/2)×2 = 4s   (与落盘实测 4s 完全一致)
   interval=1.5 → interval < tick → 每 tick 到期 = 2s(重启后)
   interval=30 → ceil(30/2)×2 = 30s (缺省路径不受影响)

3.3 截图像素实测: 点距恒 48px ≈ 4.1s, 全孤点无连线

对截图(3839×665)按色相过滤做点簇检测: 下行(靛)点簇 30 个, 相邻点距中位 48px(16 次, 众数绝对主导); 尾部存在连续 14 点全部严格 48px 等距(x 3073→3722)。比例尺: 横轴 16:18:48→16:23:24 共 276s 对应 3247px ⇒ 11.76px/s ⇒ 48px = 4.08s/点。全部点均为孤立点标(无连线段); 检出的大间距(96/144/192px)为 4s 的整数倍, 系悬停浮层遮盖与低值点越出检测带, 非数据缺失。上图与 3.1 的落盘行距互相印证: 图上每个点 = 一条 4s 落盘行。

3.4 桶覆盖演算: 4s 行距 × 窄桶 → 系统性空桶

读侧桶宽 = max(1, ceil(sample_interval))(traffic_grid.py:91; build_grid 经 traffic_qb.py:65–70 消费), 行按 ts - ts % interval 归桶(traffic_grid.py:134), 空桶出 null, 前端 spanGaps:false 断线不连线(qb_traffic_chart.js:452), 两侧皆 null 的非空桶画点标(_qbIsolatedIdxs, qb_traffic_chart.js:123–130)。行距 4s、相位 r(行首对 3 取模)分三种走向:

档位占用桶序列(以相位 r=0 为例)图面形态
3s 桶(3s 设置)行 0,4,8,12,16,20,24 → 桶 0,1,2,[3 空],4,5,6,[7 空],8…3~6s 连线段 + 每空 1 桶断一次 ⇒ 6~12s 一段、段间 3s 缺口(=「10 秒两条折线, 前后不连接」)

4s 桶(修复后应有)行 0,4,8 → 桶 0,1,2 连续行距 == 桶宽 ⇒ 每桶恰一行, 折线连续

04根因(按因果序四条)

#根因机制锚点
A 写侧: 采样节奏被节拍量化(主因) TaskQueue 周期任务的到期判据只在主循环 tick 边界评估, next_run = now + interval 的真实兑现节奏 = ceil(max(interval, tick)/tick)×tick。3s 配置兑现为 4s —— 消费侧任何「按配置 interval 推算数据粒度」的假设都不成立。 taskqueue.py:206, 226
config/models.py:331
traffic_sample_mod.py:228
B 读侧: 栅格桶宽口径缺量化(直接成因) build_grid 桶宽 = ceil(sample_interval)(小数间隔向上取整修过「floor 伪断线」, 但没修 tick 量化这一层)。桶宽 < 实际行距 ⇒ 空桶系统性出现, spanGaps:false 如实断线。空桶语义本是「无采样=断线」, 此处被错位制造出伪断线。 traffic_grid.py:89–91
qb_traffic_chart.js:452–459
C 热重载: task.interval 注册时定死 _register_task 只在启动/queue_rebuilt 跑; 运行期改 sample_interval 后 handler 每轮现读配置的只有 enabled/dry_run 等开关, interval 不回写任务。读侧 L0 换对象即时生效 ⇒ 改 1.5s 后「写 4s / 读 2s 桶」错位最大, 全孤点持续。(重启进程反而自愈: 1.5s → 节奏 2s = 桶宽 2s。) traffic_sample_mod.py:215–232
D 前端: 轮询下界 15s 旧边界残留 刷新间隔 = clamp(meta.interval_s, 15s, 600s); 15s 是放宽前的配置校验下限(26-10-04 已放宽到 1.5s), 前端常量与注释没跟 ⇒ 3s/1.5s 采样下刷新恒 15s, 与采样频率解耦(用户感知「固定 ~10 秒」)。 qb_traffic_chart.js:43–48, 334–340

05症状 ↔ 根因对照

用户症状实测真值解释
「10 秒两条折线, 与前后 10 秒的折线未连接」段宽 6~12s + 3s 缺口A+B: 4s 行距 × 3s 桶 → 每 3~4 行空一桶, spanGaps:false 断开; 「两条」= 上行/下行两系列同桶同断
「更新频率固定 10 秒, 不对齐 3s 采样」15s(代码夹取下界)D: 前端轮询下界 = 旧配置校验下限 15s, 与 sample_interval 解耦

06排除项(查过, 无罪)

  • v2 零值行程(z 行)纪律: 截图中种 5 分钟窗内 z 行数 0(逐样本非零); 有 z 行的三个系列, 行程衔接处的桶覆盖演算为相邻(z1 末桶与 z2 首桶之间无空桶, 4s 行程间隙落在 z1 末桶宽度内)—— 空闲段 0 平线语义工作正常。
  • 断连/停机洞: global.dat 活跃期连续无 null 行; b88271a8 的 495s 大间隔属种子真实空闲(09:48 后无传输), 与本症状无关。
  • 前端渲染链: setData 原地快路 / 锚点重建(_qbPointsToData 等距 xs)核对无错 —— 图如实画出了后端给的 null 分布, 缺口在数据侧不在画图侧。
  • 次级观察(随修复自然消失, 不单独立项): 现状下相邻 z 行程的封口间隙(一个采样节奏)在「节奏 > 桶宽」档位会露出一桶宽的缝; 修复后节奏 == 桶宽, 封口边界恒邻接。
