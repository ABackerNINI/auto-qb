01 · 结论先行

「弹窗内无法用键盘」不是单一缺陷，而是缺了一整层「焦点管理」骨架；而骨架之下，行为层的键位处理其实已做了大半 —— 确认框/输入框有初始焦点与 Enter/Esc、添加窗三个下拉有 ↑↓/Enter/Esc、Esc 退栈链覆盖全部浮层。用户感知「完全没法用」，主要来自三个结构性缺口：

三个根因（覆盖 90% 的体感）

R1 · 打开时焦点不进窗：除通用确认框外，绝大多数弹窗（添加种子、目录浏览器、统计、管理、标签分类）打开后焦点仍留在触发处/文档头，Tab 要从页面顶部开始数几十个停靠点才摸到弹窗 —— 体感即「键盘进不去」。

R2 · 无焦点陷阱（focus trap）：Tab/Shift+Tab 会跑出弹窗遍历遮罩背后的整页（背景 DOM 无 inert），在窗内操作到一半焦点就「消失」了 —— 体感即「键盘留不住」。

R3 · 目录浏览器（选择位置面板）纯鼠标：目录行没有方向键光标、打开无初始焦点、无「进入/上一级」键位 —— 这是「无法通过键盘选择保存位置」的直接对应物。

业界成熟方案高度收敛，权威口径就是 WAI-ARIA APG Dialog (Modal) Pattern：打开即焦点入窗 → Tab 在窗内循环 → Esc 关闭 → 关闭后焦点归还触发者；工程实现上则有三条成熟路线（自研 trap / focus-trap 库 / 原生 <dialog>+inert）。结合本项目「Vue 3 全局构建 + 静态文件无构建链 + 三皮肤共用自绘遮罩体系」的约束，推荐自研一个轻量焦点管理单点（P0），复用仓内已有的 roving tabindex 成法键盘化目录浏览器（P1），再补 combobox 的 ARIA 语义与危险确认框的初始焦点口径（P2）；不建议现在迁移原生 <dialog> 或引入 headless 组件库（详见 §04/§05）。

02 · 现状取证

2.1 弹窗体系结构

WEBUI 是单 Vue 3 实例（vendor/vue.global.prod.js），弹窗不是组件而是 v-if 浮层模板 + mixin 方法：app.js 按域拆出 dialogs.js / add_torrent.js / delete_flow.js / ui_feedback.js 等片段注入同一实例，模板集中在 shared/tpl/（三皮肤共用），遮罩为自绘 .modal-mask（带「拖选文字不误关」的 maskDownSelf 守卫）。没有任何 portal/焦点管理设施 —— 这层从未建过。

两条全局键盘链已经存在且质量很高：Esc 逐层退栈链（lifecycle.js:89-128，顺序严格对齐视觉层叠，注释 WARN「新增浮层两处同步 escBusy」）与快捷键引擎（shortcuts.js，59 条注册表，浮层打开时经 _kbOverlayBusy（shortcuts.js:435-440）屏蔽列表键位、模态层内只放行模态键位）。

03 · 成熟方案调研

3.1 WAI-ARIA APG Dialog (Modal) Pattern —— 权威规范基线

APG Dialog (Modal) 是所有实现的对照原点，键位契约只有四条：

  • 打开即焦点入窗：默认落第一个可聚焦控件；内容复杂时在开头放 tabindex="-1" 静态元素先读后操作；含不可逆操作（如删除数据）时宜聚焦最不具破坏性的动作；以信息/继续为主的框可聚焦最常用按钮（OK）。
  • Tab / Shift+Tab 在窗内循环（首尾相接），「modal dialog 的窗序必须自包含」。
  • Esc 关闭。
  • 关闭后焦点归还触发者（触发者已不存在时给工作流上的合理落点）。

ARIA 侧两条强约束：role="dialog" + aria-modal="true" + 可见标题（labelledby/label）——本项目模板已挂前两条（如 popovers.html:116）；但 APG 注释明确警告：对 AT 标 modal 而对普通用户不做模态（背景可 Tab/可点）是禁止的反模式——这正是本项目现状（G2），修 inert 与修语义必须一起做。另外推荐 Tab 序里常驻一个可见关闭控件（关闭钮/取消钮），本项目每个弹窗都有，达标。

3.2 原生 <dialog> + showModal() —— 平台内建方案

HTML 标准元素，Baseline 已全线可用（Chrome 37+ / Firefox 98+ / Safari 15.4+，2022 年起）。showModal() 一次性给出：浏览器级焦点陷阱（Tab 出不了窗）、页面其余内容自动 inert（规范行为，无需手挂）、初始焦点规则（autofocus 属性优先，否则首个可聚焦控件）、Esc 触发 cancel → close 事件、::backdrop 遮罩伪元素。MDN 对 inert 属性的定位同样是「模态 UI 的标准构件」，2023-04 起 Baseline。

与本项目的冲突点（迁移成本为什么高）：

  • 自绘遮罩承担了行为：maskDownSelf/maskCloseIfArmed 的「拖选文字不误关」判据挂在 .modal-mask 的 mousedown/mouseup 上，<dialog> 的 backdrop 点击模型不同，需重建；
  • 三皮肤的 .modal-mask 过渡动画（pop/leave transition）与 ::backdrop 样式体系是两套写法，全部弹窗模板 + 三份 CSS 要动；
  • Esc 的 cancel 事件与现有「Esc 退栈链 + escBusy 名单两处同步」的既有约定要重新对齐（退栈链是本 UI 的成熟资产，不能被绕开）。

定位：方向正确、但属于「重写承载层」的方案，不是本项目当下性价比最高的路径。

3.3 focus-trap / tabbable —— 库方案的事实标准

focus-trap（依赖 tabbable）是 vanilla JS 焦点陷阱的通用事实标准（MIT、零框架依赖、UMD 构建可直接 <script> 引入，适配本项目「静态文件、无构建链」的形态）。行为面完整对应 APG：initialFocus（指定初始焦点，支持 selector/函数）、fallbackFocus（窗内无可聚焦元素时兜底）、Tab/Shift+Tab 循环、returnFocusOnDeactivate（归还触发者）、escapeDeactivates/clickOutsideDeactivates 开关、嵌套 trap（pause/unpause）。Vue 侧另有 vue-a11y-dialog 等薄封装，但本项目弹窗不是组件形态，直接用底层库或自研等价物更贴。

3.4 Vue headless 生态（reka-ui 等）—— 行为参照与「什么时候才值得引入」

reka-ui（原 radix-vue，v2.8.x）是 Vue 生态最完整的 headless 无障碍组件库：Dialog/Combobox/Popover 等 40+ 原语内建 WAI-ARIA、FocusScope 焦点陷阱与 DismissableLayer 关闭语义（其 Combobox 键位表与 APG 一致：方向键开层/移动、Enter 选中、Esc 收层回填）。同类还有 Headless UI（Vue 版组件较少）与 Ark UI。它们的价值对本项目主要是「可抄的实现参照」：FocusScope 的 Tab 循环写法、Combobox 的 activedescendant 管理。整体引入则意味着把 v-if 浮层模板体系换成组件树 —— 与「单实例 mixin + 三皮肤共用模板」的既有架构正面冲突，不建议。

3.5 APG Combobox Pattern —— 保存路径/分类/标签下拉的规范口径

APG Combobox（autocomplete list 形态）与本项目三下拉的现状逐项对表：

05 · 推荐路线（P0 → P2，实施需另立计划拍板）

P0 · 焦点管理单点（治 R1/R2 + G3，覆盖全部弹窗）

  • 新增 shared/focus_trap.js（或并入 lifecycle）：_openDialog(el, {initial, returnTo}) —— 记账触发者 → 焦点入窗（按弹窗配置落点）→ 窗上挂 keydown 捕获做 Tab/Shift+Tab 首尾循环 → 主内容容器挂 inert → 关闭时摘 inert 并归还焦点。
  • 所有弹窗 open/close 方法接线（openAddTorrent/openDirBrowse/openStats/openMgr/openMeta/openHistory/_openModal/…）。_openModal 已有初始焦点逻辑，并入单点即可，同时顺手落实 G6：danger 确认框初始焦点改落「取消」钮（APG 对不可逆操作的明确建议，一行改动）。
  • 初始焦点落点表：添加窗 → ad-save-path（最高频字段，聚焦即展开候选面板）；目录浏览器 → 面板标题或「上一级」；管理框 → 新建名输入框；统计/历史 → 关闭钮或标题（APG：内容复杂先读后操作）。
  • 边界：无遮罩浮层（限速 speed-pop）不适用 modal trap（页面其余部分本就可操作），只做初始焦点；嵌套层（添加窗 → 目录浏览器 → 下拉）按 trap 栈 pause/unpause 处理，focus-trap 原生支持，自研版需记一个栈。

P1 · 目录浏览器键盘化（治 R3/G4）

  • 复用仓内成法 drawer_templates.js:155-200 的 roving tabindex 套件：目录行 tabindex="-1" + 锚点 0，↑↓ 移焦、Enter 进入目录、Alt+↑（或 Backspace，对齐 OS 文件选择器习惯，实施时拍板）上一级、Enter 于「选择该文件夹」语义不变。
  • 打开时初始焦点落首行/锚点行；目录加载重建后按 rowFocusKey/rowRestore 成法回焦，避免键盘用户被甩回文档头。
  • 收尾链：Esc 归 escAddTorrent 既有退栈（已支持），无需新链。

P2 · 语义与一致性收尾（G5 + 边角）

  • 三下拉 + meta 分类下拉补 ARIA 桥：role="combobox"/aria-expanded/aria-controls、列表 role="listbox"/role="option"、高亮索引桥 aria-activedescendant（行为不动，纯语义补层）。
  • 全弹窗核对 aria-labelledby 指向可见标题（多数已有 aria-label，达标）；添加窗内补「Enter = 添加」主路径评估（当前仅按钮，可仿 modal 输入框 @keyup.enter，但需防止与候选 Enter 冲突 —— 仅在无浮层开着时生效）。
  • 按仓库既有 WARN（dialogs.js:527、lifecycle.js:87）：本专题不改浮层名单本身，但实施时须把新焦点模块与「两处同步」约定写进坑档。
