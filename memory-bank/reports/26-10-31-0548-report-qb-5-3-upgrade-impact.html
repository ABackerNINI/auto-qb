§01结论与影响统计

1.1 一句话结论

升级目标(qB 5.2.3 → 5.3.x HEAD 线,WebAPI 2.16.2,libtorrent 后端可选 2.1 线)对 auto-qb 的破坏面收敛到一处:WebUI「分享限制」命令调用的 torrents/setShareLimits 在 5.3 要求新必填参数 shareLimitsMode(缺失直接 HTTP 400)。其余全部变更要么不在本项目使用范围内,要么被既有架构(单一 Facade 出口、字段存在性探测、_raw 前向兼容)天然吸收。唯一必改动作:core/qbapi.py 的 torrents_set_share_limits 增加 share_limits_mode 形参(缺省 "Default"),5.2 忽略未知参数、向后兼容,可先合入再升级。

1.3 为什么只有 1 条硬破坏(结构性利好)

  1. 所有 qB 调用收敛在单一 Facade(src/auto_qb/core/qbapi.py)与钉死版本的 qbittorrent-api==2026.8.1(pyproject.toml:29 / uv.lock:70)——该库版本已内置 5.3 参数兼容(seedMode 双发、Bearer 认证);
  2. 无运行时版本号解析,版本差异全靠字段探测与响应形态双认(对 5.3 天然兼容);
  3. torrent 快照对新字段前向兼容(_raw 落袋,record.py:144-160,192-196),启动期字段契约只要求 5.3 仍保留的老字段;
  4. search / rss / torrentcreator / 导出目录等被破坏面全部不在使用范围内。

1.4 升级建议要点(详单见 §09;库支持度专项见 §08)

  1. 升级前修:facade 增加 share_limits_mode 形参,_cmd_set_share_limits 显式传 "Default",并补请求体级测试断言。该修复与库版本解耦(share_limits_mode 参数 2026.8.1 已有,钉死 2026.8.1 也能修,§8.4)。
  2. 库版本口径:下限 qbittorrent-api==2026.8.1 不许降——跳检(is_skip_checking)的 5.3 兼容完全依赖该库对 skip_checking 与 seedMode 的双发行为;推荐升级到 2026.10.1(纯增量,对本项目调用面 100% 兼容,§8.2)——但注意升库不解决 🔴(§8.3)。
  3. 升级后走查:跳检全流程、强制汇报回执口径、重复添加回执、流量采样速率读数、HR 达标时点(数值口径方向都是更准,但与旧基线数字不可直接对比)。

  1. 5.2.3 非 HEAD 祖先:范围语义是「HEAD 上不可从 5.2.3 到达的提交」,不是「5.2.3 发布后的增量」;个别条目已随 5.2.1~5.2.3 stable 先行发布。按 5.2.3→5.3.x 做升级判断时不受影响(两个端点状态都是已核验的)。

5.2.1 torrents/add:skip_checking → seedMode(6e493381a)

  • HEAD 代码:const bool seedMode = parseBool(params()[u"seedMode"_s]).value_or(false);(torrentscontroller.cpp addAction())。

5.2.2 torrents/setShareLimits:shareLimitsMode 必填(80b5edbec)

  • HEAD 代码:requireParams({hashes, ratioLimit, seedingTimeLimit, inactiveSeedingTimeLimit, shareLimitAction, shareLimitsMode});
  • 缺失 shareLimitsMode → BadParams → HTTP 400。旧调用方不带该参数直接失败(硬破坏,本项目唯一一条,见 §07)。
  • 非法值(非 Default/MatchAny/MatchAll)→ toEnum 静默回退 Default(与 torrents/add 一致;分类端点才抛错)。
  • 实现改为一次性 torrent->setShareLimits(ShareLimits{...}) 替代旧四个 setter;缺参报错消息含参数名。
  • 关联:全局偏好 share_limits_mode;setPreferences 里该键非法值静默回退 MatchAny(注意回退值不是 Default)。

5.2.3 POST-only:search/downloadTorrent、rss/setFeedRefreshInterval(27a1fab8d)

  • 机制:方法白名单 m_allowedMethod(webapplication.h:153,键为 {scope,action})。5.2.3 中这两个端点不在表内→默认允许 GET+POST;HEAD 在表内加 {POST}。

5.2.6 X-Forwarded-For 解析改写(68a5d7e34)

  • 旧(5.2.3):客户端 IP 在受信反代列表 → 取 XFF 列表中第一个全局 IP,找不到取列表第一个。
  • 新(Utils::Net::resolveForwardedClientAddress,src/base/utils/net.cpp:212):从 XFF 右往左走;第一个不属于受信代理网段的 hop 即客户端;hop 解析失败→链不可信,直接用 TCP 对端地址;全部受信→取最左 hop。
  • 影响:伪造的 XFF 不再被采信;反代部署下 resolve_peer_countries/封禁/认证子网白名单的判定对象可能变化。依赖「按 IP 白名单免认证」时,受信代理网段必须覆盖实际代理链,否则白名单失效。

5.2.7 会话数上限默认 15(09bd46d1f)

新偏好 web_ui_sessions_count_limit(int,默认 15,0=不限)。sessionStartImpl 新建会话时先清过期会话,然后若 size ≥ limit LRU 逐出最久未活动会话直到有空位。并发脚本各持独立 SID 超过 15 个时,最老会话被顶掉→其后续请求 403(会话失效)。API key 会话同样计入(每个 key 一个)。

5.2.8 API key 会话不再种 cookie(926d96111)

setSessionCookie 仅在 cookie 会话状态变更时发;API key 路径完全不进该分支。API key 会话是纯 header 认证、无 cookie 刷新;且会话 id = API key 本身——同一 key 的所有客户端共享一个会话状态(controller 实例、sync 增量缓冲共享)。API key 不能访问 auth/*(403)。

5.2.9 torrents/add / setShareLimits / setPreferences 的静默回退值不一致(P2 diff 新发现)

5.2.10 createCategory 的 downloadPathEnabled 校验收紧(784a6e188)

downloadPathEnabled 非空但非法(bool 解析失败)→ 400;5.2.3 是静默忽略——边缘破坏。editCategory 特有:传空串 → 清除 download path(置 nullopt)。
