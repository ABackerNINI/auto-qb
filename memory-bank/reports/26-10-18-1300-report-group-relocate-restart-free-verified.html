两条主推路线都真实跑通：别名接续(A) 的三种形态(Junction / 目录符号链接 / 文件符号链接)全部做到「暂停态换路径 → qB 零感知 → 重启后仍 100% 且不解析别名」；机会式收尾(C) 走通了「文件丢失 → 设定位置 → 1.4 秒零 hash 恢复到 100%」。唯一需要修正的是 C 的表述：恢复过程不是「无 Checking」，而是有约 1 秒的 checkingResumeData 瞬态(非全量 re-hash)。

§01结论

总判：A 与 C 均成立，可直接作为 auto-qb 的实现依据；三种别名形态对 qBittorrent / libtorrent 完全透明。证据是 2026-10-18 在真实实例上的 5 次重启、4 次跨盘搬迁、1 次 setLocation 的端到端实测，不是源码推演。唯一被推翻的是措辞而非机制：C 的恢复会闪一下 checkingResumeData(约 1 秒)，那一步是 resume data 的 stat + 大小比对，不是全量哈希。

对前序报告的三处修正 / 补充

  1. 「恢复后无 Checking 状态」不准确(0818 §01 验收标准)：200ms 采样在 t=0.33s 捕到 state=checkingResumeData，t=1.39s 直接 100%。该状态是 resume data 的 stat + 大小比对(verify_resume_data)，不是全量 re-hash——progress 没有中间爬升，0% 直接跳到 100%。正确表述应为「无全量 re-hash，仅有约 1 秒的 checkingResumeData 瞬态」。
  2. 文件级符号链接是 0818 未覆盖的一档：Junction 只能链目录，而文件 symlink 可把别名粒度下沉到单个文件。实测同样透明、同样扛重启，正好补上 0818 §01「别名的目录粒度」缺失的粒度——save_path 下混放多个组时，可以只给本组文件建链接，不动别组数据。
  3. 权限门槛是落地关键，且与实现语言相关：Junction 免管理员；symlink 需开发者模式或管理员。但 PowerShell 5.1 的 New-Item -ItemType SymbolicLink 即便开发者模式已开启仍报「此操作需要管理员权限」(它不带 ALLOW_UNPRIVILEGED_CREATE 标志)，换成 Python os.symlink 直接成功。对 auto-qb(Python) 是好消息：开发者模式下无需提权即可建 symlink。

落地口径

  • A 作为默认：不改 qBittorrent 侧任何种子状态，暂停态即可完成，失败可回滚(删别名 + 搬回)。
  • 别名形态选择：组共享同一数据目录 → Junction(零权限门槛，最省事)；需要指向网络路径或只覆盖组内文件 → symlink(需开发者模式)。
  • C 作为中期收尾：唯一硬成本是「必须一次重启」，换来的收益是元数据彻底干净、进度零 hash 恢复；窗口期即使不手动暂停也安全(见 §02.7)。

2.6 回滚与数据完整性

  • 4 次跨盘搬迁(R→H、H→R、R→H、H→R)后 SHA1 始终为 F3AA424D0FBF48F0CFECE0141061F068C7307558，字节级无损。
  • 回滚方式：优雅退出 → 数据搬回 R:\Download\Testing(真实目录) → 用备份覆盖 fastresume/torrent → 重启；最终 stoppedUP / progress=1 / save_path=R:\Download\Testing / added_on 未变，与基线一致。
  • H: 侧无残留(Testing-relocated 与父目录 H:\Download 均已清理)；种子全程未启动。

2.7 附：运行中把目录整个移走、且不建别名

同样 qB 保持运行、种子暂停时，把 R:\Download\Testing 整体搬到 H: 且不建任何别名，qB 依然零日志、progress=1、state=stoppedUP。说明「路径消失」只有重启或 reload 才会被发现——这直接支撑 C 的窗口期安全性：移动过程中不需要停 qB，也不会触发错误状态。

§03方法与局限

3.1 操作序列

  1. 备份 BT_backup 的 fastresume + torrent，记录基线(API/fastresume/SHA1/日志偏移)。
  2. 轮 1 Junction：运行中移动 → 建 Junction → 断言 → 重启 → 断言 → 运行中回滚。
  3. 轮 2 目录 symlink：运行中移动 → 建 symlink → 断言 → 重启 → 断言 → 回滚。
  4. 轮 3 文件 symlink：只移数据文件 → 建文件 symlink → 断言 → 重启 → 断言。
  5. 轮 4 C：删别名 → 重启(进文件丢失) → setLocation → 200ms 采样。
  6. 回滚原状 + 全量 SHA1 复核。共 5 次重启、4 次跨盘搬迁、1 次 setLocation。

3.2 采样与取证

  • 每次状态变更都留 {API 快照, fastresume 指纹, 日志增量} 三元组，共 9 份 JSON 快照 + 备份目录。
  • 「无感知」的判据是日志零新增行，不是「没看到报错」——qB 的文件日志记录了所有 restore/move/check 事件，零新增即等于没触发任何路径。
  • C3 用 200ms 轮询 + 状态迁移去重，因此能捕到 1 秒级的 checkingResumeData；重启路径只观测了稳定态(启动后 8 秒)，未做启动期高频采样。

3.3 未覆盖的边界

  • 单种子组：本实例只有 1 个种子，组内第 2..N 个成员「目标已有文件 → need_full_check」的场景没测到，只测了单成员的等价路径。
  • 统计保留无法证明：该种子 uploaded/downloaded/ratio 均为 0，只能证明「未被重加」(added_on 不变、日志无 delete/add 事件)，不能证明分享率/统计值被保留。
  • 恢复后继续做种未验证：按约束全程暂停、操作完未启动，A/C 的「恢复后自动重连做种」未实测。
  • 网络路径未测：Junction 不能指向 UNC，symlink 可以；本轮目标盘是本地 NTFS 固定盘，SMB/NFS 场景未覆盖。
  • 源码行号口径：引用行号来自 D:\Projects\Else 的 qBittorrent master 与 libtorrent 2.1.2，实际运行的是 qB 5.2.3 + libtorrent 2.0.13；机制一致但行号可能有偏移。

3.4 环境坑(复现时避开)

  • 重启 qB 不能用 Start-Process：工具 shell 退出时会回收子进程，第一次重启后 qB 被静默杀掉(日志无终止记录)。改用 explorer.exe "<exe>" 分离启动才稳定存活。
  • qB WebAPI 的 POST 参数必须放 form body：setLocation 把 hashes/location 拼在 query string 会返回 400(requireParams 只读 body 参数)。
  • symlink 权限与实现语言相关：开发者模式开启后，PowerShell 5.1 的 New-Item -ItemType SymbolicLink 仍失败，Python os.symlink 成功；Junction 两种语言都免权限。
  • 删链接勿用递归删除：Remove-Item -Recurse 有跟随 reparse 点删目标的风险；本轮统一用 [IO.Directory]::Delete(path,$false) / os.rmdir / os.unlink，删后立即验证目标数据仍在。
