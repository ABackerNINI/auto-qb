评审容量实验: 批次大小对发现数与幻觉率的影响

为回答「agent 一次能评审多少行」而做的对照实验: 同一份 diff 按 4 批 / 2 批 / 1 批三种粒度各评审一遍, 共 10 次派发、56 条发现。结论: 发现数约等于派发次数乘以固定值, 与批次大小无关; 幻觉率不随批次变大而上升; 大块的真正代价是换了地方找——对已知缺陷的召回从 7/8 掉到 0/8。

实验件 test-results/review-exp/(gitignored, 未入版本库): 10 份 diff + 10 份 findings JSON + 2 份只读快照

§01结论

① 发现数 ≈ 派发次数 × 5.6, 与批次大小无关。 两轮独立数据都落在同一区间: 26/4=6.5、8/2=4.0、5/1=5.0、12/2=6.0、5/1=5.0, 合计 56 条 / 10 次 = 5.6 条每次。评审者的产出不是被"读得动多少"决定, 而是被"派发了几次"决定——每次派发是一次独立的注意力分配。

② 幻觉率不随批次变大而上升(负面结论, 推翻了事前假设)。 56 条发现全部通过 review.check 逐字引文校验, 0 条被弃, 包括 1313 行的单块评审。事前假设是"块越大越会编引文", 数据不支持。因此容量不是安全约束, 只是经济约束。

③ 大块不是"少找几条", 而是"换了地方找"。 在有真值的 D2 上: 2 批召回已知修正点的 7/8; 1 批召回 0/8——它报出的 5 条全是另一批问题。这条最锋利, 也解释了为什么"收口一次评"看起来一直在干活、却总漏掉该漏的。

三条结论合起来, 把"400 行"的性质改了: 它不再是容量上限(agent 读得动 1300 行, 且不编造), 而是产出密度的经济学选择——切得细, 派发次数多, 发现就多, 且近似线性(4 倍派发 ≈ 5 倍发现), 未观察到收益递减拐点。

§02方法与实验设计

控制变量: 同一份 diff 的总改动量恒定, 只改切分粒度; 评审提示逐字相同(同一套 14 条清单、同一份不报清单、同一份输出 schema、同一份只读契约); 评审者同为 Explore 子代理; 每批独立派发, 批内不共享上下文。

变量: 每批的平均改动行数(328 / 657 / 1313 / 388 / 775)。

指标: ①发现数(以及 blocker/major 占比); ②review.check 引文通过率(幻觉率, 机械可测); ③对有真值 diff 的绝对召回。

两个数据集:

  • D1 = 2a58021f(release 管线: 5 个脚本 + 测试 + SKILL.md + 配置), 14 文件 / +1308 −5 = 1313 行。分 4 批(~328)、2 批(~657)、1 批(1313)三档。
  • D2 = 771b8d8e(提交消息机检), 15 文件 / +762 −13 = 775 行。分 2 批(~388)、1 批(775)两档。选它是因为它有已知真值: 原始收口评审用 3 个分面代理评过同一份 diff, 修复提交 60f030e5 逐项记录了 8 处修正点。

评审者看到的材料: 该提交的只读快照(git archive 导出到仓库外) + 本批的 diff 文件。允许读快照内任意文件判断调用面, 但发现只收 diff 范围内。快照根加了一个空的 .git 目录, 只为通过 review.check --root 的仓库校验, 未执行任何 git 写操作。

§04真值锚: 已知缺陷的召回

D2 的修复提交 60f030e5 逐项记录了原始 17 条发现的处置, 可归并为 8 处修正点: c2 降警告 / B3 收敛到已知 gitmoji / SLOT 行首锚定 + hash 移出强表 / 读写两侧补瞬时锁重试 / d6 scissors 判据 / a3 单字签名 / emoji 排除区 / b4 截断。

⚠ 该档 n=1(每档只跑一次), 0/8 有可能部分来自单次运行方差; 但方向与 D1 的 26→8→5 一致, 故按"方向可靠、幅度待复测"采信。

§05对评审模型的修正

原设计的问题不是数字错, 是理由错。 code-review skill 的 TIER_LIMIT = 400 注明来源是「SmartBear/Cisco 检出率衰减点」——那是人类注意力的实证(200–400 行 / 60–90 分钟 / 70–90% 检出), 其约束是生理性的。agent 没有这个约束: 1300 行照读, 引文零幻觉。把人类数字当默认值, 是方法论错误。

修正后的三条口径:

  • 批次上限 400 行保留, 但改称"建议上限"——理由从"容量红线"改为"产出密度与切分合理性的折中": 切得更细发现更多, 但每次派发有成本, 且切到低于"一个自包含变更"时, 跨块问题(接口漂移、重复机制)开始被切断。
  • 触发条件与批次大小脱钩: 要不要评, 由"累计未评改动量"决定(下限 50 行, 或触碰安全敏感面/红线); 一次能评多少, 由批次切分决定。
  • 大块不再靠"分面"救: 分面只是换问法, 每个子代理仍要读整块; 超限应拆批(按可独立编译/测试的文件组), 分面只保留给"批内触安全敏感面"的情形。

§06局限

  • n=1 × 单次运行: 每个档位只跑一次, 无法把"批次大小效应"与"单次运行方差"分开。D1 的三档呈单调关系、D2 两档同向, 故认为方向可靠; 精确幅度需重复实验。
  • 单一模型 / 单一代理类型(Explore), 换模型后 5.6 条/次这个常数会变, 但"产出∝派发次数"的结构性结论不依赖具体常数。
  • 发现数不等于真缺陷数: 本次只机械校验引文(防幻觉), 未对每条 claim 做正确性裁决; D2 有真值锚, D1 没有。
  • 未测下限 50 行: 实验只覆盖 328–1313 行, 小于 50 行的批次未验证——"低于 50 行不值得单独派发"仍是推断, 不是实测。
  • 未测跨块问题: 实验没有构造"只有看全才能发现"的缺陷(接口漂移/重复机制), 因此"切太细会丢跨块问题"这一条来自推理, 不是数据。
