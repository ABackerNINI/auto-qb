## 03 S1 探针结论与拍板落地(D1-D5 实测记账)

1. **S1 探针①(L2 互传, D4)成立**: 56589 做种 → 56590 下载, 2MB 经本机伪 tracker 互传 **13.0s 完成**, tracker announce 计数 3(双端同 infohash), leech progress 1.00。环境2 的 L2 互传面(§2.5.2 已修 current_network_interface 之后)首次实证成立 → RM08-06 照跑主路径, 未触发 BLOCKED 预登记。
2. **S1 探针②(RM08-07 鉴权形态, D2)成立**: skip_local_verify=false + 显式 web.token 的产品实例上 —— Bearer 好票: /api/state 200、/api/events/ticket 200、好票连流 200; 坏票连流 **401**、无票 **401**、错 Bearer **401**、无凭证 **401**(全部 `{"detail":"invalid token"}` 族, 流不建立)。负向断言锚点在改造前定死, 排除「断言写错方向」的假红面。
3. **D2 升档实现口径**: product_case 加 `auth` 形参(scoped, 只影响 RM08-07 实例; 其余 7 条零改动)—— auth 非空 ⇒ 配置写 skip_local_verify: false + token: "<测试自造令牌>", Bearer 经 `_AUTH_TOKENS` 按 web 端口派发、web_req/web_err 自动携带、收尾即撤。**负向腿必须显式 `token=""` 压掉自动 Bearer**: auth.py 的闸序是「票据消费失败 → 落回 Bearer 校验」, 带正确 Bearer 时坏票/无票也会放行 —— 负向测的是「无有效凭证」路径, 与探针②口径一致。
4. **D1 替身腿落地**: guard.snapshot(qb95, skip_tags=(TAG,)) 计数主实例真实种子 = 0 → 替身分支。mask 断言机制与原腿等价成立(private:1 假种子的 tracker 条目同样被 mask_tracker_entry 脱敏, 原文/passkey 形参值零外发断言真跑过); **降级记账: 「真实 PT 域名」词面缺失**(替身用 127.0.0.1 死端口 + 假 passkey), 解锁 = 用户在主实例添加真实种子后按原腿复测(用例已留原腿分支, 计数 >0 自动走原腿)。
