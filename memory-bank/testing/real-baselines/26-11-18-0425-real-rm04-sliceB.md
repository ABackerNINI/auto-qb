## 03 修法清单(全部测试侧, 产品代码零改动)

### 3.1 RM04-22 首跑前 4 处造法缺陷
1. **junction readlink 设备前缀**: 产品建链带 Windows 长路径前缀(alias_fs
   add_long_path_prefix_for_win), os.readlink 原样回吐 `\\?\D:\...` → `startswith(M.norm(dst))`
   恒 False 假红。修: `_readlink_norm` 归一时剥 `//?/`(UNC 形 `//?/UNC/` 还原 `//`)。
2. **handover 日志锚写严**: `_repoint_inherited` 的「别名统一改指」行含前任 job_id + 终位置
   路径, **不含新任务 job_id**(收官行才有双 id) → 断言改「前任 id + 终位置 C 路径」双条件。
3. **穿透读路径拼重**: junction 位已是内容根, 再拼含组名的 REL 变双组名。修: 增
   REL_UNDER(内容根下相对路径)用于 junction 穿透读; save_path 侧仍拼全 REL。
4. **无删除路由探测口径**: 首跑实测 POST 未知 /api 路径回 **405**(factory 的静态挂载 "/" 是
   兜底路由, POST 不在其方法集), 非 404。修: 断言改 `in (404, 405)`(两态都是「无该 API
   handler」的面; 2xx/4xx 业务态才算存在删除入口)。

### 3.2 RM04-23 首跑前 2 处造法缺陷(含一条跨用例纪律)
1. **骨架停法**: plain `app.start` + `p.stop()` 在 Windows = 外部 terminate(非优雅: 退出码恒
   1、finally 不跑、state 不优雅落盘)。**孤儿机制已证伪**(评审 R16 现场探针: 当前 uv trampoline
   下 stub 死连带真解释器终止, job-object 连带; 且本片 RM04-22 遍 1 plain stop → 遍 2 同 case
   全新 boot 成功为旁证) —— 锁撞秒退危害归因**未停净的存活进程(中断轮次)**, 非 stop 孤儿。
   修: 骨架改 `graceful_after=6.0` 自发 SIGTERM(RM04-06 预热先例);
   三腿主启改 **W.start_bypass_app**(sentinel 进程内 SIGTERM, RM04-21 同款)—— 纪律保留, 理由改为
   优雅 rc=0 可断言 + state 优雅落盘。历史危害记录(孤儿机制误信期): 撞 state.lock 秒退 rc=1 零日志
   + wait_web 读到陈旧日志假阳性 —— 「迁移没跑」的假红即由此而来(实发归因见上: 未停净的存活进程,
   非 stop 孤儿)。
2. **wait_web 撞同 case 追加日志旧行**: 同 case 目录先跑过骨架进程, 其「WEB UI 已启动」行留在
   追加式日志里, 主启的 wait_web **毫秒级假阳性**(RM04-06「日志是追加式, wait_log 会撞旧行立刻
   返回」陷阱的同族新形态 —— 那里是恢复行计数, 这里是 WEB 就绪判断)。修: 主启等待面改「只有本
   主启会打的新日志锚」—— good 腿等 v7→v8 收编 WARNING、bad 腿等「旧账迁移完成」、restart 腿等
   「启动对账」(三锚骨架进程结构性地不会打); 另补两处落盘竞态窗轮询(WARNING 落日志先于
   materialize 写盘 → 轮询盘上 v8 章; 旧账迁移行先于接管面写穿 → 轮询 model_version)。

### 3.3 v7 旧版章迁移夹具与守卫的相容(设计内, 非缺陷修复)
RM04-23 要写 schema_version: 7 的迁移被测输入, 而 `tests/test_real_schema_version_guard.py`
扫 tests-real 全部 YAML/dict 字面量并要求等于现行 v8。修: 模板里版本章占位符动态注入
(`schema_version: {schema_version}`, V7=7 常量经 format 注入)—— 字面量扫描不命中, 守卫只拦真
漂移不误伤迁移夹具; 用例 docstring 已写明构造纪律。**守卫测试零改动**。
