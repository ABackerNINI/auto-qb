## 03 造法校准与新增环境事实(已回写规程 §2.10)

开工前置两探针(2026-11-01, 对 56590 直测)实测推翻计划草案两条造法前提, 用例侧按实况校准(校准注记已落 test_rm03_drift.py 模块头注):

1. **`/torrents/add` 的 skip_checking 实测语义**(qB 5.2.3): +有数据 → 视为已完成(stoppedUP progress=1, 不校验); +无数据 → missingFiles —— 两形态都造不出「暂停中未完成」, 计划草案「add skip_checking 造暂停未完成」不成立。**正确造法 = paused + 数据在场 + 不带 skip_checking → stoppedDL progress=0**(qB 5.2.3 暂停加种只查 resume data 不做全量校验)。
2. **full-checking 证据窗校准**: 证据闩(store 快照 1S 同步 + 2S 轮询)要求校验窗口 ≥3s。实测 2GB 数据 recheck 的 checkingDL 窗口 ~3s(0.43s→3.46s); 512MB 窗口毫秒级不可捕(missingFiles 造法路径连状态迁移都不出现)。RM03-15/16 目标种子数据量取 2GB(写盘 ~5s); RM03-17 走跳检无证据窗维持 KB 级。
3. **stalledDL 活跃下载族造法**: 不暂停 + 无数据 + 不带 skip_checking(is_downloading=True 且 amount_left>0; skip_checking+无数据落 missingFiles 不算下载族)—— D5 腿据此真跑成, 未降级。
4. **跳检重加后种子被视为已完成**(重加 is_skip_checking+is_stopped+数据在场 → progress=1): 成功跳检后的种子被决策链 0 拦住, 同日去重闸不可达 —— RM03-17 去重红验前置 = 首跳完成后删掉重加回「暂停中未完成」态(同 hash, paused+数据在场), 第二次触发穿透链 0 到闸门。
5. **环境2 鉴权事实**(见 §04-1): 56590 要求鉴权; Bearer/API-Key 通路不受 IP 封禁影响, 登录(login 端点)通路受 —— 产品空凭据触发封禁后 token 侧仍可用。
6. `real.list` 显示面小瑕疵: RM03-15 函数体 `warnings.warn` 文案里的 `[RM03-15][BLOCKED-腿]` 被用例 id 抽取器误认为第二条用例(多显示一行), 纯显示面, 不影响 real.suite(按文件跑)。

1. **官方首轮 17 条全败 —— 环境2 副实例鉴权封禁连环(环境事件, 作废不计账)**: 产品进程配置空凭据(username/password 为空)连 56590, 实况 `bypass_local_auth=False` 要求鉴权 → 连续 401 触发 qB WebUI 封禁(5 次失败/3600s), 此后一切登录通路(含用例客户端外的后续产品进程)全数「身份认证失败次数过多, 您的 IP 地址已被封禁」。处置: ①经 token 通路置 `bypass_local_auth=True`(仅 localhost 免鉴权, token 与 LAN 鉴权不受影响); ②`real.down/--port 56590` + `real.up` 重启清封禁(pid 3532→11644, 连接状态回 firewalled); ③第三轮官方账后**还原 bypass_local_auth=False**(原值), 空凭据登录复测回到 401。遗留决策交用户: 环境2 副实例鉴权常开与真机轨「产品进程空凭据连副实例」的基建约定冲突(全部 11 片的 CONFIG_TEMPLATE 均空凭据), 建议后续把「副实例 localhost 免鉴权」定为环境2 的标准配置(56590 只绑测试用途, LAN 侧鉴权不受影响), 本轮不擅自改永久配置。
