## 04 本轮踩到并已解决的坑(全部写进规程 §02.5)

1. **60537 与生产实例撞车**(最贵的一个): 36596 抢不到 listen socket ⇒ `connection_status=disconnected` ⇒
   libtorrent 一个 announce 都不发。表现极具误导性: 种子状态正常(`stalledUP`)、tracker `status=1`(未联系)、
   日志无任何错误(announce 失败只在 Debug 级)。**换成 60539 后立刻恢复**; 已固化成 RM00-03 + `real.guard` 的在线核验。
2. **伪 tracker 把请求者自己也回给请求者**: 两实例同 IP 只差端口, 种子去连自己 ⇒
   `enable_multi_connections_from_same_ip=false` 下同一 IP 只留一条连接, 真 leech 被挤掉。
   表现是 `connections_count` 1→0、`uploaded/downloaded` 恒 0 —— 极易误判成加密或防火墙。
3. **实例自带 `dl_limit=1024`(1 KiB/s)**: 2MB 互传要半小时。L2 用 `transfer_limits` fixture 临时钉 256 KiB/s 并还原。
4. **`/torrents/trackers` 里的 `** [DHT] **` / `** [PeX] **` / `** [LSD] **` 不是地址**: 直接丢进 `is_local_url` 会误报"非本机地址", 断言前按 `http` 前缀过滤。
5. **`uploaded` 计数比 `progress` 慢一拍**(实测差 ~20KB): 临界断言会假红, 改成轮询等它追平。
6. **`/torrents/peers` 在 5.2.3 上是 404**: 拿 peer 明细只能走 `/sync/...` 之外的路子(本轮改用连接表 + tracker 视图, 够用)。
