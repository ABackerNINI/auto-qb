### 03b.1 二分: 账面 rewritten 相位在 happy path 不可观测(非产品回归)

- 产品机制(代码链): 镜像合并(journal rewritten → job 相位 rewritten)**只在主循环**
  `_step_reconcile`(D13 协议, relocate_exec.py:947-948/965-968)做, 经 on_task_line→
  _advance 触发(relocate_lifecycle.py:527-553); **没有任何 daemon 侧写账面相位的路径**。
- 主循环断连稳态(qbmanager.py:623-644): qB 离线(client None + _last_conn_ok False)后
  **不执行任何请求线**, 只做重连判定 —— 任务线(含合并)整个下线窗不跑; 单线程主循环还
  被 sync 失败的 urllib3 重试阻塞(~29s/次)。
- 实证(重跑 attempt1, Z2 log 012602): 01:25:41 连接失败转换落账后到产品停机 01:25:55
  **零 relocate 日志**; S5 等待全程(01:25:40→01:25:55)账面观测恒 None; 而同窗 journal
  (daemon 账)01:25:32 已 rewritten —— 账面恒 armed。
- 重启后: 对账表 all_at_dst && qb_up → ACT_VERIFY(relocate_units.py:1704)与合并在
  **同一拍**执行(_step_reconcile 顶部合并 → 表判 VERIFY → _step_verify 删别名+done),
  账面 rewritten 是毫秒级瞬态, 0.4s 轮询不可观测(armed→rewritten→done 一拍内完成)。
- 判定: 产品行为符合设计(D13 + 断连稳态), **非产品回归**; R26 对「虚标」的指控成立

  (同拍收敛)都不可达 —— 修法落点错在取数面。

## 06 坑点候选(供 pitfalls 回写)

1. **journal 在 armed 相位恒无文件, 「job 仍 armed」类断言的取数面单点 = 成员详情端点 relocate
   相位**(RM04-28 首跑断轮实锤): journal 是 daemon/下线窗侧账(改写/重建/收尾才写), armed 稳态
   下 `journal_of` 恒 None —— 按它断「相位未变」结构性扑空。state.json 30S 落盘周期又追不上
   实时相位; 取 `GET /api/torrents/{hash}` 的 `relocate.phase`(产品快照内存值)是唯一实时面
   (E9 mover_of 同源)。片F RM04-30(E5 收缩)的 armed 期断言直接适用。
2. **断轮重跑复用同一 run log 文件名会覆写断轮证据**(RM04-28 首跑实锤): 逐案 evidence JSON 带
   时刻戳天然防覆写, 但 run log 我按「遍次」命名(`run_rm04_28_pass1.log`), 断轮与修后 pass1
   同名 —— 断轮 pytest 栈被覆写。**run log 命名也要带「尝试序」**(断轮=attempt1, 修后=pass1)
   或断轮时先 mv 留证; 逐案 evidence 齐备时损失可控, 但栈文字要靠切片手抄。
3. (继承确认, 非新坑)窗口期纪律(片D §06 坑点1)在 RM04-29 的落法: 无下线窗用例的 armed 态
   全程存续, 探针任意时点安全; 有下线窗用例(RM04-28)的两类预检探针分别钉在 armed(S3)与
   rewritten(S5)两态 —— 重启后只等收敛不再布探针, 与片D 三跑实锤一致。

   D13 镜像合并只在主循环 `_step_reconcile`, 而 qB 离线 = 主循环断连稳态(qbmanager.py:623-644)
