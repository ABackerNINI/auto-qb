## 03 本轮实测确认的代码事实(回写素材)

1. **「写序号单调」外部不可观测**(RM09-01 实测): `write_seq` 只进读缓存键(web/server/context.py RoCache),
   不出现在任何端点载荷里 —— 计划 §03 的「断言写序号单调(回执序号)」如实降为可观测面: 回执 `ts` 单调 +
   `wait_ms/exec_ms` 埋点齐全(命令线消费时序的可见代理)。
2. **GET /api/config 的树根 = 整份 YAML 文档**(RM09-07 实测): 段在 `tree["config"]` 之下, 不是顶层段字典
   (RM05-02 的 `tree["config"]["trackers"]` 配方同源); PUT 回执 `changes` 收顶层段名(`interval`),
   非 R 级键无 restart_required —— 与 RM02-04 口径一致。
3. **`/api/torrents/add` 的 save_path 必须逐条给**(RM09-02 实测): 一条 add 命令只有一个 save_path
   (多文件一次入列共享落点); 独立落点要拆多条 add 命令。
4. **rename-fs 的 old_path 相对 save_path 且含内容根**(RM09-05 实测): 多文件种子传
   `rm09epack/a.bin`(非 `a.bin`), `/torrents/files` 回读与磁盘文件名双双验证。
5. **qB 多文件种子的 content root**(RM09-05 实测): location 移动后 `save_path/<名称>/` 布局原样保持,
   qB 跨目录真搬文件且旧目录清空 —— 单成员组恒 FORM_DIRECT(§2.9)。
6. **确认跟踪的首拍即判**(RM09-04 实测): `check_pending` 在指令 drain 后同一节拍立即首判(+1ms),
   tracker 行 updating 瞬态 + 基线 min 缺失 → 直接 confirmed 终态 —— 见入池缺陷。
7. **组命令对空组静默**(RM09-06 实测): `_group_hashes` 空 → 不下发、无日志、drain 恒 ok —— 见入池缺陷。
