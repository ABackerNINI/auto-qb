## 03 造法校准与口径修正(计划冻结后实测推翻的预写造法, 用例侧当轮落地)

1. **RM02-05 负向对照「创建全局任务 0 行」造法不成立(实测推翻, 等价口径落地)**: 最小配置下启动期恒有 1 行「创建全局任务 1 个: ['internal:traffic_snapshot_refresh']」—— 流量快照任务注册**无配置门槛**(traffic_snapshot_mod 模块注释明示"没配曲线也能看历史图", 结构性设计), 任何配置都造不出字面 0 行(必然假红)。对照腿按等价口径落地: 无认领段(delete_tags/global_speed_limit_curve 均缺省)配置下, 除该无门槛快照任务外 0 行 0 异种任务、单行 N 恒 1 —— 红验意图(重建无中生有即红)完整保留, 口径注记落 test docstring。
2. **RM02-07 probe 计量口径校准(首轮官方 FAIL 的根因, 测试侧假红)**: proxy probe 计的是 **TCP 连接 accept 数**, 一次 connect() 周期在 cut 代理下实测开 ~10-22 条连接(qbittorrent-api `_request_manager` 每请求至少重试 1 次(HTTP→HTTPS 切换兜底, 轮间 session 重建+0.6s sleep, 实测隔 ~1.7s)+ session 级 urllib3 Retry)—— probe 数 ≠ 重连尝试数。用例已改为按 >2.5s 间隙聚簇成「尝试」再断言(尝试数 ≤8 / 簇跨度 ≤5s / 簇间距 ≤32s)。上轮(环境1)此断言从未真跑到(修复前产品在 ERROR 刷屏断言先红), 首轮是它第一次对修复后产品真跑, 假红即暴露。
