## 04 本轮踩到并已解决的问题 + 观察项

1. **venv 基解释器又漂回无 Tk 的 H:\ 裁剪版(已记的坑复发)**: RM02-06 托盘小节首轮 `No module named 'tkinter'`。查 `.venv/pyvenv.cfg` → `home = H:\Programs\AutoClaw\resources\python`(3.13.12), RM01 §04-5 / real-machine §2.7 记载的同款回归 —— 中途某次 venv 重建被 uv 用回了宿主解释器。已按 RM01 口径重建(`uv venv --clear --python 3.13.15` + `env.sync`), 重建后 RM02-06 全绿。**为什么没命中**: 守卫(guard)与片内基座都不查解释器, 该坑只在用例真用 GUI 栈时暴露; §2.7 有文字但无开工检查项。
2. **qB WebUI 校验 Host 头(新环境事实)**: 代理转发若保留原 Host(`127.0.0.1:<代理端口>`), qB 对 `/auth/login` 直接 401(直连同 body 204) —— 已在 `lib/proxy.py` 统一改写 Host 为实例 host:port。
3. **本机 loopback 连接失败单次 ~2s(新环境事实)**: 连无监听端口的 connect 不是瞬时 RST; 托管模式首个 connect() 周期(detect_scheme http/https + login 三连)约 20-40s 才落第一条 ERROR —— RM02-06/07 的等待窗按此放宽, "慢不是挂死"。
4. **`.bak` 只在写盘前已有旧文件时生成(代码事实)**: `atomic_write(keep_backup)` 语义, fresh 目录首次优雅退出只有 state.json 没有 .bak —— RM02-02 的 .bak 断言移到 RM02-08(两次起停后)。
5. **FAIL(RM02-07)根因已查、入池不修**: 见 issue 26-10-31-1029 —— 断连处置置 `client=None` 后同步线 AttributeError 被 `_SYNC_UNAVAILABLE` 误分类(还打出误导性「qB 不支持 sync/maindata」WARNING), 落进通用 except 每 main_tick 一条「主循环异常」ERROR(75s 内 39-45 条); 且该路径不再调 `connect()`, **恢复代理后 60s 不回连, 进程永久停在断连态**(独立复跑: 断 30s + 恢复等 60s, 「已重新连接 qBittorrent」未出现, ERROR 持续累计)。
6. **计划外缺陷(非用例 FAIL)入池**: 托盘模式(--tray)进程内 SIGTERM 不生效 —— graceful 跑壳对 CLI 模式 rc=0 有效, 对 --tray 3/3 无效(45s+ 仍存活), 与 cli.py「所有模式一致」注释相悖 → issue 26-10-31-1030。RM02-06 托管小节因此不验优雅退出, 收尾 taskkill。
7. **观察项(未入池)**: RM02-01/04 代理观测的节拍序列稳定(1.5s/2.5s 中位数), 无抖动异常; RM02-05 全程仅 2s(warm 进程启动快), 属正常非异常。
