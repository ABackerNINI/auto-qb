### 03.1 RM04-32 try1(04:53, 126.0s)

S1 断于 `wait_complete 超时(120s): 种子未完成校验: [组 A 两枚 + 组 B 两枚]`(全部 progress 0)。
产品日志锚: `辅种组(2个) | 多个种子同时下载, 暂停整组: 'nsfb' (7af7d3c9), 'nsfb' (dafd391c)`
—— 产品把组 B 双成员按「活跃下载中」判据(grouping_mod._is_active_download: downloading 且
非停/非校验且 amount_left>0)整组暂停, 永不完成 → 超时。
根因(测试侧造法): 组 B 平铺数据写盘用 `write_file(..., "random", SALT_B)`(**整体盐**), 而
`_build_nsf_raw` 的 pieces 按 M.fake_multi 同款**逐文件盐** `f"{salt}:{rel}"` 计算 → 盘上字节
与 pieces 失配 → qB 校验不过视为缺数据(stalledDL + .!qB 孪生, diag 脚本实锤: save_path/
content_path 均 SRC_B 但 amount_left 满额)→ 双成员同处活跃下载态 → 产品整组暂停(该暂停是
产品正确行为, 组内多种子同时下载防护, 非缺陷)。
修法(当轮修): 写盘盐改逐文件口径 `f"{SALT_B}:{NSF_A}"`/`f"{SALT_B}:{NSF_B}"`(与 pieces 计算
逐字一致, 修点已带首跑实锤注释), 修后 pass1/pass2 全绿(04:57 / 04:59)。
判非产品回归的依据: 组 A(单文件 E2 造法, 盐经 build_from_path 读实盘)全程不受扰; 同款
「同时下载暂停」防护语义有单测+既有用例钉扎。

1. **「假种子手工造数据的盐必须与 pieces 计算同口径」**: M.fake_multi 族的逐文件盐
   `f"{salt}:{rel}"` 是 pieces 与盘上字节的一致性契约 —— 手工平铺实写(NoSubfolder 剥根形态/
   多文件种子)若用整体盐写盘, pieces 失配 → qB 视为缺数据 stalledDL → 产品「多个种子同时
   下载, 暂停整组」把组停死, 表象是 wait_complete 超时假红(RM04-32 try1 实锤)。判别锚:
   产品日志「同时下载, 暂停整组」+ qB 侧 amount_left 满额 + .!qB 孪生在落点。
   造法纪律: 多文件种子凡绕过 fake_multi/fake_with_data 手工写数据, 盐表达式必须从 pieces
   计算侧逐字誊写。
2. **「NoSubfolder(contentLayout)加库配方」**(测试基建面, 供复用): qB 5.2.3 支持
   /torrents/add 表单域 `contentLayout=NoSubfolder` 剥根平铺 —— files API 名单**不带 info 根
   前缀**且与磁盘平铺逐项一致(报告 26-11-13-0617 E7b 实证 + 本片 armed 迁移后复证); lib/qb.
   add_torrent 不透传该域, 用例侧 multipart 直加(配方单点 = rm04_e7_filemap_consistency.
   _add_with_layout, docstring 已声明誊写来源)。
3. **片E/F 坑点传承全命中**(零复发): 取数面单点(相位断言走成员详情 relocate 相位/live
   WARNING 面, 磁盘账只配终态等待)、先删 mover 不适用本片(RM04-33 删光全体成员直达删链门,
   RM04-25 A3 同款通路; RM04-32 无成员删除)、main_tick 1S 纪律(R4 收缩拍错竞态面不触发)。
