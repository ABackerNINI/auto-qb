## 03 本轮实测确认的代码事实(回写素材)

1. **off 快照复位 limit 段 + derive 优先级**(RM07-02 实测): 来源 off → `publish_off` 把 limit 段复位
   disabled; 曲线未配置时没有发布者再动它, 之后 ok 轮 `publish_source` 保留旧 limit 段 ——
   顶层 state 在 off→ok 全程停在 **"disabled"**(derive_state 的「曲线未启用 > 正常」格), 不是缺陷;
   来源段级 `source.state=ok` 才是三态判据。
2. **零传输种子不进采样集**(RM07-07 实测): `_sample_torrents` 数据门 = 采样目录存在才采, 零传输假种子
   整体跳过、不产目录 —— 「暂停态种子进 null run」(:831)是**活跃但缺字段**分支, 健康 qB 到不了;
   单种系列/重启首窗 null(基线空 → inc=None, 只在非零速率路径可见)的真数据面归 RM07-08 的 L2。
3. **纯空闲系列的「关块重开」空态形态**(RM07-09② 实测): 开放 z 游程**从不形成盘上旧块**(记录只在封口时
   append, `_append_record` 才开块)→ 切 interval 时「无开放块的开放游程不封, 将成为新块首记录」
   (`_close_blocks_for_interval_change` docstring 原文), 盘上恰一个 interval=6s 新块、z 游程无缝横跨
   全程, 零数据零坏行。「旧块封口」面需要块内有 r 行, 归 L2 真流量。
4. **gtm 工具在本机真实运行**(RM07-10 环境实况): 冻结计划「未安装 → not_installed」前提为假 ——
   发现指针指向另一 clone(`D:\Projects\auto-qb`)的安装, state=ready/reachable=true/autostart 已注册。
   用例按「按实况定档」改双分支断言(ready 验就绪载荷全貌含工具 /status 回显); 「PUT /config 未就绪 → 502」
   与「密钥缺失降级 not_running」两个子项在本机不可达(写端点会真写用户运行中的 gtm, 跨 clone 红线),
   跳过并记账, 解锁条件 = gtm 停跑或用户授权的隔离环境。provider=traffic_monitor 缺省下产品**不订阅**
   该工具(订阅按期望态收敛), 状态端点只读探测, 无跨 clone 写。
5. **RM01 观察项收口**(RM07-01): 「未配流量源启动打空路径 WARNING」行为未变, 观察项原文与实测逐字一致,
   重复启动每次都打、同进程内单轮一条 —— 观察项正式关闭。
