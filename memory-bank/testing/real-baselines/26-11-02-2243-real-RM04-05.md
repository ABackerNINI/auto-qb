## 03 L490 前置构造(历史记录, 已废弃; 保留证据链)

1. **为什么带盘符卷造不出(当时的判断)**: 全部带盘符卷剩余 ≥ 31.89GB, 远大于用例组数据量; 把 needed 抬到 30GB+ 需要造 30GB 级种子, 代价不可接受。当时转向无盘符小容量卷(**该转向已废弃**; 现行做法见 real-machine.md §2.9 的 `QBT_REAL_SMALL_TARGET` 配方)。
2. **卷枚举**: `kernel32.FindFirstVolumeW/FindNextVolumeW` 枚举全部卷(唯一能看见无盘符隐藏卷的 Win32 面)。筛选 `0 < free < needed`(needed=128MiB)且 `shutil.disk_usage` 可读的卷。
3. **junction 暴露(历史做法, 已废弃并移除; 仅留证据)**: `cmd /c mklink /J <case>/smallvol \\?\Volume{3047a86e-fab4-4bd4-a4d6-8824b76ce3d6}\`。PowerShell `New-Item -ItemType Junction` 会把卷 GUID 目标拼成 `\??\\\?\Volume...`(WinError 123), mklink /J 才能正确落成 `\??\Volume{...}\`。
4. **两个前置同时成立(探针实测)**:
   - 跨卷: `os.stat("R:/").st_dev = 5401726539199518491` vs `os.stat(smallvol).st_dev = 10571167978917014475` → `_same_volume_resolved(alias_fs, "R:/", <leaf>) = False`;
   - 空间不足: 目标叶子不存在, `_volume_free_resolved(fa, <leaf>)` 上溯 junction = `86,564,864 < 134,217,728`(needed = 2×64MiB)。
5. **产品纯函数同源探针**: `evaluate_group(GroupFacts(...))` → `cls=blocked`, reason = `{"gate":"space","text":"目标卷剩余 86564864 字节 < 本组数据 134217728 字节: 空间不足, 拒绝迁移"}`。
6. **零写入(无法证实, 已作废表述)**: 当时只有「L490 在一切搬运之前拒绝」的代码路径间接证据, **未采集该卷前后 free**, 因此不能宣称「零写入已证实」。该卷依赖已在本轮彻底移除。
