# WEB UI 选中 × 触发 口径 (作用域契约)

> 摘要: 「选中 / 锚点 / 光标」三态作用域 + C1–C5 一致性契约 + 触发点登记表位置 —— 判断「这次动作作用在谁身上」的唯一口径出处。
> 触发: 选中与触发不一致, 作用域, scope, 右键菜单作用于谁, 批量动作目标, 菜单变体, 触发点登记, 新增动作入口

来源: 计划 `memory-bank/plans/26-10-10-2001-plan-webui-selection-trigger-parity.html`(专题 `webui-selection-trigger-parity`)。本文是该计划的**口径单点**; 实现进度与路线在计划与任务档案里, 本文不复述。

## 1. 四个术语(与代码字段一一对应, 不是新概念)

| 术语 | 代码权威 | 说明 |
|---|---|---|
| **选中** selection | `selGroups`(组 key) · `selMembers`(成员 hash) · 派生 `selHashSet` | 用户显式圈进来的对象。**普通单击不构成选中**(2026-09-17 口径) |
| **锚点** anchor | 触发时指针所落的那一行 / 按钮绑定的那个对象 | 右键点的那行、`menu.key` / `menu.hash` / `menu.episode` 所代表的形态 |
| **光标** cursor | `kbCursor` | 键盘焦点行。**focus 语义, 不等于选中**(2026-09-30 方案 B) |
| **触发** trigger | 会改变远端状态的用户输入 | 右键菜单项 / 面板按钮 / 快捷键 / 对话框提交 |

**作用域三态**(描述一次触发的作用对象):

- `sel` —— 目标 = **选中集合**的展开闭包。
- `anchor` —— 目标 = **触发锚点**的展开闭包。
- `cursor` —— 目标 = **键盘光标行**的展开闭包。

派生两态(既有实现的口径, 保留为具名值, 不得再散写):

- `sel-first-cursor` —— 有选中用选中, 无选中用光标(`_kbTargets` 口径)。
- `panel` —— 目标 = 面板/菜单当前目标(`torrentCmd` 读 `menu.hash`; 抽屉内命令读抽屉 hash)。
- `none` —— 与选中/锚点无关(全局资源类: 分类/标签/全局限速/HR/添加种子)。

## 2. 契约 C1–C5

- **C1 解析单点** —— 任一次触发解析出一个作用域描述符(`ScopeDescriptor`), 由**唯一函数**产出; 任何触发点不得自行拆解选中集合。
- **C2 变体派生** —— 菜单/对话框的 UI 变体(`multi` / `group` / `member` / `episode`)由描述符**派生**, 不得用第二个 token 并行判定。
- **C3 文案同源** —— toast 与确认框里的目标形态(「该种子」/「整组」/「N 个目标」)由描述符派生, 与实际载荷同一份来源。
- **C4 出口唯一** —— 所有动作投递经统一出口; 出口内部做一次「描述符 ↔ 实际载荷」一致性自检。调用方**拿不到**自己拼目标的接口。
- **C5 锚点资格** —— **仅当选中集合为空时, 锚点与光标才有资格当目标**。选中非空时, 锚点只能用于**改变选中**(选中/取消/扩段), 不能静默改变作用对象 —— 除非该触发点在登记表里显式声明 `scope: 'anchor'` 且可被守阵查到。

> C5 是本专题的**待拍板项**: 口径甲(保持「选中 N 项右键 = 对全部生效」, 但菜单上明示「将作用于已选 N 项」)= 推荐; 口径乙(右键哪行就以哪行为目标, 变体重排)= 更贴肌肉记忆但改动大。

## 3. 现状教训:四条偏差机制

这四条是「选中 A 却动了 B」这类**静默作用对象偏移**的成因。新增触发点时必须能明确回答自己属于哪一条(或都不属于):

1. **两套判定并行** —— 菜单变体由 `_ctxMulti` / `_ctxScopeKey`(menu.js)判, 动作目标由 `_bulkTargets` / `_groupTargets` / `menu.*` 算。两套逻辑互不知情, 各自演化。
2. **优先级相反** —— 鼠标路径**锚点优先**(右键哪行定变体), 键盘路径**选中优先**(`_kbTargets` 有选中即忽略光标)。同一屏、同一选中集合, 两种输入给出不同答案, 且都不提示。
3. **借道菜单状态** —— `_kbEditAct` / `_kbTorrentCmd` / `_kbTorrentToggle` 把键盘解析出的 hash **写进 `this.menu.hash`** 再调菜单绑定方法 ⇒ 键盘目标解析与菜单状态耦合, 菜单开着时 `menu.hash` 的有效性无从校验。
4. **两套「选中展开」** —— 批量动作按 `_bulkTargets`(组 key 优先覆盖成员, 一个组算 1 个目标), 导出按 `selHashSet`(全量展开为 hash)。同一选中集合在两条路径上「N 个目标」的含义不同。

## 4. 触发点登记表(声明式单点)

单点文件: `src/auto_qb/webui/static/shared/triggers.js`(常量 `TRIGGER_DEFS`, 经 `window.AQB_TRIGGERS.triggerDefs()` 暴露)。

两张表:

- `ui` —— **触发点**: `{id, ui, variant, entry, scope, dispatch}`。`ui ∈ ctx-menu | kbd | drawer`; `variant` 仅 `ctx-menu` 有(与 `tpl/ctx-menus.html` 四支一一对应)。
- `calls` —— **投递调用点**: `{file, fn, ep, scope, why}`。覆盖 `shared/*.js` 里**每一个** `method: "POST"` 出现点(含 `scope: "none"` 的豁免项 —— 豁免也登记, 白名单不复存在)。

**新增触发点/新增投递点的唯一动作 = 在 `TRIGGER_DEFS` 加一行。** 不登记会被守阵直接判红(见下)。

## 5. 三张网(检查怎么自动跟上新功能)

| 网 | 落点 | 接住什么 |
|---|---|---|
| ① 静态守阵 | `tests/test_webui_trigger_registry.py` | 表外直投递 / 出口外展开选中集合 / 菜单变体缺支 / 四支动作族不齐 / 登记了不存在的入口 |
| ② 运行时审计 | `scopeAudit`(计划 S4) | 走统一出口的动作**零新增代码**自动被比对描述符与载荷 |
| ③ 真浏览器矩阵 | `e2e/trigger-scope.spec.mjs`(计划 S5) | 从 `TRIGGER_DEFS.ui` 生成用例, 真实输入 × 载荷比对 |

「自动停靠」= 新增功能**要么走统一出口**(网②自动罩), **要么登记进表**(网①强制), **要么新增变体**(网①/③自动扩)。
