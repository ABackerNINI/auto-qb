# 修 `${-n 0}` 串行挂死: Windows 子进程看门狗 (Done)

> 摘要: 清偿上一会话([26-10-03-2116-argv-flag-swallowed](26-10-03-2116-argv-flag-swallowed.md))的遗留观察 —— `test.pkg` / `test_sync` 的 `-n 0` 串行在 `test_sync` 第 15 个用例后**无限挂住**(不报错、不退出), 拖垮 `ship.commit` 闸门(=提交无输出即中止)。**根因不是仓库逻辑**: Windows 上 `subprocess.run(capture_output=True)` 在**高负载 + 大量 spawn**(本机 4 clone 同跑测试)时无限挂死, `faulthandler` 抓栈到两种等价入口 —— ①`_winapi.CreateProcess`(`Popen.__init__`)不返回; ②`communicate()` join 读线程等不到 EOF(git 的**孙进程** `git push → sh.exe → git-receive-pack → git` 继承了管道写端不退)。此时 `subprocess.run(timeout=…)` 也救不了(timeout 只杀直接子进程, `communicate` 仍阻塞在 join)。**修法**: `.commands/my-commit-flow/scripts/_pipeline.py` 新增 `run_capture()` —— `Popen + communicate` 放**看门狗线程**, 主线程硬等到 deadline, 到点 `taskkill /F /T` 杀**整棵进程树** + 关本端管道(不 join), 返回 `rc=-1`; `git` / `git_rc` / `git_run` / 闸门 `run_gates` / `_safe_files` 探针**全改走它**, `test_sync.py` / `test_commit.py` 的 `_git` 同。两个改错被抓出的坑: ①超时收成 `rc=-1`**不抛** ⇒ `_safe_files` 必须显式判 `rc != 0`(否则静默放行真动作脚本); ②裸 `Popen` 在 `TimeoutExpired` 分支必须自己 `taskkill + wait()`, 否则子进程活着占 cwd, `tearDown` 立刻 `rmtree` 临时目录 → `WinError 32`。实测: `-n 0` 三个包脚本用例 **79 passed / 275s 不再挂**, `-n 4` **79 passed / 100s**, `test.full` **2415 passed + 3 skipped / 99%**。`test.pkg` 保持 `-n 4`(闸门要快 + 能收口), note 已改。坑档 [pitfalls/testing/parallel-run.md](../pitfalls/testing/parallel-run.md) 已从「根因未定位, 留给 issue」改写为真根因 + 修法。
