## 关键结论

- **「渲染器注册表」= `app.js` 末尾那组 `app.component` 调用**(行模型 → 组件), 组件模板内部再按 `col.key` 查表(v-if 链)。六个组件: `<aq-table>`(表壳) + 五个行模型渲染器 `<aq-member-cells>`(member, P2)/`<aq-group-cells>`/`<aq-torrent-cells>`/`<aq-show-cells>`/`<aq-ep-cells>`(P3)。**页面模板只剩结构**(行容器 + `v-for` + 组件调用), 改一处不再漏一处。
- **搬模板必须逐字搬, 只加 `$root.` 前缀**: 分支体从页面模板原样搬进 x-template, 方法调用/根数据(`speedLimitBytes` 等)统一加 `$root.`(`this` 仍是根实例, 结果不变); **props 保留各行自然名**(`g`/`m`/`s`/`e`)而不统一改成 `row` —— 少改一字就少一处 DOM 等价风险。这是本轮「零回归」能成立的关键。
- **计划的「同名列跨表复用同一份实现」在保持 DOM 等价下不可达**: 同名列跨表的 class 与口径不同(组行 `dlspeed` = `:class="{zero}"` vs 种子行 = `:class="[{zero}, numTone(...)]"`; `site` 成员格 `.m-site` vs 种子行 `.g-sites > .site-chip`)。按 P3 停手点(D2=B「保留声明式模板, 按行模型收敛为单份」)落地为**每行模型单份渲染器**; 跨表合并(`h()` VNode)留作 P6 之后的可选优化。
- **分片体量两个硬顶要一起算**: ①`prism/index.html` 贴着 shell **210 行**上限; ②**单分片 ≤400 行**。`tpl/xtpl.html` 收不下全部渲染器(302 + 211 = 513)⇒ 另开 `tpl/xtpl-cells.html`。三份 shell 的 `parts` 各加一行, 而 prism 无空行可腾 ⇒ 把相邻两个 `parts` 数组项合并到同一行(JSON 空白不参与解析, 清单等价断言比对 `json.loads` 结果; 合并只对 `parts` 做)。已回写 [pitfalls/web-ui/frontend-split.md](../pitfalls/web-ui/frontend-split.md)。
- **收敛模板会连带改掉按「字面调用」计数的守阵** —— 同轮补覆盖, 不是放宽。本轮: 四表列 key 扫描面全改到渲染器分片; 组件注册面 2 → 6; 删掉种子页 `.h-cell` 例外; 横滚同步守阵从"扫三份实现"改为"钉单点 + 三个调用点"; 做种时长列"要求渲染门"的字面量断言改成兼容 `$root.` 前缀的正则(语义不变)。
- **A/B 逐字节等价是本轮硬验收**: 一次性探针 spec 在两皮肤各 dump 20 项(列选择器弹层 + 三视图的表头/行/明细/成员行 `outerHTML` + **子节点骨架含注释与文本节点** + 行内联 grid 样式 + `col-align-css`)。A 侧 = 14 个改动件 `git checkout` 回 HEAD + 新分片移出树(跑完 `sha256sum -c` 复核还原); B 侧 = 本轮构建。**合计 40 项差异 0, A/B dump sha256 相同**。
- **e2e 存量 34 项红已由上游转绿**: 上一片 P0 基线记的是 124 passed / 34 failed / 10 skipped; 上游提交 `c2a723a3`(e2e 菜单选择器同步 qB GUI 新文案)把 34 条转绿 ⇒ 本轮实测 158 passed / 0 failed / 10 skipped(124 + 34 = 158 逐项对得上)。**不是本轮遮蔽**。
