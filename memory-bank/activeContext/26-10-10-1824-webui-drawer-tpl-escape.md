# 详情面板变体模板: 漏包 R() 致标签被转义成纯文本

> 摘要: 用户报「种子详情面板出现 `<span class="dt05-offnote">虚拟条目由 qBittorrent 合成, 不参与汇报</span>`」, 复报确认为**渲染 bug**(健康分组模板常显这串原文, 且带 span 标签)。根因 = 变体模板的 `dtHtml`(即 `T`)对**所有**插值一律转义, 只有 `dtRaw`(即 `R()`)包过的才豁免 —— 条件子块把内层 `` T`<span...>` `` 的结果**裸插值**进外层模板、漏了 `R()` ⇒ 整段标签被当纯文本透出(附带的静默后果: 该元素独占的 CSS `.dt05-offnote{...}` 从未命中)。用户拍板「同族一起修」, 共修 2 处: `05-trackers-health-groups-low.js`(未启用区虚拟条目备注) + `11-content-treegrid-batch-low.js`(筛选无结果的空态); 提示文案本身按用户选择**保留**。机理入坑档 `pitfalls/web-ui/template-render.md`。

## 关键结论(供后续改变体模板参考)

- **条件子块一律 `` ${cond ? R(T`<...>`) : ""} ``**: 把 T 标签模板的结果当插值就必须套 `R()`; 写成 `` ${cond ? T`<...>` : ""} `` 会被外层模板再转义一次, 页面显示成标签原文(无报错)。
- **数组形态同理**: `dtHtml` 对数组逐元素 `esc` —— `.map(T`...`).join("")` 的结果也必须经 `R()` 才能进模板。
- **这类静默失效靠静态扫描兜**: 判据 = 逐个 `${...}` 插值表达式, 内容含 `T` + 反引号却不含 `R(` 即命中(本轮据此扫全量 `drawer_tpl/` + `drawer_pages/`, 命中即上述 2 处); 暂无守阵, 见坑档。
- **`dt05-offnote` 样式自此才生效**: 该 CSS 规则本就在, 只是此前标签被转义、从未命中 —— 修完按预期渲染为 11.5px / `--fg-dim` 的说明文字。
