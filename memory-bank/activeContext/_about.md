# 会话滚动状态切片
> 摘要: 每个在办专题一个时间戳切片，各 clone 只写 / 更新自己的文件
> 触发: 现在做到哪, 上次做到哪, 收尾更新状态, 会话状态

## 四条约定（2026-09-23 定）

1. **文件名** `YY-MM-DD-HHMM-<slug>.md` —— 前缀**定宽**才能保证字典序 == 时间序（`26-9-3-34` 会乱序）。
   时分无考时用 `0000` 占位。与 `tasks/` 档案「不带时分、同天同专题必撞同路径」的故意设计**意图相反**，
   所以两者分目录存放。
2. **不带 clone 标记** —— 同分钟同名 add/add 概率极低，撞了改个 slug 重来。「我上次做到哪」靠
   **slug 复用**检索：同一专题跨会话沿用同一个 slug，自然串成时间线。
3. **写**：会话收尾时更新自己的切片（换专题才新建文件）；切片 >14 天未动且已完成 → 蒸馏进
   `progress/` 或任务档案后删除。
4. **读**：`python <skill-dir>/scripts/gen_active_recent.py` —— 全量按「最后活动」倒序 + 陈旧标记。
   **不做「取最近 N 条」截断**，也不产出任何缓存文件。

## 不在这里的东西

本目录只承载**会话滚动状态**。长青职能各有归属：下一步候选 → `想法.md` + `progress/roadmap.md`；
定案口径 → 根 `AGENTS.md` / `conventions/` / `pitfalls/`；真机走查 → `checklists/`；
历史归档 → `tasks/` 档案的「历史会话纪要」段。

## 为什么是这个形态（原文照搬自旧 activeContext.md 头部）

> Memory Bank 核心文件之一: 回答「现在正在做什么 / 上次做到哪 / 下一步从哪继续」。
> 稳定事实在 projectbrief.md / productContext.md / systemPatterns/ / techContext.md 与各主题文档;
> 已完成状态在 progress/, 陷阱与判据在 pitfalls/。
> 维护纪律(完整规程见 memory-bank skill):
> ①每次会话收尾更新状态; **已完成条目沉淀到 progress/ 或主题文档后删除**;
> ②命中立档阈值的任务在 tasks/ 立档并同步索引;
> ③**禁止**追加长流水账纪要 —— 那是 2026-09-17 那次膨胀 10 倍的直接原因, 现已由 cap 守卫兜住。
> ⚠ 旧版的「最后更新」是**滚动状态**(每轮会话替换上一轮), **不是档案** —— 要回查「某次改动何时入库 /
> 带哪个 sha」, 请看 tasks/ 各档案的「进度日志」段或 progress/。

**2026-09-23 改**：滚动状态按专题切片（即本目录），「每会话重写头部同一段」这个最热写点随之消失。
