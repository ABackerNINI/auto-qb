01现象与发现场景

复盘 config 校验体系时发现：validate_config 是 fail-fast 全量校验，但拦截的对象集中在「错误」上 —— 格式解析失败（_try/_try_time）、未知键（_check_unknown_keys）、类型不符（_check_str_list）；对「格式合法但取值不合理」的值缺少上下限/合理区间约束。数值与时间类配置多数只查下界甚至不查，能配出格式完全合法、运行时却有问题的值（如超长时间、超大并发、0 或负值视实现而定）。本 issue 的后续工作是逐项分析各配置的合理取值范围并收紧，不预设哪些值一定要限。

与平台/环境无关，纯校验层缺口；触发与具体配置写法相关（例如把时间配成极大值、把计数类配成极大值）。

_check_unknown_keys   # 未知键

05根因（可选）

默认「待查」—— 不为填单做分析。有结论才写；不确定就写已排除的假设，不要把猜测写成结论。

已定位（2026-09-22 逐键分析后收敛为三类助手级缺口，见 07 节逐键清单）：
  1. _try_time 的 positive 形参未用满：仅 main_tick / sync_interval / 曲线 interval 三处启用；config.interval（core.py:146）与规则 interval/cooldown（rules.py:102-104）漏用，0 值可配。所有时间键均无上界。
  2. _try(int/float, ...) 只查可解析：无 min/max，更不拦 nan/inf（float("nan") 可解析通过）。max_tasks_per_tick 的 ≥1 是全库唯一一处手写范围检查。
  3. 领域解析器边界语义无人接住：parse_hr_condition 允许 0%/负数/>100%；parse_fsize 允许 0（log.max_bytes=0 = RotatingFileHandler 从不轮转）。

06建议修法（可选）

方向 + 候选方案 + 各自代价；没有想法就留「待定」，只写方案，不在本报告里实施。

方向（07 节逐键分析后的具体化；均不在本报告实施）：

  1. 助手层：validation/core.py 增加 _try_number(value, where, errors, *, integer=False, min=None, max=None)（内部用 math.isfinite 拦 nan/inf），_try_time 增加可选 max 形参；沿用聚合报错风格。逐键手写（max_tasks_per_tick 先例）作为最小改动的备选。
  2. 收紧清单：按 07 节红/黄标行逐键落地。上界取值原则走保守默认（黄金法则 2）：只拦「明显危险」或「与键语义明确失配」的值（0 高频、负数、nan/inf、0 字节日志轮转），拿不准的不拦。
  3. 跨段冲突检查（web.port 与 qbittorrent.port 撞端口）机制不同（需段间可见），单独立项不并入本 issue。
  4. 每收一批键同步补 tests/ 校验用例与 schema help 文案（新键进 validate_config 的守卫已有先例）。

07逐键取值范围分析 （2026-09-22 用户指派，取证 19:43-19:51）

覆盖全部配置路径（顶层 19 键 + 各段子键 + 规则 spec + 曲线段）。徽标：缺口 = 建议必须收紧（明确副作用/语义失配）；建议收紧 = 有副作用但触发条件苛刻或影响小；已良好 = 现有校验已覆盖范围/枚举，无需动。分析维度：运行副作用（qB API / CPU）、文件读写、安全、语义可达性。

三条横向结论：① 副作用类缺口集中在「0 可配」——队列层 _norm_interval 把 <=0 归一化为 1s 兜了底，但把语义错误转成了高频风暴（每秒全量任务/规则决策链）；② 文件读写链路本身健壮（atomic_write + 自动建目录 + 路径空串兜底），唯一缺口是 log.max_bytes=0 不轮转直至磁盘写满；③ web 段安全默认全保守（enabled=False / 127.0.0.1 / token 随机 / skip_local_verify=False），暴露面建议用配置期 WARNING 提示而非硬禁，唯一「配置驱动的外部执行」是 checking 自定义校验程序路径。
