§01现象与发现场景

YAML 写 cooldown: 0.0（浮点）时：校验侧放行（_try_time(0.0) 经 parse_time 的 empty_zero 分支得 0），但 Rule 构造期 str(0.0) = "0.0" 后 parse_time 抛「无效时间格式」裸 ValueError，绕过 ConfigError 契约。与本批已修 issue 26-11-08-0703（config-bare-zero-cooldown-keys）同根的残余缝隙。

复验

复验（2026-11-08, HEAD f42fe5db）：仍复现, 但触发面比 §01 记载的窄。真链路实测（load_config 走 yaml.BaseLoader, 标量全为字符串）: 配置文件写 cooldown: 0.0 到达校验侧时已是字符串 "0.0", _is_bare_zero("0.0") 为 False → _try_time("0.0") 裸拒 → 干净的 ConfigError 聚合报错「config.example_rules.r1.cooldown: 无效时间格式: 0.0」, 契约未破。§01 的「校验放行 0.0 经 empty_zero」只在程序内 dict 构造路径成立: validate_config({'example_rules': {'r1': {'cooldown': 0.0, ...}}}) 放行（parse_time(0.0) 经 empty_zero 得 0）, 随后 Rule({'cooldown': 0.0}) 构造期 str(0.0)="0.0" → 裸 ValueError「无效时间格式: 0.0」, 绕过 ConfigError 契约 —— 锚点 base.py:369 引文仍在, 缺口真实。

修复后补充

实际修法与 §06 建议不同 —— 用户拍板改道为口径 A（谓词扩 float）, 不在构造期包裹 ConfigError（保留建议原文于 §06）:

  • 谓词扩 float: validation/core.py _is_bare_zero 的 isinstance(value, int) 分支扩为 (int, float), 只对数值 0（含 -0.0）放行; 字符串 "0.0" 与非零浮点（3.5）不在内, 照走原有「无效时间格式」报错。
  • 构造侧同口径: rules/base.py cooldown 解析去掉 str() 包裹, 原始值直传 _parse_time_bare_zero_ok —— 浮点 0.0 须以数值形态进谓词（包裹成 "0.0" 会绕过特判）; 非零值由 parse_time 内部自行 str(), 报错行为不变。
  • 既有四键口径核对（issue §05 的牵动担忧）: 其余三键（state_save_interval / notify.dedup_window / gtm.notify_cooldown_s）对浮点 0.0 在校验侧本就经 empty_zero 放行（parse_time(0.0)==0）, 谓词扩 float 后走 bare-zero 特判早退, 结果值与放行结论均不变; 非零浮点照拒。四键行为零变化, 仅闭合构造期缺口。
  • 文件路径口径: 配置文件写 cooldown: 0.0（BaseLoader → 字符串 "0.0"）仍干净拒（聚合计数报错形态, 非裸抛）——扩法只对数值 0 放行, 未顺手放宽字符串; 逃生口 0S 照旧。
  • 测试: 新增 test_rule_cooldown_float_zero_means_no_cooldown（test_rule_base_rule: 0.0 校验过 → Rule 构造成功 cooldown==0.0 → 运行时不冷却; 3.5 校验侧照拒）; 扩 test_validate_rule_cooldown_bare_zero（test_config_misc: 浮点 0.0 dict 路径放行 / 文件路径 "0.0" 干净拒 / 浮点 3.5 照拒）; 两文件头「测试计划」清单同步。
