01现象与发现场景

发现场景: 实施 A 系 S1 值层（计划 26-10-13-0540，删合成回写）后跑 test.quick，两条 grouping 用例转红：test_grouping_state_change_triggers_check 与 test_grouping_errored_transition_pauses_group。逐行核对后确认二者不是实现缺陷，而是 S1 语义变化的显形 —— 用例原本断言「状态不变不重复触发」，在 A 系下该断言的前提（自有停种当场改快照）已不成立。

现象: A 系 S1 删掉 _sync_paused_state 后，自有「整组停种」不再于动作当轮改写 store 快照，被停成员的 stalledUP → pausedUP 变化要等到下一轮同步才进 store.state_changed。而 grouping_mod._handle_state_transitions 的触发谓词只看「本轮变化」（cur.is_complete && cur.is_stopped && prev.is_uploading），且它对同一物理停种事件没有跨轮去重 —— 于是同一组会被判定两次「上传转暂停」：第一次在停种当轮（由外部/其他路径驱动），第二次在下一轮（由自有停种经同步回流驱动）⇒ 追加一次缺文件扫描 + 停种。

与配置/平台无关: 只要存在「一次动作把整个做种组（含正在做种的成员）转入暂停」的路径即可触发。当前实现里至少两条：文件大小不一致整组暂停（_check_size_consistency）与缺文件扫描的组内停种（_check_missing_files）。幂等、无害、一轮即收敛（第二次扫描结果与第一次一致），故严重度低，但属无谓重复。

02证据

触发谓词（grouping_mod.py:205-208，取证 2026-10-13 06:26）—— 只按「本轮 state 变化」判定，无跨轮去重：

    for h, cur in store.state_changed:
        prev = state_snapshot.get(h)  # 上一轮 state_enum 枚举
        if prev is None:
            continue
        if not (
            (cur.is_complete and cur.is_stopped and prev.is_uploading) or (cur.is_errored and not prev.is_errored)
        ):
            continue

用例侧为迎合该语义而补的「收敛轮」断言（test_grouping.py:201-210，S1 迁移时新增）：

        # 状态不变 -> 不重复触发
        # !A 系 26-10-13-0540 S1 语义变更: 上一轮的整组停种(H1+H2)不再当场改写快照, 其中 H2 的
        #   stalledUP->pausedUP 于**下一轮同步**才可见、并再次满足「上传转暂停」谓词(:206)
        #   ⇒ 追加一次扫描+停种(幂等)。这是「源无关」的应有之义(2229 裁定), 且一轮即收敛。
        #   故先跑一个收敛轮, 再断言真正的「状态不变不重复触发」。
        client.calls.clear()
        mgr._refresh_torrents()  # 收敛轮: 承接整组停种经同步回流的 H2 状态变化
        client.calls.clear()
        mgr._refresh_torrents()
        assert _non_tag_calls(client) == [], f"状态不变不应重复触发: {client.calls}"

同类第二处：test_grouping.py:1198-1201（test_grouping_errored_transition_pauses_group）加了同款「收敛轮」说明。S1 前这两条用例无此轮次、直接断言空调用集，说明该二次触发是 S1 引入的新现象。

03影响面

维度结论
触发条件一次动作把「含正在做种成员的组」整组转入暂停（如大小不一致整组暂停 / 缺文件扫描组内停种），且该组 check_missing_files 未禁用。则下一轮同步会追加一次 _handle_state_transitions 命中。
影响范围仅 grouping 缺文件扫描路径多跑一轮；状态机 / 快照正确性 / 视图均不受影响。停种与打标签在 qB 侧幂等，第二次扫描结果与第一次一致。
严重度低（幂等、一轮收敛、无数据风险）。代价 = 每例一次冗余扫描 + 冗余停种调用 + 可能的重复日志。

05根因（可选）

已基本定位（结构性副产物，非独立缺陷）：A 系 S1 使自有停种的可见性从「动作当轮」推迟到「下一轮同步」。_handle_state_transitions 只对本轮 store.state_changed 判定，且去重只在轮内（triggered 集合，_scan_triggered_groups），无跨轮去重。同一物理停种事件因此在两个不同轮次各命中一次谓词 ⇒ 第二次为冗余触发。

待确认：该二次触发是否应在 A 系 S2（own_writes + 局部 deferral）或后续统一处理 —— 若采用「自有停种 hash 登记」的跨轮去重，其登记容器可能与 S2 的 own_writes 有交集，宜一并设计而非各造一套。已排除：不是测试替身保真度问题（FakeClient 四方法翻转 state 后现象仍在）、也不是快照错乱。

06建议修法（可选）

方向 A · 接受（零改动）：认定这是「源无关」语义的应有之义（2229 裁定），代价仅为一次幂等扫描，收敛明确。此时本 issue 可转 Dropped（写明理由）。

方向 B · 跨轮去重：在 grouping 侧维护「已处理过的 (hash, 目标状态) 转换」跨轮去重集合（仿 _missing_scanned_keys，但需跨轮存活 + TTL/有界），或对自有停种的 hash 打登记标记，令 _handle_state_transitions 跳过「本进程自有停种回流」产生的命中。代价：新增状态 + 有界性维护；与 A 系 own_writes 存在合并空间（见 §05）。

结论待拍板，未在本报告实施。
