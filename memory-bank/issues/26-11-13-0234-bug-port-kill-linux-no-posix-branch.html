§03影响面

维度结论
触发条件POSIX 宿主(无 powershell)上调 listening_pids() 或 process_info() 即崩, 无配置可绕; Windows 宿主不受影响(设计平台)
影响范围仅 dev 工具链, 生产代码零涉: dev.e2e-check(e2e 前置自检)、dev.e2e(run 列表首条即 selfcheck)、dev.port-kill(残留桩定点杀通道)三者在原生 Linux 全部失效; pytest/e2e 断言面与 CI 行为均不变
严重度低-中 —— 不挡 CI/Windows; 但 env3 类原生 Linux 宿主上 e2e 的「前置自检 + 残留清理」两保障面全缺, 本机暂以直跑 npm run test:e2e:fast 绕行(webServer 恒 OS 取号 + reuseExistingServer:false 兜底); 残留桩时只能人工 ps/kill

§05根因（可选）

默认「待查」—— 不为填单做分析。有结论才写；不确定就写已排除的假设，不要把猜测写成结论。

port_kill.py 设计时只面向 Windows 宿主(文件头注释即「PowerShell 一行式经 PS → cmd 批处理不可靠, 落成脚本跨 shell 稳定」的 Windows 语义), 进程查询共三处硬编码 powershell(port_kill.py listening_pids/process_info 两函数 + e2e_selfcheck.py _proc_info)而未按 os.name 分派; env3 探测轮只验证了 pytest 面, e2e 工具链面在本轮(26-11-13)首次实跑即暴露。已排除: 非 PATH 配置问题(POSIX 本无 powershell, 属预期), 非参数/时序问题(blocking=False 默认主路径即触发, 0.1s 即崩), 非本机特例(任何无 powershell 的宿主同炸)。

§06建议修法（可选）

方向 + 候选方案 + 各自代价；没有想法就留「待定」，只写方案，不在本报告里实施。

方向: 按 os.name 加 POSIX 分支, Windows 支路原样保留; 修复面 = 三处查询 + 一处实杀共四个 powershell/taskkill 位: port_kill.py listening_pids/process_info + e2e_selfcheck.py:76 _proc_info(建议直接复用 port_kill 的 POSIX 支, 不再复制一份)+ port_kill.py:149 实杀 taskkill(POSIX 支 os.kill SIGKILL, 归属核验语义不变)。必须保持脚本「先核身份再定点杀、非 python 监听者须显式 --yes、验证失败拒绝杀」的豁免语义(AGENTS.md「🔴 进程安全」节, 2026-11-07 用户拍板)。候选:
  • A(推荐): POSIX 支走 /proc 直读零外部依赖 —— listening_pids 解析 /proc/net/tcp{,6} Listen 态 inode → /proc/*/fd 反查 PID(或 ss -tlnp 一行式, 前提是同用户可见性, 桩进程恒同用户); process_info/_proc_info 读 /proc/<pid>/comm + /proc/<pid>/cmdline, 归属核验语义与 Windows 支等价。
  • B: ss -tlnp 一行式解析 —— 实现短, 但引入对 ss 输出格式的文本耦合, 且需处理无 -p 权限时的空归属(fail-safe 拒杀语义要对齐)。

认领时先复验本锚点(dev.e2e-check 在 env3 仍崩 + Windows 侧行为不变), 守阵按平台双支覆盖(参照 recycle-obs os.name 分派先例: 两支各 os.name 桩钉住, 在任一平台都跑); 改完跑 test.quick + 在 env3 实测 dev.e2e-check 绿(端口空闲 + --blocking/8099 留桩两场景, 后者验 _proc_info 支) + dev.port-kill 实杀面(杀一个自起的占口进程)。
