01现象与发现场景

2026-11-07 修 Linux CI 三条红（alias_kind_of 把真目录误判成硬链接）时，读 retarget_alias 的「链接位被真目录占据」保护分支，发现它的注释写的是「真目录/真文件占着」， 但只实现了目录支：真文件位没有任何保护，直接落到 remove_alias → os.unlink。

触发条件：supersede 重定向（收尾窗再迁移）时，别名位置是一个真普通文件（nlink == 1、 非链接、非目录）—— 例如 qB 在旧 save_path 下把同路径重新落成真文件、或用户/其它工具手工放了一个同名文件。 此时 alias_kind_of(link) 返回 None（不是链接）、is_real_dir 为 False （不是目录），代码认定「没有东西」，删掉后按新目标重建 —— 那个真文件被静默删除，且日志只说「重指向成功」。 与平台无关（Windows/POSIX 同路径）；不需要特殊配置。

02证据

贴原文（报错 / 日志 / 命令输出），不转述；附取证时间，让读者自己判断新鲜度。

代码原文（取证 2026-11-07 07:48，src/auto_qb/infra/alias_fs.py:939-952）：

    # 删旧链接前先处理「位置被真目录/真文件占着」的形态: 与 _build_links 目录支同口径,
    # 只挪**空**目录(qB 搬走文件后的残留); 非空 = 有真数据, 绝不动(不猜)。
    try:
        st = os.lstat(utils.add_long_path_prefix_for_win(link))
        is_real_dir = stat.S_ISDIR(st.st_mode) and existing is None and             getattr(st, "st_reparse_tag", 0) == 0
    except OSError:
        is_real_dir = False
    if is_real_dir:
        if os.listdir(utils.add_long_path_prefix_for_win(link)):
            raise RuntimeError(f"重定向失败: 链接位置被非空真目录占据({link}), 不猜测不动数据")
        os.rmdir(utils.add_long_path_prefix_for_win(link))
    else:
        remove_alias(link)          # <- 真文件也走这里

被调用的删除原语末尾（alias_fs.py:802，remove_alias 内）只有一句 os.unlink(p) —— 对「真文件」与「文件型链接」不做区分，删的都是同一个名字。对照：目录支已经有「非空 -> RuntimeError」 这一层，文件支没有。

本报告只做代码级取证，没有跑真实 supersede 现场复现；未验证的假设已写在根因段。

03影响面

维度结论
触发条件仅 supersede 重定向路径（relocate_exec 的别名重指向段）且链接位恰好是真普通文件； 概率低但无开关可关、也没有预检能挡：搬前占用预检（probe_alias_rebuild_busy）只探「此刻删除会成功吗」 （Windows 以 DELETE 访问权 + 全共享打开链接本体，POSIX 恒返 None），从不判路径身份 —— 非链接的真文件探测照样放行
影响范围该文件在旧位置的那一份真实数据被删（新位置的目标数据不受影响）；无备份、日志不告警 ⇒ 用户只会看到「文件没了」， 且因为重定向成功、job 继续推进，事后难以归因
严重度高（不可逆数据删除；与「非空真目录绝不动」的既有设计意图相反）

05根因（可选）

默认「待查」—— 不为填单做分析。有结论才写；不确定就写已排除的假设，不要把猜测写成结论。

机制已在代码上读通（见证据段）：保护分支只判 S_ISDIR，真文件既不是目录也不是链接， 于是落到 remove_alias 的 os.unlink。
待查：真实 supersede 现场会不会真的出现「链接位是真文件」（qB 在搬移/重定向期间有没有可能重建同路径真文件）； 以及历史上是否已经发生过（可按 supersede 日志 + 备份目录反查）。
已排除：①与 alias_kind_of 的真目录误判无关（那条已修，修完本路径行为不变）；②与平台无关。

06建议修法（可选）

方向 + 候选方案 + 各自代价；没有想法就留「待定」，只写方案，不在本报告里实施。

与目录支同口径收口，两个候选：

  1. 直接拒绝（推荐）：真文件位没有「空残留」形态可学目录支的 rmdir —— 判据加一条 is_real_file = stat.S_ISREG(st.st_mode) and existing is None and tag == 0，命中即 raise RuntimeError("链接位置被真文件占据")，交 D20「重试至收敛」路径留现场给人。 代价：真文件若确实是 qB 重建的同路径空壳，会卡在 supersede 等人工确认（保守默认，符合黄金法则 2）。
  2. 先比对再决定：真文件的 size/inode 与新目标一致（= 同一份数据的再来一份）才允许替换，否则拒绝。 代价：多一套判据与边界（mtime 不可靠、跨卷 inode 不可比），误判方向是删数据，风险更高。

守阵建议：tests/test_alias_fs.py 加「链接位放真文件 -> retarget_alias 抛 RuntimeError 且文件原样保留、内容不变」；与既有 test_retarget_alias_refuses_nonempty_real_dir 同族。

修复后补充

实际修法(与建议①改道, 收窄式放行): 未采用①的「真文件一律拒绝」—— retarget_alias 内「删旧链接」段下游存在一条有意删除真文件的路径: hardlink 形态的孪生残名(qB 跨卷搬移删掉另一名字后 nlink 收敛 1, alias_kind_of 认不出 → existing is None + 真文件), 数据已随搬移落到新目标, 该残名必须可删, 否则 supersede 永久重试不收敛(即代码注释引 N10 真机实测描述的形态)。 故改为①+②混合收窄: 判据 existing is None 且 lstat 非链接(重解析标签豁免只认 MOUNT_POINT/SYMLINK 两个)时, S_ISREG → 仅当 plan 声明 hardlink 形态且与新目标尺寸一致 (孪生残名的必要特征)才放行删除并照常重建; S_ISDIR → 沿用原目录支口径(非空拒绝/空则挪); 其余(意外真文件/云占位符真体/尺寸不符)一律 RuntimeError 留现场交 D20 重试路径。

验证: 红验两条(拒绝用例对未修代码 DID NOT RAISE; 云占位符用例对 tag == 0 判据红验后收窄标签豁免转绿); 放行族钉住孪生残名两分支(同卷保 hardlink / 跨卷回落 symlink)。测试数字: test_alias_fs.py 68 passed; test.full 全量 5626 passed, 2 skipped(覆盖率 99%, 2026-11-07 实测; 上一基线 5621, 本批 +4 用例, 另 +1 来自开工同步远端)。评审 1 条 minor(链接标签豁免过宽)当场修, review.check 过检 1/1。
