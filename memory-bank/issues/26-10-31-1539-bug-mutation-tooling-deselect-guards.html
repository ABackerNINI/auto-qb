01现象与发现场景

mutmut 会把变异体写进源文件, 「读源码文本做断言」的静态守阵在变异基线必红(整轮中断或判据被污染), 靠 set_conf.py 的 DEFAULT_DESELECT 表豁免。两条:

  1. 表缺条目: DEFAULT_DESELECT 只有 2 条旧守阵, 缺 W4-A 新增的 tests/test_traffic_store.py::test_v4_parse_skeleton_single_point(traffic_store 骨架静态守阵, commit 6b435638)——W4 轮实证该守阵击穿基线。
  2. 系统性缺口: 任何晚于该表新增的文本层守阵都会击穿基线, 而表没有提醒机制——表注释只写「报错时先核这里」(事后排障口径), 没有「新增文本层守阵时同步改表」的前置纪律或机械守阵。

05根因（可选）

默认「待查」—— 不为填单做分析。有结论才写；不确定就写已排除的假设，不要把猜测写成结论。

不是表逻辑错误，是「表与测试面的同步」没有机械约束：DEFAULT_DESELECT 是纯手写常量表，新增/改名「读源码文本做断言」的测试时没有任何守卫会提醒补 node id；失败又发生在变异轮基线（离改动时刻很远），提示信息也不指向该表 ⇒ 缺口只能靠人事后排障才发现。
  1. 表补 tests/test_traffic_store.py::test_v4_parse_skeleton_single_point。
  2. 机械守阵(方向): 扫描 tests/ 中读源码文本做断言的用例(如 docstring「静态守阵」标记/命名约定), 与 DEFAULT_DESELECT 对差, 缺了判红——把「报错时先核这里」变成 CI 层提醒; 或至少在 mutants.run 基线失败提示里点名 set_conf.py 表。
  3. 纪律兜底: 新增文本层守阵的收尾 DoD 加一句「同步核 DEFAULT_DESELECT」(mutation-testing skill 记录口径处)。

修复后补充

实际修法（三路，均在 .commands/mutants/ 命令包内，零 src/ 改动）：

  1. 机械守阵：scripts/test_mutants.py 新增 DeselectTableTest —— 逐条断言测试文件存在、node id 形如 <path.py>::<name>、文件内有 def <name>；测试文件拆分或函数改名即判红，失败信息点名「测试文件拆分后路径漂移，改 DEFAULT_DESELECT」。同一守阵覆盖新增的 FLAKY_DESELECT。
  2. 失败现场提示：scripts/mutants.py 的 cmd_run 基线失败 [FAIL] 分支追加一行，点名 set_conf.py 的 DEFAULT_DESELECT 与处置（把 node id 加进表后重跑）。
  3. 前置纪律：scripts/set_conf.py 表前写明「新增/改名任何读源码文本做断言的测试，必须同步把 node id 加进本表」；mutation-testing skill 硬约束 4 补同步核表与漂移兜底说明。

改道说明：建议修法里的「扫描 tests/ 自动检测所有读源码文本守阵」未采用 —— 现有守阵标记不统一（docstring 自称、命名约定、间接 read_text 混用），粗扫会把读静态资产/临时文件的用例大量误报，维护成本高于收益；本件选择「机械对差守阵（管已入表条目的漂移）+ 失败现场点名（管漏入表）+ 前置纪律」三路，满足建议修法允许的「至少在 mutants.run 基线失败提示里点名」路径。

验证方式：commands run test.pkg 全绿（含新增四组守阵）· commands run test.full 全绿（覆盖率闸 99 达标）· set_conf.py --print 自证输出同时含两类 deselect 的全部条目。实测数字只记在本轮基线切片（memory-bank/testing/baselines/26-11-02-0209-mutation-tooling-issues.md），本文不手抄。
