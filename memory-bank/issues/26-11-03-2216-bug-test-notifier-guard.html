NOTIFIER_EXECUTABLES 按命令名拦 powershell/pwsh: 非通知用途的子进程在 Popen 构造前抛 FileNotFoundError, sidefx 台账因此出现偶然遮蔽与假绿

01现象

测试期「真实副作用」的可见性失真：子进程只要命令名是 powershell / pwsh，会话级通知器守卫就在 Popen 构造前直接抛 FileNotFoundError（哪怕用途与通知完全无关）。该调用既不真实执行，也不会在 tests/sidefx.py 的台账里留下 POPEN 记录 ⇒ 同一用例 Linux 红、Windows 假绿。

  • 影响面：仅测试期（守卫只在 pytest 会话内安装），生产代码路径与真实运行行为不受影响。
  • 直接后果：Windows 本机/CI 的 sidefx 台账漏记这类调用，「本机全绿」不能证明「测试没有跑外部命令」。
  • 间接后果：排查 Linux CI 越界时容易误判成「Linux 专属 / xdist 竞态」，实际是守卫按命令名误拦造成的平台差异。

02位置

文件 + grep 关键词（比行号稳）；行号要标取证时间。

  • tests/conftest.py:89（取证 2026-11-03 22:16）· grep NOTIFIER_EXECUTABLES —— 集合只装命令名 {"notify-send", "osascript", "powershell", "pwsh"}，判别维度是「谁」，不是「用来干什么」。
  • tests/conftest.py:126（同）· grep _guard_run —— 命中命令名即抛 FileNotFoundError；抛点在 subprocess.run 的包装层，早于 Popen 构造，因此 sidefx 的 POPEN 记录器没有机会落账。
  • 被误拦的实例：src/auto_qb/infra/port_owner.py:203（同）· grep Get-NetTCPConnection —— 端口占用者探针的第二段 PowerShell 查询，与通知无关。
  • 本次实证（2026-11-03）：CI 报越界 POPEN ['ss','-ltnp']（Linux）；本机单跑 tests/test_web_admin.py::test_webui_module_start_raises_bind_error_when_port_taken 台账 POPEN 0 条，强制 Linux 分支后才复现同样越界 ⇒ Windows 的拦截确实落在 Popen 之前。

03建议（可选）

方向待定（二选一）：① 按用途判别 —— 只在通知器的「发送」入口拦截，不再按命令名拦 subprocess；② 按 argv 特征精确匹配 —— 仅当 argv 命中通知载荷形态才拦，其余 PowerShell 放行。

验收口径：构造一个非通知用途的 PowerShell 调用（如 Get-NetTCPConnection 查询）——修复前被误拦（抛 FileNotFoundError 且台账无 POPEN），修复后正常执行（台账记 POPEN 且结果可用）；同时原有「通知调用必须被挡住」用例仍须红，证明确实的通知路径没被放开。
