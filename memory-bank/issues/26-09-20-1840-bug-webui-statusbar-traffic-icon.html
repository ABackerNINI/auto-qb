01现象与发现场景

用户目视反馈（2026-09-20 18:38，非测试/非命令触发）：日常使用 WEBUI 读状态栏时，星图界面底部状态栏「今日流量」块里，前面的图标与后面的数值同一个颜色，一眼扫过去图标容易被当成数值的一部分。

叠加因素：数值本身带字面量 ↓ / ↑ 前缀字符，与前面的图形图标在视觉上连成一串；而该图标用的是柱状图 #i-chart，本身不是「流量 / 上下行」语义的真图标。

棱镜（prism）界面同一处有同样的问题，且用户明确说棱镜侧图标没有颜色（视觉上更弱、更不像图标）。与平台、主题、配置无关。

06建议修法（可选）

方向 + 候选方案 + 各自代价；没有想法就留「待定」，只写方案，不在本报告里实施。

待定 —— 图标选型与配色口径需用户定调，这里只列方向：

  • ① 今日流量图标换成语义明确的真图标（上下行 / 双向箭头一类），不再用柱状图 #i-chart（它更像「统计/历史」，与「完整统计」按钮也撞符号）。
  • ② 图标与数值配色解耦：图标走中性/faint 色或独立令牌，数值保留 down/up 语义色；同时考虑去掉数值里的字面量 ↓/↑，方向语义交给图标承担，从根上消除「图标像数值一部分」。
  • ③ 棱镜侧补齐配色，并确认两套皮肤（atlas / prism）在这一点上口径一致。

修复后补充

实际修法（走建议 ①②③，两套 UI 同步）：

  • ① 新增 sprite 符号 #i-traffic（上下行箭头：左箭向下 = 下载 / 右箭向上 = 上传，与右侧 ↓/↑ 数值同序），两侧 .sb-today 的图标改用它。
    改道：首版做成左右双向箭头，用户判「语义错误」（左右 = 传输/交换，不是上下行流量），19:00 改为上下行箭头； 19:05 再改为双色（两条 path 各自内联 stroke: var(--today-down / --today-up)， 与后面两个数值同族；颜色靠 CSS 变量穿越 <use> 影子树生效，外部选择器进不去） #i-chart 保留给「完整统计 / 历史流量」语义，两处注释同步更新。
  • ② 新增专用色位令牌 --today-ico（星图 :root 与棱镜五个主题各一份，取 --pink 族）， .ico-today 与 .sb-hist .ico 改取 var(--today-ico, var(--pink)) —— 带兜底值，即便某主题漏定义也不会掉回继承色（顺带覆盖棱镜"无颜色"）。数值色 --today-up/--today-down 不动。
  • ③ 数值里的字面量 ↓/↑ 已移除（19:05 用户追加要求）：改用 #i-arrow-down / #i-arrow-up 真箭头图标， 图标继承 .val 字色（与各自数值同族），.sb-today .val 改 inline-flex + 3px 间距。
  • ④ 棱镜侧数值与箭头图标仍是白色的真因（19:40 用户追加反馈）： .sb-today .v-* 与后面的 .sb-item .val 特异性同为 (0,2,0)， 后者靠书写顺序赢 → 掉回 --fg（白）。星图只是因为 .sb-today .v-* 写在后面才碰巧正确。改成 .sb-item.sb-today .v-*（(0,3,0)），两套同口径且与顺序解耦。
  • ⑤ “今日” 标签与后面 “连接 / 剩余” 对齐（19:40）：.sb-today 不在 .sb-stats 里， 吃不到 .sb-stats .lbl，字号与亮度都跟邻居不一致；改写成 .sb-stats .lbl, .sb-today .lbl { color: var(--fg-dim); font-size: 11.5px }（两侧同步）。
  • ⑥ 历史入口图标弃用粉色（20:04 用户追加）：--today-ico 改取 --lime （星图 :root + 棱镜五主题各一份，兜底同步）—— 该令牌现在只喂组内历史按钮，总图标已走双色。
  • ⑦ 速度 / 限速合成整组按钮（20:04 用户追加）：每方向改为 [方向图标] 速度 / 限速 一个 <button class="sb-spd">， 点图标 / 速度 / 限速任一处都触发 openSpeedAt（弹窗锚点取 ev.currentTarget，天然生效）； 不再单独给限速配图标（状态栏的仪表盘 #i-gauge 退役，右键菜单「限速…」等其它位置仍保留）； 随之删除已失活的 .sb-pair / .sb-limit 规则，"不限"只弱化限速值 .sb-spd.off .lim。
