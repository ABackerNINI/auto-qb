§01现象与发现场景

2026-11-07「整组迁移状态展示 v2」grilling 中拍板：路径列行级 A→B 两排展示（参照做种时长 HR 在线核实浮窗范式）。用户要求覆盖范围 = 所有有链接的种子，包括其它程序/用户自己设置的链接。但行级数据现状只有 auto-qb job 快照（member_relocate），外部 junction/symlink 链接行级不可知；而列表渲染有零触盘纪律，渲染期不能探测 → 缺一个行级数据源，需新基建。

先行方案（展示设计已拍板）：行级 A→B 先仅读 job 快照（零新基建）；本件落地后外部链接才进得了行级 A→B。

§05根因（可选）

不适用（feat 需求件，非缺陷）。已排除：① qB API 侧没有链接信息可用（save_path/content_path/root_path 均不暴露链接事实，无免费数据源）；② 外部逐文件硬链接行级可测 —— path 链不含硬链接（同 inode 孪生非路径链接），发现它需全树逐文件扫 nlink，探测成本爆炸，明确不进登记簿边界。

§06建议修法（可选）

主循环维护「链登记簿」（2026-11-07 grilling 拍板方向，落地前需立计划细化）：

  • 分片扫描：每 tick 探 N 个种子（起点派生与 probe_chain 同口径），全量一遍约几十 ms 摊进主循环；只跟 junction/symlink，复用环检测 + 跳数上限
  • 事件失效：save_path 变更（视图脏事件）即重探该种子；低频周期复扫兜底链接被外部改动
  • 快照发布：不可变 snapshot 只读引用给 Web（复刻 _publish_snapshot 模式），渲染期零触盘纪律不破、单一写线程不破
  • 登记内容（per hash）：链首尾端点（初始/最终位置）、跳数、是否含外部链接、auto/非 auto 归属章（供展示层区分着色与标注）
  • 边界：外部逐文件硬链接不进登记簿（见 §05 已排除②），只到 hover 浮窗/链浮窗按需探测
