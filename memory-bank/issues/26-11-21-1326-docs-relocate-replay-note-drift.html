§01现象

relocate_journal.py 的 settled 词表注记明说 unmatched「确定性无操作, 重放无意义」、member_gone「成员已删, 改写步跳过并按 settled 收口, 不再无限重试」，且 REWRITE_SETTLED_FROZEN 注记强调「把 member_gone 当已落账会误堵」；但既有重放闸 reset_rewrites 的重置判据用 REWRITE_SETTLED 全集（含 unmatched/member_gone）—— 核验不过触发重放时，这两类 settled 记录照样被清回 pending。注记口径与重放闸行为自证不一致（行为本身无害: unmatched 重放是确定性空转、member_gone 重放会再次 settle, 均收敛; 注记内部也有「缺失下窗重确认无害」的承认句, 但与「重放无意义」并陈, 读者无法判断哪个是权威口径）。存量行为, 与计划 26-11-20-0434 的改动无关, T4 实施时发现, 可独立小考。

§03建议（可选）

独立小考二选一: (a) 收窄 reset_rewrites 只清 rewritten/already（REWRITE_SETTLED_FROZEN 集, 语义 = 「已落账但未生效」才值得重放）, unmatched/member_gone 维持 settled —— 需核对 pending_members 消费面与既有重放测试（tests/test_relocate_exec_verify.py::test_step_verify_member_not_at_dst_hangs_and_replays 等）; (b) 保持全集重置, 在注记补一句「unmatched/member_gone 重置属无害重确认, 与『重放无意义』不矛盾（后者指改写动作本身无意义, 前者指账面重置收敛）」对齐口径。

实际修法（2026-11-23，采纳 (b)）：保持 reset_rewrites 的 REWRITE_SETTLED 全集重置行为不变（行为本身无害且收敛，改它属扩大范围），仅在 src/auto_qb/infra/relocate_journal.py 补注记消歧：
  • unmatched / member_gone 词表注记：「重放无意义」「不再无限重试」明确为只约束 daemon 改写步，不约束重放闸的账面重置；
  • REWRITE_SETTLED_FROZEN 消费方注记与 reset_rewrites docstring 同步点明：清回 pending 属下窗重确认（缺失即收缩复核），无害收敛、二者不矛盾；
  • 三处统一指向 REWRITE_SETTLED_FROZEN 注记「消费方按语义取用」句作口径单点，消除「读者无法判断哪个权威」的歧义。
