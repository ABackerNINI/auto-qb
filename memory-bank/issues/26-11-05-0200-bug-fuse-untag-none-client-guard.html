fuse release 摘标签路径缺 None-client 守卫(潜在, 现行接线不可达)

01现象与发现场景

覆盖率提升第三轮 T0b（fuse 家族补测）审查 fuse_mod.release() 状态机时发现:同函数内两条出口路径对 api.client is None 的防御不一致——限速写回侧有守卫安全降级,摘标签侧没有,会直接 AttributeError。当前为潜在缺陷:唯一调用方 CLI 的 fuse_release 先 manager.connect() 成功才进 release,connect 后 client 非 None,故现行接线不可达。

02证据

取证 2026-11-05(来源:第三轮 T0b 子智能体代码审查报告,commit 806f954b 时点):

fuse_mod.py:253  # release() 已显式预期 api.client 可能为 None, 降级为「只标记 released」
fuse_mod.py:265  # 限速写回侧: api.client is not None 守卫
fuse_mod.py:282-283  # 摘标签路径: to_untag -> _apply_tag_remove, 对同一 None client 无守卫
qbapi.py:76      # _apply_tag_remove 底层调 api.client.xxx, client 为 None 即 AttributeError

03影响面

维度结论
触发条件release() 在 api.client 为 None 时被调且 to_untag 非空(如未来新增内部调用方绕过 connect 直驱模块)
影响范围fuse release CLI 与任何未来直驱 FuseModule.release 的调用方; 不影响主循环相位(主循环另有依赖缺失早退)
严重度低(现行不可达; 一旦触发是未捕获异常而非数据损坏)

04定位锚点

  • src/auto_qb/core/modules/fuse_mod.py:282-283(取证 2026-11-05)· to_untag / _apply_tag_remove 调用点 · grep to_untag
  • 对照守卫:src/auto_qb/core/modules/fuse_mod.py:265 · grep api.client is not None
  • 底层触点:src/auto_qb/core/qbapi.py:76 · grep _apply_tag_remove

05根因（可选）

两条出口路径由不同轮次补测覆盖(写回侧先被测到故有守卫, 摘标签侧当时未被直驱), 防御补齐不齐——非行为回归。

06建议修法（可选）

照 265 行同款守卫给摘标签路径补 api.client is None 早退(与「只标记 released」同口径), 一行 + 一条直驱用例; 顺带核对 release() 其余出口是否还有同类不对称。
