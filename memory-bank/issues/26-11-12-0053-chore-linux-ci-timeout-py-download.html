§01现象

本机复现 Linux CI 的 test.linux 两处环境缺口(取证 2026-11-12, 修 CI 红测试时实测): ①引擎包装超时 900s 不够 —— 仓库 477M 走 Docker 共享挂载 cp -a /src/. /work/ 实测约 1MB/s(光拷贝 ~10 分钟), 加 uv sync + 全量 pytest 合计 ~15 分钟; 超时杀包装进程后容器成孤儿继续跑(docker run 客户端进程死、容器不随 --rm 退), 输出全丢。②默认镜像 python3.12-bookworm-slim 下, uv 因 .python-version=3.13 补下载托管 CPython(astral-sh/python-build-standalone, 源在 github), 容器内直连 github 超时(容器通 PyPI 200, github timeout) → uv sync 直接失败。

§02位置

  • .commands/test/config.toml [tasks."test.linux"] timeout = 900(取证 2026-11-12 00:53)· grep 关键词 test.linux
  • .commands/test/scripts/linux_ci.py INNER(拷贝 + uv sync 的容器内命令)、IMAGE = "ghcr.io/astral-sh/uv:python3.12-bookworm-slim"(取证同上)· grep 关键词 IMAGE = / cp -a /src(python-build-standalone 串只出现在 uv sync 失败输出里, 本仓代码无)
  • 根因侧: .python-version = 3.13 与默认镜像 3.12 不匹配, 是 ② 的触发条件

§03建议（可选）

临时绕法(本次已用, 未入库): 直跑脚本绕开 900s; 传参 ghcr.io/astral-sh/uv:python3.13-bookworm-slim 用 3.13 镜像免下载。正修方向: timeout 抬到 ~1800s、默认镜像改 3.13 或 uv 钉 --python, 孤儿容器按容器名/挂载源核验后回收。
