§01现象与发现场景

实施 issue 26-11-07-0527-bug-legacy-review4-hr #15（_history_lanes 改用 model 层 _as_int 容错）的批次评审中，评审子代理发现该注释声称的「兜住不抛」言过其实：_as_int 只捕 (TypeError, ValueError)，数值字段写 1e999（合法 JSON，解析为 inf）或裸 Infinity（Python json 默认接受）时 int(inf) 抛 OverflowError 穿透——读路径仍可整体抛错。属 model._as_int 约 30 处调用方共有的存量缺口，非 #15 批次回归（旧 int() 同样抛）；该批只把注释改如实，缺口按范围守恒入池。

§02证据

§03影响面

维度结论
触发条件站点文件数值字段为 inf/超大浮点（手改坏或外部工具写入）

严重度低（需文件被写坏才触发；触发时与「站点文件读坏时不抛」契约相悖）
