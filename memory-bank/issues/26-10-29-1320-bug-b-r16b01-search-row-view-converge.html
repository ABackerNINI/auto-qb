01现象与发现场景

搜索结果行由 search_torrents 的局部函数 _view 自己手建一份字典, 与分组成员行 _member_view 的字段构建是两份互不引用的同族实现; 后果有两层:

  • 量化口径分歧: 同一颗种子的 seeding_time, 在成员行/种子页走 view_field_value 分钟量化, 在搜索结果行是原始秒。
  • 字段集分歧(用户可见): 搜索结果行缺 eta / num_seeds / num_leechs / downloaded / availability 等 19 个字段。未归组的命中种子 在辅种页以"虚拟组行"兜底展示(filters.js::filteredGroups 的 searchUncovered 段), 展开该行的明细表用的就是这份行 —— 于是同一颗种子, 在种子页/真实组的明细里做种数、用户、剩余时间、 已下载、可用性都有值, 在搜索虚拟行的明细里这几列全空白(默认可见列, 非可选列)。

发现场景: 2026-10 全仓重复代码审查 B 类复核批次 D2, 逐项回查 R16-B01(search 行与 member 行构建近似) 与 R19-B01(量化口径两处) —— 两者同族, 合并为本条。

03影响面

维度结论
触发条件辅种页(groups 视图)输入搜索词 → 命中未归组种子(searchUncovered) → 展开该虚拟行。 未归组种子是常态(未进入任何辅种组、或文件列表尚未就绪), 无需特殊配置
影响范围只影响搜索结果行:_member_view / _seed_view / 组行聚合均不受影响; 搜索的匹配语义(hash 集合、by)不受影响 —— 差异只在行字段
严重度低(展示缺列, 无错值、无匹配错漏); 但属"同一份数据两处不同"的口径漂移, 且 docstring 已承诺对齐

量化口径一项单独看当前不可见: 前端 format.js::fmtDuration 按 Math.floor(sec/60) 出分钟, sec 与 sec//60*60 的分钟取整恒等(小时/天分档同理), 故 seeding_time 原始秒与量化值渲染文本逐字相同。唯一可观测的次生差异是 hr.js::hrTimeReached 用 seeding_time >= hr_req_time 本地比色 —— 落在 60s 内的边界会翻色, 仅限虚拟行。

05根因（可选）

行构造无单点: 搜索接口另建一份字段字典, 只"抄了当时用得上的字段"。 同一族的第三处(_seed_view)已于 issue 26-10-11-0310-refactor-webui-seed-view-restate-dup 收敛为 {**_member_view(r), ...} 并加静态守阵; 搜索结果行是漏收的一处。

已排除: ① 不是"故意的字段子集"—— 函数 docstring 明写"与分组成员视图对齐"; ② 不是性能取舍 —— _view 已经调用了 _site_alert / state_kind / _error_reason / hr_view_fields, 与 _member_view 的重活完全重叠, 真正差的是若干 O(1) 字段读取 + 一次 store.group_key 查表(该方法 docstring 已声明 Web 线程并发读安全)。

06建议修法（可选）

方向: 让搜索结果行 = 成员行 + by, 沿用 _seed_view 已确立的范式。

def _view(rec, by):
    return {**self._member_view(rec), "by": by}

代价与影响:

  • 字段集变为成员行的超集(新增 19 键 + by), 前端只读它认识的键 —— 纯增字段, 无破坏; 虚拟行明细的空白列随同一改动补齐。
  • seeding_time 变分钟量化: 渲染文本恒等(见 §03), 唯一变化是 hr.js 本地比色 在 60s 边界上取量化值 —— 与成员行/种子页此时的行为一致, 属于"分歧消失"而非"新分歧"。
  • 每命中一行多算一次 store.group_key(dict 查表)+ 若干字段读取; 搜索本就对全库逐条构行, 增量可忽略。
  • 顺带把 docstring(views.py:1099-1102)的"完整明细字段"改为指向 _member_view, 不再手抄字段清单。

验证手段:

  1. 新守阵(静态 + 动态, 复刻 tests/test_web_seed_center.py:162 的 test_seed_view_no_member_view_restatement): _view 字典字面量不得显式重述 _member_view 的键; 同一记录下两侧同名字段值等值; 搜索结果键集 ⊇ 成员行键集(仅多 by)。
  2. 既有搜索语义用例全绿: tests/test_web_hr.py 的 test_search_torrents_*(name_match / cross_row_and / negative_term / facet_rows / phrase / ..., 断言的是 hash 列表与 by, 与该改动正交)。
  3. e2e 冒烟(可选): 辅种页搜一颗未归组种子 → 展开虚拟行 → 做种数/用户/剩余时间/已下载/可用性有值。

相邻但不在本条范围: 虚拟组行组级列(做种时间/进度/剩余/可用性/最近活动)仍空白 —— 那是 filters.js:233-248 只搬了少数字段, 属前端聚合口径, 与本条后端字段集同因不同点; 本条修完不自动覆盖, 是否入池另行判断。
