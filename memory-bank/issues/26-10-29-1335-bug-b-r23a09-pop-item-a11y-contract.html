01现象与发现场景

同一个可点击行原语 .pop-item 被三种浮层复用，但可访问性契约是三套，且其中一套整段缺失： 五个 combobox（添加种子窗口的保存路径/分类/标签、设定位置 movePath、编辑弹窗 metaCat）已经是同一组件 <aq-combo-input>，键盘高亮靠 hi 索引 + .on/data-hi 自绘， 却没有 role="combobox"/listbox/option、没有 aria-expanded、没有 aria-activedescendant —— 读屏用户按 ↑↓ 时听不到「当前第几项、选中什么」，面板开关状态也不播报。

同族另外两处各自一套：列选择器项是 role="button" + tabindex + aria-pressed， 但只响应 keyup.enter（Space 无反应，与筛选器项不一致）；UI 切换项是 <a href> 导航语义， 但当前项只靠 :class="{ on }" 上色，没有 aria-current。

发现场景：2026-10 重复代码审查 R23-A-09 的 B 类复核（本轮重新核查），在 src/auto_qb/webui/static/shared/tpl/ 逐处比对四类 .pop-item 调用点。注：审计当时是五处各自复写；本轮 26-10-20-2230 已把 combobox 骨架收敛成单组件，故修复面从五处缩到一处（本项因此比审计当时更值得做）。

03影响面

维度结论
触发条件纯键盘 + 读屏操作任一 combobox（必然）；列选择器里对项按 Space（必然无反应）；UI 切换面板打开后无法得知哪项是当前值（必然）。鼠标用户不受影响。
影响范围5 个 combobox 调用点（dialogs-mgr.html:49/70/83 保存路径/分类/标签、move-dialog.html:36 movePath、popovers.html:55 metaCat，均经 <aq-combo-input> 继承同一份模板）+ 顶栏列选择器 + 顶栏 UI 切换；右键菜单族（ctx-menus.html）目前无任何键盘入口，属更大缺口但见 06 的分步建议。
严重度中 —— 无数据错值、无静默改配置；纯辅助技术不可用（WCAG 4.1.2 Name/Role/Value、2.1.1 Keyboard 的实际不合规面）。

05根因（可选）

三套不是"谁抄错谁"，而是三条不同交互路线的历史演进产物（项可聚焦的多选、自绘高亮的 combobox、导航链接）， 但从未把判据写下来：菜单式 / 选择式 / 导航式各该有哪几个属性、键盘该由项还是容器处理， CSS 段头与模板注释都没有一句。于是每加一处浮层都按"就近抄一份"决定，combobox 那一路直接零 ARIA。 已排除：不是 data-hi 没生效（视觉高亮正常，见 atlas/css/dialogs.css:213）， 也不是焦点样式缺失（:focus-visible 两个 UI 都有）。

06建议修法（可选）

第 1 步（本件主干，收益最大、风险最低）—— combobox 补 ARIA，只改一处组件： 输入框加 role="combobox" + :aria-expanded="menu" + aria-autocomplete="list" + :aria-controls（面板 id，可由 inputId + '-pop' 派生）+ :aria-activedescendant="hi >= 0 ? optionId(hi) : null"； 面板加 role="listbox" + 与上面同 id；候选项加 role="option" + :id="optionId(i)" + :aria-selected="i === hi"。id 用 inputId + '-opt-' + i 由索引派生即可（同一帧内 options 是渲染源， 过滤后索引与视觉序一致；不需要把值编进 id）。预置行（:66 的 "(无分类)"）不参与键盘索引，给 role="option" 反而不对， 建议保持不可选语义（或标 aria-hidden 让读屏忽略其可点性）。五个调用点零改动即可继承。

第 2 步（同族口径补齐，各一行）：列选择器项补 @keyup.space.prevent（与筛选器项完全同款 handler， 行为不变）；UI 切换项补 :aria-current="o.id === ui ? 'page' : null"（不改视觉，只补状态）。

第 3 步（把判据写下来，防第四次漂移）：在 shared/tpl/combo-input.html 头注（已有大段契约注释，续写一段即可） 或 atlas/css/components.css 的 .pop-item 段头写三分类判据： 菜单式（.ctx-item，项可聚焦 + roving）／选择式（.pop-item 于 combobox，容器 listbox + aria-activedescendant）／ 导航式（<a href> + aria-current）。新增浮层按此对号入座。

明确不做（重开条件）：ctx-item 右键菜单整族键盘化（Shift+F10 / 菜单键入口 + roving tabindex）—— 它是另一条独立能力缺口（入口本身只有 @contextmenu，见 lifecycle.js:224-225）， 与本件的"口径三套"不同量级。重开条件：若后续需要键盘操作右键菜单，另立一件，本件的三分类契约正好是它的判据底稿。

验证手段：① 静态守阵（本项目既有范式，加进 tests/test_webui_static_dom_panel.py）： 断言 combo-input.html 含 role="combobox"／role="listbox"／aria-activedescendant／ aria-selected，且候选项的 :id 与 aria-activedescendant 用同一 id 生成式； 断言列选择器项同时含 @keyup.enter 与 @keyup.space.prevent（防只补一处）。 ② 真浏览器比对：Chrome DevTools → Accessibility 树，展开任一 combobox 面板应看到 combobox 节点 + listbox 子树，按 ↑↓ 时该节点 activedescendant 属性随 hi 变化（这是"等价性"的直接证据）。 ③ 回归面：纯视觉零变化（本件不碰 CSS 与布局），跑既有 pytest tests/test_webui_static_dom_panel.py tests/test_webui_static_dom_page.py -q 即可。
