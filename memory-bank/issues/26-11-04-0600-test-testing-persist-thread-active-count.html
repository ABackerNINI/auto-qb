01现象与发现场景

2026-11-04 05:53 与 05:57 在 Windows 本机连续跑两次 commands run test.full（仓库根全量，pytest-xdist 并行），两次都在同一条用例判红；同 HEAD 下把该用例单独跑则通过。触发场景是「全量 + 并行」：用例断言 threading.active_count() 在采样前后不变，失败值为 3 == 4（采样后 3、采样前 4），方向是「有线程减少」而非产品新增线程。

该用例本身验证的黄金法则 5（单写线程：批量落盘发生在调用钩子的线程内、模块不建线程），与产品功能无直接关联；红的是门禁稳定性。

06建议修法（可选）

待定（以下候选均未验证）：

  • 候选 1：断言从「全局 active_count 快照相等」改为「采样前后线程集合的差集里没有本模块新建的线程」，允许无关线程自然退出；代价是用例断言实现更复杂。
  • 候选 2：为该用例加 xdist 串行/独占标记，降低同 worker 上其它用例线程启停的干扰；代价是全量耗时增加。
