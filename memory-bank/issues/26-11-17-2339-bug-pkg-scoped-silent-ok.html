§01现象与发现场景

skill 可移植性改造批6 收尾时发现：test.pkg.scoped wrapper 在受影响包集合为空时不跑 pytest, 直接返回 rc 0, commands 引擎输出 [ok] (0.0s) —— 与「实跑并通过」在输出上不可区分, 反馈语义误导。批6 场景里工作树有未提交改动时也出现过跳过实跑但报 ok, 当时疑似「按已提交 diff 判定受影响包」（根因未查实, 见 §05）。

§02证据

取证 2026-11-17 23:39, HEAD eff52f0a：

$ commands run test.pkg.scoped        # 裸调(零包), 实测:
[ok] test.pkg.scoped (0.0s)           # 未跑 pytest, rc=0

$ grep -n "if not pkgs" .commands/test/scripts/pkg_scoped.py
48:    if not pkgs:
49:        return 0

注（入池者注, 非工具输出）: 49 行裸 return 0 —— 零包静默 rc 0, 无提示行。

机制面事实: wrapper 本身无任何 git 调用, 只消费 argv（闸门经 <changed:...> 喂参）; 闸门侧 changed 清单来自 git status --porcelain -uall（staged+unstaged, gate.py:61-62）—— 该口径包含工作树未提交改动。批6 观察到的「脏树仍跳过」具体走的是哪条路径未查实。

§03影响面

维度结论
触发条件wrapper 收到零包 argv（裸调, 或闸门 <changed:...> 展开无匹配时）
影响范围提交闸门的测试收窄反馈: 「跳过」与「实跑通过」输出相同, 人读反馈失真
严重度低-中（不漏真实闸门 —— 闸门无匹配本应整条跳过; 害处是反馈语义误导）

§04定位锚点

  • .commands/test/scripts/pkg_scoped.py:48-49（取证 2026-11-17 23:39, HEAD eff52f0a）· 符号 main · grep if not pkgs
