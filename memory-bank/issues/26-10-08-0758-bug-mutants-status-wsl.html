05根因（可选）

默认「待查」—— 不为填单做分析。有结论才写；不确定就写已排除的假设，不要把猜测写成结论。

已定位(2026-10-08 09:50 复验时确认): WSL 里 bash -lc 的登录壳实为 zsh($0=/usr/bin/zsh), zsh 的 $PWD / 内建 pwd / 相对路径解析走的是**逻辑目录**, 而 cd 只更新真实 cwd 却**没同步逻辑 PWD**; 于是 $() 子壳里的相对路径按**启动目录**解析。判别: 同一脚本里 pwd(内建, 走真实 cwd —— 实测反而对)与 echo "$(pwd)"(子壳, 报启动目录)不一致。已排除的假设不变(镜像路径 / 工具未装 / Windows 路径)。

影响 cmd_status 里**三条**取相对路径的行: mutmut=$(test -x .venv/bin/mutmut …) · mutants=$(du -sh mutants …) · head=$(git rev-parse …)(前二恒失真, 第三条在 cd 未生效时也会读到别处的 HEAD)。cd X && cmd 直连形态全程正确 —— 这就是修法。

06建议修法（可选）

方向 + 候选方案 + 各自代价；没有想法就留「待定」，只写方案，不在本报告里实施。

把 cmd_status 里所有「$(...) 取相对路径」的写法改成 cd {mq} && <直接命令> 形态(与 cmd_run 一致), 例如逐条 echo 改为 cd {mq} && test -x .venv/bin/mutmut && echo yes || echo no; 或统一改用绝对路径($HOME/...)参与 $()。

修复后补充

实际修法（采纳建议修法第 1 项，未改道）：.commands/mutants/scripts/mutants.py 的 cmd_status —— 把四条 echo X=$(…相对路径…) 全部改成 cd {mq} && <直接命令> 形态（与 cmd_run 一致），单次 wsl 调用内多条 cd {mq} && … 并列，**保持一屏回显**（不拆成多次 wsl 调用，避开候选代价里的 ~0.45s/次固定开销）。绝对路径方案未采纳：改动面更大且要保证 _bq() 展开后的路径不再进 $()，不如直连形态直白。
