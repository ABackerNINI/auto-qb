01现象与发现场景

RM04 漂移复测轮(计划 plans/26-11-01-2033)新增真机用例 RM04-09(qbapi facade share_limits_mode 的 5.2.3 端到端, 本路径首次真机覆盖): WebUI 命令线 POST /api/torrents/{hash}/share-limits 下发 ratio/seeding_time 两维具体值, 回执恒 status=error, 文案「qB 拒绝执行: 缺少必需参数：shareLimitAction」; qB 侧两维限值零变化。环境2(qBittorrent 5.2.3, 副实例 56590)实测, 与平台无关 —— qB 5.0+ 的 torrents/setShareLimits 端点把 shareLimitAction 列为必填(库 docstring: Web API v2.10.4 引入), facade 从不传它。

03影响面

维度结论
触发条件任何 WebUI 种子分享限制命令(set_share_limits: 右键/详情/批量入口共用的命令单点); qB ≥5.0(实测 5.2.3 必现, 5.3.x 按同一必填语义大概率同炸)
影响范围WebUI「分享限制」写侧面整条失效(回执 error, qB 侧零生效); 跳检重加(torrents/add 线)不受影响(RM03-15..17 真机绿); 既有单测 test_qbapi_wire.py 只守 wire 形态不验 qB 必填语义, 故全绿假阴性
严重度中 —— 功能整体不可用但无数据损坏; 属 fbaf0446(qB 5.3 双版本支持)声称覆盖的面上, 且非 fbaf0446 引入: 旧库 2026.8.1 同款缺省 None, 本缺陷在库升版前已潜伏, 首次真机覆盖即暴露

04定位锚点

  • src/auto_qb/core/qbapi.py:197 torrents_set_share_limits(取证 2026-11-01 21:02)· 符号 torrents_set_share_limits · grep share_limits_mode —— facade 只补 share_limits_mode="Default", 从不传 share_limit_action
  • src/auto_qb/webui/commands.py _cmd_set_share_limits(同上)· grep share_limits_mode="Default" —— 命令层调用点
  • .venv/Lib/site-packages/qbittorrentapi/torrents.py:294/437 · 符号 share_limit_action · grep shareLimitAction —— 库缺省 None + None 值键不上线

05根因（可选）

facade 层(qbapi.torrents_set_share_limits)假设「5.2 对未知参数免疫 = 只需补 shareLimitsMode 即可双服」, 漏了 qB 5.0(Web API 2.10.4)起 shareLimitAction 是**必填**参: 库缺省 None 被丢弃 → 请求体缺参 → qB 400 → 命令层包成「qB 拒绝执行」error 回执。已排除: 库升版回归(2026.8.1 同款缺省)、qB 5.2 忽略语义失效(400 是必填校验, 非未知参报错)。

06建议修法（可选）

facade 补 share_limit_action: str = "Default" 显式发参(与 share_limits_mode 同一手法: 缺省 None 不上线, 显式 "Default" = qB 全局动作, 5.2/5.3 同义), commands.py 调用点透传; test_qbapi_wire.py 补一条「shareLimitAction 在体」守阵。修后 RM04-09 转绿即验收(用例已就位, tests-real/rm04_relocate/test_rm04_relocate.py test_rm04_09)。
