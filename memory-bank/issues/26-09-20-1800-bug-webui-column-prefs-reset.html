01现象与发现场景

用户在日常使用 WebUI 时反馈（2026-09-20 18:00 口述，不是本次任务撞见、未复现）：表格的列顺序、列显隐、列宽三类偏好会被重置回默认布局，不是每次都发生，而是"经常"。

  • 被重置的对象 = 列偏好三件套：colOrder（顺序）/ colHidden（显隐）/ colWidths（宽度），外加 colManual（该页是否手动调过宽度）标志；四个表格页各一份（group / detail / torrent / show）。
  • 触发条件（2026-09-20 18:2x 用户确认）：同时开多个标签页；单标签下"刷新 / 重开程序"没问题，换地址 / 换浏览器未测。用户平时用固定地址（书签 / 手输）打开 —— 基本排除"origin 隔离"那条已知限制。
  • 是否与浏览器/平台相关：未知。存储走 localStorage，私隐模式、配额满、多标签页互相覆盖都可能参与。

05根因（可选）

默认「待查」—— 不为填单做分析。有结论才写；不确定就写已排除的假设，不要把猜测写成结论。

已确认（2026-09-20 18:2x 真浏览器复现）：多标签页整份覆盖（last-writer-wins，无跨标签同步）。
已排除：假设 2（读入被洗净）、3（自适应覆盖）、4（v3→v4 迁移）—— 单标签六条路径全保持，且新标签能读到最新存储；假设 1 的"写失败"也排除（localStorage 有值且被正确读出）。

机制（不是猜测，是实测）：

  1. 每个标签在页面加载时把存储读进内存（app.js:273 initialColState），之后内存就是一份独立快照。
  2. saveColState()（columns.js:318）写的是整份 {widths, hidden, manual, order}，不是"我改的那一段"。
  3. 于是：哪个标签最后动一下，整份存储就变成它的快照 —— 先改的那个标签的改动被静默吞掉。这是"后写赢"，不是随机。
  4. 同一个标签内改同一个表必然命中：用户在 A 标签调好列 → 去 B 标签（A 改动前就开着）顺手点一次列 → A 的设置全没。

次生问题（同一根因的另一面）：另一个标签的改动不会反映到当前标签，用户会以为"改了没生效"，再改一次 → 又是一次整份覆盖。

06建议修法（可选）

方向 + 候选方案 + 各自代价；没有想法就留「待定」，只写方案，不在本报告里实施。

方向已定（详细计划见 docs/plans/ 本轮计划文档；本报告不实施）：

  1. F1 写入改 read-modify-write：saveColState() 写前先读回存储，以存储为底、只覆盖本次操作涉及的那一个 page 的 widths/hidden/manual/order 四段，其余段取存储最新值（6 处调用点都能给出 page）。挡住“两个标签几乎同时写”的竞态。
  2. F2 监听 storage 事件做跨标签同步（关键）：别的标签写了 COLS_STORE_KEY → 当前标签整份采用存储值 + $nextTick(materializeColumns)。
    ❗ 只做 F1 不够：用户两个标签里改的通常就是同一个表（辅种页），F1 的 page 级合并在同表冲突时仍然“后写赢”；只有让每个标签的内存态保持新鲜（F2），后续写入才不会再吞掉别人的改动。
  3. F3 visibilitychange 补漏：已有监听的 !document.hidden 分支加一次 adopt —— 覆盖“标签被冻结 / 事件丢失”。
  4. F4 冒烟：scripts/ui_smoke.cjs 加一条“双标签各自改列互不吞”（复用本次复现脚本的双页流程）。
  5. 不做：服务端化（用户已明确只存浏览器）、冲突提示弹窗（过度设计）。

二次修复（2026-09-21，宽度段）

为什么第一次没修干净：第一次修的是"多标签整份覆盖"，它治好了显隐与列序。但宽度还有一条独立通道 —— colManual[page] 为假时，colWidths[page] 是 materializeColumns 按当前窗口算出的自适应快照，不是用户偏好，却照样被落盘 ⇒ 谁最后操作，存储就变成谁那个窗口算出的 px。

真机实测(用户真实实例 38080/atlas, A 窗 1600 / B 窗 1200):
R2  A 只改显隐(不拖宽)   内存 229px / 12 键   存储 0 键
R3  B 也只改一次显隐     存储变 210px
R4  A 刷新              229px -> 210px        ← 宽度变成 B 窗口算的
    (显隐保住 ✓ · 拖过宽的页 300px 全程安全 ✓)

修法（两处成对，缺一不可）：

// ① shared/columns.js :: saveColState(page) —— 写侧: 非手动页不落 px
if (!this.colManual[page]) payload.widths = { ...payload.widths, [page]: {} };

// ② shared/app.js :: loadColState() —— 读侧: 非手动页不读 px
if (!out.manual[page]) out.widths[page] = {};

② 不是可选项：只改写侧的话，浏览器里已存在的污染 px 仍会被读出来，刷新后还是旧值，修复会"看起来没生效"。⚠ 光把"先存后算"改成"先算后存"不够 —— 顺序改了存储拿到的仍是最后操作那个窗口的值。

验证：污染 210px → 刷新后按当前窗口重算 231px 且填满容器（表头 1576 / 容器 1576）；manual=true 的 336px 跨操作保住；守阵经红验（整行注释掉必须 FAIL）；全量 1134 passed；冒烟 52 项失败 2 项，均为既有议题「P0-3 乐观态及时落回真值」（与列偏好无关）。
