01现象与发现场景

在实施计划 26-10-07-2127 的 S2(三端点接线+窗首种子) 中发现: 设计决定 D3 的「窗首种子跨真空(程序停机)时由 v4_series_points 既有真空判定自动断链」在一条 1 秒宽边界带上不成立。

场景(raw 段窗 1m-24h): S2 把 read_window/v4_series_points 的 t0 外扩一个响应桶宽 seed_t0 = grid.t0 - grid.interval 取前驱桶点作差分基线。若停机时刻恰落在 (seed_t0-1, seed_t0) 这 1 秒带、且恢复块落在窗内: 真空 null 点的时间戳 int(prev_chain_end) 取整后 = seed_t0 - 1 < t0, 被返回流的窗过滤(if t0 <= t < t1)丢弃 —— 于是返回流里种子点与恢复首点之间看不到 null 断链标记, 差分链被误接, 离线期 qB 自行传输的字节被误归到恢复首桶, 出一个假尖峰。

发现方式: S2 实施期读码推断(非测试撞见); S2 未写复现用例, 复验时需构造该 1s 几何。

修复后补充

实际修法（与「建议修法」不同，改道原因见下）：core/traffic_grid.py 新增模块常量 _V4_NULL_FLOOR_S = 1（null 点标记时间取整的最大下偏，秒）；v4_series_points 内 null_lo = t0 - _V4_NULL_FLOOR_S，把真空 null（int(prev_chain_end)）与断连 n 槽 null（floor(ts)）两处窗过滤下界由 t0 放宽为 null_lo。区头「窗口」注释同步。

  • 为什么 1 秒即完整：种子点保留 ⟺ ceil(prev_chain_end) >= t0 ⟺ prev_chain_end > t0-1；标记被丢 ⟺ int(prev_chain_end) < t0 ⟺ prev_chain_end < t0。两条件交集恰为 prev_chain_end ∈ (t0-1, t0)，取整后标记恒 = t0-1。带外（prev_chain_end <= t0-1）种子点亦被滤，恢复首点本就无基线，无假尖峰路径 —— 故下界放宽 1 秒不多留也不少留。
  • 无输出面副作用：null 点恒不外发（v4_grid_obs 跳过），多留的标记只影响链断位置；真空与断连两处过滤点同款取整下偏一并覆盖。
  • 改道原因：原「建议修法」① 「按原始窗 t0 判保留」方向相反（原始窗 t0 > seed_t0，会更严而非放宽）；② 「种子只喂差分基线、不参与 null 过滤」语义不清。实际采「取整下偏容差」—— 与种子点保留带精确对齐，纯读侧一行语义改动。

验证方式：① 复现脚本（纯函数）先红后绿；② 新增守阵 tests/test_traffic_grid.py::test_v4_seed_vacuum_null_t0_edge_band_chain_break（纯函数 1s 几何 + 带外对照）与 tests/test_web.py::test_api_traffic_qb_raw_seed_vacuum_null_1s_edge_band（端点面，时钟钉死使 1s 几何确定），两条逐条红验：临时置 _V4_NULL_FLOOR_S = 0 复现红（端点实测恢复首桶 dl=300/up=150、totals 9000），还原复绿。
