§03影响面

维度结论
触发条件test.quick / test.full 默认 -n 8；多个 worker 在同一轮里首次调用 bundle_file(同一 name)，共享同一实例临时根并写同一固定路径。偶发：同一棵树 3 次全绿 / 2 次红，Windows 下更敏感。
影响范围所有经 tests/webui_helpers.bundle_file 落临时脚本的 node 电池用例（test_webui_static_r4_static_batteries.py、test_webui_static_r4_drawer.py 等）；表现层是 ship.commit 的 test.quick 闸门假红 —— 提交被拦或推送未完成，需人工诊断后补推。
严重度中。不改产品行为，但每次假红逼出一次全量重跑（约 60-125s）；更麻烦的是它与真回归同形，反复「重跑即绿」会钝化闸门信号，有掩盖真回归的风险。既有同类先例：issue 26-10-16-0348（端口竞态误拦一次 ship.commit）。

§04定位锚点

写「符号名 + grep 关键词 + 当时的行号（标取证时间）」—— 代码会漂移，靠符号与 grep 重新定位，行号只是加速项。

  • tests/webui_helpers.py:373-381（取证 2026-11-08 19:54）· def bundle_file · grep aqb_js_bundle_ —— 写死 tempfile.gettempdir() + 固定文件名。
  • tests/webui_helpers.py:370 · _BUNDLE_FILES 进程内缓存 · grep _BUNDLE_FILES —— 每个 worker 各持一份缓存，因此每个 worker 都会各自去写同一路径。
  • tests/test_webui_static_r4_static_batteries.py:918 · bundle_file("shortcuts.js") · grep bundle_file（第一次红的调用点）。
  • tests/test_webui_static_r4_drawer.py:57-69 · _run_probe / assert proc.returncode == 0 · grep node 电池跑挂（第二次红的断言）。
  • memory-bank/pitfalls/testing/tmpdir.md「xdist worker 同根」· grep 同根 —— 实例临时根由 tests/_tmp_bootstrap.py 自举、同一次运行的 worker 共用，是「共享路径」这一事实的口径来源。

§05根因（可选）

默认「待查」—— 不为填单做分析。有结论才写；不确定就写已排除的假设，不要把猜测写成结论。

入池时为待查推断（2026-11-09 已证实，见本节末段；下段保留当时的推断链）。已排除：① 本批 AST 守阵改动（只新增 1 个测试文件与知识库文档，不碰前端静态资源、临时根或 webui_helpers）；② 合流的远端 7 笔提交引入前端回归（两个失败文件单跑全绿、合流树独立全量全绿）。
推断链：_tmp_bootstrap 让同一次运行的 8 个 xdist worker 共用同一个实例临时根，而 bundle_file 把路径拼成不含 worker 标识的固定名；两个 worker 同时 open(path, "w") 在 Windows 共享语义下可抛 PermissionError，或某个 worker 读到别的 worker 尚未写完/内容不同的文件，使 node 探针 returncode != 0 触发断言。_BUNDLE_FILES 是进程级缓存，不能跨 worker 去重，反而保证每个 worker 都会各自写一次。

2026-11-09 已证实（不再是推断）。Linux（WSL）复现：4 写 4 读各 4000 次，共享路径读到空/半文件 1600+ 次/读；换 mkstemp + os.replace 原子替换后 0 次。CI 那次的形态也坐实「读到空文件」：报错栈 <anonymous>:5:34 ⇔ new Function(src + …) 的 src 是空串（实测 100 行 src 报 :104:34），即 fs.readFileSync(process.argv[1]) 拿到 0 字节，与 JS 逻辑无关。

§06建议修法（可选）

方向 + 候选方案 + 各自代价；没有想法就留「待定」，只写方案，不在本报告里实施。

方向：让 bundle 临时路径按 worker 唯一（或彻底不落共享路径）。候选：

  1. 路径掺 worker 标识：文件名加 PYTEST_XDIST_WORKER 或 os.getpid()。改动最小（bundle_file 一行），代价是临时文件数随 worker 数增长，需纳入实例根清扫。
  2. 改用 tmp_path / tempfile.NamedTemporaryFile(delete=False)：逐次唯一、pytest 收尾自动回收。代价是要改 bundle_file 签名并逐个改调用点（test_webui_static_r4_*.py 多处）。
  3. 原子替换 + 只读加载：先写 .pid 临时件再 os.replace。代价是 Windows 共享语义仍要处理，实现最复杂，且要额外守阵证明不再竞态。

另按 memory-bank/testing/flaky-ledger.md 先归因登记（flaky / 恒红候选的登记单点），重跑不是修复；改完需红验（注入并发写或固定同路径反复跑）并用 test.quick 复跑验证。本件只记录方案，不实施。

修复后补充

实际修法：取 §06 候选 ①，但标识用 os.getpid() 而非 PYTEST_XDIST_WORKER（后者在非 xdist 串跑时不存在，pid 恒可用）。tests/webui_helpers.py::bundle_file 落点改为 aqb_js_bundle_<pid>_<name>，各 worker 只读写自己的文件，跨进程零争用。

同类一并收口：同一形态另有两处（评审发现）—— tests/extension_proxy_support.py::background_bundle 的 aqb_background_bundle.js（经 trace 辅助被 test_extension_proxy_page_fetch.py 的多条用例调用，同文件内用例被 xdist 分到不同 worker，并发面与本次同级）与 test_webui_static_r4_node_batteries.py::test_r4_load_col_state_seeding 的 aqb_app_head_for_probe.js，均已掺 pid；两处 helper 各配守阵（test_bundle_file_is_process_private / test_background_bundle_is_process_private），head 探针在用例内联断言 pid。

改道说明：候选 ③（os.replace 原子替换）实测能消掉 Linux 竞态（1600+ 次坏读 → 0），但 Windows 下替换正被别的进程打开的目标会抛 PermissionError —— 只是把一种偶发红换成另一种，故不采用；候选 ②（改 tmp_path）要动签名与多处调用点，收益不抵改动面。

验证方式：新增守阵 test_bundle_file_is_process_private（pid 入文件名 + 内容 == read_shared(name)），摘掉 pid 当场红（红绿双验）；tests/test_webui_static_r4_static_batteries.py 以 -n 8 复跑全绿；全量数字见基线切片（commands run kb.baseline）；doc.caps 与 kb.check 通过。坑档沉淀在 memory-bank/pitfalls/testing/parallel-run.md「共享实例根下的聚合脚本」条。
