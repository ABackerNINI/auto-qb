§01现象与发现场景

优雅停 38s issue(26-11-18-2350)的静态排查顺带发现(2026-11-19): 计划 26-11-18-0259 S0 真机取证轮的产品日志里, 每轮启动后约 0.7s 固定出现一条流量快照 WARNING, 且失败路径为空串。测量派生配置(tests-real/.work/s0boot/config.yml)没有 traffic_source 段: source_enabled 对缺段按「未配置」处理恒 True, provider 缺省落 traffic_monitor, dat_path() 取 traffic_monitor.dat_path 得 "" —— 空路径被原样塞进 open()。生产默认形态(未配流量来源)同理。

契约原文(paths.py docstring, 取证 2026-11-19): 「dat_path(config) → 当前生效来源的 dat 文件路径(空 = 取不到; 调用方决定报错口径) —— 取数唯一入口」; tool_dat_path: 「指针缺失/字段空 -> ""」。即空串是合法返回值, 报错口径归调用方 —— 而 refresh() 没有实现这半边契约。

§05根因（可选）

调用侧缺分支: paths.dat_path() 的空串契约只写了「调用方决定报错口径」, refresh() 未特判 if not dat_path, 空路径与「文件真丢了」共用 dat_missing 一套文案与 code —— 缺的是消费侧分支, 不是 paths 层语义。

§06建议修法（可选）

方向: refresh() 在 read_source_rows 前特判空路径 —— 不读盘, 发布 source=stale + 专门 code(如 source_missing); 人读文案复用现成单点 paths.unavailable_reason()(paths.py:100, docstring「让运行期报错直接指到该改哪里」, 已被 rules/expr/env.py:198 复用 —— 不另造第二份文案口径; 该分支实际只覆盖「未配置/GTM 指针缺席」两形态, 关源在 refresh() 入口 :228 已提前 return), 日志降 DEBUG 或改为一次性 WARNING。备选(不推荐): paths 层返回三态结构区分「关源/未配置/有路径」 —— 改契约面, 波及曲线模块等全部调用方, 收益不成比例。
