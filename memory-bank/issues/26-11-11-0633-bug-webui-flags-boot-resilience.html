§01现象与发现场景

会话在归因 26-11-11-0134-test-e2e-traffic-gap-zones-load-flake(e2e 测试竞态)时顺藤读到一个生产行为面的相邻事实: boot 期 loadWebFlags() 对 /api/webui/flags 是单发请求、无重试, 且 flags 初值恒为 fail-closed(false/null)。请求一旦偶发失败(网络抖动/代理超时/服务端瞬时错误), catch 分支把四个键全部写回 false/null —— 此后无自动恢复: 跳检菜单项、qB 口径流量页签、整组迁移常驻提示全部静默消失; 用户侧恢复手段 = 刷新页面重新触发 boot 期请求, 或设置页保存一次触发重拉(config_editor.js:230,232 保存成功后重调 + 2s 补拉, 见 §02 调用链)。

本 issue 是生产行为变更建议, 与 0134 的测试竞态面是两件事(0134 的取证脚本里"flags 延迟即确定性复现同形态"恰好反证了本条后果的真实性, 但修的对象不同)。

平台/配置无关: 纯前端行为, 任何后端瞬时不可用都会触发; 触发概率低但后果持续整个会话。

§03影响面

维度结论
触发条件boot 期(登录/bootstrap)对 /api/webui/flags 的那一次请求失败或超时即触发; 设置保存后的补拉(config_editor)失败同样落入, 但概率面主要是 boot 期
影响范围跳检菜单项不渲染、Ctrl+\ 打开流量图只弹「功能未启用: qB 口径流量图」toast(fail-closed 点在 qb_traffic_chart.js:582, gate 581-583 openQbHistory 内; Ctrl+\ 经 shortcuts_engine.js:704 _kbToggleQbTraffic → openQbHistory)、详情面板流量页签消失(页签切换 Alt+5 路径 toast 在 shortcuts_engine.js:455 同文案)、设定位置对话框不出「整组迁移已启用」提示、ctx_menu 退回默认布局 —— 直到用户侧恢复(刷新/设置保存重拉)前不自愈
严重度中: 不丢数据、后端端点 403 兜底仍在(fail-closed 语义保住了安全面), 但真实用户在单次偶发失败后整个会话失去功能入口, 且没有任何提示指向原因, 只能靠刷新碰运气恢复

§05根因（可选）

默认「待查」—— 不为填单做分析。有结论才写；不确定就写已排除的假设，不要把猜测写成结论。

机制明确(非待查): 请求单发 + 初值/兜底同为 fail-closed, 两者叠加把「一次偶发失败」放大成「会话级功能缺失」—— 失败后没有任何后续拉取时机, 而 flags 的全部消费点都以 false/null 为"功能未启用"的判据, 用户侧无法区分"没开"与"没取到"。

§06建议修法（可选）

方向 + 候选方案 + 各自代价；没有想法就留「待定」，只写方案，不在本报告里实施。

候选方向(仅方案, 不在本报告实施; 任一修法都是生产行为变更, 需走计划/拍板流程):

  • 有限重试: boot 期失败后按短退避重试 N 次(如 2-3 次, 间隔 1s/3s)。代价最小, 但仍非确定自愈(持续故障期错过窗口仍落入)。
  • 惰性补拉: 失败置一个"flags 待取"标记, 下次任一功能入口交互(开抽屉/右键)时先补拉一次。自愈最及时, 改动面在消费路径, 需防并发重复请求。
  • 区分"未启用"与"未取到": flags 增加 loaded 态, 未取到时入口处给可重试提示而非静默隐藏。交互语义最诚实, 但涉及 v-if 门控重构, 面最大。

取舍与是否修由 issue 侧决定; 无论选哪条, 后端 403 兜底与 fail-closed 安全语义必须保持不变。
