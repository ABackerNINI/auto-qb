01现象与发现场景

修复后补充

实际修法（用户 2026-11-10 显式指派「认领并真修全部 4 组」，覆盖本文原「只展示不修、等排期」拍板）：① gtm-alert 给 reload 后等轮询落地的 expect.poll 显式 20s，断言仍严格 toBe(ts) —— 修的是默认 5s 等待窗口不足，不是放宽断言；② perf W5 注入 window.__tickT0 与 window.__pollMs = vm.basePollMs()，拍数上界由固定 <=3 改为 ceil(elapsed / pollMs) + 1，从测量层消掉「交互窗恒 4.4s」的假设（600 种子档真实节拍 1500ms，旧注释写 2000ms 亦已订正）；③ kbd-scroll-band 改产品侧 _kbScrollRowIntoView：抽 reveal() 按真实 DOM 矩形校正，revealWhenRendered(deadline) 在 1s 时间窗跨帧重试到目标行渲染，修窗口化重渲晚于 $nextTick 时旧码静默放弃滚动；④ drawer-general-variants / menus / optimistic 同步 76deeb7d 复制 magnet 入口下线后的过期断言（改钉「入口不得回潮」而非删断言），并给 BASE_PATCH 补 content_path / download_path / root_path 三个非空路径值，对齐 26-11-08-1621 的「值非空才 wide」口径。

验证方式 / 测试数字：env -u TMPDIR -u TEMP -u TMP commands run test.full 全绿（实测数字见 kb.baseline / 基线切片 26-11-10-0121，205.90s，TOTAL 99%）；静态守阵 test_kb_view_band_single_points 1 passed；目标 e2e：drawer 4 / gtm 2 / kbd 6 / perf W5 2 / menus 2 / optimistic 2 全 passed；6 个 JS 文件 node --check 全过；两分片并行回归 222 例各有 1 条无关偶发红，串行单跑分别 2 / 6 passed。分批评审两轮：轮 1 两条 major（硬编码 2000ms 与真实档不符、单次 rAF 仍会扑空）当场修完，轮 2 零 actionable。
