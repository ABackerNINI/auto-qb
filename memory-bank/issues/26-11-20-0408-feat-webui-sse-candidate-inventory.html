§06建议修法（可选）

共同纪律：复用一次性票据 / 心跳 / 满额 503 退轮询；事件只带小真值或信号；带单调 seq，断档与静默走全量重拉 + 低频对账；发布点只在主循环线程（沿用活尾快照模式）；高频专用通道优先于扩 /api/events 枢纽；不加配置键。

优先级功能当前机制推送化形态 / 代价
P0（已立项）流量图 raw 段窗 1m-24hstartPoll("qb:*")，节拍 = meta.sample_interval_s（生产 1.5s）计划 26-11-18-0037 的专用 /api/traffic/qb/stream + seq + 30s 对账 + 503 兜底；收益是尾端无持有失真与毫秒级管线，前端重写面大（R1），需后端前端同提交硬切。agg(3d+)不动。
P1后端错误日志 / 通知中心setInterval 60s 拉 /api/errlog?after=后端已有 err_log_since(after) 与 seq 环；新增 errlog 事件推增量，60s GET 降为对账。载荷极小，重启 seq 归零逻辑可复用；前端需去重与未读计数接线。
P2长任务两段回执（relocate 探针 / transfer 验证）受理后 waitCmd 与轮询赛跑，等单段终态复用 cmd 事件补发终态/进度，payload 带 cmd_id 由前端过滤（现网 notify 是广播）。相关方向已在计划 26-11-10-2350 D8 / 26-11-20-0127 D5b 拍板，实施前先与计划合流，避免重复立项。
P3抽屉详情 trackers / peersstartPoll("drawer") 按主节拍 1.5/2/3s 直拉「变化才推」可免空转，但上游 qB 自身有 1s/2s 缓存，推送快过缓存无收益；建议等 P0 的 per-scope 通道落地后复用其纪律再评估。

明确排除：主列表 /api/state 全量推送（已是 ver 驱动 + delta + 轮询兜底，优化空间仅 60ms 去抖）；search_rev 自动刷新（随每轮 status 回传，不额外发请求）；FX 时钟 setInterval、限速托管 loadSpeedMode、web flags / 快捷键加载（本地时钟或一次性取数）；批量添加种子（瓶颈在服务端 qB 管线）；流量图 agg 3d+（计划 D4 明确不动）。
