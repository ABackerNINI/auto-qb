01现象

HR 两张表的行键面（闭集断言）在两个文件各手写一份全量字面量：history 行 23 键（test_hr_status.test_history_rows_field_surface ↔ test_web_hr:307）+ entry 键面（test_hr_status:246 ↔ test_web_hr:140）—— 后端加字段须同改两处，漏改即两守阵口径分叉。

02位置

文件 + grep 关键词（比行号稳）；行号要标取证时间。

  • tests/test_hr_status.py（539 与 246 附近）· tests/test_web_hr.py（307 与 140 附近）（取证 2026-10-21，基线 cecbe4a9；grep assert set(row) == {）

03建议（可选）

键面常量收 webui_helpers 单点（如 HISTORY_ROW_KEYS / ENTRY_ROW_KEYS），两个闭集断言改引同一常量 —— 守阵语义不变，单点声明。

04实际修法 / 验证

按建议修法落地，但复验实测修正了两处口径：

  • history 实为 22 键（ts … by），不是摘要里的 23；两侧逐字相同 ⇒ 共用一个 HISTORY_ROW_KEYS。
  • entry 面两侧本就不同集：test_hr_status 断言 EntryDetail.to_dict()（模型面 20 键），test_web_hr 断言端点响应面（21 键，多 local_present，由 server/routes/hr.py::mark_local_present 响应层 join 追加）。硬套单一常量会抹掉这条差异 ⇒ 拆两层：ENTRY_ROW_KEYS + ENTRY_ROW_KEYS_API = ENTRY_ROW_KEYS | {"local_present"}（改道原因：保留「响应层只多这一个只读标记」这一事实）。
  • 三常量落在 tests/webui_helpers.py 的 HR 段；刻意不从 dataclass 派生——EntryDetail.to_dict = asdict(self)，派生会让「实现」与「期望键面」同步漂移，守阵失效。
  • 四处断言改引常量：test_hr_status.py（history 行 / entry 行）、test_web_hr.py（history 行 / entry 响应行）。lane 子键面与 SiteStatus 键面首轮未动，R1（同档案续作）已一并收单点：HISTORY_LANE_KEYS（7 键，两处去重）、SITE_STATUS_KEYS（39 键，原本只有一处，收进同一常量模块 —— 单点声明，无去重收益）。LaneStatus（14 键，波次级）与 QuotaStatus 仍就地，不在本条范围。

验证方式：① 探针——临时给 EntryDetail 加 probe_extra 字段，两处闭集断言同时变红（2 failed），还原后归绿 ⇒ 守阵语义未因收单点而削弱；② 全量闸门 commands run test.full 全绿，实测数字见 commands run kb.baseline（本轮新切片；本件不抄数字）；③ 档案 memory-bank/tasks/26-10-22-test-hr-row-key-surface-dup.md。
