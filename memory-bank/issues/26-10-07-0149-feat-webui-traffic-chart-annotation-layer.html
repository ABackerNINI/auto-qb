修复后补充

实际修法（与 §06 建议修法同向，但落点从「13 变体」扩到共享图面 —— 用户拍板，改道原因见下）：不走「暴露 uPlot 实例给 13 变体、插件整体放变体文件」的窄口径，而是直接把注解画进建图管线 —— hooks.drawClear 画缺口斜纹（在系列之下）、hooks.draw 画限速虚线（在系列之上），三挂点 + 经典/所有变体一次全生效，且不需要对外暴露实例（净改动面反而更小）。画布口径（读 vendor 源码确认，非猜测）：uPlot 1.6.32 的 ctx 不设 transform、坐标是设备像素，故新增 _qbCanvasScale 统一 ctx.scale(uPlot.pxRatio) 转 CSS 像素后按 u.bbox/pxRatio + valToPos(v, scale) 定位；色值走建图时读到的令牌（tk，与系列同源），不硬编码。缺口游程抽成模块级纯函数 _qbGapRuns（上下行皆 null 才算缺口）。限速虚线只画落在可视值域内的限速（0 < 限速 < yMax）—— 自动模式下峰值未超限速时线在顶沿之上、自然不画（用户拍板「自动模式最大值超过限速才画」），固定模式下恒画；一条判据覆盖两态，不写模式分支。0（不限速）/null（未知）一律不画。

改道原因：本件原为详情面板重构计划 P-03 的「13 变体」备选；本次与「流量图纵轴固定模式」同批实施时用户拍板注解层归共享图面（三挂点全生效）—— 限速虚线正好标注「限速+20%」的基准，两件事同源；且画布绘制天然属于建图管线，放变体文件反而要额外暴露实例。

验证方式 / 测试数字：新增守阵 tests/test_webui_static_dom_panel.py::test_frontend_qb_traffic_yaxis_and_annotation（含 _qbGapRuns 与 _qbYRange 两组 node 真跑电池）+ 接线/持久化/模板/CSS 成对静态锚；红验三次（去掉峰值保底 / 摘 drawClear 钩子 / 断 y range 接线）均按预期变红，还原复绿。test.full 2772 passed + 4 skipped / 0 failed / 48.44s / TOTAL 99%（基线切片 26-10-08-0559）；旁证 npm run test:e2e:fast 8 passed（含「渲染健康: Vue 挂载成功…无运行时错误」）+ 真浏览器加载 vendor 与组件跑注解钩子自检零 pageerror、带钩子画布比不带多 9,870 个已绘制像素。13 变体自身的 KPI 限速文字格保留（其展示的是单种限速，与本次「全局限速」口径不同，属两件事）。
