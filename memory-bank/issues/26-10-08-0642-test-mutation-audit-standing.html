01这个锚是干什么的

项目已有 98% 分支覆盖闸, 但覆盖率量不出测试的强弱: 两个「公认覆盖良好」的模块实测出 10 与 70 个存活变异; rules/ 与 infra/utils.py 覆盖率是同一个 98%, 变异分数却差 17 个点(55.5% vs 72.5%)。变异测试补的就是这个刻度 —— 详见可行性报告 26-10-08-0231。

这条锚只回答两件事: 要不要继续做、覆盖到哪几个包了。它不记流水(轮次记录在任务档案与基线切片), 也不替真洞背书(每个确认的真洞各自入池)。

四段职责(每段只在一个工位有权威): ①排期锚=本 issue(要不要做 / 什么时候做 / 覆盖到哪) → ②派生计划=memory-bank/plans/(针对某个包怎么修) → ③执行一轮=mutants 包(跑 + 手工确认) → ④记录=基线切片 + 任务档案 + 真洞各自的 issue。

02为什么不进提交闸门

维度结论
节奏按包一轮 1–21 min(实测 rules/ 7m31s); 全项目 ≈ 79 min。是审计信号, 不是放行条件
工具硬要求基线全绿才开跑(不绿直接跳过), 与提交闸门「先绿再提」的时序冲突
已有闸门98% 分支覆盖已挂在 pytest.ini; 再叠变异分数只会拖队, 且追不平(等价变异杀不掉是数学事实)
分母不可比no tests(无覆盖)与 survived(有覆盖没杀掉)是两类; 两个工具分母不同, 分数只能各自纵向比

03覆盖范围与节奏

粒度是「一个包」或「一个模块」 —— 全项目一把跑不可行(实测在 37% / 74% 两处把 WSL 打挂, 要 wsl --shutdown 才救回), 按包切是硬要求而非偏好。

优先级(按「判据密度 × 出错代价」, 不是按行数):

  1. rules/ —— 规则引擎判据, 实测 3,270 变异 / 杀死率 55.5%(分数最低, 最该先补)
  2. hr/ —— HR 判定与做种要求链路
  3. config/ —— fail-fast 校验
  4. core/ —— 主循环 / 限速

infra/ 与 webui/server/ 估值最低(IO 胶水层, 变异多为等价或平凡杀死)。入场练手用 infra/versioning.py 或 infra/utils.py(流程已跑通, 成本低到跑错再跑一次无所谓)。

节奏建议: 每周 / 每个 Release 前挑 1 个包; 季度做一次逐包累加(不要一把跑)。「全量」= 逐包跑完, 不是一次跑完。

04怎么跑

命令一律走 task id, 不要手抄命令本体(会被 commands run doc.drift 判红):

task id干什么
commands run mutants.setup建 / 刷新 WSL 镜像仓 + 装工具(首次或镜像落后)
commands run mutants.run -- --target '<glob>' --pool <测试文件...>主力: 对某包 / 模块跑一轮 mutmut
commands run mutants.gremlins -- --target <文件> --pool <测试文件...>Windows 侧兜底 / 交叉验证
commands run mutants.status回看镜像状态与上一轮未杀死条数

用法与陷阱用 commands show mutants.run 取; 深读在包内 references/why.md。硬约束(按包 / 定向池 / forkserver / deselect / -n 0 --no-cov / --max-children 4)已内建在脚本里, 正常路径不用手工拼。

05一轮的标准动作

  1. 入场: 基线全绿(commands run test.quick 过) —— 不绿先修, 别跑变异。
  2. 定目标与池: 一个包 / 模块; 池 = 直接相关的那几个测试文件。
  3. 跑一轮: mutants.run; 记下变异数 / 杀死率 / 耗时 / 工具版本 / 选择池。
  4. 三分类存活变异 → 真洞 / 等价变异 / 假存活(这是人的动作)。
  5. 手工确认: 对每个疑似真洞, 在全套件下改造同构变异, 看红不红 —— 只认这个判据。
  6. 处置: 真洞 → 各自入池或当场补断言(补完 test.full); 等价变异 / 假存活 → 记一笔理由。
  7. 复跑: 同目标同池, 看存活数是否下降(换池的数字不可比)。
  8. 记录: 新建基线切片 + 任务档案追加一行轮次; 本 issue 不动(除非改覆盖范围)。
别把存活清单当缺口单: 窄池下的存活相当比例是「相关测试不在池里」的假存活 —— 实测同一 utils.py 只换池, 存活 97 → 70; 判据与处置见坑档 mutation-pool-artifact.md。
