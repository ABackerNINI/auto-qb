复验

复验：2026-10-31 10:18 根因仍在（认领后以代码锚点复验，当期 HEAD 4c4edd20）。_autostart 成功路径只做 installer 注册/卸载 + config autostart 回写，全程不触碰发现指针；指针 autostart_registered 的唯一写点仍只有 start() 现货态探测 —— 与根因结论逐字一致。注：入池时的真机桩测现场为一次性环境已还原，未重跑真机复现，以代码事实为准。

修复后补充

实际修法（采纳建议修法①）：_autostart 成功路径（config 回写之后、响应之前）新增 _patch_endpoint_autostart()：读现有指针，autostart_registered 以现货态探测结果改写（与 start() 同一探测口径），整份原子写回 —— 指针与真值即时一致，UI 开关不再漂移到重启。两点与建议原文的偏差，均已注明理由：

  • autostart_error 一并清空：控制面操作成功后，启动期失败原因已过时（install 成功 = 已补救；uninstall 成功 = 已无注册可言）。同族过时字段，同一写点顺手一致。
  • 指针缺失时静默幂等不补写（patch 不是 create）；读/写失败只 WARNING 不阻断 200 响应（与 §09/S12 同口径）。⚠ Windows 平台事实：open() 对「父路径是文件」也抛 FileNotFoundError（POSIX 是 NotADirectoryError），异常类型区分不了「指针缺失」与「路径组件异常」—— 处置：两种形态一律静默，可观测的读失败（坏 JSON → ValueError）走 WARNING。已记坑档 pitfalls/backend/platform-fs.md。

验证方式：新增回归三案（tools/global-traffic-monitor/tests/test_server.py）：①uninstall 后指针 autostart_registered 即时 false 且其余字段（port/pid）原样保留；②install 后即时 true 且启动期 autostart_error 清空；③指针损坏（坏 JSON）只 WARNING 不阻断 200 + 指针缺失再开关不报错不补写。
