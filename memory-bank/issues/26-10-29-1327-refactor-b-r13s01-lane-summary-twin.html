01现象

同一个「各档波次摘要串」在两处各实现一遍：hr/service.py::_lanes_summary_from（刷新结果，CLI 刷新命令用）与 hr/status.py::_lane_statuses 里的 parts（站点状态快照，CLI 状态命令 + webui 用）。两处都在遍历 FETCH_LANES、拼 档:标记N页M行(深度)/声明N 对不平，但文案与回落规则已分叉：深度标记一侧 (全深度)、一侧 (全)；状态标记一侧用字典透传未知值、一侧用三元静默降级成 -。

03分歧点与判定

  • 深度标记字面：(全深度) ↔ (全)。同一布尔两种标签，且都出现在同一 CLI 的不同子命令里 —— 无判据支持。
  • 未知档位状态回落：service 侧 dict.get(status, status) 原样透传（将来加 LANE_PARTIAL 会直接打印 partial）；status 侧三元 else 分支一律 -（静默降级）。当前三值域 {""/"ok"/"failed"} 下等价，扩展路径已分叉。
  • 计数段：两侧都是 /声明N + 对不平，字面一致；差异只在 status 侧把深度标记放在 claim 之前 —— 属排版顺序，不属事实差异。
  • 缺档：两处都输出 lane:无，一致。
  • detail / 连续失效波：只有 status 侧 verbose 串有；紧凑串不展示属有意取舍，不算分歧。

判定：(b) 无判据漂移，该合（限「部件」层，不合并排版）。两处算的是同一事实（wave.lanes 的一行摘要），没有任何注释/文档写明「刷新命令说全深度、状态命令说全」是有意区分；hr 与 hr status 对同一波次给出不同深度标签即是漂移的可观察证据；tag 回落一侧透传一侧静默降级更无判据。不归 (a)：未发现「紧凑 vs verbose」之外的正当分叉（verbose 串本就单独存在，不参与本项收敛）。不归 (c)：无错值、无报错，未达「用户可见缺陷」的 bug 门槛。

04收敛建议与验证

抽「部件」不抽「排版」：在 hr/status.py（或 hr/model.py，取决于依赖方向）落三个单点 —— LANE_TAGS = {LANE_OK: "[x]", LANE_FAILED: "x", LANE_IDLE: "-"}、FULL_DEPTH_TEXT = "全深度"、以及一个 _lane_count_segment(st) -> str（/声明N + 对不平）。_lanes_summary_from 与 _lane_statuses 的 parts 各自保留现有排版模板，只改读这三个部件。深度标签统一取 (全深度)（与 verbose 串、webui 详情一致，须同步改 test_hr_status.py:663/705/1006 的期望串）。未知状态统一用 LANE_TAGS.get(status, status) 透传 —— 若维护者更愿静默 -，须把该选择写成常量旁的一句判据，二选一，不允许两侧各写一套。

验证手段：① 新增 tests/test_hr_status.py 同族用例，构造同一 wave fixture，断言 service._lanes_summary_from(data.wave.lanes) 与 _lane_statuses(...)[1] 在 tag / 深度 / 计数三部件上逐项一致（现实现红、收敛后绿）；② 既有 :663/:705/:1006 期望串的改动本身即等价性证据（除深度字面外逐字不变）；③ 静态判据：src/ 内 "[x]" 映射与 /声明 拼接各只剩 1 处（可做成 grep 型断言）。

收益：6 行重复拼装收成 1 份，加档位状态 / 改深度文案只动一处，顺手消掉两命令文案不一致；风险：低 —— 纯展示层，唯一不可见行为 delta 是「未知状态回落」二选一，无数据面影响。
