01现象与发现场景

W2–W4 三轮 core/ 变异审计累积的 mutants 工具链坑 3 条(档案 R26/R27/W4 均「待入池」注记, 本件合并建账)+ R29 轮补充形态 1 条(2026-11-01 追加)。共同点: 都直接打击 mutants.verify 判定的可信度或造成误判, 与生产代码无关:

  1. mutmut 单文件轮清注册表 → 跨目标 verify 恒 APPLY_FAIL: mutants.run 每轮先 rm -rf mutants mutmut-cache.db, 该目录是 mutmut 的变异注册表, 单文件轮把其它目标的注册表一并清掉; 换目标直接 verify 时 mutmut 找不到变异体 → APPLY_FAIL。且 verify 对 APPLY_FAIL 只计数不自动续跑(收尾提示「重跑同一命令会自动重试」只提 TIMEOUT/FLAKY/UNKNOWN), 未判定会静默堆积。实证: R26(grid 16 条因注册表被清改走手工同构机械化, tmp-analysis/mut-core-w2-classify.md)。
  2. mutmut dump 伪 hunk 行号 + /mnt 空读假成功: dump 的 @@ 行号相对源码漂移, 拿它直接 git apply 大偏移搜索恒失败; 可靠做法=按 dump diff 定位唯一匹配行后整文件 post-image cp(S4 通道演进终点)。另: WSL /mnt/* 偶发空读使 GNU patch 静默 rc=0 假成功, apply 结论须以 post-image 通道复跑为准。实证: R27(档案「遗留/待入池」a/b 两条)。
  3. 全套件 flaky 集污染 verify 差集判据: relocate / web_views_reload / commands_engine wrapper / hr_discovery 绑定类用例随机红, verify 判据「新增失败 − 基线」会把这些当击杀信号。现有「复跑复现」门槛(FLAKY 判定)已挡掉误判——W4 S4 五条首轮记 FLAKY、复验全部落定未虚增假存活——但 verify 前仍须 deselect, 否则每条候选多一轮复验开销且日志噪声大。实证: R27(遗留 c)+ W4 S4(tmp-analysis/mut-core-w4-classify.md §S4)。
  4. WSL VM 死亡窗口内 _ensure_mirror 把 test -d .git 失败误判为「镜像缺失」→ 尝试 git clone 重建(R29 补充, 2026-11-01): WSL VM 被 OOM 杀掉的窗口里任何 wsl.exe 调用都失败(Wsl/Service/E_UNEXPECTED),_ensure_mirror 的存在性探测 test -d {mirror}/.git 拿到非零返回码即判「镜像缺失」走重建分支 —— WSL 不可达 ≠ 镜像缺失。R29 S4 轮 WSL VM 反复被杀 30+ 次,该误判路径多次触发,克隆均未遂(镜像核验完好: head 3275c1d4 / pytest 9.1.1 / timeout_multiplier=2 / mutants/ 注册表俱在),本次未造成实际损坏,但一次克隆成功即会毁掉整个专用镜像(含注册表与本地 pyproject/venv 钉版),属高危误判路径。实证: R29(tmp-analysis/mut-core-w5-classify.md §S4 环境事件实录 1)。

03影响面

维度结论
触发条件①单文件轮之后换目标跑 verify; ②拿 dump 的伪 hunk 行号做 git apply 或经 /mnt/* 走 GNU patch; ③基线/池含 flaky 用例时跑 verify; ④WSL VM 死亡(如 OOM)窗口内启动/续跑任何 mutants 命令(_ensure_mirror 探测误判)。
影响范围mutants 命令包的 verify 判定链(APPLY_FAIL 堆积 / apply 假成功 / 差集污染多跑复验 / 专用镜像被误判缺失而重建), 不涉 src/。
严重度中 —— 不修则每轮 verify 结果可信度打折; 现有 FLAKY 复验门槛已兜住最坏的「假 KILLED」误判; 形态④的克隆一旦成功会毁专用镜像(注册表+钉版全失), 幸未遂但路径在高危侧。

05根因（可选）

默认「待查」—— 不为填单做分析。有结论才写；不确定就写已排除的假设，不要把猜测写成结论。

四条形态都是「判定链缺前置校验/缺状态区分」，不是同一个根因，但共享同一处代码面：
  1. ①注册表：mutmut 的变异注册表就是镜像里的 mutants/（按 id 落 *.meta），而 cmd_run 每轮无条件 rm -rf mutants mutmut-cache.db（为避开「0 files mutated」提前收工），该清理对所有目标生效；cmd_verify 不核注册表存在性，且旧完成的 id 集合把 APPLY_FAIL 当成「已判定」跳过 ⇒ 未判定静默堆积。
  2. ②apply 通道：把 mutmut dump 的 diff 当成可直接应用的补丁 —— 其 @@ 行号相对源码漂移，git apply 大偏移搜索必失败；/mnt/* 偶发空读使 GNU patch rc=0 假成功。判据缺「以 post-image 复跑为准」的最后一环。
  3. ③flaky：差集判据「本次失败 − 基线」本身正确，但池里含随机红用例时每条候选要多跑一轮复验才能落定 FLAKY；跑前未 deselect 只是开销与噪声，不是误判根因（复跑复现门槛已兜住假 KILLED）。
  4. ④镜像探测：_ensure_mirror 用 test -d {mirror}/.git 一个布尔量同时表达「WSL 可达」与「镜像存在」—— WSL VM 死亡窗口里任何 wsl.exe 都非零，于是「WSL 不可达」被误读成「镜像缺失」并进入 git clone 重建分支。
  1. verify 入口先核目标注册表存在性, 缺了提示「先跑 mutants.run 该目标」或自动补跑, 不让 APPLY_FAIL 静默堆积; 收尾提示把 APPLY_FAIL 一并列入「未判定」。
  2. apply/dump 通道统一走「dump diff 定位唯一匹配行 → 整文件 post-image cp」, 弃 git apply 直 apply 与 /mnt/* patch; 两路结论不一致时以 post-image 为准。
  3. flaky 集落成 deselect 常量表(与姊妹件 mutation-tooling-deselect-guards 的 DEFAULT_DESELECT 同一张表维护), verify 前自动带上。
  4. _ensure_mirror 探测失败先区分「WSL 不可达」与「镜像缺失」: 先跑一条平凡 wsl.exe 探测(如 wsl echo ok), 不可达即 fail-fast 提示稍后重跑, 不进重建分支; 重建前若镜像目录已存在, 先做内容核验(head/注册表)再决定 clone。

修复后补充

实际修法（四形态一一对应，均在 .commands/mutants/ + mutation-testing skill 内，零 src/ 改动）：

  1. 注册表预检 + APPLY_FAIL 归入未判定：cmd_verify 开跑前查镜像 mutants/**/*.meta（grep 前提为 find mutants -name '*.meta' -print -quit），缺失即 Fail 并提示「先跑 mutants.run 该目标再 verify；单文件轮会清掉其它目标的注册表」；新增 UNDETERMINED_VERDICTS=("APPLY_FAIL","TIMEOUT","FLAKY","UNKNOWN") 与纯函数 _done_ids，未判定不进完成集（续跑自动重试），收尾提示补列 APPLY_FAIL；cmd_run 清理前打印「该清理会一并清掉其它目标注册表」的警告。
  2. apply 通道固化为 post-image：references/why.md 新增「S4 手工通道：dump diff → 整文件 post-image」小节（按 dump 定位唯一匹配行 → 取整文件 post-image cp → 以 post-image 复跑为准），并写明禁 git apply 直 apply 与 /mnt/* patch；排障表补「换目标 verify 全 APPLY_FAIL」「APPLY_FAIL 不再自动跳过」两行；skill 坑段加指针。
  3. flaky 集落到共享表并自动 deselect：set_conf.py 新增 FLAKY_DESELECT（6 条已实证 node id，与 DEFAULT_DESELECT 同表维护），--deselect 默认合并两类；_suite_cmd 自动从 FLAKY_DESELECT 派生 --deselect，verify 前无需手工带；DeselectTableTest 对两张表统一做条目对差守阵。
  4. WSL 可达性与镜像存在性分离：_ensure_mirror 先跑 echo ok 探 WSL 可达性，非零即 Fail（提示 VM 可能被杀/OOM，稍后重跑）且不进入 clone 分支；随后按三态处理——目录不存在才 clone、目录在但 .git 缺失则停手不覆盖、正常则按需 refresh；新增 EnsureMirrorTest（mock WSL）覆盖四路径。
