01现象与发现场景

计划 26-10-31-0306(种子转移)真机验收发现: 主 qB 配置(QbittorrentConfig)有 api_key 字段(qB 5.x Web UI API Key, 经 Authorization: Bearer 直连、跳过密码登录), 而转移目标(TransferTargetConfig)只有 username/password —— 只发了 API Key 没给密码的目标实例无法通过 test_connection/add_torrent 鉴权(空密码登录 401)。本次验收因此只能做 36595(api_key, 主)→ 36596(本机免鉴权, 目标)单向。

02证据

实测(2026-11-01 02:10, 双实例 qBittorrent v5.2.3):

POST /auth/login (username=&password=) -> 401            # 36595, 空密码被拒
GET  /app/version (Authorization: Bearer qbt_...) -> 200 # 36595, Bearer 直连可用
qbittorrent-api Client(host=..., username/password=None) -> LoginFailed  # adapter 现状对 36595

03影响面

维度结论
触发条件目标 qB 只配置了 API Key(WebUI 选项), 未提供/不知道 WebUI 密码
影响范围转移目标连通面; 与主 qB 连接的凭据能力不对齐
严重度低(有密码时不受影响; 属能力补齐)
