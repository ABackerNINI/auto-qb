01现象

journal 实际有两个写者(guardian 进程 + auto-qb 主循环), 与 relocate_journal 模块头注「两个进程永不写同一份文件 ⇒ 不需要跨进程锁」的事实前提相反;write_journal 是整包 last-writer-wins 无前向合并(读侧 _step_reconcile 有前向合并, 写侧没有)。auto-qb 写入的终态相位若落在 guardian 一次循环的「读 → 心跳写」间隙(毫秒级, 但心跳每 10s 一次、armed 态可能等数月)即被覆盖回 armed: guardian 看不到退休指令, 取消迁移后 qB 持续在跑 ⇒ guardian 永久每 10s 写心跳 + 持 pid 锁(僵尸进程), 且 job journal 终态被回退 —— 对账面相位失真。数据权威在 state.json, 无数据危害。

来源: 第二次全项目 code review(报告 memory-bank/reports/26-10-30-0237-report-full-code-review-2.html)批GH 条目 GH-01, P3; 复验留待认领时做。
