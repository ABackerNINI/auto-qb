流量卡「启用」开关恒显启用且无法保存: aq-fold 缺 ce 透传, hub-field 注入到空 cfg 树

aq-fold 未按既有范式透传 ce, 折叠段内 hub-field 注入到带空 cfg 树的组件实例: 字段只显 schema 默认值、编辑不进根树。磁盘 traffic_source.enabled=false 时开关恒显「启用」, 拨动不脏树、「保存并应用」不出现, 重启无效

01现象与发现场景

生产实例（schema v5、traffic_source.provider: global_traffic_monitor）跑 WEBUI，在「流量与限速」卡点「关闭工具」后：磁盘与运行时的 traffic_source.enabled 正确变为 false（日志见 §02），但卡片上「数据来源」区的「启用」开关仍显示开启；把开关往「关闭」拨不产生未保存改动，「保存并应用」按钮不出现；F5 刷新、重启 auto-qb 均无效；工具也无法从 UI 重新拉起，只能手改 config.yml 恢复。

手工把 traffic_source.enabled 改成 false 再启动，GET /api/config 响应里该键确实是 false，界面仍显示「启用」——服务端真相与界面相反，且同一页面里顶部横幅（$root.tmSourceOff()）正确显示「流量来源已关闭」，与开关自相矛盾。

03影响面

维度结论
触发条件凡经 <aq-fold> 渲染的 <hub-field>（即折叠段内的字段）全部中招，与具体配置无关——默认折叠的 object 段展开后必现
影响范围设置页所有可折叠段：流量卡三区（数据来源/限速曲线/流量图采样）、xtpl 的 object group 段（各分区嵌套 object 段）、规则页「触发与节奏」折叠段。平铺块（settings-detail 的 hb-blk）不受影响。表现为字段只显 schema 默认值、编辑不进根树、保存按钮不出现
严重度高——静默数据丢失面：用户以为在改配置，实际一个字节都没进树；磁盘值（如 enabled=false）与界面长期相反，只能手改文件恢复

05根因（可选）

默认「待查」—— 不为填单做分析。有结论才写；不确定就写已排除的假设，不要把猜测写成结论。

已确认（浏览器级实证，非推断）：CONFIG_EDITOR 以全局 mixin 注册（app.js:913），其 provide(){ ce:this } 因此挂在每个组件实例上——每个实例都带着 mixin data() 新建的空 cfg 树（tree:null）。<aq-fold> 作为中间层组件没有把自己注入到的 ce 原样透传（inject:["ce"] + provide(){ce:this.ce} 二件皆缺），其默认插槽里的 <hub-field> 于是注入到 aq-fold 实例本身：字段读写全部落在空树上——只显 schema 默认值（cfgFallbackValue）、编辑不进根树（根 cfgDirty 恒 false、「保存并应用」不出现）、磁盘原样不动。

已排除：重复键/版本闸门等配置内容病（生产配置是最新版且启动正常）、渲染层字符串真值化（cfgBool 对 "false" 解析正确）、多标签/缓存/Service Worker（静态层 no-cache、无 SW、无跨标签配置同步）、陈旧标签页（重启+刷新均复现）。
