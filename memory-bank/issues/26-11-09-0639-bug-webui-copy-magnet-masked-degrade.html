§01现象与发现场景

issue 26-11-08-0043（详情响应体 magnet_uri 泄敏）修复轮的产品拍板副产物：magnet_uri 改为入库掩码槽（apply_delta 单点，tr= 只落掩码值）后，前端「复制 magnet」功能三处入口仍从详情响应取 d.magnet_uri，复制到剪贴板的是 tr= 已掩的废链接 —— 私站贴进别的客户端无法 announce。修复轮拍板口径从紧（不动前端、复制出掩码版），入口处置留本件独立任务。与平台/配置无关。

§02证据

取证 2026-11-09（HEAD eefda04f 后的修复轮工作区），不转述：

  • 三处复制入口全部依赖详情响应的 magnet_uri 字段：drawer_files.js:141-149 copyTorrentInfo("magnet")（右键菜单「复制 magnet」+ 快捷键 shortcuts.js:299）、drawer_tpl/02-general-cards-low.js:347-352 与 drawer_tpl/03-general-dossier-collapsed.js:392-397（抽屉标识卡磁力行按钮），取数路径都是 _editDetail(hash) → GET /api/torrents/{hash}。
  • 入口 UI 文案已是掩码前口径：抽屉磁力行 02 模板 :262 显示「点击按钮按需获取(不进轮询载荷)」、03 模板 :298 显示「点击按钮按需获取」，均未提示复制出来的是掩码版。
  • 掩码后形态：tr= 值变为 percent-encoded 的 hash 掩码（host/参数名保留），xt/dn 原样 —— 链接可复制但 announce 不可用。

§03影响面

维度结论
触发条件任何带 magnet_uri 的种子点「复制 magnet」（右键/快捷键/抽屉标识卡三处任一）
影响范围复制 magnet 功能整体（私站种子复制出的链接不可用；公共种子无凭据面无感）
严重度中（功能退化，非性能/数据损坏；泄漏面本身已由 26-11-08-0043 收窄）
