修复后补充

实际修法：按建议抽三件，但 def 同时承担「差异清单」的角色 —— 每个实体只声明自己的路径/文案/初始值/选中键，骨架本身只有一份。

  • config_editor.js 新增三个骨架：cfgEntityAdd(def)（trim → normalize → 空判 → 查重 toast → cfgSetPath → select）、cfgEntityRename(def)（promptDialog → 取消/同名判 → 查重 → 重建对象换键以保键序 → select）、cfgEntityRemove(def)（confirmDialog(danger) → cfgDelPath，无 name 时删整段 → after() 收尾）。
  • 三份差异清单：cfgTrackerDef / cfgRuleGroupDef（normalize 补 _rules）/ cfgRuleDef；九处入口各自只剩一行 { ...def, title/body/okText }。
  • config_hub.js 三处 promptDialog 包装合并为 hubAddEntity(def)：取消/空名/查重判据只写一遍，三个入口只声明标题/占位/预填。
  • 连带删除只服务旧「hub 写 state → editor 读 state」两段式新增的中间态：cfg.newTrackerName / newRuleGroupName / newRuleName / cfg.addOpen / cfgAddCancel()，以及唯一调用方是那处重复查重的读访问器 cfgTracker(name)（全仓 grep 零残留）。
  • 规模：config_editor.js 1405 → 1435 行（+131 / −101），config_hub.js +27 / −22 —— 九处骨架 ~135 行变为三骨架 + 三 def + 九个一行入口。

与建议修法的差异：建议写 _entityAdd(ctx, def) 显式带 ctx —— 实际 ctx 就是 mixin 的 this，显式传参只多一层，故签名为 cfgEntity*(def)；hub 侧建议 hubAddEntity(title, cfgAdd) 传回调，实际传 def —— 新增要写的初始值/选中键本来就在 def 里，再传 add 回调等于把同一份差异拆到两处。
