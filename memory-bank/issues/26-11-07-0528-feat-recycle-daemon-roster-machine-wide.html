01现象与发现场景

0808 计划（26-11-05-0808-plan-relocate-fastresume-finalize，已实施完成，档案 Done）收尾时用户裁决的两条设计遗留之二。这不是缺陷，是已声明的设计取舍记录 + 未来增强方向。

收口评审修复 #6（recycle_daemon._proc_absent 进程证与端口证双判合取）后，进程名册证为全机口径：进程名册见任一 qB 进程（任一实例，日常库/测试库）即判「进程在」。同机多 qB 实例形态（P7 真机实测形态：目标实例已死、同机另一实例在跑）下，daemon 永等不到下线窗口——收尾改写一直不发生，直至同机全部 qB 实例都退出。这是 N1 铁律（qB 运行期零写入）优先于窗口可用性的显式取舍，已在 _proc_absent docstring 与档案切片 26-11-07-0440 声明；单实例部署零影响（qB 真死时进程证与端口证自然同向，合取不损窗口可用性）。

本条记录该取舍及其边界，并挂账未来增强方向：若日后要多实例兼顾，需比映像名更强的实例身份证据——设计题，不是一行修复。

03影响面

非缺陷——证据结构使然：进程名册只有映像名（跨平台 tasklist//proc/ps 尽力而为），分不出实例；而端口证据只在实例死后才成立（端口释放才拒连），彼时全机名册仍见另一实例——两证天然矛盾，实例级判定做不出。取舍 = N1 零写入铁律优先于窗口可用性（假阳性进窗 = daemon 在 qB 运行期改写 fastresume，铁律被破；假阴性 = 只延迟收尾，方向安全）。

未来增强方向（未排期；动手前先拍板证据链形态）：若要多实例兼顾收尾窗，需比映像名更强的实例身份证据。候选思路（仅方向，未论证）：

  • 按端口的进程归属探测（netstat / /proc net → pid → 命令行）把「该端点的实例」与「其它实例」分开；难点：实例死后端口释放，端口证即刻失效，会与全机名册证矛盾——需定义「实例死后如何证明它死了」的证据链（如名册数量下降 + 该端口历史归属记录）。
  • qB 侧身份凭据（WebUI 登录态 + 实例指纹 API，若可用）：实例活着时可验，死后同样面临「死无对证」，须与落盘侧证据（journal / BT_backup 文件锁）组合。

约束不变：任何放宽都不得引入「qB 运行期改写 fastresume」的假阳性进窗（N1 铁律）；证据链弱化必须留痕告警（现行退化路径同款纪律）。
