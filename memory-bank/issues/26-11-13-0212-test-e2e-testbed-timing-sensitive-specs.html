  • e2e/ 下 settings-bt-backup spec · grep 关键词 ambiguous / 计时探测 · 失败点 :303(取证同上)

§05根因（可选）

已定位(2026-11-12 S3 验收轮): 容器慢 CPU(软件渲染)使 spec 内异步等待余量不足 —— ① route.fetch() 的 resolve 时序未与测试生命周期绑定(测试结束才 resolve); ② 计时探测阈值按硬件余量写死, 无 testbed 档。非容器/接挂/桩缺陷(独立复跑 deterministic 佐证)。

§06建议修法（可选）

两个方向(取自 S3 验收轮, 实施时以现场复验为准):

  • spec 层加固: route.fetch 竞态面用 unrouteAll({ behavior: 'ignoreErrors' }) 之类把清理与生命周期绑定;
  • 计时探测接档: 探测类阈值参照 pytest 侧 perf_baseline.json 的 testbed 档做法, 按 AUTO_QB_TESTBED 放宽(e2e 侧现不导出该变量, 需同步决定导出面)。

修完验收口径: 容器内 fast 子集与全量 e2e 全绿(容器实测耗时锚 Windows 侧, 不进基线)。
