01现象与发现场景

2026-10-30 实施计划 26-10-30-0610(乐观UI扩面)S1 时,为 editRename 的 rename 四态单测构造「失败回滚」用例时发现:贴乐观补丁时 drawer.detail.name 被同步改成新名,但失败路径的回滚只走 _forEachRow 三数组,抽屉 detail 不在回滚面里——命令失败后抽屉侧停留新名。

02证据

# drawer.js::editRename(取证 2026-10-30, HEAD c9b9a1c8)
889:      this.applyOptimisticPatch([hash], "rename", { name: res.name });
891:        this.drawer.detail.name = res.name;          // 贴补丁时 detail 同步改新名
# 失败路径 resolveOptimistic([hash], false) 的回滚只覆盖 _forEachRow 三数组,
# drawer.detail.name 无还原写入 —— 失败后抽屉侧停留新名, 直到重开抽屉或下次 _fetchDrawerDetail

05根因（可选）

已定案（2026-10-31 修复时）：editRename 贴补丁时按 D3 把 detail.name 同步改新名，但 detail 是独立拉取的对象、不在 _forEachRow 三数组里 —— commands.js 的两条回滚出口（resolveOptimistic 失败分支 / _expirePending 3s 兜底）都只还原行，贴补丁面与回滚面不对称。

06建议修法（可选）

候选:失败路径(resolveOptimistic([hash], false) 处或 editRename 的 error 分支)把 drawer.detail.name 还原为贴补丁前捕获的旧名;代价几行。或让 detail.name 不在贴补丁时同步(等 memberByHash/重开抽屉自然纠正),但会牺牲成功路径的标题即时性。

复验

复验：2026-10-31 03:29 仍复现（HEAD 4d885851）—— drawer.js::editRename 贴补丁时写 detail.name、commands.js 两条回滚出口均无 detail 还原写入，与取证锚点逐字一致。另核实影响面细节：drawerTitle 优先 memberByHash（行引用，行回滚自动跟随），仅 hash 不在视图三数组时回落 detail.name —— 恰是「行不在视图 + 抽屉开着」的组合，此时 applyOptimisticPatch 连 op.prev 都采不到，detail 是唯一旧名落点。

修复后补充

实际修法（2026-10-31，与建议修法同向、落点改道）：未在 editRename 内显式还原，而是收敛进 commands.js 回滚单点 —— 新增 _syncDrawerRollback(hash, patch, rolled)，两条回滚出口（resolveOptimistic 失败分支 / _expirePending 兜底）都把行同款回滚值（op.prev，兜底时 t || op.prev）对称写回 drawer.detail（只写 patch 出现过的键；抽屉不在该 hash / 已关时跳过）；editRename 贴补丁时把抽屉旧名回填进 op.prev，补上「行不在视图采不到 prev」时 detail 无原名可退的缺口。改道原因：editRename 内只还原显式失败会漏掉 3s 无回执兜底出口（本件触发条件明确含它）；且回滚值须与行同源 —— 兜底要回「最后已知真值」而非盲回点击时的旧值（pitfalls/web-ui/contract-api.md「"真值到达" ≠ "值覆盖结束"」条）。

验证方式：扩展 tests/test_webui_optimistic_rename_alt.py 的 rename 四态 node 电池（真跑 commands.js + drawer.js）加 7 条断言 —— 失败 / 3s 兜底两出口 detail 还原原名；行不在视图时 op.prev.name 回填当回滚锚；抽屉在别的 hash / 已关时回滚不碰 detail；兜底时行与 detail 同回最后已知真值（不盲回 prev）。

测试数字（2026-10-31 实测，4d885851 工作区，未提交）：rename四态 node 电池 25/25 过；全量 commands run test.full 4190 passed, 2 skipped，覆盖率 99.28%（基线切片见 commands run kb.baseline）。
