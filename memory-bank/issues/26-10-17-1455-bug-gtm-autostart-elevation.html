01现象与发现场景

2026-10-17 14:00，auto-qb 经 launch.cmd 拉起工具（python -m gtm run --autostart，PID 22336，普通用户令牌、未过 UAC）。工具启动时按 D13/D19 幂等注册开机自启，schtasks /Create 返回 rc=1「拒绝访问」，工具按「不阻断服务」只记 WARNING；设置页「全局流量来源 → 开机自启」因此恒显示「未注册(开机不会自动起)」，用户点勾选同样失败。

触发条件：Windows 平台 + 非提权进程注册 ONLOGON 触发器（该触发器是「任何用户登录」级别的系统触发器）。管理员 cmd 下同一条命令可成功 —— 这与用户「怀疑需要管理员权限」的判断一致，但未在非提权会话复跑验证（见复验段）。

03影响面

维度结论
触发条件Windows + 工具由普通权限进程拉起（auto-qb 拉起 / 自启项之外的任何路径）—— 必现
影响范围只有「开机自启」这一项：机器重启后工具不会自己起来，需 auto-qb 下次启动时再拉起（曲线数据出现空窗）；取数、订阅、通知均不受影响
严重度低（功能降级，非数据错误）；但用户侧表现为「点了勾选没反应 + 只有一行 WARNING」，排障成本高

待查（已排除：工具路径/解释器不存在、任务名冲突、schtasks 缺失 —— 报错是「拒绝访问」而非「找不到文件」或「已存在」）。
强候选：ONLOGON 是系统级触发器（微软文档：任何用户登录时运行），非提权进程创建时被 Task Scheduler 拒绝；管理员会话下应可成功。

06建议修法（可选）

方向 + 候选方案 + 各自代价；没有想法就留「待定」，只写方案，不在本报告里实施。

方向：让「注册自启」不再依赖提权，或在必须提权时把话说清楚。

  • A. 换零提权后端（推荐）：Windows 改用 HKCU\Software\Microsoft\Windows\CurrentVersion\Run 或启动文件夹快捷方式（登录即起、当前用户、无需 UAC）；schtasks 仅作可选路径。代价：与既有 is_registered 判据、卸载路径、三平台对齐测试都要改。
  • B. 保持 schtasks + 显式提权：设置页点勾选时用 ShellExecuteW("runas") 起一次 UAC（用户点「是」）。代价：无法在无人值守的拉起路径里完成；与 D13「启动器恒定携带自启意图」的自动化预期冲突。
  • C. 只改文案：把「拒绝访问」翻成「需要管理员权限：请用管理员身份运行 install-autostart」，并在状态区给一键命令。代价：不解决自动化，只降低排障成本。

无论选哪条，都应把「注册失败」从 WARNING 升到状态区可见（指针 autostart_registered=false 目前不带失败原因）。

复验

复验 2026-10-17 15:20：代码锚点仍在 —— WindowsTaskBackend.register 仍拼 schtasks /Create /SC ONLOGON（installer.py:253/:258，取证 15:20），_maybe_register_autostart 仍只 logger.warning 后 return（__main__.py:236，同上）。

现象未在本会话重跑：本会话的命令安全策略把 schtasks.exe 列入 Program Blacklist（pitfalls/ops/session-program-blacklist.md），换壳重试被明令禁止。但报告证据是 rc=1 + schtasks 自身的中文报错「错误: 拒绝访问。」⇒ 当时 schtasks 真的执行了、被 Task Scheduler 拒绝；黑名单拦截的指纹是 Python PermissionError [WinError 5] 且拿不到 rc，两者不同 ⇒ 认定仍复现，根因方向（ONLOGON 需提权）仍需真机验证。

修复后补充

实际修法（选建议修法 A，并把 schtasks 路径整个移除）：Windows 后端 WindowsTaskBackend 换成 WindowsRunKeyBackend —— 写 HKCU\Software\Microsoft\Windows\CurrentVersion\Run 值 global-traffic-monitor（REG_SZ，值 = "<venv python>" -m gtm run --data-dir "<data dir>"），零提权、零第三方依赖（stdlib winreg）。配套三条：①Run 值 260 字符上限在写入前 fail-fast 报错（本机实测命令 158 字符），不截断、不降级到启动文件夹；②is_registered = 值存在即算（开关语义），命令漂移由 register() 无条件覆盖写收敛；③失败可见性 —— _maybe_register_autostart 把失败原因交给 ControlServer，落进 endpoint.json 新增的 autostart_error 字段（schema 不升版，双向 .get 兼容），设置页在「未注册」后直接显示原因。未选 B：ShellExecuteW("runas") 的 UAC 无法在 auto-qb 无人值守拉起路径完成，且 ONLOGON 是「任何用户登录」级触发器，语义比「当前用户」更宽。未选 C：只改文案不解决 D4「自启绝对支持」。

根因口径：按共识未做 schtasks 真机探针（A 方案成立不依赖「B 不可行」），故根因仍是「强候选 + 平台行为佐证」，未升级为实测结论；证据侧已排除「schtasks 被本会话黑名单拦」（黑名单是 PermissionError [WinError 5] 且拿不到 rc，而报告证据有 rc=1 与 schtasks 自己的中文文案）。

验证方式：①单测 —— 工具侧 Windows 段整体重写（FakeRegistry 替身，含「超限 fail-fast」与「runner 一次都不该被调」两条守阵），工具套件 210 passed；②真机（Windows 非提权会话）—— install-autostart 写入后 winreg 读回 158 字符 REG_SZ → 重复注册走 skipped → 手工执行该命令行能起（被单实例锁挡下，说明命令解析与模块入口都通）→ uninstall-autostart 删除后读回 FileNotFoundError；验证后已卸载（该值指向 clone4 开发目录，留在用户机上会与生产 clone 抢登录自启）。③reg.exe 被本会话 Program Blacklist 拦，注册表真值改用 Python winreg 读（同一 API，非换壳绕行）。

测试数字：根 test.full 3537 passed, 4 skipped（126.28s，覆盖率 98.13%）；工具侧 210 passed。见 testing/baselines/26-10-17-1549-gtm-autostart-hkcu-run.md。缺口：重启/注销后的真实登录自起未验证（需真实登录会话，不可自动化）。
