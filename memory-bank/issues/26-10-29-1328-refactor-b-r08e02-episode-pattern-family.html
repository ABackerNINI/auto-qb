01现象

集数标记正则族仍是两套：core/episodes.py::_EPISODE_PATTERNS（4 项，文件列表路径）与 core/tvshows.py::_EPISODE_PATTERNS（7 项，种子标题路径）。原报告记为「tvshows 是超集」，本轮实测该判断不成立 —— 两族互有对方不认的形态（episodes 认 ShowE05 粘连，tvshows 不认；tvshows 认 1x05/第5话/区间续接，episodes 不认）。无任何用例把这一双向差异钉住，任何「顺手合并」都能全绿通过并静默改行为。

02现状取证

行号为取证时（2026-10-29 13:28，HEAD 1b7dd104）的快照；重定位用 grep 关键词。实测命令：.venv/Scripts/python.exe -c "from auto_qb.core import episodes as e, tvshows as t; ..."。

  • src/auto_qb/core/episodes.py:17-30（grep _EPISODE_PATTERNS）：第(\d)+集 / [Ss]\d+[Ee](\d) / [Ee][Pp](\d) / [Ee](\d)；协议是 (regex, extractor->List[int])，无边界预查、无区间续接、无中文数字。14-16 行注释自称「tvshows 子集」。
  • src/auto_qb/core/tvshows.py:126-173（grep _EPISODE_PATTERNS）：SxxExx（含 x、区间续接 -06/E06、内嵌季号）、1x05、第N[集话話]（数字或中文数字、区间 -~至到）、EP/Episode、E、- 05、[05]；协议是 (regex, extractor->三元组, is_bare)，全部带左右边界预查。123-125 行注释自称「episodes 的超集」。
  • 两条注释互指同一个已 Done 的 issue （26-10-11-0207-refactor-core-episode-marker-dup），但那条只做了排除集单点（episodes.RESOLUTION_EXCLUDE ↔ tvshows._BARE_EXCLUDE，tvshows.py:189），正则族本身原样保留。
  • 文件列表侧只有一套：tvshows.parse_files 在 tvshows.py:445 直接复用 _episodes.extract_episodes_from_names。所以真正的两套是「种子标题解析（tvshows）」对「文件列表解析（episodes）」，不是两个包各扫同一输入。
  • 实测非对称（同一文件名，两侧结果）：
    • ShowE05.mkv — 文件侧 [5]；标题侧 unknown（E 模式要左边界）。
    • Show.第5话.mkv — 文件侧 []；标题侧 S1E5（話 只在 tvshows 里）。
    • Show.1x05.mkv — 文件侧 []；标题侧 S1E5。
    • Show.S01E05-E06.mkv — 文件侧 [5]（丢 E06）；标题侧 ep 5-6。
    • 次要：文件侧对 E05 无左边界、标题侧有；文件侧不做 1 <= start <= 9999 之外的区间终点收敛。
  • 守阵缺口：tests/test_episodes.py 只正测 第x集/EP/E/SxxExx 与优先级（:25-67），无一条负测断言 episodes 不认 1x05/第五集/第5话/区间续接；tests/test_tvshows.py:101-106 只正测 tvshows 侧。合并任一侧，两边测试都不会红。

03分歧点与判定

  • 输入域不同：tvshows 解析含噪音的种子标题（发布组、分辨率、语言标记），必须靠边界预查防 webdl5 类误判；episodes 解析已规范化的文件列表，容忍度更高（ShowE05 也算）。这是两种输入口径，不是同一事实的两种写法。
  • 协议不同：列表版 extractor 返回 List[int]（天然支持一文件多集）；标题版返回 (start, end, 内嵌季) 三元组 + bare 标志（要点位、要季号回填）。「共享一个 pattern 列表 + 各自取子集」在此不成立：共有 4 个形态的正则体与捕获组语义都不同，取子集只能取到名字，取不到可执行体。
  • 合并的代价：文件侧改读标题版 → ShowE05 退化为不识别、1x05/第5话 被新识别（改自动打标行为）；标题侧改读文件版 → 失去边界与区间续接、且要重写 _find_episode 的点位/季回填逻辑。两个方向都动生产行为，收益仅是「少一份正则」。

判定：(a) 业务正解不该合，可做且值得做的只有补守阵钉差异（对应报告给的第二条出路）。理由：合并收益是伪的（两族覆盖的输入与返回协议都不同，不是同一事实的两表示），而现状风险是真的 —— 注释把关系写成「超集/子集」，direction 写反一半，且零负测，后来者按注释「对齐」就会静默改掉自动打标与视图归档。不归 (b) 的「该合」：没有可保持行为的合并路径；不归 (c)：实测差异只造成「少识别」（漏标签/进未识别桶），未见错值或错季。

04收敛建议与验证

不做正则合并，做三件事：① 在 tests/test_episodes.py 加一组负测（参数化）：extract_episodes_from_names(["Show.1x05.mkv"])==[]、["Show.第五集.mkv"]==[]、["Show.第5话.mkv"]==[]、["Show.S01E05-E06.mkv"]==[5]（钉住「文件侧不做区间续接」这一现状）；② 在 tests/test_tvshows.py 加一条对照：parse_release("ShowE05.mkv").kind == unknown（钉住标题侧左边界）；③ 把两处注释（episodes.py:14-16、tvshows.py:123-125）的「子集/超集」改成可核对的表述（「覆盖域不同：文件列表 vs 种子标题，互有对方不认的形态，见 tests/... 的对照用例」），并把指向 Done issue 的句子改为指向本 issue。

验证手段：新增用例即验证手段本身 —— 先在现实现上跑绿（证明钉的是现状而非愿望）；未来谁要合并，这组用例必红，从而强迫其显式改期望并说明行为 delta。补充可选判据：grep -c "re.compile" src/auto_qb/core/episodes.py 与 tvshows 侧计数不作为收益指标（数量不是目标）。

收益：把「合并会改行为」从注释里的口头声明变成可执行断言，成本约一小时、零生产风险；风险：无（只加测试与改注释）。重开条件：若确认要统一两族，正确路径不是合并正则，而是让 episodes 复用 tvshows._find_episode 的点位解析后再展开区间，届时须先跑样例集对比（本 issue 的负测会被有意改写），并单独立 bug/feat 单评估自动打标的行为 delta。
