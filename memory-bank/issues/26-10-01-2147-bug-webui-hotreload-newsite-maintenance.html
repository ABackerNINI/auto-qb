03影响面

维度结论
触发条件WEBUI 添加站点（或任何触发 tracker 绑定变化的配置保存）→ 配置热重载（统一挂载口 apply 路径）：绑定变化（含站点增删，o is None 判 True）命中 L2 结构重建 rebuild_runtime()（取证 2026-10-04，新机制下复验确认）
影响范围所有 L2 级热重载后的存量种子，不止新站点：① 新匹配上的存量种子永远等不到 torrents_added 相位，种子级任务（内置维护 + interval 规则任务）不被创建；② 其余存量种子的既有种子级任务随 TaskQueue() 换新被丢弃，L2 重建后只重注册全局 delete_tags* 任务，无人重建。两类均需重启进程才恢复（取证 2026-10-04）。不触 L2 重建的热重载不受影响
严重度中偏高（2026-10-04 复验改判）—— 受影响存量的维护面（标签/分类等）整体停摆直到重启进程；与字段变化触发链（on_torrent_field_changed）无衔接（热重载不改变任何种子字段，field_changed 为空，不触发）

05根因（可选）

默认「待查」—— 不为填单做分析。有结论才写；不确定就写已排除的假设，不要把猜测写成结论。

已定位（复验取证 2026-10-04，新机制下仍复现）：种子级任务（内置维护 + interval 规则任务）唯一创建点 _create_torrent_tasks（rules_mod.py:397-429），唯一触发源 torrents_added 相位；而 L2 结构重建 rebuild_runtime() 换新 TaskQueue() 后只重注册全局 delete_tags* 任务，种子级任务无人重建。热重载引入 tracker 绑定变化（添加新站点含 o is None 判 True）→ L2 重建 + store.reset_runtime()（记录保留、conf 置 None）→ 下轮 full_round 重匹配，但契约是「存量记录不走 added 分支」（_apply 只对 prev 没有的 hash 判 added）⇒ 绑定补上了、任务面没人管：新匹配存量种子等不到 torrents_added，其余存量种子的既有种子级任务被换队列丢弃。旁证：计划 26-09-27-1438 §07「首轮全量收敛」假设在代码上不成立 —— reset_runtime 登记的 external_tag_changes（store.py:435-437）唯一消费方是 handle_maintenance（maintenance_mod.py:147-150），任务不存在则无人消费。旧级别表机制同构（ed514e30~1 的 L2 分支同样只建全局任务），非重构回归；on_torrent_field_changed 字段变化链与热重载无衔接（热重载不改变任何种子字段，不触发）。
