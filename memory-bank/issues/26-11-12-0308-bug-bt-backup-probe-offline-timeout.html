§01现象与发现场景

真机复测(计划 26-11-11-0259 S6 判据② offline 组)取证时撞见: 主测试 qB(56589)经 real.down 优雅退出后, 在设置页整组迁移编辑器点「自动探测」, UI 恒渲染 探测失败: 请求超时(15s) —— offline verdict 的渲染形态(online=false + 未自证标注)从未出现。同一时刻 curl 直探同端点却正常返回 HTTP 200 + verdict=manual-set + 离线标注, 即网络层行为正确, 只有 UI 形态结构性不可达。复现条件: qB 实例 down/不可达 + 前端点「自动探测」; 与配置数据量无关(单 fastresume 即现)。逐字证据见切片 memory-bank/testing/real-baselines/26-11-12-0229-real-relocate-bt-backup-retest.md §05-6/§3.2。

§03影响面

维度结论
触发条件qB 实例 down/不可达时在设置页点「自动探测」必现(服务端 offline 探测耗时 > 15s 即触发)
影响范围仅 bt_backup_probe 的 offline verdict 渲染形态(用户侧永远只见「请求超时(15s)」); 在线形态(hit/ambiguous/miss/manual-set)不受影响 —— 网络层 200+未自证标注行为本身正确
严重度低(功能无错判、配置零误写, 是「离线反馈形态不可达 + 15s 空等」的体验/可观测性缺陷)

§05根因（可选）

待查（已排除：前端常量为本轮改动引入 —— 复测基线 703ceb6c 上即此行为; 服务端慢因疑 qB 连接重试窗口(qB down 后 API 调用重试至超时才走 offline 降级), 未深挖, 不作结论）

§06建议修法（可选）

方向二选一(待定): ① 服务端 offline 快速失败 —— qB 不可达时探测前置轻量探活或收紧重试, 让 offline verdict 在 15s 内返回(改探测/重试策略, 收益: 全部前端调用点受益); ② 前端该端点单独放宽 fetch 预算(如 30s, 改常量/调用点, 代价: 用户空等更久)。也可两者组合(收紧服务端 + 适度放宽前端)。
