01现象

03分歧点与判定

  • 形状：对象（键 = 桶名，靠 sev 升序排）↔ 数组（顺序即处理序，元素带 key）。同一顺序事实两处编码：04/06 的顺序由 sev 0/1/2/3/9 表达，05 由数组下标表达，两者当前一致。
  • 附加列：sev（排序权值）vs cnt（副标题话术）vs cls/tip（胶囊色与悬浮说明）。消费场景不同，本身正当 —— 分歧不在附加列，而在「文案与桶集」被复制了五遍。
  • 是否有意分叉：无判据。没有任何注释说明「04 的胶囊文案必须与 06 的桶表分开维护」；五份 text 当前完全一致，说明是复制而非演化。归类 (b)：无判据漂移，该合（只合文案与桶集，不合附加列与排版）；不判 (c) —— 五份字面目前一致，用户看不到错。

判定：值得做（refactor / light）。① 重复真实（5 处，两形状）；② 行为可保持 —— 只把 text 抽成单源，sev/cnt/cls/tip 与各处顺序、DOM 结构全不动，字面逐字不变；③ 可验证 —— 静态守阵（未联系 在 drawer_tpl/ 只允许 1 处命中）+ 现有 tests/e2e/drawer-trackers-variant-tables.spec.mjs / drawer-trackers-reannounce.spec.mjs 回归；④ 收益（改文案/加桶一处，避免「同一桶三版式三种写法」的未来漂移）> 风险（低：纯查表 + 渲染装配不变）。

04收敛建议与验证

一张表带全部列、各取所需：核心层落 TRACKER_BUCKETS = { err: { text:"未工作", sev:0, order:0, cnt:"正在拖后腿 · 优先处理" }, warn: {…}, upd: {…}, ok: {…}, off: {…} }，另导出 TRACKER_BUCKET_ORDER = ["err","warn","upd","ok","off"]（05 的分区顺序与 04/06 的 sev 升序同源，写一次即可）。04/06 的 BUCKET[b].text/.sev、05 的 GROUPS 全部改为读该表（05 仍用数组派生的局部视图，不直接持有字面）；04 PILLS 的 text、05 stripHtml 的五个桶名改读 TRACKER_BUCKETS[k].text（cls/tip 与色族仍留在各自文件 —— 那是版式语义）。

挂载位置：抽屉层已有 reg.peers 这种「判据命名空间」先例，本表属同类，建议一并挂同类命名空间（或 reg.helpers）；服务 3 个变体 5 个消费点才够格，不要为单处造 helper。

协同提醒：bucketOf(ctx,t)（状态码 → 桶）在 04/05/06 另有逐字三份，属 R21-B-05 / R21-C-05 的范围（不在本项）。若那件先落，本表应随 bucketOf 并入同一命名空间，避免出现两个半套的「tracker 判据单点」；本项不顺手改 bucketOf，只把文案表收单。

验证手段：① 静态守阵（tests/test_webui_static_dom_panel.py 抽屉变体族，写法参照 test_drawer_variant_skeleton_single_point ②「判据单点在核心 + 各变体经 const 消费 + 本地副本零残留」）：drawer_tpl/ 下字面 未联系 命中数 == 1（在核心层表内），04/05/06 各出现 TRACKER_BUCKETS 消费 ≥1 次；② 等价性：五处取到的 text 与现状逐字相同（静态断言可覆盖），sev 值 0/1/2/3/9 不动 ⇒ 排序权值不变；③ e2e 回归 drawer-trackers-variant-tables.spec.mjs（三档表体）+ drawer-trackers-reannounce.spec.mjs，另手工过 04 胶囊/05 计数条/06 表头三处文案。

收益：桶文案与桶集从 5 处收成 1 处，新增第六桶或改中文只动一处；风险：低 —— 纯查表替换，DOM/class/顺序均不变。
