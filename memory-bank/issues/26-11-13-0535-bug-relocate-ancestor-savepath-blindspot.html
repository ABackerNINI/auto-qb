§01现象与发现场景

发现场景: 评审计划 26-11-13-0448(relocate 收尾窗写路径误拦修正)轮 1 的 major 发现 —— 该计划把删链门/删种拦截的判据换成「种子文件清单 × job.alias_paths 交集」时,宣称交集判据「恰覆盖」;核查发现候选面(预过滤)本身按 save_path 收窄,存在一类真实相交却被候选面挡在判据之外的形态,且该洞为现状代码既有、非计划引入。计划 §07 已如实披露(「候选面外祖先形态漏判(既有洞,如实披露)」行),本条把它独立成池。

漏判形态: 组外种子 save_path 为 job.src 的祖先,且其内容根恰覆盖 src。例: 组 src = R:\Download\PTing(成员内容根 PTing\<name>),组外种子 save_path = R:\Download、name = PTing → 内容根 = R:\Download\PTing == src。若它与组同内容(跨种),其文件清单与 alias_paths 真实相交,但它的 save_path 既不在 scope 之下也不恰等 src —— 两处判据的候选面都收不到它。生产布局(R:\Download\PTing 直接挂在下载根下)下该形态真实可达。

under_alias_root(relocate_units.py:1252-1267)只判「path 在根上(等值)或根内(前缀)」—— 祖先方向(path 是根的父目录)结构性漏;等值面 equal_root 只并列恰等形态(1300 收口评审 9f0cbe4e 加,其「断粮」论据即针对恰等)。祖先形态两头都不命中。计划 26-11-13-0448 §07 风险表「候选面外祖先形态漏判」行为同一结论的披露面。

§03影响面

维度结论
触发条件组外种子 save_path 为 job.src 祖先 且 内容根恰覆盖 src 且 文件清单与 alias_paths 相交(同内容跨种最典型);迁移组收尾(armed/rewritten → verify)期间即暴露
影响范围① 删链门漏计依赖: 收尾核验通过后别名被删,祖先种子经链接做种的数据丢失(断粮),且失去 D16 保护;② D16 不拦其带文件删除: qB deleteFiles 经文件级 symlink 跟随直删(N5 实测通路)可破坏 dst 侧成员数据,目录级形态经 junction 同通路;③ 文件级/目录级两形态同洞
严重度高(数据丢失通路),但拓扑窄 —— 需祖先 save_path + 内容根恰好覆盖 src 的组合,常规分目录布局不可达

§05根因

候选面以 save_path 的「包含关系」为唯一预过滤维度: under_alias_root 只判「sp 在根上/内」,等值面只并列恰等 —— 「sp 为根祖先但内容根覆盖根」的形态两头都不命中,交集判据根本不运行。已排除: 非取数错/归一错(文件清单本身可得),非判据实现 bug(判据从未被触发)。该洞为现状既有(0808 S4 引入 D16、1300 R7 重锚时均未覆盖祖先方向),非 26-11-13-0448 计划引入。

§06建议修法（可选）

方向: 补候选面而非改判据(交集谓词本体正确,漏在预过滤):

  • 候选面加一格: 「save_path ∈ src 严格祖先(父方向链)且 content_root_of(save_path, files) == src」(files = 文件清单,签名 content_root_of(save_path, files) 全库调用点同款;清单取数走 relocate_plan._file_map 同款缓存单点,祖先格命中面极小、开销可控)—— 命中该格的种子进入同一交集判据(R2 删链门计依赖 / R3 D16 拦带文件删除)。
  • 备选: 放弃 save_path 预过滤,对 qB 全量种子跑清单×alias_paths 交集 —— 判据最完备但 files API 请求面扩大到全库,成本不成比例,不建议。
  • 实施注意: 与计划 26-11-13-0448 的 R2/R3 同点施工(候选面构造单点共用),建议认领时并入该计划实施或紧随其后,避免两处候选面漂移。
