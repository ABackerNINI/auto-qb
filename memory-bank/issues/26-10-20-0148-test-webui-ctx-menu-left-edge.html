01现象

顶层右键菜单(.ctx-menu)的左缘 clamp 在实现层存在(ui_feedback.js 开层估算 + 实测重钳位两级, 均含 max(EDGE, …)), 但 e2e 只有右缘一条顺带断言, 左缘无任何用例 —— 菜单贴近视口左缘打开时是否被正确钳位, 没有回归保护。

02位置

  • src/auto_qb/webui/static/shared/ui_feedback.js grep「_menuPos」/「_menuFit」(取证 2026-10-20 01:48): :245-249 开层估算宽 w=214, :254-271 实测重钳位 nx = Math.max(EDGE, Math.min(x, Math.max(EDGE, vw - w - EDGE)))
  • e2e/menus.spec.mjs grep「菜单右缘」(取证 2026-10-20 01:48): :391-392 右缘 ≤ vw-8+1 一条(嵌在垂直回归用例内), 无左缘用例; 子菜单四边用例在 :456-494(不含顶层)
  • src/auto_qb/webui/static/shared/menu.js: 定位计算不在此文件, 单点在 ui_feedback.js(取证 2026-10-20 01:48)

03建议（可选）

在 menus.spec.mjs CTX-fit 用例补左缘独立断言(≥ 8px)与右缘对称; 顺带可把右缘那条从垂直用例里拆出来独立成例。

04修复与验证（2026-10-20 认领并修）

复验(认领后第一件事, 2026-10-20 10:45): 现象仍在 —— ui_feedback.js 的 _menuPos(:255 开层估算)与 _menuFit(:264-281 实测重钳位, nx :271)两级 max(EDGE, …) 在码; menus.spec.mjs 左缘仍无用例(右缘只有垂直 CTX-fit 里一条顺带断言)。

实际修法: e2e/menus.spec.mjs 横轴拆出两支独立用例 ——

  • CTX-fit 右缘: 真实右键, 锚点贴 .group-table 滚动容器右缘内侧 2px(clientX≈1426, 落点经 elementFromPoint 验在行上), 断言菜单右缘 ≤ 视口宽 - 8(+1px 容差, 与既有几何守阵同口径)。
  • CTX-fit 左缘: 锚点 clientX=2, 断言菜单左缘 ≥ 8(-1px)。clientX<8 真实手势结构上不可达 —— 表格滚动容器左缘被 .layout 的 12px padding 钉死(实测 x=12, 双皮肤同), 行可点击区恒 ≥12, 而 EDGE=8; 故在真实行元素上派发合成 contextmenu, 事件仍走真实链路 @contextmenu → openMemberMenu → _menuPos → _menuFit 实测重钳位(不借道 vm, D4 守则只禁 vm 旁路; 本文件既有 dispatchEvent 先例)。坑档已立: pitfalls/web-ui/ctx-menu-edge-clamp.md。
  • 原 CTX-fit 垂直用例里那条顺带右缘断言随之移除: 其锚点在行左缘(clientX≈14), 菜单盒 14..210 远离两缘, 恒真。

与建议(§03)的改道: 建议"在 CTX-fit 用例补左缘独立断言(≥ 8px)与右缘对称" —— 照此补则锚点仍在行左缘(clientX≈14), 断言恒真(红验证实: 拆掉左缘两级 clamp 也不红), 守住的是假象; 故改为锚点贴缘的独立两支, 保留建议的语义(左缘 ≥8 / 右缘对称)而换成立即可红的安排。左缘一支因真实手势不可达改用合成 contextmenu, 是建议未预见的路径(原文保留备查)。

验证: 双皮肤(prism/atlas)新两支 + 垂直 CTX-fit 全绿; 红验两类突变各自判红且不误红 —— ①左缘两级 max 全拆 → 左缘支双皮肤 2 红、右缘支与垂直支绿(菜单左缘 2 < 8); ②右缘两级钳位全拆 → 右缘支双皮肤 2 红、左缘支与垂直支绿(菜单右缘 1622 > 1432); 突变均以精确反向编辑还原, git diff 实证 ui_feedback.js 零改动(生产代码未动, 本 issue 纯测试缺口)。menus.spec.mjs 全量、全量 e2e 默认轮与 test.full 的实测数字见基线切片(commands run kb.baseline)。
