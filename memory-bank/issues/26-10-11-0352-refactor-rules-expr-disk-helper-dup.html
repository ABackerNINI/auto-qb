01现象

rules/expr/env.py 的 _freespace/_disk_total/_disk_used 三个取值器逐字同骨架（仅 .free/.total/.used 属性与函数名不同）；且与 rules/conditions.py FreespaceCondition.match 的「取盘用量 + FileAccessError/OSError→ExprError 映射」同构 —— 同一「盘用量取数 + 错误映射」逻辑四处各写一遍，改一处口径（错误文案/异常类别）易漏。

02位置

文件 + grep 关键词（比行号稳）；行号要标取证时间。

  • rules/expr/env.py:199-226（_freespace/_disk_total/_disk_used）· rules/conditions.py:250-263（FreespaceCondition.match）（取证 2026-10-11 03:52）· grep disk_usage( / get_file_access().disk_usage

03建议（可选）

抽 _disk_usage_value(path, attr)（或返回 DiskUsage 单点）供四处共用，保留「不可判定显式报错、绝不降级成假值」的既有口径。收益中/风险低。

04实际修法（Done）

rules/expr/env.py 新增模块级 disk_usage_value(path, attr)（承载 get_file_access().disk_usage(path) 取数 + FileAccessError/(OSError, ValueError) → ExprError 映射），_freespace/_disk_total/_disk_used 降为一行委托（attr = free/total/used）；rules/conditions.py 的 FreespaceCondition.match 改为 from .expr.env import disk_usage_value 复用同一单点，并删去随之不再使用的 file_access 导入。四处逐字同 → 一处。

口径复核（与报告描述一致）：错误映射语义逐字保留 —— 映射 miss 转 ExprError(str(e))、盘不可读转 ExprError("磁盘不可用: '<path>': …")，绝不降级成假值。唯一差异：条件侧原只捕 OSError，单点统一为 (OSError, ValueError)（env 侧既有口径）—— 属超集，shutil.disk_usage 两实现（Local / Mapped）实际不抛 ValueError，行为等价。

验证：新增守阵 test_disk_usage_value_single_point（patch disk_usage_value 断言 env 三取值器 + FreespaceCondition 均经其路由）；既有 test_expr_exists_and_disk_undetermined / test_freespace_condition_undetermined / test_freespace_os_error / test_freespace_triggered·not_triggered 全绿。
