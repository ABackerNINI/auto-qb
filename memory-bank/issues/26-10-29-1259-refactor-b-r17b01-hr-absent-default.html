01现象

「站点未配 HR 就不判定」这条缺省在表达式取值面又抄了一份：env._hr 自己判 tracker_conf is None or not tracker_conf.hr 返 false，而记录侧已把同一口径收成 单点 record._hr_guard（前一轮 issue torrents-hr-entry-guard-dup 刚把三处入口收口）。 表达式侧成了该口径的第四份拷贝，守卫日后加条件（例如数据源未同步）它不会跟随。

02现状取证（2026-10-29 12:54 实测，git 1b7dd104）

  • src/auto_qb/rules/expr/env.py:99-107 · grep def _hr(
    实际代码：if tor.tracker_conf is None or not tor.tracker_conf.hr: return False —— 一句里同时表达「无 conf」与「无 hr 配置」，并自带注释「有定义的缺省, 不是错误」。 三个消费点：tor.hr_condition_met=_hr("hr_managed")、 tor.hr_local_triggered=_hr("check_hr_condition")、 tor.hr_satisfied=_hr("check_hr_satisfied")（env.py:314-316）。
  • src/auto_qb/torrents/record.py:385-393 · grep def _hr_guard
    实际代码：return not self.tracker_conf.hr or self.hr_excluded()， docstring 明写「站点未配 hr 或命中排除表」→ 三个入口 check_hr_condition(:409)、 hr_managed(:424)、check_hr_satisfied(:458) 顶部各调用一次。
  • src/auto_qb/rules/conditions.py:151-168 · grep class HrCondition
    条件侧第三种写法：conf is None → mode == "condition-not-met"； conf.hr is None → mode != "condition-met"（不调记录方法）。

03分歧点逐条与判定

  • ① conf=None 时三档取值：两侧一致 —— 条件侧 (False, True, False)； 表达式侧 _hr 全 False，反写 not tor.hr_condition_met 即 (False, True, False)。无分歧。
  • ② conf.hr=None 且 mode=satisfied：两侧相反 —— 条件侧 True （conditions.py:162，schema 帮助文案 config/schema/rules.py:120-121「没有要求 = 视为已满足」、测试 tests/test_conditions.py:283 都按 True 钉住）；表达式侧 tor.hr_satisfied 为 False（_hr 守卫生效、tests/test_expr_eval.py:131 钉住）。 这不是同一件事的两种写法：条件侧答「有无义务」，表达式侧答「HR 达标（可打标/可删）」—— WebUI 的「可删/不能删」徽章就走 check_hr_satisfied（webui/views.py:453）， 若改成 True，所有无 HR 站点的种子会集体跳「已达标」。判 (a) 业务正解不该合，本次不动， 仅要求在两侧注释互指（见 04）。
  • ③ 「未配 hr 不判定」的判定语句本身被抄了 2 份（②之外的那部分）—— 这是纯实现重复，且可等价收敛：记录侧三个入口已各自过守卫， _hr 里那半句 not tor.tracker_conf.hr 是冗余判定，删掉行为逐字不变 （tests/helpers.py:800/820/832 的替身同样自带同一守卫）。判 (b) 该合。

04收敛建议 + 验证手段

  • 建议 A（最小）：_hr 只保留 tor.tracker_conf is None 短路， 删掉 or not tor.tracker_conf.hr，把「未配 hr」交给记录侧守卫；_hr 退化为 「无 conf 兜底 + 委托」。
  • 建议 B（更彻底）：_hr_guard 改为 self.tracker_conf is None or not self.tracker_conf.hr or self.hr_excluded()， _hr 直接 bool(getattr(tor, method)())，全仓「无配置不判定」只留一处。
  • 顺带在 _hr / HrCondition 注释里互指 ②的差异（条件侧 True、表达式侧 False 各是哪个消费者要的），避免以后有人当成 bug 单边「修」掉。
  • 验证：等价性由既有测试守阵，无需新写行为断言 —— pytest tests/test_expr_eval.py -k "derived_values or legacy_condition_equivalence" （:120-131 无 conf 三值、:385-414 条件↔表达式等价表）、 tests/test_conditions.py -k hr、tests/test_hr.py。 若要更硬，可加一条「同一 ctx 下 _hr 与记录方法逐项相同」的参数化对拍（3 名字 × {无 conf, 无 hr, 有 hr}）。
  • 改动范围仅 rules/expr/env.py（必要时 + torrents/record.py 一行守卫），不涉及条件侧语义。
