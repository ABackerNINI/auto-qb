§05根因（可选）

默认「待查」—— 不为填单做分析。有结论才写；不确定就写已排除的假设，不要把猜测写成结论。

根因(2026-11-11 修复轮定位): tests/ 内自起假服用裸 ThreadingHTTPServer, 继承 HTTPServer.allow_reuse_address = 1(SO_REUSEADDR) —— Windows 上它允许抢绑已监听端口(生产侧 src/auto_qb/hr/server.py:20 同款论述)。-n 8 下各 worker 的假服都带 REUSEADDR, 两把 bind(0) 可能拿到同一端口双绑, 客户端连接被递给别人的假服/已关闭的 socket ⇒ ConnectionError(被中止)。与「单跑不复现、复跑全绿」吻合。已排除: 被测代码缺陷(两症状被测面无共享)、TOCTOU 取号(假服构造即 bind+listen, 无窗口)。症状 2(hr_discovery bind 用例)报错原文未录且其 socket 全部独占口径、无 HTTP 客户端流量, 双绑机制对它不成立 —— 不强行归因, 再现时先抓 traceback。
