实际修法：

  • 落点：不新建 shared 文件，追加到 shared/console_hub.css 尾段「三皮肤共用规则族单点」（A qb-tabs / B drawer-tabs / C 弹窗语义配色分级 / D HR 表① 件，共 35 条规则 +96 行；余下 4 条是三个差异底形的色义修饰 .hr-vsrc-b/-d、.hr-pres-on/-out，与差异绑成一族一并留皮肤内）。三份 shell 里 console/prism 已卡满 212 行 cap，新增 <link> 要动 cap 与守阵；而该文件事实上已是共用层（.kb-cursor / .ctx-custom-* / .aq-tip 都住这里），且三皮肤都挂它并排在各自 CSS 之后 —— 级联序天然就是收敛点，不需要 !important。
  • 三皮肤：逐条删同族规则，原位留一行指针注释（说明搬去哪、哪些留、为什么留）。净行数 atlas/views −35 / console/views −35 / prism/views −23 / atlas/dialogs −20 / console/dialogs −20 / prism/components −29 ⇒ 三皮肤合计 −162 行（共用层 +96，全仓净 −66；指针注释也占了若干行，故不是「删三份」的字面 3×）。顺带：prism/css/components.css 728 → 699，回到 700 行体量线以下。
  • 真差异留皮肤内（按本文口径，不抹平）：.drawer-tabs button.active 令牌、.hr-vsrc/.hr-pres 描边、.hr-sub 字体；弹窗的基线规则组（.modal-title / .modal.danger .modal-title .ico）也留各皮肤 —— 那是弹窗基础语言，三皮肤本就不同。
  • 守阵：新增 tests/webui_helpers.py::_ui_css_effective(ui) = 皮肤聚合 + shell 里挂的 shared CSS（link 序），三处断言改量「该皮肤实际吃到的级联面」（原判据在规则搬走后恒红，而直接放宽成「共用层有就算过」又会放过单皮肤漏改）。另补反向断言：徽章底形族必须留在各皮肤自己的 CSS 里。prism 拆 components/views 两件 那条钉法改为「共用层持有」。

与建议修法的差异：建议「一次一族、每族独立回归」，实际按逐字节同 / 有差异分组一次做完 —— 差异判定是机械的（脚本比对），不是判断，分批只多三次全量；建议顺序里 hr-detail-table 放最后（差异最多），实际它的 19 条同族规则同样机械可搬，3 条差异按规则留原地，没有需要人判的地方。建议的前置（fe-css-skin-token-layer-dup 分层统一）本轮未做 —— 它是独立的结构调整，且本轮不需要它就能判「哪两份该对齐」（用逐字节比对代替人工判断）。

验证方式：① 等价性：脚本对改前/改后各现算「最终生效规则表」（按 link 序拼接后取每个 selector 的最后一条声明），59 条族内规则 selector→body 逐条一致、无新增/丢失，且生效表内 无重复声明（证明搬走的那份与留下的那份不冲突）；② 红验两支：删 atlas 的 .hr-pres 底形 → 新反向断言判红（首次实测竟绿 —— 见下条，改成带 { 边界后才红）；删共用层的 .hr-detail-table-bar → 共用层断言判红；③ commands run test.full 全绿（数字见基线切片 memory-bank/testing/baselines/26-10-21-0340-webui-css-rule-family-shared.md）；④ commands run dev.e2e 三皮肤主表/抽屉/设置页 HR 表①/弹窗全绿。
