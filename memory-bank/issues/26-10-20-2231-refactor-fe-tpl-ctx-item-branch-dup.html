01现象

现象: 右键菜单的"项集/顺序/显隐/跨层"已经收敛到注册表 window.AQB_CTX_MENU_REG, 但渲染骨架仍是四支各一份:

  • multi / episode / member / group 四支的 .ctx-item 各行 3 行, 其中 4 份逐字同; 次级面板第 5 份只换了遍历变量名。
  • 差异只有 ctxItems('<支名>') 的支名与遍历变量。
  • 讽刺之处: ctx-menus.html 的模板注释自己写着"改项集改注册表单点, 别回本模板逐项直写(直写 = 四支人肉奇偶, 复发路径即 pitfall ctx-menu-branch-parity)" —— 项集侧确实收敛了, 骨架侧没有。

02位置

  • src/auto_qb/webui/static/shared/tpl/ctx-menus.html grep class="ctx-item" / ctxRun(it)(取证 2026-10-20 22:30)。
  • 支名判据已是单点: 同文件容器绑 :data-kind="ctxMenuKind()"。
  • 明细台账: R23-A-04。

03建议（可选）

四支合一: 用 ctxItems(ctxMenuKind()) 单一 v-for, 四条 <template v-if> 退化为一条; submenu 分支保留独立判断(它是唯一带子面板的 kind)。

收益不在行数, 在消灭一个有前科的复发面 —— 下次给 .ctx-item 加属性时, 少改一支就是同族缺陷。

04实际修法

  • 行菜单根块 class="ctx-item" 骨架: 5 份 → 2 份(一级项 + 次级面板项), has-sub 1 份; 行数 101 → 68。
  • DOM 结构零变化(v-for 挂在 <template> 上不产生元素) —— .ctx-menu > .ctx-item 选择器与 e2e 的 data-item/data-kind 挂点全部原样。
  • 各支语义注释未丢: 单种子支的 FX-15/CTX-05/06/D7 长注随 submenu 分支保留; 组级 CTX-03 收录口径与支目标语义本就在注册表 CTX_ITEM_DEFS 支注释与模板头部注释里, 合并块只留一句指路, 不复制第二份。
