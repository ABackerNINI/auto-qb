01现象

pytest.ini 的 --cov-fail-under=98 对 test.one (单文件/筛选) 部分运行同样生效: 用例全绿时仍因部分运行覆盖率低于全库闸而以覆盖率 FAIL 退出, 单文件排障必须手工附加 --no-cov, 易误判成测试失败。

02位置

  • pytest.ini 的 --cov-fail-under=98 与 addopts (取证 2026-10-05 09:22, 计划 26-10-05-0555 S1 阶段发现)
  • .commands/ 各包 test.one 的 task 定义 · grep: cov-fail-under · test.one

03建议（可选）

二选一: test.one 的 task 内置 --no-cov; 或覆盖率闸仅对 test.full / test.quick 生效 (部分运行不背全库闸)。方向待拍板, 改动只涉及 pytest.ini / task 定义, 不动测试。

05实际修法 / 验证

拍板方向: 采纳建议① —— .commands/test/config.toml 的 test.one run 串尾部加 --no-cov。理由: 与既有 test.quick / test.pkg 同款; pytest.ini addopts 的闸门原样保留 ⇒ test.full 与 CI 两处 uv run pytest tests -q 的覆盖率闸零回归; 改动面最小 (1 处 task 定义)。

改动文件: .commands/test/config.toml (test.one run 串 + when/note 说明) · 事实回写 memory-bank/testing/run.md 与 memory-bank/pitfalls/testing/single-file-coverage-gate.md (该坑条 复发 1→2)。

验证: 修复前复验 commands run test.one -- tests/test_docs_forms.py → 11 passed in 4.42s 同屏 FAIL Required test coverage of 98% not reached. Total coverage: 18.52% (现象仍在); 修复后同命令 → 11 passed in 1.50s, 无覆盖率 FAIL, 且因免去覆盖率插桩而更快。全量数字见 testing/baselines/ 本轮切片。

注: 裸跑 uv run pytest tests/x.py -q 不经过 task, 仍会撞该假红 (手工加 --no-cov) —— 坑档保留此半边判据。
