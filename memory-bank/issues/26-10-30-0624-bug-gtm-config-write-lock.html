01现象

config.yml 有两个 HTTP 线程写点且无锁: /autostart 是读-改-写(基于 config_holder.current 旧快照整份重写 + 只翻 autostart 位), 与并发 PUT /config(全量覆盖)或另一 /autostart 交叠时丢更新 —— 读到旧快照后他人写入的新参数被「旧快照 + autostart 位」整份覆盖回去。ThreadingHTTPServer 每请求一线程, 交叠真实存在; state.json 同款双线程写已用 _state_lock 串行化, config 路径没有对等防护。后果限配置回退(刚改的参数被静默还原), 无数据破坏。
