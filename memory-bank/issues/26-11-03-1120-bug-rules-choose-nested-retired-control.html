01现象与发现场景

第三次全量 code review S3 深读 shared/config_rules.js 并对照 config/compat.py 时发现：退役伪动作 ignore_next_action_error 的检测与剔除都只扫规则**顶层** actions。把它写进 choose 分支的 then（或 default）时，校验器放行（视为合法伪动作），但规则未被转未启用、伪动作也未被剔除，构造 Rule 时按未知动作抛 ConfigError。触发条件是手写 YAML 显式使用 choose + 嵌套退役伪动作；webui 不能创建此形态（插件清单不含退役项），程序化 config 可达。

03影响面

维度结论
触发条件手写/程序化生成的 YAML 在 choose 的 then/default 里使用 ignore_next_action_error
影响范围规则载入链（rules_mod.load_rules → Rule 构造）；该规则不再「转未启用 + 告警」，而是抛 ConfigError 中断载入
严重度中（P2）：可达性低（webui 无法创建该形态），但一旦命中是启动期硬失败，且与文档承诺的「含退役键规则自动转未启用」不一致

06建议修法（可选）

方案 A（推荐）：retired_control_keys_in 与 disable_retired_rule_spec 递归进 choose 分支的 then/default（保持单点），剔除后规则转未启用；前端 cfgRuleRetiredKeys 同步递归以保证提示面一致。代价：两处遍历逻辑需与 choose 形状演进同步，建议抽出共用递归。
