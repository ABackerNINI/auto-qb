§01现象与发现场景

RM11 真机复验轮（2026-11-21）开工环境自检，real.guard 首跑报「56590 真实种子 210 个，已全部暂停」；执行计划 26-11-21-0223 §3.2 环境钉死表按该输出誊写「真实种子面：56590 真实种子 210 个」。经二分定性（切片 26-11-21-0446 §03.1 族甲）：这 210 个全是上轮遗留的 real-fake 假种子（名形「Boot Show 032 S01E066 1080p.bin」= seed 工具 --name 自定义名 + 合成 .bin），非 PT 真实种子。计数误标的直接后果：①环境指纹与计划誊写误标；②RM04-35 attempt1 撞用例的 fail-closed 前置断言（发现残留即红）断轮一次。非「真实 PT 种子禁入」红线触碰（seed.list/guard 复核实测 0 真实种子）。

触发条件：实例带 real-fake 残留时跑 guard / 真机用例（conftest 环境层）。与平台/配置无关。

§05根因（可选）

skip_tags 定义了「豁免自造种子」的语义并写进 docstring，但三处调用全走缺省空元组——豁免语义从未被任何调用方兑现；「真实种子」输出文案又直接取 len(hashes)，两层叠加使误标成为必然而非偶发。

§06建议修法（可选）

  • 三处调用（runner.py:74/:87、conftest.py:33）统一传 skip_tags=("real-fake",)——标签名与 seed 工具族认领口径同源，建议把标签常量收敛到 lib 单点（如 guard.REAL_FAKE_TAG）避免第三处手抄；
  • cmd_guard 输出文案同步区分：「真实种子 N 个 / 自造(real-fake) M 个」，让环境指纹誊写天然双口径；
  • 注意 conftest 保护面改窄后看门狗行为面变化（假种子不再受保护）——这正是 docstring 本意，但需确认无用例依赖「假种子被暂停」的隐含前提。
