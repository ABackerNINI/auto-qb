01现象与发现场景

ui_smoke.cjs 分批迁移到 @playwright/test 过程中(plan 26-10-06-0708 S4 批)实测撞见: 行位于视口下部时打开批量菜单(移动/标签分类/导出/批量删除), 菜单底部超出视口, 菜单项真实点击不可达 —— Playwright click 对被遮挡目标重试报 element is outside of the viewport 直至超时。旧脚本 W4「组选中导出」段的存量 30s 超时(S0 起每轮 2 项 FAIL, 4/4 确定性复现)即此问题所致, 旧脚本时代被误当 flaky。

与数据量无关, 纯几何问题: 只要目标行落在视口下部约 40% 区域即触发; 行靠上时菜单向上弹则不触发。双皮肤均复现。

02证据

取证 2026-10-06, S4 对账轮(dev.e2e / 旧脚本双轨同现):

批量菜单实测高度: 361px (约 10 项)
_menuPos 钳位用常量: h = 222
Playwright 重试日志: element is outside of the viewport 持续 108 次重试耗尽 (Timeout 30000ms)
桩: scripts/ui_harness.py --torrents 300 (150 组行, 文档占满视口, 无 arrange 可解)

旧脚本同位置失败签名(S0/S1 批实测, 与上同根因): [prism]/[atlas] 冒烟整体执行 — elementHandle.click: Timeout 30000ms exceeded, 重试 element is not stable ×2 → element is outside of the viewport 55+ 次。

03影响面

维度结论
触发条件多选后对位于视口下部的行打开批量菜单(约视口下 40% 区域); 菜单项越多越易触发
影响范围全部批量菜单(移动/标签分类/导出/批量删除等 ~10 项); 双皮肤一致; 真实用户同样点不到菜单底部项
严重度中 —— 功能可达性缺陷(非数据损坏); e2e 测试侧已用「挑视口上部行」arrange 对冲(e2e/menus.spec.mjs), 产品侧未修

05根因（可选）

_menuPos 以常量 h=222 估算菜单高度做「向下放不下则向上弹」的钳位判断, 实际批量菜单 361px —— 估算低估 139px, 判定「放得下」的行实际放不下, 菜单底部溢出视口。余下细节(是否有 maxHeight/滚动兜底)待查。

06建议修法（可选）

方向: 钳位前按真实内容测高(offsetHeight / 先挂载再定位), 或给菜单容器加 max-height + overflow-y:auto 兜底。代价都小; 具体取哪条待认领时定。

修复后补充

实际修法（走的是建议修法的第一条：钳位前按真实内容测高；第二条 max-height + overflow-y 只留作极矮视口的退化兜底，理由见下）：

  • shared/ui_feedback.js 新增 _menuFit(el, x, y)：按 offsetWidth/offsetHeight 实测尺寸把菜单盒整体收进视口（边缘留 8px）；每次先复位兜底限高（否则量到的是上次压过的高度）；菜单比视口还高时顶到上缘 + max-height 可滚，保证底部项仍够得着。_menuPos 降级为「光标处初值」，注释写明常量只是初值。
  • 新增 _menuFitRefit(stateKey, refName) 作为 watcher 出口：现读 this[stateKey] / this.$refs[refName]（不闭包捕获旧对象），并守 visible。
  • shared/state.js 新增 menu / headMenu / filePrio 三个开层 watcher，在 $nextTick 里调出口。判据用对象替换而非 visible 翻转：三个菜单的开层入口一律写 this.X = {…}（menu.js 组/成员/表头三个、shows.js 整集/整剧两个、drawer.js 文件优先级一个），关层与执行动作只改字段 ⇒ 每次开层恰好触发一次，连「菜单还开着又右键另一行」（右键不触发 window 的 click 收层）也覆盖；量测在 Vue 补丁后、浏览器绘制前完成，无可见跳位。
  • shared/tpl/ctx-menus.html：三个 .ctx-menu 各补 ref（ctxMenu / headMenuEl / filePrioEl）。
  • 为什么第二方案不作常态解：.ctx-menu 内嵌 position:absolute 的 flyout 次级面板（.ctx-sub，「更多操作」），给菜单盒加 overflow 非 visible 会把它裁掉 ⇒ 只在 h > innerHeight - 16 的退化分支挂限高与可滚。

验证方式：① 新增静态守阵 tests/test_web.py::test_frontend_ctx_menu_refit_by_measured_size（钉「三个 ref ↔ 三个 watcher ↔ _menuFit 实测算」三向对齐；红验：摘掉 ref="ctxMenu" 立刻 FAIL）；② 新增 e2e 回归 e2e/menus.spec.mjs「CTX-fit 视口下部行的批量菜单整份落在视口内(底部项可点)」—— 故意挑视口下半带的行（与 W4 那段「挑上部行」的对冲方向相反），断言菜单盒整体在视口内 + 真实点击底部最后一项「批量删除…」；修复前双皮肤红 / 修复后双皮肤绿；③ 全量 e2e commands run dev.e2e 82 passed + 10 skipped / 0 failed（2.9m，含新增 2 条）；④ commands run test.full 2678 passed + 4 skipped / TOTAL 99%（基线切片 memory-bank/testing/baselines/26-10-06-1830-webui-ctx-menu-viewport.md）。
