01现象与发现场景

来源: 第二次全项目 code review(26-10-30-0237)批A 条目 A-05; 复验留待认领时做。

ACT_FINALIZE 的收尾集合计算对全库每一条种子先发 torrents/files API 再按 save_path 过滤 —— 目录别名 job 在 qB 重启后走标准收尾路径(missingFiles ⇒ finalize)时, 单个主循环 tick 内串行发 N(全库种子数)次 HTTP, 大库下主循环停摆分钟级; 而判定实际只需要 save_path==src 的成员(covers 分支)与 job.hashes(无需文件表)。

场景: 目录别名形态 job 武装后 qB 重启 ⇒ 对账表 journal removed + 链接不在 + qb_up + missingFiles ⇒ ACT_FINALIZE —— 这是该形态设计的标准收尾路径; _file_map 对 files() 异常按空表吞, 停摆只表现为同步线掉拍。
