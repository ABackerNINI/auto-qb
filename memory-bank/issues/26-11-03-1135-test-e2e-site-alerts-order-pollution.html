05根因（可选）

默认「待查」—— 不为填单做分析。有结论才写；不确定就写已排除的假设，不要把猜测写成结论。

已证实（2026-11-03 12:35，真桩实验 + 代码链路）：根因是桩侧共享状态泄漏， 不是浏览器存储、跨 context 复用或时序抖动。
  • 桩启动用 seed_store() 直写 store.by_hash（保留对象身份），绕过了 apply_sync， 故 store.rid 仍为 0。
  • 第一个 /__harness__/add_torrent|remove_torrent 探针调用 mgr._refresh_torrents(False) ⇒ apply_sync(rid=0) 拿到 FakeClient 的 full_update=true （tests/helpers.py 的 sync_maindata：rid==0 必回全量）。
  • need_validate 为真 ⇒ 内核 emit("full_round")（core/qbmanager.py 同步段） ⇒ TrackerModule._on_full_round（core/modules/tracker_mod.py）把全部 tracker_conf is None 的记录按 client.torrents_trackers() 重匹配。
  • 桩的 torrents_trackers() 默认对任意 hash 都回 HHan URL，于是 _inject_site_alerts 注入的 no_site_conf 行被改回 HHan 配置，_site_alert 回落为空串；tracker_error 行的 tracker_health_msg 不经 full_round，故幸存 —— 这正是「每皮肤 3 条红、第 2 条用例仍绿」的分型。

实测证据（真桩 --torrents 300 --port 8088）：注入后 /api/state 有 2 条 site_alert（no_site_conf + tracker_error）；POST add_torrent 后只剩 1 条 （tracker_error），再 remove_torrent 也不回弹；同一请求序列在修桩后恒为 2 条。

已排除：① BASE_URL 收集崩溃（已另修，收集 440/48 通过）；② 端口/URL 写死；③ site-alerts 自身逻辑 （隔离 8/8 绿）；④ 浏览器 localStorage / page-context 跨 spec 复用（红/绿只随「此前是否跑过含探针的 spec」 变化，与页面存储无关）；⑤ 产品搜索逻辑（探针走生产 _refresh_torrents，被改写的只是桩注入的配置派生态）。

06建议修法（可选）

方向 + 候选方案 + 各自代价；没有想法就留「待定」，只写方案，不在本报告里实施。

方向: 先定位污染源 spec（用已复现的三件套做二分：逐个移出前置集，看 6 红是否消失），再按「谁写谁复位」收口。候选方案与代价：

  • A. 前置自证 + 复位：在 site-alerts.spec.mjs 的 beforeEach 重新注入/校验站点健康两态（桩侧暴露一个 idempotent 的 /__harness__/reset_site_alerts），代价最小但要求桩新增一个只读/幂等端点。
  • B. 污染源隔离：找到改写共享态的 spec（候选 search-* 的 add/remove_torrent、config 保存类），在其 afterEach 复位，代价是要先定位、且容易再回潮。
  • C. 分轮执行：把 site-alerts 划进独立 worker/批次（CI 与 dev.e2e 双份配置），代价是总时长上升、且掩盖真污染。

倾向 A + B 组合：先用二分定位源，A 兜底判据，不选 C。

实际修法（2026-11-03 12:36，改走「修桩」）：根因在桩自身（直写 store 未对齐同步游标），注入态被探针路径 触发的生产 full_round 改写，故不在 spec 侧兜底、也不改产品代码。改 scripts/ui_harness.py： 在 seed_store() + client.torrents 灌入之后补一次真实全量同步 mgr.store.apply_sync(mgr.api) 对齐 rid（生产首轮本就是全量轮），再把 _inject_site_alerts() 移到其后（防止全量 delta 覆盖注入的 tracker 字段）。 效果：所有后续 add/remove 探针都走增量路径，不再触发 full_round 重匹配。spec/产品代码零改动。

验收判据：① 全量 commands run dev.e2e 440 例跑完且 site-alerts 6 条转绿、其余用例无新增红； ② 隔离 commands run dev.e2e -- e2e/site-alerts.spec.mjs 仍 8 passed；③ 三件套组合 （search-auto-refresh + search-uncovered-no-duplicate + site-alerts）全绿。
