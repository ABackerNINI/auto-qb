01现象与发现场景

在 issue 26-11-02-1144（RM04-05 负向对照红灯失守）定位到闸门 GATE_SPACE 有两条拒绝分支，分别对应 relocate_units.py:488 与 L490：

  • L488：target_free is None AND same_volume is not True（空间不可判定 + 跨卷）→ 在 Z:/ 不存在盘上真实命中 → 已用方案 A 补进 RM04-05 负向对照
  • L490：target_free is not None AND target_free < needed AND same_volume is not True（空间可判定且不足 + 跨卷）→ 目前 RM04-05 无覆盖此分支的红验

为什么环境2 做不了（取证 2026-11-02 12:05，入池时所在机器为环境2 C盘机）：disk_usage 实测仅 C:/ 存在（68.3 GB free），D:/E:/F:/G:/H:/ 全 missing。跨卷前置 same_volume=False 在 _same_volume_resolved 里要求 src 与 dst 分属不同卷；只有 C: 盘时上溯到根也在 C: 上 → same_volume=True。且闸门自身 L492 有注释"同卷 rename 不占额外空间，空间预检不适用"——同卷即跳过 L490 分支。

前提更正（2026-11-02 22:43）：上一轮接手时把「本机各卷剩余 ≥ 30GB ⇒ 造不出 target_free < needed」当作不可造结论，这是错的。接手机是环境1(D盘机)，与撰写本 issue 的环境2 不是同一套；环境1 有多个可写卷、可连真实 qB 的写侧，并且存在无盘符的隐藏 Recovery 卷（0.55GB，free 86,564,864 字节 ≈ 82.5MiB）。该卷经 junction 暴露为普通路径后，「跨卷 + 目标剩余严格小于 needed」两个前置同时成立；L490 在一切搬运之前拒绝，不需要向该卷写入。

安全边界复验更正（2026-11-02 23:3x，最终口径）：隐藏 Recovery 卷是 Windows 系统恢复分区，除读空闲外的任何操作都不许可，用 junction 指向它同样不许可。上一轮「隐藏卷 + mklink /J」的构造已废弃并彻底移除（源码、文档、用例推荐做法中均已删除，仅在本 issue 与真机基线留历史证据链）。当前真机前置只认用户显式准备的普通小容量卷路径（环境变量 QBT_REAL_SMALL_TARGET），并有硬守卫拒绝无盘符/系统卷/Recovery-System-EFI 卷标/reparse point/hidden-system/st_dev 跨卷路径；前置缺失时显式断言失败并给准备指引，不静默 skip。

为什么不移除这个分支红验：L490 是 GATE_SPACE 两条拒绝分支之一（不是冗余），且"目标卷空间不足"在跨卷迁移动作中是真实风险场景——目标盘比源盘小、用户预算错误、qB 临时落盘吃满等。缺少覆盖不等于分支没用，应在有条件的机器上补。

05安全构造配方（当前口径：显式入口 + 硬守卫）

只认显式入口：环境变量 QBT_REAL_SMALL_TARGET 指向用户自己准备的小容量目录（绝对路径、带盘符、已存在、非系统卷）。测试绝不枚举、绝不挂接任何无盘符/隐藏/Recovery/System/EFI 卷，也不创建 junction 指向它们。前置缺失或剩余不小于 needed 时显式断言失败并给准备指引，不静默 skip。

硬守卫（tests-real/lib/small_target.py:assert_safe_target，任一不满足即 AssertionError）：

  • 拒绝 UNC / 卷 GUID 路径（\\?\Volume{...}）；
  • 必须是绝对路径且带盘符（[A-Za-z]:）；
  • 必须是已存在的目录（测试不替用户创建目录）；
  • 拒绝系统卷（盘符 == %SystemDrive%）；
  • 拒绝卷标含 Recovery / System / EFI / 恢复 / 系统；
  • 目标路径各级不得含 hidden/system 属性、不得是 reparse point（junction/symlink/mount point）；
  • 目标 st_dev 必须与盘符根一致（拒绝经挂载点跨卷）。

用户准备（唯一指定方式：手动挂载 ImDisk 内存盘，需管理员）：

  1. imdisk -a -s 96M -t vm -o fix -m Y: -p "/fs:ntfs /q /y"（96M=100,663,296 字节，严格小于 needed 134,217,728；-t vm=系统虚拟内存承载，-o fix=固定介质；不要加 -P）。
  2. New-Item -ItemType Directory Y:\small_target，设 QBT_REAL_SMALL_TARGET=Y:\small_target。
  3. 测毕由用户卸载：imdisk -d -m Y:（失败再 -D 强制），复核 imdisk -l 为 No virtual disks. 且 Test-Path Y:\ 为 False。容量按需最小化（≤128MiB），用完必须卸载。

不提供备选：不写小 VHD / 小 U 盘 / 小分区等替代路径；测试不自动枚举、不自动挂载任何卷。

ImDisk 官方依据（2026-11-03 调研）：CLI 内置帮助（本机 v2.1.1）确认 -a 附加、-t vm 系统虚拟内存、-s 单位与后缀（M=MiB）、-o fix/rem 固定/可移动介质、-d 卸载、-D 强制卸载；官方 FAQ 给出 imdisk -a -s 400M -m R: -p "/fs:ntfs /q /y" 与 -o awe 常驻物理内存说明（-t vm 可能被页面文件换出）。2026-11-03 已由用户以管理员挂载 96M 盘并真机跑通，实测数值见 §06。

预计磁盘占用上限：RAM 落点 128MiB（2×64MiB 只写一份，R: 内存盘；缺 R: 时退回 tests-real/.work 真写盘）+ D: dst 搬迁 128MiB + 日志/元数据约 4KB；小容量目标卷 0 写入（用例只读卷剩余与 st_dev，不建叶子）。峰值 ≤ 约 270MiB。

清理：用例 finally 删除 tests-real/.work/rm04 与 R:/qbt-fake/rm04；若闸门失守意外建了唯一 pid 叶子，只删该叶子、不触碰用户目录既有数据；ImDisk 内存盘由用户主导卸载（imdisk -d -m Y:，失败再 -D）。

为什么绝不使用 Recovery 卷：隐藏 Recovery 卷是 Windows 系统恢复分区，写入或挂接可能破坏系统恢复能力；除读空闲外的任何操作都不许可。上一轮曾用它造前置，已废弃并彻底移除（源码、文档、用例推荐做法均已删除，仅 issue 与真机基线留历史证据链）。tests/test_real_machine_safety.py 扫描 tests-real/ 源码，禁止 FindFirstVolumeW/FindNextVolumeW、卷 GUID 字面量、旧构造函数名；再引入隐藏卷路径即红。
