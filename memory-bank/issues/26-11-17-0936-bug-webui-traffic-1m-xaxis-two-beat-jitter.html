计划外问题（未修）· bug

流量图 1m/5m/30m 窗 x 轴抖动: 后端 int(now) 整秒截断撞 1.5s 轮询 → 桶格步进不均（1m/5m 二拍窜动，30m 轻二拍）

1m/5m 桶宽=轮询=采样=1.5s，30m 桶宽=4.5s；build_grid 用 t1=int(now) 整秒截断，Δt1 按相位在 +1/+2 交替。1m/5m 由 (int(now₀) mod3, frac) 联合判据产生 +3.0(2格)/0.0 二拍窜动；30m 由 (int(now₀) mod9, frac) 产生 0/+4.5(1格) 的 2~3 拍不均步进（部分组合连出 0/+4.5 二拍），每次只 1 格且 cellPx≈2px，故更轻。前端 L0 固定 shiftMs 只播有位移拍，死拍无 L0。

§01现象与发现场景

用户复测反馈「流量图 x 轴跳动依然没有彻底解决：之前每拍跳一下，现在每两拍跳一下」。按 1m 窗深挖：该窗桶宽=采样间隔=轮询周期=1.5s、桶数恒 41（没有非整倍窗的 497↔498 翻动拍，排除先前复刻的 R5 根因）；同采样间隔下 5m 窗桶宽也恰为 1.5s、桶数恒 201，命中同一机制。用户随后补报「30m 视图也有轻微抖动，没有 1m 剧烈，也是两拍抖动一次」；真算确认 30m 桶宽 4.5s、桶数恒 401，同源但只走 0/+4.5s（1 格），故更轻。首轮只扫 frac(now) 得出「≥0.5 才二拍」，复评二维复扫发现该判据不成立：frac=0.7 也可能干净（int(now₀)=1000002, mod3=0），frac=0.0 也可能二拍（同样 mod3=0）。1m/5m 的真正判据是 (int(now₀) mod 3, frac(now₀))，30m 走 (int(now₀) mod 9, frac(now₀))，详见 §02。

取证方式：Python 直接调 build_grid 扫相位 + Node 加载真 qb_traffic_chart.js 把生成的 xs 喂给 _qbRollJudge/_qbPadTailColumns 并模拟收敛帧 dropPad，测 settled 视口。未做浏览器目视复现（见 §07 复验 TODO）。

§03影响面

维度结论
触发条件1.5s 桶宽窗（1m n=41 / 5m n=201）+ (int(now₀) mod 3, frac(now₀))：A%3=0 且 frac<0.5 或 A%3=1 且 frac≥0.5 → +3.0(2格)/0.0 二拍；30m 桶宽 4.5s / n=401 + (int(now₀) mod 9, frac(now₀)) → 0/+4.5(1格) 的 2~3 拍不均（部分组合连出二拍交替）。config 现值 qb_traffic.sample_interval: 1.5S（config.yml:544）。3h 起 interval≥22.5s，首桶数拍内不动，不形成可见二拍；默认 24h 桶宽 174s 不受影响 —— 此前 24h 取证测不到。
影响范围只影响 x 轴视口平移节奏（观感），不影响桶值 / tooltip 真值 / 悬停读数。三挂点（全局/分组/种子）共用同一前端逻辑，理论上同样命中；1m/5m 满足上述联合判据时必现，30m 在同一轮询混叠下呈更轻的 1 格不均步进。
严重度低—中 —— 无数据错误、无内容错位，纯视觉窜动；1m/5m 为 2 格固定时长窜动（较重），30m 为 1 格不均 + 死拍（较轻）；但都是用户复测反复报的「x 轴跳动未根治」，属上一次根修（计划 26-11-15-1104）的残留观感问题。

§05根因（可选）

默认「待查」—— 不为填单做分析。有结论才写；不确定就写已排除的假设，不要把猜测写成结论。

已定位（双探针 + 二维复扫取证，非目视）：后端窗锚的整秒截断与 1.5s 轮询/桶宽发生二拍混叠。build_grid 用 t1=int(now) 取整秒；令 A=int(now₀)、f=frac(now₀)，第 k 拍 t1=A+floor(f+1.5k)，first=floor((t1−span)/1.5)×1.5。因此 Δfirst 不是单由 f 决定，而由 (A mod 3, f) 联合决定：A%3=0 且 f<0.5，或 A%3=1 且 f≥0.5 时，窗起点 +3.0/0.0 交替（一拍 2 格、下一拍不动）；其余组合干净 +1.5。对 1m（span=60，first=t1−60−(t1%1.5)）与 5m（span=300）同构。首轮「f≥0.5 才二拍」被两个反例证伪：A=1000002,f=0.7 干净、A=1000002,f=0.0 反而二拍（另 A=1000001,f=0.7 也干净）。
前端 _qbRollJudge 的 rewin 是 |dx0| > step×2，dx0=3.0 恰等于 3.0（边界）判非换档 → L0 放行，把 2 格用固定 shiftMs 滑完（2×速度窜动）；紧接的 0.0 拍 roll=false 无 L0（死拍）。合成「窜一下、停一拍」= 每两拍跳。F5 放宽 roll 门到 ≤2 格 + 补尾格修掉 G-B 左缺口，正是把原来的每拍硬跳变成现在这个更轻的二拍窜动，故频率减半但未消失。
30m 同源但更轻：interval=4.5s（3×si），t1 整数仍每拍 +1/+2，但 first=floor(t1/4.5)×4.5−1800 按 A mod 9 只跳 0 或 +4.5（1 格）；每 6 拍 t1 走 9s、恰两次 +4.5，平均节奏仍对，分配却成 0/+4.5/0/0 或 0/+4.5/0/+4.5/0/0 等簇，部分 (A mod9, frac) 连出 0/+4.5 二拍交替。前端 step=4.5，dx0 只有 0 或 1 格，roll/shift 只在有位移拍真播、死拍无 L0；单格不超速且 cellPx≈2px，观感比 1m/5m 的 2 格固定时长窜动轻得多。
已排除：① 497↔498 翻动拍（1m 桶数恒 41、5m 恒 201、30m 恒 401）；② 数据值 / 尾段失真（真值未错）；③ 粒子 / fx（与 x 视口无关）；④ 24h 默认窗（桶宽 174s）。

§06建议修法（可选）

方向 + 候选方案 + 各自代价；没有想法就留「待定」，只写方案，不在本报告里实施。

  • A · 后端去掉整秒截断（推荐，治本）：build_grid raw 分支让 t1 保留浮点（或按 si 对齐），first = floor(t0/si)×si 直接对浮点 now 对齐，使 Δfirst 恒为 1 格。需确认不破坏 t1 在 meta / holding / 封口桶里的整秒假设（_floor_buckets 注释提到「整值宽归一 int」）—— 改动面在后端栅格单点及依赖它的电池，面较大。
  • B · 前端按格数放大滑动时长（治标）：让 shiftMs 随 |dx0|/step 线性放大，消除 2×速度窜动。代价：死拍（0.0）仍在，二拍节奏未根治，只是每拍位移视觉变均匀；且与 I1「真值 ≤beat 落地」预算冲突，需重排时间线。

守阵建议：若走 A，在 test_traffic_grid_*.py 加「1m/5m 任意 (int(now₀) mod 3, frac) + 30m 任意 (int(now₀) mod 9, frac) 组合下 Δfirst 恒 = interval」的二维扫描用例，不能只扫 frac；e2e 帧探针相位注入要同时钉死 epoch 对齐（1m/5m 推荐 A=1000000,f=0.7 与 A=1000002,f=0.0；30m 推荐 A%9=3,f=0.0 与 A%9=4,f=0.7 两条二拍簇）再断言 settled 视口。两条路都需先目视复验（§07）。
