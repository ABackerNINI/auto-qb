06建议修法（可选）

让循环固定在同一天内（推荐）：把 ts 取为当日 00:01（如 ts = int(time.time()) // 86400 * 86400 + 60，或 datetime 取当日 00:01），则 ts + i（i ≤ 2030s）恒同日，护栏计数不再跨天清零；两条用例同改。注意 v4_epoch_date_str 的日界时区口径要与取 ts 的一致（改时对齐，否则新 flaky）。

备选（不推荐）：把步长压小、总跨度 < 到零点的剩余秒数 —— 脆弱，换个时刻又红。

修复后补充

实际修法：两条用例把循环起点 ts 锚到当日 00:01 —— ts = v4_day_epoch(int(time.time())) + 60（v4_day_epoch 本地口径单点，与 v4_epoch_date_str 一致），跨度 <86400 恒同日，_day_events 不再跨天清零。两条同改（test_recorder_patological_flip_guard / test_recorder_warn_first_fire_on_fresh_boot 场景 B）。

与建议修法改道原因：建议写 int(time.time()) // 86400 * 86400 + 60（UTC 秒对齐），改道用 v4_day_epoch —— 后者按本地时区（与 v4_epoch_date_str 的 datetime.fromtimestamp 口径）取当日 00:00，前者按 UTC 秒对齐；非 UTC+0 时两者日界不一致，建议形态会把 date = v4_epoch_date_str(ts) 与循环跨天判定错位，在 UTC+8 上距零点 <8h 仍跨天 —— 用仓库现单点 v4_day_epoch 对齐两端口径，避免新 flaky。

验证方式：① test.one tests/test_traffic_limits.py 13 passed；② 时刻无关证 —— 把 time.time() 钉距零点 1359s（死窗）跑两用用例 2 passed（修复前同时刻直读探针 day_events=672、告条 False 即红验锚点）；③ 全量 test.full 全绿，数字见 commands run kb.baseline。
