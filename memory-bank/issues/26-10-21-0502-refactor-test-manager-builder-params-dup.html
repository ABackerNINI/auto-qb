01现象

helpers.make_manager 是 manager 构造单点（45 文件在用），但不收 config 覆盖参数 —— 需要 grouping / add_episode_tags 等段的测试只能内联 cfg=FakeConfig()+改段; QbManager("", config=cfg, no_lock=True); client=FakeClient(); mgr.client=client，全 tests 89 处 / 15 文件（test_grouping 60 / test_episodes 5 / test_delete_tags 5 / test_hr 4 / test_checking 3 等）；test_grouping 因此成为 jscpd 自克隆最大户（210 行/19 组）。

02位置

文件 + grep 关键词（比行号稳）；行号要标取证时间。

  • tests/helpers.py:1102（make_manager）· tests/test_grouping.py（grep QbManager("", config=cfg，60 处）· tests/test_episodes.py:24 等（取证 2026-10-21，基线 cecbe4a9）

03建议（可选）

make_manager 加 cfg 覆盖参（如 cfg_mutator 回调或 **overrides），内联装配回收 —— 扩参数而非新建第二构造器；与 test_grouping 归组样板（R24-C-02）同根一并收敛。

04实际修法 / 验证

按建议修法落地（扩参数而非新建第二构造器），复验实测把规模从「89 处 / 15 文件」校正为 86 处 / 12 文件（差在：原计数含 test_web_seed_center / test_qbmanager_alias_freeze 的 docstring 提及，以及 helpers.py 单点本体）。

  • make_manager 参数面扩为 state_file / tracker_rules / tracker_kw / cfg / client / no_lock / bare / load_rules / **cfg_overrides，三种装配形态：默认（假 tracker + 三条示例规则 + load_rules()，与改动前逐字等价）、cfg=（现成配置对象，供共享 cfg 与包装器委派）、bare=True（空 FakeConfig + 段覆盖，86 处里绝大多数走这条）。
  • load_rules 三态（None / True / False）：内联用例本来就不加载规则，让 cfg/bare 路径默认加载等于顺手改了它们的装配语义（grouping 用例断言 task_queue._fast 无多余任务）；故 None = 自动（默认装配 True，cfg/bare 路径 False），自备 rules_config 的三处显式 load_rules=True。
  • **段覆盖 未知段名抛 TypeError（fail-fast）：**kwargs 静默 setattr 会在段名写错时造出幽灵属性——配置没生效而测试照样绿，那是「旁路」的变体形态。
  • grouping_cfg() 收分组段单点（missing_tag="MISSING" 口径），替换 test_grouping / test_state_matrix 两份逐字相同的 _group_cfg 与 test_modules_p4 的 _mgr 装配。
  • 新增静态守阵 tests/test_manager_single_point.py：AST 扫 tests/*.py，除单点本体 helpers.py 外零豁免（持锁走 no_lock=False、自备配置走 cfg=、空配置走 bare=True，没有绕不过去的场景），另带一支「造违规文件必须被报出」的自检，防扫描型守阵退化成恒绿。
  • 测试面 13 文件 净 −91 行（165+/256−）；src/ 零改动。
