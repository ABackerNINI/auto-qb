§01现象与发现场景

存量评审 R4·webui-py(issue 26-11-07-0536)认领修复轮批I 修表行19(R4#19)时发现的相邻残留: 批I 已给 _ensure_thread 的检查+创建段加实例锁(_ensure_lock), 但 stop() 的两条路径全在锁外 —— 起停并发仍有两条竞争路径。本轮不改码入池。与平台/配置无关。

§02证据

取证 2026-11-08(分支 fix/r4-webui-py 顶 6352ccc8), src/auto_qb/webui/tool_client.py:195-204:

  • 路径①: stop() 在锁外 join 期间, _ensure_thread 可经 _ensure_lock 起一条替换线程; stop() 随后把线程引用置 None —— 替换线程的引用被丢成孤儿, 双订阅(先注册 sub_id 被后者覆盖后泄漏到工具租约过期)。
  • 路径②: _stop.set() 落在锁内 clear() 之前, 新起线程读不到停位(标志位未过锁/无代际计数), 照常运行。
  • 相邻修复参照: 批I(表行19/R4#19, 6352ccc8 前的 a79cc045)只锁了 _ensure_thread 的检查+创建段。

§03影响面

维度结论
触发条件stop() 与 _ensure_thread 并发(如热重载 sync() 与设置页「立即拉起」同时发生); 窗口窄但存在
影响范围tool_client 线程生命周期; 孤儿线程双订阅, sub_id 泄漏到工具租约过期
严重度中(竞态窗口窄, 后果为资源泄漏/双订阅)

§04定位锚点

  • src/auto_qb/webui/tool_client.py:195-204(取证 2026-11-08)· 符号 stop/_ensure_lock/_ensure_thread · grep _ensure_lock

§05根因（可选）

待查(批I 只收了起侧竞态, 停侧未纳入同一把锁 —— 具体交错时序待认领时复验)。

§06建议修法（可选）

置 None 挪进锁 + 同一性判断(join 后确认仍是当前线程才置 None); 路径②需标志位过锁或代际计数。
