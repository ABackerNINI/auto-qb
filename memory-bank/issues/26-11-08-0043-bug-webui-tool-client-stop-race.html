§02证据

取证 2026-11-08(分支 fix/r4-webui-py 顶 6352ccc8), src/auto_qb/webui/tool_client.py:195-204:

  • 路径①: stop() 在锁外 join 期间, _ensure_thread 可经 _ensure_lock 起一条替换线程; stop() 随后把线程引用置 None —— 替换线程的引用被丢成孤儿, 双订阅(先注册 sub_id 被后者覆盖后泄漏到工具租约过期)。
  • 路径②: _stop.set() 落在锁内 clear() 之前, 新起线程读不到停位(标志位未过锁/无代际计数), 照常运行。
  • 相邻修复参照: 批I(表行19/R4#19, 6352ccc8 前的 a79cc045)只锁了 _ensure_thread 的检查+创建段。

复验

复验 2026-11-08 19:03（锚点 37710f5e，分支 fix/issue-batch-26-11-08）——仍复现。批I 后现状：_ensure_thread 的「检查+清停位+创建+start」段已整段持 _ensure_lock，但 stop() 三步全在锁外（置停位 / 取引用+join / 置 None）。真实交错时序：

  • 路径①（丢引用成孤儿）：旧线程 T1 收线 → stop 锁外 join T1 返回 → 同一窗口 _ensure_thread 持锁见 T1 已死，起替换线程 T2 并把 self._thread 换成 T2 → stop 随后无条件 self._thread = None → T2 引用被丢成孤儿（无人能 join，下轮 sync 见「无线程」再起一条 = 双订阅，先注册的 sub_id 泄漏到工具租约过期）。
  • 路径②（停位被抹）：T1 已死 → stop 锁外 _stop.set() → _ensure_thread 持锁已过 is_alive 检查，随后 _stop.clear() 把停位抹掉 → 起替换线程 T2 读不到停位照常运行（stop 语义落空；与①叠合则再丢一次引用）。

修复后补充

实际修法（建议 §06 全盘采纳：标志位过锁 + 同一性判断，未引入代际计数或新并发原语）：stop() 的「置停位+取线程引用」整段挪进 _ensure_lock；join 留锁外（持锁 join 会与 _ensure_thread 互卡死——死锁自查：三段临界区内只有 Event.set / 引用读写 / 造线程+start，_run 与控制面动作全程不取这把锁，无重入无嵌套，Thread.start() 只等线程自举不取锁）；join 成功后回锁内做同一性判断 if self._thread is thread: self._thread = None；超时未退出仍不摘引用（既有口径不变）。

交错枚举（置停位与清停位被同一把锁全序化后）：

  • 置停位在锁序上晚于 ensure 的清停位+起线：新线程的事件被置位，当轮收尾即照停，stop 锁外 join 它、同一性匹配清引用 —— 路径②闭合；
  • 置停位早于 ensure 的清停位+起线（仅 T1 已死时可达）：那次起线请求在锁序上晚于本次关停，等价于「stop 之后再 sync」的合法重启（_ensure_thread 文档既有口径），引用不丢、后续 stop 可补 join —— 并发的起/停请求以锁序后者赢，这是重启语义下的不可归约残留（不是孤儿面，孤儿双订阅已闭合）；
  • join 期间 ensure 换上替换线程引用：join 后同一性不匹配，不置 None —— 路径①闭合；
  • 超时未退出：保留引用待补 join（test_stop_is_bounded_when_tool_hangs 继续守）。

孤儿泄漏面（sub_id 挂到租约过期）随「引用不丢 + 停位必达」闭合：不再存在无主线程持 sub_id 空转的形态。测试（commands run test.one -- tests/test_traffic_monitor_client.py）：39 passed（含新增 3 条确定性交错用例 —— 事件 / join 钩子 / 线程构造闸钉死交错，不靠 sleep 碰运气）；变异验证：修前代码跑新增用例 2 failed 1 passed —— 路径①为确定性 failed，路径②修前为概率性 failed（旧 stop 不取锁，stopper 可在 ensure 换上 T2 引用之后才取旧引用，存在窄通过窗口；实测一例 failed），修后全绿；test.quick 全量 5854 passed 2 skipped。
