03影响面

维度结论
触发条件非优雅终止（taskkill /F / 原生崩溃 / OOM / 断电 / 关机 / 注销 / 关闭控制台窗口）；Ctrl+C 与托盘退出不受影响
影响范围state.json 全部键：exec_history（execute_once/cooldown 去重）、skip_check_day（同日跳检去重）、recheck_fails（校验失败冷却）、upload_snapshots（周期上传基线）、auto_categories、reannounce_ts。state.json 文件本身无损坏风险（atomic_write 保证全旧或全新）
严重度高 —— 丢失量 = 整个运行期；重放有实际代价：skip_check_day 丢失 ⇒ 同日可重复跳检（PT 本地统计再丢一次）、reannounce_ts 丢失 ⇒ 可立即再 announce；其余重放多为幂等 API 重复调用（动作插件普遍先查状态再写）

06建议修法（可选）

方向 + 候选方案 + 各自代价；没有想法就留「待定」，只写方案，不在本报告里实施。

方向：把丢失窗口缩小到可接受量级，不追求零丢失。

  • 候选 A（推荐）：状态变更后 debounce 周期落盘（60–300s）。本项目状态真实变更频率为小时~天级，写放大代价近乎零；.bak 管线保持不变。
  • 候选 B：低频关键键（skip_check_day / recheck_fails）变更即落盘 —— 这两个键的重放代价最实在，且变更天然低频。
  • 候选 C（可选叠加）：Windows 注册 SetConsoleCtrlHandler（CTRL_CLOSE_EVENT / CTRL_SHUTDOWN_EVENT 有数秒清理窗口），落盘后退出。
  • 验收：补守阵「模拟脏退出后重启，exec_history 保留量符合新策略」。

修复后补充

实际修法 —— 采纳候选 A(周期落盘) + 候选 B(关键键即时落盘)；候选 C (SetConsoleCtrlHandler)未采纳：它覆盖不了 taskkill /F / OOM / 断电这个主威胁面 （Windows 关控制台的 CTRL_CLOSE_EVENT 也不进 Python 异常语义），只救得到其中一种情况，复杂度不值。 另按用户拍板新增配置端 30s 下限（建议里没有）：

  1. 新配置键 state_save_interval（默认 120s，0 = 关闭回到旧行为）： 五处注册（models / loaders / schema / validation / impact=L0 热重载即时生效）； 校验为「合法时间格式且为 0 或 ≥ 30s」—— 下限防误配置写放大（STATE_SAVE_INTERVAL_MIN）。
  2. 主循环周期落盘：RuleEngineMixin._maybe_flush_state，挂在 run() 正常路径 flush_truths() 之后、if not dry_run 门内；到期点在 run() 加载状态后 重置（启动即到期会造成无意义重写）；暂停分支不经过（暂停期无变更）；单一写线程约束不变。
  3. 关键键即时落盘：skip_checking.py 跳检完成标记（skip_check_day）后显式 save —— 不能指望 _clear_backup 顺带落（备份元数据为空时它提前 return，不经过 save_state）； full_checking._bump_recheck_fail 尾部 save（上界 3 次/日/种）。 exec_history 刻意不即时（初轮爆发式写入放大写盘，重放多为幂等，交给周期兑底）。
  4. 不做写点级 dirty 插桩（否决候选之一）：state 写点散在 7 个文件约 12 处， 逐点插桩必漏（与「.bak 没人读」同一形态）；周期兑底对未来新增写点自动生效。

验证方式 —— 新增 9 条守阵（均已同步各测试文件头部测试计划清单）：

  • test_maybe_flush_state_periodic / test_maybe_flush_state_disabled_zero —— 到期触发顺延 / interval=0 逃生口恒不落。
  • test_dirty_exit_keeps_exec_history_after_periodic_flush（验收阵）—— 记录执行历史 → 周期落盘触发 → 实例被弃（不走 finally，等价 taskkill /F）→ 新实例加载，exec_history 在盘上； 对照阵 test_dirty_exit_interval_zero_loses_runtime_state 钉住 0 = 旧行为。
  • test_checking_skip_day_flushed_immediately / test_recheck_fail_flushed_immediately —— 两个写点落盘后直接读磁盘断言（不等退出/周期）。
  • test_validate_state_save_interval —— 0/30S/120S/2M 合法；29S 报「须为 0(关闭)或 ≥ 30S」； 裸数字/负数报格式错误。
  • test_state_save_interval_is_l0 —— L0 分级（热重载即时生效）。
  • test_periodic_flush_is_wired_in_run_loop —— 接线守阵：钩子必须在 run() 的 not dry_run 门内、到期点必须在加载状态后重置。
