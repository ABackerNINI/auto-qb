01现象与发现场景

RM02 真机实测写 tests-real/rm02_loop/test_rm02_loop.py::test_rm02_06 托管小节时撞见: 用 lib/app.py 的 graceful 跑壳(进程内 threading.Timer → signal.raise_signal(SIGTERM), 与 RM01-07 验证过的 CLI 优雅退出同法)对 --tray 进程发停止信号, 进程不退出。CLI(非托管)模式同法 rc=0 正常收尾。

03影响面

维度结论
触发条件--tray 模式 + 外部投递 SIGTERM(服务化/脚本停止/进程管理器); 托盘菜单「退出」路径(stop_event+wake)不受影响
影响范围声称的「SIGTERM 转入 Ctrl+C 同款优雅关闭(所有模式一致)」对托盘模式失效: 状态不落盘、锁不放(靠 filelock 进程死才释放); 自动化停止只能强杀
严重度中(承诺的停止语义与实际不符; 用户常驻的恰是托盘形态)

04定位锚点

  • src/auto_qb/cli.py:41-45(取证 2026-10-31 10:30)· _sigterm_to_keyboardinterrupt · grep「SIGTERM」: handler 在主线程 raise KeyboardInterrupt。
  • src/auto_qb/cli.py:139 · grep「所有模式一致」: 注释声称对托盘同样生效(与实测相悖的点)。
  • src/auto_qb/tray/app.py:509 · TrayUi.run · grep「mainloop」: 主线程阻塞在 Tk mainloop; 推测 KeyboardInterrupt 在 Tk 回调层(report_callback_exception)被吞 —— 待查, 未做代码验证。

待查（已排除：跑壳本身 —— 同一跑壳对 CLI 模式同时刻验证有效(RM01-07/RM02-02 rc=0); 已排除信号未送达 —— handler 已注册且 CLI 模式可触发）。候选解释: 主线程长期处于 Tcl C 调用内/回调包装层, KeyboardInterrupt 被吞。

修复后补充

实际修法(2026-11-01, 档案 memory-bank/tasks/26-11-01-backend-tray-sigterm-quit.md):

  • 根因修正: KeyboardInterrupt 并未被 Tk 吞 —— 复验日志已见 cli 捕获点 Shutting down..., 纯 tkinter 最小实验亦证 after 回调里的 KeyboardInterrupt 能从 mainloop 传播。真断点: 异常把 TrayUi.run() mainloop 之后的收尾编排(停托盘/停 manager/清 IPC)整段跳过, 而进程退出挂在 pystray run_detached 非 daemon 线程(pystray/_win32.py:130)的 threading._shutdown 上(daemon 的 manager 线程还在继续重试连接)。
  • 修法(采纳建议方向 a/b 合流 + 补一档): ①tray 模式 SIGTERM handler 换装为「投递 quit 事件」(TrayUi._sigterm_to_quit/_install_sigterm_quit, run() 开头换装, 首信号后 SIG_IGN) —— 与托盘菜单「退出」同一条停止编排; ②run() 收尾移入 finally —— Ctrl+C 等异常路径也保证收尾后上抛(关的是「异常跳过收尾」这一类)。§05 的根因与 §06 的前提「被吞」描述按复验证据改道, 建议方向本身被采纳。
  • cli.py「所有模式一致」注释如实化(非托盘经 KeyboardInterrupt / 托盘由 TrayUi 换装交接)。

验证方式:

  • headless 守阵 4 条(tests/test_tray.py): handler 本体只投递 quit 事件+SIG_IGN / 注册失败静默 / run 正常退出编排含换装断言 / run 异常路径收尾; 红绿双验(raise 突变、finally 退化突变各命中对应守阵后精确还原)。
  • 真机回归: graceful 跑壳 SIGTERM@25s 对 --tray 3/3 于 27.0s 退出 rc=0, 无「主循环未在 10s 退出预算内收尾」WARNING, ui.port 清理, stderr 无堆栈(修复前同法 3/3 观测 70s 不退)。qB 两实例当时不在线, 与 RM02-06 的 dead-port 等价(本件证据已声明 qB 无关)。
  • 托盘菜单「退出」与 SIGTERM 现为同一代码路径(quit 事件); 菜单点击本体属人工验收面。
