01现象与发现场景

2026-11-01 收尾一轮任务（core/ W9b 变异审计，档案 memory-bank/tasks/26-10-08-test-mutation-audit.md）后做远端合流：把本地 37 笔提交 rebase 到远端新基 6a390e76。两次跑 commands run my-commit-flow.sync 都失败，且失败行不含冲突清单。

人工用 git merge-tree --write-tree --name-only 6a390e76 1aed1a33（非破坏性探测，不写工作树）查出冲突面只有 3 个文件，全部在 gen_all.py --list 的生成物白名单内。随后手动 rebase 逐轮化解 8 次，全部成功，零手写件冲突。

平台 Windows Git Bash，git 2.55。第一次失败的直接脏源是当时尚未被 .gitignore 忽略的未跟踪 .tools/（属「.gitignore 还没进本地 HEAD」的阶段性问题，与本次要记的缺陷无关，仅作背景）。

03影响面

维度结论
触发条件分叉（本地领先多笔提交）+ 远端新基改变了生成物集合（新增 / 移除一个生成物路径）；每停一轮 rebase 都会重跑生成器
影响范围多 clone 并行时每次合流都要人工介入（本轮 37 笔 / 8 轮）；失败行不给冲突清单，需自己 merge-tree 探测才能判断「其实全是生成物」
严重度中 —— 不丢数据（失败即整体回滚），但把自动化的价值全吞掉，且失败行的可观测性反向误导「有手写件冲突」

05根因（可选）

默认「待查」—— 不为填单做分析。有结论才写；不确定就写已排除的假设，不要把猜测写成结论。

待查 —— 下面两条是假设，不是结论；已实证 / 待验证分开写。

已实证（事实）

  • 冲突面 3 件全部在生成物白名单内（merge-tree 探测 + 8 轮人工化解零手写件冲突）。
  • 白名单集合随树内容漂移：同一条 --list 命令在旧 tip 树给 21 行、在 rebase 中的树上给 23 行；差的 2 条（plans/attachments/_archive.md、tasks/attachments/_archive.md）确认为 rebase 前旧树里不存在的文件。
  • 失败行不含冲突清单：conflict_line（sync.py:425）构造的模板里本就没有路径位。
定案（2026-11-02 00:49 复验后）：主因 = 假设 B 实证 —— 每轮重跑后只 git add 冲突集，重跑把其它干净自动合并的白名单件改成 MM 态，rebase --continue 被 git 拒绝。假设 A 排除：白名单本就是每轮循环重算（无「rebase 前旧快照」），但它影响的是 add 面 / 收尾 amend 面（新基引入的新生成物路径会被重跑写成未跟踪/MM 件，不在 add 范围）—— 与 B 同根，修法一并覆盖。红验：把修后代码的暂存面还原成「只 add 冲突集」，最小复现用例即红。

假设 A（次要候选）：白名单求值时机

重跑生成器时白名单是对半重放中的树求值的，因此集合与「rebase 前那次求值」不一致；重跑会写到旧快照以外的路径。待验证，因为按代码 _whitelist 是每轮循环重算（sync.py:299）而非 rebase 前求值一次 —— 它更可能以「重跑写出的路径不在 git add 覆盖范围 / 不在 _modified_paths 的 M 过滤里」的形态影响覆盖率，而不是直接触发拒绝。

验证方法：合成一个仓（远端新基新增一个生成物路径 + 本地有与生成物重叠的提交），在 _whitelist / _regen / _self_check 三处打点，记录每轮求值的行数与集合差，并采集 git status --short。最小复现步骤：①在镜像 clone 造一个分叉（远端新基多一个生成物路径，如新增一个带 _archive.md 的文档族）；②本地造 1 笔以上会与该生成物重叠的提交；③跑 commands run my-commit-flow.sync，记录失败行与 git status --short。

假设 B（主因候选）：重跑后只 add 冲突集

_regen 会把其它干净自动合并的白名单件改出「已暂存 + 又有未暂存修改」（MM 态），而 sync.py:316 只 git add 冲突集 ⇒ rebase --continue 被 git 拒绝 ⇒ 整体 abort ⇒ 对外仍是同一句「需解决冲突」失败行。机理与已记坑档 pitfalls/git/rebase-continue-needs-clean-index.md 同款，且能解释「第一轮冲突件（issues/attachments/_archive.md，本就在 21 行白名单内）也没被自动化解」。待验证：本轮失败时未采集 git status --short 现场，无法区分是 continue 被拒、_regen 非 0、还是 _self_check 未过。

06建议修法（可选）

方向 + 候选方案 + 各自代价；没有想法就留「待定」，只写方案，不在本报告里实施。

  • 观测面（最小改动，建议先做）：失败行带上冲突清单（前 N 条 + 总数）与回滚原因分级（rebase 未落地 / 重跑失败 / 自证未过 / continue 被拒）。代价：改一处失败行模板 + 一处异常分派。
  • 暂存面：_regen 之后按「白名单 ∩ 全部改动路径（含新增）」一并 git add，而不是只 add 冲突集。代价：需把 _modified_paths 的 --diff-filter=M 扩到 A/M，并复核不会把手写件卷进来。
  • 求值时机：把白名单求值钉在「rebase 落地后的树」上，或对两次求值做差集告警。代价：需要在 rebase 中途的合法状态下求值，需先验证假设 A。

三条互不冲突，可先做观测面让下次复现自带现场。

修复后补充

实际修法（2026-11-02 落库，.commands/my-commit-flow/scripts/sync.py）：建议三条全部采纳，互不冲突——

  • 暂存面（主因修复）：新增 _changed_paths()（status --porcelain -uall 全量改动路径，含新增/删除/未跟踪），化解循环里暂存 冲突集 ∪ (白名单 ∩ 全部改动路径)；收尾 amend 的 dirty 判定从 _modified_paths()（仅 M）换成同款全量交集 —— 新基引入的新生成物路径（未跟踪件）由此入库，不再卡 continue。
  • 观测面：_resolve_rebase 返回值扩到五元组（末位 = 失败原因人话分级），失败行在「已自动回滚」后带 (原因; 冲突清单) —— 分级覆盖白名单取不到 / 含非生成物 / 重跑失败 / 自证未过 / 超限；清单前 5 条 + 总数（DETAIL_CAP=5）。约定模板前缀「需解决冲突 本地x 远端y」逐字保留（commit.py 透传与守阵不变）。
  • 求值时机：无需单独改 —— 假设 A 排除后确认每轮重算本就正确，暂存面取「当时白名单 ∩ 当时改动路径」已把漂移覆盖。

验证方式：真实临时仓守阵两条新增 —— test_sync.py::test_diverged_new_generated_path_autoresolves（本 issue 最小复现：远端新基引入 gen/b/arc.md + 本地重叠提交 → 自动化解成功、新件重跑后入库、status --porcelain 零残留）与 test_conflict_failure_line_lists_conflicts（失败行带「冲突含非生成物: base.txt」）。红验通过：把暂存面还原成旧行为，新复现用例即红（FAILED），恢复修复后转绿。基线 151 → 153 passed（commands run test.pkg.scoped -- .commands/my-commit-flow，36.6s；红验 1 failed / 恢复后 153 passed 40s）。
