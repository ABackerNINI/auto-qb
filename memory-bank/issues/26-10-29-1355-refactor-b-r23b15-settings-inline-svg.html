01现象

03分歧点与判定

  • 搜索图标（×2）：内联 path ↔ sprite #i-search，几何逐字相同 ⇒ 纯冗余，换 <use> 零视觉差。
  • 加号（×2）：内联 ↔ #i-plus，几何差 0.4 单位（3/10 vs 3.4/9.2）⇒ 换过去有微小可见变化，需拍板，本项不做。
  • 返回箭头 / 导入箭头：sprite 无对应 symbol ⇒ 若要统一须三皮肤同步加 symbol（改 3 份 80 行 sprite 段），成本 ≫ 收益，本项不做。
  • 是否有意分叉：无判据。全文件没有一句注释说明「为何这几处内联」，而 26-10-20-2231 那次 sprite 统一也没回头收它。归类 (b)：无判据漂移，只对「逐字同形」的那两处可无风险收敛。

判定：值得做（refactor / light，范围只取搜索图标这两处 + 一行纪律注释）。① 重复真实：同一 path 在仓内共 3 份（settings ×2 + 三皮肤 sprite 各 1）；② 行为可保持：#i-search 与内联 path 几何逐字相同、viewBox 相同、描边同样由 .hb-ico 给出 ⇒ 像素等价；③ 可验证：既有 sprite 三皮肤对齐守阵 + 把「#i-* 必须命中 sprite」的断言扩到 shared/tpl/*.html（否则将来引用到某皮肤缺的 symbol 会静默空白）+ 设置页抬头真浏览器截图比对；④ 收益中（消 2 份拷贝、图标来源纪律成文）＞ 风险极低（仅 2 行标记替换）。
