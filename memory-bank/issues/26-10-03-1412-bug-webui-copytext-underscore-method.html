01现象与发现场景

来源：另一 agent 在真浏览器验证 WebUI 抽屉 / 弹窗时上报（2026-10-03）；本轮只做入池记录， 未起真浏览器复现，报错原文未采集（见第 02 节备注）。

现象：shared/tpl/drawer.html 常规页长值块行（路径 / 哈希 / 备注）与 shared/tpl/popovers.html 弹窗详情行的「复制」图标按钮，@click 处理器写成下划线前缀的 _copyText(...)；真浏览器点击恒抛错，复制功能不可用。

同源坑位：memory-bank/pitfalls/web-ui/vue-reactivity.md「模板里不允许下划线前缀标识符」 已把本次记为 复发 1（2026-10-03；未命中原因：判别当时只写了插值形态， @click="_x()" 这类事件绑定形态对不上没认出来）。drawer.js 侧已注释钉原因。

05根因（可选）

默认「待查」—— 不为填单做分析。有结论才写；不确定就写已排除的假设，不要把猜测写成结论。

待查 —— 本轮未起真浏览器复现，不把上报结论当结论写。

已排除：不是漏定义 —— commands.js:594 确有 _copyText，且 drawer.js:442 用 this._copyText(...) 调得到，说明该成员在组件实例上是可达的； 差异只出现在模板表达式解析这一条路径上。

上报方假设（未验证）：Vue 3.5 把 _ 前缀当内部保留域，模板里的 _copyText 解析不到 ⇒ ReferenceError ⇒ 整块渲染失败。该说法与坑位 vue-reactivity.md 的记录一致。

待排除：commands.js 的方法究竟以哪种方式挂进组件（mixin methods / setup() 返回 / data 键）—— Vue 3 对 _ / $ 前缀的过滤规则 在 data、setupState 与 methods 上并不完全一样，需真机抓原始报错才能定性。

复现手法：用 scripts/ui_harness.py 起页面（坑位文件里给过同类手法）， 打开种子详情抽屉常规页点一次复制钮，DevTools console 取报错原文与栈。

06建议修法（可选）

方向 + 候选方案 + 各自代价；没有想法就留「待定」，只写方案，不在本报告里实施。

  1. 最小面（推荐）：保留 commands.js::_copyText 不动，在 methods 上补一个无下划线别名 copyText(v, l) { return this._copyText(v, l); }，两处模板改调 copyText(...)。 改动 = 2 行模板 + 1 处别名；JS 内部 this._copyText 调用点全部不动，回归面最小。
  2. 彻底：把 commands.js::_copyText 重命名为 copyText，同步 drawer.js:442 的调用点。改 2 文件 3 处，代价是内部「_ = 内部约定」的命名约定要一并调整。
  3. 防复发（建议与 1 或 2 一起做）：加一条静态守卫 —— 模板里禁止 _ / $ 前缀标识符，且必须同时覆盖插值与指令表达式两类形态（本次复发的根子就是判别只记了插值形态， @click="_x()" 没被认出来）。本轮扫描只有 2 处，可一次清干净后再上守卫。
