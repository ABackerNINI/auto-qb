01现象与发现场景

设置页 → 某站点 HR 详情表 → 点任意列头: 无排序、无光标变化、第三次点击也回不到默认序。表头右缘能看到排序箭头位, 但列头「看着能点、点了没反应」。

发现场景: 重复代码审查 B 类复核(本专题)核对 R23-B-10「aq-table thead / grid 双分支排序箭头口径相反」时, 顺着「thead 分支没用到 col.sortable」这条线索读后端字段来源, 发现 HR 详情表的列定义**一个都没有** sortable 标记 —— 于是同一份表壳的两分支在能力判定上分叉成了「grid 能用 / thead 全哑」。

03影响面

维度结论
触发条件必现, 与数据量/配置无关: 设置页任一站点展开 HR 详情表(需该站点有 HR 明细行), 点任意列头。
影响范围设置页 HR 详情表一处(thead 模式当前唯一调用点)。hrsSetSort 三态机/hrsCompareRows/sortSel 全套实现仍在但没有可达入口 —— 该表的排序能力整体不可用, 而非仅某一列失效。

05根因（可选）

默认「待查」—— 不为填单做分析。有结论才写；不确定就写已排除的假设，不要把猜测写成结论。

根因已定位(非待查): 表壳两模式对「列是否可排序」的判定源不一致 —— grid 读 col.sortable, thead 既不读它(硬编码 class="sortable"、箭头恒渲染), 又在行为侧被 headActivate 的 col.sortable 门控拦住; 而 thead 唯一的调用方(HR 详情表)列定义从未标 sortable。视觉与行为各取一半, 两端都无法自证。

5aria-sortheadAriaSort 同门控 ⇒ 恒 null与「看着能排」的视觉相反, 读屏反而「正确」地什么都不报

判定: 这不是「两种合理口径」, 是同一判据(col.sortable)在视觉侧与行为侧被各用一半后产生的**静默失效**。原报告把它记成 B 类「无注释的用户可见差异」; 今天补查后端/注册表字段后升级为缺陷 —— thead 模式当前唯一消费方(HR_TABLE_DEFS.hrDetail)恰好是「零列可排序」的形态, 差异从「审美不一致」塌成「功能整体不可用」。

06建议修法（可选）

方向 + 候选方案 + 各自代价；没有想法就留「待定」，只写方案，不在本报告里实施。

方向: 让两模式共用**同一份**可排序判据, 且判据落在列定义(唯一事实源)上; 模板只呈现。

  1. 首选(最小面): 在 HR_TABLE_DEFS.hrDetail.columns 上按真实能力补 sortable: true(hrsCompareRows 支持哪些 key, 就以哪些为准 —— 先读该函数, 别把全部 10 列一刀切), 并给 thead 分支补 v-if="col.sortable" 的箭头门控 + :class 里用 col.sortable 取代硬编码 sortable。两模式至此判据同源, 视觉与行为一致。
  2. 备选: 若认定「HR 表列头排序本就不该有」(features 里的 sort: true 就需同步改), 则应删掉 @sort 接线与 thead 的箭头/可点样式, 把不可点说清楚 —— 但不能保留现在这种「箭头 + 光标 + 点击无声」。

不推荐「在 thead 分支去掉 headActivate 门控」: 那会让不可排序列也能 emit, 把 hrsSetSort 的 key 校验责任推给调用方, 与 grid 分叉更大。

验证手段

  • 既有静态守阵可扩: tests/test_webui_static_skins.py::test_frontend_hr_detail_table_wiring(已断言三皮肤 .hr-detail-table th.sortable 等规则)与 tests/test_webui_static_dom_panel.py 的 DT_TABLE.hasArrow 段 —— 加一条「thead 分支含 v-if="col.sortable" 且 HR_TABLE_DEFS.hrDetail.columns 至少一列 sortable: true」的静态断言即可锁死回归。
  • 等价性: 真浏览器开设置页 → HR 详情表 → 点同列三次, 行序应依次为「降序 / 升序 / 后端默认序」(hrsCompareRows + hrsSortKeyOf 既有语义), 且 aria-sort 与箭头同步。
  • 回归面: thead 是当前唯一 mode="thead" 调用点(grep 'mode="thead"' 命中 settings-detail.html:296 + 模板注释), grid 四表不受影响。
