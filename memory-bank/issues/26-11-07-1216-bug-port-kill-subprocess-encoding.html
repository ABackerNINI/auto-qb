§01现象与发现场景

发现场景: R4 scripts 修复批（2026-11-07 会话，修复存量评审 R4 的 24 条 scripts findings）的清单外发现，经只读评审确认（评审报告 blocker 0 / minor 3 + nit 1 已修，本件为其裁决不入批部分）。本批 P5 只给新增的 process_info（:49 一带）补了钉码，存量两处经裁决不入本批范围。

现象: scripts/port_kill.py 两处 subprocess.run(..., capture_output=True, text=True) 缺 encoding/errors——:29（listening_pids 的 Get-NetTCPConnection powershell）与 :142（taskkill 调用）。2026-11-06 CI 六连红事故口径（英文 runner cp1252 打死文本子进程读线程）只对 tests/** 有静态守卫（test_platform_tolerance_guards.py::test_repo_text_subprocess_calls_pin_utf8 只 rglob tests/），scripts/ 不在扫描范围，故 CI 不红但同病。

§03影响面

维度结论
触发条件非 UTF-8 活动码页（英文 Windows runner cp1252）上跑 dev.port-kill，且子进程输出含非 ASCII 字符（如中文进程名）时解码错乱或打死读线程
影响范围仅 scripts/port_kill.py 两处调用点（:29 监听者发现 / :142 击杀结果回读）；不影响 src/auto_qb 主程序，也不影响 tests/（有守卫）
严重度低——人工触发的一次性运维脚本且 CI 不挡；但与 2026-11-06 六连红同病（同类解码路径致死已实证过一次）
