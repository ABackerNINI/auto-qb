§05根因（可选）

静态排查一轮已闭合(2026-11-19, 证据 = tests-real/.work/s0boot/ 留存产物; 排除面全量以本节为准, 判别方案见复验计划 26-11-19-0054 §02/§04): 硬判定 = 「停止」的 LogRecord.created(asctime 取记录创建时刻非写盘时刻)= 50.995 ⇒ KI 实际浮出 50.995, 此前主线程零 eval-loop checkpoint ~38.4s; 信号触发 ~12.4-12.6(watcher 0.2s 轮询)。已排除: stdout/stderr 管道背压(驱动 Popen 直写文件句柄)、qB API 单调用挂死(有界 (3,10)s 且失败必落日志)、GTM 工具面(tool_client 全 urlopen(timeout) 有界, 订阅在 daemon 线程)、flush_truths/_publish 阻塞(空 pending 直 return / 无锁单引用)、管线 re 灾难回溯(210 种子管线含 re 段在 ~09.584 gen2 完成点收尾, 早于 touch ~12.4)、logging 锁阻塞(被 LogRecord.created 时间戳证伪)、KI 在 watcher 线程误投递(stderr 全空)。剩余假设: H1 整机/进程级冻结(磁盘停顿/AV/系统暂停 —— 进程内证据完全不可见, 奥卡姆, 1/6 形态吻合) > H2 主线程单个不可中断 C 调用(具体嫌疑 = qB 忙时涓流响应 defeating 字节间读超时, 见 §04 锚) > H3 其他线程持 GIL 的 C 调用(无持有者候选, 存疑)。判别与抓证方案见复验计划。
