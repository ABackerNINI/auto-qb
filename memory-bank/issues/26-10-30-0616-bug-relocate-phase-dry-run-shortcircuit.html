01现象与发现场景

来源: 第二次全项目 code review(26-10-30-0237)批A 条目 A-01; 复验留待认领时做。

relocate 执行相位机与撤销路径全程无 dry_run 闸门: relocate_execute 只在首步下发处(:826)判 _dry_run, 而 on_task_line 驱动的 _step_move(真实 setLocation)、_build_links(真实建删文件系统链接)、_arm(guardian 拉起 + resume)、relocate_cancel(删链接 + 搬回)一律照跑 —— --dry-run「只观察不落盘不建链」契约被相位机绕开。

场景: 现两个 job 创建入口各自在入口侧闸住 dry_run(rules move_to 与 WEB 命令), 故正常路径不可达; 但 start() 恢复账本不走这两道闸 —— 上一轮真实运行在 state.json relocate.jobs 留有非终态 job(崩溃/重启窗口即常态), 携它以 --dry-run 启动且 relocate.enabled 时, _load_jobs 恢复后下一任务线 tick 即真写下发 setLocation。
