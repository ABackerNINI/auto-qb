01现象与发现场景

RM04「辅种与分组」真机实测轮(2026-10-31): 带数据的假种子被产品打上 MISSING 标签后, tags 变成 MISSING, real-fake(qB 多标签以「, 」逗号+空格连接)。此后 tests-real 一侧所有「按 real-fake 标签认领自造种子」的代码都对它失明: real.seed.list 报「自造 0 个」、real.seed.rm --all 删不掉、用例收尾清场函数同样漏删。隐形残留被下一轮同 infohash 的用例收养(预打标/预暂停状态带入) → 触发源永不触发 → 假 FAIL 自续。RM04-03/04 在 2026-10-31 12:02 官方轮的 FAIL 均由此导致(用例侧已换 strip 版解析并重跑全绿, 见 memory-bank/testing/real-baselines/ 的 RM04 切片)。

03影响面

维度结论
触发条件任何自造种子携带第二个标签(实测: 产品的 MISSING 标签)即必现, 与数据量/配置无关
影响范围real.seed.list / real.seed.rm --all / guard.snapshot 的 skip_tags 判定 / 各片用例自写的清场逻辑
严重度中 —— 不影响产品代码, 但让真机轨的清理收尾与守卫归零对这类种子静默失效, 残留毒化后续轮次(实测连续毒化两轮官方跑)

  • tests-real/lib/guard.py:97（取证 2026-10-31 12:15）· 符号 snapshot · grep tags") or "").split
  • strip 版参考实现: tests-real/rm04_relocate/test_rm04_relocate.py 的 _tags_of()

05根因（可选）

qBittorrent 5.2 的 tags 字段以「, 」(逗号+空格)连接多标签; tests-real 一侧的成员判断统一 split(",") 且不 strip —— 单标签时无空白无感, 第二个标签进场即失明。根因明确, 非猜测。

06建议修法（可选）

把标签成员判断统一为 strip 版集合解析({x.strip() for x in tags.split(",")}), seed.py 与 guard.py 两处调用点同改; 改完用一枚手动打好双标签的种子验 real.seed.list / real.seed.rm --all 能看见并删净。
