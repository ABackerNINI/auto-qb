§01现象

§03建议（可选）

基座加惰性 desc(desc 支持 callable, 超时报错时才调用)。

修复后补充(2026-11-09)

实际修法(与建议同向): ① 9 份基座 desc: str → desc: str | Callable[[], str], 报错行改 {desc() if callable(desc) else desc} —— callable 只在超时构造报错时才求值, str 调用点零漂移; ② AST 全量扫 193 处调用点, 把 desc 内嵌活值(f-string 里含函数调用, 如 qb.torrent() / speed_limits_mode(qb) / rglob() / last_matched_set())的 19 处改传 lambda: (f"…"); 静态值 f-string(ih[:8] / path 等不可变量)保持 str 不动, sorted(want)(纯局部值)2 处同样不动(rm10:219 与 rm08_missing_groups:184)。首轮扫描按 f-string 插值顶层节点判活值, 评审抓出列表推导内嵌 qb.torrent(h) 的漏判 1 处(rm04_relocate:1736, 现树行号), 复查改用递归深扫(f-string 内任意深度出现调用即活值)后仅剩上述刻意豁免点。
