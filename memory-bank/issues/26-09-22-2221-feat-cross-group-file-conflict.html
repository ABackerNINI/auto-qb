01现象与发现场景

用户提出的风险场景（2026-09-22 会话）：不同组之间出现文件交叉时，目前没有任何检测与紧急处置 —— 典型后果是新种子开始下载后写盘，覆盖了另一组已下载部分/已完成的同名文件，数据损坏是静默且不可逆的。

本程序按「(规范化 save_path, 排序后的文件相对路径元组)」归组，组边界不等于文件不交叉。至少三类真实场景会让两个不同组的种子在磁盘上指向同一物理文件：

  • 同一 save_path 下文件列表部分重叠的两个种子（如 A=[ep01,ep02]、B=[ep02,ep03]）—— 列表不同即归入不同组，但 ep02 是同一物理文件；
  • 文件名仅大小写不同（Windows 不区分大小写）—— 文件列表文本上不同 → 不同组，磁盘上却是同一文件；
  • 不同 save_path 经 junction/symlink/盘符别名 指向同一物理目录 —— path_normalize 不解析这些别名。

期望行为：检测到跨组文件交叉时紧急处置（至少警告 + 暂停涉事下载方），与现有同组下载冲突检查（警告 + 整组暂停）同级。

03影响面

维度结论
触发条件分组 enabled 时；两个不同组的种子有文件映射到同一磁盘物理路径（部分重叠文件列表 / 大小写不同文件名 / junction·symlink 别名路径），且其中一方处于下载中
影响范围数据安全而非功能缺失：被覆盖组的已完成文件损坏 → 做种数据错误、后续校验失败、误触发缺文件（MISSING）处置；所有分组用户均暴露
严重度高 —— 静默发生、不可逆（已完成文件被覆盖，重新下载才能恢复）
