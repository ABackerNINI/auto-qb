§01现象与发现场景

发现于计划 26-11-12-1048 T8(根滚动器禁 CSS scroll anchoring, commit 5c04d0e7)的红验构造期。触发条件:zoom != 1 的分数布局(如 html{zoom:0.9} 或浏览器/DPR 缩放)下,滚动到文档底后,主表行窗口化的渲染窗整体错位——渲染行落在视口上方约 1900px,底部 pad 独占视口。flux 最严重(全部行不可见、无可点行);prism/atlas 存在两态平衡(禁锚前后方向翻转)。T8 取证前浏览器 scroll anchoring 以不同方向掩盖此缺陷,禁锚后暴露。

§03影响面

维度结论
触发条件zoom != 1(浏览器缩放/系统 DPR 缩放导致的分数布局)+ 滚动到文档底附近;用户真机 DPR 1.25 即在此面
影响范围主表行窗口化渲染(四皮肤);flux 最严重(全行不可见),prism/atlas 两态平衡;抽屉内表格(dt10/dt11, content-visibility)不受扰
严重度中——分数布局下列表可能整屏空白,但 scrollBy ±1 可临时恢复;用户若用 100% 整数缩放不触发
