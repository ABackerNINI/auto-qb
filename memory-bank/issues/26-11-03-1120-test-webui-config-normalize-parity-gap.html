01现象

前端 config_rules.js 用 cfgNormalizeRulesDraft / cfgNormalizeActionEntryDraft 手抄了后端 config/compat.py 的规则归一语义(扁平动作→规范形、缺省 on_error 注入、when 列表包 all、choose 保留)。当前两侧行为一致，但没有任何用例把**同一输入**同时喂给 JS 与 Python 并断言输出等价：Python 侧归一用 pytest 断言，JS 侧靠 tests/webui_dom_page_support.py 的 DOM 电池各自写期望。任一侧改语义(如新增缺省键、调整退役动作处理)都不会有守卫报警。

03建议（可选）

加一条跨语言对拍：一份共享 fixtures(旧扁平动作 / 规范形 / choose / 非法透传)分别走 JS 与 Python 归一，断言两侧 JSON 等价；fixtures 单点存放，避免两套期望各写一遍。若判定镜像可退役（后端已在载入时归一），也可改为删掉前端镜像，改由后端下发规范形，二者取一。
