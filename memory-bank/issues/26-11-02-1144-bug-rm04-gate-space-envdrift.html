01现象与发现场景

漂移复测轮 RM04（辅种与分组）2026-11-02 在环境2（C盘机）重跑时，用例 RM04-05「同卷跨盘移动主链」的负向对照红灯失守。

用例意图：dst 目录故意不预建，期望闸门 GATE_SPACE 以「剩余空间不可判定」拒绝（status=error + reasons.gate=space），实现零副作用负向验证。

实测：闸门直接放行，status=ok，与预期相反。

触发条件：目标叶子目录不存在但上溯一层即命中可读父目录（C: 盘充足、父目录存在）。不触发：上轮环境1（2026-11-01）R: 盘缺席时，上溯整链不可用 → 闸门命中。

03影响面

维度结论
触发条件目标叶子目录不存在 + 父目录可读 + 同卷（same_volume=True）+ 空间充足 → 闸门按设计放行；仅当「路径上溯整链不可判定 + 跨卷」才命中 GATE_SPACE 拒绝
影响范围仅 RM04-05 用例 L3 红验前提写窄；闸门逻辑本身在生产路径上行为正确（设计如此）
严重度低：代码零回归、闸门零失效；测试红验前提需按"上溯整链不可判定"条件收紧（或换另一条真正不可判定的路径）

05根因

定性：环境差量（用例红验前提写窄）。闸门逻辑按设计工作——GATE_SPACE 拒绝条件是 target_free is None AND same_volume is not True。环境2 C盘充足 + dst 叶子不存在但父目录可读 → 上溯一层即命中 target_free=73GB + same_volume=True，闸门放行合理。

上轮环境1（2026-11-01）R: 盘缺席 → 上溯整链到 R:/ 仍不可判定 → target_free=None + same_volume=None → GATE_SPACE 命中。

已排除：产品回归（闸门条件 relocate_units.py:488 自 2026-11-02-0134 方案A 起稳定，本轮探针与上轮探针对照完全吻合设计分支）。

06建议修法

不改代码，改测试红验前提。候选方案：

  • 方案 A（窄化）：把 dst 改成"上溯整链不可判定"的路径（如 UNC 缺席、容器映射 miss），而不是"叶子不存在但父目录可读"——这正是计划 R1 方案A 的适用条件
  • 方案 B（增补对照）：在现有"空间充足应放行"路径再加一条红验：当 target_free < needed 且 same_volume=False 时 GATE_SPACE 应拒绝（relocate_units.py:490 的 elif 分支），覆盖第二种闸门拒绝形态
  • 方案 C（改写）：把用例 docstring 里的"dst 缺席应被 GATE_SPACE 拒绝"改成"当 dst 上溯整链不可判定时应被 GATE_SPACE 拒绝"，明确前提

修复后补充

实际修法（方案 A）：RM04-05 负向对照 dst 从 case/"dst"（C: 现存父目录下）改成 Z:/rm04_05_neg_ctl/dst（不存在盘，上溯整链不可判定），主链 dst=case/"dst" 保持原路径不改。闸门 GATE_SPACE 条件（target_free is None AND same_volume is not True）在 Z:/ 路径下两边同时命中 → 真实拦截。不改产品代码，只改测试红验前提。
