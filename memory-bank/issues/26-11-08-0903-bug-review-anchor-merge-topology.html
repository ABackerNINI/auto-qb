§03影响面

维度结论
触发条件最近 trailer 在侧分支 tip 上 + 该分支基线旧于主线(跨 clone 分支流合流的常态)
影响范围所有 >50 行的提交被闸门以虚增行数拦下; 且死锁 —— 锚点前进需要一笔带 trailer 的提交落地, 而任何新提交的实算都恒被污染(此前三笔合并后提交能过纯属记账类文件实算 <50 行)
严重度高(阻塞提交流程; 但只假红不假绿 —— 不会放行漏评)

§04定位锚点

  • .commands/review/scripts/check_review_trace.py:237(取证 2026-11-08 09:03)· anchor_commit · grep "log", "--format" —— 平铺 log 无 --first-parent
  • .commands/review/scripts/check_review_trace.py:150· _numstat · grep "diff", "--numstat" —— 树差 base→工作树, 合并提交间语义失真

§05根因

锚点与计数两面都按「树差」思考, 合并拓扑下树差 ≠ 「新增了哪些提交」: ①锚点取平铺 log 最新 trailer, 侧分支 tip(基线旧)遮蔽主线锚点; ②批次行数 = git diff <锚点> 两棵树的差, 锚点即使换到主线, 间隔含合并提交时树差仍把被合并分支的已评内容整支算入。 已排除: 记账类排除面(与之无关, 污染源在 src/e2e 代码面)。

§06建议修法

两面一起改: ①锚点 walk 加 --first-parent(侧分支 trailer 不再遮蔽主线); ②计数改「主线逐笔累计」—— git rev-list --first-parent base..HEAD 每笔取 git diff <sha>^ <sha>(普通提交 = 自身改动, 合并提交 = 对第一父母的差 = 冲突解决面, 分支侧内容已随分支自己的 trailer 评过)+ 工作树 git diff HEAD。
