§01现象与发现场景

RM11 真机复验轮（2026-11-21，切片 26-11-21-0446-real-rm11-sliceA §07）收尾核净步骤，执行代理裸跑 real.seed.clean --yes 整扫：.work 顶层当时只剩 seeds/ 与 rm04/（均为「认得的落点」），证据保护闸放行；随后 _clean_root 对 rm04 整树递归全删，把本轮全部取证 rm04/async/（24 份 evidence json + 3 份产品日志副本）、9 份 slice tee 日志、2 份 prep 日志共 38 份文件连带清掉（gitignored 直删不进回收站，git 不可恢复，memory-bank 无副本）。这是坑档 pitfalls/ops/seed-clean-vs-evidence.md（2026-11-12 前科 + 2026-11-19 --dir 复发）的第三种触发形态：前科面是「误以为只清种子残留」与「--dir 定点误当只清本轮」，本轮暴露的是保护闸自身的粒度盲区——rmNN 内层证据完全不在闸的视野里。

触发条件：clean 整扫（不带 --dir）时 .work 顶层恰好只有 seeds/rmNN，而 rmNN 内层存在待留证据。与平台/配置无关（Windows/Linux 同路径）。

§02证据

seed.py 原文（取证 2026-11-21 06:38）——闸只看顶层：

CLEAN_KNOWN_WORK = re.compile(r"^(?:seeds|rm\d+)$")

def _work_strays(work: Path) -> list[Path]:
    """`.work` 顶层不属于「认得的落点」的子项 —— 那里可能躺着测量证据, clean 不许碰。"""
    if not work.exists():
        return []
    return sorted(p for p in work.iterdir() if not CLEAN_KNOWN_WORK.fullmatch(p.name))

放行后 _clean_root 对整树递归全删（不分层、无白名单）：

def _clean_root(root: Path, yes: bool) -> int:
    ...
    files = [p for p in root.rglob("*") if p.is_file()]
    ...
    for p in files:
        p.unlink()

实损清单（切片 26-11-21-0446 §07 誊录）：rm04/async/ 24 evidence + 3 产品日志副本；rm04/ 顶层 9 slice tee + 2 prep tee。RM04-35 attempt1 已实证同闸对 rmNN 内层无防护（前置残留断言先红，人工核对才免于误删）。

§03影响面

维度结论
触发条件real.seed.clean --yes 整扫且 .work 顶层仅 seeds/rmNN；或 --dir 指名 rmNN 子树——两形态都绕过现有闸（--dir 指向 .work 本体之外时闸根本不查顶层）
影响范围rmNN 内层的全部测量/真机取证（本轮新落点 rm04/async/ 即此形态）；gitignored 直删不可恢复，只能靠执行时誊录减损
严重度高

§05根因（可选）

闸的设计粒度停在 2026-11-13 落地时的证据形态（.work 顶层散件）——rmNN 内层当时是「逐案 evidence 落 case 根」的旧惯例，被认为可整清；本轮 rm04/async/ 是 RM11 轮新启用的专用证据落点（计划 26-11-21-0223 §3.2 钉死），闸面没有随落点演化升级，形成「白名单放行 rmNN → rglob 无差别全删」的盲区。

§06建议修法（可选）

  • 方案A（闸升级）：整扫时对 rmNN 内层做递归 strays 检查——按证据形态点名（如 evidence/、*slice*.log、rm11_prep_* 等白名单外内容即拒跑），代价 = 证据形态清单需随轮维护；
  • 方案B（默认收紧）：clean 整扫对 rmNN 只删「本轮 seed 工具自建形态」（种子 .torrent/.bin），其余内层内容一律拒跑要求 --dir 逐处指名，代价 = 收尾多几步显式动作；
  • 方向待裁决；无论取哪案，坑档 pitfalls/ops/seed-clean-vs-evidence.md 的「--dir 前先 ls 盘点」纪律应同步升级为「clean 前先 ls 盘点」。
