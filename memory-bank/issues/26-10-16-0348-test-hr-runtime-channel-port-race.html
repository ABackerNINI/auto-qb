01现象与发现场景

在做「qB 流量图统计栏对齐」的收尾提交时，commands run ship.commit 的内联闸门在合并远端后复跑 test.quick（xdist 并行）报红，两条用例失败：

  • tests/test_hr_runtime.py::test_start_stop_messages_are_info_not_warning
  • tests/test_hr_runtime.py::test_apply_remount_message_is_info

两条都断言「HR 生命周期消息不得打 WARNING」（本仓 WARNING 以上会被推成系统通知）。同一份内容单独跑（不加 -n）通过，随后原样重跑 test.quick 全绿 ⇒ 判为并行下的偶发不确定性失败。

两条用例都会真实启动本机回环 HR 端点，端口由 _free_port() 现取 —— 触发条件疑似与端口有关（见「定位锚点」「根因」）。

03影响面

维度结论
触发条件xdist 并行跑全量（test.quick / test.full）时偶发；非必现（同一内容连跑两次，一红一绿）。疑与并行 worker 争抢本机回环端口有关
影响范围test.quick 是提交闸门（ship.commit 内联）—— 红即 STOP，导致提交已入库但推送被挡，需人工复跑判定真伪后才补推
严重度低（非产品缺陷、非确定性；代价 = 误拦一次推送 + 一次人工复跑）
