§05根因（可选）

默认「待查」—— 不为填单做分析。有结论才写；不确定就写已排除的假设，不要把猜测写成结论。

已定位: _measureRowH 的量高循环对 querySelectorAll(sel) 命中的每一行无条件调 r.getBoundingClientRect(), 行高存值仅在 |差|>0.5 时覆盖 —— 即"签名未变的行也逐拍重探"。首访期间 updated() 收敛拍有 ~4 拍(页签切换渲染 + 窗口填充 + _rowHVer 收敛重算), 32 行 x ~4 拍 + reprobe + 非行级 ≈ 155。已排除: 背景轮询混入(隔离试验数字逐位不变)、种子档位放大(distinct rows 恒 32, 300/3000 档同量级)、rowWin 关窗路径(关窗 gBCR=1)。

§06建议修法（可选）

方向 + 候选方案 + 各自代价；没有想法就留「待定」，只写方案，不在本报告里实施。

签名未变行跳过: 量高循环前先按行签名(窗宽代 + 行键 + 已存值在案)过滤, 只对"无存值 / 签名作废 / 窗口新进"的行发 gBCR, 存值在案的未变行直接复用 _rowHs。注意与既有机制共存: 签名作废面(列集合/窗宽变化翻 _winMeasured)与 _reprobeRenderedRowH 的 render 拍真值修正语义不变 —— 跳过的是"未变行每拍重探", 不是"存值永不复核"; reprobe 拍的逐行修正保留(它是首访后唯一的真值收敛面)。代价: 判定逻辑加一拍哈希比对, 换掉的是物理 gBCR(强制同步布局)。修后量具面收益: 首访指纹从 ~155 回落到 ~"行数 x 实际变化拍 + reprobe", e2e/perf.spec.mjs 的 FIRST_VISIT_GBR_BUDGET 可回抬余量(该注已声明联动)。
