05根因（可选）

默认「待查」—— 不为填单做分析。有结论才写；不确定就写已排除的假设，不要把猜测写成结论。

已定位（有构造复现实测支撑；链首间隔那段属口径推断，未逐点打印验证 —— 入池不改码的边界内到此为止） —— 用例的时间轴起点取真实此刻（:589），base 由 now - 600 对齐而来（:590），于是：

  • 常态（本地 ≥ 00:10）：base 落在窗口最后一天，involved[0] 是前一日；造数把 base 块放进 base 天、其余各天只在天首 +30s 放一块。读侧算 24h 窗时，窗首那天的块早于窗首 → 链首 = 该块，与 base 块相隔 ≈ 24h+ → 超 v4_block_gap_continuous 阈值 → 断链 → base 桶判 null（这正是 §05.2 要守的跨日长洞）。
  • 00:00-00:10：base 落到前一日，与 involved[0]（窗首所在天）撞进同一天；那天里唯一的块就是 base+30（23:5x），它晚于窗首（00:0x）→ 链首 = 它自己，与 base 桶只隔 30s → 判连续 → 出 (0, 0) 而不是 null。

一句话：断言依赖「base 恒落在窗口最后一天」这个隐含前提；每天头 10 分钟 base 翻到前一日，前提破裂、长洞消失，null 语义随之落空。

已排除：与 2026-10-20 那轮前端改动相关（该轮只动 webui 静态 CSS 与 e2e，与本用例无交集）；服务端 24h 收边算错（同一端点在窗口外、即 00:10 之后与假钟 12:00 下断言全过）；造数分支写错文件（假钟 12:00 下 dat_opens 与 len(involved) 两条断言都过，只有 base 桶那条红）。

06建议修法（可选）

方向 + 候选方案 + 各自代价；没有想法就留「待定」，只写方案，不在本报告里实施。

方向：沿用 26-10-19-0013 的同族修法 —— 时间轴不取真钟。

  • 方案 A（窄改，推荐）：只挪 base 的构造。保留 now 在真钟（involved、dat_opens、服务端 24h 收边全都照旧），把 :590 的 base = ((now - 600) // 30) * 30 改成钉在 v4_epoch_date_str(now) 当天的对齐桶（如该日 00:00 + 30 的整数倍，取靠正午那档）。这样 base 恒在窗口最后一天，跨日长洞前提恒成立，:607 的 null 断言不再依赖跑测时刻；造数分支 :596 的 v4_epoch_date_str(base + 30) 语义不变。代价：改一处，且用例里「窗内 10 分钟前的对齐桶」这层现网形状（base 距 now 约 10 分钟）会变成固定的一天内位置 —— 该形状是否为被测口径，需认领时先确认。
  • 方案 B（照搬先例）：全套钉钟。照 tests/test_traffic_limits.py 的 _anchored_ts() 把 :589 的 now 也钉到当日正午。⚠️ 本用例与那条保留真钟的 test_api_payload_limits_shape_and_same_source 同款耦合：/api/traffic/qb/global 的 24h 窗由服务端按真实 now 收边，只挪用例侧的 now 会让「用例算的 involved」与「服务端算的窗」分家 —— 选 B 就必须同时把服务端取时符号也钉上（monkeypatch），或让端点接受显式 window 起止。代价明显大于 A。

无论走哪条，都请补一道守阵：把假钟 00:05 这档工况钉成常驻用例（沿用 26-10-19-0013 的假钟手法），否则下次还得靠"恰好在 00:0x 跑全量"才撞得见。红验方式同上：临时改回 now - 600 → 该守阵必红。

实际修法（2026-10-20 00:4x，用户指派「认领修复」）—— 按方案 A 走，且 A/B 的门槛差异比我入池时写的要小：

  • 只动 base 的构造：base = ((now - 600) // 30) * 30 → base = v4_day_epoch(now)（本地当日 00:00，30 对齐）。now 留在真钟，involved / dat_opens / 服务端 24h 收边全照旧 —— base 必在窗内（窗尾是 now，当日总在窗里）且恒落 involved 末日，跨日长洞前提恒成立。选 A 而非 B 的理由不是门槛，是改动面应该等于破面：破的只有 base 落在哪一天这一件事。
  • 订正 B 的门槛：服务端 _grid（traffic_qb.py:133）与用例同读 time.time()，钉一次双边生效，我在 §06 里担心的「两侧分家」不成立 —— 那条顾虑作废，但修法仍按 A 走。钉的时候要先取一次真值算当日 00:00，别在 lambda 里再取（否则自指）。
  • 守阵：@pytest.mark.parametrize("frozen_offset", [None, _FIRST_10MIN_OFFSET]) 两档 —— 真钟 + 假钟本地 00:05，把那 10 分钟永久钉在门禁上。红验形状是反向的：改回旧写法后假钟档红、真钟档（当时 00:3x 在窗口外）仍绿 —— 钉的是窗口本身，不是当时的钟点。
  • 邻域证伪：假钟 00:05 下 traffic 全家族 14 个文件 281 passed，本文件 19 passed，无第二条同病（:751 那条同款 ((now-600)//30)*30 不依赖跨日长洞前提，不在此列）。
