01现象

现象: 项目里有多个已经抽好的单点函数, 但调用侧仍内联重写了一遍。这类比"没有单点"更危险 —— 因为看代码的人会以为改单点就够了。

  • cfgBool: 单点存在, 另有 3 处内联真值判断。
  • hubKey(path→key): 单点存在, config_rules.js 2 处内联 .join(".")。
  • directionKey: 单点 cfgCurveDirectionKey 存在, cfgCurvePointAdd 内联三元。
  • Bearer 头: 注释声明的单点在 auth.js, 另有 3 处手拼。
  • KiB↔bytes: format.js 单点存在, fmtLimit 内联 kib * 1024。
  • 单位梯: config_editor.js 有一份 _fmtBytes/_fmtSpeed, 与 format.js 的 fmtSpeed/fmtSize 并行; 模板侧 hb-unit 又有 unitOptions 与 cfgUnitOptions(kind) 两套。
  • hrGroupTitle: HR 徽标 title 的单点存在, ep 行却在模板里内联手写四层三元。

02位置

  • grep 各单点名: cfgBool / hubKey / cfgCurveDirectionKey / Authorization / fmtLimit / unitOptions / hrGroupTitle(取证 2026-10-20 22:30)。
  • 明细台账: R20-C-06 / R20-C-10 / R20-C-18 / R20-F-04 / R20-F-05 / R23-B-04 / R23-B-12。

03建议（可选）

逐族改调单点(机械改动, 无结构风险), 并在单点处加一行"禁止内联重写"注释。单位梯两族要先确认阶梯值是否一致(KiB vs KB 的口径差会写坏配置)。
