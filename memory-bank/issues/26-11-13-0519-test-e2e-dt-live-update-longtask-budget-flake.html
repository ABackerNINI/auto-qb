修复后补充

实际修法(建议 B 量级口径, 建议 A 采样先行改道): e2e/dt-live-update.spec.mjs #10/#11 longtask 断言 lt.length === 0 → 量级口径 Math.max(0, ...lt) < LT_REGRESSION_MS(=100, 单点常量); 阈值锚三处: ①负载噪声实测上限 63ms; ②回归面下界 = W1 千行 keyed diff 残留(W1 长任务预算 <150ms, 同 longtask 口径; W6a 旧 全路径同面可见延迟 171-174ms 含 100ms 回执延迟, 非 longtask 口径, 仅旁证旧路径慢一个量级); ③长任务定义界(>50ms)的 2 倍。同形先例 perf.spec.mjs W5「灾难冻结帧 <500ms」; 计数不随时长线性, ③ 坑档的 elapsed 归一化不适用(timing-tolerance.md 复发④)。检测力不丢: 行侧零重建的主守阵是 mut 预算(≤8/≤16, DOM 记录数与 CPU 负载无关, 千行重写必爆), longtask 预算只作计时伴证。

改道说明(不采纳建议 A 的多轮负载采样): 机制类已定位(GC/调度毛刺 × 计数零容差, timing-tolerance ③ 同族), 采样只补偶红率数字、不改判据形态。改用注入复刻: ①红验注入 130ms 页面任务 → 双皮红(Expected: < 100 / Received: 130, 回归量级仍必红); ②注入 63ms(=假红实测值, 旧口径此形态必红) → 双皮绿(诊断行 longtask 63(合 63ms))—— 假红条件的确定性等价物, 证据硬于概率采样。附带实测: CDP page.evaluate 直跑忙等 不产生 longtask 条目(独立探针 [] vs 页面自调度 [130]), 红验注入必须走页面任务队列 —— 新坑档 pitfalls/testing/longtask-redverify-page-task.md。

验证方式与数字(2026-11-13, clone2 本机): ①红验 130ms 注入双皮红; ②噪声容忍 63ms 注入双皮绿; ③静机全 spec 14/14 全绿(1.9m), 双皮 longtask 无; ④全量 fast 门禁轮复跑(原假红场景) npm run test:e2e:fast 356P/0F/flaky 0/40.6m(上轮同场景 349P/1F/44.8m); ⑤test.full 数字见最新基线切片。 台账已登记(flaky-ledger.md 2026-11-13 行, time(边界/粒度)); #11 同窗在险面同批收口。
