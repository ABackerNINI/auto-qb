01现象与发现场景

怎么撞见的：用户第一张 1m 窗截图（真实时间 04:45:40）上，无采样区被一个孤立的点从中间切开 —— 用户原话「有异常点将无采样区分割」。

现象：04:45 重启的缝首桶取值 (0, 0) —— 不是 null，但速率字段在语义上是「未知」而非「零」。它的左右两侧都是 null 桶，于是三件事同时发生：①前端孤点判据命中，给它打上一个点标；②全窗唯一非 null 值就是 0，峰值 0 使 y 轴值域回落到 [0, 1]，该点被贴在图底；③两侧 null 被铺成 45° 斜纹。叠加的观感就是「一个异常点把无采样区切成两半」。

触发条件：停机洞（观测覆盖缝 > _V4_SEAM_NULL_S）之后的第一个桶 —— 也就是任何停机超过 1 分钟的重启。本例停机 26.5 分钟（04:18:30 旧进程被外部误杀 → 04:45:01 重启）。

function _qbIsolatedIdxs(u, sIdx) {
  const v = u.data[sIdx];
  const out = [];
  for (let i = 0; i < v.length; i++) {
    if (v[i] != null && (i === 0 || v[i - 1] == null) && (i === v.length - 1 || v[i + 1] == null)) out.push(i);

  return out;
}

03影响面

维度结论
触发条件停机洞（观测缝 > 60s）之后的第一个桶。停机越久越容易触发（越可能整窗只剩它一个非 null 值）。
影响范围raw 段窗全部，但只影响缝后首桶这一个点；agg 段窗（3d+）不受影响。表现强度取决于该窗内是否还有其它有效点：若全窗只有它一个非 null 值（窄窗 + 长停机），值域会塌成 [0,1]，点贴底、视觉上把斜纹区一分为二。
严重度低-中。不产生错误数据（0 速率对该桶确实是「未知」而非「零」），但读图体验上等价于「图中多了一个假数据点」，并打断了「斜纹 = 无采样」这条视觉语义 —— 用户会拿它当异常点去追问。

05根因（可选）

默认「待查」—— 不为填单做分析。有结论才写；不确定就写已排除的假设，不要把猜测写成结论。

机理已定（读码 + 真实数据复算，未跑用例）：(0,0) 这个取值由两个各自正确的决定叠出来 —— 读侧「停机洞后差分链断开 ⟹ delta=None」是诚实的（G2 口径）；v4_grid_obs 的 D4 豁免「有快照无速率 ⟹ 照常出桶、权重记 0」也是对的（为程序启动窗首桶设计）。但两者相交时产出一个「非 null 却无速率语义」的桶，而下游再也无法把它与「真实零速率」区分开：前端孤点判据只看 null 邻接，值域只看峰值。

已排除：不是写侧把停机期增长记成了 0 —— 该桶的 totals 是有效快照、delta 才是 None，两者语义不同；也不是渲染层涂错色 —— 后端接口对该桶确实返回 0/0。

06建议修法（可选）

方向 + 候选方案 + 各自代价；没有想法就留「待定」，只写方案，不在本报告里实施。

  1. 读侧（推荐）：让 D4 豁免区分「程序启动窗首桶」与「停机洞后首桶」—— 后者不应出 0 线，直接出 null，与两侧斜纹同语义。代价：需要把「洞后首桶」这一事实从 v4_totals_points 传到 v4_grid_obs（标记可能已在，属复用面）。
  2. 前端值域兜底：_qbYRange 在「峰值 == 0 且存在非 null 点」时不要回落到 [0,1]，按「无有效数据」处理或抬高下限。代价：只遮症状，孤点标记仍在。
  3. 前端孤点判据收紧：点标条件加上「该桶速率权重 > 0」，权重为 0 的桶不打点标。代价：需要后端把权重透出（当前前端只看得到聚合后的速率值）。

三条可叠加；最小闭环是 1 或 3。

修复后补充

实际修法（读侧，即建议修法 1 的最小闭环；未采用 2/3）：core/traffic_grid.py 的 v4_grid_obs 归桶时跟踪「本桶覆盖起点晚于上一观测点覆盖末端」（观测缝 / 停机洞 / 块界真空），该向无速率覆盖时出 None 而非 0（BucketObs.dl_rate/up_rate 放宽为 Optional）；快照照记（差分链基线不断 —— 次桶 delta 仍为真实值），rate_points 的逐向 None 落成 JSON null（前端与空桶同语义：缺口斜纹）。「程序启动窗首桶」的 0 线保留（无观测缝的链路首点，1/N 缺口视觉无感）—— 与建议修法 1 的「区分两者」一致，且判别信号不需要从 v4_totals_points 透传（覆盖缝几何在栅格层即可判，活尾路径无真空标记时同样成立）。前端孤点判据 / 值域口径零改动（null 天然被 _qbGapRuns / _qbIsolatedIdxs 当缺口）。组面同规则：成员速率未知按 0 计入和，但该桶有观测而全成员该向皆未知时出 null。

验证：新增守阵 tests/test_traffic_grid.py::test_v4_grid_obs_break_bucket_rate_null_snapshot_kept（断链桶 null + 快照链 + 无观测缝 0 线对照 + 组面）；既有 D4 豁免用例改钉「无观测缝 0 线」面；端点面 4 条期望同步（test_web_traffic_qb.py）。红绿双验：该向改回 0 → 新守阵判红，还原复绿。全量数字见基线切片 memory-bank/testing/baselines/26-10-16-1057-qb-traffic-seam-fixes.md。
