01现象与发现场景

GitHub Actions（github 镜像）的 Test Windows (Python 3.12) 与 Test Windows (Python 3.13) 两个 job 连续 failure，且起点远早于版本管理本轮全部涉码改动。发现场景：机械化发版管线 S6 落地后真机冒烟 commands run release.ci-gate（check-runs API 轮询），对发版提交 a3ccf82e 按设计停手报告 CI 红——顺藤查证后确认是存量红，非本轮引入。

本地（Windows 10 真机）test.quick / test.full 均全绿（5412 / 5392 passed），失败为 CI 环境特有。

03影响面

维度结论
触发条件CI 环境（windows-latest × py3.12/3.13）push 即现；本地 Windows 复测不复现
影响范围① 发版管线 CI 全绿门（release.ci-gate）被存量红拦死，S7 补发 v0.3.0 无法过门；② 对外 CI 信号失真（真回归会淹没在存量红里）；③ 交付判定不受影响（判定口径 = ls-remote + 本地闸门）
严重度中（不损数据、不拦日常交付，但拦发版且腐蚀 CI 信号价值）

05根因（可选）

待查（已排除：本地 Windows 可复现的一般性回归——本地全量两套均绿；已排除：版本管理本轮涉码引入——起点早于其 3 天）。候选方向（未验证）：覆盖率闸 Windows 99.0 边界在 CI 采集面的漂移 / TMPDIR 自举在 CI 环境的候选序差异（tests/_tmp_bootstrap.py R→H→%TEMP%）/ 平台差异用例（test.linux 口径外的路径行为）/ 依赖安装面差异。

06建议修法（可选）

① 配 gh token 后 gh run view <run> --log-failed 取失败行定位（第一步，无此不动手）；② 按失败行对症修复；③ 修复验证 = 修复提交 push 后 check-runs 全绿（Windows 两 job + ubuntu + smoke）且本地全量不回归。注意：发版管线（S7）依赖本件清偿——CI 全绿门在存量红下会停手，属预期行为不绕过。
