修复时定位到的两条假红源(2026-11-06 05:03)

① TOCTOU 窗口: _free_port() 取号(含回绑自验)后到服务真正 bind 之间, 端口可能被并行 worker 抢走 ⇒ 服务顺延 base+1。这是正确行为, 钉死 bound_port == base 才是假红源。
② 断言钉死具体端口号: 同族还有 == base + 1 的写法 —— base+1/base+2 可能落进 Windows 动态排除段(netsh … excludedportrange, 每次开机不同), 那时顺延到 base+2 同样正确。断言该落在「候选表语义」上, 不是某个具体号(同族实证见 26-11-06-0330-test-hr-discovery-busy-retry-flake)。
