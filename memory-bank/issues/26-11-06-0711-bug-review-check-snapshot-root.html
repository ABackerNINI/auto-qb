03影响面

维度结论
触发条件按命令 help 文档的存量用法传 --root <git archive 快照目录>（快照无 .git）必现
影响范围存量评审 R4 全部 5 条路线的引文校验环节；R2 全程走「快照-HEAD 零 diff → 对工作树根默认校验」等价通路绕过（等价性每批先 git diff --stat <freeze>..HEAD -- <批文件> 验证）
严重度中 —— 不阻塞（有等价通路），但违反 fail-fast 工具契约且迫使每批做额外 diff 核对

04定位锚点

写「符号名 + grep 关键词 + 当时的行号（标取证时间）」—— 代码会漂移，靠符号与 grep 重新定位，行号只是加速项。

  • .commands/review/scripts/review_pack.py:68-73（取证 2026-11-06 07:11）· _resolve_root · grep「不是 git 仓库」
  • .commands/review/scripts/review_pack.py:260-290（同上）· cmd_check/_verify —— 校验本体直接从 root 读文件逐字比对，无任何 git 依赖
  • .commands/review/config.toml · review.check 条目注意栏（commands show review.check 可见）

05根因（可选）

默认「待查」—— 不为填单做分析。有结论才写；不确定就写已排除的假设，不要把猜测写成结论。

已定位（非猜测，代码直读）：_resolve_root 对显式 --root 一律要求 root/.git 存在，该检查本意是「默认取 cwd 仓库根」路径的兜底防呆，被复制到显式路径分支后误伤快照目录。_verify 的引文比对只做「读文件 + 逐字匹配（±window 行）」，无任何 git 依赖，与 root 是否 git 仓库无关。

06建议修法（可选）

方向 + 候选方案 + 各自代价；没有想法就留「待定」，只写方案，不在本报告里实施。

两个候选方向（取一即可）：

  • 方案 A（小改）：_resolve_root 显式 --root 分支去掉 .git 强检查，改为「存在即用」（或仅 warning 不 die）——校验本体本就只读文件。
  • 方案 B（防呆更强）：保留检查但放宽为「.git 存在 或 目录内有 .snapshot-hash 标记文件」——把 review.lane 快照的标记文件作为合法 root 凭证，防呆语义不丢。

同时核对 pack 子命令是否共用 _resolve_root（pack 语义确实需要 git 仓库，改法需区分两命令）。
