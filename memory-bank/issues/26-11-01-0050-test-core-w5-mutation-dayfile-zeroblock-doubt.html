根因定案

  • _agg_credit_day_file__mutmut_9（if not slots: continue → break）：零槽块生产不可达。解析器 src/auto_qb/core/traffic_store.py 的 parse_v4_day_text._close() 仅在 cur_start is not None and cur_records 时 append V4Block（V4ParsedDay docstring 明写「空块不保留」）；v4_block_slots 亦从 block.records 展开。故「B 行后无任何记录」的零记录块永不进入 parsed_day.blocks —— 该空块支是防御死码，变异在真实解析产物上等价。
  • _agg_flush_series__mutmut_13（空桶 continue → break）：空桶生产点不存在。_agg_credit_hours 恒 pending.setdefault(h, []).append(...)，且 end <= start 直接 return 不建桶；恢复路径同样过滤空桶（if not samples: continue）。该空桶支同为防御死码，变异等价。

实际修法

生产代码不改（现码语义正确）；在 tests/test_traffic_sample.py 新增两条定向用例钉住不可达性，并同步该文件头部「测试计划」：

  • test_parser_never_emits_zero_slot_block：构造「零记录 B 块 + 有记录 B 块 + r 行」与「文件尾孤立 B 行」，断言 bad_lines == 0、blocks 仅剩有记录块、all(block.records)；证实解析器不产零槽块。
  • test_agg_credit_hours_never_creates_empty_bucket：退化区间（end <= start）不建桶、有效区间每桶至少一条样本；证实 pending 空桶生产点不存在。
