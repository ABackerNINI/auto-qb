01现象与发现场景

修复核报告 §11（/api/state、/api/groups 改为 JSONResponse 直返） 时，顺手把全部 GET 端点的体积与服务端耗时量了一遍，发现 /api/search 是第二大载荷 （1.46 MB / 服务端 82.6 ms），仍然 return 裸 dict ⇒ 仍在白跑 jsonable_encoder。详情族（/api/torrents/{hash} 及 /files、 /trackers、/peers）写法相同，只是桩服务的 FakeClient 返回空/小数据， 真实体积被严重低估。

触发条件：每次搜索（前端有防抖，但大库下每次仍要传 1.46 MB）、每次打开详情抽屉。与平台无关。

03影响面与严重度

维度结论
触发频率/api/search：每次搜索（有防抖）；详情族：每次打开详情抽屉（peers 还会 5s 轮询）
影响范围大库（/api/search 索引含全量文件列表）；文件数多的整包（/files）。桩服务下 files/peers/trackers 返回空，真实体积被低估，真机可能比 search 还大
数据风险无 —— 纯性能（但改造后若 payload 混入非 JSON 原生类型会 500，见「建议修法」的 fail-fast 提醒）
严重度低~中 —— /api/search 82.6 ms 服务端耗时且全程占 GIL，与主循环抢 CPU；大库搜索时是可感知的卡顿来源之一

04根因（初步）

结论（与 §11 同源，机制已实测确认）：FastAPI 对普通 dict 返回值会先跑 jsonable_encoder 递归遍历整个响应体（/api/state 3000×74 = 22 万个值实测 161 ms，占端点总耗时 189 ms 的 85%），而我们的数据本来就是 JSON 原生类型 （str/int/float/bool/None/dict/list），这趟遍历纯属白跑。返回 Response 实例 即被 fastapi/routing.py 短路跳过。

已排除：① 不是搜索索引本身慢 —— 索引由主循环预建，Web 线程只读 （api_search 的函数体只有两行）；② 不是网络/传输 —— 同尺寸 5.12 MiB JSON 走 uvicorn+StaticFiles 实测只要 1.6 ms，gzip 也无从可省；③ 不是客户端解析 —— 浏览器内 JSON.parse 只占 4.1 ms（4.76 MB 那次实测）。

05建议修法

与已修的 /api/state、/api/groups 完全同一套改法，推荐 A。

方案 A（推荐）：逐个改为 return JSONResponse(content=…)

零契约变更，改法与 web.py:263 逐字一致。预期 /api/search 服务端 82.6 ms → 十几毫秒（按 /api/state 的比例粗估，实际以量出来为准）。 建议范围：/api/search、/api/torrents/{hash}、 /api/torrents/{hash}/files、/trackers、/peers； /api/config/schema（45 KB / 8 ms）可顺手带上，其余 <10 KB 的端点不必改（省不到 1 ms， 反而多一处 fail-fast 面）。

fail-fast 提醒：改成 JSONResponse 后，若 payload 里出现非 JSON 原生类型 （datetime/set/Decimal）会直接抛 TypeError 变 500， 而不再被静默转成字符串 —— 所以改完必须逐个端点真请求一次（尤其 /files 与 /peers，它们是 qB 透传，字段类型不完全由我们控制）。

方案 B（更大，另开计划）：给 /api/search 做结果裁剪/分页

1.46 MB 的搜索结果本身就是设计问题（含全量文件列表）。但会动前端对搜索结果的使用方式， 成本显著高于 A。建议先做 A（1 行、零风险、立刻见效），把 B 作为独立计划评估。

实际改道（与建议不同，建议原文保留）：方案 A 里标注「可顺手带上」的 /api/config/schema 实测不能直返 —— schema_payload() 返回的是 dataclass 实例（Group / Field / Plugin）， 直返会在 json.dumps 处抛 TypeError: Object of type Group is not JSON serializable ⇒ 500。 判据：载荷里有没有非 JSON 原生类型 —— 有就必须保留编码器（或先显式转换成原生类型再直返）。 已把它回退为裸 dict，并在端点上留注释防后人再改。这也印证了本条「fail-fast 提醒」不是理论风险。
