05根因（可选）

已查清（2026-11-03 08:02）。已排除：端口改造、夹具、环境。
① dt-live #10/#12（4 条）= 产品缺陷，窗口引擎三处接线错（src/auto_qb/webui/static/shared/columns_grid.js）：
- 抽屉内容桥首渲时 .group-table 尚未落 DOM（同一次 patch 的 Teleport 子节点），_winGapFor 回退 0；不能借主表 rowGap —— 主表挂 .rl-scope，row_lang.css 把它的 rowGap 清零，抽屉不挂该类恒为皮肤基值 5/6px（实测借到 0）。首拍占位总高少 5~6px×1000 行（27309 vs 约 33150），滚到底被钳在被压短的总高上 → 间距随后收敛时末行已不在视窗。
- _rowWindow 的 end 用文档型 _winViewH 而非容器 vh，抽屉按主表/文档视口开窗（多渲染约一倍行数）。
- 行高首拍在抽屉入场期被 content-visibility:auto 报成 contain-intrinsic-size 内容盒 27+边框=28，落定后真渲染 27；首拍均值 28 使「下一次实测」（点勾选那拍）才发现差 1px → 再收一窗，正是 #10 变异数超预算的来源。
② dt11 树表批量（2 条）= 过时 spec：批量「最高」的产品行为已改为乐观写（drawer_files.js::setFilePriority 先写本地 priority 再 POST），批量后 E01 徽章当帧读 7，PRIO_CYCLE [0,1,6,7] 循环 7→0；原断言 6 基于「批量后 E01 仍为 1」的旧行为，已落后于产品（提交 2d5d7b8c「抽屉文件优先级乐观写落地」）。
