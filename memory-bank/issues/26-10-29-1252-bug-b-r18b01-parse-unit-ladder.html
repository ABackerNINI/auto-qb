01现象与发现场景

重复代码审查 B 类复核（2026-10-29, 原编号 R18-B01）读到 parse_time/parse_fsize/parse_speed 三份同构解析器时发现: 三份的单位表白名单宽度不一致 —— parse_fsize 在算乘数前多一道 unit not in units 的显式检查, parse_speed 没有, 而它的正则 [KMG]?i?B/S 允许「无前缀 iB/S」这种单位表里不存在的写法。于是 parse_speed("1iB/s") 抛 KeyError 而不是 ValueError, 校验层 _try 只接 ValueError → 原样逃出 load_config, 用户看到 traceback 而不是「配置校验失败(...) 共 N 处」的聚合报错。

触发条件: config.yml 任一速度键写成无前缀 iB 形式（如 1iB/s），键面为 trackers.*.upload_speed_limit / trackers.*.download_speed_limit / global_speed_limit_curve 的 upload_curve|download_curve 速度值。平台无关。

03影响面

维度结论
触发条件速度类配置键写成无前缀 iB/S（1iB/s 是当前唯一能命中该分支的写法：正则 [KMG]?iB/S 允许 i?B/S，单位表只有 B/S|KIB/S|MIB/S|GIB/S）。手写 config.yml 与 WebUI 提交树两条路径都会走到。
影响范围配置加载整体 fail-fast（这部分是既有设计，不新增停机面）；损失落在可诊断性上：本该是「配置校验失败, 共 N 处 / [i] config.trackers.HHan.upload_speed_limit: ...」的聚合报错，退化成裸 traceback，不知道是哪个键、也没跑完其余校验。同一路径上的曲线段（global_speed_limit_curve）同样。
严重度低（输入本身非法，必然失败；错在报错形态与「统一 ConfigError」契约）。归 bug 而非 refactor 的理由：用户可见的错误形态退化，不是纯风格。

05根因（可选）

三份解析器是「regex → 单位表 → 乘数」的同构副本（B 类分歧重复），单位白名单记在两处（正则字符类 + dict 键），只有 fsize 那份在两个白名单之间补了一道 unit not in units。speed 这份在演化中没跟上这一步，正则比 dict 宽一格，于是 units[unit] 直接下标抛 KeyError。换句话说：不是「speed 少写一行」的偶发疏漏，而是同构副本演化出的分歧——补哪个副本都只治一处。

已排除：① 非「校验层漏放行」——_try 捕获面窄是设计选择（ValueError = 用户输入错）；② 非 floats 解析差异——1.5.5 两侧都抛 ValueError，仅文案不同。

方案 A（最小修，只治缺陷）

parse_speed 补上与 parse_fsize 同形的兜底：if unit not in units: raise ValueError(f"无效速度格式(需使用iB单位, 如 10MiB/s): {speed_str}")。代价 +3 行；不治「下一个副本再漂一次」。

方案 B（收敛 + 缺陷一起治，推荐）

抽一个私有阶梯 _parse_quantity(raw, pattern, units, *, cast, empty_default, err)，三个公有函数各留 3–5 行包装，**各自保留**：单位表、正则、报错文案、返回类型（time→float、fsize/speed→int）、空串语义（time/speed 空串→0，fsize 空串→ValueError）。_parse_quantity 内统一做 if unit not in units: raise ValueError(err % raw) —— 于是「正则比单位表宽」这一类漂移**结构上不可能再发生**。

明确不做：把三个函数合成一个带 mode 参数的函数（返回类型与空串语义三份都不同，参数化后每个调用点都要记 mode 语义，可读性净损）。

验证手段

  • 等价性守阵: 现有 tests/test_utils.py:132-150（happy path）+ :434-475（空串/非法/非 iB 单位）已覆盖两侧行为，改造前先跑绿作为基线；改造后同一批断言必须仍绿（这是「行为可保持」的判据）。
  • 新增表驱动用例: 三函数 × {合法值, 空串, 纯非法串, 无前缀 iB（1iB/1iB/s）, 小数多段（1.5.5MiB）}，断言异常**类**（ValueError）而非仅断言「抛异常」——现有 3 处 except ValueError 写法已能接住，但表驱动才能固定 KeyError 不复现。
  • 配置层守阵: 一条 load_config 用例（temp config，trackers.X.upload_speed_limit: 1iB/s），断言抛 ConfigError 且消息含 upload_speed_limit —— 钉住「任何配置问题统一抛 ConfigError」的契约。

来源：重复代码审查报告 §21 R18-B01（B 类复核 2026-10-29）。原判定「抽通用解析器会损可读性，只登记」——复核后维持「不参数化 mode」的部分，但单位表宽度分歧已构成用户可见的错误形态退化，故升级为 bug 入池（方案 B 的可读性代价由「各函数保留自己的表与文案」吸收）。
