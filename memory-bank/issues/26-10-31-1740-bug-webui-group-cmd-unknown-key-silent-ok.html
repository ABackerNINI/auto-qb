01现象与发现场景

RM09 真机实测(plan plans/26-10-31-1710-plan-real-RM09.html 用例 RM09-06)发现。场景: 对 /api/groups/{key}/pause 传一个 base64url 形状合法但 store 里不存在的组 key(直调 API / 前端视图过期时的真实形态), 轮询回执。

计划口径(RM09-06 负向): 「不存在的 key → 端点行为按实况断(路由层拒收或错误回执), 只要不是「静默成功」」; 失败判据「未知 key 静默成功(无账)」。实测正是静默成功: 回执 ok、零效果、零日志。

对照: 畸形 key(非法 base64)走 common.group_key_param 400 拒收(分组标识无效), 同用例已验证为红验通过 —— 缺的只是「形状对但组不在」这一层。

03影响面

维度结论
触发条件组命令(pause/resume/reannounce/delete)的 key 解码成功但 store.groups 无该组 —— 组刚解散 / 视图过期 / 直调 API 传错 key
影响范围groups.py 全部四个组命令端点; 用户/调用方拿不到任何「目标不存在」信号(_group_hashes 空即静默返回, drain 照写 ok)
严重度中(无账操作, 排障时「点了没反应」无日志可查; 不损数据)

05根因（可选）

_cmd_reannounce_group 对「成员执行时刻已全部不在快照」有显式 error 回执口径(commands.py:559-563 注释引用 issue 26-10-06-0028 E-03「旧版静默无回执易被误读为已执行」), 但 pause/resume/delete 走的 _group_action/_cmd_delete_group 没有同款兜底 —— 空组不下发也不写账, drain 侧 RESYNC 通路又恒给 ok。已排除: 组 key 编解码问题(畸形 key 已 400); 命令未入队(回执有 wait_ms/exec_ms 埋点)。
