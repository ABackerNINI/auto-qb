01现象

infra/notify.py 与 tray/app.py 各自用逐字同的表达式推导 icon 路径：os.path.join(os.path.dirname(os.path.dirname(__file__)), "assets", "icon.ico")（tray 另有同式的 icon.png）。同一 assets 目录事实两份表示；包目录移动时需两处同改（notify 处注释已记「两级 dirname 与 tray/app.py 同口径」）。

文件 + grep 关键词（比行号稳）；行号要标取证时间。

03建议（可选）

路径单点（如 infra/assets_dir() 或 notify 导出 ICON_ICO、tray 引用）。收益低/风险低。

修复后补充

实际修法：取建议的第二支「notify 导出 ICON_ICO、tray 引用」—— src/auto_qb/infra/notify.py 的 ICON_ICO（表达式字节不动，注释升格为单点说明）成为包 assets 目录推导全仓唯一处；src/auto_qb/tray/app.py 删去两行逐字同表达式，改 from ..infra.notify import ICON_ICO, WINDOWS_TOAST_APPID + ICON_PNG = os.path.join(os.path.dirname(ICON_ICO), "icon.png")（与旧 ICON_PNG 字节同）。两级 dirname 表达式 3 处 → 1 处，包目录移动只需改 notify 一处。

与建议修法改道原因：未走第一支「infra/assets_dir() 新单点函数」—— 那要多改一个源文件（infra/utils.py），且当前无常驻配置入口需要参数化 assets 目录，提前抽函数属过度设计；notify 导出 + tray 引用依赖方向不变（tray 本就已从 notify import），净收敛相同。若将来 assets 目录需参数化，再升级为函数单点。

验证方式：① 运行期探针 —— tray.ICON_ICO == notify.ICON_ICO 且 os.path.isfile 为真，ICON_PNG 与改前字节同（零行为变化）；② 既有守阵 tests/test_notify.py::test_notify_icon_ico_points_to_real_file 及该文件全部用例先跑绿；③ 全量 test.full 全绿，数字见 commands run kb.baseline（基线切片 memory-bank/testing/baselines/26-10-15-0423-notify-tray-icon-path-dup.md）。首轮全量曾因认领链创建顺序误用红 1 条（先回填 doc-refs 后建认领方切片的悬空窗口），已在坑档 pitfalls/kb/refs-rename.md 记复发 6，非本修复缺陷。
