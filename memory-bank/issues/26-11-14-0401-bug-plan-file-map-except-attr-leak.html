§01现象与发现场景

2026-11-14 计划 26-11-13-0448 T3(R2 交集判据)实施期发现: PlanMixin._file_map 的取数异常兜底 except 支直接格式化 rec.log_repr —— 当 store 里的替身/异常形状记录缺该属性时, AttributeError 会从 except 分支内部漏出, 把「取数失败→保守计依赖」的兜底路径本身变成异常路径。生产形状(TorrentRecord)不受影响(T3 测试替身已补 log_repr 绕开); 用户拍板(2026-11-14)入池, 修复不紧急。

§02证据

贴原文（报错 / 日志 / 命令输出），不转述；附取证时间，让读者自己判断新鲜度。

# 形状(取证 2026-11-14, T3 批工作树):
def _file_map(...):
    try:
        ...
    except Exception:
        # 兜底分支内直接格式化:
        ... f"{rec.log_repr}" ...   # rec 非 TorrentRecord(缺属性)时此处 AttributeError 漏出
# 语义后果: 「取数失败 → 返回 {} → 谓词 None → 保守计依赖」的兜底链在异常形状下断裂。

§03影响面

维度结论
触发条件store 中出现缺 log_repr 属性的记录形状(测试替身/异常数据), 且 files 取数恰好抛错走 except 支
影响范围仅异常形状下的兜底路径断裂(AttributeError 代替保守返回); 生产 TorrentRecord 形状不受影响
严重度低(生产不可达; 测试基建健壮性问题)
