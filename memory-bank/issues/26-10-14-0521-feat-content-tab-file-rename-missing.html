01现象与发现场景

在「移除种子详情面板除流量页的 4 个经典 UI + 移除流量页/qB 流量页的非经典档」变更（档案 memory-bank/tasks/26-10-14-webui-detail-classic-removal.md）的收尾盘点中撞见： 内容页签的文件/目录重命名能力整体消失 —— 全 UI 已无任何入口。

该能力此前只有一条实现路径：经典渲染链的内容页工具栏「重命名…」按钮 → renameFileRow()（依赖行选中 fileRowSelect/drawerSelPath）。 经典链整体退役后按钮与方法一并删除，而内容页签现存的三个变体 10-content-tree-detail-tall / 11-content-treegrid-batch-low / 12-content-space-treemap-collapsed 都不含重命名入口（10 头注原话： 「重命名不在本变体设计内 → 回 classic 用」）—— 而 classic 档已不存在， 这条指示现在指向空。

触发条件：打开任意种子的详情面板切到内容页签（含单文件种子，旧逻辑对单文件免选中直接改名）。 与平台/配置无关，三皮肤同现。

05根因（可选）

默认「待查」—— 不为填单做分析。有结论才写；不确定就写已排除的假设，不要把猜测写成结论。

已知, 非待查 —— 经典渲染链是内容页签唯一的重命名实现载体, 它随用户批准的移除变更整体退役(删 drawer_tabs.js / drawer-tabs.html + renameFileRow / fileRowSelect / drawerSelPath / .f-row.sel 选中态 / .drawer-toolbar 及其死 CSS); 三个内容变体按试用期对照口径本就不含重命名(10 头注明示), 故移除后无入口。已排除: 后端命令缺失(④ 完好)、发令链不可达(_editPost 通用可用)、选择器机械故障。

06建议修法（可选）

方向 + 候选方案 + 各自代价；没有想法就留「待定」，只写方案，不在本报告里实施。

方向：把重命名作为变体自带动作回补(不复活经典档)，复用既有三段链 promptDialog → _editPost(hash, "rename-fs", …) → _fetchDrawerFiles(true)，零后端工作。

  • 方案 A(推荐): 在三个内容变体各加一个「重命名…」入口 —— 10 放右详情头部(作用于左树选中节点); 11 放工具条(作用于勾选行, 单勾选时可用); 12 放体积榜行选中后的详情区。均走 onSelect 自管选中态取 path, 单文件种子免选中。同步删 10 的孤儿文案。
  • 方案 B: 右键菜单(内容页签行右键)挂「重命名…」项, 一处覆盖三变体; 但变体自带右键语义(10/12 行内有点选), 需逐个协调, 协调成本高于 A。
  • 代价提示: 三个变体 = 三处 UI + 各自 e2e; 需补守阵断言「每变体重命名入口 ≥1」「rename-fs 回执后 files 重拉」。入池修时先确认在产品口径上是否接受变体自带 toolbar(当初移除就是把重量收回变体, 与该口径一致)。
