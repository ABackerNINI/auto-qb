01现象

models.py 的 hr_check 字段注释仍称旧 YAML 键「兼容接受并等价迁移」，但现行校验层对 trackers.<站点>.hr_check 直接报错。读注释会误判兼容入口仍在。

发现来源：本轮文档压缩的 code review（B2 收尾，2026-11-06 核对注释与校验行为）。

02位置与证据

  • src/auto_qb/config/models.py:203-205（取证 2026-11-06 03:06）· grep 旧 YAML 键 trackers。原文：旧 YAML 键 trackers.<站点>.hr_check 兼容接受并等价迁移(计划 26-09-27-1318 §3.4), 不再是配置入口
  • src/auto_qb/config/validation/sections.py:802-811 · grep 该键已于 schema v2 废除。现行行为：命中 hr_check 键即 errors.append(...)，报「该键已于 schema v2 废除 —— 存量配置应由迁移链自动改写」。
  • 复现：grep -n "旧 YAML 键 trackers" src/auto_qb/config/models.py · grep -n "schema v2 废除" src/auto_qb/config/validation/sections.py

影响：注释描述的「兼容接受」在配置校验阶段不存在，只有迁移链会改写存量文件；按注释判断兼容行为会误判。

03建议（可选）

只改注释，不改行为与校验：把「兼容接受并等价迁移」改为「历史键已废除，仅迁移链改写；校验层出现即报错」。验收：注释表述与 sections.py 报错口径一致，现行迁移/校验测试不变。
