§01现象

滚动长列表时窗口滑动瞬间内容整体跳数px: 行高逐行实测表 _rowHs 只在行渲染在场时更新(_measureRowH 每拍只量 querySelectorAll 到的在场行) —— 首渲量过的行若之后变矮/变高(字体交换/内容重排, 机器环境相关)且已滚出窗口, 存值永不修正; 窗口滑动越过它时 padTop 按陈旧存值超量替换, 下方渲染行整体跳 ±数px。取证(issue 26-11-14-1323 修复批, 2026-11-15): 单行存值 69.609 vs 实际 65.781, padTop +69.609 超量替换 → 内容 +3.828px 跳变; S-A 让位滚动同机制偏差 +5px。发源于 issue 26-11-14-1323 的 e2e 像素判据取证(测试侧已用预热滚动消化, 产品面未动)。

§03处置（2026-11-16 已修）

取证把「同症」拆成两根因, 同批处置(取证细节与守阵清单见 pitfalls/web-ui/rowwin-stale-rowh-pad-jump.md):

  • 根因一 · 陈旧存值: 新增 _reprobeRenderedRowH(kind, sig), 在 _rowWindow 重建 pre[] 之前、所有早退之后调用 —— 此刻 render 尚未 patch, 旧窗口的行仍在 DOM, 量最后一发真值顶掉 _rowHs 陈旧存值, 同一拍前缀和即按真值累加。只刷已有键, 不动 _rowH / _winMeasured / _rowHVer / _rowHSig / 签名(不踩全表作废坑), 同拍 sig 去重, 抽屉行过 checkVisibility({contentVisibilityAuto:true}) 守卫。
  • 根因二 · 占位基准漂移(只修根因一时 flux T7/S-A 仍红 5px 的那一根): 全局均值从前每量到一行就微动 δ, 而 pad 区上百行未渲染行全按它估高 → 被连坐搬 δ×N(取证 106×0.036 = +3.8px)。改为只在「首访量齐那一拍」校准后冻结, 门恰两支: !_winMeasured[kind](首校)与 !(this._rowH[kind] > 0)(存值非正 = 还没校准, 兜住 v-show 收走时 gBR 全报 0 把均值校成 0 的情形), 新量行只把自己那一项换成真值。抽屉内容桥显式不冻结(content-visibility:auto 首拍是 intrinsic 28, 需逐拍收敛到 27)。已知边界(刻意不做): 冻结后基准不随「行集变了 / 数据刷新了」重算 —— 曾试过按行集身份签名重校, 但 _rowHAvgOf 汇总 _rowHs 全部键(只在列/宽签名变时剪枝), 重算出的仍是被上一批 population 稀释的混合值 = 假重校; 真重校得按 kind 剔旧批键, 而这对 member 是灾难(成员列表逐组子集, 换组剔一次 = 每次展开都重新实测)。权衡取稳定: 估偏只影响「从未渲染过的行」的占位与滚动条长度, 而基准一动滚动中的内容就整段跳(本 issue 要修的正病)。
  • 测试侧绕过退役: e2e/drawer-dock-stability.spec.mjs 的 preheatRowWindow() 删除 —— T7/S-A/S-C 改为不预热直接判, 任一根因回潮即撞红。同时把位移判据两侧换成分数精度(采样器新增 rowBf/rowTf, 直接拿 gBR 原值比分数基线), 消掉「基线分数 vs 采样取整」最多 0.5px 的量化偏置(实测同一份代码基线 482.0625 → 落定 481.0625, 真实位移恰 1.0px, 原先的 1.0625 是取整造出来的假红; 该 1px 是选中行开抽屉自身箱变, HEAD 上同样存在, 与本次修复无关)。

守阵: 静态 test_frontend_outgoing_rowh_reprobe_guard + node 电池 test_r4_outgoing_rowh_reprobe_kills_pad_jump(22 检查; 红验复现 69.609 超量替换 / 绿验 65.781 落地且前后差恰 +3.828px) + e2e 像素面 T7/S-A/S-C 去预热后仍绿。
