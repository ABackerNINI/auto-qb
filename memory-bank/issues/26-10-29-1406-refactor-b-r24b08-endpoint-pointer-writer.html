01现象

endpoint.json（工具侧写、auto-qb 侧读的唯一端点事实源）在 tests 里由三份各自手写的载荷字面量模拟写出：其中两份是 15 行逐字拷贝（只差 host/port/autostart_error 三参），第三份是"任意载荷直注"；三份的字段集与工具侧真实写手已经不一致（client 版少一个 autostart_error），而现有守阵只镜像常量（文件名 / schema 版本），不镜像载荷字段集。

02现状取证

取证 2026-10-29 14:06，基线 1b7dd104。grep -rn "def _write_pointer" tests/*.py

  • tests/test_traffic_monitor_client.py:90 _write_pointer(tmp_path, monkeypatch, *, token_path, schema=agent.ENDPOINT_SCHEMA) -> str：写 tmp/pointer/endpoint.json，载荷 10 键（host/port 取文件内常量 POINTER_HOST="127.0.0.1" / POINTER_PORT=8099，见 :67-68），无 autostart_error。注释自述「载荷字段名与工具侧 gtm 的写出契约一致」。
  • tests/test_traffic_source_agent.py:83 _write_pointer(..., *, token_path, host="127.0.0.1", port=8099, schema=..., autostart_error=None) -> str：同路径，载荷 11 键（多 autostart_error）。
  • tests/test_traffic_source_paths.py:33 _write_pointer(tmp_path, monkeypatch, payload: dict) -> None：写到 tmp/endpoint.json（无 pointer 子目录），载荷整字典直注，用途是喂"最小合法指针 / schema 不匹配"等任意形态。
  • 生产侧真实写手：tools/global-traffic-monitor/src/gtm/server.py:216 _write_endpoint，11 键含 autostart_error；读侧 src/auto_qb/core/traffic_source/agent.py:144-168 parse_pointer 用 payload.get("autostart_error")（缺键安全）。
  • 现有守阵：tests/test_traffic_source_agent.py:531 test_pointer_constants_mirror_tool_side 只 AST 比对 POINTER_DIR_NAME / ENDPOINT_FILE_NAME / ENDPOINT_SCHEMA —— 字段集无守阵。

03分歧点与判定

  • client 版缺 autostart_error —— (b) 无判据漂移。工具侧每次都会写这个键（可为 null），client 版的用例因此从未在"带该键的真实指针"上跑过；读侧 .get() 容错使后果仅为镜像不完整，不构成假绿（autostart_error 的解析有专门用例 :189 覆盖）。
  • paths 版"payload 直注" —— (a) 不同意图（喂任意形态测读者容错），不该被抹平；但可以用 payload=None 参数挂在同一个写手上，不必保留第二份实现。
  • 落盘路径 tmp/pointer/ vs tmp/ —— (b) 无判据。三处都 monkeypatch 了 agent.endpoint_path，路径本身不进断言，统一取 pointer/ 子目录（更贴真实目录形态）即可。

判定：值得做。①两份 15 行逐字拷贝 + 一份 3 行同族，符合 test-shared-micro-helper-dup 已收口的规模门槛（该次含大量 ×2 族）；②合并后载荷只有一处镜像，工具侧新增字段时只需改一处；③验证只需跑三个模块，风险近零。收益不算大，但代价同样小，属"顺手做掉比留着划算"。

04收敛建议与验证手段

  • tests/helpers.py 收 write_endpoint_pointer(tmp_path, monkeypatch, *, token_path="", host="127.0.0.1", port=8099, schema=agent.ENDPOINT_SCHEMA, autostart_error=None, payload=None) -> str：payload 非空则原样写（覆盖 paths 版意图），否则按 11 键默认载荷写；统一 tmp/pointer/endpoint.json，统一 monkeypatch + 返回路径。
  • 三处删本地定义改 import；POINTER_HOST/POINTER_PORT 常量保留在 client 测试里作调用参数（它们被断言引用，不是写手内部细节）。
  • 可选（不强制）：把 test_pointer_constants_mirror_tool_side 的镜像扩到"字段集"——AST 读 gtm/server.py 里 payload = {...} 的键集合，与测试写手的默认载荷键集合比对。价值是让"工具加字段、测试没跟上"从静默变成红；代价是绑到工具侧实现细节（_write_endpoint 改名/改结构就红）。认领人判断值不值得，本单只要求"写手合一"。
  • 验证：改前后各跑 commands run test.quick -- tests/test_traffic_monitor_client.py tests/test_traffic_source_agent.py tests/test_traffic_source_paths.py，断言零改动、全绿；grep -rn "def _write_pointer" tests/*.py 应归零。
