01现象与发现场景

来源: full-code-review 全项目评审(计划 26-10-05-0951) · 发现 B2-01(批 B2) · 审计报告 26-10-05-1036-report-full-code-review §2 批 B2 发现表 / §3.1 分级终表 · 批实测 HEAD a4d14a8d, S5/S6 复核 HEAD 145eedea

站点文件含非法 UTF-8 字节时 UnicodeDecodeError(ValueError 子类, 非 OSError)从 read_text 逃出 —— 专为坏文件设计的整条自愈链(quarantine → .bak 兜底 → read_error 如实带回)对该类坏文件全程不可达; 且 build_views 单站点抛异常会中止整个视图集构建, 一个坏文件拖垮全部站点的视图发布。

02证据

可达性证据(调用链论证 / 复现路径), 摘自评审报告发现表原文; 取证时间见各锚点标注。

①坏文件来源可达 — 站点 JSON 含中文种子名, Windows 记事本/编辑器按 ANSI(GBK)重存即产出; ②取数线程: run_once → refresh_site → hold() → HrLockSession.__init__ 首行 store._read_full() 上抛 ⇒ quarantine 未及执行, 异常被 refresh_site 宽捕记 ACTION_ERROR — 坏文件永不被隔离、.bak 永不被消费, 每波 ERROR 刷屏; ③视图面: 轮末 _build_views → build_views 逐站 read_unlocked ⇒ 上抛被 _loop 单轮兜住但发布中止 — 全部站点 judge() 回落行 4 本地兜底(HR 管束/终态证据全失, 且每轮复现直到人工介入); ④CLI: --hr-status(report.py:158 无 try)直接 traceback 崩溃; ⑤status.py:623 docstring「站点文件读坏时不抛」契约对 encoding 类读坏不成立(WebUI /hr 路由面 500)。
