01现象与发现场景

怎么撞见的：2026-10-18 收尾「WEBUI 选中摘要」计划(26-10-18-2013)时，按 memory-bank/testing/smoke.md 的矩阵轮纪律补跑全量 e2e 的 error 模式轮(E2E_CMD_RESULT=error commands run dev.e2e)，本轮 266 passed / 26 skipped / 4 failed，失败全部集中在 e2e/delta-sync.spec.mjs 的两条真值对齐用例(双皮肤 ×2)。

触发条件：模式矩阵的 E2E_CMD_RESULT=error(命令回执为失败)或 hang(命令永不回执)下必现；默认 ok 模式全绿(2026-10-18 默认轮 286 passed / 10 skipped / 0 failed 含这两条)。

与本次选中摘要改动无关的实证：git stash 暂存该计划全部改动(11 个跟踪文件)后，在 HEAD 同参数下隔离复跑这 4 条(E2E_CMD_RESULT=error npx playwright test delta-sync --grep "增量轮")，同样 4 failed 且失败断言逐字同签名(取证 2026-10-18 21:1x，本机 Windows / chromium headless，桩 300 种子)。

平台与配置：Windows 本机，桩服务 scripts/ui_harness.py(端口 8137，300 种子 / 150 组)。error 与 hang 两个模式均已实证(取证 2026-10-18 21:07–21:30)：error 轮 266 passed / 26 skipped / 4 failed；hang 轮 252 passed / 40 skipped / 同样 4 failed、逐字同签名(hang 下命令无回执 ⇒ 桩不改真值 ⇒ 同一 8s 轮询超时)。

03影响面

维度结论
触发条件模式矩阵 E2E_CMD_RESULT=error 或 hang 下必现(error 已实证; hang 按机理推断, 待实证)。ok 模式不触发。
影响范围仅测试面：生产代码零牵连(HEAD 同参复现同红已证)。受影响的是矩阵轮 ②/③ 的回归信号 —— 4 条存量恒红会把新增红色淹没(与 issue 26-10-08-0818 记载的「恒红使 dev.e2e 失去回归信号价值」同型)。
严重度中 —— 不阻塞生产与默认轮; 但使 error/hang 两个矩阵轮永远无法全绿, 收尾 DoD 的「六轮」实质打折。

写「符号名 + grep 关键词 + 当时的行号（标取证时间）」—— 代码会漂移，靠符号与 grep 重新定位，行号只是加速项。
