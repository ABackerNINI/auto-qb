# 分批评审 (Code Review)

设计主轴是**判断与机械分离**: 批次判定、相关性裁决、severity 定级是 agent 的判断; 引文校验、规模分档、锚点推进是脚本的机械。机械面命令: `commands run review.pack`(评审包生成)与 `commands run review.check`(引文校验)。

## 铁律

> **一批一评, blocker 清零再进下一批; 收口只补接缝终审。**

评审单元是**批**, 不是任务。任务可以有很多批; 批次边界由"上一次评审过的提交"机械决定, 不由 agent 感觉决定。

**残余窗口(诚实声明)**: 齐平协议只闭合**评审时点** —— 批次齐平评完到提交之间远端再推进的组合树, 仍只有测试闸门兜底; 该窗口由提交时点的「评审边界」提示行点亮(`commit.py` 步骤 6c), **不新增提交后补评时点**(计划 `26-11-07-0201`)。评审后到提交之间的**本地**再改动已由 `· 基 <hash>` 机检闭合(⑦): 评审快照后可评内容再有新 diff, 闸门重算哈希不一致判红 —— 残余窗口 = 远端推进一侧 + **0 行无 trailer 窗口**(numstat 对二进制计 0 行, 0 行批无 `Review:` trailer 仍静默放行 —— issue `26-11-08-1701` 方案 A 有意保留的通路; 带 trailer 的 0 行批不走短路, 基比对可达且对 tracked/untracked 二进制都有效: tracked 替换必改 blob, diff 文本的 `index` 旧/新行随之变, untracked 按原文字节入哈希)。**本地分支态下**(③ 探针判定)「远端推进一侧」窗口扩至任务全程 —— 由合流时点的 test.full + 接缝终审挂「远端交叉面」收口(计划 `26-11-10-0342` D4), 不新增中途远端核对。

## ① 触发与豁免

| 触发 (必须评审) | 不触发 (跳过) |
|---|---|
| 可评内容(代码 + 事实性文档)**>0 行** —— 每笔可评提交必评, 不论行数 | 仅**生成物**(`gen_all.py --list` 清单)与**记账类**文件(任务档案/会话切片/基线切片)改动, 机械排除不计行 |
| 触碰**安全敏感面/红线**(不论行数; 有效 trailer 即放行 —— 敏感面强制的是「必须评」) | |
| 任务**收口**: 另加一次接缝终审 | |

- **取消按任务类型/立档阈值的豁免**: 有没有档案、是不是"小修", 都不再决定要不要评。判据只看**改动面与可评行数**。
- **Review-Skip 已退役**(计划 `26-11-08-1240` D8): 新提交写 `Review-Skip:` 闸门判红, 理由长短不再看; 历史 trailer 不追溯 —— 锚点 walk 照旧识别、不重判。
- **取消"中途提交不触发"**: 中途提交正是批次边界 —— 每批收尾都要评, 不是留到收口一次评。
- **纯文档任务也要评**(文档错误会直接误导后续会话), 但只评**事实性文档**(计划/报告/约定/坑档/README/AGENTS.md); 档案与切片是记账, 已有 `check_doc_templates` / `check_status_drift` / `gen_active_recent` 三道守卫。
- **收口判定**仍由 agent 判("本次收尾是否该任务最后一次"), 拿不准就问用户一句。收口那次**不重评代码**, 只做 ②的接缝终审。
- 评审固定发生在该批**提交之前**; 已推送的提交不回头重评。

## ② 批次与容量

- **批次范围** = 上一条带 `Review:`(或 `Review-Skip:`)的提交 → 当前工作树(含未提交改动)。锚点由脚本从 git 历史现算, agent 不用填 hash; 冷启动(历史里一条都没有)时起点退化为 HEAD, 只算工作树 —— 落地后第一笔带 trailer 的提交即建立锚点, 此后漏评的提交一律滚进下一批。
- **齐平时点**: 评审批次的上下文必须含**远端全部最新代码**; 批次锚点在 sync 后现算会自动跳到远端最新一条 trailer, 评审包 diff 仍只含本批改动 —— 锚点法天然兼容(计划 `26-11-07-0201` 验证过的关键事实)。
- **建议上限 400 行/批**。依据不是"agent 读不动"——实测 1313 行单块照读、零幻觉——而是**产出密度**: 发现数 ≈ 派发次数 × 5.6, 与批次大小无关(见 `reports/26-11-06-0723-report-review-capacity-experiment.html`)。切得细发现得多, 但每次派发有成本, 且切到低于"一个自包含变更"会切断跨块问题。
- **超 400 行 → 拆批**(按可独立编译/测试的文件组; 拆完仍按两档走), 不是分面; 确实不可拆的残余批 → 派发 ≥2 并在 trailer 记 `· 派发 <K>`(拍板 D1: `· 分面` 降级为信息字段, 不再是超限通路 —— 计划 `26-11-07-0441`)。
- **收口接缝终审 ≤200 行**: 只看跨批接缝 —— 接口/数据结构在批与批之间漂移、同一机制被两批各造一套、测试面遗漏、偏离计划; **不重评已评过的代码**。子代理无记忆, 没有任何一批的评审者能看见全局, 这是终审唯一不可替代的职责。**发现处置与批次轮拉齐**(计划 `26-11-08-1240` D10): 相关的 blocker/major/minor 修完才可收尾, 计划外的入池; 接缝修复引出的新改动照 ⑤ 的扳机走复评循环。

## ③ 评审包

`commands run review.pack --base <上一条 Review: 提交>` 生成机械五件: 基线 hash / **评审规模与分档提示**(行数 = 闸门实算口径 —— 锚点核对/排除面/逐笔实算与提交闸门共用 `review_content` 单点, trailer 的 `<N> 行` 与 `· 基` 都以它为准; 记账类/生成物/二进制不计行; `--base` ≠ 闸门锚点时打可见警告, 改用锚点重跑)/ 改动文件清单(可评面; 记账/生成物列进排除面行, 不入清单)/ 红线命中预警 / **基哈希** —— 整批(锚点→当前树)过滤 diff 的 12 位哈希(生成物/记账类不计入, 所以末轮 pack 后补写记账/生成物不动哈希, 不误红); trailer 的 `· 基` 引**末轮 pack** 输出的值(⑦)。

- **pack 前置(齐平)**: 生成评审包前主会话跑 `commands run my-commit-flow.sync`, 结果行贴进评审记录; sync 失败按失败行自带出路解决, 确实解决不了(离线)才允许声明**未齐平态派遣**(reviewer 侧由 ④ 三钉的「无法核实」分支兜住)。
- **pack 前置(闸门预跑, 计划 `26-11-11-0408`)**: 齐平之后、pack 之前主会话跑 `commands run ship.gate`, 结果行贴进评审记录 —— 让 review 评到的树已经是闸门绿的, 小失误(格式化/测试红/措辞/坏链)不再等到提交一刻才暴露; 红 → 修 → 重跑绿才 pack(`dev.fmt` 是真动作, 必须先跑再 pack, 否则基哈希失真)。**凡 pack 必前置**: 复评轮与接缝终审不豁免; 非评审提交(纯生成物/记账)可选不预跑, commit 闸门兜底。
- **本地分支态(探针判定, 计划 `26-11-10-0342` D1/D2)**: pack 前主会话先跑探针 `git ls-remote origin <当前分支>` —— 命令成功且输出有该分支 ref = **远端分支态**, 照上行走 sync 齐平; 命令成功且输出无该分支 ref = **本地分支态**(分支无远端对应): 跳过前置 sync, 评审记录记「本地分支态」行(替代齐平行); **探针命令本身失败(网络错误/超时) = 离线**, 不判分支态, 照走 sync(失败按上一行既有未齐平逃生口申报)。判定自证式, 不依赖 agent 声明, 三态口径与 ④ 钉3 探针一致。本地态评审对象 = 分支自身 diff 锚点链, 远端推进不进评审上下文(组合树窗口由合流终审收口, 见铁律段); trailer `· 齐平` 字段缺省, `· 基`/`检 P/T`/锚点 walk 照旧。
- **指路四件**(主 agent 随评审包给出): 档案/计划路径(验收标准 = 档案「原始请求」)、涉及模块清单、安全敏感面(凭据/网络/state 写入/红线文件)、批次 base hash。
- **禁整库扫描**; reviewer 可读周边代码判调用面, 但发现只收评审包范围内的改动。

## ④ 派遣协议

| 档 | 条件 | 拓扑 |
|---|---|---|
| 全能 | 批 ≤400 行且未触安全敏感面 | 1 个子代理全量评审 |
| 分面 | 批 ≤400 行但触安全敏感面 | 2–3 个子代理按面拆(正确性 / 安全 / 测试缺口), 主 agent 合并去重 |
| 拆批 | 批 >400 行 | 先拆批, 拆完按上面两档走 |

> 分面代理**逐个串行派遣**: 宿主并发上限会拒收并发派遣(失败串 `user concurrency limit exceeded`), 逐个重派即恢复 —— 见 `pitfalls/kb/kb-subagent-concurrency.md`。

**reviewer 只读** —— 修复一律主 agent 执行。派遣提示**照抄三件套**, 不临场发挥:

> 1. **只读契约**: 禁止**一切写操作** —— git 状态变更(sync/rebase/merge/stash/checkout/commit/push)、写任何文件、跑 kb 等写类 task id 一律禁止, 只允许读命令(`git ls-remote` / `git rev-list` 属读命令); AGENTS.md 的开工同步对本任务豁免, 主会话已完成 pack 前置同步(③; 离线未齐平态/本地分支态派遣除外)。
> 2. **三钉钉死**: diff 范围 = 批次 base `<base>`(评审包的基线); 自检锚 = 派遣时 HEAD `<head>`(`git rev-parse HEAD` 现取); **远端 tip** = `<tip>`(reviewer 跑 `git ls-remote` 现查, 属读命令)。本地分支态派遣时第三钉填 **`本地分支态(探针 ref 不存在)`**。
> 3. **开工自检**: `git rev-parse HEAD` ≠ 自检锚 `<head>` → **停手报告, 不评审**; 工作树出现评审包未声明的改动同样停手; 远端核对先跑**探针** `git ls-remote origin <当前分支>`(读命令): 命令成功且输出无该分支 ref = **本地分支态** → 跳过 tip 比对放行(与派遣第三钉互证: 派遣写本地态而探针取到 ref、或反之 = 派遣已过期/失真 —— **停手交主会话重派**, 不按探针结果续评); 取得到 ref → tip = 该 ref 现值, `git rev-list --count HEAD..<tip>` 落后 >0 → **停手报告**(评审上下文缺远端 N 笔, 主会话 sync 后重派); 落后 =0(含本地领先, 上一批推送失败的合法态) → 放行; 探针命令本身失败(网络错误/超时, 区别于成功但空输出) = 离线 → 打「无法核实」行继续评(「无法核实 ≠ 不一致」, `sync.py:78` 同款哲学)。

评审交回后主会话**收尾复核**: `git rev-parse HEAD` 仍 == 自检锚, 否则评审期间树被动过 —— 发现作废, 重新锚定后重评; 分支态以**派遣时探针判定**为准(第三钉), 收尾复核不重判态: **远端分支态**做**同款远端核对**(`git ls-remote` 现查 tip → `git rev-list --count HEAD..<tip>`): 发现评审期间远端推进 → **不作废已交发现**(评审对象 diff 未变), 但修复/收尾前必须重新 sync; **本地分支态跳过远端核对**——跳过的是 tip 比对, 探针照跑一次仅测 ref 存在性(计划 `26-11-10-0342` D1, 供下句态翻转检测); 复核发现态翻转(本地态派遣而探针取得到同名 ref、或反之)= 评审期间异常态变化(如撞名分支) —— 如实打异常行交人工裁决, **不按翻转后路径走 sync**(那是本地分支 sync 死路的复发路径); 修复增量触发复评(扳机见 ⑤: 上轮评审快照后可评内容出现任何新 diff)时以**齐平后上下文**评(本地态即本地分支态上下文, 不 sync)。

## ⑤ 产出与裁决

**产出 schema**(reviewer 输出 JSON 数组, 逐条):

```json
{"file": "相对路径", "line": 42, "quote": "单行内连续引文", "severity": "blocker|major|minor|nit", "claim": "问题一句话", "relevance": "相关|不相关", "fix": "修法一句话"}
```

- `quote` 必须是**单行内连续片段**; `commands run review.check --findings <json>` 逐条校验: 引文与源码逐字比对(行号允许 ±3 邻近)、字段齐、severity 枚举合法。**refute 的条目直接弃, 不复核** —— 幻觉引文是 LLM 评审的头号失效模式。
- reviewer 指令里显式写"**不报清单**": 理论风险(说不出具体失败场景)/ 未改动代码 / 风格偏好 / 库推荐, 一律不报。
- **相关性裁决**(主 agent, reviewer 初判仅参考): 相关 = 属于本批计划目标之内, **或**由本批改动直接引入/直接暴露; 其余一律按 create-issue skill 入池。拿不准 → 默认入池(与 scope-guard 同口径)。
- **分级处置**: blocker(真缺陷/违反黄金法则/碰红线风险)**必修完才可收尾**(硬门槛); major/minor 裁量当场修或入池; nit 通常忽略。test.full 照常兜底。
- **修/入池 计数口径**(计划 `26-11-07-0441` D2, 与 `review.check` 必跑衔接): ⑦ trailer 里的 `修`/`入池` 只数**过检且未被 REFUTE 的发现** —— 自发顺手修、被 REFUTE 弃掉的条目不进这两个数; 不跑 `review.check` 就报不出能过闸门的数(下界 `P ≥ 修+入池`, 见 ⑦)。
- **修复循环**(计划 `26-11-08-1240` D3/D4/D5): **扳机** = 上一轮评审快照之后可评内容出现**任何新 diff** → 必走一轮 —— `dev.fmt` 算改动(要格式化就在评审前做, 不设「只是格式化」口子); 记账/生成物补写不触发(基哈希过滤面与其同源, 也不动哈希)。**载体** = 每轮 `review.pack` 照旧出**整批过滤 diff**(轮间无提交对象, 对象级增量不可行), 评审指令限定「**只报新增改动的问题 + 校验上一轮发现未被回退**」, 上一轮发现清单随包附带 —— 已干净的代码不重新开庭。**出口** = 裁决后**零 actionable**: refute 弃、计划外入池算闭合、blocker/major/minor 当场修完; nit 不阻塞但留痕(档案 `review:` 行)。**轮次不限**, 直到某轮零 actionable; 修/入池/检 P/T 按**全轮累计**申报(⑦)。

## ⑥ checklist(20 条, 评审与降级自查共用)

**通用面**(源自调研: Google Engineering Practices / Mozilla goal review / OWASP 子集):

1. **Goal**: 改动对准任务目标, 修根因而非症状。
2. **Design**: 与周边架构一致, 未引入平行机制。
3. **正确性**: 边界条件、错误路径、对用户与调用方都正确。
4. **Tests**: 新行为有测试、测试有意义且会真失败。
5. **可读性**: 有无更简单的等价实现; 命名传达意图; 注释解释 why 而非 what。
6. **安全面**: 硬编码凭据、日志泄敏、输入未校验。

**本仓库面**(条条挂锚点, 锚点失效 = 文档修正任务):

7. 幂等性: 重复执行无副作用; 窗口语义走 state_file 去重(`record_execution`), 不靠循环频率 → AGENTS.md 法则 1。
8. 单一写线程: 队列结构与 state_file 只由主循环线程写; 查 TOCTOU → 法则 5。
9. 状态持久化: 跨轮状态进 state_file; 优雅退出立即落盘 + 周期落盘 → 法则 3。
10. fail-fast: 新配置键进了 `validate_config` 且同步 `src/auto_qb/config/schema/` → 法则 4(键面守卫 `test_config_key_surface` 已兜底, 查守卫外侧面)。
11. 保守默认: 高风险动作默认关, 只对显式配置范围生效 → 法则 2。
12. 红线: diff 未触碰 `config.yml` / `auto-qb-data/` → AGENTS.md 红线节 + `pitfalls/ops/prod-files.md`。
13. 范围守恒: diff 无计划外文件与"顺手改" → 法则 6 + scope-guard skill。
14. 非ASCII图形符号: 代码/配置无 emoji 与图形符号 → `conventions/code-style.md`(提交闸门 test.quick 已拦表 A 新增 —— 冻结表纯只拦新增, `tests/test_ascii_symbol_guard.py`; 评审查语义面: 豁免理由/冻结递减/表 B 边界)。
15. 测试基建: 新增测试同步 docstring"测试计划"清单; TMPDIR 约束未破坏 → AGENTS.md 测试节 + `pitfalls/testing/tmpdir.md`。
16. 真机准入: 完工功能落入真机轨两类准入 → 真机验收已做或理由已明示 → `testing/real-machine.md` §00/§06。

**文档面**(文档也要评, 这几条机器判不了):

17. **事实**: 文档里的命令、路径、行号、计数在快照里真实存在且对得上(实测: 计划引用 `commit.py:279` 已失效、基线写 "+16 例" 实为 17)。
18. **口径**: 与单点定义一致, 没有造出第二份口径; 指针指向的文件真实存在。
19. **可执行**: 照文档步骤能走通 —— 参数必填、前置条件、停手点是否写清。
20. **反面证据**: 结论是否只挑了支持自己的证据; 有没有该写而未写的反例。

## ⑦ 留痕

**提交信息 trailer 是唯一闸门键**(随提交走、跨 clone 一致、`git log --grep` 可统计)。**提交闸门是记账闸门**(声明与实算一致), 不是质量闸门 —— 不假装能验真, 人工抽查看 git log 比例:

```
Review: <范围> · <N> 行 · blocker <N> · 修 <N> · 入池 <N> · 检 P/T[ · 轮 R] · 基 <hash>[ · 派发 K][ · 分面][ · 齐平 <远端tip前8位>]
```

- `<N> 行` 必须等于闸门实算的批内改动行数(±0) —— 这一条把"声明"和"事实"绑死, 逼你真的对着这段 diff 报数。
- **`· 检 P/T` 必填**: T = 送检发现数, P = 引文逐字通过数(`review.check` 判过的条目), 同为**全轮累计**口径(修复循环首轮 + 各修复轮累加申报, 判定式对累计数照旧成立); 闸门校验 `0 ≤ P ≤ T` 且 `P ≥ 修 + 入池`(修/入池 计数口径见 ⑤) —— 写 `修 N` 就必须有过检 P ≥ N, 凭空编不出下界。
- **`· 轮 <R>` 可缺省(缺省 1)**: 修复循环轮数(计划 `26-11-08-1240` D7); 出现时必须整数 ≥ 1。**`· 基 <hash>` 必填**(D6): 值 = **末轮 `review.pack` 输出的整批过滤 diff 基哈希**(③); 闸门用同一套过滤实现**现算**当前批哈希比对, 不一致 = 评审快照后有新改动 → 判红, 出路 = 重跑 pack 取新基并补一轮复评(⑤ 修复循环)。
- **`· 派发 <K>` 缺省 1**: K = **首轮拓扑派遣数, 修复轮不计入**(累计会稀释 >400 行批的容量下界; 修复轮深度由 `· 轮 R` 与累计 检 P/T 反映); 批 >400 行时闸门要求 K ≥ 2(② 拆批优先, 走到这条的都是「确实不可拆」的残余批); ≤400 不校验数值只查形状(写了 `派发` 字样就必须是数字)。
- **`· 分面` 与 `· 齐平 <远端tip前8位>` 都是信息字段**(不判红、不参与判据)。`· 分面` 自 2026-11-07 起不再是超限的合法通路(超限只认 `派发 ≥2`), 只作 ≤400 触敏感面走了分面档(④)的叙事留痕。`· 齐平` 是弱校验字段(值 = ④ 三钉自检核对的**远端 tip 前 8 位**, 与评审记录交叉可验): 不强制存在、不验 hash 真值, 只查格式 —— 缺失/合法均静默, 格式异常一行 `[warn]` 但 **rc=0 放行, 绝不因齐平判红**; 与上行 `<N> 行 ±0` 的强校验区分。齐平态的事后审计以 **git log 里的 trailer** 为准。该 `[warn]` **不保证可见** —— 闸门通过时输出被丢弃, 仅闸门因其它原因判红时随尾行露出。
- **生效日**: 本批(计划 `26-11-08-1240`: `· 基` 必填、`· 轮 R`、全轮累计、Review-Skip 判红、50 行下限退役)落地起新批全适用; `检 P/T` 与 `派发 K` 自 2026-11-07 起要求 —— 闸门只看当前批, 老 trailer 不追溯、不重判(`26-11-07-0441` 生效日先例)。
- **Review-Skip 已退役**(计划 `26-11-08-1240` D8): 新提交写 `Review-Skip:` 闸门判红, 理由长短不再看 —— 没有免评通道, 写 `Review:` 走正常评审; 历史 trailer 不追溯, 锚点 walk 照旧识别、不重判。
- **档案进度日志的 `review:` 行仍写**(叙事与结论), 但**不当闸门键** —— 两处必然漂移, 只认提交信息一处。
- 闸门: `.commands/review/scripts/check_review_trace.py`(挂 my-commit-flow 的提交闸门, 每次提交跑, 无待评改动即静默)。

## ⑧ 降级自查

无子代理能力的工具环境: 主 agent 按 ⑥ checklist **逐条**自查, 产出同 schema 的发现列表, `review.check` 照跑; 自我裁决时**从严**(相关性与严重度都取保守侧)。其余流程(评审包/校验/裁决/留痕)不变; **基哈希照常要求** —— pack 是机械命令, 无子代理环境照跑, trailer 的 `· 基` 照填(⑦)。

## 反模式

- ❌ 把评审留到收口一次做 —— 1300 行的单块评审对已知缺陷召回 0/8, 而 400 行分批召回 7/8。
- ❌ 拿"这次改动小"当免评理由 —— 判据是可评内容 >0 行与面, 不是感觉; 1 行也要评(50 行下限已退役, 计划 `26-11-08-1240` D9)。
- ❌ 评审快照后又改了可评内容不带新基直接提交 —— 闸门基哈希机检会红, 红了补一轮复评而不是硬凑。
- ❌ 只写 trailer 不真评 —— 闸门验的是声明与实算一致, `检 P/T` 的下界(`P ≥ 修+入池`)让凭空写 `修 N` 编不出来; 走过场的批次会被下一批连坐(锚点从最近一条 `Review:` 现算, 漏评的提交滚进下一批)。
- ❌ 拿「会话开工 sync 过」当免齐平理由 —— 开工同步只覆盖会话开始时点, 窗口在会话中途; 每批派遣前照样走 ③ pack 前置 sync + ④ 三钉自检(计划 `26-11-07-0201`)。
- ❌ reviewer 顺手修 —— 它只读; 修复一律主 agent 执行, 否则评审与实现混在同一双眼睛里。
- ❌ 引文没过 `review.check` 就采信 —— 对不上即弃, 不复核。
- ❌ 超 400 行不拆批也不多派, 拿 `· 分面` 蒙混 —— 闸门只认 `派发 ≥2`, 分面写了也不放行; 分面只是换问法, 每个子代理仍要读整块, 容量没降。
