# howto — 收录一条命令进包

> [SKILL.md](../SKILL.md) 只留摘要(它每次加载都要进上下文); 细节在这里, **真到要收录时才读**。

## 三条判据(任一命中就收, 不必等人下指令)

| 判据 | 怎么判 |
|---|---|
| 重复 | 同一条在本会话(或近几轮)出现**第二次** —— 第二次就是"它会再出现"的最强信号 |
| 难拼 | 拼它要 ≥2 个环境前缀/参数, 或**得先查文档才知道怎么写**(查文档本身就是成本) |
| 易错 | 存在"看起来正常但不生效"的写法(如 POSIX 的 `TMPDIR=x cmd`)—— 这类错误没有提示, 只有假结果 |

三条都不中(只跑一次/纯调试)→ **不收**。配置保持瘦, 是它能被信任的前提。

## 命令的归宿

| 情况 | 放哪 |
|---|---|
| 会话固定流程的一环/反复要跑 | 写进某包 `config.toml` 的 `[tasks.*]`(改超时、加 task 都只是改 TOML) |
| 逻辑复杂: 多步/要解析输出/要条件分支 | 落到该包 `scripts/`, task 用 `script =` 指过去 |
| 成套的、别的仓库也用得上 | **单独成包** —— 包是复用单位, 整包复制即可带走 |
| 只跑一次/纯调试 | 不收, 直接在对话里跑 |

## 收录动作

```
add --id <id> --pack <包> --run '<命令>' --when '<何时用>' --note '<为什么必须这么写>' [--doc '<深读看哪份>']
add ... --write          # 核对落点与片段后才落盘; 落盘后自动 show 自证
```

`--when` 与 `--note` **必填**, 缺了等于没收录:

- `--when` 是**下次能被发现的唯一线索** —— 缺了它, 这条在 `list` 里只剩一个 id, 别人遇到同样场景也认不出来。
- `--note` 是**环境陷阱的判据** —— 缺了它, 下次有人(含 agent)"顺手把命令写正常点", 就退回那个不生效的写法。
- `--doc` 是**深读指针**(包内文档的相对路径, 子包继承父包基准; 指向的文件不存在即 STOP)—— 缺了它,
  想看细节的人只能整读包内 README。

两条其实是同一件事: 把"这条为什么长这样"从**执行者的记忆**搬到**包里** —— 改配置比改记忆可靠。

## 低噪音包: 一条命令的价值 = 它省下的上下文 − 它占用的上下文

包会被**反复读到**(`list` 的每一行 / `when` / `note` / 每次执行的输出), 所以"收进来"只是第一步 ——
收成**低噪音**才算合格。八条判据(前三条是硬要求, 后五条是纪律):

| 判据 | 怎么写 | 反例 |
|---|---|---|
| **输出自带静音** | 命令带"只要结论"的开关(`-q` / `--no-cov` / `-s` 这类); 要细节由调用方显式要 | 一条高频命令每次把整段测试输出灌进上下文 |
| **异常行可被机器认出** | 输出里保留 `[WARN]` / `FAILED` / `Traceback` 这类标记 —— 引擎的摘要**按它们挑行**, 标记丢了就等于把警告藏起来 | 自造 `~~ 注意 ~~` 这种只有人眼认得的记号 |
| **一条 = 一个动作** | 要串 3 条命令时先问"这是不是一个脚本"(落包内 `scripts/`, 用 `script =` 指过去) | 一条 `run` 里 `a && b && c`, 红了不知道死在哪一步 |
| **`when` 一句话** | 写"什么时候该调它" —— 它是下次能被发现的**唯一**线索 | 把教程 / 背景写进 `when`(`list` 每行都被拉长) |
| **`note` 只写陷阱判据** | "为什么必须这么写"(不写就会退回那个不生效的写法) | 复述命令本身、写历史沿革 |
| **长文进 `doc`** | 判据 / 排障 / 迁移说明外置到包内 `references/`, `note` 只留一行指针 | 二十行说明塞进 `note`(每次 `show` 都付这份钱) |
| **`timeout` 按最坏情况给** | 它同时是"卡死多久算失败"的护栏 | 全包抄同一个 600 —— 真正会挂住的命令等于没护栏 |
| **`pin` 是稀缺资源** | 只给"每次会话都要用"的; 一层浮出超 `MAX_PIN_PER_LEVEL` 引擎会 WARN | 见命令就 `--pin`, 一级视图退回平表 |

**收完自检三句**: ①这条每次跑会往上下文灌多少行? ②真出错时, 调用方**只看摘要**能不能看出死在哪一步?
③下次有人遇到同样场景, 光看 `list` 那行 `when` 认不认得出它? 三句都答不上来 ⇒ 这条还没写完。

> wrapper 与收录**无关**: 它只做"向上找仓库根 → 找引擎 → 转发参数"(见 [wrapper.md](wrapper.md)),
> 新命令进包后 `list` / `run` 立刻可见 —— 不需要动 wrapper。

## 防滥用(别让配置变垃圾桶)

- `add` 默认 **dry-run**: 先看到"写进哪个文件、写成什么样", 加 `--write` 才落盘。
- `--when` 空即拒绝; `--pack` 指向不存在的包即拒绝; `--id` 已存在即**拒绝覆盖**(改既有命令请直接编辑包的 `config.toml`)。
- `--pin` 只给"每次会话都要用"的命令 —— 滥用等于把平表搬回一级视图(引擎有 `MAX_PIN_PER_LEVEL` 兜底)。
- 落盘即入库改动 ⇒ 会走提交闸门(反漂移闸门也在那里), 天然有复核点。
- 三条判据同时是**上限**, 不是"看到就收"。
