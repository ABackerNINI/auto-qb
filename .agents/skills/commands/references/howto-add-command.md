# howto — 收录一条命令进包

> [SKILL.md](../SKILL.md) 只留摘要(它每次加载都要进上下文); 细节在这里, **真到要收录时才读**。

## 三条判据(任一命中就收, 不必等人下指令)

| 判据 | 怎么判 |
|---|---|
| 重复 | 同一条在本会话(或近几轮)出现**第二次** —— 第二次就是"它会再出现"的最强信号 |
| 难拼 | 拼它要 ≥2 个环境前缀/参数, 或**得先查文档才知道怎么写**(查文档本身就是成本) |
| 易错 | 存在"看起来正常但不生效"的写法(如 POSIX 的 `TMPDIR=x cmd`)—— 这类错误没有提示, 只有假结果 |

三条都不中(只跑一次/纯调试)→ **不收**。配置保持瘦, 是它能被信任的前提。

## 命令的归宿

| 情况 | 放哪 |
|---|---|
| 会话固定流程的一环/反复要跑 | 写进某包 `config.toml` 的 `[tasks.*]`(改超时、加 task 都只是改 TOML) |
| 逻辑复杂: 多步/要解析输出/要条件分支 | 落到该包 `scripts/`, task 用 `script =` 指过去 |
| 成套的、别的仓库也用得上 | **单独成包** —— 包是复用单位, 整包复制即可带走 |
| 只跑一次/纯调试 | 不收, 直接在对话里跑 |

## 收录动作

```
add --id <id> --pack <包> --run '<命令>' --when '<何时用>' --note '<为什么必须这么写>' [--doc '<深读看哪份>']
add ... --write          # 核对落点与片段后才落盘; 落盘后自动 show 自证
```

`--when` 与 `--note` **必填**, 缺了等于没收录:

- `--when` 是**下次能被发现的唯一线索** —— 缺了它, 这条在 `list` 里只剩一个 id, 别人遇到同样场景也认不出来。
- `--note` 是**环境陷阱的判据** —— 缺了它, 下次有人(含 agent)"顺手把命令写正常点", 就退回那个不生效的写法。
- `--doc` 是**深读指针**(包内文档的相对路径, 子包继承父包基准; 指向的文件不存在即 STOP)—— 缺了它,
  想看细节的人只能整读包内 README。

两条其实是同一件事: 把"这条为什么长这样"从**执行者的记忆**搬到**包里** —— 改配置比改记忆可靠。

## 防滥用(别让配置变垃圾桶)

- `add` 默认 **dry-run**: 先看到"写进哪个文件、写成什么样", 加 `--write` 才落盘。
- `--when` 空即拒绝; `--pack` 指向不存在的包即拒绝; `--id` 已存在即**拒绝覆盖**(改既有命令请直接编辑包的 `config.toml`)。
- `--pin` 只给"每次会话都要用"的命令 —— 滥用等于把平表搬回一级视图(引擎有 `MAX_PIN_PER_LEVEL` 兜底)。
- 落盘即入库改动 ⇒ 会走提交闸门(反漂移闸门也在那里), 天然有复核点。
- 三条判据同时是**上限**, 不是"看到就收"。
