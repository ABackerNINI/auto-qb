# commands

项目命令的**统一调用面**。要跑一条命令时不去文档里抄 —— 先按层级定位, 再调。
命令只有一处定义(某个包里), 所以写法不会发散, 改一处即全局生效。

> **路径约定**：`<skill-dir>` = 本 skill 所在的目录。安装位置因项目而异 —— **先用 Glob 定位**
> （`**/commands/scripts/run.py`），别照抄路径。

## 两种记法（都是记法, 不是可直接粘贴的命令）

- **文档记法** `commands run <task>` —— 文档与回复里一律用它：短, 且不含任何实现细节。
- **真实入口** `python <skill-dir:commands>/scripts/run.py <子命令> [参数]` —— 真要用 shell 敲时,
  把 `commands` 换成这一串, 后面的子命令与参数原样接上。

两种都**不是**让你去抄命令本体：命令只在包里定义一处, 文档里再抄一份就是反漂移闸门要判红的形态。
`<skill-dir:commands>` 是占位符, 敲之前先按上面的路径约定展开成真实路径。

## 引擎不认识"我们在做什么事"

这里只有机制：**包**与**命令**。引擎里没有"哪个仓库""推哪个远端""要不要带环境前缀"这类事实 ——
那些都在包里, 包是**黑盒**：引擎唯一读的文件是 `<包>/config.toml`, 包里还有什么它不知道, 也不该知道。
所以本 skill 对任何仓库都成立, 仓库特有的东西一份也不会漏进来。

推论：**想加命令, 只有"放进某个包"这一条路**。散在包外的文件引擎扫不到 —— 那是静默失效。

## 四个子命令

| 子命令 | 作用 | 什么时候用 |
|---|---|---|
| `run <task>` | 校验前置后执行；超时按失败计。**常规路径只用它** | 已经知道 id |
| `list [包路径]` | 列出**当前层级**：包 + 常显命令 | 还不知道调哪个 |
| `show <task>` | 打印展开占位符后的真实命令, 不执行 | 排障 / 自证 |
| `add` | 收录一条命令进包（默认 dry-run, `--write` 才落盘） | 见下面收录协议 |

`run` 默认只回结果摘要, 不 dump 命令 —— 省 token, 也把环境前缀这类细节留在包里；
**带 `requires` 或标 `risky = true` 的例外**, 它先打印将要执行什么再执行（高风险恰恰最需要先自证）。

## 引导：按当前任务逐级下钻

- **要执行动作, 还不知道调哪个** → `list`：看有哪些包、各自管什么事, 以及各包的常显命令（`★`）
- **按当前任务选包** → `list <包>`：看这个包的本级命令与子包
- **还没定位** → 继续下钻 `list <包>/<子包>`（深度不限）
- **已经知道 id** → 直接 `run <id>`, 跳过前面所有步骤
- **排障** → `list --all`：一次性列出全树（含被禁用的, 标出来）

`★` = 常显：标了 `pin = true` 的命令**浮到父级列表**, 不必进到所属包就能看到。
一级视图里只有包与常显命令, 所以命令总数从十条长到两百条, 一级视图都不会臃肿 ——
**不臃肿靠的是分层, 不是靠写得短**。`list --all` 是兜底不是入口：一旦被当成常规入口,
臃肿就从那张平表搬到这里。同理 `pin` 只给"每次会话都要用"的命令, 滥用等于把平表搬回一级。

## 收录协议（本 skill 会自己长大）

遇到一条命令, 三条判据**任一命中**就自己收进配置, 不必等人下指令：

1. **重复** —— 同一条在本会话（或近几轮）出现第二次。第二次出现就是"它会再出现"的最强信号。
2. **难拼** —— 拼它要 ≥2 个环境前缀 / 参数, 或**得先查文档才知道怎么写**（查文档本身就是成本）。
3. **易错** —— 存在"看起来正常但不生效"的写法。这类错误没有提示, 只有假结果。

三条都不命中（只跑一次 / 纯调试）→ **不收**。配置保持瘦, 是它能被信任的前提。

收录动作：

```
add --id <id> --pack <包> --run '<命令>' --when '<何时用>' --note '<为什么必须这么写>'
add ... --write          # 核对落点与片段后才落盘; 落盘后自动 show 自证
```

- `--when` 与 `--note` **必填**：前者是下次能被发现的唯一线索（缺了它这条只剩一个 id, 等于没收录）；
  后者是环境陷阱的判据（缺了它, 下次有人"顺手把命令写正常点"就退回那个不生效的写法）。
  两条其实是同一件事：把"这条为什么长这样"从执行者的记忆搬到包里。
- `--id` 已存在则**拒绝覆盖**（改既有命令请直接编辑包的 `config.toml`）；`--pack` 不存在则拒绝。
- 逻辑复杂（多步 / 要解析输出 / 要条件分支）就落到包的 `scripts/`, task 用 `script =` 指过去。

## 停手点

- **STOP（退出码 1）**：配置写错（未知键 / `timeout` 非法 / 包级 `confirmed = false`）·
  占位符展不开 · `requires` 的前置非 0 · task id 全树重复 · 包名与目录名不一致 ·
  子包注册指向的目录不存在。**一律不静默降级** —— 静默失效意味着"看起来跑过了",
  那比报错坏得多, 而且 WARN 会被淹没在十几行输出里。
- **命令非 0（退出码 3）**：看输出里的失败行, 不要照着重跑一遍。

## 反模式

- ❌ 去文档里抄命令 —— 抄来的那份可能正是"看起来最正常但不生效"的那一版；用 `list` / `show` 取。
- ❌ 把命令写进包外的散文件 —— 引擎扫不到, **静默失效**；收录只能走 `add`。
- ❌ 把项目事实写进引擎 —— 那是包的事, 引擎只管机制。
- ❌ 把 `list --all` 当常规入口 —— 它是排障兜底。
- ❌ 见命令就收 —— 三条判据同时也是上限, 不满足的收录会让配置变成垃圾桶。
