# commands

项目命令的**统一调用面**:要跑命令时不去文档里抄,先按层级定位再调。命令只有一处定义(某个包里),改一处即全局生效。

> **路径约定**:`<skill-dir>` = 本 skill 所在目录,安装位置因项目而异 —— 先用 Glob 定位(`**/commands/scripts/run.py`),别照抄路径。

引擎只认识**包**与**命令**:项目事实(哪个仓库/推哪个远端/环境前缀)全在包里,引擎只读 `<包>/config.toml`,包里还有什么它不知道也不该知道 —— 所以**加命令只有"放进某个包"这一条路**,散在包外的文件引擎扫不到(静默失效)。

## 两种记法(都是记法,不是可直接粘贴的命令)

- **文档记法** `commands run <task>` —— 文档与回复里一律用它:短,且不含实现细节。
- **真实入口** `python <skill-dir:commands>/scripts/run.py <子命令> [参数]` —— 要用 shell 敲时把 `commands` 换成这一串、后面原样接上;`<skill-dir:commands>` 按上面的路径约定展开。

两者都**不是**让你去抄命令本体:命令只在包里定义一处,文档里再抄一份就是反漂移闸门要判红的形态。

## 四个子命令

| 子命令 | 作用 |
|---|---|
| `run <task>` | 校验前置后执行,超时按失败计。**常规路径只用它** |
| `list [包路径]` | 列出**当前层级**:包 + 常显命令 |
| `show <task>` | 打印展开占位符后的真实命令与 `doc` 深读指针,不执行(排障/自证) |
| `add` | 收录一条命令进包(默认 dry-run),见「收录协议」 |

`run` 默认只回结果摘要、不 dump 命令 —— 省 token,细节留在包里;**带 `requires` 或 `risky = true` 的例外**,先打印要执行什么再执行。

## 引导:按当前任务逐级下钻

- **要执行动作、还不知道调哪个** → `list`:有哪些包、各自管什么事,以及各包的常显命令(`★`)
- **按任务选包** → `list <包>`;还没定位 → 继续下钻 `list <包>/<子包>`(深度不限)
- **已知 id** → 直接 `run <id>`
- **要看细节** → `show <id>` 给的 `doc` 指针(包内 `references/`)
- **排障** → `list --all`:全树(含被禁用的)

包内 README 与 `references/` 是**包私有**(引擎不读):日常只要 task id,**不要整读包内 README** ——
纪律该走 `doc` 指针按需读,整读等于把"读整份文档找命令"的成本搬回来。

`★` = 常显(`pin = true`),浮到父级列表。一级视图只出"包 + 常显",所以命令从 10 条长到 200 条也不臃肿 —— **靠分层,不是靠写得短**。`list --all` 是兜底不是入口;`pin` 只给"每次会话都要用"的命令。

## 收录协议

三条判据**任一命中**就自己收,不必等人下指令:①**重复**(本会话出现第二次) ②**难拼**(≥2 个环境前缀/参数,或得先查文档) ③**易错**(有"看起来正常但不生效"的写法)。都不中(只跑一次/纯调试)→ **不收**。

细节(判据怎么判/放哪个包/`add` 必填项与防滥用)见 **[references/howto-add-command.md](references/howto-add-command.md)**,真到要收录时才读。

## 停手点

- **STOP(rc=1)**:配置写错(未知键/`timeout` 非法/`confirmed = false`)·占位符展不开 · **参数给了不接参数的 task** · `requires` 前置非 0 · task id 全树重复 · 包名≠目录名 · 子包目录不存在 · **`doc` 指向的文件不存在**(指针指空会让人回头整读包内 README)。**不静默降级** —— 静默失效意味着"看起来跑过了",比报错坏得多。
- **命令非 0(rc=3)**:看输出里的失败行,不要照着重跑。

## 反模式

- ❌ 去文档里抄命令(可能正是"看起来最正常但不生效"的那版);用 `list`/`show` 取。
- ❌ 见命令就收 —— 三条判据同时是上限,否则配置变垃圾桶。
