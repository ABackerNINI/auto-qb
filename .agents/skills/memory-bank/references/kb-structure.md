# howto — 知识库结构 / 索引 / 脚本

> [SKILL.md](../SKILL.md) 只留**每次会话都要用的**(会话两端 + 立档); 结构改造的细节在这里,
> **要拆文档 / 改目录 / 动脚本 / 查索引时才读**。

## 超标文档怎么拆: 五步配方

1. **量**: 按 `##`/`###` 切段统计字符数, 对照 SKILL.md 的 cap 表定目标文件数; 同时统计引用处数(决定存根的必要性)。
2. **建**: 建 `<文档>/` 目录; 每个主题文件头部写三行头; **原句照搬, 不重写内容** —— 只做三件事:
   按动作补 `触发`、长叙事压成一句「为什么」、散落的实测数字与守阵名收进字段。
3. **生成**: 仅 pitfalls 类目录跑生成器产出 `_index.md`(**不许手写**; 其余族索引已退役, 26-11-08)。
   不留墓碑/存根 —— git 历史即冷库, 旧引用靠 `grep` + `git log -- <旧路径>` 兜底。
4. **接线**: 更新路由(`memory-bank/README.md` 细路由 + `AGENTS.md` 粗路由)、改活文档互引、改 skill/DoD 里的路径。
   **历史文档(计划 HTML / issue 报告 / 任务档案正文)一行不改**(死链不修, 同上兜底)。
5. **守恒核对**: 迁移前的条目/段落清单(`md5` + 字节)与迁移后逐条比对, **missing 必须为 0**; 守卫与闸门转绿。

## 主题文件的三行头元数据(生成器的数据源)

```
# <标题>                                  ← 索引行用它
> 摘要: 一句话说清「这文件治什么病」        ← 索引行用它
> 触发: 推送, 同步, ref 核对               ← 动作词, 供 grep 与路由
```

条目型(`pitfalls/`)与叙述型**共用同一套** —— 新增一个主题文件 = 写三行头 + 跑生成器, 不需要新脚本、不改守卫。
`<文档>/_about.md` 同格式, 存的是**目录**的元数据(标题 / 一句话 / 触发条件)。

## cap 与流水轮转

cap 的机器单点是 `_common.CAP_POLICY`, 人读镜像在 [SKILL.md](../SKILL.md) 的 cap 表(守卫钉住两者一致)——
**别在别处抄第三张表**。下限建议 1.5 KB **只 WARN**: 主题文件过小会让「读三个文件」取代「读一节」, 反而更贵。

**触顶处置 = 固定动作, 禁止压文案 (2026-11-05 用户重定调)**: 任何文件超 cap, 目标**刚好 ≤ cap**,
只做「外迁 `attachments/` → 删除死段 → 合并邻近件」; 压文案会丢事实且每次触顶都返工。
**append-only 流水触顶 = 轮转, 不是删**: `*-history.md` 这类 `log` 文件超 cap 时, 从**最老一端**
切到 ≤ cap, 外迁**同目录** `attachments/` 并原位留一行指针 ——
❌ 只搬"最老的一条"是错的: 条目大小不受控, 下次追加会立刻再触顶(2026-09-23 实测 `testing/baseline-history.md`
触顶时只剩 170 字符余量)。`check_kb_structure.py` 报这条时会把目标字符数直接打出来;
搬运按原换行风格切分**原样**写回, 不手抄。

## 脚本(统一落在本 skill 的 `scripts/`; 文档里一律写 `<skill-dir>/scripts/…`)

| 脚本 | 干什么 |
|---|---|
| `_common.py` | `find_root()` / `CAP_POLICY` / `FAMILIES` / `PITFALL_CLASSES` / 三行头读取 —— 各脚本共用, 守卫也 import 它 |
| `gen_kb_index.py` | **通用**: 任意目录 → `_index.md`(有子目录出类指针, 无则出文件指针; 26-11-08 后生成集合只剩 pitfalls 两级) |
| `gen_doc_map.py` | 认领链/主键校验(无物化文件): `--check` 查 ref 双向闭环与孤儿, 挂 `kb.check` |
| `check_kb_structure.py` | 结构检查: cap 策略 / 元数据 / 双向一致 / 无孤儿 / 存根 / 条目三字段 |
| `gen_active_recent.py` | 读 `active-context/` 切片: 按「最后活动」倒序输出一行摘要 + 陈旧标记; **不写任何文件**; `--check` 校验命名 / 元数据 / cap(「最后活动」存在但格式坏也判红) |
| `timekit.py` | 时间单点 (UTC+8 钉死, 与机器时区无关): `date` / `time` / `stamp` / 无参三行; `check` 是三层日期守卫(文件名 / 元数据 / 正文) |
| `check_doc_links.py` | 相对链接存在性扫描 —— 改名 / 搬家后的坏链不会让任何测试失败, 只能机检(2026-10-06 从根 `scripts/` 迁入) |

**「索引目录」是自发现的**: 含 `_about.md` 的目录即纳入 —— 26-11-08 重构后只有 pitfalls 一族仍走生成索引, 其余族的 `_index` 已删(检索 = grep + `kb.nav`(人))。
生成器都有 `--check`(只比对, 闸门用); 守卫**在进程内 import 检查器**(本项目测试禁止起子进程, `tests/sidefx.py` 会记账越界)。

## active-context 会话切片的四条约定

多 clone 并行下「每个收尾 DoD 都必写的单文件」是最热的冲突源 —— 最热的写点还集中在文件头同一段。
切片把它从「每会话重写头部同一段」变成「新增/更新自己的文件」, 不同文件在三方合并里结构性无冲突:

- **文件名** `YY-MM-DD-HHMM-<slug>.md`: 前缀**定宽**才能保证字典序 == 时间序(`26-9-3-34` 立刻乱序)。
  ⚠ 与 tasks/ 档案「不带时分、同天同专题必撞同路径」的故意设计**意图相反** —— 那边靠撞名暴露重复,
  这边靠带时分避撞名 —— 所以两者必须分目录, 别混。
- **不带 clone 标记**: 同分钟同名 add/add 概率极低, 撞了改 slug 重来即可。「我上次做到哪」靠 **slug 复用**检索,
  这给出的是**专题维度的时间线**, 比 clone 维度分区信息价值更高。
- **读法**: 跑 `gen_active_recent.py` —— **默认按字节预算取最近 K 条**(2026-10-02 修订: 全量倒序在切片 90+ 条后
  撞壳 30KB 内联上限; 排序键仍是「最后活动」, 推进中的切片必在最近侧; `--all` / `-n N` 逃生);
  目录规模靠**归档**控制, 不靠 N。
- **不产出任何缓存文件**(没有 `_recent.md`): 缓存会过期, 一个看着可读、实际是上次运行快照的文件
  比「没跑脚本」更危险; 时间戳文件名自带时间与主题, `ls` 本身就是索引。

## 检索纪律: kb.active(最近) → README 路由 → grep 兜底, **禁止整读**

```
commands run kb.active     最近会话滚动状态(在办专题切片)
→ memory-bank/README.md   细路由表, 按任务选目录/文档
  → grep -rn "<词>" memory-bank/    兜底(不确定关键词时)
```

**「禁止整读某个目录」不是格式洁癖, 是预算纪律** —— 整读行为一旦回来, 目录化就白做了。

## 扩类 / 扩目录: 必须同时改三处

新增一个类或目录, 要同步改: ①枚举(`_common.PITFALL_CLASSES`, 仅类范畴) ②`memory-bank/README.md` 细路由
③该目录的 `_about.md`。少一处守卫就红。

## 结构相关的反模式(本仓库已踩过)

- ❌ 全量倒序输出切片清单 → 90+ 条撞壳 30KB 内联上限(2026-10-02 实测); 默认按字节预算取最近 K 条, 全量 `--all` 逃生。
- ❌ 生成 `_recent.md` 之类的摘要缓存 → 会过期; 看着可读的旧快照比「没跑脚本」更危险。脚本直接打印。
- ❌ 往切片文件名里塞 clone 标记 → 把「专题维度的时间线」降级成「clone 维度的分区」; 撞名改 slug 即可。
- ❌ 在 active-context 里维护长青内容(定案口径 / 下一步候选 / 待走查) → 那些在别处都有事实源, 这里是副本, 双份必然漂移。
- ❌ 把维护规则只放在 `applyTo: 'memory-bank/**'` 的 instruction 里 → 编辑 `src/` 时该规则不在上下文, **决策点与生效点错位**。
- ❌ 手改 `pitfalls/` 的 `_index.md` → 它是生成物, 冲突的解决方式是重跑生成器, 不是人工合并两版文本。
