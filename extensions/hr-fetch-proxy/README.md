# auto-qb HR 取数代理(浏览器扩展)

一个**哑取数器**: 它只负责「在真实浏览器里取内容, 然后原样回传」, 不做解析、不做频控判断、
**不读也不传 cookie**。所有策略与解析都在 auto-qb 后端。

## 为什么是这个形态

- 站点访问必须带你的登录态, 但后端**不该持有 cookie**(Chrome 127+ 的 App-Bound Encryption
  已经让「后端直读 cookie 库」既不可靠也不合法; 手工填 cookie 等于把维护成本转嫁给你);
- 扩展跑在**你日常的浏览器**里, 登录态由浏览器自己带, cookie 全程不出浏览器;
- 页面**默认无界面直取**(扩展后台自己发请求, 带站点 cookie, 不开标签也不开窗口);
  只有当直取到的内容看起来不像已登录的页面时才退到**离屏窗口**渲染取 DOM(拿得到 JS 渲染后的内容,
  也过得了挑战页); `.torrent` 同样由后台请求取(带 `credentials: 'include'`)。

❗**抓数默认不占你的界面**: 两轮实报之后定下的口径 —— 最早用 `chrome.tabs.create({active:false})`
在你窗口里开后台标签, 会被浏览器连窗口一起抬到前台; 改成最小化的自建窗口后, 部分平台仍会先显示一下。
现在的做法是: **能直取就不开任何界面**, 需要渲染时用一个**屏幕外(离屏)的 popup 窗口**
(不进任务栏 + 不聚焦), 用完立即连窗口一起删, 并在极端情况下把焦点还回你原来的窗口。

## 安装

1. 打开 `chrome://extensions`(Edge 是 `edge://extensions`), 右上角开启 **开发者模式**;
2. 点 **加载已解压的扩展程序**, 选本目录(`extensions/hr-fetch-proxy`);
3. 点扩展的 **详情 → 扩展程序选项**(或在列表里点「扩展程序选项」)进入配置页;
4. **授权站点**(独立一步, 别跳过): 在「② 站点权限」勾选要取数的站点 → 点 **申请勾选站点的权限**
   → 每行右侧出现 **已授权**。**没授权 = 该站点一次都取不到。**

> ❗**重装 / 重新加载扩展会清空站点权限**
>
> 站点 origin 走的是 MV3 的**可选权限**(`optional_host_permissions`, 安装时默认不授予, 由你在选项页
> 运行时申请)。所以只要点了「重新加载」、更新了扩展、或重装了它, 这组权限**全部回到未授予**,
> 而**安装步骤不会提醒你**。症状是「拉清单正常、自测正常、日志也在动, 但站点一个都取不到」,
> 后端日志里是 `扩展未授权该站点, 取数请求根本没发出去`(旧版本只会显示 `Failed to fetch`)。
>
> 判断方法: 看工具栏图标 —— 有站点未授权时徽标是红底 `!`(悬停「站点未授权」); 或直接看选项页
> 「② 站点权限」每行右侧的状态列 / 顶部那句「N 个站点未授权, 取数会全部失败」。
> 处置: 点一次 **授权未授权站点** 即可(只申请缺的那几个 origin)。

## 配置

### 0. 先满足「端点会启动」的三个开关(缺一不可)

后端的本地端点只有在**同时**满足三件事时才启动; 任一没开, 扩展那边看到的就是一句
`TypeError: Failed to fetch`(浏览器对网络层失败只会给这句话, 查不出原因):

1. `hr_check.enabled: true` —— 总开关;
2. 至少一个站点 `trackers.<站点>.hr_check.mode` 不是 `off`(如 `partial`);
3. `hr_check.channel.enabled: true` —— 本实例装了扩展。

满足后, 后端启动日志会打一行(`port` 配 0(默认)时端口随机, 实绑端口以这行为准; 配了发现端点时扩展会自动拿到, 无需手抄):

```
HR 取数通道端点已启动: http://127.0.0.1:<端口>(仅监听本机回环, 需 token 鉴权)
```

### 1. 后端侧(`config.yml`)

```yaml
hr_check:
  enabled: true
  channel:
    enabled: true
    port: 0             # 默认 0 = 交 OS 随机(实绑端口经发现端点自动分发给扩展); 显式端口 = 完全旧行为
    # discovery_port: 18788   # 默认即 18788; 0 = 关闭发现; 被占自动顺延 +1/+2
    # token: ""         # 留空 = 自动生成到 <data_dir>/hr.token(配了发现后扩展免手抄)

trackers:
  pt.btschool.club:
    hr_check:
      mode: partial                  # 该站启用在线核实
      hr_page_url: "https://pt.btschool.club/myhr.php"
```

启动 auto-qb(主程序, 不是 `--hr-once` 走查)后, 密钥文件在 `<data_dir>/hr.token`(内容不打印到日志, 直接打开复制)。

### 2. 扩展侧(选项页)

2026-09-26 定稿: 风格选型 **A 瑞士网格**(样张 [memory-bank/plans/26-09-26-0031-plan-hr-ext-options-style.html](../../memory-bank/plans/26-09-26-0031-plan-hr-ext-options-style.html)),
页面自上而下四步 + 两张表, 冗长 log 收进折叠区只作排障用:

```
① 连接后端(自动发现自愈; 手动指定优先) —— 状态卡 + 发现操作 + 实例表 + 动作行 + 折叠说明:
   状态卡: 大状态字(未配置 / 连接正常 / 重连中 / 发现失败 / 站点未授权) + 一行指标(实例数(可用) · 上次发现
     时间与命中端口); 重连中 / 发现失败态整卡描边(橙 / 红), 发现失败时下方「手动端点」自动展开。
   自动发现: 发现地址默认 http://127.0.0.1:18788, 同机零配置; 跨机只填 NAS 地址
     (跨机/开启配对时填后端 6 位展示码); 「立即发现」= 隐式保存(地址与配对码随点击落盘)+ 发现的一次
     点击闭环 —— 用输入框**当前值**探测, 命中后实例自动入列(徽标「自动」, token 免手抄), 并自动接一次
     自测给出「到底能不能用」的结论。
   实例表(真表头): 来源(手动/自动) · 端点 · token(前 32 位指纹, 悬停完整值; 自动条目显示「-」) ·
     状态(四态色点: 绿=正常 / 橙=连败中 / 红=token 或来源被拒 / 灰=还没轮过, 悬停可见 note 与最近
     联系) · 最近联系 · 操作(手动条目只有「删」; 自动条目留空, 由发现租约自动管理)。手动组在前、
     自动组在后。
   动作行: 「重测全部」(逐实例只读探测, 结论落台账后状态列即时刷新; 10s 禁用窗) + 「立即拉取一次」;
     状态行 + 提示行紧贴其下。
   折叠区「说明与排障」: 徽标图例 / 端口机制 / 配对码 / 排查指路; 手动端点(优先)折叠表单。
   手动端点(优先: 你显式指定的实例, 永远优先使用, 不会被自动发现覆盖或删除) —— 折叠区表单: 地址 + token;
     「存入实例列表」即时生效(不用点保存)。发现只**补齐**手动没覆盖的端点, 绝不覆盖或删除手动条目。
② 站点权限 —— 进页自动从后端拉清单(GET /api/hr/sites, 按 trackers.*.hr_check 配置派生),
   勾选(默认全勾) → 点「申请勾选站点的权限」一键授权; 拿不到时展开「手动填写站点」兜底。
   每行右侧带**授权状态列**(已授权 / 未授权, 读 chrome.permissions.getAll() 现算, 进页与授权后各刷一次);
   有未授权时顶部给汇总句「N 个站点未授权, 取数会全部失败」+ 「授权未授权站点」按钮(只申请缺的那几个);
   徽标随之进入「站点未授权」态(红底 `!`)。
③ 站点现状 —— 一行一站: 最近活动 / 最近动作与结果 / 用量(本时·本日, 访问/下种) / 状态(正常·受限·登录失效·异常)。
④ 最近取数明细 —— 一次取数一行(环形最近 50 条): 时间 / 站点 / 类型 / 结果 / 耗时 / 大小。
折叠区: 运行日志(逐条完整记录, 排障用) + 扩展侧硬上限展示 + 高级 JSON 直接编辑 + 保存
```

**连接自愈 + 不静默(2026-10-16)**: 数据端口在 `port: 0` 下每次重启都会变, 所以连接是**自愈**的 ——
**任一实例拉取失败即触发一次发现**(60s 节流), 另有 **2 分钟**的周期发现兜底; 端口变了不用人工干预,
发现会自动补入新端点、并把失效的旧发现端点剪除(手动条目原样保留)。发现结果不再只躺在日志里:

- **浏览器工具栏的扩展图标状态色外框**(常驻可见): 未配置(无框) / 连接正常(绿框) / 重连中(橙框) /
  发现失败(红框, 图标角标补 `!`) / **站点未授权**(红框 + 角标 `!`, 悬停「站点未授权」) ——
  平时徽标文字清空零遮挡, 故障时恢复文字报警; 悬停有中文结论,
  **点图标即回本页**(那是报警后的第一动作);
- **选项页「① 连接后端」顶部状态卡**: 大状态字 + 实例数(可用) · 上次发现时间/命中端口 · 最近一次发现结果;
- 发现失败一律给**中文结论 + 逐候选探测结果**(如 `18788 连接失败 · 18789 HTTP 404`), 不再把
  `no-hit`/`未知` 这类后台失败码原样丢给用户猜。

③④ 的数据源是后台与运行日志**同源双写**的结构化事件环(`chrome.storage` 的 `events`, 上限 50 条)——
日志给人读排障, 事件环给表格渲染, 两者各记各的; 「清空日志」只清日志, 不动两表。
「保存」按钮只剩高级 JSON 与手动站点源两个职责, 会把归一化结果写回输入框, 看得见存的是什么。
点 **重测全部** 先确认后端那边通了(逐实例只读探测, 结论落实例表状态列), 再点 **立即拉取一次**: 它会先请求后端立即开波
(POST /api/hr/refresh, 跳过后端的数据复用窗与拉取间隔 —— 账号频控仍由后端把守), 随后照旧排空
本轮任务。后端版本较旧(端点 404)时自动降级为纯排空, 日志里会提示升级主程序。

## 跨机部署(NAS + 外部浏览器)

后端在 NAS、浏览器扩展在外部 PC —— 四条达成路径, 按运维成本从低到高:

| 路径 | 做法 | 适合 |
|---|---|---|
| **直绑 + 发现(推荐)** | 后端 `hr_check.channel.host: <NAS 内网 IP>`; 扩展「自动发现」填 `http://<NAS IP>:18788` | 同一局域网(受信内网) |
| SSH 隧道兜底 | PC 上 `ssh -L 18788:127.0.0.1:18788 -L <数据端口>:127.0.0.1:<数据端口> nas`, 扩展全部按 127.0.0.1 配(旧同机形态) | 不想暴露端口到内网; 数据端口随机时隧道要跟端口变, 这种场景**给 `port` 配显式值更省心** |
| 反代终止 TLS | 反代把 `https://nas.example/...` 指到后端端点; 扩展填 `https://` 地址(scheme 保留不折) | 跨网段 / 不受信网络 |
| VPN | 组网(如 WireGuard)后同「直绑 + 发现」, 地址换 VPN 网段 | 已有组网 |

**发现与配对上手(直绑路径)**:

1. 后端配 `host: <NAS 内网 IP>`(「非回环 + pairing=off + 未配 token」会被校验拦下); 启动日志打
   数据端点行 + `HR 发现端点已启动` 行(实绑 18788/18789/18790 之一)+ 一行**配对展示码**(6 位);
2. 扩展选项页「① 连接后端」的发现地址填 `http://<NAS IP>:18788` → 点「立即发现」(地址与配对码随这次点击一起保存, 无需单独的保存按钮);
3. 首次会提示**要求配对码**: 把后端日志/HR 状态卡里的 6 位展示码填进「配对码」再点一次「立即发现」;
   命中后实例自动入列(徽标「自动」), token 免手抄 —— 之后无需再管;
4. 安全口径: 传输是明文 HTTP(token 在 LAN 上可被嗅探) —— **仅限受信内网**; 非受信网络走反代(TLS)
   路径; 配对码只挡「未授权拉取」, 不挡链路嗅探。删除后端 `<data_dir>/hr.pairing` = 吊销全部配对
   (所有配对方下次重新配)。

## 排障

| 现象 | 真实原因 | 怎么办 |
|---|---|---|
| **拉清单 / 自测**报 `TypeError: Failed to fetch` | 后端端点**没在监听**(三个开关缺一 / 主程序没在跑 —— `--hr-once` 是只读走查, **不会**起端点), 或端口/主机写法不对 | 按上面 §0 逐个开关核对; 点选项页动作行的 **重测全部**(或看实例表「状态」列色点), 它会直接告诉你是「连不上」「401 token 不对」还是「403 来源被拒」 |
| **站点取数**报 `Failed to fetch`(拉清单却正常) | 与上一行**完全不同的病因**, 而且两种, 动作相反: ① **扩展没有该站点的 host 权限**(可选权限未授予 / **重装或重载扩展后被清空**) ② 扩展到该站点的**网络层**失败(DNS / 代理 / VPN / 断网)。浏览器对两者都只给这一句, 后端侧则分得清: 前者日志是「扩展未授权该站点」+ 站点卡「通道: 扩展未授权该站点(去扩展选项页授权)」, 后者是「扩展到站点的网络请求失败」 | ① 去选项页看「② 站点权限」每行右侧状态列(或点 **授权未授权站点**), 徽标红底 `!` 也是同一信号; 授权后**不必重装**, 下一轮轮询即恢复 ② 若状态列显示**已授权**却仍取不到: 查浏览器所在机器的网络 / 代理 / VPN 规则是否覆盖该站点(后端与频控无关, 此时 `fail_streak` 不增长、日志不带 `[HR 页面改版]`) |
| 跨机连不通(同机正常, 跨机 `Failed to fetch`) | 跨机网络不可达: NAS 防火墙拦了端口 / 不在同一网段 / `host` 没配成 NAS 内网 IP | 先在 PC 上 `curl http://<NAS IP>:18788/api/hr/discover` 验证可达; 再查 NAS 防火墙端口放行; 数据端口随机时靠「立即发现」自动拿, 不要手抄旧端口 |
| 自动发现未命中 / 后端报「发现端点候选端口 … 全部被占」 | 18788/18789/18790 三候选被占(后端绑定自动顺延, 扩展并行探测同表); Windows 上还有 Hyper-V/WSL2 动态**排除段**(无监听者也绑不上, 且随重启漂移) | 选项页会给出**逐候选探测结果**(如 `18788 连接失败 · 18789 HTTP 404`)与中文结论, 工具栏图标同时转「发现失败(红框 + 角标 !)」; 三候选全占 ⇒ 数据端点照常、扩展退**手动指定**; 换 `discovery_port` 到临时端口段外(默认 18788 在 Windows 49152–65535 之外); Windows 排障查 `netsh interface ipv4 show excludedportrange protocol=tcp` |
| 发现报「要求配对码」/ 配对失败 | 非回环端点必须过 6 位配对码(防 LAN 上未授权拉取 token); 连续错码按来源临时静默(5 次/分钟) | 在后端启动日志 / WebUI HR 状态卡找 6 位展示码, 填进选项页「配对码」再「立即发现」; 展示码跨重启稳定(密钥在 `<data_dir>/hr.pairing`, 删除即吊销重配) |
| `Invalid value for origin pattern xxx: Missing scheme separator.` | 站点权限那栏填了**裸域名**(如 `pt.btschool.club`), 而 Chrome 只收匹配模式 | 现在填裸域名也能用了(保存时自动补成 `https://pt.btschool.club/*`); 修正后重新 **保存** + **申请勾选站点的权限** |
| 拉清单报 `401` | 端点可达, 但 token 不对或该实例没启用通道 | 把 `<data_dir>/hr.token` 的内容整串复制到实例的 `token` 字段; 并确认 `channel.enabled: true` |
| 报 `403` | 非扩展 origin 被拒(或配了 `channel.extension_id` 但与本扩展 id 不一致) | 要么清空 `channel.extension_id`(靠 token 鉴权), 要么把本扩展 id 填进去 |
| 任务能拉但一直「无任务」 | 该站点未到刷新时机 / 数据还在复用窗内 / 日额到顶 / Retry-After 未到 | 看后端日志里该站点的 action 与原因(或跑 `auto-qb --hr-once` 只读走查看全景) |
| 后端日志反复出现 `配额/间隔受限(还差 Ns)` | 后端在按频控节奏取数: 每个站点请求之间要等 `min_interval`(默认 90s, 抖动只向上), 而一个波要跑 A/B/C 三个档位 + 回填 `.torrent` | **什么都不用做**: 取数线程会在**锁内把间隔等满**(单次上限 5 分钟), 慢慢跑完一波。只有「还差 Ns」超过单次上限(日额到顶 / Retry-After / 时间窗)时才会真的让位 —— 那才是值得看一眼的情况 |
| 状态栏/日志出现 `扩展侧硬上限挡下` | 后端自己的频控**没拦住**, 被扩展的**第二道闸**退了回去(见下面「扩展侧硬上限」) | 先看后端配置与日志(`hr_check.min_interval` / 日额 / 是否有人手工灌任务), 再跑 `auto-qb --hr-status` 看频控账本 |
| 重启后报 `站点文件解析失败: Expecting value: line 1 column 1 (char 0)` | 站点数据文件是**空的或坏了** (常见: 写盘时被强杀 / 有编辑器或同步盘在动那个目录) | 后端已自动把坏文件挪到 `<站点>.json.bad-<时间戳>` 并尝试用 `.bak` 恢复, 无需手工干预; 若反复出现, 检查该目录是否被云同步盘/编辑器占用(HR 目录不要放同步盘) |
| 抓取时看到一个 **Chrome 窗口/标签闪一下** | 设计如此: 直取到的内容不像已登录页面(需 JS 渲染或命中挑战页)时, 扩展会用离屏窗口渲染一下 | 不用管; 正常情况**什么都不开**(直取即可)。若每次抓取都闪, 说明该站点直取拿不到内容 —— 把后端日志里那行「直取到的内容不像已登录的页面」告诉维护者 |
| 站点页面取回来了但后端说「不完备」 | 分页没到底 / 档位没抓全 / 必填字段缺失超阈 | 确认 `hr_page_scopes` 含 A+B+C; 若页面确实改版, 后端会告警(改版只改后端, 扩展不用重装) |

## 怎么确认它在工作

- **工具栏图标状态色外框**是常驻信号(五态见「配置 §2」图例); **选项页「① 连接后端」顶部的状态卡**
  给出大状态字 · 实例数 · 上次发现时间与结果 —— 不点开页面也能知道连不连得上;
- 「① 连接后端」区的**实例表「状态」列**给出每实例四态(绿=正常 / 橙=连败中 / 红=token 或来源被拒 /
  灰=还没轮过), 悬停可见 note 与最近联系时间; 状态行会显示每次轮询的结果(取了几条 / 回传 HTTP 状态;
  并标明是「全部直取(无界面)」还是有哪几条走了渲染; 被硬上限挡下的会单独标出); 点 **重测全部**
  立即探一遍(逐实例只读), 区分「连不上 / 401 / 403」;
- 后端日志(以及 `auto-qb --hr-once` 报告里的「取数通道」段)会显示端点、密钥来源与最近联系时间;
- 通道静默超过 `hr_check.channel_silence_warn` 会告警一次(浏览器没开 / 扩展被停用 / token 不一致)。

### 运行日志(扩展侧取证)

选项页折叠区的运行日志是扩展自己的运行日志, 排查「这轮到底发生了什么」不用再去翻 SW 控制台:

- **记什么**: 每次轮询的开始/结束、后端下发的每条命令(kind · id · 站点)、对站点的每次请求
  (类型: 拉任务清单 / 页面直取 / 页面渲染 / 种子下载 · HTTP 结果 · 耗时 · 字节数)、回传结果与
  **后端响应体快照**、扩展侧硬上限的每次拒发 —— 全部带时间戳(精确到毫秒);
- **分级**: `debug / info / warn / error`。「记录」级别(默认 info, 低于它的直接丢弃不占额度)与
  「显示」过滤是两个独立设置; 条数上限可设 10–10000(默认 1000, 超出丢最旧)。两个设置**即时生效**;
- **连不上时自动降噪(2026-09-28)**: 后端端点不在跑时, 轮询每分钟一轮若都打全量排查清单, 日志环几小时
  就被同一句话灌满。故按「故障期」只打头尾 —— **首次失败**照旧打全量 ERROR; **连败期**降为 debug 短句
  (默认级别下不落盘), 每连败 30 轮(约半小时)重提一次全量防失联; **恢复**时补一句 INFO 并注明此前连败
  轮数。状态栏每轮照常刷新, 但**同文复读**进日志时也降为 debug(状态有变化才记 info)。要看连败期每一轮
  的记录, 把「记录」级别调到 debug 即可;
- **存哪**: 只存本地 `chrome.storage.local`(随环形上限滚动覆盖, 不上传); service worker 被回收
  重启后日志不丢(唯一事实源是 storage, 防抖整份写回);
- **清空**: 点「清空日志」经后台清(后台内存缓冲是唯一写入口); 清完会留一条「日志已清空」证明清过;
- **限制**: 单字段超长自动截断(页面 HTML 不会整份进日志), 一次最多渲染最近 3000 行(更早的收窄过滤看)。

## 安全边界(设计如此, 不是省略)

| 项 | 做法 |
|---|---|
| cookie / passkey | 后端既不接收也不存储; 扩展不调用 `chrome.cookies`, 只回传页面 HTML 与 `.torrent` 字节 |
| 端点监听 | 默认仅 `127.0.0.1`(`host` 可配私网 = 跨机直绑); 数据端点必须带 `X-Hr-Token`, 无 token / token 不符 ⇒ 401 **且不写任何状态**; 发现端点(发 token 的那端)免 token, 两道关 = origin 白名单 + 配对码(非回环默认强制) |
| origin 白名单 | 只放行 `chrome-extension://`(配了 `channel.extension_id` 就只认那一个); 普通网页一律 403 |
| URL 白名单 | 任务 URL 只能由后端按配置拼出(域名 + 路径受限) ⇒ 端点不会变成「带登录态的任意站代理」 |
| 任务绑定 | 只有**后端确实派发过**的任务回传才被接受, 且回传 URL 域名须与任务一致 —— 伪造数据进不来 |
| 轮询节奏 | 扩展每 **1 分钟**拉一次清单(空轮询只打本机 loopback, 不碰站点); **站点侧节奏由后端决定**(间隔 / 日额 / Retry-After / 时间窗的第一道闸在后端); 扩展另有一道**独立计数**的硬上限(见下节)作为第二道闸。❗轮询周期(1 分钟)必须小于后端 `channel.request_timeout`(默认 180s), 否则任务会等不到轮询而超时(v2.6 实报修复) |
| 界面 API 的作用面 | `tabs` / `scripting` / 窗口创建**只**在渲染兜底路径用(直取路径一个都不碰), 且只操作扩展自建的那个离屏窗口, 从不改用户的标签/窗口 |

### 扩展侧硬上限(第二道闸: 后端出错时的兜底)

后端的频控(间隔 + 日额)与扩展跑在**同一个账号**的两侧: 后端代码写错、配置被改坏、
或有人手工灌任务时, 承受后果的是用户的账号。所以扩展自己另计一层数 —— 阈值在
[`site-caps.js`](site-caps.js)(**唯一事实源**, 后台与选项页共用), 超限即**拒发**那次请求:

| 指标 | 每小时 | 每天 |
|---|---|---|
| 访问同一站(HR 统计页; 渲染兜底那次额外导航也算) | 60 | 600 |
| 下载同一站的 `.torrent` | 50 | 200 |

> 2026-09-27 随后端配额模型拆分(计划 26-09-27-1815)上调 page caps: 后端 split 模型页面桶
> 40/时, 上限口径维持「≥ 后端 × 1.5」⇒ 10/时·50/天 → 60/时·600/天。

- 计数按**站点域名**分开, 窗口键按本地时区的整点/零点翻篇(与后端同一套口径: 靠键比较, service worker 被回收重启也不归零);
- 拒发时**不发出任何请求**, 并回传 `kind: "ext-quota"` + `retry_after` —— 后端据此把本轮记成「让位」
  (不计失败, 本波让位), 并在日志里提醒「后端频控可能失效」(这需要人看一眼, 所以它是一条 WARNING, 每个站点只报一次);
- 选项页折叠区的「扩展侧硬上限」会列出当前阈值与各站点的**已用量**, 据此就知道闸门是否在起作用。

## 已知限制

- 站点 `.torrent` 若校验 `Referer` 或要求 XHR 专用头, 可能取不到 —— 通道会把失败如实上报(计入退避),
  不会静默; 届时按站点实际情况调整策略(例如改由页面上下文取)。
- 扩展需要浏览器处于运行状态; 浏览器关闭期间通道静默, 后端保守回落「未核实」。
- 站点改版只需**改后端**(解析在后端), 扩展无需重装。
- **站点 origin 是可选权限**: 重装 / 重新加载扩展会把它们清空(见上面「安装」第 4 步), 需重新授权一次;
  这是浏览器行为, 不是本扩展的选择 —— 授权状态随时可在选项页「② 站点权限」看到。
