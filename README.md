# auto-qb

**基于 qBittorrent WebUI API 的 PT 种子自动化管理工具**

[![Python](https://img.shields.io/badge/python-3.12+-blue?logo=python&logoColor=white)](https://www.python.org/) [![License](https://img.shields.io/badge/license-Apache%202.0-green)](https://www.apache.org/licenses/LICENSE-2.0)

Web UI 管理台 · 标签 / 分类 / HR 管理 · 辅种分组与缺文件保护 · 自定义规则引擎 · 多级限速 · 校验 / 跳检 · 桌面通知 · 托盘常驻

---

auto-qb 常驻后台运行,实时跟随 qBittorrent 的状态,自动帮你打理 PT 种子:该打的标签自动打、HR 帮你盯着、有风险的操作先拦住。它与 qB 之间只同步发生变化的数据,几乎不给 qB 增加负担。

> 🚧 **施工中**:功能已实现、测试完备,但尚未经过大规模实机验证。标记 🚧 的功能请先用 `--dry-run` 观察,谨慎在生产环境使用。

## 功能特性

### 🏷️ 标签 / 分类管理

- 自动添加 / 删除站点标签 / 分类, 自动清理相似标签(单词相同、大小写不同)
- 不再需要的标签可自动清理: 能彻底删除, 也能只在无种子使用时才删
- 新种子自动打**集数标签**: 从文件列表解析集数, 如 `EP01.mkv`~`EP05.mkv` → `zE1-5`

### ⏱️ HR 管理

- 满足 HR 触发条件(下载比例 / 下载量)时自动加 HR 标签或分类, 如 `!!HR3D!!`
- 做种时长达到「要求时间 + 额外时间」后自动加「达标」标签 / 分类, 如 `--HR3D--`
- 每个站点可单独配置 HR 规则

### 👯 辅种管理

- 将指向**相同文件列表**的种子(辅种)自动归为一组, 并检查组内文件大小一致性(不一致 → 警告 + 整组暂停)
- **缺文件保护**:文件丢失立即发现, 整组暂停 + 打上 `MISSING` 标签
- 下载冲突(多种子写同一份文件)立即拦截, 整组暂停🚧

### 🐢 限速

- 可根据站点配置单种限速, 种子添加即生效
- **全局限速曲线**: 根据每天 / 每N天 / 每月的上传下载总量自动调整总限速

### 🌐 Web UI

浏览器打开就是一个为 PT 而生的管理台:

- **辅种分组,一目了然** - 指向同一份文件的种子自动归成一组, 组内速度、进度、站点一眼看清
- **追剧视图,自动归位** - 全部种子按 剧 → 季 → 集 聚合, 缺哪集直接标出来🚧
- **配置全程点选** - 站点 / 规则 / 限速曲线在浏览器里完成, 保存即校验、备份、热生效
- **批量操作利落** - 搜索 + 标签 / 站点 / H&R 多维筛选, 多选后批量 开始 / 暂停 / 强制汇报 / 删除
- **双皮肤** - 经典深色仪表盘与工程仪器风一键互切, 后者内置 5 套主题

### 🛡️ 稳定运行

- 各功能独立计时、互不干扰, 单个功能出错不影响其他功能与整体运行
- 运行状态与历史记录都保存在数据目录,重启接着上次继续; 状态定期落盘, 断电 / 强杀也只丢几分钟进度
- 启动时**全量检查配置**, 所有问题一次报出,不带病运行
- 同一份配置同时只能运行一个实例, 防止两个实例互相打架
- **主动通知**: 出错 / 危险情况推送系统原生通知

### 🧩 自定义规则引擎🚧

- 触发时机 + 筛选条件 + 动作, 动作顺序执行, 支持去重、冷却与错误处理
- **?? 种条件 × 12 种动作**, 全部可自由组合; 除固定间隔外还支持种子添加 / 状态变化 / 删除事件触发

### 🔍 HR 在线核实🚧

有些站点只有**一部分**种子受 HR 约束, 开启后按站点定期取「我的 H&R」清单、逐种子对账。

## 快速开始

### 环境要求

- Python 3.12+
- [uv](https://docs.astral.sh/uv/) 0.12+(依赖与虚拟环境管理;Windows: `winget install astral-sh.uv`)
- qBittorrent(已开启 Web UI;已在 qB 5.2.3 测试,其他版本待测)

### 1. 安装

```text
# 下载 / 克隆源码后,进入项目目录
commands run env.sync    # 一次装齐全部依赖(含托盘 / Web UI / 测试)
```

> `commands run <task>` 是本仓库命令的统一调用面: `<task>` 对应 `.commands/` 包里的一条命令
> (真实命令与环境前缀都在包里, 不在这里抄)。不知道有哪些就 `list` 逐级看 —— 用法见 AGENTS.md。

依赖全部锁定在锁文件里,重复执行 `commands run env.sync` 结果可复现,无需其他安装步骤。

### 2. 配置

**推荐用 Web UI 图形化配置**:`minimal.yml` 已默认开启 Web UI,开箱只需要填好 qBittorrent 连接信息,其余全部在浏览器里点选完成:

```yaml
config:
    qbittorrent:          # qBittorrent 连接信息(WebUI 端口)
        host: 127.0.0.1
        port: 8080
        username: <USERNAME>
        password: <PASSWORD>
    web:                  # 本程序 Web UI(minimal.yml 已默认开启)
        enabled: true
        port: 8080        # 与 qB WebUI 同端口时请改开一个
        token: ""         # 访问密钥; 留空 = 首次启动随机生成
```

启动程序(见下一步)后,浏览器打开 `http://127.0.0.1:8080`,输入访问密钥登录,在「设置」页完成站点 / 规则 / 限速曲线等**全部配置**:表单化增删改、保存前自动校验、自动 `.bak` 备份、改完即时生效。

> 访问密钥留空时首次启动自动生成(存到数据目录的 `web.token` 文件,日志打印一次);本机访问可开启「跳过本地验证」免密钥进入。
>
> ⚠️ **安全提示**:默认只监听 `127.0.0.1`(仅本机可访问)。改为 `0.0.0.0` 等对外地址会把**可删除种子、可改配置**的管理界面暴露到网络,请务必配合防火墙 / 反向代理 / 额外鉴权使用。

偏好直接编辑 YAML 时,也可以根据**已有种子的 tracker 自动导出配置模板**(先在 `minimal.yml` 填好连接信息):

```bash
# 读取 minimal.yml 的连接信息, 把生成的模板写入 config.yml
# ⚠️ 注意: 该命令会写入(覆盖)指定的输出文件
uv run auto-qb minimal.yml --export-yaml config.yml

# 加 --only-missing 只导出尚未配置的 tracker, 生成最小骨架(同样会覆盖输出文件)
uv run auto-qb minimal.yml --export-yaml config.yml --only-missing
```

> 全部配置项的字段说明与完整示例见[配置参考](docs/configuration.md);直接编辑 YAML 后需重启程序生效。

### 3. 运行

```bash
# 强烈建议第一次先试运行: 只打印将执行的动作,不实际改动 qBittorrent
uv run auto-qb --dry-run

# 确认无误后正式运行(默认读取 config.yml)
uv run auto-qb

# 指定配置文件
uv run auto-qb my-config.yml

# 托盘常驻模式(状态窗口 + 系统托盘, 详见[托盘模式](#托盘模式))
uv run auto-qb --tray
```

> 上面是用户可见的入口; `commands run dev.run -- config.yml` 走的是同一份源码入口,两者等价。

### Docker 部署

不想装 Python 环境也可以用 Docker:`docker compose up -d --build` 一条命令起服务,状态跨重启续接。
构建 / 配置 / 升级 / 排障见 **[部署文档](docs/deployment.md)**。

## 命令行参数

| 参数                         | 说明                                                                    |
|------------------------------|-------------------------------------------------------------------------|
| `config`                     | 配置文件路径(位置参数,默认 `config.yml`)                              |
| `--export-yaml`, `-e OUTPUT` | 导出 YAML 配置模板到 OUTPUT 后退出(不进入自动管理)                     |
| `--only-missing`             | 仅导出尚未配置的 tracker 站点(配合 `--export-yaml` 使用)               |
| `--dry-run`, `-n`            | 试运行:只打印将执行的动作,不实际操作 qBittorrent                      |
| `--tray`                     | 托盘常驻模式:系统托盘图标 + 状态窗口;再次启动会唤起已运行实例的窗口   |
| `--export-torrents_info`     | 把全部种子的信息导出到 `torrents.txt`(排障用,导出后退出)             |

## 托盘模式

不想留终端窗口时,可用 `--tray` 让程序缩进系统托盘常驻,自动化照常在后台运行:

```bash
uv run auto-qb --tray             # 默认 config.yml, 也可在前面指定配置文件
uv run auto-qb --tray --dry-run   # 托盘模式同样支持试运行
```

- **深色状态窗口**:显示受管种子数、运行时长、qB 连接状态与最近日志;点关闭按钮只是隐藏到托盘,程序继续在后台运行
- **托盘菜单 / 窗口控件**:暂停 / 恢复自动管理(暂停期间不动任何种子,恢复后自动补上错过的处理)、通知开关(随时生效)、开机自启开关、打开 qBittorrent WebUI、打开日志目录、退出
- **不会双开**:重复执行 `--tray` 时,第二次启动会唤起已运行实例的窗口,然后自己退出
- **开机自启**:注册为当前用户的开机启动项(自动带上当前配置文件路径),不需要时在菜单中关闭即可
- 无桌面环境(SSH / 服务会话)下托盘模式会报错退出,不影响命令行模式

## 桌面通知

配置 `notify.enabled: true` 后,运行中的 WARNING / ERROR 日志(缺文件、下载冲突、跳检失败等)会以**系统原生通知**推送,无需安装任何额外组件:

- **防打扰**:免打扰时段(支持跨午夜)、每小时条数上限、相同内容自动去重
- 全屏游戏 / 演示等繁忙场景由系统专注助手 / 勿扰模式自动静默
- 托盘菜单可随时开关通知(本次运行生效,重启后回到配置状态)
- `--dry-run` 试运行不发送通知

## 设计理念

这些原则决定了 auto-qb 在各种情况下的行为方式,也是它「敢于自动操作」的底气:

- **幂等**:同一个动作重复执行不会产生额外副作用;「每天一次」这类节奏由程序自己记录、重启也不受影响,而不是靠检查得频繁来碰运气
- **保守默认**:高风险动作(跳检、强制汇报、删除种子、覆盖限速)默认关闭,或只对你明确允许的范围生效
- **状态可续**:跨重启的状态(规则执行历史、上传量统计、限速状态等)都保存在数据目录,重启后接着上次的进度继续
- **先查再跑**:启动时把整个配置检查一遍,所有问题一次报出来;检查通过才开始操作 qBittorrent
