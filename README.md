# auto-qb

**基于 qBittorrent WebUI API 的 PT 种子自动化管理工具**

[![Python](https://img.shields.io/badge/python-3.12+-blue?logo=python&logoColor=white)](https://www.python.org/) [![License](https://img.shields.io/badge/license-Apache%202.0-green)](https://www.apache.org/licenses/LICENSE-2.0)

auto-qb 常驻后台运行，实时跟随 qBittorrent 的状态，自动帮你打理 PT 种子：该打的标签自动打、HR 帮你盯着、有风险的操作先拦住。它与 qB 之间只同步发生变化的数据，几乎不给 qB 增加负担：

- **省心保种** — 自动打站点标签、跟踪 HR（Hit & Run）触发与达标状态，做种时长满足要求后自动标记
- **辅种安全** — 把指向相同文件的种子自动归组，缺文件 / 大小不一致 / 下载冲突时**整组暂停**，防止误传垃圾数据被站点封号
- **灵活自动化** — 16 种筛选条件 × 12 种动作自由组合成规则，周期 / 事件触发、去重冷却、错误处理一应俱全
- **智能限速** — 按站点单种限速 + 规则限速 + 依据每日流量数据的全局限速曲线，流量到量自动降速
- **可视可控** — 内置 Web UI（推荐的配置方式，默认关闭）：辅种分组 / 单种子双视图、种子搜索、右键控制 + **全部配置图形化增删改**（自动校验、备份、改完即生效）；另支持 `--tray` 托盘常驻与系统原生桌面通知
- **安全第一** — 高风险动作（跳检、强制汇报、移动）默认关闭；提供 `--dry-run` 试运行；启动时全量检查配置

> 🚧 **施工中**：项目功能已实现并带有完整测试（872 个用例），但尚未经过大规模实机验证。标记 🚧 的功能尤其请先用 `--dry-run` 观察，谨慎在生产环境使用。

## 功能特性

### 🏷️ 标签 / 分类管理

- 按 tracker 自动添加 / 删除站点标签，自动清理相似标签（单词相同、大小写不同）
- 彻底删除标签 `delete_tags`，或仅在无种子使用时删除 `delete_tags_if_has_no_torrents`（均支持正则与 `@tracker_tags` 引用）
- 新种子自动打**集数标签**：从文件列表解析集数，如 `EP01.mkv`～`EP05.mkv` → `zE1-5`；多集不连续则视为不可靠、放弃打标

### ⏱️ HR 管理

- 满足 HR 触发条件（下载比例 / 下载量）时自动加 HR 标签或分类，如 `!!HR3D!!`
- 做种时长达到「要求时间 + 额外时间」后自动加达标标签 / 分类，如 `--HR3D--`
- 标签格式支持变量，站点配置可覆盖全局配置

### 👯 辅种管理（种子分组）

- 将指向**相同文件列表**的种子（辅种）自动归为一组，并检查组内文件大小一致性（不一致 → 警告 + 整组暂停）
- **缺文件检查**：组内种子被删除、由上传转暂停、重新校验发现文件缺失（种子进入错误状态）、或保存路径变化时立即触发磁盘扫描；文件丢失 → 整组暂停 + `MISSING` 标签
- 组内多个种子同时下载、或已完成与下载中并存 → 警告 + 整组暂停 🚧（已带 `MISSING` 标签的完成成员不计入"已完成"——已知缺文件的组允许重新下载补救；多个种子同时下载仍拦截）

### 🐢 限速

- tracker 配置内置单种限速字段，种子添加即生效
- 规则动作支持单种上传 / 下载限速
- **全局限速曲线**：根据每天 / 每N天 / 每月的上传下载总量自动调整总限速（见[配置参考 · 全局限速曲线](docs/configuration.md#全局限速曲线)）
- 限速不覆盖奇数 KiB/s 值——手动设置且不希望被覆盖的限速可设为单数（如 `2001 KiB/s`）

### 🌐 Web UI（默认关闭）

- **辅种管理页**：分组 / 单种子双视图，辅种分组表格（组内速度 / 总上传 / 总大小 / 站点徽章，列头排序、拖拽调宽、展开各站点成员明细）+ 按种子名 / 文件名搜索；多选（Ctrl/⌘ 点选、Shift 范围选择）+ 批量操作浮条（开始 / 暂停 / 强制汇报 / 删除，选中后吸顶常驻）；组级与单种子级右键操作（暂停 / 开始、强制汇报、删除），每个命令都有执行结果提示（强制汇报有 等待中 / 汇报成功 / 超时失败 三种状态，tracker 确认窗口 30s）；删除确认框展示待删目标明细（整组逐个列出成员种子）并提供"删除前强制汇报"（默认勾选，汇报失败则不删除）与"删除磁盘文件"选项；今日流量面板可打开历史流量折线图（天 / 月 / 年视图，悬停取值）
- **图形化设置页**：全部配置表单化增删改——基础设置、站点、规则集（16 种条件 / 12 种动作的选择、排序与参数编辑）、全局限速曲线等；只读 YAML 预览，保存时自动校验 + `.bak` 备份 + 改完即生效（需重启的项自动回退并提示）
- **安全默认**：默认仅监听 `127.0.0.1`（仅本机可访问），访问密钥鉴权（未配置则首启随机生成）；前端完全本地托管，不依赖任何外部网络资源（见 [Web UI](#web-ui)）

### 🧩 自定义规则引擎 🚧

- 触发时机 + 筛选条件 + 动作，动作顺序执行，支持去重、冷却与错误处理（见[配置参考 · 规则系统](docs/configuration.md#规则系统)）
- **16 种条件 × 12 种动作**，全部可自由组合；除固定间隔外还支持种子添加 / 状态变化 / 删除事件触发

### 🛡️ 稳定运行

- 各功能独立计时、互不干扰，单个功能出错不影响其他功能与整体运行
- 运行状态与历史记录都保存在数据目录（规则执行历史、上传量统计、限速状态、跳检备份等），重启后接着上次的进度继续
- 启动时**全量检查配置**：未知配置项、格式错误、规则引用错误一次性全部报出，不带病运行
- 同一份配置同时只能运行一个实例，防止两个实例互相打架
- **主动通知**（见 [桌面通知](#桌面通知)）：程序出错 / 危险情况（缺文件、下载冲突、跳检失败等）时推送**系统原生通知**（Windows / Linux / macOS，无需安装额外组件）；免打扰时段 + 频率节流防打扰，全屏等繁忙场景由系统专注助手自动静默
- **托盘常驻**（`--tray`，见 [托盘模式](#托盘模式)）：系统托盘图标运行，深色状态窗口（种子数 / 运行时长 / 最近日志）；可随时暂停 / 恢复自动管理、开关通知、设置开机自启；重复启动自动唤起已运行实例的窗口；跨平台（Windows / Linux / macOS）
- 从已有种子的 tracker 一键导出 YAML 配置模板

## 快速开始

### 环境要求

- Python 3.12+
- [uv](https://docs.astral.sh/uv/) 0.12+（依赖与虚拟环境管理；Windows: `winget install astral-sh.uv`）
- qBittorrent（已开启 Web UI；已在 qB 5.2.3 测试，其他版本待测）

### 1. 安装

```bash
# 下载 / 克隆源码后，进入项目目录
uv sync    # 按 pyproject.toml + uv.lock 精确创建虚拟环境(含开发依赖)
```

全部依赖（含托盘与 Web UI 所需组件）已在 `pyproject.toml`(直接依赖)与 `uv.lock`(全量传递依赖)中锁定，重复执行 `uv sync` 结果可复现，无需其他安装步骤。

### 2. 配置

**推荐用 Web UI 图形化配置**：`minimal.yml` 已默认开启 Web UI，开箱只需要填好 qBittorrent 连接信息，其余全部在浏览器里点选完成：

```yaml
config:
    qbittorrent:          # qBittorrent 连接信息(WebUI 端口)
        host: 127.0.0.1
        port: 8080
        username: <USERNAME>
        password: <PASSWORD>
    web:                  # 本程序 Web UI(minimal.yml 已默认开启)
        enabled: true
        host: "127.0.0.1" # 监听地址, 默认仅本机
        port: 8080        # Web UI 端口; 若与 qB WebUI 同端口请改开一个
```

启动程序（见下一步）后，浏览器打开 `http://127.0.0.1:8080`，输入访问密钥登录（见 [Web UI](#web-ui)），在「设置」页完成站点 / 规则 / 限速曲线等**全部配置**：表单化增删改、保存前自动校验、自动 `.bak` 备份、改完即时生效。

偏好直接编辑 YAML 时，也可以根据**已有种子的 tracker 自动导出配置模板**（先在 `minimal.yml` 填好连接信息）：

```bash
# 读取 minimal.yml 的连接信息, 把生成的模板写入 config.yml
# ⚠️ 注意: 该命令会写入(覆盖)指定的输出文件
uv run auto-qb minimal.yml --export-yaml config.yml

# 加 --only-missing 只导出尚未配置的 tracker, 生成最小骨架(同样会覆盖输出文件)
uv run auto-qb minimal.yml --export-yaml config.yml --only-missing
```

> 全部配置项的字段说明与完整示例见[配置参考](docs/configuration.md)；直接编辑 YAML 后需重启程序生效。

### 3. 运行

```bash
# 强烈建议第一次先试运行: 只打印将执行的动作，不实际改动 qBittorrent
uv run auto-qb --dry-run

# 确认无误后正式运行(默认读取 config.yml)
uv run auto-qb

# 指定配置文件
uv run auto-qb my-config.yml

# 托盘常驻模式(状态窗口 + 系统托盘, 详见[托盘模式](#托盘模式))
uv run auto-qb --tray
```

> `uv run python src/auto-qb.py` 是等价的旧式写法，两者任选。

## 命令行参数

| 参数                         | 说明                                                                    |
|------------------------------|-------------------------------------------------------------------------|
| `config`                     | 配置文件路径（位置参数，默认 `config.yml`）                              |
| `--export-yaml`, `-e OUTPUT` | 导出 YAML 配置模板到 OUTPUT 后退出（不进入自动管理）                     |
| `--only-missing`             | 仅导出尚未配置的 tracker 站点（配合 `--export-yaml` 使用）               |
| `--dry-run`, `-n`            | 试运行：只打印将执行的动作，不实际操作 qBittorrent                      |
| `--tray`                     | 托盘常驻模式：系统托盘图标 + 状态窗口；再次启动会唤起已运行实例的窗口   |
| `--export-torrents_info`     | 把全部种子的信息导出到 `torrents.txt`（排障用，导出后退出）             |

## 托盘模式

不想留终端窗口时，可用 `--tray` 让程序缩进系统托盘常驻，自动化照常在后台运行：

```bash
uv run auto-qb --tray             # 默认 config.yml, 也可在前面指定配置文件
uv run auto-qb --tray --dry-run   # 托盘模式同样支持试运行
```

- **深色状态窗口**：显示受管种子数、运行时长、qB 连接状态与最近日志；点关闭按钮只是隐藏到托盘，程序继续在后台运行
- **托盘菜单 / 窗口控件**：暂停 / 恢复自动管理（暂停期间不动任何种子，恢复后自动补上错过的处理）、通知开关（随时生效）、开机自启开关、打开 qBittorrent WebUI、打开日志目录、退出
- **不会双开**：重复执行 `--tray` 时，第二次启动会唤起已运行实例的窗口，然后自己退出
- **开机自启**：注册为当前用户的开机启动项（Windows 注册表 / Linux XDG autostart / macOS LaunchAgents），启动参数自动带上当前配置文件路径；不需要时在菜单中关闭即可
- 无桌面环境（SSH / 服务会话）下托盘模式会报错退出，不影响命令行模式

## 桌面通知

配置 `notify.enabled: true` 后，运行中的 WARNING / ERROR 日志（缺文件、下载冲突、跳检失败等）会以**系统原生通知**推送，无需安装任何额外组件：

- **Windows 10/11**：原生 toast 通知，首次运行自动注册通知来源（显示程序名与图标）；**Linux**：`notify-send`（桌面环境自带 libnotify）；**macOS**：系统通知
- **防打扰**：`quiet_hours` 免打扰时段（支持跨午夜）、`max_per_hour` 每小时条数上限、`dedup_window` 相同内容去重窗口；节流状态重启后重新计算
- 全屏游戏 / 演示等繁忙场景由系统专注助手 / 勿扰模式自动静默
- 托盘模式下可在菜单中随时开关通知（仅对本次运行生效，重启后回到配置状态）；程序异常退出前也会尽力补发一条通知
- `--dry-run` 试运行不发送通知

## Web UI

**Web UI 是推荐的配置方式**：全部配置都能在设置页图形化编辑，保存即校验、备份并热生效（下文「设置页」详述，字段说明见[配置参考](docs/configuration.md)）。

在配置中开启后，程序正常运行（含 `--tray`）时会在后台启动内置 Web 服务，浏览器打开即可使用；`--dry-run` 试运行不启动。

```yaml
config:
    web:
        enabled: true          # 总开关, 默认关闭(保守默认)
        host: "127.0.0.1"      # 监听地址, 默认仅本机
        port: 8080             # 监听端口
        token: ""              # 访问密钥; 留空 = 首次启动随机生成
```

**访问与鉴权**：浏览器访问 `http://127.0.0.1:8080`（端口以配置为准），在登录页输入访问密钥。密钥取 `web.token`；留空时首次启动会随机生成并保存到 `<data_dir>/web.token`（仅当前用户可读写），启动日志中也会打印一次。所有接口都有密钥校验，密钥错误返回 401。

> ⚠️ **安全提示**：默认只监听 `127.0.0.1`（仅本机可访问）。改为 `0.0.0.0` 等对外地址会把**可删除种子、可改配置**的管理界面暴露到网络，请务必配合防火墙 / 反向代理 / 额外鉴权使用。

**新版界面（可选切换）**：浏览器访问 `http://127.0.0.1:8080/newui/`（端口以配置为准）体验全新视觉与多主题。顶栏「主题」按钮可随时切换 5 套主题：深海机房 / 暗夜星云 / 极地晨霜 / 麦秋 / 品牌轨道（暗色系统默认「深海机房」，浅色系统默认「极地晨霜」，手动选择后保存在浏览器本地）。新旧两版功能完全一致，只是视觉与主题系统不同，可随时互切。

**辅种管理页**：

- **双视图切换**：**分组视图**（默认）与**单种子视图**（每个种子一行，含未归组种子；独立排序 / 列宽记忆 / 多选批量，右键单种子菜单）；筛选与搜索两视图共用
- **辅种分组表格**：组内下载 / 上传速度、总上传、总大小、站点徽章；点击列头三态排序（降序 → 升序 → 恢复默认）、拖拽调宽 + 列选择器显隐（列宽按列记忆），展开查看各站点成员明细（进度、做种时长、分享率、hash）
- **多选筛选器**：标签 / 分类 / 站点 / **H&R（达标 / 未达标）** / 保存路径组合（同一筛选器内"或"、不同筛选器间"且"），叠加搜索；状态分布条点击即筛
- **按种子名 / 文件名搜索**：任一成员命中即保留整组并高亮命中成员，实时生效无需刷新
- **信息栏双模式**：默认左侧悬浮卡（概览 / 今日流量 / 限速对照），可一键移到顶部导航成紧凑双排条（第一排 = 下载 / 上传速度，其余缩小显示），偏好自动记忆
- **批量操作**：Ctrl / Shift 多选组与成员，浮条开始 / 暂停 / 强制汇报 / 删除 / 清除
- **组级与单种子级右键操作**：暂停 / 开始、强制汇报、删除（保留文件 / 连同文件删除）；删除确认框显示待删种子明细（站点 / 名称 / **保存路径**），批量删除同样逐行列出，删除前默认先强制汇报（tracker 确认失败则不删除）

**设置页（图形化配置编辑，推荐的配置入口）**：

- **全部配置表单化增删改**：基础设置、qB 连接、日志、通知、站点（左列表 + 右详情）、规则集（规则 + 16 种条件 / 12 种动作的选择、排序与参数编辑）、全局限速曲线（表单 + 阶梯图）等
- **只读 YAML 预览**：保存前可展开预览，与最终保存的内容完全一致，不会落盘
- **保存并热重载**：保存前自动校验（不通过不会写盘）→ 自动备份 `.bak` → 写入配置文件（保留你原有的注释与书写风格）→ 改动立即生效；个别需重启的项（如数据目录）会自动保持旧值并提示重启

- 规则系统：触发时机、16 种筛选条件、12 种动作、去重与错误处理、状态映射表、checking 校验 / 跳检的风险对照与安全保障

最常踩的几个点提前说：时间单位 `S/M/H/D`、速度 `[KMG]iB/s`、大小 `[KMGT]iB`（不区分大小写）；标签 / 路径匹配用 `regex:` 前缀走正则；多实例运行请为每个实例单独指定 `data_dir`。

## 设计理念

这些原则决定了 auto-qb 在各种情况下的行为方式，也是它「敢于自动操作」的底气：

- **幂等**：同一个动作重复执行不会产生额外副作用；「每天一次」这类节奏由程序自己记录、重启也不受影响，而不是靠检查得频繁来碰运气
- **保守默认**：高风险动作（跳检、强制汇报、删除种子、覆盖限速）默认关闭，或只对你明确允许的范围生效
- **状态可续**：跨重启的状态（规则执行历史、上传量统计、限速状态等）都保存在数据目录，重启后接着上次的进度继续
- **先查再跑**：启动时把整个配置检查一遍，所有问题一次报出来；检查通过才开始操作 qBittorrent

> 想了解代码结构与内部实现？开发者请看 [memory-bank/README.md](memory-bank/README.md) 知识库。
