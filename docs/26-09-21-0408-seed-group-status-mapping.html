01结论速览

四条先记住

  • 组行颜色 = 组内成员 kind 里 rank 最小的那一个。**不是多数票**,1 个做种 + 3 个暂停也取做种色。
  • rank 顺序:error < downloading < checking < seeding < paused < other。2026-09-21 修正
  • 辅种表没有状态列 —— 组状态只由颜色表达,所以颜色错了没有任何文字可以兜底。
  • 只有 6 个 kind,但它们由 22 个 qB 原始状态折叠而来。

3.2 为什么顺序不能换4 个状态命中多个标志

只有这 4 个状态同时命中两个标志位,顺序写反就会改变分类结果:

state同时命中实际取若顺序写反会变成
checkingUPchecking + uploadingcheckingseeding ✗
checkingDLchecking + downloadingcheckingdownloading ✗
pausedDLstopped + downloadingpauseddownloading ✗
stoppedDLstopped + downloadingpauseddownloading ✗

所以 _state_kind 里 is_stopped 必须排在 is_downloading / is_uploading 之前 —— 暂停的种子同时"像在下载/像在做种"。

04组级:6 类怎么合成 1 个组色

组状态 = 组内所有成员 kind 里 rank 数值最小的那一个。语义是"先报需要处理的,再报在跑的,最后报已完成的"。

4.3 第 3 / 第 4 条的先后2026-09-21 修正

2026-09-19 为消除"同一概念两张表"把前端表整体对齐后端时,paused 被提到了 seeding 之前 —— 于是"部分暂停、部分做种中"的组由绿变灰(回归提交 04cbc8e)。现两张表一起改回做种优先,理由:组内"个别站点被暂停"是常态,取 paused 会把整个在做种的组刷成灰。

代价与边界:追剧页集行用的是后端那张表,所以两页同步变绿。若只想改辅种页,就得拆成两张表并放弃"两页同色"这条不变量 —— 当前选择是保持两页一致。

07口径与易错点

  1. 多数票无效。组色取 rank 最小,与数量无关 —— 1 做种 + 3 暂停仍然是s-seeding绿。看到"大部分站点已暂停却是绿的"属设计如此,不是 bug。
  2. 组表没有状态列。组状态只由颜色承载;聚合文案(做种 3 · 已暂停 1)虽然算出来了,但当前模板里没有消费者。所以颜色错 = 用户完全看不到真实状态。本次 bug 之所以刺眼,根因在此
  3. 站点芯片不跟随组色。它是成员级信息(组内不同站点状态可不同),强行统一会把这一层信息抹平 —— 所以"组行是绿的、其中一个芯片是灰的"是正确的。
  4. 乐观 UI 期间组色会先变。点击暂停/开始后,前端先按预测的成员 kind 重算组色并挂 is-pending,约 100~300ms 后以真值收敛;发送失败则回滚。这段时间的组色是"预测"不是"事实"。
  5. 值为 0 的单元格不着色。:not(.zero) 是有意的 —— 否则一整行绿色里混着 0,分不清哪些是真数据。
  6. 组内其它标记与状态色无关。标签/分类的 ±(不一致)、大小列的 sizeMismatch 警告、H&R 列的图标各有自己的语义色,不要拿它们判断组状态。
  7. 追剧页集行用的是后端那张表。epState(e) 在稳态下直接返回后端算好的 e.state(后端 min(kinds, key=rank)),只有"成员在飞"时才按前端表现算。所以改顺序必须两处一起改,否则两页不同色 + 乐观 UI 颜色弹回。两表一致性由静态守阵机械比对。

08自检手法

怀疑某一行颜色不对时,在页面控制台里直接问 Vue 实例要答案 —— 不用猜,也不用截图比对。

// 1. 看某一组算出来的 primary 与聚合文案(取前 5 组)
const vm = document.querySelector('#app')._vnode.component.proxy;
vm.decoratedGroups.slice(0, 5).map(g => ({
  name: g.name,
  primary: g.status.primary,      // → 决定 s-<primary>
  summary: g.status.text,         // → "做种 3 · 已暂停 1"
  kinds:   g.members.map(m => m.kind),
}));

// 2. 看某一行真实渲染出的 class 与颜色(最权威)
const el = document.querySelector('.group-row[data-table="group"]');
el.className;                                     // "group-row s-seeding"
getComputedStyle(el.querySelector('.g-name-text')).color;   // 绿/灰

// 3. 只看某一行的成员构成(找"混合态"样本)
vm.decoratedGroups.filter(g => new Set(g.members.map(m => m.kind)).size > 1)
  .map(g => [g.name, g.status.primary, g.status.text]);

注意:组表是窗口化 + 客户端排序的(默认按"添加于"降序,只渲染视口附近约 26 行)。所以用 querySelector 找一行时,该行可能压根没渲染 —— 先 scrollIntoView 或按 data-key 定位,别把"没渲染"读成"没生效"。
